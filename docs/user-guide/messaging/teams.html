      إعداد Microsoft Teams

      اربط Hermes Agent بـ Microsoft Teams كبوت. بخلاف Socket Mode في Slack، يسلّم Teams الرسائل عبر استدعاء webhook عام يعمل بـ HTTPS، لذا تحتاج نسختك إلى endpoint يمكن الوصول إليه علنًا — إما نفق تطوير (dev tunnel) للتطوير المحلي، أو نطاق حقيقي لبيئة الإنتاج.

      هل تحتاج إلى ملخّصات الاجتماعات المستندة إلى أحداث Microsoft Graph بدلًا من محادثات البوت العادية؟ استخدم صفحة الإعداد المخصّصة: اجتماعات Teams.

      نفّذ hermes gateway setup واختر Microsoft Teams للحصول على إعداد موجَّه خطوة بخطوة.

      كيف يستجيب البوت​

      السياقالسلوك
      المحادثة الشخصية (DM)يردّ البوت على كل رسالة، دون الحاجة إلى @mention.
      المحادثة الجماعيةيردّ البوت فقط عند الإشارة إليه بـ @mention.
      القناةيردّ البوت فقط عند الإشارة إليه بـ @mention.

      يسلّم Teams الإشارات (@mentions) كرسائل عادية تحتوي على وسوم <at>BotName</at>، ويزيلها Hermes تلقائيًا قبل المعالجة.

      في التثبيت من المصدر أو التثبيت المحلي، ضمّن الإضافة (extra) الخاصة بـ Teams حتى يتمكن المحوّل (adapter) المضمّن من استيراد Microsoft Teams SDK:

      uv sync --extra teams
      # or, for editable installs:
      uv pip install -e ".[teams]"

      الخطوة 1: ثبّت Teams CLI​

      تؤتمت أداة @microsoft/teams.cli تسجيل البوت — دون الحاجة إلى بوابة Azure.

      npm install -g @microsoft/teams.cli@preview
      teams login

      للتحقق من تسجيل دخولك ومعرفة AAD object ID الخاص بك (المطلوب لـ TEAMS_ALLOWED_USERS):

      teams status --verbose

      الخطوة 2: أتِح منفذ Webhook​

      لا يستطيع Teams تسليم الرسائل إلى localhost. في التطوير المحلي، استخدم أي أداة نفق (tunnel) للحصول على عنوان URL عام يعمل بـ HTTPS. المنفذ الافتراضي هو 3978 — ويمكنك تغييره عبر TEAMS_PORT عند الحاجة.

      # devtunnel (Microsoft)
      devtunnel create hermes-bot --allow-anonymous
      devtunnel port create hermes-bot -p 3978 --protocol http  # replace 3978 with TEAMS_PORT if changed
      devtunnel host hermes-bot

      # ngrok
      ngrok http 3978  # replace 3978 with TEAMS_PORT if changed

      # cloudflared
      cloudflared tunnel --url http://localhost:3978  # replace 3978 with TEAMS_PORT if changed

      انسخ عنوان https:// من المخرجات — ستستخدمه في الخطوة التالية. أبقِ النفق قيد التشغيل أثناء التطوير.

      يستخدم عنوان URL العام للنفق بروتوكول HTTPS، أما مستمع webhook المحلي في Hermes فيستخدم HTTP عاديًا. ينهي النفق اتصال TLS ويمرّر طلبات HTTP إلى المنفذ 3978؛ لذا لا تضبط منفذ النفق المحلي على HTTPS.

      في بيئة الإنتاج، وجّه endpoint البوت إلى النطاق العام لخادمك بدلًا من ذلك (راجع النشر في بيئة الإنتاج).

      الخطوة 3: أنشئ البوت​

      teams app create \
        --name "Hermes" \
        --endpoint "https://<your-tunnel-url>/api/messages"

      تعرض CLI قيم CLIENT_ID و CLIENT_SECRET و TENANT_ID، إضافةً إلى رابط تثبيت ستستخدمه في الخطوة 6. احفظ client secret — فلن يُعرض مرة أخرى.

      الخطوة 4: اضبط متغيرات البيئة​

      أضف ما يلي إلى ~/.hermes/.env:

      # Required
      TEAMS_CLIENT_ID=<your-client-id>
      TEAMS_CLIENT_SECRET=<your-client-secret>
      TEAMS_TENANT_ID=<your-tenant-id>

      # Restrict access to specific users (recommended)
      # Use AAD object IDs from `teams status --verbose`
      TEAMS_ALLOWED_USERS=<your-aad-object-id>

      الخطوة 5: شغّل Gateway​

      Docker (يجب التشغيل من المجلد الذي يحتوي على docker-compose.yml — وهو عادةً مستودع hermes-agent الذي نسخته، لا ~):

      cd /path/to/hermes-agent
      HERMES_UID=$(id -u) HERMES_GID=$(id -g) docker compose up -d gateway

      التثبيت الأصلي / عبر systemd (المُثبّت المعتاد لـ hermes بسطر واحد، ضمن ~/.hermes/hermes-agent):

      hermes gateway restart
      # or foreground: hermes gateway run

      إن Teams SDK اختياري؛ فعند تفعيل Teams، يثبّته gateway عند الطلب (lazy-install) داخل الـ venv الخاص بـ Hermes عند أول تشغيل (لا تستخدم pip install الخاص بالنظام على Ubuntu 24.04 — إذ يصطدم ذلك بخطأ PEP 668 externally-managed-environment). للتثبيت يدويًا داخل venv الخاص بـ Hermes:

      ~/.hermes/hermes-agent/venv/bin/pip install microsoft-teams-apps aiohttp
      # or from a clone of the agent: uv sync --extra teams

      منفذ webhook الافتراضي هو 3978 (يمكن تغييره عبر TEAMS_PORT). تحقّق من أنه يعمل:

      curl http://localhost:3978/health   # should return: ok
      # Docker:
      docker logs -f hermes
      # Native:
      hermes gateway status -l

      ابحث عن:

      [teams] Webhook server listening on * (all interfaces, IPv4+IPv6):3978/api/messages

      الخطوة 6: ثبّت التطبيق في Teams​

      teams app get <teamsAppId> --install-link

      افتح الرابط المطبوع في متصفحك — وسيُفتح مباشرةً في عميل Teams. بعد التثبيت، أرسل رسالة مباشرة إلى البوت — وسيكون جاهزًا.

      مرجع الإعدادات​

      متغيرات البيئة​

      المتغيرالوصف
      TEAMS_CLIENT_IDمعرّف التطبيق (client ID) في Azure AD
      TEAMS_CLIENT_SECRETclient secret الخاص بـ Azure AD
      TEAMS_TENANT_IDمعرّف المستأجر (tenant ID) في Azure AD
      TEAMS_ALLOWED_USERSمعرّفات AAD object IDs المسموح لها باستخدام البوت، مفصولة بفواصل
      TEAMS_ALLOW_ALL_USERSاضبطه على true لتخطّي قائمة السماح والسماح لأي شخص
      TEAMS_HOME_CHANNELمعرّف المحادثة (Conversation ID) لتسليم رسائل cron والرسائل الاستباقية
      TEAMS_HOME_CHANNEL_NAMEالاسم المعروض للقناة الرئيسية (home channel)
      TEAMS_PORTمنفذ webhook (الافتراضي: 3978)

      config.yaml​

      بدلًا من ذلك، يمكنك الضبط عبر ~/.hermes/config.yaml:

      platforms:
        teams:
          enabled: true
          extra:
            client_id: "your-client-id"
            client_secret: "your-secret"
            tenant_id: "your-tenant-id"
            port: 3978

      الميزات​

      بطاقات الموافقة التفاعلية​

      عندما يحتاج الوكيل إلى تنفيذ أمر قد يكون خطيرًا، يرسل Adaptive Card تحتوي على أربعة أزرار بدلًا من أن يطلب منك كتابة /approve:

      • Allow Once — الموافقة على هذا الأمر تحديدًا
      • Allow Session — الموافقة على هذا النمط لبقية الجلسة
      • Always Allow — الموافقة الدائمة على هذا النمط
      • Deny — رفض الأمر

      يؤدي النقر على أحد الأزرار إلى حسم الموافقة مباشرةً واستبدال البطاقة بالقرار المتخذ.

      تسليم ملخّصات الاجتماعات (Teams Meeting Pipeline)​

      عند تفعيل إضافة Teams meeting pipeline، يتولى هذا المحوّل أيضًا التسليم الصادر لملخّصات الاجتماعات — أي واجهة تكامل واحدة مع Teams لا اثنتين. بعد تلخيص نص الاجتماع (transcript)، ينشر الكاتب (writer) الملخّص في وجهة Teams التي اخترتها.

      يُضبط تسليم ملخّصات pipeline ضمن مدخل المنصة teams إلى جانب إعدادات البوت:

      platforms:
        teams:
          enabled: true
          extra:
            # existing bot config (client_id, client_secret, tenant_id, port) ...

            # Meeting summary delivery (only used when the teams_pipeline plugin is enabled)
            delivery_mode: "graph"       # or "incoming_webhook"
            # For delivery_mode: graph — pick ONE of:
            chat_id: "19:meeting_..."    # post into a Teams chat
            # team_id: "..."             # OR post into a channel
            # channel_id: "..."
            # access_token: "..."        # optional; falls back to MSGRAPH_* app credentials
            # For delivery_mode: incoming_webhook:
            # incoming_webhook_url: "https://outlook.office.com/webhook/..."
      الوضعمتى تستخدمهالمقايضة
      incoming_webhookحالة بسيطة من نوع "انشر ملخّصًا في هذه القناة" باستخدام عنوان URL ثابت يولّده Teams.لا يدعم سلاسل الردود ولا التفاعلات (reactions)، ويظهر بالهوية المضبوطة لـ webhook.
      graphمنشورات القنوات ضمن سلاسل، أو منشورات المحادثات الفردية/الجماعية بهوية البوت عبر Microsoft Graph.يتطلب تسجيل تطبيق Graph مع صلاحيات التطبيق ChannelMessage.Send (للقنوات) أو Chat.ReadWrite.All (للمحادثات).

      إذا كانت الإضافة teams_pipeline غير مفعّلة، فلا أثر لهذه الإعدادات — إذ لا تُربط إلا عندما يرتبط وقت تشغيل pipeline بمدخل webhook الخاص بـ Graph.

      النشر في بيئة الإنتاج​

      على خادم دائم، أنهِ اتصال TLS عند reverse proxy ومرّر الطلبات إلى مستمع HTTP العادي في Hermes، وهو عادةً http://127.0.0.1:3978. سجّل endpoint الـ HTTPS العام للـ proxy لدى Teams:

      teams app create \
        --name "Hermes" \
        --endpoint "https://your-domain.com/api/messages"

      إذا كنت قد أنشأت البوت بالفعل وتحتاج فقط إلى تحديث endpoint:

      teams app update --id <teamsAppId> --endpoint "https://your-domain.com/api/messages"

      تأكد من أن endpoint الـ HTTPS العام يمكن الوصول إليه من الإنترنت ويستخدم شهادة TLS صالحة، إذ يرفض Teams الشهادات الموقّعة ذاتيًا. أبقِ مستمع Hermes خلف الـ proxy؛ فالمنفذ 3978 لا يقدّم HTTPS بنفسه.

      يتغيّر عنوان URL للنفق عند إعادة التشغيلتبقى عناوين devtunnel ثابتة إذا استخدمت نفقًا مُسمّى (devtunnel create hermes-bot). أما ngrok و cloudflared فيولّدان عنوان URL جديدًا في كل تشغيل ما لم تكن لديك خطة مدفوعة — حدّث endpoint البوت باستخدام teams app update عند تغيّره
      يعرض Teams الرسالة "This bot is not responding"أعاد webhook خطأً. راجع docker logs hermes / hermes gateway status -l بحثًا عن traceback
      ظهور [teams] Failed to connect في السجلاتفشل SDK في المصادقة. تحقّق جيدًا من بيانات الاعتماد، ومن أن tenant ID يطابق الحساب الذي استخدمته في teams login

      الأمان​

      تحذير

      اضبط دائمًا TEAMS_ALLOWED_USERS بمعرّفات AAD object IDs الخاصة بالمستخدمين المصرّح لهم. بدون ذلك، يستطيع أي شخص يعثر على البوت أو يثبّته التفاعل معه.

      تعامل مع TEAMS_CLIENT_SECRET ككلمة مرور — وغيّره دوريًا عبر بوابة Azure أو Teams CLI.

      • خزّن بيانات الاعتماد في ~/.hermes/.env بصلاحيات 600 (chmod 600 ~/.hermes/.env)
      • لا يقبل البوت الرسائل إلا من المستخدمين المُدرجين في TEAMS_ALLOWED_USERS؛ وتُسقَط الرسائل غير المصرّح بها بصمت
      • تتم مصادقة endpoint العام (/api/messages) بواسطة Teams Bot Framework — وتُرفض الطلبات التي لا تحمل JWT صالحًا
