      التكامل مع Home Assistant

      يتكامل Hermes Agent مع Home Assistant بطريقتين:

      1. منصة Gateway — تشترك في تغييرات الحالة في الوقت الفعلي عبر WebSocket وتستجيب للأحداث
      2. أدوات المنزل الذكي — أربع أدوات يمكن للـ LLM استدعاؤها للاستعلام عن الأجهزة والتحكم فيها عبر REST API

      الإعداد​

      1. إنشاء Long-Lived Access Token​

      1. افتح نسخة Home Assistant الخاصة بك
      2. انتقل إلى Profile (انقر على اسمك في الشريط الجانبي)
      3. مرّر إلى Long-Lived Access Tokens
      4. انقر على Create Token، وامنحه اسمًا مثل "Hermes Agent"
      5. انسخ الـ token

      2. ضبط متغيرات البيئة​

      # Add to ~/.hermes/.env

      # Required: your Long-Lived Access Token
      HASS_TOKEN=your-long-lived-access-token

      # Optional: HA URL (default: http://homeassistant.local:8123)
      HASS_URL=http://192.168.1.100:8123
      معلومة

      يُفعَّل الـ toolset homeassistant تلقائيًا عند ضبط HASS_TOKEN. وتُفعَّل منصة الـ gateway وأدوات التحكم في الأجهزة كلتاهما بهذا الـ token الواحد.

      3. تشغيل الـ Gateway​

      hermes gateway

      سيظهر Home Assistant كمنصة متصلة إلى جانب أي منصات مراسلة أخرى (Telegram و Discord وغيرهما).

      الأدوات المتاحة​

      يسجّل Hermes Agent أربع أدوات للتحكم في المنزل الذكي:

      ha_list_entities​

      تعرض قائمة كيانات (entities) Home Assistant، مع إمكانية التصفية حسب النطاق (domain) أو المنطقة.

      المعاملات:

      • domain (اختياري) — التصفية حسب نطاق الكيان: light، switch، climate، sensor، binary_sensor، cover، fan، media_player، وغيرها.
      • area (اختياري) — التصفية حسب اسم المنطقة/الغرفة (يُطابَق مع الأسماء المألوفة friendly names): living room، kitchen، bedroom، وغيرها.

      مثال:

      List all lights in the living room

      تُرجع معرّفات الكيانات وحالاتها وأسماءها المألوفة.

      ha_get_state​

      تجلب الحالة التفصيلية لكيان واحد، بما في ذلك جميع خصائصه (السطوع، واللون، ودرجة الحرارة المستهدفة، وقراءات المستشعرات، وغيرها).

      المعاملات:

      • entity_id (مطلوب) — الكيان المراد الاستعلام عنه، مثل light.living_room، climate.thermostat، sensor.temperature

      مثال:

      What's the current state of climate.thermostat?

      تُرجع: الحالة، وجميع الخصائص، والطوابع الزمنية لآخر تغيير/تحديث.

      ha_list_services​

      تعرض قائمة الخدمات (الإجراءات) المتاحة للتحكم في الأجهزة، وتوضّح الإجراءات التي يمكن تنفيذها على كل نوع من الأجهزة والمعاملات التي تقبلها.

      المعاملات:

      • domain (اختياري) — التصفية حسب النطاق، مثل light، climate، switch

      مثال:

      What services are available for climate devices?

      ha_call_service​

      تستدعي خدمة في Home Assistant للتحكم في جهاز.

      المعاملات:

      • domain (مطلوب) — نطاق الخدمة: light، switch، climate، cover، media_player، fan، scene، script
      • service (مطلوب) — اسم الخدمة: turn_on، turn_off، toggle، set_temperature، set_hvac_mode، open_cover، close_cover، set_volume_level
      • entity_id (اختياري) — الكيان المستهدف، مثل light.living_room
      • data (اختياري) — معاملات إضافية على شكل كائن JSON

      أمثلة:

      Turn on the living room lights
      → ha_call_service(domain="light", service="turn_on", entity_id="light.living_room")
      Set the thermostat to 22 degrees in heat mode
      → ha_call_service(domain="climate", service="set_temperature",
          entity_id="climate.thermostat", data={"temperature": 22, "hvac_mode": "heat"})
      Set living room lights to blue at 50% brightness
      → ha_call_service(domain="light", service="turn_on",
          entity_id="light.living_room", data={"brightness": 128, "color_name": "blue"})

      منصة Gateway: الأحداث في الوقت الفعلي​

      يتصل محوّل (adapter) الـ gateway الخاص بـ Home Assistant عبر WebSocket ويشترك في أحداث state_changed. وعندما تتغير حالة جهاز وتطابق عوامل التصفية لديك، يُمرَّر الحدث إلى الوكيل على شكل رسالة.

      تصفية الأحداث​

      إعداد مطلوب

      افتراضيًا، لا يُمرَّر أي حدث. يجب أن تضبط واحدًا على الأقل من watch_domains أو watch_entities أو watch_all لاستقبال الأحداث. ومن دون عوامل تصفية، يُسجَّل تحذير عند بدء التشغيل وتُسقط جميع تغييرات الحالة بصمت.

      اضبط الأحداث التي يراها الوكيل في ~/.hermes/config.yaml ضمن القسم extra الخاص بمنصة Home Assistant:

      platforms:
        homeassistant:
          enabled: true
          extra:
            watch_domains:
              - climate
              - binary_sensor
              - alarm_control_panel
              - light
            watch_entities:
              - sensor.front_door_battery
            ignore_entities:
              - sensor.uptime
              - sensor.cpu_usage
              - sensor.memory_usage
            cooldown_seconds: 30
      الإعدادالقيمة الافتراضيةالوصف
      watch_domains(لا شيء)مراقبة نطاقات الكيانات هذه فقط (مثل climate، light، binary_sensor)
      watch_entities(لا شيء)مراقبة معرّفات الكيانات المحددة هذه فقط
      watch_allfalseاضبطه على true لاستقبال جميع تغييرات الحالة (غير موصى به لمعظم الإعدادات)
      ignore_entities(لا شيء)تجاهل هذه الكيانات دائمًا (يُطبَّق قبل عوامل تصفية النطاقات/الكيانات)
      cooldown_seconds30الحد الأدنى بالثواني بين الأحداث للكيان نفسه
      نصيحة

      ابدأ بمجموعة مركّزة من النطاقات — إذ تغطي climate و binary_sensor و alarm_control_panel أكثر عمليات الأتمتة فائدة. وأضف المزيد حسب الحاجة. استخدم ignore_entities لكتم المستشعرات كثيرة الضجيج مثل حرارة المعالج أو عدّادات مدة التشغيل.

      تنسيق الأحداث​

      تُنسَّق تغييرات الحالة كرسائل مقروءة للبشر بحسب النطاق:

      النطاقالتنسيق
      climate"HVAC mode changed from 'off' to 'heat' (current: 21, target: 23)"
      sensor"changed from 21°C to 22°C"
      binary_sensor"triggered" / "cleared"
      light، switch، fan"turned on" / "turned off"
      alarm_control_panel"alarm state changed from 'armed_away' to 'triggered'"
      (أخرى)"changed from 'old' to 'new'"

      ردود الوكيل​

      تُسلَّم الرسائل الصادرة من الوكيل على شكل إشعارات دائمة في Home Assistant (عبر persistent_notification.create). وتظهر في لوحة إشعارات HA بالعنوان "Hermes Agent".

      إدارة الاتصال​

      • WebSocket مع نبضات قلب (heartbeat) كل 30 ثانية للأحداث في الوقت الفعلي
      • إعادة اتصال تلقائية مع تأخير متزايد (backoff): 5s → 10s → 30s → 60s
      • REST API للإشعارات الصادرة (جلسة منفصلة لتجنب التعارض مع WebSocket)
      • التفويض — أحداث HA مُفوَّضة دائمًا (لا حاجة إلى قائمة سماح للمستخدمين، لأن HASS_TOKEN يصادق على الاتصال)

      تفرض أدوات Home Assistant قيودًا أمنية:

      النطاقات المحظورة

      نطاقات الخدمات التالية محظورة لمنع تنفيذ شيفرة عشوائية على مضيف HA:

      • shell_command — أوامر shell عشوائية
      • command_line — مستشعرات/مفاتيح تنفّذ أوامر
      • python_script — تنفيذ Python عبر السكربتات
      • pyscript — تكامل أوسع للبرمجة النصية
      • hassio — التحكم في الإضافات (addons)، وإيقاف تشغيل المضيف/إعادة تشغيله
      • rest_command — طلبات HTTP من خادم HA (منفذ لهجمات SSRF)

      تؤدي محاولة استدعاء خدمات ضمن هذه النطاقات إلى إرجاع خطأ.

      يُتحقق من معرّفات الكيانات مقابل النمط ^[a-z_][a-z0-9_]*\.[a-z0-9_]+$ لمنع هجمات الحقن.

      أمثلة على الأتمتة​

      الروتين الصباحي​

      User: Start my morning routine

      Agent:
      1. ha_call_service(domain="light", service="turn_on",
           entity_id="light.bedroom", data={"brightness": 128})
      2. ha_call_service(domain="climate", service="set_temperature",
           entity_id="climate.thermostat", data={"temperature": 22})
      3. ha_call_service(domain="media_player", service="turn_on",
           entity_id="media_player.kitchen_speaker")

      الفحص الأمني​

      User: Is the house secure?

      Agent:
      1. ha_list_entities(domain="binary_sensor")
           → checks door/window sensors
      2. ha_get_state(entity_id="alarm_control_panel.home")
           → checks alarm status
      3. ha_list_entities(domain="lock")
           → checks lock states
      4. Reports: "All doors closed, alarm is armed_away, all locks engaged."

      الأتمتة التفاعلية (عبر أحداث Gateway)​

      عند الاتصال كمنصة gateway، يستطيع الوكيل التفاعل مع الأحداث:

      [Home Assistant] Front Door: triggered (was cleared)

      Agent automatically:
      1. ha_get_state(entity_id="binary_sensor.front_door")
      2. ha_call_service(domain="light", service="turn_on",
           entity_id="light.hallway")
      3. Sends notification: "Front door opened. Hallway lights turned on."

      استكشاف الأخطاء وإصلاحها​

      عدم التقاط متغيرات البيئة. يقرأ المحوّل بيانات الاعتماد من ~/.hermes/.env (الذي يُدمج تلقائيًا عند بدء التشغيل) أو من config.yaml. تحقق جيدًا من أن الملف موجود ضمن المجلد الرئيسي لـ profile Hermes النشط، ومن عدم وجود علامات اقتباس زائدة حول الـ URL أو الـ token. أعد تشغيل الـ gateway بعد التعديل — إذ لا تُطبَّق تغييرات متغيرات البيئة إلا عند بدء العملية.

      فشل مصادقة REST (401 Unauthorized). يجب أن يكون الـ token من نوع Long-Lived Access Token مُنشأً من صفحة ملف المستخدم في HA (Profile → Security → Long-lived access tokens). لن تعمل tokens جلسات الواجهة قصيرة الأمد. وتحقق أيضًا من أن الـ URL الأساسي يتضمن البروتوكول (scheme) والمنفذ (مثل http://homeassistant.local:8123) وأنه يمكن الوصول إليه من المضيف الذي يشغّل Hermes — يجب أن يُرجع الأمر curl -H "Authorization: Bearer <token>" <url>/api/ الناتج {"message": "API running."}.
