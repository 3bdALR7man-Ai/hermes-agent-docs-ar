      مستمع Microsoft Graph Webhook

      منصة gateway المسمّاة msgraph_webhook هي مستمع للأحداث الواردة، وهي الطريقة التي يستقبل بها Hermes إشعارات التغيير (change notifications) من Microsoft Graph — مثل "انتهى اجتماع على Teams"، و"وصلت رسالة جديدة إلى هذه المحادثة"، و"جرى تحديث حدث التقويم هذا". وهي تختلف عن المنصة teams (وهي بوت محادثة يكتب إليه المستخدمون) — فهنا تُبلغ خدمة M365 نفسها Hermes بأن شيئًا ما قد حدث، لا شخص.

      حاليًا، المستهلك الرئيسي لها هو pipeline ملخّصات اجتماعات Teams: يُرسل Graph إشعارًا عندما ينتج اجتماعٌ نصًّا (transcript)، فيجلبه pipeline، ثم ينشر Hermes ملخّصًا في Teams. تستخدم موارد Graph الأخرى (/chats/.../messages و /users/.../events) المستمع نفسه — وستصل مستهلكات pipeline الخاصة بها عبر pull requests مستقلة.

      المتطلبات المسبقة​

      • بيانات اعتماد تطبيق Microsoft Graph — راجع تسجيل تطبيق Microsoft Graph
      • عنوان URL عام يعمل بـ HTTPS يستطيع Microsoft Graph الوصول إليه (لا يستدعي Graph أي endpoints خاصة). يكفي نفق تطوير (dev tunnel) للاختبار، أما بيئة الإنتاج فتحتاج إلى نطاق حقيقي بشهادة صالحة.
      • سرّ مشترك قوي لاستخدامه كقيمة لـ clientState. ولّده باستخدام openssl rand -hex 32 وضعه في ~/.hermes/.env باسم MSGRAPH_WEBHOOK_CLIENT_STATE.

      البدء السريع​

      الحد الأدنى من ~/.hermes/config.yaml:

      platforms:
        msgraph_webhook:
          enabled: true
          extra:
            host: 127.0.0.1
            port: 8646
            client_state: "replace-with-a-strong-secret"
            accepted_resources:
              - "communications/onlineMeetings"

      أو عبر متغيرات البيئة في ~/.hermes/.env (تُدمَج تلقائيًا عند بدء التشغيل):

      MSGRAPH_WEBHOOK_ENABLED=true
      MSGRAPH_WEBHOOK_PORT=8646
      MSGRAPH_WEBHOOK_CLIENT_STATE=<generate-with-openssl-rand-hex-32>
      MSGRAPH_WEBHOOK_ACCEPTED_RESOURCES=communications/onlineMeetings

      ملاحظة: يُقرأ مضيف الربط (bind host) من extra.host في config.yaml (راجع المثال أعلاه)؛ ولا يوجد متغير بيئة باسم MSGRAPH_WEBHOOK_HOST لتجاوزه.

      شغّل gateway: hermes gateway run. يوفّر المستمع:

      • POST /msgraph/webhook — إشعارات التغيير من Graph
      • GET /msgraph/webhook?validationToken=... — مصافحة التحقق (validation handshake) لاشتراكات Graph
      • GET /health — فحص الجاهزية (readiness probe) مع عدّادات للإشعارات المقبولة والمكرّرة

      أتِح المستمع للوصول العام (عبر reverse proxy أو dev tunnel أو ingress). عنوان URL للإشعارات في اشتراكات Graph هو أصل HTTPS العام الخاص بك متبوعًا بـ /msgraph/webhook:

      https://ops.example.com/msgraph/webhook

      الإعدادات​

      توضع جميع الإعدادات ضمن platforms.msgraph_webhook.extra:

      الإعدادالقيمة الافتراضيةالوصف
      hostغير مضبوط (dual-stack: جميع الواجهات، IPv4+IPv6)عنوان الربط لمستمع HTTP. يتطلب الربط على عنوان غير loopback ضبط allowed_source_cidrs؛ أما loopback (127.0.0.1 / ::1) فهو أسهل إعداد مع dev tunnel أو reverse proxy.
      port8646منفذ الربط.
      webhook_path/msgraph/webhookمسار URL الذي يرسل إليه Graph طلبات POST.
      health_path/healthendpoint فحص الجاهزية.
      client_state—سرّ مشترك يعيده Graph في كل إشعار. تجري المقارنة باستخدام hmac.compare_digest — ولّده باستخدام openssl rand -hex 32.
      accepted_resources[] (قبول الكل)قائمة سماح لمسارات/أنماط موارد Graph. تعمل علامة * في النهاية كمطابقة للبادئة، ويُتسامَح مع وجود / في البداية. مثال: ["communications/onlineMeetings", "chats/*/messages"].
      max_seen_receipts5000حجم ذاكرة التخزين المؤقت لإزالة تكرار معرّفات الإشعارات. تُحذف أقدم المدخلات عند بلوغ الحدّ الأقصى.
      allowed_source_cidrs[]مطلوب عند الربط على عنوان غير loopback. اتركه فارغًا فقط عندما يكون المستمع مربوطًا على loopback وخلف نفق محلي أو reverse proxy.

      لمعظم الإعدادات أيضًا متغير بيئة مكافئ (MSGRAPH_WEBHOOK_*) يُدمَج في الإعدادات عند بدء تشغيل gateway (باستثناء host، الذي يُضبط عبر ملف الإعدادات فقط — راجع الملاحظة أعلاه) — راجع مرجع متغيرات البيئة.

      تعزيز الأمان​

      clientState هو فحص المصادقة الأساسي​

      يتضمن كل إشعار من Graph سلسلة clientState التي سُجِّل بها اشتراكك. يرفض المستمع أي إشعار لا تتطابق فيه قيمة clientState، باستخدام مقارنة آمنة من هجمات التوقيت (timing-safe). هذه هي الآلية الموثّقة من Microsoft — لذا تعامل مع هذه القيمة كسرّ مشترك قوي.

      إذا لم تُضبط client_state، فسيرفض المستمع بدء التشغيل.

      قائمة السماح لعناوين IP المصدر (لبيئات الإنتاج)​

      في بيئة الإنتاج، قيّد المستمع بنطاقات عناوين IP المصدر المنشورة من Microsoft لـ Graph webhook. توثّق Microsoft نطاقات العناوين الصادرة ضمن Office 365 IP Address and URL Web service. اضبطها على النحو التالي:

      platforms:
        msgraph_webhook:
          enabled: true
          extra:
            host: 0.0.0.0
            client_state: "..."
            allowed_source_cidrs:
              - "52.96.0.0/14"
              - "52.104.0.0/14"
              # ...add the current Microsoft 365 "Common" + "Teams" category egress ranges

      أو كمتغير بيئة:

      MSGRAPH_WEBHOOK_ALLOWED_SOURCE_CIDRS="52.96.0.0/14,52.104.0.0/14"

      يُرفض عند بدء التشغيل الربطُ على مضيف غير loopback مثل 0.0.0.0 أو :: أو عنوان IP في الشبكة المحلية دون ضبط allowed_source_cidrs. إذا كنت تستخدم dev tunnel أو reverse proxy على الجهاز نفسه، فاربط Hermes على 127.0.0.1 أو ::1 واترك قائمة السماح فارغة في هذه الحالة. تؤدي سلاسل CIDR غير الصالحة إلى تسجيل تحذير ويجري تجاهلها. راجع قائمة عناوين IP من Microsoft كل ثلاثة أشهر — فهي تتغيّر.

      إنهاء HTTPS​

      يتعامل المستمع بـ HTTP عادي. أنهِ اتصال TLS عند reverse proxy (مثل Caddy أو Nginx أو Cloudflare Tunnel أو AWS ALB) ومرّر الطلبات إلى المستمع عبر الشبكة المحلية. يرفض Graph التسليم إلى endpoints لا تعمل بـ HTTPS، لذا لا يوجد مسار يمكن أن تصل عبره حركة مرور غير مشفّرة من Graph نفسه إليك.

      نظافة الاستجابات​

      عند النجاح، يعيد المستمع 202 Accepted بجسم فارغ — فالعدّادات الداخلية لا تُضمَّن في الاستجابة المرسلة. يمكن للمشغّلين الاطلاع على الأعداد عبر /health، الذي تحميه قواعد عناوين IP المصدر نفسها المطبّقة على مسار webhook.

      جدول رموز الحالة:

      النتيجةالحالة
      قبول الإشعار (أو الإشعارات) أو إزالة تكرارها202
      مصافحة التحقق (طلب GET مع validationToken)200 (يعيد الـ token)
      فشل جميع عناصر الدفعة في فحص clientState403
      JSON غير صالح / غياب المصفوفة value / مورد غير معروف400
      عنوان IP المصدر غير موجود في قائمة السماح403
      طلب GET مجرّد دون validationToken400

      استكشاف الأخطاء وإصلاحها​

      المشكلةما الذي تتحقق منه
      فشل التحقق من اشتراك Graphأن عنوان URL العام قابل للوصول، وأن المسار /msgraph/webhook مطابق، وأن طلب GET مع validationToken يعيد الـ token حرفيًا بصيغة text/plain خلال 10 ثوانٍ.
      تصل إشعارات POST لكن لا يُستوعب شيءأن client_state يطابق القيمة التي سجّلت بها الاشتراك. أعد تنفيذ openssl rand -hex 32 وأنشئ اشتراكًا جديدًا إذا تغيّرت القيمة. وتحقّق من أن accepted_resources يتضمن مسار المورد الذي يرسله Graph.
      كل الإشعارات تُرفض بالرمز 403عدم تطابق clientState (إشعار مزوّر، أو اشتراك مسجَّل بقيمة مختلفة). أعد إنشاء الاشتراك باستخدام hermes teams-pipeline subscribe --client-state "$MSGRAPH_WEBHOOK_CLIENT_STATE" ... (يأتي مع PR الخاص بوقت تشغيل pipeline).
      يرفض المستمع بدء التشغيل على 0.0.0.0اضبط allowed_source_cidrs على نطاقات العناوين الصادرة الحالية لـ webhook من Microsoft، أو اربط Hermes على 127.0.0.1 / ::1 خلف النفق أو reverse proxy.
      يبدأ المستمع لكن curl http://localhost:8646/health يتعلّقتعارض في ربط المنفذ. تحقّق باستخدام ss -tlnp | grep 8646 وغيّر port: عند الحاجة.
      طلبات Graph الحقيقية من Microsoft تُرفض بالرمز 403قائمة السماح لعناوين IP المصدر ضيقة جدًا. وسّع القائمة لتشمل نطاقات العناوين الصادرة الحالية من Microsoft. وإذا كنت لا تزال تتحقق من مسار النفق، فاربط Hermes على loopback ودع النفق يتولى الإتاحة العامة.
