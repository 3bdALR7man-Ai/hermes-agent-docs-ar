      اجتماعات Microsoft Teams

      استخدم Teams meeting pipeline عندما تريد من Hermes استقبال أحداث اجتماعات Microsoft Graph، وجلب نصوص الاجتماعات (transcripts) أولًا، والرجوع إلى التسجيلات مع STT عند الحاجة، ثم تسليم ملخّص منظَّم إلى الوجهات اللاحقة (downstream sinks).

      المتطلبات المسبقة: راجع Microsoft Teams لإعداد البوت وبيانات الاعتماد الأساسية.

      نفّذ hermes gateway setup واختر Teams Meetings للحصول على إعداد موجَّه خطوة بخطوة.

      تركّز هذه الصفحة على الإعداد والتفعيل:

      • بيانات اعتماد Graph
      • إعدادات مستمع webhook
      • أوضاع التسليم في Teams
      • بنية إعدادات pipeline

      للعمليات التشغيلية اليومية بعد الإطلاق، وفحوصات الانتقال إلى الإنتاج، وورقة عمل المشغّل، استخدم الدليل المخصّص: تشغيل Teams Meeting Pipeline.

      ما الذي تفعله هذه الميزة​

      يقوم pipeline بما يلي:

      1. يستقبل أحداث webhook من Microsoft Graph
      2. يحدّد الاجتماع ويفضّل عناصر النصوص (transcript artifacts) أولًا
      3. يرجع إلى تنزيل التسجيل مع STT عند عدم توفّر نص صالح للاستخدام
      4. يخزّن حالة المهام الدائمة وسجلات الوجهات (sink records) محليًا
      5. يمكنه كتابة الملخّصات إلى Notion و Linear و Microsoft Teams

      تبقى إجراءات المشغّل ضمن CLI (الأمر الفرعي teams-pipeline تسجّله الإضافة teams_pipeline — فعّلها عبر hermes plugins enable teams_pipeline أو اضبط plugins.enabled: [teams_pipeline] في config.yaml):

      hermes teams-pipeline validate
      hermes teams-pipeline list
      hermes teams-pipeline maintain-subscriptions

      المتطلبات المسبقة​

      قبل تفعيل pipeline الاجتماعات، تأكد من توفّر ما يلي:

      • تثبيت Hermes يعمل
      • إعداد بوت Microsoft Teams القائم، إذا كنت تريد التسليم الصادر إلى Teams
      • بيانات اعتماد تطبيق Microsoft Graph مع الصلاحيات المطلوبة لموارد الاجتماعات التي تنوي الاشتراك فيها
      • عنوان URL عام يعمل بـ HTTPS يستطيع Microsoft Graph استدعاءه لتسليم webhook
      • تثبيت ffmpeg إذا كنت تريد الرجوع الاحتياطي إلى التسجيل مع STT

      الخطوة 1: أضف بيانات اعتماد Microsoft Graph​

      أضف بيانات اعتماد Graph الخاصة بالتطبيق فقط (app-only) إلى ~/.hermes/.env:

      MSGRAPH_TENANT_ID=<tenant-id>
      MSGRAPH_CLIENT_ID=<client-id>
      MSGRAPH_CLIENT_SECRET=<client-secret>

      تُستخدم بيانات الاعتماد هذه من قِبل:

      • الأساس البرمجي لعميل Graph
      • أوامر صيانة الاشتراكات
      • تحديد الاجتماعات وجلب العناصر (artifacts)
      • التسليم الصادر إلى Teams عبر Graph عندما لا توفّر access token مخصّصًا لـ Teams

      الخطوة 2: فعّل مستمع Graph Webhook​

      مستمع webhook هو منصة gateway باسم msgraph_webhook. كحدّ أدنى، فعّله واضبط قيمة client state:

      MSGRAPH_WEBHOOK_ENABLED=true
      MSGRAPH_WEBHOOK_PORT=8646
      MSGRAPH_WEBHOOK_CLIENT_STATE=<random-shared-secret>
      MSGRAPH_WEBHOOK_ACCEPTED_RESOURCES=communications/onlineMeetings

      يُقرأ مضيف الربط (bind host) من extra.host الخاص بالمنصة في config.yaml (لا يوجد متغير بيئة باسم MSGRAPH_WEBHOOK_HOST — راجع مرجع مستمع webhook).

      يوفّر المستمع:

      • /msgraph/webhook لإشعارات Graph
      • /health لفحص سلامة بسيط

      تحتاج إلى توجيه endpoint الـ HTTPS العام إلى هذا المستمع. على سبيل المثال، إذا كان نطاقك العام https://ops.example.com، فسيكون عنوان URL لإشعارات Graph عادةً:

      https://ops.example.com/msgraph/webhook

      الخطوة 3: اضبط التسليم إلى Teams وسلوك Pipeline​

      يقرأ pipeline الاجتماعات إعدادات وقت التشغيل من مدخل المنصة teams القائم. توجد الخيارات الخاصة بـ pipeline ضمن teams.extra.meeting_pipeline، بينما يبقى التسليم الصادر إلى Teams ضمن إعدادات منصة Teams المعتادة.

      مثال على ~/.hermes/config.yaml:

      platforms:
        msgraph_webhook:
          enabled: true
          extra:
            host: 127.0.0.1
            port: 8646
            client_state: "replace-me"
            accepted_resources:
              - "communications/onlineMeetings"

        teams:
          enabled: true
          extra:
            client_id: "your-teams-client-id"
            client_secret: "your-teams-client-secret"
            tenant_id: "your-teams-tenant-id"

            # outbound summary delivery
            delivery_mode: "graph" # or incoming_webhook
            team_id: "team-id"
            channel_id: "channel-id"
            # incoming_webhook_url: "https://..."

            meeting_pipeline:
              transcript_min_chars: 80
              transcript_required: false
              transcription_fallback: true
              ffmpeg_extract_audio: true
              notion:
                enabled: false
              linear:
                enabled: false

      إذا ربطت المستمع بمضيف غير loopback مثل 0.0.0.0، فيجب عليك أيضًا ضبط allowed_source_cidrs على نطاقات العناوين الصادرة لـ webhook من Microsoft. أما الربط على loopback (127.0.0.1 / ::1) فهو الإعداد المقصود للأنفاق التطويرية (dev tunnels) و reverse proxy المحلي.

      أوضاع التسليم في Teams​

      يدعم pipeline وضعين لتسليم الملخّصات إلى Teams ضمن إضافة Teams القائمة.

      incoming_webhook​

      استخدم هذا الوضع عندما تريد نشرًا بسيطًا عبر webhook إلى Teams دون إنشاء رسائل القنوات عبر Graph.

      الإعدادات المطلوبة:

      platforms:
        teams:
          enabled: true
          extra:
            delivery_mode: "incoming_webhook"
            incoming_webhook_url: "https://..."

      graph​

      استخدم هذا الوضع عندما تريد أن ينشر Hermes الملخّص عبر Microsoft Graph في محادثة أو قناة على Teams.

      الوجهات المدعومة:

      • chat_id
      • team_id + channel_id
      • team_id + home_channel كقيمة احتياطية لمنصة Teams القائمة

      مثال:

      platforms:
        teams:
          enabled: true
          extra:
            delivery_mode: "graph"
            team_id: "team-id"
            channel_id: "channel-id"

      الخطوة 4: شغّل Gateway​

      شغّل Hermes بالطريقة المعتادة بعد تحديث الإعدادات:

      hermes gateway run

      أو، إذا كنت تشغّل Hermes داخل Docker، فشغّل gateway بالطريقة نفسها التي تتبعها في عملية النشر لديك.

      تحقّق من المستمع:

      curl http://localhost:8646/health

      الخطوة 5: أنشئ اشتراكات Graph​

      استخدم CLI الخاصة بالإضافة لإنشاء الاشتراكات وفحصها.

      أمثلة:

      hermes teams-pipeline subscribe \
        --resource communications/onlineMeetings/getAllTranscripts \
        --notification-url https://ops.example.com/msgraph/webhook \
        --client-state "$MSGRAPH_WEBHOOK_CLIENT_STATE"

      hermes teams-pipeline subscribe \
        --resource communications/onlineMeetings/getAllRecordings \
        --notification-url https://ops.example.com/msgraph/webhook \
        --client-state "$MSGRAPH_WEBHOOK_CLIENT_STATE"
      تنتهي صلاحية اشتراكات Graph خلال 72 ساعة

      يحدّ Microsoft Graph مدة اشتراكات webhook بـ 72 ساعة ولا يجدّدها تلقائيًا. يتعيّن عليك إلزامًا جدولة hermes teams-pipeline maintain-subscriptions قبل الانتقال إلى الإنتاج، وإلا ستتوقف الإشعارات بصمت بعد ثلاثة أيام من أي إنشاء يدوي للاشتراك. راجع أتمتة تجديد الاشتراكات في دليل تشغيل المشغّل (runbook) — حيث تجد ثلاثة خيارات (Hermes cron، أو systemd timer، أو crontab عادي).

      لصيانة الاشتراكات ومسارات عمل المشغّل اليومية، تابع مع الدليل: تشغيل Teams Meeting Pipeline.

      التحقق​

      نفّذ لقطة التحقق (validation snapshot) المدمجة:

      hermes teams-pipeline validate

      فحوصات مصاحبة مفيدة:

      hermes teams-pipeline token-health
      hermes teams-pipeline subscriptions

      استكشاف الأخطاء وإصلاحها​

      المشكلةما الذي تتحقق منه
      فشل التحقق من Graph webhookتأكد من أن عنوان URL العام صحيح ويمكن الوصول إليه، وأن Graph يستدعي المسار /msgraph/webhook بالضبط
      لا تظهر المهام في hermes teams-pipeline listتأكد من تفعيل msgraph_webhook ومن أن الاشتراكات تشير إلى عنوان URL الصحيح للإشعارات
      لا ينجح أسلوب النص أولًا (transcript-first) أبدًاتحقّق من صلاحيات Graph لموارد النصوص، ومن وجود عنصر النص (transcript artifact) لذلك الاجتماع
      فشل الرجوع الاحتياطي إلى التسجيلتأكد من تثبيت ffmpeg ومن أن تطبيق Graph يستطيع الوصول إلى عناصر التسجيل
      فشل تسليم الملخّص إلى Teamsأعد التحقق من delivery_mode ومعرّفات الوجهات وإعدادات مصادقة Teams
