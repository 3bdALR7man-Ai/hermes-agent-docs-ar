      إعداد LINE

      شغّل Hermes Agent كبوت على LINE عبر LINE Messaging API الرسمية. يوجد المحوِّل (adapter) كإضافة منصة مضمّنة (bundled platform plugin) ضمن plugins/platforms/line/ — دون أي تعديل على النواة، ما عليك إلا تفعيله كأي منصة أخرى.

      LINE هو تطبيق المراسلة المهيمن في اليابان وتايوان وتايلاند. إذا كان مستخدموك يعيشون هناك، فهذه هي الوسيلة التي يصلون بها إليك.

      نفّذ hermes gateway setup واختر LINE للحصول على إعداد موجَّه خطوة بخطوة.

      كيف يستجيب البوت​

      السياقالسلوك
      محادثة فردية 1:1 (معرّفات U)يستجيب لكل رسالة
      محادثة جماعية (معرّفات C)يستجيب عندما تكون المجموعة ضمن قائمة السماح (allowlist)
      غرفة متعددة المستخدمين (معرّفات R)يستجيب عندما تكون الغرفة ضمن قائمة السماح

      يعالج المحوِّل جميع الرسائل الواردة من نصوص وصور وصوت وفيديو وملفات وملصقات ومواقع. أما النصوص الصادرة فتستخدم reply token المجاني أولًا (صالح لمرة واحدة، ضمن نافذة تقارب 60 ثانية)، وترجع احتياطيًا إلى Push API المدفوعة حسب الاستخدام عندما تنتهي صلاحية الـ token.

      الخطوة 1: أنشئ قناة LINE Messaging API​

      1. انتقل إلى LINE Developers Console.
      2. أنشئ Provider، ثم أنشئ تحته قناة Messaging API.
      3. من تبويب Basic settings في القناة، انسخ Channel secret.
      4. من تبويب Messaging API، مرّر إلى Channel access token (long-lived) وانقر Issue. انسخ الـ token.
      5. في تبويب Messaging API أيضًا، عطّل Auto-reply messages و Greeting messages حتى لا تتعارض مع ردود البوت.

      الخطوة 2: اكشف منفذ الـ webhook​

      يسلّم LINE الـ webhooks عبر HTTPS عام. المنفذ الافتراضي هو 8646 — يمكنك تغييره عبر LINE_PORT عند الحاجة.

      # Cloudflare Tunnel (recommended for production — fixed hostname)
      cloudflared tunnel --url http://localhost:8646

      # ngrok (good for dev)
      ngrok http 8646

      # devtunnel
      devtunnel create hermes-line --allow-anonymous
      devtunnel port create hermes-line -p 8646 --protocol https
      devtunnel host hermes-line

      انسخ عنوان https://... — إذ ستضبطه لاحقًا بوصفه URL الـ webhook. اترك النفق (tunnel) قيد التشغيل أثناء الاختبار. وفي بيئة الإنتاج، أعِدّ نفق Cloudflare مُسمّى وثابتًا كي لا يتغير URL الـ webhook عند إعادة التشغيل.

      الخطوة 3: اضبط Hermes​

      أضف إلى ~/.hermes/.env:

      LINE_CHANNEL_ACCESS_TOKEN=YOUR_LONG_LIVED_TOKEN
      LINE_CHANNEL_SECRET=YOUR_CHANNEL_SECRET

      # Allowlist — at least one of these (or LINE_ALLOW_ALL_USERS=true for dev)
      LINE_ALLOWED_USERS=U1234567890abcdef...           # comma-separated U-prefixed IDs
      LINE_ALLOWED_GROUPS=C1234567890abcdef...          # optional group IDs
      LINE_ALLOWED_ROOMS=R1234567890abcdef...           # optional room IDs

      # Required for image / audio / video sends — the public HTTPS base URL
      # the tunnel resolves to.  Without it, send_image/voice/video will refuse.
      LINE_PUBLIC_URL=https://my-tunnel.example.com

      ثم في ~/.hermes/config.yaml:

      gateway:
        platforms:
          line:
            enabled: true

      هذا كافٍ — إذ يلتقط فحص الإضافات المضمّنة في gateway/config.py المجلد plugins/platforms/line/ تلقائيًا. لا حاجة إلى تعديل enum Platform.LINE، ولا إلى تسجيل في _create_adapter.

      الخطوة 4: اضبط URL الـ webhook​

      عُد إلى وحدة تحكم LINE:

      1. افتح قناتك → تبويب Messaging API.
      2. ضمن Webhook settings → Webhook URL، الصق https://<your-tunnel>/line/webhook (انتبه إلى المسار /line/webhook — فالمحوِّل يستمع عليه).
      3. انقر Verify. سيرسل LINE طلب اختبار إلى الـ URL، ويُفترض أن ترى الاستجابة 200.
      4. بدّل Use webhook إلى On.

      الخطوة 5: شغّل الـ gateway​

      hermes gateway

      يُظهر سجل الوكيل:

      LINE: webhook listening on * (all interfaces, IPv4+IPv6):8646/line/webhook (public: https://my-tunnel.example.com)

      أضف البوت كصديق من تطبيق LINE (امسح رمز QR الموجود في تبويب Messaging API للقناة) وأرسل إليه رسالة.

      ردود LLM البطيئة​

      الـ reply token في LINE صالح لمرة واحدة وتنتهي صلاحيته بعد نحو 60 ثانية من الحدث الوارد. لا تستطيع نماذج LLM البطيئة الرد في الوقت المناسب، ما يفرض عادةً استدعاءً مدفوعًا لـ Push API.

      عندما يستمر الـ LLM في العمل لأكثر من LINE_SLOW_RESPONSE_THRESHOLD ثانية (الافتراضي 45)، يستهلك المحوِّل الـ reply token الأصلي لإرسال فقاعة Template Buttons:

      🤔 Still thinking. Tap below to fetch the answer when it's ready.

      [ Get answer ]

      ينقر المستخدم Get answer متى شاء — فيسلّم ذلك الـ postback reply token جديدًا، يستخدمه المحوِّل لإرسال الإجابة المخزّنة مؤقتًا (مجانًا أيضًا).

      آلة الحالات: PENDING → READY → DELIVERED، إضافة إلى ERROR للتشغيلات الملغاة (تتحول حالة PENDING اليتيمة إلى "Run was interrupted before completion." بعد /stop كي لا يدخل الزر الدائم في حلقة).

      لتعطيل زر الـ postback والرجوع احتياطيًا إلى Push دائمًا بدلًا منه:

      LINE_SLOW_RESPONSE_THRESHOLD=0

      لكي يعمل تدفق الـ postback بشكل موثوق، أوقف الرسائل الجانبية التي قد تستهلك الـ reply token قبل بلوغ الحد:

      # ~/.hermes/config.yaml
      display:
        interim_assistant_messages: false
        platforms:
          line:
            tool_progress: off

      تسليم Cron والإشعارات​

      LINE_HOME_CHANNEL=Uxxxxxxxxxxxxxxxxxxxx     # default delivery target

      تُوجَّه مهام cron التي تحمل deliver: line إلى LINE_HOME_CHANNEL. يأتي المحوِّل مع مُرسِل مستقل يعتمد على Push فقط، كي تعمل مهام cron حتى عندما يعمل cron في عملية منفصلة عن الـ gateway.

      مرجع متغيرات البيئة​

      المتغيرمطلوبالقيمة الافتراضيةالوصف
      LINE_CHANNEL_ACCESS_TOKENنعم—channel access token طويل الأمد
      LINE_CHANNEL_SECRETنعم—سرّ القناة (للتحقق من الـ webhook عبر HMAC-SHA256)
      LINE_HOSTلاغير مضبوط (dual-stack: جميع الواجهات، IPv4+IPv6)المضيف الذي يرتبط به الـ webhook
      LINE_PORTلا8646المنفذ الذي يرتبط به الـ webhook
      LINE_PUBLIC_URLللوسائط—URL أساسي عام عبر HTTPS؛ مطلوب لإرسال الصور والصوت والفيديو
      LINE_ALLOWED_USERSأحدها—معرّفات مستخدمين مفصولة بفواصل (تبدأ بـ U)
      LINE_ALLOWED_GROUPSأحدها—معرّفات مجموعات مفصولة بفواصل (تبدأ بـ C)
      LINE_ALLOWED_ROOMSأحدها—معرّفات غرف مفصولة بفواصل (تبدأ بـ R)
      LINE_ALLOW_ALL_USERSللتطوير فقطfalseتجاوز قائمة السماح كليًا

      LINE_PENDING_TEXTلا"🤔 Still thinking…"نص الفقاعة المعروض بجانب زر الـ postback
      LINE_BUTTON_LABELلا"Get answer"تسمية الزر
      LINE_DELIVERED_TEXTلا"Already replied ✅"الرد عند النقر مجددًا على زر سبق تسليم إجابته
      LINE_INTERRUPTED_TEXTلا"Run was interrupted before completion."الرد عند النقر على زر يتيم بسبب /stop
      LINE_EXPIRED_TEXTلا"That request has expired — send your message again."الرد عند النقر على زر لم تعد إجابته المخزّنة مؤقتًا متوفرة

      استكشاف الأخطاء وإصلاحها​

      ظهور "invalid signature" عند التحقق من الـ webhook. نُسخ Channel secret بشكل خاطئ، أو أعاد النفق كتابة جسم الطلب. تحقّق أولًا باستخدام curl -i https://<tunnel>/line/webhook/health — يُفترض أن يعيد {"status":"ok","platform":"line"}.

      لا يستقبل البوت أي شيء في المجموعات. تحقّق من أن LINE_ALLOWED_GROUPS يتضمن معرّف المجموعة C.... لمعرفة معرّف مجموعة، أرسل رسالة تجريبية وابحث باستخدام grep في ~/.hermes/logs/gateway.log عن LINE: rejecting unauthorized source — يحتوي قاموس المصدر المرفوض على المعرّفات.

      فشل send_image مع الرسالة "LINE_PUBLIC_URL must be set". لا تقبل LINE Messaging API رفع البيانات الثنائية — يجب أن تكون الصور والصوت والفيديو عناوين HTTPS يمكن الوصول إليها. اضبط LINE_PUBLIC_URL على اسم المضيف العام للنفق، وسيقدّم المحوِّل الملفات من /line/media/<token>/<filename> تلقائيًا.

      زر الـ postback لا يظهر أبدًا. إما أن الـ LLM استجاب أسرع من LINE_SLOW_RESPONSE_THRESHOLD، أو أن فقاعة أخرى (تقدّم الأدوات، البث المتدفق) استهلكت الـ reply token أولًا. راجع كتلة الإيقاف في قسم "ردود LLM البطيئة".

      ظهور "already in use by another profile". channel access token نفسه مرتبط بـ profile آخر من Hermes قيد التشغيل. أوقف الـ gateway الآخر أو استخدم قناة منفصلة.

      القيود​

      • حدود الفقاعات والطول. الحد الأقصى لكل فقاعة نصية في LINE هو 5000 حرف. تُقسَّم الردود الأطول بذكاء إلى أجزاء بنحو 4500 حرف على ما يصل إلى 5 فقاعات لكل استدعاء Reply/Push، مع التقسيم عند الحدود الطبيعية للنص قدر الإمكان.
      • لا يوجد تحرير أصلي للرسائل. لا تملك LINE واجهة API لتحرير الرسائل — لذا ترسل الردود المتدفقة دائمًا فقاعات جديدة، ولا تحرّر الفقاعات السابقة أبدًا.
      • لا يوجد عرض لـ Markdown. يظهر الخط العريض (**) والمائل (*) وأسوار الشيفرة (code fences) والعناوين كأحرف حرفية. يزيلها المحوِّل قبل الإرسال، مع الحفاظ على عناوين URL (يصبح [label](url) بالشكل label (url)).
      • مؤشر التحميل متاح في المحادثات المباشرة فقط. ترفض LINE واجهة chat/loading API للمجموعات والغرف، لذا لا يظهر مؤشر الكتابة إلا في المحادثات الفردية 1:1.
