      1Password

      احصل على قيم مفاتيح API الخاصة بالمزوّدين من 1Password عند بدء تشغيل العملية بدلًا من تخزينها كنص صريح داخل ~/.hermes/.env. تحتفظ بمفاتيحك كعناصر (items) في 1Password وتشير إليها عبر op://vault/item/field؛ فيصبح تدوير (rotation) أي بيانات اعتماد مجرد تغيير واحد في 1Password.

      آلية العمل​

      1. تثبّت 1Password CLI الرسمية (op) وتصادق عليها — إما باستخدام token حساب خدمة (service-account token) (للخوادم التي تعمل دون واجهة) أو عبر جلسة تفاعلية/جلسة تطبيق سطح المكتب (على حاسوبك المحمول).
      2. تربط أسماء متغيرات البيئة بمراجع op:// في ~/.hermes/config.yaml.
      3. في كل مرة يبدأ فيها hermes (أو الـ gateway، أو مهمة cron)، وبعد تحميل ~/.hermes/.env، ينفّذ Hermes الأمر op read لكل مرجع ويضع القيم الناتجة في os.environ.
      4. افتراضيًا، يستبدل Hermes القيم الموجودة مسبقًا في بيئتك، فيكون 1Password هو مصدر الحقيقة — دوّر بيانات الاعتماد مرة واحدة وستلتقطها كل عمليات Hermes عند بدء تشغيلها التالي. اضبط override_existing: false إن أردت أن تكون الأولوية لـ .env بدلًا من ذلك.

      لا يصادق Hermes أبدًا نيابةً عنك ولا يُنزّل op أبدًا: بل يستدعي عبر الـ shell أداة CLI المثبّتة والموثوقة لديك مسبقًا. إذا كانت op غير موجودة، أو كانت جلستك مقفلة، أو كان أحد المراجع خاطئًا، يطبع Hermes تحذيرًا من سطر واحد ويواصل العمل بأي بيانات اعتماد موجودة مسبقًا في .env — فهو لا يعطّل بدء التشغيل أبدًا.

      المصادقة​

      تدعم op وضعين يناسبان التشغيل غير التفاعلي؛ ويعمل Hermes مع أيٍّ منهما:

      • حسابات الخدمة (Service accounts) (موصى بها للخوادم و CI): أنشئ حساب خدمة في 1Password، وامنحه صلاحية القراءة على الخزنة (vault) المعنية، وصدّر الـ token الخاص به باسم OP_SERVICE_ACCOUNT_TOKEN في ~/.hermes/.env. الـ token هو بيانات الاعتماد نفسها — فتعامل معه كأي bearer token آخر.
      • جلسات سطح المكتب / الجلسات التفاعلية (للحواسيب المحمولة): شغّل op signin (أو فعّل تكامل CLI في تطبيق 1Password). يمرّر Hermes متغيرات OP_SESSION_* الخاصة بك إلى العملية الفرعية op. ويتضمن مفتاح الـ cache الخاص بـ 1Password متغيرات الجلسة تلك، لذا فإن تسجيل الدخول بحساب مختلف لا يُعيد أبدًا قيمة مخزّنة مؤقتًا تحت الهوية السابقة.

      الـ token التمهيدي (Bootstrap token)​

      عندما تصادق باستخدام token حساب خدمة، يكون ذلك الـ token بحد ذاته بيانات الاعتماد التمهيدية التي يحتاجها Hermes قبل أن يتمكن من حلّ أي مرجع op://. ويجب أن يكون موجودًا في os.environ لكل عملية تحلّ الأسرار — بما في ذلك مهام cron (kanban.dispatch_in_gateway: false)، واستدعاءات العمليات الفرعية، وتشغيلات CLI، ووكلاء launchd على macOS، وحاويات Docker — وليس فقط الـ gateway التفاعلي. هناك ثلاث طرق لإتاحته، مرتبة حسب الأولوية:

      1. في ~/.hermes/.env (موصى به). يكتب hermes secrets onepassword setup --token <token> الـ token إلى ~/.hermes/.env، تمامًا مثل BWS_ACCESS_TOKEN في Bitwarden. ولأن load_hermes_dotenv() يحمّل .env دائمًا، يصبح الـ token متاحًا في كل مكان دون أي إعداد إضافي. وهذا هو الخيار الموثوق الأبسط.

      2. في ~/.hermes/.op.env (مُستثنى في gitignore). إن كنت تفضّل إبقاء token حساب الخدمة خارج .env — مثلًا كي يمكن إيداع .env في مستودع dotfiles خاص بينما يبقى الـ token خارج نظام التحكم في الإصدارات — فضعه في ~/.hermes/.op.env:

        echo 'OP_SERVICE_ACCOUNT_TOKEN=ops_...' > ~/.hermes/.op.env
        chmod 600 ~/.hermes/.op.env

        يحمّل Hermes الملف .op.env تلقائيًا عند بدء التشغيل، بعد .env، ولا يستبدل أبدًا token موجودًا مسبقًا في البيئة. والملف .op.env مُستثنى في gitignore، لذا لا يدخل الـ token أبدًا في ملف مُودَع (committed).

      3. عبر EnvironmentFile في systemd (لـ gateway على Linux). إذا كنت تشغّل الـ gateway تحت systemd، فيمكنك حقن الـ token مباشرةً في بيئة الخدمة:

        [Service]
        EnvironmentFile=-/home/youruser/.hermes/.op.env

        تكون الأولوية للـ token المحقون بهذه الطريقة — إذ يكتشف Hermes أن OP_SERVICE_ACCOUNT_TOKEN مضبوط مسبقًا فيتخطى تحميل .op.env كليًا.

      إذا كان الوصول إلى الـ token ممكنًا فقط عبر shell تفاعلي (op signin، أو تصدير OP_SESSION_* في .bashrc، وما إلى ذلك)، فلن ترثه مهام cron أو العمليات الفرعية المُنشأة حديثًا، وستسجّل تلك السياقات تحذيرًا وتعود إلى أي بيانات اعتماد كانت موجودة مسبقًا في .env. استخدم أحد الخيارات الثلاثة أعلاه لأي عبء عمل غير تفاعلي.

      الإعداد​

      1. ثبّت op وسجّل الدخول إليها​

      اتبع دليل البدء مع 1Password CLI. ثم تحقّق من أنها تعمل:

      op whoami

      2. فعّل التكامل​

      hermes secrets onepassword setup

      يتحقق هذا الأمر من وجود op في PATH (أو استخدم --binary-path)، ويسجّل إعدادات الحساب/الـ token، ويتحقق من وجود جلسة نشطة، ثم يضبط secrets.onepassword.enabled: true. الخيارات (flags) غير التفاعلية:

      hermes secrets onepassword setup \
        --account my.1password.com \
        --token-env OP_SERVICE_ACCOUNT_TOKEN \
        --token "$OP_SERVICE_ACCOUNT_TOKEN"

      3. اربط بيانات الاعتماد​

      صيغة المرجع هي op://<vault>/<item>/<field>:

      hermes secrets onepassword set OPENAI_API_KEY    "op://Private/OpenAI/api key"
      hermes secrets onepassword set ANTHROPIC_API_KEY "op://Private/Anthropic/credential"

      4. عاين النتيجة وتحقّق منها​

      hermes secrets onepassword sync     # dry-run: resolve now, show what would apply
      hermes secrets onepassword status   # config + binary + references + auth

      من الآن فصاعدًا، يحلّ كل استدعاء لـ hermes المراجع عند بدء التشغيل. وسترى ملخصًا من سطر واحد في stderr في أول مرة تُطبَّق فيها الأسرار داخل عملية ما.

      الإعدادات​

      القيم الافتراضية في ~/.hermes/config.yaml:

      secrets:
        onepassword:
          enabled: false
          env:
            OPENAI_API_KEY: "op://Private/OpenAI/api key"
            ANTHROPIC_API_KEY: "op://Private/Anthropic/credential"
          account: ""
          service_account_token_env: OP_SERVICE_ACCOUNT_TOKEN
          binary_path: ""
          cache_ttl_seconds: 300
          override_existing: true
      المفتاحالقيمة الافتراضيةوظيفته
      enabledfalseالمفتاح الرئيسي. عند ضبطه على false لا تُستدعى op إطلاقًا.
      env{}ربط اسم متغير البيئة → مرجع op://vault/item/field. تُتخطى مع تحذير الإدخالات التي لا يكون اسمها اسم متغير بيئة صالحًا، أو لا تكون قيمتها مرجع op://.
      account""الاسم المختصر للحساب / عنوان تسجيل الدخول، ويُمرَّر كـ op read --account. القيمة الفارغة تعني استخدام الحساب الافتراضي لـ op.
      service_account_token_envOP_SERVICE_ACCOUNT_TOKENمتغير البيئة الذي يقرأ منه Hermes token حساب الخدمة. تُصدَّر قيمته إلى العملية الفرعية op باسم OP_SERVICE_ACCOUNT_TOKEN (وهو الاسم الذي تتوقعه op). اترك المتغير غير مضبوط لاستخدام جلسة سطح المكتب/الجلسة التفاعلية.
      binary_path""المسار المطلق إلى op. عند ضبطه يُستخدم كما هو حرفيًا وPATH لا يُستشار — ثبّت هذه القيمة لتتجنب الوثوق بأي op يظهر أولًا في PATH.
      cache_ttl_seconds300المدة التي يُعاد خلالها استخدام القيم المحلولة (في ذاكرة العملية وعلى القرص). اضبطه على 0 لتعطيل طبقتي الـ cache كلتيهما — فلا تُكتب أي قيم على القرص إطلاقًا.
      override_existingtrueعند ضبطه على true، تستبدل القيم المحلولة أي قيمة موجودة مسبقًا في البيئة (كي يسري التدوير). اضبطه على false لتكون الأولوية لـ .env / متغيرات الـ shell المُصدَّرة؛ وعندها تُتخطى تلك المراجع قبل استدعاء op.

      حالات الإخفاق​

      لا يعطّل 1Password بدء تشغيل Hermes أبدًا. إذا حدث أي خطأ فسترى تحذيرًا من سطر واحد في stderr ويواصل Hermes العمل:

      العَرَضالسببالحل
      the op CLI was not found on PATHop غير مثبّتة / غير موجودة في PATHثبّت CLI، أو اضبط secrets.onepassword.binary_path
      op read failed for 'op://…': …جلسة مقفلة، أو token منتهي الصلاحية، أو عدم وجود صلاحية وصول إلى الخزنةنفّذ op signin، أو شغّل hermes secrets onepassword token لتدوير token حساب الخدمة، أو امنح حساب الخدمة صلاحية الوصول
      op read returned an empty value for 'op://…'الحقل المشار إليه موجود لكنه فارغأصلح العنصر/الحقل في 1Password (لا تُطبَّق القيمة الفارغة أبدًا — ويبقى متغير البيئة الحالي لديك سليمًا)
      … is not an op:// secret referenceقيمة أحد الروابط ليست مرجع op://أعد ضبطها بالصيغة الصحيحة op://vault/item/field
      op read timed outالشبكة محجوبة أو 1Password بطيءتحقّق من الاتصال / من تكامل تطبيق سطح المكتب

      تتضمن تحذيرات بدء التشغيل الآن سطر معالجة يبدأ بـ → يخبرك بالضبط بالأمر الذي يصلح الإخفاق.

      التخزين المؤقت (Caching)​

      تُخزَّن عمليات السحب الناجحة والمكتملة مؤقتًا في ذاكرة العملية وعلى القرص في <hermes_home>/cache/op_cache.json (تُكتب بشكل ذرّي، وبصلاحيات 0600)، كي لا تعيد استدعاءات hermes القصيرة المتتالية تشغيل op لكل مرجع. وهذا الـ cache:

      • يخزّن قيم الأسرار المحلولة فقط — ولا يخزّن أبدًا token حساب الخدمة أو أي مواد مصادقة خام (إذ تُضمَّن بصمة المصادقة في مفتاح الـ cache)؛
      • يُبطَل عند تغيّر الـ token، أو الحساب، أو متغيرات OP_SESSION_*، أو مجموعة المراجع؛
      • لا يُكتب إذا واجهت عملية السحب أي خطأ في أحد المراجع، كي لا يُجمَّد إخفاق مصادقة عابر طوال مدة الـ TTL؛
      • يُعطَّل بالكامل — القراءة والكتابة — عند ضبط cache_ttl_seconds: 0.

      ملاحظات أمنية​

      • يستطيع token حساب الخدمة في 1Password قراءة كل سرّ يملك الحساب صلاحية الوصول إليه. خزّنه في ~/.hermes/.env (وليس في config.yaml)، وألغِه ثم أعد توليده من 1Password إذا تسرّب.
      • يرفض Hermes السماح لأي قيمة محلولة باستبدال متغير بيئة الـ token نفسه، حتى مع override_existing: true.
      • تحصل العملية الفرعية op على بيئة مصغّرة تقتصر على قائمة سماح (متغيرات المصادقة/الجلسة + PATH/HOME)، لا على نسخة من os.environ كاملًا، لذا لا ترث العملية الفرعية كل بيانات اعتماد المزوّدين المحمّلة بعد dotenv.
      • يُتحقَّق من أن المراجع تبدأ بـ op://، ويُمرَّر المرجع بعد فاصل الخيارات -- كي لا تُفسَّر قيمة مصمّمة بخبث على أنها خيار (flag) لـ op.

      متى لا تستخدم هذه الميزة​

      • الإعدادات الشخصية على جهاز واحد حيث يكفي ~/.hermes/.env.
      • البيئات المعزولة عن الشبكة (air-gapped) التي لا تستطيع الوصول إلى 1Password.
      • CI/CD حيث تكون هناك آلية قائمة لحقن الأسرار موصولة بالفعل — اختر مسارًا واحدًا لا مسارين.

      الحالة المناسبة لهذه الميزة هي أساطيل الأجهزة المتعددة، وأجهزة التطوير المشتركة، وخوادم VPS الخاصة بالـ gateway، أو أي مكان تريد فيه تدويرًا وإلغاءً مركزيين عبر عدة تثبيتات لـ Hermes.
