      TUI

      واجهة TUI هي الواجهة الأمامية الحديثة لـ Hermes — واجهة مستخدم طرفية تعمل فوق بيئة تشغيل Python نفسها التي تعتمد عليها واجهة CLI الكلاسيكية. الوكيل نفسه، والجلسات نفسها، والـ slash commands نفسها؛ لكن بواجهة أنظف وأسرع استجابةً للتفاعل معها.

      وهي الطريقة الموصى بها لتشغيل Hermes تفاعليًا.

      التشغيل​

      # Launch the TUI
      hermes --tui

      # Resume the latest TUI session (falls back to the latest classic session)
      hermes --tui -c
      hermes --tui --continue
      hermes --tui --resume latest

      # Resume a specific session by ID or title
      hermes --tui -r 20260409_000000_aa11bb
      hermes --tui --resume "my t0p session"

      # Resume the latest session for a specific project directory
      hermes --tui --resume latest --in ./my-project

      # Run source directly — skips the prebuild step (for TUI contributors)
      hermes --tui --dev

      يمكنك أيضًا تفعيلها عبر متغير بيئة (environment variable):

      export HERMES_TUI=1
      hermes          # now uses the TUI
      hermes chat     # same

      أو اجعلها الواجهة الافتراضية الدائمة في ~/.hermes/config.yaml:

      display:
        interface: tui   # "cli" (default) or "tui"

      مع display.interface: tui، يؤدي تشغيل الأمر hermes وحده (وكذلك hermes chat) إلى فتح TUI. والخيارات (flags) الصريحة لها الأولوية دائمًا — نفّذ hermes --cli للعودة إلى الـ REPL الكلاسيكي في استدعاء واحد، أو hermes --tui / HERMES_TUI=1 لفرض TUI عندما تكون القيمة الافتراضية في الإعدادات هي cli.

      تظل واجهة CLI الكلاسيكية هي الافتراضية عند التثبيت. وكل ما هو موثّق في واجهة CLI — الـ slash commands، والأوامر السريعة، والتحميل المسبق للمهارات، والشخصيات، والإدخال متعدد الأسطر، والمقاطعات — يعمل في TUI بالطريقة نفسها تمامًا.

      لماذا TUI​

      • إطار أول فوري — تُرسم اللافتة (banner) قبل أن ينتهي التطبيق من التحميل، فلا تبدو الطرفية متجمدة أبدًا أثناء بدء تشغيل Hermes.
      • إدخال غير حاجب — اكتب الرسائل وضعها في قائمة الانتظار قبل أن تصبح الجلسة جاهزة. يُرسَل أول prompt لديك لحظة اتصال الوكيل.
      • نوافذ منبثقة غنية — منتقي النموذج، ومنتقي الجلسات، وطلبات الموافقة والاستيضاح، كلها تُعرض كلوحات منبثقة (modal) بدلًا من تدفقات مضمّنة في السطر.
      • لوحة جلسة حيّة — تظهر الأدوات والمهارات تدريجيًا كلما اكتملت تهيئتها.
      • تحديد سهل بالفأرة — اسحب لتمييز النص بخلفية موحّدة بدلًا من عكس الألوان بـ SGR. انسخ بطريقة النسخ المعتادة في طرفيتك.
      • العرض على الشاشة البديلة (alternate screen) — التحديثات التفاضلية تعني عدم وجود وميض أثناء البث، وعدم تكدّس سجل التمرير بعد الخروج.
      • تسهيلات في مربع الكتابة — طيّ النصوص الطويلة الملصقة داخل السطر، ولصق النص بـ Cmd+V / Ctrl+V مع الرجوع إلى صورة الحافظة احتياطيًا، وحماية اللصق المحاط (bracketed paste)، وتوحيد صيغة مرفقات الصور ومسارات الملفات.

      تنطبق المظاهر (skins) والشخصيات نفسها. بدّل بينها في منتصف الجلسة باستخدام /skin ares و/personality pirate، وستُعاد رسم الواجهة مباشرةً. راجع المظاهر والسمات (Skins & Themes) للاطلاع على القائمة الكاملة للمفاتيح القابلة للتخصيص وأيها ينطبق على الواجهة الكلاسيكية مقابل TUI — إذ تلتزم TUI بلوحة ألوان اللافتة، وألوان الواجهة، ورمز الـ prompt ولونه، وعرض الجلسة، وقائمة الإكمال، وخلفية التحديد، وtool_prefix، وhelp_header.

      أقسام اللافتة القابلة للطي​

      تجمع لافتة بدء تشغيل TUI معلومات وقت التشغيل في أربعة أقسام قابلة للطي، يُعرض كل منها مع سهم ▸ / ▾ بجوار عنوان القسم:

      القسمالحالة الافتراضية
      Toolsمفتوح
      Skillsمطويّ
      System Promptمطويّ
      MCP Serversمطويّ

      انقر في أي مكان على ترويسة القسم (أو على سهمه) لتبديل حالته. تُفتح قائمة Tools افتراضيًا لأنها القسم الأكثر تفقدًا عند بدء الجلسة؛ أما Skills و System Prompt و MCP Servers فتُطوى افتراضيًا كي تبقى اللافتة مدمجة حتى لو ثبّتّ عشرات المهارات أو ربطت العديد من خوادم MCP. الحالة محلية لنسخة اللافتة الحالية، لذا تعود إلى القيم الافتراضية في التشغيل التالي.

      المتطلبات​

      • Node.js ≥ 20 — تعمل TUI كعملية فرعية (subprocess) تُطلق من واجهة CLI المكتوبة بـ Python. ويتحقق hermes doctor من ذلك.
      • TTY — كما في واجهة CLI الكلاسيكية، يؤدي تمرير stdin عبر pipe أو التشغيل في بيئات غير تفاعلية إلى الرجوع إلى وضع الاستعلام الواحد.

      عند التشغيل الأول، يثبّت Hermes اعتماديات Node الخاصة بـ TUI في ui-tui/node_modules (مرة واحدة فقط، وتستغرق بضع ثوانٍ). وتكون مرات التشغيل اللاحقة سريعة. وإذا سحبت إصدارًا جديدًا من Hermes، تُعاد بناء حزمة TUI تلقائيًا عندما تكون ملفات المصدر أحدث من مجلد dist.

      تعمل عبر عدة git worktrees؟

      يمكن للمساهمين الذين يشغّلون hermes --tui --dev من عدة worktrees مشاركة مجلد node_modules واحد بدلًا من التثبيت لكل نسخة مسحوبة (checkout) — راجع تطوير TUI و Desktop من Worktrees.

      حزمة مبنية مسبقًا من الخارج​

      يمكن للتوزيعات التي تشحن حزمة مبنية مسبقًا (Nix، وحزم النظام) أن توجّه Hermes إليها:

      export HERMES_TUI_DIR=/path/to/prebuilt/ui-tui
      hermes --tui

      يجب أن يحتوي المجلد على dist/entry.js.

      اختصارات لوحة المفاتيح​

      تتطابق اختصارات لوحة المفاتيح تمامًا مع واجهة CLI الكلاسيكية. والاختلافات الوحيدة في السلوك هي:

      • Ctrl+T يوسّع شريط الـ subagents الحيّة التلقائي إلى قائمة /agents بكامل الارتفاع. اختر عاملًا واضغط Enter (أو t) لعرض سجله الحيّ، أو d للتفاصيل الكاملة، أو e لتوجيهه، أو x لإيقافه. يضبط الشريط عدد صفوفه وفق ارتفاع الطرفية ويحافظ على مسودتك في مربع الكتابة. راجع مراقبة الـ subagents.
      • F7 يبدّل الشريط الحيّ بين معاينته الافتراضية وسطر ملخص واحد. لا يفتح ذلك شاشة المراقبة ولا ينقل التركيز من مربع الكتابة؛ ويبقى الاختيار سارياً طوال عملية TUI الحالية دون تغيير الإعدادات.
      • السحب بالفأرة يميّز النص بخلفية تحديد موحّدة.
      • Cmd+V / Ctrl+V يحاول أولًا لصق النص العادي، ثم يرجع إلى قراءة الحافظة عبر OSC52 أو الحافظة الأصلية للنظام، وأخيرًا إرفاق صورة عندما تكون محتويات الحافظة أو البيانات الملصقة صورة.
      • /terminal-setup يثبّت اختصارات طرفية محلية لـ VS Code / Cursor / Windsurf لتحسين التوافق في Cmd+Enter والتراجع/الإعادة على macOS.
      • الإكمال التلقائي للأوامر يُفتح كلوحة عائمة مع أوصاف، لا كقائمة منسدلة داخل السطر.
      • Ctrl+X يفتح مبدّل الجلسات الحيّة. وعندما تكون رسالة في قائمة الانتظار مميّزة (أُرسلت بينما كان الوكيل لا يزال يعمل)، فإنه يحذف تلك الرسالة بدلًا من ذلك. أما Esc فيلغي التحرير ويزيل التمييز دون حذف.
      • Ctrl+G / Ctrl+X Ctrl+E — يفتح محتوى الإدخال الحالي في $EDITOR لكتابة نصوص متعددة الأسطر أو prompts طويلة؛ وعند الحفظ والخروج يُرسَل المحتوى بوصفه الـ prompt.

      Slash commands​

      تعمل جميع الـ slash commands دون تغيير. وبعضها خاص بـ TUI — إذ ينتج مخرجات أغنى أو يُعرض كنوافذ منبثقة بدلًا من لوحات داخل السطر:

      الأمرالسلوك في TUI
      /helpنافذة منبثقة بأوامر مصنّفة، يمكن التنقل فيها بمفاتيح الأسهم
      /sessions (الاسم البديل /switch)مبدّل الجلسات الحيّة — يعرض جلسات TUI المفتوحة، ويتيح التبديل بينها، أو إغلاقها، أو بدء جلسة أخرى
      /modelمنتقي نموذج منبثق مجمّع حسب المزوّد، مع تلميحات عن التكلفة
      /skinمعاينة حيّة — يُطبَّق تغيير السمة أثناء التصفح
      /detailsتبديل عرض التفاصيل المطوّلة لاستدعاءات الأدوات (على المستوى العام أو لكل قسم)
      /usageلوحة غنية بالـ tokens والتكلفة والسياق
      /agents (الاسم البديل /tasks)نافذة مراقبة — شجرة حيّة للـ subagents مع أدوات الإنهاء/الإيقاف المؤقت، وتجميعات للتكلفة والـ tokens والملفات لكل فرع، وسجل دورًا بدور
      /reloadيعيد قراءة ~/.hermes/.env داخل عملية TUI الجارية، فتسري مفاتيح API المضافة حديثًا دون إعادة التشغيل
      /mouse [on|off|toggle|wheel|buttons|all]اختر إعدادًا مسبقًا لتتبّع الفأرة أثناء التشغيل (ويُحفظ أيضًا في display.mouse_tracking ضمن config.yaml). يحافظ wheel (1000+1006) على التمرير بعجلة الفأرة دون أحداث التمرير فوق العناصر (hover) التي تجعل tmux يغرق سطر الـ prompt برسالة "No image in clipboard"؛ ويضيف buttons التحديد بالسحب؛ أما all فهو الافتراضي مع واجهة تستجيب للتمرير فوق العناصر.

      كل الـ slash commands الأخرى (بما فيها المهارات المثبّتة، والأوامر السريعة، ومبدّلات الشخصية) تعمل تمامًا كما في واجهة CLI الكلاسيكية. راجع مرجع Slash Commands.

      مبدّل الجلسات الحيّة​

      استخدم مبدّل الجلسات الحيّة عندما تريد أن تعمل طرفية واحدة كموزّع لعدة جلسات TUI. لا يعرض إلا الجلسات الحيّة حاليًا في عملية TUI هذه؛ أما الجلسات المغلقة فتبقى سجلات محفوظة ويمكن إعادة فتحها باستخدام /resume أو hermes --tui --resume <id-or-title>.

      افتحه بأي من الطرق التالية:

      • Ctrl+X من داخل TUI.
      • /sessions أو /switch.
      • /sessions new لإنشاء جلسة حيّة جديدة فورًا.
      • انقر على عدّاد N live sessions في سطر الحالة.

      داخل المبدّل:

      • ↑ / ↓ لتحريك التحديد؛ ويمكن أيضًا تحديد الصفوف بالنقر بالفأرة.
      • Enter للتبديل إلى الجلسة الحيّة المحددة.
      • Ctrl+D لإغلاق الجلسة الحيّة المحددة.
      • Ctrl+N لبدء جلسة حيّة فارغة.
      • Ctrl+R لتحديث قائمة الجلسات الحيّة.
      • Esc لإغلاق المبدّل.
      • اختر +new، واكتب prompt، ثم اضغط Enter لإطلاق جلسة حيّة جديدة. اضغط Tab أولًا إذا أردت اختيار نموذج لتلك الجلسة الجديدة وحدها.

      عرض معادلات LaTeX​

      يعرض pipeline الخاص بـ markdown في TUI معادلات LaTeX داخل النص: إذ تُعرض $E = mc^2$ و$$\frac{a}{b}$$ كرياضيات منسّقة بـ Unicode بدلًا من مصدر TeX الخام. يعمل ذلك مع المعادلات المضمّنة في السطر والمعادلات الكتلية؛ أما الصيغ غير المدعومة فتُعرض كنص TeX حرفي داخل مقطع كود ليبقى قابلًا للنسخ.

      هذه الميزة مفعّلة دائمًا — لا شيء يحتاج إلى ضبط. أما واجهة CLI الكلاسيكية فتُبقي على TeX الخام.

      اكتشاف الطرفيات الفاتحة​

      تكتشف TUI الطرفيات ذات الخلفية الفاتحة تلقائيًا وتنتقل إلى السمة الفاتحة وفقًا لذلك. يعمل الاكتشاف على ثلاث طبقات:

      1. متغير البيئة HERMES_TUI_THEME — الأولوية القصوى. القيم: light، أو dark، أو قيمة hex خام من 6 أحرف للون الخلفية (مثل ffffff، 1a1a2e).
      2. متغير البيئة COLORFGBG — التلميح الكلاسيكي "ما لون خلفيتي؟" الذي تستخدمه الطرفيات المشتقة من xterm.
      3. فحص خلفية الطرفية عبر OSC 11 — يعمل على الطرفيات الحديثة (Ghostty، Warp، iTerm2، WezTerm، Kitty) التي لا تضبط COLORFGBG.

      إذا أردت السمة الفاتحة بشكل دائم بغض النظر عن الطرفية:

      export HERMES_TUI_THEME=light

      أنماط مؤشر الانشغال​

      مؤشر الانشغال في شريط الحالة قابل للتبديل — إذ يدوّر النمط الافتراضي مجموعة وجوه kawaii الخاصة بـ Hermes كل 2.5 ثانية أثناء عمل الوكيل. اختر نمطًا مختلفًا عبر الإعدادات أو الـ slash command /indicator:

      display:
        tui_status_indicator: kaomoji   # kaomoji | emoji | unicode | ascii

      أو من داخل الجلسة: /indicator emoji (وهكذا). تأتي الأنماط برموز متساوية العرض حتى لا يهتز باقي شريط الحالة عند التدوير.

      الاستئناف التلقائي​

      افتراضيًا، يبدأ hermes --tui جلسة جديدة في كل تشغيل. لإعادة الاتصال تلقائيًا بأحدث جلسة TUI (وهو مفيد عند انقطاع الطرفية أو اتصال SSH بشكل غير متوقع)، فعّل الخيار التالي:

      export HERMES_TUI_RESUME=1          # most-recent TUI session
      # or:
      export HERMES_TUI_RESUME=<session-id>   # specific session

      ألغِ ضبط المتغير أو مرّر --resume <id> صراحةً لتجاوز ذلك في كل تشغيل على حدة.

      سطر الحالة​

      يتتبّع سطر الحالة في TUI حالة الوكيل لحظة بلحظة:

      بعد تسمية الجلسة، يظهر عنوانها كشارة بلون مميّز عند الطرف الأيمن الأقصى من سطر الحالة. يحلّ العنوان محل تسمية مساحة العمل ويُقتطع في الطرفيات الضيقة.

      الحالةالمعنى
      starting agent…معرّف الجلسة نشط؛ والأدوات والمهارات لا تزال قيد التهيئة. يمكنك الكتابة — إذ تُوضع الرسائل في قائمة الانتظار وتُرسل عند الجاهزية.
      readyالوكيل خامل ويستقبل الإدخال.
      thinking… / running…الوكيل يفكّر أو يشغّل أداة.
      interruptedأُلغي الدور الحالي؛ اضغط Enter لإرساله مجددًا.
      forging session… / resuming…الاتصال الأولي أو مصافحة --resume.

      ألوان شريط الحالة وعتباته الخاصة بكل مظهر مشتركة مع واجهة CLI الكلاسيكية — راجع المظاهر (Skins) للتخصيص.

      يعرض سطر الحالة أيضًا:

      • مجلد العمل مع git branch — ~/projects/hermes-agent (docs/two-week-gap-sweep). تتحدّث لاحقة الـ branch عند تنفيذ git checkout في طرفية جانبية (مع تخزين مؤقت يعتمد على mtime)، بحيث تعكس TUI الـ branch النشط فعليًا، لا الـ branch الذي كان نشطًا عند التشغيل.
      • الوقت المنقضي لكل prompt — ⏱ 12s/3m 45s أثناء تنفيذ الدور (مباشرةً)، ويتجمّد على ⏲ 32s / 3m 45s بعد اكتمال الدور. الرقم الأول هو الوقت منذ آخر رسالة من المستخدم؛ والثاني هو المدة الإجمالية للجلسة. يُعاد ضبطه مع كل prompt جديد.
      • 🗜️ N — عدد مرات الضغط التلقائي للجلسة الجارية. يظهر بمجرد حدوث أول عملية ضغط.
      • ▶ N — عدد مهام /bg الجارية حاليًا في هذه الجلسة. يظهر كلما كانت هناك مهمة واحدة على الأقل قيد التنفيذ.
      • ⚠ YOLO — تحذير مرئي كلما كان وضع YOLO مفعّلًا (hermes --yolo، أو /yolo، أو HERMES_YOLO_MODE=1). وتظهر الشارة نفسها في لافتة بدء التشغيل، فلا يمكنك تشغيل جلسة تمنح الموافقات تلقائيًا دون أن تلاحظ ذلك.

      الإعدادات​

      تلتزم TUI بجميع إعدادات Hermes القياسية: ~/.hermes/config.yaml، والـ profiles، والشخصيات، والمظاهر، والأوامر السريعة، ومجمّعات بيانات الاعتماد، ومزوّدي الذاكرة، وتفعيل الأدوات/المهارات. لا يوجد ملف إعدادات خاص بـ TUI.

      هناك عدد قليل من المفاتيح يضبط واجهة TUI تحديدًا:

      display:
        skin: default              # any built-in or custom skin
        personality: helpful
        details_mode: collapsed    # hidden | collapsed | expanded — global accordion default
        sections:                  # optional: per-section overrides (any subset)
          thinking: expanded       # always open
          tools: expanded          # always open
          activity: collapsed      # opt back IN to the activity panel (hidden by default)
        mouse_tracking: all        # off | wheel | buttons | all (or true/false for back-compat).
                                   #   wheel   — 1000+1006 (scroll + click; no drag, no hover —
                                   #             recommended inside tmux to silence the prompt-row
                                   #             "No image in clipboard" spam from hover events)
                                   #   buttons — adds 1002 for terminal-side drag selection
                                   #   all     — adds 1003 for hover (scrollbar paginate-on-hover,
                                   #             link mouseenter, etc.)

      مبدّلات وقت التشغيل:

      • /details [hidden|collapsed|expanded|cycle] — يضبط الوضع العام
      • /details <section> [hidden|collapsed|expanded|reset] — يتجاوز الإعداد لقسم واحد (الأقسام: thinking، tools، subagents، activity)

      الظهور الافتراضي

      تأتي TUI بقيم افتراضية مدروسة لكل قسم، تبث الدور كسجل حيّ بدلًا من جدار من الأسهم المطويّة:

      • thinking — موسَّع. يُبث الاستدلال داخل السطر فور إصداره من النموذج.
      • tools — موسَّع. تُعرض استدعاءات الأدوات ونتائجها مفتوحة.
      • subagents — يرث قيمة details_mode العامة (مطويّ تحت سهم افتراضيًا — ويبقى هادئًا إلى أن يحدث تفويض فعلي).
      • activity — مخفي. المعلومات الجانبية (تلميحات الـ gateway، وتنبيهات التوافق مع الطرفية، والإشعارات الخلفية) مجرد ضجيج في معظم الاستخدام اليومي. ولا تزال إخفاقات الأدوات تُعرض داخل السطر في صف الأداة الفاشلة؛ أما الأخطاء والتحذيرات الجانبية فتظهر عبر تنبيه عائم احتياطي عندما تكون جميع اللوحات مخفية.

      للتجاوزات الخاصة بكل قسم أولوية على كلٍّ من القيمة الافتراضية للقسم وقيمة details_mode العامة. لإعادة تشكيل التخطيط:

      • display.sections.thinking: collapsed — يعيد التفكير إلى الطيّ تحت سهم
      • display.sections.tools: collapsed — يعيد استدعاءات الأدوات إلى الطيّ تحت سهم
      • display.sections.activity: collapsed — يعيد تفعيل لوحة النشاط
      • /details <section> <mode> أثناء التشغيل

      كل ما يُضبط صراحةً في display.sections له الأولوية على القيم الافتراضية، لذا تستمر الإعدادات الحالية في العمل دون تغيير.

      الجلسات (Sessions)​

      الجلسات مشتركة بين TUI وواجهة CLI الكلاسيكية — فكلتاهما تكتبان في ~/.hermes/state.db نفسه. يمكنك بدء جلسة في إحداهما واستئنافها في الأخرى. ويعرض منتقي الجلسات الجلسات من المصدرين، مع وسم يبيّن المصدر.

      راجع الجلسات (Sessions) للاطلاع على دورة الحياة، والبحث، والضغط، والتصدير.

      كيف تتواصل TUI مع الـ gateway الخاص بها​

      افتراضيًا، تُطلق TUI الـ gateway الخاص بها داخل العملية نفسها، فتكون كل نسخة من TUI مستقلة بذاتها — ولا شيء يحتاج إلى ضبط.

      قد ترى إشارة إلى متغير البيئة HERMES_TUI_GATEWAY_URL في قاعدة الكود أو السجلات. هذا تفصيل داخلي في آلية ربط لوحة تحكم الويب، وليس خيارًا موجّهًا للمستخدم للاتصال عن بُعد. عند فتح تبويب "Chat" في لوحة التحكم (hermes dashboard → /chat)، يُطلق خادم الويب الخاص بلوحة التحكم عملية TUI فرعية مضمّنة ويحقن HERMES_TUI_GATEWAY_URL كي تتصل تلك العملية الفرعية بـ tui_gateway الذي يعمل داخل عملية لوحة التحكم نفسها عبر WebSocket على واجهة loopback (/api/ws). ولا يوجد الـ endpoint /api/ws إلا داخل خادم لوحة التحكم (hermes_cli/web_server.py)، وهو مرتبط بعمر تلك العملية ومصادقتها.

      لا يوجد وضع عام من قبيل "وجّه أي TUI إلى أي منفذ gateway مستقل". وعلى وجه الخصوص، فإن خادم API المتوافق مع OpenAI (hermes gateway / منصة api_server) لا يقدّم /api/ws — فهو واجهة الـ backend الخاصة بالنماذج (/v1/chat/completions، /v1/models، …) ولا يكشف عمدًا قناة التحكم JSON-RPC الخاصة بـ TUI. وضبط HERMES_TUI_GATEWAY_URL على ذلك المنفذ سيعيد الخطأ 404.

      إذا أردت أن تتشارك عدة واجهات مجموعة جلسات واحدة، فاستخدم ~/.hermes/state.db المشترك (راجع الجلسات (Sessions)) أو المحادثة المضمّنة في لوحة تحكم الويب (راجع لوحة تحكم الويب) — لا عنوان URL لـ gateway مضبوطًا يدويًا.

      العودة إلى واجهة CLI الكلاسيكية​

      تشغيل hermes (دون --tui) يبقى على واجهة CLI الكلاسيكية افتراضيًا. لجعل جهاز ما يفضّل TUI، اضبط display.interface: tui في ~/.hermes/config.yaml (بشكل دائم) أو HERMES_TUI=1 في ملف تعريف الـ shell (لكل shell). وللعودة، اضبط interface: cli / ألغِ ضبط متغير البيئة، أو مرّر hermes --cli لمرة واحدة.

      إذا فشل تشغيل TUI (لا يوجد Node، أو الحزمة مفقودة، أو مشكلة في TTY)، يطبع Hermes رسالة تشخيصية ويرجع إلى الواجهة الكلاسيكية — بدلًا من أن يتركك عالقًا.
