      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      Shopify — واجهات Admin و Storefront GraphQL

      تعامل مع متاجر Shopify مباشرة عبر curl: اعرض قائمة المنتجات، وأدر المخزون، واسحب الطلبات، وحدّث بيانات العملاء، واقرأ metafields. بلا SDK، وبلا إطار عمل تطبيقات — فقط endpoint الخاص بـ GraphQL ورمز وصول تطبيق مخصَّص.

      واجهة REST Admin API قديمة (legacy) منذ 2024-04 ولا تتلقى سوى إصلاحات أمنية. استخدم GraphQL Admin لكل أعمال الإدارة. استخدم Storefront GraphQL للاستعلامات المخصَّصة للعملاء والمقتصرة على القراءة (المنتجات، المجموعات، سلة الشراء).

      المتطلبات المسبقة​

      1. في لوحة إدارة Shopify: Settings → Apps and sales channels → Develop apps → Create an app.
      2. انقر Configure Admin API scopes، وحدّد ما تحتاجه (أمثلة أدناه)، ثم احفظ.
      3. Install app → يظهر رمز وصول Admin API مرة واحدة فقط. انسخه فورًا — فلن يعرضه Shopify مجددًا أبدًا. تبدأ الرموز بـ shpat_.
      4. احفظه في ${HERMES_HOME:-~/.hermes}/.env: 
        SHOPIFY_ACCESS_TOKEN=shpat_xxxxxxxxxxxxxxxxxxxx
        SHOPIFY_STORE_DOMAIN=my-store.myshopify.com
        SHOPIFY_API_VERSION=2026-01

      تنبيه: اعتبارًا من 1 يناير 2026، لم تعد "التطبيقات المخصَّصة القديمة" الجديدة المُنشأة من لوحة إدارة Shopify متاحة. يجب أن تستخدم الإعدادات الجديدة Dev Dashboard (shopify.dev/docs/apps/build/dev-dashboard). تظل التطبيقات المُنشأة سابقًا من لوحة الإدارة تعمل. إذا لم يكن لدى متجر المستخدم تطبيق مخصَّص موجود وكان التاريخ بعد 2026-01-01، وجّهه إلى Dev Dashboard بدلًا من مسار لوحة الإدارة.

      النطاقات (scopes) الشائعة حسب المهمة:

      • المنتجات / المجموعات: read_products، write_products
      • المخزون: read_inventory، write_inventory، read_locations
      • الطلبات: read_orders، write_orders (أحدث 30 طلبًا دون read_all_orders)
      • العملاء: read_customers، write_customers
      • الطلبات المسوَّدة: read_draft_orders، write_draft_orders
      • عمليات التنفيذ: read_fulfillments، write_fulfillments
      • Metafields / metaobjects: مغطاة بنطاقات الموارد المطابقة

      أساسيات API​

      • Endpoint: https://$SHOPIFY_STORE_DOMAIN/admin/api/$SHOPIFY_API_VERSION/graphql.json
      • ترويسة المصادقة: X-Shopify-Access-Token: $SHOPIFY_ACCESS_TOKEN (وليست Authorization: Bearer)
      • الطريقة: دائمًا POST، ودائمًا Content-Type: application/json، والمتن هو {"query": "...", "variables": {...}}
      • لا يعني HTTP 200 النجاح. تُعيد GraphQL الأخطاء في مصفوفة errors على المستوى الأعلى، وأخطاء userErrors لكل حقل. تحقق دائمًا من الاثنتين.
      • المعرّفات هي سلاسل GID: gid://shopify/Product/10079467700516، gid://shopify/Variant/...، gid://shopify/Order/.... مرّرها كما هي حرفيًا — لا تحذف البادئة.
      • حدّ المعدل (rate limit): يُحسَب عبر تكلفة الاستعلام (leaky bucket). تحمل كل استجابة extensions.cost ومعها requestedQueryCost، وactualQueryCost، وthrottleStatus.{currentlyAvailable, maximumAvailable, restoreRate}. تباطأ عندما تنخفض currentlyAvailable دون تكلفة استعلامك التالي. المتاجر القياسية = دلو (bucket) بـ100 نقطة، استعادة 50/ثانية؛ Plus = 1000/100.

      نمط curl الأساسي (قابل لإعادة الاستخدام):

      shop_gql() {
        local query="$1"
        local variables="${2:-{}}"
        curl -sS -X POST \
          "https://${SHOPIFY_STORE_DOMAIN}/admin/api/${SHOPIFY_API_VERSION:-2026-01}/graphql.json" \
          -H "Content-Type: application/json" \
          -H "X-Shopify-Access-Token: ${SHOPIFY_ACCESS_TOKEN}" \
          --data "$(jq -nc --arg q "$query" --argjson v "$variables" '{query: $q, variables: $v}')"
      }

      مرّر الناتج عبر jq لإخراج مقروء. يبقي -sS الأخطاء ظاهرة لكنه يخفي شريط التقدّم.

      الاستكشاف​

      معلومات المتجر + إصدار API الحالي​

      shop_gql '{ shop { name myshopifyDomain primaryDomain { url } currencyCode plan { displayName } } }' | jq

      عرض كل إصدارات API المدعومة​

      shop_gql '{ publicApiVersions { handle supported } }' | jq '.data.publicApiVersions[] | select(.supported)'

      المنتجات​

      البحث في المنتجات (أول 20 نتيجة مطابقة للاستعلام)​

      shop_gql '
      query($q: String!) {
        products(first: 20, query: $q) {
          edges { node { id title handle status totalInventory variants(first: 5) { edges { node { id sku price inventoryQuantity } } } } }
          pageInfo { hasNextPage endCursor }
        }
      }' '{"q":"hoodie status:active"}' | jq

      تدعم صياغة الاستعلام title:، وsku:، وvendor:، وproduct_type:، وstatus:active، وtag:، وcreated_at:>2025-01-01. القواعد الكاملة: https://shopify.dev/docs/api/usage/search-syntax

      ترقيم صفحات المنتجات (cursor)​

      shop_gql '
      query($cursor: String) {
        products(first: 100, after: $cursor) {
          edges { cursor node { id handle } }
          pageInfo { hasNextPage endCursor }
        }
      }' '{"cursor":null}'
      # subsequent calls: pass the previous endCursor

      جلب منتج مع متغيّراته وmetafields​

      shop_gql '
      query($id: ID!) {
        product(id: $id) {
          id title handle descriptionHtml tags status
          variants(first: 20) { edges { node { id sku price compareAtPrice inventoryQuantity selectedOptions { name value } } } }
          metafields(first: 20) { edges { node { namespace key type value } } }
        }
      }' '{"id":"gid://shopify/Product/10079467700516"}' | jq

      إنشاء منتج بمتغيّر واحد​

      shop_gql '
      mutation($input: ProductCreateInput!) {
        productCreate(product: $input) {
          product { id handle }
          userErrors { field message }
        }
      }' '{"input":{"title":"Test Hoodie","status":"DRAFT","vendor":"Hermes","productType":"Apparel","tags":["test"]}}'

      أصبح للمتغيّرات الآن mutations خاصة بها في الإصدارات الحديثة:

      # Add variants after creating the product
      shop_gql '
      mutation($productId: ID!, $variants: [ProductVariantsBulkInput!]!) {
        productVariantsBulkCreate(productId: $productId, variants: $variants) {
          productVariants { id sku price }
          userErrors { field message }
        }
      }' '{"productId":"gid://shopify/Product/...","variants":[{"optionValues":[{"optionName":"Size","name":"M"}],"price":"49.00","inventoryItem":{"sku":"HD-M","tracked":true}}]}'

      تحديث السعر / SKU​

      shop_gql '
      mutation($productId: ID!, $variants: [ProductVariantsBulkInput!]!) {
        productVariantsBulkUpdate(productId: $productId, variants: $variants) {
          productVariants { id sku price }
          userErrors { field message }
        }
      }' '{"productId":"gid://shopify/Product/...","variants":[{"id":"gid://shopify/ProductVariant/...","price":"55.00"}]}'

      الطلبات​

      عرض الطلبات الأخيرة (آخر 30 افتراضيًا دون read_all_orders)​

      shop_gql '
      {
        orders(first: 20, reverse: true, query: "financial_status:paid") {
          edges { node {
            id name createdAt displayFinancialStatus displayFulfillmentStatus
            totalPriceSet { shopMoney { amount currencyCode } }
            customer { id displayName email }
            lineItems(first: 10) { edges { node { title quantity sku } } }
          } }
        }
      }' | jq

      فلاتر استعلام طلبات مفيدة: financial_status:paid|pending|refunded، وfulfillment_status:unfulfilled|fulfilled، وcreated_at:>2025-01-01، وtag:gift، وemail:foo@example.com.

      جلب طلب واحد مع عنوان الشحن​

      shop_gql '
      query($id: ID!) {
        order(id: $id) {
          id name email
          shippingAddress { name address1 address2 city province country zip phone }
          lineItems(first: 50) { edges { node { title quantity variant { sku } originalUnitPriceSet { shopMoney { amount currencyCode } } } } }
          transactions { id kind status amountSet { shopMoney { amount currencyCode } } }
        }
      }' '{"id":"gid://shopify/Order/...."}' | jq

      العملاء​

      # Search
      shop_gql '
      {
        customers(first: 10, query: "email:*@example.com") {
          edges { node { id email displayName numberOfOrders amountSpent { amount currencyCode } } }
        }
      }'

      # Create
      shop_gql '
      mutation($input: CustomerInput!) {
        customerCreate(input: $input) {
          customer { id email }
          userErrors { field message }
        }
      }' '{"input":{"email":"test@example.com","firstName":"Test","lastName":"User","tags":["api-created"]}}'

      المخزون​

      يقيم المخزون في عناصر المخزون (inventory items) المرتبطة بالمتغيّرات، وتُتبَّع الكميات حسب الموقع (location).

      # Get inventory for a variant across all locations
      shop_gql '
      query($id: ID!) {
        productVariant(id: $id) {
          id sku
          inventoryItem {
            id tracked
            inventoryLevels(first: 10) {
              edges { node { location { id name } quantities(names: ["available","on_hand","committed"]) { name quantity } } }
            }
          }
        }
      }' '{"id":"gid://shopify/ProductVariant/..."}'

      تعديل المخزون (فارق) — يستخدم inventoryAdjustQuantities:

      shop_gql '
      mutation($input: InventoryAdjustQuantitiesInput!) {
        inventoryAdjustQuantities(input: $input) {
          inventoryAdjustmentGroup { reason changes { name delta } }
          userErrors { field message }
        }
      }' '{
        "input": {
          "reason": "correction",
          "name": "available",
          "changes": [{"delta": 5, "inventoryItemId": "gid://shopify/InventoryItem/...", "locationId": "gid://shopify/Location/..."}]
        }
      }'

      ضبط المخزون كقيمة مطلقة (لا فارق) — inventorySetQuantities:

      shop_gql '
      mutation($input: InventorySetQuantitiesInput!) {
        inventorySetQuantities(input: $input) {
          inventoryAdjustmentGroup { id }
          userErrors { field message }
        }
      }' '{"input":{"reason":"correction","name":"available","ignoreCompareQuantity":true,"quantities":[{"inventoryItemId":"gid://shopify/InventoryItem/...","locationId":"gid://shopify/Location/...","quantity":100}]}}'

      Metafields وMetaobjects​

      تُرفق Metafields بيانات مخصَّصة بالموارد (المنتجات، العملاء، الطلبات، المتجر).

      # Read
      shop_gql '
      query($id: ID!) {
        product(id: $id) {
          metafields(first: 10, namespace: "custom") {
            edges { node { key type value } }
          }
        }
      }' '{"id":"gid://shopify/Product/..."}'

      # Write (works for any owner type)
      shop_gql '
      mutation($metafields: [MetafieldsSetInput!]!) {
        metafieldsSet(metafields: $metafields) {
          metafields { id key namespace }
          userErrors { field message code }
        }
      }' '{"metafields":[{"ownerId":"gid://shopify/Product/...","namespace":"custom","key":"care_instructions","type":"multi_line_text_field","value":"Wash cold. Tumble dry low."}]}'

      واجهة Storefront API (عامة، للقراءة فقط)​

      Endpoint مختلف، ورمز مختلف، تُستخدم لتطبيقات مواجهة العملاء أو إعدادات headless من طراز hydrogen. تختلف الترويسات:

      • Endpoint: https://$SHOPIFY_STORE_DOMAIN/api/$SHOPIFY_API_VERSION/graphql.json
      • ترويسة المصادقة (عامة): X-Shopify-Storefront-Access-Token: <public token> — قابلة للتضمين في المتصفح
      • ترويسة المصادقة (خاصة): Shopify-Storefront-Private-Token: <private token> — للخادم فقط
      curl -sS -X POST \
        "https://${SHOPIFY_STORE_DOMAIN}/api/${SHOPIFY_API_VERSION:-2026-01}/graphql.json" \
        -H "Content-Type: application/json" \
        -H "X-Shopify-Storefront-Access-Token: ${SHOPIFY_STOREFRONT_TOKEN}" \
        -d '{"query":"{ shop { name } products(first: 5) { edges { node { id title handle } } } }"}' | jq

      العمليات الدفعية (Bulk Operations)​

      للتفريغات الأكبر مما تسمح به حدود المعدل (كامل كتالوج المنتجات، كل طلبات سنة كاملة):

      # 1. Start bulk query
      shop_gql '
      mutation {
        bulkOperationRunQuery(query: """
          { products { edges { node { id title handle variants { edges { node { sku price } } } } } } }
        """) {
          bulkOperation { id status }
          userErrors { field message }
        }
      }'

      # 2. Poll status
      shop_gql '{ currentBulkOperation { id status errorCode objectCount fileSize url partialDataUrl } }'

      # 3. When status=COMPLETED, download the JSONL file
      curl -sS "$URL" > products.jsonl

      كل سطر JSONL هو عقدة (node)، وتُصدَر الاتصالات المتداخلة كسطور منفصلة تحمل __parentId. أعد تجميعها من جانب العميل عند الحاجة.

      Webhooks​

      اشترك في الأحداث كي لا تضطر إلى الاستطلاع (polling):

      shop_gql '
      mutation($topic: WebhookSubscriptionTopic!, $sub: WebhookSubscriptionInput!) {
        webhookSubscriptionCreate(topic: $topic, webhookSubscription: $sub) {
          webhookSubscription { id topic endpoint { __typename ... on WebhookHttpEndpoint { callbackUrl } } }
          userErrors { field message }
        }
      }' '{"topic":"ORDERS_CREATE","sub":{"callbackUrl":"https://example.com/webhook","format":"JSON"}}'

      تحقق من HMAC الوارد في الـ webhook باستخدام سر عميل التطبيق (وليس رمز الوصول):

      echo -n "$REQUEST_BODY" | openssl dgst -sha256 -hmac "$APP_SECRET" -binary | base64
      # Compare to X-Shopify-Hmac-Sha256 header

      المزالق​

      • لا تزال endpoints واجهة REST موجودة لكنها مجمَّدة. لا تكتب تكاملات جديدة باستخدام /admin/api/.../products.json. استخدم GraphQL.
      • تحقق من صيغة الرمز. تبدأ رموز Admin بـ shpat_. وتبدأ رموز Storefront العامة بـ shpua_. إذا كان لديك رمز واستخدمت الترويسة الخاطئة، تعيد كل الطلبات 401 دون نص خطأ مفيد.
      • 403 مع رمز صالح = نطاق (scope) مفقود. يعيد Shopify {"errors":[{"message":"Access denied for ..."}]}. أعد ضبط نطاقات Admin API على التطبيق، ثم أعد تثبيته لتوليد رمز جديد.
      • فراغ userErrors لا يعني النجاح. تحقق أيضًا من أن data.<mutation>.<resource> ليست null. بعض الإخفاقات لا تملأ أيًا منهما — افحص الاستجابة كاملة.
      • GID مقابل المعرّف الرقمي. كانت REST القديمة تعطي معرّفات رقمية؛ أما GraphQL فتطلب سلاسل GID كاملة. للتحويل: gid://shopify/Product/<numeric>.
      • مفاجأة حدّ المعدل. يمكن لاستعلام واحد من نوع products(first: 250) بتداخل عميق أن يكلّف أكثر من 1000 نقطة ويتسبب في التباطؤ فورًا على متجر بخطة قياسية. ابدأ ضيقًا، واقرأ extensions.cost، ثم اضبط.
      • ترتيب ترقيم الصفحات. يرتّب products(first: N, reverse: true) حسب id DESC وليس created_at. استخدم sortKey: CREATED_AT, reverse: true لـ"الأحدث أولًا".
      • read_all_orders للبيانات التاريخية. دونه، تقتصر orders(...) صامتة على نافذة الـ 60 يومًا. لن تحصل على خطأ، بل نتائج أقل مما تتوقع. لتجار Shopify Plus ذوي الطلبات الكثيرة، اطلب هذا النطاق عبر إعدادات protected-data للتطبيق.
      • العملات نصوص (strings). تعود المبالغ كـ "49.00" وليس 49.0. لا تستخدم jq tonumber عشوائيًا إن كنت تهتم بالأصفار البادئة.
      • حقول Money متعددة العملات تحمل shopMoney (عملة المتجر) وpresentmentMoney (عملة العميل). اختر واحدة بثبات.

      السلامة​

      الـ mutations في Shopify حقيقية — فهي تنشئ منتجات، وتُصدر استردادات، وتلغي طلبات، وتشحن عمليات تنفيذ. قبل تشغيل productDelete، أو orderCancel، أو refundCreate، أو أي mutation دفعي: اذكر بوضوح ماهية التغيير، وعلى أي متجر، وأكّد مع المستخدم. لا توجد نسخة تجريبية (staging) من بيانات الإنتاج ما لم يمتلك المستخدم متجرًا تطويريًا منفصلًا.
