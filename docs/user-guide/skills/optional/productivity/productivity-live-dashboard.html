      Live Dashboard

      أنشئ لوحات تحكم ذاتية التحديث من مصادر حية.

      بيانات المهارة الوصفية​

      المصدراختيارية — ثبّتها باستخدام hermes skills install official/productivity/live-dashboard
      المسارoptional-skills/productivity/live-dashboard
      الإصدار0.2.0
      المؤلفTeknium (teknium1), Hermes Agent
      الترخيصMIT
      المنصاتlinux, macos, windows
      الوسومdashboards, monitoring, status, automation, reporting
      مهارات ذات صلةproduct-price-monitor, competitor-news-monitor, email-inbox-triage, google-workspace

      المرجع: ملف SKILL.md كاملًا​

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      Live Dashboard

      حوّل جملة واحدة — "أنشئ لوحة تحكم لطلبات التأشيرات لدينا، وحدّثها يوميًا من سلاسل البريد الإلكتروني وموقع حالة الطلب" — إلى صفحة حالة دائمة ذاتية التحديث. يصف المستخدم ما يريد رؤيته؛ وتحدد أنت عقد البيانات، وتنشئ لوحة HTML مكتفية ذاتيًا، وتتحقق من تحديث حي واحد، ثم تُجدول tick المتكرر.

      يُنفّذ الإعداد مرة واحدة في المقدمة؛ ويُنفَّذ التحديث المتكرر كـ tick cronjob. ويعرض تثبيت هذه المهارة مسحًا يوميًا لكل لوحات التحكم عبر /suggestions (blueprint في frontmatter).

      متى تُستخدم​

      • "أنشئ لوحة تحكم لـ <المشروع/العملية> وأبقها محدَّثة."
      • "أريد مكانًا واحدًا لرؤية حالة <الصفقات / الطلبات / الأخطاء / الشحنات>."
      • "تابع <الشيء> عبر بريدي الإلكتروني و <الموقع> وأرني وضعه."
      • "أرني لوحة تحكم <slug>." (إعادة عرض/معاينة لوحة موجودة)
      • يعمل tick cron للوحة تحكم موجودة (الخطوات 5-7).

      لا تستخدمها لأسئلة حالة لمرة واحدة (أجب مباشرة)، أو عتبات السعر/الإتاحة لعنصر واحد (استخدم product-price-monitor)، أو متابعة أخبار الشركات (استخدم competitor-news-monitor).

      المتطلبات المسبقة​

      • موصل مصدر واحد على الأقل تقرأ منه اللوحة: البريد/التقويم عبر himalaya أو google-workspace، والمواقع عبر web_extract أو browser_exec، والملفات المحلية عبر read_file. إذا لم يُعدّ أي مصدر، فأعد الاتفاق على المصادر في الخطوة 1 قبل كتابة أي مُخرج.
      • cronjob للـ tick المتكرر.
      • اختياري: أداة desktop_preview (جلسات تطبيق Hermes Desktop). عند وجودها ضمن toolset تُعرض لوحات التحكم في لوحة المعاينة داخل التطبيق؛ وإلا يُعطى المستخدم مسار الملف.

      الإجراء — الإعداد (في المقدمة، مرة واحدة)​

      1. حدد عقد لوحة التحكم​

      استخلص من جملة المستخدم: غرض اللوحة في سطر واحد، والكيانات المتابَعة (الصفوف)، وحقول كل كيان (الأعمدة/المؤشرات)، ومعنى "يحتاج اهتمامًا"، والمصادر التي يُقرأ منها كل حقل، ووتيرة التحديث. اسأل عن كل ما هو غامض — فاللوحة التي تتابع مستوى تفصيل خاطئًا عديمة القيمة. تُنجز الخطوة عندما يسمّي كل حقل في اللوحة المصدر الذي سيُقرأ منه.

      2. تحقق من كل مصدر بقراءة حية واحدة​

      لكل مصدر، نفّذ الآن قراءة واحدة محدودة في المقدمة: البريد/التقويم عبر مهارات الموصلات (himalaya, google-workspace)، والمواقع عبر web_extract أو browser_exec، والملفات المحلية عبر read_file. سجّل ما أمكن استرجاعه فعلًا — تظهر هنا حواجز المصادقة والصلاحيات الناقصة والنتائج الفارغة، لا في أول تشغيل مجدول. احذف المصادر التي تفشل أو استبدلها. تُنجز الخطوة عندما يعيد مصدر كل حقل بيانات حقيقية أو يُعاد الاتفاق عليه صراحة مع المستخدم.

      3. أنشئ مُخرج لوحة التحكم​

      اكتب ملفين تحت dashboards/<slug>/ في الدليل الرئيسي لـ Hermes (الدليل نفسه الذي يحمل config.yaml؛ ولا تفترض موضعًا ثابتًا مطلقًا):

      • dashboard.json — العقد بالإضافة إلى الحالة الحالية: الغرض، والكيانات، وقيم كل حقل، ومصدر كل حقل + طابع وقت الاسترجاع، وقائمة needs_attention، وسجل تغييرات (للإلحاق فقط، والأحدث أولًا).
      • index.html — صفحة HTML واحدة مكتفية ذاتيًا (CSS مضمّن، دون طلبات خارجية) تعرض الحالة: ترويسة بالغرض ووقت آخر تحديث، وقسم "Needs attention" في الأعلى، وجدول الكيانات، وقائمة التغييرات الحديثة. أعد توليدها من dashboard.json في كل تحديث؛ ولا تعدّل حالة HTML يدويًا مطلقًا.

      املأ الملفين من قراءات الخطوة 2، ثم اعرض النتيجة (الخطوة 8). تُنجز الخطوة عندما تعرض الصفحة البيانات الحية وتحمل كل قيمة فيها طابع وقت استرجاع في dashboard.json.

      4. جدوِل التحديث​

      لا تُجدول tick إلا بعد نجاح الخطوة 3. إذا كان المسح اليومي لكل لوحات التحكم من /suggestions مجدولًا بالفعل وكانت وتيرته مناسبة، فسيلتقط هذه اللوحة — اذكر ذلك وتوقف. وإلا أنشئ مهمة خاصة باللوحة يسمّي prompt الخاص بها ملف الحالة:

      cronjob(action="create",
              schedule=<cadence from the contract, e.g. "0 8 * * *">,
              prompt="Load the live-dashboard skill and run the refresh tick for the dashboard at <absolute path to dashboards/<slug>/dashboard.json>.",
              deliver=<user's destination>)

      اختر وتيرة تحترم حدود معدل المصادر. تُنجز الخطوة عند وجود مهمة تغطي هذه اللوحة ويسمّي prompt الخاص بها مسار ملف الحالة (أو المسح).

      الإجراء — Tick (كل تشغيل مجدول)​

      5. أعد قراءة المصادر وقارن​

      حمّل dashboard.json (للمسح: كل dashboards/*/dashboard.json، واحدًا بعد آخر)، وأعد قراءة كل حقل من مصدره المسمّى، واحسب فرقًا على مستوى الحقول مقارنة بالحالة المخزّنة. فشل قراءة مصدر يعني حالة غير معروفة: احتفظ بآخر قيمة سليمة، وعلّم الحقل كقديم مع وقت الفشل، ولا تستبدل بيانات سليمة بخطأ مطلقًا. تُنجز الخطوة عندما يكون كل حقل محدَّثًا أو دون تغيير أو معلّمًا صراحة كقديم.

      6. حدّث الحالة وأعد العرض​

      طبّق الفرق على dashboard.json: حدّث القيم والطوابع الزمنية، وألحق التغييرات الجوهرية بسجل التغييرات، وأعد حساب needs_attention وفق قواعد الاهتمام في العقد. أعد توليد index.html من الحالة المحدَّثة، ثم اعرض النتيجة (الخطوة 8). تُنجز الخطوة عندما يتفق JSON و HTML ، ويوجد إدخال سجل التغييرات لهذا التشغيل (أو يُسجّل التشغيل دون تغيير).

      7. أرسل عند تغيير جوهري، وإلا التزم الصمت​

      إذا تضمن الفرق تغييرات جوهرية أو عناصر جديدة تحتاج اهتمامًا، فأرسل ملخصًا قصيرًا: ما تغير، وما يحتاج اهتمامًا، ومكان اللوحة. وإلا فأجب بـ [SILENT] — دون ضجيج "ما زلت أتابع" ما لم يطلب المستخدم موجزًا دوريًا. تُنجز الخطوة عندما يطابق التسليم الفرق.

      الإجراء — عرض لوحة التحكم (بعد كل إنشاء أو إعادة عرض، وعند الطلب)​

      8. اعرضها حيث يستطيع المستخدم رؤيتها​

      • جلسة Desktop/GUI (desktop_preview ضمن toolset): desktop_preview(action="open", url=<absolute path to index.html>, label=<dashboard purpose>) كي تُعرض الصفحة مباشرة في لوحة المعاينة بجوار المحادثة؛ وأعد فتحها بعد كل إعادة عرض كي تُظهر اللوحة الحالة الجديدة.
      • أي جلسة أخرى (CLI ، أو تطبيق مراسلة، أو tick cron دون GUI): أبلغ عن المسار المطلق لـ index.html واعرض فتحه حيث تسمح المنصة.

      تُنجز الخطوة عندما يرى المستخدم الصفحة المعروضة أو يُبلَّغ بمكانها الدقيق.

      المزالق​

      • إنشاء الصفحة قبل التحقق من المصادر — فتظهر إخفاقات المصادقة عند تشغيل دون مراقبة.
      • استبدال آخر قيم سليمة معروفة بصفحة خطأ أو قراءة فارغة.
      • عرض الحالة في HTML وحده — dashboard.json هو المرجع المعتمد؛ و HTML إسقاط له.
      • إرسال تنبيه في كل تحديث بدلًا من التغيير الجوهري.
      • متابعة مستوى تفصيل خاطئ (لكل سلسلة محادثة بينما يفكر المستخدم لكل طلب).
      • ترميز مسار Hermes الرئيسي ثابتًا — حدده من التثبيت العامل (الدليل الذي يحمل config.yaml) واكتب مسارات مطلقة في prompts cron.
      • استدعاء desktop_preview خارج جلسة Desktop — فهي لا تكون ضمن toolset إلا لجلسات GUI ؛ واستخدم المسار بدلًا منها.

      التحقق​

      • يسمّي كل حقل في اللوحة مصدره، ونجح كل مصدر في قراءة واحدة في المقدمة قبل الجدولة.
      • dashboard.json و index.html موجودان ومتفقان؛ وتحمل كل قيمة طابع وقت استرجاع.
      • علّمت القراءات الفاشلة الحقول كقديمة دون إتلاف آخر حالة سليمة معروفة.
      • لا تُرسل ticks إلا عند تغيير جوهري؛ وتكون التشغيلات دون تغيير [SILENT].
      • يعيد سجل التغييرات بناء تاريخ اللوحة من ملف الحالة وحده.
      • عُرضت اللوحة في لوحة المعاينة (Desktop) أو أُبلغ بمسارها (غيره).
