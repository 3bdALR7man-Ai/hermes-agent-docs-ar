      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      Setup Wizard Generator

      يولّد wizard تفاعليًا بلغة bash: سكربت يرشد إنسانًا، خطوة خطوة، خلال إجراء يدوي مملّ في التنفيذ اليدوي ومملّ في إعادة شرحه في كل مرة. يفتح كل رابط، ويقول بالضبط ماذا يُنقر وماذا يُنسخ، ويلتقط القيم، ويكتبها حيث ينبغي (.env، أسرار GitHub)، ويؤكّد في كل مرحلة، ويعرض عدد المراحل المتبقية.

      مُنقول عن مهارة wizard المرخّصة بموجب MIT من mattpocock/skills.

      متى تُستخدم​

      • تجهيز بنية تحتية أو خدمات جهات خارجية (Stripe، Supabase، DNS، تطبيقات OAuth) حيث لا يستطيع سوى الإنسان النقر عبر لوحة التحكم
      • إعداد بيانات الاعتماد، أو أسرار CI، أو متغيرات المستودع
      • عمليات ترحيل أو تحوّل لمرة واحدة تتضمّن خطوات لا رجعة فيها يتحكم بها إنسان
      • أي إجراء سيسلّمه المستخدم لزميل ليقوم بتشغيله

      لا تستخدمها للخطوات التي يستطيع الوكيل تنفيذها بنفسه — نفّذ تلك مباشرة.

      المتطلبات المسبقة​

      • bash؛ CLI الخاص بـ gh فقط إذا كانت المراحل تكتب أسرار أو متغيرات GitHub
      • قالب المكتبة: templates/template.sh في مجلد هذه المهارة

      الإجراء​

      1. حدّد نطاق الإجراء​

      حدّد كل خطوة يدوية يجب أن يقوم بها الإنسان وكل قيمة تُلتقط على طول الطريق. اقرأ المستودع أولًا، لا تسأل دون تحضير:

      • الإعداد: .env، .env.example، README، docker-compose*، إعدادات الإطار، و.github/workflows/* (كل مرجع secrets.* / vars.* هو قيمة يجب على الـ wizard إنتاجها).
      • الترحيل/التحوّل: الحالة الحالية، والحالة المستهدفة، والإجراءات التي لا رجعة فيها بينهما.

      اعرض على المستخدم قائمة المراحل مرتّبة والقيم التي تنتجها كل واحدة؛ قد يضيف أو يحذف أو يعيد الترتيب. تنتهي هذه الخطوة عندما تُسمّى كل مرحلة بترتيبها، وتعرف لكل قيمة مُلتقطة (أ) من أين يحصل عليها الإنسان، (ب) أين تُكتب (.env، سر في GitHub، كلاهما، أو لا مكان)، و(ج) هل هي سرّية (إدخال مخفي) أم عامة.

      2. ارسم مسار كل مرحلة​

      لكل مرحلة، اكتب المسار الدقيق الذي يتبعه الإنسان: أي رابط يُفتح، وماذا يفعل هناك، وأين تظهر القيمة — مثل "Dashboard → Developers → API keys → Reveal test key → copy". حيثما لا تعرف الواجهة الحالية أو الأمر الدقيق، قل ذلك وتحقّق من المستندات أو اسأل — لا تخترع أبدًا خطوات قد لا تكون موجودة.

      3. أنشئ الـ wizard​

      انسخ templates/template.sh (من مجلد هذه المهارة) إلى المسار المستهدف. استبدل المرحلة النموذجية بـ stage واحدة لكل خطوة، بترتيب الاعتماديات. اضبط TOTAL_STAGES على عدد المراحل التي كتبتها.

      مساعدات المكتبة: stage، say/step/note/warn، open_url، ask/ask_secret، write_env، set_secret/set_var، pause/confirm، banner، finish. المكتبة الموجودة فوق علامة STAGES مطابقة في كل wizard — لا تعدّلها يدويًا أبدًا؛ فهذا الاتساق هو بيت القصيد.

      التزم بالمعيار الذي يضعه القالب: افتح الرابط قبل طلب قيمته، واستخدم ask_secret لأي شيء سرّي، وwrite_env لكل قيمة تُحفظ، وset_secret لما يحتاجه CI فعليًا فقط، وconfirm قبل أي شيء لا رجعة فيه. تمسح كل stage الشاشة — أبقِ مهمة واحدة مركّزة لكل مرحلة حتى لا يختفي بالتمرير ما يحتاجه الإنسان.

      الـ wizard مؤقت افتراضيًا: احفظه في مسار مؤقت أو مسار scripts/، واحذفه عند انتهاء المهمة. لا تُدرجه في commit إلا عندما يريد المستخدم مسار إعداد متكرّرًا يعيش داخل المستودع.

      4. تحقّق وسلّم العمل​

      • bash -n <script>؛ شغّل shellcheck إن كان متاحًا؛ chmod +x <script>.
      • لا تُشغّله من البداية إلى النهاية بنفسك: فهو يفتح متصفحات ويتوقف بانتظار مُدخلات الإنسان. تتبّعه بصورة ساكنة (statically): تحقّق أن كل قيمة من الخطوة 1 مُلتقطة وتصل إلى حيث حدّدته الخطوة 1، وأن كل اسم set_secret يطابق تمامًا مرجع secrets.* في CI.
      • أخبر المستخدم كيف يشغّله. إذا كان متكرّرًا، أدرجه في commit واربطه من README.

      المزالق الشائعة​

      1. تعديل قسم المكتبة. كل ما فوق علامة STAGES هو مكتبة الـ wizard؛ اكتب فقط تحتها.
      2. اختلاق مسارات لوحات التحكم. واجهات الجهات الخارجية تتغيّر. إذا لم تكن متأكدًا من مسار النقر، تحقّق من المستندات الحالية أو أشِر إلى أنه تقريبي.
      3. استخدام set_secret لقيم لا يستخدمها CI. لا تدفع إلى أسرار GitHub إلا ما يشير إليه سير عمل فعليًا.
      4. تشغيل الـ wizard بنفسك. فهو يتوقف بانتظار مُدخلات الإنسان؛ التتبّع الساكن مع bash -n هو أسلوب التحقق.
      5. مرحلة ضخمة واحدة. مسح الشاشة لكل مرحلة يعني أن مرحلة طويلة تُخفي تعليمات مهمة بالتمرير؛ قسّمها.

      التحقق​

      • تم تأكيد قائمة المراحل مع المستخدم قبل الكتابة
      • bash -n ينجح؛ السكربت قابل للتنفيذ
      • كل قيمة مُلتقطة متتبَّعة إلى وجهتها المُعلَنة
      • كل اسم set_secret يطابق مرجع secrets.* في CI
      • قسم المكتبة لم يُمسّ منذ القالب
