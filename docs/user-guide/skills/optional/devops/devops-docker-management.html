      Docker Management

      أدِر حاويات Docker وصوره وأحجامه (volumes) وشبكاته ومكدّسات Compose باستخدام أوامر Docker CLI القياسية. لا حاجة إلى أي اعتماديات إضافية غير Docker نفسه.

      متى تُستخدم​

      • تشغيل الحاويات أو إيقافها أو إعادة تشغيلها أو حذفها أو فحصها
      • بناء صور Docker أو سحبها أو دفعها أو وسمها أو تنظيفها
      • العمل مع Docker Compose (مكدّسات متعددة الخدمات)
      • إدارة الأحجام (volumes) أو الشبكات
      • تشخيص حاوية متعطّلة أو تحليل السجلات
      • التحقق من استخدام Docker لمساحة القرص أو تحرير المساحة
      • مراجعة Dockerfile أو تحسينه

      المتطلبات المسبقة​

      • محرّك Docker مثبّت وقيد التشغيل
      • المستخدم مُضاف إلى مجموعة docker (أو استخدم sudo)
      • Docker Compose v2 (مضمّن مع تثبيتات Docker الحديثة)

      تحقّق سريع:

      docker --version && docker compose version

      مرجع سريع​

      المهمةالأمر
      تشغيل حاوية (في الخلفية)docker run -d --name NAME IMAGE
      الإيقاف + الحذفdocker stop NAME && docker rm NAME
      عرض السجلات (بمتابعة)docker logs --tail 50 -f NAME
      الدخول إلى shell داخل الحاويةdocker exec -it NAME /bin/sh
      سرد جميع الحاوياتdocker ps -a
      بناء صورةdocker build -t TAG .
      تشغيل Composedocker compose up -d
      إيقاف Composedocker compose down
      استخدام القرصdocker system df
      تنظيف العناصر المعلّقةdocker image prune && docker container prune

      الإجراء​

      1. حدّد المجال​

      حدّد أي مجال ينطبق على الطلب:

      • دورة حياة الحاوية → التشغيل، الإيقاف، البدء، إعادة التشغيل، الحذف، الإيقاف المؤقت/الاستئناف
      • التفاعل مع الحاوية → exec وcp والسجلات والفحص والإحصاءات
      • إدارة الصور → البناء والسحب والدفع والوسم والحذف والحفظ/التحميل
      • Docker Compose → up وdown وps والسجلات وexec والبناء والإعدادات
      • الأحجام والشبكات → الإنشاء والفحص والحذف والتنظيف والربط
      • استكشاف الأخطاء وإصلاحها → تحليل السجلات وأكواد الخروج ومشكلات الموارد

      2. عمليات الحاوية​

      تشغيل حاوية جديدة:

      # Detached service with port mapping
      docker run -d --name web -p 8080:80 nginx

      # With environment variables
      docker run -d -e POSTGRES_PASSWORD=secret -e POSTGRES_DB=mydb --name db postgres:16

      # With persistent data (named volume)
      docker run -d -v pgdata:/var/lib/postgresql/data --name db postgres:16

      # For development (bind mount source code)
      docker run -d -v $(pwd)/src:/app/src -p 3000:3000 --name dev my-app

      # Interactive debugging (auto-remove on exit)
      docker run -it --rm ubuntu:22.04 /bin/bash

      # With resource limits and restart policy
      docker run -d --memory=512m --cpus=1.5 --restart=unless-stopped --name app my-app

      الخيارات الأساسية: -d للتشغيل في الخلفية، -it للتفاعل مع طرفية، --rm للحذف التلقائي، -p للمنفذ (host:container)، -e لمتغير البيئة، -v للحجم، --name للاسم، --restart لسياسة إعادة التشغيل.

      إدارة الحاويات قيد التشغيل:

      docker ps                        # running containers
      docker ps -a                     # all (including stopped)
      docker stop NAME                 # graceful stop
      docker start NAME                # start stopped container
      docker restart NAME              # stop + start
      docker rm NAME                   # remove stopped container
      docker rm -f NAME                # force remove running container
      docker container prune           # remove ALL stopped containers

      التفاعل مع الحاويات:

      docker exec -it NAME /bin/sh          # shell access (use /bin/bash if available)
      docker exec NAME env                   # view environment variables
      docker exec -u root NAME apt update    # run as specific user
      docker logs --tail 100 -f NAME         # follow last 100 lines
      docker logs --since 2h NAME            # logs from last 2 hours
      docker cp NAME:/path/file ./local      # copy file from container
      docker cp ./file NAME:/path/           # copy file to container
      docker inspect NAME                    # full container details (JSON)
      docker stats --no-stream               # resource usage snapshot
      docker top NAME                        # running processes

      3. إدارة الصور​

      # Build
      docker build -t my-app:latest .
      docker build -t my-app:prod -f Dockerfile.prod .
      docker build --no-cache -t my-app .              # clean rebuild
      DOCKER_BUILDKIT=1 docker build -t my-app .       # faster with BuildKit

      # Pull and push
      docker pull node:20-alpine
      docker login ghcr.io
      docker tag my-app:latest registry/my-app:v1.0
      docker push registry/my-app:v1.0

      # Inspect
      docker images                          # list local images
      docker history IMAGE                   # see layers
      docker inspect IMAGE                   # full details

      # Cleanup
      docker image prune                     # remove dangling (untagged) images
      docker image prune -a                  # remove ALL unused images (careful!)
      docker image prune -a --filter "until=168h"   # unused images older than 7 days

      4. Docker Compose​

      # Start/stop
      docker compose up -d                   # start all services detached
      docker compose up -d --build           # rebuild images before starting
      docker compose down                    # stop and remove containers
      docker compose down -v                 # also remove volumes (DESTROYS DATA)

      # Monitoring
      docker compose ps                      # list services
      docker compose logs -f api             # follow logs for specific service
      docker compose logs --tail 50          # last 50 lines all services

      # Interaction
      docker compose exec api /bin/sh        # shell into running service
      docker compose run --rm api npm test   # one-off command (new container)
      docker compose restart api             # restart specific service

      # Validation
      docker compose config                  # validate and view resolved config

      مثال compose.yml بسيط:

      services:
        api:
          build: .
          ports:
            - "3000:3000"
          environment:
            # Password comes from the POSTGRES_PASSWORD secret, not the URL
            - DATABASE_URL=postgres://mydb_user@db:5432/mydb
          depends_on:
            db:
              condition: service_healthy

        db:
          image: postgres:16-alpine
          environment:
            POSTGRES_USER: user
            POSTGRES_PASSWORD: pass
            POSTGRES_DB: mydb
          volumes:
            - pgdata:/var/lib/postgresql/data
          healthcheck:
            test: ["CMD-SHELL", "pg_isready -U user"]
            interval: 10s
            timeout: 5s
            retries: 5

      volumes:
        pgdata:

      5. الأحجام والشبكات​

      # Volumes
      docker volume ls                       # list volumes
      docker volume create mydata            # create named volume
      docker volume inspect mydata           # details (mount point, etc.)
      docker volume rm mydata                # remove (fails if in use)
      docker volume prune                    # remove unused volumes

      # Networks
      docker network ls                      # list networks
      docker network create mynet            # create bridge network
      docker network inspect mynet           # details (connected containers)
      docker network connect mynet NAME      # attach container to network
      docker network disconnect mynet NAME   # detach container
      docker network rm mynet                # remove network
      docker network prune                   # remove unused networks

      6. استخدام القرص والتنظيف​

      ابدأ دائمًا بتشخيص قبل التنظيف:

      # Check what's using space
      docker system df                       # summary
      docker system df -v                    # detailed breakdown

      # Targeted cleanup (safe)
      docker container prune                 # stopped containers
      docker image prune                     # dangling images
      docker volume prune                    # unused volumes
      docker network prune                   # unused networks

      # Aggressive cleanup (confirm with user first!)
      docker system prune                    # containers + images + networks
      docker system prune -a                 # also unused images
      docker system prune -a --volumes       # EVERYTHING — named volumes too

      تحذير: لا تُشغّل أبدًا docker system prune -a --volumes دون تأكيد ذلك مع المستخدم. فهذا يحذف الأحجام المُسمّاة التي قد تحتوي على بيانات مهمة.

      المزالق الشائعة​

      المشكلةالسببالحل
      الحاوية تخرج فورًاالعملية الرئيسية انتهت أو تعطّلتتحقّق من docker logs NAME، وجرّب docker run -it --entrypoint /bin/sh IMAGE
      "port is already allocated"عملية أخرى تستخدم ذلك المنفذاستخدم docker ps أو lsof -i :PORT لتحديدها
      "no space left on device"قرص Docker ممتلئdocker system df ثم تنظيف مُوجّه
      تعذّر الاتصال بالحاويةالتطبيق يرتبط بـ 127.0.0.1 داخل الحاويةيجب أن يرتبط التطبيق بـ 0.0.0.0، تحقّق من تعيين -p
      رفض إذن الوصول (Permission denied) على الحجمعدم تطابق UID/GID بين المضيف والحاويةاستخدم --user $(id -u):$(id -g) أو أصلح الأذونات
      خدمات Compose لا تصل إلى بعضهاشبكة أو اسم خدمة خاطئتستخدم الخدمات اسم الخدمة كاسم مضيف، تحقّق باستخدام docker compose config
      ذاكرة التخزين المؤقت للبناء لا تعملترتيب الطبقات خاطئ في Dockerfileضع الطبقات النادرة التغيير أولًا (الاعتماديات قبل كود المصدر)
      الصورة كبيرة جدًالا يوجد بناء متعدد المراحل، ولا يوجد .dockerignoreاستخدم البناء متعدد المراحل، وأضِف .dockerignore

      التحقق​

      بعد أي عملية Docker، تحقّق من النتيجة:

      • هل بدأت الحاوية؟ → docker ps (تحقّق أن الحالة "Up")
      • هل السجلات نظيفة؟ → docker logs --tail 20 NAME (بلا أخطاء)
      • هل المنفذ متاح؟ → curl -s http://localhost:PORT أو docker port NAME
      • هل تم بناء الصورة؟ → docker images | grep TAG
      • هل مكدّس Compose سليم؟ → docker compose ps (كل الخدمات "running" أو "healthy")
      • هل تحرّرت مساحة القرص؟ → docker system df (قارن قبل/بعد)

      نصائح لتحسين Dockerfile​

      عند مراجعة Dockerfile أو إنشائه، اقترح هذه التحسينات:

      1. البناء متعدد المراحل — افصل بيئة البناء عن بيئة التشغيل لتقليل حجم الصورة النهائية
      2. ترتيب الطبقات — ضع الاعتماديات قبل كود المصدر حتى لا تُبطل التغييرات الطبقات المخزّنة مؤقتًا
      3. دمج أوامر RUN — طبقات أقل، صورة أصغر
      4. استخدام .dockerignore — استبعِد node_modules، .git، __pycache__، وما شابه
      5. تثبيت إصدارات الصورة الأساسية — node:20-alpine بدلًا من node:latest
      6. التشغيل بدون صلاحيات root — أضِف تعليمة USER لأغراض الأمان
      7. استخدام قواعد slim/alpine — python:3.12-slim بدلًا من python:3.12
