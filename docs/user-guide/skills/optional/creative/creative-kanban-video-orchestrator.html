      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      Kanban Video Orchestrator

      لُف أي طلب فيديو — من إعلان دعائي للمنتج مدته 15 ثانية إلى فيلم قصير سردي مدته 5 دقائق إلى فيديو موسيقي إلى حلقة ASCII — في خط أنابيب Hermes Kanban الذي يفكّك العمل إلى ملفات وكلاء (profiles) متخصصة.

      هذه المهارة لا تعرض أي شيء بنفسها. إنها خط أنابيب وصفي (meta-pipeline) يقوم بما يلي:

      1. يحدّد نطاق الطلب من خلال استكشاف موجّه
      2. يصمّم فريقًا مناسبًا (أي الأدوار، وأي الأدوات لكل دور) بناءً على الأسلوب
      3. يولّد سكربت إعداد ينشئ ملفات Hermes، ومساحة عمل المشروع، ومهمة kanban الأولية
      4. يسلّم إلى ملف المخرج (director profile)، الذي يفكّك العمل عبر kanban
      5. يراقب التنفيذ، ويساعد على التدخّل عندما تتعطّل المهام أو تفشل

      يحدث العرض الفعلي داخل kanban بمجرد تشغيله، عبر أي من المهارات والأدوات الموجودة التي تناسب المشاهد — ascii-video، manim-video، p5js، comfyui، touchdesigner-mcp، songwriting-and-ai-music، heartmula، واجهات API خارجية، أو Python عادي مع PIL و ffmpeg.

      متى لا تستخدم هذه المهارة​

      • الفيديو مشروع إجرائي واحد ومستمر لا يحتاج متخصصين. اكتب الكود مباشرة فقط.
      • يريد المستخدم تحويلًا سريعًا لمرة واحدة (مثل "حوّل هذا الـ mp4 إلى GIF") — استخدم ffmpeg مباشرة.
      • المخرج صورة ثابتة، أو GIF، أو ناتج صوتي فقط — استخدم المهارة المحدّدة المطابقة (ascii-art، gifs، meme-generation، songwriting-and-ai-music).
      • يتناسب العمل مع مهارة موجودة واحدة بشكل نظيف (مثل فيديو ASCII خالص — استخدم فقط ascii-video).

      سير العمل​

      DISCOVER  →  BRIEF  →  TEAM DESIGN  →  SETUP  →  EXECUTE  →  MONITOR

      الخطوة 1 — الاستكشاف (اطرح الأسئلة الصحيحة)​

      عملية الاستكشاف تكيّفية: اطرح فقط ما هو ضروري فعلًا. ابدأ دائمًا بثلاثة أسئلة لتحديد الشكل العام:

      • ما هو الفيديو؟ (وصف موجز بجملة واحدة)
      • ما مدته؟ (إعلان دعائي 5-30 ثانية / فيديو قصير 30-90 ثانية / شرح توضيحي 90 ثانية-3 دقائق / فيلم 3-10 دقائق / أطول)
      • ما نسبة العرض إلى الارتفاع والمنصة المستهدفة؟ (1:1 / 9:16 / 16:9؛ X، إنستغرام، يوتيوب، داخلي، إلخ)

      من الإجابة، صنّف فئة الأسلوب. يحدّد الأسلوب أي أسئلة متابعة تُطرح. لا تطرح كل الأسئلة دفعة واحدة. اطرح 2-4 في كل مرة، استمع، ثم تابع. اتّخذ افتراضات معقولة كلما ألمح المستخدم إلى إجابة.

      لأنماط الاستقبال الكاملة وبنوك الأسئلة الخاصة بكل أسلوب، انظر references/intake.md.

      الخطوة 2 — الملخص (Brief)​

      بمجرد معرفة ما يكفي، أنتج ملف brief.md منظّمًا باستخدام القالب في assets/brief.md.tmpl. المراحل:

      1. المفهوم — العرض بجملة واحدة + النجم الشمالي العاطفي
      2. النطاق — المدة، النسبة، المنصة، الموعد النهائي
      3. الأسلوب — المراجع البصرية، قيود العلامة التجارية، النبرة
      4. المشاهد — تفصيل نبضة بنبضة (المدد، المحتوى، الأداة المستهدفة)
      5. الصوت — سرد / موسيقى / مؤثرات صوتية / صامت (لكل مشهد عند الحاجة)
      6. المخرجات — صيغة الملف، الدقة، بدائل اختيارية (مقطع عمودي، GIF، إلخ)

      اعرض الملخص على المستخدم للتأكيد قبل تصميم الفريق. الملخص هو العقد — كل مهمة لاحقة تشير إليه.

      الخطوة 3 — تصميم الفريق​

      اختر أنماط أدوار نموذجية من المكتبة تناسب هذا الفيديو. ركّب، ولا تستنسخ. تحتاج معظم الفيديوهات 4-7 ملفات وكلاء. المخرج حاضر دائمًا؛ والبقية تُختار وفق ما يتطلبه الملخص فعلًا.

      لمكتبة الأدوار وتركيبات الفريق الخاصة بكل أسلوب، انظر references/role-archetypes.md.

      لربط كل دور ← بمهارات وtoolsets Hermes التي يحمّلها، انظر references/tool-matrix.md.

      الخطوة 4 — الإعداد​

      ولّد سكربت إعداد (setup.sh) وشغّله. يقوم السكربت بما يلي:

      1. ينشئ مساحة عمل المشروع (~/projects/video-pipeline/<slug>/)
      2. ينسخ أي أصول مقدَّمة إلى taste/، audio/، assets/
      3. ينشئ كل ملف Hermes عبر hermes profile create --clone
      4. يكتب SOUL.md لكل ملف (تعريف الشخصية والدور)
      5. يضبط YAML الخاص بالملف (toolsets، مهارات always_load، دليل العمل cwd)
      6. يكتب brief.md، وTEAM.md، ومحتوى taste/
      7. يطلق مهمة hermes kanban create الأولية المسندة إلى المخرج

      استخدم scripts/bootstrap_pipeline.py لتوليد setup.sh من ملخص + JSON تصميم الفريق. انظر references/kanban-setup.md لبنية سكربت الإعداد، وأنماط ضبط الملف، وقاعدة "مساحة العمل المشتركة" الحاسمة.

      الخطوة 5 — التنفيذ​

      شغّل setup.sh. ثم زوّد المستخدم بأوامر المراقبة:

      hermes kanban watch --tenant <project-tenant>     # live events
      hermes kanban list  --tenant <project-tenant>     # board snapshot
      hermes dashboard                                   # visual board UI

      يتولّى ملف المخرج الأمر من هنا، ويفكّك العمل ويوجّه المهام إلى الملفات المتخصصة عبر toolset الخاص بـ kanban.

      الخطوة 6 — المراقبة والتدخّل​

      ابقَ منخرطًا — يعمل kanban بشكل مستقل لكن مهمة عالقة أو ناتج سيّئ يحتاج حكمًا بشريًا (أو حكم ذكاء اصطناعي).

      أنماط المراقبة: استطلع kanban list دوريًا، وافحص أي مهمة قيد التشغيل (RUNNING) تتجاوز مدتها المتوقعة باستخدام kanban show <id>، وتحقّق من نبضات القلب (heartbeats). عندما يفشل ناتج عامل في المراجعة، التدخّلات القياسية هي:

      1. علّق على مهمة العامل بملاحظات محددة (kanban_comment)
      2. أنشئ مهمة إعادة تشغيل مع المهمة الأصلية كأصل (parent) لها
      3. عدّل نطاق الملخص واترك المخرج يعيد تفكيك العمل

      لأنماط التشخيص، وسيناريوهات التدخّل، ودليل "المهمة عالقة"، انظر references/monitoring.md.

      مرجع: أمثلة عملية محلولة​

      ستة خطوط أنابيب ملموسة تغطي أساليب فيديو مختلفة جدًا — فيلم سردي، منتج/تسويق، فيديو موسيقي، شرح رياضي/خوارزمي، فيديو ASCII، تركيب مباشر (real-time) — توضّح كيف ينتج نفس سير العمل فرقًا ومخططات مهام مختلفة جدًا. انظر references/examples.md.

      قواعد حاسمة​

      1. الاستكشاف قبل الفعل. لا تبدأ أبدًا بتوليد ملخص أو فريق دون طرح الأسئلة الثلاثة الأساسية على الأقل. الملخص السيّئ يتسلسل خطأه عبر خط الأنابيب بالكامل.

      2. طابق الفريق مع الفيديو. لا تُعِد استخدام نفس إعداد الأربعة ملفات لكل عمل. الفيديو الموسيقي الذي لا يملك ملف تحليل نبضات سيفشل. الفيلم السردي الذي لا يملك ملف كاتب سينتج مشاهد غير متماسكة. انظر references/role-archetypes.md.

      3. مساحة عمل واحدة لكل مشروع. تشترك كل ملفات فيديو معيّن في نفس مساحة عمل dir:. تمرّر المهام الأصول عبر نظام ملفات مشترك وتسليمات منظّمة. يمرّر كل استدعاء kanban_create workspace_kind="dir" + workspace_path="<absolute project path>".

      4. استأجر (tenant) كل مشروع. استخدم مستأجرًا خاصًا بالمشروع (--tenant <project-slug>). يبقي لوحة التحكم محدودة النطاق ويمنع التداخل مع لوحات kanban الجارية الأخرى.

      5. احترم المهارات الموجودة. عندما يناسب مشهد ما مهارة موجودة، يجب أن يحمّل المُعرِّض المعني تلك المهارة عبر --skill <name> على مهمته أو always_load في ملفه. لا تُعِد اشتقاق ما توفّره مهارة موجودة بالفعل.

      6. المخرج لا ينفّذ أبدًا. حتى مع توفّر مجموعة أدوات kanban + terminal + file الكاملة، تمنع قواعد SOUL.md الخاصة بالمخرج تنفيذ العمل بنفسه. يفكّك ويوجّه فقط — تتحوّل كل مهمة ملموسة إلى استدعاء hermes kanban create لملف متخصص. توضّح إرشادات تنسيق kanban المحقونة تلقائيًا في system prompt لكل عامل kanban هذا بمزيد من التفصيل.

      7. لا تُفرط في التفكيك. فيديو منتج مدته 30 ثانية لا يحتاج 20 مهمة. اسعَ لأصغر مخطط مهام لا يزال يوازي العمل بشكل جيد ويكشف بوابات المراجعة البشرية الصحيحة.

      8. تحقّق من مفاتيح API قبل الإطلاق. تحتاج واجهات API الخارجية (TTS، توليد الصور، تحويل الصورة إلى فيديو) مفاتيح في ${HERMES_HOME:-~/.hermes}/.env أو مخزن أسرار المستخدم. العامل الذي يواجه خطأ مفتاح مفقود يهدر فتحة مهمة. تُلغي دالة check_key في سكربت الإعداد العملية بأمان إذا كان مفتاح مطلوب مفقودًا.
