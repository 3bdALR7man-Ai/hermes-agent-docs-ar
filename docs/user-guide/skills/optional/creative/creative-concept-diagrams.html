      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      Concept Diagrams

      توليد مخططات SVG بجودة إنتاجية باستخدام نظام تصميم مسطّح وبسيط وموحّد. الناتج ملف HTML واحد قائم بذاته يُعرض بشكل متطابق في أي متصفح حديث، مع تبديل تلقائي بين الوضعين الفاتح والداكن.

      النطاق​

      الأنسب لـ:

      • إعدادات الفيزياء، آليات الكيمياء، منحنيات الرياضيات، الأحياء
      • الأجسام المادية (الطائرات، التوربينات، الهواتف الذكية، الساعات الميكانيكية، الخلايا)
      • التشريح، المقاطع العرضية، عروض الطبقات المفكّكة
      • المخططات الطابقية، والتحويلات المعمارية
      • الرحلات السردية (دورة حياة X، عملية Y)
      • تكاملات الأنظمة بنمط hub-spoke (المدينة الذكية، شبكات إنترنت الأشياء، شبكات الكهرباء)
      • الصور التعليمية بأسلوب الكتب المدرسية في أي مجال
      • المخططات الكمّية (الأعمدة المجمّعة، مخططات الطاقة)

      ابحث في مكان آخر أولًا من أجل:

      • بنية برمجيات مخصّصة / بنية بنية تحتية سحابية بطابع تقني داكن (فكّر في architecture-diagram إن كانت متوفرة)
      • الرسومات اليدوية على السبورة البيضاء (فكّر في excalidraw إن كانت متوفرة)
      • الشروحات المتحركة أو مخرجات الفيديو (فكّر في مهارة رسوم متحركة)

      إن توفّرت مهارة أكثر تخصصًا للموضوع، فضّلها. إن لم تناسب أي مهارة، يمكن لهذه المهارة أن تكون حلًا احتياطيًا عامًا لمخططات SVG — إذ سيحمل الناتج الطابع التعليمي النظيف الموصوف أدناه، وهو خيار افتراضي معقول لمعظم الموضوعات.

      سير العمل​

      1. حدّد نوع المخطط (انظر أنواع المخططات أدناه).
      2. رتّب المكوّنات باتباع قواعد نظام التصميم.
      3. اكتب صفحة HTML الكاملة مستخدمًا templates/template.html كغلاف — والصق SVG الخاص بك في المكان الذي يشير إليه القالب بـ <!-- PASTE SVG HERE -->.
      4. احفظه كملف .html مستقل (على سبيل المثال ~/my-diagram.html أو ./my-diagram.html).
      5. يفتحه المستخدم مباشرة في المتصفح — دون خادم ودون اعتماديات.

      اختياري: إن أراد المستخدم معرض متصفَّح لعدة مخططات، انظر "خادم المعاينة المحلي" في الأسفل.

      حمّل قالب HTML:

      skill_view(name="concept-diagrams", file_path="templates/template.html")

      يضمّن القالب نظام تصميم CSS كاملًا (فئات الألوان c-*، فئات النصوص، متغيرات الوضعين الفاتح والداكن، أنماط رأس السهم). يعتمد SVG الذي تولّده على وجود هذه الفئات في الصفحة المضيفة.

      نظام التصميم​

      الفلسفة​

      • مسطّح: بلا تدرّجات لونية، ولا ظلال، ولا ضبابية، ولا توهّج أو تأثيرات نيون.
      • بسيط: أظهر الجوهري فقط. بلا أيقونات زخرفية داخل المربعات.
      • متّسق: نفس الألوان والتباعد والخطوط وعروض الحدود في كل مخطط.
      • جاهز للوضع الداكن: كل الألوان تتكيّف تلقائيًا عبر فئات CSS — بلا SVG منفصل لكل وضع.

      قواعد إسناد الألوان​

      اللون يعبّر عن المعنى، لا عن التسلسل. لا تتنقّل بين الألوان بطريقة قوس قزح.

      • جمّع العُقد حسب الفئة — كل عُقد من نفس النوع تشترك في لون واحد.
      • استخدم c-gray للعُقد المحايدة/البنيوية (البداية، النهاية، الخطوات العامة، المستخدمون).
      • استخدم 2-3 ألوان لكل مخطط، لا 6 أو أكثر.
      • فضّل c-purple، c-teal، c-coral، c-pink للفئات العامة.
      • خصّص c-blue، c-green، c-amber، c-red للمعنى الدلالي (معلومة، نجاح، تحذير، خطأ).

      تخصيص درجات التوقّف حسب الوضع (يتولّاه CSS الخاص بالقالب — فقط استخدم الفئة):

      • الوضع الفاتح: تعبئة بدرجة 50 + حدّ بدرجة 600 + عنوان بدرجة 800 / عنوان فرعي بدرجة 600
      • الوضع الداكن: تعبئة بدرجة 800 + حدّ بدرجة 200 + عنوان بدرجة 100 / عنوان فرعي بدرجة 200

      الطباعة​

      حجمان للخط فقط. بلا استثناءات.

      الفئةالحجمالوزنالاستخدام
      th14px500عناوين العُقد، تسميات المناطق
      ts12px400العناوين الفرعية، الأوصاف، تسميات الأسهم
      t14px400النص العام
      • حالة الجملة دائمًا (Sentence case). أبدًا Title Case، وأبدًا أحرف كبيرة بالكامل.
      • يجب أن يحمل كل <text> فئة (t أو ts أو th). لا نص بلا فئة.
      • dominant-baseline="central" على كل نص داخل المربعات.
      • text-anchor="middle" للنص المُمركز داخل المربعات.

      تقدير العرض (تقريبيًا):

      • 14px بوزن 500: ~8px لكل حرف
      • 12px بوزن 400: ~6.5px لكل حرف
      • تحقّق دائمًا من: box_width >= (char_count × px_per_char) + 48 (24px حشوة من كل جانب)

      التباعد والتخطيط​

      • ViewBox: viewBox="0 0 680 H" حيث H = ارتفاع المحتوى + هامش وقائي 40px.
      • المنطقة الآمنة: من x=40 إلى x=640، ومن y=40 إلى y=(H-40).
      • بين المربعات: فجوة لا تقل عن 60px.
      • داخل المربعات: حشوة أفقية 24px، وحشوة رأسية 12px.
      • فجوة رأس السهم: 10px بين رأس السهم وحافة المربع.
      • مربع أحادي السطر: ارتفاع 44px.
      • مربع ثنائي السطر: ارتفاع 56px، مع 18px بين خطوط أساس العنوان والعنوان الفرعي.
      • حشوة الحاوية: 20px كحدّ أدنى داخل كل حاوية.
      • أقصى تعشيش: 2-3 مستويات. أي تعشيش أعمق يصبح غير قابل للقراءة عند عرض 680px.

      الحدود والأشكال​

      • عرض الحدّ: 0.5px على كل حدود العُقد. ليس 1px، وليس 2px.
      • تدوير المستطيلات: rx="8" للعُقد، rx="12" للحاويات الداخلية، ومن rx="16" إلى rx="20" للحاويات الخارجية.
      • مسارات الموصّلات: يجب أن تحمل fill="none". وإلا فإن SVG يستخدم افتراضيًا fill: black.

      رأس السهم (Arrow Marker)​

      ضمّن كتلة <defs> هذه في بداية كل SVG:

      <defs>
        <marker id="arrow" viewBox="0 0 10 10" refX="8" refY="5"
                markerWidth="6" markerHeight="6" orient="auto-start-reverse">
          <path d="M2 1L8 5L2 9" fill="none" stroke="context-stroke"
                stroke-width="1.5" stroke-linecap="round" stroke-linejoin="round"/>
        </marker>
      </defs>

      استخدم marker-end="url(#arrow)" على الخطوط. يرث رأس السهم لون الخط عبر context-stroke.

      فئات CSS (التي يوفّرها القالب)​

      توفّر صفحة القالب:

      • النصوص: .t, .ts, .th
      • المحايدة: .box, .arr, .leader, .node
      • تدرّجات الألوان: .c-purple, .c-teal, .c-coral, .c-pink, .c-gray, .c-blue, .c-green, .c-amber, .c-red (جميعها مع تبديل تلقائي بين الوضعين الفاتح والداكن)

      لست بحاجة لإعادة تعريف هذه الفئات — فقط طبّقها في SVG الخاص بك. يحتوي ملف القالب على تعريفات CSS الكاملة.

      الهيكل الأساسي لـ SVG​

      يبدأ كل SVG داخل صفحة القالب بهذه البنية بالضبط:

      <svg width="100%" viewBox="0 0 680 {HEIGHT}" xmlns="http://www.w3.org/2000/svg">
        <defs>
          <marker id="arrow" viewBox="0 0 10 10" refX="8" refY="5"
                  markerWidth="6" markerHeight="6" orient="auto-start-reverse">
            <path d="M2 1L8 5L2 9" fill="none" stroke="context-stroke"
                  stroke-width="1.5" stroke-linecap="round" stroke-linejoin="round"/>
          </marker>
        </defs>

        <!-- Diagram content here -->

      </svg>

      استبدل {HEIGHT} بالارتفاع الفعلي المحسوب (أسفل آخر عنصر + 40px).

      أنماط العُقد​

      عُقدة أحادية السطر (44px):

      <g class="node c-blue">
        <rect x="100" y="20" width="180" height="44" rx="8" stroke-width="0.5"/>
        <text class="th" x="190" y="42" text-anchor="middle" dominant-baseline="central">Service name</text>
      </g>

      عُقدة ثنائية السطر (56px):

      <g class="node c-teal">
        <rect x="100" y="20" width="200" height="56" rx="8" stroke-width="0.5"/>
        <text class="th" x="200" y="38" text-anchor="middle" dominant-baseline="central">Service name</text>
        <text class="ts" x="200" y="56" text-anchor="middle" dominant-baseline="central">Short description</text>
      </g>

      موصّل (بلا تسمية):

      <line x1="200" y1="76" x2="200" y2="120" class="arr" marker-end="url(#arrow)"/>

      حاوية (متقطعة أو صلبة):

      <g class="c-purple">
        <rect x="40" y="92" width="600" height="300" rx="16" stroke-width="0.5"/>
        <text class="th" x="66" y="116">Container label</text>
        <text class="ts" x="66" y="134">Subtitle info</text>
      </g>

      أنواع المخططات​

      اختر التخطيط الذي يناسب الموضوع:

      1. مخطط تدفّق (Flowchart) — خطوط CI/CD، دورات حياة الطلبات، سير عمل الموافقات، معالجة البيانات. تدفّق باتجاه واحد (من الأعلى للأسفل أو من اليسار لليمين). حد أقصى 4-5 عُقد لكل صف.
      2. البنية / الاحتواء — تعشيش البنية التحتية السحابية، بنية النظام ذات الطبقات. حاويات خارجية كبيرة مع مناطق داخلية. مستطيلات متقطعة للتجميعات المنطقية.
      3. خريطة API / Endpoint — مسارات REST، مخططات GraphQL. شجرة من الجذر، تتفرّع إلى مجموعات موارد، كل واحدة تحتوي عُقد endpoint.
      4. طوبولوجيا الخدمات المصغّرة (Microservice) — شبكة خدمات، أنظمة قائمة على الأحداث. الخدمات كعُقد، وأسهم لأنماط الاتصال، وطوابير رسائل بينها.
      5. تدفّق البيانات — خطوط ETL، بنى البث المباشر. تدفّق من اليسار لليمين من المصادر عبر المعالجة إلى الوجهات.
      6. مادي / بنيوي — المركبات، المباني، الأجهزة، التشريح. استخدم أشكالًا تطابق الصورة المادية — <path> للأجسام المنحنية، <polygon> للأشكال المدبّبة، <ellipse>/<circle> للأجزاء الأسطوانية، ومستطيلات <rect> متداخلة للحجرات. انظر references/physical-shape-cookbook.md.
      7. البنية التحتية / تكامل الأنظمة — المدن الذكية، شبكات إنترنت الأشياء، الأنظمة متعددة المجالات. تخطيط hub-spoke بمنصة مركزية تربط الأنظمة الفرعية. أنماط خطوط دلالية (.data-line، .power-line، .water-pipe، .road). انظر references/infrastructure-patterns.md.
      8. نماذج واجهة المستخدم / لوحات التحكم — لوحات الإدارة، لوحات المراقبة. إطار شاشة مع عناصر مخططات/عدادات/مؤشرات متداخلة. انظر references/dashboard-patterns.md.

      بالنسبة للمخططات المادية ومخططات البنية التحتية ولوحات التحكم، حمّل ملف المرجع المطابق قبل التوليد — إذ يوفّر كل منها فئات CSS جاهزة وأشكالًا أساسية.

      قائمة تحقّق التحقّق​

      قبل إنهاء أي SVG، تحقّق من كل ما يلي:

      1. كل <text> يحمل فئة t أو ts أو th.
      2. كل <text> داخل مربع يحمل dominant-baseline="central".
      3. كل موصّل <path> أو <line> مستخدم كسهم يحمل fill="none".
      4. لا يعبر أي خط سهم عبر مربع غير مرتبط.
      5. box_width >= (longest_label_chars × 8) + 48 للنص بحجم 14px.
      6. box_width >= (longest_label_chars × 6.5) + 48 للنص بحجم 12px.
      7. ارتفاع ViewBox = أسفل العنصر الأدنى + 40px.
      8. كل المحتوى ضمن x=40 إلى x=640.
      9. فئات الألوان (c-*) موجودة على <g> أو عناصر الأشكال، أبدًا على موصّلات <path>.
      10. كتلة السهم <defs> موجودة.
      11. بلا تدرّجات لونية، أو ظلال، أو ضبابية، أو توهّج.
      12. عرض الحدّ 0.5px على كل حدود العُقد.

      المخرجات والمعاينة​

      الافتراضي: ملف HTML مستقل​

      اكتب ملف .html واحد يمكن للمستخدم فتحه مباشرة. بلا خادم، بلا اعتماديات، ويعمل دون اتصال. النمط:

      # 1. Load the template
      template = skill_view("concept-diagrams", "templates/template.html")

      # 2. Fill in title, subtitle, and paste your SVG
      html = template.replace(
          "<!-- DIAGRAM TITLE HERE -->", "SN2 reaction mechanism"
      ).replace(
          "<!-- OPTIONAL SUBTITLE HERE -->", "Bimolecular nucleophilic substitution"
      ).replace(
          "<!-- PASTE SVG HERE -->", svg_content
      )

      # 3. Write to a user-chosen path (or ./ by default)
      write_file("./sn2-mechanism.html", html)

      أخبر المستخدم كيف يفتحه:

      # macOS
      open ./sn2-mechanism.html
      # Linux
      xdg-open ./sn2-mechanism.html

      اختياري: خادم معاينة محلي (معرض متعدد المخططات)​

      استخدم هذا فقط عندما يريد المستخدم صراحة معرضًا متصفَّحًا لعدة مخططات.

      القواعد:

      • اربط بـ 127.0.0.1 فقط. أبدًا 0.0.0.0. كشف المخططات على كل واجهات الشبكة يمثّل خطرًا أمنيًا على الشبكات المشتركة.
      • اختر منفذًا حرًا (لا تُثبّت رقمه في الكود) وأخبر المستخدم بالرابط المختار.
      • الخادم اختياري وبموافقة صريحة — فضّل ملف HTML المستقل أولًا.

      النمط الموصى به (يترك نظام التشغيل يختار منفذًا حرًا مؤقتًا):

      # Put each diagram in its own folder under .diagrams/
      mkdir -p .diagrams/sn2-mechanism
      # ...write .diagrams/sn2-mechanism/index.html...

      # Serve on loopback only, free port
      cd .diagrams && python -c "
      import http.server, socketserver
      with socketserver.TCPServer(('127.0.0.1', 0), http.server.SimpleHTTPRequestHandler) as s:
          print(f'Serving at http://127.0.0.1:{s.server_address[1]}/')
          s.serve_forever()
      " &

      إن أصرّ المستخدم على منفذ ثابت، استخدم 127.0.0.1:<port> — دون 0.0.0.0 أبدًا. وثّق كيفية إيقاف الخادم (kill %1 أو pkill -f "http.server").

      مرجع سريع: ماذا تستخدم ومتى​

      يقول المستخدمنوع المخططالألوان المقترحة
      "show the pipeline"مخطط تدفّقرمادي للبداية/النهاية، بنفسجي للخطوات، أحمر للأخطاء، تركواز للنشر
      "draw the data flow"خط أنابيب بيانات (يسار-يمين)رمادي للمصادر، بنفسجي للمعالجة، تركواز للوجهات
      "visualize the system"بنيوي (احتواء)حاوية بنفسجية، خدمات تركوازية، بيانات مرجانية
      "map the endpoints"شجرة APIجذر بنفسجي، تدرّج لوني واحد لكل مجموعة موارد
      "show the services"طوبولوجيا خدمات مصغّرةرمادي للمدخل، تركواز للخدمات، بنفسجي للناقل، مرجاني للعمّال
      "draw the aircraft/vehicle"ماديمسارات وأشكال مضلّعة وإهليلجية لأشكال واقعية
      "smart city / IoT"تكامل hub-spokeأنماط خطوط دلالية لكل نظام فرعي
      "show the dashboard"نموذج واجهة مستخدمشاشة داكنة، ألوان المخططات: تركواز، بنفسجي، مرجاني للتنبيهات
      "power grid / electricity"تدفّق متعدد المراحلتسلسل هرمي للجهد (أوزان خطوط HV/MV/LV)
      "wind turbine / turbine"مقطع عرضي ماديالأساس + مقطع البرج + النصلة المروحية بترميز لوني
      "journey of X / lifecycle"رحلة سرديةمسار متعرّج، تغيّرات حالة تدريجية
      "layers of X / exploded"عرض طبقات مفكّكتكديس رأسي، تسميات متبادلة
      "CPU / pipeline"خط أنابيب أجهزةمراحل رأسية، تفرّع إلى منافذ التنفيذ
      "floor plan / apartment"مخطط طابقيالجدران، الأبواب، التغييرات المقترحة بخط أحمر منقّط
      "reaction mechanism"كيمياءالذرات، الروابط، أسهم منحنية، حالة انتقالية، مخطط طاقة
