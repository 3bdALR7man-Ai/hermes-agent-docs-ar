      الإنجليزية المبسّطة (Simple English)

      أعِد صياغة النص إلى إنجليزية تقنية مبسّطة وفق معيار ASD-STE100.

      بيانات المهارة الوصفية​

      المصدراختيارية — ثبّتها باستخدام hermes skills install official/creative/simple-english

      الإصدار1.2.0

      المرجع: ملف SKILL.md كاملًا​

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      الإنجليزية المبسّطة: اكتب كما لو كنت تكتب دليل طيران

      اكتب النص التقني وفق قواعد ASD-STE100 Simplified Technical English. الـ STE هي اللغة المضبوطة التي تستخدمها الشركات المصنّعة في مجالَي الطيران والدفاع لوثائق الصيانة. توجد هذه القواعد حتى لا يُخطئ قارئ متعب وليس ناطقًا أصليًا بالإنجليزية في فهم تعليمة ما. وهي تزيل كأثر جانبي العلامات المعتادة للنص المولّد بالذكاء الاصطناعي: الجمل الطويلة، وتناوب المرادفات، والتحوّطات، والحشو، والعبارات الزخرفية.

      اكتب من أجل ذلك القارئ المتعب. يجب أن تصمد كل جملة أمام قراءة واحدة.

      كيفية استخدامها في Hermes​

      يصل النص عادة بواحدة من ثلاث طرق:

      1. مضمّن في الرسالة. يلصق المستخدم النص في الرسالة. أعِد صياغته في مكانه ورُدّ بالنتيجة.
      2. ملف. يشير المستخدم إلى ملف (README، دليل تشغيل، صفحة توثيق). استخدم read_file لتحميله، ثم patch لإعادة صياغة أقسام محدّدة أو write_file لإعادة صياغة كاملة. لا تلمس أبدًا كتل الكود أو المعرّفات أو الأخطاء المقتبسة (راجع قسم ما لا يُمَسّ).
      3. وضع الفحص. يطلب منك المستخدم تدقيق النص للتحقّق من التوافق مع STE بدلًا من إعادة صياغته. أبلغ عن كل مخالفة بصيغة: رقم القاعدة + النص المخالف + إعادة صياغة متوافقة، مستخدمًا references/checklist.md.

      تختلف هذه المهارة عن humanizer: يعيد humanizer الصوت الإنساني الطبيعي؛ بينما تفرض simple-english لغة مضبوطة للتعليمات التقنية. للوثائق وأدلة التشغيل ورسائل الأخطاء استخدم هذه المهارة. أما للتدوينات والمقالات والكتابة الشخصية فاستخدم humanizer. لا تطبّق كلتيهما على النص نفسه.

      مهمتك​

      عند الطلب منك كتابة أو إعادة صياغة نص تقني:

      1. اختر النمط (عملي أو صارم، أدناه).
      2. صنّف كل مقطع إلى إجرائي أو وصفي. تعتمد كل القواعد الأخرى على هذا التصنيف.
      3. صحّح مفرداتك قبل الصياغة. في النمط الصارم، استخدم make sure that لمفهوم check/verify/confirm/ensure — يرفض القاموس الكلمات الأربع كأفعال. في النمط العملي، اختر واحدة والتزم بها. اختر اسمًا واحدًا (NOUN) لـ config/settings (كلها أسماء تقنية صحيحة — اختر واحدًا والتزم به). لا تستخدم أي كلمة أخرى لهذين المفهومين في المستند كله.
      4. طبّق القواعد من الكتالوج أدناه.
      5. نفّذ الفحص الذاتي قبل التسليم. هذه الخطوة ليست اختيارية.
      6. لا تلمس أبدًا الكود أو المعرّفات أو الأوامر أو الأخطاء المقتبسة (راجع قسم ما لا يُمَسّ).

      عند الطلب منك فحص النص بدلًا من كتابته، أبلغ عن كل مخالفة كالتالي: رقم القاعدة، النص المخالف، إعادة صياغة متوافقة. استشهد فقط بأرقام قواعد موجودة في هذا الملف. لا تستشهد بأرقام قواعد من الذاكرة: الترقيم غير بديهي وتخترعه النماذج (اختُبر ذلك — استشهد وكيل بلا هذا الملف بـ"Rule 3.1: short sentences"؛ بينما القاعدة 3.1 الحقيقية تتعلّق بصيغ الأفعال).

      نمطان​

      النمطمتىما تطبّقه
      عملي (الافتراضي)الوثائق، ملفات README، رسائل الأخطاء — يريد المستخدم نصًا واضحًاكل القواعد البنيوية. تبقى كلمات المجال ("idempotent", "webhook").
      صارميذكر المستخدم STE أو ASD-STE100 أو التوافقالقواعد البنيوية + انضباط مفرداتي كامل، وأخبر المستخدم أن التوافق الكامل يتطلّب القاموس الرسمي (مجاني على asd-ste100.org).

      الخطوة 1: صنّف النص​

      إجرائي (تعليمات)وصفي (شروحات)
      الغرضإخبار القارئ بما يفعلهشرح ماهية شيء أو وظيفته
      صيغة الفعلأمر: "Install the pump."مضارع/ماضٍ/مستقبل بسيط
      حدّ الجملة20 كلمة (القاعدة 5.1)25 كلمة (القاعدة 6.3)
      قاعدة الوحدةتعليمة واحدة لكل جملة (5.2)موضوع واحد لكل فقرة (6.5)، حد أقصى ست جمل لكل فقرة (6.6)

      لا تخلط بين الاثنين في مقطع واحد. قسم "البدء" إجرائي. قسم "البنية المعمارية" وصفي. ملاحظة داخل إجراء وصفية (حد 25 كلمة، بلا صيغة أمر).

      كتالوج القواعد​

      53 قاعدة في 9 أقسام، مُعاد صياغتها من ASD-STE100 الإصدار 9 مع أمثلة برمجية. النص الرسمي موجود في المعيار المجاني على asd-ste100.org.

      القسم 1 — الكلمات (القواعد 1.1-1.14)​

      القاعدةالتعليمة
      1.1استخدم فقط كلمات معتمدة أو أسماء تقنية أو أفعالًا تقنية.
      1.2استخدم الكلمة المعتمدة فقط بصنفها اللغوي المُدرَج.
      1.3استخدم الكلمة المعتمدة فقط بمعناها المعتمد.
      1.4استخدم فقط الصيغ المعتمدة للأفعال والصفات.
      1.5يمكنك استخدام كلمات المجال كأسماء تقنية ("webhook", "commit", "endpoint").
      1.6استخدم الكلمة غير المعتمدة فقط عندما تكون اسمًا تقنيًا أو جزءًا منه.
      1.7لا تستخدم الأسماء التقنية كأفعال.
      1.8استخدم الأسماء التقنية الخاصة بمشروعك أو مجال عملك.
      1.9عندما تختار اسمًا تقنيًا، اختر واحدًا قصيرًا وواضحًا.
      1.10لا كلمات إقليمية أو عامّية أو مصطلحات مهنية ضيقة كأسماء تقنية.
      1.11عنصر واحد، اسم واحد. لا تسمّه "config" هنا و"settings" هناك.
      1.12يمكنك استخدام أفعال المجال كأفعال تقنية ("deploy", "compile", "merge").
      1.13لا تستخدم الأفعال التقنية كأسماء.
      1.14استخدم الإملاء الإنجليزي الأمريكي.

      في النمط العملي، تقوم القواعد 1.5 و1.8 و1.12 بمعظم العمل: مفرداتك الخاصة بالمجال مشروعة. أما القواعد التي يخالفها الوكلاء فهي 1.7 و1.11 و1.13.

      قبل: You can webhook the event, then do a deploy. بعد: Send the event to the webhook. Then deploy the service.

      القسم 2 — الأسماء متعددة الكلمات (القواعد 2.1-2.2)​

      القاعدةالتعليمة
      2.1اكتب الأسماء متعددة الكلمات بثلاث كلمات أو أقل.
      2.2عندما يحتاج اسم تقني إلى أكثر من ثلاث كلمات، اكتبه كاملًا مرة واحدة، ثم أعطِ صيغة مختصرة أو صِل الوحدات بشرطة.

      افصل سلاسل الأسماء الطويلة بحروف الجر (of, on, in, for):

      قبل: the connection pool timeout configuration value بعد: the timeout value for the connection pool

      القسم 3 — الأفعال (القواعد 3.1-3.7)​

      القاعدةالتعليمة
      3.1استخدم فقط صيغ الأفعال التي يعطيها القاموس.
      3.2استخدم فقط: المصدر، الأمر، المضارع البسيط، الماضي البسيط، المستقبل البسيط، اسم المفعول كصفة.
      3.3استخدم اسم المفعول فقط كصفة ("the cached response").
      3.4لا أفعال مساعدة للتراكيب المعقّدة. لا حاضر تام، ولا "is to be installed".
      3.5استخدم صيغة "-ing" فقط كاسم تقني أو داخله ("logging", "the mounting bracket") — لا كفعل أبدًا.
      3.6المبني للمعلوم. في النص الوصفي، المبني للمجهول مقبول فقط عندما يكون الفاعل غير معروف.
      3.7صف الفعل بفعل، لا باسم ("compress the file"، لا "perform compression of the file").

      الأفعال المساعدة المعتمدة: can، will، must. الممنوعة: should، would، may، might، could (القاعدة 3.2). يرفض المعيار "could" حتى للاحتمال: اكتب "an explosion can occur"، لا "could occur" أبدًا. أما "should": يصبح المتطلَّب "must"؛ ويُذكر الاقتراح كحقيقة أو يُحذف. يهم هذا مضاعفًا لتعليمات الوكلاء — تقرأ النماذج "should" على أنها اختيارية.

      قبل: The migration has completed and the table is being rebuilt. بعد: The migration is complete. The database rebuilds the table.

      قبل: The flag can be set in the config file, making restarts unnecessary. بعد: You can set the flag in the config file. Then a restart is not necessary.

      قبل: The temperature must be adjusted. بعد: Adjust the temperature.

      القسم 4 — الجمل (القواعد 4.1-4.5)​

      القاعدةالتعليمة
      4.1اكتب جملًا قصيرة وواضحة.
      4.2لا تحذف الكلمات ولا تستخدم الاختصارات (contractions) لتقصير الجمل. أبقِ أدوات التعريف، وأبقِ "that".
      4.3استخدم قائمة عمودية للنص المعقّد.
      4.4استخدم كلمات ربط بين الجمل ذات المواضيع المترابطة ("Then", "As a result").
      4.5ضع أداة تعريف (the, a, an) أو صفة إشارة (this, these) قبل الأسماء عند الاقتضاء.

      القاعدة 4.2 هي قاعدة مناهضة الاقتضاب. الـ STE جمل قصيرة بقواعد نحوية كاملة، لا أسلوب برقي:

      اختصار خاطئ: Ensure file exists before running. STE: Make sure that the file exists before you run the command.

      القسم 5 — الكتابة الإجرائية (القواعد 5.1-5.5)​

      القاعدةالتعليمة
      5.120 كلمة كحد أقصى لكل جملة. يشمل ذلك التحذيرات والتنبيهات.
      5.2تعليمة واحدة لكل جملة، إلا إذا حدث إجراءان في الوقت نفسه.
      5.3اكتب التعليمات بصيغة الأمر: "Run the migration."
      5.4ضع الشرط المطلوب قبل الأمر، مفصولًا بفاصلة: "If the build fails, read the log."
      5.5الملاحظات تعطي معلومة، لا تعليمات أبدًا. تخضع الملاحظات لحد 25 كلمة.

      قبل: You'll want to grab the API key from the dashboard before configuring the client, which you can do under Settings. بعد: Get the API key from the dashboard, under Settings. Then configure the client with this key.

      القسم 6 — الكتابة الوصفية (القواعد 6.1-6.6)​

      القاعدةالتعليمة
      6.1أعطِ المعلومة تدريجيًا: حقيقة جديدة واحدة لكل جملة.
      6.2استخدم كلمات وعبارات مفتاحية لإعطاء النص بنية منطقية.
      6.325 كلمة كحد أقصى لكل جملة.
      6.4اجمع المعلومات المترابطة في فقرات.
      6.5موضوع واحد لكل فقرة.
      6.6ست جمل كحد أقصى لكل فقرة.

      لا صيغة أمر في النص الوصفي. الشروحات تشرح؛ والإجراءات تُصدر تعليمات.

      القسم 7 — تعليمات السلامة (القواعد 7.1-7.3)​

      القاعدةالتعليمة
      7.1استخدم كلمة تُظهر مستوى الخطر ("WARNING" = إصابة، "CAUTION" = ضرر).
      7.2ابدأ بأمر أو شرط واضح.
      7.3ثم أعطِ الخطر أو النتيجة المحتملة.

      لا تدفن التعليمة أبدًا بعد الشرح. ينتقل هذا النمط مباشرة إلى أعلام (flags) سطر الأوامر المدمّرة، والترحيلات (migrations) التي لا رجعة فيها، وخيارات API الخطرة.

      قبل: Note that data loss may occur in some circumstances if the destructive flag happens to be enabled when running against production. بعد: CAUTION: Do not use the --force flag against production. The flag deletes rows that do not match the source.

      القسم 8 — علامات الترقيم وعدّ الكلمات (القواعد 8.1-8.7)​

      القاعدةالتعليمة
      8.1كل علامات الترقيم القياسية مشروعة إلا الفاصلة المنقوطة. اكتب جملتين بدلًا منها.
      8.2استخدم الشرطات لربط الكلمات التي تعمل كوحدة واحدة.
      8.3الأقواس مشروعة للمراجع، وأرقام العناصر، والاختصارات، وصيغ الجمع، والشروحات، والبدائل.
      8.4في القائمة العمودية، تنهي النقطتان الرأسيتان الاستهلاليتان جملة لغرض عدّ الكلمات.
      8.5يُحسب النص داخل الأقواس ككلمة واحدة.
      8.6يُحسب كل مما يلي ككلمة واحدة: الأرقام، الأرقام مع الوحدات، الاختصارات، المعرّفات الأبجدية الرقمية، النص المقتبس، العناوين، التسميات، الأسماء العلَم.
      8.7تُحسب الكلمة الموصولة بشرطة ككلمة واحدة.

      القاعدة 8.6 مهمة للنص البرمجي: يُعدّ sqlpipe run --config sqlpipe.yaml بين علامتَي اقتباس مائل نصًا مقتبسًا ويُحسب ككلمة واحدة. المعرّفات الطويلة لا تستهلك رصيد جملتك.

      القسم 9 — ممارسات الكتابة (القواعد 9.1-9.4، GR-1 إلى GR-8)​

      القاعدةالتعليمة
      9.1عندما لا ينجح الاستبدال كلمة بكلمة، أعِد بناء الجملة.
      9.2استخدم كل كلمة معتمدة بشكل صحيح: بمعناها المعتمد وصنفها اللغوي المعتمد.
      9.3لا تبنِ أفعالًا مركّبة ("go down" ← "decrease", "set up" ← "install" أو "configure").
      9.4حافظ على أسلوب ومصطلحات ثابتة عبر المستند كله.

      التوصيات العامة GR-1 إلى GR-8: أبقِ حرف العطف "that"، وكن حذرًا مع "with"، وأعطِ الضمائر مرجعيات واضحة، وفضّل "this + اسم" على "this" المجرّدة، وتجنّب الأصدقاء الزائفين (false friends)، وتجنّب الاختصارات اللاتينية، واستخدم لغة شاملة، واستخدم صيغة الملكية بالفاصلة العليا فقط عندما تكون متأكدًا من صحتها (GR-8: إن لم تكن متأكدًا، لا تستخدمها — يجدها القراء غير الناطقين الأصليين صعبة).

      GR-6 للوثائق البرمجية: "e.g." ← "for example"، "i.e." ← "that is"، واحذف "etc." — سمِّ العناصر أو اكتب "and more".

      الانضباط المفرداتي​

      القاموس الرسمي (نحو 900 كلمة معتمدة، ونحو 1200 كلمة ممنوعة مع بدائل) محمي بحقوق نشر تابعة لـ ASD ولا يُستنسخ هنا. تنطبق آلياته من دونه: كلمة واحدة، معنى واحد، صنف لغوي واحد.

      أحكام أصناف لغوية معروفة، مفيدة كأنماط:

      الكلمةالحكم
      test, check, workاسم فقط. "Do a test"، لا "test the pump". تصبح "Check that X" هي "make sure that X".
      oilاسم تقني (TN) فقط. أما الفعل، فيعطي القاموس "lubricate": "Lubricate the linkage with oil."

      مراجعة الاتساق​

      وحّد تناوبات المرادفات إلى مصطلح واحد لكل منها (القاعدتان 1.11، 9.4). تعمل القائمتان أدناه بشكل مختلف.

      أسماء تقنية — غير موجودة في القاموس. اختر واحدًا والتزم به (في كلا النمطين):

      • config / configuration / settings / options ← اختر واحدة

      أحكام القاموس — اختار المعيار بالفعل. استخدم الكلمة المعتمدة (النمط الصارم)؛ اختر واحدة والتزم بها (النمط العملي):

      ما كتبتهحالة القاموساستخدم بدلًا منها
      check (فعل) / verify / confirm / ensureمرفوضة جميعًا كأفعالmake sure that (صارم)؛ اختر واحدة (عملي)
      validateغير موجودة في القاموساستخدمها كفعل تقني (القاعدة 1.12)، أو استبدلها بـ make sure that
      delete / drop (فعل) / destroyمرفوضة جميعًاerase (للبيانات)، remove (للمادي)؛ تجنّب drop وdestroy
      removeفعل معتمدأبقِها
      run / executeمرفوضتان معًاoperate لـ run، وdo لـ execute (صارم)؛ اختر واحدة (عملي)
      invoke / launchغير موجودتين في القاموساستخدمهما كفعلين تقنيين (القاعدة 1.12)
      display (فعل) / render / present (فعل)مرفوضة جميعًاshow (فعل معتمد)
      issueغير موجودة في القاموساستخدمها كاسم تقني، أو استبدلها بـ problem (معتمدة)
      failureمرفوضة في الاستخدام العام؛ معتمدة كاسم تقني لفقدان الأداءاستخدمها فقط عندما تعني خطأ أداء: "a failure of the pump"
      errorاسم معتمدأبقِها
      problemاسم معتمدأبقِها

      ما لا يُمَسّ​

      هذه أسماء تقنية (القاعدتان 1.5، 8.6). اتركها كما هي بالضبط، حتى إن خالفت قواعد المفردات:

      • كتل الكود، الكود المضمّن، المعرّفات، أوامر CLI، الأعلام (flags)، مسارات الملفات
      • رسائل الأخطاء المقتبسة وسطور السجلّ (log)
      • أسماء المنتجات، أسماء نقاط نهاية API، مفاتيح الإعدادات
      • الأرقام مع الوحدات — يُحسب كل منها ككلمة واحدة في حدّ الجملة

      أبعد من التوثيق​

      القواعد نفسها، أهداف مختلفة. تكييفات كاملة في references/use-cases.md:

      • رسائل الأخطاء: اذكر ما حدث (الماضي البسيط)، ثم السبب إن كان معروفًا، ثم الحل بصيغة الأمر. لا "Oops"، ولا "Please ensure"، ولا حشو اعتذاري.
      • أدلة التشغيل (Runbooks): الميدان الأصلي للـ STE. خطوات بصيغة الأمر، الشروط أولًا، التحذيرات قبل الخطوة.
      • تقارير الحوادث: الماضي البسيط فقط. تصبح "We have identified an issue that may have impacted" هي "Between 14:02 and 14:31 UTC, 12% of requests failed."
      • ملاحظات الإصدار: تتبع التغييرات الجذرية (breaking changes) نمط التحذير — الأمر أولًا، الخطر ثانيًا.
      • تعليمات الوكلاء (الـ prompts، AGENTS.md): الـ system prompt إجراء لقارئ لا يستطيع طرح أسئلة. تعليمة واحدة لكل جملة، بلا "should"، الشرط أولًا.
      • تحضير الترجمة: المهمة الأصلية للـ STE. معنى واحد لكل كلمة إضافة إلى نحو كامل يُزيل معظم غموض الترجمة.

      الفحص الذاتي قبل التسليم​

      هذه الخطوة ليست اختيارية. نفّذ هذه الفحوصات الأربعة على مسودّتك:

      1. عُدّ الكلمات في أطول ثلاث جمل لديك. إن تجاوزت حدّ 20/25 ← قسّمها.
      2. ابحث في مسودّتك عن: 'll، 're، 's (اختصار)، has been، have been، should، أفعال -ing بعد فاصلة، الفواصل المنقوطة.
      3. ابحث عن كل if وwhen. يجب أن يقف كل منهما في بداية جملته، قبل الأمر. تصبح "Increase the timeout if the network is slow" هي "If the network is slow, increase the timeout."
      4. ابحث عن الأفعال التي لم تخترها في الخطوة 3 من "مهمتك" (مجموعة check/verify/confirm). استبدل كل نتيجة بفعلك المختار.

      أصلح ما تجده، ثم سلّم. لتدقيق كامل، شغّل references/checklist.md.

      مثال كامل​

      قبل (ناتج ذكاء اصطناعي حقيقي غير مُحرَّر):

      Connection timeouts. If sqlpipe hangs or fails with dial tcp: i/o timeout, check that the host running sqlpipe can reach the Postgres port (usually 5432) — this is often a security group or firewall rule blocking the connection. If you're connecting to a managed database (RDS, Cloud SQL, etc.), confirm the instance allows connections from sqlpipe's IP. You can also try increasing source.connect_timeout_seconds in your config, since a slow network path can trip the default timeout even when the connection eventually succeeds.

      بعد (مصنَّف إجرائيًا، الفعل = "make sure"، الشروط أولًا، تعليمة واحدة لكل جملة):

      Connection timeouts. sqlpipe stops with dial tcp: i/o timeout when it cannot reach the Postgres port (5432 by default).

      1. Make sure that the host that runs sqlpipe can reach the Postgres port. A firewall or security group usually blocks it.
      2. If the database is managed (RDS, Cloud SQL), make sure that the instance accepts connections from the IP of sqlpipe.
      3. If the network is slow, increase source.connect_timeout_seconds in the configuration.

      ما تغيّر: قُسّمت الجمل ذات الـ40 كلمة إلى ما دون 20؛ وسُّعت "you're"؛ اختُزلت "check/confirm" إلى "make sure that"؛ نُقل كل شرط قبل أمره؛ حُذفت "etc."؛ ولم يُمسّ الكود وسلاسل الأخطاء.

      الحدود​

      الـ STE مخصّصة للحقائق والتعليمات التقنية. لا تطبّقها على نصوص تسويقية، أو صوت تدوينات، أو كتابة العلامة التجارية — فهي تحذف الإقناع بالتصميم. عندما يطلب مستخدم STE على نص تسويقي، أخبره بذلك واعرض تطبيقها على الوثائق بدلًا من ذلك.

      هذه المهارة أداة غير رسمية. وهي غير تابعة لـ ASD أو STEMG ولا معتمدة منهما، ولا يمكن لأي أداة ضمان التوافق مع STE. علامة ASD-STE100 التجارية مسجّلة باسم ASD. المعيار الرسمي متاح للتنزيل مجانًا على asd-ste100.org.
