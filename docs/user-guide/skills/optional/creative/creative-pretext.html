      ابنِ عروضًا تجريبية إبداعية في المتصفح مع تخطيط نص بلا DOM.

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      عروض Pretext الإبداعية التجريبية

      نظرة عامة​

      @chenglou/pretext مكتبة TypeScript بحجم 15KB بلا أي اعتماديات من تأليف Cheng Lou (من فريق نواة React، وReasonML، وMidjourney)، مخصّصة لقياس النص متعدد الأسطر وتخطيطه بلا DOM. تقوم بشيء واحد فقط: بإعطائها (text, font, width)، تُعيد مواضع فواصل الأسطر، وعرض كل سطر، ومواضع كل حرف رسمي (grapheme)، والارتفاع الإجمالي — كل ذلك عبر قياس بالـ canvas، بلا إعادة تدفق (reflow).

      يبدو هذا كعمل بنية تحتية بحتة. لكنه ليس كذلك، فبفضل سرعتها وطبيعتها الهندسية تُعدّ لبنة إبداعية أساسية: يمكنك إعادة تدفق الفقرات حول عنصر متحرك بمعدل 60 إطارًا في الثانية، أو بناء ألعاب تكون هندسة مستوياتها مكوّنة من كلمات حقيقية، أو تحريك شعارات ASCII عبر النثر، أو تفتيت النص إلى جسيمات بمواضع بداية دقيقة لكل حرف رسمي، أو تنظيم واجهة نص متعدد الأسطر مُحكمة التغليف بلا أي إرهاق لـgetBoundingClientRect.

      وُجدت هذه المهارة لكي يتمكّن Hermes من صنع عروض رائعة باستخدامها — من النوع الذي ينشره الناس على X. راجع pretext.cool وchenglou.me/pretext للاطلاع على مجموعة العروض المجتمعية.

      متى تُستخدم​

      استخدمها عندما يطلب المستخدم:

      • "عرض pretext" / "شيء pretext رائع" / "نص-كـ-X"
      • نصًا يتدفق حول شكل متحرك (أقسام رئيسية، تخطيطات تحريرية، صفحات طويلة متحركة)
      • تأثيرات فن ASCII باستخدام كلمات أو نثر حقيقي، لا نقوش أحادية التباعد
      • ألعابًا تكون فيها ساحة اللعب / العوائق / اللبنات مصنوعة من نص (Tetris من الحروف، Breakout من النثر)
      • طباعة حركية بفيزياء لكل رمز على حدة (تفتيت، تناثر، تجمّع، تدفق)
      • فنًا توليديًا طباعيًا، خصوصًا بخطوط غير لاتينية أو مختلطة
      • واجهة نص متعدد الأسطر "محكمة التغليف" (أصغر عرض حاوية يظل يسع النص)
      • أي شيء يتطلب معرفة فواصل الأسطر قبل الرسم

      لا تستخدمها من أجل:

      • صفحات SVG/HTML ثابتة تحلّ CSS تخطيطها بالفعل — استخدم CSS فقط
      • محرّرات النصوص المنسّقة أو محركات التنسيق المضمّن العامة (pretext ضيّقة الغرض عمدًا)
      • تحويل صورة إلى نص (استخدم مهارتَي ascii-art / ascii-video)
      • فنًا توليديًا بالكانفاس خالٍ من دور للنص — استخدم p5js

      المعيار الإبداعي​

      هذا فن بصري يُعرض في متصفح. تُعيد pretext أرقامًا؛ أنت من يرسم الشيء الفعلي.

      • لا تُسلّم عرضًا بمستوى "hello world". قالب hello-orb-flow.html هو نقطة البداية. يجب أن يضيف كل عرض تُسلّمه لونًا وحركة وتكوينًا مقصودًا، وتفصيلًا بصريًا واحدًا لم يطلبه المستخدم لكنه سيقدّره.
      • خلفيات داكنة، نوى دافئة، لوحة ألوان مدروسة. يصلح الطابع الكلاسيكي أصفر عنبري على أسود (CRT / طرفية)، لكن يصلح أيضًا أبيض بارد على فحمي (تحريري) أو باستيل باهت (ريزوغراف). اختر واحدًا والتزم به.
      • الخطوط المتناسبة هي جوهر الفكرة. جوهر pretext كله هو "ليس أحادي التباعد" — استثمر ذلك. استخدم Iowan Old Style أو Inter أو JetBrains Mono أو Helvetica Neue أو خطًا متغيرًا. لا تعتمد أبدًا على sans الافتراضي.
      • نص/مصدر حقيقي، لا lorem ipsum. يجب أن يحمل المتن معنى. بيانات قصيرة، شعر، كود مصدري حقيقي، نص موجود، ملف README الخاص بالمكتبة نفسها — لا تستخدم أبدًا lorem ipsum.
      • تميّز عند أول عرض. بلا حالات تحميل، بلا إطارات فارغة. يجب أن يبدو العرض جاهزًا للتسليم لحظة فتحه.

      المكدّس التقني​

      ملف HTML واحد قائم بذاته لكل عرض. بلا خطوة بناء (build).

      الطبقةالأداةالغرض
      الأساس@chenglou/pretext عبر شبكة توزيع esm.shقياس النص + تخطيط الأسطر
      الرسمHTML5 Canvas 2Dرسم الرموز، وتركيب كل إطار
      التجزئةIntl.Segmenter (مدمجة)تقسيم الأحرف الرسمية (grapheme) للرموز التعبيرية / CJK / علامات التركيب
      التفاعلأحداث DOM الخامالماوس / اللمس / عجلة التمرير — بلا إطار عمل
      <script type="module">
      import {
        prepare, layout,                   // use-case 1: simple height
        prepareWithSegments, layoutWithLines,  // use-case 2a: fixed-width lines
        layoutNextLineRange, materializeLineRange, // use-case 2b: streaming / variable width
        measureLineStats, walkLineRanges,  // stats without string allocation
      } from "https://esm.sh/@chenglou/pretext@0.0.6";
      </script>

      ثبّت رقم إصدار محدّد. @0.0.6 وقت كتابة هذا النص — راجع npm للاطلاع على الأحدث إذا بدا سلوك العرض غير متوقّع.

      حالتا الاستخدام​

      يختزل كل شيء تقريبًا إلى إحدى هاتين الصيغتين. تعلّم كلتيهما.

      حالة الاستخدام 1 — القياس، ثم الرسم بـ CSS/DOM​

      const prepared = prepare(text, "16px Inter");
      const { height, lineCount } = layout(prepared, 320, 20);

      ما زلت تترك المتصفح يرسم النص. تخبرك pretext فقط بارتفاع الصندوق عند عرض معيّن، بلا قراءة من DOM. استخدمها من أجل:

      • القوائم الافتراضية (virtualized) حيث تحتوي الصفوف نصًا يلتف
      • تخطيط Masonry بارتفاعات بطاقات دقيقة
      • فحوصات وقت التطوير من نوع "هل تسع هذه التسمية؟"
      • منع انزياح التخطيط عند تحميل نص بعيد

      حافظ على تطابق font وletterSpacing تمامًا مع CSS الخاص بك. يجب أن تطابق صيغة ctx.font في canvas (مثل "16px Inter"، "500 17px 'JetBrains Mono'") الـCSS المُعروض، وإلا ستنحرف القياسات.

      حالة الاستخدام 2 — القياس والرسم بنفسك​

      const prepared = prepareWithSegments(text, FONT);
      const { lines } = layoutWithLines(prepared, 320, 26);
      for (let i = 0; i < lines.length; i++) {
        ctx.fillText(lines[i].text, 0, i * 26);
      }

      هنا يكمن العمل الإبداعي. أنت تملك زمام الرسم، لذا يمكنك:

      • الرسم على canvas أو SVG أو WebGL أو أي نظام إحداثيات
      • استبدال تحويلات لكل رمز (دوران، اهتزاز، تحجيم، شفافية)
      • استخدام بيانات السطر الوصفية (العرض، مواضع الأحرف الرسمية) كهندسة

      لتدفق عرض متغيّر لكل سطر (نص حول شكل، نص في حزام دونات، نص في عمود غير مستطيل):

      let cursor = { segmentIndex: 0, graphemeIndex: 0 };
      let y = 0;
      while (true) {
        const lineWidth = widthAtY(y);  // your function: how wide is the corridor at this y?
        const range = layoutNextLineRange(prepared, cursor, lineWidth);
        if (!range) break;
        const line = materializeLineRange(prepared, range);
        ctx.fillText(line.text, leftEdgeAtY(y), y);
        cursor = range.end;
        y += lineHeight;
      }

      هذا هو أهم نمط في المكتبة كلها. إنه ما يتيح "نصًا يتدفق حول عنصر مسحوب" — العرض الذي انتشر بشكل واسع على X.

      دوال مساعدة تستحق المعرفة​

      • measureLineStats(prepared, maxWidth) ← { lineCount, maxLineWidth } — أعرض سطر، أي عرض التغليف المُحكم متعدد الأسطر.
      • walkLineRanges(prepared, maxWidth, callback) — تكرار عبر الأسطر بلا تخصيص سلاسل نصية. استخدمها للإحصاءات/الفيزياء عبر الأحرف الرسمية عندما لا تحتاج إلى المحارف نفسها.
      • @chenglou/pretext/rich-inline — النظام نفسه لكن للفقرات التي تمزج خطوطًا / شرائح / إشارات (mentions). استورده من هذا المسار الفرعي.

      أنماط وصفات العروض​

      تتجمّع مجموعة العروض المجتمعية (راجع references/patterns.md) في عدد قليل من الأنماط القوية. اختر واحدًا وابنِ عليه — لا تخترع فئة جديدة إلا إذا طُلب منك ذلك.

      النمطالواجهة البرمجية الأساسيةفكرة مثال
      إعادة تدفق حول عائقlayoutNextLineRange + دالة عرض لكل صففقرة تحريرية تنفرج حول مؤشر مسحوب
      نص كهندسة لعبةlayoutWithLines + مستطيلات تصادم لكل سطرBreakout حيث كل لبنة كلمة مقيسة
      تفتيت / جسيماتwalkLineRanges ← إحداثيات (x,y) لكل حرف رسمي ← فيزياءجملة تنفجر إلى حروف عند النقر
      طباعة عائق ASCIIlayoutNextLineRange + مساحات عوائق مقيسة لكل صفشعار ASCII نقطي، تحوّل أشكال، وأجسام سلكية قابلة للسحب تجعل النص ينفتح حول هندستها الفعلية
      تحريري متعدد الأعمدةlayoutNextLineRange لكل عمود + مؤشر مشتركصفحة مجلة متحركة مع اقتباسات بارزة
      طباعة حركيةlayoutWithLines + تحويل لكل سطر عبر الزمنزحف Star Wars، موجة، ارتداد، تشويش
      تغليف محكم متعدد الأسطرmeasureLineStatsبطاقة اقتباس تتحجّم تلقائيًا مع أضيق حاوية

      راجع templates/donut-orbit.html وtemplates/hello-orb-flow.html للاطلاع على نماذج بدء عاملة بملف واحد.

      سير العمل​

      1. اختر نمطًا من الجدول أعلاه بناءً على طلب المستخدم.
      2. ابدأ من قالب:
        • templates/hello-orb-flow.html — نص يعيد التدفق حول كرة متحركة (نمط إعادة التدفق حول عائق)
        • templates/donut-orbit.html — مثال متقدّم: عوائق شعار ASCII مقيسة، كرة/مكعب سلكي قابل للسحب، حقول أشكال متحوّلة، نص DOM قابل للتحديد، وضوابط لأغراض التطوير فقط
        • استخدم write_file لإنشاء ملف .html جديد في /tmp/ أو مساحة عمل المستخدم.
      3. استبدل المتن بشيء مقصود يناسب الطلب. نثر حقيقي، من 10 إلى 100 جملة، بلا lorem.
      4. اضبط الجمالية — الخط، لوحة الألوان، التكوين، التفاعل. هذا هو العمل الفعلي؛ لا تتخطاه.
      5. تحقّق محليًا: 
        cd <dir-with-html> && python -m http.server 8765
        # then open http://localhost:8765/<file>.html
      6. افحص وحدة التحكم (console) — تطلق pretext استثناءً إذا استُدعيت prepareWithSegments بسلسلة خط غير صحيحة؛ Intl.Segmenter متاحة في كل متصفح حديث.
      7. أرِ المستخدم مسار الملف، لا الكود فقط — فهو يريد فتحه.

      ملاحظات الأداء​

      • prepare() / prepareWithSegments() هو الاستدعاء المكلف. نفّذه مرة واحدة لكل زوج نص+خط. خزّن المقبض (handle) في ذاكرة تخزين مؤقت.
      • عند تغيير الحجم، أعِد تشغيل layout() / layoutWithLines() فقط — ولا تُعِد التحضير أبدًا.
      • للرسوم المتحركة لكل إطار حيث لا يتغيّر النص لكن الهندسة تتغيّر، يكون استدعاء layoutNextLineRange في حلقة مُحكمة رخيصًا بما يكفي لتنفيذه كل إطار بمعدل 60 إطارًا في الثانية للفقرات العادية الطول.
      • عند رسم أقنعة ASCII في كل إطار، احتفظ بمخزن خلايا (Uint8Array/مصفوفات مكتوبة)، واستنتج مساحات عوائق مقيسة لكل صف من الخلايا أو الهندسة المسقطة، وادمج المساحات، ثم مرّرها إلى layoutNextLineRange قبل رسم النص.
      • حافظ على ترابط الحركة البصرية مع حركة التخطيط. إذا تحوّلت كرة إلى مكعب، حرّك بالتدرّج (tween) كلًا من مخزن الخلايا المُعروض ومساحات العوائق بنفس القيمة؛ وإلا سيبدو العرض مرسومًا فوق النص لا مُعاد تدفقه فيزيائيًا.
      • للتلاشي، فضّل شفافية الطبقة على تغيير شدة الرمز أو مقياس العائق. ضع رسومات ASCII المؤقتة في canvas خاص بها، ولاشِ الـ canvas بشفافية CSS/GSAP حتى لا تبدو الهندسة وكأنها تنكمش.
      • ضبط ctx.font في canvas بطيء بشكل مفاجئ؛ اضبطه مرة واحدة لكل إطار إذا لم يتغيّر الخط، لا مع كل استدعاء لـ fillText.

      مزالق شائعة​

      1. انحراف سلاسل خطوط CSS/canvas. قِسْت بـ ctx.font = "16px Inter"، لكن CSS يقول font-family: Inter, sans-serif; font-size: 16px. هذا مقبول إذا تحمّل خط Inter بنجاح. إذا فشل تحميل Inter (404)، يرجع CSS إلى sans-serif وتنحرف القياسات بنسبة 5-20%. استخدم دائمًا preload للخط أو عائلة خط آمنة على الويب.

      2. إعادة التحضير داخل حلقة الرسم المتحرك. فقط layout* رخيص. إعادة استدعاء prepare في كل إطار ستُنهك الأداء. أبقِ المقبض المُحضَّر في نطاق الوحدة (module scope).

      3. نسيان Intl.Segmenter لتقسيم الأحرف الرسمية. الرموز التعبيرية، علامات التركيب، CJK — يعطيك "é".split("") محرفين. استخدم new Intl.Segmenter(undefined, { granularity: "grapheme" }) عند أخذ عيّنات من الرموز المرئية الفردية.

      4. شرائح break: 'never' بلا extraWidth. في rich-inline، إذا استخدمت break: 'never' لشريحة/إشارة ذرية، يجب أيضًا توفير extraWidth لحشو الحبّة (pill) — وإلا سيفيض إطار الشريحة خارج الحاوية.

      5. استخدام @chenglou/pretext من unpkg بمدخل TypeScript فقط. استخدم esm.sh — فهي تُحوّل صادرات TS تلقائيًا إلى ESM جاهزة للمتصفح. أما unpkg فقد تعيد 404 أو تُقدّم TS خامًا.

      6. بدائل الخط أحادي التباعد تمحو الفكرة كلها بصمت. غالبًا ما يكون لدى المستخدمين الذين يرون ناتجًا يشبه الخط أحادي التباعد قيمة font-family في CSS تراجعت إلى monospace. تحقّق من الخط الفعلي المُعروض عبر أدوات المطوّر.

      7. تخطّي الصفوف بدلًا من تعديل العرض عند التدفق حول شكل. إذا كان الممر في هذا الصف ضيقًا جدًا بحيث لا يسع سطرًا، تخطَّ الصف (y += lineHeight; continue;) بدلًا من تمرير maxWidth صغير جدًا إلى layoutNextLineRange — إذ ستُعيد pretext أسطرًا من حرف رسمي واحد تبدو معطوبة.

      8. تسليم عرض بارد. يبدو العرض عند أول ظهور افتراضي بمستوى تعليمي بحت. أضِف: تظليل حواف (vignette)، خطوط مسح خفيفة، حركة تلقائية عند الخمول، استجابة تفاعلية واحدة مختارة بعناية (سحب، تحويم، تمرير، نقر). بلا هذه العناصر، سيبدو "عرض pretext رائع" وكأنه "إعادة إنتاج مبتدئ لملف README".

      قائمة التحقّق​

      • العرض ملف .html واحد قائم بذاته — يُفتح بنقرة مزدوجة أو عبر python -m http.server
      • استيراد @chenglou/pretext عبر esm.sh بإصدار مثبّت
      • المتن نثر حقيقي، لا lorem ipsum، ويطابق فكرة العرض
      • سلسلة الخط الممرّرة إلى prepare تطابق خط CSS تمامًا
      • استُدعيت prepare() / prepareWithSegments() مرة واحدة، لا في كل إطار
      • خلفية داكنة + لوحة ألوان مدروسة — لا الكانفاس الأبيض الافتراضي
      • استجابة تفاعلية واحدة على الأقل (سحب / تحويم / تمرير / نقر) أو حركة تلقائية عند الخمول
      • اختُبر محليًا عبر python -m http.server وتأكّد من خلوّه من أخطاء وحدة التحكم
      • 60 إطارًا في الثانية على حاسوب محمول متوسط الفئة (أو تدهور تدريجي موثّق)
      • تفصيل واحد "إضافي" لم يطلبه المستخدم
