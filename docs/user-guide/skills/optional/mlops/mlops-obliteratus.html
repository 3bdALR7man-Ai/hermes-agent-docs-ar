      Obliteratus

      OBLITERATUS: إزالة سلوك الرفض من نماذج LLM عبر abliteration (diff-in-means).

      بيانات المهارة الوصفية​

      المصدراختيارية — ثبّتها باستخدام hermes skills install official/mlops/obliteratus
      المسارoptional-skills/mlops/obliteratus
      الإصدار2.0.0
      المؤلفHermes Agent
      الترخيصMIT
      الاعتمادياتobliteratus, torch, transformers, bitsandbytes, accelerate, safetensors
      المنصاتlinux, macos
      الوسومAbliteration, Uncensoring, Refusal-Removal, LLM, Weight-Projection, SVD, Mechanistic-Interpretability, HuggingFace, Model-Surgery
      مهارات ذات صلةserving-llms-vllm, llama-cpp, huggingface-tokenizers

      المرجع: ملف SKILL.md كاملًا​

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      OBLITERATUS Skill

      محتويات المهارة​

      9 طرق عبر CLI، و28 وحدة تحليل، و116 إعدادًا مسبقًا للنماذج موزعة على 5 مستويات حوسبة، مع تقييم بنظام البطولات (tournament)، وتوصيات مبنية على بيانات telemetry.

      أزل سلوكيات الرفض (guardrails) من نماذج LLM مفتوحة الأوزان دون إعادة تدريب أو fine-tuning. تستخدم المهارة تقنيات قابلية التفسير الآلي (mechanistic interpretability) — ومنها diff-in-means وSVD وwhitened SVD ومحو المفاهيم بـ LEACE وتحليل SAE وإسقاط النواة البايزي (Bayesian kernel projection) وغيرها — لتحديد اتجاهات الرفض في أوزان النموذج وحذفها جراحيًا مع الحفاظ على قدرات الاستدلال.

      تحذير الترخيص: ترخيص OBLITERATUS هو AGPL-3.0. لا تستورده أبدًا كمكتبة Python. استدعِه دائمًا عبر CLI (الأمر obliteratus) أو عبر subprocess. بهذا يبقى ترخيص MIT الخاص بـ Hermes Agent نظيفًا.

      الدليل المرئي​

      شرح عملي لاستخدام وكيل Hermes لـ OBLITERATUS في إجراء abliteration على Gemma: https://www.youtube.com/watch?v=8fG9BrNTeHs ("OBLITERATUS: An AI Agent Removed Gemma 4's Safety Guardrails")

      يفيد هذا الدليل عندما يريد المستخدم نظرة مرئية عامة على سير العمل (workflow) من البداية إلى النهاية قبل أن ينفّذه بنفسه.

      متى تستخدم هذه المهارة​

      فعّل المهارة عندما يقوم المستخدم بأحد الأمور التالية:

      • يريد «إلغاء الرقابة» ("uncensor") عن نموذج LLM أو إجراء "abliterate" عليه
      • يسأل عن إزالة الرفض/guardrails من نموذج
      • يريد إنشاء نسخة غير خاضعة للرقابة من Llama أو Qwen أو Mistral وغيرها
      • يذكر "refusal removal" أو "abliteration" أو "weight projection"
      • يريد تحليل كيفية عمل آلية الرفض في نموذج ما
      • يشير إلى OBLITERATUS أو abliterator أو اتجاهات الرفض (refusal directions)

      الخطوة 1: التثبيت​

      تحقق مما إذا كانت الأداة مثبّتة بالفعل:

      obliteratus --version 2>/dev/null && echo "INSTALLED" || echo "NOT INSTALLED"

      إذا لم تكن مثبّتة، فاسحبها من GitHub ثم ثبّتها:

      git clone https://github.com/elder-plinius/OBLITERATUS.git
      cd OBLITERATUS
      pip install -e .
      # For Gradio web UI support:
      # pip install -e ".[spaces]"

      مهم: أكّد مع المستخدم قبل التثبيت. فهو يجلب نحو 5-10 GB من الاعتماديات (PyTorch وTransformers وbitsandbytes وغيرها).

      الخطوة 2: فحص العتاد​

      قبل أي شيء، تحقق من وحدة GPU المتاحة:

      python3 -c "
      import torch
      if torch.cuda.is_available():
          gpu = torch.cuda.get_device_name(0)
          vram = torch.cuda.get_device_properties(0).total_memory / 1024**3
          print(f'GPU: {gpu}')
          print(f'VRAM: {vram:.1f} GB')
          if vram < 4: print('TIER: tiny (models under 1B)')
          elif vram < 8: print('TIER: small (models 1-4B)')
          elif vram < 16: print('TIER: medium (models 4-9B with 4bit quant)')
          elif vram < 32: print('TIER: large (models 8-32B with 4bit quant)')
          else: print('TIER: frontier (models 32B+)')
      else:
          print('NO GPU - only tiny models (under 1B) on CPU')
      "

      الخطوة 4: اختيار الطريقة​

      دليل اختيار الطريقة​

      الخيار الافتراضي والموصى به في معظم الحالات: advanced. تعتمد على SVD متعدد الاتجاهات مع إسقاط يحافظ على المعيار (norm-preserving) وهي مجرَّبة جيدًا.

      الحالةالطريقة الموصى بهاالسبب
      الافتراضي / معظم النماذجadvancedSVD متعدد الاتجاهات، يحافظ على المعيار، موثوقة
      اختبار سريع / بناء نموذج أوليbasicسريعة وبسيطة وكافية للتقييم
      نموذج كثيف (Llama, Mistral)advancedمتعددة الاتجاهات، تحافظ على المعيار
      نموذج MoE (DeepSeek, Mixtral)nuclearدقيقة على مستوى الخبراء (expert-granular)، وتتعامل مع تعقيد MoE
      نموذج استدلال (R1 distills)surgicalتراعي CoT وتحافظ على سلسلة التفكير (chain-of-thought)
      استمرار الرفض العنيدaggressiveWhitened SVD مع head surgery وjailbreak
      الرغبة في تغييرات قابلة للعكساستخدم steering vectors (راجع قسم التحليل)
      أعلى جودة دون قيد على الوقتoptimizedبحث بايزي عن أفضل المعاملات
      اكتشاف تلقائي تجريبيinformedتكتشف نوع المواءمة (alignment) تلقائيًا — تجريبية، وقد لا تتفوق دائمًا على advanced

      9 طرق عبر CLI​

      • basic — اتجاه رفض واحد عبر diff-in-means. سريعة (نحو 5-10 دقائق لنموذج 8B).
      • advanced (الافتراضية، والموصى بها) — عدة اتجاهات SVD، وإسقاط يحافظ على المعيار، ومرورَان للتحسين. سرعة متوسطة (نحو 10-20 دقيقة).
      • aggressive — Whitened SVD مع jailbreak-contrastive وattention head surgery. خطر أعلى لإلحاق الضرر بالتماسك (coherence).
      • spectral_cascade — تحليل في نطاق التردد باستخدام DCT. نهج بحثي جديد.
      • informed — تشغّل التحليل أثناء abliteration لضبط الإعدادات تلقائيًا. تجريبية — أبطأ وأقل قابلية للتنبؤ من advanced.
      • surgical — ميزات SAE مع neuron masking وhead surgery وper-expert. بطيئة جدًا (نحو 1-2 ساعة). الأفضل لنماذج الاستدلال.
      • optimized — بحث بايزي عن المعاملات الفائقة (Optuna TPE). أطول زمن تشغيل لكنها تجد المعاملات المثلى.
      • inverted — تعكس اتجاه الرفض. يصبح النموذج راغبًا بنشاط في الاستجابة.
      • nuclear — تركيبة بأقصى قوة لنماذج MoE العنيدة. دقيقة على مستوى الخبراء.

      طرق استخراج الاتجاه (الخيار --direction-method)​

      • diff_means (الافتراضية) — فرق المتوسطات البسيط بين تنشيطات الرفض والاستجابة. متينة.
      • svd — استخراج متعدد الاتجاهات بـ SVD. أفضل للمواءمة المعقدة.
      • leace — LEACE (Linear Erasure via Closed-form Estimation). محو خطي أمثل.

      4 طرق عبر Python API فقط​

      (غير متاحة عبر CLI — تتطلب استيرادًا في Python، وهذا ينتهك حدود AGPL. اذكرها للمستخدم فقط إذا أراد صراحةً استخدام OBLITERATUS كمكتبة في مشروعه الخاص المرخّص بـ AGPL.)

      • failspy, gabliteration, heretic, rdo

      الخطوة 5: تشغيل abliteration​

      الاستخدام القياسي​

      # Default method (advanced) — recommended for most models
      obliteratus obliterate <model_name> --method advanced --output-dir ./abliterated-models

      # With 4-bit quantization (saves VRAM)
      obliteratus obliterate <model_name> --method advanced --quantization 4bit --output-dir ./abliterated-models

      # Large models (70B+) — conservative defaults
      obliteratus obliterate <model_name> --method advanced --quantization 4bit --large-model --output-dir ./abliterated-models

      معاملات الضبط الدقيق​

      obliteratus obliterate <model_name> \
        --method advanced \
        --direction-method diff_means \
        --n-directions 4 \
        --refinement-passes 2 \
        --regularization 0.1 \
        --quantization 4bit \
        --output-dir ./abliterated-models \
        --contribute  # opt-in telemetry for community research

      الخيارات الأساسية​

      الخيارالوصفالقيمة الافتراضية
      --methodطريقة abliterationadvanced
      --direction-methodاستخراج الاتجاهdiff_means
      --n-directionsعدد اتجاهات الرفض (1-32)يعتمد على الطريقة
      --refinement-passesمرات التمرير التكرارية (1-5)2
      --regularizationقوة التنظيم (regularization) (0.0-1.0)0.1
      --quantizationالتحميل بدقة 4bit أو 8bitلا شيء (دقة كاملة)
      --large-modelقيم افتراضية متحفظة للنماذج بحجم 120B+false
      --output-dirمكان حفظ النموذج بعد abliteration./obliterated_model
      --contributeمشاركة نتائج مجهولة الهوية لأغراض البحثfalse
      --verify-sample-sizeعدد prompts الاختبار لفحص الرفض20
      --dtypeنوع بيانات النموذج (dtype) (float16, bfloat16)auto

      أوضاع التنفيذ الأخرى​

      # Interactive guided mode (hardware → model → preset)
      obliteratus interactive

      # Web UI (Gradio)
      obliteratus ui --port 7860

      # Run a full ablation study from YAML config
      obliteratus run config.yaml --preset quick

      # Tournament: pit all methods against each other
      obliteratus tourney <model_name>

      الخطوة 6: التحقق من النتائج​

      بعد abliteration، افحص مقاييس المخرجات:

      المقياسالقيمة الجيدةالتحذير
      معدل الرفض< 5% (والأفضل ~0%)> 10% يعني استمرار الرفض
      تغيّر perplexityزيادة < 10%> 15% يعني تضرر التماسك
      تباعد KL< 0.1> 0.5 يعني تحولًا كبيرًا في التوزيع
      التماسكعالٍ / يجتاز الفحص النوعيردود متدهورة، وتكرار

      إذا استمر الرفض (> 10%)​

      1. جرّب الطريقة aggressive
      2. زد قيمة --n-directions (مثلًا 8 أو 16)
      3. أضف --refinement-passes 3
      4. جرّب --direction-method svd بدلًا من diff_means

      إذا تضرر التماسك (زيادة perplexity بأكثر من 15%)​

      1. قلّل قيمة --n-directions (جرّب 2)
      2. زد قيمة --regularization (جرّب 0.3)
      3. خفّض --refinement-passes إلى 1
      4. جرّب الطريقة basic (الأخف)

      الخطوة 7: استخدام النموذج بعد abliteration​

      المخرجات عبارة عن مجلد نموذج HuggingFace قياسي.

      python3 -c "
      from transformers import AutoModelForCausalLM, AutoTokenizer
      model = AutoModelForCausalLM.from_pretrained('./abliterated-models/<model>')

      استراتيجيات Ablation​

      إلى جانب abliteration المعتمد على الاتجاهات، يتضمن OBLITERATUS استراتيجيات ablation بنيوية:

      • Embedding Ablation — يستهدف مكونات طبقة embedding
      • FFN Ablation — إزالة كتلة الشبكة التغذوية الأمامية (feed-forward network)
      • Head Pruning — تقليم رؤوس الانتباه (attention heads)
      • Layer Removal — إزالة طبقة كاملة

      لعرض كل الاستراتيجيات المتاحة: obliteratus strategies

      التقييم​

      يتضمن OBLITERATUS أدوات تقييم مدمجة:

      • CPU — مدعوم للنماذج الصغيرة جدًا (< 1B params)

      Telemetry​

      يمكن لـ OBLITERATUS اختياريًا المساهمة ببيانات تشغيل مجهولة الهوية في مجموعة بيانات بحثية عالمية. فعّل ذلك بالخيار --contribute. لا تُجمع أي بيانات شخصية — فقط اسم النموذج والطريقة والمقاييس.

      أخطاء شائعة​

      1. لا تستخدم informed كخيار افتراضي — فهي تجريبية وأبطأ. استخدم advanced للحصول على نتائج موثوقة.
      2. النماذج التي تقل عن ~1B تستجيب بشكل ضعيف لـ abliteration — فسلوكيات الرفض فيها سطحية ومجزأة، مما يصعّب استخراج الاتجاه بشكل نظيف. توقّع نتائج جزئية (بقاء 20-40% من الرفض). أما النماذج بحجم 3B فأكثر فاتجاهات الرفض فيها أوضح وتستجيب بشكل أفضل بكثير (غالبًا 0% رفض مع advanced).
      3. aggressive قد تزيد الأمور سوءًا — ففي النماذج الصغيرة قد تُضر بالتماسك وترفع معدل الرفض فعليًا. لا تستخدمها إلا إذا تركت advanced أكثر من 10% من الرفض في نموذج بحجم 3B فأكثر.
      4. افحص perplexity دائمًا — إذا ارتفعت بأكثر من 15% فالنموذج تضرر. خفّف حدّة الإعدادات.
      5. نماذج MoE تحتاج معالجة خاصة — استخدم الطريقة nuclear مع Mixtral وDeepSeek-MoE وما شابههما.
      6. لا يمكن إعادة تكميم النماذج المكمَّمة — نفّذ abliteration على النموذج بدقة كاملة، ثم كمِّم المخرجات.
      7. تقدير VRAM تقريبي — التكميم بـ 4-bit يساعد لكن الاستهلاك الأقصى قد يقفز أثناء الاستخراج.
      8. نماذج الاستدلال حساسة — استخدم surgical مع R1 distills للحفاظ على سلسلة التفكير (chain-of-thought).
      9. راجع obliteratus recommend — فقد تحمل بيانات telemetry معاملات أفضل من القيم الافتراضية.
      10. ترخيص AGPL — لا تستخدم import obliteratus أبدًا في مشاريع MIT/Apache. الاستدعاء عبر CLI فقط.
      11. النماذج الكبيرة (70B+) — استخدم الخيار --large-model دائمًا للحصول على قيم افتراضية متحفظة.
      12. ظهور شهادة الطيف (spectral certification) باللون RED أمر شائع — كثيرًا ما يشير فحص الطيف إلى "incomplete" حتى عندما يكون معدل الرفض العملي 0%. افحص معدل الرفض الفعلي ولا تعتمد على شهادة الطيف وحدها.
