      Slime

      تدريب لاحق بالتعلّم المعزز (RL post-training) لنماذج LLM باستخدام Megatron وSGLang.

      بيانات المهارة الوصفية​

      المصدراختيارية — ثبّتها باستخدام hermes skills install official/mlops/slime
      المسارoptional-skills/mlops/slime
      الإصدار1.0.0
      المؤلفOrchestra Research
      الترخيصMIT
      الاعتمادياتsglang-router>=0.2.3, ray, torch>=2.0.0, transformers>=4.40.0
      المنصاتlinux, macos
      الوسومReinforcement Learning, Megatron-LM, SGLang, GRPO, Post-Training, GLM

      المرجع: ملف SKILL.md كاملًا​

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      slime: إطار عمل للتدريب اللاحق لنماذج LLM لتوسيع التعلّم المعزز

      slime هو إطار عمل للتدريب اللاحق لنماذج LLM من فريق THUDM بجامعة Tsinghua، ويشغّل GLM-4.5 وGLM-4.6 وGLM-4.7. يربط بين Megatron-LM للتدريب وSGLang لتوليد rollout بإنتاجية عالية.

      متى تستخدم slime​

      اختر slime عندما تحتاج إلى:

      • تدريب أصلي بـ Megatron-LM مع استدلال بـ SGLang
      • سير عمل مخصص لتوليد البيانات مع مخازن بيانات (data buffers) مرنة
      • تدريب نماذج GLM أو Qwen3 أو DeepSeek V3 أو Llama 3
      • إطار عمل بحثي المستوى مدعوم إنتاجيًا (من Z.ai)

      ضع البدائل في الاعتبار عندما:

      • تحتاج إلى ميزات استقرار بمستوى المؤسسات ← استخدم miles
      • تريد مرونة في تبديل الواجهة الخلفية (backend) ← استخدم verl
      • تحتاج إلى تجريدات (abstractions) أصلية لـ PyTorch ← استخدم torchforge

      الميزات الرئيسية​

      • التدريب: Megatron-LM مع دعم كامل للتوازي (TP وPP وDP وSP)
      • Rollout: توليد بإنتاجية عالية قائم على SGLang مع موجّه (router)
      • مخزن البيانات (Data Buffer): إدارة مرنة للمطالبات وتخزين العينات
      • النماذج: GLM-4.x، Qwen3، DeepSeek V3/R1، Llama 3

      نظرة عامة على البنية المعمارية​

      ┌─────────────────────────────────────────────────────────┐
      │                    Data Buffer                          │
      │ - Prompt initialization and management                  │
      │ - Custom data generation and filtering                  │
      │ - Rollout sample storage                                │
      └─────────────┬───────────────────────────┬───────────────┘
                    │                           │
      ┌─────────────▼───────────┐ ┌─────────────▼───────────────┐
      │ Training (Megatron-LM)  │ │ Rollout (SGLang + Router)   │
      │ - Actor model training  │ │ - Response generation       │
      │ - Critic (optional)     │ │ - Reward/verifier output    │
      │ - Weight sync to rollout│ │ - Multi-turn support        │
      └─────────────────────────┘ └─────────────────────────────┘

      التثبيت​

      # Recommended: Docker
      docker pull slimerl/slime:latest
      docker run --rm --gpus all --ipc=host --shm-size=16g \
        -it slimerl/slime:latest /bin/bash

      # Inside container
      cd /root/slime && pip install -e . --no-deps

      من المصدر​

      git clone https://github.com/THUDM/slime.git
      cd slime
      pip install -r requirements.txt
      pip install -e .

      البدء السريع: تدريب GRPO​

      # Source model configuration
      source scripts/models/qwen3-4B.sh

      # Launch training
      python train.py \
          --actor-num-nodes 1 \
          --actor-num-gpus-per-node 4 \
          --rollout-num-gpus 4 \
          --advantage-estimator grpo \
          --use-kl-loss --kl-loss-coef 0.001 \
          --rollout-batch-size 32 \
          --n-samples-per-prompt 8 \
          --global-batch-size 256 \
          --num-rollout 3000 \
          --prompt-data /path/to/data.jsonl \
          ${MODEL_ARGS[@]} ${CKPT_ARGS[@]}

      سير العمل 1: تدريب GRPO القياسي​

      استخدم سير العمل هذا لتدريب نماذج الاستدلال بمزايا نسبية للمجموعة (group-relative advantages).

      قائمة تحقق المتطلبات المسبقة​

      • بيئة Docker أو تثبيت Megatron-LM + SGLang
      • نقطة حفظ للنموذج (بصيغة HuggingFace أو Megatron)
      • بيانات تدريب بصيغة JSONL

      الخطوة 1: تحضير البيانات​

      # data.jsonl format
      {"prompt": "What is 2 + 2?", "label": "4"}
      {"prompt": "Solve: 3x = 12", "label": "x = 4"}

      أو بصيغة محادثة (chat format):

      {
          "prompt": [
              {"role": "system", "content": "You are a math tutor."},
              {"role": "user", "content": "What is 15 + 27?"}
          ],
          "label": "42"
      }

      الخطوة 2: ضبط إعداد النموذج​

      اختر سكربت نموذج مُعَدّ مسبقًا:

      # List available models
      ls scripts/models/
      # glm4-9B.sh, qwen3-4B.sh, qwen3-30B-A3B.sh, deepseek-v3.sh, llama3-8B.sh, ...

      # Source your model
      source scripts/models/qwen3-4B.sh

      الخطوة 3: تشغيل التدريب​

      python train.py \
          --actor-num-nodes 1 \
          --actor-num-gpus-per-node 8 \
          --rollout-num-gpus 8 \
          --advantage-estimator grpo \
          --use-kl-loss \
          --kl-loss-coef 0.001 \
          --prompt-data /path/to/train.jsonl \
          --input-key prompt \
          --label-key label \
          --apply-chat-template \
          --rollout-batch-size 32 \
          --n-samples-per-prompt 8 \
          --global-batch-size 256 \
          --num-rollout 3000 \
          --save-interval 100 \
          --eval-interval 50 \
          ${MODEL_ARGS[@]}

      الخطوة 4: مراقبة التدريب​

      • تحقّق من TensorBoard: tensorboard --logdir outputs/
      • تأكد من أن منحنيات المكافأة (reward) في تزايد
      • راقب استخدام GPU عبر العُقد

      سير العمل 2: التدريب غير المتزامن​

      استخدم الوضع غير المتزامن لتحقيق إنتاجية أعلى عبر تداخل rollout مع التدريب.

      متى تستخدم الوضع غير المتزامن​

      • النماذج الكبيرة ذات أزمنة التوليد الطويلة
      • ارتفاع زمن خمول GPU في الوضع المتزامن
      • ذاكرة كافية للتخزين المؤقت (buffering)

      تشغيل التدريب غير المتزامن​

      python train_async.py \
          --actor-num-nodes 1 \
          --actor-num-gpus-per-node 8 \
          --rollout-num-gpus 8 \
          --advantage-estimator grpo \
          --async-buffer-size 4 \
          --prompt-data /path/to/train.jsonl \
          ${MODEL_ARGS[@]}

      معاملات خاصة بالوضع غير المتزامن​

      --async-buffer-size 4        # Number of rollouts to buffer
      --update-weights-interval 2  # Sync weights every N rollouts

      سير العمل 3: تدريب وكيل متعدد الأدوار​

      استخدم سير العمل هذا لتدريب وكلاء يستخدمون أدوات أو استدلالًا متعدد الخطوات.

      المتطلبات المسبقة​

      • دالة توليد مخصصة لمنطق تعدد الأدوار
      • واجهة أداة/بيئة

      الخطوة 1: عرّف دالة توليد مخصصة​

      # custom_generate.py
      async def custom_generate(args, samples, evaluation=False):
          """Multi-turn generation with tool calling."""
          for sample in samples:
              conversation = sample.prompt

              for turn in range(args.max_turns):
                  # Generate response
                  response = await generate_single(conversation)

                  # Check for tool call
                  tool_call = extract_tool_call(response)
                  if tool_call:
                      tool_result = execute_tool(tool_call)
                      conversation.append({"role": "assistant", "content": response})
                      conversation.append({"role": "tool", "content": tool_result})
                  else:
                      break

              sample.response = response
              sample.reward = compute_reward(sample)

          return samples

      الخطوة 2: شغّل باستخدام الدالة المخصصة​

      python train.py \
          --custom-generate-function-path custom_generate.py \
          --max-turns 5 \
          --prompt-data /path/to/agent_data.jsonl \
          ${MODEL_ARGS[@]}

      راجع examples/search-r1/ للاطلاع على مثال بحث متعدد الأدوار كامل.

      مرجع الإعدادات​

      فئات المعاملات الثلاث​

      يستخدم slime ثلاثة أنواع من المعاملات:

      1. معاملات Megatron (تُمرَّر مباشرة):

      --tensor-model-parallel-size 2
      --pipeline-model-parallel-size 1
      --num-layers 32
      --hidden-size 4096

      2. معاملات SGLang (تبدأ بـ --sglang-):

      --sglang-mem-fraction-static 0.8
      --sglang-context-length 8192
      --sglang-log-level INFO

      3. معاملات slime:

      # Resource allocation
      --actor-num-nodes 1
      --actor-num-gpus-per-node 8
      --rollout-num-gpus 8
      --colocate  # Share GPUs between training/inference

      # Data
      --prompt-data /path/to/data.jsonl
      --input-key prompt
      --label-key label

      # Training loop
      --num-rollout 3000
      --rollout-batch-size 32
      --n-samples-per-prompt 8
      --global-batch-size 256

      # Algorithm
      --advantage-estimator grpo  # or: gspo, ppo, reinforce_plus_plus
      --use-kl-loss
      --kl-loss-coef 0.001

      القيود الرئيسية​

      rollout_batch_size × n_samples_per_prompt = global_batch_size × num_steps_per_rollout

      مثال: 32 × 8 = 256 × 1

      نظام مخزن البيانات​

      يتيح مخزن بيانات slime إدارة بيانات مرنة:

      مصدر بيانات أساسي​

      class RolloutDataSource:
          def get_samples(self, num_samples):
              """Fetch prompts from dataset."""
              return self.dataset.sample(num_samples)

          def add_samples(self, samples):
              """Called after generation (no-op by default)."""
              pass

      مصدر بيانات مخزَّن مؤقتًا (Off-Policy)​

      class RolloutDataSourceWithBuffer(RolloutDataSource):
          def __init__(self):
              self.buffer = []

          def add_samples(self, samples):
              """Store generated samples for reuse."""
              self.buffer.extend(samples)

          def buffer_filter(self, args, buffer, num_samples):
              """Custom selection logic (prioritized, stratified, etc.)."""
              return select_best(buffer, num_samples)

      المشكلات الشائعة وحلولها​

      المشكلة: انهيار محرك SGLang​

      الأعراض: يتوقف محرك الاستدلال في منتصف التدريب

      الحلول:

      # Enable fault tolerance
      --use-fault-tolerance

      # Increase memory allocation
      --sglang-mem-fraction-static 0.85

      # Reduce batch size
      --rollout-batch-size 16

      المشكلة: انتهاء مهلة مزامنة الأوزان​

      الأعراض: يتوقف التدريب بعد rollout

      الحلول:

      # Increase sync interval
      --update-weights-interval 5

      # Use colocated mode (no network transfer)
      --colocate

      المشكلة: نفاد الذاكرة (OOM) أثناء التدريب​

      الأعراض: نفاد ذاكرة CUDA في مرحلة backward pass

      الحلول:

      # Enable gradient checkpointing
      --recompute-activations

      # Reduce micro-batch size
      --micro-batch-size 1

      # Enable sequence parallelism
      --sequence-parallel

      المشكلة: بطء تحميل البيانات​

      الأعراض: خمول GPU أثناء جلب البيانات

      الحلول:

      # Increase data workers
      --num-data-workers 4

      # Use streaming dataset
      --streaming-data

      مواضيع متقدمة​

      وضع التشارك (Co-location)​

      شارك وحدات GPU بين التدريب والاستدلال لتقليل استهلاك الذاكرة:

      python train.py \
          --colocate \
          --actor-num-gpus-per-node 8 \
          --sglang-mem-fraction-static 0.4 \
          ${MODEL_ARGS[@]}

      نموذج مكافأة مخصص​

      # custom_rm.py
      class CustomRewardModel:
          def __init__(self, model_path):
              self.model = load_model(model_path)

          def compute_reward(self, prompts, responses):
              inputs = self.tokenize(prompts, responses)
              scores = self.model(inputs)
              return scores.tolist()
      --custom-rm-path custom_rm.py

      --n-samples-per-eval-prompt 16
