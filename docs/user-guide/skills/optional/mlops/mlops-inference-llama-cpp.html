      llama.cpp

      استدلال محلي بصيغة GGUF عبر llama.cpp + اكتشاف نماذج من HF Hub.

      بيانات المهارة الوصفية​

      المصدراختيارية — ثبّتها باستخدام hermes skills install official/mlops/llama-cpp
      المسارoptional-skills/mlops/inference/llama-cpp
      الإصدار2.1.2
      المؤلفOrchestra Research
      الترخيصMIT
      الاعتمادياتllama-cpp-python>=0.2.0

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      llama.cpp + GGUF

      استخدم هذه المهارة للاستدلال المحلي بصيغة GGUF، واختيار الـ quant، أو اكتشاف مستودعات Hugging Face المتوافقة مع llama.cpp.

      متى تستخدمها​

      • تشغيل نماذج محلية على المعالج (CPU) أو Apple Silicon أو CUDA أو ROCm أو وحدات GPU من Intel
      • إيجاد ملف GGUF المناسب لمستودع Hugging Face محدَّد
      • بناء أمر llama-server أو llama-cli انطلاقًا من الـ Hub
      • البحث في الـ Hub عن نماذج تدعم llama.cpp بالفعل
      • سرد ملفات .gguf المتاحة وأحجامها لمستودع معيّن
      • الاختيار بين نسخ Q4/Q5/Q6/IQ بحسب ذاكرة RAM أو VRAM لدى المستخدم

      سير عمل اكتشاف النماذج​

      فضّل سير العمل القائم على الروابط (URL) قبل اللجوء إلى hf أو Python أو سكربتات مخصّصة.

      1. ابحث عن مستودعات مرشَّحة على الـ Hub:
        • الأساس: https://huggingface.co/models?apps=llama.cpp&sort=trending
        • أضف search=<term> لعائلة نماذج معيّنة
        • أضف num_parameters=min:0,max:24B أو ما شابه عندما يكون لدى المستخدم قيود على الحجم
      2. افتح المستودع بواجهة تطبيق llama.cpp المحلي:
        • https://huggingface.co/<repo>?local-app=llama.cpp
      3. اعتمد مقتطف local-app كمرجع أساسي متى كان ظاهرًا:
        • انسخ أمر llama-server أو llama-cli كما هو تمامًا
        • اذكر نسخة الـ quant الموصى بها تمامًا كما تعرضها HF
      4. اقرأ رابط ?local-app=llama.cpp نفسه كنص أو HTML للصفحة واستخرج القسم الموجود تحت Hardware compatibility:
        • فضّل تسميات الـ quant وأحجامها الدقيقة الواردة فيه على الجداول العامة
        • احتفظ بالتسميات الخاصة بالمستودع مثل UD-Q4_K_M أو IQ4_NL_XL
        • إذا لم يكن هذا القسم ظاهرًا في مصدر الصفحة المجلوبة، اذكر ذلك واستخدم بدلًا منه واجهة tree API مع إرشادات عامة عن الـ quant
      5. استعلم واجهة tree API للتأكد ممّا هو موجود فعليًا:
        • https://huggingface.co/api/models/<repo>/tree/main?recursive=true
        • احتفظ بالمُدخلات التي يكون فيها type مساويًا لـ file وينتهي path بـ .gguf
        • استخدم path وsize كمرجع أساسي لأسماء الملفات وأحجامها بالبايت
        • افصل نقاط التفتيش المُكمَّمة (quantized) عن ملفات الإسقاط (projector) mmproj-*.gguf وملفات الأجزاء (shard) BF16/
        • استخدم https://huggingface.co/<repo>/tree/main فقط كبديل يقرؤه البشر
      6. إذا لم يكن مقتطف local-app ظاهرًا كنص، أعِد بناء الأمر من المستودع والـ quant المختار:
        • اختيار مختصر للـ quant: llama-server -hf <repo>:<QUANT>
        • بديل باسم الملف الدقيق: llama-server --hf-repo <repo> --hf-file <filename.gguf>
      7. اقترح التحويل من أوزان Transformers فقط إذا لم يكن المستودع يعرض ملفات GGUF بالفعل.

      البدء السريع​

      تثبيت llama.cpp​

      # macOS / Linux (simplest)
      brew install llama.cpp
      winget install llama.cpp
      git clone https://github.com/ggml-org/llama.cpp
      cd llama.cpp
      cmake -B build
      cmake --build build --config Release

      التشغيل مباشرة من Hugging Face Hub​

      llama-cli -hf bartowski/Llama-3.2-3B-Instruct-GGUF:Q8_0
      llama-server -hf bartowski/Llama-3.2-3B-Instruct-GGUF:Q8_0

      تشغيل ملف GGUF محدَّد من الـ Hub​

      استخدم هذا عندما تُظهر واجهة tree API تسمية ملفات مخصّصة أو عند غياب مقتطف HF الدقيق.

      llama-server \
          --hf-repo microsoft/Phi-3-mini-4k-instruct-gguf \
          --hf-file Phi-3-mini-4k-instruct-q4.gguf \
          -c 4096

      التحقق من خادم متوافق مع OpenAI​

      curl http://localhost:8080/v1/chat/completions \
        -H "Content-Type: application/json" \
        -d '{
          "messages": [
            {"role": "user", "content": "Write a limerick about Python exceptions"}
          ]
        }'

      روابط Python (llama-cpp-python)​

      pip install llama-cpp-python (لـ CUDA: CMAKE_ARGS="-DGGML_CUDA=on" pip install llama-cpp-python --force-reinstall --no-cache-dir؛ ولـ Metal: CMAKE_ARGS="-DGGML_METAL=on" ...).

      توليد أساسي​

      from llama_cpp import Llama

      llm = Llama(
          model_path="./model-q4_k_m.gguf",
          n_ctx=4096,
          n_gpu_layers=35,     # 0 for CPU, 99 to offload everything
          n_threads=8,
      )

      out = llm("What is machine learning?", max_tokens=256, temperature=0.7)
      print(out["choices"][0]["text"])

      المحادثة + البث​

      llm = Llama(
          model_path="./model-q4_k_m.gguf",
          n_ctx=4096,
          n_gpu_layers=35,
          chat_format="llama-3",   # or "chatml", "mistral", etc.
      )

      resp = llm.create_chat_completion(
          messages=[
              {"role": "system", "content": "You are a helpful assistant."},
              {"role": "user", "content": "What is Python?"},
          ],
          max_tokens=256,
      )
      print(resp["choices"][0]["message"]["content"])

      # Streaming
      for chunk in llm("Explain quantum computing:", max_tokens=256, stream=True):
          print(chunk["choices"][0]["text"], end="", flush=True)

      Embeddings​

      llm = Llama(model_path="./model-q4_k_m.gguf", embedding=True, n_gpu_layers=35)
      vec = llm.embed("This is a test sentence.")
      print(f"Embedding dimension: {len(vec)}")

      يمكنك أيضًا تحميل ملف GGUF مباشرة من الـ Hub:

      llm = Llama.from_pretrained(
          repo_id="bartowski/Llama-3.2-3B-Instruct-GGUF",
          filename="*Q4_K_M.gguf",
          n_gpu_layers=35,
      )

      اختيار الـ quant​

      استخدم صفحة الـ Hub أولًا، والقواعد العامة (heuristics) ثانيًا.

      • فضّل الـ quant الدقيق الذي تحدّده HF كمتوافق مع ملف عتاد المستخدم.
      • للمحادثة العامة، ابدأ بـ Q4_K_M.
      • للأعمال البرمجية أو التقنية، فضّل Q5_K_M أو Q6_K إن سمحت الذاكرة.
      • لميزانيات RAM محدودة جدًا، فكّر في Q3_K_M أو نسخ IQ، أو نسخ Q2 فقط إذا أعطى المستخدم صراحةً الأولوية للمساحة على الجودة.
      • بالنسبة للمستودعات متعددة الوسائط (multimodal)، اذكر mmproj-*.gguf بشكل منفصل. فملف الإسقاط (projector) ليس ملف النموذج الرئيسي.
      • لا توحّد التسميات الخاصة بالمستودع. إذا كانت الصفحة تذكر UD-Q4_K_M، فاذكر UD-Q4_K_M.

      استخراج ملفات GGUF المتاحة من مستودع​

      عندما يسأل المستخدم عن ملفات GGUF الموجودة، أرجع:

      • اسم الملف
      • حجم الملف
      • تسمية الـ quant
      • ما إذا كان نموذجًا رئيسيًا أم ملف إسقاط (projector) مساعدًا

      تجاهل ما يلي إلا إذا طُلب:

      • README
      • ملفات أجزاء (shard) BF16
      • كتل imatrix أو عناصر المعايرة (calibration)

      استخدم واجهة tree API لهذه الخطوة:

      • https://huggingface.co/api/models/<repo>/tree/main?recursive=true

      بالنسبة لمستودع مثل unsloth/Qwen3.6-35B-A3B-GGUF، قد تعرض صفحة local-app شرائح quant مثل UD-Q4_K_M وUD-Q5_K_M وUD-Q6_K وQ8_0، بينما تعرض واجهة tree API مسارات ملفات دقيقة مثل Qwen3.6-35B-A3B-UD-Q4_K_M.gguf وQwen3.6-35B-A3B-Q8_0.gguf مع أحجامها بالبايت. استخدم واجهة tree API لتحويل تسمية quant إلى اسم ملف دقيق.

      • hub-discovery.md - سير عمل Hugging Face عبر الروابط فقط، وأنماط البحث، واستخراج GGUF، وإعادة بناء الأوامر
      • advanced-usage.md — فك الترميز التخميني (speculative decoding)، الاستدلال الدفعي (batched)، التوليد المقيّد بـ grammar، LoRA، تعدد GPU، بُنى مخصّصة، سكربتات قياس الأداء

      • optimization.md — خيوط المعالج (CPU threading)، BLAS، قواعد إسناد العمل إلى GPU، ضبط الدفعات (batch)، قياسات الأداء
      • troubleshooting.md — مشاكل التثبيت/التحويل/التكميم/الاستدلال/الخادم، Apple Silicon، تصحيح الأخطاء
