      Lambda Labs

      نُسخ سحابية من وحدات معالجة رسومية (GPU) عند الطلب لتدريب نماذج التعلّم الآلي.

      بيانات المهارة الوصفية​

      المصدراختيارية — ثبّتها باستخدام hermes skills install official/mlops/lambda-labs
      المسارoptional-skills/mlops/lambda-labs
      الإصدار1.0.0
      المؤلفOrchestra Research

      المرجع: ملف SKILL.md كاملًا​

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      Lambda Labs GPU Cloud

      دليل لتشغيل أحمال عمل التعلّم الآلي على سحابة Lambda Labs للـ GPU باستخدام نُسخ عند الطلب وعناقيد (clusters) 1-Click.

      متى تستخدم Lambda Labs​

      استخدم Lambda Labs عندما:

      • تحتاج إلى نُسخ GPU مخصّصة بوصول SSH كامل
      • تشغّل مهام تدريب طويلة (من ساعات إلى أيام)
      • تريد تسعيرًا بسيطًا بلا رسوم egress
      • تحتاج إلى تخزين دائم بين الجلسات
      • تحتاج إلى عناقيد (clusters) عالية الأداء متعددة العقد (16-512 وحدة GPU)
      • تريد حزمة أدوات تعلّم آلي مثبّتة مسبقًا (Lambda Stack مع PyTorch وCUDA وNCCL)

      الميزات الرئيسية:

      • تنوّع وحدات GPU: B200، H100، GH200، A100، A10، A6000، V100
      • Lambda Stack: PyTorch وTensorFlow وCUDA وcuDNN وNCCL مثبّتة مسبقًا
      • أنظمة ملفات دائمة: تحافظ على البيانات عبر إعادة تشغيل النُسخ
      • عناقيد 1-Click: عناقيد Slurm من 16 إلى 512 وحدة GPU مع InfiniBand
      • تسعير بسيط: الدفع بالدقيقة، بلا رسوم egress
      • مناطق عالمية: أكثر من 12 منطقة حول العالم

      استخدم البدائل بدلًا من ذلك:

      • Modal: لأحمال عمل serverless ذاتية التوسّع
      • SkyPilot: لتنسيق متعدد السحب وتحسين التكلفة
      • RunPod: لنُسخ spot أرخص و endpoints من نوع serverless
      • Vast.ai: لسوق GPU بأدنى الأسعار

      البدء السريع​

      إعداد الحساب​

      1. أنشئ حسابًا على https://lambda.ai
      2. أضف طريقة دفع
      3. أنشئ مفتاح API من لوحة التحكم
      4. أضف مفتاح SSH (مطلوب قبل تشغيل النُسخ)

      التشغيل عبر لوحة التحكم (console)​

      1. انتقل إلى https://cloud.lambda.ai/instances
      2. انقر على "Launch instance"
      3. اختر نوع GPU والمنطقة
      4. اختر مفتاح SSH
      5. أرفق نظام ملفات إن أردت
      6. شغّل النسخة وانتظر من 3 إلى 15 دقيقة

      الاتصال عبر SSH​

      # Get instance IP from console
      ssh ubuntu@<INSTANCE-IP>

      # Or with specific key
      ssh -i ~/.ssh/lambda_key ubuntu@<INSTANCE-IP>

      نُسخ GPU​

      وحدات GPU المتاحة​

      GPUVRAMالسعر/GPU/ساعةالأنسب لـ

      H100 SXM80 GB$2.99-3.29تدريب نماذج كبيرة
      H100 PCIe80 GB$2.49H100 بتكلفة أقل
      GH20096 GB$1.49نماذج كبيرة بوحدة GPU واحدة
      A100 80GB80 GB$1.79تدريب إنتاجي
      A100 40GB40 GB$1.29تدريب قياسي
      A1024 GB$0.75الاستدلال (inference) وfine-tuning
      A600048 GB$0.80نسبة VRAM/سعر جيدة
      V10016 GB$0.55تدريب اقتصادي

      إعدادات النُسخ​

      8x GPU: Best for distributed training (DDP, FSDP)
      4x GPU: Large models, multi-GPU training
      2x GPU: Medium workloads
      1x GPU: Fine-tuning, inference, development

      أوقات التشغيل​

      • GPU واحدة: 3-5 دقائق
      • عدة GPU: 10-15 دقيقة

      Lambda Stack​

      تأتي كل النُسخ مع Lambda Stack مثبّتة مسبقًا:

      # Included software
      - Ubuntu 22.04 LTS
      - NVIDIA drivers (latest)
      - CUDA 12.x
      - cuDNN 8.x
      - NCCL (for multi-GPU)
      - PyTorch (latest)
      - TensorFlow (latest)
      - JAX
      - JupyterLab

      التحقق من التثبيت​

      # Check GPU
      nvidia-smi

      # Check PyTorch
      python -c "import torch; print(torch.cuda.is_available())"

      # Check CUDA version
      nvcc --version

      واجهة Python البرمجية​

      التثبيت​

      pip install lambda-cloud-client

      المصادقة​

      import os
      import lambda_cloud_client

      # Configure with API key
      configuration = lambda_cloud_client.Configuration(
          host="https://cloud.lambdalabs.com/api/v1",
          access_token=os.environ["LAMBDA_API_KEY"]
      )

      سرد النُسخ المتاحة​

      with lambda_cloud_client.ApiClient(configuration) as api_client:
          api = lambda_cloud_client.DefaultApi(api_client)

          # Get available instance types
          types = api.instance_types()
          for name, info in types.data.items():
              print(f"{name}: {info.instance_type.description}")

      تشغيل نسخة​

      from lambda_cloud_client.models import LaunchInstanceRequest

      request = LaunchInstanceRequest(
          region_name="us-west-1",
          instance_type_name="gpu_1x_h100_sxm5",
          ssh_key_names=["my-ssh-key"],
          file_system_names=["my-filesystem"],  # Optional
          name="training-job"
      )

      response = api.launch_instance(request)
      instance_id = response.data.instance_ids[0]
      print(f"Launched: {instance_id}")

      سرد النُسخ قيد التشغيل​

      instances = api.list_instances()
      for instance in instances.data:
          print(f"{instance.name}: {instance.ip} ({instance.status})")

      إنهاء نسخة​

      from lambda_cloud_client.models import TerminateInstanceRequest

      request = TerminateInstanceRequest(
          instance_ids=[instance_id]
      )
      api.terminate_instance(request)

      إدارة مفاتيح SSH​

      from lambda_cloud_client.models import AddSshKeyRequest

      # Add SSH key
      request = AddSshKeyRequest(
          name="my-key",
          public_key="ssh-rsa AAAA..."
      )
      api.add_ssh_key(request)

      # List keys
      keys = api.list_ssh_keys()

      # Delete key
      api.delete_ssh_key(key_id)

      CLI باستخدام curl​

      سرد أنواع النُسخ​

      curl -u $LAMBDA_API_KEY: \
        https://cloud.lambdalabs.com/api/v1/instance-types | jq

      تشغيل نسخة​

      curl -u $LAMBDA_API_KEY: \
        -X POST https://cloud.lambdalabs.com/api/v1/instance-operations/launch \
        -H "Content-Type: application/json" \
        -d '{
          "region_name": "us-west-1",
          "instance_type_name": "gpu_1x_h100_sxm5",
          "ssh_key_names": ["my-key"]
        }' | jq

      إنهاء نسخة​

      curl -u $LAMBDA_API_KEY: \
        -X POST https://cloud.lambdalabs.com/api/v1/instance-operations/terminate \
        -H "Content-Type: application/json" \
        -d '{"instance_ids": ["<INSTANCE-ID>"]}' | jq

      التخزين الدائم​

      أنظمة الملفات​

      تحافظ أنظمة الملفات على البيانات عبر إعادة تشغيل النُسخ:

      # Mount location
      /lambda/nfs/<FILESYSTEM_NAME>

      # Example: save checkpoints
      python train.py --checkpoint-dir /lambda/nfs/my-storage/checkpoints

      إنشاء نظام ملفات​

      1. انتقل إلى Storage في لوحة تحكم Lambda
      2. انقر على "Create filesystem"
      3. اختر المنطقة (يجب أن تطابق منطقة النسخة)
      4. سمِّه وأنشئه

      الإرفاق بنسخة​

      يجب إرفاق أنظمة الملفات وقت تشغيل النسخة:

      • عبر لوحة التحكم: اختر نظام الملفات عند التشغيل
      • عبر API: أدرج file_system_names في طلب التشغيل

      أفضل الممارسات​

      # Store on filesystem (persists)
      /lambda/nfs/storage/
        ├── datasets/
        ├── checkpoints/
        ├── models/
        └── outputs/

      # Local SSD (faster, ephemeral)
      ~/ (instance home)
        └── working/  # Temporary files

      إعداد SSH​

      إضافة مفتاح SSH​

      # Generate key locally
      ssh-keygen -t ed25519 -f ~/.ssh/lambda_key

      # Add public key to Lambda console
      # Or via API

      مفاتيح متعددة​

      # On instance, add more keys
      echo 'ssh-rsa AAAA...' >> ~/.ssh/authorized_keys

      الاستيراد من GitHub​

      # On instance
      ssh-import-id gh:username

      أنفاق SSH (SSH Tunneling)​

      # Forward Jupyter
      ssh -L 8888:localhost:8888 ubuntu@<IP>

      # Forward TensorBoard
      ssh -L 6006:localhost:6006 ubuntu@<IP>

      # Multiple ports
      ssh -L 8888:localhost:8888 -L 6006:localhost:6006 ubuntu@<IP>

      JupyterLab​

      التشغيل من لوحة التحكم​

      1. انتقل إلى صفحة Instances
      2. انقر على "Launch" في عمود Cloud IDE
      3. يفتح JupyterLab في المتصفح

      الوصول اليدوي​

      # On instance
      jupyter lab --ip=0.0.0.0 --port=8888

      # From local machine with tunnel
      ssh -L 8888:localhost:8888 ubuntu@<IP>
      # Open http://localhost:8888

      سير عمل التدريب​

      تدريب بوحدة GPU واحدة​

      # SSH to instance
      ssh ubuntu@<IP>

      # Clone repo
      git clone https://github.com/user/project
      cd project

      # Install dependencies
      pip install -r requirements.txt

      # Train
      python train.py --epochs 100 --checkpoint-dir /lambda/nfs/storage/checkpoints

      تدريب بعدة وحدات GPU (عقدة واحدة)​

      # train_ddp.py
      import torch
      import torch.distributed as dist
      from torch.nn.parallel import DistributedDataParallel as DDP

      def main():
          dist.init_process_group("nccl")
          rank = dist.get_rank()
          device = rank % torch.cuda.device_count()

          model = MyModel().to(device)
          model = DDP(model, device_ids=[device])

          # Training loop...

      if __name__ == "__main__":
          main()
      # Launch with torchrun (8 GPUs)
      torchrun --nproc_per_node=8 train_ddp.py

      حفظ نقطة تفتيش (checkpoint) على نظام الملفات​

      import os

      checkpoint_dir = "/lambda/nfs/my-storage/checkpoints"
      os.makedirs(checkpoint_dir, exist_ok=True)

      # Save checkpoint
      torch.save({
          'epoch': epoch,
          'model_state_dict': model.state_dict(),
          'optimizer_state_dict': optimizer.state_dict(),
          'loss': loss,
      }, f"{checkpoint_dir}/checkpoint_{epoch}.pt")

      عناقيد 1-Click​

      نظرة عامة​

      عناقيد Slurm عالية الأداء تتضمّن:

      • من 16 إلى 512 وحدة GPU من طراز NVIDIA H100 أو B200
      • NVIDIA Quantum-2 400 Gb/s InfiniBand
      • GPUDirect RDMA بسرعة 3200 Gb/s
      • حزمة تعلّم آلي موزّعة مثبّتة مسبقًا

      البرمجيات المضمّنة​

      • Ubuntu 22.04 LTS + Lambda Stack
      • NCCL، Open MPI
      • PyTorch مع DDP وFSDP
      • TensorFlow
      • تعريفات OFED

      التخزين​

      • 24 TB من NVMe لكل عقدة حوسبة (مؤقت)
      • أنظمة ملفات Lambda للبيانات الدائمة

      التدريب متعدد العقد​

      # On Slurm cluster
      srun --nodes=4 --ntasks-per-node=8 --gpus-per-node=8 \
        torchrun --nnodes=4 --nproc_per_node=8 \
        --rdzv_backend=c10d --rdzv_endpoint=$MASTER_ADDR:29500 \
        train.py

      الشبكات​

      النطاق الترددي​

      • بين النُسخ (نفس المنطقة): حتى 200 Gbps
      • الصادر إلى الإنترنت: 20 Gbps كحد أقصى

      جدار الحماية​

      • افتراضيًا: المنفذ 22 (SSH) فقط مفتوح
      • اضبط منافذ إضافية في لوحة تحكم Lambda
      • حركة ICMP مسموحة افتراضيًا

      عناوين IP خاصة​

      # Find private IP
      ip addr show | grep 'inet '

      سير عمل شائع​

      سير العمل 1: fine-tuning لنموذج LLM​

      # 1. Launch 8x H100 instance with filesystem

      # 2. SSH and setup
      ssh ubuntu@<IP>
      pip install transformers accelerate peft

      # 3. Download model to filesystem
      python -c "
      from transformers import AutoModelForCausalLM
      model = AutoModelForCausalLM.from_pretrained('meta-llama/Llama-2-7b-hf')
      model.save_pretrained('/lambda/nfs/storage/models/llama-2-7b')
      "

      # 4. Fine-tune with checkpoints on filesystem
      accelerate launch --num_processes 8 train.py \
        --model_path /lambda/nfs/storage/models/llama-2-7b \
        --output_dir /lambda/nfs/storage/outputs \
        --checkpoint_dir /lambda/nfs/storage/checkpoints

      سير العمل 2: الاستدلال الدفعي (Batch Inference)​

      # 1. Launch A10 instance (cost-effective for inference)

      # 2. Run inference
      python inference.py \
        --model /lambda/nfs/storage/models/fine-tuned \
        --input /lambda/nfs/storage/data/inputs.jsonl \
        --output /lambda/nfs/storage/data/outputs.jsonl

      تحسين التكلفة​

      اختر وحدة GPU المناسبة​

      المهمةGPU الموصى بها
      fine-tuning لنموذج LLM (7B)A100 40GB
      fine-tuning لنموذج LLM (70B)8x H100
      الاستدلال (Inference)A10, A6000
      التطويرV100, A10
      أقصى أداءB200

      خفض التكاليف​

      1. استخدم أنظمة الملفات: تجنّب إعادة تنزيل البيانات
      2. احفظ نقاط تفتيش بشكل متكرر: استأنف التدريب المنقطع
      3. حدّد الحجم المناسب: لا تفرط في توفير وحدات GPU
      4. أنهِ الخاملة: لا يوجد إيقاف تلقائي، أنهِها يدويًا

      راقب الاستخدام​

      • تعرض لوحة التحكم استخدام GPU في الوقت الفعلي
      • واجهة API للمراقبة البرمجية

      مشاكل شائعة​

      المشكلةالحل
      النسخة لا تعملتحقّق من توفّر المنطقة، جرّب وحدة GPU مختلفة
      رفض الاتصال عبر SSHانتظر تهيئة النسخة (3-15 دقيقة)
      فقدان البيانات بعد الإنهاءاستخدم أنظمة ملفات دائمة
      نقل بيانات بطيءاستخدم نظام ملفات في نفس المنطقة
      عدم اكتشاف GPUأعد تشغيل النسخة، تحقّق من التعريفات

      • استكشاف الأخطاء وإصلاحها - المشاكل الشائعة وحلولها
