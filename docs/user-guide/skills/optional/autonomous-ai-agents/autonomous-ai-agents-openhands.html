      OpenHands

      فوّض البرمجة إلى OpenHands CLI (مستقل عن النموذج، عبر LiteLLM).

      بيانات المهارة الوصفية​

      المصدراختيارية — ثبّتها باستخدام hermes skills install official/autonomous-ai-agents/openhands
      المسارoptional-skills/autonomous-ai-agents/openhands
      الإصدار0.1.0
      المؤلفTim Koepsel (xzessmedia), Hermes Agent
      الترخيصMIT
      المنصاتlinux, macos
      الوسومCoding-Agent, OpenHands, Model-Agnostic, LiteLLM
      مهارات ذات صلةclaude-code, codex, opencode, hermes-agent

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      OpenHands CLI

      فوّض مهام البرمجة إلى OpenHands CLI عبر أداة terminal. OpenHands مستقل عن النموذج: يعمل مع أي مزوّد مدعوم من LiteLLM (OpenAI، Anthropic، OpenRouter، DeepSeek، Ollama، vLLM، إلخ).

      هذه المهارة هي غلاف الوضع اللاواجهي (headless) للتفويض الدفعي / لمرة واحدة. الواجهة النصية التفاعلية (textual UI) لا تُستخدم من Hermes.

      متى تُستخدم​

      • يريد المستخدم تفويض مهمة برمجية إلى OpenHands تحديدًا.
      • يريد المستخدم وكيلًا برمجيًا يمكنه العمل على مزوّد غير Anthropic / غير OpenAI (DeepSeek، Qwen، Ollama، vLLM، Nous، إلخ) — المهارتان الشقيقتان claude-code وcodex مرتبطتان بمزوّد واحد.
      • تعديلات ملفات متعددة الخطوات + أوامر shell داخل مساحة عمل.

      لـ Claude الأصيل، فضّل claude-code. لـ OpenAI الأصيل، فضّل codex. للـ subagents الأصيلة في Hermes، استخدم delegate_task.

      المتطلبات الأساسية​

      1. ثبّت الأداة الأصلية (تتطلب Python 3.12+ وuv):

        terminal(command="uv tool install openhands --python 3.12")

        تحقّق: openhands --version (حاليًا OpenHands CLI 1.16.0 / SDK v1.21.0 وقت كتابة هذا النص).

      2. اختر نموذجًا واضبط متغيرات البيئة لـ --override-with-envs:

        export LLM_MODEL=openrouter/openai/gpt-4o-mini       # or any LiteLLM slug
        export LLM_API_KEY=$OPENROUTER_API_KEY
        export LLM_BASE_URL=https://openrouter.ai/api/v1     # omit for native OpenAI

        يستخدم LLM_MODEL الصيغة (slug) الكاملة لـ LiteLLM. عندما يكون المزوّد OpenRouter تكون الصيغة مسبوقة مرتين: openrouter/<vendor>/<model> (مثلًا openrouter/anthropic/claude-sonnet-4.5). لـ Anthropic الأصيل: anthropic/claude-sonnet-4-5. لـ OpenAI الأصيل: openai/gpt-4o-mini.

      3. اكتم شعار البدء حتى لا تسبق مخرجات JSON فنون ASCII:

        export OPENHANDS_SUPPRESS_BANNER=1

      طريقة التشغيل​

      نفّذ دائمًا عبر أداة terminal. مرّر دائمًا --headless --json --override-with-envs --exit-without-confirmation للأتمتة.

      مهمة لمرة واحدة​

      terminal(
        command="OPENHANDS_SUPPRESS_BANNER=1 LLM_MODEL=openrouter/openai/gpt-4o-mini LLM_API_KEY=$OPENROUTER_API_KEY LLM_BASE_URL=https://openrouter.ai/api/v1 openhands --headless --json --override-with-envs --exit-without-confirmation -t 'Add error handling to all API calls in src/'",
        workdir="/path/to/project",
        timeout=600
      )

      الخلفية للمهام الطويلة​

      terminal(command="<same as above>", workdir="/path/to/project", background=true, notify_on_complete=true)
      process(action="poll", session_id="<id>")
      process(action="log", session_id="<id>")

      استئناف محادثة سابقة​

      يطبع OpenHands Conversation ID: <32-hex> وسطر Hint: openhands --resume <dashed-uuid> في نهاية كل تشغيل. استخدم الصيغة بالشرطات للاستئناف:

      terminal(
        command="OPENHANDS_SUPPRESS_BANNER=1 LLM_MODEL=... openhands --headless --json --override-with-envs --exit-without-confirmation --resume <dashed-uuid> -t 'Now fix the bug you found'",
        workdir="/path/to/project"
      )

      قائمة الخيارات الفعلية​

      تم التحقق منها مقابل openhands --help (CLI 1.16.0). أي شيء غير مذكور في هذا الجدول ليس خيارًا — مرّره عبر متغير بيئة أو ملف إعدادات.

      الخيارالأثر
      --headlessبلا واجهة، يتطلب -t أو -f. يوافق تلقائيًا على كل الإجراءات (لا يوجد --llm-approve في هذا الوضع).
      --jsonتدفق أحداث JSONL (يتطلب --headless).
      -t TEXTنص المهمة.
      -f PATHقراءة المهمة من ملف.
      --resume [ID]استئناف محادثة. بلا معرّف ← عرض الأحدث.
      --lastاستئناف الأحدث (مع --resume).
      --override-with-envsتطبيق متغيرات LLM_API_KEY / LLM_BASE_URL / LLM_MODEL. بدونه، يستخدم OpenHands ~/.openhands/settings.json ويتجاهل البيئة.
      --exit-without-confirmationعدم إظهار حوار تأكيد الخروج.
      --always-approve / --yoloالموافقة التلقائية على كل إجراء (الافتراضي في --headless).
      --llm-approveبوابة أمان قائمة على LLM (تفاعلية فقط — لا تعمل في الوضع اللاواجهي).
      --version / -vطباعة الإصدار والخروج.

      لا يوجد خيار --model، أو --max-iterations، أو --workspace، أو --sandbox، أو --sandbox-type. النموذج هو LLM_MODEL. ومساحة العمل هي workdir الذي تمرّره إلى أداة terminal. أما الـ sandbox / بيئة التشغيل فهما متغيرا البيئة RUNTIME وSANDBOX_VOLUMES.

      مخطط أحداث JSON​

      مع --json --headless، يُصدر OpenHands JSONL — كائن JSON واحد لكل سطر، بالإضافة إلى بضعة أسطر حالة ليست بصيغة JSON (Initializing agent...، Agent is working، Agent finished، صندوق الملخص النهائي، Goodbye!، Conversation ID:، Hint:). صفِّ الأسطر التي تبدأ بـ {.

      حقل kind على المستوى الأعلى يميّز الأحداث:

      • MessageEvent — دور نصي للمستخدم / الوكيل. source إما user أو agent.
      • ActionEvent — اختار الوكيل أداة. اقرأ tool_name (file_editor، terminal، finish) وaction.kind (FileEditorAction، TerminalAction، FinishAction).
      • ObservationEvent — نتيجة أداة. observation.is_error هو مؤشر النجاح. source هو environment.
      • FinishAction داخل ActionEvent يحمل رسالة الوكيل النهائية في action.message.

      يطبع الـ CLI كل مخرجات stderr من LiteLLM/Authlib أولًا — انظر المزالق. حلّل فقط stdout، سطرًا سطرًا، متجاهلًا الأسطر التي لا تبدأ بـ {.

      المزالق​

      • تحذيرات LiteLLM في كل استدعاء. يطبع الـ CLI تحذيرات bedrock-runtime وsagemaker-runtime إلى stderr لأن botocore غير مثبّت. بالإضافة إلى تحذير إهمال (deprecation) من Authlib. هذه ضوضاء لا إخفاقات. وجّه stderr إلى /dev/null أو صفِّها قبل عرضها للمستخدم.
      • ضجيج الشعار. بدون OPENHANDS_SUPPRESS_BANNER=1، يبدأ كل تشغيل بصندوق ASCII متعدد الأسطر +--+ يُعلن عن الـ SDK. صدِّره دائمًا.
      • --override-with-envs إلزامي للأتمتة. بدونه، يتجاهل OpenHands LLM_API_KEY / LLM_BASE_URL / LLM_MODEL ويعود إلى ~/.openhands/settings.json. في تثبيت جديد هذا الملف غير موجود ويتجمد الـ CLI منتظرًا إعداد أول تشغيل.
      • صيغة اسم النموذج (slug) خاصة بـ LiteLLM، لا بالمزوّد. يعمل openrouter/openai/gpt-4o-mini؛ بينما openai/gpt-4o-mini مع توجيهه إلى OpenRouter لا يعمل. anthropic/claude-sonnet-4-5 (بشرطة) هو Anthropic الأصيل؛ وopenrouter/anthropic/claude-sonnet-4.5 (بنقطة) عبر OpenRouter. أخطئ فيها ← خطأ LiteLLM 400 غامض.
      • pip install openhands-ai الحزمة الخاطئة. تلك هي SDK القديمة V0. الـ CLI الجديد هو uv tool install openhands --python 3.12. لا توجد حزمة conda مدعومة.
      • صيغة معرّف الاستئناف دقيقة. ينتهي الـ CLI بـ Conversation ID: f46573d9cfdb45e492ca189bde40019b (بلا شرطات) ثم سطر Hint: openhands --resume f46573d9-cfdb-45e4-92ca-189bde40019b (بشرطات). استخدم الصيغة بالشرطات.
      • يتجاهل الوضع اللاواجهي --llm-approve. إذا مررته، تحصل على خطأ argparse. يفرض الوضع اللاواجهي الموافقة التلقائية دائمًا.
      • لا دعم لـ Windows من المصدر. تتطلب مستندات OpenHands استخدام WSL على Windows. لذا هذه المهارة مقيَّدة بـ [linux, macos] وفقًا لذلك.
      • ~/.openhands/conversations/<id>/ يتراكم. كل تشغيل يحفظ مسارًا (trajectory). نظّفه إن كنت تشغّل دفعات.
      • تثبيت ثقيل (~200 حزمة). استخدم uv tool install (بيئة venv معزولة) لتجنّب تعارضات الاعتماديات مع المشروع النشط.

      التحقق​

      terminal(
        command="OPENHANDS_SUPPRESS_BANNER=1 LLM_MODEL=openrouter/openai/gpt-4o-mini LLM_API_KEY=$OPENROUTER_API_KEY LLM_BASE_URL=https://openrouter.ai/api/v1 openhands --headless --json --override-with-envs --exit-without-confirmation -t 'Print the string OPENHANDS_OK to stdout via the terminal tool.'",
        workdir="/tmp",
        timeout=120
      )

      إذا انتهى تدفق JSONL بـ FinishAction تذكر رسالته action.message OPENHANDS_OK، فالتثبيت يعمل.
