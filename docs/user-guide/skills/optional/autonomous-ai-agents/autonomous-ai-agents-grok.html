      Grok

      تفويض البرمجة إلى xAI Grok Build CLI (الميزات، الـ PRs).

      المرجع: ملف SKILL.md كاملًا​

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      دليل تنسيق Grok Build CLI مع Hermes

      فوّض مهام البرمجة إلى Grok Build (وكيل البرمجة المستقل من xAI عبر سطر الأوامر، أمر grok) عبر طرفية Hermes. يستطيع Grok قراءة الملفات، وكتابة الكود، وتشغيل أوامر shell، وإطلاق subagents، وإدارة سير عمل git. يعمل بثلاث طرق: واجهة TUI تفاعلية، ووضع بلا واجهة (headless) (-p)، وكـ وكيل ACP عبر JSON-RPC.

      هذه هي المهارة الشقيقة الثالثة لـ codex وclaude-code. نمط التنسيق مطابق تقريبًا — يُفضَّل الوضع بلا واجهة -p للمهام لمرة واحدة، واستخدم PTY للجلسات التفاعلية.

      متى تُستخدم​

      • بناء الميزات
      • إعادة الهيكلة
      • مراجعات PR
      • إصلاح المشكلات دفعيًا
      • أي مهمة كنت لتلجأ فيها عادة إلى Codex / Claude Code لكنك تريد Grok

      المتطلبات المسبقة​

      • التثبيت (المُفضَّل): npm install -g @xai-official/grok
        • يعمل أيضًا المُثبّت الرسمي curl -fsSL https://x.ai/cli/install.sh | bash، لكن مضيف x.ai محجوب خلف Cloudflare في بعض البيئات. مسار npm يتجنّب هذا الاعتماد كليًا.
      • المصادقة — اشتراك SuperGrok / X Premium+ (المسار الأساسي):
        • شغّل grok login مرة واحدة ← يفتح متصفحًا لتنفيذ OAuth ← يُخزَّن token في ~/.grok/auth.json. يستخدم هذا اشتراكك في SuperGrok أو X Premium+ (بلا فوترة لكل token عبر API).
        • تحقق من حالة تسجيل الدخول بالبحث عن ~/.grok/auth.json، أو شغّل اختبارًا سريعًا بلا واجهة: grok --no-auto-update -p "Say ok."
        • في TUI، يسجّل /logout الخروج، ويسجّل /login (أو إعادة التشغيل) الدخول مجددًا.
      • لا حاجة إلى مستودع git — بخلاف Codex، يعمل Grok جيدًا خارج دليل git (مناسب للمهام المؤقتة/غير المحفوظة).
      • متوافق مع Claude Code / AGENTS.md بلا أي إعداد — يقرأ Grok تلقائيًا CLAUDE.md، و.claude/ (المهارات، الوكلاء، خوادم MCP، الـ hooks، القواعد)، وعائلة AGENTS.md. سياق المشروع الحالي يعمل تلقائيًا دون تدخل.

      مفتاح API كخيار احتياطي (ليس الافتراضي لهذا المستخدم): يدعم Grok أيضًا ضبط متغير البيئة XAI_API_KEY للفوترة حسب الاستخدام عبر api.x.ai. استخدم هذا فقط إذا تعذّرت مصادقة grok login / SuperGrok. مسار الاشتراك (grok login) هو الإعداد المقصود هنا.

      وضعا التنسيق​

      الوضع 1: بلا واجهة (-p) — غير تفاعلي (مُفضَّل)​

      يُنفّذ مهمة واحدة، ويطبع النتيجة، ثم يخرج. بلا PTY، وبلا حوارات تفاعلية يجب التنقل بينها. هذا هو مسار التكامل الأنظف — نظير claude -p وcodex exec.

      terminal(command="grok --no-auto-update -p 'Add a dark mode toggle to settings'", workdir="/path/to/project", timeout=180)

      مرّر دائمًا --no-auto-update في الأتمتة لتجاوز فحوصات التحديث في الخلفية.

      متى تستخدم الوضع بلا واجهة:

      • مهام برمجة لمرة واحدة (إصلاح خلل، إضافة ميزة، إعادة هيكلة)
      • أتمتة CI/CD والسكربتة
      • تحليل مخرجات مُهيكلة عبر --output-format json
      • أي مهمة لا تحتاج إلى محادثة متعددة الأدوار

      الوضع 2: PTY تفاعلي — جلسات TUI متعددة الأدوار​

      واجهة TUI هي تطبيق بملء الشاشة وتفاعلي بالماوس. شغّلها بـ pty=true. للمراقبة والإدخال الموثوق استخدم tmux (نفس نمط مهارة claude-code).

      # Launch in a tmux session for capture-pane monitoring
      terminal(command="tmux new-session -d -s grok-work -x 140 -y 40")
      terminal(command="tmux send-keys -t grok-work 'cd /path/to/project && grok' Enter")

      # Wait for startup, then send a task
      terminal(command="sleep 5 && tmux send-keys -t grok-work 'Refactor the auth module to use JWT' Enter")

      # Monitor progress
      terminal(command="sleep 15 && tmux capture-pane -t grok-work -p -S -50")

      # Exit when done
      terminal(command="tmux send-keys -t grok-work '/quit' Enter && sleep 1 && tmux kill-session -t grok-work")

      نصيحة لمخرجات مضمّنة بأسلوب TUI بلا واجهة: إذا أردت مخرجات بأسلوب TUI بلا الاستحواذ على الشاشة الكاملة (alt-screen) (لسجلات أنظف مثلًا)، أضف --no-alt-screen. للأتمتة الخالصة، يبقى الوضع بلا واجهة -p أنظف من TUI.

      تفصيل الوضع بلا واجهة​

      الخيارات الشائعة​

      الخيارالأثر
      -p, --single <PROMPT>أرسل prompt واحدًا، شغّله بلا واجهة، ثم اخرج
      -m, --model <MODEL>اختر نموذجًا
      -s, --session-id <UUID>عيّن UUID جديدًا صالحًا لمحادثة جديدة (يجب ألا يكون موجودًا مسبقًا). لا يستأنف — استخدم --resume/--continue لذلك. صالح فقط مع --resume/--continue عند اقترانه بـ --fork-session
      -r, --resume [<UUID>]استأنف جلسة قائمة عبر UUID الخاص بها (أو الأحدث إن حُذفت)
      -c, --continueتابع أحدث جلسة في الدليل الحالي
      --fork-sessionعند الاستئناف، أنشئ معرّف جلسة جديدًا بدل إعادة استخدام الأصلي
      --max-turns <N>حدّد الحد الأقصى لعدد أدوار الوكيل
      --cwd <PATH>حدّد دليل العمل
      --output-format <FMT>plain (الافتراضي)، أو json، أو streaming-json
      --always-approveوافق تلقائيًا على كل تنفيذ للأدوات (يعادل --full-auto / --yolo)
      --no-alt-screenشغّل مضمّنًا، بلا استحواذ TUI على الشاشة الكاملة
      --no-auto-updateتجاوز فحوصات التحديث في الخلفية (استخدمه في كل أتمتة؛ مخفي عن --help لكنه يعمل)

      صيغ المخرجات​

      • plain — نص قابل للقراءة البشرية (الافتراضي)
      • json — كائن JSON واحد في نهاية التشغيل (لتحليل النتيجة بدقة)
      • streaming-json — أحداث JSON مفصولة بأسطر جديدة عند وصولها
      # Structured result for parsing
      terminal(command="grok --no-auto-update -p 'List all TODO comments in src/' --output-format json", workdir="/project", timeout=120)

      # Auto-approve for autonomous building
      terminal(command="grok --no-auto-update --always-approve -p 'Refactor the database layer and run the tests'", workdir="/project", timeout=300)

      وضع الخلفية (المهام الطويلة)​

      # Start headless in background
      terminal(command="grok --no-auto-update --always-approve -p 'Refactor the auth module'", workdir="/project", background=true, notify_on_complete=true)
      # Returns session_id

      # Monitor
      process(action="poll", session_id="<id>")
      process(action="log", session_id="<id>")

      # Kill if needed
      process(action="kill", session_id="<id>")

      لجلسة خلفية تفاعلية (TUI)، استخدم pty=true + tmux وراقبها عبر tmux capture-pane، تمامًا كما في مهارتَي claude-code / codex.

      استئناف الجلسة​

      الجلسات تُعرَّف بـ UUID، لا بالاسم. يعيّن --session-id UUID جديدًا لتشغيل جديد (لا يستأنف)؛ ويأخذ --resume UUID جلسة قائمة (أو احذف القيمة لاستئناف الأحدث).

      # Start a session with a self-assigned UUID (must be a valid, unused UUID)
      SID=$(uuidgen)
      terminal(command="grok --no-auto-update -s $SID -p 'Start refactoring the database layer' --always-approve", workdir="/project", timeout=240)

      # Resume that exact session later by its UUID
      terminal(command="grok --no-auto-update -r $SID -p 'Now add connection pooling' --always-approve", workdir="/project", timeout=180)

      # Or just continue the most recent session in this directory (no UUID needed)
      terminal(command="grok --no-auto-update -c -p 'What did you change last time?'", workdir="/project", timeout=60)

      نمط التدقيق للقراءة فقط ← ملاحظة Markdown​

      لجعل Grok يراجع مُصنَّفات (artifacts) محلية ويعيد ملاحظة markdown نظيفة (لـ Obsidian أو مستودع) دون تعديل أي شيء:

      1. جهّز ملفات إدخال ثابتة أولًا بأدوات Hermes (read_file، write_file). التقط لقطة (Snapshot) للسياق ذي الصلة فقط في ملف مؤقت بدل تفريغ مسارات خام.
      2. شغّل Grok بلا واجهة دون --always-approve حتى لا يكتب تلقائيًا، واطلب markdown only, no preamble.
      3. احفظ مخرجات Grok القياسية (stdout) مباشرة في الملاحظة الوجهة عبر write_file().
      grok --no-auto-update -p "Read /tmp/current.md and /tmp/inventory.md. Produce markdown only, no preamble. Output a clean note titled 'Cleanup Review'." --output-format plain

      مزلق (كما في Claude Code): عند إعادة كتابة المستندات، قد يعيد prompt فضفاض مثل "أعد كتابة هذا" ملخص تغيير بدل الملف الكامل. بدلًا من ذلك: مرّر الملف عبر الأنبوب (pipe)، واطلب Return ONLY the full revised markdown document. No intro, no explanation, no code fences. Start immediately with '# Title'. تحقق من الأسطر الأولى بـ read_file() قبل الكتابة فوق الوجهة.

      أنماط مراجعة PR​

      مراجعة سريعة (بلا واجهة)​

      terminal(command="cd /path/to/repo && git diff main...feature-branch | grok --no-auto-update -p 'Review this diff for bugs, security issues, and style problems. Be thorough.'", timeout=120)

      مراجعة عبر استنساخ إلى مجلد مؤقت (آمن، بلا تعديل للمستودع)​

      terminal(command="REVIEW=$(mktemp -d) && git clone https://github.com/user/repo.git $REVIEW && cd $REVIEW && gh pr checkout 42 && grok --no-auto-update -p 'Review the changes vs origin/main. Check bugs, security, race conditions, missing tests.'", pty=true, timeout=300)

      نشر المراجعة​

      terminal(command="gh pr comment 42 --body '<review text>'", workdir="/path/to/repo")

      إصلاح المشكلات بالتوازي باستخدام Worktrees​

      # Create worktrees
      terminal(command="git worktree add -b fix/issue-78 /tmp/issue-78 main", workdir="~/project")
      terminal(command="git worktree add -b fix/issue-99 /tmp/issue-99 main", workdir="~/project")

      # Launch Grok headless in each (background)
      terminal(command="grok --no-auto-update --always-approve -p 'Fix issue #78: <description>. Commit when done.'", workdir="/tmp/issue-78", background=true, notify_on_complete=true)
      terminal(command="grok --no-auto-update --always-approve -p 'Fix issue #99: <description>. Commit when done.'", workdir="/tmp/issue-99", background=true, notify_on_complete=true)

      # Monitor
      process(action="list")

      # After completion: push and open PRs
      terminal(command="cd /tmp/issue-78 && git push -u origin fix/issue-78")
      terminal(command="gh pr create --repo user/repo --head fix/issue-78 --title 'fix: ...' --body '...'")

      # Cleanup
      terminal(command="git worktree remove /tmp/issue-78", workdir="~/project")

      أوامر فرعية مفيدة وأوامر TUI​

      الأمرالغرض
      grokابدأ واجهة TUI التفاعلية
      grok -p "query"تشغيل بلا واجهة لمرة واحدة
      grok login / grok logoutتسجيل الدخول / الخروج (OAuth عبر SuperGrok / X Premium+)
      grok inspectاعرض ما اكتشفه Grok في دليل العمل الحالي: مصادر الإعدادات، التعليمات، المهارات، الإضافات، الـ hooks، خوادم MCP
      grok agent stdioشغّله كوكيل ACP عبر JSON-RPC (لتكامل بيئة التطوير/الأدوات)
      grok updateحدّث سطر الأوامر (يحتاج مضيف x.ai؛ تجاوزه في الأتمتة)

      أوامر TUI بشرطة مائلة (تفاعلية فقط): /model <name>، /always-approve، /plan، /context، /compact، /resume، /sessions، /fork، /usage، /quit. يتنقل Shift+Tab بين أوضاع الجلسة (بما فيها وضع Plan، الذي يمنع أدوات الكتابة عدا ملف خطة الجلسة).

      الإعدادات (~/.grok/config.toml)​

      [cli]
      auto_update = false          # skip background update checks persistently

      [ui]
      permission_mode = "ask"      # or "always-approve" to skip tool prompts by default

      [models]
      default = "grok-build-0.1"

      ضع التفضيلات العامة في ~/.grok/config.toml (وليس .grok/config.toml المحصور بالمشروع). يحلّ permission_mode محل مفتاحَي approval_mode / yolo = true القديمين.

      المزالق والتفاصيل الدقيقة​

      1. المصادقة مرتبطة بالاشتراك. يتطلب grok login اشتراك SuperGrok أو X Premium+. إذا فشل تسجيل الدخول أو لم يوجد ~/.grok/auth.json، تأكد من أن الاشتراك فعّال قبل الرجوع إلى XAI_API_KEY.
      2. لا تخلط بين مصادقة xAI الخاصة بـ Hermes ومصادقة سطر أوامر grok. تعمل x_search الخاصة بـ Hermes على OAuth خاص بها من xAI؛ ولسطر أوامر grok المستقل token منفصل في ~/.grok/auth.json. عمل x_search بنجاح لا يعني أن grok مسجّل الدخول.
      3. مرّر دائمًا --no-auto-update في الأتمتة — وإلا يتصل Grok بمصادره لفحص التحديثات (وقد يتعذّر الوصول إلى x.ai/storage.googleapis.com).
      4. يُفضَّل التثبيت عبر npm على مُثبّت curl — يتجنّب npm install -g @xai-official/grok مضيف x.ai المحجوب خلف Cloudflare.
      5. --always-approve هو مفتاح البناء المستقل. بدونه، قد تتوقف التشغيلات بلا واجهة في انتظار موافقات الأدوات. احذفه عمدًا لأعمال المراجعة/التدقيق للقراءة فقط حتى لا يستطيع Grok تعديل الملفات.
      6. يتجاوز الوضع بلا واجهة -p حوارات TUI؛ وتحتاج TUI إلى pty=true (+ tmux للمراقبة)، تمامًا كما Claude Code.
      7. استخدم --no-alt-screen إذا شغّلت TUI مضمّنًا واستحواذ الشاشة الكاملة (alt-screen) يشوّه المخرجات المُلتقَطة.
      8. لا حاجة إلى مستودع git، لكن لسير عمل PR/commit ستحتاج إليه — استخدم mktemp -d && git init لمهام commit المؤقتة.
      9. نظّف جلسات tmux بـ tmux kill-session -t <name> عند الانتهاء.

      قواعد لوكلاء Hermes​

      1. يُفضَّل الوضع بلا واجهة -p للمهام المفردة — أنظف تكامل، ومخرجات مُهيكلة عبر --output-format json.
      2. اضبط دائمًا workdir (أو --cwd) حتى يستهدف Grok المشروع الصحيح.
      3. مرّر --no-auto-update في كل استدعاء آلي.
      4. استخدم --always-approve فقط عندما يجب أن يكتب Grok باستقلالية؛ واحذفه للمراجعات والتدقيقات للقراءة فقط.
      5. ضع المهام الطويلة في الخلفية بـ background=true, notify_on_complete=true وراقبها عبر أداة process.
      6. استخدم tmux للعمل التفاعلي متعدد الأدوار وراقبه بـ tmux capture-pane -t <session> -p -S -50.
      7. تحقق من المصادقة قبل الاعتماد عليها — تحقق من ~/.grok/auth.json أو شغّل اختبارًا رخيصًا grok -p "Say ok."؛ ولا تفترض أن مصادقة xAI الخاصة بـ Hermes تنتقل تلقائيًا.
      8. أبلغ المستخدم بالنتائج — لخّص ما غيّره Grok وما تبقّى.
