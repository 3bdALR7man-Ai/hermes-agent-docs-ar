      Jupyter Notebook

      Python تفاعلي عبر kernel حيّ لـ Jupyter (hamelnb).

      بيانات المهارة الوصفية​

      المصدراختيارية — ثبّتها باستخدام hermes skills install official/data-science/jupyter-notebook

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      Jupyter Notebook (kernel حيّ عبر hamelnb)

      يمنحك REPL حالة (stateful) لـ Python عبر kernel حيّ لـ Jupyter. تبقى المتغيرات محفوظة عبر عمليات التنفيذ المتتالية. استخدم هذا بدلًا من execute_code عندما تحتاج إلى بناء حالة تدريجيًا، أو استكشاف واجهات برمجية، أو فحص DataFrames، أو التكرار على كود معقّد.

      متى تُستخدم هذه مقابل أدوات أخرى​

      الأداةاستخدمها عندما
      هذه المهارةاستكشاف تكراري، حالة محفوظة عبر الخطوات، علوم البيانات، تعلّم الآلة، "دعني أجرّب هذا وأتحقق"
      execute_codeسكربتات لمرة واحدة تحتاج وصولًا لأدوات Hermes (web_search، عمليات الملفات). عديمة الحالة.
      terminalأوامر shell، عمليات البناء، التثبيتات، git، إدارة العمليات

      قاعدة عامة: إذا كنت تريد notebook من Jupyter لهذه المهمة، استخدم هذه المهارة.

      المتطلبات الأساسية​

      1. يجب أن يكون uv مثبّتًا (تحقق: which uv)
      2. يجب أن يكون JupyterLab مثبّتًا: uv tool install jupyterlab
      3. يجب أن يكون خادم Jupyter قيد التشغيل (انظر الإعداد أدناه)

      الإعداد​

      موقع سكربت hamelnb:

      SCRIPT="$HOME/.agent-skills/hamelnb/skills/jupyter-live-kernel/scripts/jupyter_live_kernel.py"

      إذا لم يُستنسخ بعد:

      git clone https://github.com/hamelsmu/hamelnb.git ~/.agent-skills/hamelnb

      تشغيل JupyterLab​

      تحقق مما إذا كان هناك خادم قيد التشغيل بالفعل:

      uv run "$SCRIPT" servers

      إذا لم توجد خوادم، شغّل واحدًا:

      jupyter-lab --no-browser --port=8888 --notebook-dir=$HOME/notebooks \
        --IdentityProvider.token='' --ServerApp.password='' > /tmp/jupyter.log 2>&1 &
      sleep 3

      ملاحظة: الرمز/كلمة المرور معطّلان للوصول المحلي للوكيل. يعمل الخادم بلا واجهة (headless).

      إنشاء notebook للاستخدام كـ REPL​

      إذا كنت تحتاج فقط إلى REPL (بلا notebook موجود)، أنشئ ملف notebook بسيطًا:

      mkdir -p ~/notebooks

      اكتب ملف .ipynb بصيغة JSON بسيطة يحتوي خلية كود فارغة واحدة، ثم ابدأ جلسة kernel عبر واجهة Jupyter REST API:

      curl -s -X POST http://127.0.0.1:8888/api/sessions \
        -H "Content-Type: application/json" \
        -d '{"path":"scratch.ipynb","type":"notebook","name":"scratch.ipynb","kernel":{"name":"python"}}'

      سير العمل الأساسي​

      كل الأوامر تُعيد JSON منظّمًا. استخدم دائمًا --compact لتوفير token.

      1. اكتشاف الخوادم والـ notebooks​

      uv run "$SCRIPT" servers --compact
      uv run "$SCRIPT" notebooks --compact

      2. تنفيذ الكود (العملية الأساسية)​

      uv run "$SCRIPT" execute --path <notebook.ipynb> --code '<python code>' --compact

      تبقى الحالة محفوظة عبر استدعاءات execute المتتالية. المتغيرات وعمليات الاستيراد والكائنات كلها تبقى.

      الكود متعدد الأسطر يعمل مع اقتباس $'...':

      uv run "$SCRIPT" execute --path scratch.ipynb --code $'import os\nfiles = os.listdir(".")\nprint(f"Found {len(files)} files")' --compact

      3. فحص المتغيرات الحيّة​

      uv run "$SCRIPT" variables --path <notebook.ipynb> list --compact
      uv run "$SCRIPT" variables --path <notebook.ipynb> preview --name <varname> --compact

      4. تحرير خلايا الـ notebook​

      # View current cells
      uv run "$SCRIPT" contents --path <notebook.ipynb> --compact

      # Insert a new cell
      uv run "$SCRIPT" edit --path <notebook.ipynb> insert \
        --at-index <N> --cell-type code --source '<code>' --compact

      # Replace cell source (use cell-id from contents output)
      uv run "$SCRIPT" edit --path <notebook.ipynb> replace-source \
        --cell-id <id> --source '<new code>' --compact

      # Delete a cell
      uv run "$SCRIPT" edit --path <notebook.ipynb> delete --cell-id <id> --compact

      5. التحقق (إعادة تشغيل + تنفيذ الكل)​

      استخدمها فقط عندما يطلب المستخدم تحقّقًا نظيفًا أو عندما تحتاج إلى تأكيد أن الـ notebook يعمل من البداية إلى النهاية:

      uv run "$SCRIPT" restart-run-all --path <notebook.ipynb> --save-outputs --compact

      نصائح عملية من الخبرة​

      1. قد ينتهي أول تنفيذ بعد بدء الخادم بمهلة (timeout) — يحتاج الـ kernel لحظة للتهيئة. إذا واجهت مهلة، أعد المحاولة فقط.

      2. Python الخاص بالـ kernel هو Python الخاص بـ JupyterLab — يجب تثبيت الحزم في تلك البيئة. إذا احتجت حزمًا إضافية، ثبّتها أولًا في بيئة أداة JupyterLab.

      3. خيار --compact يوفّر token بشكل ملحوظ — استخدمه دائمًا. مخرجات JSON يمكن أن تكون مطوّلة جدًا بدونه.

      4. للاستخدام كـ REPL محض، أنشئ scratch.ipynb ولا تكلّف نفسك بتحرير الخلايا. استخدم execute بشكل متكرر فقط.

      5. ترتيب المعاملات مهم — خيارات الأمر الفرعي مثل --path تأتي قبل الأمر الفرعي التالي. مثلًا: variables --path nb.ipynb list وليس variables list --path nb.ipynb.

      6. إذا لم تكن هناك جلسة بعد، تحتاج إلى بدء واحدة عبر REST API (انظر قسم الإعداد). لا يمكن للأداة التنفيذ بلا جلسة kernel حيّة.

      7. تُعاد الأخطاء بصيغة JSON مع traceback — اقرأ حقلَي ename وevalue لفهم ما حدث خطأ.

      8. مهلات websocket عرضية — قد تنتهي بعض العمليات بمهلة في المحاولة الأولى، خصوصًا بعد إعادة تشغيل الـ kernel. أعد المحاولة مرة واحدة قبل التصعيد.

      9. إذا كان websocket ينتهي بمهلة باستمرار على هذا الجهاز، اجبر النقل عبر zmq: uv run "$SCRIPT" execute --transport zmq .... العرض: كل execute يعيد "Websocket execution may already have reached the kernel, so auto fallback was skipped". الـ kernel نفّذ العملية فعليًا بنجاح (يُظهر REST أن execution_state=idle ويتزايد execution_count) — فقط قناة رد websocket معطّلة. نقل zmq يستخدم jupyter_client مباشرة ويتجاوز المشكلة.

      10. عند بدء خادم جديد للاستخدام عبر REST فقط، أضف --ServerApp.disable_check_xsrf=True — وإلا يعيد POST /api/sessions "'_xsrf' argument missing from POST" ويفشل إنشاء جلسة الـ kernel.

      قيم المهلة الافتراضية​

      للسكربت مهلة افتراضية 30 ثانية لكل تنفيذ. للعمليات الطويلة، مرّر --timeout 120. استخدم مهلًا سخيّة (60 فأكثر) للإعداد الأولي أو الحوسبة الثقيلة.
