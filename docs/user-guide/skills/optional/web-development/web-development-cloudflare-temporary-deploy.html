      نشر Cloudflare المؤقت

      انشر Worker مباشرًا دون حساب، عبر wrangler --temporary.

      بيانات المهارة الوصفية​

      المصدراختيارية — ثبّتها باستخدام hermes skills install official/web-development/cloudflare-temporary-deploy

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      مهارة نشر Cloudflare المؤقت

      انشر Cloudflare Worker إلى رابط workers.dev مباشر دون أي إعداد حساب، باستخدام wrangler deploy --temporary. يوفّر Cloudflare حسابًا مؤقتًا قابلًا للإهمال، وينشر، ويطبع رابط مطالبة (claim URL) صالحًا لمدة 60 دقيقة؛ والحسابات غير المُطالَب بها تُحذف تلقائيًا. هذا يمنح الوكيل حلقة كتابة ← نشر ← تحقّق سريعة دون أي OAuth أو تسجيل أو نسخ ولصق للرموز (tokens).

      لا تغطّي هذه المهارة عمليات النشر إلى الإنتاج (استخدم wrangler login مع حساب دائم لذلك)، ولا منتجات Cloudflare غير Worker خارج حدود الحساب المؤقت أدناه.

      متى تُستخدم​

      حمّل هذه المهارة عندما يريد المستخدم:

      • شحن كود كتبه الوكيل إلى رابط مباشر دون إنشاء حساب Cloudflare أولًا — "انشر هذا وأعطني رابطًا"
      • التكرار ضمن جلسة تعمل في الخلفية/بشكل مستقل حيث تكون خطوة OAuth عبر المتصفح توقفًا صعبًا
      • بناء نموذج أوّلي أو تقييم Workers بسرعة باستخدام هدف مؤقت قابل للمطالبة
      • بناء حلقة نشر ذاتية التحقّق — انشر، استخدم curl على الرابط المباشر، تأكّد من تطابق الناتج مع الكود، أعد النشر

      متى لا تُستخدم​

      • الإنتاج أو CI/CD ← استخدم حسابًا دائمًا (wrangler login أو CLOUDFLARE_API_TOKEN). يفشل --temporary إذا كانت أي بيانات اعتماد موجودة.
      • Wrangler مصادَق عليه بالفعل ← يُعيد --temporary خطأً بشكل مقصود. شغّل wrangler logout أولًا فقط إذا أراد المستخدم صراحةً نشرًا مؤقتًا قابلًا للإهمال.
      • الاستضافة طويلة الأمد ← تُحذف عمليات النشر المؤقتة بعد 60 دقيقة ما لم تتم المطالبة بها.

      المتطلبات المسبقة​

      • Wrangler 4.102.0 أو أحدث. هذا هو الإصدار الذي أضاف --temporary. الإصدارات الأقدم لا تملكه. تحقّق بـ npx wrangler@latest --version.
      • Node 18 أو أحدث / npm (أو npx، yarn، pnpm). لا حاجة إلى تثبيت عام — npx wrangler@latest يعمل مباشرة.
      • عدم وجود بيانات اعتماد Cloudflare. يعمل --temporary فقط عندما لا يكون Wrangler مصادَقًا عليه: لا تسجيل دخول عبر OAuth، ولا متغير بيئة CLOUDFLARE_API_TOKEN / CLOUDFLARE_API_KEY، ولا OAuth مخزّن مؤقتًا في ~/.wrangler / ~/.config/.wrangler. استخدم بيئة أداة terminal كما هي؛ لا تضبط هذه المتغيرات.
      • اتصال شبكي صادر إلى cloudflare.com وworkers.dev.
      • استخدام --temporary يعني الموافقة على شروط خدمة Cloudflare وسياسة الخصوصية.

      طريقة التشغيل​

      استخدم أداة terminal لكل خطوة. ثبّت الإصدار دائمًا (wrangler@latest أو wrangler@4.102.0 أو أحدث) حتى لا تُشغّل عن طريق الخطأ نسخة wrangler عامة قديمة تفتقر إلى هذا الخيار.

      1. أنشئ Worker بسيطًا (تخطَّ هذه الخطوة إذا كان المشروع موجودًا بالفعل). يحتاج Worker إلى ملف wrangler.toml (أو wrangler.jsonc) وسكربت نقطة دخول. مثال بسيط بلغة TypeScript — اكتب هذه الملفات باستخدام write_file:

        wrangler.jsonc:

        {
          "name": "hello-agent",
          "main": "src/index.ts",
          "compatibility_date": "2025-01-01"
        }

        src/index.ts:

        export default {
          async fetch(): Promise<Response> {
            return new Response("hello cloudflare");
          },
        };

      2. انشر باستخدام --temporary من دليل المشروع:

        npx wrangler@latest deploy --temporary

        يضيف فحص إثبات العمل (proof-of-work) تأخيرًا تلقائيًا قصيرًا. عند النجاح يطبع Wrangler سطر Account: <name> (created) (أو (reused))، ورابط Claim URL، والرابط المباشر https://<worker>.<account>.workers.dev.

      3. حلّل الروابط من ذلك الناتج. شغّل الأداة المساعدة لاستخراجها بموثوقية بدلًا من قراءتها بالعين:

        npx wrangler@latest deploy --temporary 2>&1 | python scripts/parse_deploy_output.py

        (حلّ مسار scripts/parse_deploy_output.py إلى المسار المطلق لهذه المهارة.) يطبع JSON: {"live_url", "claim_url", "account", "account_state", "expires_minutes", "deployed"}.

      4. تحقّق من أن النشر فعّال بالفعل — لا تثق بسجل النشر وحده. استخدم curl على الرابط المباشر وتأكّد من تطابق النص المُعاد مع ما يُعيده الكود:

        curl -sS <live_url>

      5. كرّر العملية. عدّل الكود، وأعد النشر بنفس الأمر npx wrangler@latest deploy --temporary. ضمن نافذة الـ60 دقيقة، يعيد Wrangler استخدام الحساب المؤقت المخزَّن مؤقتًا (Account: <name> (reused))، لذا يبقى الرابط ثابتًا. استخدم curl مجددًا للتأكّد من التغيير.

      6. سلّم رابط المطالبة للمستخدم. أخبره: افتحه خلال 60 دقيقة للاحتفاظ بالنشر وأي موارد؛ وإن لم يطالب به، يُحذف كل شيء تلقائيًا. عامل رابط المطالبة كسرّ — فهو يمنح ملكية الحساب.

      المزالق​

      • --temporary غير مذكور في wrangler deploy --help وليس خيارًا (flag) عامًا. إنه مخفي عمدًا ويظهر ديناميكيًا: عندما يفشل wrangler deploy غير المصادَق عليه، يطبع Wrangler "rerun with --temporary". لا تستنتج أن الخيار غير موجود لمجرد أن --help لا يذكره — تحقّق من الإصدار بدلًا من ذلك.
      • نسخة wrangler عامة قديمة. نسخة wrangler مثبَّتة عامةً وقديمة (< 4.102.0) تفتقر إلى هذا الخيار بصمت. استدعِ دائمًا npx wrangler@latest (أو نسخة مثبَّتة >=4.102.0) حتى تتحكّم في الإصدار.
      • وجود مصادقة ← خطأ حتمي. إذا شُغِّل wrangler login في أي وقت، أو كان CLOUDFLARE_API_TOKEN/CLOUDFLARE_API_KEY مضبوطًا، يُعيد --temporary خطأً. إمّا ألغِ ضبط المتغير لهذا الـ shell أو نفّذ wrangler logout. لا تحذف بيانات اعتماد المستخدم الحقيقية أبدًا دون إخباره.
      • حدّ المعدل (rate limiting). إنشاء حسابات مؤقتة بسرعة كبيرة يفشل. أعد استخدام الحساب المخزَّن مؤقتًا (فقط أعد النشر) ضمن نافذة الـ60 دقيقة بدلًا من فرض حساب جديد؛ وإن واجهت حدّ المعدل، انتظر أو استخدم حسابًا دائمًا.
      • انتهاء صلاحية حتمي بعد 60 دقيقة، غير قابل للتمديد. إذا احتاج النشر للبقاء أكثر من ساعة، يجب على المستخدم المطالبة به. وضّح ذلك بجلاء.
      • قد يعرض curl النص القديم لوقت قصير بعد إعادة النشر. يملك workers.dev ذاكرة تخزين مؤقتة طرفية قصيرة الأمد؛ سطر (reused) مع Current Version ID جديد يؤكّدان نجاح النشر حتى لو أظهر curl محتوى قديمًا لبضع ثوانٍ. أعد تشغيل curl، أو أضف سلسلة استعلام لكسر التخزين المؤقت، قبل أن تستنتج فشل إعادة النشر.
      • لا تُدرج رابط المطالبة في محادثات مشتركة باعتباره "مجرد رابط". فهو يعادل بيانات اعتماد.

      التحقق​

      • يُعيد npx wrangler@latest --version قيمة >= 4.102.0.
      • يطبع npx wrangler@latest deploy --temporary رابطًا مباشرًا من workers.dev ورابط مطالبة claim-preview?claimToken=.
      • يُعيد curl -sS <live_url> النص الدقيق الذي يُنتجه كود Worker.
      • تُظهر عملية نشر ثانية Account: <name> (reused) ويبقى الرابط المباشر دون تغيير.
      • ينجح الاختبار الذاتي لسكربت التحليل: python scripts/parse_deploy_output.py --selftest.
