      GitNexus Explorer

      شغّل واجهة ويب تفاعلية لعرض رسم بياني معرفي (knowledge graph) لقاعدة الكود (codebase).

      بيانات المهارة الوصفية​

      المصدراختيارية — ثبّتها باستخدام hermes skills install official/research/gitnexus-explorer
      المسارoptional-skills/research/gitnexus-explorer
      الإصدار1.0.0
      المؤلفHermes Agent + Teknium
      الترخيصMIT
      المنصاتlinux, macos, windows
      الوسومgitnexus, code-intelligence, knowledge-graph, visualization
      مهارات ذات صلةhermes-agent, codebase-inspection

      المرجع: ملف SKILL.md كاملًا​

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      GitNexus Explorer

      فهرِس أي قاعدة كود في رسم بياني معرفي، وشغّل واجهة ويب تفاعلية لاستكشاف الرموز (symbols) وسلاسل الاستدعاء والتجمّعات (clusters) ومسارات التنفيذ. تُربط عبر نفق Cloudflare للوصول عن بُعد.

      متى تُستخدم​

      • يريد المستخدم استكشاف بنية قاعدة كود بصريًا
      • يطلب المستخدم رسمًا بيانيًا معرفيًا / رسمًا بيانيًا للاعتماديات لمستودع
      • يريد المستخدم مشاركة مستكشف تفاعلي لقاعدة الكود مع شخص آخر

      المتطلبات المسبقة​

      • Node.js (الإصدار 18 فما فوق) — مطلوب لـ GitNexus وللـ proxy
      • git — يجب أن يحتوي المستودع مجلد .git
      • cloudflared — لإنشاء النفق (يُثبَّت تلقائيًا في ~/.local/bin إن لم يكن موجودًا)

      تحذير بشأن الحجم​

      تعرض واجهة الويب جميع العُقد داخل المتصفح. المستودعات التي تحتوي أقل من 5000 ملف تعمل جيدًا. المستودعات الكبيرة (30 ألف عقدة فأكثر) ستكون بطيئة أو قد تُعطِّل تبويب المتصفح. تعمل أدوات CLI/MCP عند أي حجم — القيد يخص واجهة العرض على الويب فقط.

      الخطوات​

      1. استنساخ وبناء GitNexus (إعداد لمرة واحدة)​

      GITNEXUS_DIR="${GITNEXUS_DIR:-$HOME/.local/share/gitnexus}"

      if [ ! -d "$GITNEXUS_DIR/gitnexus-web/dist" ]; then
        git clone https://github.com/abhigyanpatwari/GitNexus.git "$GITNEXUS_DIR"
        cd "$GITNEXUS_DIR/gitnexus-shared" && npm install && npm run build
        cd "$GITNEXUS_DIR/gitnexus-web" && npm install
      fi

      2. تعديل واجهة الويب للوصول عن بُعد​

      تستخدم واجهة الويب افتراضيًا localhost:4747 لاستدعاءات API. عدِّلها لتستخدم نفس المصدر (same-origin) بحيث تعمل عبر نفق/proxy:

      الملف: $GITNEXUS_DIR/gitnexus-web/src/config/ui-constants.ts غيّر:

      export const DEFAULT_BACKEND_URL = 'http://localhost:4747';

      إلى:

      export const DEFAULT_BACKEND_URL = typeof window !== 'undefined' && window.location.hostname !== 'localhost' ? window.location.origin : 'http://localhost:4747';

      الملف: $GITNEXUS_DIR/gitnexus-web/vite.config.ts أضف allowedHosts: true داخل قسم server: { } (مطلوب فقط عند تشغيل وضع التطوير (dev) بدلًا من البناء الإنتاجي (production build)):

      server: {
          allowedHosts: true,
          // ... existing config
      },

      ثم ابنِ الحزمة الإنتاجية:

      cd "$GITNEXUS_DIR/gitnexus-web" && npx vite build

      3. فهرسة المستودع الهدف​

      cd /path/to/target-repo
      npx gitnexus analyze --skip-agents-md
      rm -rf .claude/    # remove Claude Code-specific artifacts

      أضف --embeddings للبحث الدلالي (semantic search) (أبطأ — دقائق بدلًا من ثوانٍ).

      يقيم الفهرس في .gitnexus/ داخل المستودع (يُستثنى تلقائيًا في gitignore).

      4. إنشاء سكربت الـ proxy​

      اكتب هذا في ملف (مثلًا $GITNEXUS_DIR/proxy.mjs). يخدّم واجهة الويب الإنتاجية ويمرِّر /api/* إلى خلفية (backend) GitNexus — بنفس المصدر، دون مشكلات CORS، ودون sudo أو nginx.

      import http from 'node:http';
      import fs from 'node:fs';
      import path from 'node:path';

      const API_PORT = parseInt(process.env.API_PORT || '4747');
      const DIST_DIR = process.argv[2] || './dist';
      const PORT = parseInt(process.argv[3] || '8888');

      const MIME = {
        '.html': 'text/html', '.js': 'application/javascript', '.css': 'text/css',
        '.json': 'application/json', '.png': 'image/png', '.svg': 'image/svg+xml',
        '.ico': 'image/x-icon', '.woff2': 'font/woff2', '.woff': 'font/woff',
        '.wasm': 'application/wasm',
      };

      function proxyToApi(req, res) {
        const opts = {
          hostname: '127.0.0.1', port: API_PORT,
          path: req.url, method: req.method, headers: req.headers,
        };
        const proxy = http.request(opts, (upstream) => {
          res.writeHead(upstream.statusCode, upstream.headers);
          upstream.pipe(res, { end: true });
        });
        proxy.on('error', () => { res.writeHead(502); res.end('Backend unavailable'); });
        req.pipe(proxy, { end: true });
      }

      function serveStatic(req, res) {
        let filePath = path.join(DIST_DIR, req.url === '/' ? 'index.html' : req.url.split('?')[0]);
        if (!fs.existsSync(filePath)) filePath = path.join(DIST_DIR, 'index.html');
        const ext = path.extname(filePath);
        const mime = MIME[ext] || 'application/octet-stream';
        try {
          const data = fs.readFileSync(filePath);
          res.writeHead(200, { 'Content-Type': mime, 'Cache-Control': 'public, max-age=3600' });
          res.end(data);
        } catch { res.writeHead(404); res.end('Not found'); }
      }

      http.createServer((req, res) => {
        if (req.url.startsWith('/api')) proxyToApi(req, res);
        else serveStatic(req, res);
      }).listen(PORT, () => console.log(`GitNexus proxy on http://localhost:${PORT}`));

      5. تشغيل الخدمات​

      # Terminal 1: GitNexus backend API
      npx gitnexus serve &

      # Terminal 2: Proxy (web UI + API on one port)
      node "$GITNEXUS_DIR/proxy.mjs" "$GITNEXUS_DIR/gitnexus-web/dist" 8888 &

      للتحقّق: يجب أن يعيد curl -s http://localhost:8888/api/repos المستودع(ات) المفهرسة.

      6. إنشاء نفق عبر Cloudflare (اختياري — للوصول عن بُعد)​

      # Install cloudflared if needed (no sudo)
      if ! command -v cloudflared &>/dev/null; then
        mkdir -p ~/.local/bin
        curl -sL https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64 \
          -o ~/.local/bin/cloudflared
        chmod +x ~/.local/bin/cloudflared
        export PATH="$HOME/.local/bin:$PATH"
      fi

      # Start tunnel (--config /dev/null avoids conflicts with existing named tunnels)
      cloudflared tunnel --config /dev/null --url http://localhost:8888 --no-autoupdate --protocol http2

      يُطبع رابط النفق (مثل https://random-words.trycloudflare.com) على stderr. شاركه — يمكن لأي شخص لديه الرابط استكشاف الرسم البياني.

      7. التنظيف​

      # Stop services
      pkill -f "gitnexus serve"
      pkill -f "proxy.mjs"
      pkill -f cloudflared

      # Remove index from the target repo
      cd /path/to/target-repo
      npx gitnexus clean
      rm -rf .claude/

      المزالق​

      • --config /dev/null مطلوب لـ cloudflared إذا كان لدى المستخدم إعداد نفق مُسمّى موجود مسبقًا في ~/.cloudflared/config.yml. بدونه، تُعيد قاعدة التوجيه الشاملة (catch-all ingress rule) في الإعداد الخطأ 404 لجميع طلبات النفق السريع.

      • البناء الإنتاجي إلزامي لإنشاء النفق. يحجب خادم التطوير Vite افتراضيًا المضيفين غير المحليين (allowedHosts). يتجنّب البناء الإنتاجي مع proxy الخاص بـ Node هذا تمامًا.

      • واجهة الويب لا تُنشئ .claude/ أو CLAUDE.md. تلك يُنشئها npx gitnexus analyze. استخدم --skip-agents-md لتجاهل ملفات markdown، ثم rm -rf .claude/ للباقي. هذه تكاملات خاصة بـ Claude Code لا يحتاجها مستخدمو hermes-agent.

      • حدّ ذاكرة المتصفح. تحمّل واجهة الويب الرسم البياني كاملًا في ذاكرة المتصفح. قد تكون المستودعات التي تحتوي 5 آلاف ملف فأكثر بطيئة. أما 30 ألف ملف فأكثر فستُعطِّل التبويب على الأرجح.

      • Embeddings اختيارية. يفعّل --embeddings البحث الدلالي لكنه يستغرق دقائق على المستودعات الكبيرة. تجاوزه للاستكشاف السريع؛ أضِفه إذا أردت استعلامات بلغة طبيعية عبر لوحة محادثة الذكاء الاصطناعي.

      • مستودعات متعددة. يخدّم gitnexus serve جميع المستودعات المفهرسة. فهرِس عدة مستودعات، شغّل serve مرة واحدة، وتتيح لك واجهة الويب التبديل بينها.
