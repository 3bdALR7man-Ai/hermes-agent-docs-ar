      تصحيح REST/GraphQL

      صحّح واجهات REST/GraphQL: رموز الحالة، المصادقة، المخططات، إعادة الإنتاج.

      بيانات المهارة الوصفية​

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      اختبار وتصحيح API

      نفّذ تشخيص REST وGraphQL عبر أدوات Hermes — terminal لأمر curl، وexecute_code لاستخدام requests في Python، وweb_extract لمستندات المزوّد. اعزل الطبقة المُعطَّلة قبل تخمين الإصلاح.

      متى تُستخدم​

      • تُعيد الواجهة رمز حالة أو نصًا غير متوقع
      • فشل المصادقة (401/403 بعد تحديث token، أو OAuth، أو مفتاح API)
      • تعمل في Postman لكنها تفشل في الكود
      • تصحيح تكامل webhook / callback
      • بناء أو مراجعة اختبارات تكامل API
      • مشكلات حدّ المعدل (rate limiting) أو التقسيم إلى صفحات (pagination)

      تخطَّها بالنسبة لعرض واجهة المستخدم، أو ضبط استعلامات قاعدة البيانات، أو بنية DNS/جدار الحماية التحتية (صعّدها لجهة أخرى).

      المبدأ الأساسي​

      اعزل الطبقة، ثم أصلح. قد تُخفي استجابة 200 OK بيانات معطوبة. وقد يُخفي خطأ 500 خطأً إملائيًا بحرف واحد في المصادقة. تتبّع السلسلة بالترتيب؛ لا تتخطَّ أي خطوة أبدًا.

      1. Connectivity   → can we reach the host at all?
      1.5 Timeouts      → connect-slow vs read-slow?
      2. TLS/SSL        → cert valid and trusted?
      3. Auth           → credentials correct and unexpired?
      4. Request format → payload shape match server expectations?
      5. Response parse → does our code accept what came back?
      6. Semantics      → does the data mean what we assume?

      بدء سريع خلال 5 دقائق​

      REST عبر terminal​

      # Verbose request/response exchange
      terminal('curl -v https://api.example.com/users/1')

      # POST with JSON
      terminal("""curl -X POST https://api.example.com/users \\
        -H 'Content-Type: application/json' \\
        -H "Authorization: Bearer $TOKEN" \\
        -d '{"name":"test","email":"test@example.com"}'""")

      # Headers only
      terminal('curl -sI https://api.example.com/health')

      # Pretty-print JSON
      terminal('curl -s https://api.example.com/users | python -m json.tool')

      GraphQL عبر terminal​

      terminal("""curl -X POST https://api.example.com/graphql \\
        -H 'Content-Type: application/json' \\
        -H "Authorization: Bearer $TOKEN" \\
        -d '{"query":"{ user(id: 1) { name email } }"}'""")

      مأزق GraphQL: غالبًا ما تُعيد الخوادم رمز HTTP 200 حتى عندما يفشل الاستعلام. افحص دائمًا حقل errors بصرف النظر عن رمز الحالة:

      execute_code('''
      import os, requests
      resp = requests.post(
          "https://api.example.com/graphql",
          json={"query": "{ user(id: 1) { name email } }"},
          headers={"Authorization": f"Bearer {os.environ['TOKEN']}"},
          timeout=10,
      )
      data = resp.json()
      if data.get("errors"):
          for err in data["errors"]:
              print(f"GraphQL error: {err['message']} (path: {err.get('path')})")
      print(data.get("data"))
      ''')

      Python (باستخدام requests) عبر execute_code​

      execute_code('''
      import requests
      resp = requests.get(
          "https://api.example.com/users/1",
          headers={"Authorization": "Bearer <TOKEN>"},
          timeout=(3.05, 30),  # (connect, read)
      )
      print(resp.status_code, dict(resp.headers))
      print(resp.text[:500])
      ''')

      تدفّق التصحيح المتدرّج​

      الخطوة 1 — الاتصال​

      terminal('nslookup api.example.com')
      terminal('curl -v --connect-timeout 5 https://api.example.com/health')

      الأعطال: عدم تحليل DNS، جدار حماية، الحاجة إلى VPN، proxy مفقود.

      الخطوة 1.5 — انتهاء المهلة (Timeouts)​

      ميّز بين عدم القدرة على الوصول والوصول ببطء:

      terminal('''curl -w "dns:%{time_namelookup}s connect:%{time_connect}s tls:%{time_appconnect}s ttfb:%{time_starttransfer}s total:%{time_total}s\\n" \\
        -o /dev/null -s https://api.example.com/endpoint''')

      في Python، مرّر دائمًا مهلة على شكل tuple — فمكتبة requests لا تملك قيمة افتراضية وستنتظر إلى ما لا نهاية:

      execute_code('''
      import requests
      from requests.exceptions import ConnectTimeout, ReadTimeout
      try:
          requests.get(url, timeout=(3.05, 30))
      except ConnectTimeout:
          print("Cannot reach host — DNS, firewall, VPN")
      except ReadTimeout:
          print("Connected but server is slow")
      ''')

      التشخيص: ارتفاع time_connect يدل على مشكلة شبكة/جدار حماية؛ وارتفاع time_starttransfer مع انخفاض time_connect يدل على خادم بطيء.

      الخطوة 2 — TLS/SSL​

      terminal('curl -vI https://api.example.com 2>&1 | grep -E "SSL|subject|expire|issuer"')

      الأعطال: شهادة منتهية الصلاحية، شهادة موقّعة ذاتيًا، عدم تطابق اسم المضيف، حزمة CA مفقودة. استخدم -k فقط للتصحيح المؤقت، ولا تستخدمها أبدًا في الكود.

      الخطوة 3 — المصادقة​

      # Token validity check
      terminal('curl -s -o /dev/null -w "%{http_code}\\n" -H "Authorization: Bearer $TOKEN" https://api.example.com/me')

      # Decode JWT exp claim — handles base64url padding correctly
      execute_code('''
      import json, base64, os
      tok = os.environ["TOKEN"]
      payload = tok.split(".")[1]
      payload += "=" * (-len(payload) % 4)
      print(json.dumps(json.loads(base64.urlsafe_b64decode(payload)), indent=2))
      ''')

      قائمة تحقق:

      • هل انتهت صلاحية الـ token؟ (خاصية exp في JWT)
      • هل المخطط (scheme) الصحيح مستخدم؟ Bearer مقابل Basic مقابل Token مقابل X-Api-Key
      • هل البيئة صحيحة؟ استخدام مفتاح staging على prod خطأ كلاسيكي
      • هل مفتاح API في الترويسة (header) أم في معامل الاستعلام (?api_key=…)؟

      الخطوة 4 — صيغة الطلب​

      terminal("""curl -v -X POST https://api.example.com/endpoint \\
        -H 'Content-Type: application/json' \\
        -d '{"key":"value"}' 2>&1""")

      عدم تطابق Content-Type / نص الطلب — خطأ 415/400 الصامت:

      # WRONG — data= sends form-encoded, header lies
      requests.post(url, data='{"k":"v"}', headers={"Content-Type": "application/json"})

      # RIGHT — json= auto-sets header AND serializes
      requests.post(url, json={"k": "v"})

      # WRONG — Accept says XML, code calls .json()
      requests.get(url, headers={"Accept": "text/xml"})

      # RIGHT — let requests build multipart with boundary
      requests.post(url, files={"file": open("doc.pdf", "rb")})

      شائع: form-encoded مقابل JSON، حقول مطلوبة مفقودة، طريقة HTTP خاطئة، معاملات استعلام غير مُرمَّزة.

      الخطوة 5 — تحليل الاستجابة​

      افحص دائمًا نوع المحتوى (content-type) قبل استدعاء .json():

      execute_code('''
      import requests
      resp = requests.post(url, json=payload, timeout=10)
      print(f"status={resp.status_code}")
      print(f"headers={dict(resp.headers)}")
      ct = resp.headers.get("Content-Type", "")
      if "application/json" in ct:
          print(resp.json())
      else:
          print(f"unexpected content-type {ct!r}, body={resp.text[:500]!r}")
      ''')

      الأعطال: صفحة خطأ HTML بدلًا من JSON المتوقّع، نص فارغ، ترميز محارف (charset) خاطئ.

      الخطوة 6 — التحقق الدلالي​

      تم التحليل بنجاح — لكن هل البيانات صحيحة؟

      • هل "status": "active" يعني ما يفترضه الكود؟
      • هل المعرّف (ID) في الاستجابة يطابق المطلوب؟
      • هل الطوابع الزمنية في المنطقة الزمنية المتوقعة؟
      • هل التقسيم إلى صفحات (pagination) يُعيد كل النتائج، أم الصفحة الأولى فقط؟

      دليل رموز حالة HTTP​

      401 Unauthorized — بيانات اعتماد مفقودة أو غير صالحة​

      1. هل ترويسة Authorization موجودة فعليًا؟ (تأكّد بـ curl -v)
      2. هل الـ token صحيح وغير منتهي الصلاحية؟
      3. هل مخطط المصادقة (auth scheme) صحيح؟ (Bearer مقابل Basic مقابل Token)
      4. بعض الواجهات تستخدم معامل استعلام (?api_key=…) بدلًا من ترويسة.

      403 Forbidden — مصادَق عليه لكن غير مخوَّل​

      1. هل يملك الـ token الصلاحيات/النطاقات (scopes) المطلوبة؟
      2. هل المورد مملوك لحساب آخر؟
      3. هل قائمة IP المسموح بها تحظرك؟
      4. هل هي مشكلة CORS في المتصفح؟ (تحقّق من Access-Control-Allow-Origin)

      404 Not Found — المورد غير موجود أو الرابط خاطئ​

      1. هل المسار صحيح؟ (شرطة مائلة زائدة، خطأ إملائي، بادئة الإصدار)
      2. هل معرّف المورد موجود؟
      3. هل إصدار API صحيح (/v1/ مقابل /v2/)؟
      4. هل الرابط الأساسي (base URL) صحيح (staging مقابل prod)؟

      409 Conflict — تعارض في الحالة​

      1. هل المورد موجود مسبقًا (إنشاء مكرّر)؟
      2. هل ETag / If-Match غير محدَّث؟
      3. هل هناك تعديل متزامن من عملية أخرى؟

      422 Unprocessable Entity — JSON صالح، بيانات غير صالحة​

      عادةً ما يذكر نص الخطأ الحقول الخاطئة. تحقّق من:

      • أنواع الحقول (نص مقابل عدد صحيح، صيغة التاريخ)
      • الحقول المطلوبة مقابل الاختيارية
      • قيم enum ضمن المجموعة المسموح بها

      429 Too Many Requests — تجاوز حدّ المعدل​

      تحقّق من ترويستَي Retry-After وX-RateLimit-*. تراجع أُسّي (exponential backoff):

      execute_code('''
      import time, requests

      def with_backoff(method, url, **kwargs):
          for attempt in range(5):
              resp = requests.request(method, url, **kwargs)
              if resp.status_code != 429:
                  return resp
              wait = int(resp.headers.get("Retry-After", 2 ** attempt))
              time.sleep(wait)
          return resp
      ''')

      5xx — من جانب الخادم، غالبًا ليس خطأك​

      • 500 — خلل في الخادم. سجّل معرّف الترابط (correlation ID) وأبلغ المزوّد.
      • 502 — الخادم الأعلى (upstream) متوقف. تراجع + إعادة محاولة.
      • 503 — حمل زائد / صيانة. تحقّق من صفحة الحالة.
      • 504 — انتهت مهلة الخادم الأعلى. قلّل حجم البيانات أو ارفع المهلة.

      لكل رموز 5xx: تراجع مع jitter، وأصدر تنبيهًا إذا استمر الخطأ.

      التقسيم إلى صفحات والقُصدية (Idempotency)​

      التقسيم إلى صفحات. تحقّق من أنك تحصل على كل النتائج. ابحث عن next_cursor، next_page، total_count. نمطان:

      • الإزاحة (offset) (?limit=100&offset=200) — بسيط، لكن قد يتخطّى عناصر إذا تغيّرت البيانات.
      • المؤشر (cursor) (?cursor=abc123) — مفضّل للبيانات الحية أو المجموعات الكبيرة.

      القُصدية (Idempotency). للعمليات غير القُصدية (POST)، أرسل Idempotency-Key: <uuid> حتى لا تتسبب إعادة المحاولة في خصم مزدوج / إنشاء مزدوج. إلزامي للمدفوعات والطلبات.

      التحقق من العقد (Contract Validation)​

      اكتشف انحراف المخطط (schema) قبل أن يصل إلى الإنتاج:

      execute_code('''
      import requests

      def validate_user(data: dict) -> list[str]:
          errors = []
          required = {"id": int, "email": str, "created_at": str}
          for field, expected in required.items():
              if field not in data:
                  errors.append(f"missing field: {field}")
              elif not isinstance(data[field], expected):
                  errors.append(f"{field}: want {expected.__name__}, got {type(data[field]).__name__}")
          return errors

      resp = requests.get(f"{BASE}/users/1", headers=HEADERS, timeout=10)
      issues = validate_user(resp.json())
      if issues:
          print(f"contract violations: {issues}")
      ''')

      شغّله بعد ترقيات API، وعند التكامل مع أطراف ثالثة جديدة، أو ضمن اختبارات CI السريعة (smoke tests).

      معرّفات الترابط (Correlation IDs)​

      احرص دائمًا على تسجيل معرّف الطلب الخاص بالمزوّد — أسرع طريق لدعم المزوّد:

      execute_code('''
      import requests
      resp = requests.post(url, json=payload, headers=headers, timeout=10)
      request_id = (
          resp.headers.get("X-Request-Id")
          or resp.headers.get("X-Trace-Id")
          or resp.headers.get("CF-Ray")  # Cloudflare
      )
      if resp.status_code >= 400:
          print(f"failed status={resp.status_code} req_id={request_id} ts={resp.headers.get('Date')}")
      ''')

      قالب تقرير خطأ للمزوّد:

      Endpoint:    POST /api/v1/orders
      Request ID:  req_abc123xyz
      Timestamp:   2026-03-17T14:30:00Z
      Status:      500
      Expected:    201 with order object
      Actual:      500 {"error":"internal server error"}
      Repro:       curl -X POST … (auth: <REDACTED>)

      قالب اختبار الانحدار (Regression)​

      ضع هذا في tests/ وشغّله عبر terminal('pytest tests/test_api_smoke.py -v'):

      import os, requests, pytest

      BASE_URL = os.environ.get("API_BASE_URL", "https://api.example.com")
      TOKEN    = os.environ.get("API_TOKEN", "")
      HEADERS  = {"Authorization": f"Bearer {TOKEN}"}

      class TestAPISmoke:
          def test_health(self):
              resp = requests.get(f"{BASE_URL}/health", timeout=5)
              assert resp.status_code == 200

          def test_list_users_returns_array(self):
              resp = requests.get(f"{BASE_URL}/users", headers=HEADERS, timeout=10)
              assert resp.status_code == 200
              data = resp.json()
              assert isinstance(data.get("data", data), list)

          def test_get_user_required_fields(self):
              resp = requests.get(f"{BASE_URL}/users/1", headers=HEADERS, timeout=10)
              assert resp.status_code in (200, 404)
              if resp.status_code == 200:
                  user = resp.json()
                  assert "id" in user and "email" in user

          def test_invalid_auth_returns_401(self):
              resp = requests.get(
                  f"{BASE_URL}/users",
                  headers={"Authorization": "Bearer invalid-token"},
                  timeout=10,
              )
              assert resp.status_code == 401

      الأمان​

      التعامل مع الـ token​

      • لا تسجّل رموز (tokens) كاملة في السجلّات أبدًا. احجبها: Bearer <REDACTED>.
      • لا تُدرج الرموز في الكود مباشرةً أبدًا. اقرأها من متغيرات البيئة (os.environ["API_TOKEN"]) أو من ${HERMES_HOME:-~/.hermes}/.env.
      • غيّر الرمز فورًا إذا ظهر في السجلّات، أو رسائل الخطأ، أو تاريخ git.

      التسجيل الآمن​

      def redact_auth(headers: dict) -> dict:
          sensitive = {"authorization", "x-api-key", "cookie", "set-cookie"}
          return {k: ("<REDACTED>" if k.lower() in sensitive else v) for k, v in headers.items()}

      قائمة تحقق من التسريبات​

      • بيانات اعتماد في الروابط. مفاتيح API في معاملات الاستعلام تنتهي في سجلّات الخادم، وسجل المتصفح، وترويسات referrer — استخدم الترويسات (headers) بدلًا من ذلك.
      • معلومات تعريف شخصية (PII) في استجابات الخطأ. لا ينبغي لخطأ 404 on /users/123 أن يكشف ما إذا كان المستخدم موجودًا (تعداد/enumeration).
      • تتبّعات المكدّس (stack traces) في الإنتاج. لا ينبغي لأخطاء 500 أن تسرّب مسارات الملفات أو إصدارات إطار العمل.
      • أسماء مضيفين/عناوين IP داخلية. مثل 10.x.x.x أو internal-api.corp.local في نصوص الخطأ.
      • رموز يُعاد إظهارها. بعض الواجهات تُضمِّن رمز المصادقة في تفاصيل الخطأ. تحقّق من أنها لا تفعل ذلك.
      • ترويستا Server / X-Powered-By المطوّلتان. تسريب معلومات المكدّس التقني. سجّلها للمراجعة الأمنية.

      أنماط أدوات Hermes​

      terminal — لـ curl وdig وopenssl​

      terminal('curl -sI https://api.example.com')
      terminal('openssl s_client -connect api.example.com:443 -servername api.example.com </dev/null 2>/dev/null | openssl x509 -noout -dates')

      execute_code — لتدفقات Python متعددة الخطوات​

      عندما يمتد التصحيح عبر مصادقة ← جلب ← تقسيم إلى صفحات ← تحقّق، استخدم execute_code. تبقى المتغيرات محفوظة طوال السكربت، وتُطبع النتائج على stdout، دون خطر إغراق سياقك (context) بالرموز:

      execute_code('''
      import os, requests

      token = os.environ["API_TOKEN"]
      base  = "https://api.example.com"
      H     = {"Authorization": f"Bearer {token}"}

      # 1. auth
      me = requests.get(f"{base}/me", headers=H, timeout=10)
      print(f"auth {me.status_code}")

      # 2. paginate
      all_users, cursor = [], None
      while True:
          params = {"cursor": cursor} if cursor else {}
          r = requests.get(f"{base}/users", headers=H, params=params, timeout=10)
          body = r.json()
          all_users.extend(body["data"])
          cursor = body.get("next_cursor")
          if not cursor:
              break
      print(f"users={len(all_users)}")
      ''')

      web_extract — لمستندات API الخاصة بالمزوّد​

      اسحب مواصفات نقطة النهاية (endpoint) التي تُصحّحها بدلًا من التخمين:

      web_extract(urls=["https://docs.example.com/api/v1/users"])

      delegate_task — لعمليات اختبار CRUD الشاملة​

      delegate_task(
          goal="Test all CRUD endpoints for /api/v1/users",
          context="""
      Follow the rest-graphql-debug skill (optional-skills/software-development/rest-graphql-debug).
      Base URL: https://api.example.com
      Auth: Bearer token from API_TOKEN env var.

      For each verb (POST, GET, PATCH, DELETE):
        - happy path: assert status + response schema
        - error cases: 400, 404, 422
        - log a repro curl for any failure (redact tokens)

      Output: pass/fail per endpoint + correlation IDs for failures.
      """,
          toolsets=["terminal", "file"],
      )

      صيغة الإخراج​

      عند تقرير النتائج:

      ## Finding
      Endpoint: POST /api/v1/users
      Status:   422 Unprocessable Entity
      Req ID:   req_abc123xyz

      ## Repro
      curl -X POST https://api.example.com/api/v1/users \
        -H 'Content-Type: application/json' \
        -H 'Authorization: Bearer <REDACTED>' \
        -d '{"name":"test"}'

      ## Root Cause
      Missing required field `email`. Server validation rejects before processing.

      ## Fix
      -d '{"name":"test","email":"test@example.com"}'
