      ast-grep

      بحث وإعادة كتابة بنيوية للكود واعية بشجرة AST عبر ast-grep.

      بيانات المهارة الوصفية​

      المصدراختيارية — ثبّتها باستخدام hermes skills install official/software-development/ast-grep
      المسارoptional-skills/software-development/ast-grep

      المرجع: ملف SKILL.md كاملًا​

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      ast-grep

      ast-grep (يُسمى الملف التنفيذي أيضًا sg) هي أداة بحث وإعادة كتابة واعية بشجرة AST عبر 25 لغة. تعامل نمطك ككود، وتحلّله بالطريقة نفسها التي تحلّل بها مشروعك، وتطابقه بنيويًا. إنها الأداة الصحيحة كلما اعتمد سؤالك على شكل الكود لا على بايتات النص.

      تأتي هذه المهارة مع مُغلِّف Python في scripts/ast_grep_helper.py وسكربتات تثبيت لكل منصة في install.sh (POSIX) وinstall.ps1 (Windows). يضيف المساعد التحقق دون اتصال من صحة النمط، وحيلة الكتابة على مرحلتين، والتحديد التلقائي للملف التنفيذي. استخدمه كنقطة الدخول الافتراضية لديك.

      المصدر الأصلي: مأخوذ من code-yeongyu/ast-grep-skill (MIT)، كما وُرِّد في حزمة shared-skills الخاصة بـ oh-my-openagent.

      متى تُستخدم هذه المهارة​

      استخدمها كلما كان السؤال عن بنية الكود، لا عن البايتات:

      • "اعثر على كل دالة تأخذ معاملًا من نوع Request."
      • "أعد كتابة كل console.log(x) إلى logger.info(x)."
      • "احذف كل تحويل as any."
      • "استبدل require(...) بـ import عبر المستودع."
      • "اعثر على كتل catch الفارغة."
      • "هاجر Optional[X] إلى X | None."
      • "طبّق هذا الـ codemod عبر هذه الـ200 ملف."
      • "شغّل قواعد YAML lint الخاصة بنا وأظهر المخالفات."

      انتقل إلى search_files (أو rg العادية) عندما يكون السؤال نصي الشكل (محتويات سلسلة نصية حرفية، تعليقات، ترويسات ترخيص، أسماء ملفات، تعبير نمطي (regex) عابر للغات). عند الشك، اسأل: "هل تعتمد الإجابة على شجرة صياغة اللغة، أم فقط على بايتات الملف؟" إذا كانت الأولى، استخدم ast-grep. وإذا كانت الثانية، استخدم search_files.

      ملاحظات تكامل Hermes:

      • شغّل المساعد وsg عبر أداة terminal. ضع كل نمط بين علامتي اقتباس مفردة كي لا يوسِّع الـ shell أبدًا $VAR.
      • لسلاسل البحث ثم القراءة حول المطابقات، استخدم --json-out وعالجها عبر execute_code بدلًا من التمرير عبر مفسِّرات.
      • هذه المهارة تكمّل (لا تستبدل) أداة patch في Hermes: patch مخصَّصة للتعديلات المحدَّدة التي تكتبها بنفسك؛ وast-grep مخصَّصة لإعادة الكتابة الدفعية المدفوعة بنمط عبر مواضع كثيرة.

      ثلاثة أمور يجب أن يستوعبها الوكيل​

      1. ast-grep ليست تعبيرات نمطية (regex)​

      البدائل (wildcards) هي $VAR (عقدة AST واحدة) و$$$ (صفر عقدة أو أكثر). تفشل صياغة regex بصمت:

      ما كتبتهما رأته ast-grepما أردته
      foo|barOR بتّي (bitwise) لـ foo وbarشغّل بحثين منفصلين
      .*fooغير قابل للتحليل$$$ foo (إذا كانت $$$ قائمة عقد) أو استخدم rg
      \w+غير قابل للتحليل$VAR لالتقاط أي معرِّف
      [a-z]فئة أحرف، غير قابلة للتحليلانتقل إلى rg

      جدول الأنماط المضادة الكامل موجود في references/pitfalls.md §1. أداة المساعد الفرعية validate تكتشف هذه الحالات آليًا — استدعِها قبل تصحيح خطأ "لا مطابقات" يدويًا.

      2. يجب أن تكون الأنماط كودًا صالحًا​

      يجب أن يُحلَّل النمط نفسه بنجاح. يفشل def $FN($$$): لأن : اللاحقة تجعله غير مكتمل؛ استخدم def $FN($$$). يفشل function $NAME دون معاملات/جسم؛ استخدم function $NAME($$$) { $$$ }. الجدول الكامل لكل لغة في references/pitfalls.md §2.

      3. --update-all و--json متنافيتان (بصمت)​

      هذه أكبر مصيدة عند كتابة السكربتات. يعيد sg run -p P -r R --json --update-all بيانات JSON لكنه لا يعدِّل الملفات. للمعاينة والتطبيق معًا، شغّل مرحلتين:

      sg run -p P -r R --json=compact .   # pass 1: see what would change
      sg run -p P -r R --update-all .     # pass 2: actually apply

      يقوم المساعد بذلك تلقائيًا عند استدعاء replace --apply. راجع references/pitfalls.md §9.

      السكربت المساعد — scripts/ast_grep_helper.py​

      مُغلِّف Python 3 من ملف واحد يعتمد على المكتبة القياسية فقط. متماثل على كل نظام تشغيل. نقطة الدخول الافتراضية للوكيل.

      search — العثور على كل مطابقات نمط​

      python scripts/ast_grep_helper.py search 'console.log($MSG)' --lang ts src/

      يتحقق من صحة النمط أولًا دون اتصال. إذا بدا النمط أشبه بتعبير نمطي (\w، .*، |، إلخ)، يخرج المساعد مع تلميح ولا يستدعي sg أبدًا — ما يوفر جولة استدعاء. مرّر --force لتخطي التحقق.

      الخيارات (flags):

      • --lang ts (أو أي من اللغات الـ25؛ الأسماء المستعارة مثل js، py، rs، kt مقبولة)
      • --globs '!**/*.test.ts' (قابل للتكرار؛ البادئة ! للاستثناء)
      • -C 3 (أسطر سياق)
      • --json-out (JSON خام بدل الصيغة المقروءة للبشر)

      replace — إعادة كتابة حسب النمط، تجربة جافة (dry-run) افتراضيًا​

      # Dry-run preview (default — no files mutated)
      python scripts/ast_grep_helper.py replace 'console.log($MSG)' 'logger.info($MSG)' --lang ts src/

      # Actually apply
      python scripts/ast_grep_helper.py replace 'console.log($MSG)' 'logger.info($MSG)' --lang ts src/ --apply

      يقوم المساعد بما يلي:

      1. يتحقق من صحة كل من pattern وrewrite بحثًا عن أخطاء قابلة للاكتشاف بتلميح.
      2. يشغّل المرحلة الأولى بـ --json=compact لجمع المطابقات وعرض معاينة.
      3. إذا ضُبط --apply، يشغّل المرحلة الثانية بـ --update-all لتعديل الملفات.

      scan — تشغيل قواعد YAML​

      # Discover sgconfig.yml from cwd and run all rules
      python scripts/ast_grep_helper.py scan src/

      # Run a single rule file
      python scripts/ast_grep_helper.py scan -r rules/no-console.yml src/

      # Apply auto-fixes
      python scripts/ast_grep_helper.py scan -U src/

      # CI-friendly GitHub annotations
      python scripts/ast_grep_helper.py scan --report-style short src/

      validate — فحص النمط دون اتصال (بلا استدعاء لـ sg)​

      مفيدة لفحوصات lint في CI، وربط pre-commit، وفحوصات سريعة للسلامة:

      python scripts/ast_grep_helper.py validate '\w+' --lang ts
      # → exit 2: regex \w not supported. Use $VAR for identifiers.

      python scripts/ast_grep_helper.py validate 'console.log($MSG)' --lang ts
      # → exit 0: pattern looks plausible for ast-grep.

      langs / doctor / install​

      python scripts/ast_grep_helper.py langs       # list 25 supported languages and aliases
      python scripts/ast_grep_helper.py doctor      # check ast-grep binary availability
      python scripts/ast_grep_helper.py install     # delegate to install.sh / install.ps1

      تُمرِّر الأمران الفرعيان new وtest مباشرة إلى sg new وsg test.

      استخدام sg مباشرة (عندما لا يكفي المساعد)​

      المساعد له أسلوب محدَّد. للتحكم الكامل، انزل إلى sg. تأتي هذه المهارة مع ورقة غش (cheat sheet) لواجهة CLI في references/cli.md. الأنماط الأدنى:

      # Search
      sg run -p 'console.log($MSG)' --lang ts src/

      # Search with JSON for scripting
      sg run -p 'console.log($MSG)' --lang ts --json=compact src/

      # Rewrite, dry-run
      sg run -p 'console.log($MSG)' -r 'logger.info($MSG)' --lang ts --json=compact src/

      # Rewrite, apply
      sg run -p 'console.log($MSG)' -r 'logger.info($MSG)' --lang ts --update-all src/

      # Pattern from stdin (great for ad-hoc experiments)
      echo 'console.log("hi")' | sg run -p 'console.log($MSG)' --lang js --stdin

      # Debug a pattern that returns 0 matches
      sg run -p '<your pattern>' --lang <lang> --debug-query=ast --stdin <<< '<sample-code>'

      # Run YAML rules
      sg scan src/

      # Inline YAML rule (one-off)
      sg scan --inline-rules '
      id: no-todo
      language: TypeScript
      severity: warning
      rule: { pattern: TODO }' src/

      عند استخدام sg مباشرة في shell، ضع الأنماط دائمًا بين علامتي اقتباس مفردة كي لا يوسِّع الـ shell قيمة $VAR.

      شجرة القرار — ماذا تستخدم، ومتى​

      USER asks for "find/rewrite/codemod"
      │
      ├─ structural pattern (function shape, call, class, import, control flow)
      │  └→ ast-grep (this skill)
      │
      ├─ text pattern (regex, alternation, character classes, file names)
      │  └→ search_files / rg
      │
      ├─ semantic question (what variable does this refer to? does this throw?)
      │  └→ LSP tools, TypeScript compiler, Pyright, Semgrep with type inference
      │
      └─ multiple repos / federated search
         └→ a search engine + then ast-grep / rg / LSP per-repo

      إذا قال المستخدم "اعثر على كل" أو "كل"، فاختر افتراضيًا ast-grep عندما تكون الغاية ذات شكل بنيوي (دالة، صنف، استدعاء، استيراد، عبارة). واختر افتراضيًا search_files عندما تكون الغاية نصية (محتوى سلسلة، تعليق، ترويسة ترخيص، اسم ملف، جزء من معرِّف).

      شغّل التجربة الجافة (dry-run) دائمًا أولًا عند إعادة الكتابة​

      يمكن لنمط سيئ أن يعيد كتابة الشيء الخاطئ بصمت. لهذا السبب يكون الوضع الافتراضي لأمر replace في المساعد هو التجربة الجافة. سير العمل هو:

      1. ابحث للتأكد من المطابقات: helper search '<pattern>' --lang X .
      2. أعد الكتابة كتجربة جافة: helper replace '<pattern>' '<rewrite>' --lang X . (دون --apply)
      3. افحص ملخص التجربة الجافة: عدد المطابقات، والملفات المتأثرة، ومعاينة كل موضع.
      4. إذا كانت النتيجة خاطئة: نقّح النمط، وعد إلى الخطوة 1.
      5. إذا كانت صحيحة: helper replace '<pattern>' '<rewrite>' --lang X . --apply.

      لا تطبّق أبدًا إعادة كتابة لم تجرِّبها جافة أولًا. بعد --apply في مستودع git، راجع بـ git diff --stat قبل الالتزام (commit).

      عندما تعيد sg صفر مطابقات لكنك تعلم أن الكود موجود​

      بترتيب الأولوية:

      1. شغّل helper validate '<pattern>' --lang <lang> — يكتشف سوء استخدام regex، والأجسام الدالية المفقودة، والنقطتين اللاحقتين في Python.
      2. تحقق من --lang — تستنتج sg اللغة من الامتداد؛ فإذا مررت ملف .tsx مع --lang ts (وليس tsx)، لن يتم تحليل JSX.
      3. افحص النمط بعد تحليله: sg run -p '<pattern>' --lang <lang> --debug-query=ast --stdin <<< '<sample>'. إذا ظهرت عقد ERROR، فالنمط غير صحيح البنية.
      4. افحص شجرة AST الخاصة بالملف الهدف: sg run -p '$_' --lang <lang> --debug-query=cst path/to/file | head -40 — ابحث عن kind الذي تحاول مطابقته.
      5. جرّب ساحة اللعب (playground): <https://ast-grep.github.io/playground.html> — الصق الكود والنمط، وانظر ما يحدث.

      لا تعد المحاولة عشوائيًا بتنويعات مختلفة. لكل فشل سبب؛ أظهره.

      متى تستخدم قواعد YAML مقابل أنماط -p المضمَّنة​

      استخدم -p المضمَّنة عندما:

      • الاستعلام لمرة واحدة وعابر.
      • النمط بسيط (بلا قيود، بلا قالب إصلاح).
      • أنت في طور الاستكشاف.

      استخدم قواعد YAML (ملف تحت rules/، يُشغَّل عبر sg scan) عندما:

      • النمط يُعاد استخدامه (قاعدة lint، أو codemod يعمل في CI).
      • تحتاج إلى constraints، أو transform، أو inside/has معقدة، أو منطق مركَّب.
      • تريد إصلاحًا تلقائيًا (حقل fix:).
      • تريد اختبار القاعدة (اختبارات لقطة عبر sg test).

      مخطط قواعد YAML الكامل في references/yaml-rules.md. إعداد المشروع (sgconfig.yml، ruleDirs، utilDirs) في references/sgconfig.md.

      انضباط المخرجات​

      • ينتج sg run --json=compact مصفوفة من كائنات المطابقة: { file, range: {start, end}, text, replacement?, lines, language, ... }.
      • دون --json، تنتج sg مخرجات مقروءة وملوَّنة مناسبة للطرفيات (terminals).
      • المخرجات الافتراضية للمساعد مقروءة للبشر (ملف:سطر:عمود + معاينة المطابقة). مرّر --json-out للحصول على JSON خام.
      • يلخّص أمر replace في المساعد دائمًا: عدد المطابقات، وعدد الملفات، ومعاينة كل موضع.

      عند التلخيص للمستخدم، ضمِّن دائمًا عدد الملفات المتأثرة، لا عدد المطابقات فقط. يهتم المستخدمون بنطاق التأثير.

      ثوابت (لا تكسرها)​

      • تحقق من الصحة قبل البحث. عند توليد نمط برمجيًا، استدعِ helper validate أولًا. فهو يكتشف فئة أخطاء سوء استخدام regex التي تمثل نحو 70% من جلسات تصحيح "صفر مطابقات".
      • جرّب جافًا قبل التطبيق. لا تشغّل أبدًا sg run -r ... --update-all دون فحص المطابقات أولًا. يفرض أمر replace في المساعد هذا افتراضيًا.
      • كتابة على مرحلتين. عند استخدام sg مباشرة للمعاينة والتطبيق معًا، شغّل استدعاءين — --json يتجاهل --update-all.
      • ضع الأنماط بين علامتي اقتباس مفردة في الـ shell. '$VAR' وليس "$VAR". يوسِّع الـ shell قيمة $VAR إلى سلسلة فارغة داخل علامتي الاقتباس المزدوجتين، ما يكسر النمط.
      • النمط كود، وليس تعبيرًا نمطيًا (regex). عندما يحتاج النمط إلى |، أو .*، أو \w، أو [a-z]، انتقل إلى search_files بدلًا من ذلك. لا تحاول إجبار ast-grep على شكل regex.
      • --lang مطلوب لـ stdin. عند التمرير عبر --stdin، اضبط --lang صراحةً؛ فلا يمكن لـ sg الاستنتاج من الامتداد.
      • Linux: فضِّل ast-grep على sg لأن sg يتعارض مع setgroups من util-linux. يتولى المساعد هذا الأمر؛ فإذا استدعيت sg مباشرة، اجعل له اسمًا مستعارًا: alias sg=ast-grep.
