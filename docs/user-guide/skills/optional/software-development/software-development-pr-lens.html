      PR Lens

      ارسم تغييرات الكود كرسوم SVG معمارية/تدفق بيانات متحركة.

      بيانات المهارة الوصفية​

      المصدراختيارية — ثبّتها باستخدام hermes skills install official/software-development/pr-lens
      المسارoptional-skills/software-development/pr-lens

      الوسومdiagrams, pull-requests, code-review, svg

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      مهارة PR Lens

      ترسم PR Lens الكود كرسوم تخطيطية متحركة غنية بصريًا: الفروقات (diffs)، البنية المعمارية، وتدفقات البيانات. تصف الفرق أو قاعدة الكود بوثيقة JSON واحدة (مسارات، عقد، حواف، تدفقات مرتّبة) وتُصيّرها CLI كرسوم SVG متحركة. لا توجد فيها عدسة نتائج (findings lens) — فـ PR Lens طبقة استيعاب، لا بوت مراجعة. لا يوجد حقل لخلل أو خطر أو ملاحظة أمنية، وتُرفض أي وثيقة تخترع واحدًا منها.

      متى تُستخدم​

      • عند الطلب برسم أو تصوير أو شرح تغيير في الكود أو نظام.
      • عندما ينبغي أن يحمل pull request رسمًا معماريًا أو رسم تدفق بيانات.
      • كلمات مفتاحية: PR Lens، رسم تخطيطي، بنية معمارية، تدفق بيانات، تصوير، pull request.

      المتطلبات الأساسية​

      • Node.js مع npx (تعمل CLI عبر npx @coldtea/pr-lens-cli@latest؛ بلا خطوة تثبيت).
      • gh (GitHub CLI) — اختياري، فقط لإرفاق الرسوم التخطيطية بطلبات PR.
      • نشر canvas الاختياري يستدعي خدمة الطرف الثالث prlens.dev (انظر الخطوة 4ب).

      كيفية التشغيل​

      نفّذ جميع الأوامر باستخدام أداة الطرفية من جذر المستودع.

      1. اقرأ الفرق (diff). عند تمثيل تغيير في الكود: git diff --find-renames <base>...<head>. القاعدة هي نقطة الدمج المشترك (merge base)، وليست طرف الفرع الأساسي. إن لم تكن تمثّل فرقًا، اقرأ الكود المراد تصويره.

      2. اكتب الوثيقة إلى .pr-lens/graph.json، متّبعًا references/graph-document.md. يُعدّ references/example.graph.json مرجعًا صالحًا بثلاثة مسارات، وكل حالات الفروقات الأربع (delta states)، وحافة بطولية (hero edge)، وتدفق من سبع خطوات، وشجرة تفصيل متداخلة (drill-down)، وجولة شرح من ست خطوات. اقرأه قبل كتابة وثيقتك الأولى — أسرع من قراءة المرجع.

      3. تحقّق، وأصلح.

        npx @coldtea/pr-lens-cli@latest validate .pr-lens/graph.json

        أصلح كل خلل ثم أعد التشغيل. لا تُصيّر وثيقة غير صالحة؛ ولا "تلتف" حول خلل بحذف العنصر الذي يذكره.

      4. صيِّر.

        npx @coldtea/pr-lens-cli@latest render .pr-lens/graph.json --theme light

        صيّر بالسمة الفاتحة (light) افتراضيًا ما لم يطلب المستخدم سمة أخرى. تحطّ ملفات SVG والبيان (manifest) وملف drawn.graph.json في .pr-lens/، التي تضيفها CLI إلى ملف .gitignore الخاص بالمستودع. لا تلتزم (commit) أيًا منها — فهذه الملفات تُعاد بناؤها من الفرق عند الطلب. تُسمّى كل صورة SVG وفق عرضها وسمتها وبصمة محتواها (hash)؛ ويسرد manifest.json هذه الصور حسب العدسة (lens) والعرض.

      4ب. دفع Canvas — اختياري، بالموافقة الصريحة فقط. فقط عندما يطلب المستخدم صراحة رابطًا قابلًا للمشاركة. ينشر هذا ملف .pr-lens/drawn.graph.json إلى خدمة الطرف الثالث prlens.dev:

      npx @coldtea/pr-lens-cli@latest canvas push

      تُطبع ثلاثة روابط. أعطِ المستخدم رابط العرض (https://prlens.dev/c/{id}): الرسم التخطيطي بملء الشاشة، كل عرض في صفحة واحدة، بلا تسجيل دخول. رابط التحرير (المنتهي بـ #w=…) يتيح لحامله الكتابة فوق الـ canvas — إنه سرّي: اتركه خارج الرد ما لم يُطلب، ولا تلصقه أبدًا في مكان عام. رابط التضمين (embed) يقدّم أعلى عرض كصورة SVG لملف README. دفع نفس الملف مرة أخرى يحدّث نفس الـ canvas، لذا "أعد تسمية تلك العقدة" يعني: تحرير، ثم تحقق، ثم تصيير، ثم دفع — ويبقى الرابط كما هو. إذا فشل الدفع، أخبر بذلك ودُلّ المستخدم على مكان صور SVG المحلية وأيّها العرض الأعلى.

      1. أرفق بـ PR، عند وجود واحد. توثّق المنبع (upstream) استخدام gh pr create/edit/comment --attach <path>، لكن --attach وصلت في الإصدار 2.99 من GitHub CLI — تحقق من gh --version أولًا (مثلًا، الإصدار gh 2.97 لا يملكها). مع gh ≥ 2.99: اكتب نص الرسالة بصورة Markdown ![alt](https://github.com/NousResearch/hermes-agent/blob/main/optional-skills/software-development/pr-lens/.pr-lens/<view>.svg) (يُترك وسم <img> بصيغة HTML كما كُتب ويُضاف الملف في الأسفل بدلًا من ذلك؛ ونص alt هو التعليق السطري الذي يراه قارئ بلا صور)، ثم كرّر --attach <path> لكل رسم تخطيطي مُشار إليه:

        gh pr create --title "…" --body-file .pr-lens/body.md --attach .pr-lens/overview-light-<hash>.svg

        بدون --attach، استخدم مسارًا بلا commit:

        • ارفع ملفات SVG إلى gist: gh gist create .pr-lens/<view>.svg، ثم أشر إلى رابط gist الخام في نص PR أو التعليق، أو
        • انشر عبر رابط canvas (الخطوة 4ب، بموافقة المستخدم) واربط رابط العرض، أو
        • سجّل مسار .pr-lens/ المحلي في نص PR ليتمكن المراجعون من إعادة البناء.

        بمجرد النشر في مكان دائم، دع CLI تصوغ نص التعليق:

        npx @coldtea/pr-lens-cli@latest comment \
          --graph .pr-lens/drawn.graph.json \
          --manifest .pr-lens/manifest.json \
          --asset-base-url <where you published the SVGs>

        يأخذ --graph ملف drawn.graph.json، لا الوثيقة التي كتبتها — ترفض CLI وثيقة لا يصفها بيانها (manifest). إغفال --asset-base-url يجعل نص Markdown يشير إلى مسارات محلية لا يستطيع أي قارئ جلبها. يُطبع نص Markdown إلى stdout؛ نشره متروك لك.

        أرفق العروض التي يحتاجها المراجع واترك الباقي في .pr-lens/: العرض المعماري الأعلى أولًا، ثم تدفق بيانات إن كان التغيير يستحق متابعة تسلسل. عادةً ما يتفوّق رسمان تخطيطيان على أربعة.

      2. أتمتة اختيارية: ينفّذ npx @coldtea/pr-lens-cli@latest analyze --base <ref> الخطوتين 1 و2 بسؤال مزوّد (Gemini، أو OpenAI، أو أي endpoint من نوع /chat/completions) بمفتاح خاص بك. هذا هو المسار الوحيد هنا الذي يحتاج مفتاحًا؛ عادة تصوغ الوثيقة بنفسك.

      ما الذي يجعل الوثيقة تستحق القراءة​

      • ضمّن ما لم يتغيّر. الجيران غير المتغيّرين الذين يلمسهم تغيير ما هم السياق؛ ضع عليهم علامة delta: "unchanged".
      • المسارات هي النموذج الذهني للقارئ (بيئة تشغيل، طبقة، حد فاصل)، وليست شجرة المجلدات.
      • حافة بطولية واحدة، واثنتان على الأكثر: الاتصال الذي يدور حوله التغيير فعليًا.
      • أضف تدفقًا فقط عندما يكون هناك تسلسل يستحق التحريك. تدفق جيد واحد أفضل من ثلاثة ضعيفة.
      • أرفق مراجع الملفات: تصبح الروابط الدائمة التي ينقر عليها المراجع.
      • عروض البنية المعمارية شجرة قرار مستوحاة من C4: سياق النظام ← الحاوية ← المكوّن، كل فرع أضيق ماديًا من سابقه. تخطَّ المستويات الفارغة أو المتكررة؛ أبقِ عروض تدفق البيانات جذورًا منفصلة؛ اضبط defaultOpen: true على أعلى عرض معماري مفيد.
      • جولات الشرح (Walkthroughs) (2–12 خطوة، هدفك 3–7): اكتب واحدة لأي شيء غير بديهي. كل خطوة = تغيير واحد (أُضيف/أُزيل/نُقل)، مع التغيير الرئيسي أولًا ولمحة عامة أخيرًا. العناوين ≤48 حرفًا مبنية من كلمات التغيير؛ والنصوص ≤140 حرفًا عن السلوك، وإلزامية. اكتب كما لو كنت تخاطب مراهقًا ذكيًا في الثانية عشرة؛ بلا "يستفيد من"/"ينسّق". أبقِ الخطوات المتتالية على نفس المرحلة. يحتاج حقل جولة الشرح إلى CLI ≥ 0.4.0 (العقد 0.1.1).
      • تصحيح خريطة خاطئة: لا تُعدّل أبدًا الوثيقة المولَّدة — اكتب التصحيحات في .github/pr-lens.yml (انظر references/config.md)، ثم تحقق منه: npx @coldtea/pr-lens-cli@latest validate .github/pr-lens.yml. فضّل أنماط المسار (globs) على تطابقات id:.

      رموز فشل المدقّق (Validator):

      الرمزما فعلته
      BROKEN_REFERENCEحافة، أو خطوة تدفق، أو عرض، أو خطوة جولة شرح تسمّي معرّفًا لم تُعلنه قط
      INVALID_DOCUMENTحقل مخترَع؛ المخططات (schemas) صارمة، والمفاتيح غير المعروفة تُرفض
      DUPLICATE_IDعقدتان أو حافتان أو عرضان يتشاركان معرّفًا واحدًا
      UNSUPPORTED_SCHEMA_VERSIONschemaVersion ليس إصدار العقد المثبّت

      المزالق​

      • ستة قواعد خاصة بالمحلّل (parser) فقط وليست في مخطط JSON (السلامة المرجعية، نطاقات الأسطر المعكوسة، تعارض نقاط النهاية self، commits تصحيح متطابقة، عدد كبير جدًا من العروض لبيان واحد، تركيز خطوة تدفق على مرحلة خاطئة) — شغّل دائمًا validate، فالمخرجات المهيكلة وحدها لا تكفي.
      • لا تلتزم (commit) بأي شيء في .pr-lens/؛ فهي تُولَّد وتُستثنى من git بواسطة CLI.
      • يحتاج علم --attach في gh إلى إصدار gh ≥ 2.99؛ الإصدارات الأقدم تفتقده بصمت — تحقق قبل كتابة نص يعتمد عليه.
      • رابط تحرير canvas (#w=…) بيانات اعتماد للكتابة — لا تشاركه أبدًا دون طلب أو تلصقه علنًا.
      • الخريطة المخزَّنة لا تحمل أبدًا جولة شرح؛ فجولة الشرح تروي قصة تغيير واحد.
      • يُبلغ pr-lens render عن تصحيحات في .github/pr-lens.yml لم تطابق شيئًا — هذا انحراف (drift) يستحق الإصلاح، وليس خطأً.

      التحقق​

      اختبار تدخين (Smoke test) (تم التحقق منه حيًّا في 2026-09-12 باستخدام @coldtea/pr-lens-cli عبر npx، وnode على Linux):

      cp references/example.graph.json /tmp/prlens-smoke/ && cd /tmp/prlens-smoke
      npx -y @coldtea/pr-lens-cli@latest validate example.graph.json
      # ✓ example.graph.json — graph document · 3 lanes, 10 nodes, 13 edges, 1 flow · 6 walkthrough steps
      npx -y @coldtea/pr-lens-cli@latest render example.graph.json --theme light
      # ✓ .pr-lens/manifest.json — 4 SVGs across 4 diagrams

      يُتوقَّع خروج بالرمز 0 في كلتا الحالتين وأربعة ملفات *-light-<hash>.svg بالإضافة إلى manifest.json وdrawn.graph.json في .pr-lens/.
