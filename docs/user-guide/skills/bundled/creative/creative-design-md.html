      أنشئ وتحقّق من وصدّر ملفات مواصفات الرموز (tokens) الخاصة بـ Google المسمّاة DESIGN.md.

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      مهارة DESIGN.md

      DESIGN.md هي مواصفة مفتوحة من Google (بترخيص Apache-2.0، google-labs-code/design.md) لـ وصف الهوية البصرية لوكلاء البرمجة. يجمع ملف واحد بين:

      • مقدّمة YAML (front matter) — رموز تصميم (design tokens) قابلة للقراءة آليًا (قيم معيارية)
      • نص Markdown — مسوّغ قابل للقراءة البشرية، منظَّم في أقسام قياسية

      تعطي الرموز (tokens) قيمًا دقيقة. أما النص فيخبر الوكلاء لماذا توجد تلك القيم وكيف يطبّقونها. الـ CLI (npx @google/design.md) يفحص البنية + تباين WCAG، ويقارن الإصدارات لرصد التراجعات، ويصدّر إلى Tailwind أو JSON بصيغة W3C DTCG.

      متى تُستخدم هذه المهارة​

      • يطلب المستخدم ملف DESIGN.md، أو رموز تصميم، أو مواصفة نظام تصميم
      • يريد المستخدم واجهة/علامة تجارية متسقة عبر مشاريع أو أدوات متعددة
      • يلصق المستخدم ملف DESIGN.md موجودًا ويطلب فحصه أو مقارنته أو تصديره أو توسيعه
      • يطلب المستخدم تحويل دليل أسلوب إلى صيغة يمكن للوكلاء استهلاكها
      • يريد المستخدم التحقق من التباين/إمكانية الوصول (WCAG) لألوانه

      للإلهام البصري المحض أو أمثلة التخطيط، استخدم popular-web-designs بدلًا من ذلك. أما لـ الطريقة والذوق عند تصميم artifact HTML لمرة واحدة من الصفر (نموذج أولي، عرض تقديمي، صفحة هبوط، مختبر مكوّنات)، فاستخدم claude-design. هذه المهارة مخصّصة لـ ملف المواصفة الرسمي نفسه.

      بنية الملف​

      ---
      version: alpha
      name: Heritage
      description: Architectural minimalism meets journalistic gravitas.
      colors:
        primary: "#1A1C1E"
        secondary: "#6C7278"
        tertiary: "#B8422E"
        neutral: "#F7F5F2"
      typography:
        h1:
          fontFamily: Public Sans
          fontSize: 3rem
          fontWeight: 700
          lineHeight: 1.1
          letterSpacing: "-0.02em"
        body-md:
          fontFamily: Public Sans
          fontSize: 1rem
      rounded:
        sm: 4px
        md: 8px
        lg: 16px
      spacing:
        sm: 8px
        md: 16px
        lg: 24px
      components:
        button-primary:
          backgroundColor: "{colors.tertiary}"
          textColor: "#FFFFFF"
          rounded: "{rounded.sm}"
          padding: 12px
        button-primary-hover:
          backgroundColor: "{colors.primary}"
      ---

      ## Overview

      Architectural Minimalism meets Journalistic Gravitas...

      ## Colors

      - **Primary (#1A1C1E):** Deep ink for headlines and core text.
      - **Tertiary (#B8422E):** "Boston Clay" — the sole driver for interaction.

      ## Typography

      Public Sans for everything except small all-caps labels...

      ## Components

      `button-primary` is the only high-emphasis action on a page...

      أنواع الرموز (Tokens)​

      النوعالصيغةمثال
      لونأي لون CSS (سداسي، rgb()، oklch()، مُسمّى)"#1A1C1E", "oklch(62% 0.18 250)"
      بُعد (Dimension)رقم + وحدة (px, em, rem)48px, -0.02em
      مرجع رمز (Token reference){path.to.token}{colors.primary}
      الطباعة (Typography)كائن يضم fontFamily, fontSize, fontWeight, lineHeight, letterSpacing, fontFeature, fontVariationانظر أعلاه

      القائمة البيضاء لخصائص المكوّنات: backgroundColor, textColor, typography, rounded, padding, size, height, width. المتغيرات (hover، active، pressed) هي إدخالات مكوّنات منفصلة بأسماء مفاتيح مرتبطة (button-primary-hover)، وليست متداخلة.

      ترتيب الأقسام القياسي​

      الأقسام اختيارية، لكن الأقسام الموجودة ينبغي أن تظهر بهذا الترتيب. يُبلِغ الفاحص (linter) عن الأقسام غير المرتّبة (section-order، تحذير) والعناوين المكرّرة — حيث ترفض التطبيقات المستهلِكة وفق المواصفة التكرارات، لذا أصلِح كليهما قبل إرجاع الملف.

      1. نظرة عامة (اسم بديل: Brand & Style)
      2. Colors
      3. Typography
      4. Layout (اسم بديل: Layout & Spacing)
      5. Elevation & Depth (اسم بديل: Elevation)
      6. Shapes
      7. Components
      8. Do's and Don'ts

      الأقسام غير المعروفة تُحفظ ولا يُبلَّغ عنها كخطأ. أسماء الرموز غير المعروفة مقبولة إذا كان نوع القيمة صحيحًا. خصائص المكوّنات غير المعروفة تُصدر تحذيرًا.

      سير العمل: تأليف ملف DESIGN.md جديد​

      1. اسأل المستخدم (أو استنتج) نبرة العلامة التجارية ولون التمييز واتجاه الطباعة. إذا زوّدك بموقع أو صورة أو إحساس عام (vibe)، ترجمه إلى شكل الرموز أعلاه.
      2. اكتب DESIGN.md في جذر مشروعه باستخدام write_file. ضمِّن دائمًا name: وcolors:؛ الأقسام الأخرى اختيارية لكن يُستحسن تضمينها.
      3. استخدم مراجع الرموز ({colors.primary}) في قسم components: بدلًا من إعادة كتابة القيم السداسية. يبقي هذا اللوحة اللونية بمصدر واحد.
      4. افحصه (lint) (انظر أدناه). أصلِح أي مراجع معطوبة أو إخفاقات WCAG قبل الإرجاع.
      5. إذا كان لدى المستخدم مشروع موجود، اكتب أيضًا تصديرات Tailwind أو DTCG بجانب الملف (tailwind.theme.json, tokens.json).

      سير العمل: الفحص (lint) / المقارنة (diff) / التصدير (export)​

      الـ CLI هو @google/design.md (Node). استخدم npx — لا حاجة لتثبيت عام.

      # Validate structure + token references + WCAG contrast
      npx -y @google/design.md lint DESIGN.md

      # Compare two versions, fail on regression (exit 1 = regression)
      npx -y @google/design.md diff DESIGN.md DESIGN-v2.md

      # Export to Tailwind v3 theme JSON (`tailwind` is a back-compat alias)
      npx -y @google/design.md export --format json-tailwind DESIGN.md > tailwind.theme.json

      # Export to a Tailwind v4 CSS @theme block (--color-*, --text-*, --radius-*, ...)
      npx -y @google/design.md export --format css-tailwind DESIGN.md > theme.css

      # Export to W3C DTCG (Design Tokens Format Module) JSON
      npx -y @google/design.md export --format dtcg DESIGN.md > tokens.json

      # Print the spec itself — useful when injecting into an agent prompt
      npx -y @google/design.md spec --rules-only --format json

      تقبل جميع الأوامر - للإدخال من stdin. يُرجِع lint رمز خروج 1 عند وجود أخطاء (التحذيرات وحدها تُخرج برمز 0). ينتهي export برمز 0 عند نجاح التصدير بغض النظر عن نتائج الفحص في المصدر — شغّل lint بشكل منفصل للتحكم في ذلك. المخرجات JSON افتراضيًا؛ حلّلها إذا احتجت الإبلاغ عن النتائج بشكل مُهيكل.

      على Windows، قد يتعارض اسم ملف design.md التنفيذي مع ارتباط امتداد .md (لا شيء يحدث بصمت أو يُفتح الملف في محرّر). استخدم البديل الخالي من النقاط: npx -y -p @google/design.md designmd lint DESIGN.md.

      مرجع قواعد الفحص (القواعد التسع، اعتبارًا من CLI 0.3.0)​

      • broken-ref (خطأ) — {colors.missing} يشير إلى رمز غير موجود
      • contrast-ratio (تحذير) — textColor للمكوّن مقابل backgroundColor دون مستوى WCAG AA (4.5:1)
      • missing-primary (تحذير) — ألوان مُعرَّفة لكن بلا رمز primary
      • missing-typography (تحذير) — ألوان مُعرَّفة لكن بلا رموز طباعة
      • orphaned-tokens (تحذير) — رموز ألوان لا يشير إليها أي مكوّن
      • section-order (تحذير) — أقسام خارج الترتيب القياسي
      • unknown-key (تحذير) — مفتاح YAML من المستوى الأعلى يبدو خطأً إملائيًا لمفتاح مخطط (colours: ← colors:)؛ مفاتيح التمديد المخصّصة تبقى صامتة
      • token-summary, missing-sections (معلومة) — أعداد وأقسام اختيارية غائبة

      عندما يهتم المستخدم بإمكانية الوصول، أشِر إلى ذلك صراحةً في ملخّصك — نتائج WCAG هي السبب الأكثر أهمية لاستخدام الـ CLI.

      مزالق شائعة​

      • لا تُدرِج متغيرات المكوّنات متداخلة. button-primary.hover خطأ؛ button-primary-hover كمفتاح شقيق (sibling key) هو الصحيح.
      • يجب وضع الألوان السداسية بين علامتي اقتباس كسلاسل نصية. وإلا سيختنق YAML عند # أو يقطع قيمًا مثل #1A1C1E بشكل غريب.
      • الأبعاد السالبة تحتاج علامات اقتباس أيضًا. letterSpacing: -0.02em يُفسَّر كـ YAML flow — اكتب letterSpacing: "-0.02em".
      • ترتيب الأقسام مهم حتى وإن كان الفاحص يكتفي بالتحذير. إذا زوّدك المستخدم بنص بترتيب عشوائي، أعِد ترتيبه ليطابق القائمة القياسية قبل الحفظ — التطبيقات المستهلِكة المتوافقة مع المواصفة تتوقع ذلك.
      • الأخطاء الإملائية في الخصائص الفرعية للطباعة تُحذف بصمت. اعتبارًا من CLI 0.3.0، خطأ إملائي مثل fontwight: لا ينتج عنه أي إشعار، وتختفي القيمة من التصديرات — تحقّق من أسماء الخصائص الفرعية مقارنةً بالمخطط (fontFamily, fontSize, fontWeight, lineHeight, letterSpacing, fontFeature, fontVariation).
      • version: alpha هو إصدار المواصفة الحالي (اعتبارًا من يوليو 2026، CLI 0.3.0). المواصفة مُصنَّفة alpha — انتبه للتغييرات الجذرية (breaking changes).
      • مراجع الرموز تُحلّ حسب المسار المنقّط. {colors.primary} يعمل؛ {primary} لا يعمل.
