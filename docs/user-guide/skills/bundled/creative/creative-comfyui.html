      ComfyUI

      ولّد الصور والفيديو والصوت عبر تدفقات عمل (workflows) الانتشار (diffusion).

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      ComfyUI

      ولّد الصور والفيديو والصوت والمحتوى ثلاثي الأبعاد عبر ComfyUI باستخدام comfy-cli الرسمي للإعداد ودورة حياة الخدمة، و REST/WebSocket API المباشر لتنفيذ تدفقات العمل (workflows).

      ما تحتويه هذه المهارة​

      وثائق مرجعية (references/):

      • official-cli.md — كل أوامر comfy ... مع خياراتها (flags)
      • rest-api.md — نقاط REST و WebSocket (محليًا وعلى السحابة)، ومخططات الحمولة (payload)
      • workflow-format.md — صيغة JSON بتنسيق API، أنواع العُقد الشائعة، وربط المعاملات
      • template-integrity.md — تحويل comfyui-workflow-templates من تنسيق المحرر إلى تنسيق API: تجاوز Reroute، مفاتيح المدخلات الديناميكية المنقّطة (values.a, resize_type.width)، خصائص Cloud (إعادة توجيه 302، مهمة واحدة متزامنة على المستوى المجاني، سقف VRAM عند 1080p)، ودمج ffmpeg المتوافق مع Discord. من تأليف @purzbeats. حمّل هذا الملف كلما بدأت من قالب رسمي.

      السكربتات (scripts/):

      السكربتالغرض
      _common.pyHTTP مشترك، توجيه السحابة، كتالوجات العُقد (لا تُشغّله مباشرة)
      hardware_check.pyفحص GPU/VRAM/القرص ← يوصي بـ محلي مقابل Comfy Cloud
      comfyui_setup.shفحص العتاد + تثبيت comfy-cli + ComfyUI + التشغيل + التحقق
      extract_schema.pyيقرأ تدفق عمل ← يسرد المعاملات القابلة للتحكم واعتماديات النماذج
      check_deps.pyيفحص تدفق عمل مقابل الخادم العامل ← يسرد العُقد/النماذج الناقصة
      auto_fix_deps.pyيشغّل check_deps ثم comfy node install / comfy model download
      run_workflow.pyيحقن المعاملات، يرسل المهمة، يراقبها، ويُنزّل المخرجات (HTTP أو WS)
      run_batch.pyيرسل تدفق عمل N مرة مع مسح للقيم (sweeps)، بالتوازي حتى حد مستواك
      ws_monitor.pyعارض WebSocket لحظي للمهام قيد التنفيذ (تقدّم مباشر)
      health_check.pyمشغّل قائمة تحقق — comfy-cli + الخادم + النماذج + اختبار سريع
      fetch_logs.pyيجلب رسائل traceback/الحالة لمعرّف prompt_id معيّن

      تدفقات عمل نموذجية (workflows/): SD 1.5، SDXL، Flux Dev، SDXL img2img، SDXL inpaint، ترقية ESRGAN، فيديو AnimateDiff، Wan T2V. راجع workflows/README.md.

      متى تستخدمها​

      • عندما يطلب المستخدم توليد صور بـ Stable Diffusion أو SDXL أو Flux أو SD3 وغيرها.
      • عندما يريد المستخدم تشغيل ملف تدفق عمل ComfyUI محدد.
      • عندما يريد المستخدم ربط خطوات توليد متسلسلة (txt2img ← ترقية ← استعادة الوجه).
      • عندما يحتاج المستخدم إلى ControlNet أو inpainting أو img2img أو أنابيب متقدمة أخرى.
      • عندما يطلب المستخدم إدارة قائمة انتظار ComfyUI، أو فحص النماذج، أو تثبيت عُقد مخصّصة.
      • عندما يريد المستخدم توليد فيديو/صوت/محتوى ثلاثي الأبعاد عبر AnimateDiff أو Hunyuan أو Wan أو AudioCraft وغيرها.

      البنية المعمارية: طبقتان​

      ┌─────────────────────────────────────────────────────┐
      │ Layer 1: comfy-cli (official lifecycle tool)        │
      │   Setup, server lifecycle, custom nodes, models     │
      │   → comfy install / launch / stop / node / model    │
      └─────────────────────────┬───────────────────────────┘
                                │
      ┌─────────────────────────▼───────────────────────────┐
      │ Layer 2: REST/WebSocket API + skill scripts         │
      │   Workflow execution, param injection, monitoring   │
      │   POST /api/prompt, GET /api/view, WS /ws           │
      │   → run_workflow.py, run_batch.py, ws_monitor.py    │
      └─────────────────────────────────────────────────────┘

      لماذا طبقتان؟ الـ CLI الرسمي ممتاز للتثبيت وإدارة الخادم لكنه يقدّم دعمًا محدودًا لتنفيذ تدفقات العمل. تسدّ REST/WS API تلك الفجوة — إذ تتولى السكربتات حقن المعاملات، ومراقبة التنفيذ، وتنزيل المخرجات، وهو ما لا يقوم به الـ CLI.

      البدء السريع​

      اكتشاف البيئة​

      # What's available?
      command -v comfy >/dev/null 2>&1 && echo "comfy-cli: installed"
      curl -s http://127.0.0.1:8188/system_stats 2>/dev/null && echo "server: running"

      # Can this machine run ComfyUI locally? (GPU/VRAM/disk check)
      python3 scripts/hardware_check.py

      إذا لم يكن أي شيء مثبّتًا، راجع الإعداد والانضمام أدناه — لكن نفّذ دائمًا فحص العتاد أولًا.

      فحص صحة سريع في سطر واحد​

      python3 scripts/health_check.py
      # → JSON: comfy_cli on PATH? server reachable? at least one checkpoint? smoke-test passes?

      تدفق العمل الأساسي​

      الخطوة 1: احصل على JSON لتدفق عمل بتنسيق API​

      يجب أن تكون تدفقات العمل بتنسيق API (كل عقدة لها class_type). تأتي من:

      • واجهة ComfyUI على الويب ← Workflow → Export (API) (الواجهة الأحدث) أو زر "Save (API Format)" القديم (الواجهة الأقدم)
      • مجلد workflows/ الخاص بهذه المهارة (أمثلة جاهزة للتشغيل)
      • تنزيلات من المجتمع (civitai، Reddit، Discord) — عادة بتنسيق المحرر، ويجب تحميلها في ComfyUI ثم إعادة تصديرها

      تنسيق المحرر (مصفوفتا nodes و links على المستوى الأعلى) غير قابل للتنفيذ مباشرة. تكتشف السكربتات ذلك وتطلب منك إعادة التصدير.

      الخطوة 2: اطّلع على ما هو قابل للتحكم​

      python3 scripts/extract_schema.py workflow_api.json --summary-only
      # → {"parameter_count": 12, "has_negative_prompt": true, "has_seed": true, ...}

      python3 scripts/extract_schema.py workflow_api.json
      # → full schema with parameters, model deps, embedding refs

      الخطوة 3: نفّذ مع المعاملات​

      # Local (defaults to http://127.0.0.1:8188)
      python3 scripts/run_workflow.py \
        --workflow workflow_api.json \
        --args '{"prompt": "a beautiful sunset over mountains", "seed": -1, "steps": 30}' \
        --output-dir ./outputs

      # Cloud (export API key once; uses correct /api routing automatically)
      export COMFY_CLOUD_API_KEY="comfyui-..."
      python3 scripts/run_workflow.py \
        --workflow workflow_api.json \
        --args '{"prompt": "..."}' \
        --host https://cloud.comfy.org \
        --output-dir ./outputs

      # Real-time progress via WebSocket (requires `pip install websocket-client`)
      python3 scripts/run_workflow.py \
        --workflow flux_dev.json \
        --args '{"prompt": "..."}' \
        --ws

      # img2img / inpaint: pass --input-image to upload + reference automatically
      python3 scripts/run_workflow.py \
        --workflow sdxl_img2img.json \
        --input-image image=./photo.png \
        --args '{"prompt": "make it watercolor", "denoise": 0.6}'

      # Batch / sweep: 8 random seeds, parallel up to cloud tier limit
      python3 scripts/run_batch.py \
        --workflow sdxl.json \
        --args '{"prompt": "abstract"}' \
        --count 8 --randomize-seed --parallel 3 \
        --output-dir ./outputs/batch

      القيمة -1 لـ seed (أو حذفها مع --randomize-seed) تولّد بذرة عشوائية جديدة في كل تشغيل.

      الخطوة 4: اعرض النتائج​

      تُصدر السكربتات JSON إلى stdout يصف كل ملف مخرج:

      {
        "status": "success",
        "prompt_id": "abc-123",
        "outputs": [
          {"file": "./outputs/sdxl_00001_.png", "node_id": "9",
           "type": "image", "filename": "sdxl_00001_.png"}
        ]
      }

      الإعداد والانضمام​

      عندما يطلب المستخدم إعداد ComfyUI، أول شيء ينبغي فعله هو سؤاله عمّا إذا كان يريد Comfy Cloud (مُستضاف، بلا تثبيت، بمفتاح API) أو محليًا (تثبيت ComfyUI على جهازه). لا تبدأ بتشغيل أوامر التثبيت أو فحوصات العتاد قبل أن يجيب.

      الوثائق الرسمية: https://docs.comfy.org/installation وثائق CLI: https://docs.comfy.org/comfy-cli/getting-started وثائق Cloud: https://docs.comfy.org/get_started/cloud Cloud API: https://docs.comfy.org/development/cloud/overview

      الخطوة 0: اسأل عن محلي مقابل Cloud (دائمًا أولًا)​

      نص مقترح:

      "هل تريد تشغيل ComfyUI محليًا على جهازك، أم استخدام Comfy Cloud؟

      • Comfy Cloud — مُستضاف على وحدات معالجة رسومية RTX 6000 Pro، مع كل النماذج الشائعة مثبّتة مسبقًا، وبلا أي إعداد. يتطلب مفتاح API (اشتراك مدفوع مطلوب لتشغيل تدفقات العمل فعليًا؛ المستوى المجاني للقراءة فقط). الأنسب إن لم يكن لديك GPU كافٍ.
      • محليًا — مجاني، لكن يجب أن يستوفي جهازك متطلبات العتاد:
        • GPU من NVIDIA بذاكرة ≥6 GB VRAM (≥8 GB لـ SDXL، ≥12 GB لـ Flux/الفيديو)، أو
        • GPU من AMD يدعم ROCm (Linux)، أو
        • Mac بمعالج Apple Silicon (M1 فما فوق) بذاكرة موحّدة ≥16 GB (يُنصح بـ ≥32 GB).
        • أجهزة Mac بمعالج Intel والأجهزة بلا GPU لن تعمل — استخدم Cloud بدلًا من ذلك.

      أيهما تفضّل؟"

      التوجيه:

      • Cloud ← انتقل إلى المسار A.
      • محليًا ← نفّذ فحص العتاد أولًا، ثم اختر مسارًا من المسارات B–E بناءً على النتيجة.
      • غير متأكد ← نفّذ فحص العتاد ودع النتيجة تقرر.

      الخطوة 1: تحقّق من العتاد (فقط إذا اختار المستخدم المحلي)​

      python3 scripts/hardware_check.py --json
      # Optional: also probe `torch` for actual CUDA/MPS:
      python3 scripts/hardware_check.py --json --check-pytorch
      النتيجةالمعنىالإجراء
      ok≥8 GB VRAM (منفصلة) أو ≥32 GB ذاكرة موحّدة (Apple Silicon)تثبيت محلي — استخدم comfy_cli_flag من التقرير
      marginalSD1.5 يعمل؛ SDXL ضيّق؛ Flux/الفيديو غير مرجّحمحلي مناسب لتدفقات العمل الخفيفة، وإلا المسار A (Cloud)
      cloudلا يوجد GPU قابل للاستخدام، <6 GB VRAM، <16 GB ذاكرة موحّدة على Apple، Mac بمعالج Intel، Python عبر Rosettaانتقل إلى Cloud ما لم يفرض المستخدم المحلي صراحة

      يُظهر السكربت أيضًا wsl: true (WSL2 مع تمرير NVIDIA) و rosetta: true (Python بمعمارية x86_64 على Apple Silicon — يجب إعادة تثبيته بمعمارية ARM64).

      إذا كانت النتيجة cloud لكن المستخدم يريد المحلي، لا تمضِ في صمت. اعرض مصفوفة notes كما هي واسأله هل يريد (أ) الانتقال إلى Cloud أو (ب) فرض تثبيت محلي (قد يستنفد الذاكرة أو يكون بطيئًا جدًا مع النماذج الحديثة).

      اختيار مسار التثبيت​

      استخدم فحص العتاد أولًا. الجدول أدناه هو الخيار الاحتياطي عندما يكون المستخدم قد أخبرك بعتاده مسبقًا:

      الحالةالمسار الموصى به
      النتيجة verdict: cloud من فحص العتادالمسار A: Comfy Cloud
      لا يوجد GPU / يريد التجربة دون التزامالمسار A: Comfy Cloud
      Windows + NVIDIA + غير تقنيالمسار B: ComfyUI Desktop
      Windows + NVIDIA + تقنيالمسار C: Portable أو المسار D: comfy-cli
      Linux + أي GPUالمسار D: comfy-cli (الأسهل)
      macOS + Apple Siliconالمسار B: Desktop أو المسار D: comfy-cli
      بلا واجهة / خادم / CI / وكلاءالمسار D: comfy-cli

      للمسار المؤتمت بالكامل (فحص العتاد ← التثبيت ← التشغيل ← التحقق):

      bash scripts/comfyui_setup.sh
      # Or with overrides:
      bash scripts/comfyui_setup.sh --m-series --port=8190 --workspace=/data/comfy

      ينفّذ هذا داخليًا hardware_check.py، ويرفض التثبيت محليًا عندما تكون النتيجة cloud (ما لم تستخدم --force-cloud-override)، ويختار خيار comfy-cli المناسب، ويفضّل pipx/uvx على pip العام لتجنّب تلويث Python النظامي.

      المسار A: Comfy Cloud (بلا تثبيت محلي)​

      للمستخدمين بلا GPU كافٍ أو الراغبين في إعداد صفري. مُستضاف على RTX 6000 Pro.

      الوثائق: https://docs.comfy.org/get_started/cloud

      1. سجّل في https://comfy.org/cloud
      2. ولّد مفتاح API في https://platform.comfy.org/login
      3. اضبط المفتاح: 
        export COMFY_CLOUD_API_KEY="your-comfyui-key"
      4. شغّل تدفقات العمل: 
        python3 scripts/run_workflow.py \
          --workflow workflows/flux_dev_txt2img.json \
          --args '{"prompt": "..."}' \
          --host https://cloud.comfy.org \
          --output-dir ./outputs

      التسعير: https://www.comfy.org/cloud/pricing المهام المتزامنة: Free/Standard: 1، Creator: 3، Pro: 5. المستوى المجاني لا يمكنه تشغيل تدفقات العمل عبر API — يمكنه فقط تصفّح النماذج. الاشتراك المدفوع مطلوب لـ /api/prompt, /api/upload/*, /api/view، وغيرها.

      المسار B: ComfyUI Desktop (Windows / macOS)​

      مُثبّت بنقرة واحدة للمستخدمين غير التقنيين. حاليًا في مرحلة Beta.

      الوثائق: https://docs.comfy.org/installation/desktop

      • Windows (NVIDIA): https://download.comfy.org/windows/nsis/x64
      • macOS (Apple Silicon): https://comfy.org

      Linux غير مدعوم لـ Desktop — استخدم المسار D.

      المسار C: ComfyUI Portable (Windows فقط)​

      الوثائق: https://docs.comfy.org/installation/comfyui_portable_windows

      نزّل من https://github.com/comfyanonymous/ComfyUI/releases، استخرج، شغّل run_nvidia_gpu.bat. حدّث عبر update/update_comfyui_stable.bat.

      المسار D: comfy-cli (كل المنصات — موصى به للوكلاء)​

      الـ CLI الرسمي هو أفضل مسار للإعدادات المؤتمتة وبلا واجهة.

      الوثائق: https://docs.comfy.org/comfy-cli/getting-started

      تثبيت comfy-cli​

      # Recommended:
      pipx install comfy-cli
      # Or use uvx without installing:
      uvx --from comfy-cli comfy --help
      # Or (if pipx/uvx unavailable):
      pip install --user comfy-cli

      عطّل التحليلات (analytics) بشكل غير تفاعلي:

      comfy --skip-prompt tracking disable

      تثبيت ComfyUI​

      comfy --skip-prompt install --nvidia              # NVIDIA (CUDA)
      comfy --skip-prompt install --amd                 # AMD (ROCm, Linux)
      comfy --skip-prompt install --m-series            # Apple Silicon (MPS)
      comfy --skip-prompt install --cpu                 # CPU only (slow)
      comfy --skip-prompt install --nvidia --fast-deps  # uv-based dep resolution

      الموقع الافتراضي: ~/comfy/ComfyUI (Linux)، ~/Documents/comfy/ComfyUI (macOS/Win). تجاوزه بـ comfy --workspace /custom/path install.

      التشغيل / التحقق​

      comfy launch -- --listen 0.0.0.0 --port 8190    # LAN-accessible custom port
      curl -s http://127.0.0.1:8188/system_stats      # health check

      رفع الصور (img2img / Inpainting)​

      أبسط طريقة هي استخدام --input-image مع run_workflow.py:

      python3 scripts/run_workflow.py \
        --workflow workflows/sdxl_img2img.json \
        --input-image image=./photo.png \
        --args '{"prompt": "make it cyberpunk", "denoise": 0.6}'

      يرفع هذا الخيار (flag) الملف photo.png، ثم يحقن اسمه على جانب الخادم في أي معامل مخطط (schema parameter) مسمّى image. لـ inpainting، مرّر كليهما:

      python3 scripts/run_workflow.py \
        --workflow workflows/sdxl_inpaint.json \
        --input-image image=./photo.png \
        --input-image mask_image=./mask.png \
        --args '{"prompt": "fill with flowers"}'

      الرفع اليدوي عبر REST:

      curl -X POST "http://127.0.0.1:8188/upload/image" \
        -F "image=@photo.png" -F "type=input" -F "overwrite=true"
      # Returns: {"name": "photo.png", "subfolder": "", "type": "input"}

      # Cloud equivalent:
      curl -X POST "https://cloud.comfy.org/api/upload/image" \
        -H "X-API-Key: $COMFY_CLOUD_API_KEY" \
        -F "image=@photo.png" -F "type=input" -F "overwrite=true"

      خصائص Cloud​

      • الرابط الأساسي: https://cloud.comfy.org
      • المصادقة: ترويسة X-API-Key (أو ?token=KEY لـ WebSocket)
      • مفتاح API: اضبط $COMFY_CLOUD_API_KEY مرة واحدة وتلتقطه السكربتات تلقائيًا
      • تنزيل المخرجات: يُعيد /api/view إعادة توجيه 302 إلى رابط موقّع؛ تتبع السكربتات ذلك الرابط وتزيل X-API-Key قبل الجلب من خدمة التخزين (كي لا يتسرّب مفتاح API إلى S3/CloudFront).
      • الفروقات في نقاط النهاية (endpoints) مقارنة بـ ComfyUI المحلي:
        • /api/object_info, /api/queue, /api/userdata — 403 على المستوى المجاني؛ مدفوعة فقط.
        • يُعاد تسمية /history إلى /history_v2 على السحابة (توجّهها السكربتات تلقائيًا).
        • يُعاد تسمية /models/<folder> إلى /experiment/models/<folder> على السحابة (توجّهها السكربتات تلقائيًا).
        • يُتجاهل حاليًا clientId في WebSocket — كل الاتصالات لمستخدم واحد تستلم نفس البث. صفِّ حسب prompt_id من جانب العميل.
        • يُقبل subfolder عند الرفع لكن يُتجاهل — تستخدم السحابة مساحة أسماء مسطّحة.
      • المهام المتزامنة: Free/Standard: 1، Creator: 3، Pro: 5. المهام الإضافية تدخل قائمة الانتظار تلقائيًا. استخدم run_batch.py --parallel N لاستغلال مستواك بالكامل.

      المزالق​

      1. تنسيق API مطلوب — يتوقّع كل سكربت ونقطة النهاية /api/prompt أن يكون JSON تدفق العمل بتنسيق API. تكتشف السكربتات تنسيق المحرر (مصفوفتا nodes و links على المستوى الأعلى) وتطلب منك إعادة التصدير عبر "Workflow → Export (API)" (الواجهة الأحدث) أو "Save (API Format)" (الواجهة الأقدم).

      2. يجب أن يكون الخادم قيد التشغيل — كل عمليات التنفيذ تتطلب خادمًا حيًا. يشغّل comfy launch --background واحدًا. تحقّق بـ curl http://127.0.0.1:8188/system_stats.

      3. أسماء النماذج دقيقة — حساسة لحالة الأحرف، وتشمل امتداد الملف. يقوم check_deps.py بمطابقة تقريبية (مع/بدون الامتداد وبادئة المجلد)، لكن يجب أن يستخدم تدفق العمل نفسه الاسم القانوني (canonical). استخدم comfy model list لمعرفة ما هو مثبّت.

      4. عُقد مخصّصة مفقودة — تعني رسالة "class_type not found" أن عقدة مطلوبة غير مثبّتة. يُبلّغ check_deps.py بأي حزمة يجب تثبيتها؛ ويشغّل auto_fix_deps.py التثبيت نيابة عنك.

      5. دليل العمل (working directory) — يكتشف comfy-cli مساحة عمل ComfyUI تلقائيًا. إذا فشلت الأوامر برسالة "no workspace found"، استخدم comfy --workspace /path/to/ComfyUI <command> أو comfy set-default /path/to/ComfyUI.

      6. حدود API للمستوى المجاني على Cloud — تُعيد /api/prompt, /api/view, /api/upload/*, /api/object_info كلها 403 على الحسابات المجانية. يتعامل health_check.py و check_deps.py مع ذلك بسلاسة ويعرضان رسالة واضحة.

      7. مهلة تدفقات عمل الفيديو/الصوت — تُكتشف تلقائيًا عندما تكون عقدة المخرجات VHS_VideoCombine أو SaveVideo وغيرها؛ ترتفع القيمة الافتراضية من 300 ثانية إلى 900 ثانية. تجاوزها صراحة بـ --timeout 1800.

      8. اجتياز المسارات (path traversal) في أسماء ملفات المخرجات — تمرّ أسماء الملفات القادمة من الخادم عبر safe_path_join لرفض أي شيء يخرج عن --output-dir. أبقِ هذه الحماية مفعّلة — إذ يمكن لتدفقات العمل ذات عُقد الحفظ المخصّصة أن تنتج مسارات عشوائية.

      9. JSON تدفق العمل كود تعسّفي — تشغّل العُقد المخصّصة كود Python، لذا فإرسال تدفق عمل مجهول له نفس مستوى الثقة الخطر لأمر eval. افحص تدفقات العمل من مصادر غير موثوقة قبل تشغيلها.

      10. بذرة عشوائية تلقائيًا — مرّر seed: -1 في --args (أو استخدم --randomize-seed واحذف seed) للحصول على بذرة جديدة في كل تشغيل. تُسجَّل البذرة الفعلية إلى stderr.

      11. مُوجِّه tracking — قد يطلب أول تشغيل لـ comfy إذنًا للتحليلات. استخدم comfy --skip-prompt tracking disable لتخطّي ذلك بشكل غير تفاعلي. يقوم comfyui_setup.sh بهذا نيابة عنك.

      قائمة تحقق​

      استخدم python3 scripts/health_check.py لتشغيل القائمة كاملة دفعة واحدة. يدويًا:

      • نتيجة hardware_check.py هي ok أو أن المستخدم اختار Comfy Cloud صراحة
      • يعمل comfy --version (أو uvx --from comfy-cli comfy --help)
      • يُعيد curl http://HOST:PORT/system_stats بيانات JSON
      • يُظهر comfy model list نقطة تفتيش (checkpoint) واحدة على الأقل (محليًا) أو يُعيد /api/experiment/models/checkpoints نماذج (على السحابة)
      • JSON تدفق العمل بتنسيق API
      • يُبلّغ check_deps.py بـ is_ready: true (أو node_check_skipped فقط على المستوى المجاني للسحابة)
      • يكتمل تشغيل تجريبي بتدفق عمل صغير؛ وتصل المخرجات إلى --output-dir
