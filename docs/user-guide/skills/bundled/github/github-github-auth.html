      مصادقة GitHub

      إعداد مصادقة GitHub: tokens عبر HTTPS، مفاتيح SSH، تسجيل الدخول عبر gh CLI.

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      إعداد مصادقة GitHub

      تُعِدّ هذه المهارة المصادقة كي يتمكّن الوكيل من العمل مع مستودعات GitHub وطلبات pull request والمشكلات (issues) والتكامل المستمر (CI). وهي تغطّي مسارين:

      • git (متاح دائمًا) — يستخدم personal access tokens عبر HTTPS أو مفاتيح SSH
      • gh CLI (إن كان مثبّتًا) — وصول أغنى إلى API الخاص بـ GitHub مع مسار مصادقة أبسط

      مسار الاكتشاف​

      عندما يطلب منك المستخدم العمل مع GitHub، نفّذ هذا التحقق أولًا:

      # Check what's available
      git --version
      gh --version 2>/dev/null || echo "gh not installed"

      # Check if already authenticated
      gh auth status 2>/dev/null || echo "gh not authenticated"
      git config --global credential.helper 2>/dev/null || echo "no git credential helper"

      شجرة القرار:

      1. إذا أظهر gh auth status أنّك مصادَق عليك ← أنت جاهز، استخدم gh لكل شيء
      2. إذا كان gh مثبّتًا لكن غير مصادَق عليه ← استخدم طريقة "gh auth" أدناه
      3. إذا لم يكن gh مثبّتًا ← استخدم طريقة "git فقط" أدناه (لا حاجة إلى sudo)

      الطريقة 1: المصادقة باستخدام git فقط (بدون gh، بدون sudo)​

      تعمل هذه الطريقة على أي جهاز مثبّت عليه git. لا حاجة لصلاحيات الجذر (root).

      الخيار أ: HTTPS مع Personal Access Token (موصى به)​

      هذه هي الطريقة الأكثر قابلية للنقل — تعمل في كل مكان، ولا تحتاج إلى إعداد SSH.

      الخطوة 1: إنشاء personal access token

      اطلب من المستخدم الانتقال إلى: https://github.com/settings/tokens

      • اضغط "Generate new token (classic)"
      • أعطه اسمًا مثل "hermes-agent"
      • اختر النطاقات (scopes):
        • repo (وصول كامل إلى المستودع — قراءة، كتابة، push، PRs)
        • workflow (تشغيل وإدارة GitHub Actions)
        • read:org (عند العمل مع مستودعات مؤسسة)
      • اضبط تاريخ انتهاء الصلاحية (90 يومًا خيار افتراضي جيد)
      • انسخ الـ token — لن يظهر مجددًا

      الخطوة 2: إعداد git لتخزين الـ token

      # Set up the credential helper to cache credentials
      # "store" saves to ~/.git-credentials in plaintext (simple, persistent)
      git config --global credential.helper store

      # Now do a test operation that triggers auth — git will prompt for credentials
      # Username: <their-github-username>
      # Password: <paste the personal access token, NOT their GitHub password>
      git ls-remote https://github.com/<their-username>/<any-repo>.git

      بعد إدخال بيانات الاعتماد مرة واحدة، تُحفظ ويُعاد استخدامها في كل العمليات اللاحقة.

      بديل: مساعد التخزين المؤقت (cache) (تنتهي صلاحية بيانات الاعتماد من الذاكرة)

      # Cache in memory for 8 hours (28800 seconds) instead of saving to disk
      git config --global credential.helper 'cache --timeout=28800'

      بديل: ضبط الـ token مباشرة في عنوان الـ remote (لكل مستودع)

      # Embed token in the remote URL (avoids credential prompts entirely)
      git remote set-url origin https://<username>:<token>@github.com/<owner>/<repo>.git

      الخطوة 3: إعداد هوية git

      # Required for commits — set name and email
      git config --global user.name "Their Name"
      git config --global user.email "their-email@example.com"

      الخطوة 4: التحقق

      # Test push access (this should work without any prompts now)
      git ls-remote https://github.com/<their-username>/<any-repo>.git

      # Verify identity
      git config --global user.name
      git config --global user.email

      الخيار ب: المصادقة بمفتاح SSH​

      مناسب للمستخدمين الذين يفضّلون SSH أو لديهم مفاتيح مُعدّة مسبقًا.

      الخطوة 1: التحقق من وجود مفاتيح SSH

      ls -la ~/.ssh/id_*.pub 2>/dev/null || echo "No SSH keys found"

      الخطوة 2: توليد مفتاح عند الحاجة

      # Generate an ed25519 key (modern, secure, fast)
      ssh-keygen -t ed25519 -C "their-email@example.com" -f ~/.ssh/id_ed25519 -N ""

      # Display the public key for them to add to GitHub
      cat ~/.ssh/id_ed25519.pub

      اطلب من المستخدم إضافة المفتاح العام في: https://github.com/settings/keys

      • اضغط "New SSH key"
      • الصق محتوى المفتاح العام
      • أعطه عنوانًا مثل "hermes-agent-<machine-name>"

      الخطوة 3: اختبار الاتصال

      ssh -T git@github.com
      # Expected: "Hi <username>! You've successfully authenticated..."

      الخطوة 4: إعداد git لاستخدام SSH مع GitHub

      # Rewrite HTTPS GitHub URLs to SSH automatically
      git config --global url."git@github.com:".insteadOf "https://github.com/"

      الخطوة 5: إعداد هوية git

      git config --global user.name "Their Name"
      git config --global user.email "their-email@example.com"

      الطريقة 2: المصادقة عبر gh CLI​

      إذا كان gh مثبّتًا، فهو يتولّى الوصول إلى API وبيانات اعتماد git في خطوة واحدة.

      تسجيل الدخول التفاعلي عبر المتصفح (Desktop)​

      gh auth login
      # Select: GitHub.com
      # Select: HTTPS
      # Authenticate via browser

      تسجيل الدخول عبر Token (خوادم بلا واجهة / SSH)​

      echo "<THEIR_TOKEN>" | gh auth login --with-token

      # Set up git credentials through gh
      gh auth setup-git

      التحقق​

      gh auth status

      استخدام API الخاص بـ GitHub بدون gh​

      عندما لا يكون gh متوفرًا، لا يزال بإمكانك الوصول إلى كامل API الخاص بـ GitHub باستخدام curl مع personal access token. هكذا تنفّذ مهارات GitHub الأخرى طرقها الاحتياطية.

      ضبط الـ token لاستدعاءات API​

      # Option 1: Export as env var (preferred — keeps it out of commands)
      export GITHUB_TOKEN="<token>"

      # Then use in curl calls:
      curl -s -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/user

      استخراج الـ token من بيانات اعتماد git​

      إذا كانت بيانات اعتماد git مُعدّة مسبقًا (عبر credential.helper store)، يمكن استخراج الـ token:

      # Read from git credential store
      uv run python3 "${HERMES_HOME:-$HOME/.hermes}/skills/github/github-auth/scripts/git-credential-token.py"

      مساعد: اكتشاف طريقة المصادقة​

      استخدم هذا النمط في بداية أي سير عمل يخص GitHub:

      # Try gh first, fall back to git + curl
      if command -v gh &>/dev/null && gh auth status &>/dev/null; then
        echo "AUTH_METHOD=gh"
      elif [ -n "$GITHUB_TOKEN" ]; then
        echo "AUTH_METHOD=curl"
      elif _hermes_env="${HERMES_HOME:-$HOME/.hermes}/.env"; [ -f "$_hermes_env" ] && grep -q "^GITHUB_TOKEN=" "$_hermes_env"; then
        export GITHUB_TOKEN=$(grep "^GITHUB_TOKEN=" "$_hermes_env" | head -1 | cut -d= -f2 | tr -d '\n\r')
        echo "AUTH_METHOD=curl"
      elif grep -q "github.com" ~/.git-credentials 2>/dev/null; then
        export GITHUB_TOKEN=$(uv run python3 "${HERMES_HOME:-$HOME/.hermes}/skills/github/github-auth/scripts/git-credential-token.py")
        echo "AUTH_METHOD=curl"
      else
        echo "AUTH_METHOD=none"
        echo "Need to set up authentication first"
      fi

      استكشاف الأخطاء وإصلاحها​

      المشكلةالحل
      git push يطلب كلمة مرورعطّل GitHub المصادقة بكلمة المرور. استخدم personal access token ككلمة المرور، أو انتقل إلى SSH
      remote: Permission to X deniedقد يفتقر الـ token إلى نطاق repo — أعد توليده بالنطاقات الصحيحة
      fatal: Authentication failedقد تكون بيانات الاعتماد المخزّنة مؤقتًا قديمة — نفّذ git credential reject ثم أعد المصادقة
      ssh: connect to host github.com port 22: Connection refusedجرّب SSH عبر منفذ HTTPS: أضف Host github.com مع Port 443 وHostname ssh.github.com إلى ~/.ssh/config
      بيانات الاعتماد لا تُحفظ بشكل دائمتحقّق من git config --global credential.helper — يجب أن تكون store أو cache
      حسابات GitHub متعددةاستخدم SSH بمفاتيح مختلفة لكل اسم مستعار مضيف (host alias) في ~/.ssh/config، أو عناوين اعتماد لكل مستودع
      gh: command not found + بدون sudoاستخدم الطريقة 1 (git فقط) أعلاه — لا حاجة للتثبيت
