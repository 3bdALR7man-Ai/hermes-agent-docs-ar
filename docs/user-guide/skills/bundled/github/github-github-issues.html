      مشكلات GitHub

      إنشاء مشكلات GitHub وفرزها ووسمها وإسنادها عبر gh أو REST.

      بيانات المهارة الوصفية​

      المصدرمضمّنة (مثبّتة افتراضيًا)
      المسارskills/github/github-issues
      الإصدار1.1.0
      المؤلفHermes Agent
      الترخيصMIT
      المنصاتlinux, macos, windows
      الوسومGitHub, Issues, Project-Management, Bug-Tracking, Triage
      مهارات ذات صلةgithub-auth, github-pr-workflow

      المرجع: ملف SKILL.md كاملًا​

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      إدارة مشكلات GitHub

      إنشاء مشكلات GitHub والبحث فيها وفرزها وإدارتها. يعرض كل قسم gh أولًا، ثم الطريقة الاحتياطية عبر curl.

      المتطلبات الأساسية​

      • مصادَق عليه مع GitHub (راجع مهارة github-auth)
      • داخل مستودع git له remote على GitHub، أو حدِّد المستودع صراحةً

      الإعداد​

      if command -v gh &>/dev/null && gh auth status &>/dev/null; then
        AUTH="gh"
      else
        AUTH="git"
        if [ -z "$GITHUB_TOKEN" ]; then
          if _hermes_env="${HERMES_HOME:-$HOME/.hermes}/.env"; [ -f "$_hermes_env" ] && grep -q "^GITHUB_TOKEN=" "$_hermes_env"; then
            GITHUB_TOKEN=$(grep "^GITHUB_TOKEN=" "$_hermes_env" | head -1 | cut -d= -f2 | tr -d '\n\r')
          elif grep -q "github.com" ~/.git-credentials 2>/dev/null; then
            GITHUB_TOKEN=$(uv run python3 "${HERMES_HOME:-$HOME/.hermes}/skills/github/github-auth/scripts/git-credential-token.py")
          fi
        fi
      fi

      REMOTE_URL=$(git remote get-url origin)
      OWNER_REPO=$(echo "$REMOTE_URL" | sed -E 's|.*github\.com[:/]||; s|\.git$||')
      OWNER=$(echo "$OWNER_REPO" | cut -d/ -f1)
      REPO=$(echo "$OWNER_REPO" | cut -d/ -f2)

      1. عرض المشكلات​

      باستخدام gh:

      gh issue list
      gh issue list --state open --label "bug"
      gh issue list --assignee @me
      gh issue list --search "authentication error" --state all
      gh issue view 42

      باستخدام curl:

      # List open issues
      curl -s \
        -H "Authorization: token $GITHUB_TOKEN" \
        "https://api.github.com/repos/$OWNER/$REPO/issues?state=open&per_page=20" \
        | python3 -c "
      import sys, json
      for i in json.load(sys.stdin):
          if 'pull_request' not in i:  # GitHub API returns PRs in /issues too
              labels = ', '.join(l['name'] for l in i['labels'])
              print(f\"#{i['number']:5}  {i['state']:6}  {labels:30}  {i['title']}\")"

      # Filter by label
      curl -s \
        -H "Authorization: token $GITHUB_TOKEN" \
        "https://api.github.com/repos/$OWNER/$REPO/issues?state=open&labels=bug&per_page=20" \
        | python3 -c "
      import sys, json
      for i in json.load(sys.stdin):
          if 'pull_request' not in i:
              print(f\"#{i['number']}  {i['title']}\")"

      # View a specific issue
      curl -s \
        -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/repos/$OWNER/$REPO/issues/42 \
        | python3 -c "
      import sys, json
      i = json.load(sys.stdin)
      labels = ', '.join(l['name'] for l in i['labels'])
      assignees = ', '.join(a['login'] for a in i['assignees'])
      print(f\"#{i['number']}: {i['title']}\")
      print(f\"State: {i['state']}  Labels: {labels}  Assignees: {assignees}\")
      print(f\"Author: {i['user']['login']}  Created: {i['created_at']}\")
      print(f\"\n{i['body']}\")"

      # Search issues
      curl -s \
        -H "Authorization: token $GITHUB_TOKEN" \
        "https://api.github.com/search/issues?q=authentication+error+repo:$OWNER/$REPO" \
        | python3 -c "
      import sys, json
      for i in json.load(sys.stdin)['items']:
          print(f\"#{i['number']}  {i['state']:6}  {i['title']}\")"

      2. إنشاء المشكلات​

      باستخدام gh:

      gh issue create \
        --title "Login redirect ignores ?next= parameter" \
        --body "## Description
      After logging in, users always land on /dashboard.

      ## Steps to Reproduce
      1. Navigate to /settings while logged out
      2. Get redirected to /login?next=/settings
      3. Log in
      4. Actual: redirected to /dashboard (should go to /settings)

      ## Expected Behavior
      Respect the ?next= query parameter." \
        --label "bug,backend" \
        --assignee "username"

      باستخدام curl:

      curl -s -X POST \
        -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/repos/$OWNER/$REPO/issues \
        -d '{
          "title": "Login redirect ignores ?next= parameter",
          "body": "## Description\nAfter logging in, users always land on /dashboard.\n\n## Steps to Reproduce\n1. Navigate to /settings while logged out\n2. Get redirected to /login?next=/settings\n3. Log in\n4. Actual: redirected to /dashboard\n\n## Expected Behavior\nRespect the ?next= query parameter.",
          "labels": ["bug", "backend"],
          "assignees": ["username"]
        }'

      قالب تقرير الخلل (Bug Report)​

      ## Bug Description
      <What's happening>

      ## Steps to Reproduce
      1. <step>
      2. <step>

      ## Expected Behavior
      <What should happen>

      ## Actual Behavior
      <What actually happens>

      ## Environment
      - OS: <os>
      - Version: <version>

      قالب طلب الميزة (Feature Request)​

      ## Feature Description
      <What you want>

      ## Motivation
      <Why this would be useful>

      ## Proposed Solution
      <How it could work>

      ## Alternatives Considered
      <Other approaches>

      3. إدارة المشكلات​

      إضافة/إزالة الوسوم​

      باستخدام gh:

      gh issue edit 42 --add-label "priority:high,bug"
      gh issue edit 42 --remove-label "needs-triage"

      باستخدام curl:

      # Add labels
      curl -s -X POST \
        -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/repos/$OWNER/$REPO/issues/42/labels \
        -d '{"labels": ["priority:high", "bug"]}'

      # Remove a label
      curl -s -X DELETE \
        -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/repos/$OWNER/$REPO/issues/42/labels/needs-triage

      # List available labels in the repo
      curl -s \
        -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/repos/$OWNER/$REPO/labels \
        | python3 -c "
      import sys, json
      for l in json.load(sys.stdin):
          print(f\"  {l['name']:30}  {l.get('description', '')}\")"

      الإسناد​

      باستخدام gh:

      gh issue edit 42 --add-assignee username
      gh issue edit 42 --add-assignee @me

      باستخدام curl:

      curl -s -X POST \
        -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/repos/$OWNER/$REPO/issues/42/assignees \
        -d '{"assignees": ["username"]}'

      إضافة التعليقات​

      باستخدام gh:

      gh issue comment 42 --body "Investigated — root cause is in auth middleware. Working on a fix."

      باستخدام curl:

      curl -s -X POST \
        -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/repos/$OWNER/$REPO/issues/42/comments \
        -d '{"body": "Investigated — root cause is in auth middleware. Working on a fix."}'

      الإغلاق وإعادة الفتح​

      باستخدام gh:

      gh issue close 42
      gh issue close 42 --reason "not planned"
      gh issue reopen 42

      باستخدام curl:

      # Close
      curl -s -X PATCH \
        -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/repos/$OWNER/$REPO/issues/42 \
        -d '{"state": "closed", "state_reason": "completed"}'

      # Reopen
      curl -s -X PATCH \
        -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/repos/$OWNER/$REPO/issues/42 \
        -d '{"state": "open"}'

      ربط المشكلات بطلبات pull request​

      تُغلَق المشكلات تلقائيًا عند دمج PR يحتوي على الكلمات المفتاحية الصحيحة في نصه:

      Closes #42
      Fixes #42
      Resolves #42

      لإنشاء branch من مشكلة:

      باستخدام gh:

      gh issue develop 42 --checkout

      باستخدام git (المكافئ اليدوي):

      git checkout main && git pull origin main
      git checkout -b fix/issue-42-login-redirect

      4. سير عمل فرز المشكلات​

      عند الطلب منك فرز المشكلات:

      1. اسرد المشكلات غير المفروزة:
      # With gh
      gh issue list --label "needs-triage" --state open

      # With curl
      curl -s \
        -H "Authorization: token $GITHUB_TOKEN" \
        "https://api.github.com/repos/$OWNER/$REPO/issues?labels=needs-triage&state=open" \
        | python3 -c "
      import sys, json
      for i in json.load(sys.stdin):
          if 'pull_request' not in i:
              print(f\"#{i['number']}  {i['title']}\")"

      1. اقرأ وصنِّف كل مشكلة (اطّلع على التفاصيل، وافهم الخلل/الميزة)

      2. طبّق الوسوم والأولوية (راجع "إدارة المشكلات" أعلاه)

      3. أسنِد المشكلة إذا كان المالك واضحًا

      4. علّق بملاحظات الفرز عند الحاجة

      5. العمليات الدفعية​

      للعمليات الدفعية، ادمج استدعاءات API مع سكربتات الـ shell:

      باستخدام gh:

      # Close all issues with a specific label
      gh issue list --label "wontfix" --json number --jq '.[].number' | \
        xargs -I {} gh issue close {} --reason "not planned"

      باستخدام curl:

      # List issue numbers with a label, then close each
      curl -s \
        -H "Authorization: token $GITHUB_TOKEN" \
        "https://api.github.com/repos/$OWNER/$REPO/issues?labels=wontfix&state=open" \
        | python3 -c "import sys,json; [print(i['number']) for i in json.load(sys.stdin)]" \
        | while read num; do
          curl -s -X PATCH \
            -H "Authorization: token $GITHUB_TOKEN" \
            https://api.github.com/repos/$OWNER/$REPO/issues/$num \
            -d '{"state": "closed", "state_reason": "not_planned"}'
          echo "Closed #$num"
        done

      جدول مرجعي سريع​

      الإجراءghنقطة نهاية curl
      سرد المشكلاتgh issue listGET /repos/{o}/{r}/issues
      عرض مشكلةgh issue view NGET /repos/{o}/{r}/issues/N
      إنشاء مشكلةgh issue create ...POST /repos/{o}/{r}/issues
      إضافة وسومgh issue edit N --add-label ...POST /repos/{o}/{r}/issues/N/labels
      الإسنادgh issue edit N --add-assignee ...POST /repos/{o}/{r}/issues/N/assignees
      التعليقgh issue comment N --body ...POST /repos/{o}/{r}/issues/N/comments
      الإغلاقgh issue close NPATCH /repos/{o}/{r}/issues/N
      البحثgh issue list --search "..."GET /search/issues?q=...
