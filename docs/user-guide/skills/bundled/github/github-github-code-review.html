      مراجعة كود GitHub

      مراجعة PRs: الفروقات (diffs)، التعليقات السطرية عبر gh أو REST.

      بيانات المهارة الوصفية​

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      مراجعة كود GitHub

      نفّذ مراجعات للكود على التغييرات المحلية قبل الدفع (push)، أو راجع طلبات pull request المفتوحة على GitHub. تعتمد معظم هذه المهارة على git العادي — والفصل بين gh/curl مهم فقط في التفاعلات على مستوى الـ PR.

      المتطلبات الأساسية​

      • مصادَق عليه مع GitHub (راجع مهارة github-auth)
      • داخل مستودع git

      الإعداد (للتفاعلات على مستوى الـ PR)​

      if command -v gh &>/dev/null && gh auth status &>/dev/null; then
        AUTH="gh"
      else
        AUTH="git"
        if [ -z "$GITHUB_TOKEN" ]; then
          if _hermes_env="${HERMES_HOME:-$HOME/.hermes}/.env"; [ -f "$_hermes_env" ] && grep -q "^GITHUB_TOKEN=" "$_hermes_env"; then
            GITHUB_TOKEN=$(grep "^GITHUB_TOKEN=" "$_hermes_env" | head -1 | cut -d= -f2 | tr -d '\n\r')
          elif grep -q "github.com" ~/.git-credentials 2>/dev/null; then
            GITHUB_TOKEN=$(uv run python3 "${HERMES_HOME:-$HOME/.hermes}/skills/github/github-auth/scripts/git-credential-token.py")
          fi
        fi
      fi

      REMOTE_URL=$(git remote get-url origin)
      OWNER_REPO=$(echo "$REMOTE_URL" | sed -E 's|.*github\.com[:/]||; s|\.git$||')
      OWNER=$(echo "$OWNER_REPO" | cut -d/ -f1)
      REPO=$(echo "$OWNER_REPO" | cut -d/ -f2)

      1. مراجعة التغييرات المحلية (قبل الدفع)​

      هذا استخدام خالص لـ git — يعمل في كل مكان، ولا حاجة إلى API.

      الحصول على الـ diff​

      # Staged changes (what would be committed)
      git diff --staged

      # All changes vs main (what a PR would contain)
      git diff main...HEAD

      # File names only
      git diff main...HEAD --name-only

      # Stat summary (insertions/deletions per file)
      git diff main...HEAD --stat

      استراتيجية المراجعة​

      1. احصل على الصورة الكبيرة أولًا:
      git diff main...HEAD --stat
      git log main..HEAD --oneline
      1. راجع ملفًا بملف — استخدم read_file على الملفات المتغيّرة للحصول على السياق الكامل، واستخدم الـ diff لمعرفة ما تغيّر:
      git diff main...HEAD -- src/auth/login.py
      1. تحقّق من المشكلات الشائعة:
      # Debug statements, TODOs, console.logs left behind
      git diff main...HEAD | grep -n "print(\|console\.log\|TODO\|FIXME\|HACK\|XXX\|debugger"

      # Large files accidentally staged
      git diff main...HEAD --stat | sort -t'|' -k2 -rn | head -10

      # Secrets or credential patterns
      git diff main...HEAD | grep -in "password\|secret\|api_key\|token.*=\|private_key"

      # Merge conflict markers
      git diff main...HEAD | grep -n "<<<<<<\|>>>>>>\|======="
      1. اعرض ملاحظات منظّمة على المستخدم.

      صيغة مخرجات المراجعة​

      عند مراجعة التغييرات المحلية، اعرض النتائج بهذا الهيكل:

      ## Code Review Summary

      ### Critical
      - **src/auth.py:45** — SQL injection: user input passed directly to query.
        Suggestion: Use parameterized queries.

      ### Warnings
      - **src/models/user.py:23** — Password stored in plaintext. Use bcrypt or argon2.
      - **src/api/routes.py:112** — No rate limiting on login endpoint.

      ### Suggestions
      - **src/utils/helpers.py:8** — Duplicates logic in `src/core/utils.py:34`. Consolidate.
      - **tests/test_auth.py** — Missing edge case: expired token test.

      ### Looks Good
      - Clean separation of concerns in the middleware layer
      - Good test coverage for the happy path

      2. مراجعة طلب pull request على GitHub​

      عرض تفاصيل الـ PR​

      باستخدام gh:

      gh pr view 123
      gh pr diff 123
      gh pr diff 123 --name-only

      باستخدام git + curl:

      PR_NUMBER=123

      # Get PR details
      curl -s \
        -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/repos/$OWNER/$REPO/pulls/$PR_NUMBER \
        | python3 -c "
      import sys, json
      pr = json.load(sys.stdin)
      print(f\"Title: {pr['title']}\")
      print(f\"Author: {pr['user']['login']}\")
      print(f\"Branch: {pr['head']['ref']} -> {pr['base']['ref']}\")
      print(f\"State: {pr['state']}\")
      print(f\"Body:\n{pr['body']}\")"

      # List changed files
      curl -s \
        -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/repos/$OWNER/$REPO/pulls/$PR_NUMBER/files \
        | python3 -c "
      import sys, json
      for f in json.load(sys.stdin):
          print(f\"{f['status']:10} +{f['additions']:-4} -{f['deletions']:-4}  {f['filename']}\")"

      سحب الـ PR محليًا لمراجعة كاملة​

      يعمل هذا مع git العادي — لا حاجة إلى gh:

      # Fetch the PR branch and check it out
      git fetch origin pull/123/head:pr-123
      git checkout pr-123

      # Now you can use read_file, search_files, run tests, etc.

      # View diff against the base branch
      git diff main...pr-123

      باستخدام gh (اختصار):

      gh pr checkout 123

      ترك تعليقات على PR​

      تعليق عام على الـ PR — باستخدام gh:

      gh pr comment 123 --body "Overall looks good, a few suggestions below."

      تعليق عام على الـ PR — باستخدام curl:

      curl -s -X POST \
        -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/repos/$OWNER/$REPO/issues/$PR_NUMBER/comments \
        -d '{"body": "Overall looks good, a few suggestions below."}'

      ترك تعليقات مراجعة سطرية (inline)​

      تعليق سطري واحد — باستخدام gh (عبر API):

      HEAD_SHA=$(gh pr view 123 --json headRefOid --jq '.headRefOid')

      gh api repos/$OWNER/$REPO/pulls/123/comments \
        --method POST \
        -f body="This could be simplified with a list comprehension." \
        -f path="src/auth/login.py" \
        -f commit_id="$HEAD_SHA" \
        -f line=45 \
        -f side="RIGHT"

      تعليق سطري واحد — باستخدام curl:

      # Get the head commit SHA
      HEAD_SHA=$(curl -s \
        -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/repos/$OWNER/$REPO/pulls/$PR_NUMBER \
        | python3 -c "import sys,json; print(json.load(sys.stdin)['head']['sha'])")

      curl -s -X POST \
        -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/repos/$OWNER/$REPO/pulls/$PR_NUMBER/comments \
        -d "{
          \"body\": \"This could be simplified with a list comprehension.\",
          \"path\": \"src/auth/login.py\",
          \"commit_id\": \"$HEAD_SHA\",
          \"line\": 45,
          \"side\": \"RIGHT\"
        }"

      إرسال مراجعة رسمية (اعتماد / طلب تغييرات)​

      باستخدام gh:

      gh pr review 123 --approve --body "LGTM!"
      gh pr review 123 --request-changes --body "See inline comments."
      gh pr review 123 --comment --body "Some suggestions, nothing blocking."

      باستخدام curl — مراجعة متعددة التعليقات تُرسَل ذريًا (atomically):

      HEAD_SHA=$(curl -s \
        -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/repos/$OWNER/$REPO/pulls/$PR_NUMBER \
        | python3 -c "import sys,json; print(json.load(sys.stdin)['head']['sha'])")

      curl -s -X POST \
        -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/repos/$OWNER/$REPO/pulls/$PR_NUMBER/reviews \
        -d "{
          \"commit_id\": \"$HEAD_SHA\",
          \"event\": \"COMMENT\",
          \"body\": \"Code review from Hermes Agent\",
          \"comments\": [
            {\"path\": \"src/auth.py\", \"line\": 45, \"body\": \"Use parameterized queries to prevent SQL injection.\"},
            {\"path\": \"src/models/user.py\", \"line\": 23, \"body\": \"Hash passwords with bcrypt before storing.\"},
            {\"path\": \"tests/test_auth.py\", \"line\": 1, \"body\": \"Add test for expired token edge case.\"}
          ]
        }"

      قيم الحدث (event): "APPROVE"، "REQUEST_CHANGES"، "COMMENT"

      يشير الحقل line إلى رقم السطر في النسخة الجديدة من الملف. للأسطر المحذوفة، استخدم "side": "LEFT".

      3. قائمة مراجعة​

      عند إجراء مراجعة كود (محلية أو PR)، تحقّق بشكل منهجي من:

      الصحة (Correctness)​

      • هل يقوم الكود بما يدّعي القيام به؟
      • هل الحالات الحدّية معالَجة (مدخلات فارغة، قيم null، بيانات كبيرة، وصول متزامن)؟
      • هل مسارات الأخطاء مُعالَجة بسلاسة؟

      الأمان​

      • لا توجد أسرار (secrets) أو بيانات اعتماد أو مفاتيح API مضمّنة في الكود مباشرة
      • التحقق من صحة المدخلات (input validation) على المدخلات الموجَّهة للمستخدم
      • لا يوجد SQL injection أو XSS أو path traversal
      • وجود فحوص المصادقة/التفويض حيثما لزم

      جودة الكود​

      • تسمية واضحة (المتغيرات، الدوال، الأصناف)
      • لا تعقيد غير ضروري أو تجريد سابق لأوانه
      • مبدأ DRY — لا منطق مكرر كان ينبغي استخلاصه
      • الدوال مركّزة (مسؤولية واحدة)

      الاختبار​

      • هل مسارات الكود الجديدة مُختبَرة؟
      • هل المسار السليم وحالات الخطأ مغطّاة؟
      • هل الاختبارات قابلة للقراءة والصيانة؟

      الأداء​

      • لا استعلامات N+1 أو حلقات غير ضرورية
      • تخزين مؤقت مناسب حيثما كان مفيدًا
      • لا عمليات حاجبة (blocking) في مسارات الكود غير المتزامنة (async)

      التوثيق​

      • واجهات API العامة موثَّقة
      • المنطق غير الواضح يحتوي على تعليقات تشرح "السبب"
      • README محدَّث إذا تغيّر السلوك

      4. سير عمل المراجعة قبل الدفع (Push)​

      عندما يطلب منك المستخدم "مراجعة الكود" أو "التحقق قبل الدفع":

      1. git diff main...HEAD --stat — اطّلع على نطاق التغييرات
      2. git diff main...HEAD — اقرأ الـ diff الكامل
      3. لكل ملف متغيّر، استخدم read_file إذا احتجت سياقًا إضافيًا
      4. طبّق القائمة أعلاه
      5. اعرض النتائج بالصيغة المنظَّمة (حرِج / تحذيرات / اقتراحات / جيد)
      6. إذا وُجدت مشكلات حرِجة، اعرض إصلاحها قبل أن يدفع المستخدم

      5. سير عمل مراجعة PR (من البداية للنهاية)​

      عندما يطلب منك المستخدم "مراجعة PR رقم N" أو "الاطّلاع على هذا الـ PR"، أو يعطيك رابط PR، اتّبع هذه الوصفة:

      الخطوة 1: إعداد البيئة​

      source "${HERMES_HOME:-$HOME/.hermes}/skills/github/github-auth/scripts/gh-env.sh"
      # Or run the inline setup block from the top of this skill

      الخطوة 2: جمع سياق الـ PR​

      احصل على البيانات الوصفية للـ PR ووصفه وقائمة الملفات المتغيّرة لفهم النطاق قبل الخوض في الكود.

      باستخدام gh:

      gh pr view 123
      gh pr diff 123 --name-only
      gh pr checks 123

      باستخدام curl:

      PR_NUMBER=123

      # PR details (title, author, description, branch)
      curl -s -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/repos/$GH_OWNER/$GH_REPO/pulls/$PR_NUMBER

      # Changed files with line counts
      curl -s -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/repos/$GH_OWNER/$GH_REPO/pulls/$PR_NUMBER/files

      الخطوة 3: سحب الـ PR محليًا​

      هذا يمنحك وصولًا كاملًا إلى read_file وsearch_files، والقدرة على تشغيل الاختبارات.

      git fetch origin pull/$PR_NUMBER/head:pr-$PR_NUMBER
      git checkout pr-$PR_NUMBER

      الخطوة 4: اقرأ الـ diff وافهم التغييرات​

      # Full diff against the base branch
      git diff main...HEAD

      # Or file-by-file for large PRs
      git diff main...HEAD --name-only
      # Then for each file:
      git diff main...HEAD -- path/to/file.py

      لكل ملف متغيّر، استخدم read_file للاطّلاع على السياق الكامل حول التغييرات — فقد يفوت الـ diff وحده مشكلات لا تظهر إلا مع الكود المحيط.

      الخطوة 5: شغّل الفحوصات الآلية محليًا (إن أمكن)​

      # Run tests if there's a test suite
      python -m pytest 2>&1 | tail -20
      # or: npm test, cargo test, go test ./..., etc.

      # Run linter if configured
      ruff check . 2>&1 | head -30
      # or: eslint, clippy, etc.

      الخطوة 6: طبّق قائمة المراجعة (القسم 3)​

      راجع كل فئة: الصحة، الأمان، جودة الكود، الاختبار، الأداء، التوثيق.

      الخطوة 7: انشر المراجعة على GitHub​

      اجمع نتائجك وقدّمها كمراجعة رسمية مع تعليقات سطرية.

      باستخدام gh:

      # If no issues — approve
      gh pr review $PR_NUMBER --approve --body "Reviewed by Hermes Agent. Code looks clean — good test coverage, no security concerns."

      # If issues found — request changes with inline comments
      gh pr review $PR_NUMBER --request-changes --body "Found a few issues — see inline comments."

      باستخدام curl — مراجعة ذرّية (atomic) بعدة تعليقات سطرية:

      HEAD_SHA=$(curl -s -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/repos/$GH_OWNER/$GH_REPO/pulls/$PR_NUMBER \
        | python3 -c "import sys,json; print(json.load(sys.stdin)['head']['sha'])")

      # Build the review JSON — event is APPROVE, REQUEST_CHANGES, or COMMENT
      curl -s -X POST \
        -H "Authorization: token $GITHUB_TOKEN" \
        https://api.github.com/repos/$GH_OWNER/$GH_REPO/pulls/$PR_NUMBER/reviews \
        -d "{
          \"commit_id\": \"$HEAD_SHA\",
          \"event\": \"REQUEST_CHANGES\",
          \"body\": \"## Hermes Agent Review\n\nFound 2 issues, 1 suggestion. See inline comments.\",
          \"comments\": [
            {\"path\": \"src/auth.py\", \"line\": 45, \"body\": \"🔴 **Critical:** User input passed directly to SQL query — use parameterized queries.\"},
            {\"path\": \"src/models.py\", \"line\": 23, \"body\": \"⚠️ **Warning:** Password stored without hashing.\"},
            {\"path\": \"src/utils.py\", \"line\": 8, \"body\": \"💡 **Suggestion:** This duplicates logic in core/utils.py:34.\"}
          ]
        }"

      الخطوة 8: انشر أيضًا تعليقًا ملخِّصًا​

      بالإضافة إلى التعليقات السطرية، اترك ملخّصًا على المستوى الأعلى كي يحصل صاحب الـ PR على الصورة الكاملة بنظرة واحدة. استخدم صيغة مخرجات المراجعة من references/review-output-template.md.

      باستخدام gh:

      gh pr comment $PR_NUMBER --body "$(cat <<'EOF'
      ## Code Review Summary

      **Verdict: Changes Requested** (2 issues, 1 suggestion)

      ### 🔴 Critical
      - **src/auth.py:45** — SQL injection vulnerability

      ### ⚠️ Warnings
      - **src/models.py:23** — Plaintext password storage

      ### 💡 Suggestions
      - **src/utils.py:8** — Duplicated logic, consider consolidating

      ### ✅ Looks Good
      - Clean API design
      - Good error handling in the middleware layer

      ---
      *Reviewed by Hermes Agent*
      EOF
      )"

      الخطوة 9: التنظيف​

      git checkout main
      git branch -D pr-$PR_NUMBER

      القرار: اعتماد مقابل طلب تغييرات مقابل تعليق​

      • اعتماد (Approve) — لا توجد مشكلات حرِجة أو على مستوى التحذير، فقط اقتراحات بسيطة أو كل شيء سليم
      • طلب تغييرات (Request Changes) — أي مشكلة حرِجة أو على مستوى التحذير يجب إصلاحها قبل الدمج
      • تعليق (Comment) — ملاحظات واقتراحات، لكن لا شيء يعيق الدمج (استخدمها عندما تكون غير متأكد أو عندما يكون الـ PR مسوّدة)
