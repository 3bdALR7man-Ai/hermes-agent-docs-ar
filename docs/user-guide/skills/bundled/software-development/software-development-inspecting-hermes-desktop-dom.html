      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      فحص الـ DOM الحيّ لـ Hermes desktop

      نظرة عامة​

      عندما تطوّر apps/desktop والمستخدم يشغّل نفس التطبيق (hgui / npm run dev)، يمكنك قراءة الـ DOM المعروض حيًا للنافذة التي ينظر إليها — الأنماط المحسوبة، الأبعاد الهندسية، أي قاعدة CSS فازت فعليًا، مخرجات الـ console — بدلًا من استنتاج ذلك من ملفات .tsx وإصابة الخطأ.

      تفتح جلسات تشغيل خادم التطوير منفذ Chrome DevTools Protocol على 127.0.0.1:9222 تلقائيًا. المُصيِّر (renderer) هو صفحة Chromium، فكل ما يستطيع DevTools قراءته يستطيع سكربت قراءته أيضًا.

      هذا لا يغني عن النظر إليه فعليًا. يجيب CDP عن أسئلة واقعية («ما هي القيمة المحسوبة لـ padding»، «هل عُرض هذا العنصر»، «أي محدِّد يطابق»). لا يستطيع أن يخبرك إن كانت النتيجة تبدو جيدة. توازن الألوان وإحساس التباعد و«هل هذا قبيح» ما زالت تحتاج عينَي المستخدم أو لقطة شاشة. أجب عن الحقائق بـ CDP، واترك الجماليات للمستخدم.

      متى تستخدمها​

      • التحقق من أن تغييرًا في الواجهة أُنجز فعليًا في التطبيق قيد التشغيل
      • «لماذا ما زال هذا العنصر X؟» — اعثر على القاعدة الفائزة قبل تعديل أي شيء
      • تحديد محدِّد (selector) ثابت لمكوّن توشك على تغييره
      • التحقق من القيمة المحسوبة لرمز تصميم (design token) على عقدة حقيقية
      • قراءة أخطاء console الخاصة بالمُصيِّر التي يذكرها المستخدم لكن لا يستطيع نسخها

      لا تستخدمها في: تحليل الأداء (perf) أو أعمال الـ heap (node-inspect-debugger، debugging-hermes-desktop)، أو أي حالة يكون فيها السؤال الحقيقي «هل يبدو هذا صحيحًا».

      المنفذ (port)​

      مفتوح على 127.0.0.1:9222 لأي تشغيل لخادم التطوير. مغلق في حالتين فقط (apps/desktop/electron/dev-cdp.ts):

      • الإصدارات المُحزَّمة (packaged) — دائمًا، ولا توجد قيمة بيئة تتجاوز ذلك؛
      • غياب HERMES_DESKTOP_DEV_SERVER — تشغيل electron . غير مُحزَّم على dist/ هو الطريقة التي يُختبر بها التطبيق المُحزَّم بشكل واقعي، لذا يتصرف مثله.

      HERMES_DESKTOP_CDP_PORT ينقل المنفذ (=9333) أو يعطّله (=off).

      تحقّق قبل فعل أي شيء آخر:

      curl -s --max-time 3 http://127.0.0.1:${HERMES_DESKTOP_CDP_PORT:-9222}/json/version

      نتيجة فارغة ← لا يوجد منفذ. لا تخمّن منفذًا آخر بصمت.

      لا تُعِد تشغيل تطبيق المستخدم أبدًا للحصول على منفذ. هذا يدمّر جلسته وحالته. شغّل بدلًا من ذلك نسخة معزولة خاصة بك (أدناه).

      قراءة الـ DOM​

      apps/desktop/scripts/eval.mjs هو الحل السريع بسطر واحد:

      cd apps/desktop
      node scripts/eval.mjs "document.querySelectorAll('[data-slot]').length"

      للعمل متعدد الخطوات استخدم العميل المشترك — فهو يتضمن اكتشاف الهدف (target discovery) و تقييمًا (eval) واعيًا بالـ promise:

      import { CDP, SELECTORS } from './scripts/perf/lib/cdp.mjs'

      const cdp = await CDP.connect({ port: 9222, match: '5174' })
      const out = await cdp.eval(`JSON.stringify({
        radius: getComputedStyle(document.documentElement).getPropertyValue('--radius-scalar').trim(),
        composer: !!document.querySelector('[data-slot="composer-rich-input"]')
      })`)
      cdp.close()

      يحتوي SELECTORS في scripts/perf/lib/cdp.mjs على مواضع data-slot الثابتة (الـ composer، إطار عرض الخيط (thread viewport)، رسالة المساعد، زوج الدور (turn pair)، شريط الملف الشخصي). فضّلها على ابتكار querySelector جديد — إذ يتم تحديثها كوحدة واحدة عند انتقال المكوّنات.

      السؤال الذي تُجيب عنه هذه المهارة أفضل: أي قاعدة فازت؟​

      تعديل كل موضع استدعاء لأن نمطًا «لا يُطبَّق» هو الهدر الكلاسيكي. اقرأ العقدة الحقيقية أولًا:

      const el = document.querySelector('[data-slot="aui_assistant-message-root"] a')
      JSON.stringify({
        ownClasses: el.className,
        weight: getComputedStyle(el).fontWeight,
        parents: (() => {
          const out = []
          let n = el
          while ((n = n.parentElement) && out.length < 6) out.push(n.className)
          return out
        })()
      })

      إذا لم تحمل العقدة أي صنف (class) خاص بها، فإن القيمة موروثة — وتعديل مواضع الاستدعاء بالجملة لن يصلح الأمر، وتحتاج إلى قاعدة السلف (ancestor). ورقة أنماط من إضافة (plugin) (مثل @tailwindcss/typography التي تتضمّن prose a { font-weight: 500 }) تتغلب عادةً على صنف utility؛ تجاوَزها على الصنف المشترك، لا في كل موضع استخدام.

      نسختك المعزولة الخاصة​

      عندما لا يوجد منفذ، أو حين يجب ألا تُزعج نافذة المستخدم:

      cd apps/desktop
      HERMES_HOME=/tmp/cdp-probe-home \
      HERMES_DESKTOP_DEV_SERVER=http://127.0.0.1:5174 \
      HERMES_DESKTOP_CDP_PORT=9333 \
        npx electron . --user-data-dir=/tmp/cdp-probe-userdata

      يتجنّب --user-data-dir المنفصل قفل المثيل الواحد (single-instance lock) في Electron، فلا يتعارض مع نسخة hgui قيد التشغيل؛ ويبقيه HERMES_HOME المنفصل بعيدًا عن الجلسات الحقيقية. اختر منفذًا غير 9222 للسبب نفسه. شغّله في الخلفية وأنهِه عند الانتهاء.

      npm run perf:serve يفعل الشيء نفسه مع HERMES_HOME مؤقت مضمّن فيه، إذا أردت أيضًا أداة القياس (perf harness).

      مزالق شائعة​

      • لا تُنهِ أبدًا خادم التطوير أو تطبيق المستخدم «لتحرير» أي شيء. إنهاء منتصف الخدمة يدمّر مجمّع مقابس (sockets) Chromium، وتُنسَب ERR_NETWORK_CHANGED الناتجة إلى أيًّا كان ما غيّرته للتو.
      • HERMES_HOME مؤقت ليس له خلفية (backend). يسجّل التطبيق ECONNREFUSED لأجل hermes:api وقد يُغلق من تلقاء نفسه. يظل المُصيِّر مُحمّلًا والـ DOM قابلًا للقراءة — اقرأه بسرعة، ولا تخلط بين اختبار أُغلق من تلقاء نفسه ومنفذ معطوب. يسجّل Chromium السطر DevTools listening on ws://127.0.0.1:<port>/… عند ربطه؛ ذلك السطر هو الدليل على فتح المنفذ.
      • افحص بشكل متكرر، لا مرة واحدة. يحتاج التطبيق المُشغَّل حديثًا ثانية أو ثانيتين قبل أن يستجيب المنفذ.
      • لا تُفرِغ الـ DOM بالكامل أبدًا. يعرض سطح المكتب مئات العقد، و outerHTML سيُغرق سياقك. اختزل الأمر إلى كائن JSON صغير داخل التعبير المُقيَّم.
      • مرّر match إلى CDP.connect. بدونه قد تتصل بنافذة الحيوان الأليف العائمة، أو نافذة الإدخال السريع، أو هدف devtools بدلًا من النافذة الرئيسية.
      • cdp.eval يعيد القيمة مباشرة؛ أما Runtime.evaluate الخام فيضاعف التعشيش (.result.result.value). استخدم الغلاف (wrapper).
      • import.meta.env.DEV تساوي true تحت vite dev في هذا المستودع. الملاحظة في apps/desktop/scripts/profile-typing-lag.md التي تدّعي عكس ذلك قديمة وغير صحيحة.
