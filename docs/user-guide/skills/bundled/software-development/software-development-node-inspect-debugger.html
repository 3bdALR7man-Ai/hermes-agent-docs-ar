      Node --inspect Debugger

      صحّح أخطاء Node.js عبر --inspect و واجهة Chrome DevTools Protocol من CLI.

      بيانات المهارة الوصفية​

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      Node.js Inspect Debugger

      نظرة عامة​

      عندما لا يكفي console.log، شغّل مفحّص V8 المدمج في Node برمجيًا من الطرفية. تحصل على نقاط توقف حقيقية، وخطو Step In/Over/Out، وتتبّع مكدس الاستدعاءات (call stack)، وعرض النطاقات المحلية/الإغلاق (closure)، وتقييم أي تعبير في الإطار المتوقف.

      أداتان، اختر واحدة:

      • node inspect — مدمجة، بلا تثبيت، REPL عبر CLI. الأفضل للفحص السريع.
      • ndb / CDP عبر chrome-remote-interface — قابلة للبرمجة من Node/Python؛ الأفضل عندما تريد أتمتة عدد كبير من نقاط التوقف، أو تجميع الحالة عبر عدة تشغيلات، أو التصحيح دون تفاعل من حلقة وكيل (agent loop).

      فضّل node inspect أولًا. فهي متاحة دائمًا و REPL سريع.

      متى تستخدمها​

      • يفشل اختبار Node وتحتاج إلى رؤية حالة وسيطة
      • تتعطل ui-tui أو تتصرف بشكل خاطئ وتريد فحص حالة React/Ink قبل العرض (pre-render)
      • تسيء العمليات الفرعية لـ tui_gateway (_SlashWorker، عمّال جسر PTY) التصرف
      • تحتاج إلى فحص قيمة في closure لا يستطيع console.log الوصول إليها دون تعديل الكود
      • الأداء: الاتصال بعملية قيد التشغيل لالتقاط ملف تعريف CPU أو لقطة heap

      لا تستخدمها في: ما يحلّه console.log في أقل من دقيقة. التصحيح المعتمد على نقاط التوقف أثقل؛ استخدمه عندما تكون الفائدة حقيقية.

      مرجع سريع: REPL الخاص بـ node inspect​

      شغّله متوقفًا عند أول سطر:

      node inspect path/to/script.js
      # or with tsx
      node --inspect-brk $(which tsx) path/to/script.ts

      يقبل الموجّه debug>:

      الأمرالإجراء
      c أو contالمتابعة (continue)
      n أو nextخطو فوق (step over)
      s أو stepخطو داخل (step into)
      o أو outخطو خارج (step out)
      pauseإيقاف الكود قيد التشغيل مؤقتًا
      sb('file.js', 42)تعيين نقطة توقف عند السطر 42 من file.js
      sb(42)تعيين نقطة توقف عند السطر 42 من الملف الحالي
      sb('functionName')التوقف عند استدعاء الدالة
      cb('file.js', 42)حذف نقطة التوقف
      breakpointsعرض جميع نقاط التوقف
      btتتبّع الرجوع (backtrace) — مكدس الاستدعاءات
      list(5)عرض 5 أسطر من الكود المصدري حول الموضع الحالي
      watch('expr')تقييم التعبير في كل توقف
      watchersعرض التعبيرات المراقَبة
      replالدخول إلى REPL في النطاق الحالي (Ctrl+C للخروج من REPL)
      exec exprتقييم التعبير مرة واحدة
      restartإعادة تشغيل السكربت
      killإنهاء السكربت
      .exitالخروج من المصحّح

      في نمط repl الفرعي: اكتب أي تعبير JS، بما في ذلك الوصول إلى المتغيرات المحلية/متغيرات الـ closure. يُخرجك Ctrl+C إلى debug>.

      الاتصال بعملية قيد التشغيل​

      عندما تكون العملية قيد التشغيل فعلًا (مثل خادم تطوير طويل الأمد أو TUI gateway):

      # 1. Send SIGUSR1 to enable the inspector on an existing process
      kill -SIGUSR1 <pid>
      # Node prints: Debugger listening on ws://127.0.0.1:9229/<uuid>

      # 2. Attach the debugger CLI
      node inspect -p <pid>
      # or by URL
      node inspect ws://127.0.0.1:9229/<uuid>

      لبدء عملية بالمفحّص منذ البداية:

      node --inspect script.js           # listen on 127.0.0.1:9229, keep running
      node --inspect-brk script.js       # listen AND pause on first line
      node --inspect=0.0.0.0:9230 script.js   # custom host:port

      لـ TypeScript عبر tsx:

      node --inspect-brk --import tsx script.ts
      # or older tsx
      node --inspect-brk -r tsx/cjs script.ts

      CDP برمجيًا (سكربتة من الطرفية)​

      عندما تريد الأتمتة — تعيين عدد كبير من نقاط التوقف، أو التقاط حالة النطاق، أو كتابة سكربت لإعادة إنتاج المشكلة — استخدم chrome-remote-interface:

      npm i -g chrome-remote-interface        # or project-local
      # Start your target:
      node --inspect-brk=9229 target.js &

      سكربت التشغيل (احفظه باسم /tmp/cdp-debug.js):

      const CDP = require('chrome-remote-interface');

      (async () => {
        const client = await CDP({ port: 9229 });
        const { Debugger, Runtime } = client;

        Debugger.paused(async ({ callFrames, reason }) => {
          const top = callFrames[0];
          console.log(`PAUSED: ${reason} @ ${top.url}:${top.location.lineNumber + 1}`);

          // Walk scopes for locals
          for (const scope of top.scopeChain) {
            if (scope.type === 'local' || scope.type === 'closure') {
              const { result } = await Runtime.getProperties({
                objectId: scope.object.objectId,
                ownProperties: true,
              });
              for (const p of result) {
                console.log(`  ${scope.type}.${p.name} =`, p.value?.value ?? p.value?.description);
              }
            }
          }

          // Evaluate an expression in the paused frame
          const { result } = await Debugger.evaluateOnCallFrame({
            callFrameId: top.callFrameId,
            expression: 'typeof state !== "undefined" ? JSON.stringify(state) : "n/a"',
          });
          console.log('state =', result.value ?? result.description);

          await Debugger.resume();
        });

        await Runtime.enable();
        await Debugger.enable();

        // Set a breakpoint by URL regex + line
        await Debugger.setBreakpointByUrl({
          urlRegex: '.*app\\.tsx$',
          lineNumber: 119,       // 0-indexed
          columnNumber: 0,
        });

        await Runtime.runIfWaitingForDebugger();
      })();

      شغّله:

      node /tmp/cdp-debug.js

      ملاحظة خاصة بـ Hermes: chrome-remote-interface غير موجود في ui-tui/package.json. ثبّته في موقع مؤقت إذا كنت لا تريد تعديل المشروع:

      mkdir -p /tmp/cdp-tools && cd /tmp/cdp-tools && npm i chrome-remote-interface
      NODE_PATH=/tmp/cdp-tools/node_modules node /tmp/cdp-debug.js

      تصحيح أخطاء Hermes ui-tui​

      واجهة TUI مبنية بـ Ink و tsx. سيناريوهان شائعان:

      تصحيح مكوّن Ink واحد أثناء التطوير​

      يحتوي ui-tui/package.json على npm run dev (tsx --watch). أضف --inspect-brk بتشغيل tsx مباشرة:

      cd <hermes-agent-repo>/ui-tui
      npm run build    # produce dist/ once so transpile isn't needed on first load
      node --inspect-brk dist/entry.js
      # In another terminal:
      node inspect -p <node pid>

      ثم داخل debug>:

      sb('dist/app.js', 220)     # or wherever the suspect render is
      cont

      عند توقفه، استخدم repl ← افحص props، ومراجع الحالة، وقيم معالج useInput، وما إلى ذلك.

      تصحيح hermes --tui قيد التشغيل​

      تنشئ TUI عملية Node من واجهة سطر أوامر Python. أسهل طريقة:

      # 1. Launch TUI
      hermes --tui &
      TUI_PID=$(pgrep -f 'ui-tui/dist/entry' | head -1)

      # 2. Enable inspector on that Node PID
      kill -SIGUSR1 "$TUI_PID"

      # 3. Find the WS URL
      curl -s http://127.0.0.1:9229/json/list | jq -r '.[0].webSocketDebuggerUrl'

      # 4. Attach
      node inspect ws://127.0.0.1:9229/<uuid>

      يستمر التفاعل مع TUI (الكتابة في نافذتها) في تقديم التنفيذ؛ ويمكن لمصحّحك إيقافها عند أي نقطة توقف بـ sb(...).

      تصحيح العمليات الفرعية _SlashWorker / PTY​

      تلك عمليات Python، وليست Node — استخدم مهارة python-debugpy لها. تستخدم هذه المهارة فقط في أجزاء Node (واجهة Ink، عميل tui_gateway، اختبارات tsx-run تحت ui-tui/).

      تشغيل اختبارات Vitest تحت المصحّح​

      cd <hermes-agent-repo>/ui-tui
      # Run a single test file paused on entry
      node --inspect-brk ./node_modules/vitest/vitest.mjs run --no-file-parallelism src/app/foo.test.tsx

      في طرفية أخرى: node inspect -p <pid>، ثم sb('src/app/foo.tsx', 42)، ثم cont.

      استخدم --no-file-parallelism (في vitest) أو --runInBand (في jest) بحيث يوجد عامل (worker) واحد فقط — تصحيح تجمّع من العمّال (pool) أمر مؤلم.

      لقطات Heap وملفات تعريف CPU (دون تفاعل)​

      من سكربت CDP أعلاه، استبدل Debugger بـ HeapProfiler / Profiler:

      // CPU profile for 5 seconds
      await client.Profiler.enable();
      await client.Profiler.start();
      await new Promise(r => setTimeout(r, 5000));
      const { profile } = await client.Profiler.stop();
      require('fs').writeFileSync('/tmp/cpu.cpuprofile', JSON.stringify(profile));
      // Open /tmp/cpu.cpuprofile in Chrome DevTools → Performance tab
      // Heap snapshot
      await client.HeapProfiler.enable();
      const chunks = [];
      client.HeapProfiler.addHeapSnapshotChunk(({ chunk }) => chunks.push(chunk));
      await client.HeapProfiler.takeHeapSnapshot({ reportProgress: false });
      require('fs').writeFileSync('/tmp/heap.heapsnapshot', chunks.join(''));

      مزالق شائعة​

      1. أرقام أسطر خاطئة في مصدر TS. تصيب نقاط التوقف كود JS المُصدَر، لا ملف .ts. إما (أ) التوقف في dist/*.js المبني، أو (ب) تفعيل خرائط المصدر (sourcemaps) عبر (node --enable-source-maps) واستخدام sb('src/app.tsx', N) — لكن فقط مع عملاء CDP الذين يتّبعون خرائط المصدر. لا تفعل ذلك واجهة node inspect عبر CLI.

      2. --inspect مقابل --inspect-brk. يبدأ --inspect المفحّص لكن لا يوقفه؛ فيتجاوز سكربتك أول نقطة توقف إن اتصلت متأخرًا جدًا. استخدم --inspect-brk عندما تحتاج إلى تعيين نقاط التوقف قبل تشغيل أي كود.

      3. تعارض المنافذ (ports). الافتراضي هو 9229. إذا كانت عدة عمليات Node قيد الفحص، مرّر --inspect=0 (منفذ عشوائي) واقرأ الرابط الفعلي من /json/list:

        curl -s http://127.0.0.1:9229/json/list   # lists all inspectable targets on the host

      4. العمليات الفرعية. لا يفحص --inspect على عملية أب عملياتها الفرعية. استخدم NODE_OPTIONS='--inspect-brk' node parent.js لينتقل ذلك إلى كل عملية فرعية؛ وانتبه أنها جميعًا تحتاج منافذ فريدة (يزيد Node المنفذ تلقائيًا عند وراثة NODE_OPTIONS='--inspect').

      5. إنهاء في الخلفية. إذا ضغطت Ctrl+C للخروج من node inspect بينما الهدف متوقف، يبقى الهدف متوقفًا. إما نفّذ cont أولًا، أو أنهِ الهدف صراحةً بـ kill.

      6. تشغيل node inspect عبر طرفية وكيل. إنه REPL متوافق مع PTY. في Hermes، شغّله بـ terminal(pty=true) أو background=true مع process(action='submit', data='...'). يعمل نمط المقدمة غير PTY للأوامر المفردة لكن ليس للخطو التفاعلي.

      7. الأمان. يعرّض --inspect=0.0.0.0:9229 تنفيذ كود تعسفي. اربط دائمًا بـ 127.0.0.1 (الافتراضي) إلا إذا كانت لديك شبكة معزولة.

      قائمة التحقق​

      بعد إعداد جلسة تصحيح، تحقّق من:

      • يعيد curl -s http://127.0.0.1:9229/json/list الهدف الذي تتوقعه بالضبط
      • نقطة التوقف الأولى تُصاب فعليًا (إن لم تُصب، فمن المرجّح أنك فوّت --inspect-brk أو اتصلت بعد اكتمال التنفيذ)
      • عرض المصدر عند التوقف يُظهر الملف الصحيح (عدم التطابق = مشكلة في خرائط المصدر، انظر المزلق 1)
      • يعيد exec process.pid في repl رقم العملية (PID) الذي قصدت الاتصال به

      وصفات لمرة واحدة​

      «لماذا هذا المتغير غير معرّف (undefined) عند السطر X؟»

      node --inspect-brk script.js &
      node inspect -p $!
      # debug>
      sb('script.js', X)
      cont
      # paused. Now:
      repl
      > myVariable
      > Object.keys(this)

      «ما مسار الاستدعاء إلى هذه الدالة؟»

      debug> sb('suspectFn')
      debug> cont
      # paused on entry
      debug> bt

      «هذه السلسلة غير المتزامنة (async) عالقة — أين؟»

      # Start with --inspect (no -brk), let it run to the hang, then:
      debug> pause
      debug> bt
      # Now you see the stuck frame
