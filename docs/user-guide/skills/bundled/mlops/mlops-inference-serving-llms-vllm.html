      Serving LLMs (vLLM)

      vLLM: تقديم خدمة (serving) عالية الإنتاجية لنماذج اللغة الكبيرة، OpenAI API، التكميم (quantization).

      بيانات المهارة الوصفية​

      المصدرمضمّنة (مثبّتة افتراضيًا)
      المسارskills/mlops/inference/serving-llms-vllm
      الإصدار1.0.1
      المؤلفOrchestra Research
      الترخيصMIT
      الاعتمادياتvllm, torch, transformers
      المنصاتlinux, macos

      المرجع: ملف SKILL.md كاملًا​

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      vLLM - تقديم خدمة عالية الأداء لنماذج اللغة الكبيرة

      متى تُستخدم​

      استخدمها عند نشر واجهات LLM API في بيئة الإنتاج، أو تحسين زمن استجابة/إنتاجية الـ inference، أو تقديم خدمة نماذج بذاكرة GPU محدودة. تدعم نقاط نهاية متوافقة مع OpenAI، والتكميم (GPTQ/AWQ/FP8)، والتوازي الموتري (Tensor Parallelism).

      البدء السريع​

      تحقّق vLLM إنتاجية أعلى بـ 24 ضعفًا مقارنةً بمكتبة transformers القياسية بفضل PagedAttention (تخزين مؤقت KV قائم على الكتل) والدُفعات المستمرة (continuous batching) (مزج طلبات prefill/decode).

      التثبيت:

      pip install vllm

      Inference أساسي دون اتصال (offline):

      from vllm import LLM, SamplingParams

      llm = LLM(model="meta-llama/Meta-Llama-3-8B-Instruct")
      sampling = SamplingParams(temperature=0.7, max_tokens=256)

      outputs = llm.generate(["Explain quantum computing"], sampling)
      print(outputs[0].outputs[0].text)

      خادم متوافق مع OpenAI:

      vllm serve meta-llama/Meta-Llama-3-8B-Instruct

      # Query with OpenAI SDK
      python -c "
      from openai import OpenAI
      client = OpenAI(base_url='http://localhost:8000/v1', api_key='EMPTY')
      print(client.chat.completions.create(
          model='meta-llama/Meta-Llama-3-8B-Instruct',
          messages=[{'role': 'user', 'content': 'Hello!'}]
      ).choices[0].message.content)
      "

      سير العمل الشائعة​

      سير العمل 1: نشر API في بيئة الإنتاج​

      انسخ قائمة التحقق هذه وتتبّع التقدّم:

      Deployment Progress:
      - [ ] Step 1: Configure server settings
      - [ ] Step 2: Test with limited traffic
      - [ ] Step 3: Enable monitoring
      - [ ] Step 4: Deploy to production
      - [ ] Step 5: Verify performance metrics

      الخطوة 1: اضبط إعدادات الخادم

      اختر الإعدادات وفقًا لحجم نموذجك:

      # For 7B-13B models on single GPU
      vllm serve meta-llama/Meta-Llama-3-8B-Instruct \
        --gpu-memory-utilization 0.9 \
        --max-model-len 8192 \
        --port 8000

      # For 30B-70B models with tensor parallelism
      vllm serve meta-llama/Meta-Llama-3-70B-Instruct \
        --tensor-parallel-size 4 \
        --gpu-memory-utilization 0.9 \
        --quantization awq \
        --port 8000

      # For production with caching (Prometheus metrics are exposed
      # automatically at /metrics on the API port)
      vllm serve meta-llama/Meta-Llama-3-8B-Instruct \
        --gpu-memory-utilization 0.9 \
        --enable-prefix-caching \
        --port 8000 \
        --host 0.0.0.0

      الخطوة 2: اختبر بحركة مرور محدودة

      نفّذ اختبار حمل (load test) قبل الإنتاج:

      # Install load testing tool
      pip install locust

      # Create test_load.py with sample requests
      # Run: locust -f test_load.py --host http://localhost:8000

      تحقّق من أن TTFT (الزمن حتى أول token) أقل من 500ms والإنتاجية أعلى من 100 طلب/ثانية.

      الخطوة 3: فعِّل المراقبة

      يعرض vLLM مقاييس Prometheus على المسار /metrics عبر منفذ API (المنفذ الافتراضي 8000):

      curl http://localhost:8000/metrics | grep vllm

      المقاييس الأساسية التي يجب مراقبتها:

      • vllm:time_to_first_token_seconds - زمن الاستجابة (latency)
      • vllm:num_requests_running - الطلبات النشطة
      • vllm:gpu_cache_usage_perc - استخدام التخزين المؤقت KV

      الخطوة 4: انشر إلى بيئة الإنتاج

      استخدم Docker لنشر متسق:

      # Run vLLM in Docker
      docker run --gpus all -p 8000:8000 \
        vllm/vllm-openai:latest \
        --model meta-llama/Meta-Llama-3-8B-Instruct \
        --gpu-memory-utilization 0.9 \
        --enable-prefix-caching

      الخطوة 5: تحقّق من مقاييس الأداء

      تحقّق من أن النشر يفي بالأهداف:

      • TTFT أقل من 500ms (بالنسبة للـ prompts القصيرة)
      • الإنتاجية أعلى من الهدف المحدّد بالطلب/الثانية
      • استخدام GPU أعلى من 80%
      • لا توجد أخطاء OOM في السجلّات

      سير العمل 2: inference دفعي دون اتصال (offline)​

      لمعالجة مجموعات بيانات كبيرة دون عبء تشغيل خادم.

      انسخ قائمة التحقق هذه:

      Batch Processing:
      - [ ] Step 1: Prepare input data
      - [ ] Step 2: Configure LLM engine
      - [ ] Step 3: Run batch inference
      - [ ] Step 4: Process results

      الخطوة 1: جهّز بيانات الإدخال

      # Load prompts from file
      prompts = []
      with open("prompts.txt") as f:
          prompts = [line.strip() for line in f]

      print(f"Loaded {len(prompts)} prompts")

      الخطوة 2: اضبط محرّك LLM

      from vllm import LLM, SamplingParams

      llm = LLM(
          model="meta-llama/Meta-Llama-3-8B-Instruct",
          tensor_parallel_size=2,  # Use 2 GPUs
          gpu_memory_utilization=0.9,
          max_model_len=4096
      )

      sampling = SamplingParams(
          temperature=0.7,
          top_p=0.95,
          max_tokens=512,
          stop=["</s>", "\n\n"]
      )

      الخطوة 3: نفّذ الـ inference الدفعي

      يقوم vLLM تلقائيًا بتجميع الطلبات في دفعات لتحقيق الكفاءة:

      # Process all prompts in one call
      outputs = llm.generate(prompts, sampling)

      # vLLM handles batching internally
      # No need to manually chunk prompts

      الخطوة 4: عالج النتائج

      # Extract generated text
      results = []
      for output in outputs:
          prompt = output.prompt
          generated = output.outputs[0].text
          results.append({
              "prompt": prompt,
              "generated": generated,
              "tokens": len(output.outputs[0].token_ids)
          })

      # Save to file
      import json
      with open("results.jsonl", "w") as f:
          for result in results:
              f.write(json.dumps(result) + "\n")

      print(f"Processed {len(results)} prompts")

      سير العمل 3: تقديم خدمة نموذج مكمَّم (quantized)​

      لتشغيل نماذج كبيرة ضمن ذاكرة GPU محدودة.

      Quantization Setup:
      - [ ] Step 1: Choose quantization method
      - [ ] Step 2: Find or create quantized model
      - [ ] Step 3: Launch with quantization flag
      - [ ] Step 4: Verify accuracy

      الخطوة 1: اختر طريقة التكميم

      • AWQ: الأفضل لنماذج 70B، مع أدنى فقدان في الدقة
      • GPTQ: دعم واسع للنماذج، ضغط جيد
      • FP8: الأسرع على معالجات H100 الرسومية

      الخطوة 2: ابحث عن نموذج مكمَّم مسبقًا أو أنشئه

      استخدم نماذج مكمَّمة مسبقًا من HuggingFace:

      # Search for AWQ models
      # Example: TheBloke/Llama-2-70B-AWQ

      الخطوة 3: شغّل مع خيار التكميم

      # Using pre-quantized model
      vllm serve TheBloke/Llama-2-70B-AWQ \
        --quantization awq \
        --tensor-parallel-size 1 \
        --gpu-memory-utilization 0.95

      # Results: 70B model in ~40GB VRAM

      الخطوة 4: تحقّق من الدقة

      اختبر أن المخرجات تطابق الجودة المتوقّعة:

      # Compare quantized vs non-quantized responses
      # Verify task-specific performance unchanged

      متى تستخدمه مقابل البدائل​

      استخدم vLLM عندما:

      • تنشر واجهات LLM API في بيئة الإنتاج (أكثر من 100 طلب/ثانية)
      • تقدّم خدمة نقاط نهاية متوافقة مع OpenAI
      • تحتاج نماذج كبيرة مع ذاكرة GPU محدودة
      • تطبيقات متعددة المستخدمين (chatbots، مساعدون)
      • تحتاج زمن استجابة منخفض مع إنتاجية عالية

      استخدم البدائل بدلًا من ذلك:

      • llama.cpp: الـ inference على CPU/الأطراف (edge)، لمستخدم واحد
      • HuggingFace transformers: البحث، النمذجة الأولية، التوليد لمرة واحدة
      • TensorRT-LLM: خاص بـ NVIDIA فقط، عند الحاجة إلى أقصى أداء مطلق
      • Text-Generation-Inference: عندما تكون بالفعل ضمن منظومة HuggingFace

      المشاكل الشائعة​

      المشكلة: نفاد الذاكرة أثناء تحميل النموذج

      قلّل استخدام الذاكرة:

      vllm serve MODEL \
        --gpu-memory-utilization 0.7 \
        --max-model-len 4096

      أو استخدم التكميم:

      vllm serve MODEL --quantization awq

      المشكلة: بطء أول token (TTFT أكثر من ثانية واحدة)

      فعِّل التخزين المؤقت للبادئات (prefix caching) للـ prompts المتكرّرة:

      vllm serve MODEL --enable-prefix-caching

      بالنسبة للـ prompts الطويلة، فعِّل chunked prefill:

      vllm serve MODEL --enable-chunked-prefill

      المشكلة: خطأ النموذج غير موجود

      استخدم --trust-remote-code للنماذج المخصّصة:

      vllm serve MODEL --trust-remote-code

      المشكلة: إنتاجية منخفضة (أقل من 50 طلب/ثانية)

      زِد عدد التسلسلات المتزامنة:

      vllm serve MODEL --max-num-seqs 512

      تحقّق من استخدام GPU باستخدام nvidia-smi - يجب أن يكون أعلى من 80%.

      المشكلة: الـ inference أبطأ من المتوقّع

      تحقّق من أن التوازي الموتري (tensor parallelism) يستخدم عدد GPUs من مضاعفات القوة الثانية:

      vllm serve MODEL --tensor-parallel-size 4  # Not 3

      فعِّل فك الترميز التخميني (speculative decoding) لتوليد أسرع (مرّر الإعدادات بصيغة JSON؛ تمت إزالة --speculative-model لصالح --speculative-config):

      vllm serve MODEL \
        --speculative-config '{"model": "DRAFT_MODEL", "num_speculative_tokens": 5, "method": "draft_model"}'

      مواضيع متقدّمة​

      أنماط نشر الخادم: راجع references/server-deployment.md للاطلاع على إعدادات Docker وKubernetes وموازنة الحمل.

      تحسين الأداء: راجع references/optimization.md لضبط PagedAttention، وتفاصيل الدُفعات المستمرة، ونتائج القياس المرجعي.

      دليل التكميم: راجع references/quantization.md لإعداد AWQ/GPTQ/FP8، وتجهيز النماذج، ومقارنات الدقة.

      استكشاف الأخطاء وإصلاحها: راجع references/troubleshooting.md للاطلاع على رسائل الأخطاء التفصيلية، وخطوات تصحيح الأخطاء، وتشخيصات الأداء.

      متطلبات العتاد​

      • النماذج الصغيرة (7B-13B): بطاقة A10 واحدة (24GB) أو A100 (40GB)
      • النماذج المتوسطة (30B-40B): بطاقتا A100 (40GB) مع التوازي الموتري
      • النماذج الكبيرة (70B فأكثر): 4 بطاقات A100 (40GB) أو بطاقتا A100 (80GB)، استخدم AWQ/GPTQ

      المنصات المدعومة: NVIDIA (الأساسية)، AMD ROCm، معالجات Intel الرسومية، وحدات TPU
