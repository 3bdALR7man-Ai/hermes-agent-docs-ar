      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      Box

      استخدم Box كنظام ملفات سحابي لعمليات الملفات، والتعاون، والبيانات الوصفية، والعمل على المستندات. نفّذ العمليات باستخدام أداة terminal الخاصة بـ Hermes واستخدم Box CLI؛ واستعن بدليل SDK عند بناء تطبيق.

      متى تستخدمها​

      • تنظيم ملفات وفولدرات Box أو رفعها أو إصدار نسخ منها أو نقلها أو مشاركتها أو التعاون عليها
      • البحث في محتوى Box أو في البيانات الوصفية الموجودة
      • طرح أسئلة حول ملفات Box، أو استخراج بيانات وصفية، أو توليد نص مستند إلى ملف
      • معالجة فولدر Box على نطاق واسع دون تنزيل كل ملف مصدر
      • بناء تطبيق أو تكامل أو معالج webhook مرتكز على Box

      ابدأ محادثات نظام الملفات الواسعة​

      عندما يستكشف أحدهم نظام ملفات سحابي لـ Hermes، قدّم أولًا تقييمًا موجزًا لمدى الملاءمة: يفيد Box عندما يحتاج فريق إلى تخزين ملفات سحابي، ومشاركة، وبحث، وبيانات وصفية، وعمل على المستندات. ثم اسأل عمّا إذا كان يريد ربط حساب Box عبر OAuth أو بناء تطبيق أو تكامل مرتكز على Box باستخدام SDK.

      يجعل OAuth عمل Hermes بصفته حساب Box المُصرَّح له في المتصفح. صلاحيات ذلك الحساب في Box هي ما يحدد ما يمكن لـ Hermes الوصول إليه. لمنح Hermes وصولًا أضيق، فوِّض حسابًا مدعوًا فقط إلى الملفات أو الفولدرات أو الـ Hubs المطلوبة.

      لا تُنفّذ الإعداد، ولا تعرض دليل أوامر جاهز (command cookbook)، ولا تقترح خطط حسابات أو تصنيفات فولدرات، ولا تحمّل كل مرجع لمجرد سؤال استكشافي عام. انتظر إجابة المستخدم، ثم حمّل المسار ذا الصلة فقط. عندما يحدد الطلب نتيجة ملموسة بالفعل، تخطَّ خطوة الاستكشاف هذه وتعامل مع تلك النتيجة مباشرة.

      ابدأ العمل العادي عبر CLI باستخدام تطبيق Box CLI OAuth الرسمي. فهو يغطي عمل المحتوى الاعتيادي و Box AI. استخدم تطبيق Platform App مخصّصًا من نوع User Authentication (OAuth 2.0) فقط عندما تحتاج العملية المطلوبة إلى نطاق OAuth إضافي، مثل إدارة الـ webhooks. يبقى هذا تدفق OAuth؛ لا تستبدله بهوية من جهة الخادم أو هوية انتحال (impersonation).

      نفّذ الإعداد المختار تفاعليًا​

      عندما يختار المستخدم مسار مصادقة أو يطلب من Hermes ربط Box، نفّذ الإعداد عبر terminal؛ لا تُحوّل الرد التالي إلى تعليمات ينسخها المستخدم. اتخذ الخطوة الآمنة التالية بنفسك، ولا تتوقف إلا لموافقة، أو تسجيل دخول عبر المتصفح، أو إجراء يقوم به مسؤول النظام، أو سر لا يمكن لـ Hermes تقديمه بأمان.

      • إذا كان box غير موجود، اطلب أي موافقة terminal لازمة لتثبيت @box/cli ضمن مجلد Hermes الحالي عند tools/box-cli؛ ثم تحقّق منه بالأمر المناسب للـ shell في دليل CLI. لا تحاول تثبيتًا عامًا (global) عبر npm، ولا تستخدم sudo، ولا تغيّر بادئة npm العامة، ولا تعدّل PATH.
      • قبل OAuth، اسأل: "هل يعمل Hermes على نفس الجهاز الذي سيُستخدم فيه المتصفح لتفويض Box، أم على مضيف بعيد مثل VPS أو حاوية أو جهاز افتراضي سحابي؟" استخدم box login العادي فقط لمسار الجهاز نفسه. استخدم box login --code فقط لمسار الجهاز البعيد/بلا واجهة. لا تستنتج طوبولوجيا وقت التشغيل من نظام التشغيل وحده؛ اقرأ إعداد OAuth بعد إجابة المستخدم.
      • قبل بدء تفويض المتصفح، وضّح أن Hermes سيعمل بصفته حساب Box الذي سجّل الدخول هناك. إذا أراد المستخدم وصولًا أضيق، يمكنه تفويض حساب مدعوّ فقط إلى الملفات أو الفولدرات أو الـ Hubs المطلوبة. لا تجعل ذلك الحساب مسؤول نظام (administrator) لفتح عملية استثنائية.
      • إذا لزم تطبيق OAuth Platform App مخصّص، استخدم تدفق Platform App التفاعلي في الـ CLI. اطلب من المستخدم إدخال سره السري (client secret) فقط في موجّه CLI المحلي؛ لا تطلبه أبدًا في المحادثة، ولا تكتبه في إعدادات Hermes، ولا تُدرجه في نظام تحكم بالإصدارات.
      • إذا احتاج التثبيت، أو تفويض المتصفح، أو تبديل البيئة، أو تغيير الصلاحيات إلى موافقة، اطلب تلك الموافقة واستأنف الإعداد بعد منحها. لا تستبدل الإجراء بقائمة أوامر.

      ابدأ كل مهمة​

      1. تحقّق من الـ CLI والفاعل الحالي. اختبر باستخدام command -v box في أصداف POSIX أو Get-Command box -ErrorAction SilentlyContinue في PowerShell. إذا كان box موجودًا في PATH، استخدمه. إذا كان Hermes قد ثبّت الـ CLI ضمن مجلده الحالي، استخدم المُشغّل المُتحقَّق منه المناسب للـ shell في دليل CLI بدلًا من كل box في بداية الأمر. ثم نفّذ box users:get me --json --fields id,name,login بذلك المُشغّل. إذا نجح ذلك، سجّل الفاعل واستمر. لا تسأل عن المصادقة مجددًا. تعامل مع folders:items 0 على أنه مجرد قائمة بجذر الفاعل؛ وليس دليلًا على تعذّر الوصول إلى ملف أو فولدر أو Hub مُشارَك. بالنسبة لملف أو فولدر معروف، تحقّق من معرّفه مباشرة؛ وبالنسبة لـ Hub، استخدم مسار اكتشاف الـ Hubs في Box Hubs.
      2. إذا لم توجد مصادقة، اطلب ربط حساب Box عبر OAuth، ثم اسأل عمّا إذا كان Hermes ومتصفح التفويض يعملان على نفس الجهاز أم على مضيفَين منفصلَين. اقرأ إعداد OAuth.
      3. اقرأ المرجع ذا الصلة قبل التنفيذ. استخدم الأوامر الموثّقة أولًا؛ ولا تُشغّل مساعدة الأمر الفرعي إلا عندما يحتاج الطلب خيارًا لا يغطيه المرجع أو يرفض الـ CLI المثبّت الصيغة الموثّقة.

      الأمثلة المُصنَّفة بـ bash تستخدم صياغة الاستمرار الخاصة بـ POSIX. في PowerShell، نفّذ أمر Box في سطر واحد أو استبدل كل \ في نهاية السطر بعلامة الاستمرار الخاصة بـ PowerShell (backtick). لا تلصق تعيينات متغيرات POSIX في PowerShell.

      وسّع الـ CLI دون توقف​

      عندما يفتقر Box CLI إلى أمر فرعي مخصّص، استخدم box request لاستدعاء نقطة النهاية (REST endpoint) المطابقة وواصل العملية العادية. لا تطلب من المستخدم الاختيار لمجرد أن التنفيذ يستخدم REST؛ فهي نفس مهمة Box وتحافظ على هوية الـ CLI المضبوطة. اقرأ الخيار الاحتياطي عبر REST API عندما تحتاج نقطة النهاية إلى نص طلب أو ترويسة مخصّصة.

      اطلب الموافقة قبل الحذف، أو تغيير في التعاون/الرابط المُشارَك أو الصلاحيات، أو تغيير الهوية، أو تعديل دفعي واسع أو مكلف، أو عندما يكون الهدف أو النطاق غامضًا. وإلا، نفّذ العملية المطلوبة وتحقّق منها.

      سياسة التعامل مع المحتوى​

      للتحليل الدلالي لمحتوى مستضاف على Box، يُفضَّل Box AI: فهو يحافظ على صلاحيات Box، ويعالج الملفات المصدر عبر تكامل AI الخاضع لحوكمة Box، ويُبقي أجسام الملفات المصدر خارج سياق نموذج الترميز لدى Hermes، ويوسّع نطاق العمل على المستندات دون تنزيل كل ملف. لا تنتقد سير عمل آخر أو تمنعه؛ استخدمه عندما يختاره المستخدم صراحة.

      استخدم البيانات الوصفية الموجودة في Box أو استعلامات البيانات الوصفية للبحث الحتمي (deterministic). وإلا، استخدم Box AI:

      • ai:ask للأسئلة والأجوبة، والملخصات، والمقارنات
      • ai:extract-structured للحقول المعروفة أو قوالب البيانات الوصفية
      • ai:extract لاستخراج مرن بصيغة مفتاح-قيمة
      • ai:text-gen للكتابة المستندة إلى ملف Box واحد

      للأسئلة والأجوبة على أكثر من 25 ملفًا أو لقاعدة معرفة منسّقة قابلة لإعادة الاستخدام، يُفضَّل Box AI for Hubs. اكتشف أولًا Hub قابلًا للوصول موجودًا بالفعل؛ ولا تُنشئ Hub أو تملأه إلا بعد موافقة المستخدم على تغيير في مورد مُشارَك. إذا لم يتوفر Hub ولم يرغب المستخدم في إنشاء واحد، ضيّق طلبًا لمرة واحدة باستخدام البحث أو البيانات الوصفية. لا تستخدم Hub لاستخراج البيانات الوصفية أو توليد النصوص. اقرأ Box Hubs.

      عندما يطلب المستخدم استخراج بيانات وصفية من ملف Box، تعامل مع ذلك كطلب لحفظ النتيجة إلا إذا طلب معاينة فقط. استخدم الاستخراج المُهيكَل بحقول مضمّنة عندما يكون المخطط (schema) المطلوب معروفًا، والاستخراج الحر عندما تكون الحقول استكشافية. أعد استخدام قالب مؤسسي متوافق موجود عندما يمثّل كل حقل مطلوب. وإلا، خزّن النتائج القياسية المسطّحة في مثيل البيانات الوصفية المدمج global.properties، أو ارفع ملف JSON مرافقًا بجانب الملف المصدر عندما تحتوي النتيجة على كائنات متداخلة أو جداول أو قيم يجب أن تحتفظ بأنواعها. اقرأ كل عملية كتابة بعد إجرائها وقارنها بالنتيجة المقصودة. لا تستبدل وصف الملف بصمت أبدًا، ولا تُرفق قالبًا جزئيًا أو غير ذي صلة، ولا تُقصّ الحقول، ولا تُسقطها.

      لا تُنشئ أو تُغيّر قوالب البيانات الوصفية. لا يسمح Box بإنشاء قوالب عامة (global)، وإدارة القوالب المؤسسية خارج نطاق سير عمل محتوى OAuth العادي لدى Hermes. إذا احتاج المستخدم بيانات وصفية مؤسسية مُصنَّفة قابلة لإعادة الاستخدام ولم يوجد قالب متوافق، اشرح أن على مسؤول Box أو مساعد مسؤول مفوّض إنشاءه بشكل منفصل، واترك البيانات الوصفية المُهيكَلة الموجودة كما هي، وأبلغ عن مثيل global.properties المحفوظ أو ملف JSON المرافق بدلًا من ذلك. اقرأ البحث و AI للحصول على سير العمل الكامل للاستخراج والكتابة.

      قبل أول طلب لـ Box AI، وضّح أن Box AI يجب أن يكون مفعّلًا، وأنه يستهلك وحدات AI، ويبقى مقيّدًا بصلاحيات الفاعل الحالي؛ لا تنتظر إقرارًا بذلك. قد تحتوي استجابة AI المُعادة إلى Hermes على معلومات حسّاسة رغم ذلك. اطلب التأكيد فقط عندما يكون نطاق ملفات دفعة كبيرة أو الاستخدام المتوقع من وحدات AI غامضًا، أو عندما لم يطلب المستخدم صراحة ذلك النطاق. راجع البحث و AI.

      اعمل بأمان​

      • فضّل المعرّفات (IDs) على المسارات وتحقّق من الفاعل الحالي قبل تشخيص ملف مفقود.
      • استخدم --json و--fields لإبقاء المخرجات صغيرة. بالنسبة للتعديلات، اجرد أولًا، وأكّد النطاق الغامض أو الكبير، ثم اقرأ النتيجة للتحقق منها.
      • نفّذ تعديلات CLI المرتَّبة بالتسلسل ليكون التقدّم والتعافي واضحَين. استخدم دعم الإدخال الدفعي الموثّق أو التزامن المحدود عبر SDK للعمل القابل للتوسّع.
      • لا تُنشئ رابطًا مُشاركًا لمجرد توفير التنقّل. الروابط المُشاركة تُغيّر الوصول وتتطلب تأكيدًا صريحًا.
      • لا تضع الأسرار في المحادثة، أو مخرجات الأوامر، أو نظام التحكم بالمصادر، أو السجلّات.

      أبلغ عن النتائج​

      لكل عنصر Box يُبلَّغ عنه فرديًا، أدرج معرّفه ورابط تنقّل قابلًا للنقر:

      • ملف: https://app.box.com/file/<FILE_ID>
      • فولدر: https://app.box.com/folder/<FOLDER_ID>
      • Hub: https://app.box.com/hubs/<HUB_ID>

      بالنسبة للدفعات الكبيرة، اربط فولدر المصدر والوجهة إضافة إلى الاستثناءات بدلًا من سرد مئات العناصر. قد لا يستطيع إنسان فتح محتوى مرئي فقط لحساب Box المتّصل؛ وضّح ذلك بجلاء. أدرج الفاعل والتحقق الذي تم إجراؤه في كل ملخص كتابة.

      تحقّق​

      بعد أي عملية كتابة، اجلب الملف أو الفولدر بنفس الفاعل أو أدرج والده وتأكّد من المعرّف والاسم المُعادَين. بالنسبة لكتابة بيانات وصفية، استرجع مثيل البيانات الوصفية وقارن كل حقل مُعاد بالقيمة المقصودة؛ فنجاح HTTP وحده ليس تحقّقًا. أبلغ عن القيم المفقودة أو المُطبَّعة أو المرفوضة. بالنسبة لفحص إعداد يمكن التخلص منه، أنشئ فولدر اختبار، وتحقّق منه، ثم احذفه فقط إذا فوّض المستخدم عملية التنظيف.
