      Airtable

      واجهة Airtable REST API عبر curl. عمليات CRUD على السجلات، والفلاتر، وعمليات upsert.

      بيانات المهارة الوصفية​

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      Airtable — القواعد والجداول والسجلات

      تعامل مع واجهة Airtable REST API مباشرةً عبر curl باستخدام أداة terminal. بلا خادم MCP، وبلا تدفق OAuth، وبلا SDK بلغة Python — فقط curl ورمز وصول شخصي.

      المتطلبات المسبقة​

      1. أنشئ رمز وصول شخصي (Personal Access Token - PAT) من https://airtable.com/create/tokens (تبدأ الرموز بـ pat...).
      2. امنح هذه الصلاحيات (كحد أدنى):
        • data.records:read — قراءة الصفوف
        • data.records:write — إنشاء / تحديث / حذف الصفوف
        • schema.bases:read — سرد القواعد والجداول
      3. مهم: في واجهة الرمز نفسها، أضِف كل قاعدة تريد الوصول إليها إلى قائمة Access الخاصة بالرمز. رموز PAT مخصصة النطاق لكل قاعدة على حدة — إذ يُعيد رمز صالح على قاعدة غير مصرّح بها الخطأ 403.
      4. خزّن الرمز في ${HERMES_HOME:-~/.hermes}/.env (أو عبر hermes setup): 
        AIRTABLE_API_KEY=pat_your_token_here

      ملاحظة: أصبحت مفاتيح API القديمة من نوع key... مهملة منذ فبراير 2024. لا يعمل الآن سوى رموز PAT ورموز OAuth.

      أساسيات API​

      • Endpoint: https://api.airtable.com/v0
      • ترويسة المصادقة: Authorization: Bearer $AIRTABLE_API_KEY
      • كل الطلبات تستخدم JSON (Content-Type: application/json لأي جسم طلب من نوع POST أو PATCH أو PUT).
      • مُعرّفات الكائنات: القواعد app...، والجداول tbl...، والسجلات rec...، والحقول fld.... لا تتغيّر المُعرّفات أبدًا، بخلاف الأسماء التي قد تتغيّر. فضّل استخدام المُعرّفات في الأتمتة.
      • حدّ المعدل: 5 طلبات/ثانية لكل قاعدة. عند ظهور 429 ← خفّف معدل الطلبات. سيُقيَّد أي دفق طلبات مكثّف على قاعدة واحدة.

      نمط curl الأساسي:

      curl -s "https://api.airtable.com/v0/$BASE_ID/$TABLE?maxRecords=5" \
        -H "Authorization: Bearer $AIRTABLE_API_KEY" | python -m json.tool

      يُخفي -s شريط تقدّم curl — أبقِه مفعّلًا في كل استدعاء ليبقى ناتج الأداة نظيفًا بالنسبة لـ Hermes. مرّر الناتج عبر python -m json.tool (متوفرة دائمًا) أو jq (إن كانت مثبّتة) لعرض JSON بشكل مقروء.

      أنواع الحقول (أشكال جسم الطلب)​

      نوع الحقلشكل الكتابة
      نص سطر واحد"Name": "hello"
      نص طويل"Notes": "multi\nline"
      رقم"Score": 42
      مربع اختيار"Done": true
      اختيار مفرد"Status": "Todo" (يجب أن يكون الاسم موجودًا مسبقًا ما لم تستخدم typecast: true)
      اختيار متعدد"Tags": ["urgent", "bug"]
      تاريخ"Due": "2026-04-01"
      تاريخ ووقت (UTC)"At": "2026-04-01T14:30:00.000Z"
      رابط / بريد إلكتروني / هاتف"Link": "https://…"
      مرفق"Files": [{"url": "https://…"}] (يجلبه Airtable ويستضيفه من جديد)
      سجل مرتبط"Owner": ["recXXXXXXXXXXXXXX"] (مصفوفة من مُعرّفات السجلات)
      مستخدم"AssignedTo": {"id": "usrXXXXXXXXXXXXXX"}

      مرّر "typecast": true في المستوى الأعلى من جسم طلب الإنشاء/التحديث للسماح لـ Airtable بتحويل القيم تلقائيًا (مثل إنشاء خيار اختيار جديد أثناء العملية، أو تحويل "42" إلى 42).

      استعلامات شائعة​

      سرد القواعد التي يمكن للرمز رؤيتها​

      curl -s "https://api.airtable.com/v0/meta/bases" \
        -H "Authorization: Bearer $AIRTABLE_API_KEY" | python -m json.tool

      سرد جداول قاعدة ما وبنيتها​

      curl -s "https://api.airtable.com/v0/meta/bases/$BASE_ID/tables" \
        -H "Authorization: Bearer $AIRTABLE_API_KEY" | python -m json.tool

      استخدم هذا قبل التعديل — فهو يؤكد أسماء الحقول ومُعرّفاتها بدقة، ويُظهر options.choices لحقول الاختيار، وأسماء الحقول الأساسية.

      سرد السجلات (أول 10)​

      curl -s "https://api.airtable.com/v0/$BASE_ID/$TABLE?maxRecords=10" \
        -H "Authorization: Bearer $AIRTABLE_API_KEY" | python -m json.tool

      جلب سجل واحد​

      curl -s "https://api.airtable.com/v0/$BASE_ID/$TABLE/$RECORD_ID" \
        -H "Authorization: Bearer $AIRTABLE_API_KEY" | python -m json.tool

      تصفية السجلات (filterByFormula)​

      يجب ترميز صيغ Airtable بصيغة URL. اترك مكتبة Python القياسية تتولى ذلك — لا ترمّزها يدويًا أبدًا:

      FORMULA="{Status}='Todo'"
      ENC=$(python -c 'import sys, urllib.parse; print(urllib.parse.quote(sys.argv[1], safe=""))' "$FORMULA")
      curl -s "https://api.airtable.com/v0/$BASE_ID/$TABLE?filterByFormula=$ENC&maxRecords=20" \
        -H "Authorization: Bearer $AIRTABLE_API_KEY" | python -m json.tool

      أنماط صيغ مفيدة:

      • تطابق تام: {Email}='user@example.com'
      • يحتوي على: FIND('bug', LOWER({Title}))
      • شروط متعددة: AND({Status}='Todo', {Priority}='High')
      • أو: OR({Owner}='alice', {Owner}='bob')
      • غير فارغ: NOT({Assignee}='')
      • مقارنة تاريخ: IS_AFTER({Due}, TODAY())

      الترتيب + اختيار حقول محددة​

      curl -s "https://api.airtable.com/v0/$BASE_ID/$TABLE?sort%5B0%5D%5Bfield%5D=Priority&sort%5B0%5D%5Bdirection%5D=asc&fields%5B%5D=Name&fields%5B%5D=Status" \
        -H "Authorization: Bearer $AIRTABLE_API_KEY" | python -m json.tool

      يجب ترميز الأقواس المربعة في معاملات الاستعلام بصيغة URL (%5B / %5D).

      استخدام عرض (view) مُسمّى​

      curl -s "https://api.airtable.com/v0/$BASE_ID/$TABLE?view=Grid%20view&maxRecords=50" \
        -H "Authorization: Bearer $AIRTABLE_API_KEY" | python -m json.tool

      تطبّق العروض فلترها وترتيبها المحفوظين من جانب الخادم.

      عمليات التعديل الشائعة​

      إنشاء سجل​

      curl -s -X POST "https://api.airtable.com/v0/$BASE_ID/$TABLE" \
        -H "Authorization: Bearer $AIRTABLE_API_KEY" \
        -H "Content-Type: application/json" \
        -d '{"fields":{"Name":"New task","Status":"Todo","Priority":"High"}}' | python -m json.tool

      إنشاء ما يصل إلى 10 سجلات في استدعاء واحد​

      curl -s -X POST "https://api.airtable.com/v0/$BASE_ID/$TABLE" \
        -H "Authorization: Bearer $AIRTABLE_API_KEY" \
        -H "Content-Type: application/json" \
        -d '{
          "typecast": true,
          "records": [
            {"fields": {"Name": "Task A", "Status": "Todo"}},
            {"fields": {"Name": "Task B", "Status": "In progress"}}
          ]
        }' | python -m json.tool

      تُحدَّد endpoints الدُفعية بحد أقصى 10 سجلات لكل طلب. للإدراجات الأكبر، كرّر العملية على دفعات من 10 مع فاصل زمني قصير لاحترام حدّ 5 طلبات/ثانية لكل قاعدة.

      تحديث سجل (PATCH — يدمج ويحافظ على الحقول غير المتغيّرة)​

      curl -s -X PATCH "https://api.airtable.com/v0/$BASE_ID/$TABLE/$RECORD_ID" \
        -H "Authorization: Bearer $AIRTABLE_API_KEY" \
        -H "Content-Type: application/json" \
        -d '{"fields":{"Status":"Done"}}' | python -m json.tool

      عملية upsert باستخدام حقل دمج (بلا حاجة إلى مُعرّف)​

      curl -s -X PATCH "https://api.airtable.com/v0/$BASE_ID/$TABLE" \
        -H "Authorization: Bearer $AIRTABLE_API_KEY" \
        -H "Content-Type: application/json" \
        -d '{
          "performUpsert": {"fieldsToMergeOn": ["Email"]},
          "records": [
            {"fields": {"Email": "user@example.com", "Status": "Active"}}
          ]
        }' | python -m json.tool

      تُنشئ performUpsert سجلات عندما تكون قيم حقل الدمج جديدة، وتُحدّث السجلات التي توجد قيم حقل الدمج الخاصة بها بالفعل. مفيدة جدًا لعمليات المزامنة المتكررة الآمنة (idempotent).

      حذف سجل​

      curl -s -X DELETE "https://api.airtable.com/v0/$BASE_ID/$TABLE/$RECORD_ID" \
        -H "Authorization: Bearer $AIRTABLE_API_KEY" | python -m json.tool

      حذف ما يصل إلى 10 سجلات في استدعاء واحد​

      curl -s -X DELETE "https://api.airtable.com/v0/$BASE_ID/$TABLE?records%5B%5D=rec1&records%5B%5D=rec2" \
        -H "Authorization: Bearer $AIRTABLE_API_KEY" | python -m json.tool

      التصفح المُقسّم (Pagination)​

      تُعيد endpoints السرد 100 سجل كحد أقصى لكل صفحة. إذا تضمّنت الاستجابة "offset": "..."، فمرّرها في الاستدعاء التالي. كرّر العملية حتى يغيب هذا الحقل:

      OFFSET=""
      while :; do
        URL="https://api.airtable.com/v0/$BASE_ID/$TABLE?pageSize=100"
        [ -n "$OFFSET" ] && URL="$URL&offset=$OFFSET"
        RESP=$(curl -s "$URL" -H "Authorization: Bearer $AIRTABLE_API_KEY")
        echo "$RESP" | python -c 'import json,sys; d=json.load(sys.stdin); [print(r["id"], r["fields"].get("Name","")) for r in d["records"]]'
        OFFSET=$(echo "$RESP" | python -c 'import json,sys; d=json.load(sys.stdin); print(d.get("offset",""))')
        [ -z "$OFFSET" ] && break
      done

      سير عمل نموذجي لـ Hermes​

      1. تأكّد من المصادقة. curl -s -o /dev/null -w "%{http_code}\n" https://api.airtable.com/v0/meta/bases -H "Authorization: Bearer $AIRTABLE_API_KEY" — يُتوقع الحصول على 200.
      2. حدّد القاعدة. اسرد القواعد (الخطوة أعلاه) أو اطلب من المستخدم مُعرّف app... مباشرةً إن كان الرمز لا يملك صلاحية schema.bases:read.
      3. افحص البنية (schema). GET /v0/meta/bases/$BASE_ID/tables — خزّن أسماء الحقول الدقيقة واسم الحقل الأساسي محليًا في الجلسة قبل إجراء أي تعديل.
      4. اقرأ قبل أن تكتب. بالنسبة لعبارة "حدّث X حيث Y"، استخدم filterByFormula أولًا لتحديد مُعرّف rec...، ثم نفّذ PATCH /v0/$BASE_ID/$TABLE/$RECORD_ID. لا تخمّن مُعرّفات السجلات أبدًا.
      5. اجمع الكتابات في دفعات. ادمج عمليات الإنشاء المترابطة في طلب POST واحد بحد أقصى 10 سجلات للبقاء ضمن حدّ 5 طلبات/ثانية.
      6. العمليات الإتلافية. لا يمكن التراجع عن الحذف عبر API. إذا طلب المستخدم "احذف كل عناصر X"، فاعرض عليه الفلتر وعدد السجلات وانتظر تأكيده قبل التنفيذ.

      مزالق شائعة​

      • يجب ترميز filterByFormula بصيغة URL. كذلك أسماء الحقول التي تحتوي مسافات أو أحرفًا غير ASCII تحتاج إلى ترميز ({My Field} ← %7BMy%20Field%7D). استخدم مكتبة Python القياسية (النمط أعلاه) — لا ترمّزها يدويًا أبدًا.
      • تُحذَف الحقول الفارغة من الاستجابات. غياب مفتاح "Assignee" لا يعني أن الحقل غير موجود — بل يعني أن قيمته في هذا السجل فارغة. تحقّق من البنية (الخطوة 3) قبل استنتاج أن حقلًا مفقود.
      • الفرق بين PATCH و PUT. يدمج PATCH الحقول المُرسَلة في السجل. أمّا PUT فيستبدل السجل بالكامل ويمسح أي حقل لم تُدرجه. اجعل PATCH هو الخيار الافتراضي.
      • يجب أن تكون خيارات الاختيار المفرد موجودة مسبقًا. كتابة "Status": "Shipping" عندما لا يكون Shipping ضمن قائمة خيارات الحقل يُصدر الخطأ INVALID_MULTIPLE_CHOICE_OPTIONS ما لم تمرّر "typecast": true (التي تُنشئ الخيار تلقائيًا).
      • نطاق الرمز مخصص لكل قاعدة. ظهور 403 على قاعدة بينما تعمل قاعدة أخرى بلا مشكلة يعني أن قائمة Access الخاصة بالرمز لا تشمل تلك القاعدة — وليس مشكلة في الصلاحيات أو المصادقة. وجّه المستخدم إلى https://airtable.com/create/tokens لمنح الوصول.
      • حدود المعدل مرتبطة بكل قاعدة، لا بكل رمز. 5 طلبات/ثانية على baseA و5 طلبات/ثانية على baseB أمر مقبول؛ أمّا 6 طلبات/ثانية على baseA وحدها فسيتم تقييدها. راقب ترويسة Retry-After عند ظهور 429.

      ملاحظات مهمة لـ Hermes​

      • استخدم دائمًا أداة terminal مع curl. لا تستخدم web_extract (لأنها لا تستطيع إرسال ترويسات المصادقة) ولا browser_navigate (تحتاج إلى مصادقة عبر الواجهة وبطيئة).
      • يتدفق AIRTABLE_API_KEY تلقائيًا من ${HERMES_HOME:-~/.hermes}/.env إلى العملية الفرعية عند تحميل هذه المهارة — بلا حاجة لإعادة تصديره قبل كل استدعاء curl.
      • احرص على معالجة الأقواس المعقوفة في الصيغ بعناية. في جسم heredoc، تكون {Status} نصًا حرفيًا. وفي وسيط shell، تكون {Status} آمنة خارج سياق توسيع الأقواس {...} (brace-expansion) — لكن مرّر السلاسل الديناميكية عبر python urllib.parse.quote قبل دمجها في رابط.
      • اطبع الناتج بشكل مقروء باستخدام python -m json.tool (متوفرة دائمًا) بدلًا من jq (اختيارية). الجأ إلى jq فقط عند الحاجة إلى فلترة أو إسقاط حقول.
      • التصفح المُقسّم لكل صفحة، لا على مستوى شامل. حدّ Airtable البالغ 100 سجل هو حدّ صارم لا يمكن رفعه. كرّر العملية باستخدام offset حتى يغيب هذا الحقل.
      • اقرأ مصفوفة errors في الاستجابات غير الناجحة (non-2xx) — يُعيد Airtable رموز أخطاء منظّمة مثل AUTHENTICATION_REQUIRED و INVALID_PERMISSIONS و MODEL_ID_NOT_FOUND و INVALID_MULTIPLE_CHOICE_OPTIONS تُخبرك بدقة بمصدر المشكلة.
