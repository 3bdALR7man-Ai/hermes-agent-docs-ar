      OpenCode

      تفويض مهام البرمجة إلى OpenCode CLI (الميزات، ومراجعة PR).

      بيانات المهارة الوصفية​

      المصدرمضمّنة (مثبّتة افتراضيًا)
      المسارskills/autonomous-ai-agents/opencode
      الإصدار1.2.0
      المؤلفHermes Agent
      الترخيصMIT
      المنصاتlinux, macos, windows
      الوسومCoding-Agent, OpenCode, Autonomous, Refactoring, Code-Review
      مهارات ذات صلةclaude-code, codex, hermes-agent

      المرجع: ملف SKILL.md كاملًا​

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      OpenCode CLI

      استخدم OpenCode كعامل برمجة مستقل تُنسّقه أدوات الطرفية/العمليات في Hermes. OpenCode هو وكيل برمجة مفتوح المصدر ومستقل عن المزوّد، بواجهة TUI وCLI.

      متى تُستخدم​

      • عندما يطلب المستخدم صراحةً استخدام OpenCode
      • عندما تريد وكيل برمجة خارجيًا لتنفيذ/إعادة هيكلة/مراجعة الكود
      • عندما تحتاج إلى جلسات برمجة طويلة الأمد مع تحقّقات دورية من التقدّم
      • عندما تريد تنفيذ مهام متوازية في مجلدات عمل/worktrees معزولة

      المتطلبات المسبقة​

      • OpenCode مُثبَّت: npm i -g opencode-ai@latest أو brew install anomalyco/tap/opencode
      • المصادقة مُهيَّأة: opencode auth login أو ضبط متغيرات بيئة المزوّد (OPENROUTER_API_KEY، إلخ)
      • التحقّق: يجب أن يعرض opencode auth list مزوّدًا واحدًا على الأقل
      • مستودع git لمهام الكود (يُنصح به)
      • pty=true لجلسات TUI التفاعلية

      تحديد الملف الثنائي (مهم)​

      قد تحلّ بيئات shell ملفات OpenCode الثنائية بشكل مختلف. إذا اختلف السلوك بين طرفيتك وHermes، تحقّق من:

      terminal(command="which -a opencode")
      terminal(command="opencode --version")

      عند الحاجة، ثبّت مسارًا صريحًا للملف الثنائي:

      terminal(command="$HOME/.opencode/bin/opencode run '...'", workdir="~/project", pty=true)

      المهام الفورية (One-Shot)​

      استخدم opencode run للمهام المحدودة وغير التفاعلية:

      terminal(command="opencode run 'Add retry logic to API calls and update tests'", workdir="~/project")

      أرفِق ملفات السياق باستخدام -f:

      terminal(command="opencode run 'Review this config for security issues' -f config.yaml -f .env.example", workdir="~/project")

      أظهِر تفكير النموذج باستخدام --thinking:

      terminal(command="opencode run 'Debug why tests fail in CI' --thinking", workdir="~/project")

      فرض نموذج مُحدَّد:

      terminal(command="opencode run 'Refactor auth module' --model openrouter/anthropic/claude-sonnet-4", workdir="~/project")

      الجلسات التفاعلية (في الخلفية)​

      للعمل التكراري الذي يتطلّب عدة تبادلات، شغّل TUI في الخلفية:

      terminal(command="opencode", workdir="~/project", background=true, pty=true)
      # Returns session_id

      # Send a prompt
      process(action="submit", session_id="<id>", data="Implement OAuth refresh flow and add tests")

      # Monitor progress
      process(action="poll", session_id="<id>")
      process(action="log", session_id="<id>")

      # Send follow-up input
      process(action="submit", session_id="<id>", data="Now add error handling for token expiry")

      # Exit cleanly — Ctrl+C
      process(action="write", session_id="<id>", data="\x03")
      # Or just kill the process
      process(action="kill", session_id="<id>")

      مهم: لا تستخدم /exit — إنه ليس أمرًا صالحًا في OpenCode وسيفتح بدلًا من ذلك مربع حوار لاختيار وكيل. استخدم Ctrl+C (\x03) أو process(action="kill") للخروج.

      اختصارات لوحة مفاتيح TUI​

      المفتاحالإجراء
      Enterإرسال الرسالة (اضغط مرتين إن لزم الأمر)
      Tabالتبديل بين الوكلاء (build/plan)
      Ctrl+Pفتح لوحة الأوامر
      Ctrl+X Lتبديل الجلسة
      Ctrl+X Mتبديل النموذج
      Ctrl+X Nجلسة جديدة
      Ctrl+X Eفتح المحرر
      Ctrl+Cالخروج من OpenCode

      استئناف الجلسات​

      بعد الخروج، يطبع OpenCode معرّف جلسة. استأنفها بـ:

      terminal(command="opencode -c", workdir="~/project", background=true, pty=true)  # Continue last session
      terminal(command="opencode -s ses_abc123", workdir="~/project", background=true, pty=true)  # Specific session

      الخيارات الشائعة​

      الخيارالاستخدام
      run 'prompt'تنفيذ فوري ثم الخروج
      --continue / -cمتابعة آخر جلسة OpenCode
      --session <id> / -sمتابعة جلسة مُحدَّدة
      --agent <name>اختيار وكيل OpenCode (build أو plan)
      --model provider/modelفرض نموذج مُحدَّد
      --format jsonمخرجات/أحداث قابلة للقراءة الآلية
      --file <path> / -fإرفاق ملف/ملفات بالرسالة
      --thinkingإظهار كتل تفكير النموذج
      --variant <level>جهد الاستدلال (high، max، minimal)
      --title <name>تسمية الجلسة
      --attach <url>الاتصال بخادم opencode قيد التشغيل

      الإجراء​

      1. تحقّق من جاهزية الأداة:
        • terminal(command="opencode --version")
        • terminal(command="opencode auth list")
      2. للمهام المحدودة، استخدم opencode run '...' (لا حاجة إلى pty).
      3. للمهام التكرارية، شغّل opencode بـ background=true, pty=true.
      4. راقب المهام الطويلة باستخدام process(action="poll"|"log").
      5. إذا طلب OpenCode إدخالًا، جاوِب عبر process(action="submit", ...).
      6. اخرج باستخدام process(action="write", data="\x03") أو process(action="kill").
      7. لخّص للمستخدم تغييرات الملفات، ونتائج الاختبارات، والخطوات التالية.

      سير عمل مراجعة PR​

      يملك OpenCode أمر PR مُدمَجًا:

      terminal(command="opencode pr 42", workdir="~/project", pty=true)

      أو راجع في نسخة مستنسخة مؤقتة لعزل العملية:

      terminal(command="REVIEW=$(mktemp -d) && git clone https://github.com/user/repo.git $REVIEW && cd $REVIEW && opencode run 'Review this PR vs main. Report bugs, security risks, test gaps, and style issues.' -f $(git diff origin/main --name-only | head -20 | tr '\n' ' ')", pty=true)

      نمط العمل المتوازي​

      استخدم مجلدات عمل/worktrees منفصلة لتجنّب التعارضات:

      terminal(command="opencode run 'Fix issue #101 and commit'", workdir="/tmp/issue-101", background=true, pty=true)
      terminal(command="opencode run 'Add parser regression tests and commit'", workdir="/tmp/issue-102", background=true, pty=true)
      process(action="list")

      إدارة الجلسات والتكلفة​

      عرض الجلسات السابقة:

      terminal(command="opencode session list")

      تحقّق من استخدام tokens والتكاليف:

      terminal(command="opencode stats")
      terminal(command="opencode stats --days 7 --models anthropic/claude-sonnet-4")

      المزالق​

      • جلسات opencode التفاعلية (TUI) تتطلّب pty=true. أمر opencode run لا يحتاج إلى pty.
      • /exit ليس أمرًا صالحًا — بل يفتح أداة اختيار وكيل. استخدم Ctrl+C للخروج من TUI.
      • عدم تطابق PATH قد يختار ملف OpenCode الثنائي/إعداد النموذج الخاطئ.
      • إذا بدا أن OpenCode عالق، افحص السجلّات قبل إنهاء العملية:
        • process(action="log", session_id="<id>")
      • تجنّب مشاركة مجلد عمل واحد بين جلسات OpenCode المتوازية.
      • قد يحتاج مفتاح Enter إلى ضغطه مرتين للإرسال في TUI (مرة لإنهاء النص، ومرة للإرسال).

      التحقّق​

      اختبار سريع (Smoke Test):

      terminal(command="opencode run 'Respond with exactly: OPENCODE_SMOKE_OK'")

      معايير النجاح:

      • تتضمّن المخرجات OPENCODE_SMOKE_OK
      • يخرج الأمر بلا أخطاء مزوّد/نموذج
      • لمهام الكود: تغيّرت الملفات المتوقّعة ونجحت الاختبارات

      القواعد​

      1. فضّل opencode run للأتمتة الفورية — فهي أبسط ولا تحتاج إلى pty.
      2. استخدم وضع الخلفية التفاعلي فقط عند الحاجة إلى التكرار.
      3. احصر دائمًا جلسات OpenCode في مستودع/مجلد عمل واحد.
      4. للمهام الطويلة، قدّم تحديثات تقدّم من سجلّات process.
      5. أبلغ بنتائج ملموسة (الملفات المتغيّرة، والاختبارات، والمخاطر المتبقية).
      6. اخرج من الجلسات التفاعلية باستخدام Ctrl+C أو kill، ولا تستخدم /exit أبدًا.
