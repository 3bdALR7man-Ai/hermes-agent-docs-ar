      Claude Code

      فوّض مهام البرمجة إلى Claude Code CLI (ميزات، pull requests).

      بيانات المهارة الوصفية​

      المصدرمضمّنة (مثبّتة افتراضيًا)
      المسارskills/autonomous-ai-agents/claude-code
      الإصدار2.2.1
      المؤلفHermes Agent + Teknium
      الترخيصMIT
      المنصاتlinux, macos, windows
      الوسومCoding-Agent, Claude, Anthropic, Code-Review, Refactoring, PTY, Automation
      مهارات ذات صلةcodex, hermes-agent, opencode

      معلومة

      ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

      Claude Code — دليل توجيه Hermes

      فوّض مهام البرمجة إلى Claude Code (وكيل البرمجة الذاتي التابع لـ Anthropic بصيغة CLI) عبر طرفية Hermes. يستطيع Claude Code v2.x قراءة الملفات وكتابة الكود وتشغيل أوامر shell وإطلاق subagents وإدارة سير عمل git بشكل ذاتي.

      المتطلبات الأساسية​

      • التثبيت: npm install -g @anthropic-ai/claude-code
      • المصادقة: نفّذ claude مرة واحدة لتسجيل الدخول (OAuth عبر المتصفح لخطط Pro/Max، أو اضبط ANTHROPIC_API_KEY)
      • مصادقة عبر Console: claude auth login --console للفوترة بمفتاح API
      • مصادقة SSO: claude auth login --sso لإصدار Enterprise
      • التحقق من الحالة: claude auth status (JSON) أو claude auth status --text (نص مقروء للبشر)
      • فحص الحالة الصحية: claude doctor — يفحص المُحدّث التلقائي وسلامة التثبيت
      • التحقق من الإصدار: claude --version (يتطلب v2.x فأعلى)
      • التحديث: claude update أو claude upgrade

      وضعا التنسيق​

      يتعامل Hermes مع Claude Code بطريقتين مختلفتين جذريًا. اختر بينهما حسب المهمة.

      الوضع 1: Print Mode (-p) — غير تفاعلي (مفضّل لمعظم المهام)​

      يشغّل Print mode مهمة واحدة، ويعيد النتيجة، ثم يخرج. لا يحتاج PTY. لا حوارات تفاعلية. هذا هو مسار التكامل الأنظف.

      terminal(command="claude -p 'Add error handling to all API calls in src/' --allowedTools 'Read,Edit' --max-turns 10", workdir="/path/to/project", timeout=120)

      متى تستخدم print mode:

      • مهام برمجية لمرة واحدة (إصلاح خطأ، إضافة ميزة، إعادة هيكلة)
      • أتمتة CI/CD والبرمجة النصية (scripting)
      • استخراج بيانات مهيكلة باستخدام --json-schema
      • معالجة الإدخال المُمرَّر عبر الأنابيب (cat file | claude -p "analyze this")
      • أي مهمة لا تحتاج فيها إلى محادثة متعددة الأدوار

      يتجاوز Print mode جميع الحوارات التفاعلية — لا مطالبة بثقة مساحة العمل، ولا تأكيدات صلاحيات. هذا يجعله مثاليًا للأتمتة.

      الوضع 2: PTY تفاعلي عبر tmux — جلسات متعددة الأدوار​

      يمنحك الوضع التفاعلي REPL محادثيًا كاملًا يمكنك فيه إرسال مطالبات متابعة، واستخدام slash commands، ومشاهدة Claude يعمل في الوقت الفعلي. يتطلب تنسيق tmux.

      # Start a tmux session
      terminal(command="tmux new-session -d -s claude-work -x 140 -y 40")

      # Launch Claude Code inside it
      terminal(command="tmux send-keys -t claude-work 'cd /path/to/project && claude' Enter")

      # Wait for startup, then send your task
      # (after ~3-5 seconds for the welcome screen)
      terminal(command="sleep 5 && tmux send-keys -t claude-work 'Refactor the auth module to use JWT tokens' Enter")

      # Monitor progress by capturing the pane
      terminal(command="sleep 15 && tmux capture-pane -t claude-work -p -S -50")

      # Send follow-up tasks
      terminal(command="tmux send-keys -t claude-work 'Now add unit tests for the new JWT code' Enter")

      # Exit when done
      terminal(command="tmux send-keys -t claude-work '/exit' Enter")

      متى تستخدم الوضع التفاعلي:

      • عمل تكراري متعدد الأدوار (إعادة هيكلة → مراجعة → إصلاح → دورة اختبار)
      • مهام تتطلب قرارات بمشاركة الإنسان (human-in-the-loop)
      • جلسات برمجة استكشافية
      • عندما تحتاج إلى استخدام slash commands الخاصة بـ Claude (/compact, /review, /model)

      التعامل مع حوارات PTY (بالغ الأهمية للوضع التفاعلي)​

      يعرض Claude Code حتى حوارين للتأكيد عند أول تشغيل. يجب عليك التعامل معهما عبر tmux send-keys:

      الحوار 1: ثقة مساحة العمل (أول زيارة لمجلد)​

      ❯ 1. Yes, I trust this folder    ← DEFAULT (just press Enter)
        2. No, exit

      التعامل: tmux send-keys -t <session> Enter — الاختيار الافتراضي صحيح.

      الحوار 2: تحذير تجاوز الصلاحيات (فقط مع --dangerously-skip-permissions)​

      ❯ 1. No, exit                    ← DEFAULT (WRONG choice!)
        2. Yes, I accept

      التعامل: يجب التنقل إلى الأسفل أولًا، ثم Enter:

      tmux send-keys -t <session> Down && sleep 0.3 && tmux send-keys -t <session> Enter

      نمط قوي للتعامل مع الحوارات​

      # Launch with permissions bypass
      terminal(command="tmux send-keys -t claude-work 'claude --dangerously-skip-permissions \"your task\"' Enter")

      # Handle trust dialog (Enter for default "Yes")
      terminal(command="sleep 4 && tmux send-keys -t claude-work Enter")

      # Handle permissions dialog (Down then Enter for "Yes, I accept")
      terminal(command="sleep 3 && tmux send-keys -t claude-work Down && sleep 0.3 && tmux send-keys -t claude-work Enter")

      # Now wait for Claude to work
      terminal(command="sleep 15 && tmux capture-pane -t claude-work -p -S -60")

      ملاحظة: بعد أول قبول للثقة بمجلد ما، لن يظهر حوار الثقة مرة أخرى. فقط حوار الصلاحيات يتكرر في كل مرة تستخدم فيها --dangerously-skip-permissions.

      التعمّق في Print Mode​

      إخراج JSON مهيكل​

      terminal(command="claude -p 'Analyze auth.py for security issues' --output-format json --max-turns 5", workdir="/project", timeout=120)

      يُعيد كائن JSON يحتوي على:

      {
        "type": "result",
        "subtype": "success",
        "result": "The analysis text...",
        "session_id": "75e2167f-...",
        "num_turns": 3,
        "total_cost_usd": 0.0787,
        "duration_ms": 10276,
        "stop_reason": "end_turn",
        "terminal_reason": "completed",
        "usage": { "input_tokens": 5, "output_tokens": 603, ... },
        "modelUsage": { "claude-sonnet-4-6": { "costUSD": 0.078, "contextWindow": 200000 } }
      }

      الحقول الرئيسية: session_id للاستئناف، وnum_turns لعدد دورات الحلقة الوكيلية، وtotal_cost_usd لتتبع الإنفاق، وsubtype لاكتشاف النجاح/الخطأ (success, error_max_turns, error_budget).

      إخراج JSON متدفق (streaming)​

      للبث الفوري للـ tokens، استخدم stream-json مع --verbose:

      terminal(command="claude -p 'Write a summary' --output-format stream-json --verbose --include-partial-messages", timeout=60)

      يعيد أحداث JSON مفصولة بأسطر جديدة. صفِّها باستخدام jq للحصول على نص مباشر:

      claude -p "Explain X" --output-format stream-json --verbose --include-partial-messages | \
        jq -rj 'select(.type == "stream_event" and .event.delta.type? == "text_delta") | .event.delta.text'

      تتضمن أحداث البث system/api_retry مع حقول attempt وmax_retries وerror (مثل rate_limit, billing_error).

      البث ثنائي الاتجاه​

      لبث الإدخال والإخراج في الوقت الفعلي معًا:

      claude -p "task" --input-format stream-json --output-format stream-json --replay-user-messages

      --replay-user-messages يعيد بث رسائل المستخدم على stdout للإقرار بها.

      الإدخال عبر الأنابيب​

      # Pipe a file for analysis
      terminal(command="cat src/auth.py | claude -p 'Review this code for bugs' --max-turns 1", timeout=60)

      # Pipe multiple files
      terminal(command="cat src/*.py | claude -p 'Find all TODO comments' --max-turns 1", timeout=60)

      # Pipe command output
      terminal(command="git diff HEAD~3 | claude -p 'Summarize these changes' --max-turns 1", timeout=60)

      JSON Schema للاستخراج المهيكل​

      terminal(command="claude -p 'List all functions in src/' --output-format json --json-schema '{\"type\":\"object\",\"properties\":{\"functions\":{\"type\":\"array\",\"items\":{\"type\":\"string\"}}},\"required\":[\"functions\"]}' --max-turns 5", workdir="/project", timeout=90)

      استخرج structured_output من نتيجة JSON. يتحقق Claude من صحة الإخراج مقابل الـ schema قبل إعادته.

      متابعة الجلسة​

      # Start a task
      terminal(command="claude -p 'Start refactoring the database layer' --output-format json --max-turns 10 > /tmp/session.json", workdir="/project", timeout=180)

      # Resume with session ID
      terminal(command="claude -p 'Continue and add connection pooling' --resume $(cat /tmp/session.json | python -c 'import json,sys; print(json.load(sys.stdin)[\"session_id\"])') --max-turns 5", workdir="/project", timeout=120)

      # Or resume the most recent session in the same directory
      terminal(command="claude -p 'What did you do last time?' --continue --max-turns 1", workdir="/project", timeout=30)

      # Fork a session (new ID, keeps history)
      terminal(command="claude -p 'Try a different approach' --resume <id> --fork-session --max-turns 10", workdir="/project", timeout=120)

      Bare Mode لـ CI/Scripting​

      terminal(command="claude --bare -p 'Run all tests and report failures' --allowedTools 'Read,Bash' --max-turns 10", workdir="/project", timeout=180)

      يتخطى --bare الـ hooks والإضافات واكتشاف MCP وتحميل CLAUDE.md. أسرع بدء تشغيل. يتطلب ANTHROPIC_API_KEY (يتخطى OAuth).

      لتحميل سياق بشكل انتقائي في bare mode:

      ما تريد تحميلهالعلم (flag)
      إضافات إلى الـ system prompt--append-system-prompt "text" أو --append-system-prompt-file path
      الإعدادات--settings <file-or-json>
      خوادم MCP--mcp-config <file-or-json>
      subagents مخصصة--agents '<json>'

      نموذج احتياطي عند التحميل الزائد​

      terminal(command="claude -p 'task' --fallback-model haiku --max-turns 5", timeout=90)

      يرجع تلقائيًا إلى النموذج المحدد عندما يكون النموذج الافتراضي محمّلًا بشكل زائد (في print mode فقط).

      مرجع كامل لخيارات CLI​

      الجلسة والبيئة​

      الخيارالأثر
      -p, --printوضع غير تفاعلي لمرة واحدة (يخرج عند الانتهاء)
      -c, --continueاستئناف أحدث محادثة في المجلد الحالي
      -r, --resume <id>استئناف جلسة محددة عبر المعرّف أو الاسم (منتقٍ تفاعلي إن لم يُحدَّد معرّف)
      --fork-sessionعند الاستئناف، إنشاء معرّف جلسة جديد بدلًا من إعادة استخدام الأصلي
      --session-id <uuid>استخدام UUID محدد للمحادثة
      --no-session-persistenceعدم حفظ الجلسة على القرص (print mode فقط)
      --add-dir <paths...>منح Claude وصولًا إلى مجلدات عمل إضافية
      -w, --worktree [name]التشغيل في worktree معزول لـ git عند .claude/worktrees/<name>
      --tmuxإنشاء جلسة tmux للـ worktree (يتطلب --worktree)
      --ideالاتصال تلقائيًا بـ IDE صالح عند بدء التشغيل
      --chrome / --no-chromeتفعيل/تعطيل تكامل متصفح Chrome لاختبار الويب
      --from-pr [number]استئناف جلسة مرتبطة بـ pull request محدد على GitHub
      --file <specs...>موارد ملفات لتنزيلها عند بدء التشغيل (الصيغة: file_id:relative_path)

      النموذج والأداء​

      الخيارالأثر
      --model <alias>اختيار النموذج: sonnet, opus, haiku, أو اسم كامل مثل claude-sonnet-4-6
      --effort <level>عمق الاستدلال: low, medium, high, xhigh, max
      --max-turns <n>تحديد حلقات وكيلية (print mode فقط؛ يمنع التمادي)
      --max-budget-usd <n>تحديد سقف الإنفاق بالدولار على API (print mode فقط)
      --fallback-model <model>رجوع تلقائي عندما يكون النموذج الافتراضي محمّلًا بشكل زائد (print mode فقط)
      --betas <betas...>رؤوس beta لتضمينها في طلبات API (لمستخدمي مفتاح API فقط)

      الصلاحية والأمان​

      الخيارالأثر
      --dangerously-skip-permissionsالموافقة التلقائية على كل استخدام للأدوات (كتابة الملفات، bash، الشبكة، إلخ)
      --allow-dangerously-skip-permissionsتفعيل التجاوز كخيار دون تفعيله افتراضيًا
      --permission-mode <mode>default, acceptEdits, plan, auto, dontAsk, bypassPermissions
      --allowedTools <tools...>إدراج أدوات محددة في قائمة السماح (مفصولة بفواصل أو مسافات)
      --disallowedTools <tools...>إدراج أدوات محددة في قائمة الحظر
      --tools <tools...>تجاوز مجموعة الأدوات المدمجة ("" = بلا شيء، "default" = الكل، أو أسماء أدوات)

      صيغة الإخراج والإدخال​

      الخيارالأثر
      --output-format <fmt>text (الافتراضي)، json (كائن نتيجة واحد)، stream-json (مفصول بأسطر جديدة)
      --input-format <fmt>text (الافتراضي) أو stream-json (إدخال متدفق في الوقت الفعلي)
      --json-schema <schema>فرض إخراج JSON مهيكل مطابق لـ schema
      --verboseإخراج كامل دورًا بدور
      --include-partial-messagesتضمين أجزاء الرسائل الجزئية فور وصولها (stream-json + print)
      --replay-user-messagesإعادة بث رسائل المستخدم على stdout (stream-json ثنائي الاتجاه)

      الـ system prompt والسياق​

      الخيارالأثر

      CLAUDE.md — ملف سياق المشروع​

      يحمّل Claude Code تلقائيًا ملف CLAUDE.md من جذر المشروع. استخدمه لحفظ سياق المشروع بشكل دائم:

      # Project: My API

      ## Architecture
      - FastAPI backend with SQLAlchemy ORM
      - PostgreSQL database, Redis cache
      - pytest for testing with 90% coverage target

      ## Key Commands
      - `make test` — run full test suite
      - `make lint` — ruff + mypy
      - `make dev` — start dev server on :8000

      ## Code Standards
      - Type hints on all public functions
      - Docstrings in Google style
      - 2-space indentation for YAML, 4-space for Python
      - No wildcard imports

      كن محدّدًا. بدلًا من "اكتب كودًا جيدًا"، استخدم "استخدم مسافة بادئة من مسافتين لملفات JS" أو "سمِّ ملفات الاختبار بلاحقة .test.ts." التعليمات المحدّدة توفّر دورات تصحيح لاحقة.

      مجلد القواعد (CLAUDE.md معياري)​

      للمشاريع ذات القواعد الكثيرة، استخدم مجلد القواعد بدلًا من ملف CLAUDE.md ضخم واحد:

      • قواعد المشروع: .claude/rules/*.md — مشتركة بين الفريق، مُتتبَّعة عبر git
      • قواعد المستخدم: ~/.claude/rules/*.md — شخصية، عامة

      يُحمَّل كل ملف .md في مجلد القواعد كسياق إضافي. هذا أنظف من حشو كل شيء في ملف CLAUDE.md واحد.

      الذاكرة التلقائية (Auto-Memory)​

      يخزّن Claude تلقائيًا سياق المشروع المُتعلَّم في ~/.claude/projects/<project>/memory/.

      • الحد الأقصى: 25 KB أو 200 سطر لكل مشروع
      • هذا منفصل عن CLAUDE.md — إنه ملاحظات Claude الخاصة حول المشروع، المتراكمة عبر الجلسات

      Subagents مخصّصة​

      عرّف وكلاء متخصّصين في .claude/agents/ (على مستوى المشروع)، أو ~/.claude/agents/ (شخصي)، أو عبر خيار --agents في CLI (خاص بالجلسة):

      أولوية موقع الوكيل​

      1. .claude/agents/ — على مستوى المشروع، مشترك بين الفريق
      2. خيار --agents في CLI — خاص بالجلسة، ديناميكي
      3. ~/.claude/agents/ — على مستوى المستخدم، شخصي

      إنشاء وكيل​

      # .claude/agents/security-reviewer.md
      ---
      name: security-reviewer
      description: Security-focused code review
      model: opus
      tools: [Read, Bash]
      ---
      You are a senior security engineer. Review code for:
      - Injection vulnerabilities (SQL, XSS, command injection)
      - Authentication/authorization flaws
      - Secrets in code
      - Unsafe deserialization

      استدعِه عبر: @security-reviewer review the auth module

      وكلاء ديناميكيون عبر CLI​

      terminal(command="claude --agents '{\"reviewer\": {\"description\": \"Reviews code\", \"prompt\": \"You are a code reviewer focused on performance\"}}' -p 'Use @reviewer to check auth.py'", timeout=120)

      يمكن لـ Claude تنسيق عدة وكلاء: "استخدم @db-expert لتحسين الاستعلامات، ثم @security لمراجعة التغييرات."

      Hooks — الأتمتة عند الأحداث​

      اضبطها في .claude/settings.json (على مستوى المشروع) أو ~/.claude/settings.json (عام):

      {
        "hooks": {
          "PostToolUse": [{
            "matcher": "Write(*.py)",
            "hooks": [{"type": "command", "command": "ruff check --fix $CLAUDE_FILE_PATHS"}]
          }],
          "PreToolUse": [{
            "matcher": "Bash",
            "hooks": [{"type": "command", "command": "if echo \"$CLAUDE_TOOL_INPUT\" | grep -q 'rm -rf'; then echo 'Blocked!' && exit 2; fi"}]
          }],
          "Stop": [{
            "hooks": [{"type": "command", "command": "echo 'Claude finished a response' >> /tmp/claude-activity.log"}]
          }]
        }
      }

      جميع أنواع Hooks الثمانية​

      Hookوقت التشغيلالاستخدام الشائع
      UserPromptSubmitقبل معالجة Claude لطلب المستخدمالتحقّق من صحة الإدخال، التسجيل
      PreToolUseقبل تنفيذ الأداةبوابات الأمان، منع الأوامر الخطرة (exit 2 = منع)
      PostToolUseبعد انتهاء الأداةتنسيق الكود تلقائيًا، تشغيل أدوات linter
      Notificationعند طلبات الصلاحية أو انتظار الإدخالإشعارات سطح المكتب، التنبيهات
      Stopعندما ينهي Claude ردًاتسجيل الإنجاز، تحديثات الحالة
      SubagentStopعندما يكمل subagent مهمتهتنسيق الوكلاء
      PreCompactقبل مسح ذاكرة السياقنسخ احتياطي لنصوص الجلسة
      SessionStartعند بدء جلسةتحميل سياق التطوير (مثل git status)

      أشِر إلى موارد MCP في المحادثة: @github:issue://123

      حدود MCP وضبطها​

      • أوصاف الأدوات: حد أقصى 2 KB لكل خادم لأوصاف الأدوات وتعليمات الخادم
      • حجم النتيجة: محدود افتراضيًا؛ استخدم سمة (annotation) maxResultSizeChars للسماح بما يصل إلى 500 ألف حرف للمخرجات الكبيرة
      • tokens المخرجات: export MAX_MCP_OUTPUT_TOKENS=50000 — تحديد مخرجات خوادم MCP لمنع إغراق السياق
      • وسائل النقل (transports): stdio (عملية محلية)، http (عن بُعد)، sse (أحداث مُرسَلة من الخادم)

      مراقبة الجلسات التفاعلية​

      قراءة حالة TUI​

      # Periodic capture to check if Claude is still working or waiting for input
      terminal(command="tmux capture-pane -t dev -p -S -10")

      ابحث عن هذه المؤشرات:

      • ❯ في الأسفل = بانتظار إدخالك (Claude انتهى أو يطرح سؤالًا)
      • أسطر ● = Claude يستخدم الأدوات بفعالية (يقرأ، يكتب، يشغّل أوامر)
      • ⏵⏵ bypass permissions on = شريط الحالة يُظهر وضع الصلاحيات
      • ◐ medium · /effort = مستوى الجهد الحالي في شريط الحالة
      • ctrl+o to expand = تم اقتطاع مخرجات الأداة (يمكن توسيعها تفاعليًا)

      سلامة نافذة السياق​

      استخدم /context في الوضع التفاعلي لرؤية شبكة ملوّنة لاستخدام السياق. العتبات الرئيسية:

      • أقل من 70% — تشغيل طبيعي، دقّة كاملة
      • 70-85% — تبدأ الدقّة بالانخفاض، ضع في اعتبارك /compact
      • أكثر من 85% — يرتفع خطر الهلوسة بشكل ملحوظ، استخدم /compact أو /clear

      MAX_THINKING_TOKENSتحديد tokens التفكير (اضبط على 0 لتعطيل التفكير تمامًا)
      MAX_MCP_OUTPUT_TOKENSتحديد مخرجات خوادم MCP (تختلف القيمة الافتراضية؛ اضبطها مثلًا على 50000)
      CLAUDE_CODE_NO_FLICKER=1تفعيل عرض alt-screen للقضاء على وميض الطرفية
      CLAUDE_CODE_SUBPROCESS_ENV_SCRUBإزالة بيانات الاعتماد من العمليات الفرعية لأغراض أمنية

      نصائح للتكلفة والأداء​

      1. استخدم --max-turns في وضع الطباعة لمنع الحلقات الجامحة. ابدأ بـ 5-10 لمعظم المهام.
      2. استخدم --max-budget-usd لتحديد سقف التكلفة. ملاحظة: الحد الأدنى تقريبًا 0.05 دولار لإنشاء ذاكرة تخزين مؤقت لـ system prompt.
      3. استخدم --effort low للمهام البسيطة (أسرع وأرخص). و high أو max للاستدلال المعقّد.
      4. استخدم --bare لبيئات CI/البرمجة النصية لتخطّي الحمل الزائد لاكتشاف الإضافات/hooks.
      5. استخدم --allowedTools للتقييد بما هو ضروري فقط (مثلًا Read فقط للمراجعات).
      6. استخدم /compact في الجلسات التفاعلية عندما يكبر السياق.
      7. مرّر الإدخال (Pipe) بدلًا من جعل Claude يقرأ الملفات عندما تحتاج فقط إلى تحليل محتوى معروف.
      8. استخدم --model haiku للمهام البسيطة (أرخص) و --model opus للعمل المعقّد متعدّد الخطوات.
      9. استخدم --fallback-model haiku في وضع الطباعة للتعامل بسلاسة مع ازدحام النموذج.
      10. ابدأ جلسات جديدة للمهام المنفصلة — تستمر الجلسات 5 ساعات؛ السياق الجديد أكثر كفاءة.
      11. استخدم --no-session-persistence في CI لتجنّب تراكم الجلسات المحفوظة على القرص.

      المزالق والمشكلات الشائعة​

      1. الوضع التفاعلي يتطلّب tmux — Claude Code تطبيق TUI كامل. استخدام pty=true وحده في طرفية Hermes يعمل، لكن tmux يمنحك capture-pane للمراقبة و send-keys للإدخال، وهو أمر أساسي للتنسيق.
      2. مربع حوار --dangerously-skip-permissions يكون افتراضيًا "No, exit" — يجب إرسال Down ثم Enter للقبول. وضع الطباعة (-p) يتخطّى هذا تمامًا.
      3. الحد الأدنى لـ --max-budget-usd تقريبًا 0.05 دولار — إنشاء ذاكرة تخزين مؤقت لـ system prompt وحده يكلّف هذا المبلغ. ضبط قيمة أقل سيؤدي إلى خطأ فوري.
      4. --max-turns خاص بوضع الطباعة فقط — يُتجاهَل في الجلسات التفاعلية.
      5. قد يستخدم Claude python بدلًا من python — على الأنظمة التي لا تملك رابطًا رمزيًا (symlink) لـ python، ستفشل أوامر bash الخاصة بـ Claude في المحاولة الأولى لكنه يصحّح نفسه تلقائيًا.
      6. استئناف الجلسة يتطلّب نفس المجلد — --continue يجد أحدث جلسة لمجلد العمل الحالي.
      7. --json-schema يحتاج إلى عدد كافٍ من --max-turns — يجب على Claude قراءة الملفات قبل إنتاج مخرجات مُهيكلة، وهو ما يستغرق عدة أدوار.
      8. مربع حوار الثقة يظهر مرة واحدة فقط لكل مجلد — أول مرة فقط، ثم يُخزَّن مؤقتًا.
      9. جلسات tmux في الخلفية تبقى قائمة — نظّفها دائمًا باستخدام tmux kill-session -t <name> عند الانتهاء.
      10. الأوامر ذات الشرطة المائلة (مثل /commit) تعمل فقط في الوضع التفاعلي — في وضع -p، صِف المهمة بلغة طبيعية بدلًا من ذلك.
      11. --bare يتخطّى OAuth — يتطلّب متغير بيئة ANTHROPIC_API_KEY أو apiKeyHelper في الإعدادات.
      12. تدهور السياق أمر حقيقي — تنخفض جودة مخرجات الذكاء الاصطناعي بشكل ملموس فوق نسبة استخدام 70% من نافذة السياق. راقب باستخدام /context وبادر باستخدام /compact.

      قواعد لوكلاء Hermes​

      1. فضّل وضع الطباعة (-p) للمهام المفردة — أنظف، بلا التعامل مع مربعات الحوار، ومخرجات مُهيكلة
      2. استخدم tmux للعمل التفاعلي متعدّد الأدوار — الطريقة الموثوقة الوحيدة لتنسيق TUI
      3. اضبط دائمًا workdir — أبقِ Claude مركّزًا على مجلد المشروع الصحيح
      4. اضبط --max-turns في وضع الطباعة — يمنع الحلقات اللانهائية والتكاليف الجامحة
      5. راقب جلسات tmux — استخدم tmux capture-pane -t <session> -p -S -50 لمتابعة التقدّم
      6. ابحث عن رمز ❯ — يشير إلى أن Claude بانتظار الإدخال (انتهى أو يطرح سؤالًا)
      7. نظّف جلسات tmux — أنهِها عند الانتهاء لتجنّب تسرّب الموارد
      8. أبلغ المستخدم بالنتائج — بعد الانتهاء، لخّص ما فعله Claude وما الذي تغيّر
      9. لا تُنهِ الجلسات البطيئة — قد يكون Claude يقوم بعمل متعدّد الخطوات؛ تحقّق من التقدّم بدلًا من ذلك
      10. استخدم --allowedTools — قيّد القدرات على ما تحتاجه المهمة فعليًا
