      الصوت و TTS

      يدعم Hermes Agent كلًّا من إخراج تحويل النص إلى كلام (text-to-speech) وتفريغ الرسائل الصوتية نصيًا عبر جميع منصات المراسلة.

      مشتركو Nous

      إذا كان لديك اشتراك مدفوع في Nous Portal، فإن OpenAI TTS متاح عبر Tool Gateway دون الحاجة إلى مفتاح OpenAI API منفصل. يمكن لعمليات التثبيت الجديدة تشغيل hermes setup --portal لتسجيل الدخول وتفعيل كل أدوات الـ gateway دفعة واحدة؛ أما عمليات التثبيت الحالية فيمكنها اختيار Nous Subscription لـ TTS وحده عبر hermes model أو hermes tools.

      يختار MiniMax TTS المنطقة والـ endpoint وبيانات الاعتماد معًا:

      • القيمة region: "global" تستخدم https://api.minimax.io/v1/t2a_v2 مع MINIMAX_API_KEY.
      • القيمة region: "cn" تستخدم https://api.minimaxi.com/v1/t2a_v2 مع MINIMAX_CN_API_KEY.
      • إذا أُغفل region، تبقى الأولوية لـ MINIMAX_API_KEY حفاظًا على التوافق مع الإصدارات السابقة. وإذا لم يُضبط سوى MINIMAX_CN_API_KEY، يختار Hermes المنطقة cn.
      • يجب أن تتوفر للمنطقة المختارة صراحةً بيانات الاعتماد المطابقة لها، إذ لا يستعير Hermes أبدًا مفتاح المنطقة الأخرى. ولا يغيّر تجاوز base_url بيانات الاعتماد المختارة، ويُرفض أي تجاوز يشير إلى الـ endpoint الرسمي للمنطقة الأخرى.

      التحكم في السرعة: تُطبَّق القيمة العامة tts.speed على جميع المزوّدين افتراضيًا. ويمكن لكل مزوّد تجاوزها بإعداد speed الخاص به (مثل tts.openai.speed: 1.5). وتتقدّم السرعة الخاصة بالمزوّد على القيمة العامة. القيمة الافتراضية هي 1.0 (السرعة العادية).

      Persona Prompts في Gemini​

      يستطيع Gemini TTS اتباع توجيهات أداء مكتوبة بلغة طبيعية. اضبط tts.gemini.persona_prompt_file على ملف Markdown أو ملف نصي محلي يصف شخصية الصوت (persona). يمكن أن يتضمن الملف أقسامًا بأسلوب Gemini مثل AUDIO PROFILE و SCENE و DIRECTOR'S NOTES و SAMPLE CONTEXT و TRANSCRIPT.

      إذا احتوى الملف على {transcript} أو {{ transcript }}، يستبدل Hermes هذا العنصر النائب بنص TTS الفعلي. وإلا فيُلحق Hermes قسمًا معنونًا TRANSCRIPT تلقائيًا. يبقى الـ prompt الخاص بالشخصية محليًا ولا يظهر في رد المحادثة.

      tts:
        provider: gemini
        gemini:
          voice: Algieba
          persona_prompt_file: ~/.hermes/tts/butler-voice.md

      الوسوم الصوتية (Gemini و xAI)​

      يدعم Gemini 3.1 Flash TTS من Google و Grok TTS من xAI وسومًا صوتية حرة بين أقواس مربعة مثل [whispers] و [excitedly] و [very slow] و [laughs]، وغيرها من ملاحظات الأداء التعبيري. فعّل tts.gemini.audio_tags أو tts.xai.auto_speech_tags كي يُجري Hermes مرحلة إعادة صياغة مخفية قبل TTS. تُدرج إعادة الصياغة الوسوم ضمن نص TTS فقط؛ ويبقى رد المحادثة المرئي دون تغيير.

      tts:
        provider: gemini
        gemini:
          model: gemini-3.1-flash-tts-preview
          audio_tags: true
        xai: 
          auto_speech_tags: true

      تستخدم إعادة الصياغة auxiliary.tts_audio_tags، وتعتمد افتراضيًا على نموذج المحادثة الرئيسي لديك. تجاوز هذه المهمة المساعدة إذا أردت أن يتولى نموذج أرخص أو أسرع إدراج الوسوم.

      اللغة (endpoints المتوافقة مع OpenAI): تُمرَّر tts.openai.language إلى الـ endpoint كمعامل طلب lang_code. وهي مخصصة لخوادم TTS المتوافقة مع OpenAI التي تدعم lang_code — مثل Kokoro-FastAPI، حيث تختار language: "es" محلّل الفونيمات الإسباني بدلًا من الإنجليزي الافتراضي. اتركها دون ضبط عند استخدام OpenAI API الرسمية، التي لا تقبل هذا المعامل. وعند عدم ضبطها، لا يُرسل أي شيء إضافي.

      لكل مزوّد حد موثّق لعدد أحرف الإدخال في كل طلب. يقسّم Hermes الردود الأطول إلى أجزاء مرتبة تراعي حدود الجمل قبل استدعاء المزوّد، لذا يُحفظ النص الكامل بعد التطبيع بدلًا من اقتطاعه بصمت:

      الفقاعات الصوتية في Telegram و ffmpeg​

      تتطلب الفقاعات الصوتية في Telegram صيغة الصوت Opus/OGG:

      • OpenAI و ElevenLabs و Mistral تُنتج Opus أصلًا — دون إعداد إضافي
      • Edge TTS (الافتراضي) يُخرج MP3 ويحتاج إلى ffmpeg للتحويل:
      • MiniMax TTS يُخرج MP3 ويحتاج إلى ffmpeg للتحويل من أجل الفقاعات الصوتية في Telegram
      • Google Gemini TTS يُخرج PCM خامًا ويستخدم ffmpeg لترميزه مباشرةً إلى Opus من أجل الفقاعات الصوتية في Telegram
      • xAI TTS يُخرج MP3 ويحتاج إلى ffmpeg للتحويل من أجل الفقاعات الصوتية في Telegram
      • NeuTTS يُخرج WAV ويحتاج كذلك إلى ffmpeg للتحويل من أجل الفقاعات الصوتية في Telegram
      • KittenTTS يُخرج WAV ويحتاج كذلك إلى ffmpeg للتحويل من أجل الفقاعات الصوتية في Telegram
      • Piper يُخرج WAV ويحتاج كذلك إلى ffmpeg للتحويل من أجل الفقاعات الصوتية في Telegram

      sudo apt install ffmpeg

      # macOS
      brew install ffmpeg

      # Fedora
      sudo dnf install ffmpeg

      دون ffmpeg، يُرسل الصوت الناتج عن Edge TTS و MiniMax TTS و NeuTTS و KittenTTS و Piper كملفات صوتية عادية (قابلة للتشغيل، لكنها تظهر كمشغّل مستطيل بدلًا من فقاعة صوتية).

      نصيحة

      إذا أردت الفقاعات الصوتية دون تثبيت ffmpeg، فانتقل إلى المزوّد OpenAI أو ElevenLabs أو Mistral.

      الأصوات المخصصة في xAI (استنساخ الصوت)​

      يدعم xAI استنساخ صوتك واستخدامه مع TTS. أنشئ صوتًا مخصصًا في xAI Console، ثم اضبط قيمة voice_id الناتجة في إعداداتك:

      tts:
        provider: xai
        xai:
          voice_id: "nlbqfwie"   # your custom voice ID

      راجع توثيق xAI Custom Voices للاطلاع على تفاصيل التسجيل والصيغ المدعومة والحدود.

      Piper (محلي، 44 لغة)​

      Piper محرك TTS عصبي محلي وسريع من Open Home Foundation (القائمون على صيانة Home Assistant). يعمل بالكامل على المعالج (CPU)، ويدعم 44 لغة بأصوات مدرّبة مسبقًا، ولا يحتاج إلى مفتاح API.

      ثبّته عبر hermes tools → Voice & TTS → Piper — وسينفّذ Hermes الأمر pip install piper-tts نيابةً عنك. أو ثبّته يدويًا: pip install piper-tts.

      التبديل إلى Piper:

      tts:
        provider: piper
        piper:
          voice: en_US-lessac-medium

      عند أول استدعاء TTS لصوت غير مخزّن محليًا، يشغّل Hermes python -m piper.download_voices <name> وينزّل النموذج (نحو 20-90MB حسب مستوى الجودة) إلى ~/.hermes/cache/piper-voices/. وتعيد الاستدعاءات اللاحقة استخدام النموذج المخزّن.

      اختيار صوت. يغطي كتالوج الأصوات الكامل الإنجليزية والإسبانية والفرنسية والألمانية والإيطالية والهولندية والبرتغالية والروسية والبولندية والتركية والصينية والعربية والهندية وغيرها — ولكل منها مستويات الجودة x_low / low / medium / high. استمع إلى عينات الأصوات على rhasspy.github.io/piper-samples.

      استخدام صوت منزّل مسبقًا. اضبط tts.piper.voice على مسار مطلق ينتهي بـ .onnx:

      tts:
        piper:
          voice: /path/to/my-custom-voice.onnx

      الإعدادات المتقدمة (tts.piper.length_scale / noise_scale / noise_w_scale / volume / normalize_audio، use_cuda) تقابل واحدًا لواحد إعدادات SynthesisConfig في Piper. وتُتجاهل في إصدارات piper-tts الأقدم.

      التحميل المسبق والإلغاء عبر مفاتيح الكلام (المحركات المحلية)​

      تحمّل المحركات المحلية (Piper و KittenTTS) نموذجها عند الحاجة فقط (lazily)، لذا فدون مساعدة، يدفع الرد المنطوق الأول بعد تفعيل الكلام ثمن تحميل النموذج كاملًا — وفي التثبيت الجديد، ثمن تنزيل الصوت أيضًا — على شكل صمت قبل الكلمة الأولى. لذلك يعدّ Hermes مفاتيح تفعيل إخراج الكلام إشارةً إلى أن TTS على وشك أن يُستخدم:

      • Desktop — الخيار Read replies aloud تفضيل محلي في تطبيق سطح المكتب، مستقل عن إعداد voice.auto_tts الخاص بالـ gateway في Settings → Voice. تُرحَّل القيمة المشتركة مرة واحدة، ثم لا تتجاوز تغييرات إعدادات الـ gateway اللاحقة مفتاح سطح المكتب. إذا كان التخزين المحلي ممتلئًا أو غير متاح، يظل الاختيار ساريًا لهذه النافذة؛ ويبقى الاحتفاظ به بعد إعادة التحميل بأفضل جهد. يؤدي تفعيل Read replies aloud، أو بدء محادثة صوتية، إلى تحميل المحرك المضبوط مسبقًا في الخلفية فورًا. ويؤدي تعطيل كليهما مجددًا إلى إلغاء تحميل النموذج المقيم في الذاكرة (يبلغ حجم صوت Piper عشرات الـ MB، و KittenTTS حتى نحو 80MB) كي لا يبقى في الذاكرة العشوائية دون فائدة.
      • CLI / TUI — يفعل /voice tts (و /voice on عندما يكون voice.auto_tts مضبوطًا) الشيء نفسه؛ بينما يحرّره /voice off.

      يحتفظ كل مفتاح بـ عقد استخدام (lease) على المحرك؛ ولا يُلغى تحميل النموذج إلا عند تحرير آخر عقد عبر كل الواجهات، لذا فإن إيقاف القراءة بصوت عالٍ في نافذة Desktop واحدة لا يسحب الصوت أبدًا من محادثة جارية في نافذة أخرى. أما مع المزوّدين السحابيين فلا يوجد نموذج للاحتفاظ به — إذ يقتصر دور المفتاح على التأكد من وجود الـ SDK الذي يُثبَّت عند الحاجة (edge-tts و ElevenLabs و Mistral). التحميل المسبق بأفضل جهد: فإذا تعذّر تحميل المحرك، يظل تفعيل المفتاح ناجحًا، ويرجع الرد الأول إلى التحميل عند الطلب كما في السابق.

      يستدعي Desktop المسار POST /api/audio/tts-lease مع {"lease": "<name>", "active": true|false}؛ ويمكن للواجهات الأمامية الأخرى استخدام الـ endpoint نفسه.

      يصل عقد الاستخدام نفسه أيضًا إلى المزوّدين الذين يعرّفهم المستخدم، لذا يستطيع خادم TTS المستضاف ذاتيًا تحميل نموذجه مسبقًا وإلغاء تحميله مع المفاتيح: إذ يشغّل مزوّد الأوامر الأمرين الاختياريين warm_command / release_command، ويتلقى مزوّد إضافة Python الاستدعاءين warm() / release().

      مزوّدو الأوامر المخصصة​

      إذا كان محرك TTS الذي تريده غير مدعوم أصلًا (VoxCPM أو MLX-Kokoro أو XTTS CLI أو سكربت لاستنساخ الصوت أو أي شيء آخر يوفّر CLI)، يمكنك ربطه بوصفه مزوّدًا من نوع command دون كتابة أي كود Python. يكتب Hermes نص الإدخال في ملف UTF-8 مؤقت، ويشغّل أمر الـ shell الخاص بك، ثم يقرأ الملف الصوتي الذي أنتجه الأمر.

      عرّف مزوّدًا واحدًا أو أكثر ضمن tts.providers.<name> وبدّل بينها عبر tts.provider: <name> — بالطريقة نفسها التي تبدّل بها بين المزوّدين المدمجين مثل edge و openai.

      tts:
        provider: voxcpm                 # pick any name under tts.providers
        providers:
          voxcpm:
            type: command
            command: "voxcpm --ref ~/voice.wav --text-file {input_path} --out {output_path}"
            output_format: mp3
            timeout: 180
            voice_compatible: true       # try to deliver as a Telegram voice bubble

          mlx-kokoro:
            type: command
            command: "python -m mlx_kokoro --in {input_path} --out {output_path} --voice {voice}"
            voice: af_sky
            output_format: wav

          piper-custom:                  # native Piper also supports custom .onnx via tts.piper.voice
            type: command
            command: "piper -m /path/to/custom.onnx -f {output_path} < {input_path}"
            output_format: wav

      قيم output_format المدعومة: mp3 (الافتراضية)، wav، ogg، flac، m4a، aac، amr، opus. يجب أن يُنتج أمرك تلك الصيغة فعلًا (مثلًا عبر ffmpeg)؛ إذ يكتفي Hermes بالتحقق من القيمة المعلنة وتسمية ملف الإخراج وفقًا لها. وتؤول القيمة غير المعروفة إلى mp3. كما تُتاح الصيغة المختارة للأمر عبر العنصر النائب {format}.

      بيئة العملية الفرعية: يعمل مزوّدو الأوامر (TTS و STT) مع إزالة أسرار Hermes من بيئة العملية الفرعية — إذ تُحذف tokens بوتات الـ gateway، ومفاتيح API لمزوّدي LLM، وبيانات اعتماد الترحيل الداخلية؛ بينما تُحفظ PATH و HOME وإعدادات اللغة المحلية (locale) وغيرها من المتغيرات العادية. إذا كان قالب الأمر يحتاج إلى مفتاح API خاص به من البيئة (مثل أمر curl من سطر واحد)، فأدرج أسماء المتغيرات ضمن env_passthrough في إعدادات المزوّد:

      tts:
        providers:
          mycloud:
            type: command
            command: 'curl -s -H "Authorization: Bearer $MYCLOUD_API_KEY" ... -o {output_path}'
            env_passthrough: [MYCLOUD_API_KEY]

      مثال: Doubao (seed-tts-2.0 للغة الصينية)​

      للحصول على TTS صيني عالي الجودة عبر API ثنائية الاتجاه للبث المتدفق seed-tts-2.0 من ByteDance، ثبّت حزمة PyPI doubao-speech واربطها كمزوّد أوامر:

      pip install doubao-speech
      export VOLCENGINE_APP_ID="your-app-id"
      export VOLCENGINE_ACCESS_TOKEN="your-access-token"
      tts:
        provider: doubao
        providers:
          doubao:
            type: command
            command: "doubao-speech say --text-file {input_path} --out {output_path}"
            output_format: mp3
            max_text_length: 1024
            timeout: 30

      تأتي بيانات الاعتماد من بيئة الـ shell لديك (VOLCENGINE_APP_ID / VOLCENGINE_ACCESS_TOKEN) أو من ~/.doubao-speech/config.yaml. اختر صوتًا بإضافة --voice zh-female-warm (أو أي اسم بديل آخر من doubao-speech list-voices) إلى الأمر. تتضمن doubao-speech أيضًا ASR متدفقًا — راجع قسم STT أدناه لمعرفة كيفية دمجه مع Hermes. المصدر والتوثيق الكامل: github.com/Hypnus-Yuan/doubao-speech.

      يمكن لقالب الأمر لديك الإشارة إلى هذه العناصر النائبة. يستبدلها Hermes وقت العرض ويضع كل قيمة بين علامات اقتباس shell مناسبة للسياق المحيط (دون اقتباس / اقتباس مفرد / اقتباس مزدوج)، لذا تكون المسارات التي تحتوي على مسافات وغيرها من المحارف الحساسة للـ shell آمنة.

      العنصر النائبالمعنى

      {text_path}اسم بديل لـ {input_path}
      {output_path}المسار الذي يجب أن يكتب الأمر الصوت فيه

      استخدم {{ و }} للأقواس المعقوفة الحرفية.

      المفاتيح الاختيارية​

      المفتاحالقيمة الافتراضيةالمعنى

      voice_compatiblefalseعند ضبطه على true، يحوّل Hermes إخراج MP3/WAV إلى Opus/OGG عبر ffmpeg كي يعرضه Telegram كفقاعة صوتية.

      voice / modelفارغيُمرَّران إلى الأمر كقيم للعناصر النائبة فقط.

      ملاحظات حول السلوك​

      • الأسماء المدمجة لها الأولوية دائمًا. لا يحجب الإدخال tts.providers.openai أبدًا مزوّد OpenAI الأصلي، لذا لا يمكن لأي إعدادات من المستخدم استبدال مزوّد مدمج بصمت.
      • التسليم الافتراضي يكون كمستند. يسلّم مزوّدو الأوامر الصوت كمرفقات صوتية عادية على كل المنصات. ويمكنك تفعيل التسليم كفقاعة صوتية لكل مزوّد على حدة عبر voice_compatible: true.
      • تظهر حالات فشل الأوامر للوكيل. فرمز الخروج غير الصفري، أو الإخراج الفارغ، أو انتهاء المهلة، كلها تعيد خطأً يتضمن stderr/stdout الخاص بالأمر، كي تتمكن من تصحيح أخطاء المزوّد من داخل المحادثة.
      • type: command هو الافتراضي عند ضبط command:. كتابة type: command صراحةً ممارسة جيدة لكنها غير مطلوبة؛ فأي إدخال يحتوي على سلسلة command غير فارغة يُعامل كمزوّد أوامر.
      • {input_path} / {text_path} قابلان للتبادل. استخدم أيهما أوضح في أمرك.

      الأمان​

      يشغّل المزوّدون من نوع command أي أمر shell تضبطه، بصلاحيات المستخدم الخاص بك. يضع Hermes قيم العناصر النائبة بين علامات اقتباس ويفرض المهلة المضبوطة، لكن قالب الأمر نفسه يُعدّ إدخالًا محليًا موثوقًا — لذا تعامل معه كما تتعامل مع سكربت shell موجود في PATH لديك.

      مزوّدو إضافات Python​

      بالنسبة إلى محركات TTS التي لا يمكن التعبير عنها بأمر shell واحد — مثل حزم Python SDK التي لا تملك CLI، أو محركات البث المتدفق، أو واجهات API لسرد الأصوات، أو المصادقة التي تتطلب تجديد OAuth — سجّل إضافة Python عبر ctx.register_tts_provider(). تعمل الإضافة جنبًا إلى جنب مع سجل مزوّدي الأوامر المخصصة (ولا تستبدله)؛ فاختر الواجهة التي تناسب محركك.

      متى تختار كلًّا منهما​

      إذا كان الـ backend لديك يتضمن…استخدم

      اثنين أو ثلاثة من أدوات CLI مربوطة بـ pipes في الـ shellمزوّد أوامر
      Python SDK فقط — دون CLIإضافة

      واجهة API لسرد الأصوات يستخدمها hermes setupإضافة (تجاوز list_voices())

      المزوّدون المدمجون لهم الأولوية دائمًا، ومزوّدو الأوامر يتقدّمون على أي إضافة تحمل الاسم نفسه — لذا يمكنك تسجيل الإضافات بأمان بأي اسم غير مدمج دون القلق من حجب إعداداتك الحالية.

      إضافة بالحد الأدنى​

      ضع ما يلي في ~/.hermes/plugins/my-tts/:

      الملف plugin.yaml:

      name: my-tts
      version: 0.1.0
      description: "My custom Python TTS backend"

      الملف __init__.py:

      from agent.tts_provider import TTSProvider


      class MyTTSProvider(TTSProvider):
          @property
          def name(self) -> str:
              return "my-tts"  # what tts.provider matches against

          @property
          def display_name(self) -> str:
              return "My Custom TTS"

          def is_available(self) -> bool:
              # Return False when credentials/deps are missing — picker skips
              # this row but the dispatcher still routes here on explicit config.
              import os
              return bool(os.environ.get("MY_TTS_API_KEY"))

          def synthesize(self, text, output_path, *, voice=None, model=None,
                         speed=None, format="mp3", **extra) -> str:
              # Write audio bytes to output_path, return the path.
              # Raise on failure — the dispatcher converts exceptions to a
              # standard error envelope.
              import my_tts_sdk
              client = my_tts_sdk.Client()
              audio_bytes = client.synthesize(text=text, voice=voice or "default")
              with open(output_path, "wb") as f:
                  f.write(audio_bytes)
              return output_path


      def register(ctx):
          ctx.register_tts_provider(MyTTSProvider())

      فعّلها (hermes plugins enable my-tts)، ووجّه tts.provider إليها (tts.provider: my-tts في config.yaml)، وستمر الأداة text_to_speech عبر إضافتك.

      الـ hooks الاختيارية​

      تجاوز هذه الدوال في صنف المزوّد الخاص بك للحصول على تكامل أغنى:

      • list_voices() → قائمة من قواميس {id, display, language, gender, preview_url} تُعرض في hermes tools.
      • list_models() → قائمة من قواميس {id, display, languages, max_text_length}.
      • get_setup_schema() → تعيد {name, badge, tag, env_vars: [{key, prompt, url}]} لتغذية صف أداة الاختيار في hermes tools / hermes setup. ودونها تظل الإضافة تعمل، لكن صفها في أداة الاختيار يكون بالحد الأدنى.
      • stream(text, *, voice, model, format, **extra) → مكرِّر (iterator) يُنتج بايتات الصوت للتسليم المتدفق (ترفع افتراضيًا NotImplementedError).
      • الخاصية voice_compatible → اضبطها على True إذا كان إخراجك متوافقًا مع Opus وينبغي أن يسلّمه الـ gateway كفقاعة صوتية (القيمة الافتراضية False = مرفق صوتي عادي).
      • warm() / release() → تُستدعيان عندما تفعّل واجهة ما إخراج الكلام / عند تحرير آخر عقد استخدام عبر الواجهات، ما دام مزوّدك هو tts.provider المضبوط — حمّل خادم نموذج محليًا مسبقًا أو ألغِ تحميله هنا. كلتاهما لا تفعلان شيئًا افتراضيًا؛ وتُسجَّل الاستثناءات بمستوى debug ولا تُفشل تفعيل المفتاح أبدًا.

      راجع agent/tts_provider.py للاطلاع على الصنف المجرد (ABC) الكامل مع سلاسل التوثيق (docstrings).

      تفريغ الرسائل الصوتية نصيًا (STT)​

      تُفرَّغ الرسائل الصوتية المُرسَلة على Telegram أو Discord أو WhatsApp أو Slack أو Signal نصيًا بشكل تلقائي، ويُدرَج النص في المحادثة. ويرى الوكيل النص المُفرَّغ كأي نص عادي.

      المزوّدالجودةالتكلفةمفتاح API

      Groq Whisper APIجيدة–ممتازةفئة مجانيةGROQ_API_KEY
      OpenAI Whisper APIجيدة–ممتازةمدفوعVOICE_TOOLS_OPENAI_KEY أو OPENAI_API_KEY

      الإعدادات​

      تفاصيل المزوّدين​

      Local (faster-whisper) — يشغّل Whisper محليًا عبر faster-whisper. يستخدم CPU افتراضيًا، و GPU إن كان متاحًا. أحجام النماذج:

      النموذجالحجمالسرعةالجودة
      tiny~75 MBالأسرعأساسية
      base~150 MBسريعجيدة (الافتراضي)
      small~500 MBمتوسطأفضل
      medium~1.5 GBأبطأعالية جدًا
      large-v3~3 GBالأبطأالأفضل

      Groq API — يتطلب GROQ_API_KEY. خيار سحابي احتياطي جيد عندما تريد خدمة STT مستضافة مجانية. اضبط stt.groq.language (أو متغير البيئة العام HERMES_LOCAL_STT_LANGUAGE) لتجاوز الاكتشاف التلقائي للغة في Whisper وتقليل زمن الاستجابة عندما تكون لغة الصوت معروفة.

      OpenAI API — يقبل VOICE_TOOLS_OPENAI_KEY أولًا، ثم يعود إلى OPENAI_API_KEY احتياطيًا. ويدعم whisper-1 و gpt-4o-mini-transcribe و gpt-4o-transcribe و gpt-transcribe.

      Mistral API (Voxtral Transcribe) — يتطلب MISTRAL_API_KEY. يستخدم نماذج Voxtral Transcribe من Mistral. ويدعم 13 لغة، وتمييز المتحدثين (speaker diarization)، والطوابع الزمنية على مستوى الكلمة. ثبّته باستخدام cd ~/.hermes/hermes-agent && uv pip install -e ".[mistral]".

      xAI Grok STT — يتطلب XAI_API_KEY. يُرسل الطلبات إلى https://api.x.ai/v1/stt بصيغة multipart/form-data. وهو خيار جيد إذا كنت تستخدم xAI بالفعل للمحادثة أو TTS وتريد مفتاح API واحدًا لكل شيء. يأتي بعد Groq في ترتيب الاكتشاف التلقائي — لذا اضبط stt.provider: xai صراحةً لفرض استخدامه.

      أمر CLI محلي مخصّص كخيار احتياطي — اضبط HERMES_LOCAL_STT_COMMAND إذا أردت أن يستدعي Hermes أمر تفريغ محليًا مباشرةً. يدعم قالب الأمر العناصر النائبة {input_path} و {output_dir} و {language} و {model}. يقسّم Hermes القالب بعد تعبئته إلى قائمة وسائط وينفّذه دون shell، لذا تُمرَّر العوامل مثل | و > و && و ; كوسائط حرفية. ويجب أن يكتب أمرك ملف تفريغ .txt في مكانٍ ما داخل {output_dir}.

      مثال: Doubao / Volcengine ASR​

      إذا كنت تستخدم doubao-speech لـ Doubao TTS (راجع ما ورد أعلاه)، فإن الحزمة نفسها تتولى تحويل الكلام إلى نص عبر واجهة STT القائمة على الأوامر المحلية:

      pip install doubao-speech
      export VOLCENGINE_APP_ID="your-app-id"
      export VOLCENGINE_ACCESS_TOKEN="your-access-token"
      export HERMES_LOCAL_STT_COMMAND='doubao-speech transcribe {input_path} --out {output_dir}/transcript.txt'

      إذا كان قالب محلي موثوق يحتاج عمدًا إلى pipes أو إعادة توجيه (redirects) أو أي ميزة أخرى من ميزات الـ shell، فاستدعِ الـ shell صراحةً. وأبقِ المسارات الديناميكية خارج برنامج الـ shell، ومرّرها كوسائط موضعية:

      export HERMES_LOCAL_STT_COMMAND='sh -c '\''whisper "$1" --output_format txt --output_dir "$2" | tee "$2/whisper.log"'\'' _ {input_path} {output_dir}'

      على Windows، استخدم بدلًا من ذلك wrapper صريحًا عبر cmd /c أو PowerShell. فالـ wrapper الصريح يجعل تفسير الـ shell جزءًا اختياريًا تفعّله بنفسك ضمن argv المُعدّ، بدلًا من أن يكون خاصية ضمنية لكل قالب STT محلي.

      stt:
        provider: local_command

      يكتب Hermes الرسالة الصوتية الواردة إلى {input_path}، ثم يشغّل الأمر، ويقرأ ملف .txt الناتج داخل {output_dir}. ويكتشف endpoint الخاص بـ Volcengine bigmodel اللغة تلقائيًا.

      السلوك الاحتياطي (Fallback)​

      يُلتزَم بدقة بالاختيار الصريح للمزوّد عبر stt.provider (المكتوب في config.yaml، مثلًا عبر hermes tools) — فإذا تعذّر تشغيل ذلك المزوّد، يفشل التفريغ برسالة خطأ واضحة (stt is configured to use <provider> (set via hermes tools), but <failure>. Run 'hermes tools' to change it.) بدلًا من التبديل بصمت إلى محرّك آخر. لاحظ أن كتابة stt.provider: local في إعداداتك تُعدّ اختيارًا صريحًا.

      عندما لا يكون أي مزوّد قد اختير من قبل، يكتشف Hermes تلقائيًا ما هو متاح:

      • Local faster-whisper غير متاح → يجرّب أداة CLI محلية باسم whisper أو HERMES_LOCAL_STT_COMMAND قبل المزوّدين السحابيين
      • مفتاح Groq غير مضبوط → يُتجاوَز؛ وينتقل إلى المزوّد المتاح التالي
      • مفتاح OpenAI غير مضبوط → يُتجاوَز؛ وينتقل إلى المزوّد المتاح التالي
      • مفتاح Mistral أو الـ SDK غير مضبوط → يُتجاوَز في الاكتشاف التلقائي؛ وينتقل إلى المزوّد المتاح التالي
      • لا شيء متاح → تمرّ الرسائل الصوتية كما هي مع ملاحظة دقيقة للمستخدم

      مزوّدو STT القائمون على أوامر مخصّصة​

      إذا لم يكن محرّك STT الذي تريده مدعومًا بشكل أصلي (Doubao ASR، أو NVIDIA Parakeet، أو نسخة مبنية من whisper.cpp، أو أداة CLI مفتوحة المصدر لـ SenseVoice، أو أي شيء آخر يوفّر أمر shell)، فاربطه بوصفه مزوّدًا من نوع command دون كتابة أي كود Python. يشغّل Hermes أمر الـ shell الخاص بك على الملف الصوتي، ثم يقرأ النص المُفرَّغ.

      عرّف مزوّدًا واحدًا أو أكثر تحت stt.providers.<name> وبدّل بينها باستخدام stt.provider: <name> — بالبنية نفسها المستخدمة في سجل مزوّدي الأوامر الخاص بـ TTS، مع تكييفها لاتجاه الإدخال=صوت → الإخراج=نص مُفرَّغ.

      stt:
        provider: parakeet                # pick any name under stt.providers
        providers:
          parakeet:
            type: command
            command: "parakeet-asr --model nvidia/parakeet-tdt-0.6b-v2 --in {input_path} --out {output_path}"
            format: txt
            language: en
            timeout: 300

          whispercpp:
            type: command
            command: "whisper-cli -m ~/models/ggml-large-v3.bin -f {input_path} -otxt -of {output_dir}/transcript"
            format: txt

          sensevoice:
            type: command
            command: "sensevoice-cli {input_path} --json | tee {output_path}"
            format: json

      يُكمّل هذا منفذ الطوارئ القديم HERMES_LOCAL_STT_COMMAND المتاح عبر المسار المدمج local_command. وعلى عكس سجل مزوّدي الأوامر المعتمد على الـ shell، يُقسَّم القالب القديم إلى argv ويعمل دون تفسير ضمني من الـ shell. استخدم stt.providers.<name> عندما تريد عدة محرّكات STT معتمدة على الـ shell، أو اسمًا يمكنك اختياره عبر stt.provider، أو أي شيء يحتاج إلى language / model / timeout خاصة بكل مزوّد.

      العناصر النائبة في STT​

      يمكن لقالب الأمر الخاص بك الإشارة إلى العناصر النائبة التالية. يستبدلها Hermes وقت التعبئة، ويُطبّق على كل قيمة اقتباس الـ shell المناسب للسياق المحيط بها (دون اقتباس / داخل علامات اقتباس مفردة / داخل علامات اقتباس مزدوجة)، لذا فالمسارات التي تحتوي على مسافات آمنة.

      العنصر النائبالمعنى
      {input_path}المسار المطلق لملف الصوت المُدخَل (موقعه الأصلي، للقراءة فقط)
      {output_path}المسار المطلق الذي يجب أن يكتب الأمر النص المُفرَّغ إليه
      {output_dir}المجلد الأب لـ {output_path} (مفيد للأدوات المشابهة لـ whisper)
      {format}صيغة الإخراج المُعدّة: txt / json / srt / vtt
      {language}رمز اللغة المُعدّ (القيمة الافتراضية en)
      {model}stt.providers.<name>.model، ويكون فارغًا إن لم يُضبط

      استخدم {{ و }} للأقواس المعقوفة الحرفية (مفيد عند تضمين مقتطفات JSON في الأمر).

      كيف يُقرأ النص المُفرَّغ​

      بعد أن ينتهي أمرك بنجاح:

      1. إذا كان {output_path} موجودًا وغير فارغ → يقرأه Hermes كنص UTF-8.
      2. وإلا، إذا كتب الأمر إلى stdout → يستخدم Hermes ذلك الناتج.
      3. وإلا → خطأ: "Command STT provider wrote no output file and produced no stdout".

      يتيح لك هذا استخدام السجل مع أدوات CLI التي تكتب ملفات (whisper-cli، parakeet-asr) ومع الأوامر ذات السطر الواحد على طريقة curl التي تُخرج النص المُفرَّغ إلى stdout (curl … | jq -r .text).

      مع format: json / srt / vtt، يُعيد Hermes محتوى الملف الخام في الحقل transcript. واستخراج .text من JSON خارج نطاق المُشغّل — فإما أن تضبط format: txt، أو تعالج JSON لاحقًا في مرحلة تالية.

      المفاتيح الاختيارية لمزوّدي أوامر STT​

      المفتاحالقيمة الافتراضيةالمعنى
      timeout300بالثواني؛ تُنهى شجرة العمليات كاملةً عند انقضاء المهلة (start_new_session على Unix، و taskkill /T على Windows).
      formattxtإحدى القيم txt / json / srt / vtt. تحدّد امتداد {output_path}.
      languageenتُمرَّر إلى {language}. وقيمتها الافتراضية stt.language ثم en.
      modelفارغتُمرَّر إلى {model}. ويتجاوزها الوسيط model= الممرَّر إلى transcribe_audio().

      ملاحظات حول سلوك مزوّدي أوامر STT​

      • المزوّدون المدمجون لهم الأولوية دائمًا. تعريف stt.providers.openai: type: command لا يتجاوز معالج OpenAI Whisper الحقيقي. إذ يُحسم الاسم المدمج مبكرًا قبل تشغيل آلية تحديد مزوّدي الأوامر.
      • تنظيف شجرة العمليات. عندما يتجاوز أمرٌ مدة timeout، تُنهى شجرة عملياته بالكامل، لا الـ shell wrapper وحده. لذا تُحصَد بشكل موثوق خطوط ASR طويلة التشغيل التي تُنشئ عمليات فرعية لتحميل النماذج.
      • اقتباس الـ shell تلقائي. العناصر النائبة داخل '…' تحصل على تهريب آمن لعلامات الاقتباس المفردة؛ وداخل "…" تحصل على تهريب لـ $/`/"؛ وخارج علامات الاقتباس تُعالَج بـ shlex.quote. لا تضع علامات اقتباس مسبقًا حول قيم العناصر النائبة.

      أمان مزوّدي أوامر STT​

      يعمل أمر الـ shell بصلاحيات المستخدم نفسه الذي يشغّل Hermes مع وصول كامل إلى نظام الملفات — وهو نموذج الثقة نفسه المتّبع في tts.providers.<name>: type: command و HERMES_LOCAL_STT_COMMAND. لا تعرّف مزوّدي أوامر إلا من مصادر تثق بها.

      مزوّدو الإضافات بلغة Python (STT)​

      لمحرّكات STT غير المدمجة والتي لا يمكن التعبير عنها كأمر shell (لأنها تحتاج إلى Python SDK، أو مصادقة مع تحديث OAuth، أو مقاطع متدفقة، وما إلى ذلك)، سجّل إضافة Python عبر ctx.register_transcription_provider(). تعمل الإضافة جنبًا إلى جنب مع المزوّدين المدمجين الثمانية (local، local_command، groq، openai، mistral، xai، elevenlabs، deepinfra) ومع سجل stt.providers.<name>: type: command — إذ يحتفظ المزوّدون المدمجون بتطبيقاتهم الأصلية ولهم الأولوية دائمًا عند تعارض الأسماء؛ ولمزوّدي الأوامر الأولوية على الإضافات التي تحمل الاسم نفسه (لأن الإعدادات أقرب محليًا من تثبيت الإضافة).

      متى تختار كل خيار (STT)​

      الـ backend لديه…استخدم
      أمر shell واحد يأخذ ملفًا صوتيًا ويُخرج نصًاstt.providers.<name>: type: command (لا حاجة إلى Python)
      المطلوب هو منفذ الطوارئ القديم ذو الأمر الواحد فقطمتغير البيئة HERMES_LOCAL_STT_COMMAND (مُقسَّم إلى argv؛ دون shell ضمني)
      Python SDK دون CLIإضافة register_transcription_provider()
      مصادقة مع تحديث OAuth، أو مقاطع متدفقة، أو بيانات وصفية لقائمة الأصواتإضافة register_transcription_provider()
      مزوّد مدمج يغطي الحالة بالفعل (local، groq، openai، …)اضبط stt.provider: <name> — المزوّدون المدمجون مضمَّنون مباشرةً

      ترتيب التحديد​

      1. stt.provider اسم مزوّد مدمج → توجيه إلى المزوّد المدمج. له الأولوية دائمًا.
      2. stt.provider يطابق stt.providers.<name> مع ضبط command: → مُشغّل مزوّد الأوامر (راجع مزوّدو STT القائمون على أوامر مخصّصة). وله الأولوية على إضافة تحمل الاسم نفسه.
      3. stt.provider يطابق TranscriptionProvider مسجّلًا عبر إضافة → توجيه إلى الإضافة:
        • إذا أعادت الدالة is_available() الخاصة بالإضافة القيمة False (بسبب نقص بيانات الاعتماد أو الـ SDK)، يُظهر الاستدعاء رسالة خطأ بعدم التوفر تحدّد الإضافة المعنية — وليس الرسالة العامة "No STT provider available".
        • وإلا، تُستدعى الدالة transcribe() الخاصة بالإضافة مع model (من الوسيط العام model=، مع الرجوع احتياطيًا إلى stt.<provider>.model) و language (من stt.<provider>.language).
      4. لا يوجد تطابق → خطأ "No STT provider available".

      نطاق الإعدادات الخاص بكل مزوّد​

      تقرأ الإضافات إعداداتها الخاصة بكل مزوّد من stt.<provider> في config.yaml، على غرار قراءة المزوّدين المدمجين لـ stt.openai.model / stt.mistral.model:

      stt:
        provider: my-stt
        my-stt:
          model: whisper-large-v3
          language: ja          # forwarded as language= to transcribe()
          # any other plugin-specific keys go here; read them via your
          # own config.yaml access in __init__/is_available/transcribe

      يُمرّر الموزِّع (dispatcher) القيمتين model و language من هذا القسم؛ أما كل ما عداهما فيمكن للإضافة قراءته بنفسها.

      إضافة بالحد الأدنى​

      ضع ما يلي في ~/.hermes/plugins/my-stt/:

      plugin.yaml:

      name: my-stt
      version: 0.1.0
      description: "My custom Python STT backend"

      __init__.py:

      from agent.transcription_provider import TranscriptionProvider


      class MySTTProvider(TranscriptionProvider):
          @property
          def name(self) -> str:
              return "my-stt"  # what stt.provider matches against

          @property
          def display_name(self) -> str:
              return "My Custom STT"

          def is_available(self) -> bool:
              # Return False when credentials/deps are missing — picker skips
              # this row but the dispatcher still routes here on explicit config.
              import os
              return bool(os.environ.get("MY_STT_API_KEY"))

          def transcribe(self, file_path, *, model=None, language=None, **extra):
              # Return the standard transcribe envelope:
              #   {"success": bool, "transcript": str, "provider": str, "error": str}
              # Do NOT raise — convert exceptions to the error envelope so the
              # gateway/CLI caller sees a consistent shape on failure.
              try:
                  import my_stt_sdk
                  client = my_stt_sdk.Client()
                  text = client.transcribe(open(file_path, "rb"))
                  return {
                      "success": True,
                      "transcript": text,
                      "provider": "my-stt",
                  }
              except Exception as exc:
                  return {
                      "success": False,
                      "transcript": "",
                      "error": f"my-stt failed: {exc}",
                      "provider": "my-stt",
                  }


      def register(ctx):
          ctx.register_transcription_provider(MySTTProvider())

      فعّلها (hermes plugins enable my-stt)، واضبط stt.provider: my-stt في config.yaml، وسيُوجَّه تفريغ الرسائل الصوتية عبر إضافتك.

      Hooks اختيارية​

      أعِد تعريف ما يلي في صنف المزوّد الخاص بك للحصول على تكامل أغنى:

      • list_models() → قائمة من القواميس بالشكل {id, display, languages, max_audio_seconds}.
      • default_model() → سلسلة نصية تُعاد عندما لا يحدّد المستخدم نموذجًا آخر.
      • get_setup_schema() → أعِد {name, badge, tag, env_vars: [{key, prompt, url}]} لتغذية صفوف أداة الاختيار في hermes tools / hermes setup (فئة أداة الاختيار الخاصة بـ STT لم تُطرح بعد — وهذه البيانات الوصفية متاحة للإضافات من أجل التوافق المستقبلي).

      راجع agent/transcription_provider.py للاطلاع على الصنف المجرّد (ABC) الكامل مع docstrings.
