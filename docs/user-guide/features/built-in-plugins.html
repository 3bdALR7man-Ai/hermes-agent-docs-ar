      الإضافات المدمجة

      يأتي Hermes مع مجموعة صغيرة من الإضافات المضمّنة في المستودع. توجد هذه الإضافات تحت <repo>/plugins/<name>/ وتُحمَّل تلقائيًا إلى جانب الإضافات التي يثبّتها المستخدم في ~/.hermes/plugins/. وتستخدم واجهة الإضافات نفسها التي تستخدمها إضافات الجهات الخارجية — hooks، والأدوات، و slash commands — مع فارق أنها تُصان داخل شجرة المستودع.

      راجع صفحة الإضافات (Plugins) للتعرف على نظام الإضافات عمومًا، وصفحة بناء إضافة لـ Hermes لكتابة إضافتك الخاصة.

      كيف يعمل الاكتشاف​

      يفحص PluginManager أربعة مصادر، بالترتيب التالي:

      1. المضمّنة (Bundled) — <repo>/plugins/<name>/ (وهي موضوع هذه الصفحة)
      2. المستخدم (User) — ~/.hermes/plugins/<name>/
      3. المشروع (Project) — ./.hermes/plugins/<name>/ (يتطلب HERMES_ENABLE_PROJECT_PLUGINS=1)
      4. نقاط دخول Pip — hermes_agent.plugins

      عند تعارض الأسماء، تكون الأولوية للمصادر اللاحقة — فإضافة مستخدم باسم disk-cleanup ستحل محل الإضافة المضمّنة.

      يُستثنى plugins/memory/ و plugins/context_engine/ عمدًا من فحص الإضافات المضمّنة. إذ تستخدم هذه المجلدات مسارات اكتشاف خاصة بها، لأن مزوّدي الذاكرة ومحركات السياق (context engines) مزوّدون يُختار واحد منهم فقط، ويُعدّون عبر hermes memory setup / context.engine في الإعدادات.

      الإضافات المضمّنة تتطلب تفعيلًا اختياريًا​

      تأتي الإضافات المضمّنة معطّلة. يعثر عليها الاكتشاف (فتظهر في hermes plugins list وفي واجهة hermes plugins التفاعلية)، لكن لا يُحمَّل أيٌّ منها حتى تفعّله صراحةً:

      hermes plugins enable disk-cleanup

      أو عبر ~/.hermes/config.yaml:

      plugins:
        enabled:
          - disk-cleanup

      هذه هي الآلية نفسها التي تستخدمها الإضافات التي يثبّتها المستخدم. لا تُفعَّل الإضافات المضمّنة تلقائيًا أبدًا — لا عند التثبيت الجديد، ولا للمستخدمين الحاليين عند الترقية إلى إصدار أحدث من Hermes. فأنت تختار تفعيلها صراحةً دائمًا.

      لإيقاف إضافة مضمّنة مرة أخرى:

      hermes plugins disable disk-cleanup
      # or: remove it from plugins.enabled in config.yaml

      disk-cleanup​

      تتتبّع الملفات المؤقتة التي تُنشأ أثناء الجلسات وتزيلها تلقائيًا — سكربتات الاختبار، والمخرجات المؤقتة، وسجلات cron، وملفات تعريف chrome القديمة — دون أن يحتاج الوكيل إلى تذكّر استدعاء أداة.

      آلية العمل:

      Hookالسلوك
      post_tool_callعندما يُنشئ write_file / terminal / patch ملفًا يطابق test_* أو tmp_* أو *.test.* داخل HERMES_HOME أو /tmp/hermes-*، يُتتبَّع بصمت كـ test / temp / cron-output.
      on_session_endإذا تُتُبِّعت أي ملفات اختبار تلقائيًا خلال الدور، يُشغَّل التنظيف الآمن quick ويُسجَّل ملخص من سطر واحد. وفي غير ذلك تبقى صامتة.

      قواعد الحذف:

      الفئةالحدالتأكيد
      testعند نهاية كل جلسةلا يُطلب أبدًا
      temp>7 أيام منذ بدء التتبعلا يُطلب أبدًا
      cron-output>14 يومًا منذ بدء التتبعلا يُطلب أبدًا
      المجلدات الفارغة تحت HERMES_HOMEدائمًالا يُطلب أبدًا
      research>30 يومًا، باستثناء أحدث 10يُطلب دائمًا (في وضع deep فقط)
      chrome-profile>14 يومًا منذ بدء التتبعيُطلب دائمًا (في وضع deep فقط)
      الملفات >500 MBلا تُحذف تلقائيًا أبدًايُطلب دائمًا (في وضع deep فقط)

      Slash command — الأمر /disk-cleanup متاح في جلسات CLI و gateway على حد سواء:

      /disk-cleanup status                     # breakdown + top-10 largest
      /disk-cleanup dry-run                    # preview without deleting
      /disk-cleanup quick                      # run safe cleanup now
      /disk-cleanup deep                       # quick + list items needing confirmation
      /disk-cleanup track <path> <category>    # manual tracking
      /disk-cleanup forget <path>              # stop tracking (does not delete)

      الحالة — كل شيء محفوظ في $HERMES_HOME/disk-cleanup/:

      الملفالمحتوى
      tracked.jsonالمسارات المتتبَّعة مع الفئة والحجم والطابع الزمني
      tracked.json.bakنسخة احتياطية للملف السابق ناتجة عن الكتابة الذرّية (atomic write)
      cleanup.logسجل تدقيق لا يُضاف إليه إلا في نهايته، يوثّق كل عملية track / skip / reject / delete

      الأمان — لا يمس التنظيف إلا المسارات الواقعة تحت HERMES_HOME أو /tmp/hermes-*. وتُرفض نقاط تركيب Windows (/mnt/c/...). ولا تُحذف أبدًا مجلدات الحالة المعروفة في المستوى الأعلى (logs/، memories/، sessions/، cron/، cache/، skills/، plugins/، و disk-cleanup/ نفسه) حتى لو كانت فارغة — فلا يُفرَّغ التثبيت الجديد من محتواه عند انتهاء أول جلسة.

      التفعيل: hermes plugins enable disk-cleanup (أو حدّد مربع الاختيار في hermes plugins).

      التعطيل مجددًا: hermes plugins disable disk-cleanup.

      security-guidance​

      تحذيرات أمنية سريعة قائمة على مطابقة الأنماط عند كتابة الملفات. عندما تحمل استدعاءات الوكيل لـ write_file / patch / skill_manage محتوى يطابق نمط كود معروفًا بخطورته — pickle.load، و yaml.load دون SafeLoader، و eval(، و os.system، و subprocess(..., shell=True)، و child_process.exec في JS، و dangerouslySetInnerHTML في React، و .innerHTML = / .outerHTML = / document.write الخام، و crypto.createCipher في Node، ووضع AES ECB، وتعطيل التحقق من TLS، والمحللات xml.etree / minidom المعرّضة لهجمات XXE، و <script src="//..." > دون SRI، و torch.load دون weights_only=True، وحقن ${{ github.event.* }} في GitHub Actions — تُلحق الإضافة كتلة ⚠️ Security guidance بنتيجة الأداة.

      يظل الملف يُكتب. يقرأ النموذج التحذير في رسالة الأداة ضمن الدور التالي، ويمكنه إما إصلاح الكود أو توثيق سبب كون هذا البناء آمنًا في هذا السياق. لمطابقة الأنماط معدل إيجابيات كاذبة غير هيّن، ولهذا يكون التحذير (لا الحظر) هو الوضع الافتراضي.

      التغطية: 25 قاعدة إجمالًا، تغطي إلغاء التسلسل غير الآمن، وحقن الأوامر، ونقاط XSS، والأخطاء الشائعة في التشفير، و XXE، وسلسلة التوريد (SRI)، وحقن سير عمل CI/CD. بيانات الأنماط نسخة مشتقة حرفية بترخيص Apache-2.0 من مستودع claude-plugins-official التابع لـ Anthropic — راجع ملفَّي LICENSE و NOTICE في الإضافة لمعرفة الإسناد.

      الأوضاع:

      متغير البيئةالتأثير
      (غير مضبوط)وضع التحذير (warn) (الافتراضي) — يُكتب الملف، ويُلحق التحذير بالنتيجة
      SECURITY_GUIDANCE_BLOCK=1وضع الحظر (block) — تُرفض الكتابة، ويُعاد التحذير كسبب للحظر
      SECURITY_GUIDANCE_DISABLE=1مفتاح إيقاف كامل — تُحمَّل الإضافة لكنها لا تفعل شيئًا

      التفعيل: hermes plugins enable security-guidance (أو حدّد مربع الاختيار في hermes plugins).

      التعطيل مجددًا: hermes plugins disable security-guidance.

      ما لا تفعله (حتى الآن): تحتوي إضافة Anthropic الأصلية على طبقتين إضافيتين — مراجعة LLM للفروقات (diff) في كل دور للوكيل يمس ملفات، ومراجعة وكيلية وقت الـ commit تتتبع تدفق البيانات عبر الملفات. ولم تُنقل أيٌّ منهما. ويستطيع الوكيل بالفعل إجراء هذه المراجعات عند الطلب عبر delegate_task.

      observability/langfuse​

      تتتبّع أدوار Hermes واستدعاءات LLM واستدعاءات الأدوات وترسلها إلى Langfuse — وهي منصة مفتوحة المصدر لمراقبة LLM (observability). ينتج span واحد لكل دور، و generation واحد لكل استدعاء API، ومشاهدة أداة واحدة لكل استدعاء أداة. تُستمد إجماليات الاستخدام وأعداد الـ tokens حسب النوع وتقديرات التكلفة من أرقام agent.usage_pricing المعتمدة في Hermes، بحيث تعرض لوحة Langfuse التفصيل نفسه (input / output / cache_read_input_tokens / cache_creation_input_tokens / reasoning_tokens) الذي يظهر في hermes logs.

      تعمل الإضافة بمبدأ fail-open: فغياب الـ SDK، أو غياب بيانات الاعتماد، أو حدوث خطأ عابر في Langfuse — كلها تتحول إلى عملية صامتة لا تفعل شيئًا داخل الـ hook. ولا تتأثر حلقة الوكيل أبدًا.

      الإعداد (تفاعلي — موصى به):

      hermes tools          # → Langfuse Observability → Cloud or Self-Hosted

      يجمع المعالج مفاتيحك، وينفّذ pip install لتثبيت SDK langfuse، ويضيف observability/langfuse إلى plugins.enabled نيابةً عنك. أعد تشغيل Hermes وسيُرسل الدور التالي تتبّعًا (trace).

      الإعداد (يدوي):

      pip install langfuse
      hermes plugins enable observability/langfuse

      ثم ضع بيانات الاعتماد في ~/.hermes/.env:

      HERMES_LANGFUSE_PUBLIC_KEY=pk-lf-...
      HERMES_LANGFUSE_SECRET_KEY=sk-lf-...
      HERMES_LANGFUSE_BASE_URL=https://cloud.langfuse.com   # or your self-hosted URL

      آلية العمل:

      Hookالسلوك
      pre_api_request / pre_llm_callفتح (أو إعادة استخدام) span جذري لكل دور باسم "Hermes turn". وبدء مشاهدة فرعية من نوع generation لاستدعاء API هذا، مع الرسائل الأخيرة بعد تسلسلها كمدخلات.
      post_api_request / post_llm_callإغلاق الـ generation، وإرفاق usage_details و cost_details و finish_reason ومخرجات المساعد + استدعاءات الأدوات. وإذا لم توجد استدعاءات أدوات وكان المحتوى غير فارغ، يُغلق الدور.
      pre_tool_callبدء مشاهدة فرعية من نوع tool مع args بعد تنقيتها.
      post_tool_callإغلاق مشاهدة الأداة مع result بعد تنقيتها. تُلخَّص حمولات read_file (البداية + النهاية + عدد الأسطر المحذوفة) كي تبقى قراءة ملف ضخم ضمن حد HERMES_LANGFUSE_MAX_CHARS.

      يعتمد تجميع الجلسات على معرّف جلسة Hermes (أو معرّف المهمة في حالة الـ subagents) عبر langfuse.propagate_attributes، بحيث يندرج كل ما يجري في جلسة hermes chat واحدة تحت جلسة Langfuse واحدة.

      التحقق:

      hermes plugins list                 # observability/langfuse should show "enabled"
      hermes chat -q "hello"              # check the Langfuse UI for a "Hermes turn" trace

      ضبط اختياري (في .env):

      المتغيرالقيمة الافتراضيةالغرض
      HERMES_LANGFUSE_ENV—وسم البيئة على التتبّعات (production، staging، …)
      HERMES_LANGFUSE_RELEASE—وسم الإصدار
      HERMES_LANGFUSE_SAMPLE_RATE1.0معدل أخذ العينات الممرَّر إلى الـ SDK (0.0–1.0)
      HERMES_LANGFUSE_MAX_CHARS12000حد الاقتطاع لكل حقل في محتوى الرسائل / وسائط الأدوات / نتائج الأدوات
      HERMES_LANGFUSE_DEBUGfalseتسجيل مفصّل للإضافة في agent.log

      تُقبل متغيرات البيئة التي تبدأ بالبادئة Hermes ومتغيرات SDK القياسية (LANGFUSE_PUBLIC_KEY، LANGFUSE_SECRET_KEY، LANGFUSE_BASE_URL) على حد سواء — وتكون الأولوية للمتغيرات ذات البادئة Hermes عند ضبط الاثنين.

      الأداء: يُخزَّن عميل Langfuse مؤقتًا بعد أول استدعاء لـ hook. وإذا كانت بيانات الاعتماد أو الـ SDK مفقودة، يُخزَّن هذا القرار مؤقتًا أيضًا — فتعود الـ hooks اللاحقة فورًا دون إعادة فحص متغيرات البيئة أو إعادة تحميل الإعدادات.

      التعطيل: hermes plugins disable observability/langfuse. تظل وحدة الإضافة تُكتشف، لكن لا يُشغَّل أي كود منها حتى تعيد تفعيلها.

      التكامل الأصلي مع NeMo Relay (ملاحظة ترحيل)​

      لم يعد NeMo Relay إضافة مضمّنة في Hermes. لا تنفّذ hermes plugins enable observability/nemo_relay؛ فنواة Hermes باتت تتولى الآن دورات حياة الجلسة والدور و LLM والأدوات في Relay.

      لتفعيل middleware أو exporters الخاصة بـ Relay، أنشئ ملف plugins.toml قياسيًا لـ Relay، ثم اضبط HERMES_NEMO_RELAY_PLUGINS_TOML ليشير إلى هذا الملف قبل تشغيل Hermes. تسري هذه السياسة على مستوى العملية لكل profile تستضيفه عملية Hermes تلك. راجع إعدادات المراقبة في NeMo Relay لخيارات ATOF و ATIF و OpenTelemetry.

      لم تعد الإعدادات القديمة HERMES_NEMO_RELAY_ATOF_* و HERMES_NEMO_RELAY_ATIF_* تفعّل الـ exporters. ويُبلغ hermes doctor عن هذه الإعدادات القديمة عندما لا يكون قد اختير ملف plugins.toml بديل.

      تقسيم span الجلسة (الجلسات المستمرة)​

      يُصدِّر Relay الـ span عند إغلاق نطاقه. وقد تُبقي جلسة gateway مستمرة span الجلسة مفتوحًا لأيام، رغم أن span كل دور يُصدَّر بشكل طبيعي. يؤدي التقسيم الاختياري إلى تدوير نطاق الجلسة وحده عند حدود الدور:

      gateway:
        telemetry:
          session_segments:
            on_compaction: false  # rotate after context compaction
            max_turns: 0          # 0 = unlimited; N = turns per segment
      المفتاحالقيمة الافتراضيةالسلوك
      on_compactionfalseالتدوير بعد اكتمال الضغط (compaction)، عند حدود الدور التالي.
      max_turns0التدوير بعد كل N من الأدوار المكتملة؛ والقيمة 0 تعطّل هذا الحد.

      تحافظ القيمتان الافتراضيتان على نطاق جلسة واحد طوال الجلسة كاملة. وتحتفظ الـ spans المُدوَّرة بقيمة session_id نفسها، وتضيف hermes.session.segment إضافةً إلى hermes.session.segment_reason (compaction أو max_turns).

      google_meet​

      تتيح للوكيل الانضمام إلى مكالمات Google Meet وتفريغها نصيًا والمشاركة فيها — تدوين ملاحظات الاجتماع، وتلخيص النقاش بعد انتهائه، ومتابعة نقاط محددة، و(اختياريًا) نطق الردود داخل المكالمة عبر TTS.

      ما تضيفه:

      • مشاركًا افتراضيًا دون واجهة (headless) ينضم إلى رابط Meet باستخدام أتمتة المتصفح
      • تفريغًا نصيًا مباشرًا لصوت الاجتماع عبر مزوّد STT المُعدّ
      • مجموعة أدوات (toolset) تضم meet_join / meet_status / meet_transcript / meet_leave / meet_say يستدعيها الوكيل للانضمام إلى المكالمات، والاستعلام الدوري عن النص المُفرَّغ المباشر، والتصرف بناءً على ما سمعه
      • مخرجات ما بعد الاجتماع (النص المُفرَّغ، والحالة) محفوظة تحت ~/.hermes/workspace/meetings/<meeting_id>/

      الإعداد:

      hermes plugins enable google_meet
      hermes meet setup   # preflight: playwright, chromium, auth file
      hermes meet auth    # opens a browser to sign into Google and saves session state —
                          # needs a Google account with Meet access. Host approval may be
                          # required if the meeting enforces "only invited participants can join".

      الاستخدام من المحادثة:

      "انضم إلى meet.google.com/abc-defg-hij ودوّن الملاحظات. وبعد انتهاء المكالمة، أرسل لي ملخصًا يتضمن بنود العمل المطلوبة."

      يبدأ الوكيل عملية الانضمام إلى الاجتماع، ويبث التفريغ النصي إلى سياقه مع تقدّم المكالمة، ثم يُنتج ملخصًا منظّمًا عند انتهاء الاجتماع (أو عندما تطلب منه التوقف).

      متى تستخدمها: اجتماعات standup المتكررة التي تريد فيها بوتًا يفرّغ النقاش ويلخّصه للحاضرين غير المتزامنين؛ والمقابلات ذات الطابع الاستجوابي التي تريد لها ملاحظات منظّمة؛ وأي حالة كنت ستحتاج فيها عادةً إلى Fireflies / Otter / Grain. وإذا كنت تفضّل ألا يستمع ذكاء اصطناعي إلى الاجتماع — فلا تفعّلها.

      التعطيل: hermes plugins disable google_meet. تبقى أي نصوص مُفرَّغة محفوظة في ~/.hermes/workspace/meetings/ حتى تحذفها.

      hermes-achievements​

      تضيف تبويب إنجازات على طريقة Steam إلى لوحة التحكم — أكثر من 60 شارة قابلة للجمع ومتدرجة المستويات، تُولَّد من سجل جلساتك الفعلي في Hermes. تشمل إنجازات سلاسل الأدوات، وأنماط تصحيح الأخطاء، وسلاسل vibe-coding المتتالية، واستخدام المهارات والذاكرة، وتنوع النماذج والمزوّدين، وعادات نمط الحياة (جلسات عطلة نهاية الأسبوع والجلسات الليلية). كتبها في الأصل @PCinkusz كإضافة خارجية، ثم ضُمّت إلى شجرة المستودع لتبقى متزامنة مع تغييرات ميزات Hermes.

      آلية العمل:

      • تفحص سجل جلساتك الكامل في ~/.hermes/state.db على الـ backend الخاص بلوحة التحكم
      • تُخزَّن إحصاءات كل جلسة مؤقتًا بحسب البصمة (started_at, last_active)، بحيث لا يُعاد تحليل سوى الجلسات الجديدة أو المتغيرة في عمليات الفحص اللاحقة
      • يعمل أول فحص على الإطلاق في خيط (thread) خلفي — فلا تتوقف لوحة التحكم أبدًا بانتظاره، حتى مع قواعد بيانات تضم آلاف الجلسات
      • تُحفظ حالة فتح الشارات في $HERMES_HOME/plugins/hermes-achievements/state.json

      تدرّج المستويات: Copper → Silver → Gold → Diamond → Olympian. تعرض كل بطاقة قسم "What counts" الذي يوضح المقياس الدقيق الذي يجري تتبّعه.

      حالات الإنجازات:

      الحالةالمعنى
      Unlockedتحقق مستوى واحد على الأقل
      Discoveredإنجاز معروف، والتقدم فيه ظاهر، لكنه لم يُحقَّق بعد
      Secretمخفي حتى يرصد Hermes أول إشارة ذات صلة في سجلك

      API — تُركَّب المسارات تحت /api/plugins/hermes-achievements/:

      Endpointالغرض
      GET /achievementsالكتالوج الكامل مع حالة فتح كل شارة (ويُرجع عنصرًا نائبًا بحالة الانتظار أثناء تشغيل أول فحص بارد)
      GET /scan-statusحالة الماسح الخلفي: idle / running / failed، ومدة آخر تشغيل، وعدد مرات التشغيل
      GET /recent-unlocksآخر عشرين شارة فُتحت، الأحدث أولًا
      GET /sessions/{id}/badgesالشارات المُكتسبة أساسًا في جلسة واحدة محددة
      POST /rescanإعادة فحص يدوية متزامنة (تحجب التنفيذ؛ استخدمها عندما ينقر المستخدم زر إعادة الفحص)
      POST /reset-stateمسح سجل فتح الشارات واللقطة (snapshot) المخزّنة مؤقتًا

      ملفات الحالة — توجد تحت $HERMES_HOME/plugins/hermes-achievements/:

      الملفالمحتوى
      state.jsonسجل فتح الشارات: أي الشارات اكتسبتها ومتى. ويبقى ثابتًا عبر تحديثات Hermes.
      scan_snapshot.jsonحمولة آخر فحص مكتمل (تُقدَّم فورًا عند تحميل لوحة التحكم)
      scan_checkpoint.jsonذاكرة مؤقتة لإحصاءات كل جلسة مفهرسة بالبصمة (تجعل عمليات إعادة الفحص الدافئة سريعة)

      ملاحظات حول الأداء:

      • يستغرق الفحص البارد لنحو 8,000 جلسة بضع دقائق. ويعمل في خيط خلفي عند أول طلب للوحة التحكم؛ فترى الواجهة عنصرًا نائبًا بحالة الانتظار وتستعلم دوريًا من /scan-status.
      • نتائج تدريجية أثناء الفحص البارد — ينشر الماسح لقطة جزئية كل نحو 250 جلسة، بحيث يعرض كل تحديث للوحة التحكم مزيدًا من الشارات المفتوحة مع تقدّم الفحص. فلا تحدّق في أصفار لدقائق.
      • تعيد عملية إعادة الفحص الدافئة استخدام إحصاءات كل جلسة تطابق بصمتها started_at + last_active نقطة الحفظ — فتكتمل في ثوانٍ حتى مع السجلات الكبيرة.
      • مدة صلاحية (TTL) اللقطة المخزّنة في الذاكرة 120 ثانية؛ وتُقدَّم اللقطة القديمة فورًا للطلبات التي تصل بعد انتهاء الصلاحية مع بدء تحديث في الخلفية. فلن تنتظر أمام مؤشر تحميل لمجرد انتهاء الـ TTL.

      التفعيل: لا شيء يحتاج إلى تفعيل — hermes-achievements إضافة خاصة بلوحة التحكم فقط (بلا hooks لدورة الحياة، وبلا أدوات مرئية للنموذج). وتُسجِّل نفسها تلقائيًا كتبويب في hermes dashboard عند أول تشغيل. لا يتحكم إعداد plugins.enabled إلا في إضافات دورة الحياة والأدوات؛ أما إضافات لوحة التحكم فتُكتشف فقط عبر ملف dashboard/manifest.json الخاص بها.

      إلغاء الاشتراك: احذف plugins/hermes-achievements/dashboard/manifest.json أو غيّر اسمه، أو تجاوزه بإضافة مستخدم بالاسم نفسه في ~/.hermes/plugins/hermes-achievements/ لا تتضمن لوحة تحكم. تبقى ملفات حالة الإضافة تحت $HERMES_HOME/plugins/hermes-achievements/ — لذا تحافظ إعادة التثبيت على سجل الشارات التي فتحتها.

      إضافة إضافة مضمّنة​

      تُكتب الإضافات المضمّنة تمامًا مثل أي إضافة أخرى لـ Hermes — راجع بناء إضافة لـ Hermes. والفروقات الوحيدة هي:

      • يوجد المجلد في <repo>/plugins/<name>/ بدلًا من ~/.hermes/plugins/<name>/
      • يُعرض مصدر الـ manifest على أنه bundled في hermes plugins list
      • تتجاوز إضافات المستخدم التي تحمل الاسم نفسه النسخة المضمّنة

      تكون الإضافة مرشحة جيدة للتضمين عندما:

      • لا تكون لها اعتماديات اختيارية (أو تكون اعتمادياتها ضمن اعتماديات pip install .[all] أصلًا)
      • يفيد سلوكها معظم المستخدمين، ويكون من المنطقي تفعيله مع إمكانية إلغائه بدلًا من اشتراط تفعيله
      • يرتبط منطقها بـ hooks دورة الحياة التي كان على الوكيل خلافًا لذلك أن يتذكر استدعاءها
      • تُكمّل قدرة أساسية دون توسيع مجموعة الأدوات المرئية للنموذج

      أمثلة معاكسة — أشياء ينبغي أن تبقى إضافات يثبّتها المستخدم لا مضمّنة: تكاملات الجهات الخارجية التي تتطلب مفاتيح API، وسير العمل المتخصصة، وشجرات الاعتماديات الكبيرة، وأي شيء من شأنه أن يغيّر سلوك الوكيل تغييرًا ملموسًا افتراضيًا.
