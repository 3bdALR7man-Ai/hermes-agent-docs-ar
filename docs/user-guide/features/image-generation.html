      توليد الصور

      يولّد Hermes Agent الصور انطلاقًا من prompts نصية عبر FAL.ai. ويدعم أحد عشر نموذجًا جاهزة للاستخدام مباشرةً، لكل منها موازنات مختلفة بين السرعة والجودة والتكلفة. ويمكن للمستخدم ضبط النموذج النشط عبر hermes tools، ويُحفَظ اختياره في config.yaml.

      الإعداد​

      مشتركو Nous

      إذا كان لديك اشتراك مدفوع في Nous Portal، فيمكنك استخدام توليد الصور عبر Tool Gateway دون مفتاح FAL API. ويبقى اختيارك للنموذج محفوظًا في كلا المسارين. يمكن للتثبيتات الجديدة تشغيل hermes setup --portal لتسجيل الدخول وتفعيل جميع أدوات الـ gateway دفعة واحدة؛ أما التثبيتات الحالية فيمكنها اختيار Nous Subscription بوصفه الـ backend لتوليد الصور عبر hermes tools.

      إذا أعاد الـ gateway المُدار الاستجابة HTTP 4xx لنموذج معين، فهذا يعني أن ذلك النموذج لم يُمرَّر بعد عبر الـ proxy من جهة البوابة (portal) — وسيخبرك الوكيل بذلك مع خطوات المعالجة (التبديل إلى FAL.ai في hermes tools باستخدام FAL_KEY الخاص بك للوصول المباشر، أو اختيار نموذج مختلف).

      الحصول على مفتاح FAL API​

      1. أنشئ حسابًا على fal.ai
      2. أنشئ مفتاح API من لوحة التحكم الخاصة بك

      الإعداد واختيار النموذج​

      شغّل أمر الأدوات:

      hermes tools

      انتقل إلى 🎨 Image Generation، واختر الـ backend (Nous Subscription أو FAL.ai)، وبعدها تعرض أداة الاختيار جميع النماذج المدعومة في جدول بأعمدة محاذاة — استخدم مفاتيح الأسهم للتنقل، و Enter للاختيار:

        Model                          Speed    Strengths                    Price
        fal-ai/flux-2/klein/9b         <1s      Fast, crisp text             $0.006/MP   ← currently in use
        fal-ai/flux-2-pro              ~6s      Studio photorealism          $0.03/MP
        fal-ai/z-image/turbo           ~2s      Bilingual EN/CN, 6B          $0.005/MP
        ...

      يُحفَظ اختيارك في config.yaml:

      image_gen:
        provider: fal                 # `nous` if you picked Nous Subscription
        model: fal-ai/flux-2/klein/9b
        max_parallel_requests: 4      # concurrent images in one tool-call batch

      يمثّل image_gen.provider مفتاح الاختيار الوحيد: القيمة nous توجّه الطلبات عبر Tool Gateway المُدار؛ واسم المورّد (fal، openai، xai، krea، ...) يتصل مباشرةً باستخدام مفتاحك الخاص. يتبع وقت التشغيل هذا الاختيار المحفوظ دائمًا — إذ يُتجاهَل FAL_KEY الموجود في .env ما دام الإعداد provider: nous، ويؤدي provider: fal دون FAL_KEY إلى الخطأ image_gen is configured to use fal (set via hermes tools), but FAL_KEY is not set. Run 'hermes tools' to change it. بدلًا من إعادة التوجيه بصمت. غيّر المزوّدين عبر hermes tools، لا بإضافة المفاتيح أو حذفها. (القيمة المنطقية القديمة use_gateway موروثة (legacy) — ما زالت تُقرأ على أنها nous عندما تكون true، لكنها لم تعد تُكتب أبدًا.)

      القيمة الافتراضية لـ max_parallel_requests هي 4. يقيّدها Hermes بحيث لا تقل عن واحد ولا تتجاوز الحد العام لعمّال الأدوات (tool-worker)، فيتلقى مزوّدو الصور طلبات متوازية محدودة دون السماح لدفعة صور بتجاوز سقف التزامن الخاص بالوكيل.

      OpenRouter: كتالوج Image API الكامل​

      مع image_gen.provider: openrouter، تعرض أداة اختيار النماذج كتالوج الصور الحي الكامل لدى OpenRouter — أي نماذج Image API المخصّصة (Seedream و FLUX.2 و Recraft و Qwen Image و MAI و Krea و Riverflow و Grok Imagine وغيرها — أكثر من 40 معرّفًا) مدمجةً مع نماذج الصور في chat-completions. يُجلَب الكتالوج مباشرةً من GET /images/models و GET /models، لذا تظهر النماذج الجديدة في أداة الاختيار بمجرد أن يوفّرها OpenRouter؛ دون الحاجة إلى تحديث Hermes. ويوجّه التوليد كل نموذج تلقائيًا إلى الواجهة التي تخدمه (POST /images/generations المخصّصة أو chat-completions). يمرّر Nous Portal بروتوكول chat-completions فقط، لذا تعرض أداة الاختيار الخاصة به النماذج التي تُخدَم عبر المحادثة فقط.

      توضع الإعدادات الاختيارية لكل طلب الخاصة بنماذج Image API ضمن قسم الإعدادات المخصّص لها (أو عبر متغيرات البيئة OPENROUTER_IMAGE_API_*):

      image_gen:
        provider: openrouter
        model: bytedance-seed/seedream-4.5
        openrouter:
          resolution: 2K        # model-dependent: 1K / 2K / 4K
          quality: high         # gpt-image models
          output_format: png

      جودة GPT-Image​

      جودة طلبات fal-ai/gpt-image-1.5 و fal-ai/gpt-image-2 مثبّتة على medium (~$0.034–$0.06/image بدقة 1024×1024). لا نتيح المستويين low / high كخيار للمستخدم حتى تبقى فوترة Nous Portal قابلة للتنبؤ لجميع المستخدمين — إذ يتراوح فرق التكلفة بين المستويات من 3 إلى 22 ضعفًا. إذا أردت خيارًا أرخص، فاختر Klein 9B أو Z-Image Turbo؛ وإذا أردت جودة أعلى، فاستخدم Nano Banana Pro أو Recraft V4 Pro.

      Meta Model API: Muse Image​

      مع image_gen.provider: meta-ai، تُولَّد الصور عبر Meta Model API (https://api.meta.ai/v1)، وهو الـ endpoint نفسه المتوافق مع OpenAI الذي يخدم نماذج المحادثة Muse Spark. وهو الرفيق الخاص بتوليد الصور لمزوّد المحادثة المضمّن meta-ai.

      النموذجالسرعةنقاط القوةالسعر
      muse-image-1.0 (الافتراضي)~10sتوليد الصور عبر Meta Model API$0.01/image
      image_gen:
        provider: meta-ai
        model: muse-image-1.0

      تعيد المصادقة استخدام متغيرات البيئة نفسها الخاصة بمزوّد المحادثة من Meta — MODEL_API_KEY (الاسم الموثّق لدى Meta)، مع قبول META_API_KEY / META_MODEL_API_KEY كأسماء بديلة. اضبط META_BASE_URL للإشارة إلى proxy أو مضيف بديل. يقتصر الدعم حاليًا على تحويل النص إلى صورة فقط؛ وتُحفَظ الاستجابات في $HERMES_HOME/cache/images/.

      FAL: GPT Image 2.5​

      اختر GPT Image 2.5 Flare أو GPT Image 2.5 Sunburst ضمن hermes tools → Image Generation → FAL.ai. معرّفات النماذج هي:

      • openai/gpt-image-2.5/flare/text-to-image
      • openai/gpt-image-2.5/sunburst/text-to-image

      على سبيل المثال:

      hermes config set image_gen.provider fal
      hermes config set image_gen.model openai/gpt-image-2.5/flare/text-to-image

      يؤدي تمرير image_url أو صور مرجعية إلى الاختيار التلقائي لـ endpoint openai/gpt-image-2.5/flare/edit أو openai/gpt-image-2.5/sunburst/edit المقابل. ويقبل كلاهما حتى 16 صورة مصدرية. يثبّت Hermes الجودة على medium، تماشيًا مع سياسته الحالية لـ FAL GPT Image بدلًا من القيمة الافتراضية الأعلى تكلفةً لدى FAL وهي high. يستخدم الوضعان الأفقي والعمودي إعدادات 4:3 المسبقة لاستيفاء الحد الأدنى لعدد البكسلات؛ أما المربع فيستخدم square_hd. ويبقى تكبير الدقة (upscaling) معطّلًا ما لم يُطلَب.

      تحتسب FAL الرسوم بحسب الـ tokens، لا بسعر ثابت للصورة: $5/M لإدخال النص، و$1.25/M لإدخال النص المخزّن مؤقتًا، و$10/M لإخراج النص، و$8/M لإدخال الصور، و$2/M لإدخال الصور المخزّن مؤقتًا، و $30/M لإخراج الصور، مع التقريب للأعلى إلى $0.0001 لكل طلب. راجع صفحتي Flare و Sunburst. يتطلب استخدام FAL مباشرةً مفتاح FAL_KEY ممولًا برصيد؛ أما التوفر عبر الـ gateway المُدار فيعتمد على قائمة الـ endpoints المسموح بها في ذلك الـ gateway، ولا يُستدَل عليه من توفر النموذج لدى FAL. وتبقى القيم الافتراضية الحالية للمزوّد والنموذج دون تغيير.

      OpenAI API: GPT Image 2.5​

      يدعم المزوّد OpenAI نموذجي GPT Image 2.5 Flare (للإنشاء اليومي السريع) و Sunburst (للتوليد والتحرير بدقة)، باستخدام OPENAI_API_KEY. اخترهما عبر hermes tools → Image Generation → OpenAI، أو اضبط:

      hermes config set image_gen.provider openai
      hermes config set image_gen.openai.model gpt-image-2.5-flare

      يستخدم gpt-image-2.5-flare و gpt-image-2.5-sunburst الجودة التلقائية. أضف -low أو -medium أو -high أو -xhigh أو -max لاختيار جودة ثابتة، مثل gpt-image-2.5-sunburst-high. ويدعم كلاهما التوليد والتحرير مع ما يصل إلى 16 صورة مرجعية. وتبقى اختيارات GPT Image 2 الحالية والقيمة الافتراضية gpt-image-2-medium دون تغيير.

      هذا استخدام مدفوع لـ API، منفصل عن اشتراك ChatGPT/Codex. تبلغ تكلفة كلا النموذجين $5 لكل مليون token من إدخال النص، و$8 لكل مليون token من إدخال الصور، و $30 لكل مليون token من إخراج الصور (وأسعار الإدخال المخزّن مؤقتًا هي $1.25 و$2 على التوالي). تختلف تكلفة الصورة الواحدة بحسب الاستخدام؛ ولا تقدّر حاسبة GPT Image 2 استهلاك الـ tokens في الإصدار 2.5. راجع الوثائق الرسمية لـ Flare و Sunburst.

      يبقى المزوّد OpenAI (Codex auth) منفصلًا: فالـ backend الخاص به قد يقبل قيمة لنموذج الصور دون أن يلتزم بذلك الاختيار، لذا فإن نجاح توليد صورة وحده لا يثبت أن التوجيه تم إلى Flare أو Sunburst. تُتاح هذه الاختيارات عبر مزوّد OpenAI API المباشر و FAL، لا كاختيارات مُتحقَّق منها عبر Codex auth.

      الاستخدام​

      المخطط (schema) الذي يراه الوكيل مبسّط عن قصد — إذ يعتمد النموذج ما قمت بإعداده أيًّا كان:

      Generate an image of a serene mountain landscape with cherry blossoms
      Create a square portrait of a wise old owl — use the typography model
      Make me a futuristic cityscape, landscape orientation

      تحويل صورة إلى صورة / التحرير​

      الأداة نفسها image_generate تحرّر الصور الموجودة أيضًا عندما يدعم النموذج النشط ذلك — مرّر صورة مصدرية وسيوجّه الـ backend الطلب تلقائيًا إلى endpoint التحرير الخاص به (على غرار طريقة تعامل video_generate مع تحويل الصورة إلى فيديو). وإذا أغفلت الصورة المصدرية، يصبح الطلب تحويلًا عاديًا من نص إلى صورة.

      Take this photo and make it a rainy Tokyo street at night → <image>
      Blend these two product shots into one hero image → <image1> <image2>

      يتحكم مُدخلان في عملية التحرير:

      • image_url — الصورة المصدرية الأساسية المراد تحريرها/تحويلها (URL عام أو مسار محلي).
      • reference_image_urls — مراجع إضافية للأسلوب/التكوين (بحد أقصى يختلف بحسب النموذج).

      نماذج FAL التي تملك endpoint للتحرير: flux-2/klein/9b، flux-2-pro، nano-banana-pro، gpt-image-1.5، gpt-image-2، ideogram/v3، و qwen-image، إضافةً إلى GPT Image 2.5 Flare و Sunburst المذكورين أعلاه. أما نماذج FAL المخصّصة لتحويل النص إلى صورة فقط (z-image/turbo، recraft، krea/*) فترفض مدخلات الصور برسالة خطأ واضحة توجّهك إلى نموذج قادر على التحرير.

      دعم OpenAI (Codex auth) بأفضل جهد

      تستضيف واجهة Codex (chatgpt.com/backend-api/codex) الأداة image_generation كأداة قد يستدعيها نموذج المحادثة، ولا يستطيع Hermes فرض الاستدعاء — إذ يرفض الـ backend كل أشكال tool_choice للأدوات المستضافة، لذا يعتمد الطلب على التعليمات لتوجيه النموذج. وعندما يمتنع النموذج المضيف عن استدعاء الأداة، يفشل الاستدعاء بالخطأ empty_response. كما أُفيد بأن إمكانية الوصول إلى أداة الصور المستضافة أصلًا تختلف من حساب إلى آخر. إذا كنت تحتاج إلى أن يعمل توليد الصور بشكل حتمي، فاضبط الـ backend OpenAI (مفتاح API) أو FAL أو xAI بدلًا من ذلك.

      تُعرَض قدرة النموذج النشط على التحرير في وصف الأداة وقت التشغيل، فيعرف الوكيل ما إذا كان image_url سيُحترَم قبل أن يستدعي الأداة.

      نسب الأبعاد​

      تقبل جميع النماذج نسب الأبعاد الثلاث نفسها من منظور الوكيل. وداخليًا، تُملأ مواصفات الحجم الأصلية لكل نموذج تلقائيًا:

      مُدخل الوكيلimage_size (flux/z-image/qwen/recraft/ideogram)aspect_ratio (nano-banana-pro)image_size (gpt-image-1.5)image_size (gpt-image-2)
      landscapelandscape_16_916:91536x1024landscape_4_3 (1024×768)
      squaresquare_hd1:11024x1024square_hd (1024×1024)
      portraitportrait_16_99:161024x1536portrait_4_3 (768×1024)

      يُربَط GPT Image 2 بإعدادات 4:3 المسبقة بدلًا من 16:9 لأن الحد الأدنى لعدد البكسلات لديه هو 655,360 — وسيُرفَض الإعداد المسبق landscape_16_9 (1024×576 = 589,824).

      يحدث هذا التحويل في _build_fal_payload() — فلا يحتاج كود الوكيل أبدًا إلى معرفة الفروق في المخطط بين النماذج.

      تكبير الدقة (Upscaling)​

      بالتفعيل الاختياري فقط​

      لا يكبّر أي نموذج الدقة افتراضيًا. فنماذج الصور الحديثة تُخرج أفضل جودة لديها بشكل أصلي، ومكبّرات الدقة المتاحة هي محسّنات إبداعية (تمريرات diffusion) قد تعيد رسم المحتوى بشكل خفي — مما يُضعف النصوص المعروضة والوجوه والتفاصيل الدقيقة. لذلك لا يعمل تكبير الدقة إلا عندما يطلبه الوكيل صراحةً.

      المعامل upscale (تفعيل اختياري لكل استدعاء)​

      • upscale: true — يضيف تمريرة عالية الدقة بعد التوليد:
      الـ Backendمكبّر الدقة
      FAL.aiClarity Upscaler (2×، +$0.03/MP)
      KreaKrea Enhance (2×، بحد أقصى 8K)
      الـ backends الأخرىلا يوجد مكبّر دقة؛ تُعاد الدقة الأصلية
      • upscale: false / أو إغفاله — الدقة الأصلية (الافتراضي)

      يقبل video_generate أيضًا upscale: true على الـ backend الخاص بـ FAL، فيضيف مكبّر الفيديو SeedVR2 من ByteDance (2×، $0.001/MP من الفيديو الناتج) بعد التوليد.

      عند تشغيل تمريرة الصور في FAL، تُستخدم الإعدادات التالية:

      الإعدادالقيمة
      معامل التكبير (Upscale factor)2×
      الإبداعية (Creativity)0.35
      التشابه (Resemblance)0.6
      مقياس التوجيه (Guidance scale)4
      خطوات الـ inference18

      إذا فشل تكبير الدقة (مشكلة في الشبكة، أو حدّ المعدل)، تُعاد الصورة الأصلية تلقائيًا. وتتضمن الاستجابة upscaled: true/false ليعرف الوكيل الدقة التي حصل عليها.

      آلية العمل الداخلية​

      1. تحديد النموذج — تقرأ _resolve_fal_model() القيمة image_gen.model من config.yaml، ثم تعود احتياطيًا إلى متغير البيئة FAL_IMAGE_MODEL، ثم إلى fal-ai/flux-2/klein/9b.
      2. بناء الحمولة (payload) — تحوّل _build_fal_payload() قيمة aspect_ratio إلى الصيغة الأصلية للنموذج (enum للإعداد المسبق، أو enum لنسبة الأبعاد، أو قيمة GPT حرفية)، وتدمج المعاملات الافتراضية للنموذج، وتطبّق أي تجاوزات من المستدعي، ثم ترشّح النتيجة وفق القائمة البيضاء supports الخاصة بالنموذج حتى لا تُرسَل المفاتيح غير المدعومة أبدًا.
      3. الإرسال — توجّه _submit_fal_request() الطلب عبر بيانات اعتماد FAL المباشرة أو عبر Nous gateway المُدار، بحسب الاختيار المحفوظ في image_gen.provider.
      4. تكبير الدقة — لا يعمل إلا عندما يمرّر الوكيل upscale: true؛ فالقيمة الافتراضية في الكتالوج معطّلة لكل النماذج.
      5. التسليم — يُعاد URL الصورة النهائية إلى الوكيل، الذي يُصدر الوسم MEDIA:<url> الذي تحوّله محوّلات المنصات (platform adapters) إلى وسائط أصلية.

      تصحيح الأخطاء​

      فعّل سجلات تصحيح الأخطاء:

      export IMAGE_TOOLS_DEBUG=true

      تُكتب سجلات تصحيح الأخطاء في ./logs/image_tools_debug_<session_id>.json مع تفاصيل كل استدعاء (النموذج، والمعاملات، والتوقيت، والأخطاء).

      القيود​

      • تتطلب بيانات اعتماد للـ backend النشط (FAL FAL_KEY / Nous Subscription، OPENAI_API_KEY، xAI OAuth، KREA_API_KEY)
      • التحرير يعتمد على النموذج — لا يعمل تحويل الصورة إلى صورة إلا على النماذج القادرة على التحرير (راجع الجدول أعلاه)؛ أما النماذج المخصّصة لتحويل النص إلى صورة فقط فترفض مدخلات الصور برسالة خطأ واضحة
      • عناوين URL مؤقتة — تُعيد الـ backends عناوين URL مستضافة تنتهي صلاحيتها بعد ساعات/أيام؛ ويحفظ Hermes محتواها في الـ cache المحلي لكي يظل التسليم يعمل بعد انتهاء الصلاحية
      • قيود خاصة بكل نموذج — بعض النماذج لا تدعم seed و num_inference_steps وغيرها. يُسقط المرشّح supports / edit_supports المعاملات غير المدعومة بصمت؛ وهذا سلوك متوقع
