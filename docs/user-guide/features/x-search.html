      البحث في X (Twitter)

      تتيح أداة x_search للوكيل البحث مباشرةً في منشورات X (Twitter) والملفات الشخصية والسلاسل (threads). وهي تعتمد على أداة x_search المدمجة لدى xAI في Responses API على https://api.x.ai/v1/responses — إذ يُجري Grok نفسه البحث على جانب الخادم ويُعيد نتائج مُركَّبة مع استشهادات تشير إلى المنشورات الأصلية.

      استخدمها بدلًا من web_search عندما تريد تحديدًا النقاشات أو ردود الفعل أو الادعاءات الحالية على X. أما لصفحات الويب العامة، فاستمر في استخدام web_search / web_extract.

      x_search مقابل xurl​

      يستطيع Hermes إتاحة واجهتين مختلفتين للتعامل مع X:

      الواجهةاستخدمها لـلا تستخدمها لـ
      x_searchالاستكشاف العام على X للقراءة فقط: النقاشات الحالية، وردود الفعل، والادعاءات، والملفات الشخصية، والسلاسل، والإجابات المُركَّبة مع الاستشهادات.النشر، أو الرد، أو الإعجاب، أو الرسائل المباشرة (DM)، أو رفع الوسائط، أو الحذف، أو إثبات أن حالة حساب X مُصادَق عليه قد تغيّرت.
      مهارة xurlأعمال X API الدقيقة أو التي تتطلب مصادقة: post و reply و read و like و dm، والخطوط الزمنية (timelines)، والإشارات (mentions)، ورفع الوسائط، والقراءات الخاصة بحساب معيّن، و endpoints الخام في الإصدار v2.الأبحاث العامة الواسعة على X التي يُركّب Grok نتائجها، عندما تكون x_search متاحة ولا حاجة إلى سياق حساب مُصادَق عليه.

      في سير العمل المختلط، استخدم x_search لاكتشاف المنشورات العامة المرشّحة، ثم انتقل إلى xurl read أو أمر xurl دقيق آخر بعد أن يتضح المنشور أو المستخدم أو الإجراء المستهدف. يجب تأكيد أي إجراء على X يغيّر الحالة عبر مخرجات xurl أو استجابة X API؛ فإجابة x_search ليست دليلًا أبدًا على أن عملية كتابة قد حدثت.

      نصيحة

      إذا كنت تدفع لـ Portal مقابل نموذج xAI على أي حال، فإن استدعاءات Live Search تُحتسب على مفتاح xAI نفسه المُعدّ للمحادثة. راجع Nous Portal.

      المصادقة​

      تُسجَّل x_search عندما يتوفر أيٌّ من مساري بيانات اعتماد xAI:

      بيانات الاعتمادالمصدرالإعداد
      SuperGrok / X Premium+ OAuthتسجيل الدخول عبر المتصفح على accounts.x.ai، مع تحديث تلقائيhermes auth add xai-oauth — راجع xAI Grok OAuth (SuperGrok / X Premium+)
      XAI_API_KEY (المُفضَّل)مفتاح xAI API مدفوعيُضبط في ~/.hermes/.env

      يتصل كلاهما بالـ endpoint نفسه وبالحمولة (payload) نفسها — والفرق الوحيد هو الـ bearer token. عند إعداد كليهما، تكون الأولوية لـ XAI_API_KEY الصريح — فالـ bearer الخاص بـ OAuth الاشتراك يُفوِّض الوصول إلى /v1/responses لكنه يجيب عن x_search بوضع شرح Grok محدود القدرات ودون استشهادات، بينما يُعيد مفتاح API منشورات حقيقية. لاحظ أن هذا يعني أن x_search تعمل وفق فوترة API المحسوبة حسب الاستخدام عند ضبط مفتاح؛ احذف XAI_API_KEY للرجوع إلى حصة اشتراكك (مع التحفّظ المتعلق بالإجابات محدودة القدرات).

      تُشغّل الدالة check_fn الخاصة بالأداة محلّل بيانات اعتماد xAI في كل مرة تُعاد فيها بناء قائمة أدوات النموذج. تعني القيمة True أن الـ bearer يمكن جلبه، وأنه غير فارغ، وأنه (إن كان منتهي الصلاحية) قد جُدِّد بنجاح. أما الـ tokens الملغاة التي فشل تجديدها فتُخفي الأداة من الـ schema؛ فببساطة لا يستطيع النموذج رؤيتها.

      تفعيل الأداة​

      تُفعَّل تلقائيًا عند وجود بيانات اعتماد xAI (OAuth token أو XAI_API_KEY). عطّلها صراحةً عبر hermes tools → Search → x_search إذا كنت لا تريدها.

      hermes tools
      # → 🐦 X (Twitter) Search   (press space to toggle on)

      يعرض المُنتقي خيارين لبيانات الاعتماد:

      1. xAI Grok OAuth (SuperGrok / Premium+) — يفتح المتصفح على accounts.x.ai إذا لم تكن مسجّل الدخول بالفعل
      2. xAI API key — يطلب منك إدخال XAI_API_KEY

      أيٌّ من الخيارين يستوفي شرط التفعيل. يمكنك اختيار بيانات الاعتماد المتوفرة لديك أصلًا؛ فالأداة تعمل بالطريقة نفسها مع كليهما. وإذا انتهى بك الأمر إلى إعداد كليهما، يُفضَّل OAuth وقت الاستدعاء.

      الإعدادات​

      # ~/.hermes/config.yaml
      x_search:
        # xAI model used for the Responses call.
        # grok-4.5 is the recommended default; any Grok model
        # with x_search tool access works.
        model: grok-4.5

        # Optional reasoning effort: low, medium, high, or xhigh. When omitted,
        # the selected model's default applies. xhigh is supported only by
        # models that document it, such as grok-4.20-multi-agent.
        # reasoning_effort: low

        # Request timeout in seconds. x_search can take 60–120s for
        # complex queries — the default is generous. Minimum: 30.
        timeout_seconds: 180

        # Number of automatic retries on 5xx / ReadTimeout / ConnectionError.
        # Each retry backs off (1.5x attempt seconds, capped at 5s).
        retries: 2

      يُرسَل reasoning_effort إلى xAI Responses API في صورة reasoning: {effort: ...}. اتركه دون ضبط للنماذج التي لا تدعم التفكير القابل للضبط. تفشل القيم غير الصالحة قبل إرسال أي طلب إلى API.

      معاملات الأداة​

      يستدعي الوكيل x_search بهذه الوسائط:

      المعاملالنوعالوصف
      querystring (مطلوب)ما تريد البحث عنه على X.
      allowed_x_handlesstring arrayقائمة اختيارية بالمعرّفات (handles) المراد تضمينها حصريًا (10 كحد أقصى). تُزال علامة @ البادئة.
      excluded_x_handlesstring arrayقائمة اختيارية بالمعرّفات المراد استبعادها (10 كحد أقصى). لا يمكن استخدامها مع allowed_x_handles في الوقت نفسه.
      from_datestringتاريخ بداية اختياري بصيغة YYYY-MM-DD.
      to_datestringتاريخ نهاية اختياري بصيغة YYYY-MM-DD.
      enable_image_understandingbooleanيطلب من xAI تحليل الصور المرفقة بالمنشورات المطابقة.
      enable_video_understandingbooleanيطلب من xAI تحليل مقاطع الفيديو المرفقة بالمنشورات المطابقة.

      تُعيد الأداة JSON يحتوي على:

      • answer — استجابة نصية مُركَّبة من Grok
      • citations — الاستشهادات التي يُعيدها الحقل ذو المستوى الأعلى في Responses API
      • inline_citations — تعليقات url_citation التوضيحية المستخرجة من نص الرسالة (يحتوي كلٌّ منها على url و title و start_index و end_index)
      • degraded — تكون true عندما يكون أي مرشّح تضييق (allowed_x_handles أو excluded_x_handles أو from_date أو to_date) مضبوطًا وتعود قناتا الاستشهادات كلتاهما فارغتين. في هذه الحالة تكون answer قد رُكِّبت من معرفة النموذج الذاتية لا من فهرس X، لذا تعامل معها على أنها بلا مصدر. وتكون false في غير ذلك (بما في ذلك حالة "عدم ضبط أي مرشّحات" — فالإجابة الواسعة بلا مصدر مجرد إجابة، وليست إخفاقًا في المرشّح)
      • degraded_reason — نص قصير يذكر المرشّحات التي كانت نشطة، أو null عندما تكون قيمة degraded هي false
      • credential_source — "xai-oauth" إذا حُلّت بيانات الاعتماد عبر OAuth، و "xai" إذا حُلّت عبر مفتاح API
      • model، query، provider، tool، success

      التحقق من التواريخ​

      يُتحقَّق من from_date / to_date على جانب العميل قبل استدعاء HTTP:

      • يجب أن يكون كلاهما، إن وُفِّرا، قابلًا للتحليل بصيغة YYYY-MM-DD.
      • عند ضبط كليهما، يجب أن يكون from_date في تاريخ to_date نفسه أو قبله.
      • يجب ألا يكون from_date بعد تاريخ اليوم بتوقيت UTC — إذ لا يمكن وجود منشورات في نافذة زمنية لم تبدأ بعد، لذا سيُعيد الاستدعاء حتمًا صفر استشهادات.
      • يُسمح بأن يكون to_date في المستقبل (فقد يطلب المستدعون لسبب مشروع نطاق "من الأمس إلى الغد" لالتقاط المنشورات فور وصولها).

      تظهر إخفاقات التحقق في صورة نتيجة أداة منظّمة {"error": "..."}، ولا تتحول أبدًا إلى استدعاء HTTP إلى xAI.

      مثال​

      عند التحدث إلى الوكيل:

      ماذا يقول الناس على X عن ميزات الصور الجديدة في Grok؟ ركّز على الردود من @xai.

      سيقوم الوكيل بما يلي:

      1. يستدعي x_search مع query="reactions to new Grok image features" و allowed_x_handles=["xai"]
      2. يتلقى إجابة مُركَّبة إضافةً إلى قائمة استشهادات ترتبط بمنشورات محددة
      3. يردّ بالإجابة والمراجع

      إذا كان طلب المستخدم التالي "ردّ على أفضلها" أو "أعجب بذلك المنشور"، فعلى الوكيل أن ينتقل إلى مهارة xurl، ويتأكد من المنشور المستهدف بدقة، ويستخدم إجراء X API. تبقى x_search أداةً للاستكشاف.

      استكشاف الأخطاء وإصلاحها​

      "No xAI credentials available"​

      تُظهر الأداة هذه الرسالة عندما يفشل مسارا المصادقة كلاهما. إما أن تضبط XAI_API_KEY في ~/.hermes/.env أو تنفّذ hermes auth add xai-oauth وتُكمل تسجيل الدخول عبر المتصفح. ثم أعد تشغيل جلستك ليعيد الوكيل قراءة سجل الأدوات.

      "x_search is not enabled for this model"​

      لا يملك النموذج المُعدّ في x_search.model صلاحية الوصول إلى أداة x_search على جانب الخادم. انتقل إلى grok-4.5 (الافتراضي) أو إلى نموذج Grok آخر يدعمها. راجع توثيق xAI للاطلاع على القائمة الحالية.

      الأداة لا تظهر في الـ schema​

      هناك سببان محتملان:

      1. الـ toolset غير مفعّل. نفّذ hermes tools وتأكد من تحديد 🐦 X (Twitter) Search.
      2. لا توجد بيانات اعتماد xAI. تُعيد check_fn القيمة False، لذا يبقى الـ schema مخفيًا. نفّذ hermes auth status للتأكد من حالة تسجيل الدخول عبر xai-oauth، وتحقّق من ضبط XAI_API_KEY (إذا كنت تستخدم مسار مفتاح API).

      degraded: true — إجابة بلا استشهادات​

      عندما تستخدم allowed_x_handles أو excluded_x_handles أو نطاقًا زمنيًا وتعود الاستجابة مع degraded: true، فهذا يعني أن فهرس X لدى xAI لم يُعِد أي منشورات مطابقة، لكن Grok أنتج مع ذلك إجابة مُركَّبة من بيانات تدريبه الخاصة. الإجابة بلا مصدر — لا تتعامل معها كنتيجة حقيقية من X.

      أسباب تستحق التحقق منها:

      • خطأ إملائي في المعرّف. أزل علامة @، وراجع الإملاء مجددًا، وتأكد من وجود الحساب.
      • نطاق زمني ضيق جدًا أو يتخطى منشورات اليوم؛ وسّعه وأعد المحاولة.
      • فجوة في فهرس xAI. تفشل بعض الحسابات النشطة أحيانًا في الظهور في x_search حتى عندما تنشر بانتظام. أعد المحاولة بعد بضع دقائق، أو استخدم مهارة xurl للقراءة المباشرة عبر X API عندما تحتاج إلى الخط الزمني لمعرّف محدد بعينه.

      انظر أيضًا​

      • xAI Grok OAuth (SuperGrok / Premium+) — دليل إعداد OAuth
      • مهارة xurl — أداة CLI الرسمية لـ X API لإجراءات الحساب المُصادَق عليها
      • البحث في الويب واستخراج المحتوى — للبحث العام في الويب (خارج X)
      • مرجع الأدوات — الكتالوج الكامل للأدوات
