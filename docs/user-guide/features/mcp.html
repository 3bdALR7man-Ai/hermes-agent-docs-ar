      MCP (Model Context Protocol)

      يتيح MCP لـ Hermes Agent الاتصال بخوادم أدوات خارجية، بحيث يستطيع الوكيل استخدام أدوات موجودة خارج Hermes نفسه — مثل GitHub، وقواعد البيانات، وأنظمة الملفات، وحِزم المتصفحات، وواجهات API الداخلية، وغير ذلك.

      إذا سبق أن أردت أن يستخدم Hermes أداة موجودة بالفعل في مكان آخر، فإن MCP هو عادةً أنظف طريقة لتحقيق ذلك.

      قادم من Claude Code؟

      تقابل كتلة mcpServers في ملف ~/.claude.json لديك المفتاح mcp_servers في ملف config.yaml الخاص بـ Hermes — ويتولى الأمر hermes import-agent claude-code ترحيلها تلقائيًا (إلى جانب المهارات والتعليمات). راجع الاستيراد من وكلاء آخرين.

      ما الذي يمنحك إياه MCP​

      • الوصول إلى منظومات أدوات خارجية دون الحاجة إلى كتابة أداة Hermes أصلية أولًا
      • خوادم stdio محلية وخوادم HTTP MCP بعيدة في ملف الإعدادات نفسه
      • اكتشاف الأدوات وتسجيلها تلقائيًا عند بدء التشغيل
      • أغلفة (wrappers) مساعدة لموارد MCP والـ prompts عندما يدعمها الخادم
      • تصفية على مستوى كل خادم، بحيث لا تكشف إلا أدوات MCP التي تريد فعلًا أن يراها Hermes

      البدء السريع​

      1. يأتي دعم MCP مع التثبيت القياسي — ولا حاجة إلى أي خطوة إضافية.

      2. أضف خادم MCP إلى ~/.hermes/config.yaml:

      mcp_servers:
        filesystem:
          command: "npx"
          args: ["-y", "@modelcontextprotocol/server-filesystem", "/home/user/projects"]
      1. شغّل Hermes:
      hermes chat
      1. اطلب من Hermes استخدام القدرة التي يوفّرها MCP.

      على سبيل المثال:

      List the files in /home/user/projects and summarize the repo structure.

      سيكتشف Hermes أدوات خادم MCP ويستخدمها مثل أي أداة أخرى.

      الكتالوج: تثبيت بنقرة واحدة لخوادم MCP المعتمدة من Nous​

      يأتي Hermes مع كتالوج منتقى من خوادم MCP راجعها فريق Nous ودمجها. وهي معطّلة افتراضيًا — فلا تثبّت إلا ما تحتاجه فعلًا.

      hermes mcp                # interactive picker (default)
      hermes mcp catalog        # plain-text list, scriptable
      hermes mcp install n8n    # install a catalog entry by name

      تعرض أداة الاختيار كل إدخال مع حالته الحالية:

      n8n          available              Manage and inspect n8n workflows from Hermes
      linear       enabled                Linear issue/project management (remote OAuth)
      github       installed (disabled)   GitHub repo + PR tools

      اضغط Enter على أي صف للتثبيت (مع المرور بخطوات إدخال أي بيانات اعتماد مطلوبة)، أو التفعيل، أو التعطيل، أو إلغاء التثبيت. تُخزَّن إدخالات الكتالوج ضمن optional-mcps/ في مستودع hermes-agent — ووجود الإدخال في ذلك المجلد يعني أنه معتمد من Nous. لا يوجد مستوى لإسهامات المجتمع؛ إذ تُضاف الإدخالات عبر دمج PR.

      قد تتطلب إدخالات الكتالوج:

      • مفتاح API — يطلبه Hermes عند التثبيت ويكتب القيمة في ~/.hermes/.env. وتُكتب القيم غير السرية (مثل عناوين URL الأساسية) في الملف نفسه.
      • OAuth (لخوادم MCP البعيدة) — يُكتب كـ auth: oauth في ملف الإعدادات؛ ويفتح عميل MCP المتصفح عند أول اتصال.
      • OAuth (لمزوّد خارجي مثل Google/GitHub) — يوجّهك Hermes إلى hermes auth <provider> إذا لم تكن قد أجريت المصادقة بعد.

      اختيار الأدوات عند التثبيت​

      بعد إعداد بيانات الاعتماد، يفحص Hermes خادم MCP ليسرد كل أداة يوفّرها، ثم يعرض قائمة تحقق:

      Select tools for 'linear' (SPACE toggle, ENTER confirm)
        [x] find_issues       Find issues matching a query
        [x] get_issue         Get a single issue
        [x] create_issue      Create a new issue
        [ ] delete_workspace  Delete a Linear workspace
        ...

      تأتي الصفوف المحددة مسبقًا من:

      1. اختيارك السابق إذا كنت قد ثبّتّ هذا الإدخال من قبل (إعادة التثبيت تحافظ على ما كان لديك — ولا تتجاوزه القيم الافتراضية في الـ manifest)
      2. قيمة tools.default_enabled في الـ manifest إذا صرّح بها الإدخال (بعض إدخالات الكتالوج تستبعد مسبقًا الأدوات التي تُجري تغييرات أو نادرًا ما تكون مفيدة)
      3. كل الأدوات إذا لم ينطبق أيٌّ مما سبق

      بعض الإدخالات ذات الواجهات الضخمة المولَّدة تلقائيًا (مثل cloudflare، بنحو 3,300 أداة تمثّل endpoints من OpenAPI) تُصرّح بدلًا من ذلك بـ tools.default_excluded — وهي قائمة حظر منتقاة من الأسماء وأنماط glob. يؤدي تثبيت أحد هذه الإدخالات إلى تخطي قائمة التحقق كليًا وكتابة tools.exclude؛ ويبقى كل ما لا يطابقها مفعّلًا، بما في ذلك الأدوات التي يضيفها الخادم لاحقًا. عدّل mcp_servers.<name>.tools.exclude في config.yaml لإعادة تفعيل عائلة من الأدوات.

      أرسل قائمة التحقق بالضغط على ENTER. لا ينتهي في mcp_servers.<name>.tools.include إلا الأدوات المحددة. وإذا اخترت كل الأدوات، فلن يُكتب أي مرشّح (أنظف شكل للإعدادات، مع سلوك مطابق).

      إذا فشل الفحص (الخادم غير قابل للوصول، أو لم تكتمل OAuth بعد، أو الخدمة الخلفية لا تعمل)، يظل التثبيت ناجحًا: إذ تُطبَّق قيمة tools.default_enabled من الـ manifest مباشرةً (إن كانت مُصرَّحًا بها)، وإلا فلا يُكتب أي مرشّح. أعد تشغيل hermes mcp configure <name> بمجرد أن يصبح الخادم قابلًا للوصول لتحسين الاختيار.

      نموذج الثقة​

      يؤدي تثبيت إدخال من الكتالوج إلى تنفيذ كل ما يحدده الـ manifest — أي git clone، وأوامر bootstrap الخاصة بالإدخال (pip install، وnpm install، وغيرها)، وفي النهاية كود خادم MCP نفسه. تخضع ملفات الـ manifest لمراجعة PR قبل دمجها في مستودع hermes-agent، لذا راجع فريق Nous كل إدخال قبل إصداره — لكن ينبغي لك مع ذلك قراءة الـ manifest قبل التثبيت، ولا سيما المستودع المذكور في الحقل source:، وأوامر install.bootstrap:، وأي استدعاء في transport.command:.

      توجد ملفات الـ manifest في optional-mcps/<name>/manifest.yaml على GitHub. كما تطبع أداة الاختيار عنوان source: URL الخاص بالـ manifest عند التثبيت، لتتمكن من التحقق سريعًا من المستودع الأصلي. وتعرض صفحة MCP في لوحة التحكم على الويب التفاصيل نفسها لكل إدخال في الكتالوج — طبقة النقل، ونوع المصادقة، وعنوان URL للـ endpoint (HTTP) أو الأمر + الوسائط (stdio)، ومصدر التثبيت/المرجع في git وأوامر bootstrap، وملاحظات الإعداد — مع عرض source: كرابط قابل للنقر، حتى تتمكن من فحص ما يتصل به الإدخال أو ينفّذه بالضبط قبل النقر على Install.

      توافق إصدارات الـ manifest​

      تُثبّت ملفات الـ manifest قيمة manifest_version. والكتالوج متوافق مع الإصدارات المستقبلية: فإذا أضاف PR إدخالًا بقيمة manifest_version أحدث مما يفهمه إصدار Hermes المثبّت لديك، فستعرض أداة الاختيار تحذيرًا (⚠ '<name>' requires a newer Hermes) لذلك الإدخال بدلًا من إخفائه بصمت. شغّل hermes update لتثبيت أحدث إصدار من Hermes عندما ترى ذلك.

      استبدال ${ENV_VAR} وقت التشغيل​

      داخل transport.command، وtransport.args، وtransport.url، وheaders الخاصة بأي إدخال، تُحلّ العناصر النائبة ${VAR} عند الاتصال بالخادم من متغيرات البيئة (التي تشمل كل ما في ~/.hermes/.env). يفيد هذا عندما يريد إدخال في الكتالوج الإشارة إلى قيمة ضبطها المستخدم في مكان آخر — مثل ${HOME}/foo أو ${MY_PROVIDER_TOKEN}.

      تُستبدل أيضًا متغيرات السياق على نمط Cursor (مع مراعاة حالة الأحرف): ${userHome} (المجلد الرئيسي)، و${workspaceFolder} (جذر مساحة عمل الجلسة)، و${workspaceFolderBasename}، و${pathSeparator} / ${/} (فاصل المسارات في نظام التشغيل). راجع مرجع إعدادات MCP للتفاصيل.

      لاحظ أن هذا يختلف عن ${INSTALL_DIR} في ملفات manifest الخاصة بالكتالوج، والذي يُستبدل وقت التثبيت بالمسار الذي نسخ إليه الكتالوجُ مستودعَ الإدخال.

      تحديث اختيار الأدوات لاحقًا​

      hermes mcp configure linear

      يعيد فتح قائمة التحقق نفسها مع تحديد اختيارك الحالي مسبقًا. استخدمه عندما تريد تفعيل مزيد من الأدوات، أو عندما يضيف الخادم أدوات جديدة تريد الاشتراك فيها.

      تحديث manifest الكتالوج​

      لا تُحدَّث خوادم MCP تلقائيًا أبدًا. أعد تشغيل hermes mcp install <name> للتحديث بعد تحديث Hermes إذا تغيّر إصدار الـ manifest.

      لإضافة خادم MCP إلى الكتالوج، افتح PR على optional-mcps/.

      بيانات الاقتراح الوصفية (suggest:)​

      يمكن للـ manifest أن يُصرّح بكتلة suggest: اختيارية تحتوي على قائمتَي keywords: و/أو hosts:. تستخدمها واجهات المستخدم (حاليًا محرّر الرسائل في تطبيق Desktop) لعرض زر "Add <server>" بنقرة واحدة عندما تذكر مسودتك إحدى الكلمات المفتاحية ككلمة مكتملة، أو تحتوي على رابط ملصوق ينتهي اسم مضيفه بإحدى لواحق المضيفين. وهي استشارية بحتة — إذ تمر عمليات التثبيت دائمًا عبر مسارات الكتالوج/الإعدادات نفسها التي خضعت للتحقق — وتُصرّح بها معظم الإدخالات البعيدة المستضافة (Atlassian و Sentry و Notion و Stripe و Vercel و Supabase وغيرها).

      GitHub غير موجود في الكتالوج عن قصد: فخادم MCP المستضاف الخاص به يتطلب أن يستخدم كل عميل تطبيق OAuth خاصًا به (إذ يُرفض التسجيل الديناميكي العام للعملاء)، كما أن مهارات github/* المضمّنة في Hermes التي تعتمد على CLI gh تمثّل تكاملًا أكثر قدرة. وفي Desktop، يؤدي ذكر GitHub بدلًا من ذلك إلى اقتراح المهارة github-auth عندما لا يكون gh مسجَّل الدخول بعد.

      نوعان من خوادم MCP​

      خوادم Stdio​

      تعمل خوادم Stdio كعمليات فرعية محلية وتتواصل عبر stdin/stdout.

      mcp_servers:
        github:
          command: "npx"
          args: ["-y", "@modelcontextprotocol/server-github"]
          env:
            GITHUB_PERSONAL_ACCESS_TOKEN: "***"

      استخدم خوادم stdio عندما:

      • يكون الخادم مثبّتًا محليًا
      • تريد وصولًا منخفض زمن الاستجابة إلى الموارد المحلية
      • تتبع توثيق خادم MCP يعرض command وargs وenv

      خوادم HTTP​

      خوادم HTTP MCP هي endpoints بعيدة يتصل بها Hermes مباشرةً.

      mcp_servers:
        remote_api:
          url: "https://mcp.example.com/mcp"
          headers:
            Authorization: "Bearer ***"

      استخدم خوادم HTTP عندما:

      • يكون خادم MCP مستضافًا في مكان آخر
      • توفّر مؤسستك endpoints داخلية لـ MCP
      • لا تريد أن يُطلق Hermes عملية فرعية محلية لذلك التكامل

      خوادم HTTP بمصادقة OAuth​

      تتطلب معظم خوادم MCP المستضافة (Cloudflare و Linear و Sentry و Atlassian و Asana و Figma و Stripe و…) مصادقة OAuth 2.1 بدلًا من bearer token ثابت. اضبط auth: oauth وسيتولى Hermes الاكتشاف، وتعريف العميل، و PKCE، وتبادل الـ token، وتجديده، والمصادقة التصاعدية (step-up auth) عبر MCP Python SDK.

      يعرّف Hermes نفسه باستخدام Client ID Metadata Document على الخوادم التي تدعمه، ويلجأ إلى Dynamic Client Registration على الخوادم التي لا تدعمه. كلا الأمرين يحدث تلقائيًا؛ ولا يوجد ما تحتاج إلى إعداده.

      خادم Figma MCP البعيد

      يسمح endpoint المستضاف الخاص بـ Figma (https://mcp.figma.com/mcp) بـ Dynamic Client Registration وفق قائمة سماح تعتمد على قيمة client_name المطابقة تمامًا — فالقيمة المجردة "Hermes Agent" تُرجع 403، بينما تنجح "Claude Code" و"Codex". يضبط Hermes تلقائيًا oauth.client_name: "Claude Code" لـ mcp.figma.com حتى يعمل التثبيت/تسجيل الدخول دون أي حيلة خاصة:

      mcp_servers:
        figma:
          url: "https://mcp.figma.com/mcp"
          auth: oauth

      أو: hermes mcp install figma، ثم hermes mcp login figma.

      mcp_servers:
        linear:
          url: "https://mcp.linear.app/mcp"
          auth: oauth

      عند أول اتصال، يطبع Hermes عنوان URL للتفويض، ويفتح متصفحك متى أمكن، وينتظر استدعاء OAuth الراجع (callback) على منفذ loopback محلي. تُخزَّن الـ tokens مؤقتًا في ~/.hermes/mcp-tokens/<server>.json بصلاحيات 0o600؛ وتعيد التشغيلات اللاحقة استخدامها بصمت إلى أن يفشل التجديد.

      الأجهزة البعيدة / غير التفاعلية (headless). عندما يعمل Hermes على جهاز غير الجهاز الذي يعمل عليه متصفحك، لا يستطيع الـ callback عبر loopback الوصول إلى حاسوبك المحمول. هذه طرق إكمال التدفق:

      • Hermes Desktop (تلقائيًا): عندما تُجري تسجيل الدخول عبر OAuth من واجهة إعداد MCP في تطبيق Desktop مع backend بعيد، يستضيف Desktop مستمع الـ callback على جهازك أنت ويُرحِّل التفويض إلى الـ gateway تلقائيًا — دون الحاجة إلى نفق أو لصق أو proxy. يتطلب ذلك أن يكون كلٌّ من تطبيق Desktop والـ backend محدَّثَين.
      • اللصق العكسي (دون إعداد): في الطرفية التفاعلية يطبع Hermes الرسالة "Or paste the redirect URL here…" إلى جانب عنوان URL للتفويض. افتح العنوان في متصفحك، ووافق، ثم انسخ عنوان URL الكامل الذي ينتهي إليه المتصفح (ستُظهر إعادة التوجيه خطأ في الاتصال — وهذا متوقع)، والصقه عند المطالبة. تعمل أيضًا سلاسل الاستعلام المجردة ?code=…&state=….
      • تسجيل الدخول برمز الجهاز (دون أي callback): إذا كان خادم التفويض الخاص بالخادم يُعلن عن endpoint لتفويض الأجهزة، فشغّل hermes mcp login <server> --flow device على الجهاز الذي يعمل عليه Hermes. سيطبع عنوان URL للتحقق ورمزًا قصيرًا؛ افتح العنوان على أي جهاز، وأدخل الرمز، وسيستطلع Hermes حالة الموافقة. لا يُفتح أي متصفح على المضيف ولا حاجة إلى مستمع callback. اضبط oauth.flow: device على الخادم لجعل login وreauth يستخدمانه افتراضيًا. التفاصيل: تسجيل الدخول برمز الجهاز.
      • توجيه منفذ SSH: شغّل ssh -N -L <port>:127.0.0.1:<port> user@host في طرفية منفصلة، ثم دع إعادة التوجيه تسير بشكل طبيعي.
      • Callback عبر proxy (redirect_uri): عندما يكون هناك endpoint عام بـ HTTPS يُعيد التوجيه إلى المضيف (مثل Tailscale Funnel أو reverse proxy موجَّه إلى منفذ الـ callback)، اضبط oauth.redirect_uri وستصل إعادة توجيه المتصفح إلى Hermes من تلقاء نفسها — دون الحاجة إلى نفق أو لصق:
      mcp_servers:
        myserver:
          url: "https://mcp.example.com/mcp"
          auth: oauth
          oauth:
            redirect_port: 8765                                # fixed port for the proxy to target
            redirect_uri: "https://oauth.example.ts.net/callback"

      بالنسبة للـ gateways غير التفاعلية بالكامل (بوت مراسلة، دون أي طرفية تفاعلية)، ترشد المهارة الاختيارية mcp-oauth-remote-gateway الوكيلَ خلال إكمال التدفق يدويًا وكتابة الـ tokens في المكان الذي يتوقعه Hermes.

      مشكلة شائعة — جدار WAF يرفض عناوين إعادة التوجيه 127.0.0.1. يضع عدد قليل من المزوّدين أمام خادم التفويض لديهم جدار WAF يُرجع 403 لأي طلب تفويض تحتوي سلسلة استعلامه على 127.0.0.1 حرفيًا (ومن الأمثلة المعروفة AWS API Gateway الخاص بـ Reclaim.ai — إذ تُرجع كل محاولة {"message":"Forbidden"} قبل الوصول إلى تطبيق OAuth). اضبط oauth.redirect_host: localhost لاستخدام http://localhost:<port>/callback بدلًا منه؛ وسيظل مستمع الـ callback مرتبطًا بـ 127.0.0.1 في الحالتين.

      راجع OAuth عبر SSH / الأجهزة البعيدة للاطلاع على الشرح الكامل، بما في ذلك الخوادم التي لا تدعم DCR (مثل Slack)، وقيم client_id/client_secret المسجّلة مسبقًا، وتخصيص النطاقات (scopes)، وإعادة المصادقة عبر hermes mcp login <server>.

      مشكلة شائعة — مزوّدون لا يدعمون التسجيل التلقائي (Google Drive و Atlassian). ترفض بعض الخوادم خطوة التسجيل الديناميكي للعميل (RFC 7591) التي يعتمد عليها auth: oauth المجرد — فخادم Drive الرسمي من Google (https://drivemcp.googleapis.com/mcp/v1) يُرجع 400 Bad Request، فلا يُنشأ أي عميل OAuth ولا يُحصل على أي token. العَرَض خفي: فهذه الخوادم تقدّم أيضًا tools/list دون مصادقة، لذا يستطيع hermes mcp login سرد الأدوات ويبدو وكأنه نجح، لكن كل استدعاء فعلي لأداة ينتهي لاحقًا بانتهاء المهلة. أصبح hermes mcp login الآن يكتشف هذه الحالة (إذ يتحقق من أن الـ token حُفظ فعلًا على القرص) ويطلب منك توفير عميل OAuth خاص بك. أنشئ واحدًا في وحدة التحكم الخاصة بالمزوّد وأضفه إلى الإعدادات:

      mcp_servers:
        googledrive:
          url: "https://drivemcp.googleapis.com/mcp/v1"
          auth: oauth
          oauth:
            client_id: "<your-oauth-client-id>"
            client_secret: "<your-oauth-client-secret>"

      ثم شغّل hermes mcp login googledrive — ومع العميل المسجّل مسبقًا، يتخطى Hermes خطوة التسجيل وينفّذ تدفق التفويض المعتاد عبر المتصفح.

      مشكلة شائعة — تعارض توقيت إعادة التحميل التلقائي للإعدادات. عندما تعدّل ~/.hermes/config.yaml من داخل جلسة Hermes قيد التشغيل، يعيد CLI تحميل اتصالات MCP تلقائيًا بمهلة 30 ثانية. وهذا لا يكفي لتدفق OAuth تفاعلي. أضف الإدخال، ثم شغّل hermes mcp login <server> من طرفية جديدة — إذ ينتظر 5 دقائق كاملة حتى تُكمل المصادقة.

      mTLS / شهادات العميل​

      خوادم HTTP MCP البعيدة التي تتطلب TLS المتبادل (المصادقة بشهادة العميل) مدعومة عبر client_cert / client_key. يمرّر Hermes الشهادة بعد تحديدها إلى عميل HTTP الأساسي لإجراء مصافحة TLS.

      يقبل client_cert ثلاثة أشكال:

      • مسار PEM واحد مدمج — ملف واحد يحتوي على الشهادة والمفتاح الخاص معًا:
      mcp_servers:
        internal_api:
          url: "https://mcp.internal.example.com/mcp"
          client_cert: "~/.certs/mcp-client.pem"
      • ثنائية [cert, key] — الشهادة والمفتاح في ملفين منفصلين (يعادل ضبط client_cert + client_key):
      mcp_servers:
        internal_api:
          url: "https://mcp.internal.example.com/mcp"
          client_cert: ["~/.certs/mcp-client.crt", "~/.certs/mcp-client.key"]
      • ثلاثية [cert, key, password] — عندما يكون المفتاح الخاص مشفّرًا، يكون العنصر الثالث هو عبارة مرور المفتاح:
      mcp_servers:
        internal_api:
          url: "https://mcp.internal.example.com/mcp"
          client_cert: ["~/.certs/mcp-client.crt", "~/.certs/mcp-client.key", "${MCP_KEY_PASSWORD}"]

      يمكنك أيضًا إبقاء الشهادة والمفتاح منفصلين تمامًا عبر client_cert (PEM مدمج) مع client_key صريح. تدعم المسارات توسيع ~؛ ويؤدي غياب ملف إلى خطأ واضح مرتبط بالخادم المعني، بدلًا من فشل غامض في مصافحة TLS.

      ترويسة الهوية لكل مستخدم​

      يمكن إرسال ترويسة هوية مع كل طلب عبر identity_header إلى خوادم HTTP/SSE MCP البعيدة التي تبني سلوكها على هوية المستدعي (حدود المعدل لكل مستخدم، وسجلات التدقيق، والتوجيه متعدد المستأجرين):

      mcp_servers:
        team_api:
          url: "https://mcp.team.example.com/mcp"
          identity_header:
            name: "X-User-Id"
            value_from: "static"   # "static" (default) or "profile"
            value: "alice"         # required for static
      • يرسل value_from: static القيمة الحرفية value من config.yaml.
      • يرسل value_from: profile اسم profile النشط في Hermes، ويُحدَّد مرة واحدة عند الاتصال — وهذا مفيد عندما تتصل عدة profiles على جهاز واحد بالخادم نفسه ويحتاج هو إلى التمييز بينها.

      الإدخال الصريح في خريطة headers الخاصة بالخادم الذي يحمل الاسم نفسه (بأي حالة أحرف) هو الغالب دائمًا؛ فترويسة الهوية لا تتجاوز أبدًا إعدادات الترويسات الخاصة بك. تُصدر كتل identity_header غير الصالحة تحذيرًا ويتم تجاهلها — ولا تمنع الخادم من الاتصال أبدًا. أما في خوادم stdio فيُتجاهل المفتاح مع تحذير (إذ لا ترويسات في طبقات نقل stdio).

      مرجع الإعدادات الأساسية​

      يقرأ Hermes إعدادات MCP من ~/.hermes/config.yaml تحت المفتاح mcp_servers.

      mcp_servers:

      إعادة تدوير خوادم stdio كثيفة استهلاك الذاكرة​

      تُبقي خوادم MCP المعتمدة على المتصفح (مثل @playwright/mcp) نسخة Chromium كاملة في الذاكرة بعد أول استدعاء لأداة — أي مئات الميغابايتات التي لا تُحرَّر أبدًا. فعّل إعادة التدوير التلقائية، وسيُوقَف الخادم بعد بلوغ حد الخمول/العمر، ثم يُعاد تشغيله بشفافية في المرة التالية التي تُستدعى فيها إحدى أدواته (وتبقى أدواته مسجّلة طوال الوقت):

      mcp_servers:
        playwright:
          command: "npx"
          args: ["-y", "@playwright/mcp@latest", "--headless"]
          idle_timeout_seconds: 900     # recycle after 15 min without a tool call
          max_lifetime_seconds: 86400   # and at least once a day regardless

      مثال HTTP بسيط​

      mcp_servers:
        company_api:
          url: "https://mcp.internal.example.com"
          headers:
            Authorization: "Bearer ***"

      الإعدادات المسبقة المدمجة (Presets)​

      بالنسبة لخوادم MCP المعروفة، يقبل hermes mcp add الخيار --preset الذي يملأ تفاصيل طبقة النقل حتى لا تضطر إلى البحث عن الأمر والوسائط. يوفّر الإعداد المسبق القيم الافتراضية فقط — وأي شيء آخر تمرّره في سطر الأوامر نفسه (متغيرات البيئة، والترويسات، والتصفية) يبقى هو الغالب.

      الإعداد المسبقما يربطه
      codexخادم MCP الخاص بـ Codex CLI (codex mcp-server عبر stdio). يتطلب وجود CLI codex ضمن PATH.
      # Add Codex CLI as an MCP server in one line
      hermes mcp add codex --preset codex

      يكتب ذلك ما يعادل:

      mcp_servers:
        codex:
          command: "codex"
          args: ["mcp-server"]

      يمكنك اختيار أي اسم محلي (hermes mcp add my-codex --preset codex لا بأس به)؛ فالإعداد المسبق يوفّر فقط القيم الافتراضية لـ command/args.

      كيف يسجّل Hermes أدوات MCP​

      يضيف Hermes بادئة إلى أسماء أدوات MCP حتى لا تتعارض مع أسماء الأدوات المدمجة:

      mcp_<server_name>_<tool_name>

      أمثلة:

      الخادمأداة MCPالاسم المسجَّل
      filesystemread_filemcp_filesystem_read_file
      githubcreate-issuemcp_github_create_issue
      my-apiquery.datamcp_my_api_query_data

      عمليًا، لا تحتاج عادةً إلى استدعاء الاسم ذي البادئة يدويًا — إذ يرى Hermes الأداة ويختارها أثناء استدلاله المعتاد.

      تنقية نتائج الأدوات و _meta​

      يُطبَّق سلوكان على كل نتيجة لأداة MCP قبل أن يراها النموذج:

      • تُزال محارف Unicode TAG غير المرئية. المحارف الواقعة في النطاق U+E0000–U+E007F لا تظهر إطلاقًا في الطرفيات وواجهات المحادثة، لكنها مرئية بالكامل للنموذج — وهي قناة تهريب كلاسيكية لحقن الـ prompt (prompt injection) يستغلها خادم خبيث أو مُخترَق. يزيلها Hermes من نتائج الأدوات، ومحتوى الموارد، وأوصاف الأدوات. أما تسلسلات وسوم الإيموجي المشروعة (مثل أعلام المناطق 🏴󠁧󠁢󠁳󠁣󠁴󠁿) فتُحفظ كما هي.
      • تُعرض بيانات _meta الخاصة بالمورِّدين؛ أما المفاتيح المحجوزة للبروتوكول فلا. عندما يُرفق خادم خريطة _meta بنتيجة أداة (بمساحات أسماء خاصة بالمورِّدين مثل com.example/handoff)، يمرّرها Hermes إلى النموذج إلى جانب محتوى النتيجة. وتُحذف المفاتيح الواقعة تحت البادئات المحجوزة للبروتوكول — أي تسمية modelcontextprotocol أو mcp متبوعة بتسمية أخرى، مثل modelcontextprotocol.io/... أو tools.mcp.com/... — بما يتوافق مع قواعد أسماء المفاتيح في مواصفة MCP. وإذا لم يتبقَّ شيء موجَّه إلى النموذج، يُحذف الحقل _meta كليًا.

      أدوات MCP المساعدة​

      عندما يكون ذلك مدعومًا، يسجّل Hermes أيضًا أدوات مساعدة حول موارد MCP والـ prompts:

      • list_resources
      • read_resource
      • list_prompts
      • get_prompt

      تُسجَّل هذه الأدوات لكل خادم بنمط البادئة نفسه، على سبيل المثال:

      • mcp_github_list_resources
      • mcp_github_get_prompt

      مهم​

      أصبحت هذه الأدوات المساعدة الآن تراعي القدرات المتاحة:

      • لا يسجّل Hermes أدوات الموارد المساعدة إلا إذا كانت جلسة MCP تدعم فعلًا عمليات الموارد
      • لا يسجّل Hermes أدوات الـ prompts المساعدة إلا إذا كانت جلسة MCP تدعم فعلًا عمليات الـ prompts

      لذا فإن الخادم الذي يوفّر أدوات قابلة للاستدعاء دون موارد/prompts لن يحصل على تلك الأغلفة الإضافية.

      التصفية على مستوى كل خادم​

      يمكنك التحكم في الأدوات التي يضيفها كل خادم MCP إلى Hermes، ما يتيح إدارة دقيقة لمساحة أسماء الأدوات لديك.

      تعطيل خادم بالكامل​

      mcp_servers:
        legacy:
          url: "https://mcp.legacy.internal"
          enabled: false

      عند ضبط enabled: false، يتخطى Hermes الخادم كليًا ولا يحاول حتى الاتصال به.

      قائمة سماح لأدوات الخادم​

      mcp_servers:
        github:
          command: "npx"
          args: ["-y", "@modelcontextprotocol/server-github"]
          env:
            GITHUB_PERSONAL_ACCESS_TOKEN: "***"
          tools:
            include: [create_issue, list_issues]

      لا تُسجَّل إلا أدوات خادم MCP المذكورة.

      يمكن أن تكون الإدخالات في include/exclude أيضًا أنماط glob (*، ?، [...]، وتُطابَق مع مراعاة حالة الأحرف): فالنمط include: ["*_dns_*"] يسجّل كل أداة يحتوي اسمها على _dns_. أما الإدخالات العادية التي لا تتضمن محارف خاصة فتبقى مطابقة تامة. وأنماط glob هي الطريقة العملية لتصفية الخوادم التي توفّر آلاف الأدوات المولَّدة تلقائيًا للـ endpoints بحسب عائلة المنتج.

      قائمة حظر لأدوات الخادم​

      mcp_servers:
        stripe:
          url: "https://mcp.stripe.com"
          tools:
            exclude: [delete_customer]

      تُسجَّل جميع أدوات الخادم باستثناء الأدوات المستبعدة.

      أنماط Glob​

      تقبل كلتا القائمتين أنماط glob على نمط fnmatch إلى جانب الأسماء الدقيقة — وهذا ضروري للواجهات المسطّحة الضخمة مثل API MCP الخاص بـ Cloudflare (?codemode=false، بنحو 3,300 أداة)، حيث يكون استبعاد مجالات المنتجات endpoint تلو الآخر أمرًا غير عملي:

      mcp_servers:
        cloudflare:
          url: "https://mcp.cloudflare.com/mcp?codemode=false"
          auth: oauth
          tools:
            exclude: ["*_radar_*", "*_accounts_dlp_*", "*_zones_web3_*"]

      الإدخالات التي لا تحتوي على محارف glob الخاصة (*، ?، [) تُطابَق بدقة — فالإدخال docs يستبعد فقط الأداة المسمّاة docs، ولا يستبعد أبدًا docs_search.

      قاعدة الأولوية​

      إذا وُجدت القائمتان معًا:

      tools:
        include: [create_issue]
        exclude: [create_issue, delete_issue]

      فإن include هي الغالبة.

      تصفية الأدوات المساعدة أيضًا​

      يمكنك أيضًا تعطيل الأغلفة المساعدة التي يضيفها Hermes بشكل منفصل:

      mcp_servers:
        docs:
          url: "https://mcp.docs.example.com"
          tools:
            prompts: false
            resources: false

      وهذا يعني:

      • tools.resources: false يعطّل list_resources وread_resource
      • tools.prompts: false يعطّل list_prompts وget_prompt

      مثال كامل​

      mcp_servers:
        github:
          command: "npx"
          args: ["-y", "@modelcontextprotocol/server-github"]
          env:
            GITHUB_PERSONAL_ACCESS_TOKEN: "***"
          tools:
            include: [create_issue, list_issues, search_code]
            prompts: false

        stripe:
          url: "https://mcp.stripe.com"
          headers:
            Authorization: "Bearer ***"
          tools:
            exclude: [delete_customer]
            resources: false

        legacy:
          url: "https://mcp.legacy.internal"
          enabled: false

      ماذا يحدث إذا صُفّي كل شيء؟​

      إذا كانت إعداداتك تستبعد جميع الأدوات القابلة للاستدعاء وتعطّل أو تُغفل جميع الأدوات المساعدة المدعومة، فلن يُنشئ Hermes toolset فارغًا لـ MCP وقت التشغيل لذلك الخادم.

      وهذا يُبقي قائمة الأدوات نظيفة.

      السلوك وقت التشغيل​

      وقت الاكتشاف​

      يكتشف Hermes خوادم MCP عند بدء التشغيل ويسجّل أدواتها في سجل الأدوات المعتاد.

      الاكتشاف الديناميكي للأدوات​

      يمكن لخوادم MCP إبلاغ Hermes عند تغيّر أدواتها المتاحة وقت التشغيل عبر إرسال إشعار notifications/tools/list_changed. وعندما يتلقى Hermes هذا الإشعار، يعيد تلقائيًا جلب قائمة أدوات الخادم ويحدّث السجل — دون الحاجة إلى تشغيل /reload-mcp يدويًا.

      يفيد هذا مع خوادم MCP التي تتغير قدراتها ديناميكيًا (مثل خادم يضيف أدوات عند تحميل مخطط قاعدة بيانات جديد، أو يزيل أدوات عندما تتوقف خدمة ما عن العمل).

      عملية التحديث محمية بقفل، بحيث لا تتسبب الإشعارات المتلاحقة من الخادم نفسه في عمليات تحديث متداخلة. أما إشعارات تغيّر الـ prompts والموارد (prompts/list_changed، resources/list_changed) فتُستقبل لكن لا يُتخذ بشأنها أي إجراء بعد.

      إعادة التحميل​

      إذا غيّرت إعدادات MCP، فاستخدم:

      /reload-mcp

      يعيد هذا تحميل خوادم MCP من الإعدادات ويحدّث قائمة الأدوات المتاحة. وهو أيضًا الطريقة الصريحة لإعادة فحص الأدوات المشروطة بالتوفر (Docker، وHASS_TOKEN، و OAuth…): فمجموعة أدوات الجلسة تبقى مجمّدة فيما عدا ذلك، لذا فإن بيانات الاعتماد أو الـ daemon الذي يظهر في منتصف الجلسة لا يُلتقط إلا عند /reload-mcp، أو /new، أو ضغط السياق. أما تغييرات الأدوات وقت التشغيل التي يدفعها الخادم نفسه، فراجع الاكتشاف الديناميكي للأدوات أعلاه.

      Toolsets​

      يُنشئ كل خادم MCP مُعدّ أيضًا toolset وقت التشغيل عندما يضيف أداة مسجّلة واحدة على الأقل:

      mcp-<server>

      وهذا يسهّل فهم خوادم MCP والتعامل معها على مستوى الـ toolset.

      نموذج الأمان​

      تصفية متغيرات البيئة في Stdio​

      بالنسبة لخوادم stdio، لا يمرّر Hermes بيئة الـ shell الكاملة لديك دون تمييز.

      لا يُمرَّر إلا env المُعدّ صراحةً إلى جانب حد أدنى آمن من المتغيرات الأساسية. وهذا يقلّل من تسرّب الأسرار عن غير قصد.

      التحكم في الكشف على مستوى الإعدادات​

      دعم التصفية الجديد هو أيضًا وسيلة تحكم أمنية:

      • عطّل الأدوات الخطرة التي لا تريد أن يراها النموذج
      • اكشف قائمة سماح دنيا فقط للخوادم الحسّاسة
      • عطّل أغلفة الموارد/الـ prompts عندما لا تريد كشف تلك الواجهة

      استكشاف الأخطاء وإصلاحها​

      خادم MCP لا يتصل​

      تحقّق مما يلي:

      # Verify MCP deps are installed (already included in standard install)
      cd ~/.hermes/hermes-agent && uv pip install -e ".[mcp]"

      node --version
      npx --version

      ثم تحقّق من إعداداتك وأعد تشغيل Hermes.

      الأدوات لا تظهر​

      الأسباب المحتملة:

      • فشل الخادم في الاتصال
      • فشل الاكتشاف
      • استبعدت إعدادات التصفية لديك الأدوات
      • القدرة المساعدة غير موجودة على ذلك الخادم
      • الخادم معطّل بواسطة enabled: false

      إذا كنت تُجري التصفية عن قصد، فهذا متوقع.

      لماذا لم تظهر الأدوات المساعدة للموارد أو الـ prompts؟​

      لأن Hermes أصبح لا يسجّل تلك الأغلفة إلا عند تحقق الشرطين معًا:

      1. أن تسمح بها إعداداتك
      2. أن تدعم جلسة الخادم تلك القدرة فعلًا

      هذا مقصود، ويُبقي قائمة الأدوات معبّرة عن الواقع بدقة.

      استدعاءات الأدوات المتوازية​

      تعمل أدوات MCP افتراضيًا بالتتابع — أداة واحدة في كل مرة. إذا كان خادم MCP لديك يوفّر أدوات آمنة للتشغيل المتزامن (مثل الاستعلامات للقراءة فقط، أو استدعاءات API المستقلة)، فيمكنك تفعيل التنفيذ المتوازي:

      mcp_servers:
        docs:
          command: "docs-server"
          supports_parallel_tool_calls: true

      عندما تكون قيمة supports_parallel_tool_calls هي true، قد ينفّذ Hermes عدة أدوات من ذلك الخادم في الوقت نفسه ضمن دفعة واحدة من استدعاءات الأدوات، تمامًا كما يفعل مع الأدوات المدمجة المخصّصة للقراءة فقط (web_search و read_file وغيرهما).

      تنبيه

      لا تفعّل الاستدعاءات المتوازية إلا لخوادم MCP التي تكون أدواتها آمنة للتشغيل في الوقت نفسه. إذا كانت الأدوات تقرأ وتكتب حالة مشتركة أو ملفات أو قواعد بيانات أو موارد خارجية، فراجع حالات التسابق (race conditions) في القراءة/الكتابة قبل تفعيل هذا الإعداد.

      دعم MCP Sampling​

      يمكن لخوادم MCP طلب inference من LLM عبر Hermes باستخدام بروتوكول sampling/createMessage. يتيح ذلك لخادم MCP أن يطلب من Hermes توليد نص نيابةً عنه — وهو مفيد للخوادم التي تحتاج إلى قدرات LLM لكنها لا تملك وصولًا خاصًا بها إلى نموذج.

      الـ Sampling مفعّل افتراضيًا لجميع خوادم MCP (عندما تدعمه MCP SDK). اضبطه لكل خادم تحت المفتاح sampling:

      mcp_servers:
        my_server:
          command: "my-mcp-server"
          sampling:
            enabled: true            # Enable sampling (default: true)
            model: "openai/gpt-4o"  # Override model for sampling requests (optional)
            max_tokens_cap: 4096     # Max tokens per sampling response (default: 4096)
            timeout: 30              # Timeout in seconds per request (default: 30)
            max_rpm: 10              # Rate limit: max requests per minute (default: 10)
            max_tool_rounds: 5       # Max tool-use rounds in sampling loops (default: 5)
            allowed_models: []       # Allowlist of model names the server may request (empty = any)
            log_level: "info"        # Audit log level: debug, info, or warning (default: info)

      يتضمن معالج الـ sampling محدِّدًا للمعدل بنافذة منزلقة، ومهلًا زمنية لكل طلب، وحدودًا لعمق حلقات الأدوات لمنع الاستخدام الخارج عن السيطرة. وتُتتبَّع المقاييس (عدد الطلبات، والأخطاء، والـ tokens المستخدمة) لكل نسخة خادم.

      لتعطيل الـ sampling لخادم محدد:

      mcp_servers:
        untrusted_server:
          url: "https://mcp.example.com"
          sampling:
            enabled: false

      دعم MCP Elicitation​

      يمكن لخوادم MCP أن تطلب من المستخدم مدخلات منظّمة في منتصف استدعاء أداة عبر بروتوكول elicitation/create (mcp Python SDK ≥ 1.11.0). يوجّه Hermes طلبات الـ elicitation من نوع form-mode عبر واجهة الموافقة الموجودة لديه — مطالبة تفاعلية في CLI/TUI، أو أزرار موافقة على منصات الـ gateway مثل Telegram و Slack — بحيث يصل الطلب إليك أينما كانت الجلسة. أما طلبات الـ elicitation من نوع URL-mode (حيث يوجّهك الخادم إلى عنوان URL خارجي) فتُرفض لأنها غير مدعومة.

      الـ Elicitation مفعّل افتراضيًا لكل خادم. اضبطه تحت المفتاح elicitation:

      mcp_servers:
        my_server:
          command: "my-mcp-server"
          elicitation:
            enabled: true    # default: true
            timeout: 300     # seconds to wait for your answer (default: 300)

      تطابق المهلة الافتراضية البالغة 5 دقائق القيمة الافتراضية لموافقات الـ gateway، حتى يتسع الوقت للمستخدمين على الواجهات غير المتزامنة للرد قبل أن يستسلم الخادم. وتُتتبَّع المقاييس لكل خادم (الطلبات، والمقبولة، والمرفوضة، والأخطاء) في المعالج.

      تشغيل Hermes كخادم MCP​

      إلى جانب الاتصال بخوادم MCP، يمكن لـ Hermes أيضًا أن يكون خادم MCP. يتيح ذلك للوكلاء الآخرين الداعمين لـ MCP (Claude Code و Cursor و Codex أو أي عميل MCP) استخدام قدرات المراسلة في Hermes — سرد المحادثات، وقراءة سجل الرسائل، وإرسال الرسائل عبر جميع منصاتك المتصلة.

      متى تستخدم هذا​

      • تريد أن يرسل Claude Code أو Cursor أو أي وكيل برمجة آخر رسائل Telegram/Discord/Slack ويقرأها عبر Hermes
      • تريد خادم MCP واحدًا يربطك بجميع منصات المراسلة المتصلة بـ Hermes دفعة واحدة
      • لديك بالفعل gateway لـ Hermes قيد التشغيل مع منصات متصلة

      البدء السريع​

      hermes mcp serve

      يُشغّل هذا خادم MCP من نوع stdio. ويتولى عميل MCP (وليس أنت) إدارة دورة حياة العملية.

      إعداد عميل MCP​

      أضف Hermes إلى إعدادات عميل MCP لديك. على سبيل المثال، في ملف ~/.claude/claude_desktop_config.json الخاص بـ Claude Code:

      {
        "mcpServers": {
          "hermes": {
            "command": "hermes",
            "args": ["mcp", "serve"]
          }
        }
      }

      أو إذا كنت قد ثبّتّ Hermes في موقع محدد:

      {
        "mcpServers": {
          "hermes": {
            "command": "/home/user/.hermes/hermes-agent/venv/bin/hermes",
            "args": ["mcp", "serve"]
          }
        }
      }

      الأدوات المتاحة​

      يوفّر خادم MCP عشر أدوات، تطابق واجهة جسر القنوات في OpenClaw، إضافةً إلى متصفح قنوات خاص بـ Hermes:

      الأداةالوصف
      conversations_listيسرد محادثات المراسلة النشطة. يمكن التصفية حسب المنصة أو البحث بالاسم.
      conversation_getيجلب معلومات تفصيلية عن محادثة واحدة باستخدام مفتاح الجلسة.
      messages_readيقرأ سجل الرسائل الأخيرة لمحادثة ما.
      attachments_fetchيستخرج المرفقات غير النصية (الصور، والوسائط) من رسالة محددة.
      events_pollيستطلع أحداث المحادثات الجديدة منذ موضع مؤشر (cursor) معيّن.
      events_waitاستطلاع طويل (long-poll) / انتظار حتى وصول الحدث التالي (شبه فوري).
      messages_sendيرسل رسالة عبر منصة ما (مثل telegram:123456، discord:#general).
      channels_listيسرد وجهات المراسلة المتاحة عبر جميع المنصات.
      permissions_list_openيسرد طلبات الموافقة المعلّقة التي رُصدت خلال جلسة الجسر هذه.
      permissions_respondيسمح بطلب موافقة معلّق أو يرفضه.

      نظام الأحداث​

      يتضمن خادم MCP جسر أحداث حيًّا يستطلع قاعدة بيانات الجلسات في Hermes بحثًا عن رسائل جديدة. يمنح هذا عملاء MCP اطلاعًا شبه فوري على المحادثات الواردة:

      # Poll for new events (non-blocking)
      events_poll(after_cursor=0)

      # Wait for next event (blocks up to timeout)
      events_wait(after_cursor=42, timeout_ms=30000)

      أنواع الأحداث: message، approval_requested، approval_resolved

      طابور الأحداث موجود في الذاكرة ويبدأ عند اتصال الجسر. أما الرسائل الأقدم فمتاحة عبر messages_read.

      الخيارات​

      hermes mcp serve              # Normal mode
      hermes mcp serve --verbose    # Debug logging on stderr

      كيف يعمل​

      يقرأ خادم MCP بيانات المحادثات مباشرةً من مخزن الجلسات في Hermes — إذ يُعد ~/.hermes/state.db المصدر الأساسي، بينما يُحتفظ بـ sessions.json فقط كمصدر احتياطي قديم. يستطلع خيط (thread) في الخلفية قاعدة البيانات بحثًا عن رسائل جديدة ويحتفظ بطابور أحداث في الذاكرة. ولإرسال الرسائل، يستخدم محرك الإرسال الداخلي نفسه (tools/send_message_tool.py) الذي يشغّل تسليم مهام cron و CLI hermes send.

      لا يلزم أن يكون الـ gateway قيد التشغيل لعمليات القراءة (سرد المحادثات، وقراءة السجل، واستطلاع الأحداث). لكنه يلزم أن يكون قيد التشغيل لعمليات الإرسال، لأن محوّلات المنصات (platform adapters) تحتاج إلى اتصالات نشطة.

      القيود الحالية​

      • يوفّر hermes mcp serve المدمج حاليًا خادم MCP يعمل عبر stdio فقط. إذا كنت تحتاج إلى خادم HTTP MCP، فشغّل محوّلًا منفصلًا — أو، وهو الأكثر شيوعًا بكثير، استخدم جانب العميل في MCP ضمن Hermes، والذي يدعم بالفعل stdio و HTTP كليهما (url + headers في mcp_servers.yaml / config.yaml؛ راجع خوادم HTTP أعلاه).
      • استطلاع الأحداث بفواصل تقارب 200ms عبر استطلاع لقاعدة البيانات مُحسَّن بالاعتماد على mtime (يتخطى العمل عندما لا تتغير الملفات)
      • لا يوجد دعم لبروتوكول الإشعارات الفورية claude/channel بعد
      • الإرسال نصي فقط (لا يمكن إرسال وسائط/مرفقات عبر messages_send)
