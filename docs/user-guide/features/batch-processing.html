      المعالجة الدفعية (Batch Processing)

      تتيح لك المعالجة الدفعية تشغيل وكيل Hermes على مئات أو آلاف الـ prompts بالتوازي، مع توليد بيانات trajectories منظّمة. ويُستخدم ذلك أساسًا في توليد بيانات التدريب — أي إنتاج trajectories بصيغة ShareGPT مصحوبة بإحصاءات استخدام الأدوات، يمكن الاستفادة منها في fine-tuning أو التقييم.

      نظرة عامة​

      يعالج مشغّل الدفعات (batch_runner.py) مجموعة بيانات من الـ prompts بصيغة JSONL، فيمرّر كل prompt عبر جلسة وكيل كاملة مع إمكانية الوصول إلى الأدوات. ويحصل كل prompt على بيئة معزولة خاصة به. والناتج بيانات trajectories منظّمة تتضمن سجل المحادثة كاملًا، وإحصاءات استدعاءات الأدوات، ومقاييس تغطية الاستدلال (reasoning).

      البدء السريع​

      # Basic batch run
      python batch_runner.py \
          --dataset_file=data/prompts.jsonl \
          --batch_size=10 \
          --run_name=my_first_run \
          --model=anthropic/claude-sonnet-4.6 \
          --num_workers=4

      # Resume an interrupted run
      python batch_runner.py \
          --dataset_file=data/prompts.jsonl \
          --batch_size=10 \
          --run_name=my_first_run \
          --resume

      # List available toolset distributions
      python batch_runner.py --list_distributions
      تكلفة متوقعة على نطاق واسع

      تُطلق عمليات التشغيل الدفعية جلسات وكيل متزامنة كثيرة، وتُجري كلٌّ منها استدعاءات للنموذج واستدعاءات للأدوات. ويجمع اشتراك Nous Portal الوصول إلى النماذج مع البحث في الويب وتوليد الصور و TTS والمتصفحات السحابية في فاتورة واحدة — وهذا مفيد حين تريد تكلفة ثابتة لكل trajectory دون التوفيق بين حدود المعدل (rate limits) عبر حسابات خمسة مورّدين مختلفين. أجرِ الإعداد باستخدام hermes setup --portal، ثم وجّه --model إلى أحد نماذج Nous.

      صيغة مجموعة البيانات​

      مجموعة بيانات الإدخال ملف JSONL (كائن JSON واحد في كل سطر). ويجب أن يحتوي كل إدخال على الحقل prompt:

      {"prompt": "Write a Python function that finds the longest palindromic substring"}
      {"prompt": "Create a REST API endpoint for user authentication using Flask"}
      {"prompt": "Debug this error: TypeError: cannot unpack non-iterable NoneType object"}

      ويمكن أن تتضمن الإدخالات اختياريًا:

      • image أو docker_image: صورة حاوية تُستخدم في sandbox الخاص بهذا الـ prompt (تعمل مع الـ backends الخاصة بـ Docker و Modal و Singularity)
      • cwd: تجاوز لمجلد العمل في جلسة الطرفية الخاصة بالمهمة

      خيارات الإعداد​

      المعاملالقيمة الافتراضيةالوصف
      --dataset_file(مطلوب)مسار مجموعة بيانات JSONL
      --batch_size(مطلوب)عدد الـ prompts في كل دفعة
      --run_name(مطلوب)اسم عملية التشغيل هذه (يُستخدم لمجلد الإخراج ولنقاط الحفظ)
      --distribution"default"توزيع الـ toolsets الذي تُسحب منه العيّنات
      --modelclaude-sonnet-4.6النموذج المستخدم
      --base_urlhttps://openrouter.ai/api/v1عنوان URL الأساسي للـ API
      --api_key(متغير بيئة)مفتاح API للنموذج
      --max_turns10الحد الأقصى لدورات استدعاء الأدوات لكل prompt
      --num_workers4عدد عمليات العمل (worker processes) المتوازية
      --resumefalseالاستئناف من نقطة الحفظ
      --verbosefalseتفعيل السجلات المفصّلة
      --max_samplesالكلمعالجة أول N عيّنة فقط من مجموعة البيانات

      توجيه المزوّدين (OpenRouter)​

      المعاملالوصف
      --providers_allowedالمزوّدون المسموح بهم مفصولين بفواصل (مثل "anthropic,openai")
      --providers_ignoredالمزوّدون المُتجاهَلون مفصولين بفواصل (مثل "together,deepinfra")
      --providers_orderترتيب المزوّدين المفضّل مفصولين بفواصل
      --provider_sortالترتيب حسب "price" أو "throughput" أو "latency"

      التحكم في الاستدلال​

      المعاملالوصف
      --reasoning_effortمستوى جهد الاستدلال: none، minimal، low، medium، high، xhigh، max، ultra
      --reasoning_disabledتعطيل tokens الاستدلال/التفكير (thinking) تمامًا

      خيارات متقدمة​

      المعاملالوصف
      --ephemeral_system_promptsystem prompt يُستخدم أثناء التنفيذ لكنه لا يُحفظ في الـ trajectories
      --log_prefix_charsعدد الأحرف المعروضة في معاينات السجل (الافتراضي: 100)
      --prefill_messages_fileمسار ملف JSON يحتوي على رسائل تعبئة مسبقة (prefill) للتهيئة بأمثلة قليلة (few-shot)

      توزيعات الـ Toolsets​

      يحصل كل prompt على مجموعة من الـ toolsets مسحوبة عشوائيًا من توزيع (distribution). ويضمن ذلك أن تغطي بيانات التدريب تركيبات متنوعة من الأدوات. استخدم --list_distributions لعرض جميع التوزيعات المتاحة.

      في التطبيق الحالي، تُسند التوزيعات احتمالًا إلى كل toolset على حدة. إذ يقرّر مُنتقي العيّنات (sampler) تفعيل كل toolset بشكل مستقل، ثم يضمن تفعيل toolset واحد على الأقل. وهذا يختلف عن جدول مُعَدّ يدويًا من التركيبات الجاهزة.

      صيغة الإخراج​

      يُكتب كل الإخراج إلى data/<run_name>/:

      data/my_run/
      ├── trajectories.jsonl    # Combined final output (all batches merged)
      ├── batch_0.jsonl         # Individual batch results
      ├── batch_1.jsonl
      ├── ...
      ├── checkpoint.json       # Resume checkpoint
      └── statistics.json       # Aggregate tool usage stats

      صيغة Trajectory​

      كل سطر في trajectories.jsonl هو كائن JSON:

      {
        "prompt_index": 42,
        "conversations": [
          {"from": "human", "value": "Write a function..."},
          {"from": "gpt", "value": "I'll create that function...",
           "tool_calls": [...]},
          {"from": "tool", "value": "..."},
          {"from": "gpt", "value": "Here's the completed function..."}
        ],
        "metadata": {
          "batch_num": 2,
          "timestamp": "2026-01-15T10:30:00",
          "model": "anthropic/claude-sonnet-4.6"
        },
        "completed": true,
        "partial": false,
        "api_calls": 3,
        "toolsets_used": ["terminal", "file"],
        "tool_stats": {
          "terminal": {"count": 2, "success": 2, "failure": 0},
          "read_file": {"count": 1, "success": 1, "failure": 0}
        },
        "tool_error_counts": {
          "terminal": 0,
          "read_file": 0
        }
      }

      يستخدم الحقل conversations صيغة شبيهة بـ ShareGPT تتضمن الحقلين from و value. وتُوحَّد إحصاءات الأدوات بحيث تشمل جميع الأدوات الممكنة بقيم افتراضية صفرية، مما يضمن مخططًا (schema) متسقًا عبر الإدخالات للتوافق مع مجموعات بيانات HuggingFace.

      نقاط الحفظ (Checkpointing)​

      يتمتع مشغّل الدفعات بآلية قوية لنقاط الحفظ تضمن تحمّل الأعطال:

      • ملف نقطة الحفظ: يُحفظ بعد اكتمال كل دفعة، ويتتبّع فهارس الـ prompts التي اكتملت
      • الاستئناف المعتمد على المحتوى: عند استخدام --resume، يفحص المشغّل ملفات الدفعات الموجودة ويطابق الـ prompts المكتملة حسب نصها الفعلي (لا حسب الفهارس فقط)، مما يتيح الاستعادة حتى لو تغيّر ترتيب مجموعة البيانات
      • الـ prompts الفاشلة: لا تُعلَّم كمكتملة إلا الـ prompts التي اكتملت بنجاح — أما الفاشلة فتُعاد محاولتها عند الاستئناف
      • دمج الدفعات: عند الاكتمال، تُدمج جميع ملفات الدفعات (بما فيها ملفات عمليات التشغيل السابقة) في ملف واحد هو trajectories.jsonl

      آلية عمل الاستئناف​

      1. فحص جميع ملفات batch_*.jsonl بحثًا عن الـ prompts المكتملة (بمطابقة المحتوى)
      2. تصفية مجموعة البيانات لاستبعاد الـ prompts المكتملة مسبقًا
      3. إعادة تقسيم الـ prompts المتبقية إلى دفعات
      4. معالجة الـ prompts المتبقية فقط
      5. دمج جميع ملفات الدفعات (القديمة + الجديدة) في الإخراج النهائي

      تصفية الجودة​

      يطبّق مشغّل الدفعات تصفية تلقائية للجودة:

      • مرشّح غياب الاستدلال: تُستبعد العيّنات التي لا يحتوي أيٌّ من أدوار المساعد فيها على استدلال (لا <REASONING_SCRATCHPAD> ولا tokens تفكير أصلية)
      • مرشّح الإدخالات التالفة: تُستبعد أثناء الدمج النهائي الإدخالاتُ التي تحتوي على أسماء أدوات متوهَّمة (غير موجودة في قائمة الأدوات الصالحة)
      • إحصاءات الاستدلال: تتبّع نسبة الأدوار التي تتضمن استدلالًا أو تخلو منه على امتداد عملية التشغيل كاملة

      الإحصاءات​

      بعد الاكتمال، يطبع المشغّل إحصاءات شاملة:

      • استخدام الأدوات: عدد الاستدعاءات، ومعدلات النجاح/الفشل لكل أداة
      • تغطية الاستدلال: نسبة أدوار المساعد التي تتضمن استدلالًا
      • العيّنات المستبعدة: عدد العيّنات التي استُبعدت لافتقارها إلى الاستدلال
      • المدة: إجمالي وقت المعالجة

      كما تُحفظ الإحصاءات في statistics.json لتحليلها برمجيًا.

      حالات الاستخدام​

      توليد بيانات التدريب​

      ولّد trajectories متنوعة لاستخدام الأدوات بهدف fine-tuning:

      python batch_runner.py \
          --dataset_file=data/coding_prompts.jsonl \
          --batch_size=20 \
          --run_name=coding_v1 \
          --model=anthropic/claude-sonnet-4.6 \
          --num_workers=8 \
          --distribution=default \
          --max_turns=15

      تقييم النماذج​

      قيّم مدى إتقان نموذج ما لاستخدام الأدوات عبر مجموعة prompts موحّدة:

      python batch_runner.py \
          --dataset_file=data/eval_suite.jsonl \
          --batch_size=10 \
          --run_name=eval_gpt4 \
          --model=openai/gpt-4o \
          --num_workers=4 \
          --max_turns=10

      صور حاويات لكل Prompt​

      بالنسبة إلى معايير الأداء (benchmarks) التي تتطلب بيئات محددة، يمكن لكل prompt أن يحدد صورة الحاوية الخاصة به:

      {"prompt": "Install numpy and compute eigenvalues of a 3x3 matrix", "image": "python:3.11-slim"}
      {"prompt": "Compile this Rust program and run it", "image": "rust:1.75"}
      {"prompt": "Set up a Node.js Express server", "image": "node:20-alpine", "cwd": "/app"}

      يتحقق مشغّل الدفعات من إمكانية الوصول إلى صور Docker قبل تشغيل كل prompt.
