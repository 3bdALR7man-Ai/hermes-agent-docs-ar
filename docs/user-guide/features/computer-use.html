      التحكم في الحاسوب (Computer Use)

      يستطيع Hermes Agent قيادة سطح المكتب لديك — النقر والكتابة والتمرير والسحب — في الخلفية على macOS و Windows و Linux. لا يتحرك مؤشر الفأرة لديك، ولا يتغير تركيز لوحة المفاتيح، ولا تتبدّل أسطح المكتب الافتراضية / Spaces فجأةً. تعمل أنت والوكيل معًا على الجهاز نفسه.

      على خلاف معظم تكاملات computer-use، يعمل هذا مع أي نموذج يدعم استدعاء الأدوات — Claude أو GPT أو Gemini أو نموذج مفتوح على endpoint محلي متوافق مع OpenAI. ولا داعي للقلق بشأن مخطط (schema) خاص بـ Anthropic.

      آلية العمل​

      الـ toolset المدمج computer_use هو تكامل Hermes الموصى به. يتواصل عبر MCP فوق stdio مع cua-driver، وهو مشغّل (driver) مفتوح المصدر للتحكم في الحاسوب في الخلفية. وتستخدم كل منصة داخليًا حزمة إمكانية الوصول والإدخال المناسبة لها:

      المنصةشجرة إمكانية الوصول (Accessibility tree)إرسال الإدخال
      macOSAX (واجهات SkyLight SPIs خاصة)SLPSPostEventRecordTo — مقيّد بمعرّف العملية (pid)، دون قفز المؤشر
      WindowsUIAutomationSendInput + PostMessage — دون سرقة التركيز
      LinuxAT-SPI (X11 + Wayland)XTest (X11) / virtual-keyboard (Wayland)

      النتيجة واحدة على كل المنصات: يستطيع الوكيل قراءة شجرة إمكانية الوصول لأي نافذة ظاهرة، وكذلك إرسال أحداث مُصطنعة إليها دون إحضارها إلى المقدمة، أو تبديل أسطح المكتب الافتراضية، أو تحريك مؤشر نظام التشغيل الحقيقي.

      للاطلاع على العقد الأساسي — لماذا يهم وضع الخلفية، وثابت عدم الإحضار إلى المقدمة (no-foreground invariant)، والتفاصيل الداخلية لإرسال النقرات — راجع cua.ai/docs/explanation/the-no-foreground-contract.

      التفعيل​

      عمليات التثبيت الجديدة تتضمن المشغّل مسبقًا. يثبّت مُثبّت Hermes (install.sh / install.ps1) مسبقًا cua-driver (بأفضل جهد؛ مرّر --skip-computer-use / -SkipComputerUse لإلغاء ذلك)، لذا لا يتطلب تفعيل Computer Use سوى تبديل إعداد واحد:

      • hermes tools → اختر 🖱️ Computer Use — يثبّت المشغّل تلقائيًا إن كان لا يزال مفقودًا.
      • لوحة التحكم / تطبيق سطح المكتب → فعّل toolset الخاص بـ Computer Use — إذا كان المشغّل مفقودًا، يبدأ التبديل عملية التثبيت في الخلفية تلقائيًا (تابع التقدم في لوحة الـ toolset).

      البديل اليدوي (لعمليات التثبيت الأقدم، أو عند تخطي خطوة المُثبّت):

      hermes computer-use install

      يجلب هذا مُثبّت cua-driver الأصلي (upstream) ويشغّله — install.sh على macOS/Linux، و install.ps1 على Windows. استخدم hermes computer-use status للتحقق من التثبيت.

      هل لديك cua-driver مسبقًا؟ يعيد Hermes استخدامه إذا كان يدعم عقد وقت التشغيل 0.20. أثناء الإعداد، وتفعيل الـ toolset، و hermes update، وأول استدعاء لـ computer_use في الجلسة، يفحص Hermes الإصدار المحلي والـ manifest، ويُصلح التثبيت القياسي القديم أو غير المكتمل عبر المُثبّت الأصلي (مرة واحدة على الأكثر لكل جلسة أثناء التشغيل). أما الملف التنفيذي الذي تختاره عبر HERMES_CUA_DRIVER_CMD فيبقى تحت تحكمك، لذا يبلّغ Hermes عن عدم التوافق ويتركه دون تغيير.

      إذا ثبّتَّ Cua Driver أولًا، فإن cua-driver skills install يثبّت حزمة مهارات Cua ضمن ~/.cua-driver/skills/cua-driver. الاكتشاف التلقائي في Hermes ميزة مخطط لها لاحقًا في cua-driver، لذا وجّه Hermes حاليًا إلى ذلك المجلد أو أنشئ له رابطًا رمزيًا (symlink) داخل مساحة مهاراتك. يمكنك أيضًا تسجيل أدوات Cua MCP الخام كخادم MCP مخصص، لكن هذا بديل للمستخدمين الذين يحتاجون إلى الواجهة منخفضة المستوى. أما الـ toolset المدمج فيوفّر إجراءات Hermes والإعدادات والموافقات والتشخيصات.

      بعد التثبيت، وأيًّا كان المسار الذي اتبعته، امنح المتطلبات المسبقة المناسبة لمنصتك:

      المنصةالمتطلبات المسبقة
      macOSمن System Settings → Privacy & Security → Accessibility + Screen Recording. امنح الصلاحية للهوية التي يذكرها hermes computer-use doctor. يستخدم الوضع القياسي CuaDriver.app، بينما يستخدم الوضعان المقيّد (bounded) وغير المقيّد (unrestricted) هوية مضيف Hermes.
      Windowsلا شيء وقت التثبيت. إذا كنت تتحكم عبر SSH (وليس RDP / console)، فستحتاج إلى نمط التشغيل التلقائي (autostart) — راجع cua.ai/docs/how-to-guides/driver/windows-ssh للاطلاع على الوسيط (proxy) بين Session 0 ↔ Session 1+.
      Linuxخادم عرض يمكن الوصول إليه: ضبط DISPLAY لـ X11، أو XDG_SESSION_TYPE=wayland. تحتاج جلسات Wayland إلى جسر XWayland لالتقاط الشاشة. ويجب أن يكون AT-SPI مفعّلًا (مفعّل افتراضيًا على GNOME/KDE/Xfce).

      ثم ابدأ جلسة مع تفعيل الـ toolset:

      hermes -t computer_use chat

      أو أضف computer_use إلى الـ toolsets المفعّلة في ~/.hermes/config.yaml.

      أوضاع الصلاحيات وملفات تعريف المتصفح المسجّل الدخول فيها​

      يربط Hermes تجربة الموافقات الحالية لديه بأوضاع التشغيل الثابتة (immutable) في cua-driver. يُعدّ وضع الصلاحيات والموافقة على manifest القدرات من إعدادات الإطلاق، ولا يمكن تغييرهما بعد بدء الـ runtime:

      جلسة Hermesوضع cua-driverالتدخل البشري
      الموافقات اليدوية أو الذكية (الافتراضي)standardموافقات Hermes العادية؛ ويتوقف Cua عند حدّه المحمي
      computer_use.permission_mode: bounded + manifest تمت مراجعتهdaemon bounded خاصتراجع manifest القدرات وتوافق عليه مرة واحدة، عند الإطلاق
      --yolo، أو /yolo، أو approvals.mode: offdaemon unrestricted خاصقبول صريح واحد للمخاطر في Hermes؛ دون مطالبات من Cua أثناء التشغيل

      أعمال المتصفح — بما فيها الصفحات في profile مسجّل الدخول فيه — تمر عبر الـ toolset browser (browser_exec)، لا عبر computer_use. أُزيل خيار الاشتراك السابق computer_use.grant_existing_profile مع مسار المتصفح المُنمَّط (typed browser route)؛ وأي مفتاح متبقٍّ منه في config.yaml يُتجاهل.

      الوضع المقيّد (Bounded) للأتمتة القابلة للتكرار​

      لأتمتة المتصفح المتكررة (مهام cron، والبحث المجدول على تطبيق يتطلب المصادقة)، يستخدم وضع bounded ملف manifest للقدرات تراجعه مرة واحدة:

      # config.yaml
      computer_use:
        permission_mode: bounded
        capability_manifest: ~/.hermes/cua-manifest.yaml

      يحدد الـ manifest التطبيقات، وأنواع ملفات تعريف المتصفح، والأصول (origins) المسموح بها، والأدوات المُنمَّطة التي يمكن للجلسة استخدامها (راجع مرجع أوضاع الصلاحيات في cua-driver للاطلاع على الصيغة). يطلق Hermes runtime خاصًا باستخدام --capability-manifest ... --approve-capability-manifest؛ وأي شيء خارج الـ manifest يُرفض افتراضيًا (fails closed) داخل cua-driver. وإذا كان الـ manifest مفقودًا أو تتعذر قراءته، يفشل الأمر بشكل صريح عند بدء الجلسة بدلًا من التراجع بصمت إلى وضع أقل تقييدًا. ولا يزال YOLO على مستوى الجلسة يتجاوز الوضع المقيّد لتلك الجلسة وحدها.

      على macOS، تُطلَق خدمات daemon الخاصة بالجلسات عبر حزمة CuaDriver.app المثبّتة (كي تُنسب منح الصلاحيات إلى هوية المشغّل نفسه بدلًا من إعادة ضبطها مع كل بناء لـ Hermes)، ويتحقق Hermes من توقيع الكود للحزمة — المعرّف com.trycua.driver بالضبط وفريق التوقيع الرسمي — قبل إطلاقها. إذا بنيت cua-driver من المصدر (دون توقيع)، ففعّل ذلك صراحةً:

      # config.yaml
      computer_use:
        allow_unsigned_driver: true   # local driver development only

      يمتلك كل ناقل (transport) لـ MCP جلسة دورة حياة خاصة داخل الـ runtime التابع له. واسم الجلسة العام مجرد تسمية لهوية المؤشر والحالة المرتبطة بالجلسة، فهو لا يختار runtime ولا يشاركه ولا يُبقيه قيد التشغيل. يؤدي إيقاف /yolo، أو إعادة ضبط جلسة Hermes أو إغلاقها، أو التنظيف عند الإلغاء، أو خروج العملية، إلى إغلاق جلسة الناقل تلك. ويوقف Hermes أيضًا خدمات الـ runtime الخاصة التي أطلقها للوصول المقيّد أو غير المقيّد. ولا يمكن لمحادثة Hermes واحدة تغيير وضع runtime آخر أو الصلاحيات الممنوحة له. ويستخدم الوضعان المقيّد وغير المقيّد خدمة مضمّنة خاصة تعمل تحت هوية مضيف Hermes.

      تبقى الموافقة smart ضمن الوضع standard: فلا يمكن لتصنيف يجريه LLM أن يحل محل manifest تمت مراجعته.

      لا يحمي وضع YOLO/unrestricted من حقن الـ prompt (prompt injection) أو الإدخال غير المقصود. لا تستخدمه إلا في آلة افتراضية (VM) يمكن الاستغناء عنها، أو مع حسابات وبيانات تتقبّل احتمال اختراقها بالكامل.

      hermes computer-use doctor — محطتك الأولى لتشخيص المشكلات​

      ينفّذ hermes computer-use doctor أداة MCP المنظّمة health_report في cua-driver ويطبع مصفوفة نتائج لكل فحص. إنها أسرع طريقة لمعرفة سبب عدم عمل إجراء ما.

      $ hermes computer-use doctor
      ⚠️  cua-driver VERSION on darwin: degraded
        ✅ binary_version: cua-driver VERSION
        ✅ platform_supported: macOS 26.4.1 (arm64)
        ✅ session_active: MCP session is active.
        ❌ bundle_identity: Process has no CFBundleIdentifier.
            → Run the binary inside CuaDriver.app so TCC grants attribute correctly.
        ✅ tcc_accessibility: Accessibility is granted.
        ✅ tcc_screen_recording: Screen Recording is granted.
        ✅ ax_capability: AX is trusted and reachable.
        ✅ screen_capture_capability: ScreenCaptureKit reachable; 1 display(s) shareable.
      • رمز الخروج 0 عندما تكون الحالة العامة ok — كل شيء موصول بشكل صحيح.
      • رمز الخروج 1 عند degraded أو failed — فشل فحص واحد على الأقل؛ ويخبرك التلميح المرافق لكل فشل بما يجب إصلاحه.
      • رمز الخروج 2 عندما يتعذر الوصول إلى الملف التنفيذي لـ cua-driver نفسه.

      خيارات مفيدة:

      • --include CHECK — تشغيل الفحوص المذكورة فقط (كرّره لعدة فحوص)
      • --skip CHECK — تخطي فحص (له الأولوية على --include)
      • --json — إخراج الحمولة المنظّمة الخام، بنفس شكل استجابة MCP لـ tools/call health_report

      مصفوفة الفحوص تراعي المنصة: تكون bundle_identity / tcc_* بحالة skip على Windows و Linux لأن هذه المفاهيم لا تنطبق عليهما. ويفحص ax_capability واجهة AX على macOS، و UIA على Windows، و AT-SPI على Linux — مع تلميح التشخيص المناسب لكل منها عندما يتعذر الوصول إليها.

      مؤشر الوكيل والجلسات​

      عندما يعمل الوكيل، سترى مؤشرًا متراكبًا ملوّنًا ينزلق عبر الشاشة إلى موضع كل نقرة / كتابة / تمرير. أما مؤشر نظام التشغيل الحقيقي فلا يتحرك أبدًا، إذ يُظهر المؤشر المتراكب مكان عمل الوكيل. يعلن كل تشغيل لـ Hermes عن اسم جلسة عام في cua-driver (مثل hermes-3a7b9c14d2e8). يسمّي هذا الاسم هوية المؤشر والحالة المرتبطة به، لذا تحصل عمليات التشغيل المتزامنة والـ subagents على مؤشرات مميزة. ويمتلك ناقل MCP جلسة دورة الحياة الخاصة داخل الـ runtime، وليس الاسم العام.

      المؤشر المتراكب شكلي فقط — فالالتقاط والنقر والكتابة تعمل جميعها بدونه. يعطّله Hermes تلقائيًا حيث يُعرف أنه يسبب مشكلات: macOS (استهلاك المعالج أثناء الخمول)، و Linux بلا واجهة (headless) / WSL2 / الحاويات، و أسطح مكتب Linux X11 (فالمؤشر المتراكب نافذة بملء الشاشة تبقى دائمًا في المقدمة، ويمكن أن تعلق فوق كل مساحات العمل بعد انتهاء جلسة بشكل غير سليم، فتعطّل الإدخال على سطح المكتب). أما Linux Wayland و Windows فتحتفظان بالمؤشر المتراكب. اضبط computer_use.no_overlay: false في config.yaml لفرض تشغيل المؤشر (أو true لفرض إيقافه) على أي منصة.

      خصّص المؤشر عبر خيارات CLI في cua-driver أو أداة MCP وقت التشغيل set_agent_cursor_style — راجع cua.ai/docs/how-to-guides/driver/personalize-cursor للقائمة الكاملة (الشكل المدمج arrow مقابل teardrop، أو SVG / PNG / ICO مخصص عبر --cursor-icon، وألوان التدرّج أثناء التشغيل، وهالة التوهّج (bloom)).

      التعمق أكثر — حزمة مهارات cua-driver​

      يُبقي Hermes مهارة الـ wrapper الخاصة به (skills/autonomous-ai-agents/computer-use/SKILL.md) مركّزة على سير عمل computer_use من جانب Hermes ومفردات إجراءاته. وللاطلاع على تفاصيل المنصات، ودلالات التسجيل، والتفاعل مع صفحات المتصفح، وغيرها من سلوكيات Cua المتعمقة، ثبّت حزمة المهارات التي يصدرها فريق cua-driver ويصونها مباشرةً:

      cua-driver skills install

      يثبّت الأمر الحزمة ضمن ~/.cua-driver/skills/cua-driver. الاكتشاف التلقائي في Hermes ميزة مخطط لها لاحقًا في cua-driver، لذا وجّه Hermes حاليًا إلى ذلك المجلد أو أنشئ له symlink داخل مساحة مهاراتك. يظل الـ wrapper طبقة سير العمل، ويحيل إلى مهارة Cua المثبّتة فيما يخص سلوك المشغّل. تحتوي الحزمة على:

      الملفالموضوع
      SKILL.mdالنواة متعددة المنصات (ثابت اللقطة (snapshot invariant)، وعقد عدم الإحضار إلى المقدمة، وإرسال النقرات، وآليات شجرة AX)
      MACOS.mdتفاصيل macOS: عقد عدم الإحضار إلى المقدمة، والتنقل في AXMenuBar، وإرسال النقرات عبر SkyLight، وجسر JS لـ Apple Events
      WINDOWS.mdتفاصيل Windows: شجرة UIA، واستضافة UWP / ApplicationFrameHost، وعزل Session 0، ونمط التشغيل التلقائي
      LINUX.mdتفاصيل Linux: شجرة AT-SPI، و X11 / Wayland، واكتشاف محاكي الطرفية
      RECORDING.mdدلالات تسجيل المسار (trajectory) والفيديو
      WEB_APPS.mdنصائح للتفاعل مع صفحات المتصفح
      TESTS.mdسير عمل إعادة التشغيل وفق المسار (Replay-by-trajectory)

      هذه شروحات متعمقة للمنصات، وليست نسخًا مكررة من مهارة Hermes — فعندما يبلّغ الوكيل بأن "نقرتي على Windows وقعت على العنصر الخطأ"، يقرأ WINDOWS.md للاطلاع على سياق UIA / UWP الذي يوضح السبب وما يجب فعله بشكل مختلف.

      يعرض cua-driver skills status ما هو مثبّت، وأدوات تشغيل الوكلاء (agent harnesses) المرتبطة به. تغطي قائمة الاكتشاف التلقائي اليوم Claude Code و Codex و OpenCode و OpenClaw و Antigravity؛ أما الاكتشاف التلقائي لـ Hermes فمخطط له كخطوة لاحقة في trycua/cua — وحتى ذلك الحين، شغّل cua-driver skills install مرة واحدة ووجّه أداة التشغيل (harness) لديك إلى المجلد الناتج ~/.cua-driver/skills/cua-driver (أو أنشئ له symlink داخل مساحة مهاراتك المعتادة).

      مثال سريع​

      الـ prompt من المستخدم: "ابحث عن أحدث رسالة بريد إلكتروني من Stripe ولخّص ما يطلبونه مني."

      خطة الوكيل (بالشكل نفسه على macOS / Windows / Linux — إذ يستبدل النموذج الاختصار واسم التطبيق المعتادين على كل منصة):

      1. computer_use(action="capture", mode="som", app="Mail") — يحصل على لقطة شاشة لتطبيق البريد مع ترقيم كل عنصر في الشريط الجانبي، وكل زر في شريط الأدوات، وكل صف رسالة.
      2. computer_use(action="click", element=14) — ينقر على حقل البحث.
      3. computer_use(action="type", text="from:stripe")
      4. computer_use(action="key", keys="return", capture_after=True) — يرسل البحث ويحصل على لقطة الشاشة الجديدة.
      5. ينقر على النتيجة الأولى، ويقرأ نص الرسالة، ثم يلخّصه.

      طوال ذلك، يبقى مؤشرك حيث تركته، ولا يظهر تطبيق البريد في المقدمة أبدًا.

      استلام لقطة الشاشة الفعلية​

      لقطات الشاشة الملتقطة أثناء التحكم في الحاسوب داخلية عادةً — فهي موجودة كي يرى النموذج الشاشة، بينما يرد الوكيل نصيًا. لكن كل عملية التقاط للصورة تحفظ أيضًا نسخة محدودة الحجم قابلة للمشاركة في ذاكرة التخزين المؤقت للصور في Hermes وتبلّغ عن مسارها، لذا يمكنك على الواجهات التي تدعم المرفقات (Telegram و Discord و Desktop وغيرها من منصات الـ gateway) أن تطلب ببساطة:

      "أرسل لي لقطة شاشة لشاشتي."

      فيسلّمك الوكيل الصورة الحقيقية كمرفق أصلي، لا مجرد وصف لها. أما في CLI فلا توجد قناة للمرفقات، لذا يعطيك الوكيل مسار الملف المحفوظ بدلًا من ذلك.

      لا يُحتفظ إلا بأحدث 20 ملف التقاط، ولا تُرسل لقطات الشاشة تلقائيًا أبدًا — بل فقط عندما تطلب واحدة.

      الشاشة كاملة مقابل سطح المكتب​

      طلب "التقط شاشتي" يلتقط كل ما يُعرض حاليًا — صورة مركّبة لجميع النوافذ الظاهرة، كالضغط على PrtScn. لا تحتوي هذه الصورة على عناصر قابلة للنقر، لذا كي يتصرف الوكيل في شيء ضمنها، يعيد التقاط التطبيق المحدد.

      أما طلب سطح المكتب فيستهدف واجهة الـ shell الخاصة بنظام التشغيل نفسها — الخلفية وأيقونات سطح المكتب وشريط المهام — مع عناصرها القابلة للنقر، لذا تظل طلبات مثل "افتح Recycle Bin على سطح المكتب" تعمل.

      توافق المزوّدين​

      المزوّديدعم الرؤية؟يعمل؟ملاحظات
      Anthropic (Claude Sonnet/Opus 3+)✅✅الأفضل عمومًا؛ SOM + إحداثيات خام.
      OpenRouter (أي نموذج رؤية)✅✅رسائل الأدوات متعددة الأجزاء مدعومة.

      النماذج النصية فقط❌✅ (بقدرات محدودة)استخدم mode="ax" للعمل بشجرة إمكانية الوصول فقط.

      تُرسل لقطات الشاشة مضمّنةً في نتائج الأدوات كأجزاء image_url بأسلوب OpenAI. وبالنسبة إلى Anthropic، يحوّلها المحوّل (adapter) إلى كتل صور أصلية من نوع tool_result. ويأتي نوع MIME للصورة من الحقل الصريح mimeType في cua-driver (image/png أو image/jpeg) — دون فحص البايتات السحرية (magic bytes) من جانب العميل.

      الأمان​

      يطبّق Hermes حواجز حماية متعددة الطبقات:

      • تتطلب الإجراءات المؤثرة (click و type و drag و scroll و key و focus_app) موافقة — إما تفاعليًا عبر مربع حوار CLI أو عبر أزرار الموافقة في منصة المراسلة.
      • تركيبات مفاتيح محظورة تمامًا على مستوى الأداة: إفراغ سلة المحذوفات، والحذف القسري، وقفل الشاشة، وتسجيل الخروج، وتسجيل الخروج القسري.
      • أنماط كتابة محظورة تمامًا: curl | bash، و sudo rm -rf /، وقنابل fork، وغيرها.
      • يخبر system prompt الخاص بالوكيل صراحةً: لا نقر على مربعات حوار الصلاحيات، ولا كتابة لكلمات المرور، ولا اتباع لتعليمات مضمّنة في لقطات الشاشة.

      استخدمه مع approvals.mode: manual في ~/.hermes/config.yaml إذا أردت تأكيد كل إجراء.

      كفاءة استهلاك الـ tokens​

      لقطات الشاشة مكلفة. لذا يطبّق Hermes أربع طبقات من التحسين:

      • إزالة لقطات الشاشة القديمة — يُبقي محوّل Anthropic آخر 3 لقطات شاشة فقط في السياق؛ وتتحول الأقدم منها إلى عناصر نائبة [screenshot removed to save context].
      • التقليم ضمن الضغط من جانب العميل — يكتشف ضاغط السياق نتائج الأدوات متعددة الوسائط ويزيل أجزاء الصور من القديمة منها.
      • تقدير الـ tokens مع مراعاة الصور — تُحتسب كل صورة بنحو 1500 token (السعر الثابت لدى Anthropic) بدلًا من طول أحرفها بترميز base64.
      • تحرير السياق من جانب الخادم (Anthropic فقط) — عند تفعيله، يفعّل المحوّل clear_tool_uses_20250919 عبر context_management كي تمسح API الخاصة بـ Anthropic نتائج الأدوات القديمة من جانب الخادم.

      تكلّف جلسة من 20 إجراءً على شاشة بدقة 1568×900 عادةً نحو 30K token من سياق لقطات الشاشة، لا نحو 600K.

      القيود​

      • الأداء. وضع الخلفية أبطأ من العمل في المقدمة — تستغرق الأحداث الموجّهة عبر إمكانية الوصول نحو 5–20 ms على macOS، ونحو 3–10 ms على Windows UIA، ونحو 5–15 ms على Linux AT-SPI، مقارنةً بالإرسال المباشر عبر HID. لا يُلاحظ ذلك في النقر بسرعة الوكيل، لكنه ملحوظ إذا حاولت تسجيل speed-run.
      • لا إدخال لكلمات المرور عبر لوحة المفاتيح. لدى type أنماط حظر صارمة على حمولات أوامر الـ shell؛ أما كلمات المرور فاستخدم لها الملء التلقائي في النظام (macOS Keychain / Windows Credential Manager / GNOME Keyring / KWallet).
      • بعض التطبيقات لا تكشف شجرة إمكانية الوصول. تطبيقات UWP الحديثة على Windows، و Electron < 28 على Linux، وبعض تطبيقات macOS ذات الرسم المخصص (Logic و Final Cut وبعض الألعاب) لديها أشجار AX شحيحة أو فارغة. ارجع إلى إحداثيات البكسل إذا كانت الشجرة فارغة — أو تخطَّ المهمة كليًا.
      • Windows: لا يمكن التحكم في النوافذ ذات الصلاحيات المرتفعة (admin) من وكيل عادي. يفرض Windows UIPI (User Interface Privilege Isolation) حدودًا بين مستويات السلامة (integrity levels): فلا يمكن لعملية بمستوى Medium (وكيل Hermes الافتراضي) سرد شجرة UIA لنافذة تملكها عملية بمستوى High (Administrator)، ولا حقن إدخال الفأرة فيها. العَرَض: يعيد capture(mode='som') صفر عناصر، ويبلّغ click(...) بالنجاح دون أن يفعل شيئًا، رغم أن لقطة الشاشة تُعرض بشكل سليم (لأن التقاط GDI يقع أسفل فحص السلامة). تتجاوز أحداث لوحة المفاتيح UIPI جزئيًا، لذا يظل بإمكان Tab / Enter التنقل في مربع حوار مرتفع الصلاحيات. هذا قيد من نظام التشغيل وليس خطأً في cua-driver — وهو يؤثر في كل حزم الأتمتة على Windows. للتحكم في النوافذ مرتفعة الصلاحيات، شغّل وكيل Hermes نفسه بمستوى High (أطلقه من طرفية مرتفعة الصلاحيات)؛ وإلا فاستهدف النوافذ غير المرتفعة الصلاحيات.
      • مشكلات نشر خاصة بكل منصة:
        • يستخدم macOS واجهات SkyLight SPIs خاصة، وقد تغيّرها Apple في أي تحديث لنظام التشغيل. ويحذّر Hermes عندما يكون cua-driver المثبّت أقدم من الإصدار الذي اختُبر عليه.
        • تعمل جلسات SSH على Windows في Session 0، التي لا تحتوي على سطح مكتب تفاعلي. شغّل Hermes من داخل جلسة RDP / console، أو اضبط مهمة Scheduled Task الخاصة بالتشغيل التلقائي في cua-driver — ستجد الطريقة في windows-ssh.
        • يتطلب Linux خادم عرض يمكن الوصول إليه. تحتاج الخوادم بلا واجهة إلى Xvfb (Xvfb :99 -screen 0 1920x1080x24) قبل أن يتمكن computer_use من الالتقاط أو حقن الأحداث. وتحتاج جلسات Wayland الخالصة إلى جسر XWayland لالتقاط الشاشة (أما مسار الحقن الخاص بـ Wayland في cua-driver فيتعامل مع الإدخال بشكل مستقل).

      لأتمتة واجهات المستخدم الرسومية عبر المنصات دون عبء سطح المكتب (ودون إعداد TCC / Session 0 / X11)، يستخدم الـ toolset browser متصفح Chromium حقيقيًا بلا واجهة، وهو الخيار الصحيح لمهام الويب فقط.

      الإعدادات​

      وضع الصلاحيات والـ manifest (راجع أوضاع الصلاحيات أعلاه):

      computer_use:
        permission_mode: standard        # standard (default) | bounded
        capability_manifest: ""          # capability manifest path, required for bounded

      على Linux، يظل دعم Wayland الأصلي خيارًا يتطلب تفعيلًا صريحًا. يمرّر Hermes هذا التفعيل إلى كل عملية cua-driver، بما في ذلك جلسات الـ gateway، فقط عندما تمتلك تلك العملية أيضًا WAYLAND_DISPLAY:

      computer_use:
        native_wayland: true

      أعد تشغيل الـ gateway العامل بعد تغيير هذا الإعداد.

      تجاوز مسار الملف التنفيذي للمشغّل (للاختبارات / CI / البنايات المحلية):

      HERMES_CUA_DRIVER_CMD=/path/to/your/cua-driver

      استبدل الـ backend بالكامل (للاختبار):

      HERMES_COMPUTER_USE_BACKEND=noop   # records calls, no side effects

      القياس عن بُعد (Telemetry)​

      يأتي cua-driver في مصدره الأصلي مع قياس عن بُعد مجهول الهوية للاستخدام (PostHog) مفعّل افتراضيًا. يعطّله Hermes نيابةً عنك — ففي كل استدعاء لـ cua-driver (الـ backend الخاص بـ MCP، و status، و doctor، والتثبيت) يضبط Hermes CUA_DRIVER_RS_TELEMETRY_ENABLED=0 في بيئة المشغّل.

      لإعادة التفعيل (والسماح لـ cua-driver باستخدام إعداده الافتراضي وإرسال بيانات القياس)، اضبط ما يلي في config.yaml:

      computer_use:
        cua_telemetry: true   # default: false (telemetry off)

      عند التفعيل، يبلّغ hermes computer-use doctor بـ telemetry: enabled؛ وعند الإيقاف (الافتراضي)، يبلّغ بـ telemetry: disabled via CUA_DRIVER_RS_TELEMETRY_ENABLED.

      الاختبار باستخدام بناء محلي لـ cua-driver​

      عندما تطوّر cua-driver نفسه — أو تريد اختبار إصلاح لم يُصدر بعد — وجّه Hermes إلى ملف تنفيذي بنيته من المصدر بدلًا من الإصدار المنشور. يحدد Hermes موقع المشغّل عبر shutil.which("cua-driver") ولا يفرض HERMES_CUA_DRIVER_VERSION، لذا يُقبل البناء المحلي (الذي يظهر إصداره على شكل 0.0.0-local-*) كما هو. هناك طريقتان:

      الخيار A — install-local (البناء ثم إضافته إلى PATH)​

      من النسخة المسحوبة (checkout) لديك من trycua/cua، شغّل المُثبّت المحلي الأصلي. فهو يبني الـ backend المكتوب بـ Rust في وضع الإصدار (release) ويضع cua-driver في بنية التثبيت نفسها التي يستخدمها مُثبّت الإنتاج، مع إضافة مجلد bin الخاص به إلى PATH لديك:

      # Windows (PowerShell), from the cua repo root
      ./libs/cua-driver/scripts/install-local.ps1 -NoAutoStart
      # macOS / Linux, from the cua repo root  (defaults to a debug build without --release)
      ./libs/cua-driver/scripts/install-local.sh --release
      • على Windows يُجهَّز البناء ضمن %USERPROFILE%\.cua-driver\packages\… ويُربط إليه %LOCALAPPDATA%\Programs\Cua\cua-driver\bin (المُضاف إلى PATH الخاص بالمستخدم) عبر junction. أما على macOS/Linux فيُنشأ symlink لـ cua-driver داخل ~/.local/bin (يمكنك تغييره عبر --bin-dir <path>).
      • يتخطى -NoAutoStart تسجيل خدمة daemon cua-driver-serve التي تعمل عند تسجيل الدخول — فلا تحتاج إليها لاختبار Hermes (راجع الملاحظات).

      ثم افتح shell جديدًا (كي يظهر تغيير PATH) وتحقق:

      cua-driver --version                 # local builds report 0.0.0-local-release
      # Windows:      (Get-Command cua-driver).Source
      # macOS/Linux:  which cua-driver

      الخيار B — توجيه Hermes مباشرةً إلى الملف التنفيذي المبني (أسرع دورة عمل)​

      تخطَّ إجراءات التثبيت كليًا: نفّذ cargo build واضبط HERMES_CUA_DRIVER_CMD على الملف التنفيذي الناتج. هذا الخيار هو الأنسب لدورة التعديل/البناء/الاختبار السريعة.

      cargo build -p cua-driver            # add --release for a release build; run from libs/cua-driver/rust
      # Windows (.env)
      HERMES_CUA_DRIVER_CMD=C:\path\to\cua\libs\cua-driver\rust\target\debug\cua-driver.exe
      # macOS / Linux (.env)
      HERMES_CUA_DRIVER_CMD=/path/to/cua/libs/cua-driver/rust/target/debug/cua-driver

      التأكد من أن Hermes يستخدم بناءك​

      • يطبع hermes computer-use status مسار الملف التنفيذي الذي حُدِّد وإصداره.
      • يتأكد hermes computer-use doctor من إمكانية الوصول إلى الملف التنفيذي ويختبر مسار MCP الكامل من البداية إلى النهاية.
      • داخل الجلسة، يختبر computer_use(action="capture") العملية الفرعية cua-driver mcp التي أُطلقت.

      ملاحظات ومزالق​

      • يُطلق Hermes وسيط stdio من نوع cua-driver mcp. في الجلسة العادية يتصل هذا الوسيط بخدمة daemon القياسية على الجهاز (وقد يشغّلها). أما في وضع YOLO الصريح في Hermes، فيمتلك Hermes بدلًا من ذلك عملية فرعية خاصة cua-driver serve --embedded ويوجّه الوسيط إلى الـ socket أو الـ named pipe الخاص بها. ولا يزال نمط autostart/UIAccess على Windows مهمًا للإدخال التفاعلي في Session 1+ عبر SSH — راجع قسم القيود.
      • الملف التنفيذي المقفل على Windows. قد تحتفظ خدمة daemon cua-driver-serve العاملة بالملف cua-driver.exe وتمنع استبداله عند إعادة البناء. يعيد install-local.ps1 تسمية الملف التنفيذي المقفل تلقائيًا لإبعاده عن الطريق؛ أما إذا نفّذت cargo build يدويًا (الخيار B)، فأوقفها أولًا عبر cua-driver autostart disable (أو schtasks /End /TN cua-driver-serve).
      • دورة إعادة البناء. بعد تعديل مصدر cua-driver، أعد تشغيل install-local (يعيد البناء والتجهيز ويبدّل junction current) في الخيار A، أو أعد تنفيذ cargo build فقط في الخيار B — ولا حاجة إلى أي تغيير في Hermes في الحالتين.
      • البنايات المحلية تتخطى فحص الإصدار. يحذّر Hermes عندما يكون cua-driver المثبّت أقدم من خط الأساس المختبَر لكل نظام تشغيل، لكنه يستثني بنايات التطوير 0.0.0-local-* — لذا لن يؤدي بناؤك المحلي إلى ظهور ذلك التحذير أبدًا.

      استكشاف الأخطاء وإصلاحها​

      أول ما تفعله عند حدوث أي خلل: شغّل hermes computer-use doctor. تخبرك مصفوفة الفحوص المنظّمة (وتخبر أي وكيل يساعدك في التصحيح) بالضبط بما هو خاطئ.

      حالات فشل محددة لا يكتشفها doctor:

      computer_use backend unavailable: cua-driver is not installed — شغّل hermes computer-use install لجلب الملف التنفيذي لـ cua-driver، أو شغّل hermes tools وفعّل toolset الخاص بـ Computer Use.

      النقرات تبدو بلا أثر — التقط الشاشة وتحقق. قد تكون هناك نافذة منبثقة (modal) لم ترها تحجب الإدخال. أغلقها باستخدام escape أو زر الإغلاق.

      فهارس العناصر قديمة — فهارس SOM صالحة فقط حتى عملية capture التالية. أعد الالتقاط بعد أي إجراء يغيّر الحالة. يحمل الـ wrapper قيم element_token مبهمة لاكتشاف الفهارس القديمة — لذا سترى خطأً صريحًا بدلًا من نقرة خاطئة.

      "blocked pattern in type text" — النص الذي حاولت كتابته عبر type يطابق قائمة أنماط الـ shell الخطرة. قسّم الأمر أو أعد النظر فيه.

      التقاطات فارغة على Linux — DISPLAY غير مضبوط، أو أنك تعمل على Wayland خالص دون جسر XWayland. سيشير hermes computer-use doctor إلى ذلك بـ ax_capability: fail مع التلميح Set DISPLAY (X11)….

      التقاطات فارغة على Windows عبر SSH — أنت في Session 0 (جلسة الخدمات). تحكّم مباشرةً من RDP / console، أو اضبط نمط التشغيل التلقائي — راجع cua.ai/docs/how-to-guides/driver/windows-ssh.

        • تخصيص مؤشر الوكيل — الأشكال المدمجة، والأصول المخصصة، والتجاوزات أثناء التشغيل
        • التحكم في Windows عبر SSH — نمط التشغيل التلقائي من Session 0 → Session 1+
        • إبقاء cua-driver قيد التشغيل — التشغيل التلقائي / دورة حياة الـ daemon
        • ربط وكيلك — تسجيل cua-driver مع أدوات تشغيل الوكلاء (harnesses) المختلفة (ومنها Hermes)
