      كلمة التنبيه ("Hey Hermes")

      تجعل كلمة التنبيه (wake word) من Hermes مساعدًا يعمل دون استخدام اليدين عبر CLI و TUI وتطبيق سطح المكتب: فبتفعيل إعداد واحد، يستمع Hermes في الخلفية إلى عبارة تنبيه منطوقة. قُلها، وسيبدأ Hermes جلسة جديدة، ويفتح الميكروفون، ويلتقط أمرك عبر pipeline الصوت المعتاد، ثم يجيب — تمامًا مثل "Hey Siri" أو "Alexa". استخدم surface لاختيار الواجهة التي تستمع.

      يعمل الاكتشاف بالكامل على الجهاز. ولا يراقب المستمع الدائم إلا عبارة التنبيه؛ فلا يغادر أي صوت جهازك حتى تنطق فعليًا أمرًا موجّهًا إلى الوكيل.

      آلية العمل​

      1. مع wake_word.enabled: true (أو بعد /wake on)، يستمع كاشف hotword خفيف إلى جهاز الإدخال الذي ضبطته، أو إلى الميكروفون الافتراضي للعملية عندما لا يكون wake_word.input_device مضبوطًا.
      2. عندما يسمع عبارة التنبيه، يوقف نفسه مؤقتًا (محرّرًا الميكروفون)، ويبدأ جلسة جديدة، ويسجّل عبارة منطوقة واحدة باستخدام اكتشاف الصمت الخاص بالوضع الصوتي.
      3. يُحوَّل كلامك إلى نص ويُرسل إلى الوكيل. وبعد أن يرد، يستأنف المستمع عمله تلقائيًا وينتظر كلمة التنبيه التالية.

      وهي معطّلة افتراضيًا — فلا شيء يستمع حتى تفعّلها.

      في تطبيق سطح المكتب، يمكن إنهاء المحادثة الصوتية التي تجري دون استخدام اليدين ببساطة بقول "stop" (أو "never mind"، "goodbye"، "cancel"، "that's all") — فينهي الأمر المنطوق المحادثة بدلًا من إرساله إلى الوكيل. ولا يُطابَق إلا أمر الإيقاف الذي يشكّل العبارة المنطوقة كاملة، لذا فإن طلبًا حقيقيًا مثل "stop the docker container" يمر بشكل طبيعي.

      سطح المكتب البعيد (الالتقاط من جهة العميل)​

      عندما يتصل تطبيق سطح المكتب بـ Hermes backend بعيد (مثل مضيف Docker بلا واجهة أو جهاز في غرفة أخرى)، فغالبًا لا يكون لدى الـ backend أي ميكروفون. عندها يفشل PortAudio من جهة الخادم بالرسالة “Failed to open the wake-word microphone.”

      يدعم Hermes الالتقاط من جهة العميل (client capture) لهذه الحالة:

      1. يُفعّل تطبيق سطح المكتب التنبيه مع capture: client (تلقائيًا في الواجهة الرسومية عندما لا يملك الـ backend جهاز إدخال محليًا، أو بضبطه صراحةً كما هو موضح أدناه).
      2. يظل openWakeWord يعمل على الـ backend (المحركات نفسها، والنماذج نفسها).
      3. يفتح تطبيق سطح المكتب ميكروفون جهاز Mac/PC المحلي، ويعيد أخذ العينات إلى 16 kHz mono int16، ويبث إطارات قصيرة عبر RPC المسمى wake.feed.
      4. عند الاكتشاف، يُطلق الـ backend الحدث wake.detected كالمعتاد؛ ويبدأ تطبيق سطح المكتب pipeline الصوت المعتاد على ميكروفون العميل.
      wake_word:
        enabled: true
        capture: auto    # auto | local | client
        # auto   — local PortAudio unless the desktop arms with client_capture
        # local  — always open the backend mic (CLI/TUI default)
        # client — always expect wake.feed PCM from the desktop (remote-friendly)

      تمرّر الواجهة الرسومية لسطح المكتب دائمًا client_capture: true عند wake.start، لذا فإن الـ backends البعيدة التي لا تملك ميكروفونًا تُفعَّل في وضع العميل تلقائيًا. أما CLI و TUI فيحتفظان بالالتقاط المحلي ما لم تضبط capture: client صراحةً.

      ملاحظة حول الخصوصية: مع الالتقاط من جهة العميل، تنتقل بيانات PCM الخاصة بالتنبيه عبر اتصال WebSocket المُصادَق عليه بين سطح المكتب↔الـ backend (القناة نفسها المستخدمة لبقية الجلسة). ولا يزال الاكتشاف لا يرسل الصوت إلى APIs تنبيه تابعة لجهات خارجية؛ فالمحرك محلي داخل عملية الـ backend.

      المحركات​

      المحركالتكلفةمفتاح APIملاحظات
      openWakeWord (الافتراضي)مجانيلا يوجدنماذج ONNX محلية. يأتي مع نموذج مضمّن هو "hey hermes" (الافتراضي)؛ ويدعم أيضًا hey_jarvis و alexa و hey_mycroft و… والنماذج المخصصة
      sherpaمجانيلا يوجدمفردات مفتوحة — يكتشف أي عبارة مكتوبة دون أي تدريب. يُنزَّل نموذج إنجليزي صغير تلقائيًا عند أول استخدام (~13 MB)
      Porcupineفئة مجانية / مدفوعPORCUPINE_ACCESS_KEYمحرك Picovoice؛ كلمات مفتاحية مدمجة + ملفات .ppn مخصصة

      العبارة الافتراضية هي "hey hermes" — ويأتي نموذج خاص بها مع Hermes، لذا تعمل مباشرة دون أي تدريب. (عند أول استخدام، يُنزّل openWakeWord نماذج استخراج الميزات المشتركة الخاصة به — وهو تنزيل صغير لمرة واحدة.)

      يُثبَّت كلاهما بشكل كسول (lazy) في أول مرة تفعّل فيها كلمة التنبيه (أما عمليات تثبيت سطح المكتب التي تُجرى باستخدام --include-desktop فتثبّتها مسبقًا، فتعمل أيقونة الأذن فورًا). للتثبيت مسبقًا:

      cd ~/.hermes/hermes-agent && uv pip install -e ".[wake]"

      البدء السريع​

      # In an interactive `hermes` session:
      /wake on        # start listening (installs the engine on first use)
      /wake status    # show phrase, provider, and state
      /wake off       # stop listening

      في تطبيق سطح المكتب، انقر أيقونة الأذن في مربع الكتابة (composer).

      زر التبديل هو الإعداد نفسه: فتفعيل كلمة التنبيه أو تعطيلها — عبر /wake أو زر الأذن في سطح المكتب — يكتب أيضًا wake_word.enabled إلى ~/.hermes/config.yaml، فيبقى اختيارك محفوظًا عبر الجلسات. ويمكنك أيضًا تغييره يدويًا:

      wake_word:
        enabled: true

      الإعدادات​

      wake_word:
        enabled: false
        surface: auto               # eligible surface: "auto" | "cli" | "tui" | "gui"
        input_device: null           # PortAudio input index or device-name substring; null = process default
        capture: auto               # auto | local | client — where PCM is captured (see Remote desktop)
        provider: openwakeword      # "openwakeword" (free, local) | "sherpa" (free, any phrase) | "porcupine"
        phrase: "hey hermes"        # cosmetic label only — detection is keyed by the model/keyword below
        sensitivity: 0.6            # 0.0-1.0 — higher = stricter (fewer false triggers), consistent across all engines
        confirmation_frames: 3      # openWakeWord only — consecutive over-threshold frames required to fire
        start_new_session: true     # start a fresh session on wake vs. continue the current one
        openwakeword:
          model: hey_hermes         # bundled default; OR a built-in name OR a path to a custom .onnx/.tflite
          inference_framework: ""   # "" (auto) | "onnx" | "tflite"
        porcupine:
          keyword: jarvis           # built-in keyword OR path to a custom .ppn

      تنطبق sensitivity و phrase و start_new_session على كلا المحركين. وتحدد الكتلتان openwakeword و porcupine نموذج الاكتشاف الفعلي.

      يُمرَّر input_device مباشرة إلى تدفق PortAudio (sounddevice) الخاص بمستمع التنبيه. استخدم إما فهرس جهاز رقميًا أو جزءًا من اسم الجهاز لا يحتمل اللبس. يغيّر هذا الإعداد التقاط كلمة التنبيه فقط؛ إذ تظل ميزة push-to-talk في سطح المكتب تستخدم مسار الميكروفون الخاص بتطبيق سطح المكتب.

      تقليل التنبيهات الخاطئة الناتجة عن الكلام المحيط​

      يقيّم openWakeWord إطارًا صوتيًا قصيرًا واحدًا (~80ms) في كل مرة، لذا قد يتسبب صوت لغوي (phoneme) عابر في محادثة خلفية أحيانًا في رفع درجة إطار واحد فوق العتبة وإطلاق كلمة التنبيه دون قصد. يتحكم في ذلك خياران:

      • confirmation_frames (الافتراضي 3، في openWakeWord فقط) — عدد الإطارات المتتالية التي تتجاوز العتبة والمطلوبة قبل إطلاق التنبيه. فعبارة "hey hermes" الحقيقية تحافظ على درجة عالية عبر عدة إطارات؛ بينما يرفع الصوت المحيط العابر إطارًا واحدًا فقط. ارفع القيمة (مثل 4–5) إذا ظلت التنبيهات الخاطئة تحدث في غرفة صاخبة؛ والثمن بضع عشرات من المللي ثانية من التأخير الإضافي. وتعيد القيمة 1 السلوك القديم الذي يُطلق التنبيه عند أول إطار.
      • sensitivity (الافتراضي 0.6) — عتبة الاكتشاف، من 0.0 إلى 1.0. القيمة الأعلى أكثر صرامة (تنبيهات خاطئة أقل). وهذا الاتجاه متسق عبر جميع المحركات — ففي openWakeWord هي عتبة الدرجة الخام لكل إطار، وفي sherpa تُحوَّل إلى عتبة الكلمة المفتاحية، وفي Porcupine تُعكس داخليًا كي تبقى قاعدة "أعلى = أكثر صرامة" سارية هناك أيضًا. تقع القيمة الافتراضية 0.6 فوق خط الأساس المتساهل 0.5 في openWakeWord، والذي كان يسمح بمرور عبارات قريبة مثل "hey hor"؛ ارفعها نحو 0.8 إذا ظلت التنبيهات الخاطئة تحدث، واخفضها إذا فاتت عبارات "hey hermes" الحقيقية.

      يفك المحركان sherpa و porcupine ترميز العبارة كاملة داخليًا، لذا لا يعانيان من مشكلة ارتفاع الإطار الواحد ويتجاهلان confirmation_frames (لكنهما يلتزمان بـ sensitivity).

      يحدد inference_framework الـ backend الخاص بـ openWakeWord. اتركه فارغًا (الافتراضي) ليختار Hermes حسب المنصة: tflite على Apple Silicon، و onnx في كل مكان آخر. إذ يعيد الـ onnx backend في openWakeWord درجات قريبة من الصفر على macOS ARM64 (openWakeWord#336)، لذا فإن المستمع المثبّت على onnx هناك سيُفعَّل ويظهر كأنه يستمع، لكنه لن يُطلق التنبيه أبدًا. ويحتاج الـ tflite backend إلى ai-edge-litert على macOS، والذي يثبّته Hermes عند الطلب إلى جانب اعتماديات كلمة التنبيه الأخرى.

      الواجهات (CLI و TUI و GUI)​

      تعمل كلمة التنبيه في واجهات Hermes الثلاث جميعها، ويحدد surface الواجهة التي تمتلك المستمع وتفتح الجلسة الجديدة عند إطلاق التنبيه:

      surfaceالسلوك
      auto (الافتراضي)جميع الواجهات المحلية مؤهلة؛ وأول واجهة تُفعّل التنبيه تمتلك المستمع.
      cliواجهة hermes CLI الكلاسيكية فقط.
      tuihermes --tui فقط.
      guiتطبيق سطح المكتب فقط.

      الكاشف يعمل على الجهاز ويستخدم ميكروفونًا واحدًا، لذا لا تستمع إلا واجهة واحدة في كل مرة، حتى عندما تعمل واجهات Hermes في عمليات منفصلة. والملكية ثابتة: إذ يحتفظ أول طالب مؤهل بالمستمع حتى يتوقف، أو ينقطع اتصاله، أو تنتهي عمليته. ولا ينتقل Hermes بصمت إلى واجهة أخرى مفتوحة. اضبط surface عندما تريد تثبيت الملكية بدلًا من قاعدة "الأسبق يفوز". تتشارك TUI والواجهة الرسومية لسطح المكتب الـ backend نفسه المكتوب بـ Python (tui_gateway)، والذي يشغّل الكاشف من جهة الخادم ويتنازل عن الميكروفون لالتقاط الصوت أثناء تسجيل أمر.

      استخدام عبارة مختلفة​

      تعمل "Hey Hermes" مباشرة — فنموذج openWakeWord المضمّن (model: hey_hermes) هو الافتراضي. وللتنبيه بعبارة أخرى، فإن أسهل طريق هو محرك المفردات المفتوحة:

      الخيار A — sherpa (أي عبارة، دون تدريب)​

      اكتب العبارة التي تريدها؛ إذ تُقسَّم إلى tokens وقت التشغيل — "hey coder"، "computer"، "wake up neo"، أي شيء:

      wake_word:
        enabled: true
        provider: sherpa
        phrase: "hey coder"        # detection key — just type your phrase

      يُنزَّل نموذج KWS الإنجليزي الصغير (~13 MB) مرة واحدة عند أول استخدام. ويمكن لكل profile ضبط عبارته الخاصة — "hey <profile>" لكل profile تشغّله.

      إيقاظ profile محدد (سطح المكتب)​

      مع محرك sherpa، يستطيع مستمع واحد فقط إيقاظ أي profile. إذ يُسجَّل تلقائيًا كل profile تحتوي إعداداته على wake_word.enabled: true؛ وتكون عبارته الافتراضية hey <profile name> عندما لا تكون مضبوطة. قل عبارة profile ما، وسينتقل تطبيق سطح المكتب مباشرة إلى ذلك الـ profile، ويفتح جلسة جديدة فيه، ويبدأ الصوت دون استخدام اليدين:

      • "hey hermes" → الـ profile الافتراضي
      • "hey coder" → الـ profile coder
      • "hey trader" → الـ profile trader

      اضبط wake_word.profile_routing: false على profile المستمع لإلغاء هذا السلوك والاستماع لعبارته الخاصة فقط. أما CLI و TUI فهما عمليتان أحاديتا الـ profile: فعبارة التنبيه التي تخص profile آخر تطبع أمر التبديل (hermes -p <profile>) بدلًا من التوجيه.

      تُطابَق الأسماء صوتيًا بحسب أصوات مقاطعها الفرعية الإنجليزية: وتعمل العبارات المكونة من كلمتين بأسماء مميزة من مقطعين صوتيين أو أكثر بشكل أفضل. أما الأسماء القصيرة جدًا، أو الأسماء ذات النطق البعيد كثيرًا عن الإنجليزية، أو وجود اثنين من الـ profiles بأسماء متشابهة النطق، فستُضعف الدقة — اضبط sensitivity لكل profile عند الحاجة.

      الخيار B — openWakeWord (مجاني، نموذج مُدرَّب)​

      حدد اسم نموذج مدمج (hey_jarvis، alexa، hey_mycroft، …)، أو درّب نموذجًا مخصصًا (≈75–90 دقيقة على GPU مجاني/Colab) لأقصى قدر من المتانة، وضع ملف .onnx في أي مكان، ثم أشِر إليه:

      wake_word:
        enabled: true
        provider: openwakeword
        phrase: "computer"
        openwakeword:
          model: ~/.hermes/wakewords/computer.onnx   # or a built-in name like hey_jarvis

      مراجع التدريب:

      • openWakeWord
      • Colab التدريب لعام 2026
      اختر عبارة مميزة

      عبارات التنبيه التي لا تتداخل مع الكلام اليومي تعمل بشكل أفضل. فكلمة غير شائعة من مقطعين صوتيين ("hermes" مثال مناسب) تتفوق على الكلمات الشائعة مثل "hello" أو "stop".

      الخيار C — Porcupine (كلمة مفتاحية مخصصة في ثوانٍ)​

      أنشئ كلمة مفتاحية "Hey Hermes" في Picovoice Console، ونزّل ملف .ppn، ثم:

      wake_word:
        enabled: true
        provider: porcupine
        phrase: "hey hermes"
        porcupine:
          keyword: ~/.hermes/wakewords/hey_hermes.ppn

      اضبط مفتاح الوصول الخاص بك في ~/.hermes/.env:

      PORCUPINE_ACCESS_KEY=your-key-here

      المتطلبات​

      • ميكروفون يعمل وحزمة الصوت sounddevice + numpy (المشتركة مع الوضع الصوتي).
      • مزوّد STT لتحويل الأمر المنطوق إلى نص — يعمل faster-whisper المحلي مباشرة؛ راجع الوضع الصوتي (Voice Mode) للاطلاع على القائمة الكاملة للمزوّدين.
      • مزوّد TTS لنطق الرد (يعمل edge-tts الافتراضي دون مفتاح). ولأن مسار التنبيه يعمل بالكامل دون استخدام اليدين، يرفض زر التبديل التفعيل حتى يكون كل من STT و TTS جاهزين — ويتولى hermes tools (قسم Voice) إعدادهما.
      • اعتماديات محرك التنبيه (تُثبَّت تلقائيًا، أو عبر hermes-agent[wake]).

      يُبلغ /wake status بالضبط عمّا ينقص إذا لم يبدأ المستمع.

      "Listening" لكنه لا يستيقظ أبدًا (macOS)​

      يمنح macOS صلاحية الوصول إلى الميكروفون لكل عملية على حدة. فعمل STT في تطبيق سطح المكتب يثبت أن الـ renderer لديه صلاحية الوصول إلى الميكروفون — أما مستمع التنبيه فيعمل في الـ backend المكتوب بـ Python، والذي يحتاج إلى صلاحية خاصة به. وبدونها، يسلّم CoreAudio الـ backend تدفقًا "يعمل" لكنه لا ينقل إلا الصمت، فتظهر أيقونة الأذن وكأنها تستمع لكن العبارة لا تُطلق التنبيه أبدًا. يكتشف Hermes هذه الحالة (يعرض /wake status الرسالة "mic delivers only silence"؛ ويحمل التلميح المنبثق لأيقونة الأذن في سطح المكتب الإشارة نفسها). الحل: System Settings → Privacy & Security → Microphone → فعّل Hermes backend (قد يظهر باسم الطرفية لديك، أو python، أو Hermes)، ثم عطّل كلمة التنبيه وأعد تفعيلها.

      "Listening" لكنه لا يستقبل إلا الصمت (Windows)​

      يستخدم push-to-talk والتقاط كلمة التنبيه في سطح المكتب مسارين مختلفين للميكروفون. إذ يستخدم push-to-talk التقاط المتصفح الخاص بتطبيق سطح المكتب، بينما يفتح مستمع كلمة التنبيه تدفق PortAudio في الـ backend المكتوب بـ Python. لذا قد يعمل أحدهما بينما يختار الآخر جهاز إدخال Windows صامتًا أو غير صالح للاستخدام.

      يُبلغ /wake status عن جهاز الإدخال المحدد و host API الصوت في Windows. وعندما يُبلغ عن صمت، اضبط wake_word.input_device على الفهرس الرقمي أو على اسم لا يحتمل اللبس لجهاز إدخال PortAudio الذي يعمل، ثم بدّل حالة كلمة التنبيه:

      hermes config set wake_word.input_device "Microphone Array"

      استخدم null للعودة إلى الجهاز الافتراضي للعملية:

      hermes config set wake_word.input_device null

      ملاحظات وقيود​

      • الواجهات المحلية فقط. تعمل كلمة التنبيه في CLI و TUI والواجهة الرسومية لسطح المكتب — أينما يتوفر ميكروفون محلي. ولا تعمل في messaging gateway (Telegram و Discord و…)، إذ لا يملك ميكروفونًا.
      • ميكروفون واحد في كل مرة. يحرّر الكاشف الميكروفون أثناء تسجيل أمر ويستعيده بمجرد انتهاء الدور، لذا لن يتعارض مع التقاط الصوت.
      • الخصوصية. اكتشاف hotword محلي. اضبط sensitivity على قيمة أعلى إذا حصلت على تنبيهات خاطئة، وعلى قيمة أقل إذا لم يلتقط صوتك.
