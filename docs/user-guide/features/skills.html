      نظام المهارات (Skills)

      المهارات (skills) هي مستندات معرفية تحت الطلب يستطيع الوكيل تحميلها عند الحاجة. وهي تتبع نمط الإفصاح التدريجي (progressive disclosure) لتقليل استهلاك الـ tokens، ومتوافقة مع المعيار المفتوح agentskills.io.

      توجد جميع المهارات في ~/.hermes/skills/ — وهو المجلد الرئيسي والمصدر المرجعي الوحيد. عند التثبيت الجديد، تُنسخ المهارات المضمّنة (bundled) من المستودع. وتُحفظ هنا أيضًا المهارات المثبّتة من الـ Hub والمهارات التي ينشئها الوكيل. ويستطيع الوكيل تعديل أي مهارة أو حذفها.

      يمكنك أيضًا توجيه Hermes إلى مجلدات مهارات خارجية — وهي مجلدات إضافية تُفحص إلى جانب المجلد المحلي. راجع مجلدات المهارات الخارجية أدناه.

      انظر أيضًا:

      • كتالوج المهارات المضمّنة (Bundled)
      • كتالوج المهارات الاختيارية الرسمية

      البدء من الصفر​

      افتراضيًا، يُزوَّد كل profile بكتالوج المهارات المضمّنة، ويضيف كل تنفيذ لـ hermes update أي مهارات مضمّنة جديدة. إذا أردت profile بلا مهارات مضمّنة — ويبقى فارغًا عبر التحديثات — فأمامك طريقان:

      عند التثبيت (ينطبق على الـ profile الافتراضي ~/.hermes):

      curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash -s -- --no-skills

      عند إنشاء الـ profile (الـ profiles المسمّاة):

      hermes profile create research --no-skills

      على profile مثبّت مسبقًا (افتراضي أو مسمّى)، بدّل الإعداد وقت التشغيل:

      hermes skills opt-out            # stop future seeding — nothing on disk is touched
      hermes skills opt-out --remove   # also delete UNMODIFIED bundled skills (confirms first)
      hermes skills opt-in --sync      # undo: remove the marker and re-seed now

      تكتب الطرق الثلاث جميعها ملف علامة .no-bundled-skills في مجلد الـ profile. وما دامت العلامة موجودة، يتخطى كلٌّ من المُثبّت (installer)، و hermes update، وأي مزامنة للمهارات، تزويدَ ذلك الـ profile بالمهارات المضمّنة. احذف العلامة (أو نفّذ hermes skills opt-in) لإعادة التفعيل.

      آمن افتراضيًا

      يوقف hermes skills opt-out التزويد المستقبلي فقط — ولا يحذف أبدًا أي شيء موجود على القرص. أما الخيار الاختياري --remove فيحذف المهارات المضمّنة فقط عندما تكون غير معدّلة (مطابقة بايتًا ببايت للنسخة التي ثبّتها Hermes). وتُحفظ دائمًا المهارات التي عدّلتها، والمهارات المثبّتة من الـ hub، والمهارات التي كتبتها بنفسك.

      استخدام المهارات​

      كل مهارة مثبّتة تصبح متاحة تلقائيًا كـ slash command:

      # In the CLI or any messaging platform:
      /gif-search funny cats
      /axolotl help me fine-tune Llama 3 on my dataset
      /github-pr-workflow create a PR for the auth refactor
      /songsee analyze the frequency spread of this mix

      # Just the skill name loads it and lets the agent ask what you need:
      /excalidraw

      تكديس عدة مهارات في أمر واحد​

      يمكنك استدعاء عدة مهارات في رسالة واحدة عبر سَلسلة slash commands في بدايتها — إذ يُحمَّل كل token بصيغة /skill في البداية (حتى 5)، ويصبح الباقي تعليماتك:

      /github-pr-workflow /test-driven-development fix issue #123 and open a PR

      يتوقف التحليل عند أول token لا يمثل مهارة مثبّتة، لذا فإن الوسائط التي تصادف أنها تبدأ بـ / (مثل مسارات الملفات) لا تُبتلع أبدًا:

      /ocr-and-documents /tmp/scan.pdf extract the tables   # loads one skill; /tmp/scan.pdf is the argument

      للتركيبات التي تستخدمها بشكل متكرر، يُفضَّل استخدام حزمة مهارات (skill bundle) — فهي تحقق الأثر نفسه تحت أمر واحد قصير.

      (يعمل وضع التخطيط (Plan mode) بالطريقة نفسها لكنه أصبح الآن أمرًا مدمجًا: يطلب /plan [request] من Hermes فحص السياق عند الحاجة، وكتابة خطة تنفيذ بصيغة markdown بدلًا من تنفيذ المهمة، وحفظ النتيجة ضمن .hermes/plans/ نسبةً إلى مجلد العمل الخاص بمساحة العمل أو الـ backend النشط.)

      يمكنك أيضًا التفاعل مع المهارات عبر المحادثة الطبيعية:

      hermes chat --toolsets skills -q "What skills do you have?"
      hermes chat --toolsets skills -q "Show me the axolotl skill"

      تعلّم مهارة من المصادر (/learn)​

      /learn هو الطريقة السريعة لتحويل شيء تعرفه مسبقًا — أو كومة من المواد المرجعية — إلى مهارة قابلة لإعادة الاستخدام، دون كتابة ملف SKILL.md يدويًا. وهو مفتوح النطاق: وجّهه إلى أي شيء يمكنك وصفه وسيجمع الوكيل المادة باستخدام الأدوات المتاحة لديه، ثم يؤلّف مهارة تتبع معايير التأليف المعتمدة (وصف لا يتجاوز 60 حرفًا، وترتيب الأقسام القياسي، وصياغة مبنية على أدوات Hermes، ودون اختلاق أوامر).

      # A local SDK or doc directory — read with read_file / search_files
      /learn the REST client in ~/projects/acme-sdk, focus on auth + pagination

      # An online doc page — fetched with web_extract
      /learn https://docs.example.com/api/quickstart

      # The workflow you just walked the agent through in this conversation
      /learn how I just deployed the staging server

      # Pasted notes / a described procedure
      /learn filing an expense: open the portal, New > Expense, attach the receipt, submit

      # A whole book, paper stack, or large docs corpus — becomes a knowledge-base skill
      /learn ~/books/designing-data-intensive-applications.pdf

      المصادر الكبيرة تتحول إلى مهارات قواعد معرفة​

      عندما يكون المصدر كتابًا، أو مجموعة من الأوراق البحثية، أو مواصفة، أو مجلد توثيق كبيرًا، لا يحشره الوكيل في ملف واحد ولا يختزله في ملخص يفقد التفاصيل. بل يؤلّف مهارة قاعدة معرفة موسّعة: ملف SKILL.md موجز يحمل النماذج الذهنية الجوهرية للمصدر إضافة إلى فهرس، مع ملف مُكثَّف واحد لكل فصل أو موضوع ضمن references/ (إضافة إلى مسرد مصطلحات أو ورقة مرجعية مختصرة عندما يستحق المصدر ذلك). لا تكلّف الملفات المرجعية شيئًا حتى يحتاج سؤال ما إلى أحدها — إذ يحمّلها الوكيل عند الطلب باستخدام skill_view، فتبقى تكلفة الاستعلام متناسبة مع الإجابة لا مع المصدر. وإعادة تشغيل /learn بمواد جديدة حول الموضوع نفسه تدمجها في المهارة الموجودة بدلًا من إنشاء نسخة مكررة.

      تُركّب عملية التكثيف البنية — الأُطر، والتعريفات، وقواعد اتخاذ القرار، والأنماط المضادة (anti-patterns) — ولا تعيد أبدًا إنتاج مقاطع من نص المصدر.

      ولأن الوكيل الحي هو من يتولى جمع المصادر، يعمل /learn بالطريقة نفسها في CLI، و messaging gateway، و TUI، ولوحة التحكم (dashboard) — وعلى أي terminal backend (محلي، أو Docker، أو بعيد)، إذ لا يوجد محرك استيعاب منفصل. وفي لوحة التحكم، تحتوي صفحة Skills على زر Learn a skill يفتح لوحة تتضمن حقلًا للمجلد، وحقلًا لعنوان URL، ومربع نص مفتوحًا؛ فتُنشئ طلب /learn وتشغّله في المحادثة.

      لا يترك هذا الأمر أي أثر على أدوات النموذج: إذ يبني /learn prompt موجّهًا بالمعايير ويسلّمه إلى الوكيل كدور عادي. ويحفظ الوكيل النتيجة باستخدام الأداة skill_manage، لذا ينطبق شرط الموافقة على الكتابة إذا كان مفعّلًا لديك.

      الإفصاح التدريجي​

      تستخدم المهارات نمط تحميل موفّرًا للـ tokens:

      Level 0: skills_list()           → [{name, description, category}, ...]   (~3k tokens)
      Level 1: skill_view(name)        → Full content + metadata       (varies)
      Level 2: skill_view(name, path)  → Specific reference file       (varies)

      لا يحمّل الوكيل المحتوى الكامل للمهارة إلا عندما يحتاج إليه فعلًا.

      صيغة SKILL.md​

      ---
      name: my-skill
      description: Brief description of what this skill does
      version: 1.0.0
      platforms: [macos, linux]     # Optional — restrict to specific OS platforms
      metadata:
        hermes:
          tags: [python, automation]
          category: devops
          fallback_for_toolsets: [web]    # Optional — conditional activation (see below)
          requires_toolsets: [terminal]   # Optional — conditional activation (see below)
          config:                          # Optional — config.yaml settings
            - key: my.setting
              description: "What this controls"
              default: "value"
              prompt: "Prompt for setup"
      ---

      # Skill Title

      ## When to Use
      Trigger conditions for this skill.

      ## Procedure
      1. Step one
      2. Step two

      ## Pitfalls
      - Known failure modes and fixes

      ## Verification
      How to confirm it worked.

      المهارات الخاصة بمنصات معيّنة​

      يمكن للمهارات أن تقصر نفسها على أنظمة تشغيل محددة باستخدام الحقل platforms:

      القيمةيطابق
      macosmacOS (Darwin)
      linuxLinux
      windowsWindows
      platforms: [macos]            # macOS only (e.g., iMessage, Apple Reminders, FindMy)
      platforms: [macos, linux]     # macOS and Linux

      عند ضبط هذا الحقل، تُخفى المهارة تلقائيًا من الـ system prompt، ومن skills_list()، ومن الـ slash commands على المنصات غير المتوافقة. وإذا لم يُحدَّد، تُحمَّل المهارة على جميع المنصات.

      مخرجات المهارات وتسليم الوسائط​

      عندما تتضمن استجابة مهارة (أو أي استجابة للوكيل) مسارًا مطلقًا مجردًا لملف وسائط — مثل /home/user/screenshots/diagram.png — يكتشفه الـ gateway تلقائيًا، ويحذفه من النص المرئي، ويسلّم الملف بشكل أصلي إلى محادثة المستخدم (صورة في Telegram، أو مرفق في Discord، وما إلى ذلك) بدلًا من ترك المسار الخام في الرسالة.

      وبالنسبة للصوت تحديدًا، يحوّل التوجيه [[audio_as_voice]] الملفات الصوتية إلى فقاعات رسائل صوتية أصلية على المنصات التي تدعمها (Telegram و WhatsApp).

      فرض التسليم كمستند: [[as_document]]​

      أحيانًا تريد عكس المعاينة المضمّنة: أي أن يُسلَّم الملف كمرفق قابل للتنزيل، لا كفقاعة صورة مُعاد ضغطها. والمثال التقليدي لذلك لقطة شاشة أو مخطط عالي الدقة — إذ يعيد sendPhoto في Telegram ضغطه إلى نحو 200 KB بدقة 1280 px، مما يُفسد قابلية القراءة. أما ملف PNG بحجم 1-2 MB يُرسل عبر sendDocument فيحتفظ بالبايتات الأصلية كما هي.

      إذا احتوت استجابة (أو أي نص داخلها — عادةً السطر الأخير) على التوجيه الحرفي [[as_document]]، يُسلَّم كل مسار وسائط مُستخرج من تلك الاستجابة كمرفق مستند/ملف بدلًا من فقاعة صورة:

      Here is your rendered chart:

      /home/user/.hermes/cache/chart-q4-2025.png

      [[as_document]]

      يُحذف التوجيه قبل التسليم، فلا يراه المستخدمون أبدًا. والنطاق مقصود أن يكون كل شيء أو لا شيء لكل استجابة: أدرج [[as_document]] مرة واحدة وسيُسلَّم كل مسار صورة في الاستجابة نفسها كمستند. وهذا يطابق نطاق [[audio_as_voice]].

      استخدمه من داخل مهارة عندما:

      • تُنتج لقطات شاشة أو مخططات يحتاجها المستخدم كملفات (لتحريرها في أداة أخرى، أو أرشفتها، أو مشاركتها دون تغيير).
      • تكون المعاينة الافتراضية ذات الضغط المُفقِد للجودة ستُخفي التفاصيل (نصوص صغيرة، أو مخططات دقيقة على مستوى البكسل، أو صور حساسة للألوان).

      المنصات التي لا تملك مسارًا منفصلًا للمستندات (مثل SMS) تعود إلى آلية المرفقات المتاحة لديها أيًّا كانت.

      التفعيل المشروط (المهارات الاحتياطية)​

      يمكن للمهارات إظهار نفسها أو إخفاؤها تلقائيًا بناءً على الأدوات المتاحة في الجلسة الحالية. وهذا مفيد أكثر ما يكون مع المهارات الاحتياطية (fallback skills) — وهي بدائل مجانية أو محلية ينبغي ألا تظهر إلا عندما تكون أداة مدفوعة غير متاحة.

      metadata:
        hermes:
          fallback_for_toolsets: [web]      # Show ONLY when these toolsets are unavailable
          requires_toolsets: [terminal]     # Show ONLY when these toolsets are available
          fallback_for_tools: [web_search]  # Show ONLY when these specific tools are unavailable
          requires_tools: [terminal]        # Show ONLY when these specific tools are available
      الحقلالسلوك
      fallback_for_toolsetsتكون المهارة مخفية عندما تكون الـ toolsets المدرجة متاحة، وتظهر عندما تكون غير موجودة.
      fallback_for_toolsمثل السابق، لكنه يفحص أدوات فردية بدلًا من toolsets.
      requires_toolsetsتكون المهارة مخفية عندما تكون الـ toolsets المدرجة غير متاحة، وتظهر عندما تكون موجودة.
      requires_toolsمثل السابق، لكنه يفحص أدوات فردية.

      مثال: تستخدم المهارة المدمجة duckduckgo-search الحقل fallback_for_toolsets: [web]. عندما يكون FIRECRAWL_API_KEY مضبوطًا لديك، يكون الـ toolset الخاص بالويب متاحًا ويستخدم الوكيل web_search — فتبقى مهارة DuckDuckGo مخفية. وإذا كان مفتاح API غير موجود، يصبح الـ toolset الخاص بالويب غير متاح وتظهر مهارة DuckDuckGo تلقائيًا كبديل احتياطي.

      المهارات التي لا تحتوي على أي حقول شرطية تتصرف تمامًا كما في السابق — إذ تظهر دائمًا.

      الإعداد الآمن عند التحميل​

      يمكن للمهارات التصريح بمتغيرات البيئة (environment variables) المطلوبة دون أن تختفي من نتائج الاكتشاف:

      required_environment_variables:
        - name: TENOR_API_KEY
          prompt: Tenor API key
          help: Get a key from https://developers.google.com/tenor
          required_for: full functionality

      عند مصادفة قيمة مفقودة، يطلبها Hermes بشكل آمن فقط عندما تُحمَّل المهارة فعليًا في CLI المحلي. ويمكنك تخطي الإعداد ومواصلة استخدام المهارة. أما واجهات المراسلة فلا تطلب الأسرار (secrets) في المحادثة أبدًا — بل تطلب منك استخدام hermes setup أو ~/.hermes/.env محليًا بدلًا من ذلك.

      بمجرد ضبطها، تُمرَّر متغيرات البيئة المُصرَّح بها تلقائيًا إلى بيئات sandbox الخاصة بـ execute_code و terminal — بحيث تستطيع سكربتات المهارة استخدام $TENOR_API_KEY مباشرةً. أما متغيرات البيئة غير المرتبطة بالمهارات، فاستخدم لها خيار الإعدادات terminal.env_passthrough. راجع تمرير متغيرات البيئة للتفاصيل.

      إعدادات المهارات​

      يمكن للمهارات أيضًا التصريح بإعدادات غير سرية (مسارات، وتفضيلات) تُخزَّن في config.yaml:

      metadata:
        hermes:
          config:
            - key: myplugin.path
              description: Path to the plugin data directory
              default: "~/myplugin-data"
              prompt: Plugin data directory path

      تُخزَّن الإعدادات ضمن skills.config في ملف config.yaml الخاص بك. ويطلب hermes config migrate إدخال الإعدادات غير المضبوطة، بينما يعرضها hermes config show. وعند تحميل مهارة، تُحقن قيم إعداداتها المحسومة في السياق بحيث يعرف الوكيل القيم المضبوطة تلقائيًا.

      راجع إعدادات المهارات وإنشاء المهارات — الإعدادات للتفاصيل.

      │   │   ├── examples/              # Referenced example outputs
      │   │   └── assets/                # Supplementary files
      │   └── vllm/
      │       └── SKILL.md
      ├── devops/
      │   └── deploy-k8s/                # Agent-created skill
      │       ├── SKILL.md
      │       └── references/

      │   ├── lock.json
      │   ├── quarantine/

      تتضمن عمليات التثبيت من عناوين URL لجهات خارجية ومن GitHub ملف SKILL.md إضافة إلى الملفات المحلية التي يشير إليها تحديدًا ضمن references/، و templates/، و scripts/، و assets/، و examples/. ولا تُنسخ ملفات المستودع غير المُشار إليها. يفحص Hermes الحزمة المعزولة (quarantined) كاملةً ويسجّل عنوان URL المصدر، وقيمة hash الدقيقة للمحتوى، وإصدار الماسح، والنتائج، والطابع الزمني، وحالة الفحص (جديد أو مخزّن مؤقتًا) في skills/.hub/lock.json.

      فحص SkillEvaluator الاستشاري​

      إضافةً إلى ماسح الأمان المدمج (الذي يفرض سياسة التثبيت المذكورة أعلاه)، يستطيع Hermes تشغيل فحوصات المستوى 1 (Tier 1) من NVIDIA SkillEvaluator على كل عملية تثبيت من الـ hub كرأي ثانٍ. المستوى 1 حتمي ولا يحتاج إلى مفاتيح — ويشمل اكتشاف البيانات الشخصية PII (رسائل البريد الإلكتروني المسرّبة، والمسارات الشخصية، وسلاسل الاتصال)، واكتشاف تهريب محارف unicode، وفحص السكربتات (lint)، والامتثال للتراخيص، وفحصًا أمنيًا ثابتًا عبر NVIDIA SkillSpector.

      الفحص استشاري فقط: إذ تُطبع النتائج مع اسم الملف ورقم السطر قبل تأكيد التثبيت، ثم يستمر التثبيت. أما النتائج التي تبدو كبيانات اعتماد حقيقية (مفاتيح خاصة، ومفاتيح الوصول السحابية، و tokens، وسلاسل الاتصال المتضمنة لبيانات اعتماد) فتُبرز باللون الأحمر كي تتمكن من مراجعة الأسطر المُعلَّمة قبل اتخاذ القرار. ونتائج فئة PII معلوماتية فقط — فللماسح الأصلي فئات معروفة من الإيجابيات الكاذبة (مثل صيغة SSH git@github.com، ورسائل البريد الإلكتروني الواردة كأمثلة في التوثيق)، لذا فهي لا تمنع أي شيء أبدًا.

      لتفعيله، ثبّت الملفات التنفيذية الاختيارية للماسح (الثاني منها يشغّل فحص security؛ وبدونه يُبلغ ذلك الفحص ببساطة بأنه "not run"):

      uv tool install --python 3.13 \
        "skillevaluator @ git+https://github.com/NVIDIA/SkillEvaluator.git@v0.1.0"
      uv tool install "git+https://github.com/NVIDIA/SkillSpector.git@v2.9.5"

      إذا لم يكن الملف التنفيذي موجودًا في PATH، يُتخطّى الفحص بصمت. ولإيقافه كليًا:

      skills:
        tier1_advisory: false

      يُرجع زر الفحص في صفحة Browse-hub بلوحة التحكم البيانات الاستشارية نفسها في استجابته (الحقل tier1) إلى جانب حكم الماسح المدمج.

      مجلدات المهارات الخارجية​

      إذا كنت تحتفظ بمهارات خارج Hermes — مثل مجلد مشترك ~/.agents/skills/ تستخدمه عدة أدوات ذكاء اصطناعي — فيمكنك أن تطلب من Hermes فحص تلك المجلدات أيضًا.

      أضف external_dirs ضمن قسم skills في ~/.hermes/config.yaml:

      skills:
        external_dirs:
          - ~/.agents/skills
          - /home/shared/team-skills
          - ${SKILLS_REPO}/skills

      تدعم المسارات توسيع ~ واستبدال متغيرات البيئة بصيغة ${VAR}.

      آلية العمل​

      • الإنشاء محليًا والتحديث في المكان نفسه: تُكتب المهارات الجديدة التي ينشئها الوكيل في ~/.hermes/skills/ (أو في skills.create_dir عند ضبطه — انظر أدناه). أما المهارات الموجودة فتُعدَّل حيث وُجدت، بما في ذلك المهارات الموجودة ضمن external_dirs، عندما يستخدم الوكيل إجراءات skill_manage مثل patch، أو edit، أو write_file، أو remove_file، أو delete.
      • المجلدات الخارجية ليست حدًّا للحماية من الكتابة: إذا كان مجلد مهارات خارجي قابلًا للكتابة من قِبل عملية Hermes، فإن تحديثات المهارات التي يديرها الوكيل قد تغيّر الملفات في ذلك المجلد. استخدم صلاحيات نظام الملفات أو إعدادًا منفصلًا للـ profile أو الـ toolset إذا كان يجب أن تبقى المهارات الخارجية المشتركة للقراءة فقط.
      • الأولوية للمحلي: إذا وُجد اسم المهارة نفسه في المجلد المحلي وفي مجلد خارجي، تكون الغلبة للنسخة المحلية.
      • تكامل كامل: تظهر المهارات الخارجية في فهرس الـ system prompt، وفي skills_list، و skill_view، وكـ slash commands بصيغة /skill-name — دون أي اختلاف عن المهارات المحلية.
      • المسارات غير الموجودة تُتخطّى بصمت: إذا لم يكن مجلد مضبوط موجودًا، يتجاهله Hermes دون أخطاء. وهذا مفيد للمجلدات المشتركة الاختيارية التي قد لا تكون موجودة على كل جهاز.

      مثال​

      ~/.hermes/skills/               # Local (primary, read-write)
      ├── devops/deploy-k8s/
      │   └── SKILL.md
      └── mlops/axolotl/
          └── SKILL.md

      ~/.agents/skills/               # External (shared, mutable if writable)
      ├── my-custom-workflow/
      │   └── SKILL.md
      └── team-conventions/
          └── SKILL.md

      تظهر المهارات الأربع جميعها في فهرس المهارات لديك. وإذا أنشأت محليًا مهارة جديدة باسم my-custom-workflow، فإنها تحجب النسخة الخارجية.

      إعادة توجيه إنشاء المهارات (skills.create_dir)​

      افتراضيًا، يكتب الوكيل المهارات الجديدة في المجلد المحلي الخاص بالـ profile ~/.hermes/skills/. إذا أردت أن تُحفظ المهارات التي ينشئها الوكيل في مكان آخر — مثل مجلد "دماغ" مشترك، أو مستودع يتتبعه git، أو volume مهارات على مستوى أسطول الأجهزة — فاضبط create_dir ضمن قسم skills:

      skills:
        create_dir: /opt/brain/skills

      ما الذي يغيّره ذلك:

      • إجراء create في skill_manage يكتب هناك. تُنشأ المهارات الجديدة (بما في ذلك المجلدات الفرعية للفئات) ضمن create_dir بدلًا من مجلد المهارات المحلي. ويُنشأ المجلد عند أول عملية كتابة إذا لم يكن موجودًا.
      • تعليمات الوكيل تتبع الإعدادات. كل تعليمة موجّهة إلى الوكيل تذكر مسار إنشاء المهارات — وصف الأداة skill_manage ونصوص الـ prompt ذات الصلة — تعرض المجلد المضبوط ديناميكيًا، بحيث يُطلب من الوكيل إنشاء المهارات هناك. دون الحاجة إلى تجاوزات في الـ system prompt أو حيل على مستوى نظام الملفات.
      • المجلد متكامل بالكامل. تُفحص المهارات الموجودة ضمن create_dir إلى جانب المجلد المحلي: فتظهر في فهرس المهارات، و skills_list، و skill_view، والـ slash commands، ويمكن تعديلها أو حذفها مثل أي مهارة محلية.
      • كل ما عدا ذلك يبقى محليًا. تظل المهارات الموجودة تُعدَّل في مكانها أينما وُجدت؛ وتواصل مزامنة المهارات المضمّنة، والـ hub، والـ curator العمل على المجلد المحلي الخاص بالـ profile.

      تدعم المسارات توسيع ~ واستبدال ${VAR}؛ وتُحسم المسارات النسبية بالنسبة إلى مجلد Hermes الرئيسي. وضبط create_dir على مجلد المهارات المحلي يعادل تركه دون تعيين.

      المهارات المحلية الخاصة بالمشروع​

      يمكن للمستودعات أن تحمل مهاراتها الخاصة، التي لا تكون نشطة إلا في الجلسات التي تبدأ داخل ذلك المشروع — وهو النمط نفسه الذي تستخدمه أُطر تشغيل الوكلاء الأخرى (agent harnesses) للإعدادات المحلية الخاصة بالمستودع. عندما تشغّل Hermes داخل نسخة git مسحوبة (checkout)، فإنه يبحث عن المهارات في:

      <project-root>/.hermes/skills/    # Hermes-native location
      <project-root>/.agents/skills/    # cross-tool convention (shared with other agent CLIs)

      جذر المشروع هو أقرب مجلد أصل يحتوي على .git (وتُحتسب الـ worktrees والوحدات الفرعية submodules).

      الوثوق بمشروع​

      المهارات مستندات إجرائية يتبعها الوكيل، لذا فإن Hermes لا يحمّلها تلقائيًا من أي مستودعات مستنسخة عشوائية. في المرة الأولى التي تشغّل فيها Hermes داخل مستودع يحتوي على مهارات مشروع، تعرض اللافتة (banner) إشعارًا:

      ◆ 3 project skill(s) found in /home/you/myproject but not loaded — run `hermes skills trust` to enable them.

      امنح الثقة للمستودع مرة واحدة (من داخله، أو بتمرير المسار):

      hermes skills trust             # trust the current repo
      hermes skills trust ~/myproject # or explicitly
      hermes skills untrust           # revoke

      تُخزَّن الجذور الموثوقة في skills.trusted_project_dirs داخل ~/.hermes/config.yaml. واضبط skills.project_discovery: false لإيقاف الميزة كليًا (بلا فحص، وبلا إشعارات).

      الأولوية​

      مهارات المشروع هي المستوى الأعلى أولوية: project → local (~/.hermes/skills/) → external_dirs. فمهارة المشروع المسمّاة deploy تتجاوز مهارة profile أو مهارة مضمّنة تحمل الاسم نفسه في الجلسات داخل ذلك المستودع — وهذا هو المقصود تحديدًا: فمهارات المستودع المرفقة به تكون لها الغلبة في موطنها، دون المساس بالـ profile العام الخاص بك. وتُوسَم مهارات المشروع بـ [project] في فهرس المهارات لدى الوكيل كي يبقى مصدرها واضحًا.

      وكما هو الحال مع المجلدات الخارجية، تُعامل مجلدات مهارات المشروع على أنها مملوكة للمستودع: فالصيانة الذاتية للمهارات (الـ curator) لا تعدّلها أبدًا، والمهارات الجديدة التي ينشئها الوكيل تُحفظ دائمًا في ~/.hermes/skills/.

      العزل وقت الفحص​

      الثقة قرار على مستوى المستودع، لكن محتوى المهارات في المستودع يتغير مع كل git pull. ولسدّ هذه الثغرة، تُفحص كل مهارة مشروع بماسح الأمان نفسه المستخدم في عمليات التثبيت من Skills Hub قبل دخولها الفهرس. والمهارة التي يكون حكم فحصها خطيرة (توجيهات حقن الـ prompt، أو أوامر تسريب بيانات الاعتماد، أو حيل النصوص المخفية) تُعزل: فلا تظهر في فهرس المهارات، ولا في skills_list، ولا في الـ slash commands، وترفض التحميل بالاسم مع رسالة خطأ توضيحية. وتُخزَّن نتائج الفحص مؤقتًا بحسب hash المحتوى ضمن ~/.hermes/cache/project_skill_scans/ (وليس داخل مستودعك أبدًا)، ويُعاد تشغيلها تلقائيًا عندما يتغير محتوى المهارة.

      الواجهات غير التفاعلية (cron، و API، و ACP)​

      ترث مهام cron والواجهات غير التفاعلية الأخرى قرار الثقة الذي اتخذته تفاعليًا — فهي لا تطلب التأكيد أبدًا ولا تمنح الثقة تلقائيًا أبدًا. ويُحسم جذر المشروع انطلاقًا من مجلد العمل الخاص بالواجهة (workdir الخاص بمهمة cron، عبر الآلية نفسها التي تستخدمها أداة الطرفية). فمهمة cron التي يقع workdir الخاص بها داخل مستودع وثقت به سابقًا تحمّل مهارات المشروع الخاصة بذلك المستودع؛ أما المهمة الموجودة في مستودع غير موثوق أو لم يُتخذ بشأنه قرار فلا تحمّل أي مهارات.

      حزم المهارات (Skill Bundles)​

      حزم المهارات ملفات YAML صغيرة تجمع عدة مهارات تحت slash command واحد. عندما تنفّذ /<bundle-name>، تُحمَّل كل المهارات المدرجة في الحزمة دفعة واحدة — وهذا مفيد عندما تستفيد مهمة معيّنة دائمًا من المجموعة نفسها من المهارات معًا.

      مثال سريع​

      # Create a bundle for backend feature work
      hermes bundles create backend-dev \
        --skill github-code-review \
        --skill test-driven-development \
        --skill github-pr-workflow \
        -d "Backend feature work — review, test, PR workflow"

      ثم في CLI أو أي منصة من منصات الـ gateway:

      /backend-dev refactor the auth middleware

      يتلقى الوكيل المهارات الثلاث محمّلة في رسالة مستخدم واحدة، مع إرفاق أي نص يلي الـ slash command كتعليمات من المستخدم.

      مخطط YAML​

      توجد الحزم في ~/.hermes/skill-bundles/<slug>.yaml وتبدو على النحو التالي:

      name: backend-dev
      description: Backend feature work — review, test, PR workflow.
      skills:
        - github-code-review
        - test-driven-development
        - github-pr-workflow
      instruction: |
        Always start by writing failing tests, then implement.
        Open the PR through the standard workflow with co-author tags.

      الحقول:

      • name (اختياري — القيمة الافتراضية هي اسم الملف دون امتداده) — الاسم المعروض للحزمة. ويُحوَّل إلى slug بشرطات لاستخدامه في الـ slash command (Backend Dev → /backend-dev).
      • description (اختياري) — نص قصير يُعرض في /bundles و hermes bundles list.
      • skills (مطلوب، قائمة غير فارغة) — أسماء المهارات أو مساراتها نسبةً إلى مجلد المهارات لديك. استخدم المعرّف نفسه الذي تمرّره إلى /<skill-name>.
      • instruction (اختياري) — توجيهات إضافية تُضاف قبل محتوى المهارات المحمّلة. وهي مفيدة لتدوين "الطريقة التي نستخدم بها هذه المهارات معًا دائمًا".

      إدارة الحزم​

      # List all installed bundles
      hermes bundles list

      # Inspect one bundle
      hermes bundles show backend-dev

      # Create a bundle interactively (omit --skill flags to enter them one per line)
      hermes bundles create research

      # Overwrite an existing bundle
      hermes bundles create backend-dev --skill ... --force

      # Delete a bundle
      hermes bundles delete backend-dev

      # Re-scan ~/.hermes/skill-bundles/ and report changes
      hermes bundles reload

      من داخل جلسة محادثة، يسرد /bundles كل الحزم المثبّتة ومهاراتها.

      السلوك​

      • للحزم أولوية على المهارات الفردية عند تعارض الـ slugs. فإذا سمّيت حزمة research وكانت لديك أيضًا مهارة باسم research، فإن /research يستدعي الحزمة. وهذا مقصود — فقد اخترت الحزمة صراحةً عندما منحتها هذا الاسم.
      • المهارات المفقودة تُتخطّى ولا تُسبب فشلًا. إذا أدرجت حزمة المهارة skill-foo ولم تكن قد ثبّتها، تظل الحزمة تحمّل المهارات التي أمكن العثور عليها، ويتلقى الوكيل ملاحظة تسرد ما تم تخطيه.
      • تعمل الحزم في كل الواجهات — CLI التفاعلي، و TUI، ومحادثة لوحة التحكم، وكل منصات الـ gateway (Telegram، و Discord، و Slack، …) — لأن التوجيه مركزي في المكان نفسه الذي تُعالج فيه أوامر المهارات الفردية.
      • لا تُبطل الحزم التخزين المؤقت للـ prompt. إذ تُنشئ رسالة مستخدم جديدة وقت الاستدعاء، بالطريقة نفسها التي يعمل بها /<skill-name> — دون أي تعديل على الـ system prompt.

      متى تتفوق الحزم على تثبيت كل مهارة يدويًا​

      استخدم حزمة عندما:

      • تقرن دائمًا المهارات نفسها لمهمة متكررة (/backend-dev، /release-prep، /incident-response).
      • تريد نموذجًا ذهنيًا أبسط من كتابة عدة استدعاءات /skill متتالية.
      • تريد مشاركة "profile مهام" على مستوى الفريق عبر إضافة ملف YAML الخاص بالحزمة إلى مستودع dotfiles مشترك وإنشاء رابط رمزي (symlink) له داخل ~/.hermes/skill-bundles/.

      الحزمة مجرد اسم مستعار (alias) بصيغة YAML — ولا تثبّت المهارات نيابةً عنك. إذ يجب أن تكون المهارات نفسها موجودة مسبقًا (في ~/.hermes/skills/ أو في مجلد مهارات خارجي). وإلا فإن استدعاء الحزمة يتخطى المهارات المفقودة ببساطة.

      المهارات التي يديرها الوكيل (أداة skill_manage)​

      يستطيع الوكيل إنشاء مهاراته الخاصة وتحديثها وحذفها عبر الأداة skill_manage. وهذه هي الذاكرة الإجرائية للوكيل — فعندما يتوصل إلى سير عمل غير بسيط، يحفظ الطريقة كمهارة لإعادة استخدامها مستقبلًا.

      تعمل المهارات والذاكرة معًا في حلقة التحسين الذاتي: إذ تخزّن الذاكرة حقائق صغيرة دائمة ينبغي أن تكون في السياق دائمًا، بينما تخزّن المهارات إجراءات أطول ينبغي ألا تُحمَّل إلا عند الحاجة إليها. ويمكن للمراجعة التي تعمل في الخلفية أن تقترح تغييرات على المهارات أو تجهّزها بعد انتهاء الجلسة، لكن شرط الموافقة على الكتابة الموضح أدناه يتيح لك اشتراط مراجعة بشرية قبل اعتماد تلك التغييرات.

      متى ينشئ الوكيل المهارات​

      يطلب الـ system prompt من الوكيل تسجيل أي سير عمل غير بسيط باستخدام skill_manage لإعادة استخدامه مستقبلًا. وعمليًا يشمل ذلك:

      • عندما يتوصل إلى سير عمل متعدد الخطوات يستحق التكرار
      • عندما يواجه أخطاء أو طرقًا مسدودة ثم يجد المسار الناجح
      • عندما يصحّح المستخدم أسلوبه

      كيف يبدو مُدخل المهارة​

      المهارة هي التعليمات اللازمة لأداء فئة من المهام بأكثر الطرق كفاءةً وصحةً، وفق مواصفاتك: الإجراء بالترتيب، والأوامر واستدعاءات الأدوات التي تنجح، والشكل الذي تريده للنتيجة، والمزالق التي تُهدر الوقت. وسواء كُتبت في دور أمامي، أو عبر المراجعة في الخلفية، أو عبر تمريرة الدمج التي يجريها الـ curator، فإنها تلتقط الدروس لا السجلات: فالمزلق قاعدة قابلة للتعميم إضافة إلى عبارة واحدة توضح السبب (الآلية)، مرتبطة بالخطوة التي تؤثر فيها، ومذكورة مرة واحدة. أما سرد الحوادث، وأرقام الـ PR أو الـ issues، والتواريخ، واقتباسات المحادثات فليست من محتوى المهارة؛ إذ يجب أن تقوم القاعدة بذاتها دون القصة التي تقف خلفها. تعيش القواعد الدائمة داخل SKILL.md نفسه؛ بينما يحتوي references/ على مجموعة صغيرة من الملفات المسمّاة حسب الموضوع (جدول قرارات، أو وصفة، أو خصوصيات مزوّد ما)، تُوسَّع في مكانها بدلًا من تراكم ملف لكل جلسة. كما لا تعيد المهارات ذكر ما هو محمّل مسبقًا في كل دور (ملف AGENTS.md الخاص بالمستودع، ومخططات الأدوات).

      تشغّل skill_manage أداة فحص (linter) استشارية عند create وعند الكتابة في references/، وتُرجع نتائجها ضمن نتيجة الأداة. وتوجد قاعدتان مخصصتان لهذا الشكل تحديدًا: incident-log-shape (محتوى مكتظ بأرقام الـ PR والـ issues) و references-sprawl (أكثر من 60 ملفًا مرجعيًا). وهما تُصدران تحذيرات فقط؛ ولا تمنعان عملية الكتابة أبدًا.

      الإجراءالاستخدامالمعاملات الرئيسية

      التحكم في كتابة الوكيل للمهارات (skills.write_approval)​

      افتراضيًا، يكتب الوكيل المهارات بحرية — بما في ذلك من خلال مراجعة التحسين الذاتي في الخلفية التي تعمل بعد كل دور. وإذا كنت تفضّل الموافقة على كل عملية كتابة للمهارات أولًا (مع النماذج الصغيرة التي تسيء تقدير ما تعلّمته، أو في البيئات الآمنة، أو لمجرد رغبتك في مراقبة حلقة التحسين الذاتي)، ففعّل شرط الموافقة على الكتابة:

      skills:
        write_approval: false     # false = write freely (default) | true = require approval

      عند ضبط write_approval: true، فإن كل عملية كتابة عبر skill_manage (create / edit / patch / delete / write_file / remove_file) تُجهَّز للمراجعة بدلًا من اعتمادها مباشرةً — فملف SKILL.md أكبر من أن يُراجع ضمن السطر، لذا ينطبق التجهيز بغض النظر عن مصدر الكتابة، سواء جاءت من دور أمامي أو من المراجعة في الخلفية. تبقى عمليات الكتابة المُجهَّزة محفوظة بعد إعادة التشغيل ضمن ~/.hermes/pending/skills/ وتُراجع بمسار الموافقة/الرفض المألوف نفسه المستخدم مع الأوامر الخطيرة:

      /skills pending             # list staged skill writes + a one-line gist each
      /skills diff <id>           # full unified diff (best viewed in CLI or dashboard)
      /skills approve <id>        # apply it (or 'all')
      /skills reject <id>         # drop it (or 'all')
      /skills approval on         # turn the gate on (or 'off') and persist it

      تعمل واجهة المراجعة في CLI التفاعلي وعلى منصات المراسلة (تُقتطع مخرجات diff في فقاعات المحادثة — اقرأ الـ diff الكامل في CLI أو في ملف JSON المعلّق). ولعمليات الكتابة في الذاكرة الشرط نفسه ضمن memory.write_approval — راجع التحكم في عمليات الكتابة في الذاكرة.

      الإعداد المنفصل skills.guard_agent_created هو ماسح للمحتوى (يعتمد على استدلالات الأنماط الخطيرة)، وليس شرطًا للموافقة — والاثنان مستقلان. راجع الحماية عند كتابة الوكيل للمهارات.

      الـ Hubs والسجلات المتكاملة​

      يتكامل Hermes حاليًا مع منظومات المهارات ومصادر الاكتشاف التالية:

      1. المهارات الاختيارية الرسمية (official)​

      تُصان هذه المهارات داخل مستودع Hermes نفسه، وتُثبَّت بمستوى الثقة المدمج.

      • الكتالوج: كتالوج المهارات الاختيارية الرسمية
      • المصدر في المستودع: optional-skills/
      • مثال:
      hermes skills browse --source official
      hermes skills install official/security/1password

      2. skills.sh (skills-sh)​

      هذا هو دليل المهارات العام الخاص بـ Vercel. يستطيع Hermes البحث فيه مباشرةً، وفحص صفحات تفاصيل المهارات، وحسم الـ slugs ذات الأسماء المستعارة، والتثبيت من مستودع المصدر الأصلي.

      • الدليل: skills.sh
      • مستودع CLI والأدوات: vercel-labs/skills
      • مستودع مهارات Vercel الرسمي: vercel-labs/agent-skills
      • مثال:
      hermes skills search react --source skills-sh
      hermes skills inspect skills-sh/vercel-labs/json-render/json-render-react
      hermes skills install skills-sh/vercel-labs/json-render/json-render-react --force

      3. Endpoints المهارات المعروفة (well-known)​

      هذا اكتشاف قائم على عناوين URL من المواقع التي تنشر /.well-known/skills/index.json. وهو ليس hub مركزيًا واحدًا — بل اصطلاح لاكتشاف المهارات على الويب.

      • مثال على endpoint حي: فهرس مهارات توثيق Mintlify
      • تنفيذ مرجعي للخادم: vercel-labs/skills-handler

      hermes skills search https://mintlify.com/docs --source well-known

      يستطيع Hermes التثبيت مباشرةً من مستودعات GitHub ومن الـ taps المستندة إلى GitHub. وهذا مفيد عندما تعرف المستودع/المسار مسبقًا أو تريد إضافة مستودع مصدر مخصص خاص بك.

      • anthropics/skills

      • huggingface/skills

      • NVIDIA/skills — مهارات موثّقة من NVIDIA (موقّعة عبر skill.oms.sig + ملف الحوكمة skill-card.md)

      • garrytan/gstack

      • K-Dense-AI/scientific-agent-skills و synthetic-sciences/openscience — نحو 480 مهارة للبحث العلمي (المعلوماتية الحيوية، والكيمياء، والفيزياء، وتدريب نماذج ML، وأدوات البحث الأكاديمي)، مجمّعة تحت فئة واحدة هي science. مستوى الثقة مجتمعي: إذ تخضع كل عملية تثبيت لفحص أمني. ويغلّف كثير منها أدوات من جهات خارجية لها تراخيصها الخاصة (بعضها GPL؛ و KEGG تتطلب ترخيصًا تجاريًا للاستخدام غير الأكاديمي) — لذا تحقّق من المتطلبات المسبقة لكل مهارة.

      hermes skills install openai/skills/k8s
      hermes skills tap add myorg/skills-repo

      {
        "$schema": "https://skills.sh/schemas/skills.sh.schema.json",
        "groupings": [
          { "title": "Inference AI", "skills": ["dynamo-recipe-runner", "dynamo-router-sla"] },

      7. browse.sh (browse-sh)​

      يتكامل Hermes مع browse.sh، وهو كتالوج Browserbase الذي يضم أكثر من 200 ملف SKILL.md لأتمتة المتصفح خاصة بمواقع بعينها (Airbnb، و Amazon، و arXiv، و 12306.cn، و Etsy، و Xero، وغيرها الكثير). تصف كل مهارة كيفية التحكم في موقع ويب واحد من البداية إلى النهاية، وهي مناسبة للاستخدام مع أدوات المتصفح في Hermes ومع أي مهارات لأتمتة المتصفح مثبّتة لديك مسبقًا.

      • الموقع: browse.sh
      • واجهة API للكتالوج: https://browse.sh/api/skills
      • معرّف المصدر في Hermes: browse-sh
      • مستوى الثقة: community
      hermes skills search airbnb --source browse-sh
      hermes skills inspect browse-sh/airbnb.com/search-listings-ddgioa
      hermes skills install browse-sh/airbnb.com/search-listings-ddgioa

      تستخدم المعرّفات الصيغة browse-sh/<hostname>/<task-id> وتطابق الـ slug الذي يعرضه كتالوج browse.sh. ويُحسم المحتوى عبر endpoint التفاصيل الخاص بكل مهارة (/api/skills/<slug> → skillMdUrl)، لا عبر حقل GitHub sourceUrl في الكتالوج.

      8. عنوان URL مباشر (url)​

      ثبّت SKILL.md مباشرةً من أي عنوان URL عبر HTTP(S) — وهذا مفيد عندما يستضيف المؤلف مهارة على موقعه الخاص (دون إدراج في hub، ودون مسار GitHub لكتابته). ويجلب Hermes أيضًا الملفات المُشار إليها صراحةً ضمن references/، و templates/، و scripts/، و assets/، و examples/، ثم يفحص الحزمة الكاملة ويثبّتها.

      • معرّف المصدر في Hermes: url
      • المعرّف: عنوان URL نفسه (دون الحاجة إلى بادئة)
      • النطاق: SKILL.md إضافة إلى الملفات الداعمة المُشار إليها تحديدًا ضمن المجلدات المسموح بها. ولا يسرد Hermes الملفات غير ذات الصلة من الخادم المضيف ولا ينسخها.
      hermes skills install https://sharethis.chat/SKILL.md
      hermes skills install https://example.com/my-skill/SKILL.md --category productivity

      ترتيب حسم الاسم:

      1. الحقل name: في الـ YAML frontmatter لملف SKILL.md (مُوصى به — فكل مهارة سليمة البنية تحتوي عليه).
      2. اسم المجلد الأصل من مسار URL (مثل .../my-skill/SKILL.md → my-skill، أو .../my-skill.md → my-skill)، عندما يكون معرّفًا صالحًا (^[a-z][a-z0-9_-]*$).
      3. الإدخال التفاعلي في طرفية تملك TTY.
      4. في الواجهات غير التفاعلية (الـ slash command /skills install داخل TUI، ومنصات الـ gateway، والسكربتات)، تظهر رسالة خطأ واضحة تشير إلى خيار التجاوز --name.
      # Frontmatter has no name and the URL slug is unhelpful — supply one:
      hermes skills install https://example.com/SKILL.md --name sharethis-chat

      # Or inside a chat session:
      /skills install https://example.com/SKILL.md --name sharethis-chat

      مستوى الثقة دائمًا community — ويُجرى الفحص الأمني نفسه المُطبَّق على كل المصادر الأخرى. ويُخزَّن عنوان URL كمعرّف للتثبيت، لذا فإن hermes skills update يعيد الجلب من عنوان URL نفسه تلقائيًا عندما تريد التحديث.

      الفحص الأمني و --force​

      تمرّ جميع المهارات المثبّتة من الـ hub عبر ماسح أمني يفحص تسريب البيانات، وحقن الـ prompt، والأوامر التخريبية، ومؤشرات هجمات سلسلة التوريد، وغيرها من التهديدات.

      يعرض hermes skills inspect ... الآن أيضًا البيانات الوصفية من المصدر الأصلي عند توفرها:

      • عنوان URL للمستودع
      • عنوان URL لصفحة التفاصيل في skills.sh
      • أمر التثبيت
      • عدد عمليات التثبيت الأسبوعية
      • حالات التدقيق الأمني في المصدر الأصلي
      • عناوين URL الخاصة بفهرس/endpoint المهارات المعروفة (well-known)

      استخدم --force عندما تكون قد راجعت مهارة من جهة خارجية وتريد تجاوز حظر سياسة غير خطير:

      hermes skills install skills-sh/anthropics/skills/pdf --force

      سلوك مهم:

      • يمكن لـ --force تجاوز حظر السياسة في النتائج من نوع caution/warn.
      • --force لا يتجاوز حكم الفحص dangerous.
      • تُعامل المهارات الاختيارية الرسمية (official/...) بمستوى الثقة المدمج، ولا تعرض لوحة التحذير الخاصة بالجهات الخارجية.

      دورة حياة التحديث​

      يتتبع الـ hub الآن معلومات كافية عن مصدر المهارات (provenance) لإعادة التحقق من النسخ الأصلية للمهارات المثبّتة:

      hermes skills check          # Report which installed hub skills changed upstream
      hermes skills update         # Reinstall only the skills with updates available
      hermes skills update react   # Update one specific installed hub skill
      hermes skills update react --force   # Overwrite a skill you've edited locally

      يستخدم ذلك معرّف المصدر المخزَّن إضافة إلى قيمة hash الحالية لمحتوى الحزمة في المصدر الأصلي لاكتشاف الانحراف.

      تتخطى عمليات التحقق طلبات الشبكة لعمليات التثبيت المفقودة أو التي ليست مجلدات (orphaned)، وللمسارات المسجّلة غير الآمنة أو التي يتعذر حسمها (invalid_install). يمكن إزالة المُدخلات ذات المجلدات المفقودة باستخدام hermes skills uninstall <name>؛ أما المسارات غير الصالحة فتتطلب فحص ملف skills/.hub/lock.json الخاص بالـ profile النشط وإصلاحه قبل إعادة المحاولة. ولا تُزال أي مُدخلات تلقائيًا.

      تواصل عمليات التثبيت الصالحة استخدام عمليات الجلب المتزامنة ومهلات النقل الحالية الخاصة بمحوّل المصدر (source adapter) لديها. ولا توجد مهلة إجمالية صارمة لعملية التحقق من التحديثات: فالمصدر الذي يتعذر الوصول إليه أو البطيء لتثبيت موجود قد يؤخر المُدخلات اللاحقة.

      المهارات التي عدّلتها محليًا (أي أن المحتوى على القرص لم يعد يطابق قيمة hash المسجّلة وقت التثبيت) يتخطاها hermes skills update كي لا تُكتب تغييراتك فوقها بصمت أبدًا. مرّر --force لاستبدالها بالنسخة الأصلية رغم ذلك.

      حدود المعدل (rate limits) في GitHub

      تستخدم عمليات Skills Hub واجهة GitHub API، التي تفرض حدًّا قدره 60 طلبًا في الساعة للمستخدمين غير المصادَق عليهم. إذا ظهرت لك أخطاء حدّ المعدل أثناء التثبيت أو البحث، فاضبط GITHUB_TOKEN في ملف .env لرفع الحد إلى 5,000 طلب في الساعة. وتتضمن رسالة الخطأ تلميحًا عمليًا عند حدوث ذلك.

      نشر tap مهارات مخصص​

      إذا أردت مشاركة مجموعة منتقاة من المهارات — لفريقك، أو مؤسستك، أو للعامة — فيمكنك نشرها كـ tap: وهو مستودع GitHub يضيفه مستخدمو Hermes الآخرون باستخدام hermes skills tap add <owner/repo>. لا خادم، ولا تسجيل في سجل، ولا pipeline للإصدارات. مجرد مجلد يضم ملفات SKILL.md.

      بنية المستودع​

      الـ tap هو أي مستودع GitHub (عام أو خاص — والخاص يحتاج إلى GITHUB_TOKEN) منظّم على النحو التالي:

      owner/repo
      ├── skills/                       # default path; configurable per-tap
      │   ├── my-workflow/
      │   │   ├── SKILL.md              # required
      │   │   ├── references/           # optional supporting files
      │   │   ├── templates/
      │   │   └── scripts/
      │   ├── another-skill/
      │   │   └── SKILL.md
      │   └── third-skill/
      │       └── SKILL.md
      └── README.md                     # optional but helpful

      القواعد:

      • توجد كل مهارة في مجلدها الخاص ضمن المسار الجذري للـ tap (الافتراضي skills/).
      • يصبح اسم المجلد هو الـ slug الذي تُثبَّت به المهارة.
      • يجب أن يحتوي كل مجلد مهارة على ملف SKILL.md يتضمن SKILL.md frontmatter القياسي (name، description، إضافة إلى الحقول الاختيارية metadata.hermes.tags، version، author، platforms، metadata.hermes.config).
      • تُنزَّل المجلدات الفرعية مثل references/، و templates/، و scripts/، و assets/ إلى جانب SKILL.md وقت التثبيت.
      • تُتجاهل المهارات التي يبدأ اسم مجلدها بـ . أو _.

      يكتشف Hermes المهارات عبر سرد كل مجلد فرعي في مسار الـ tap والتحقق من احتواء كلٍّ منها على SKILL.md.

      مثال على tap بسيط​

      my-org/hermes-skills
      └── skills/
          └── deploy-runbook/
              └── SKILL.md

      skills/deploy-runbook/SKILL.md:

      ---
      name: deploy-runbook
      description: Our deployment runbook — services, rollback, Slack channels
      version: 1.0.0
      author: My Org Platform Team
      metadata:
        hermes:
          tags: [deployment, runbook, internal]
      ---

      # Deploy Runbook

      Step 1: ...

      بعد دفع ذلك إلى GitHub، يمكن لأي مستخدم لـ Hermes الاشتراك والتثبيت:

      hermes skills tap add my-org/hermes-skills
      hermes skills search deploy
      hermes skills install my-org/hermes-skills/deploy-runbook

      المسارات غير الافتراضية​

      إذا لم تكن مهاراتك موجودة ضمن skills/ (وهو أمر شائع عندما تضيف شجرة فرعية skills/ إلى مشروع قائم)، فعدّل مُدخل الـ tap في ~/.hermes/skills/.hub/taps.json:

      {
        "taps": [
          {"repo": "my-org/platform-docs", "path": "internal/skills/"}
        ]
      }

      يضبط أمر CLI hermes skills tap add الـ taps الجديدة افتراضيًا على path: "skills/"؛ فعدّل الملف مباشرةً إذا احتجت إلى مسار مختلف. ويعرض hermes skills tap list المسار الفعلي لكل tap.

      تثبيت مهارات فردية مباشرةً (دون إضافة tap)​

      يمكن للمستخدمين أيضًا تثبيت مهارة واحدة من أي مستودع GitHub عام دون إضافة المستودع بأكمله كـ tap:

      hermes skills install owner/repo/skills/my-workflow

      وهذا مفيد عندما تريد مشاركة مهارة واحدة دون مطالبة المستخدم بالاشتراك في السجل الخاص بك بأكمله.

      مستويات الثقة للـ taps​

      تُمنح الـ taps الجديدة مستوى الثقة community افتراضيًا. وتمرّ المهارات المثبّتة منها عبر الفحص الأمني القياسي، وتعرض لوحة التحذير الخاصة بالجهات الخارجية عند أول تثبيت. وإذا كان ينبغي لمؤسستك أو لمصدر موثوق على نطاق واسع الحصول على مستوى ثقة أعلى، فأضف مستودعه إلى TRUSTED_REPOS في tools/skills_guard.py (يتطلب ذلك PR إلى نواة Hermes).

      إدارة الـ taps​

      hermes skills tap list                                # show all configured taps
      hermes skills tap add myorg/skills-repo               # add (default path: skills/)
      hermes skills tap remove myorg/skills-repo            # remove

      داخل جلسة قيد التشغيل:

      /skills tap list
      /skills tap add myorg/skills-repo
      /skills tap remove myorg/skills-repo

      تُخزَّن الـ taps في ~/.hermes/skills/.hub/taps.json (ويُنشأ عند الحاجة).

      تحديثات المهارات المضمّنة (hermes skills reset)​

      يأتي Hermes مع مجموعة من المهارات المضمّنة في skills/ داخل المستودع. وعند التثبيت ومع كل تنفيذ لـ hermes update، تنسخ عملية مزامنة هذه المهارات إلى ~/.hermes/skills/ وتسجّل بيانًا (manifest) في ~/.hermes/skills/.bundled_manifest يربط اسم كل مهارة بقيمة hash لمحتواها وقت مزامنتها (hash الأصل).

      في كل مزامنة، يعيد Hermes حساب قيمة hash لنسختك المحلية ويقارنها بـ hash الأصل:

      • غير متغيّرة → من الآمن سحب التغييرات من المصدر الأصلي، ونسخ النسخة المضمّنة الجديدة، وتسجيل hash الأصل الجديد.
      • متغيّرة → تُعامل على أنها معدّلة من قِبل المستخدم وتُتخطّى إلى الأبد، كي لا تُسحق تعديلاتك أبدًا.

      ذاكرات التخزين المؤقت المُولَّدة وقت التشغيل داخل المهارة (__pycache__/، و .pytest_cache/، و .mypy_cache/، و .ruff_cache/، وملف .pyc الموجود بجوار ملف .py الخاص به) ليست جزءًا من قيمة hash، لذا فإن تشغيل سكربت مساعد خاص بمهارة لا يجعلها أبدًا معدّلة من قِبل المستخدم ولا يخفيها من hermes skills list-modified / diff.

      هذه الحماية جيدة، لكن لها جانبًا حادًا واحدًا. فإذا عدّلت مهارة مضمّنة ثم أردت لاحقًا التخلي عن تغييراتك والعودة إلى النسخة المضمّنة بمجرد النسخ واللصق من ~/.hermes/hermes-agent/skills/، فإن البيان يظل يحتفظ بـ hash الأصل القديم من آخر مزامنة ناجحة. ولن يطابق محتوى النسخ واللصق الجديد (hash النسخة المضمّنة الحالية) ذلك الـ hash القديم، فتستمر المزامنة في اعتبار المهارة معدّلة من قِبل المستخدم.

      hermes skills reset هو المخرج من هذا الموقف:

      # Safe: clears the manifest entry for this skill. Your current copy is preserved,
      # but the next sync re-baselines against it so future updates work normally.
      hermes skills reset google-workspace

      # Full restore: also deletes your local copy and re-copies the current bundled
      # version. Use this when you want the pristine upstream skill back.
      hermes skills reset google-workspace --restore

      # Non-interactive (e.g. in scripts or TUI mode) — skip the --restore confirmation.
      hermes skills reset google-workspace --restore --yes

      ويعمل الأمر نفسه في المحادثة كـ slash command:

      /skills reset google-workspace
      /skills reset google-workspace --restore
      الـ Profiles

      لكل profile ملف .bundled_manifest خاص به ضمن HERMES_HOME الخاص به، لذا فإن hermes -p coder skills reset <name> لا يؤثر إلا في ذلك الـ profile.

      الـ Slash commands (داخل المحادثة)​

      تعمل جميع الأوامر نفسها مع /skills:

      /skills browse
      /skills search react --source skills-sh
      /skills search https://mintlify.com/docs --source well-known
      /skills inspect skills-sh/vercel-labs/json-render/json-render-react
      /skills install openai/skills/skill-creator --force
      /skills check
      /skills update
      /skills reset google-workspace
      /skills list

      لا تزال المهارات الاختيارية الرسمية تستخدم معرّفات مثل official/security/1password و official/migration/openclaw-migration.
