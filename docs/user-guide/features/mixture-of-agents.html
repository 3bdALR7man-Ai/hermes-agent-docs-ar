      Mixture of Agents

      Mixture of Agents مزوّد نماذج افتراضي. يظهر كل إعداد مسبق (preset) مُسمّى من MoA كنموذج قابل للاختيار ضمن المزوّد moa.

      عند اختيار إعداد MoA مسبق، يكون المُجمِّع (aggregator) الخاص به هو النموذج المنفِّذ (acting model)، أي النموذج الذي يكتب رد المساعد ويُصدر استدعاءات الأدوات. تعمل النماذج المرجعية (reference models) أولًا وتقدّم تحليلًا يستفيد منه المُجمِّع.

      استخدم MoA عندما تستفيد مهمة صعبة من وجهات نظر عدة نماذج، مع بقاء الحاجة إلى حلقة الوكيل (agent loop) المعتادة في Hermes: استدعاءات الأدوات، وجولات المتابعة، والمقاطعات، وحفظ سجل المحادثة، وسياق الجلسة نفسه كأي رسالة أخرى.

      اختيار إعداد MoA مسبق كنموذج لك​

      يمكنك اختيار إعداد مسبق عبر واجهات اختيار النموذج المعتادة:

      /model default --provider moa
      /model review --provider moa

      يمكن اختيار إعدادات MoA المسبقة من كل واجهات Hermes، لأن MoA مزوّد عادي ضمن نظام النماذج:

      • CLI / gateway / TUI /model — /model <preset> --provider moa، أو /model --provider moa للإعداد المسبق الافتراضي. ويعمل أيضًا /model <preset> المجرّد عندما يطابق الاسم تمامًا إعدادًا مسبقًا مضبوطًا.
      • hermes model و أداة اختيار النموذج في Dashboard — يظهر صف مزوّد باسم Mixture of Agents تُعرض فيه أسماء إعداداتك المسبقة بوصفها نماذج له.
      • تطبيق Desktop الرسومي — تعرض القائمة المنسدلة للنماذج قسم MoA presets؛ واختيار أحدها (MoA: <preset>) يحوّل النموذج النشط إلى ذلك الإعداد المسبق. كما تتيح لوحة إعدادات Desktop إنشاء الإعدادات المسبقة وتعديلها.

      وبالتالي تظهر الإعدادات المسبقة المضبوطة في كل مكان تختار فيه أي نموذج آخر.

      اختصار عبر slash command​

      /moa اختصار مريح للاستخدام لمرة واحدة. فهو يشغّل prompt واحدًا عبر إعداد MoA المسبق الافتراضي، ثم يعيد النموذج الذي كنت تستخدمه:

      /moa design and implement a migration plan for this flaky test cluster

      ينتقل Hermes مؤقتًا إلى إعداد MoA المسبق الافتراضي لذلك الدور الواحد، ويرسل الـ prompt، ثم يستعيد نموذجك السابق بعد ذلك. الوسيط بأكمله هو الـ prompt — إذ لم يعد /moa يفسّره كاسم إعداد مسبق.

      /moa

      أما /moa المجرّد (بلا prompt) فيطبع طريقة الاستخدام فقط.

      للانتقال إلى إعداد MoA مسبق لبقية الجلسة، اختره من أداة اختيار النموذج — تظهر إعدادات MoA المسبقة تحت مزوّد Mixture of Agents في كل واجهة لاختيار النموذج (انظر أعلاه). و /moa ليس أداة لتبديل النموذج عن قصد، حتى لا يتمكن prompt عادي أبدًا من تغيير نموذجك عن طريق الخطأ.

      كيف يعمل داخل حلقة الوكيل​

      في كل استدعاء للنموذج الرئيسي عند اختيار المزوّد moa، يقوم Hermes بما يلي:

      1. يحدّد الإعداد المسبق المختار بالاسم؛
      2. يشغّل النماذج المرجعية المضبوطة دون مخططات الأدوات (tool schemas) (فهي لا تتلقى سوى نصوص المستخدم/المساعد في المحادثة — وليس الـ system prompt الخاص بـ Hermes أو سجل استدعاءات الأدوات — لتبقى الاستدعاءات المرجعية منخفضة التكلفة وتتجنب الرفض من المزوّدين الصارمين)؛
      3. يُلحق مخرجات النماذج المرجعية كسياق خاص بالمُجمِّع؛
      4. يستدعي المُجمِّع المضبوط مع مخطط أدوات Hermes المعتاد؛
      5. يعامل رد المُجمِّع على أنه الرد الفعلي للنموذج؛
      6. إذا استدعى المُجمِّع أدوات، ينفّذها Hermes بشكل طبيعي؛
      7. في الجولة التالية للنموذج، تُشغَّل عملية MoA نفسها مجددًا على المحادثة المحدّثة، بما في ذلك نتائج الأدوات.

      ولأن MoA يُختار عبر نظام النماذج المعتاد، فإنه يتكامل تلقائيًا مع /goal، وجلسات الـ gateway، وجلسات TUI، ومحادثات Desktop.

      ضبط الإعدادات المسبقة​

      يمكنك ضبط إعدادات MoA المسبقة المُسمّاة من:

      • Dashboard → Models → Model Settings → Mixture of Agents
      • تطبيق Desktop → Settings → Model → Mixture of Agents
      • hermes moa configure [name]
      • config.yaml

      تخزّن الإعدادات أزواجًا صريحة من المزوّد/النموذج، لذا يمكنك المزج بين المزوّدين واستخدام عدة نماذج من المزوّد نفسه:

      moa:
        default_preset: default
        presets:
          default:
            reference_models:
              - provider: openai-codex
                model: gpt-5.5
              - provider: openrouter
                model: deepseek/deepseek-v4-pro
            aggregator:
              provider: openrouter
              model: anthropic/claude-opus-4.8
            # Optional: pin sampling temperatures. When omitted (the default),
            # temperature is NOT sent and each model uses its provider default —
            # the same behavior as a single-model Hermes agent.
            # reference_temperature: 0.6
            # aggregator_temperature: 0.4

            enabled: true

      الإعداد المسبق الافتراضي:

      • نموذج مرجعي: openai-codex:gpt-5.5
      • نموذج مرجعي: openrouter:deepseek/deepseek-v4-pro
      • المُجمِّع / النموذج المنفِّذ: openrouter:anthropic/claude-opus-4.8

      مخرجات المستشارين​

      يستخدم MoA حدود المخرجات التي يحددها المزوّد. لم تعد إعدادات الحد الأقصى لـ tokens المخرجات على مستوى الإعداد المسبق أو على مستوى كل خانة مدعومة. تختلف القيم الافتراضية من مزوّد إلى آخر؛ وإغفال الحد لا يعني دائمًا الحد الأقصى للنموذج. أما البروتوكولات الأصلية التي تتطلب حدًا للمخرجات فتتلقى قيمة داخلية من Hermes.

      وتيرة المستشارين باستخدام fanout​

      افتراضيًا، يعمل المستشارون (advisors) مرة واحدة لكل دور مستخدم (fanout: user_turn) — إذ يولّفون نصائح على مستوى الخطة عند أول رسالة في الدور، ثم يتابع المُجمِّع المنفِّذ بقية حلقة الأدوات وحده. هذه هي الوتيرة الأقل تكلفة: فتكلفة المستشارين لا تتضاعف بعدد استدعاءات الأدوات في الدور. وهناك وتيرتان بديلتان تقايضان التكلفة بحداثة النصائح:

      • fanout: per_iteration — يُعاد تشغيل المستشارين في كل جولة أدوات، فتواكب نصائحهم دائمًا أحدث نتائج الأدوات — مقابل مضاعفة زمن استجابة المستشارين وتكلفتهم بعدد استدعاءات الأدوات في الدور.
      • fanout: every_n:3 — الحل الوسط: يعمل المستشارون في الجولة الأولى من كل دور مستخدم، ثم مرة كل 3 جولات أدوات (تصلح أي قيمة N >= 2). وتعيد الجولات الواقعة بينها استخدام الإرشادات المخزّنة مؤقتًا من آخر تشغيل للمستشارين، لذا يظل المُجمِّع يتلقى النصائح في كل خطوة — لكنها تُحدَّث كل N خطوات بدلًا من كل خطوة. يُعاد ضبط العدّاد مع كل رسالة مستخدم جديدة، فيبدأ كل دور بنصائح جديدة. كما تُقبل صيغة الخريطة fanout: {mode: every_n, n: 3} وتُحوَّل إلى الصيغة النصية.
      moa:
        presets:
          fresh:
            reference_models:
              - provider: openrouter
                model: anthropic/claude-opus-4.8
            aggregator:
              provider: openrouter
              model: openai/gpt-5.5
            fanout: per_iteration   # advisors refresh on every tool iteration

      تعود القيم غير المعروفة أو غير الصالحة إلى user_turn.

      تغيير القيمة الافتراضية

      قبل يوليو 2026 كانت الوتيرة الافتراضية هي per_iteration. أما الآن فالقيمة الافتراضية هي user_turn — الوتيرة الأقل تكلفة والأقل أثرًا — إلى أن تبرّر اختبارات الأداء لكل وضع قيمة افتراضية أعلى تكلفة. والإعدادات المسبقة التي تريد استعادة النصائح في كل خطوة تضبط fanout: per_iteration صراحةً.

      مرشّح الخصوصية لمخرجات المستشارين​

      قد تُردّد مخرجات المستشارين بيانات حساسة من المحادثة — عناوين البريد الإلكتروني، وأرقام الهواتف المنسّقة، ومفاتيح API، و JWTs — في الكتل المرجعية المعروضة في الواجهة، وسجلات تتبّع MoA المحفوظة، و prompt المُجمِّع. يتولى moa.privacy_filter (المعطّل افتراضيًا) تنقيح هذه المواضع:

      moa:
        privacy_filter: display   # or: full
      • display — ينقّح المواضع المرئية للمستخدم فقط: الكتل المرجعية المعنونة المعروضة في الواجهة والسجلات التي يكتبها save_traces. ويظل المُجمِّع يتلقى نص المستشارين الخام، فلا تتأثر جودة الإجابة.
      • full — ينقّح إضافةً إلى ذلك نص المستشارين المحقون في prompt المُجمِّع (ومُدخل التوليف الخاص بالأمر أحادي الاستخدام /moa).

      تُخفى أشكال بيانات الاعتماد (بادئات مفاتيح API، و JWTs، والمفاتيح الخاصة، وسلاسل الاتصال بقواعد البيانات) بواسطة أداة تنقيح الأسرار المركزية في Hermes؛ ويضيف مرشّح MoA فوق ذلك تنقيح عناوين البريد الإلكتروني وأرقام الهواتف ذات التنسيق الواضح. الأنماط متحفّظة عن قصد لتناسب النصائح بأسلوب مراجعة الكود: فسلاسل الأرقام المجرّدة، وأرقام الأسطر، والطوابع الزمنية، و git SHAs، وعناوين IP لا تُمَس أبدًا — ولا تُطابَق إلا تنسيقات الهواتف المفصولة بمحدِّدات مثل (555) 123-4567 أو 555-123-4567.

      مستوى جهد الاستدلال لكل خانة​

      يمكن لخانات النماذج المرجعية والمُجمِّع أيضًا ضبط reasoning_effort. استخدم ذلك عندما تريد أن يساهم النموذج نفسه بأعماق مختلفة، أو عندما ينبغي للمُجمِّع أن يفكّر بعمق أكبر من النماذج المرجعية الاستشارية. تتطابق القيم الصالحة مع عناصر التحكم المعتادة بالاستدلال في Hermes: none، minimal، low، medium، high، xhigh، max، و ultra.

      moa:
        presets:
          deep_review:
            reference_models:
              - provider: openai-codex
                model: gpt-5.6-sol
                reasoning_effort: low
              - provider: openai-codex
                model: gpt-5.6-sol
                reasoning_effort: xhigh
              - provider: xai-oauth
                model: grok-4.5
            aggregator:
              provider: openai-codex
              model: gpt-5.6-sol
              reasoning_effort: high

      أغفِل reasoning_effort لاستخدام القيمة الافتراضية للمزوّد/Hermes لتلك الخانة.

      إدارة الإعدادات المسبقة من الطرفية​

      hermes moa list
      hermes moa configure              # update the default preset
      hermes moa configure review       # create or update a named preset
      hermes moa delete review

      اختبارات الأداء (Benchmarks)​

      على HermesBench، يتفوق إعداد MoA مسبق من نموذجين — claude-opus-4.8 كمُجمِّع فوق gpt-5.5 كنموذج مرجعي — على كلٍّ من النموذجين عند تشغيله منفردًا:

      النموذجنتيجة HermesBench
      مُجمِّع Opus (opus-4.8 + gpt-5.5 كمرجع) — MoA0.8202
      anthropic/claude-opus-4.80.7607
      openai/gpt-5.50.7412

      يتفوق إعداد MoA على أقوى مكوّناته (opus-4.8) بنحو 6 نقاط، مما يؤكد أن تجميع وجهة نظر ثانية يرفع الجودة في المهام الصعبة بدلًا من مجرد حساب متوسط النموذجين.

      التخزين المؤقت للـ Prompt​

      صُمّم MoA بحيث لا ينكسر أبدًا prompt cache الخاص بالمحادثة الرئيسية. فاختيار إعداد MoA مسبق هو اختيار نموذج عادي: لا يعدّل السياق السابق، ولا يبدّل الـ toolsets، ولا يعيد بناء الـ system prompt في منتصف المحادثة. يبقى سجل محادثتك والـ system prompt ومخطط الأدوات ثابتة على مستوى البايت، لذا تُحفظ البادئة المخزّنة مؤقتًا التي يعتمد عليها كل نموذج آخر تمامًا كما هي مع نموذج عادي. والانتقال إلى إعداد MoA مسبق أو منه يكلّف نفس إبطال الـ cache الذي يسببه أي تبديل آخر عبر /model — لا أكثر.

      يُخزَّن كلا نوعي الاستدعاءات الداخلية مؤقتًا بشكل طبيعي:

      • النماذج المرجعية تتلقى عرضًا مختصرًا وحتميًا للمحادثة (بعد إزالة الـ system prompt وسجل الأدوات — انظر الحلقة أعلاه). ولأن هذا العرض دالة ثابتة للسجل الثابت، تتكرر بادئة الـ prompt الخاصة بالنموذج المرجعي عبر الجولات وتُخزَّن مؤقتًا بشكل طبيعي. والاستدعاءات المرجعية استدعاءات استشارية قصيرة بلا أدوات.
      • المُجمِّع هو النموذج المنفِّذ. تُلحق مخرجات النماذج المرجعية في نهاية آخر دور للمستخدم كإرشادات خاصة. ولأن هذا النص يقع في الذيل — أسفل البادئة الثابتة بأكملها (system prompt + السجل السابق) — فإنه لا يُبطل أي بادئة مخزّنة مؤقتًا: إذ يحصل المُجمِّع على cache hit لكل ما يسبق موضع الحقن، ولا يكون جديدًا سوى الذيل المُلحق حديثًا. وهذا بالضبط سلوك كل دور عادي، حيث تكون كل رسالة مستخدم جديدة أيضًا tokens ذيلية غير مخزّنة مؤقتًا.

      إذن لا يضحّي MoA بالتخزين المؤقت للـ prompt في أيٍّ من نوعي الاستدعاءات. تكلفته الحقيقية الوحيدة هي الاستدعاءات المرجعية الإضافية في كل جولة — فأنت تدفع مقابل وجهات نظر نماذج متعددة، لا مقابل cache مكسور. وتبقى بادئة المحادثة طويلة الأمد المشتركة مع بقية Hermes سليمة تمامًا.

      ملاحظات​

      • لم يعد MoA مُدرجًا ضمن hermes tools؛ ولا يوجد toolset باسم moa لتفعيله.
      • ضبط enabled: false على إعداد مسبق يعطّل توزيع الطلبات على النماذج المرجعية (fan-out) لذلك الإعداد: فيعمل المُجمِّع وحده، تمامًا كما لو اخترته كنموذج عادي. هذا هو مفتاح الإيقاف الخاص بكل إعداد مسبق الظاهر في إعدادات لوحة التحكم و Desktop.
      • لا يمكن أن يكون مُجمِّع إعداد مسبق إعدادَ MoA مسبقًا آخر. فأشجار MoA التكرارية محظورة عن قصد.
      • لا يؤدي فشل بيانات الاعتماد في أحد النماذج المرجعية إلى إلغاء الدور. إذ يُضمّن Hermes هذا الفشل في السياق المرجعي ويتابع بما أعادته النماذج الأخرى.
      • يزيد MoA عدد استدعاءات النموذج. فقد تتضمن جولة واحدة للنموذج عدة استدعاءات مرجعية إضافةً إلى استدعاء المُجمِّع.
