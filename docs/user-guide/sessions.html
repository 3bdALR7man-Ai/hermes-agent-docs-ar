      الجلسات (Sessions)

      يحفظ Hermes Agent تلقائيًا كل محادثة كجلسة. تتيح الجلسات استئناف المحادثة، والبحث عبر الجلسات، وإدارة سجل المحادثات الكامل.

      كيف تعمل الجلسات​

      كل محادثة — سواء من CLI أو Telegram أو Discord أو Slack أو WhatsApp أو Signal أو Matrix أو Teams أو أي منصة مراسلة أخرى — تُخزَّن كجلسة بسجل رسائل كامل. تُتَتبَّع الجلسات في:

      1. قاعدة بيانات SQLite (~/.hermes/state.db) — بيانات وصفية مُهيكلة للجلسة مع بحث نصي كامل عبر FTS5، بالإضافة إلى سجل الرسائل الكامل

      تخزّن قاعدة بيانات SQLite:

      • معرّف الجلسة، منصة المصدر، معرّف المستخدم
      • عنوان الجلسة (اسم فريد قابل للقراءة البشرية)
      • اسم النموذج وإعداداته
      • لقطة من system prompt
      • سجل الرسائل الكامل (الدور، المحتوى، استدعاءات الأدوات، نتائج الأدوات)
      • عدد الـ tokens (الدخل/الخرج)
      • الطوابع الزمنية (started_at، ended_at)
      • معرّف الجلسة الأصل (لتقسيم الجلسة الناتج عن الضغط)

      ما الذي يُحتسب ضمن السياق​

      يخزّن Hermes سجل الجلسة حتى يتمكن من استئناف المحادثات، لكنه لا يُعيد إرسال كل بايت تعامل معه على الإطلاق. في كل دور، يرى النموذج system prompt المختار، ونافذة المحادثة الحالية، وأي محتوى يحقنه Hermes صراحة لذلك الدور.

      تُعامَل مرفقات الوسائط كمدخلات محصورة بالدور:

      • يمكن إرفاق الصور مباشرة بالاستدعاء التالي للنموذج، أو تحليلها مسبقًا إلى وصف نصي عندما لا يدعم النموذج النشط الرؤية (vision) الأصلية.
      • يُنقَل الصوت إلى نص عند ضبط خدمة تحويل الكلام إلى نص.
      • يمكن تضمين النص المستخرج من مستندات نصية؛ أما أنواع المستندات الأخرى فعادةً ما تُمثَّل بمسار محلي محفوظ وملاحظة قصيرة.
      • يمكن أن تظهر مسارات المرفقات والنصوص المستخرَجة/المُشتقّة في النسخة النصية، لكن البايتات الخام للصورة أو الصوت أو الملف الثنائي لا تُنسَخ مرارًا إلى الـ prompts المستقبلية.

      مثلًا، إذا أرسل المستخدم صورة وطلب من Hermes صنع ميم منها، فقد يفحص Hermes تلك الصورة مرة واحدة بالرؤية ويُشغِّل سكربت معالجة صور. لا تحمل الأدوار المستقبلية تلقائيًا ملف JPEG الأصلي في السياق. بل تحمل فقط ما كُتب في المحادثة، مثل طلب المستخدم، أو وصف مختصر للصورة، أو مسار تخزين مؤقت محلي، أو استجابة المساعد النهائية.

      السبب الأكثر شيوعًا لنمو السياق ليس ملف الوسائط نفسه، بل النص المطوَّل: النصوص الملصقة، والسجلات الكاملة، ومخرجات الأدوات الضخمة، والفروقات (diffs) الطويلة، وتقارير الحالة المكرَّرة، وتفريغات الإثبات المفصَّلة. فضِّل الملخصات، ومسارات الملفات، والمقتطفات المركَّزة، والاستعلامات المدعومة بالأدوات على نسخ الأصول الكبيرة في المحادثة.

      نصيحة

      استخدم /compress عندما تطول الجلسة، و/new لبدء خيط جديد، و hermes sessions prune فقط عندما تريد حذف الجلسات المنتهية القديمة من التخزين. إذا نما state.db ببساطة إلى حجم كبير، ابدأ بالخيار غير المدمِّر أولًا: hermes sessions optimize يدمج مقاطع فهرس FTS5 وينفّذ VACUUM على قاعدة البيانات دون المساس بأي بيانات جلسة. الضغط يقلّص السياق النشط؛ وهو ليس حذفًا للخصوصية. مرّر اسمًا إلى /new (مثل /new payments-refactor) لضبط العنوان الأولي للجلسة الجديدة مسبقًا — مفيد لإيجادها لاحقًا باستخدام /resume <name> أو في قائمة /sessions.

      استئناف جلسة CLI​

      استأنف المحادثات السابقة من CLI باستخدام --continue أو --resume:

      متابعة آخر جلسة​

      # Resume the most recent CLI session
      hermes --continue
      hermes -c

      # Or with the chat subcommand
      hermes chat --continue
      hermes chat -c

      يبحث هذا عن أحدث جلسة cli من قاعدة بيانات SQLite ويحمّل سجل محادثتها الكامل.

      المتابعة لكل طرفية​

      -c المجردة تُدرك الطرفية: تترك كل جلسة CLI ملف أثر صغيرًا تحت ~/.hermes/terminal-sessions/ مفهرسًا بالطرفية التي تعمل فيها (جهاز tty، لوحة tmux، نافذة kitty، لوحة wezterm، لوحة Zellij، جلسة Windows Terminal، ...). عندما تشغّل hermes -c مرة أخرى في نفس الطرفية، يستأنف Hermes جلسة تلك الطرفية الخاصة — بحيث يتابع كل لوحين متجاورين محادثتهما الخاصة بدلًا من أن يستحوذ كلاهما على الجلسة الأحدث عالميًا. إذا لم يوجد أثر للطرفية (أول استخدام، جلسة محذوفة، أو أثر قديم يتجاوز عمره 30 يومًا)، تعود -c إلى سلوك الجلسة الأحدث. لا يتأثر -c "name" و--resume بذلك. عطِّل هذا بضبط session.terminal_continue: false في config.yaml.

      الاستئناف بالاسم​

      إذا منحت جلسة عنوانًا (راجع تسمية الجلسات أدناه)، يمكنك استئنافها بالاسم:

      # Resume a named session
      hermes -c "my project"

      # If there are lineage variants (my project, my project #2, my project #3),
      # this automatically resumes the most recent one
      hermes -c "my project"   # → resumes "my project #3"

      استئناف جلسة محدَّدة​

      # Resume a specific session by ID
      hermes --resume 20250305_091523_a1b2c3d4
      hermes -r 20250305_091523_a1b2c3d4

      # Resume by title
      hermes --resume "refactoring auth"

      # Resume the most recent session — same lookup as -c
      hermes --resume latest

      # Or with the chat subcommand
      hermes chat --resume 20250305_091523_a1b2c3d4

      تُعرَض معرّفات الجلسات عند خروجك من جلسة CLI، ويمكن إيجادها باستخدام hermes sessions list.

      ملاحظة

      latest كلمة محجوزة لـ --resume. تظل الجلسة المُسمَّاة حرفيًا "latest" قابلة للوصول عبر معرّفها أو عبر -c latest (تطابق العنوان).

      الاستئناف في دليل محدَّد​

      مرّر --in <dir> للانتقال إلى دليل قبل البدء أو الاستئناف. مع الجمع مع --resume latest (أو -c)، تُختار أحدث جلسة لمساحة عمل ذلك الدليل — دون الحاجة إلى تنفيذ cd أولًا أو تذكّر معرّفات الجلسات:

      # Resume the latest session that belongs to ./my-project
      hermes --resume latest --in ./my-project

      # Works with the TUI too
      hermes --tui --resume latest --in ./my-project

      --in يُثبِّت أيضًا الجلسة على ذلك الدليل: دليل العمل المسجَّل للجلسة المستأنفة لا يُستعاد (كما لو مُرِّر --no-restore-cwd).

      الاستئناف يستعيد دليل العمل​

      استئناف جلسة CLI يُنفّذ أيضًا cd عائدًا إلى دليل العمل المسجَّل للجلسة (جذر مستودع git أو دليل المشروع الخاص بها)، بحيث تستأنف المحادثة في مساحة العمل التي تنتمي إليها. إذا فضّلت البقاء حيث أنت، مرّر --no-restore-cwd:

      hermes --resume 20250305_091523_a1b2c3 --no-restore-cwd

      يؤكِّد سطر ↪ restored workspace dir: … التبديل. فشل الاستعادة لا يُعطِّل الاستئناف نفسه أبدًا.

      تصفية الجلسات حسب مساحة العمل​

      تقبل hermes sessions list الخيار --workspace <needle> لعرض الجلسات فقط التي يطابق مفتاح مساحة عملها (جذر مستودع git، وإلا دليل العمل) — عبر جزء من المسار أو اسم الدليل الأساسي المطابق تمامًا:

      hermes sessions list --workspace my-project
      hermes sessions list --workspace ~/code/hermes-agent

      ملخّص المحادثة عند الاستئناف​

      عندما تستأنف جلسة، يعرض Hermes ملخصًا مُختصرًا للمحادثة السابقة في لوحة مُنسَّقة قبل موجّه الإدخال:

      يعرض وضع الاستئناف لوحة ملخص مُختصرة بأدوار المستخدم والمساعد الأخيرة قبل إعادتك إلى الموجّه الحي.

      الملخّص:

      • يعرض رسائل المستخدم (● ذهبي) واستجابات المساعد (◆ أخضر)
      • يقتطع الرسائل الطويلة (300 حرف للمستخدم، 200 حرف / 3 أسطر للمساعد)
      • يطوي استدعاءات الأدوات إلى عدد مع أسماء الأدوات (مثل [3 tool calls: terminal, web_search])
      • يخفي رسائل النظام، ونتائج الأدوات، والاستدلال الداخلي
      • يحدّ العرض بآخر 10 تبادلات مع مؤشر "... N earlier messages ..."
      • يستخدم تنسيقًا خافتًا للتمييز عن المحادثة النشطة

      لتعطيل الملخّص والإبقاء على سلوك السطر الواحد المُقتضب، اضبط في ~/.hermes/config.yaml:

      display:
        resume_display: minimal   # default: full
      نصيحة

      تتبع معرّفات الجلسات الصيغة YYYYMMDD_HHMMSS_<hex> — تستخدم جلسات CLI/TUI لاحقة سداسية عشرية من 6 أحرف (مثل 20250305_091523_a1b2c3)، وتستخدم جلسات gateway لاحقة من 8 أحرف (مثل 20250305_091523_a1b2c3d4). يمكنك الاستئناف بالمعرّف (كاملًا أو بادئة فريدة) أو بالعنوان — يعمل كلاهما مع -c و-r.

      التسليم عبر المنصات​

      استخدم /handoff <platform> من جلسة CLI لنقل المحادثة الحية إلى قناة المنزل (home channel) لمنصة مراسلة. يتابع الوكيل بالضبط من حيث توقف CLI — نفس معرّف الجلسة، وسجل نصي كامل يراعي الأدوار، واستدعاءات الأدوات وكل شيء.

      # Inside a CLI session
      /handoff telegram

      ما الذي يحدث:

      1. يتحقق CLI من أن <platform> مفعَّلة ولديها قناة منزل مضبوطة (شغّل /sethome من المحادثة الوجهة مرة واحدة لضبطها).

      2. يضع CLI الجلسة في حالة انتظار ويستقصي (يـblock-poll) الـ gateway. يرفض إن كان الوكيل في منتصف دور — انتظر انتهاء الاستجابة الحالية أولًا.

      3. يستحوذ مراقب gateway على التسليم ويطلب من المحوّل الوجهة خيطًا جديدًا:

        • Telegram — يفتح موضوع منتدى جديد (مواضيع DM إذا كان وضع Topics في Bot API 9.4+ مفعَّلًا في المحادثة، أو موضوع في مجموعة منتدى فائقة).
        • Discord — ينشئ خيطًا بأرشفة تلقائية بعد 1440 دقيقة تحت قناة المنزل النصية.
        • Slack — ينشر رسالة بذرة ويستخدم ts الخاص بها كمرساة للخيط.
        • WhatsApp / Signal / Matrix / SMS — لا خيوط أصلية، فيعود إلى قناة المنزل مباشرة.

      4. يعيد الـ gateway ربط مفتاح الوجهة بمعرّف جلسة CLI الحالية لديك، ثم يصوغ دور مستخدم صناعيًا يطلب من الوكيل التأكيد والتلخيص. يصل الرد إلى الخيط الجديد.

      5. عندما يؤكد الـ gateway النجاح، يطبع CLI تلميح /resume ويخرج بسلاسة:

        ↻ Handoff complete. The session is now active on telegram.
          Resume it on this CLI later with: /resume my-session-title

      6. من تلك النقطة، تعيش المحادثة على المنصة. رُدّ في الخيط الجديد — أي شخص مُصرَّح له في تلك القناة يشارك نفس الجلسة، وأي رسالة مستخدم حقيقية لاحقة في الخيط تنضم بسلاسة لأن جلسات الخيوط تُفهرَس دون user_id.

      الاستئناف عائدًا إلى CLI: عندما تريد العودة إلى سطح المكتب، فقط شغّل /resume <title> (أو hermes -r "<title>" من الـ shell) وتابع من حيث توقفت المنصة.

      أنماط الفشل:

      • لا قناة منزل مضبوطة ← يرفض CLI مع تلميح /sethome.
      • الـ gateway غير قيد التشغيل (لا شيء يستحوذ على الطلب على الإطلاق) ← تنتهي مهلة CLI عند 60 ثانية برسالة واضحة وتظل جلسة CLI لديك سليمة.
      • نقل بطيء: بمجرد استحواذ الـ gateway على التسليم، يعيد تشغيل جلستك الكاملة عبر دور وكيل حقيقي، ما قد يستغرق دقائق قليلة على الجلسات الطويلة. يعرض CLI نبضات "Still transferring..." وينتظر حتى 15 دقيقة — لا يُبلِّغ أبدًا عن نقل بطيء خطأً على أنه "gateway غير قيد التشغيل".
      • فشل إنشاء الخيط (صلاحيات، وضع المواضيع مُعطَّل) ← يعود إلى قناة المنزل مباشرة ويكتمل مع ذلك؛ بلا عزل خيط لكن التسليم نفسه يعمل.
      • فشل adapter.send (حد معدل، خطأ API عابر) ← يُوسم التسليم كفاشل مع السبب؛ ويُمسح الصف لتتمكن من إعادة المحاولة.

      قيد يستحق المعرفة: بالنسبة إلى المنصات غير القادرة على الخيوط ذات قنوات منزل جماعية متعددة المستخدمين، يُفهرَس الدور الصناعي كجلسة بنمط DM. هذا يعمل مع قنوات المنزل ذات DM الذاتي (الإعداد المعتاد) لكنه ليس مثاليًا للمحادثات الجماعية المشتركة فعليًا. تغطي الخيوط Telegram / Discord / Slack — الحالة الشائعة إلى حد بعيد — لذا لا تصادف معظم الإعدادات هذا القيد أبدًا.

      تسمية الجلسات​

      امنح الجلسات عناوين قابلة للقراءة البشرية حتى تتمكن من إيجادها واستئنافها بسهولة.

      العناوين المُولَّدة تلقائيًا​

      يولِّد Hermes تلقائيًا عنوانًا وصفيًا قصيرًا (3-7 كلمات) لكل جلسة بعد التبادل الأول. يعمل هذا في خيط خلفي باستخدام نموذج مساعد سريع، لذا لا يضيف أي زمن انتقال (latency). سترى العناوين المُولَّدة تلقائيًا عند تصفح الجلسات باستخدام hermes sessions list أو hermes sessions browse.

      يعمل التوسيم التلقائي مرة واحدة فقط لكل جلسة ويُتخطَّى إذا كنت قد ضبطت عنوانًا يدويًا بالفعل.

      ضبط عنوان يدويًا​

      تصدير الجلسات​

      hermes sessions export واجهة واحدة لكل صيغ التصدير، تُحدَّد عبر --format:

      الصيغةالمُخرَجاستخدمها لـ
      jsonl (الافتراضي)كائن JSON واحد لكل جلسةالنسخ الاحتياطية، التبادل الآلي
      md / qmdملف Markdown/Quarto واحد لكل جلسة + بيان (manifest)الأرشيفات القابلة للقراءة، الملاحظات
      htmlصفحة واحدة قائمة بذاتها (شريط جانبي لتصدير عدة جلسات)المشاركة، التصفح
      traceClaude Code JSONLHF Agent Trace Viewer، --upload

      إضافةً إلى --only user-prompts لعرض يقتصر على الـ prompts فقط (jsonl أو md).

      تشترك كل الصيغ في نفس مفاتيح التحديد: --session-id لجلسة واحدة، أو مجموعة فلاتر prune/archive الكاملة للحجم — --older-than / --newer-than / --before / --after (مدد مثل 5h/2d/1w، أو أيام مجردة، أو طوابع ISO الزمنية)، و--source، و--title، و--model، و--provider، و--cwd، و--min/--max-messages، و--min/--max-tokens، و--min/--max-cost، و--min/--max-tool-calls، و--user، و--chat-id، و--chat-type، و--branch، و--end-reason. --dry-run يعاين مجموعة التطابق دون كتابة. --redact يزيل الأسرار (مفاتيح API، الـ tokens، بيانات الاعتماد) من المحتوى المُصدَّر بأي صيغة — موصى به لأي شيء تنوي مشاركته. ملاحظة: فلاتر الحجم تطابق الجلسات المنتهية؛ أما export بلا فلاتر فيُفرِّغ كل شيء، بما فيه الجلسات النشطة.

      JSONL (الافتراضي)​

      # Export all sessions to a JSONL file
      hermes sessions export backup.jsonl

      # Export sessions from a specific platform
      hermes sessions export telegram-history.jsonl --source telegram

      # Export a single session
      hermes sessions export session.jsonl --session-id 20250305_091523_a1b2c3d4

      # Redact API keys/tokens/credentials from the exported content
      hermes sessions export backup.jsonl --redact

      تحتوي الملفات المُصدَّرة على كائن JSON واحد في كل سطر مع بيانات وصفية كاملة للجلسة وكل الرسائل.

      HTML​

      --format html يكتب ملف HTML واحدًا قائمًا بذاته — بلا تبعيات عن بُعد — مع فقاعات رسائل مُنسَّقة، ومخرجات أدوات قابلة للطي، و(لتصدير عدة جلسات) شريط جانبي للتبديل بين الجلسات:

      # One session as a standalone HTML page
      hermes sessions export --format html --session-id 20250305_091523_a1b2c3d4 transcript.html

      # All Telegram sessions from the last week in one file, secrets redacted
      hermes sessions export --format html --newer-than 1w --source telegram --redact archive.html

      الـ prompts فقط​

      --only user-prompts يُصدِّر فقط الـ prompts التي كتبتها — دون ردود المساعد أو مخرجات الأدوات أو سياق النظام. مفيد لبناء مكتبات prompts أو مراجعة ما طلبته:

      # One JSONL record per prompt (session id, index, timestamp, text)
      hermes sessions export prompts.jsonl --session-id 20250305_091523_a1b2c3d4 --only user-prompts

      # Markdown, straight to stdout
      hermes sessions export - --session-id 20250305_091523_a1b2c3d4 --only user-prompts --format md

      يعمل مع --format jsonl (الافتراضي) أو md، ويحترم نفس فلاتر التصدير الحجمي، ويتضافر مع --redact.

      التتبعات (HF Agent Trace Viewer)​

      --format trace يُصدر Claude Code JSONL — شكل النسخة النصية الذي يكتشفه Hugging Face Hub تلقائيًا لـ Agent Trace Viewer الخاص به. اكتبها محليًا، أو أضف --upload لرفعها إلى مجموعة بياناتك الخاصة الخاصة hermes-traces (تقرأ HF_TOKEN):

      # Trace of the most recent session, to stdout
      hermes sessions export --format trace

      # One session to a local trace file
      hermes sessions export --format trace --session-id 20250305_091523_a1b2c3d4 trace.jsonl

      # Upload straight to your private HF traces dataset
      hermes sessions export --format trace --session-id 20250305_091523_a1b2c3d4 --upload

      صادرات التتبع مُعتَّمة الأسرار افتراضيًا (فهي مُعدَّة لمغادرة الجهاز)؛ --no-redact يُلغي ذلك بعد مراجعة يدوية. --upload خاص ما لم يُستخدم --public. تصدير التتبع الحجمي مع الفلاتر يكتب ملف <id>.trace.jsonl واحدًا لكل جلسة.

      Markdown / QMD​

      مرّر --format md أو --format qmd عندما تريد أرشيفًا قابلًا للقراءة قائمًا على الملفات قبل إخفاء أو حذف الجلسات القديمة. تكتب صادرات Markdown/QMD ملفًا واحدًا لكل جلسة في دليل (الافتراضي: ~/.hermes/session-exports).

      # Export one session to Markdown
      hermes sessions export --format md --session-id 20250305_091523_a1b2c3d4

      # Export a compression lineage as one logical document
      hermes sessions export --format md --session-id 20250305_091523_a1b2c3d4 --lineage logical

      # Preview ended sessions older than 90 days without writing files
      hermes sessions export --format md --older-than 90 --dry-run

      # Export ended Telegram sessions older than 2 weeks to QMD files
      hermes sessions export --format qmd --older-than 2w --source telegram

      # Export long Claude sessions, secrets redacted
      hermes sessions export --format md --model sonnet --min-messages 50 --redact

      # Only after verification, export and delete one explicitly named session
      hermes sessions export --format md --session-id 20250305_091523_a1b2c3d4 --delete-after-verified --yes

      يكتب تصدير Markdown/QMD ملف .md أو .qmd واحدًا لكل جلسة مُصدَّرة بالإضافة إلى manifest.jsonl بمسار الملف، وعدد الرسائل، ومعرّفات النسب، وSHA-256. يتطلب التصدير الحجمي فلترًا واحدًا على الأقل؛ يُرفَض التصدير الحجمي المجرَّد. --delete-after-verified مقصور عمدًا على --session-id ويتطلب --yes. نظرًا لأن حذف جلسة أصل يزيل أيضًا جلسات المفوَّض/subagent الخاصة بها، يُصدِّر هذا الوضع ويتحقق من كل مفوَّض في ملف منفصل قبل حذف أي شيء. إذا تغيّرت مجموعة المفوَّضين أثناء التصدير، يُرفَض الحذف. --redact يزيل الأسرار (مفاتيح API، الـ tokens، بيانات الاعتماد) من محتوى الرسائل ومخرجات الأدوات قبل الكتابة — موصى به لأي تصدير تنوي مشاركته.

      حذف جلسة​

      # Delete a specific session (with confirmation)
      hermes sessions delete 20250305_091523_a1b2c3d4

      # Delete without confirmation
      hermes sessions delete 20250305_091523_a1b2c3d4 --yes

      # Set or change a session's title
      hermes sessions rename 20250305_091523_a1b2c3d4 "debugging auth flow"

      # Multi-word titles don't need quotes in the CLI
      hermes sessions rename 20250305_091523_a1b2c3d4 debugging auth flow

      إذا كان العنوان مستخدمًا بالفعل لجلسة أخرى، يظهر خطأ.

      تثبيت جلسة​

      يضبط التثبيت علامة "احتفاظ" دائمة: الجلسات المثبَّتة معفاة من اكتساح sessions.auto_archive للجلسات الراكدة وتظهر دائمًا في القوائم. إنها نفس العلامة التي يستخدمها قسم Pinned في الشريط الجانبي لـ Desktop — ثبّت من أي واجهة ويراها كلاهما.

      # Pin one or more sessions (unique ID prefixes work)
      hermes sessions pin 20250305_091523_a1b2c3d4
      hermes sessions pin 20250305 20250306

      # Remove the pin
      hermes sessions unpin 20250305_091523_a1b2c3d4

      # List pinned sessions
      hermes sessions pinned

      # Machine-readable output, e.g. for a nightly backup of your pin set
      hermes sessions pinned --json > pinned-sessions.json

      تقليم الجلسات القديمة​

      # Delete ended sessions inactive for 90 days (default)
      hermes sessions prune

      # Custom age threshold — bare numbers are days
      hermes sessions prune --older-than 30

      # Durations work too: 5h, 30m, 2d, 1w
      hermes sessions prune --older-than 12h

      # Delete only a specific time window (e.g. a batch of test sessions
      # created in the last 5 hours)
      hermes sessions prune --newer-than 5h

      # Explicit window with absolute timestamps
      hermes sessions prune --after "2026-07-05 09:00" --before "2026-07-05 14:30"

      # Only prune sessions from a specific platform (all ages — any filter
      # disables the implicit 90-day default)
      hermes sessions prune --source telegram
      hermes sessions prune --source cron --older-than 60   # add a time flag to narrow

      # More filters — all AND together
      hermes sessions prune --newer-than 5h --title "smoke test"   # title substring
      hermes sessions prune --older-than 30 --max-messages 3        # tiny sessions
      hermes sessions prune --cwd ~/scratch --end-reason done       # by cwd / end reason
      hermes sessions prune --model gpt-5 --older-than 1w           # by model (substring)
      hermes sessions prune --provider openrouter --older-than 60   # by billing provider
      hermes sessions prune --branch feature/old-experiment         # by git branch
      hermes sessions prune --user 12345678 --chat-type group       # by messaging origin
      hermes sessions prune --max-tokens 500 --older-than 7         # by token usage
      hermes sessions prune --max-cost 0.01 --max-tool-calls 0      # cheap, tool-less runs

      # Preview what would be deleted, without deleting anything
      hermes sessions prune --newer-than 5h --dry-run

      # Skip confirmation
      hermes sessions prune --older-than 30 --yes

      تقبل قيم الوقت (--older-than، --newer-than، --before، --after) مدة (5h، 30m، 2d، 1w)، أو عدد أيام مجرَّدًا، أو طابعًا زمنيًا بصيغة ISO (2026-07-05، 2026-07-05 14:30). --older-than/--before يضبطان الحد الأعلى؛ --newer-than/--after يضبطان الحد الأدنى. يستخدم زوج --older-than/--newer-than آخر نشاط للرسائل (يعود إلى بدء الجلسة للجلسات الفارغة)؛ يستخدم --before/--after صراحةً وقت بدء الجلسة. اجمع بين أي زوج للحصول على نافذة زمنية.

      فلاتر الخصائص: --source (المنصة، مطابقة دقيقة)، --title / --model / --branch (سلسلة فرعية غير حساسة لحالة الأحرف)، --provider (مزوّد الفوترة، مطابقة دقيقة)، --end-reason، --user، --chat-id، --chat-type (مطابقة دقيقة)، --cwd (بادئة مسار)، بالإضافة إلى الحدود العددية --min/--max-messages، --min/--max-tokens (الدخل+الخرج)، و--min/--max-cost (بالدولار، الفعلي وإلا المقدَّر)، و--min/--max-tool-calls. استخدام أي فلتر يُعطِّل الافتراضي الضمني البالغ 90 يومًا، لذا فإن hermes sessions prune --source cron أو --model gpt-4o يطابق كل الأعمار — أضف علامة زمنية لتضييق النطاق. فقط hermes sessions prune المجردة تمامًا تحافظ على حد القطع البالغ 90 يومًا. كل تشغيل بلا --yes يعرض عدد المطابقات مع أقدم وأحدث جلسة مطابقة قبل طلب التأكيد.

      تُتخطَّى الجلسات المؤرشفة افتراضيًا؛ مرّر --include-archived لحذفها أيضًا.

      معلومة

      يحذف التقليم فقط الجلسات المنتهية (الجلسات التي أُنهيت صراحةً أو أُعيد ضبطها تلقائيًا). لا تُقلَّم الجلسات النشطة أبدًا.

      أرشفة الجلسات بالجملة​

      إذا أردت إبعاد الجلسات عن قوائمك دون حذف أي شيء، يأخذ hermes sessions archive نفس فلاتر prune لكنه يُخفي الجلسات المطابقة بنعومة بدلًا من ذلك (يضبط نفس علامة الأرشفة التي تضبطها أرشفة جلسة واحدة من واجهة Desktop/Dashboard — تبقى الرسائل والبحث سليمين):

      # Archive everything from the last 5 hours (e.g. 75 CI smoke-test sessions)
      hermes sessions archive --newer-than 5h

      # Archive by title substring, preview first
      hermes sessions archive --title "dry run" --dry-run
      hermes sessions archive --title "dry run" --yes

      إصلاح جلسات gateway العالقة​

      إذا "قفزت محادثة gateway إلى الوراء في الزمن" بعد إعادة تشغيل — فاستأنفت موضوعًا عمره أيام كما لو أن الرسائل الأخيرة لم تحدث أبدًا — فقد تكون المحادثة الحية عالقة في صف جلسة فقد هويته التوجيهية (فئة التلف التي أُصلحت في عمل استمرارية الجلسة لإصدار v0.21؛ الإصدارات الحالية تمنعها من حيث البناء وتُشفى ذاتيًا وقت التشغيل).

      يجد hermes sessions repair-routing صفوف الجلسات الحاملة للرسائل دون هوية توجيهية ويُعيد ربط كل واحدة بالمحادثة التي تكمّلها — لكن فقط عندما تكون الأدلة قاطعة:

      # Report only — shows each orphan, the proposed adoption, and the evidence
      hermes sessions repair-routing

      # Perform the adoptions (stop the gateway first — a running gateway holds
      # the old routing in memory and would write it back over the repair)
      hermes sessions repair-routing --apply

      # Widen/narrow the contiguity window (default 900 seconds)
      hermes sessions repair-routing --max-gap-seconds 300

      قواعد الأدلة:

      • النسب (lineage) — يشير parent_session_id الخاص باليتيمة إلى صف مُفهرَس من نفس المنصة (حقيقة مُسجَّلة؛ لا تُطبَّق نافذة زمنية)
      • التجاور (contiguity) — صف مُفهرَس واحد بالضبط من نفس المنصة سكت ضمن نافذة بدء اليتيمة

      أي شيء غامض (مرشحان لسابقة، أو يتيمان يدّعيان نفس السابقة) يُبلَّغ عنه مع سبب ويُترك دون تغيير — فقد يؤدي تبنٍّ خاطئ إلى دمج محادثة في محادثة أخرى. يُقاعَد الصف المُستبدَل تحت superseded_by_repair، بحيث لا يمكن لاستعادة إعادة التشغيل إحياءه أبدًا.

      الإصلاح ليس تلقائيًا عمدًا: إذا كانت المحادثة قد بنت منذ ذلك الحين تاريخًا ثانيًا، فاختيار الخيط الذي تكمّله قرارك أنت. تظل المحادثة العالقة قابلة للقراءة عبر /resume وبحث الجلسات في كلتا الحالتين — التوجيه هو الشيء الوحيد الذي يغيّره الإصلاح. اعمل نسخة احتياطية أولًا (cp ~/.hermes/state.db ~/.hermes/state.db.bak).

      استيراد الجلسات من Claude Code وCodex CLI​

      بدأت محادثة في CLI وكيل آخر؟ يمكنك سحبها إلى Hermes ومتابعتها هنا. يقرأ Hermes سجلات جلسات Claude Code (~/.claude/projects/، أو $CLAUDE_CONFIG_DIR/projects/ عندما يكون دليل إعدادات Claude Code منقولًا) وrollouts الخاصة بـ Codex CLI (~/.codex/sessions/، أو $CODEX_HOME/sessions/) — تُقرأ الملفات الأجنبية فقط، ولا تُعدَّل أبدًا.

      # Interactive picker across both tools, newest first
      hermes sessions import

      # Limit to one tool, or point at a specific file
      hermes sessions import --from claude
      hermes sessions import --from codex ~/.codex/sessions/2026/08/15/rollout-....jsonl

      # Import-and-resume in one step
      hermes --resume @claude
      hermes --resume @codex

      ينشئ hermes sessions import جلسة Hermes جديدة معنونة Imported from Claude Code: <first user message> (أو Codex CLI) ويطبع المعرّف بالإضافة إلى أمر hermes --resume <id> جاهز للصق. تعرض --resume @claude / --resume @codex نفس المُنتقي وتضعك مباشرة في المحادثة المستوردة.

      Hermes Desktop يملك نفس أداة الاستيراد في لوحة الأوامر (Import session). تعرض السجلات على الجهاز الذي يعمل عليه الـ backend المتصل — وليس الحاسوب الذي يشغّل التطبيق — وتُظهر معاينة للقراءة فقط، وContinue in Hermes ينسخ المحادثة إلى profile المحدَّد. التصفح لا يكتب أبدًا إلى مخزن جلساتك، والاستيراد لا يمسّ الملف المصدر أبدًا، واستيراد نفس السجل مرتين يفتح النسخة الموجودة بدلًا من إنشاء نسخة أخرى.

      ما الذي يُنقَل: محادثة المستخدم/المساعد المرتَّبة، مع تكثيف نشاط الأدوات إلى ملاحظات [ran tool: …] قصيرة داخل أدوار المساعد. تُترَك system prompts، والسياق المحقون، وآثار الاستدلال، ومخرجات الأدوات الخام خلفًا — الاستيراد نسخة نصية نظيفة، وليس إعادة تشغيل حرفية بايتًا بايت.

      أداة البحث في الجلسات​

      يملك الوكيل أداة session_search مدمجة تُنفِّذ بحثًا نصيًا كاملًا عبر كل المحادثات السابقة باستخدام محرك FTS5 في SQLite — وتتيح للوكيل التمرير عبر أي جلسة يجدها. لا تُجري أي استدعاءات LLM وتُعيد عروضًا لرسائل فعلية من قاعدة البيانات بدلًا من توليد ملخصات.

      أربعة أشكال استدعاء​

      تستدل الأداة على ما تريده من الوسائط التي تضبطها. لا يوجد وسيط mode.

      1. الاكتشاف — مرّر query:

      session_search(query="auth refactor", limit=3)

      يُشغِّل FTS5، ويزيل التكرار حسب نسب الجلسة، ويُعيد أفضل N جلسة. يستخدم الاكتشاف تفصيلًا تكيّفيًا افتراضيًا: تتضمن أعلى النتائج تصنيفًا نافذة سياقها الكاملة وأطرافها، بينما تبقى النتائج الأدنى تصنيفًا مُضغَّطة. مرّر detail="full" لتفصيل كل نتيجة بالكامل.

      تحمل كل نتيجة:

      • session_id، title، when، source
      • snippet — مقتطف مطابقة مُبرَز بواسطة FTS5
      • detail — full أو compact
      • bookend_start / bookend_end — أول/آخر 3 رسائل مستخدم+مساعد للنتائج الكاملة؛ قوائم فارغة للنتائج المُضغَّطة
      • messages — ±5 رسائل حول مطابقة FTS5 للنتائج الكاملة؛ رسالة الأنكر (anchor) المُعلَّمة فقط للنتائج المُضغَّطة
      • match_message_id، messages_before، messages_after

      تُعيد النتيجة الأولى بناء الهدف ← المطابقة ← الحل فورًا. إذا بدت نتيجة مُضغَّطة أخرى أكثر وعدًا، استخدم معرّفي جلستها ورسالتها مع شكل التمرير. الزمن الفعلي المعتاد عشرات المللي ثوانٍ على قاعدة بيانات جلسة حقيقية.

      2. التمرير — مرّر session_id + around_message_id:

      session_search(session_id="20260510_174648_805cc2", around_message_id=590803, window=10)

      يُعيد نافذة من ±window رسالة تتمحور حول الأنكر. لا FTS5، لا أطراف — فقط الشريحة. استخدمه بعد استدعاء اكتشاف عندما تحتاج سياقًا أكثر من النافذة الافتراضية ±5.

      • للتمرير للأمام: مرّر messages[-1].id مرة أخرى كـ around_message_id
      • للتمرير للخلف: مرّر messages[0].id مرة أخرى كـ around_message_id
      • تظهر رسالة الحد في كلتا النافذتين كعلامة توجيه
      • عندما تكون messages_before أو messages_after أقل من window، فأنت عند بداية أو نهاية الجلسة

      الزمن الفعلي المعتاد: 1-2 مللي ثانية لكل استدعاء تمرير.

      3. القراءة — مرّر session_id دون أنكر:

      session_search(session_id="20260510_174648_805cc2")

      يُعيد الجلسة كاملة، أو عرض بداية/نهاية محدود للجلسات الضخمة. يُستخدم هذا الشكل أيضًا لحل رابط @session:<profile>/<id>.

      4. التصفح — بلا وسائط:

      session_search()

      يُعيد الجلسات الأخيرة زمنيًا (العناوين، المعاينات، الطوابع الزمنية). مفيد عندما يسأل المستخدم "على ماذا كنت أعمل" دون تسمية موضوع.

      صياغة استعلام FTS5​

      يدعم وضع الكلمات المفتاحية صياغة استعلام FTS5 القياسية:

      • كلمات مفتاحية بسيطة: docker deployment (يفترض FTS5 AND افتراضيًا)
      • عبارات: "exact phrase"
      • بوليانية: docker OR kubernetes، python NOT java
      • بادئة: deploy*

      وسائط اختيارية​

      • sort — newest أو oldest، فوق ترتيب FTS5. احذفه للترتيب حسب الصلة فقط (الافتراضي؛ مناسب للاستدعاء الاستكشافي). استخدم newest لأسئلة "أين تركنا X"، وoldest لأسئلة "كيف بدأ X".
      • detail — adaptive (الافتراضي) يُفصِّل فقط أعلى نتيجة اكتشاف بالكامل؛ full يُفصِّل كل نتيجة اكتشاف.
      • role_filter — أدوار مفصولة بفواصل لتضمينها. يفترض الاكتشاف user,assistant افتراضيًا (مخرجات الأدوات عادةً ضجيج). مرّر user,assistant,tool لتضمين مخرجات الأدوات (لتصحيح سلوك الأدوات) أو tool للبحث في مخرجات الأدوات فقط.

      متى تُستخدم​

      يُوجَّه الوكيل لاستخدام بحث الجلسات تلقائيًا:

      "عندما يشير المستخدم إلى شيء من محادثة سابقة أو تشتبه في وجود سياق سابق ذي صلة، استخدم session_search لاسترجاعه قبل أن تطلب منه التكرار."

      المحفّزات النموذجية: "فعلنا هذا من قبل"، "تذكّر عندما"، "في المرة الماضية"، "كما ذكرت"، أو أي إشارة إلى مشروع/شخص/مفهوم ليس في النافذة الحالية.

      افتراضيًا، يستخدم Hermes group_sessions_per_user: true في config.yaml. هذا يعني:

      • يمكن لأليس وبوب التحدث كلاهما مع Hermes في نفس قناة Discord دون مشاركة سجل النسخة النصية
      • مهمة ثقيلة بالأدوات لمستخدم واحد لا تلوّث نافذة سياق مستخدم آخر
      • تبقى معالجة المقاطعة أيضًا لكل مستخدم لأن مفتاح الوكيل الجاري يطابق مفتاح الجلسة المعزولة

      إذا أردت "عقل غرفة" واحدًا مشتركًا بدلًا من ذلك، اضبط:

      group_sessions_per_user: false

      يُعيد ذلك المجموعات/القنوات إلى جلسة مشتركة واحدة لكل غرفة، مما يحافظ على السياق المحادثي المشترك لكن يشارك أيضًا تكاليف الـ tokens، وحالة المقاطعة، ونمو السياق.

      استمرارية الجلسة​

      لا تُعاد ضبط محادثات gateway بعد الخمول أو عند حد يومي. استخدم /new أو /reset لمحادثة جديدة صريحة؛ يبقى ضغط السياق تلقائيًا. تُتجاهَل إعدادات session_reset القديمة، وتجاوزات سياسة إعادة الضبط، ومتغيرات بيئة مؤقت إعادة الضبط. يمكن تحرير الوكلاء المُخزَّنين مؤقتًا لاستعادة الموارد دون استبدال المحادثة الدائمة. تحدّ حدود نضارة استعادة إعادة التشغيل من الاستمرار التلقائي، لا السجل المُحمَّل عندما ترسل رسالة.

      نظافة الجلسة: لماذا لا يزال ينبغي عليك تشغيل /new​

      لأن محادثات gateway لا تنتهي صلاحيتها من تلقاء نفسها أبدًا، من السهل تشغيل جلسة واحدة لأسابيع. هذا يعمل، لكنه يُبطل بصمت حلقة التعلّم ويُضخِّم التكاليف:

      • الذاكرة لا تُجدي إلا عند الحدود. تُحقَن MEMORY.md / USER.md عند بدء الجلسة، وتوجد session_search لاسترجاع ما سقط من السياق. في جلسة لا تنتهي أبدًا يبقى كل شيء داخل السياق، لذا لا سبب للوكيل لاستشارة الذاكرة — آلية "التعلّم الذاتي" بالكاد تعمل. تقطير الذاكرة (الحفظ قبل إعادة الضبط) لا يحدث أيضًا إلا عندما تنتهي جلسة فعلًا.
      • تنمو التكلفة مع السجل. يبقي الضغط جلسة طويلة عاملة، لكن كل دور لا يزال يحمل بادئة (مضغوطة) كبيرة. جلسة جديدة بذاكرة مُقطَّرة أرخص دائمًا تقريبًا من خيط عمره شهر.

      قاعدة عملية: أنهِ جلسة عندما تنهي مهمة أو موضوعًا. شغّل /new (مُسمّاة اختياريًا، مثل /new payments-refactor) عند نقاط التوقف الطبيعية — يومية أو لكل مشروع كلاهما يعمل. قبل إعادة الضبط، اطلب من الوكيل "تذكّر أي شيء يستحق الاحتفاظ به" إذا أظهر العمل تفضيلات أو إجراءات دائمة؛ يحفظ الوكيل الذاكرة والمهارات من الجلسة المنتهية تلقائيًا، لكن التنبيه الصريح يساعد. إعادة تشغيل الجهاز أو الـ gateway ليست حدًا — تُستأنف نفس الجلسة.

      راجع الذاكرة لمعرفة ما الذي يُنقَل عبر الحدود.

      الاستمرارية بعد الأعطال وإعادة التشغيل​

      مُصمَّمة محادثة gateway لتكون جلسة مستمرة واحدة — تُضغَط مرارًا مع نموّها — حتى تشغّل صراحةً /new (أو /reset). يصمد هذا عبر أعطال gateway وإعادة تشغيله وتحديثاته:

      • تُكتَب هوية الجلسة (مفتاح التوجيه، المحادثة، الأصل) ذريًا عند إنشاء صف الجلسة، في كل مسار إنشاء (/new، الرسالة الأولى، أبناء /branch). إذا فشلت هذه الكتابة يومًا، فإن تحديث التوجيه في الدور التالي مباشرة يُصلح الصف تلقائيًا.
      • بعد إعادة التشغيل، يُعيد الـ gateway حل كل محادثة إلى الجلسة ذات أحدث نشاط فعلي — لا يمكن أبدًا لصف قديم راكد أن يفوز على المحادثة التي كنت تجريها فعلًا.
      • تحترم الاستعادة حدود /new: إذا كان أحدث حدث لمحادثة هو إعادة ضبط مقصودة، تبدأ الاستعادة من جديد بدلًا من التمدد خلف إعادة الضبط لإحياء جلسة أقدم. لا يمنع الوقت المنقضي وحده أبدًا استعادة محادثة دائمة.

      مخطط قاعدة البيانات​

      الجداول الرئيسية في state.db:

      • sessions — البيانات الوصفية للجلسة (id، source، user_id، model، title، الطوابع الزمنية، عدد الـ tokens). للعناوين فهرس فريد (تُسمح القيم NULL، فقط غير NULL يجب أن تكون فريدة).
      • messages — سجل الرسائل الكامل (role، content، tool_calls، tool_name، token_count)
      • messages_fts — جدول افتراضي FTS5 للبحث النصي الكامل عبر محتوى الرسائل

      انتهاء صلاحية الجلسات وتنظيفها​

      التنظيف التلقائي​

      • تستمر محادثات gateway عبر الخمول؛ استخدم /new أو /reset لحد صريح
      • قبل إعادة الضبط، يحفظ الوكيل الذاكرة والمهارات من الجلسة المنتهية
      • التقليم التلقائي (مفعَّل افتراضيًا منذ #54189): عندما تكون sessions.auto_prune بقيمة true، تُقلَّم الجلسات المنتهية الخاملة لمدة sessions.retention_days (الافتراضي 90) عند إقلاع CLI/gateway/cron
      • بعد تقليم أزال صفوفًا فعلًا، تخضع state.db لعملية VACUUM لاستعادة مساحة القرص فقط عندما يُجتاز كلا الشرطين: مرور sessions.min_vacuum_interval_days (الافتراضي 30) على الأقل منذ آخر VACUUM ناجح، وكون أكثر من 25% من صفحات الملف قابلة للاستعادة (PRAGMA freelist_count / page_count). قاعدة بيانات كثيفة لا تدفع أبدًا ثمن إعادة كتابة كاملة لاستعادة بضعة ميغابايتات (لا يُقلِّص SQLite الملف عند DELETE عادي)
      • يعمل التقليم مرة واحدة على الأكثر كل sessions.min_interval_hours (الافتراضي 24)؛ يُتَتبَّع طابع زمن آخر تشغيل داخل state.db نفسه بحيث يُشارَك عبر كل عملية Hermes في نفس HERMES_HOME

      دون تقليم، ينمو state.db بلا حدود — أُبلغ عن ملفات بحجم عدة غيغابايتات خلال أسابيع على تثبيتات gateway وcron. إذا فضّلت الاحتفاظ بكل جلسة منتهية إلى الأبد (السلوك قبل #54189)، عطِّله في ~/.hermes/config.yaml:

      sessions:
        auto_prune: false         # default is true — set false to keep all history
        retention_days: 90        # keep ended sessions active within this window
        vacuum_after_prune: true  # reclaim disk space after a pruning sweep
        min_vacuum_interval_days: 30 # don't rewrite the DB more often than this
        min_interval_hours: 24    # don't re-run the sweep more often than this

      التثبيتات الموجودة التي ضبطت بالفعل أيًا من هذه المفاتيح صراحةً تحتفظ بقيمها؛ فقط المفاتيح غير المضبوطة تأخذ الإعدادات الافتراضية الجديدة.

      فقط الجلسات المنتهية تُحذَف على الإطلاق. لا تُقلَّم الجلسات النشطة تلقائيًا أبدًا، بغضّ النظر عن العمر. تُحسَب أعمار الجلسات المنتهية من آخر رسالة فيها، لذا لا تُحذَف محادثة طويلة الأمد استُخدمت مؤخرًا لمجرد أنها بدأت قبل نافذة الاحتفاظ.

      جلسات مفتوحة راكدة من الأتمتة. بعض المُنتِجين — مهام cron، عمّال kanban، subagents، تشغيلات CLI لمرة واحدة — يمكن أن يموتوا دون وسم جلستهم أبدًا كمنتهية، والتقليم لا يحذف إلا الصفوف المنتهية. لمنع تراكم تلك إلى الأبد، تُغلق كل مرحلة تقليم تلقائي أيضًا الجلسات المفتوحة من تلك المصادر المملوكة للحالة (cli، cron، kanban، acp، api_server، subagent، tool) التي يكون آخر نشاط لها أقدم من retention_days (end_reason: startup_orphan_reap). الإغلاق غير مدمِّر — تظل الجلسة قابلة للاستئناف — ويُحسَب عمر الصف من إغلاقه، لذا لا يُحذَف إلا في مرحلة لاحقة بعد نافذة احتفاظ كاملة أخرى. جلسات منصات المراسلة (Telegram، Discord، …)، وجلسات TUI/Desktop، والجلسات المثبَّتة، والجلسات ذات دور حي أو ضغط جارٍ لا يُغلقها هذا الاكتساح أبدًا.

      حراسة النسخ النصية الضخمة الحجم​

      حدّان يمنعان تحميل نسخة نصية جامحة إلى الذاكرة دفعة واحدة (كلاهما افتراضيًا 20000 رسالة نشطة؛ 0 يعطّل الحارس):

      sessions:
        max_resume_messages: 20000   # interactive resume (CLI / TUI / Desktop)
        max_export_messages: 20000   # one-shot in-memory export of a single session

      max_resume_messages يحدّد ما يُحمِّله الاستئناف فعليًا، وليس كامل تاريخ المحادثة:

      • يُجسِّد الاستئناف التفاعلي البسيط (CLI --resume، TUI) نسب الضغط الكامل — كل مقطع مضغوط بالإضافة إلى الطرف الحي — لذا فهو محدود عبر النسب.
      • يُصفِّح استئناف Desktop البارد النسخة النصية عبر REST ولا يحتفظ في الذاكرة إلا بمقطع الطرف الحي، لذا فهو محدود بالطرف وحده. محادثة طويلة العمر ضُغطت مرات عديدة (عشرات المقاطع، عشرات آلاف الصفوف المؤرشفة خلف طرف صغير) هي بالضبط ما يُقصد به الضغط أن يُنتج، وتُفتح عاديًا؛ يعكس عدد رسائل تذييلها النسب المُخزَّن، لا الـ prompt الحي.

      عندما يُرفَض استئناف، يتلقى العميل رمز الخطأ 4130 مع العدد والنطاق الذي قِيس فيه (across its lineage أو in its tip segment). لا يزال hermes sessions export يعمل لمثل هذه الجلسات.

      التنظيف اليدوي​

      # Prune sessions older than 90 days
      hermes sessions prune

      # Delete a specific session
      hermes sessions delete <session_id>

      # Export before pruning (backup)
      hermes sessions export backup.jsonl
      hermes sessions prune --older-than 30 --yes
      نصيحة

      التقليم التلقائي مفعَّل افتراضيًا: تُزال الجلسات المنتهية الخاملة لمدة sessions.retention_days (الافتراضي 90) عند الإقلاع، ولا تُمس الجلسات النشطة أبدًا (راجع التنظيف التلقائي أعلاه). يُغذّي سجل الجلسات استرجاع session_search عبر المحادثات السابقة، لذا إذا أردت الاحتفاظ بكل جلسة منتهية إلى الأبد، اضبط sessions.auto_prune: false في config.yaml، أو ارفع retention_days. مع تعطيل التقليم التلقائي، يبقى hermes sessions prune متاحًا للتنظيف لمرة واحدة (نمط فشل مُلاحَظ دون أي تقليم: state.db بحجم 384 ميغابايت مع نحو 1000 جلسة يُبطئ إدراجات FTS5 وقوائم /resume).
