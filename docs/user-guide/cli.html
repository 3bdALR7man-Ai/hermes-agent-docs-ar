      واجهة CLI

      واجهة CLI في Hermes Agent هي واجهة مستخدم طرفية (TUI) كاملة — وليست واجهة ويب. تتميز بالتحرير متعدد الأسطر، والإكمال التلقائي لـ slash commands، وسجل المحادثات، وإمكانية المقاطعة وإعادة التوجيه، وبث مخرجات الأدوات مباشرةً (streaming). صُممت لمن يقضون معظم وقتهم في الطرفية.

      الإعداد لأول مرة

      أمر واحد — hermes setup --portal — وتصبح جاهزًا لتشغيل hermes chat. راجع Nous Portal.

      نصيحة

      يأتي Hermes أيضًا مع TUI حديثة تتضمن نوافذ منبثقة (modal overlays)، والتحديد بالفأرة، وإدخالًا غير حاجب (non-blocking). شغّلها باستخدام hermes --tui — راجع دليل TUI.

      تشغيل CLI​

      # Start an interactive session (default)
      hermes

      # Single query mode (non-interactive)
      hermes chat -q "Hello"

      # Single query from a file or stdin — nothing is shell-interpreted, so
      # arbitrary text (quotes, $(...), backticks) arrives verbatim
      hermes chat --query-file prompt.txt
      hermes chat --query-file - < prompt.txt

      # With a specific model
      hermes chat --model "anthropic/claude-sonnet-4"

      # With a specific provider
      hermes chat --provider nous        # Use Nous Portal
      hermes chat --provider openrouter  # Force OpenRouter

      # With specific toolsets
      hermes chat --toolsets "web,terminal,skills"

      # Start with one or more skills preloaded (rendered once into the session's prompt)
      hermes chat -s hermes-agent-dev,github-auth

      # Resume previous sessions
      hermes --resume <session_id>  # Resume a specific session by ID (-r)
      hermes --resume "my thread"   # Resume by title (latest "#N" continuation in the lineage)
      hermes -c "my thread" --create-if-missing  # Resume that titled session, creating it if absent
      hermes --continue             # Resume the most recent session (bare -c)
      hermes --resume latest        # Same as bare -c
      hermes --resume latest --in ./dir  # Resume ./dir's latest session, staying in ./dir

      # Verbose mode (debug output)
      hermes chat --verbose

      # Isolated git worktree (for running multiple agents in parallel)
      hermes -w                         # Interactive mode in worktree
      hermes -w -z "Fix issue #123"     # Single query in worktree

      تنظيف Worktrees​

      تنشئ جلسات hermes -w أشجار عمل (worktrees) مؤقتة تحت <repo>/.worktrees/. عند استخدام hermes --tui -w، يؤدي إغلاق الطرفية إلى فصل الاتصال عن الجلسة التي يملكها الـ gateway. وتُزال الشجرة النظيفة مع branch الخاص بها عند الخروج ما لم يكن هناك ما يزال يحتاج إليها. وتُحتفَظ بها عندما تحتوي على تغييرات غير مُثبَّتة بـ commit أو commits غير مدفوعة، أو عندما يكون لدى الـ gateway دور في قائمة الانتظار أو قيد التشغيل هناك، أو عندما يكون لجلسة فيها /loop أو /heartbeat أو /goal نشط، أو عندما تعمل فيها مهمة cron مفعّلة أو تكون مرتبطة بجلسة كهذه، أو عندما يظل عارض آخر (نافذة Desktop مثلًا) ممسكًا بتلك الجلسة. يستخدم استئناف الجلسة مجلد العمل الخاص بها: فإذا أزال الخروج الـ worktree، فإن hermes --tui --resume <id> و hermes --tui -c و hermes --resume/-c الكلاسيكي تعيد إنشاءها في المسار نفسه قبل الاتصال (على branch الخاص بها إن كان ما زال موجودًا، وإلا على branch جديد بالاسم نفسه انطلاقًا من HEAD الحالي للمستودع). ولا يُعاد إنشاء إلا الـ worktrees التي أنشأها hermes --tui -w نفسه. يقرأ فحص وقت الخروج مخزن الجلسات ثم يزيل الشجرة؛ أما العارض الذي يتصل ويرسل في اللحظة الواقعة بين الخطوتين فلا يُرصد، لذا قد يجد ذلك الدور أن مجلده اختفى. يعمل تنظيف (sweep) تلقائيًا عند بدء hermes -w وكل 6 ساعات من مؤقّت cron: تُزال الأشجار الخاملة النظيفة والمدموجة، أما الأشجار الخاملة التي تحتوي على تغييرات غير مُثبَّتة بـ commit أو commits غير مدفوعة فـتُؤرشَف ثم تُزال (ويمكن استعادتها عبر hermes worktree restore <name>؛ راجع Stale worktree sweep). لاستعادة المساحة أو الفحص صراحةً:

      hermes worktree list              # audit: age, size, verdict, reason per tree + archives
      hermes worktree list --json       # machine-readable audit (trees, external trees, branches, archives)
      hermes worktree prune             # run the sweep now + delete merged branches
      hermes worktree prune --dry-run   # print every archive/remove/skip decision and why; changes nothing
      hermes worktree restore <name>    # recreate an archived tree (add --path DIR to put it elsewhere)
      hermes worktree prune --older-than 7   # only reap trees idle for 7+ days
      hermes worktree prune --trees-only     # leave local branches alone
      hermes worktree prune --branches-only  # leave worktrees alone

      تُبلَّغ الـ worktrees المسجّلة خارج .worktrees/ (التي أُنشئت يدويًا أو بأداة أخرى) للقراءة فقط في مخرجات list ولا تُزال أبدًا. والاستثناء الوحيد هو البيانات الوصفية: تُسقَط التسجيلات التي لم يعد مجلدها موجودًا عبر git worktree prune (دون المساس بأي ملفات). لا يفعل --older-than DAYS سوى تضييق ما يُحصَد، بما في ذلك ما يؤرشفه تنظيف الـ worktrees القديمة ويزيله أثناء ذلك التشغيل: فالشجرة الخاملة لمدة أقل من DAYS لا تُمَسّ أبدًا.

      داخل الجلسة، يؤدي /worktree prune [--dry-run] المهمة نفسها (ولا يمس أبدًا الشجرة التي تعمل فيها الجلسة).

      ضمانات الأمان (في جميع الأوضاع، وأيًّا كان العمر):

      • لا تُحذف التغييرات غير المُثبَّتة بـ commit ولا الـ commits الفريدة غير المدفوعة أبدًا دون أرشيف قابل للاستعادة (refs/hermes/archive/<tree>)؛ ومع worktrees.archive_dirty: false لا تُحذف إطلاقًا — وتُكتشَف الـ commits التي دُمجت في المصدر الأصلي عبر rebase/squash بواسطة git cherry وتكافؤ الـ patches، وتُعدّ مدمجة، وهذا ما يتيح أخيرًا استعادة المساحة المتسرّبة في الحالة الشائعة "PR مدموج لكن الشجرة محفوظة إلى الأبد".
      • المستودعات التي لا تملك remote تُقيَّم مقارنةً بالـ trunk المحلي (main/master، وإلا فالـ branch المسحوب في worktree الرئيسية): لا تُستعاد إلا الأشجار والـ branches التي يمكن الوصول إلى commits الخاصة بها من ذلك trunk أو التي تتكافأ patches الخاصة بها معه. دون trunk للمقارنة، تُحفَظ كل شجرة و branch.
      • مسارات الـ PR المفتوحة المدفوعة تحرر مساحتها على القرص دون فقدان أي شيء: عندما يطابق رأس الـ branch في شجرة نظيفة تمامًا ما يحتفظ به origin (ويُتحقق من ذلك باستدعاء واحد لـ git ls-remote في كل عملية مسح)، تصبح النسخة المسحوبة زائدة عن الحاجة — فتُزال الشجرة لكن يُحتفظ بمرجع الـ branch، وبذلك يكفي أمر واحد هو git worktree add .worktrees/<name> <branch> لاستعادة المسار. وإذا تعذّر الوصول إلى الـ remote، تُحفظ الشجرة.
      • لا تُمَسّ الأشجار قيد الاستخدام أبدًا: أي قفل جلسة hermes قيد التشغيل، أو أي عملية حيّة يقع مجلد عملها (أو، على Linux، ملف مفتوح) داخل الشجرة. وتُفحص كل شجرة مرة أخرى قبل أرشفتها أو إزالتها مباشرةً، ومرة أخرى بعد بناء أرشيفها؛ وتُبقى الشجرة التي تغيّرت في الأثناء.
      • الملفات المؤقتة غير المتتبَّعة فقط (مسودات نص الـ PR، والملاحظات) تُؤرشف في ~/.hermes/archive/worktree-prune/ قبل إزالة شجرتها — ولا تُتلف أبدًا.
      • لا يُحذف أي شيء لا يمكن إعادة إنتاجه دون أرشفة: تُبقى الشجرة عندما تحتوي على مستودع مضمَّن (حتى لو كان مُدرجًا في gitignore)، أو commit لا يصل إليه سوى ref خاص بكل worktree (refs/worktree/* و refs/bisect/*)، أو ملف غير متتبَّع يتجاوز الحد الأقصى لحجم الأرشيف. أما الملفات المتجاهَلة (نسخ .env وcaches ومخرجات البناء) فلا تُؤرشَف وتُحذف مع الشجرة؛ ومستودع git متداخل داخل مجلد متجاهَل يُبقي الشجرة. راجع الملفات المتجاهَلة.
      • يعتمد حذف الـ branches على المحتوى لا على الاسم: فأي branch محلي تكون جميع الـ commits الخاصة به موجودة في upstream يمكن حذفه بأمان؛ أما الـ branches التي تحتوي على عمل فريد، والـ branches المسحوبة حاليًا، و main/master/develop فيُحتفظ بها دائمًا.

      يعمل التنظيف نفسه أيضًا من مُجدول cron (مرة واحدة على الأكثر كل 6 ساعات لكل profile، في الخلفية) على كل مستودع أنشأ الـ profile فيه worktree، لذا فإن الأجهزة التي تشغّل الـ gateway فقط — حيث لا يُطلق أحد hermes -w لأيام — لم تعد تراكم أشجارًا مؤقتة بين جلسات CLI.

      عندما يتجاوز .worktrees/ حد 10 أشجار أو 5 GB، يطبع Hermes عند بدء التشغيل إشعارًا من سطر واحد يشير إلى هذه الأوامر.

      إدارة الإضافات (Plugins)​

      تدير أوامر hermes plugins إضافات Hermes الأصلية وحزم Agent Plugins v1 المحمولة عبر سير العمل الاختياري (opt-in) نفسه:

      hermes plugins install owner/repository --no-enable
      hermes plugins list
      hermes plugins enable <plugin-name>
      hermes plugins disable <plugin-name>
      hermes plugins update <plugin-name>
      hermes plugins remove <plugin-name>

      تبقى الحزم المحمولة معطّلة حتى تُفعَّل صراحةً. يحمّل Hermes حاليًا مدخلات Agent Skills المحمولة ومدخلات MCP من نوع stdio. راجع دليل مطوّري الإضافات لمعرفة المجموعة الفرعية المدعومة بالتحديد وحدود الثقة.

      تخطيط الواجهة​

      واجهة CLI الكلاسيكية عميل للـ gateway

      لم يعد hermes chat (والـ prompt المجرّد hermes عندما تكون قيمة display.interface هي cli) يشغّل الوكيل داخل عملية الطرفية الخاصة بك. بل يكتشف الـ gateway الخاص بالـ profile أو يشغّله (hermes gateway ensure)، وينشئ الجلسة هناك أو يستأنفها، ويتصل عبر WebSocket المحلي للـ gateway — وهي الجلسة نفسها التي يمكن لنافذة Desktop أو TUI أو موضوع Telegram فتحها في الوقت ذاته. يؤدي إغلاق الطرفية إلى الفصل (Detached; accepted work continues at the gateway.)؛ ولا يلغي الدور. أما مجلد العمل الخاص بك، و --model و --provider و --reasoning و --toolsets و --max-turns و --skills و --checkpoints و --yolo و --accept-hooks و --pass-session-id و --ignore-rules و --base-url/--api-key و --safe-mode/--ignore-user-config، فتُثبَّت في الجلسة عند إنشائها؛ ويمكن لـ --resume تكرار القيم نفسها لكنه لا يستطيع تغييرها. يسمّي --resume <id-or-title> و -c <title> الجلسة؛ ويحلّ الـ gateway العنوان (المعرّف المطابق تمامًا أولًا، ثم أحدث استمرار بصيغة "<title> #N"، متتبَّعًا حتى طرفه الحيّ) ضمن الجلسات المسموح لك بقراءتها، وإلا يبلّغ No session found matching '…' (رمز الخروج 1). ويستأنف -c المجرّد و --resume latest أحدث جلسة CLI في مساحة العمل هذه عبر الـ gateway. وينشئ -c <title> --create-if-missing جلسة بذلك العنوان عند عدم وجود أي جلسة، ويستأنفها عند وجودها، ليحصل المستدعون البرمجيون (أدوار Bot Chat في Bot Mode) على thread حتمي. أما الخيارات التي لا معنى لها إلا لوكيل يعمل داخل العملية نفسها — --image و --worktree/-w و --no-restore-cwd و --run-budget و --verbose/-v و --compact و --create-if-missing دون -c <name> — فتُرفض مسبقًا (Unsupported gateway CLI options: …، رمز الخروج 2)؛ ويسرد الرفض، لكل خيار، المكان الذي توجد فيه تلك الإمكانية الآن (خيار TUI أو مفتاح config.yaml أو الأمر الفرعي في hermes)، ولا يُرجَع إلى وكيل محلي في أي حال. ولا يقرأ تشغيل --safe-mode / --ignore-user-config أي نموذج افتراضي للـ profile، لذا يجب أن تسمّي نموذجًا؛ ويطبع الرفض مثالًا كاملًا مثل hermes chat --safe-mode --provider openrouter --model anthropic/claude-sonnet-4 -q "hello". وفي هذا الوضع تكون واجهة slash هي /stop و /approve <id> <choice> و /answer <id> <text> و /discard <admission_id> و /branch [title] و /model <model> [--provider name] و /compress [here [N] | <focus>] [--preview] و /yolo [on|off] و /help و /quit؛ أما بقية slash commands فتطبع Unsupported gateway CLI command; use /help. استخدم TUI (hermes --tui) للحصول على سجل slash الكامل.

      إذا فقد دور قيد التشغيل مالكه بينما يكون استعلام CLI المحدود الخاص بك في قائمة الانتظار، فإن CLI يخرج برمز 3. ويبقى إدخالك المقبول في قائمة الانتظار. استأنف الجلسة المطبوعة بصورة تفاعلية، وافحص الدور المجهول، واستخدم /discard <admission_id> للإقرار به قبل المتابعة. لا تُعد إرسال الإدخال الموجود في قائمة الانتظار.

      شعار Hermes CLI وتدفق المحادثة وسطر الإدخال الثابت، معروضة كصورة توضيحية ثابتة في المستندات بدلًا من رسوم نصية هشة.

      • يفتح شريط بعرض 40 عمودًا كل رسالة مستخدم وكل إجابة (بلون التمييز) وكل كتلة استدلال (بلون خافت)؛ ويُبَثّ الاستدلال مباشرةً كما في النمط الكلاسيكي وينتهي بسطر ∴ Thought for 3s · <title>. يمثّل ❯ رسالتك، واستدعاء الأداة المنتهي يتصدره رمزه التعبيري (📖 Read و 💻 $؛ و ✗ بالأحمر عند فشله، مع رمز خروجه؛ وكتابة skill_manage المرفوضة تحتفظ برمزها التعبيري وتعرض السبب بلون خافت، لأن الوكيل يعيد محاولتها بنفسه)، ويمثّل │ الـ diff الخاص بتعديل تحت صفه، و ☤ الإجابة، و ─ سطر ملخص الدور.
      • يحمل الخط العلوي لمحرر الإدخال النشاط الحيّ (المؤشر الدوّار، وما يعمل حاليًا، والزمن المنقضي، والـ tokens المبثوثة) على اليسار وعنوان الجلسة على اليمين؛ ولا يُطبع أي صف للمؤشر الدوّار في scrollback.
      • يقع سطر الحالة تحت محرر الإدخال: الحقول نفسها الموجودة في شريط الحالة الكلاسيكي (النموذج، والسياق، وإصابات cache، وزمن الاستجابة، وtokens/s، والعمل في الخلفية، والهدف، والمدة، وYOLO…) إضافةً إلى مجلد العمل (مع branch الخاص بـ git) على اليسار؛ والمفاتيح التي تفعل شيئًا الآن على اليمين.
      • لافتة الترحيب هي نفسها في كلا التخطيطين.

      اضبط display.cli_layout: classic للإبقاء على لوحات الاستدلال والإجابة المؤطَّرة وشريط الحالة فوق الإدخال.

      وجود ~ قبل عدد أو نسبة السياق يعني أنها تتضمن تقديرًا محليًا. ينطبق هذا أيضًا على /status و /context في الـ gateway، وعلى TUI، ومقياس السياق في Desktop. قراءة استخدام المزوّد غير المتغيرة لا تحمل ~؛ أما القراءة المستندة إلى مرجع من المزوّد مع رسائل جديدة غير مُسعَّرة فتحملها. ويُبلغ /context عن المصدر المحدد. تفصيلات الفئات والمساحة الحرة والمهارات والـ toolsets هي دائمًا تقديرات محلية، حتى عندما يأتي الإشغال الإجمالي من بيانات استخدام المزوّد. ولا تغيّر هذه التسميات المعروضة قرارات الضغط (compaction) ولا تُجري طلبات إضافية إلى المزوّد.

      عرض استئناف الجلسة​

      عند استئناف جلسة سابقة (hermes -c أو hermes --resume <id>)، تظهر لوحة "Previous Conversation" بين الشعار وسطر الإدخال، وتعرض ملخصًا موجزًا لسجل المحادثة. راجع الجلسات — ملخص المحادثة عند الاستئناف للاطلاع على التفاصيل والإعدادات.

      اختصارات لوحة المفاتيح​

      في macOS، تعني F6/F7 مفاتيح الوظائف الفعلية، لا عناصر التحكم بالوسائط/النظام الظاهرة في الصف العلوي. اضغط باستمرار على Fn (مفتاح الكرة الأرضية في لوحات المفاتيح الأحدث) أثناء الضغط على مفتاح الوظيفة، أو فعّل Use F1, F2, etc. keys as standard function keys في System Settings → Keyboard → Keyboard Shortcuts → Function Keys. البدائل الموثوقة في الطرفية هي Ctrl+T لـ F6 و Ctrl+R لـ F7.

      ! وضع Shell​

      ابدأ السطر بـ ! لتنفيذه كأمر shell بدلًا من إرساله إلى الوكيل:

      > !git status
      > !ls -la
      > !pytest -x tests/hermes_cli
      • دون تكلفة. لا يُستدعى النموذج أبدًا — لا استدعاء لـ API، ولا tokens، ولا زمن انتظار.
      • لا يدخل أي شيء إلى المحادثة. لا يُضاف الأمر ولا مخرجاته إلى السجل، فيبقى السياق نظيفًا ولا يتأثر التخزين المؤقت للـ prompt.
      • يعمل على جهازك، في مجلد عمل الجلسة. مع terminal backend المحلي الافتراضي، يطابق !pwd ما يراه الوكيل. أما terminal.backend (ssh, docker، …) البعيد أو المعزول فلا يُستخدَم لأوامر ! — فهي تعمل دائمًا على المضيف الذي يعمل عليه Hermes نفسه، لذا يسمّي !hostname جهازك، بينما تسمّي أداة terminal الخاصة بالوكيل backend. اطلب من الوكيل (أو افتح shell على الهدف) تشغيل شيء داخل backend. أما إكمال المسارات في مربع الكتابة فيتبع backend المضبوط ويعرض نظام ملفات الهدف.
      • تظل الموافقات سارية. يمر الأمر الخطير (rm -rf، أو الكتابة إلى ~/.hermes/config.yaml، وما إلى ذلك) عبر مطالبة الموافقة نفسها التي تستخدمها أداة terminal الخاصة بالوكيل. إن ! اختصار لتوفير التكلفة وزمن الانتظار، وليس وسيلة لتجاوز الأمان.
      • تُعرض رموز الخروج غير الصفرية. يطبع الأمر الفاشل ! exited <code> بعد مخرجاته.
      • ! وحدها تطبع تذكيرًا بطريقة الاستخدام في سطر واحد.

      وضع Shell متاح في CLI فقط. تتجاهله منصات الـ gateway (Discord و Telegram و Slack) وعمليات تشغيل cron — فهؤلاء المستخدمون لديهم الـ shells الخاصة بهم بالفعل.

      إزالة تنسيق Markdown من الردود النهائية. يزيل CLI أكثر أسوار markdown إسهابًا وأغلفة **bold** / *italic* من ردود الوكيل النهائية لتُعرض كنص مقروء في الطرفية بدلًا من المصدر الخام. تُحفظ كتل الكود والقوائم. ولا يؤثر هذا في منصات الـ gateway أو نتائج الأدوات — إذ تحتفظ بتنسيق markdown الخاص بها للعرض الأصلي.

      الـ Slash Commands​

      اكتب / لعرض القائمة المنسدلة للإكمال التلقائي. يدعم Hermes مجموعة كبيرة من slash commands الخاصة بـ CLI، وأوامر المهارات الديناميكية، والأوامر السريعة التي يعرّفها المستخدم.

      أمثلة شائعة:

      الأمرالوصف
      /helpعرض تعليمات الأوامر
      /modelعرض النموذج الحالي أو تغييره
      /toolsسرد الأدوات المتاحة حاليًا
      /skills browseتصفح Skills Hub والمهارات الاختيارية الرسمية
      /bg <prompt>تشغيل prompt في جلسة منفصلة في الخلفية
      /btw <question>طرح سؤال جانبي حول المحادثة الحالية دون مقاطعتها
      /skinعرض مظهر (skin) CLI النشط أو تبديله
      /voice onتفعيل الوضع الصوتي في CLI (اضغط Ctrl+B للتسجيل)
      /voice ttsتبديل التشغيل الصوتي لردود Hermes
      /reasoning highزيادة مستوى جهد الاستدلال (reasoning)
      /title My Sessionتسمية الجلسة الحالية
      /statusعرض معلومات الجلسة — النموذج/الـ profile/الـ tokens/المدة — متبوعة بكتلة Session recap محلية (عدد الأدوار الأخيرة، والأدوات الأكثر استخدامًا، والملفات التي جرى التعامل معها، وآخر prompt من المستخدم + رد المساعد). حساب محلي بالكامل؛ دون أي استدعاء لـ LLM.
      /context [all]تفصيل مرئي لاستخدام السياق — شبكة من الكتل الرسومية + جدول tokens لكل فئة (system prompt / الأدوات / المهارات / الذاكرة / المحادثة / المساحة الحرة). يضيف /context all التكاليف لكل مهارة ولكل toolset.
      /sessionsفتح أداة تفاعلية لاختيار الجلسات داخل CLI الكلاسيكي مباشرةً (الواجهة نفسها التي يستخدمها TUI). اكتب للتصفية، واستخدم مفاتيح الأسهم للتنقل، و Enter للاستئناف.

      للاطلاع على القوائم الكاملة للأوامر المدمجة في CLI ومنصات المراسلة، راجع مرجع Slash Commands.

      للاطلاع على الإعداد، والمزوّدين، وضبط اكتشاف الصمت، واستخدام الصوت في منصات المراسلة/Discord، راجع الوضع الصوتي (Voice Mode).

      نصيحة

      الأوامر غير حساسة لحالة الأحرف — يعمل /HELP تمامًا مثل /help. كما تتحول المهارات المثبّتة تلقائيًا إلى slash commands.

      الأوامر السريعة (Quick Commands)​

      يمكنك تعريف أوامر مخصصة تنفّذ أوامر shell فورًا دون استدعاء LLM. تعمل هذه الأوامر في كلٍّ من CLI ومنصات المراسلة (Telegram و Discord وغيرها).

      # ~/.hermes/config.yaml
      quick_commands:
        status:
          type: exec
          command: systemctl status hermes-agent
        gpu:
          type: exec
          command: nvidia-smi --query-gpu=utilization.gpu,memory.used --format=csv,noheader
        restart:
          type: alias
          target: /gateway restart

      ثم اكتب /status أو /gpu أو /restart في أي محادثة. راجع دليل الإعدادات لمزيد من الأمثلة.

      تحميل المهارات مسبقًا عند التشغيل​

      إذا كنت تعرف مسبقًا المهارات التي تريد تفعيلها في الجلسة، فمرّرها عند التشغيل:

      hermes -s hermes-agent-dev,github-auth
      hermes chat -s github-pr-workflow -s github-auth

      يحمّل Hermes كل مهارة مذكورة في الـ prompt الخاص بالجلسة قبل الدور الأول. ويعمل الخيار نفسه في الوضع التفاعلي ووضع الاستعلام الواحد.

      تحميل تلقائي دائم عبر الإعدادات​

      لتفعيل المهارات نفسها في بداية كل جلسة جديدة — CLI و TUI و gateway و cron و API على السواء — اضبط skills.auto_load في config.yaml:

      skills:
        auto_load:
          - hermes-agent-dev
          - github-pr-workflow

      كل مدخل اسم مهارة. تُحدَّد القائمة مرة واحدة عند بناء system prompt للجلسة أول مرة، وتُعاد استخدام البايتات المعروضة طوال المحادثة (عند تبديل النموذج والضغط)، لذا يبقى التخزين المؤقت للـ prompt سليمًا؛ وتُطبَّق تعديلات الإعدادات في الجلسة التالية. تُسجَّل المهارات المفقودة أو المعطّلة كتحذير وتُتجاوَز. أسماء -s التي تتداخل مع القائمة تُحمَّل مرة واحدة.

      --ignore-rules (أو ما يعادله HERMES_IGNORE_RULES=1) يتجاوز التحميل التلقائي مع AGENTS.md و SOUL.md و .cursorrules وحقن الذاكرة؛ وتظل المهارات الصريحة عبر -s تُحمَّل. الإعداد خاص بالـ profile: يتحكم config.yaml لكل profile في قائمته الخاصة.

      Slash Commands الخاصة بالمهارات​

      تُسجَّل كل مهارة مثبّتة في ~/.hermes/skills/ تلقائيًا كـ slash command. ويصبح اسم المهارة هو الأمر:

      /gif-search funny cats
      /axolotl help me fine-tune Llama 3 on my dataset
      /github-pr-workflow create a PR for the auth refactor

      # Just the skill name loads it and lets the agent ask what you need:
      /excalidraw

      الشخصيات​

      اضبط شخصية معرّفة مسبقًا لتغيير نبرة الوكيل:

      /personality pirate
      /personality kawaii
      /personality concise

      للعودة إلى الوضع الافتراضي (دون أي طبقة شخصية)، استخدم /personality none — كما يعمل default و neutral أيضًا.

      personalities:

      الإدخال متعدد الأسطر​

      توجد طريقتان لإدخال رسائل متعددة الأسطر:

      1. Alt+Enter أو Ctrl+J أو Shift+Enter — يُدرج سطرًا جديدًا
      2. المتابعة بالشرطة المائلة العكسية — أنهِ السطر بـ \ للمتابعة:
      ❯ Write a function that:\
        1. Takes a list of numbers\
        2. Returns the sum

      Ctrl+J والمتابعة بالشرطة المائلة العكسية مفعّلين افتراضيًا، بما يتوافق مع اختصارات الإدخال متعدد الأسطر في Claude Code / Codex / OpenCode. وفي الطرفيات المدعومة مثل iTerm2، يطلب Hermes أيضًا الإبلاغ الموسّع عن المفاتيح (extended key reporting) حتى يصل Shift+Enter كمفتاح سطر جديد مستقل. إذا كانت طرفيتك ترسل LF عند الضغط على Enter العادي وكنت بحاجة إلى السلوك الاحتياطي القديم الذي يستخدم Ctrl+J للإرسال، فعطّل ذلك:

      # ~/.hermes/config.yaml
      display:
        cli_multiline_shortcuts: false
      معلومة

      لصق النص متعدد الأسطر مدعوم — استخدم أيًّا من مفاتيح السطر الجديد أعلاه، أو الصق المحتوى مباشرةً ببساطة.

      في الطرفيات التي تستخدم Kitty keyboard protocol، يُدرج Alt+Enter على لوحة الأرقام أيضًا سطرًا جديدًا، بما في ذلك بجوار محتوى ملصوق مطوي. وتتبع مفاتيح التنقل في لوحة الأرقام عند استخدامها مع مفاتيح التعديل (modifiers) سلوك نظيراتها خارج لوحة الأرقام.

      توافق Shift+Enter​

      ترسل معظم الطرفيات افتراضيًا تسلسل البايتات نفسه لكلٍّ من Enter و Shift+Enter، لذا لا تستطيع التطبيقات التمييز بينهما. لا يتعرّف Hermes على Shift+Enter إلا عندما ترسل الطرفية تسلسلًا مميزًا عبر Kitty keyboard protocol أو وضع modifyOtherKeys في xterm.

      الطرفيةالحالة
      Kitty، foot، WezTerm، Ghosttyتمييز Shift+Enter مفعّل افتراضيًا
      iTerm2 (الإصدارات الحديثة)، Alacritty، طرفية VS Code، Warpمدعوم بعد تفعيل بروتوكول Kitty في الإعدادات
      Windows Terminal Preview 1.25+مدعوم بعد تفعيل بروتوكول Kitty في الإعدادات
      Terminal.app على macOS، و Windows Terminal الافتراضي (الإصدار المستقر)غير مدعوم — لا يمكن تمييز Shift+Enter عن Enter

      حيث لا تستطيع الطرفية التمييز بينهما، يستمر Alt+Enter و Ctrl+J في العمل افتراضيًا. في Windows Terminal تحديدًا، تلتقط الطرفية Alt+Enter (للتبديل إلى ملء الشاشة) فلا يصل أبدًا إلى Hermes — استخدم Ctrl+Enter (الذي يُسلَّم كـ Ctrl+J) أو Ctrl+J مباشرةً لإدراج سطر جديد.

      إعادة توجيه الوكيل في منتصف الدور​

      أثناء عمل الوكيل، يمكنك إرسال تصحيح دون بدء دور جديد:

      • اكتب رسالة جديدة + Enter — يعيد توجيه الدور النشط باستخدام تصحيحك
      • Ctrl+C — قاطع العملية الحالية (اضغط مرتين خلال 2 ثانية لفرض الخروج)؛ وإذا كان الـ prompt يحتوي على مسودة، فإن الضغطة الأولى تمسحها ويستمر الدور في العمل
      • يبقى عمل الأدوات المكتمل والاستدلال المعروض مسبقًا في السياق
      • تصل الأداة قيد التشغيل إلى نقطة توقف آمنة قبل تطبيق التصحيح

      وضع الإدخال أثناء الانشغال (Busy Input Mode)​

      يتحكم مفتاح الإعدادات display.busy_input_mode فيما يحدث عند الضغط على Enter أثناء عمل الوكيل:

      الوضعالسلوك
      "interrupt" (الافتراضي)تعيد رسالتك توجيه الدور النشط. يُعاد بدء توليد النموذج مع الحفاظ على الاستدلال المعروض والعمل المكتمل. ويُنقل أمر الطرفية الجاري في المقدمة إلى الخلفية (دون إنهائه — وستتلقى إشعارًا عند اكتماله) حتى تُقرأ رسالتك فورًا؛ أما الأدوات الأخرى قيد التشغيل فتنتهي أولًا
      "queue"تُوضع رسالتك في قائمة الانتظار بوصفها الدور التالي بعد أن ينتهي الوكيل. وتعيش قائمة الانتظار على الـ gateway (تنجو من الانهيار، ويراها كل عميل متصل).
      "steer"تُحقن رسالتك في التشغيل الحالي عبر /steer، فتصل إلى الوكيل بعد استدعاء الأداة التالي — دون مقاطعة، ودون دور جديد
      # ~/.hermes/config.yaml
      display:
        busy_input_mode: "steer"   # or "queue" or "interrupt" (default)

      يُجهّز وضع "queue" دور متابعة منفصلًا. أما "steer" فينتظر دائمًا حدّ نتيجة الأداة التالية. ويستجيب الوضع الافتراضي "interrupt" بشكل أسرع أثناء توليد النموذج مع تجنب إلغاء أداة قيد التشغيل؛ إذ يُسلَّم أمر terminal طويل يعمل في المقدمة (عملية بناء، أو أداة استطلاع poller) إلى الخلفية حتى يرى الوكيل رسالتك فورًا بدلًا من انتظار انتهاء الأمر. استخدم /stop عندما تريد إلغاء الدور والعمل الجاري في المقدمة. وتعود القيم غير المعروفة إلى "interrupt".

      لدى "steer" سلوكان احتياطيان تلقائيان: إذا لم يكن الوكيل قد بدأ بعد، أو إذا كانت هناك صور مرفقة، تعود الرسالة إلى سلوك "queue" حتى لا يُفقد شيء.

      مهما كان الوضع، فإن /queue <prompt> يضع دور متابعة في قائمة الانتظار صراحةً، وتعمل /queue list, /queue rm N, /queue edit N … و /queue move A B على قائمة الانتظار المعلّقة فورًا، حتى أثناء التشغيل. يعرض جزء العمل الحي ما ينتظر.

      عندما يعمل CLI على جلسة الـ gateway (الإعداد المحلي الافتراضي)، فإن الـ prompt الذي يُوضع في قائمة الانتظار أثناء تشغيل دور، عبر /queue أو بـ Enter في وضع queue، يدخل في قائمة الانتظار الخاصة بالـ gateway لتلك الجلسة. وهو ينجو من إعادة تشغيل الـ gateway ويُنفَّذ مرة واحدة، بالترتيب الذي أدخلته به. أما متابعات الصور فتبقى تنتظر في CLI. وهذه القائمة مشتركة: يعرض /queue list و rm و edit و clear كل prompt في قائمة انتظار الجلسة ويغيّره، بما في ذلك ما وضعته نافذة أخرى أو أتمتة. ينفّذ الـ gateway قائمته بالترتيب ولا يستطيع إعادة ترتيبها، لذا يرفض /queue move نقل prompt يمسكه الـ gateway. وأي slash command تُكتب أثناء الانشغال بعد prompt وضعتَه بنفسك عبر /queue يُنفَّذ بعد أن يبدأ دور ذلك الـ prompt؛ وهو ينتظر بضع ثوانٍ على الأكثر، فلا تمنع قائمة انتظار متوقفة مؤقتًا الكتابة أبدًا.

      يمكنك تغييره داخل CLI أيضًا:

      /busy queue
      /busy steer
      /busy interrupt
      /busy status
      تلميح الاستخدام الأول

      في المرة الأولى التي تضغط فيها Enter أثناء عمل Hermes، يطبع Hermes تذكيرًا من سطر واحد يشرح إعداد /busy. لا يظهر هذا التذكير إلا مرة واحدة لكل تثبيت؛ ويسجّل onboarding.seen.busy_input_prompt في config.yaml أنه قد عُرض. احذف هذا المفتاح لرؤية التلميح مجددًا.

      التعليق والنقل إلى الخلفية​

      على أنظمة Unix، اضغط Ctrl+Z لتعليق Hermes ونقله إلى الخلفية — تمامًا مثل أي عملية في الطرفية. تطبع الـ shell رسالة تأكيد:

      Hermes Agent has been suspended. Run `fg` to bring Hermes Agent back.

      اكتب fg في الـ shell لاستئناف الجلسة من حيث توقفت تمامًا. هذه الميزة غير مدعومة على Windows.

      عرض تقدّم الأدوات​

      يعرض CLI مؤشرات متحركة أثناء عمل الوكيل:

      حركة التفكير (أثناء استدعاءات API):

        ◜ (｡•́︿•̀｡) pondering... (1.2s)
        ◠ (⊙_⊙) contemplating... (2.4s)
        ✧٩(ˊᗜˋ*)و✧ got it! (3.1s)

      سجل تنفيذ الأدوات:

        ┊ 💻 terminal `ls -la` (0.3s)
        ┊ 🔍 web_search (1.2s)
        ┊ 📄 web_extract (2.1s)

      تنقّل بين أوضاع العرض باستخدام /verbose: off → new → all → verbose. ويمكن أيضًا تفعيل هذا الأمر لمنصات المراسلة — راجع الإعدادات.

      طول معاينة الأدوات​

      يتحكم مفتاح الإعدادات display.tool_preview_length في الحد الأقصى لعدد الأحرف المعروضة في أسطر معاينة استدعاءات الأدوات (مثل مسارات الملفات وأوامر الطرفية). القيمة الافتراضية هي 0، وتعني عدم وجود حد — فتُعرض المسارات والأوامر كاملة.

      # ~/.hermes/config.yaml
      display:
        tool_preview_length: 80   # Truncate tool previews to 80 chars (0 = no limit)

      يفيد هذا في الطرفيات الضيقة أو عندما تحتوي وسائط الأدوات على مسارات ملفات طويلة جدًا.

      إدارة الجلسات​

      استئناف الجلسات​

      عند الخروج من جلسة CLI، يُطبع أمر الاستئناف:

      Resume this session with:
        hermes --resume 20260225_143052_a1b2c3

      Session:        20260225_143052_a1b2c3
      Duration:       12m 34s
      Messages:       28 (5 user, 18 tool calls)

      خيارات الاستئناف:

      hermes --continue                          # Resume the most recent CLI session
      hermes -c                                  # Short form
      hermes -c "my project"                     # Resume a named session (latest in lineage)
      hermes -c "my project" --create-if-missing # Same, creating the titled session if none exists
      hermes --resume 20260225_143052_a1b2c3     # Resume a specific session by ID
      hermes --resume "refactoring auth"         # Resume by title
      hermes --resume latest                     # Resume the most recent session (same as -c)
      hermes --resume latest --in ./my-project   # Latest session for ./my-project's workspace
      hermes -r 20260225_143052_a1b2c3           # Short form

      يستعيد الاستئناف سجل المحادثة الكامل من SQLite. يرى الوكيل جميع الرسائل السابقة واستدعاءات الأدوات والردود — تمامًا كما لو أنك لم تغادر قط.

      استخدم /title My Session Name داخل المحادثة لتسمية الجلسة الحالية، أو hermes sessions rename <id> <title> من سطر الأوامر. واستخدم hermes sessions list لتصفح الجلسات السابقة.

      تخزين الجلسات​

      تُخزَّن جلسات CLI في قاعدة بيانات الحالة SQLite الخاصة بـ Hermes في ~/.hermes/state.db. وتحتفظ قاعدة البيانات بما يلي:

      • البيانات الوصفية للجلسة (المعرّف ID، والعنوان، والطوابع الزمنية، وعدادات الـ tokens)
      • سجل الرسائل
      • تسلسل النَّسب بين الجلسات المضغوطة/المستأنفة
      • فهارس البحث في النص الكامل التي يستخدمها session_search

      تحتفظ بعض محوّلات المراسلة (adapters) أيضًا بملفات نصوص المحادثات لكل منصة إلى جانب قاعدة البيانات، لكن CLI نفسه يستأنف الجلسات من مخزن جلسات SQLite.

      ضغط السياق​

      تُلخَّص المحادثات الطويلة تلقائيًا عند الاقتراب من حدود السياق:

      # In ~/.hermes/config.yaml
      compression:
        enabled: true
        threshold: 0.50    # Compress at 50% of context limit by default

      # Summarization model configured under auxiliary:
      auxiliary:
        compression:
          model: ""  # Leave empty to use the main chat model (default). Or pin a cheap fast model, e.g. "google/gemini-3-flash-preview".

      عند بدء الضغط، تُلخَّص الأدوار الوسطى بينما يُحتفظ دائمًا بأول 3 أدوار وآخر 20 دورًا.

      الجلسات في الخلفية​

      شغّل prompt في جلسة منفصلة في الخلفية بينما تواصل استخدام CLI لأعمال أخرى:

      /bg Analyze the logs in /var/log and summarize any errors from today

      يؤكد Hermes المهمة فورًا ويعيد إليك سطر الإدخال:

      🔄 Background task #1 started: "Analyze the logs in /var/log and summarize..."
         Task ID: bg_143022_a1b2c3

      آلية العمل​

      يُطلق كل prompt عبر /bg ينشئ جلسة وكيل منفصلة تمامًا في خيط daemon:

      • محادثة معزولة — لا يعرف الوكيل العامل في الخلفية شيئًا عن سجل جلستك الحالية. فهو لا يتلقى إلا الـ prompt الذي تقدّمه.
      • الإعدادات نفسها — يرث الوكيل العامل في الخلفية من الجلسة الحالية النموذج، والمزوّد، والـ toolsets، وإعدادات الاستدلال (reasoning)، والنموذج الاحتياطي (fallback).
      • دون حجب — تبقى جلستك في المقدمة تفاعلية بالكامل. يمكنك المحادثة، أو تنفيذ الأوامر، أو حتى بدء مزيد من المهام في الخلفية.
      • مهام متعددة — يمكنك تشغيل عدة مهام في الخلفية في وقت واحد. وتحصل كل مهمة على معرّف رقمي.

      النتائج​

      عندما تنتهي مهمة تعمل في الخلفية، تظهر النتيجة كلوحة في الطرفية:

      ╭─ ☤ Hermes (background #1) ──────────────────────────────────╮
      │ Found 3 errors in syslog from today:                         │
      │ 1. OOM killer invoked at 03:22 — killed process nginx        │
      │ 2. Disk I/O error on /dev/sda1 at 07:15                      │
      │ 3. Failed SSH login attempts from 192.168.1.50 at 14:30      │
      ╰──────────────────────────────────────────────────────────────╯

      إذا فشلت المهمة، فسترى إشعار خطأ بدلًا من ذلك. وإذا كان display.bell_on_complete مفعّلًا في إعداداتك، يرن جرس الطرفية عند انتهاء المهمة.

      حالات الاستخدام​

      • الأبحاث طويلة الأمد — "/bg ابحث في أحدث التطورات في تصحيح الأخطاء الكمومية" بينما تعمل على الكود
      • معالجة الملفات — "/bg حلّل جميع ملفات Python في هذا المستودع واذكر أي مشكلات أمنية" بينما تواصل محادثة
      • التحقيقات المتوازية — ابدأ عدة مهام في الخلفية لاستكشاف زوايا مختلفة في وقت واحد
      معلومة

      لا تظهر الجلسات العاملة في الخلفية في سجل محادثتك الرئيسية. فهي جلسات مستقلة لكل منها معرّف مهمة خاص بها (مثل bg_143022_a1b2c3).

      الوضع الهادئ (Quiet Mode)​

      يعمل CLI افتراضيًا في الوضع الهادئ الذي:

      • يُخفي السجلات التفصيلية الصادرة عن الأدوات
      • يفعّل المؤشرات المتحركة بأسلوب kawaii
      • يُبقي المخرجات نظيفة وسهلة الاستخدام

      للحصول على مخرجات تصحيح الأخطاء (debug):

      hermes chat --verbose
