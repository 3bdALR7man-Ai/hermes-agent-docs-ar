      أي ملف يفعل ماذا؟

      "أخبرت وكيلي بشيء ونسيه." "أي ملف هو دماغ وكيلي؟" "عدّلت SOUL.md — فلماذا لا يعرف اسمي؟" كل هذه الأسئلة تختصر إلى أمر واحد: يتشكّل Hermes Agent بعدة ملفات markdown، ولكل واحد منها دور مختلف. تضع هذه الصفحة خريطة لها جميعًا في مكان واحد. لمزيد من التفاصيل حول أي منها، اتبع الروابط إلى الذاكرة الدائمة، والشخصية و SOUL.md، وملفات السياق.

      الجدول الرئيسي​

      الملفما يحملهمن يكتبهمتى يراه الوكيلأين يقيم
      SOUL.mdهوية الوكيل الأساسية — الشخصية، ونبرة الحديث، وأسلوب التواصل، وما يجب تجنّبه أسلوبيًاأنت. يُنشئ Hermes ملفًا مبدئيًا تلقائيًا إن لم يكن موجودًا؛ ولا تُستبدَل الملفات الموجودة أبدًاالفتحة رقم 1 من system prompt، عند بدء الجلسة~/.hermes/SOUL.md (أو $HERMES_HOME/SOUL.md مع مجلد رئيسي مخصَّص) — أبدًا مجلد العمل
      USER.mdملف تعريف المستخدم — اسمك، ودورك، وتفضيلاتك، وأسلوب تواصلك، وتوقعاتكالوكيل، عبر أداة memory (يمكنك تقييد الحفظ بـ write_approval، أو تعديل المدخلات عبر hermes journey edit)يُدرَج في system prompt كلقطة مجمَّدة عند بدء الجلسة~/.hermes/memories/
      MEMORY.mdملاحظات الوكيل الشخصية — حقائق البيئة، وأعراف المشروع، وغرائب الأدوات، والأشياء المتعلَّمةالوكيل، عبر أداة memory (خيارات التقييد والتعديل نفسها الخاصة بـ USER.md)يُدرَج في system prompt كلقطة مجمَّدة عند بدء الجلسة~/.hermes/memories/
      AGENTS.mdتعليمات المشروع، وأعرافه، وبنيته المعمارية — الأوامر، والمنافذ (ports)، والمسارات، وسير عمل خاص بالمستودعأنت (أو من يؤلّف المشروع)يُحمَّل إلى system prompt عند بدء التشغيل من مجلد عملك؛ وتُكتشَف النسخ المتداخلة تدريجيًا كلما تنقّل الوكيل بين المجلدات الفرعيةمجلد عمل المشروع + المجلدات الفرعية
      .hermes.md / HERMES.mdتعليمات مشروع، شبيهة بـ AGENTS.md لكنها خاصة بـ Hermes وذات أعلى أولويةأنتيُحمَّل إلى system prompt عند بدء التشغيل (يفوز أول تطابق على AGENTS.md)مشروعك — يصعد الاكتشاف حتى جذر git
      ملف سياق مشروع واحد لكل جلسة

      يُحمَّل نوع واحد فقط من سياق المشروع لكل جلسة، ويفوز أول تطابق: .hermes.md ← AGENTS.md ← CLAUDE.md ← .cursorrules. أما SOUL.md فيُحمَّل دائمًا بشكل مستقل كهوية الوكيل — وهو ليس جزءًا من سلسلة الأولوية تلك. راجع ملفات السياق للقائمة الكاملة، بما في ذلك توافق CLAUDE.md و.cursorrules.

      اختصار مفيد:

      • SOUL.md هو من يكون الوكيل — إن كان ينبغي أن يرافقك في كل مكان، فمكانه هنا.
      • USER.md هو من تكون أنت — يحافظ عليه الوكيل نيابة عنك.
      • MEMORY.md هو ما تعلّمه الوكيل — يحافظ عليه بنفسه أيضًا.
      • AGENTS.md (أو .hermes.md) هو ما يحتاجه المشروع — إن كان ملكًا لمشروع، فمكانه هنا.

      "لماذا نسي ما قلته للتو؟"​

      تُدرَج الذاكرة (MEMORY.md وUSER.md) في system prompt كـلقطة مجمَّدة تُلتقَط مرة واحدة عند بدء الجلسة — فحين يحفظ الوكيل شيئًا في منتصف الجلسة، يُخزَّن التغيير على القرص فورًا لكنه لا يظهر في system prompt حتى بدء الجلسة التالية. هذا مقصود: فهو يحافظ على ذاكرة التخزين المؤقت لبادئة (prefix cache) LLM من أجل الأداء، وتُظهر استجابات الأدوات دائمًا الحالة الحيّة، لذا لا يضيع شيء — ابدأ جلسة جديدة وستجد الذاكرة المحدَّثة هناك. التفاصيل الكاملة في كيف تظهر الذاكرة في system prompt.

      الخلط الشائع​

      "وضعت حقائق عن نفسي في SOUL.md، لكن USER.md بقي فارغًا"​

      SOUL.md وUSER.md نظامان منفصلان لا يغذّي أحدهما الآخر أبدًا. SOUL.md ملف شخصية تحرّره أنت مباشرة — يشكّل النبرة والهوية، ويُدرَج محتواه حرفيًا في الفتحة رقم 1 من الـ prompt. أما USER.md فجزء من الذاكرة الدائمة ويكتبه الوكيل عبر أداة memory. إن أردت حقائق عن نفسك في USER.md، أخبر الوكيل ("تذكّر أنني أفضّل الإجابات المختصرة") فيحفظها — تحرير SOUL.md لن يملأ الذاكرة، ومدخلات الذاكرة لن تغيّر الشخصية. استخدم SOUL.md لتوجيه النبرة والشخصية الدائمة؛ واترك التفضيلات وحقائق الملف الشخصي للذاكرة. راجع ما الذي يجب أن يوضَع في SOUL.md؟ وشرح الهدفين.

      "أخبرته باسمي في منتصف الجلسة وتصرّف وكأنه لم يسمعه قط"​

      إن كان الوكيل قد حفظ اسمك في الذاكرة، فقد نجح الحفظ — تحقّق من ذلك عبر استجابات أداة memory أو hermes journey list. ما تراه هو قاعدة اللقطة المجمَّدة أعلاه: لا يتجدَّد system prompt في منتصف الجلسة، لذا لا تزال كتلة الذاكرة المُدرَجة تُظهر حالة بدء الجلسة. لا يزال بإمكان الوكيل استخدام ما أخبرته به ضمن المحادثة الحالية (فهو موجود في السياق)، وسيكون المدخل المحفوظ في system prompt ابتداءً من الجلسة التالية. ينطبق الأمر نفسه على التعديلات التي تجريها على SOUL.md أو AGENTS.md أثناء تشغيل جلسة: يُجمَّع السياق عند بدء الجلسة، لذا أعد تشغيل الجلسة لالتقاط التغييرات.

      دليل قرار سريع
      • تريد تغيير طريقة حديث الوكيل؟ حرّر ~/.hermes/SOUL.md — الشخصية و SOUL.md.
      • تريد أن يتذكّر الوكيل حقيقة؟ فقط أخبره — يحفظها في الذاكرة بنفسه. الذاكرة الدائمة.
      • تريد ضبط قواعد المشروع؟ ضع ملف AGENTS.md (أو .hermes.md) في المشروع — ملفات السياق.
      • تحتاج تغيير شخصية مؤقتًا؟ استخدم /personality — إنه طبقة تراكب على مستوى الجلسة، بلا حاجة لتعديل ملفات.

      وثائق ذات صلة​

      • الذاكرة الدائمة — MEMORY.md، وUSER.md، وأداة memory، وحدود السعة، وwrite_approval
      • الشخصية و SOUL.md — إرشادات محتوى SOUL.md، وأنماط /personality الجاهزة، وطبقات الـ prompt
      • ملفات السياق — AGENTS.md، و.hermes.md، والاكتشاف التدريجي، والفحص الأمني
