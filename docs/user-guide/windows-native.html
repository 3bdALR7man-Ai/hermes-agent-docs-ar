      دليل Windows (التشغيل الأصلي)

      يعمل Hermes أصليًا على Windows 10 و Windows 11 — دون WSL، ودون Cygwin، ودون Docker. تتعمق هذه الصفحة في التفاصيل: ما الذي يعمل أصليًا، وما المتاح في WSL فقط، وما الذي يفعله المُثبّت (installer) فعليًا، وخيارات الضبط الخاصة بـ Windows التي قد تحتاج إلى تعديلها.

      إذا كنت تريد التثبيت فحسب، فالأمر المكوّن من سطر واحد في الصفحة الرئيسية أو في صفحة التثبيت هو كل ما تحتاج إليه. عُد إلى هنا حين يفاجئك شيء ما.

      هل تفضّل WSL بدلًا من ذلك؟

      إذا كنت تفضّل بيئة POSIX حقيقية (للطرفية المضمّنة في لوحة التحكم، أو دلالات fork، أو أدوات مراقبة الملفات على نمط Linux، وما إلى ذلك)، فراجع دليل Windows (WSL2). يتعايش الخياران دون تعارض: تُخزَّن بيانات التثبيت الأصلي ضمن %LOCALAPPDATA%\hermes، بينما تُخزَّن بيانات WSL ضمن ~/.hermes.

      التثبيت السريع​

      افتح PowerShell (أو Windows Terminal) ونفّذ:

      iex (irm https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.ps1)

      لا حاجة إلى صلاحيات المسؤول. يُثبَّت Hermes في %LOCALAPPDATA%\hermes\ ويُضيف المُثبّت hermes إلى User PATH الخاص بك — افتح طرفية جديدة بعد انتهائه.

      خيارات المُثبّت (تتطلب صيغة scriptblock لتمرير المعاملات):

      & ([scriptblock]::Create((irm https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.ps1))) -NoVenv -SkipSetup -Branch main
      المعاملالقيمة الافتراضيةالغرض
      -Branchmainاستنساخ branch محدد (مفيد لاختبار PRs)
      -Commitغير محددتثبيت إصدار commit محدد عبر SHA الخاص به (يتجاوز -Branch)
      -Tagغير محددتثبيت إصدار git tag محدد (مثل v0.14.0)
      -NoVenvمعطّلتخطي إنشاء الـ venv (خيار متقدم — تدير Python بنفسك)
      -SkipSetupمعطّلتخطي معالج hermes setup الذي يعمل بعد التثبيت
      -HermesHome%LOCALAPPDATA%\hermesتغيير مجلد البيانات
      -InstallDir%LOCALAPPDATA%\hermes\hermes-agentتغيير موقع الكود

      يعيد المُثبّت تلقائيًا محاولة عمليات git fetch المتعثرة، ويزيل BOM من أي حمولة install.ps1 يجري تنزيلها، بحيث لم يعد BOM بترميز UTF-8 الذي قد يُلتقط أثناء النقل عبر HTTP يُعطّل صيغة [scriptblock]::Create((irm ...)).

      مُثبّت Desktop (بديل)​

      يتوفر أيضًا مُثبّت رسومي خفيف — وهو مفيد إذا كنت تفضّل النقر المزدوج على ملف .exe بدلًا من فتح PowerShell. نزّل Hermes Desktop، وشغّل المُثبّت، وعند التشغيل الأول تستدعي الواجهة الرسومية install.ps1 في الخلفية لتجهيز Python (عبر uv) و Node و PortableGit وبقية تهيئة الاعتماديات الموضحة أدناه. بعد التشغيل الأول، يتشارك تطبيق Desktop و CLI hermes المُثبّت عبر PowerShell التثبيتَ نفسه في %LOCALAPPDATA%\hermes\hermes-agent ومجلد البيانات نفسه %LOCALAPPDATA%\hermes — فيمكنك التنقل بين الواجهة الرسومية و CLI بحرية.

      استخدم مُثبّت Desktop عندما تريد تجربة تثبيت مألوفة في Windows أو عندما تُسلّم Hermes لشخص غير مطوّر؛ واستخدم أمر PowerShell ذا السطر الواحد عندما تكون في الطرفية بالفعل.

      تهيئة الاعتماديات (dep_ensure)​

      عند التشغيل الأول (وعند الطلب حين يُكتشف غياب أداة ما)، يشغّل Hermes أداة تهيئة صغيرة مكتوبة بـ Python — hermes_cli/dep_ensure.py — تتحقق من الاعتماديات غير المكتوبة بـ Python التي يحتاج إليها وتثبّتها عند الحاجة. وفي Windows، الاعتماديات المعنية هي:

      الاعتماديةسبب حاجة Hermes إليها
      PortableGitتوفّر bash.exe لأداة الطرفية و git لعمليات الاستنساخ داخل الجلسة. تُجهَّز وقت التثبيت، وليس عبر dep_ensure.
      Node.js 26مطلوبة لأداة المتصفح (agent-browser)، وجسر الويب في TUI، وجسر WhatsApp.
      ffmpegتحويل صيغ الصوت لـ TTS والرسائل الصوتية.
      ripgrepبحث سريع في الملفات — يُستخدم grep بديلًا إذا لم تكن متاحة.
      حزم npmتُثبَّت agent-browser و Playwright Chromium وأي اعتماديات Node خاصة بكل toolset مرة واحدة عند أول استخدام لأداة المتصفح.

      لكل اعتمادية فحص على غرار shutil.which(...)؛ فإذا كان ملف تنفيذي مفقودًا وكان التشغيل تفاعليًا، يعرض dep_ensure تثبيته (مُحيلًا منطق التثبيت الفعلي إلى scripts\install.ps1 -ensure <dep>). أما عمليات التشغيل غير التفاعلية (الـ gateway، و cron، وتشغيل Desktop دون واجهة) فتتخطى السؤال وتعرض بدلًا من ذلك خطأً واضحًا بالصيغة this feature needs <dep>.

      ما الذي يفعله المُثبّت فعليًا​

      من البداية إلى النهاية، بالترتيب:

      1. يهيّئ uv — مدير Python السريع من Astral. يُثبَّت في %USERPROFILE%\.local\bin.
      2. يثبّت Python 3.11 عبر uv. لا حاجة إلى وجود Python مسبقًا.
      3. يثبّت Node.js 26 (عبر winget إن كان متاحًا، وإلا فعبر أرشيف Node محمول يُفك ضمن %LOCALAPPDATA%\hermes\node). يُستخدم لأداة المتصفح وجسر WhatsApp.
      4. يثبّت Git محمولًا — إذا كان git موجودًا في PATH بالفعل فسيستخدمه المُثبّت؛ وإلا فينزّل نسخة PortableGit مصغّرة ومستقلة (نحو 45 MB، من إصدار git-for-windows الرسمي) إلى %LOCALAPPDATA%\hermes\git. دون صلاحيات المسؤول، ودون تسجيل في سجل مُثبّتات Windows، ودون أي تداخل مع أي شيء آخر على الجهاز.
      5. يستنسخ المستودع إلى %LOCALAPPDATA%\hermes\hermes-agent وينشئ بيئة افتراضية (virtualenv) داخله.
      6. تنفيذ uv pip install على مستويات — يحاول أولًا .[all]، ثم يتراجع إلى مجموعات أصغر تدريجيًا ([messaging,dashboard,ext] → [messaging] → .) إذا تعثرت اعتمادية من نوع git+https بسبب حدّ المعدل (rate limit) في GitHub. يمنع ذلك نمط الإخفاق "إخفاق عابر واحد يُسقطك إلى تثبيت مجرد".
      7. يثبّت SDKs المراسلة تلقائيًا بناءً على .env — إذا وُجدت TELEGRAM_BOT_TOKEN / DISCORD_BOT_TOKEN / SLACK_BOT_TOKEN / SLACK_APP_TOKEN / WHATSAPP_ENABLED، فإنه ينفّذ python -m ensurepip --upgrade واستدعاءات pip install محددة كي يصبح SDK كل منصة قابلًا للاستيراد فعلًا.
      8. يضبط HERMES_GIT_BASH_PATH على مسار bash.exe الذي جرى تحديده، كي يعثر عليه Hermes بشكل حتمي في جلسات الـ shell الجديدة.
      9. يضيف %LOCALAPPDATA%\hermes\bin إلى User PATH ويضبط HERMES_HOME=%LOCALAPPDATA%\hermes — ما يتيح الأمر hermes (ويوجّهه إلى مجلد بياناتك) بعد أن تفتح طرفية جديدة. لا يُنسخ سوى المُشغِّلين hermes.exe / hermes-acp.exe إلى مجلد bin هذا؛ أما venv\Scripts بالكامل فهو لا يوضع في PATH عن قصد، كي لا يحجب Hermes أبدًا الأمر python الخاص بك.
      10. يشغّل hermes setup — معالج التشغيل الأول المعتاد (النموذج، والمزوّد، و toolsets). تخطَّه باستخدام -SkipSetup.
      تجنّب البحث عن المزوّدين على Windows

      في Windows، يُعد إعداد مفتاح API لكل أداة على حدة (Firecrawl و FAL و Browser Use و OpenAI TTS) الجزء الأكثر إرهاقًا في الحصول على وكيل مفيد. يغطي اشتراك Nous Portal النموذج و كل تلك الأدوات عبر تسجيل دخول واحد بـ OAuth. بعد انتهاء المُثبّت، نفّذ hermes setup --portal لربط كل شيء.

      مصفوفة الميزات​

      كل شيء يعمل أصليًا على Windows باستثناء لوحة الطرفية المضمّنة في لوحة التحكم.

      الميزةWindows الأصليWSL2
      CLI (hermes chat، hermes setup، hermes gateway، …)✓✓
      TUI التفاعلية (hermes --tui)✓✓
      Messaging gateway (Telegram و Discord و Slack و WhatsApp، وأكثر من 15 منصة)✓✓
      مُجدول Cron✓✓
      أداة المتصفح (Chromium عبر Node)✓✓
      خوادم MCP (stdio و HTTP)✓✓
      Ollama / LM Studio / llama-server المحلية✓✓ (عبر شبكة WSL)
      لوحة التحكم على الويب (الجلسات، والمهام، والمقاييس، والإعدادات)✓✓
      لوحة الطرفية المضمّنة في تبويب /chat بلوحة التحكم✗ (تتطلب POSIX PTY)✓
      التشغيل التلقائي عند تسجيل الدخول✓ (schtasks)✓ (systemd)

      يضمّن تبويب /chat في لوحة التحكم طرفية حقيقية عبر POSIX PTY (ptyprocess). لا يملك Windows الأصلي لبنة أساسية مكافئة؛ ومن الممكن استخدام pywinpty في Python / أو Windows ConPTY، لكن ذلك تنفيذ منفصل — فاعتبره من الأعمال المستقبلية. بقية لوحة التحكم تعمل أصليًا — ولا يعرض سوى ذلك التبويب لافتة "use WSL2 for this".

      كيف ينفّذ Hermes أوامر الـ shell على Windows​

      تنفّذ أداة الطرفية في Hermes الأوامر عبر Git Bash، وهي الاستراتيجية نفسها التي يتبعها Claude Code. يتفادى ذلك الفجوة بين POSIX و Windows دون إعادة كتابة كل أداة.

      ترتيب البحث عن bash.exe:

      1. متغير البيئة HERMES_GIT_BASH_PATH إذا كان مضبوطًا.
      2. %LOCALAPPDATA%\hermes\git\usr\bin\bash.exe (نسخة PortableGit التي يديرها المُثبّت).
      3. %LOCALAPPDATA%\hermes\git\bin\bash.exe (البنية الأقدم لـ Git-for-Windows).
      4. تثبيت Git-for-Windows على مستوى النظام (%ProgramFiles%\Git\bin\bash.exe، وما إلى ذلك).
      5. MSYS2 أو Cygwin أو أي bash.exe موجود في PATH كملاذ أخير.

      يضبط المُثبّت HERMES_GIT_BASH_PATH صراحةً كي لا تضطر جلسات PowerShell الجديدة إلى إعادة البحث. غيّر قيمته إذا أردت أن يستخدم Hermes نسخة bash محددة — مثل Git Bash المثبّت على نظامك، أو bash مستضاف في WSL عبر رابط رمزي (symlink).

      مأزق شائع: تختلف بنية MinGit عن مُثبّت Git-for-Windows الكامل — إذ يوجد bash ضمن usr\bin\bash.exe، وليس bin\bash.exe. يتحقق Hermes من كليهما. إذا كنت تفك أرشيف MinGit يدويًا، فتأكد من اختيار النسخة غير المعتمدة على busybox (MinGit-*-64-bit.zip، وليس MinGit-*-busybox*.zip) — فنُسخ busybox تأتي بـ ash بدلًا من bash وتفتقد معظم أدوات coreutils.

      وحدة التحكم بترميز UTF-8 على Windows​

      يستخدم stdio الافتراضي في Python على Windows صفحة الترميز النشطة لوحدة التحكم (عادةً cp1252 أو cp437). وتحتوي لافتة Hermes، وقائمة slash commands، وسجل الأدوات، ولوحات Rich، وأوصاف المهارات جميعها على محارف Unicode. ودون تدخّل، يؤدي أي منها إلى انهيار مع الخطأ UnicodeEncodeError: 'charmap' codec can't encode character….

      يوجد الحل في hermes_cli/stdio.py::configure_windows_stdio()، الذي يُستدعى مبكرًا في كل نقطة دخول (cli.py::main، hermes_cli/main.py::main، gateway/run.py::main). وهو:

      1. يحوّل صفحة ترميز وحدة التحكم إلى CP_UTF8 (65001) عبر kernel32.SetConsoleCP / SetConsoleOutputCP.
      2. يعيد ضبط sys.stdout / sys.stderr / sys.stdin على UTF-8 مع errors='replace'.
      3. يضبط PYTHONIOENCODING=utf-8 و PYTHONUTF8=1 (عبر setdefault، بحيث تكون الأولوية للقيم التي يحددها المستخدم صراحةً) كي ترث عمليات Python الفرعية ترميز UTF-8.
      4. يضبط EDITOR=notepad إذا لم يكن أيٌّ من EDITOR أو VISUAL مضبوطًا (راجع قسم المحرر أدناه).

      العملية idempotent (تكرارها لا يغيّر النتيجة). ولا تفعل شيئًا على الأنظمة غير Windows.

      إلغاء التفعيل: ضبط HERMES_DISABLE_WINDOWS_UTF8=1 في البيئة يُرجع السلوك إلى مسار stdio القديم بترميز cp1252. مفيد لتتبّع خطأ ترميز بطريقة التنصيف (bisect)؛ ومن غير المرجح أن يكون الإعداد الصحيح في التشغيل العادي.

      المحرر (Ctrl-X Ctrl-E، /edit)​

      قبل #21561، كان الضغط على Ctrl-X Ctrl-E أو كتابة /edit لا يفعل شيئًا على Windows دون أي رسالة. إذ تملك prompt_toolkit قائمة احتياطية مكتوبة في الكود بمسارات POSIX مطلقة (/usr/bin/nano، /usr/bin/pico، /usr/bin/vi، …) لا يمكن العثور عليها أبدًا على Windows — حتى مع تثبيت Git for Windows كاملًا.

      تضبط طبقة stdio الخاصة بـ Windows في Hermes الآن EDITOR=notepad كقيمة افتراضية. يأتي Notepad مع كل تثبيت لـ Windows ويعمل كمحرر حاجب (blocking) — إذ يبقى subprocess.call(["notepad", file]) منتظرًا حتى تُغلق النافذة.

      تبقى الأولوية لتخصيصات المستخدم (إذ يجري التحقق منها قبل setdefault):

      المحررأمر PowerShell
      VS Code$env:EDITOR = "code --wait"
      Notepad++$env:EDITOR = "'C:\Program Files\Notepad++\notepad++.exe' -multiInst -nosession"
      Neovim$env:EDITOR = "nvim"
      Helix$env:EDITOR = "hx"

      الخيار --wait في VS Code بالغ الأهمية — فمن دونه يعود المحرر فورًا ويتلقى Hermes محتوى فارغًا.

      اضبطه بشكل دائم في ملف PowerShell profile الخاص بك:

      # In $PROFILE
      $env:EDITOR = "code --wait"

      أو اضبطه كمتغير بيئة للمستخدم (User) في إعدادات النظام، كي تلتقطه كل جلسة shell جديدة.

      Ctrl+Enter لإدراج سطر جديد في CLI​

      يمرّر Windows Terminal المفتاحين Ctrl+Enter كتسلسل مفاتيح مخصص. يربطه Hermes بإجراء "insert newline" (إدراج سطر جديد) كي تتمكن من كتابة prompts متعددة الأسطر في CLI دون اللجوء إلى Esc ثم Enter. يعمل ذلك في Windows Terminal، وفي الطرفية المدمجة في VS Code، وفي أي مضيف حديث لوحدة التحكم في Windows يدعم تسلسلات الهروب VT.

      في وحدات تحكم cmd.exe القديمة، يتحول Ctrl+Enter إلى Enter عادي — استخدم Esc Enter بدلًا منه، أو انتقل إلى Windows Terminal (فهو مجاني ومثبّت افتراضيًا على Windows 11).

      تشغيل الـ gateway عند تسجيل الدخول إلى Windows​

      يستخدم hermes gateway install على Windows ميزة Scheduled Tasks مع مجلد Startup كبديل احتياطي — دون الحاجة إلى صلاحيات المسؤول.

      التثبيت​

      hermes gateway install

      ما يحدث في الخلفية:

      1. schtasks /Create /SC ONLOGON /RL LIMITED /TN Hermes_Gateway — يسجّل مهمة تعمل عند تسجيل دخولك بصلاحيات عادية (غير مرفوعة). دون أي نافذة UAC.
      2. إذا حُظر schtasks بواسطة نهج المجموعة (group policy)، فإنه يلجأ إلى كتابة مُشغِّل صغير Hermes_Gateway.vbs (يعمل مخفيًا عبر wscript.exe) في %APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup. النتيجة نفسها، بطريقة أقل أناقة قليلًا. يُستخدم VBScript بدلًا من اختصار cmd.exe لأن وحدة التحكم التي تُخصَّص عند تسجيل الدخول قد تتلقى حدث إغلاق يُنهي الـ gateway قبل أن يكتمل بدء تشغيله.
      3. يشغّل الـ gateway منفصلًا عبر pythonw.exe — وليس python.exe. لا يرتبط pythonw.exe بأي وحدة تحكم، ما يحصّنه ضد بثّ CTRL_C_EVENT من العمليات الشقيقة (وهي مشكلة حقيقية كانت تُنهي الـ gateway عندما تضغط Ctrl+C على أي شيء في مجموعة العمليات نفسها).

      الخيارات (flags) المستخدمة عند التشغيل: DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP | CREATE_NO_WINDOW | CREATE_BREAKAWAY_FROM_JOB.

      الإدارة​

      hermes gateway status      # Merged view: schtasks + Startup folder + running PID
      hermes gateway start       # Starts the scheduled task now
      hermes gateway stop        # Graceful SIGTERM equivalent (TerminateProcess via psutil)
      hermes gateway restart
      hermes gateway uninstall   # Removes schtasks entry, Startup shortcut, pid file

      الأمر hermes gateway status idempotent — استدعِه ألف مرة متتالية ولن يُنهي الـ gateway عن طريق الخطأ أبدًا. (قبل PR #21561 كان يفعل ذلك بصمت، بسبب تصادم os.kill(pid, 0) مع CTRL_C_EVENT على مستوى C — راجع "الآليات الداخلية لإدارة العمليات" أدناه إن كانت القصة تهمك.)

      لماذا لا نستخدم Windows Service؟​

      تتطلب الخدمات صلاحيات المسؤول لتثبيتها، وتربط دورة حياة الـ gateway بإقلاع الجهاز لا بتسجيل دخول المستخدم. ما يريده مستخدم Hermes المعتاد هو: تسجيل الدخول → الـ gateway متاح، تسجيل الخروج → الـ gateway متوقف. وهذا بالضبط ما تفعله Scheduled Tasks دون رفع الصلاحيات. إذا كنت تريد خدمة فعلًا، فاستخدم nssm أو sc create يدويًا — لكنك على الأرجح لا تحتاج إلى ذلك.

      بنية البيانات​

      المسارالمحتويات
      %LOCALAPPDATA%\hermes\hermes-agent\نسخة Git المسحوبة (checkout) + الـ venv. يمكنك حذفها بأمان عبر Remove-Item -Recurse ثم إعادة التثبيت.
      %LOCALAPPDATA%\hermes\git\PortableGit (فقط إذا جهّزه المُثبّت).
      %LOCALAPPDATA%\hermes\node\Node.js المحمول (فقط إذا جهّزه المُثبّت).
      %LOCALAPPDATA%\hermes\bin\المُشغِّلان hermes / hermes-acp وملف uv.exe الذي يديره Hermes (مدير Python الذي يستخدمه للتحديثات).
      %LOCALAPPDATA%\hermes\ (الجذر)إعداداتك، وبيانات المصادقة، والمهارات، والجلسات، والسجلات (config.yaml، .env، skills\، sessions\، logs\، …). تبقى بعد إعادة التثبيت.

      في Windows الأصلي، يضبط المُثبّت HERMES_HOME=%LOCALAPPDATA%\hermes، لذا تقع بياناتك والتثبيت القابل للاستبدال ضمن الجذر نفسه %LOCALAPPDATA%\hermes: فالتثبيت وبيئة التشغيل هما المجلدات الفرعية hermes-agent\ و git\ و node\ و bin\، بينما توجد ملفات بياناتك مباشرةً في %LOCALAPPDATA%\hermes. إعادة التثبيت لا تستبدل سوى النسخة المسحوبة hermes-agent\، لذا تبقى بياناتك سليمة — ولكن بما أن الاثنين يتشاركان الجذر نفسه، لا تنفّذ Remove-Item -Recurse %LOCALAPPDATA%\hermes إذا أردت الاحتفاظ ببياناتك؛ بل احذف المجلد الفرعي hermes-agent\ بدلًا من ذلك. بنية مجلد بياناتك مطابقة لبنية ~/.hermes في Linux، لذا يمكنك مزامنتها بين الأجهزة.

      تغيير HERMES_HOME: اضبط متغير البيئة ليشير إلى مجلد بيانات مختلف (مثل %USERPROFILE%\.hermes لمطابقة بنية Linux/WSL). يعمل ذلك بالطريقة نفسها كما في Linux.

      أداة المتصفح​

      تستخدم أداة المتصفح agent-browser (أداة مساعدة مكتوبة بـ Node) للتحكم في Chromium. على Windows:

      • يضع المُثبّت agent-browser في PATH عبر npm.
      • يلتقط shutil.which("agent-browser", path=...) ملف .cmd الوسيط تلقائيًا — إذ لا يستطيع CreateProcessW تنفيذ ملف shebang بلا امتداد، لذا يعتمد Hermes دائمًا على الـ wrapper .CMD. لا تستدعِ سكربت الـ shebang يدويًا؛ بل مرّ دائمًا عبر .cmd.
      • يُثبَّت Playwright Chromium تلقائيًا عند التشغيل الأول (npx playwright install chromium). وإذا فشل التثبيت، يعرض hermes doctor المشكلة مع تلميح لإصلاحها.

      تشغيل Hermes على Windows — ملاحظات عملية​

      PATH بعد التثبيت​

      يضيف المُثبّت %LOCALAPPDATA%\hermes\bin إلى User PATH الخاص بك عبر [Environment]::SetEnvironmentVariable. لا تلتقط الطرفيات المفتوحة مسبقًا هذا التغيير — افتح نافذة PowerShell جديدة (أو تبويبًا جديدًا في Windows Terminal) بعد التثبيت. أغلق الطرفية وأعد فتحها، ولا تنفّذ $env:PATH += … يدويًا ما لم تكن تعرف ما تفعله.

      للتحقق:

      Get-Command hermes        # should print C:\Users\<you>\AppData\Local\hermes\bin\hermes.exe
      hermes --version

      متغيرات البيئة​

      يحترم Hermes كلًا من $env:X (على نطاق العملية) ومتغيرات البيئة الخاصة بالمستخدم (User) (دائمة، تُضبط من System Properties → Environment Variables). ضبط مفاتيح API في %LOCALAPPDATA%\hermes\.env (مجلد HERMES_HOME الخاص بك) هو المسار المعتاد — كما في Linux:

      OPENROUTER_API_KEY=sk-or-...
      TELEGRAM_BOT_TOKEN=...

      لا تضع الأسرار (secrets) في متغيرات البيئة الخاصة بالمستخدم إلا إذا كنت تريد تحديدًا أن تراها كل عملية في Windows (وهذا ليس ما تريده).

      متغيرات البيئة الخاصة بـ Windows​

      لا تؤثر هذه المتغيرات إلا على تثبيتات Windows الأصلية:

      المتغيرالتأثير
      HERMES_GIT_BASH_PATHيتجاوز آلية البحث عن bash.exe. وجّهه إلى أي bash — Git-for-Windows الكامل، أو bash الخاص بـ WSL عبر رابط رمزي، أو MSYS2، أو Cygwin. يضبطه المُثبّت تلقائيًا.
      HERMES_DISABLE_WINDOWS_UTF8اضبطه على 1 لتعطيل طبقة stdio بترميز UTF-8 والرجوع إلى صفحة الترميز المحلية. مفيد لتتبّع خطأ ترميز بطريقة التنصيف (bisect).
      EDITOR / VISUALالمحرر الذي تستخدمه مع /edit و Ctrl-X Ctrl-E. يستخدم Hermes افتراضيًا notepad إذا لم يكن أيٌّ منهما مضبوطًا.

      إلغاء التثبيت​

      من PowerShell:

      hermes uninstall

      هذا هو المسار النظيف — يزيل مُدخل schtasks، واختصار مجلد Startup، وملف hermes.cmd الوسيط، ويحذف %LOCALAPPDATA%\hermes\hermes-agent\، وينظّف User PATH. ويترك بقية محتويات %LOCALAPPDATA%\hermes\ دون مساس (إعداداتك، وبيانات المصادقة، والمهارات، والجلسات، والسجلات) تحسبًا لإعادة التثبيت.

      لحذف كل شيء نهائيًا:

      hermes uninstall
      Remove-Item -Recurse -Force "$env:LOCALAPPDATA\hermes"
      # Also remove a legacy CLI/WSL data dir if you ever used one:
      Remove-Item -Recurse -Force "$env:USERPROFILE\.hermes"

      يتعامل الأمر الفرعي hermes uninstall في CLI أيضًا مع الحالة التي يكون فيها مُدخل schtasks مسجّلًا تحت اسم مهمة مختلف (في التثبيتات الأقدم) — إذ يبحث حسب مسار التثبيت بدلًا من اسم مهمة ثابت في الكود.

      الآليات الداخلية لإدارة العمليات​

      هذه مادة خلفية — تخطَّها ما لم تكن تتتبّع خللًا غريبًا من نوع "إنه يُنهي نفسه".

      في Linux و macOS، يُعد التعبير الاصطلاحي في POSIX os.kill(pid, 0) فحصًا للصلاحيات لا يُحدث أي أثر: "هل هذا الـ PID حي، وهل يمكنني إرسال إشارة إليه؟" أما في Windows، فيربط os.kill في Python القيمة sig=0 بـ CTRL_C_EVENT — إذ يتصادمان عند القيمة العددية 0 — ويمرّرها عبر GenerateConsoleCtrlEvent(0, pid)، الذي يبث Ctrl+C إلى مجموعة عمليات وحدة التحكم بأكملها التي تضم الـ PID المستهدف. هذه هي المشكلة bpo-14484، المفتوحة منذ 2012. ولن تُصلح لأن تغيير هذا السلوك سيُعطّل السكربتات التي تعتمد عليه حاليًا.

      النتيجة: أي مسار في الكود كان "يتحقق مما إذا كان هذا الـ PID حيًا" عبر os.kill(pid, 0) على Windows كان يُنهي العملية المستهدفة بصمت. نقل Hermes كل موضع من هذا النوع (14 موضعًا عبر 11 ملفًا) إلى gateway.status._pid_exists()، الذي يستخدم psutil.pid_exists() (والذي يستخدم بدوره OpenProcess + GetExitCodeProcess على Windows — دون أي إشارات). إذا كنت تكتب إضافة (plugin) أو تعديلًا (patch)، فاستخدم psutil.pid_exists() مباشرةً أو gateway.status._pid_exists() — ولا تستخدم os.kill(pid, 0) أبدًا.

      يفرض scripts/check-windows-footguns.py هذه القاعدة في CI: أي استدعاء جديد لـ os.kill(pid, 0) يُفشل الفحص Windows footguns (blocking) ما لم يحمل السطر العلامة # windows-footgun: ok — <reason>.

      مآزق شائعة​

      ظهور hermes: command not found مباشرةً بعد التثبيت. افتح نافذة PowerShell جديدة. أضاف المُثبّت %LOCALAPPDATA%\hermes\bin إلى User PATH، لكن جلسات الـ shell المفتوحة مسبقًا تحتاج إلى إعادة تشغيل كي تلتقط التغيير. وفي هذه الأثناء يمكنك تنفيذ & "$env:LOCALAPPDATA\hermes\bin\hermes.exe".

      ظهور WinError 193: %1 is not a valid Win32 application عند تشغيل أداة. لقد صادفت استدعاءً لسكربت shebang تجاوز الملف الوسيط .cmd. يحدد Hermes مسارات الأوامر عبر shutil.which(cmd, path=local_bin) بحيث يلتقط PATHEXT الامتداد .CMD — فإذا كنت تستدعي الأداة عبر مسار مكتوب مباشرةً في الكود، فانتقل إلى نسخة .cmd (مثلًا npx.cmd، وليس npx).

      فشل [scriptblock]::Create(...) مع الخطأ The assignment expression is not valid. التقط ملف install.ps1 الذي نزّلته علامة BOM بترميز UTF-8. تزيل صيغة irm | iex علامات BOM تلقائيًا؛ أما [scriptblock]::Create((irm ...)) فلا تفعل. أعد التنفيذ باستخدام الصيغة البسيطة irm | iex، أو نزّل السكربت يدويًا واحفظه دون BOM عبر [IO.File]::WriteAllText($path, $text, (New-Object Text.UTF8Encoding $false)).

      الـ gateway لا يبقى قيد التشغيل بعد إعادة التشغيل. تحقق من hermes gateway status — فهو يجمع بين مُدخل schtasks، واختصار مجلد Startup (إن كان مستخدمًا)، والـ PID الحي. إذا كانت مهمة schtasks مسجّلة لكنها لا تعمل، فقد يكون نهج المجموعة (group policy) يحظر مشغّلات ONLOGON. نفّذ schtasks /Query /TN Hermes_Gateway /V /FO LIST (أو Hermes_Gateway_<profile> لـ profile مسمّى) لمعرفة سبب فشل المهمة. لا يُفعَّل البديل الاحتياطي عبر مجلد Startup تلقائيًا إلا عندما يفشل schtasks نفسه في تسجيل المهمة؛ ولا يوجد متغير بيئة أو خيار لفرضه.

      لا يزال /edit لا يفعل شيئًا بعد ضبط $env:EDITOR. لقد ضبطته للعملية الحالية فقط؛ أغلق الـ shell وأعد فتحه، أو اضبطه على نطاق المستخدم (User) من System Properties → Environment Variables. تحقق بتنفيذ echo $env:EDITOR في نافذة PowerShell جديدة.

      أداة المتصفح تبدأ العمل لكن الأدوات تنتهي مهلتها. يُثبَّت Chromium تلقائيًا عند التشغيل الأول. إذا فشل التثبيت (بسبب حدّ المعدل في GitHub، أو عطل عابر في CDN الخاص بـ Playwright)، فنفّذ hermes doctor — إذ سيكشف غياب Chromium ويطبع الأمر الدقيق npx playwright install chromium لإصلاح المشكلة.

      فشل agent-browser مع خطأ غريب متعلق بإصدار Node. يجهّز المُثبّت Node 26 في %LOCALAPPDATA%\hermes\node، لكن قد يأتي في PATH لديك إصدار Node 18 أقدم مثبّت على النظام قبله. إما أن تنقل مجلد node الخاص بـ Hermes إلى موضع أسبق في PATH، أو أن تحذف تثبيت النظام إذا كنت لا تستخدم Node في مكان آخر.

      تظهر المحارف الصينية / اليابانية / العربية على شكل ? في CLI. لم تُفعَّل طبقة stdio بترميز UTF-8. تحقق من أن HERMES_DISABLE_WINDOWS_UTF8 غير مضبوط (Get-ChildItem env:HERMES_DISABLE_WINDOWS_UTF8). إذا كان فارغًا وما زلت ترى ?، فقد لا يدعم مضيف وحدة التحكم (cmd.exe القديم جدًا) ترميز UTF-8 إطلاقًا — انتقل إلى Windows Terminal.

      لا يستطيع الـ gateway إرسال صور Telegram — "BadRequest: payload contains invalid characters". لا علاقة لهذه المشكلة بـ Windows، لكنها تظهر أحيانًا هناك أولًا. وتعني عادةً أن مسار ملفك يحتوي على شرطات مائلة عكسية غير مُهرَّبة داخل جسم JSON. يُفترض أن يتلقى Telegram مسارات يوحّدها Hermes، لا مسارات Windows خامًا — فإذا ظهر لك هذا داخل إضافة (plugin) مخصصة، فتأكد من أنك تمرّر المسار الذي يوفّره Hermes، وليس str(Path(...)) من مُدخلات المستخدم.

      غرائب ترميز من نوع "يعمل على جهازي الآخر" بعد git pull. إذا عدّلت إعدادات Hermes أو إحدى المهارات على Windows باستخدام محرر لا يعتمد UTF-8 (مثل Notepad في إصدارات Windows الأقدم، أو بعض محررات الإدخال الصينية IMEs)، فربما حُفظ الملف مع BOM. يتسامح Hermes مع utf-8-sig في معظم عمليات قراءة الإعدادات، لكن وجود BOM داخل قيمة YAML مطوية (description: >) يُعطّل تحليل YAML بصمت. أعد حفظ الملف بترميز UTF-8 عادي دون BOM.

      إلى أين بعد ذلك​

      • التثبيت — صفحة التثبيت الكاملة، بما في ذلك Linux/macOS/WSL2/Termux.

      • مرجع CLI — كل أمر فرعي من أوامر hermes.
      • الأسئلة الشائعة — الأسئلة الشائعة غير المقتصرة على Windows.
