      صيغة Trajectory

      يحفظ Hermes Agent مسارات المحادثة (trajectories) بصيغة JSONL متوافقة مع ShareGPT لاستخدامها كبيانات تدريب، ومُخرَجات لتصحيح الأخطاء، ومجموعات بيانات للتعلّم المعزَّز (reinforcement learning).

      ملفات المصدر: agent/trajectory.py، و agent/session_persistence.py (ابحث عن _save_trajectory)، و batch_runner.py

      قاعدة تسمية الملفات​

      تُكتب مسارات المحادثة (trajectories) إلى ملفات في مجلد العمل الحالي:

      الملفمتى
      trajectory_samples.jsonlالمحادثات التي اكتملت بنجاح (completed=True)
      failed_trajectories.jsonlالمحادثات التي فشلت أو انقطعت (completed=False)

      يكتب مُشغّل الدُفعات (batch runner) (batch_runner.py) إلى ملف مُخرَج مخصّص لكل دُفعة (مثال: batch_001_output.jsonl) مع حقول بيانات وصفية إضافية.

      يمكنك تجاوز اسم الملف عبر المعامل filename في save_trajectory().

      صيغة مُدخل JSONL​

      كل سطر في الملف هو كائن JSON قائم بذاته. هناك صيغتان:

      صيغة CLI/التفاعلية (من _save_trajectory)​

      {
        "conversations": [ ... ],
        "timestamp": "2026-03-30T14:22:31.456789",
        "model": "anthropic/claude-sonnet-4.6",
        "completed": true
      }

      صيغة Batch Runner (من batch_runner.py)​

      {
        "prompt_index": 42,
        "conversations": [ ... ],
        "metadata": { "prompt_source": "gsm8k", "difficulty": "hard" },
        "completed": true,
        "partial": false,
        "api_calls": 7,
        "toolsets_used": ["code_tools", "file_tools"],
        "tool_stats": {
          "terminal": {"count": 3, "success": 3, "failure": 0},
          "read_file": {"count": 2, "success": 2, "failure": 0},
          "write_file": {"count": 0, "success": 0, "failure": 0}
        },
        "tool_error_counts": {
          "terminal": 0,
          "read_file": 0,
          "write_file": 0
        }
      }

      يتم تطبيع (normalize) قواميس tool_stats و tool_error_counts لتشمل جميع الأدوات الممكنة (من model_tools.TOOL_TO_TOOLSET_MAP) بقيم افتراضية صفرية، بما يضمن مخططًا متسقًا عبر المُدخلات عند تحميل مجموعات بيانات HuggingFace.

      مصفوفة المحادثات (صيغة ShareGPT)​

      تستخدم مصفوفة conversations اصطلاحات الأدوار الخاصة بـ ShareGPT:

      دور APIfrom في ShareGPT
      system"system"
      user"human"
      assistant"gpt"
      tool"tool"

      مثال كامل​

      {
        "conversations": [
          {
            "from": "system",
            "value": "You are a function calling AI model. You are provided with function signatures within <tools> </tools> XML tags. You may call one or more functions to assist with the user query. If available tools are not relevant in assisting with user query, just respond in natural conversational language. Don't make assumptions about what values to plug into functions. After calling & executing the functions, you will be provided with function results within <tool_response> </tool_response> XML tags. Here are the available tools:\n<tools>\n[{\"name\": \"terminal\", \"description\": \"Execute shell commands\", \"parameters\": {\"type\": \"object\", \"properties\": {\"command\": {\"type\": \"string\"}}}, \"required\": null}]\n</tools>\nFor each function call return a JSON object, with the following pydantic model json schema for each:\n{'title': 'FunctionCall', 'type': 'object', 'properties': {'name': {'title': 'Name', 'type': 'string'}, 'arguments': {'title': 'Arguments', 'type': 'object'}}, 'required': ['name', 'arguments']}\nEach function call should be enclosed within <tool_call> </tool_call> XML tags.\nExample:\n<tool_call>\n{'name': <function-name>,'arguments': <args-dict>}\n</tool_call>"

          {
            "from": "human",
            "value": "What Python version is installed?"
          },
          {
            "from": "gpt",
            "value": "<think>\nThe user wants to know the Python version. I should run python3 --version.\n</think>\n<tool_call>\n{\"name\": \"terminal\", \"arguments\": {\"command\": \"python3 --version\"}}\n</tool_call>"
          },
          {
            "from": "tool",
            "value": "<tool_response>\n{\"tool_call_id\": \"call_abc123\", \"name\": \"terminal\", \"content\": \"Python 3.11.6\"}\n</tool_response>"

        "model": "anthropic/claude-sonnet-4.6",
        "completed": true
      }

      قواعد التطبيع (Normalization)​

      وسم محتوى الاستدلال (Reasoning)​

      يُطبّع محوّل مسار المحادثة (trajectory converter) كل الاستدلال (reasoning) إلى وسوم <think>، بصرف النظر عن الطريقة التي أنتج بها النموذج ذلك أصلًا:

      1. tokens الاستدلال الأصلية (native) (حقل msg["reasoning"] من مزوّدين مثل Anthropic، وسلسلة OpenAI o): تُغلَّف بالشكل <think>\n{reasoning}\n</think>\n وتُضاف قبل المحتوى.

      2. REASONING_SCRATCHPAD بصيغة XML (عندما يكون الاستدلال الأصلي مُعطَّلًا ويستدل النموذج عبر XML موجَّه من system prompt): تُحوَّل وسوم <REASONING_SCRATCHPAD> إلى <think> عبر convert_scratchpad_to_think().

      3. كتل think فارغة: كل دور من نوع gpt مضمون أن يحتوي على كتلة <think>. إن لم يُنتَج أي استدلال، تُدرَج كتلة فارغة: <think>\n</think>\n — وهذا يضمن صيغة متسقة لبيانات التدريب.

      تطبيع استدعاء الأدوات​

      تُحوَّل استدعاءات الأدوات من صيغة API (التي تتضمّن tool_call_id، واسم الدالة، والمعاملات كسلسلة JSON) إلى JSON مُغلَّف بـ XML:

      <tool_call>
      {"name": "terminal", "arguments": {"command": "ls -la"}}
      </tool_call>
      • تُحلَّل المعاملات من سلاسل JSON إلى كائنات (دون ترميز مزدوج)
      • إذا فشل تحليل JSON (وهذا لا ينبغي أن يحدث — إذ يُتحقَّق منه أثناء المحادثة)، تُستخدم قيمة فارغة {} مع تسجيل تحذير
      • استدعاءات الأدوات المتعددة في دور واحد للمساعد تُنتج كتل <tool_call> متعددة في رسالة gpt واحدة

      تطبيع استجابة الأدوات​

      تُجمَّع كل نتائج الأدوات التي تلي رسالة المساعد في دور tool واحد مع استجابات JSON مُغلَّفة بـ XML:

      <tool_response>
      {"tool_call_id": "call_abc123", "name": "terminal", "content": "output here"}
      </tool_response>
      • إذا بدا محتوى الأداة على شكل JSON (يبدأ بـ { أو [)، يُحلَّل بحيث يحتوي حقل المحتوى على كائن/مصفوفة JSON بدلًا من سلسلة نصية
      • تُدمَج نتائج الأدوات المتعددة بأسطر جديدة في رسالة واحدة
      • تُطابَق أسماء الأدوات حسب الموقع مقابل مصفوفة tool_calls الخاصة برسالة المساعد الأصلية

      رسالة System​

      تُنشَأ رسالة System عند وقت الحفظ (وليست مأخوذة من المحادثة). وهي تتبع قالب prompt الخاص باستدعاء الدوال في Hermes، وتتضمّن:

      • مقدّمة تشرح بروتوكول استدعاء الدوال
      • كتلة XML من نوع <tools> تحتوي على تعريفات أدوات JSON
      • مرجع المخطط لكائنات FunctionCall
      • مثال <tool_call>

      تتضمّن تعريفات الأدوات name و description و parameters و required (تُضبَط على null لمطابقة الصيغة القياسية).

      تحميل مسارات المحادثة (Trajectories)​

      مسارات المحادثة هي ملفات JSONL قياسية — حمّلها بأي أداة قراءة لصيغة JSON-lines:

      import json

      def load_trajectories(path: str):
          """Load trajectory entries from a JSONL file."""
          entries = []
          with open(path, "r", encoding="utf-8") as f:
              for line in f:
                  line = line.strip()
                  if line:
                      entries.append(json.loads(line))
          return entries

      # Filter to successful completions only
      successful = [e for e in load_trajectories("trajectory_samples.jsonl")
                    if e.get("completed")]

      # Extract just the conversations for training
      training_data = [e["conversations"] for e in successful]

      التحميل لمجموعات بيانات HuggingFace​

      from datasets import load_dataset

      ds = load_dataset("json", data_files="trajectory_samples.jsonl")

      يضمن مخطط tool_stats المُطبَّع أن تحتوي كل المُدخلات على الأعمدة نفسها، مما يمنع أخطاء عدم تطابق مخطط Arrow أثناء تحميل مجموعة البيانات.

      التحكّم في حفظ مسار المحادثة (Trajectory)​

      حفظ مسار المحادثة (Trajectory) هو مفتاح تبديل على مستوى run_agent.py / المكتبة — لا تعرض واجهة CLI الخاصة بـ hermes مفتاح إعداد أو علامة (flag) لذلك:

      python run_agent.py --save_trajectories --query='your question here'

      أو برمجيًا: AIAgent(..., save_trajectories=True) / initialize_agent(..., save_trajectories=True). عند التفعيل، يُستدعى التابع _save_trajectory() في نهاية كل دور من أدوار المحادثة.

      يحفظ مُشغّل الدُفعات (batch runner) مسارات المحادثة دائمًا (فهذا هو غرضه الأساسي).

      العيّنات (samples) التي لا تحتوي على أي استدلال عبر كل الأدوار تُستبعَد تلقائيًا بواسطة مُشغّل الدُفعات لتجنّب تلويث بيانات التدريب بأمثلة بلا استدلال.
