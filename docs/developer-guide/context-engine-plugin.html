      بناء إضافة Context Engine

      تستبدل إضافات محرك السياق (context engine) المكوّن المدمج ContextCompressor باستراتيجية بديلة لإدارة سياق المحادثة. ومن أمثلة ذلك محرك Lossless Context Management (LCM) الذي يبني DAG معرفيًا بدلًا من التلخيص الذي يفقد جزءًا من المعلومات.

      آلية العمل​

      تقوم إدارة السياق لدى الوكيل على الفئة المجردة (ABC) ContextEngine (agent/context_engine.py). والمكوّن المدمج ContextCompressor هو التطبيق الافتراضي لها، ويجب على المحركات المقدَّمة عبر الإضافات أن تطبّق الواجهة نفسها.

      لا يمكن تفعيل أكثر من محرك سياق واحد في الوقت نفسه، ويتحدد الاختيار عبر الإعدادات:

      # config.yaml
      context:
        engine: "compressor"    # default built-in
        engine: "lcm"           # activates a plugin engine named "lcm"

      لا تُفعَّل المحركات المقدَّمة عبر الإضافات تلقائيًا أبدًا — إذ يجب على المستخدم ضبط context.engine صراحةً على اسم الإضافة.

      بنية المجلدات​

      يوجد كل محرك سياق في plugins/context_engine/<name>/:

      plugins/context_engine/lcm/
      ├── __init__.py      # exports the ContextEngine subclass
      ├── plugin.yaml      # metadata (name, description, version)
      └── ...              # any other modules your engine needs

      الفئة المجردة ContextEngine​

      يجب أن يطبّق محركك هذه الدوال الإلزامية:

      from agent.context_engine import ContextEngine

      class LCMEngine(ContextEngine):

          @property
          def name(self) -> str:
              """Short identifier, e.g. 'lcm'. Must match config.yaml value."""
              return "lcm"

          def update_from_response(self, usage: dict) -> None:
              """Called after every LLM call with the usage dict.

              Update self.last_prompt_tokens, self.last_completion_tokens,
              self.last_total_tokens from the response.
              """

          def should_compress(self, prompt_tokens: int = None) -> bool:
              """Return True if compaction should fire this turn."""

          def compress(self, messages: list, current_tokens: int = None,
                       focus_topic: str = None) -> list:
              """Compact the message list and return a new (possibly shorter) list.

              The returned list must be a valid OpenAI-format message sequence.

              ``focus_topic`` is an optional topic string from manual
              ``/compress <focus>``; engines that support guided compression should
              prioritise preserving information related to it, others may ignore it.
              """

      خصائص الفئة التي يجب أن يحافظ عليها محركك​

      يقرأ الوكيل هذه الخصائص مباشرةً لأغراض العرض والتسجيل:

      last_prompt_tokens: int = 0
      last_completion_tokens: int = 0
      last_total_tokens: int = 0
      threshold_tokens: int = 0        # when compression triggers
      context_length: int = 0          # model's full context window
      compression_count: int = 0       # how many times compress() has run

      الدوال الاختيارية​

      لهذه الدوال قيم افتراضية معقولة في الفئة المجردة، فأعد تعريفها (override) حسب الحاجة:

      الدالةالسلوك الافتراضيمتى تعيد تعريفها
      on_session_start(session_id, **kwargs)لا تفعل شيئًا (No-op)عندما تحتاج إلى تحميل حالة محفوظة (DAG، قاعدة بيانات)
      on_session_end(session_id, messages)لا تفعل شيئًاعندما تحتاج إلى حفظ الحالة وإغلاق الاتصالات
      on_session_reset()تعيد ضبط عدّادات الـ tokenعندما تكون لديك حالة خاصة بكل جلسة تحتاج إلى مسحها
      update_model(model, context_length, ...)تحدّث context_length والعتبة (threshold)عندما تحتاج إلى إعادة حساب الميزانيات عند تبديل النموذج
      get_tool_schemas()تُرجع []عندما يوفّر محركك أدوات يستدعيها الوكيل (مثل lcm_grep)
      handle_tool_call(name, args, **kwargs)تُرجع JSON يحمل خطأعندما تطبّق معالجات الأدوات
      should_compress_preflight(messages)تُرجع Falseعندما يمكنك إجراء تقدير منخفض التكلفة قبل استدعاء API
      get_status()قاموس قياسي للـ token والعتبةعندما تكون لديك مقاييس مخصصة تريد إتاحتها
      select_context(request_messages, *, conversation_messages, incoming_message, budget_tokens)تُرجع None (لا تفعل شيئًا)عندما تختار أو توجّه السياق الذي يدخل في هذا الطلب (الاسترجاع، التوجيه حسب الموضوع) — انظر أدناه
      on_turn_complete(messages, usage=None, **kwargs)لا تفعل شيئًاعندما تستوعب الدور المكتمل أو تفهرسه أو تراقبه — انظر أدناه

      اختيار السياق ومراقبته في كل دور​

      تجيب compress() عن حالة "السياق طويل جدًا ← اجعله أقصر". أما المحور المستقل الخاص بـالاختيار / المراقبة فيغطيه اثنان من الـ hooks الاختيارية التي لا تفعل شيئًا افتراضيًا، فلم يعد المحرك مضطرًا إلى إجبار should_compress() على إرجاع True وإساءة استخدام compress() كـ callback يُستدعى في كل دور:

      def select_context(self, request_messages, *, conversation_messages=None,
                         incoming_message=None, budget_tokens=0):
          """Choose/replace the context for THIS request, before dispatch.

          Return a new message list to use for this one provider call (retrieval,
          topic routing, role/branch switching), or None to leave it unchanged.
          Request-only: the persisted conversation history is never mutated.
          """

      def on_turn_complete(self, messages, usage=None, **kwargs):
          """Observe a finished turn after the assistant/tool loop completes.

          Receives a shallow copy of the finalized transcript plus the turn's
          canonical usage dict (or None if no provider response was reached), so the
          engine can ingest/index/summarize for the next select_context(). The return
          value is ignored.
          """

      العقد:

      • لا تفعل شيئًا افتراضيًا، وتفشل بشكل مفتوح (fail-open). تنفّذ كلتاهما افتراضيًا return None. وغياب الـ hook أو حدوث استثناء أو إرجاع قيمة غير صالحة يترك الطلب دون تغيير — فلا يكون المحرك الفاشل أسوأ أبدًا من عدم تثبيت أي محرك. كما يتحقق المضيف من هوية الدالة للتعرّف على التطبيق الافتراضي الموروث من الفئة المجردة ويتخطاه كليًا، فلا تتحمل المحركات التي لا تطبّقها (بما فيها الضاغط المدمج) أي عمل إضافي في كل طلب.
      • select_context() تقتصر على الطلب. تستبدل القائمة المُرجَعة الرسائل في استدعاء واحد للمزوّد، ولا يُكتب أي شيء في السجل المحفوظ أبدًا. وإرجاع None أو [] أو قيمة ليست قائمة أو قائمة تحتوي على عناصر ليست قواميس يؤدي كله إلى الفشل المفتوح وإرسال الطلب دون تعديل.
      • الترتيب / استقرار التخزين المؤقت (cache). يعمل الـ hook قبل ضبط التخزين المؤقت للـ prompt وقبل كل أدوات تنقية الطلب، وبذلك (أ) يمر البديل بالتحقق نفسه الذي يمر به أي طلب، و(ب) يترك السلوك الافتراضي الطلب مطابقًا بايتًا ببايت — فلا يتغير سلوك التخزين المؤقت للـ prompt في المحركات التي لا تطبّقه. والمحرك الذي يستبدل القائمة لا يغيّر إلا بادئة التخزين المؤقت الخاصة به. ويُقيَّم الـ hook مع كل طلب إلى المزوّد (ويُعاد تشغيله عند إعادة المحاولة).
      • on_turn_complete() مخصصة لمراقبة ما بعد الدور فقط؛ فتعامل مع messages على أنها للقراءة فقط. التغطية بأفضل جهد: إذ تُطلَق من نقطة إنهاء الدور القياسية. وبعض مسارات الإرجاع المبكر غير الاعتيادية في الحلقة (مثل الحظر بسبب سياسة المحتوى أو فشل نهائي لدى المزوّد) تحفظ النتيجة وتعود دون المرور بمرحلة الإنهاء، فلا تُطلق هذا الـ hook حاليًا — لذا تعامل معه على أنه مراقبة بأفضل جهد للأدوار المكتملة، لا callback مضمون عند كل خروج مبكر. أما توحيد جميع المسارات النهائية خلف نقطة إنهاء واحدة فهو عمل لاحق منفصل.

      متى تستخدم هذه الـ hooks — ومتى لا تستخدمها​

      • لا تطبّق select_context() إلا عندما يتعين على محركك أن يستبدل السياق الخاص بكل طلب — كالاختيار المعزز بالاسترجاع، أو التوجيه حسب الموضوع أو الفرع، أو تبديل الأدوار. فهي الوسيلة الوحيدة التي يمكنها تبديل الرسائل التي تدخل في الطلب: أما الـ hook الخاص بالإضافات pre_llm_call فيقتصر على الحقن بحكم تصميمه الموثّق (إذ يُلحق المحتوى برسالة المستخدم ولا يعيد كتابة القائمة أبدًا، حفاظًا على بادئة التخزين المؤقت للـ prompt). وإن لم تكن بحاجة إلى الاستبدال، فلا تطبّقها.
      • إذا كانت إضافتك تحتاج فقط إلى مراقبة ما بعد الدور أو استيعابه (الفهرسة، مزامنة الذاكرة، التحليلات)، فطبّق مزوّد ذاكرة (sync_turn() — راجع إضافات مزوّدي الذاكرة) بدلًا من محرك سياق. فمحرك السياق يتولى سياسة الضغط (compaction) الخاصة بالجلسة، بينما يراقب مزوّد الذاكرة الأدوار دون أن يتولى أي شيء. وتوجد on_turn_complete() بوصفها نظير المراقبة للمحركات التي تحتاج أصلًا إلى select_context() — كي يتعلم المكوّن نفسه من الدور الذي وجّهه للتو — لا بوصفها callback عامة الغرض لكل دور.
      • أثر select_context() الفعلية على التخزين المؤقت للـ prompt. الاختيار الذي يغيّر شيئًا فعلًا يغيّر بطبيعة الحال بادئة التخزين المؤقت للـ prompt في الأدوار التي يتغير فيها الاختيار — إذ لم تعد بادئة ذلك الطلب مطابقة للبادئة المخزنة لدى المزوّد، فتعيد تلك الأدوار كتابة الـ cache بدلًا من القراءة منه. لذا ينبغي للمحركات أن تُرجع اختيارات ثابتة عندما لا يتغير شيء (الكائن نفسه أو قائمة مساوية)، وألا تعيد تشكيل السياق إلا عندما يختلف قرار التوجيه فعلًا؛ فالاختيار الذي يتبدل عشوائيًا في كل دور يُضيّع بصمت فرصة إعادة استخدام الـ cache في كل دور.

      أدوات المحرك​

      يمكن لمحركات السياق إتاحة أدوات يستدعيها الوكيل مباشرةً. أرجِع المخططات (schemas) من get_tool_schemas() وعالج الاستدعاءات في handle_tool_call():

      def get_tool_schemas(self):
          return [{
              "name": "lcm_grep",
              "description": "Search the context knowledge graph",
              "parameters": {
                  "type": "object",
                  "properties": {
                      "query": {"type": "string", "description": "Search query"}
                  },
                  "required": ["query"],
              },
          }]

      def handle_tool_call(self, name, args, **kwargs):
          if name == "lcm_grep":
              results = self._search_dag(args["query"])
              return json.dumps({"results": results})
          return json.dumps({"error": f"Unknown tool: {name}"})

      تُحقن أدوات المحرك في قائمة أدوات الوكيل عند بدء التشغيل وتُوجَّه استدعاءاتها تلقائيًا — دون حاجة إلى تسجيلها في السجل (registry).

      التسجيل​

      عبر المجلد (موصى به)​

      ضع محركك في plugins/context_engine/<name>/. يجب أن يصدّر الملف __init__.py فئة فرعية من ContextEngine، وسيعثر عليها نظام الاكتشاف وينشئ نسخة منها تلقائيًا.

      عبر نظام الإضافات العام​

      يمكن لإضافة عامة أيضًا أن تسجّل محرك سياق:

      def register(ctx):
          engine = LCMEngine(context_length=200000)
          ctx.register_context_engine(engine)

      لا يمكن تسجيل أكثر من محرك واحد، وتُرفض أي محاولة تسجيل من إضافة ثانية مع إصدار تحذير.

      دورة الحياة​

      1. Engine instantiated (plugin load or directory discovery)
      2. on_session_start() — conversation begins
      3. update_from_response() — after each API call
      4. should_compress() — checked each turn
      5. compress() — called when should_compress() returns True
      6. on_session_end() — session boundary (CLI exit, /reset, gateway shutdown)

      تُستدعى on_session_reset() عند تنفيذ /new أو /reset لمسح الحالة الخاصة بالجلسة دون إيقاف كامل.

      الإعدادات​

      يختار المستخدمون محركك عبر hermes plugins → Provider Plugins → Context Engine، أو بتعديل config.yaml:

      context:
        engine: "lcm"   # must match your engine's name property

      كتلة الإعدادات compression (compression.threshold وcompression.protect_last_n وغيرها) خاصة بالمكوّن المدمج ContextCompressor، مع استثناء صريح واحد: compression.model_thresholds (تجاوزات العتبة لكل نموذج) جزء من عقد محرك السياق. إذ يُسند المضيف الخريطة المحسومة إلى engine.model_thresholds قبل الاستدعاء الأول لـ update_model()، وتطبّقها update_model() في الفئة الأساسية (بأطول تطابق لسلسلة فرعية، مع الرجوع إلى العتبة المضبوطة للمحرك احتياطيًا). أما المحركات التي تعيد تعريف update_model() فتتولى سياسة الضغط الخاصة بها، ولها أن تلتزم بالخريطة أو تتجاهلها — استخدم from agent.context_compressor import resolve_model_threshold لإعادة استخدام منطق الحسم نفسه. وفي كل ما عدا ذلك، ينبغي لمحركك أن يعرّف صيغة إعدادات خاصة به عند الحاجة، ويقرأها من config.yaml أثناء التهيئة.

      الاختبار​

      from agent.context_engine import ContextEngine

      def test_engine_satisfies_abc():
          engine = YourEngine(context_length=200000)
          assert isinstance(engine, ContextEngine)
          assert engine.name == "your-name"

      def test_compress_returns_valid_messages():
          engine = YourEngine(context_length=200000)
          msgs = [{"role": "user", "content": "hello"}]
          result = engine.compress(msgs)
          assert isinstance(result, list)
          assert all("role" in m for m in result)

      راجع tests/agent/test_context_engine.py للاطلاع على مجموعة الاختبارات الكاملة لعقد الفئة المجردة.

      الأمان مع تعدد الخيوط (Thread safety)​

      عندما يكون compression.context_timeout_seconds > 0 (وهو الافتراضي)، يشغّل Hermes عملية الضغط بأكملها — بما فيها compress() الخاصة بمحركك وعمليات الـ callback عند الحدود، وأي on_pre_compress / on_session_switch لدى مزوّد الذاكرة — على خيط daemon من مجمّع (pool) مع مهلة زمنية يفرضها المضيف. لذا يجب أن يفترض محركك ما يلي:

      • قد تصل الاستدعاءات على أي خيط عشوائي من المجمّع. فلا تعتمد على الارتباط بخيط معين أو على حالة threading.local المشتركة مع خيط المحادثة.
      • قائمة الرسائل التي تتلقاها لقطة (snapshot) عميقة خاصة؛ ويُسمح بتعديلها مباشرةً (وفق العقد القديم)، لكن التعديل لا يظهر إلا إذا اعتُمدت العملية. وبعد انتهاء المهلة لدى المضيف، يُتجاهل عملك الذي لا يزال قيد التشغيل — فلا تنشر أبدًا إلى حالة خارجية أو دائمة خارج مرحلة الاعتماد.
      • يمكن أن تعمل عمليات الجلسات المختلفة بالتزامن على خيوط شقيقة في المجمّع؛ لذا يجب أن تكون أي نسخة واحدة من المحرك أو المزوّد مشتركة بين الجلسات آمنة مع تعدد الخيوط.

      انظر أيضًا​

      • ضغط السياق والتخزين المؤقت (Caching) — كيف يعمل الضاغط المدمج
      • إضافات مزوّدي الذاكرة — نظام إضافات مماثل للذاكرة يُختار فيه مزوّد واحد
      • الإضافات (Plugins) — نظرة عامة على نظام الإضافات العام
