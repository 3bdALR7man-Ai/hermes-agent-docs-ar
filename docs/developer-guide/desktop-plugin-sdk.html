      Desktop Plugin SDK

      تطبيق Hermes Desktop الأصلي (native) مبني بالكامل على مبدأ المساهمة (contribution-driven): كل سطح في النافذة — الأجزاء (panes)، المسارات (routes)، تنقّل الشريط الجانبي، عناصر شريط الحالة، مدخلات لوحة الأوامر، اختصارات لوحة المفاتيح، السمات (themes) — يسجَّل في سجلّ مركزي واحد. يسجّل الأساسي (Core) أسطحه بنفس الطريقة التي تسجّل بها إضافة (plugin)، لذا فإن قصة الإضافات هي القصة الحقيقية، لا إضافة لاحقة مُلصَقة.

      إضافة سطح المكتب (desktop plugin) هي ملف ESM واحد يُصدّر افتراضيًا HermesPlugin. يستورد وحدة واحدة — @hermes/plugin-sdk — ويحصل على كل شيء: حالة التطبيق الحية، باب gateway الخاص بـ JSON-RPC، مساحة أسماء خلفية REST/socket مخصّصة، React Query، وحتى عدة واجهة المستخدم (UI kit) الخاصة بالتطبيق لتبدو واجهة الإضافة أصلية افتراضيًا. دون استنساخ للمستودع، دون npm run build، ودون التعديل على كود التطبيق نفسه. ضع الملف في $HERMES_HOME/desktop-plugins/<id>/plugin.js وسيحمّله التطبيق خلال ثوانٍ ويعيد تحميله تلقائيًا (hot-reload) مع كل حفظ.

      هذا ليس SDK إضافات لوحة تحكم الويب

      كلمة "Plugin" (إضافة) تعني عدة أشياء غير مترابطة عبر Hermes. هذه الصفحة تخص SDK تطبيق سطح المكتب الأصلي (native) (hermes desktop) — وحدة @hermes/plugin-sdk ومجلد $HERMES_HOME/desktop-plugins/. أما لوحة تحكم الويب (web dashboard) (hermes dashboard) فلها نظام إضافات خاص بها غير مرتبط بهذا، على window.__HERMES_PLUGIN_SDK__ مع manifest.json — موثّق في توسيع لوحة التحكم. أما إضافات Python الخاصة بـ CLI/gateway فموثّقة في بناء إضافة Hermes. الأنظمة الثلاثة لا تتشارك الكود ولا واجهات API ولا آلية التسليم. مساحة الأسماء الخلفية plugin_api.py فقط (/api/plugins/<id>) مشتركة بين SDK سطح المكتب و SDK لوحة التحكم.

      النموذج الذهني​

      يتبع الـ SDK نموذج وحدات VS Code. يستورد مؤلّف الإضافة وحدة واحدة فقط ولا يلمس آليات التطبيق الداخلية أبدًا (فهي مستبعدة عبر lint من الإضافة المجمّعة (bundled)، ويفشل استيرادها في إضافة القرص). تأتي القدرات على شكل مستويات:

      • host.state.* — عروض للقراءة فقط على حالة التطبيق الحية (ذرّات nanostore): الجلسة النشطة، انشغال الدور (turn-busy) لكل جلسة، دليل العمل (cwd)، حالة socket الخاص بـ gateway، النموذج، profile، منفذ العرض (viewport). gateway هو WebSocket، وليس انشغال الدور.
      • إجراءات host.* — أفعال آمنة مُنتقاة بعناية: toast، التنقّل، متابعة السجلات (logs)، إعادة تشغيل gateway، الاشتراك في مجرى أحداث gateway.
      • host.request — باب gateway الخاص بـ JSON-RPC: الجلسات، الإعدادات، المهارات، cron — كل ما يستدعيه التطبيق نفسه.
      • ctx.rest / ctx.socket — مساحة الأسماء الخلفية الخاصة بإضافتك (/api/plugins/<id>) إن كنت تشحن plugin_api.py.
      • ui.* — لغة التصميم: المكوّنات الحقيقية للتطبيق، متغيرات السمة، الأيقونات، والمنسّقات (formatters)، بحيث تطابق واجهة إضافتك واجهة التطبيق بكسل بكسل.

      البدء السريع — إضافتك الأولى​

      أنشئ $HERMES_HOME/desktop-plugins/hello/plugin.js (وهو ~/.hermes/... افتراضيًا). إضافات سطح المكتب هي على مستوى التطبيق — جذر واحد لكل profile أو gateway أو جهاز بعيد تتصل به النافذة. يجب أن يطابق اسم المجلد معرّف الإضافة id.

      // ~/.hermes/desktop-plugins/hello/plugin.js
      import { host, haptic, useValue } from '@hermes/plugin-sdk'
      import { jsx, jsxs } from 'react/jsx-runtime'

      function HelloPane() {
        const gateway = useValue(host.state.gateway)

        return jsxs('div', {
          className: 'flex h-full flex-col gap-2 p-3 text-sm',
          children: [
            jsx('div', { className: 'font-medium', children: 'Hello, Hermes' }),
            jsx('div', {
              className: 'text-(--ui-text-tertiary)',
              children: `gateway: ${gateway}`
            })
          ]
        })
      }

      export default {
        id: 'hello', // must match the folder name
        name: 'Hello',
        register(ctx) {
          ctx.register({
            id: 'pane',
            area: 'panes',
            title: 'hello',
            data: { placement: 'right', width: '260px' },
            render: () => jsx(HelloPane, {})
          })
          ctx.register({
            id: 'chip',
            area: 'statusBar.right',
            order: 130,
            render: () =>
              jsx('button', {
                type: 'button',
                className: 'px-1.5 text-[0.6875rem] text-(--ui-text-tertiary)',
                onClick: () => {
                  haptic('tap')
                  host.notify({ kind: 'info', message: 'Hello from my plugin!' })
                },
                children: 'hello'
              })
          })
        }
      }

      احفظ الملف. يراقب التطبيق مجلد desktop-plugins/، ويحمّل الملف خلال ثوانٍ قليلة، ويعيد تحميله تلقائيًا (hot-reload) في مكانه مع كل حفظ لاحق. إن لم يظهر، نفّذ ⌘K ← Reload desktop plugins. وإذا فشل التحميل، يظهر toast يسمّي الخطأ — أصلِحه ثم احفظ مجددًا.

      لا JSX، ولا بناء

      يُحمَّل ملف القرص دون تجميع، لذا لن يُحلَّل صيغة JSX. اكتب واجهة المستخدم باستخدام استدعاءات jsx() / jsxs() من react/jsx-runtime (أو React.createElement). المُحدِّدات (specifiers) القابلة للاستيراد الوحيدة هي @hermes/plugin-sdk و react و react/jsx-runtime — وكل ما عداها يفشل في الحل، عمدًا.

      عقد الإضافة​

      تُصدّر الإضافة افتراضيًا HermesPlugin:

      interface HermesPlugin {
        /** Stable slug — becomes the `plugin:<id>` source and the id namespace. */
        id: string
        /** Human name for Settings / about UI. Defaults to `id`. */
        name?: string
        /** Registers on load when the user hasn't chosen (default true). Set false
         *  for opt-in plugins: they inventory in Capabilities ▸ Plugins, off until the
         *  user flips the switch. */
        defaultEnabled?: boolean
        /** Called once at load; wire contributions through `ctx`. */
        register: (ctx: PluginContext) => void
      }

      تتلقى register كائن مخصَّصًا (scoped) من نوع PluginContext. فهو لا يلمس السجلّ مباشرة أبدًا — إذ يضيف السياق تلقائيًا وسم المصدر (source: 'plugin:<id>') ويضع كل معرّف مساهمة في مساحة أسماء خاصة (<id>:<localId>)، بحيث لا يمكن أبدًا لإضافتين أن تتعارضا.

      interface PluginContext {
        /** Resolved source tag, e.g. `'plugin:hello'`. */
        readonly source: string
        /** Register one contribution (id namespaced, source stamped). Returns a disposer. */
        register: (c: PluginContribution) => () => void
        /** Register several at once; the returned disposer removes all of them. */
        registerMany: (cs: PluginContribution[]) => () => void
        /** REST to this plugin's own backend namespace (`/api/plugins/<id>`). */
        rest: <T>(path: string, opts?: PluginRestOptions) => Promise<T>
        /** Live WebSocket to this plugin's own namespace. Returns a disposer. */
        socket: (path: string, onMessage: (data: unknown) => void) => () => void
        /** The curated OS door: native notification, open-external, reveal-in-file-manager, clipboard. */
        os: PluginOs
        /** Plugin-scoped JSON persistence (keys live under `hermes.plugin.<id>.`). */
        storage: PluginStorage
      }

      المساهمة (contribution) هي المُكوّن الأولي الوحيد الذي يشترك فيه كل سطح:

      interface Contribution {
        id: string          // you write the local id; the host namespaces it
        area: string        // WHERE it goes (a contribution-area constant)
        title?: string
        order?: number      // sort within the area (lower = earlier)
        when?: () => boolean // dynamic visibility; re-evaluated by the area
        enabled?: boolean
        render?: () => ReactNode  // the component to mount
        data?: unknown      // area-specific payload (see the cookbook)
      }

      يمكنك توفير render أو data أو كليهما، حسب المنطقة (area).

      الأجزاء (Panes)​

      الجزء (pane) هو بلاطة في شجرة التخطيط. placement هو الدور الدلالي — يتكدّس الجزء (كتبويبات) مع الأجزاء الحالية التي تحمل نفس الدور؛ ويمكن للمستخدم سحبه إلى أي مكان لاحقًا.

      ctx.register({
        id: 'pane',
        area: 'panes',
        title: 'my pane',
        data: { placement: 'right', width: '260px' },
        render: () => jsx(MyPane, {})
      })

      قيمة placement هي 'main' | 'left' | 'right' | 'top' | 'bottom'. للاستقرار على حافة معينة بدلًا من التكديس، أضف إيماءة dock — وهي بالضبط ما يحدث عند سحب العنصر إلى شريحة إفلات جزء ما:

      // Below the conversation, 200px tall.
      data: {
        placement: 'bottom',
        dock: { pane: 'workspace', pos: 'bottom' },
        height: '200px'
      }

      dock.pane هو أي معرّف جزء (workspace هو الخيط الرئيسي؛ وأيضًا sessions، terminal، files، review، logs)؛ وdock.pos هو 'top' | 'bottom' | 'left' | 'right' | 'center'. حدّد width/height حتى لا يستحوذ الجزء على نصف المنطقة.

      إغلاق الجزء الوحيد الذي ساهمت به إضافة ما يعطّل تلك الإضافة، ويمكن إعادة تفعيلها من Capabilities → Plugins. عندما تساهم إضافة بعدة أجزاء، لا يؤدي إغلاق أحدها إلا لإخفاء ذلك الجزء فقط، ويبقى بقية أجزاء الإضافة، وأوامرها، والـ middleware الخاص بها نشطًا. تُعيد Reset layout الأجزاء المُساهَم بها التي تم إغلاقها.

      الصفحات وتنقّل الشريط الجانبي​

      يُحمّل المسار (route) صفحة كاملة داخل جزء مساحة العمل، تمامًا كأي عرض مدمج. اقرن ذلك بصفّ تنقّل في الشريط الجانبي (و/أو أمر في لوحة الأوامر) لجعله قابلًا للوصول.

      import { ROUTES_AREA, SIDEBAR_NAV_AREA } from '@hermes/plugin-sdk'

      ctx.registerMany([
        {
          id: 'page',
          area: ROUTES_AREA,
          data: { path: '/my-page' },
          render: () => jsx(MyPage, {})
        },
        {
          id: 'nav',
          area: SIDEBAR_NAV_AREA,
          data: { path: '/my-page', label: 'My Page', codicon: 'project' }
        }
      ])

      codicon هو معرّف VS Code codicon. انتقل إلى مسار من أي مكان باستخدام host.navigate('/my-page').

      شريط الحالة وشريط العنوان​

      تُعرَض عناصر شريط الحالة في التجمّع الأيسر أو الأيمن من الشريط السفلي. الأبسط هو دالة render؛ ولزر بسيط استخدم data كـ StatusbarItem ({ id, label?, icon?, detail?, variant?, menuItems?, … }).

      import { STATUSBAR_AREAS, TITLEBAR_AREAS } from '@hermes/plugin-sdk'

      ctx.register({
        id: 'count',
        area: STATUSBAR_AREAS.right,
        order: 120,
        render: () => jsx(MyStatus, {})
      })

      أدوات شريط العنوان تعيش في TITLEBAR_AREAS.left | .center | .right كبيانات TitlebarTool ({ id, label, icon, active?, onSelect? }).

      أوامر لوحة الأوامر واختصارات لوحة المفاتيح​

      import { PALETTE_AREA, KEYBINDS_AREA } from '@hermes/plugin-sdk'

      ctx.registerMany([
        {
          id: 'open',
          area: PALETTE_AREA,
          data: {
            id: 'my-page.open',
            label: 'Open My Page',
            keywords: ['my', 'page'],
            run: () => host.navigate('/my-page')
          }
        },
        {
          id: 'refresh',
          area: KEYBINDS_AREA,
          data: {
            id: 'my-page.refresh',
            label: 'Refresh My Page',
            category: 'My Plugin',
            defaults: ['mod+shift+r'],
            run: () => void doRefresh()
          }
        }
      ])

      اختصارات لوحة المفاتيح قابلة لإعادة الربط من قِبل المستخدم في الإعدادات؛ defaults هو الربط الأولي فقط.

      السمات (Themes)​

      مساهمة السمة تشحن كائن DesktopTheme كاملًا كبياناتها data (الاسم، التسمية، الألوان، …). تظهر في منتقي السمات كأنها سمة مدمجة.

      import { THEMES_AREA } from '@hermes/plugin-sdk'

      ctx.register({ id: 'noir', area: THEMES_AREA, data: myDesktopTheme })

      تسجيل سمة يدرجها في القائمة فقط؛ ولا يختارها. تقرأ useTheme() المظهر المُطبَّق حاليًا (theme، themeName، availableThemes، resolvedMode) وتغيّره (setTheme، setMode، previewTheme) من داخل مكوّن:

      import { Button, useTheme } from '@hermes/plugin-sdk'

      function ThemePicker() {
        const { availableThemes, setTheme, themeName } = useTheme()

        return availableThemes.map(t => (
          <Button key={t.name} disabled={t.name === themeName} onClick={() => setTheme(t.name)}>
            {t.label}
          </Button>
        ))
      }

      التبديل الناتج عن شيء آخر غير عملية render — اتصال gateway، حدث socket، أي رد نداء host.onEvent — لا يملك مكوّنًا (component) يمكن تعليق الخطاف (hook) عليه. استخدم requestTheme(name) في هذه الحالة. يُرفض الاسم غير القابل للحل بدلًا من إجباره إلى السمة الافتراضية، بحيث تُستخدم القيمة المُعادة نفسها كفحص للتوفر ولا يمكن لاسم خاطئ أن يعيد ضبط مظهر أحدهم بصمت:

      import { host, requestTheme } from '@hermes/plugin-sdk'

      host.onEvent('gateway.ready', () => {
        if (!requestTheme('noir')) {
          host.notifyError('Connected, but the noir theme is not installed.')
        }
      })

      كلا البابين يحفظان الاختيار لكل profile، لذا فإن التبديل الذي تقوده الإضافة يبقى محفوظًا تمامًا كالاختيار اليدوي. لتلوين السمة النشطة بدلًا من استبدالها، استخدم setAccentOverride(hex) وأزِله في ctx.onDispose — إضافة Accent Picker المستقلة هي المثال العملي (وهي أيضًا إضافة قرص كاملة وقابلة للتثبيت).

      امتدادات محرّر الرسائل (Composer)​

      تتيح COMPOSER_AREAS (top، bottom، leading، actions، attachments، middleware) للإضافة إضافة عناصر تحكم حول محرّر الرسائل، أو توفير مصدر مرفقات، أو تحويل مسودة قبل إرسالها (ComposerMiddleware مع handler(draft) => draft | null).

      توجيهات النسخة النصية (transcript) — مكوّنات مضمّنة يخاطبها النموذج​

      تجعل TRANSCRIPT_DIRECTIVE_AREA النسخة النصية نفسها منطقة مساهمة. سجّل توجيهًا مسمّى، ويمكن للوكيل عندها عرض مكوّنك مضمَّنًا داخل رسالة المساعد بإصدار فقرة على الصيغة ::name{key="value"}:

      import { TRANSCRIPT_DIRECTIVE_AREA } from '@hermes/plugin-sdk'

      ctx.register({
        id: 'task-card',
        area: TRANSCRIPT_DIRECTIVE_AREA,
        data: {
          name: 'task', // the model writes ::task{id="BB-12"}
          render: ({ attrs, streaming }) => jsx(TaskCard, { taskId: attrs.id, streaming })
        }
      })

      القواعد التي يفرضها المضيف (host) لإبقاء السطح آمنًا:

      • يجب أن يكون التوجيه الفقرة بأكملها — فـ::name في وسط النص العادي يبقى نصًا عاديًا، بحيث لا يمكن لمكوّنات الإضافة أبدًا اختطاف النص الجاري.
      • السمات (attributes) هي مخرجات نموذج غير موثوقة (أزواج key="value"، نصية فقط). تحقّق من حقولك الخاصة؛ ولا تعرض شيئًا عند بيانات فاسدة بدلًا من التخمين.
      • التوجيه غير المُطالَب به (لا إضافة مسجَّلة بهذا الاسم) يُعرَض كفقرة نصية عادية كما كان دائمًا — لا شيء ينكسر عندما تكون الإضافة معطّلة.
      • عمليات العرض ملفوفة داخل حدود خطأ المساهمة (error boundary): أي رمي استثناء يتحوّل إلى شريحة خطأ مضمّنة، وليس إلى رسالة ميتة.
      • التسجيل الأول يفوز عند تعارض الأسماء؛ ضع الأسماء الطموحة في مساحة أسماء خاصة بمعرّفك (myplugin-board، وليس board).

      يشحن الأساسي (Core) توجيهًا واحدًا كمستهلك مرجعي: ::preview{file="…"} يعرض ملف HTML الخاص بمساحة العمل مباشرة داخل الرسالة — عبر إطار srcdoc معزول ذي أصل (origin) غير شفاف (تعمل النصوص البرمجية والعنصر تفاعلي بالكامل؛ دون أي وصول إلى التطبيق أو تخزينه أو الجسر). يتحجّم الإطار وفق المحتوى (الارتفاع حيّ، والعرض مأخوذ من امتداد المحتوى الجوهري، محاذًا لليسار في تدفق الرسالة)، وتمنح مقدّمة سمة (theme prelude) المستند رموز التطبيق (tokens) المُحلَّلة (--foreground، --muted-foreground، --accent، --border، --card)، وخط التطبيق، وخلفية شفافة — بحيث تبدو واجهة HTML على شكل عنصر (widget) أصلية بينما تحافظ الصفحة الكاملة على تصميمها الخاص. الأهداف غير HTML و gateways البعيدة تعود إلى بطاقة المعاينة الكلاسيكية. أخبر الوكيل عن توجيهك في مهارة (skill) (فهكذا يتعلّم إصداره).

      يمكن للعناصر (widgets) المعروضة أيضًا الرد. داخل الإطار، يعطي window.hermes.send('get-price eth') (أو بشكل تصريحي عبر <button data-hermes-send="get-price eth"> — دون الحاجة لأي نص برمجي) ذلك الأمر (prompt) للوكيل كدور مستخدم، خارج الشاشة: لا تشغل فقاعة أي مساحة في النسخة النصية، وتحديث العنصر نفسه هو الاستجابة المرئية. يبقى الدور حقيقيًا — فهو يوقظ الوكيل، ويسير وفق قواعد التوجيه/الانتظار (steer/queue) الخاصة بمحرّر الرسائل، ويُحفظ (بنوع hidden) بحيث يحتفظ الاستئناف وقاعدة بيانات الجلسة بالسجل الكامل. تُقصَّ الأوامر (prompts) وتُحدّ بسقف 500 حرف، وتُقيَّد بمعدل أمر واحد في الثانية لكل إطار.

      عناصر واجهة مخصّصة بالتحميل (Contribute)​

      ctx.register مخصّص للمساهمات الدائمة. عندما ينبغي لعنصر واجهة أن يظهر ويختفي مع مكوّن موجود بالفعل على الشاشة (عنصر تحكم في شريط عنوان خاص بصفحة يختفي عند إلغاء تحميل الصفحة)، اعرض <Contribute> داخله بدلًا من ذلك:

      import { Contribute, TITLEBAR_AREAS } from '@hermes/plugin-sdk'

      jsx(Contribute, {
        area: TITLEBAR_AREAS.center,
        id: 'my-page:switcher', // namespace with your slug
        children: jsx(MySwitcher, {})
      })

      يسجَّل تلقائيًا عند التحميل ويُلغى تلقائيًا عند إلغاء التحميل.

      واجهة API الخاصة بالمضيف (Host)​

      كل ما في host يمكن الوصول إليه من أي مكان في الإضافة. ذرّات الحالة للقراءة فقط — اقرأها بـ.get() في المعالِجات (handlers)، واشترك بها بـuseValue(atom) في المكوّنات.

      host.state.activeSessionId  // ReadableAtom<string | null>
      host.state.awaitingResponse // ReadableAtom<boolean>  true until the first assistant payload
      host.state.busy             // ReadableAtom<boolean>  focused chat is working after a send
      host.state.busyBySession    // ReadableAtom<Record<string, boolean>>  runtime id → mid-turn
      host.state.focusedSessionId // ReadableAtom<string | null>  (runtime id of the FOCUSED session — tile-aware; prefer for session.* RPC)
      host.state.focusedSessionProfile // ReadableAtom<string>  (owner profile of the focused chat — prefer over `profile` for per-bot/profile readouts)
      host.state.focusedStoredSessionId // ReadableAtom<string | null>  (durable id — navigation / session-list matching)
      host.state.focusedUsage     // ReadableAtom<UsageStats | null>  (live streamed usage of the focused session, no RPC needed)
      host.state.cwd              // ReadableAtom<string>
      host.state.gateway          // ReadableAtom<string>  socket state ('idle' | 'connecting' | 'open' | …)
      host.state.model            // ReadableAtom<string>
      host.state.profile          // ReadableAtom<string>
      host.state.viewport         // ReadableAtom<{ width, height, narrow }>

      host.state.gateway هو اتصال WebSocket، وليس ما إذا كان دور محادثة يعمل حاليًا. يمكن للجلسة أن تكون في منتصف دور بينما يكون الـ socket open؛ ويمكن لجلسة أخرى أن تكون خاملة في الوقت نفسه. عطّل إجراءات المحرّر أو الإضافة بناءً على انشغال دور الجلسة التي عليها التركيز (host.state.busyBySession[sessionId]، أو view.$busy الخاصة بتلك الجلسة) — لا من gateway أبدًا، ولا من علامة انشغال عامة على مستوى العملية.

      host.notify({ kind, message, title?, detail?, action? })  // toast; returns id
      host.notifyError(error, fallbackMessage)                   // toast an error
      ctx.os.notify({ title, body?, silent?, icon?, activate?, onActivate?, actions? })
                                                 // native OS notification (attributed to your plugin)
      ctx.os.openExternal(url)                   // OS default handler (browser, mail, spotify:) → Promise<boolean>
      ctx.os.revealPath(path)                    // reveal in Finder / Explorer → Promise<boolean>
      ctx.os.writeClipboard(text)                // system clipboard → Promise<boolean>
      host.navigate('/route')                    // hash-route navigation
      host.openSession(id, { profile?, intent? }) // open a stored session core-style;
                                                 //   profile: soft-swap to that profile's backend first
                                                 //   intent: 'in-place' (default) | 'stack' | 'tab' | 'window'
      host.newChat(profile?)                     // fresh chat draft, optionally in another profile
      host.openWorkspace(id, { render, title?, minWidth?, onClose? })
                                                 // dock a plugin-rendered tab into the MAIN
                                                 //   workspace zone and reveal it; returns a disposer
      host.paneVisibility(paneId)                // ReadableAtom<boolean> — is a contributed pane
                                                 //   actually on screen (its zone's active tab)?
      host.onEvent(type, fn)                     // gateway event stream ('*' = all); returns disposer
      host.logs(...)                             // tail an app log file
      host.status()                              // one-shot system status snapshot
      host.restartGateway()                      // restart the backend gateway
      host.profileRoutes()                       // [{ profile, targetProfile, connectionId, mode }]
      host.requestProfile<T>(route, method, params?)   // registry-routed RPC; no foreground swap
      host.requestProfile<T>(profile, method, params?) // legacy v1/local overload
      host.request<T>(method, params?)           // active-gateway JSON-RPC — the real power

      host.request هو نفس JSON-RPC الذي يستخدمه التطبيق نفسه (الجلسات، الإعدادات، المهارات، cron، kanban، …). تقبل host.requestProfile وصفًا (descriptor) من host.profileRoutes() وتوجّه ذلك الاستدعاء عبر مصدر سجلّه (registry) الدقيق و profile الخاص به دون تغيير المحادثة أو الـ gateway النشطين. الحمل الزائد (overload) الخاص بـ profile فقط مُبقًى عليه فقط للطوبولوجيا الوحيدة/المحلية القديمة؛ ينبغي للإضافات المدركة للسجلّ (registry-aware) تمرير الوصف بحيث لا يمكن لمصدرين يعرضان نفس اسم profile أن يتعارضا.

      host.openWorkspace(id, { render, title?, minWidth?, onClose? }) يُرسي عرضًا يعرضه الإضافة في منطقة مساحة العمل الرئيسية — نفس المنطقة الوسطى التي تستخدمها بلاطات الجلسات والمعاينات — كتبويب، ويُظهره. إعادة استدعائه بنفس id يحدّث المحتوى في مكانه ويعيد إحضار التبويب للأمام بدلًا من فتح نسخة مكرَّرة. إغلاق التبويب (عنصر تحكم الإغلاق الخاص بالتبويب أو ⌘W) يفكّك التسجيل ويطلق onClose الخاص بك؛ ويغلقه المُتخلِّص (disposer) المُعاد برمجيًا. اكتشف توفره (typeof host.openWorkspace === 'function') وارجع إلى جزء (pane) مساهم عادي على إصدارات سطح المكتب الأقدم — غرف المحادثة الجماعية في Bot Mode هي المستهلك المرجعي (استحواذ على النافذة الرئيسية عند التوفر، وعرض داخل اللوحة خلاف ذلك).

      host.paneVisibility(paneId) تُعيد ذرّة تفاعلية للقراءة فقط تكون true طالما أن الجزء المُساهَم به موجود فعليًا على الشاشة: حاضر في شجرة التخطيط، غير مُغلَق أو مخفي، ومنطقته غير مصغَّرة، ويحمل فتحة التبويب النشط لمنطقته (الجزء الوحيد في منطقته الخاصة يُحتسَب). المعرّف هو معرّف الجزء المخصّص للمساهمة، <pluginId>:<paneId>. الذرّات محفوظة (memoized) لكل معرّف، لذا فإن استدعاءه أثناء render آمن. استخدمه لتسجيل واجهة مصاحبة فقط عندما يكون جزؤك مرئيًا — لوحة Cronjobs الخاصة بـ Bot Mode هي المستهلك المرجعي: تُسجَّل طالما تحمل لوحة Bots تبويب الشريط الجانبي وتُلغى تسجيلها عندما ينتقل المستخدم إلى Sessions. اكتشف توفره على إصدارات سطح المكتب الأقدم (typeof host.paneVisibility === 'function') وارجع إلى السلوك المسجَّل دائمًا.

      host.profileRoutes() يجرد كل مصدر مسجَّل في سجلّ الاتصال الحالي. مصادر SSH التي تتصل عند الطلب تعرض مسارًا (route) أوّليًا default خاليًا من بيانات الاعتماد دون فتح نفق (tunnel)، بحيث يمكن للإضافة أن تكون أول من يستدعيها؛ يظل remoteProfile الخاص بـ SSH هو targetProfile الخلفي للمسار. أما connectionId فهو هوية توجيه السجلّ؛ اقرنه مع profile للمفاتيح والاستمرارية (persistence). profile هو المسار المحلي للمصدر المستخدم للطلبات؛ وtargetProfile هو profile Hermes الخلفي الذي يخدمه ذلك المسار. يختلفان عندما يُخطَّط المسار صراحة إلى profile خلفي آخر (مثلًا تجاوز remoteProfile في SSH أو اسم مستعار خاص بعنوان URL لكل profile قديم). هذا التمييز يحافظ على هوية الخلفية دون كشف أسرار الاتصال.

      الإضافات المصمَّمة حول profile تحصل أيضًا على طرق (methods) من الدرجة الأولى: profiles.list (كل profile مع أحدث محادثة له كـ last_session؛ مرّر include_sessions: false لتخطي فحص قاعدة البيانات لكل profile؛ ومرّر preferred_session_ids: { profileName: sessionId } لبحث دقيق ومتحقَّق من وجوده عن جلسة واحدة مثبَّتة لكل profile — يحصل كل صف مسمّى على ملخّص preferred_session يحلّ الصفوف المخفية وسلاسل الضغط (compression lineages) إلى طرفها الحي، أو null عندما يكون المعرّف مفقودًا نهائيًا؛ وتتجاهل الـ gateways الأقدم هذا المعامِل وتحذف الحقل) وprofiles.create (name، description، clone_from، clone_all، no_skills، soul، وتثبيت اختياري لـmodel + provider) — وهما التوأمان عبر ws لمسارات /api/profiles REST الخاصة بلوحة التحكم. host.state.busy هو دور المحادثة التي عليها التركيز حاليًا (التفكير والبث). تبقى host.state.awaitingResponse صحيحة من الإرسال وحتى وصول أول حمولة من المساعد. كلاهما يتبعان المحادثة التي ينظر إليها المستخدم فعليًا — بلاطة الجلسة التي عليها التركيز عندما تحمل التركيز، وإلا فمحادثة مساحة العمل الرئيسية (نفس الإشارة التي تقرأها نبضة الانشغال في شريط الحالة). اشترك في مكوّن:

      const busy = useValue(host.state.busy)

      لتفاصيل أدق على مستوى الـ token، استمع عبر host.onEvent (message.start، message.delta، message.complete).

      host.onEvent يبثّ أحداث gateway الحية (فروقات (deltas) الرسائل، دورة حياة الجلسة، نشاط الأدوات). المستمعون (listeners) معزولون — أي رمي استثناء في مستمعك لا يمكن أن يؤثر على إرسال (dispatch) التطبيق. كل باب في host آمن غير متزامن (async-safe): أي رمي استثناء متزامن من مساعد داخلي (مثلًا عدم وجود جسر سطح مكتب في متصفح عادي) يتحوّل إلى رفض (rejection) يلتقطه .catch() الخاص بك، وليس إلى انهيار في حدود الخطأ.

      ctx.os هو باب نظام التشغيل المُنتقى بعناية — كل طريقة تصل بها الإضافة إلى خارج نافذة التطبيق، في مساحة أسماء واحدة منسوبة إلى إضافتك. يصدر ctx.os.notify إشعار نظام تشغيل أصلي (native) — نفس أنبوب Electron الذي تستخدمه تنبيهات الموافقة/الدور الخاصة بالتطبيق نفسه. لا يطلق إلا عندما يكون المستخدم بعيدًا عن Hermes (في الخلفية / غير مركَّز عليه)؛ استخدم host.notify للحصول على toast داخل التطبيق عندما يكون المستخدم ينظر إلى التطبيق. يمكن للمستخدمين كتم الإشعار لكل جهاز من Settings ▸ Notifications ▸ "Plugin notifications"، وتُقيَّد التكرارات من نفس الإضافة، لذا تعامل معه كإشارة لأحداث ملحوظة حقًا — لا كسجل (log).

      عرض غني + تفعيل (يوسّع باب ctx.os الأصلي):

      ctx.os.notify({
        title: 'New match found',
        body: 'Someone matched your signal',
        icon: '/abs/path/to/icon.png', // Electron Notification icon
        // Body click → focus Hermes + navigate. Same vocabulary as OS deep links:
        activate: 'hermes://index-network/intent/1',
        // or: activate: '/index-network/intent/1'
        // or: activate: { path: '/index-network/intent/1' }
        onActivate: () => focusLocalState('1'), // optional renderer callback
        actions: [
          { id: 'open', label: 'Open', activate: 'hermes://index-network/intent/1' },
          { id: 'dismiss', label: 'Dismiss', onAction: () => dismiss('1') },
        ],
      })

      activate متوافق مع الروابط العميقة (deeplink): يحلّ كلٌّ من hermes://index-network/intent/1 ومسار التجزئة (hash) /index-network/intent/1 إلى نفس المسار داخل التطبيق (ويعمل نفس رابط hermes://… كرابط عميق لنظام التشغيل). لا تُعرَض أزرار الإجراء إلا في إصدارات macOS الموقَّعة؛ وفي غيرها يظل النقر على المتن يفعّل. لا يحدث التنقّل إلا عند نقر المستخدم — أبدًا من حدث في الخلفية وحده.

      الأبواب الأخرى (openExternal، revealPath، writeClipboard) تُرجع false بدلًا من رمي استثناء عندما لا تكون القدرة متاحة (غلاف سطح مكتب أقدم، متصفح عادي) — افرِّع بناءً على النتيجة بدلًا من استشعار الجسر.

      طبقة البيانات — React Query + nanostores​

      تشارك الإضافات QueryClient الوحيد الخاص بالتطبيق، لذا تخزَّن استعلامات الإضافة مؤقتًا وتُنقّى من التكرار وتُستطلع وتُبطَل تمامًا مثل الشاشات الأساسية — لا تبنِ أبدًا حلقة جلب (fetch) يدوية.

      import { useQuery, useMutation, useQueryClient, atom, computed, useValue } from '@hermes/plugin-sdk'

      function MyPanel() {
        const { data, isLoading } = useQuery({
          queryKey: ['my-plugin', 'items'],
          queryFn: () => host.request('my.list', {})
        })
        // …
      }

      بالنسبة للحالة المشتركة بين مُشغِّل (trigger) ولوحته (panel) — أو حلقة استطلاع — استخدم atom / computed — نفس البدائية (primitive) التي يستخدمها host.state. اشترك في الورقة (leaf) التي تعرض القيمة باستخدام useValue. لإبطال استعلام من خارج React (مثلًا وصول إطار عبر ctx.socket)، استورد queryClient المشترك:

      import { queryClient } from '@hermes/plugin-sdk'

      ctx.socket('/events', () => {
        queryClient.invalidateQueries({ queryKey: ['my-plugin', 'items'] })
      })

      طقم واجهة المستخدم (UI Kit) والسمات (Theming)​

      استورد مكوّنات التطبيق الحقيقية مباشرة حتى تكون واجهتك أصيلة (native) افتراضيًا:

      Button، وInput، وTextarea، وSelect*، وSwitch، وCheckbox، وSegmentedControl، وTabs*، وDialog*، وConfirmDialog، وDropdownMenu*، وContextMenu*، وPopover*، وTip/Tooltip*، وBadge، وKbd/KbdGroup، وSearchField، وScrollArea، وSeparator، وSkeleton، وGlyphSpinner، وLoader، وEmptyState، وErrorState، وCopyButton، وStatusDot، وLogView، وCodicon، وDecodeText.

      صمّم باستخدام متغيرات السمة (theme variables)، ولا تستخدم ألوانًا ثابتة أبدًا. تجلس اللوحات (panes) بالفعل على خلفية محرر التطبيق — اترك الخلفية كما هي واستخدم المتغيرات لكل شيء آخر: var(--ui-text-secondary)، وvar(--ui-text-tertiary)، وvar(--ui-text-quaternary)، وvar(--ui-stroke-secondary)، وvar(--ui-accent). بالنسبة للرسم على canvas، حلّها مرة واحدة باستخدام getComputedStyle(canvas).getPropertyValue('--ui-accent'). هذا ما يجعل الإضافة تُعيد تلوين نفسها تلقائيًا مع كل سمة.

      backend لإضافتك​

      إذا احتاجت إضافتك عملًا من جهة الخادم، اشحن ملف Python plugin_api.py واستدعِه عبر ctx.rest / ctx.socket — نطاق مقيّد بإضافتك بحكم البناء.

      حزمة واحدة، وSDK لكلا الجانبين​

      الميزة التي تحتاج إلى واجهة desktop وكود من جهة الوكيل (إضافة Python، مسارات الـ backend الخاصة بها، مهارات) لا تحتاج إلى الشحن كتثبيتين مترابطين. ضع ملف desktop/plugin.js داخل حزمة الوكيل. عندما تحطّ الحزمة في أي جذر plugins/ محلي (المنزل الافتراضي أو profile)، تنسخ عملية Electron الرئيسية هذا النصف إلى $HERMES_HOME/desktop-plugins/<id>/ بجانب علامة .hermes-package.json، ويحمّله عارض الواجهة (renderer) عبر خط أنابيب مطابق تمامًا لباب القرص المستقل (hot reload متضمَّن):

      ~/.hermes/plugins/<id>/           # ONE installable folder
      ├── plugin.yaml                   # the agent half: tools, hooks, commands
      ├── skills/…
      ├── dashboard/
      │   ├── manifest.json             # { "name": "<id>", "api": "plugin_api.py" }
      │   └── plugin_api.py             # backend routes → /api/plugins/<id>/
      └── desktop/
          └── plugin.js                 # the desktop half: panes, commands, ctx.rest

      نصف desktop/plugin.js هو إضافة قرص عادية — نفس العقد، ونفس الاستيرادات، ونفس ctx.rest('/…') الذي يصل إلى plugin_api.py الموجود بجانبه. تثبيت أو مشاركة أو إزالة الميزة هو مجلد واحد: تُحدَّث نسخة جذر التطبيق عندما يتغير ملف plugin.js المصدر (hermes plugins update، أو Rescan) وتُزال عندما يختفي مجلد الحزمة. النسخ هو ما يجعل النصف الخاص بـ desktop على مستوى التطبيق: فهو موجود مرة واحدة، مهما كان عدد الـ profiles التي تحمل الحزمة، ولا يظهر أو يختفي أبدًا عندما يبدّل المستخدم محدد profile الخاص بالإمكانيات (Capabilities). لا يفحص عارض الواجهة plugins/ بنفسه أبدًا. تسجّل العلامة اسم الحزمة ومصدرها (ملحق كتالوج أو remote git)، وهذا ما يستخدمه زر Install here في صفحة الإضافات لتثبيت نصف الوكيل في profile آخر.

      ما زال هناك مفتاحا تفعيل ينطبقان، بشكل مقصود، وكلاهما افتراضيًا معطَّل: نصف desktop يُشحَن كخيار اختياري (opt-in) — يُدرَج ضمن الجرد في Capabilities → Plugins لكنه يبقى معطَّلًا حتى يبدّله المستخدم — مطابقًا لتقييد plugins.enabled الخاص بنصف Python في config.yaml (الحد الأمني أدناه). وضع حزمة في ~/.hermes/plugins خامل على كل الأسطح حتى يقول المستخدم غير ذلك. يتدهور نصف desktop بأمان عندما يكون نصف الـ backend معطَّلًا — يعيد ctx.rest أخطاء، لا انهيارات.

      ملاحظة

      النسخة محلية للجهاز الذي يعمل عليه تطبيق desktop. مقابل backend بعيد، لا يمكن الوصول إلى ~/.hermes/plugins الخاص بالجهاز البعيد كنظام ملفات — فقط الحزم المثبَّتة محليًا تسهم بنصف desktop بهذه الطريقة. بالنسبة لـ backend بعيد، يستنسخ حوار التثبيت نصف desktop بشكل منفصل إلى desktop-plugins/، تمامًا كما يحدث مع مستودع خاص بـ desktop فقط.

      التوزيع برابط تثبيت​

      اشحن مستودع إضافتك (نصف الوكيل، أو نصف desktop، أو كليهما) واربطه باستخدام مخطط hermes:// — رابط بسيط على موقعك أو في README:

      <a href="hermes://plugin/install?repo=owner/repo&enable=1">Install in Hermes</a>

      يحصل المستخدم على حوار تأكيد (معرّف المستودع، روابط المصدر، فحص لما يشحنه المستودع) ويختار المكوّنات قبل تثبيت أي شيء — الروابط العميقة لا تُثبّت تلقائيًا أبدًا. force=1 يستبدل تثبيتًا موجودًا؛ نُسخ التطوير تستخدم hermes-dev://. مرجع الروابط الكامل: روابط التثبيت بنقرة واحدة.

      جانب Python​

      تعيد إضافات desktop استخدام نقطة تركيب backend الخاصة بإضافة لوحة التحكم. ضع الـ backend في مجلد فرعي dashboard/ ضمن إضافة Hermes عادية وأعلن عنه في manifest.json:

      ~/.hermes/plugins/<id>/
      └── dashboard/
          ├── manifest.json      # { "name": "<id>", "api": "plugin_api.py" }
          └── plugin_api.py      # exports `router = APIRouter()`
      # plugin_api.py
      from fastapi import APIRouter

      router = APIRouter()

      @router.get("/board")
      async def board():
          return {"items": ["one", "two", "three"]}

      @router.post("/action")
      async def action(body: dict):
          return {"ok": True, "received": body}

      تُركَّب المسارات تحت /api/plugins/<id>/ (GET /api/plugins/<id>/board، …). يعمل كود الـ backend داخل عملية gateway، بحيث يمكنه الاستيراد مباشرة من قاعدة كود hermes-agent (hermes_state، وhermes_cli.config، …). راجع توسيع لوحة التحكم → مسارات API للـ backend للمرجع الكامل للـ backend — نقطة التركيب متطابقة.

      backend الخاص بـ Python مقيّد بشكل منفصل

      تفعيل إضافة في لوحة Capabilities → Plugins الخاصة بـ desktop اختيار من جانب عارض الواجهة (renderer)؛ وهو لا يستورد Python. يُستورد plugin_api.py الخاص بإضافة المستخدم فقط عندما تكون الإضافة في قائمة السماح plugins.enabled ضمن config.yaml (وليست في plugins.disabled). إضافات المشروع (./.hermes/) لا تستورد Python تلقائيًا أبدًا. هذا حد أمني، لا إغفال (GHSA-mcfc-hp25-cjv7).

      استدعاؤه من الإضافة​

      register(ctx) {
        // REST — namespace-relative path.
        const load = () => ctx.rest('/board')                 // GET /api/plugins/<id>/board
        const act  = () => ctx.rest('/action', { method: 'POST', body: { go: true } })

        // Live twin — a WebSocket to your own namespace.
        const stop = ctx.socket('/events', frame => {
          queryClient.invalidateQueries({ queryKey: [ctx.source, 'board'] })
        })
      }

      ctx.rest يراعي profile ويرفض اجتياز المسارات (..) بحيث لا يمكنك أبدًا التوجّه إلى واجهة API خاصة بإضافة أخرى أو مسار أساسي عبره. PluginRestOptions هو { method?, body?, upload?: { filename, contentType?, bytes }, timeoutMs? }.

      ctx.socket يعيد الاتصال تلقائيًا بتراجع تدريجي (backoff) حتى يُستبعَد. ينحل إلى عملية تجاهل (no-op) على remotes بـ OAuth (تذاكر WS أحادية الاستخدام مُدارة من النواة) — عامِله كمُسرِّع فوق الاستطلاع (polling)، لا كبديل عنه. يحتاج كل مستهلك إلى بديل استطلاع على أي حال، لأن أي مقبس (socket) قد ينقطع.

      بالنسبة لبيانات على نطاق gateway بأكمله (وليست في نطاقك الخاص)، استخدم host.request (JSON-RPC) و host.onEvent (تدفق أحداث gateway) بدلًا من ذلك.

      الإعدادات، وحالة التفعيل، والتخزين​

      كل إضافة — سواء مفعَّلة أم لا — تُدرَج ضمن الجرد في Capabilities → Plugins، حيث يبدّلها المستخدم حيًا (بلا إعادة تشغيل للتطبيق)، أو يكشف مجلدها، أو يعيد الفحص. اختيار المستخدم يُتذكَّر:

      • لا اختيار بعد ← defaultEnabled الخاصة بالإضافة نفسها (الافتراضي true). اضبط defaultEnabled: false لشحن إضافة اختيارية تبقى معطَّلة حتى يشغّلها المستخدم.
      • اختيار صريح ← يُحفظ ويُحترَم عبر إعادات التشغيل. إضافة معطَّلة تبقى معطَّلة — لا تقاوم ذلك؛ فقد أطفأك المستخدم.

      احفظ حالتك الخاصة باستخدام ctx.storage، بنطاق مُميّز باسم إضافتك (hermes.plugin.<id>.*) بحيث لا تستطيع الإضافات قراءة أو إتلاف بيانات بعضها البعض:

      ctx.storage.set('lastTab', 'board')
      const tab = ctx.storage.get('lastTab', 'summary')
      ctx.storage.remove('lastTab')

      الإضافات المضمّنة (Bundled)​

      يمكن لإضافة أن تُشحَن ضمن الشجرة عند apps/desktop/src/plugins/<id>/plugin.tsx (تصدير افتراضي HermesPlugin). تُكتشَف بواسطة discoverBundledPlugins() عند الإقلاع — بلا استيراد، بلا تعديل سجل — وتشارك نفس عقد الجرد + التفعيل/التعطيل الحي كإضافة قرص. الفرقان الاثنان:

      1. تمر عبر بناء Vite الخاص بالتطبيق، لذا يمكنك كتابة JSX حقيقي واستيراد الـ SDK عبر اسمه المستعار @hermes/plugin-sdk.
      2. لا تزال مقيَّدة بأدوات lint إلى @hermes/plugin-sdk + react فقط — بلا داخليات @/… خاصة بالتطبيق.

      لا تُشحَن إضافات desktop في الشجرة الأساسية اليوم؛ يبقى التطبيق المُشحَن غير مزدحم والعروض التوضيحية موجودة في مستودع hermes-example-plugins المصاحب.

      النموذج الأمني​

      تُقيَّم الإضافة المحمَّلة كـ ESM في عالم عارض الواجهة (renderer realm) بـسلطة كاملة على التطبيق — النسخة الوحيدة (singleton) من React، وكامل الـ SDK (RPC الخاص بـ gateway عبر host.request، وctx.rest، والتخزين، وnavigate). العزل الذي يوفّره المحمّل هو عزل الأخطاء فقط: لا يمكن لإضافة أن تُسقط التطبيق (المساهمات محدودة الأخطاء، والمستمعون معزولون)، لكن يمكنها فعل أي شيء يستطيع التطبيق فعله.

      هذا مقبول بالنسبة لمصادر محلية — إذ يمكن لملف على القرص أصلًا تشغيل كود على جهازك — وهذا سبب أن باب القرص لا يحمّل إلا ملفات محلية كتبتَها أنت (أو وكيلك). فحص integrity (sha256-…) الاختياري يثبت فقط أن البايتات تطابق تجزئة (hash)؛ ولا يعزل. باب مصدر بعيد مستقبلي سيحتاج حدًا حقيقيًا (iframe/worker + CSP + تقييد صلاحيات) قبل أن يصبح جاهزًا؛ لا تعامل خط الأنابيب هذا كحد ثقة.

      مزالق​

      • JSX لا يُحلَّل (parse) في إضافة قرص. يُحمَّل الملف دون تجميع — استخدم jsx() / jsxs() (أو React.createElement)، لا صياغة JSX. (الإضافات المضمّنة مبنية، لذا JSX مقبول فيها.)
      • ثلاثة معرّفات فقط قابلة للحل (resolve): @hermes/plugin-sdk، وreact، وreact/jsx-runtime. أي استيراد آخر يُظهر خطأ تحميل فوري.
      • لا تستخدم ألوانًا ثابتة أبدًا (#000، black، rgb(...)). اترك الخلفية كما هي؛ واستخدم متغيرات السمة (var(--ui-*)) لكل شيء.
      • أشِر فقط إلى ما استوردته. مكوّن نسيت استيراده (مثل StatusDot) يسبب ReferenceError عند العرض — تحقق مرة أخرى من أن كل معرّف في استدعاءات jsx() الخاصة بك موجود في سطر الاستيراد.
      • اقرأ الحالة بشكل أمري (imperatively) في المعالجات ($atom.get())، وليس من إغلاق (closure) خاص بالعرض — فالأحداث السريعة ستَرى قيمًا قديمة خلاف ذلك. اشترك (useValue) فقط في الورقة (leaf) التي تعرض القيمة.
      • يجب أن تتبع لوحات canvas حاويتها باستخدام ResizeObserver وتُعيد قياس canvas (سمتا العرض/الارتفاع، وليس CSS فقط) — فاللوحات تُعاد قياسها باستمرار.
      • لا تستطلع أسرع من بضع ثوانٍ باستخدام host.request؛ فضّل host.onEvent / ctx.socket ودع React Query يزيل التكرار.
      • ctx.socket عملية تجاهل (no-op) على remotes بـ OAuth. احرص دائمًا على بديل استطلاع.

      الوكلاء: مهارة hermes-desktop-plugins​

      عندما يكتب وكيل إضافة desktop، عليه تحميل مهارة hermes-desktop-plugins المضمّنة — فهي تحمل نفس عقد هذه الصفحة في صيغة موجَّهة للوكيل، مع templates/plugin.js جاهز للنسخ. هذه الصفحة هي المرجع البشري/الخاص بالمطوّر؛ والمهارة هي قائمة التحقق العملية.

      استكشاف الأخطاء وإصلاحها​

      إضافتي لا تظهر. تأكد أن الملف موجود في $HERMES_HOME/desktop-plugins/<id>/plugin.js وأن اسم المجلد يطابق id المُصدَّر. نفّذ ⌘K → Reload desktop plugins. تحقق من التطبيق بحثًا عن رسالة خطأ منبثقة تسمّي الإخفاق، وتابع سجل hermes logs gui -f.

      "unsupported import" عند التحميل. إضافة القرص لا يجوز أن تستورد سوى @hermes/plugin-sdk، وreact، وreact/jsx-runtime. أزل أي استيراد آخر.

      عنصر jsx لا يعرض شيئًا / يُطلق ReferenceError. معرّف مستخدَم في استدعاء jsx() غير مستورَد. أضفه إلى سطر الاستيراد.

      ctx.rest يعيد 404. الـ backend غير مُركَّب: تأكد من أن ~/.hermes/plugins/<id>/dashboard/manifest.json يحتوي "api": "plugin_api.py"، وأن الإضافة مدرجة في plugins.enabled ضمن config.yaml، وأعد تشغيل gateway (تُركَّب مسارات الـ backend عند بدء التشغيل). تابع ~/.hermes/logs/errors.log بحثًا عن Failed to load plugin <id> API routes.

      ctx.socket لا يُطلَق أبدًا. على remote بـ OAuth هو عملية تجاهل (no-op) بالتصميم — استخدم بديل الاستطلاع الخاص بك. وإلا تحقق من أن الـ backend يعرض مسار @router.websocket(...) المطابق تحت نطاقه.

      الألوان تبدو خاطئة بعد تبديل السمة. لقد استخدمت لونًا ثابتًا. استبدله بـ متغير سمة var(--ui-*).
