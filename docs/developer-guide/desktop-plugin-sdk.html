      Desktop Plugin SDK

      تطبيق Hermes Desktop الأصلي (native) مبني بالكامل على مبدأ المساهمة (contribution-driven): كل سطح في النافذة — الأجزاء (panes)، المسارات (routes)، تنقّل الشريط الجانبي، عناصر شريط الحالة، مدخلات لوحة الأوامر، اختصارات لوحة المفاتيح، السمات (themes) — يسجَّل في سجلّ مركزي واحد. يسجّل الأساسي (Core) أسطحه بنفس الطريقة التي تسجّل بها إضافة (plugin)، لذا فإن قصة الإضافات هي القصة الحقيقية، لا إضافة لاحقة مُلصَقة.

      إضافة سطح المكتب (desktop plugin) هي ملف ESM واحد يُصدّر افتراضيًا HermesPlugin. يستورد وحدة واحدة — @hermes/plugin-sdk — ويحصل على كل شيء: حالة التطبيق الحية، باب gateway الخاص بـ JSON-RPC، مساحة أسماء خلفية REST/socket مخصّصة، React Query، وحتى عدة واجهة المستخدم (UI kit) الخاصة بالتطبيق لتبدو واجهة الإضافة أصلية افتراضيًا. دون استنساخ للمستودع، دون npm run build، ودون التعديل على كود التطبيق نفسه. ضع الملف في $HERMES_HOME/desktop-plugins/<id>/plugin.js وسيحمّله التطبيق خلال ثوانٍ ويعيد تحميله تلقائيًا (hot-reload) مع كل حفظ.

      هذا ليس SDK إضافات لوحة تحكم الويب

      تعني "Plugin" أشياء متعددة غير مترابطة في Hermes. تتناول هذه الصفحة SDK تطبيق سطح المكتب الأصلي (hermes desktop) — وحدة @hermes/plugin-sdk و $HERMES_HOME/desktop-plugins/. أما لوحة تحكم الويب (web dashboard) (hermes dashboard) فلها نظام إضافات خاص بها غير مرتبط بهذا، على window.__HERMES_PLUGIN_SDK__ مع manifest.json — موثّق في توسيع لوحة التحكم. أما إضافات Python الخاصة بـ CLI/gateway فموثّقة في بناء إضافة Hermes. الأنظمة الثلاثة لا تتشارك الكود ولا واجهات API ولا آلية التسليم. مساحة الأسماء الخلفية plugin_api.py فقط (/api/plugins/<id>) مشتركة بين SDK سطح المكتب و SDK لوحة التحكم.

      النموذج الذهني​

      يتبع الـ SDK نموذج وحدات VS Code. يستورد مؤلّف الإضافة وحدة واحدة فقط ولا يلمس آليات التطبيق الداخلية أبدًا (فهي مستبعدة عبر lint من الإضافة المجمّعة (bundled)، ويفشل استيرادها في إضافة القرص). تأتي القدرات على شكل مستويات:

      • host.state.* — عروض للقراءة فقط على حالة التطبيق الحية (ذرّات nanostore): الجلسة النشطة، انشغال الدور (turn-busy) لكل جلسة، دليل العمل (cwd)، حالة socket الخاص بـ gateway، النموذج، profile، منفذ العرض (viewport). gateway هو WebSocket، وليس انشغال الدور.
      • إجراءات host.* — أفعال آمنة مُنتقاة بعناية: toast، التنقّل، متابعة السجلات (logs)، إعادة تشغيل gateway، الاشتراك في مجرى أحداث gateway.
      • ctx.preview — شغّل JavaScript في صفحة Browser المعاينة الخاصة بالجلسة المركّز عليها. مغلق افتراضيًا: تعلن الإضافة capabilities: ['preview.executeJavaScript'] ويسمح المستخدم بذلك لكل أصل (origin) للصفحة (سكربتات صفحة المعاينة).
      • host.request — باب gateway الخاص بـ JSON-RPC: الجلسات، الإعدادات، المهارات، cron — كل ما يستدعيه التطبيق نفسه.
      • captureGatewayFileDownload() — التقط إجراء حفظ ملف في الـ gateway مباشرة قبل بدء قراءة REST، واحتفظ به إلى جانب البيانات المعادة. يحافظ الإجراء (storedPath, suggestedName) => Promise<void> على نطاق الاتصال/profile الخاص بتلك القراءة حتى إذا بدّل المستخدم المضيفين قبل النقر. لا تستدعِه إلا استجابةً لإيماءة تنزيل صريحة من المستخدم، باستخدام مسار الملف المحفوظ في backend، لا مسار مساحة عمل مخمَّن أبدًا. يتولى Electron البث الموثّق، ومربع حوار الحفظ الأصلي، والرجوع الاحتياطي للـ gateways الأقدم؛ ولا تتلقى الإضافات بيانات الاعتماد مطلقًا ولا تفتح المسارات البعيدة باستخدام file://. ويعرض المضيف إشعارات "Saved" / "Download failed" نفسها التي تعرضها لوحة Files، ويظل صامتًا عند الإلغاء؛ ويُحسم الوعد عند حسم الحفظ ولا يُرفض أبدًا.
      • ctx.rest / ctx.socket — مساحة الأسماء الخلفية الخاصة بإضافتك (/api/plugins/<id>) إن كنت تشحن plugin_api.py.
      • ui.* — لغة التصميم: المكوّنات الحقيقية للتطبيق، متغيرات السمة، الأيقونات، والمنسّقات (formatters)، بحيث تطابق واجهة إضافتك واجهة التطبيق بكسل بكسل.

      البدء السريع — إضافتك الأولى​

      أنشئ $HERMES_HOME/desktop-plugins/hello/plugin.js (وهو ~/.hermes/... افتراضيًا). إضافات سطح المكتب هي على مستوى التطبيق — جذر واحد لكل profile أو gateway أو جهاز بعيد تتصل به النافذة. يجب أن يطابق اسم المجلد معرّف الإضافة id.

      // ~/.hermes/desktop-plugins/hello/plugin.js
      import { host, haptic, useValue } from '@hermes/plugin-sdk'
      import { jsx, jsxs } from 'react/jsx-runtime'

      function HelloPane() {
        const gateway = useValue(host.state.gateway)

        return jsxs('div', {
          className: 'flex h-full flex-col gap-2 p-3 text-sm',
          children: [
            jsx('div', { className: 'font-medium', children: 'Hello, Hermes' }),
            jsx('div', {
              className: 'text-(--ui-text-tertiary)',
              children: `gateway: ${gateway}`
            })
          ]
        })
      }

      export default {
        id: 'hello', // must match the folder name
        name: 'Hello',
        register(ctx) {
          ctx.register({
            id: 'pane',
            area: 'panes',
            title: 'hello',
            data: { placement: 'right', width: '260px' },
            render: () => jsx(HelloPane, {})
          })
          ctx.register({
            id: 'chip',
            area: 'statusBar.right',
            order: 130,
            render: () =>
              jsx('button', {
                type: 'button',
                className: 'px-1.5 text-[0.6875rem] text-(--ui-text-tertiary)',
                onClick: () => {
                  haptic('tap')
                  host.notify({ kind: 'info', message: 'Hello from my plugin!' })
                },
                children: 'hello'
              })
          })
        }
      }

      احفظ الملف. يراقب التطبيق مجلد desktop-plugins/، ويحمّل الملف خلال ثوانٍ قليلة، ويعيد تحميله تلقائيًا (hot-reload) في مكانه مع كل حفظ لاحق. إن لم يظهر، نفّذ ⌘K → Reload desktop plugins. وإذا فشل التحميل، يظهر toast يسمّي الخطأ — أصلِحه ثم احفظ مجددًا.

      لا JSX ولا بناء

      يُحمَّل ملف القرص دون تجميع، لذا لن تُحلَّل صياغة JSX. اكتب الواجهة باستخدام استدعاءات jsx() / jsxs() من react/jsx-runtime (أو React.createElement). المُحدِّدات (specifiers) القابلة للاستيراد الوحيدة هي @hermes/plugin-sdk و react و react/jsx-runtime — وكل ما عداها يفشل في الحل، عمدًا.

      عقد الإضافة​

      تُصدّر الإضافة افتراضيًا HermesPlugin:

      interface HermesPlugin {
        /** Stable slug — becomes the `plugin:<id>` source and the id namespace. */
        id: string
        /** Human name for Settings / about UI. Defaults to `id`. */
        name?: string
        /** Registers on load when the user hasn't chosen (default true). Set false
         *  for opt-in plugins: they inventory in Capabilities ▸ Plugins, off until the
         *  user flips the switch. */
        defaultEnabled?: boolean
        /** Sensitive doors this plugin uses, declared up front. Today:
         *  'preview.executeJavaScript' (ctx.preview). An undeclared door refuses. */
        capabilities?: readonly string[]
        /** Called once at load; wire contributions through `ctx`. */
        register: (ctx: PluginContext) => void
      }

      تتلقى register كائن مخصَّصًا (scoped) من نوع PluginContext. فهو لا يلمس السجلّ مباشرة أبدًا — إذ يضيف السياق تلقائيًا وسم المصدر (source: 'plugin:<id>') ويضع كل معرّف مساهمة في مساحة أسماء خاصة (<id>:<localId>)، بحيث لا يمكن أبدًا لإضافتين أن تتعارضا.

      interface PluginContext {
        /** Resolved source tag, e.g. `'plugin:hello'`. */
        readonly source: string
        /** Register one contribution (id namespaced, source stamped). Returns a disposer. */
        register: (c: PluginContribution) => () => void
        /** Register several at once; the returned disposer removes all of them. */
        registerMany: (cs: PluginContribution[]) => () => void
        /** Own entry (+ sub-pages) under Settings → Plugins. Removed on disable/unload. */
        registerSettingsPage: (page: PluginSettingsPage) => () => void
        /** REST to this plugin's own backend namespace (`/api/plugins/<id>`). */
        rest: <T>(path: string, opts?: PluginRestOptions) => Promise<T>
        /** Live WebSocket to this plugin's own namespace. Returns a disposer. */
        socket: (path: string, onMessage: (data: unknown) => void) => () => void
        /** Gateway event stream by type (`'*'` = all). Tracked: removed on unload/reload/disable. */
        onEvent: (type: string, listener: (event: GatewayEvent) => void) => () => void
        /** Any other cleanup to run on unload/reload/disable (store subscriptions, injected DOM). */
        onDispose: (fn: () => void) => void
        /** Scoped timers and DOM listeners — cleared with the plugin. Each returns a disposer. */
        setTimeout: (fn: () => void, ms: number) => () => void
        setInterval: (fn: () => void, ms: number) => () => void
        addEventListener: (target: EventTarget, type: string, listener: EventListener, options?: AddEventListenerOptions | boolean) => () => void
        /** The curated OS door: native notification, open-external, reveal-in-file-manager, clipboard. */
        os: PluginOs
        /** Lines in the core pet's speech bubble, attributed to this plugin (see "Pet bubble"). */
        pet: PluginPet
        /** Script in the preview Browser page — declared capability + per-origin user consent
         *  (see "Preview page scripts"). */
        preview: PluginPreview
        /** Plugin-scoped JSON persistence (keys live under `hermes.plugin.<id>.`). */
        storage: PluginStorage
      }

      المساهمة (contribution) هي المُكوّن الأولي الوحيد الذي يشترك فيه كل سطح:

      interface Contribution {
        id: string          // you write the local id; the host namespaces it
        area: string        // WHERE it goes (a contribution-area constant)
        title?: string
        order?: number      // sort within the area (lower = earlier)
        when?: () => boolean // dynamic visibility; re-evaluated by the area
        enabled?: boolean
        render?: () => ReactNode  // the component to mount
        data?: unknown      // area-specific payload (see the cookbook)
      }

      يمكنك توفير render أو data أو كليهما، حسب المنطقة (area).

      الأجزاء (Panes)​

      الجزء (pane) هو بلاطة في شجرة التخطيط. placement هو الدور الدلالي — يتكدّس الجزء (كتبويبات) مع الأجزاء الحالية التي تحمل نفس الدور؛ ويمكن للمستخدم سحبه إلى أي مكان لاحقًا.

      ctx.register({
        id: 'pane',
        area: 'panes',
        title: 'my pane',
        data: { placement: 'right', width: '260px' },
        render: () => jsx(MyPane, {})
      })

      placement هي 'main' | 'left' | 'right' | 'top' | 'bottom'. للاستقرار على حافة معينة بدلًا من التكديس، أضف إيماءة dock — وهي بالضبط ما يحدث عند سحب العنصر إلى شريحة إفلات جزء ما:

      // Below the conversation, 200px tall.
      data: {
        placement: 'bottom',
        dock: { pane: 'workspace', pos: 'bottom' },
        height: '200px'
      }

      dock.pane هو أي معرّف جزء (workspace هو الخيط الرئيسي؛ وأيضًا sessions، terminal، files، review، logs)؛ وdock.pos هو 'top' | 'bottom' | 'left' | 'right' | 'center'. حدّد width/height حتى لا يستحوذ الجزء على نصف المنطقة.

      إغلاق الجزء الوحيد الذي ساهمت به إضافة ما يعطّل تلك الإضافة، ويمكن إعادة تفعيلها من Capabilities → Plugins. عندما تساهم إضافة بعدة أجزاء، لا يؤدي إغلاق أحدها إلا لإخفاء ذلك الجزء فقط، ويبقى بقية أجزاء الإضافة، وأوامرها، والـ middleware الخاص بها نشطًا. تُعيد Reset layout الأجزاء المُساهَم بها التي تم إغلاقها.

      الصفحات وتنقّل الشريط الجانبي​

      يُحمّل المسار (route) صفحة كاملة داخل جزء مساحة العمل، تمامًا كأي عرض مدمج. اقرن ذلك بصفّ تنقّل في الشريط الجانبي (و/أو أمر في لوحة الأوامر) لجعله قابلًا للوصول.

      import { ROUTES_AREA, SIDEBAR_NAV_AREA } from '@hermes/plugin-sdk'

      ctx.registerMany([
        {
          id: 'page',
          area: ROUTES_AREA,
          data: { path: '/my-page' },
          render: () => jsx(MyPage, {})
        },
        {
          id: 'nav',
          area: SIDEBAR_NAV_AREA,
          data: { path: '/my-page', label: 'My Page', codicon: 'project' }
        }
      ])

      السمات (Themes)​

      مساهمة السمة تشحن كائن DesktopTheme كاملًا كبياناتها data (الاسم، التسمية، الألوان، …). تظهر في منتقي السمات كأنها سمة مدمجة.

      import { THEMES_AREA } from '@hermes/plugin-sdk'

      ctx.register({ id: 'noir', area: THEMES_AREA, data: myDesktopTheme })

      تسجيل سمة يدرجها في القائمة فقط؛ ولا يختارها. تقرأ useTheme() المظهر المُطبَّق حاليًا (theme، themeName، availableThemes، resolvedMode) وتغيّره (setTheme، setMode، previewTheme) من داخل مكوّن:

      import { Button, useTheme } from '@hermes/plugin-sdk'

      function ThemePicker() {
        const { availableThemes, setTheme, themeName } = useTheme()

        return availableThemes.map(t => (
          <Button key={t.name} disabled={t.name === themeName} onClick={() => setTheme(t.name)}>
            {t.label}
          </Button>
        ))
      }

      التبديل الناتج عن شيء آخر غير عملية render — اتصال gateway، حدث socket، أي رد نداء host.onEvent — لا يملك مكوّنًا (component) يمكن تعليق الخطاف (hook) عليه. استخدم requestTheme(name) في هذه الحالة. يُرفض الاسم غير القابل للحل بدلًا من إجباره إلى السمة الافتراضية، بحيث تُستخدم القيمة المُعادة نفسها كفحص للتوفر ولا يمكن لاسم خاطئ أن يعيد ضبط مظهر أحدهم بصمت:

      import { host, requestTheme } from '@hermes/plugin-sdk'

      host.onEvent('gateway.ready', () => {
        if (!requestTheme('noir')) {
          host.notifyError('Connected, but the noir theme is not installed.')
        }
      })

      كلا البابين يحفظان الاختيار لكل profile، لذا فإن التبديل الذي تقوده الإضافة يبقى محفوظًا تمامًا كالاختيار اليدوي. لتلوين السمة النشطة بدلًا من استبدالها، استخدم setAccentOverride(hex) وأزِله في ctx.onDispose — إضافة Accent Picker الرسمية هي المثال العملي (وهي أيضًا إضافة قرص كاملة وقابلة للتثبيت).

      تنسيق تبديل المحادثة — data-session-switching​

      يعرض فتح المحادثة سجلها على مراحل: تُحمَّل الجلسة، وتظهر الصفوف، ثم يستقر موضع التمرير المستعاد بعد بضعة إطارات. تستهدف السمة التي تريد إخفاء ذلك (أو تلاشيه) خاصية موثّقة واحدة بدلًا من مراقبة المسار أو DOM: تضبط النواة data-session-switching="true" على جذر واجهة المحادثة ([data-chat-surface]) من الإطار الذي يبدأ فيه التبديل حتى ظهور صفوف السجل الجديد واستقرار موضع تمريرها، ثم تزيلها.

      /* Hide the transcript while it is being placed, fade it in when it lands. */
      :root[data-hermes-theme="noir"] [data-chat-surface] [data-slot="aui_thread-viewport"] {
        transition: opacity 0.12s ease-out;
      }
      :root[data-hermes-theme="noir"] [data-chat-surface][data-session-switching] [data-slot="aui_thread-viewport"] {
        opacity: 0;
        transition: none;
      }
      • لكل واجهة. تملك المحادثة الأساسية وكل بلاطة [data-chat-surface] خاصة بها؛ وتوسم الخاصية الواجهة التي تبدّل وحدها. احصر الاستهداف بالجزء الأساسي عبر [data-composer-target="main"].
      • تنتهي دائمًا. تتحكم فيها مرحلتا التحميل واستعادة التمرير في النواة: تنتهي مرحلة التحميل عند وصول السجل أو توقف محاولة الاستئناف، وتنتهي مرحلة الاستعادة عند الاستقرار (ضمن عدد محدود من الإطارات) أو أول إدخال من المستخدم بالتمرير/المفاتيح/المؤشر، وتنتهيان عند إلغاء التركيب — فلا تستطيع سمة تخفي المحتوى اعتمادًا عليها إبقاء المحادثة مخفية. ولا تضبطها مسودة جديدة فارغة مطلقًا.
      • العقد هو الخاصية. استهدف [data-session-switching] و hooks data-chat-surface / data-slot؛ فأسماء الفئات الداخلية ليست عقدًا وتتغير دون إشعار. لا تبدّل الخاصية بنفسك ولا تعِد إنتاجها بمستمع للمسار أو MutationObserver (قاعدة الكتالوج 8).

      يحل هذا محل نمط installSwitchFade في t3-code-theme (مستمع لمخزن التركيز مع حلقة requestAnimationFrame تستطلع صفوف السجل وموضع التمرير، ثم تبدّل خاصية جذر خاصة بها): يمثل CSS أعلاه الانتقال كاملًا.

      امتدادات محرّر الرسائل (Composer)​

      تتيح COMPOSER_AREAS (top وbottom وunderside وleading وactions و attachments وmiddleware وcontextMenu) للإضافة أن تضيف عناصر تحكم حول محرّر الرسائل (composer)، أو توفّر مصدر مرفقات، أو تحوّل مسودة قبل إرسالها (ComposerMiddleware مع handler(draft) => draft | null). تمثّل top شريط تنبيه فوق الإدخال، وbottom صفًا تحت شبكة الإدخال، وكلاهما داخل إطار composer؛ أما underside فهو الشريط العائم أسفل composer كله دون إطار خاص به — موضع لشارة اقتراح أو تلميح حالة ينبغي أن يقع خارج إطار الإدخال (تعرض إضافة next-prompt شارة "next prompt" هناك).

      قائمة السياق في composer — صفوف عند النقر بزر الفأرة الأيمن في الإدخال​

      تضيف COMPOSER_AREAS.contextMenu صفوفًا إلى القائمة التي يفتحها التطبيق عندما ينقر المستخدم بزر الفأرة الأيمن على composer (الإدخال الرئيسي أو composer تحرير الرسالة). المساهمة عبارة عن بيانات: دالة items(context) يستدعيها التطبيق مرة واحدة عند كل نقرة يمنى. يعرض التطبيق الصفوف بعناصر القائمة الخاصة به، فتأخذ التركيز والتنسيق والتنقل بلوحة المفاتيح مثل العناصر المدمجة؛ ولا تلمس الإضافة DOM القائمة أبدًا.

      import { COMPOSER_AREAS, host } from '@hermes/plugin-sdk'

      ctx.register({
        id: 'spelling',
        area: COMPOSER_AREAS.contextMenu,
        data: {
          // context = { word: string | null, selection: string } — nothing else.
          items: ({ word }) => {
            if (!word || isKnown(word)) return []

            return [
              ...suggest(word).slice(0, 5).map(suggestion => ({
                label: suggestion,
                // Runs after the menu closed, with the caret back in the composer.
                onSelect: action => action.replaceWord(suggestion)
              })),
              { label: ctx.i18n.t('addToDictionary'), onSelect: () => void host.spellcheck.addWord(word) }
            ]
          }
        }
      })
      interface ComposerContextMenuContext {
        word: string | null // the word under the caret (or at the selection's start)
        selection: string // the selected composer text, '' when the caret is collapsed
      }

      interface ComposerContextMenuItem {
        label: string // plain text: controls/bidi overrides stripped, clamped to 80 chars
        disabled?: boolean
        onSelect: (action: ComposerContextMenuAction) => void
      }

      interface ComposerContextMenuAction extends ComposerContextMenuContext {
        replaceWord(text: string): boolean // one line, <= 200 chars
      }

      ما يملكه التطبيق. هو من يقرر أن النقرة وقعت على composer؛ أما أي حقل آخر (مدخلات Settings، ومفاتيح API، ومربعات الحوار، والنص المسجّل للمحادثة) فلا يستشير أي مزوّد أبدًا. يرى المزوّد سلسلتين نصيتين فقط — الكلمة وتحديد composer (بحد أقصى 2,000 حرف) — ولا يرى العنصر ولا Range ولا أي نص آخر. replaceWord هو التعديل الوحيد الذي يتيحه: يستبدل الكلمة التي نقر عليها المستخدم بالضبط عبر أمر التحرير الخاص بـ Chromium، ويعمل مرة واحدة، ويُرجع false (دون تغيير أي شيء) حين لا يعود composer يحتوي تلك الكلمة في ذلك الموضع. وفي أي شيء آخر، استخدم host.composer.

      التحكيم. تحصل كل إضافة على قسمها الخاص، يوضع بعد صفوف التدقيق الإملائي الخاصة بالتطبيق وقبل Cut / Copy / Paste. تُرتَّب الإضافات بحسب معرّف الإضافة (بترتيب code point، ثم معرّف المساهمة)؛ ولا دور لترتيب التحميل ولا لـ order. تعرض الإضافة ستة صفوف على الأكثر عبر جميع مساهماتها؛ وتُسقَط الصفوف الزائدة. المزوّد الذي يرمي استثناءً، أو يُرجع قيمة ليست مصفوفة، أو صفٌّ بلا تسمية نصية أو دالة onSelect لا يساهم بشيء ولا يؤثر في أي صف آخر؛ وonSelect الذي يرمي استثناءً يُسجَّل في السجل ولا يُرفَع. الصفوف المسجَّلة عبر ctx.register تختفي عند إلغاء تحميل الإضافة أو تعطيلها — بما في ذلك من قائمة مفتوحة في ذلك الوقت.

      قاموس التدقيق الإملائي — host.spellcheck​

      host.spellcheck.addWord(word: string): Promise<boolean>
      host.spellcheck.removeWord(word: string): Promise<boolean>

      يضيف كلمة واحدة إلى قاموس التدقيق الإملائي في Chromium الخاص بالتطبيق أو يزيلها منه، فيزول الخط الأحمر التحتي (أو يعود) في كل مكان في التطبيق. تقبل العملية الرئيسية (main process) كلمة واحدة محدودة فقط: أحرفًا وعلامات مركّبة وأرقامًا و' / - داخلية، مع حرف واحد على الأقل وبحد أقصى 64 حرفًا. أي شيء آخر يُرجع false دون المساس بالقاموس؛ وكذلك يفعل غلاف سطح المكتب الأقدم. لا توجد طريقة لسرد القاموس أو قراءته.

      API مسودة مربع الكتابة — قراءة الإدخال الحي وكتابته​

      لكل ما تعجز مناطق مربع الكتابة عن فعله — وضع نص داخل الإدخال، أو استبدال ما فيه، أو قراءة المسودة الحالية، أو إرسالها — استخدم host.composer. هذا هو المسار المدعوم؛ أما الوصول إلى ProseMirror DOM، أو البحث عن [data-composer-target]، أو إنشاء أحداث InputEvent اصطناعية، فهو خارج واجهة الإضافات (قاعدة الكتالوج 8) ويتعطل فور تغير markup التطبيق. العنونة: null = مربع الكتابة الذي يكتب فيه المستخدم؛ ومعرّف جلسة (مخزّن أو وقت التشغيل) = مربع تلك الجلسة، في الجزء الأساسي أو بلاطة؛ و 'new' = المسودة الجديدة التي لا تملك معرّف جلسة بعد.

      import { host } from '@hermes/plugin-sdk'

      // Append to the active composer (modes: 'block' | 'inline' | 'prefix';
      // 'prefix' seats a slash command at the start). Acknowledged like setDraft:
      // true when a mounted surface applied the text, false when the text is blank
      // or no live surface answers for the address.
      const inserted = await host.composer.insertText(null, 'draft note', { mode: 'inline' })

      // Replace a session's whole draft — '@'-ref and '/command' tokens hydrate
      // into chips exactly like an official paste. False when no mounted surface
      // answers (an unmounted session is never half-written).
      const ok = await host.composer.setDraft('sess-1', 'plan:\n- @file:src/app.ts')

      // Read the live draft: the mounted surface's in-DOM text (unsaved keystrokes
      // included), falling back to the debounced persisted stash. Null when nothing
      // holds it.
      const text = await host.composer.getDraft('sess-1')

      // Send as if the user typed + pressed Enter. Fail-closed like the app's own
      // panels: no visible surface for the address → false, never a broadcast.
      const sent = host.composer.submit('sess-1', 'ship it')

      // Put the caret in a composer (same addressing). insertText/setDraft already
      // focus a visible surface they paint; use this to return the caret after a
      // plugin popover closes or from a "go to input" keybind.
      host.composer.focus(null)
      host.composer: {
        getDraft(sessionId: string | null): Promise<string | null>
        setDraft(sessionId: string | null, text: string): Promise<boolean>
        insertText(sessionId: string | null, text: string, opts?: { mode?: 'block' | 'inline' | 'prefix' }): Promise<boolean>
        submit(sessionId: string | null, text: string): boolean
        focus(sessionId: string | null): void
      }

      التحكيم. تتعامل كل عملية مع عنوانها بالرفض عند عدم التطابق: لا يجيب الطلب إلا مربع الكتابة المركّب الذي يملك تلك الجلسة (بلاطتها، أو الجزء الأساسي إذا كان يعرضها)؛ ولا يجيب null إلا الواجهة التي يوجّه إليها ناقل التركيز في التطبيق حاليًا؛ ولا تجيب 'new' إلا في الجزء الأساسي عندما لا يعرض جلسة — ولا تنتقل مطلقًا إلى مربع الكتابة النشط. في غياب واجهة مطابقة → null/false، ولا يحدث بث إلى أي جزء صادف أنه مركّب. تمر الكتابات عبر مسار العرض الخاص بالتطبيق، فتُحمَّل tokens المراجع @ وأوامر / كشارات، وتطابق النتيجة على مستوى البايتات ما يحصل عليه المستخدم عند اللصق. هذه إجراءات منفصلة يطلقها المستخدم ولها صلاحية الكتابة نفسها — ولا تملك أي إضافة المسودة بعدها، ولذلك لا يوجد ما يلزم إزالته عند التعطيل؛ وتستخدم الإضافة التي تريد حضورًا دائمًا حول الإدخال خانة COMPOSER_AREAS بدلًا من ذلك.

      تحتفظ الإضافة متعددة الجلسات بحالتها لكل جلسة من جانبها (الجلسة التي تحررها لوحتها) وتمرّر ذلك المعرّف هنا؛ ويضمن الناقل عدم وصول كتابة إضافة إلى مربع جلسة أخرى مطلقًا.

      صفوف الجلسات — الزخارف + API قائمة الجلسات​

      import { SESSION_ROW_AREAS, type SessionRowSlotContribution } from '@hermes/plugin-sdk'

      ctx.register({
        area: SESSION_ROW_AREAS.trailing,
        id: 'my-tag',

      المعرّفات معرّفات جلسات مخزّنة: يُربَط المعرّف الحي بجذر سلالته الدائم، فتبقى التثبيتات والألوان بعد تدوير المعرّفات عند الضغط — وتسلم خانات زخرفة الصفوف دالة العرض ذلك المعرّف الدائم نفسه (_lineage_root_id ?? id)، لا الحي مطلقًا. يمر التحديد بالصفوف التي حمّلتها هذه النافذة؛ ويُكتب المعرّف الذي لا يطابق صفًا محمّلًا كما هو، لذلك مرّر معرّف الخانة الدائم (لا معرّفًا حيًا حفظته) لجلسة قد خرجت من القائمة بالتمرير. تقبل reorder المعرّفات نفسها وتربط كلًّا منها بمعرّف صفه الحي داخليًا — يُفهرَس مخزن ترتيب Recents بالمعرّف الحي، مثل مسار السحب. تضع pin(id, true, index) التثبيت في ذلك الموضع من قائمة Pinned (هدف إفلات بين تثبيتين)؛ ودون index تضيفه إلى النهاية، مثل نقرة ⇧ على الصف.

      التحكيم. العمليات تعديلات منفصلة على بيانات المستخدم يطلقها بنفسه — تفوز الكتابة الأخيرة، تمامًا كما لو نقر المستخدم، ولا تملك أي إضافة النتيجة بعدها. تُركَّب كل مساهمات الخانات (بترتيب التسجيل، لا بفوز الأول)، كل منها داخل حدود أخطائها: لا تستطيع إضافة تطلق استثناءً أو تعيد null لصف منع زخرفة إضافة أخرى عليه، وتُعرض زخرفتان على صف واحد جنبًا إلى جنب. تحتفظ النواة بتخطيط الصف وإيماءاته وعنوانه — تضيف الخانات ولا تستبدل مطلقًا.

      الإزالة. لا تحتاج إليها العمليات. تُزال مساهمات الخانات بواسطة دالة التخلص التي تعيدها ctx.register (يُسقطها التعطيل/إعادة التحميل ويُعاد عرض الصف دون الزخرفة).

      مزوّدو تسمية شارة النموذج​

      import { COMPOSER_AREAS, type ComposerModelPillContext, type ComposerModelPillProvider } from '@hermes/plugin-sdk'

      interface ComposerModelPillContext {
        model: string            // the model slug the pill would show
        reasoningEffort: string  // the session's live effort level, '' when the model has none
        compact: boolean         // floating-composer mode: chevron only, providers are NOT consulted
      }
      interface ComposerModelPillProvider {
        label: (ctx: ComposerModelPillContext) => string | null
      }

      ctx.register({
        area: COMPOSER_AREAS.modelPill,
        id: 'my-label',
        data: { label: ({ model, reasoningEffort }) => reasoningEffort ? `${model} · ${reasoningEffort}` : null } satisfies ComposerModelPillProvider
      })

      التحكيم. يُستشار المزوّدون بترتيب السجل، وتفوز أول سلسلة غير فارغة؛ ولا يُستدعى المزوّدون اللاحقون. تعني أي قيمة أخرى الرفض ويُسأل المزوّد التالي: null, ''، وسلسلة من مسافات فقط، وأي قيمة غير نصية (لا يُعرض كائن أو مصفوفة أو عدد مطلقًا — توضع التسمية مباشرةً في JSX). ويرفض أيضًا المزوّد الذي يطلق استثناءً — يُبتلع الخطأ وتنتقل الشارة إلى المزوّد التالي، ثم تسمية النواة، فلا تستطيع إضافة معطلة إفراغ الشارة مطلقًا. تكون reasoningEffort دائمًا string ('' عندما لا يملك النموذج مستوى جهد، ولا تكون undefined مطلقًا). في الوضع المضغوط (العائم)، لا تعرض الشارة إلا علامة السهم، ولا يُستدعى أي مزوّد. ولا تُقيَّم label() مجددًا إلا عند تغير السجل أو النموذج أو مستوى الجهد أو خيار الوضع المضغوط.

      الإزالة. المزوّد مساهمة بيانات عادية: تعيد ctx.register دالة التخلص الخاصة به، ويُسقطه المحمّل عند تعطيل الإضافة أو إعادة تحميلها، وعندئذ تُستعاد تسمية النواة. لا يوجد شيء لإلغائه في ctx.onDispose.

      نقل compact-reasoning-label. كانت الإضافة تعثر على الشارة عبر [data-slot="composer-root"] button span.truncate، وتحذف كلمة جهد أخيرة من span.textContent باستخدام regex، وتكرر ذلك من MutationObserver على مستوى body مع setInterval كل ثانية. في نسخ البناء الحالية لم تعد تسمية النواة تتضمن كلمة الجهد (للمستوى ReasoningPill خاصة به)، فيكون الحذف بلا أثر؛ والصيغة المعتمدة حساب التسمية من السياق بدلًا من تحرير النص المعروض:

      register(ctx) {
        ctx.register({
          area: COMPOSER_AREAS.modelPill,
          id: 'compact-reasoning-label',
          // Decline (null) whenever there is nothing to change so the core label wins.
          data: { label: ({ model }) => shorten(model) ?? null }
        })
        // No MutationObserver, no setInterval, no injected <style>: the contribution is
        // disposed with the plugin.
      }

      لا توجد hook لـ CSS رؤية شارة الاستدلال الذي كانت الإضافة تحقنه أيضًا؛ ولا يلزم إلا إذا أخفى التطبيق تلك التسمية عند عرض ضيق.

      زخارف صفوف قائمة النماذج​

      MODEL_MENU_ROW_AREA تضع علامة لكل نموذج داخل قائمة النماذج الأصلية — التي تفتحها شارة مربع الكتابة وكل واجهة أخرى تعرض ModelCatalogMenu. توفر المساهمة decorate(row)؛ وتعرض النواة ما تعيده في خانتين ثابتتين بالصف: أيقونة في البداية قبل اسم النموذج، و شارة في النهاية بعد شارات النواة نفسها. تظل markup الصف واسمه ونجمته وقائمته الفرعية والنقر عليه ملكًا للنواة.

      import { MODEL_MENU_ROW_AREA, type ModelMenuRowContribution } from '@hermes/plugin-sdk'

      interface ModelMenuRowContext {
        provider: string  // provider slug: 'anthropic', 'openrouter', …
        model: string     // the model id the row commits
        label: string     // the display name core paints on the row
      }
      interface ModelMenuRowDecoration {
        icon?: ReactNode  // element (<img>, <svg>, a component) or short text, drawn in a 1rem box
        badge?: string    // plain text chip
      }

      ctx.register({
        area: MODEL_MENU_ROW_AREA,
        id: 'provider-marks',
        data: {
          decorate: ({ provider }) => {
            const src = PROVIDER_ICONS[provider]   // data: URL of an SVG mark
            return src ? { icon: <img alt="" src={src} /> } : null
          }
        } satisfies ModelMenuRowContribution
      })

      التحكيم. تعمل دوال التزيين بترتيب السجل لكل خانة: تملأ أول دالة تعيد icon صالحة خانة الأيقونة، وتملأ أول badge صالحة خانة الشارة، فتجتمع إضافة أيقونة وإضافة شارة تسعير على الصف نفسه. تعني null (أو غياب قيمة صالحة) الرفض. لا تُقبل كأيقونة إلا عناصر React أو سلسلة غير فارغة، ولا تُقبل كشارات إلا سلسلة غير فارغة؛ ويُتجاهل أي شيء آخر بدلًا من عرضه. وترفض أيضًا دالة تزيين تطلق استثناءً، ولا يُفرغ مكوّن أيقونة يطلق استثناءً أثناء العرض إلا خانته (إذ يقع داخل حدود أخطائه) — فلا تستطيع إضافة معطلة إسقاط القائمة مطلقًا. ولا تُنفّذ decorate() مجددًا إلا عند تغير السجل أو مزوّد الصف/نموذجه/تسميته، فاجعلها عملية بحث خالصة.

      الإزالة. مساهمة بيانات عادية: تزيلها دالة التخلص الخاصة بـ ctx.register (وكذلك تعطيل الإضافة/إعادة تحميلها)، وتُعاد الصفوف للعرض دون الزخارف.

      نقل t3-code-theme. كانت علامات المزوّدين الخاصة بها تُرسَم في القائمة المفتوحة بواسطة MutationObserver يعثر على الصفوف في DOM القائمة ويكتب صور أقنعة عليها. تأتي العلامات نفسها من decorate({ provider }) التي تعيد { icon: <img alt="" src={providerSvgDataUrl(provider)} /> } — دون قراءة DOM، ويظل الصف يعمل عندما تتغير markup القائمة.

      شارات بطاقات Kanban​

      تضع KANBAN_CARD_AREAS.badges تسميات نصية صغيرة على بلاطات بطاقات Kanban: مثل tenant، أو حالة CI، أو تقدير. تقدّم المساهمة الدالة decorate(card)؛ وترسم اللوحة ما تُرجعه على هيئة رقائق (chips) في صف ثابت فوق عنوان البطاقة. تبقى بنية البطاقة وتخطيطها والسحب والإفلات والنقر وقائمة السياق من اختصاص اللوحة، ولا يشغل الصف مساحة على البطاقات التي لا توجد لها شارة من أي إضافة.

      import {
        KANBAN_CARD_AREAS,
        KANBAN_CARD_BADGE_HUES,
        type KanbanCardBadgeContribution
      } from '@hermes/plugin-sdk'

      interface KanbanCard {            // frozen; identity and routing fields only
        id: string                      // task id (t_…): key your own per-card data by it
        status: string                  // the column: 'triage', 'ready', 'running', …
        tenant: string | null
        assignee: string | null
      }
      interface KanbanCardBoard {       // frozen; shared by every card on the board
        tenants: readonly string[]      // every tenant on the board (its filter menu's list)
      }
      interface KanbanCardBadge {
        label: string                   // plain text
        tone?: KanbanCardBadgeTone      // 'neutral' (default) or one of KANBAN_CARD_BADGE_HUES
        tooltip?: string                // plain text hover line
      }

      ctx.register({
        area: KANBAN_CARD_AREAS.badges,
        id: 'tenant',
        data: {
          // `tenants` lets you give each tenant on the board its own hue instead of
          // hashing blind (two tenants can hash to the same one).
          decorate: ({ tenant }, { tenants }) =>
            tenant
              ? { label: tenant, tone: KANBAN_CARD_BADGE_HUES[distinctIndex(tenant, tenants) % 12], tooltip: `Tenant: ${tenant}` }
              : null
        } satisfies KanbanCardBadgeContribution
      })

      قد تُرجع decorate(card, board) شارة واحدة، أو مصفوفة، أو null للبطاقات التي ليس لديها ما تقوله عنها. لا تحمل عروض البطاقة نصوصًا (العنوان، والمتن، والملخصات، والتعليقات، ومخرجات التشغيل)؛ فابحث عن أي شيء آخر تحتاجه بواسطة id في بياناتك (ctx.rest إلى الواجهة الخلفية الخاصة بك، أو ctx.storage). كلا العرضين مجمّد.

      ما تقبله اللوحة (KANBAN_CARD_BADGE_LIMITS):

      • نص فقط. يجب أن تكون label وtooltip سلاسل نصية وتُعرضان كنص، لا كـ markup أبدًا. تُزال محارف التحكم، وتجاوزات الاتجاه الثنائي (bidi overrides)، والمحارف عديمة العرض، وتُدمَج المسافات البيضاء، ويُقصَّر النص الذي يتجاوز 24 حرفًا (label) أو 160 حرفًا (tooltip) بنقاط حذف. تُتجاهل التسمية الفارغة أو غير النصية. ويُتجاهل أي حقل آخر (render أو html أو نمط style).
      • لوحة ألوان ثابتة. قيمة tone إما 'neutral' أو واحدة من KANBAN_CARD_BADGE_HUES الاثنتي عشرة ('red' و'orange' … 'pink'، وهي درجات هوية التطبيق بترتيب الدرجة، وهي المجموعة نفسها في PROFILE_SWATCHES). أي قيمة أخرى تُرسم محايدة. وتختار اللوحة الألوان الفعلية بحسب السمة.
      • شارتان لكل إضافة في كل بطاقة، تُحتسبان عبر جميع مساهمات الإضافة في هذه المنطقة. وتُسقَط الشارات الزائدة.
      • النسبة إلى المصدر. ينتهي tooltip كل شارة باسم الإضافة، فيستطيع المستخدم دائمًا معرفة أي إضافة رسمتها.

      التحكيم. تُعرض شارات كل الإضافات جنبًا إلى جنب؛ ولا تستطيع أي إضافة إخفاء شارات إضافة أخرى أو إعادة ترتيبها أو تغيير نمطها. يُرتَّب الصف بحسب معرّف الإضافة، ثم معرّف المساهمة، ثم الترتيب الذي أرجعت به decorate الشارات. ويُتجاهل حقل order الخاص بالمساهمة هنا، فلا يستطيع ترتيب التحميل ولا المزايدة تحريك شارة. المزخرِف (decorator) الذي يرمي استثناءً لا يساهم بشيء (يُسجَّل مرة واحدة) وتُرسم بقية الصف كالمعتاد.

      التحديثات والتفكيك. تُعاد decorate() عند تغيّر السجل (registry)، أو عند تغيّر معرّف البطاقة أو حالتها أو tenant أو المُسنَد إليه، أو عند تغيّر قائمة tenants في اللوحة، فاجعلها بحثًا خالصًا (pure lookup). وعندما تتغير بياناتك (مثلًا يثبّت المستخدم لونًا جديدًا في صفحة الإعدادات الخاصة بك)، استدعِ ctx.register مرة أخرى بالـ id نفسه: يحل التسجيل الجديد محل القديم وتعيد اللوحة الرسم. احتفظ بأحدث disposer؛ إذ إن الأول سيزيل البديل. عند التعطيل أو إعادة التحميل أو إلغاء التحميل، يزيل المضيف المساهمة وتُعاد رسم البطاقات دون شاراتها؛ ولا شيء لتتراجع عنه في ctx.onDispose.

      ترحيل إضافة تزخرف DOM (kanban-tenant-labels): احذف استطلاع المسار (route poll) وMutationObserver ومطابقة البلاطات و<span> المُدرَج وقراءات ذاكرة الاستعلامات (query cache) الخاصة بإضافة Kanban. يصبح الزخرفة كلها استدعاء ctx.register أعلاه. ويعمل إسنادها الخالي من التصادمات على board.tenants بدلًا من لقطة query-cache، وتُربط تثبيتات ألوانها بـ KANBAN_CARD_BADGE_HUES (درجاتها الاثنتا عشرة هي المجموعة نفسها hsl(n×30 68% 58%) وبالترتيب نفسه).

      حسم التعارض: يُحمَّل كل تسجيل بترتيب السجل، كلٌّ ضمن حدود خطأ خاصة به — المساهمة التي تثير استثناءً تُختزل إلى بطاقة خطأ مضمّنة تسمّي id الخاصة بها (مع Retry)، وتستمر بقية الصفحة (وبطاقات الإضافات الأخرى) في العرض. لا تُحمَّل الخانة إلا على صفحة Appearance الرئيسية، لا على الصفحات الفرعية عبر روابط عميقة (settings/appearance/<section>)، ولا يوجد "الأول يفوز" — لا يمكن للإضافات كتم بعضها هنا.

      الإنهاء: يملك محمِّل الإضافات التسجيل؛ وتعطيل الإضافة أو إعادة تحميلها يلغيه وتختفي البطاقة في العرض التالي. لا يُحفظ شيء من جانب التطبيق، فلا يوجد ما تنظّفه في ctx.onDispose.

      لاختيار اللون استخدم شبكة عينات التطبيق نفسها — ColorSwatches (مصدَّرة بالفعل من SDK) تعرض ما يعرضه شريط profiles ومربع حوار المشروع تمامًا، مع onChange الخاصة بك؛ قدّم لها PROFILE_SWATCHES واقرنها بـ host.sessions.setColor(id, color) لألوان الجلسة.

      الترحيلات للإضافات التي دعت إلى إنشاء هذه الخانة:

      • better-session-appearance — استبدل اجتياز fiber الذي يلتقط { onChange, swatches } من قائمة Appearance الفرعية، وحقن clearBtn.after(...) / host.appendChild(panel) في قائمة التطبيق المنسدلة، باستدعاء واحد لـ ctx.register({ area: APPEARANCE_AREAS.extra, id: 'rules', render }) تعرض بطاقته <ColorSwatches swatches={PROFILE_SWATCHES} value onChange /> وعناصر التحكم الخاصة بالخط العريض/الرموز/القواعد التلقائية؛ وتخلّ عن كتابات السمة data-better-session-appearance وتجاوزات max-height في القائمة المنسدلة.
      • hermes-appearance-hub — حمّل عناصر التحكم في ملمس الورق / الخط / نص المقدمة كبطاقة APPEARANCE_AREAS.extra بدلًا من قائمة شريط حالة تمتد إلى Settings؛ وتظل قيم الإعدادات تمرّ عبر host.settings (مفاتيح قائمة السماح) و THEMES_AREA.

      صفحات إعدادات الإضافات (Settings → Plugins)​

      Settings → Plugins هو الموضع الوحيد لتفضيلات الإضافات، بتخطيط يشبه خيارات AddOns في WoW: لكل إضافة ذات إعدادات مدخلة خاصة في شريط Settings، واختيارها يوسّع صفحاتها الفرعية. لا تبنِ مربع تفضيلات أو جزءًا أو صف شريط جانبي للإعدادات. سجّل صفحة:

      ctx.registerSettingsPage?.({
        id: 'settings',            // unique within your plugin
        title: 'Weather',          // rail label + breadcrumb
        icon: 'cloud',             // codicon name; a plug when omitted
        order: 0,                  // ascending; ties sort by title
        render: () => jsx(General, {}),        // the entry's landing page
        children: [                // optional sub-pages, listed in this order
          { id: 'units', title: 'Units', render: () => jsx(Units, {}) },
          { id: 'alerts', title: 'Alerts', render: () => jsx(Alerts, {}) }
        ]
      })
      • تعيش الصفحة ما دامت الإضافة موجودة. يزيلها التعطيل أو إلغاء التحميل مثل كل تسجيل ctx آخر، وتزيلها دالة الإلغاء المُعادة مبكرًا.
      • ابنِ الصفحة من المكوّنات الأساسية للإعدادات (ToggleRow، ListRow، SegmentedControl، Select*) واحفظ باستخدام ctx.storage كي تبدو مثل Settings الأساسية. تُعرض كل صفحة ضمن حدود خطأ خاصة بها.
      • registerSettingsPage جديد؛ ويُبقي ?. الإضافة قابلة للتحميل على مضيفين أقدم. على هؤلاء المضيفين، ctx.register({ area: SETTINGS_PLUGINS_AREA, id, title, render, data: { icon, children } }) هو الشيء نفسه مكتوبًا صراحةً.
      • رابط عميق: host.navigate(pluginSettingsHref('<your-plugin-id>', 'units')) (/settings?tab=plugins&plugin=<id>&ppage=<sub-page>). معرّفات الصفحات الفرعية لك: لا معرّف محجوزًا.
      • تحصل إضافات الوكيل على صفحة تلقائيًا. تُعرض config_schema في plugin.yaml كنموذج تحت Settings → Plugins، يُحفظ عبر plugins.manage settings للـ profile الذي يستهدفه منتقي نطاق Settings (/settings?tab=plugins&agent=<key>). تفتح علامة الترس في صف الإضافة تحت Capabilities → Plugins تلك الصفحة للـ profile المحدد في Capabilities. في حزمة موحدة (جانب الوكيل مع desktop/plugin.js)، عندما يسجّل جانب Desktop صفحة أيضًا، يظهر نموذج المخطط كصفحة فرعية Agent settings لتلك المدخلة، فتملك الحزمة مدخلة واحدة.

      src/plugins/hello-runtime/plugin.runtime.js مثال وقت تشغيل كامل: صفحة واحدة وصفحتان فرعيتان، يدعمها ctx.storage.

      تضمين محتوى خارجي​

      استخدم <SandboxedFrame src title /> في SDK لأي محتوى ويب خارجي (عروض القراءة، ولوحات التحكم، والتوثيق). يعرض iframe داخل sandbox بوضعية محتوى الضيف في التطبيق: أصل معتم، و allow-scripts افتراضيًا، و no-referrer، وتحميل كسول. لا تحمّل <webview> خامًا من Electron أبدًا: فهو يقع في قسم معاينة persist: الخاص بالتطبيق، ويشارك التطبيق cookies والتخزين.

      interface SandboxedFrameProps {
        src: string      // absolute http(s): or data: URL; any other scheme renders nothing (console.warn)
        title: string    // required — an untitled frame is unlabelled in the a11y tree
        sandbox?: string // extra tokens; filtered through the allowlist below
        className?: string; style?: CSSProperties
        onLoad?, onError?: ReactEventHandler<HTMLIFrameElement>
        ref?: Ref<HTMLIFrameElement>
      }

      الخصائص قائمة سماح صريحة، لا ComponentProps<'iframe'>: allow (تفويض Permissions-Policy — سيمنح موقعًا خارجيًا صلاحية الميكروفون/الكاميرا التي يملكها التطبيق)، و srcdoc، name، allowFullScreen، csp، credentialless وكل سمات iframe الأخرى ليست خصائص، ولا يُمرَّر شيء منها إلى العنصر، فلا تصل إلى DOM حتى عبر تحويل نوع.

      حسم التعارض (قائمة سماح، لا قائمة حظر): القيم الوحيدة التي يستطيع المستدعي إضافتها هي allow-scripts، allow-forms، allow-downloads، allow-pointer-lock، allow-orientation-lock، allow-presentation. كل ما عدا ذلك — allow-same-origin، allow-top-navigation*، allow-popups*، allow-modals، allow-storage-access-by-user-activation، وأي token لا يعرفه المكوّن الأساسي — يُسقط دون اعتبار لحالة الأحرف حتى إن مُرِّر؛ وتعود المجموعة الفارغة إلى الوضعية الافتراضية (allow-scripts)، لأن إطارًا لا يحمل سمة sandbox يكون كامل الامتيازات. loading="lazy" و referrerPolicy="no-referrer" ليستا خصائص. الأصل المعتم هو العزل نفسه: لا يستطيع محتوى الضيف الوصول إلى التطبيق أو تخزينه أو جسر preload.

      الإنهاء: إنه عنصر React عادي — إلغاء تحميل جزئك/صفحتك يزيل الإطار ونطاقه؛ ولا يُسجَّل شيء من جانب التطبيق.

      ترحيل rss-reader (#115972): استبدل سلسلة /preview → 501 → host.openWorkspace('rss-browser') → RssBrowserFrame → ctx.os.openExternal الفارغة بـ <SandboxedFrame src={article.url} title={article.title} /> داخل صفحة مساحة العمل؛ وتخلّ عن CSS المتبقي الخاص بـ .rss-browser-frame-host webview.

      توجيهات النسخة النصية (transcript) — مكوّنات مضمّنة يخاطبها النموذج​

      تجعل TRANSCRIPT_DIRECTIVE_AREA النسخة النصية نفسها منطقة مساهمة. سجّل توجيهًا مسمّى، ويمكن للوكيل عندها عرض مكوّنك مضمَّنًا داخل رسالة المساعد بإصدار فقرة على الصيغة ::name{key="value"}:

      import { TRANSCRIPT_DIRECTIVE_AREA } from '@hermes/plugin-sdk'

      ctx.register({
        id: 'task-card',
        area: TRANSCRIPT_DIRECTIVE_AREA,
        data: {
          name: 'task', // the model writes ::task{id="BB-12"}
          render: ({ attrs, sessionId, streaming }) => jsx(TaskCard, { taskId: attrs.id, sessionId, streaming })
        }
      })

      تتلقى render القيمة { attrs, source, streaming, sessionId }. يسمّي sessionId المحادثة التي يعرض نصها المسجّل البطاقة (معرّفها المخزَّن، وإلا معرّفها وقت التشغيل؛ وnull ما دامت المحادثة بلا جلسة بعد). مرّره إلى أفعال host.composer ليستقر إجراء البطاقة في تلك المحادثة، حتى حين تحمل محادثة أخرى مفتوحة جنبًا إلى جنب composer النشط:

      function TaskCard({ taskId, sessionId }) {
        const next = () => {
          // Older hosts don't pass sessionId (undefined): fall back to the active
          // composer, which is what `null` addresses.
          const sent = host.composer.submit(sessionId ?? null, `Continue task ${taskId}`)
          if (!sent) host.notify({ kind: 'warning', message: 'Open that chat to continue' })
        }
        return jsx('button', { onClick: next, children: 'Next' })
      }

      الأفعال الموجّهة تفشل بإغلاق آمن (fail closed): حين لا يكون لدى محادثة البطاقة composer مرئي، تُرجع submit القيمة false ولا يُرسَل شيء إلى أي مكان آخر.

      القواعد التي يفرضها المضيف (host) لإبقاء السطح آمنًا:

      • يجب أن يكون التوجيه الفقرة بأكملها — فـ::name في وسط النص العادي يبقى نصًا عاديًا، بحيث لا يمكن لمكوّنات الإضافة أبدًا اختطاف النص الجاري.
      • السمات (attributes) هي مخرجات نموذج غير موثوقة (أزواج key="value"، نصية فقط). تحقّق من حقولك الخاصة؛ ولا تعرض شيئًا عند بيانات فاسدة بدلًا من التخمين.
      • التوجيه غير المُطالَب به (لا إضافة مسجَّلة بهذا الاسم) يُعرَض كفقرة نصية عادية كما كان دائمًا — لا شيء ينكسر عندما تكون الإضافة معطّلة.
      • عمليات العرض ملفوفة داخل حدود خطأ المساهمة (error boundary): أي رمي استثناء يتحوّل إلى شريحة خطأ مضمّنة، وليس إلى رسالة ميتة.
      • التسجيل الأول يفوز عند تعارض الأسماء؛ ضع الأسماء الطموحة في مساحة أسماء خاصة بمعرّفك (myplugin-board، وليس board).

      يشحن الأساسي (Core) توجيهًا واحدًا كمستهلك مرجعي: ::preview{file="…"} يعرض ملف HTML الخاص بمساحة العمل مباشرة داخل الرسالة — عبر إطار srcdoc معزول ذي أصل (origin) غير شفاف (تعمل النصوص البرمجية والعنصر تفاعلي بالكامل؛ دون أي وصول إلى التطبيق أو تخزينه أو الجسر). يتحجّم الإطار وفق المحتوى (الارتفاع حيّ، والعرض مأخوذ من امتداد المحتوى الجوهري، محاذًا لليسار في تدفق الرسالة)، وتمنح مقدّمة سمة (theme prelude) المستند رموز التطبيق (tokens) المُحلَّلة (--foreground، --muted-foreground، --accent، --border، --card)، وخط التطبيق، وخلفية شفافة — بحيث تبدو واجهة HTML على شكل عنصر (widget) أصلية بينما تحافظ الصفحة الكاملة على تصميمها الخاص. الأهداف غير HTML و gateways البعيدة تعود إلى بطاقة المعاينة الكلاسيكية. أخبر الوكيل عن توجيهك في مهارة (skill) (فهكذا يتعلّم إصداره).

      يمكن للعناصر (widgets) المعروضة أيضًا الرد. داخل الإطار، يعطي window.hermes.send('get-price eth') (أو بشكل تصريحي عبر <button data-hermes-send="get-price eth"> — دون الحاجة لأي نص برمجي) ذلك الأمر (prompt) للوكيل كدور مستخدم، خارج الشاشة: لا تشغل فقاعة أي مساحة في النسخة النصية، وتحديث العنصر نفسه هو الاستجابة المرئية. يبقى الدور حقيقيًا — فهو يوقظ الوكيل، ويسير وفق قواعد التوجيه/الانتظار (steer/queue) الخاصة بمحرّر الرسائل، ويُحفظ (بنوع hidden) كي يحتفظ الاستئناف وقاعدة بيانات الجلسة بالسجل كاملًا. تُزال المسافات الطرفية من prompts، ويُحد طولها بـ 500 حرف (window.hermes.maxLength)، وتُقيَّد بمرة واحدة في الثانية لكل إطار. لا يُقتطع شيء ولا يُسقط بصمت: يعيد send() كائن Promise يُحسم بالقيمة { ok: true } عند وصول الـ prompt إلى محرر رسالة المحادثة، أو { ok: false, error } حيث تكون error too_long (مع maxLength), throttled (مع retryAfterMs), invalid، أو undelivered (لم يقبله محرر رسالة مرئي). تحقّق منها قبل إظهار widget على أنه محفوظ.

      عارضات وسائط الأدوات — ارسم الملفات التي تنتجها أدواتك​

      تستطيع الحزمة الموحّدة (أدوات الوكيل + نصف خاص بسطح المكتب) أن تقرر كيف يعرض Desktop الوسائط التي تنتجها أدواتها نفسها. عندما يسلّم ردّ المساعد ملفًا بسطر MEDIA:، يبحث Desktop عن استدعاء الأداة الذي سمّى نتيجته المسار لأول مرة، في وقت سابق من النص المسجّل. وإذا كانت الإضافة المالكة لتلك الأداة قد سجّلت عارضًا لاسم الأداة، فإن مكوّنك يحل محل المشغّل المدمج:

      import * as sdk from '@hermes/plugin-sdk'
      import { useEffect, useState } from 'react'
      import { jsx, jsxs } from 'react/jsx-runtime'

      export default {
        id: 'sound-fx', // the desktop half of the `sound-fx` package
        register(ctx) {
          // Older Desktops don't export the area: keep your old path there.
          if (typeof sdk.TOOL_MEDIA_RENDERER_AREA !== 'string') return

          ctx.register({
            id: 'sound-card',
            area: sdk.TOOL_MEDIA_RENDERER_AREA,
            data: {
              tools: ['sound_fx_generate'], // a tool this package's plugin.yaml registers
              render: props => jsx(SoundCard, props)
            }
          })
        }
      }

      function SoundCard({ file, args, result, sessionId, fallback }) {
        const [src, setSrc] = useState(null)
        useEffect(() => {
          let live = true
          file.resolveUrl().then(url => live && setSrc(url), () => live && setSrc(''))
          return () => { live = false }
        }, [file])

        if (file.kind !== 'audio' || src === '') return fallback // the built-in player
        return jsxs('figure', {
          children: [
            jsx('figcaption', { children: args.prompt ?? file.name }),
            src && jsx('audio', { controls: true, src })
          ]
        })
      }

      تتلقى render:

      الخاصية (Prop)ما هي
      file{ path, name, kind, mime, resolveUrl() }. path هو المسار على جهاز الواجهة الخلفية تمامًا كما كتبه سطر MEDIA:؛ لا تفتحه بنفسك أبدًا. تُرجع resolveUrl() عنوان URL تستطيع هذه النافذة تحميله مع واجهة خلفية محلية أو بعيدة: مسار بث بالنطاقات (range-streaming) للصوت والفيديو، وdata URL لأي شيء آخر (بحد أقصى يحدده قارئ الملفات في المضيف)، ويُقرأ من الواجهة الخلفية المالكة للمحادثة. الملف الكبير (نموذج ثلاثي الأبعاد) الأفضل أن يُخدَّم عبر مسار plugin_api.py الخاص بك، يُستدعى بـ ctx.rest وpath.
      toolName, toolCallIdالاستدعاء المنتِج.
      args, resultوسائط الاستدعاء ونتيجته (النتيجة كما أرجعتها الأداة: كائن أو سلسلة نصية). تعيد المحادثة المُعاد فتحها بناءها من السجل، لذا اقرأ الحقول بحذر: قد تحمل args مفاتيح للعرض (context والتسميات) وقد تصل result مُحلَّلة (parsed) بينما كانت سلسلة JSON في الوضع الحي.
      sessionIdالمحادثة التي يعرض نصها المسجّل الملف (بالمعنى نفسه لـ sessionId في directive)، أو null.
      fallbackالمشغّل المدمج لهذا الملف. أرجِعه (أو null) لأي شيء لا ترسمه.

      ما يضمنه المضيف:

      • الملكية تُحدَّد بالمصدر (provenance) لا بنوع الملف. لا يُعتدّ بالمطالبة إلا للأدوات التي سجّلها كود حزمتك نفسه: الأدوات الأصلية من ctx.register_tool في إضافة plugin.yaml ضمن الحزمة نفسها، أو أدوات خوادم MCP التي تعلنها حزمتك المحمولة (تطابق * اللاحقة بحسب البادئة، مثل mcp__meshy__*). تُبلّغ الواجهة الخلفية بأسماء الأدوات الدقيقة لكل حزمة (plugins.manage list → tools، من الواجهة الخلفية والـ profile الخاصين بالمحادثة نفسها)، لذا تُرفَض مع تحذير في وحدة التحكم أي مطالبة بأداة أساسية (text_to_speech)، أو بأداة إضافة أخرى، أو من إضافة سطح مكتب مستقلة بلا نصف وكيل.
      • كل ما عدا ذلك يبقى على المشغّل المدمج: ردود الصوت الأساسية، والملفات من أدوات أخرى، وما يرفعه المستخدم، وأي مسار لم تنتجه أداة. المنتِج هو أقدم استدعاء ناجح تسمّي نتيجته المسار بأكمله، لذا لا يُحتسب أمر ls لاحق، أو قراءة، أو أداة إضافة تأخذ الملف مدخلًا، كما أن إعادة كتابة ملف في مكانه لا تنقله إلى أداة أخرى. والمسار الذي سمّاه المستخدم أولًا (رفع ملف، أو مسار إخراج كُتب في الـ prompt) لا منتِج له. والاستدعاء الفاشل (حيًّا، أو نتيجة مخزَّنة تحمل error / success: false) لا ينتج أي شيء أبدًا.
      • الفشل الآمن (fail-safe): العارض الذي يرمي استثناءً أو يُرجع null، والإضافة المعطّلة، والواجهة الخلفية الأقدم من أن تُبلّغ عن الملكية، والأداة التي لم يُحمَّل نصفها الوكيل كلها تعود إلى المشغّل المدمج. خادم MCP الذي لم يتصل بعد لا يملك شيئًا؛ ويعيد Desktop قراءة الملكية بتراجع محدود (backoff) ما دامت أداة مُطالَب بها بلا مالك، وبعد reload.mcp أو تغيّر قائمة الإضافات، فتظهر البطاقة حالما يعمل الخادم.
      • هذا التطبيق وحده يقرن نصف سطح المكتب بحزمة. يكتب المُثبّت وخطوة المواءمة (reconcile) العلامة .hermes-package.json؛ وأي علامة موجودة داخل مستودع خاص بسطح المكتب فقط تُسقَط عند التثبيت.
      • الأسطح الأخرى لا تتغير. تواصل الأدوات إصدار أسطر MEDIA: العادية؛ وتسلّم CLI وTUI ومنصات المراسلة الملف كما كانت.

      قبل وجود هذه المنطقة، كان على الإضافة أن تجعل النموذج يُصدر ::directive خاصًا به للحصول على بطاقة مخصصة، وهذا يتطلب تعليمة في skill ويترك مستخدمي غير Desktop مع سطر directive خام. أما مع العارض، فتُرجع الأداة وسم MEDIA: العادي الذي تفهمه كل الأسطح، ويرتقي به Desktop وحده.

      عناصر واجهة مخصّصة بالتحميل (Contribute)​

      ctx.register مخصّص للمساهمات الدائمة. عندما ينبغي لعنصر واجهة أن يظهر ويختفي مع مكوّن موجود بالفعل على الشاشة (عنصر تحكم في شريط عنوان خاص بصفحة يختفي عند إلغاء تحميل الصفحة)، اعرض <Contribute> داخله بدلًا من ذلك:

      import { Contribute, WORKSPACE_PAGE_HEADER_AREA } from '@hermes/plugin-sdk'

      jsx(Contribute, {
        area: WORKSPACE_PAGE_HEADER_AREA,
        id: 'my-page:switcher', // namespace with your slug
        children: jsx(MySwitcher, {})
      })

      يسجَّل تلقائيًا عند التحميل ويُلغى تلقائيًا عند إلغاء التحميل.

      لعنصر تحكم في ترويسة صفحة، استخدم WorkspacePageHeaderControl بدلًا من ذلك. يختار الموضع من مكان عرض الصفحة: في جزء مساحة العمل يساهم في WORKSPACE_PAGE_HEADER_AREA، وفي أي موضع آخر (مربع مسار منقسم) يعرض أبناءه في المكان نفسه. ضعه حيث ينبغي أن يقع عنصر التحكم عند تضمينه:

      import { WorkspacePageHeaderControl } from '@hermes/plugin-sdk'

      jsx(WorkspacePageHeaderControl, {
        id: 'my-page:switcher', // namespace with your slug
        children: jsx(MySwitcher, {})
      })

      WorkspacePageHeaderControl جديد في هذا الإصدار. لا تصدّره إصدارات Desktop الأقدم، واستيراد مسمّى لعنصر SDK مفقود يوقف تحميل وحدة الإضافة. الإضافة التي يجب أن تعمل أيضًا على إصدارات أقدم إما تكتشف الميزة عبر استيراد namespace (import * as sdk from '@hermes/plugin-sdk'، ثم sdk.WorkspacePageHeaderControl ?? …)، أو تُبقي صيغة Contribute الخام أعلاه.

      ظهور صفوف الملاحة الجانبية وترتيبها (SIDEBAR_NAV_PREFS_AREA)​

      تخفي الإضافة صفوف الملاحة العليا في الشريط الجانبي أو تعيد ترتيبها عبر تقديم تفضيل، لا كتابة إعداد. يدمج المكوّن الأساسي كل مساهمة sidebarNav.prefs عند العرض، ويطبّق النتيجة على الصفوف التي كان سيعرضها؛ ولا تتغيّر القائمة الافتراضية نفسها أبدًا.

      import { SIDEBAR_NAV_PREFS_AREA, type SidebarNavPrefsContribution } from '@hermes/plugin-sdk'

      // Payload (`data`) of a sidebarNav.prefs contribution
      interface SidebarNavPrefsContribution {
        hide?: string[]   // rows to drop
        order?: string[]  // rows to place first, in this order
      }

      ctx.register({
        id: 'prefs',
        area: SIDEBAR_NAV_PREFS_AREA,
        data: { hide: ['cron'], order: ['capabilities', 'new-session'] } satisfies SidebarNavPrefsContribution
      })

      معرّفات الملاحة هي معرّفات الصفوف نفسها. الصفوف الأساسية: new-session، capabilities، messaging، artifacts، cron (النوع SidebarNavId؛ ولا يُعرض artifacts و cron إلا في وضع Advanced). معرّف صف مساهمة هو معرّف تسجيله في SIDEBAR_NAV_AREA، الذي ctx.register في namespace ${pluginId}:${id} — فإضافة سجّلت { id: 'kanban-nav', area: SIDEBAR_NAV_AREA } باسم kanban تسمّي ذلك الصف 'kanban:kanban-nav' في hide/order.

      حسم التعارض. الصفوف المخفية هي اتحاد قيم hide لكل مساهمة (لا تستطيع إضافة إظهار صف أخفته أخرى؛ ويتقدم الإخفاء على الترتيب)، باستثناء capabilities: فالصف الذي يستضيف تبويب Plugins هو طريق المستخدم إلى مفتاح تعطيل الإضافة نفسها، لذا يمكن نقله لكن لا يمكن إخفاؤه أبدًا. تُطبَّق المساهمات بترتيب المنطقة في السجل — أقل order، ثم التسجيل — وتفوز order الخاصة بالأولى: لا تضع المساهمات اللاحقة إلا معرّفات لم تُوضَع بعد، وتحتفظ الصفوف التي لا يسمّيها أي ترتيب بترتيبها النسبي الافتراضي بعد الصفوف المسمّاة. المعرّفات المجهولة بلا أثر.

      الإنهاء. تعيش المساهمة في السجل، لذا يلغيها تعطيل الإضافة أو إعادة تحميلها وتعود الصفوف مباشرةً — لا شيء لمسحه. لهذا ليست فعلًا من أفعال host.sidebar.hide(): host singleton لا يستطيع نسبة كتابة إلى صاحبها، وسيعيش التفضيل المحفوظ أطول من الإضافة، وستكتب إضافتان فوق ترتيب بعضهما.

      حفظ اختيار المستخدم مسؤولية الإضافة في ctx.storage الخاص بها: اقرأ التفضيلات المحفوظة عند register، وقدّمها، وعند كل تعديل احفظ + ألغِ + قدّم مجددًا (إعادة تسجيل id نفسه تستبدله).

      // sidebar-manager: replaces `[data-sbm-off] { display:none }` + re-parenting <li>s
      let dispose = () => {}
      const apply = (prefs: SidebarNavPrefsContribution) => {
        dispose()
        dispose = ctx.register({ id: 'prefs', area: SIDEBAR_NAV_PREFS_AREA, data: prefs })
      }
      apply(ctx.storage.get('navPrefs', {}))
      // in the editor's onChange:
      ctx.storage.set('navPrefs', next); apply(next)

      لا يشمل ذلك أقسام الجلسات (Pinned، و Recents، و Cron jobs) — صفوف الملاحة فقط.

      يتصل الاستدعاء الذي عليه فتح اتصال بـ profile آخر بأولوية خلفية افتراضيًا. وبعد فشل الاتصال بذلك الـ profile، تفشل الاستدعاءات الخلفية سريعًا بينما يعمل تراجع إعادة الاتصال (Backend for "<profile>" is reconnecting; retry after it settles.) بدل إعادة الاتصال عند كل نبضة. وعندما يكون الاستدعاء إجراء مستخدم فعليًا (حفظًا، أو ضغط زر، أو فتح حوار)، مرّر host.requestProfile(route, method, params, undefined, { spawnPriority: 'foreground' }) ليتصل فورًا. أبقِ القيمة الخلفية الافتراضية للاستطلاع (polling) وتدفئة القائمة (roster).

      host.openWorkspace(id, { render, title?, minWidth?, onClose? }) يُرسي عرضًا يعرضه الإضافة في منطقة مساحة العمل الرئيسية — نفس المنطقة الوسطى التي تستخدمها بلاطات الجلسات والمعاينات — كتبويب، ويُظهره. إعادة استدعائه بنفس id يحدّث المحتوى في مكانه ويعيد إحضار التبويب للأمام بدلًا من فتح نسخة مكرَّرة. إغلاق التبويب (عنصر تحكم الإغلاق الخاص بالتبويب أو ⌘W) يفكّك التسجيل ويطلق onClose الخاص بك؛ ويغلقه المُتخلِّص (disposer) المُعاد برمجيًا. اكتشف توفره (typeof host.openWorkspace === 'function') وارجع إلى جزء (pane) مساهم عادي على إصدارات سطح المكتب الأقدم — غرف المحادثة الجماعية في Bot Mode هي المستهلك المرجعي (استحواذ على النافذة الرئيسية عند التوفر، وعرض داخل اللوحة خلاف ذلك).

      host.paneVisibility(paneId) تُعيد ذرّة تفاعلية للقراءة فقط تكون true طالما أن الجزء المُساهَم به موجود فعليًا على الشاشة: حاضر في شجرة التخطيط، غير مُغلَق أو مخفي، ومنطقته غير مصغَّرة، ويحمل فتحة التبويب النشط لمنطقته (الجزء الوحيد في منطقته الخاصة يُحتسَب). المعرّف هو معرّف الجزء المخصّص للمساهمة، <pluginId>:<paneId>. الذرّات محفوظة (memoized) لكل معرّف، لذا فإن استدعاءه أثناء render آمن. استخدمه لتسجيل واجهة مصاحبة فقط عندما يكون جزؤك مرئيًا — لوحة Cronjobs الخاصة بـ Bot Mode هي المستهلك المرجعي: تُسجَّل طالما تحمل لوحة Bots تبويب الشريط الجانبي وتُلغى تسجيلها عندما ينتقل المستخدم إلى Sessions. اكتشف توفره على إصدارات سطح المكتب الأقدم (typeof host.paneVisibility === 'function') وارجع إلى السلوك المسجَّل دائمًا.

      host.profileRoutes() يجرد كل مصدر مسجَّل في سجلّ الاتصال الحالي. مصادر SSH التي تتصل عند الطلب تعرض مسارًا (route) أوّليًا default خاليًا من بيانات الاعتماد دون فتح نفق (tunnel)، بحيث يمكن للإضافة أن تكون أول من يستدعيها؛ يظل remoteProfile الخاص بـ SSH هو targetProfile الخلفي للمسار. أما connectionId فهو هوية توجيه السجلّ؛ اقرنه مع profile للمفاتيح والاستمرارية. لا تعبر endpoint أو token أو مضيف/مفتاح SSH أو حقول الاتصال الخام الأخرى حدود IPC الخاصة بالإضافات. profile هو المسار المحلي للمصدر المستخدم للطلبات؛ وtargetProfile هو profile Hermes الخلفي الذي يخدمه ذلك المسار. يختلفان عندما يُخطَّط المسار صراحة إلى profile خلفي آخر (مثلًا تجاوز remoteProfile في SSH أو اسم مستعار خاص بعنوان URL لكل profile قديم). هذا التمييز يحافظ على هوية الخلفية دون كشف أسرار الاتصال.

      الإضافات المصمَّمة حول profile تحصل أيضًا على طرق (methods) من الدرجة الأولى: profiles.list (كل profile مع أحدث محادثة له كـ last_session؛ مرّر include_sessions: false لتخطي فحص قاعدة البيانات لكل profile؛ ومرّر preferred_session_ids: { profileName: sessionId } لبحث دقيق ومتحقَّق من وجوده عن جلسة واحدة مثبَّتة لكل profile — يحصل كل صف مسمّى على ملخّص preferred_session يحلّ الصفوف المخفية وسلاسل الضغط (compression lineages) إلى طرفها الحي، أو null عندما يكون المعرّف مفقودًا نهائيًا؛ وتتجاهل الـ gateways الأقدم هذا المعامِل وتحذف الحقل) وprofiles.create (name، description، clone_from، clone_all، no_skills، soul، وتثبيت اختياري لـmodel + provider) — وهما التوأمان عبر ws لمسارات /api/profiles REST الخاصة بلوحة التحكم. host.state.busy هو دور المحادثة التي عليها التركيز حاليًا (التفكير والبث). تبقى host.state.awaitingResponse صحيحة من الإرسال وحتى وصول أول حمولة من المساعد. كلاهما يتبعان المحادثة التي ينظر إليها المستخدم فعليًا — بلاطة الجلسة التي عليها التركيز عندما تحمل التركيز، وإلا فمحادثة مساحة العمل الرئيسية (نفس الإشارة التي تقرأها نبضة الانشغال في شريط الحالة). اشترك في مكوّن:

      const busy = useValue(host.state.busy)

      لتفاصيل أدق على مستوى الـ token، استمع عبر host.onEvent (message.start، message.delta، message.complete).

      host.onEvent يبثّ أحداث gateway الحية (فروقات (deltas) الرسائل، دورة حياة الجلسة، نشاط الأدوات). المستمعون (listeners) معزولون — أي رمي استثناء في مستمعك لا يمكن أن يؤثر على إرسال (dispatch) التطبيق. كل باب في host آمن غير متزامن (async-safe): أي رمي استثناء متزامن من مساعد داخلي (مثلًا عدم وجود جسر سطح مكتب في متصفح عادي) يتحوّل إلى رفض (rejection) يلتقطه .catch() الخاص بك، وليس إلى انهيار في حدود الخطأ.

      تقدّم الأداة المباشر — tool.progress​

      أثناء تشغيل استدعاء أداة، يصل خادم MCP الذي يرسل notifications/progress (قناة التقدم في مواصفة MCP؛ ويشترك Hermes فيها بإرسال _meta.progressToken مع كل tools/call) إلى الـ renderer بوصفه حدث tool.progress. ويعرضه صف الأداة الأصلي بالشكل 42% · <message> بجوار مؤقّته؛ ويمكن للإضافة أن تعرض واجهتها الخاصة:

      ctx.onEvent('tool.progress', ({ session_id, payload }) => {
        // payload: { tool_id, name, progress, total, percent, message }
        if (payload.name.startsWith('mcp__meshy__')) showRefineProgress(payload.tool_id, payload.percent, payload.message)

      ctx.onEvent('tool.complete', ({ payload }) => clearRefineProgress(payload.tool_id))

      progressnumberقيمة التقدم الخام من الخادم
      totalnumber | nullالإجمالي لدى الخادم، إن أرسله
      percentnumber | nullمن 0 إلى 100 (مقرَّبة ومحصورة ضمن النطاق) عند ضبط total، وإلا null
      messagestring | nullرسالة التقدم من الخادم

      تُخنَق الأحداث (throttle) بحيث يصل حدث واحد على الأكثر كل 500 ms لكل استدعاء؛ ويصل دائمًا أول تحديث والتحديث الذي يبلغ total. ولا تُخزَّن في السجل (transcript) أبدًا، فلا تعرض الجلسة المُعاد فتحها سوى الصف المنتهي.

      ctx.os هو المدخل المنظّم لنظام التشغيل — كل طريقة تصل بها الإضافة إلى خارج نافذة التطبيق، في مساحة أسماء واحدة منسوبة إلى إضافتك. ctx.os.notify يُصدر إشعار نظام تشغيل أصلي (native) — نفس أنبوب Electron الذي تستخدمه تنبيهات الموافقة/الدور الخاصة بالتطبيق نفسه. لا يطلق إلا عندما يكون المستخدم بعيدًا عن Hermes (في الخلفية / غير مركَّز عليه)؛ استخدم host.notify للحصول على toast داخل التطبيق عندما يكون المستخدم ينظر إلى التطبيق. يمكن للمستخدمين كتم الإشعار لكل جهاز من Settings ▸ Notifications ▸ "Plugin notifications"، وتُقيَّد التكرارات من نفس الإضافة، لذا تعامل معه كإشارة لأحداث ملحوظة حقًا — لا كسجل (log).

      عرض غني + تفعيل (يوسّع باب ctx.os الأصلي):

      ctx.os.notify({
        title: 'New match found',
        body: 'Someone matched your signal',
        icon: '/abs/path/to/icon.png', // Electron Notification icon
        // Body click → focus Hermes + navigate. Same vocabulary as OS deep links:
        activate: 'hermes://index-network/intent/1',
        // or: activate: '/index-network/intent/1'

        onActivate: () => focusLocalState('1'), // optional renderer callback
        actions: [
          { id: 'open', label: 'Open', activate: 'hermes://index-network/intent/1' },
          { id: 'dismiss', label: 'Dismiss', onAction: () => dismiss('1') },

      الأبواب الأخرى (openExternal، revealPath، writeClipboard) تُرجع false بدلًا من رمي استثناء عندما لا تكون القدرة متاحة (غلاف سطح مكتب أقدم، متصفح عادي) — افرِّع بناءً على النتيجة بدلًا من استشعار الجسر.

      الملفات — ctx.files​

      ctx.files هي الطريقة الوحيدة المعتمدة لتتعامل الإضافة مع الملفات على الجهاز الذي يشغّل Desktop. تصل الإضافة إلى نوعين فقط من المجلدات:

      • مجلد بياناتها الخاص، المقبض 'data': خاص بالإضافة، ومتاح دائمًا، دون طلب إذن. استخدمه للـ caches والفهارس وعمليات التصدير الأكبر من أن تناسب ctx.storage.
      • المجلدات التي منحها المستخدم لها: تفتح ctx.files.requestFolder() منتقي المجلدات الخاص بالتطبيق (بعنوان هو اسم إضافتك؛ ولا يمكنك تغيير نصه). يُحفَظ المنح لإضافتك عبر عمليات إعادة التشغيل، ويُدرَج تحت إضافتك في Capabilities → Plugins → Folder access، ويستطيع المستخدم إلغاءه من هناك في أي وقت. وإلغاء تثبيت الإضافة يُسقط ما مُنح لها.

      يسمّي كل استدعاء مقبض مجلد ومسارًا نسبيًا إلى ذلك المجلد. تتحقق العملية الرئيسية للتطبيق من كل استدعاء: يُرفَض .. والمسارات المطلقة وأحرف الأقراص والروابط الرمزية (symlinks) التي تحلّ خارج المجلد، ولا يجري تطبيعها أبدًا، ولا يمكن الوصول إلى أي شيء داخل بيانات Hermes نفسها (Hermes home الذي يضم config.yaml و.env والمصادقة وprofiles؛ ومجلد بيانات التطبيق الذي يضم بيانات كل إضافة وسجل المنح). والمجلد الذي يحوي بيانات Hermes أو يقع داخلها (مهما كانت كتابته: bind mount أو macOS firmlink أو مشاركة WSL أو مشاركة \\localhost\C$ تُحتسب)، أو مجلد مفاتيح مثل ~/.ssh، أو نظام ملفات نواة مثل /proc (أينما رُكِّب) لا يمكن منحه إطلاقًا؛ ويشرح التطبيق للمستخدم السبب. لا تُقرأ أو تُكتب إلا الملفات العادية: يُرفَض الـ pipe أو الجهاز أو الملف ذو الروابط الصلبة (hard-linked)، ويُرفَض الملف الذي استُبدل برابط بين فحص التطبيق وفتحه بدلًا من اتباعه.

      // First run: ask once, remember the handle.
      let vault = (await ctx.files.folders())[0]
      if (!vault) {
        const picked = await ctx.files.requestFolder()
        if (!picked.ok || !picked.folder) return   // cancelled, refused, or an older app
        vault = picked.folder
      }

      const listing = await ctx.files.list(vault.id, 'notes')        // { ok, entries: [{ name, path, isDirectory }], truncated }
      const note = await ctx.files.readText(vault.id, 'notes/a.md')  // { ok, text, size, mtimeMs }
      await ctx.files.writeText(vault.id, 'notes/b.md', '# B\n', { exclusive: true }) // refuses to replace a file
      await ctx.files.rename(vault.id, 'notes/b.md', 'c.md')         // same folder only
      await ctx.files.trash(vault.id, 'notes/c.md')                  // OS trash, recoverable
      await ctx.files.readDataUrl(vault.id, 'img/cover.png')         // { ok, url: 'data:image/png;base64,…' }
      await ctx.files.stat(vault.id, 'notes/a.md')                   // { ok, exists, isDirectory?, size?, mtimeMs? }
      await ctx.files.writeText('data', 'index.json', JSON.stringify(index))
      await ctx.files.release(vault.id)                              // give the folder back

      لا يرمي أي عضو استثناءً. dataFolder هي السلسلة 'data'؛ وfolders() تُرجع مصفوفة من { id, name, path } (فارغة حين لا يملك التطبيق هذا الباب)؛ وrelease(id) تُرجع true حين أعادت مجلدًا وfalse خلاف ذلك. وكل عضو آخر يُرجع { ok: true, … } أو { ok: false, error, message }، حيث error واحدة من invalid-path وoutside-folder وprotected و not-granted (أُلغي المنح، أو هو مجلد إضافة أخرى) وfolder-missing و folder-changed (نُقل المجلد الممنوح أو استُبدل: اطلب من جديد) و not-found وexists وis-directory وnot-a-directory وnot-a-file و binary وtoo-large وsensitive-file (يُرفَض .env ومفاتيح SSH وما شابهها حتى داخل مجلد ممنوح، تحت أي كتابة يعدّها نظام التشغيل الاسم نفسه، ولا يمكن إعادة تسميتها أو نقلها إلى سلة المهملات)، وio-error أو unavailable (إصدار من التطبيق بلا هذا الباب: اكتشف الميزة عبر ctx.files?.…). الحدود: قراءة وكتابة النصوص حتى 4 MiB، وdata URLs حتى 16 MiB، والقوائم حتى 10,000 مدخل. تُرفَض القراءات التي تتجاوز الحد، ولا تُقتطع أبدًا. وتتطلب الكتابة وجود مجلدها الأب.

      المسارات على الجهاز الذي يشغّل Desktop، لا على واجهة خلفية بعيدة. وللتعامل مع ملفات الواجهة الخلفية، استخدم مسارات ctx.rest الخاصة بإضافتك.

      فقاعة الحيوان الأليف — ctx.pet​

      للحيوان الأليف الأساسي (شخصية petdex، داخل النافذة أو منفصلة في نافذة خاصة لنظام التشغيل) فقاعة كلام. يتيح ctx.pet للإضافة وضع سطر قصير فيها، فلا تحتاج إلى العثور على الحيوان في DOM التطبيق أو عرض طبقة عائمة خاصة فوقه:

      register(ctx) {
        // Shows "DeepSeek ¥12.40 left" over the pet for 8 s, labelled "Pet Wallet".
        const dispose = ctx.pet.say('DeepSeek ¥12.40 left', { id: 'balance', ttlMs: 8000 })

        // Same id → replaces the line in place (a refreshed balance, a countdown).
        ctx.pet.say('DeepSeek ¥11.90 left', { id: 'balance' })

        // Tones: 'info' (default), 'wait' (clock glyph), 'error' (alert glyph).
        ctx.pet.say('Codex 5h quota at 90%', { id: 'quota', tone: 'wait' })

        dispose()              // remove early, or
        ctx.pet.clear('quota') // by id, or ctx.pet.clear() for all of yours

        // No pet on screen? Fall back to your own status-bar chip or pane.
        const visible = ctx.pet.visible.get()
      }
      interface PluginPet {
        say(text: string, options?: { id?: string; tone?: 'info' | 'wait' | 'error'; ttlMs?: number }): () => void
        clear(id?: string): void
        visible: ReadableAtom<boolean>
      }

      ما يضمنه المضيف كي لا تحتاج إلى ضمانه:

      • نص عادي. تُزال محارف التحكم وتجاوزات اتجاه الكتابة، وتُختزل المسافات إلى سطر واحد، ويُحدّ النص بـ 120 حرفًا. يُعرض كعقدة نصية؛ ويظهر الترميز حرفيًا.
      • منسوب إلى مصدره. يُطبع اسم إضافتك (من قائمة Plugins) فوق السطر، ليتميّز كلامك عن كلام الحيوان.
      • قصير العمر. تنتهي صلاحية كل سطر بعد ttlMs (6 s افتراضيًا، مقيّدة بـ 1–30 s). أعد استدعاء say مع id نفسه لإبقاء قيمة معروضة. يبقى 3 أسطر على الأكثر لكل إضافة (يُخلى الأقدم)، وتعرض الفقاعة أحدث سطر من أي إضافة.
      • محدود المعدل. 10 استدعاءات say لكل إضافة كل 10 s؛ تُسقط الاستدعاءات الزائدة مع تحذير في console وتُرجع disposer بلا أثر.
      • الأولوية للنواة. عندما يصادف الوكيل خطأً أو ينتظر المستخدم، تكون الغلبة لفقاعة الحالة الأساسية؛ ويظهر سطرك مجددًا بعد زوالها (إذا لم تنتهِ صلاحيته).
      • الغلبة لإعداد الحيوان لدى المستخدم. إذا لم يُتبنَّ حيوان أو كان معطّلًا، فلا يظهر شيء. يتيح ctx.pet.visible لك التفريع وفق ذلك.
      • يُنظَّف مع إضافتك. يؤدي تعطيل إضافتك أو إلغاء تحميلها أو إعادة تحميلها فوريًا إلى إزالة كل سطر ما زالت تعرضه.

      داخل النافذة، لا تظهر الفقاعة إلا لأسطر الإضافات (يعرض التطبيق نفسه حالة الوكيل). في الطبقة العائمة المنفصلة، تشترك أسطر الإضافات في الفقاعة مع أسطر الحالة الأساسية. الطبقة نافذة منفصلة لا تحمّل كود إضافات؛ وترسل إليها النافذة الرئيسية الأسطر النشطة مع بقية حالة الحيوان.

      إدخال المؤشر على الحيوان (السحب أو shift-click لفصله أو النقر على طبقته) خاص بالمضيف ولا يملك hook للإضافات. استخدم أمرًا في لوحة الأوامر أو عنصر شريط حالة أو جزءك الخاص للإجراءات.

      تشغيل إجراءات التطبيق — ctx.runAction​

      يمكن تشغيل أوامر التطبيق نفسه — المرتبطة باختصارات لوحة المفاتيح ولوحة الأوامر — بحسب المعرّف. تحصل الإضافة على المعالج نفسه الذي يشغّله الاختصار تمامًا، فلا يغيّر لك شيء إعادة تعيين المستخدم لذلك الاختصار (أو إلغاء تعيينه) في Settings ▸ Keyboard Shortcuts:

      import { TITLEBAR_AREAS } from '@hermes/plugin-sdk'
      import { jsx } from 'react/jsx-runtime'

      register(ctx) {
        ctx.register({
          id: 'browser',
          area: TITLEBAR_AREAS.right,
          render: () => jsx('button', { onClick: () => ctx.runAction('view.showBrowser'), children: 'Browser' })
        })

        // Results are values, never exceptions.
        const result = ctx.runAction('nav.settings')
        if (!result.ok) console.log(result.reason, result.error)

        // Discover what is allowed (labels are localized, same as the shortcuts panel).
        for (const { id, label } of ctx.listActions()) console.log(id, label)
      }
      interface PluginContext {
        runAction(id: PluginAppActionId): PluginRunActionResult
        listActions(): Array<{ id: PluginAppActionId; label: string; category: string }>
      }

      type PluginRunActionResult =
        | { ok: true }
        | { ok: false; reason: 'unknown' | 'denied' | 'unavailable'; error: string }

      لا يُسمح إلا بإجراءات العرض والتنقل. PluginAppActionId هو الاتحاد المحدد الأنواع؛ و PLUGIN_APP_ACTIONS القائمة نفسها وقت التشغيل:

      المعرّفما يفعله

      view.showFilesإظهار متصفح الملفات
      view.toggleSidebarتبديل الشريط الجانبي الأيسر
      view.toggleRightSidebarتبديل الجانب الأيمن
      view.toggleReviewتبديل جزء المراجعة (git)
      view.toggleStatusbarتبديل شريط الحالة
      view.findInPageفتح البحث في الصفحة

      session.focusSearchالتركيز على البحث في الجلسات
      conversation.scrollPageUp / conversation.scrollPageDownتمرير نص المحادثة صفحةً

      يُرفض أي شيء آخر: { ok: false, reason: 'denied' } لإجراء تطبيق فعلي غير مدرج (الأرشفة أو التثبيت أو تبديل profile / النموذج / الاستدلال أو الطرفيات أو نافذة جديدة أو فتح مجلد أو HUD أو إغلاق تبويب وغيرها)، و reason: 'unknown' لمعرّف غير موجود. في الحالتين لا يُنفّذ شيء ويُسجَّل تحذير [plugin:<id>] runAction: …. يعني reason: 'unavailable' أن shell التطبيق المسؤول عن المعالجات لم يُركّب بعد (مرحلة بدء مبكرة جدًا)؛ أعد المحاولة من إجراء مستخدم. لا تُعدّ العمليات الإتلافية وذات الامتيازات (حذف الجلسات أو تسجيل الخروج أو الموافقات أو تغيير النموذج/المزوّد أو التحديثات أو الإنهاء) إجراءات تطبيق تستطيع إضافة تنفيذها.

      تحقّق من توفر الميزة على المضيفين الأقدم: ctx.runAction?.('view.showBrowser').

      سكربتات صفحة المعاينة — ctx.preview​

      تشغّل ctx.preview.executeJavaScript(code) الشيفرة code في تبويب Browser المعاينة للجلسة المركّز عليها (نفس مشغّل الضيف الذي تستخدمه drive_preview وجولة المعاينة) وتُرجع قيمة اكتمال السكربت. وقد تكون تلك الصفحة صفحة سجّل المستخدم الدخول إليها، لذا يستطيع السكربت هناك قراءة جلسته. الباب مغلق افتراضيًا والتطبيق هو من يحكّم كل استدعاء:

      1. أعلِن عنها. يسرد التصدير الافتراضي للإضافة القدرة:

        export default {
          id: 'page-tools',
          name: 'Page Tools',
          capabilities: ['preview.executeJavaScript'],
          register(ctx) {
            ctx.register({ area: PALETTE_AREA, id: 'title', data: {
              id: 'pageTools.title', label: 'Copy page title',
              run: async () => ctx.os.writeClipboard(String(await ctx.preview.executeJavaScript('document.title')))
            } })
          }
        }

        الإضافة التي لم تعلن عنها تُرفَض في كل استدعاء؛ لا يُسأل المستخدم عن شيء ولا يُشغَّل شيء.

      2. يسمح بها المستخدم لكل أصل (origin). أول استدعاء على أصل صفحة يُظهر مربع حوار يملكه التطبيق يسمّي الإضافة والأصل (https://mail.example.com). يحفظ الخيار Allow on this site منحًا لتلك الإضافة والأصل؛ ويرفض Don't allow (أو Esc) طوال تشغيل التطبيق الحالي، ثم يسأل مجددًا عند التشغيل التالي. تُدرَج المنوح في صف الإضافة ضمن Capabilities → Plugins، ولكل منها إلغاؤه الخاص؛ والأصل الملغى يُسأل عنه من جديد.

      3. أصول الويب فقط. http(s)://host[:port]؛ وتُرفَض صفحات about:blank وdata: و file: لأنه لا يمكن حصر المنح في موقع واحد.

      4. يُعاد فحص الأصل داخل الصفحة. يعمل السكربت خلف حارس window.location.origin داخل الصفحة، فإذا حدث تنقل بين فحص الموافقة والتشغيل فإنه يُرفَض بدلًا من أن ينفَّذ على موقع آخر.

      ctx.preview.isAvailable()             // declared AND a live Browser page in this window (not consent)
      await ctx.preview.executeJavaScript(code)
      // rejects: undeclared · 'No preview page is open.' · non-web origin ·
      //          '<Plugin> is not allowed to run scripts on <origin>.' · page changed origin

      لا تصل إلى الصفحة إلا عبر هذا الباب. فاستعلام <webview> أو إنشاؤه (document.querySelector('webview')) يتجاوز الإعلان والموافقة، ويُفشل فحص lint الخاص بالكتالوج لـ desktop surface (preview guest reach). ولا تُربط نافذة Browser المنفصلة (popped-out) بالجسر.

      إعدادات مظهر Desktop — host.settings​

      host.settings هو المدخل المدعوم للمجموعة الصغيرة من تفضيلات المظهر المحلية لـ Desktop التي يمكن للإضافات مشاركتها مع صفحة Settings الأصلية. يرتبط كل مفتاح بذرّة المخزن ودالة ضبطها اللتين تستخدمهما صفحة Settings نفسها، فتكون كتابة الإضافة كنقرة المستخدم على ذلك العنصر تمامًا: تسري فورًا، وتُحفظ عبر مخطط تخزين التفضيل الحالي، وتكون الغلبة لآخر كتابة (لا "تملك" إضافة القيمة بعد ذلك، ولا شيء لتفكيكه من أجل set).

      type DesktopSettingValues = {
        'backdrop.v1': boolean
        chatTextScale: 90 | 100 | 110 | 125 | 150 | 175 // percent; Appearance → Chat Text Size
        'composerPopout.gesturesEnabled': boolean
        'intro-splash.v1': boolean
        'reasoning.collapsedByDefault': boolean
        sessionListDensity: 'compact' | 'comfortable' | 'detailed'
        tabStripDefault: 'auto' | 'always' | 'never'
      }
      host.settings.get<K extends DesktopSettingKey>(key: K): DesktopSettingValues[K]
      host.settings.set<K extends DesktopSettingKey>(key: K, value: DesktopSettingValues[K]): void
      host.settings.subscribe<K extends DesktopSettingKey>(key: K, fn: (value: DesktopSettingValues[K]) => void): () => void
      register(ctx) {
        host.settings.set('sessionListDensity', 'detailed')

        // subscribe emits the current value now, then after every native or plugin write.
        const dispose = host.settings.subscribe('backdrop.v1', enabled => { /* … */ })
        // Teardown rule: `host` is a module singleton and cannot tell which plugin
        // subscribed, so YOU retire the listener — otherwise it outlives a disable/reload.
        ctx.onDispose(dispose)

      حزم اللغات — host.i18n.registerAppLocale / ctx.i18n.registerAppLocale​

      ctx.i18n.register يوطّن نصوص إضافتك أنت. تفعل حزمة اللغة العكس: تضيف لغة (أو توسعها) للتطبيق بأكمله — كل تسمية وحوار ونصيحة أساسية — ليرى المستخدم البولندي Desktop بالبولندية. التسجيل كتالوج جزئي يُدمج فوق الكتالوج المضمّن لذلك المعرّف (أو الإنجليزية للغة جديدة)؛ يرجع كل ما تحذفه الحزمة إلى بديل لكل مفتاح، لا إلى مفتاح خام مطلقًا. يسرد المبدّل اللغة باسمها الذاتي فورًا (دون أعلام — اللغات ليست دولًا)، وتتبع <html dir> القيمة rtl، وتظل display.language كما اختارها المستخدم: التسجيل ليس اختيارًا.

      export default {
        id: 'hermes-lang-pl',
        register(ctx) {
          // Attributed to this plugin and dropped on unload/disable.
          ctx.i18n.registerAppLocale('pl', {
            endonym: 'Polski',
            englishName: 'Polish',        // search-only
            rtl: false,
            translations: {
              // Nested like en.ts…
              common: { save: 'Zapisz', cancel: 'Anuluj' },
              // …or flat dotted keys (what a .desktop.yaml pack flattens to).
              'catalog.results': '{0} wyników'
            }
          })
        }
      }
      host.i18n.registerAppLocale(id, { endonym?, englishName?, rtl?, translations? }): () => void
      host.i18n.languageOptions(): LanguageOption[]   // bundled ∪ registered ∪ backend i18n.languages

      عندما تتضمن الإنجليزية مدخل دالة (results: n => `${n} results` )، تقدّم الحزمة سلسلة عادية بعناصر نائبة موضعية — {0} و {1} بترتيب الوسائط — ويغلّفها الدمج بصيغة الاستدعاء نفسها. تُنشر مجموعة المفاتيح الكاملة في locales/_keys.desktop.json (أعد توليدها باستخدام npm run i18n:keys في apps/desktop واحفظها في commit؛ تثبّت CI الملف على en.ts)، وهي ما تفحص hermes plugins validate ملف <lang>.desktop.yaml في الحزمة مقابله.

      طبقة البيانات — React Query + nanostores​

      تشارك الإضافات QueryClient الوحيد الخاص بالتطبيق، لذا تخزَّن استعلامات الإضافة مؤقتًا وتُنقّى من التكرار وتُستطلع وتُبطَل تمامًا مثل الشاشات الأساسية — لا تبنِ أبدًا حلقة جلب (fetch) يدوية.

      import { useQuery, useMutation, useQueryClient, atom, computed, useValue } from '@hermes/plugin-sdk'

      function MyPanel() {
        const { data, isLoading } = useQuery({
          queryKey: ['my-plugin', 'items'],
          queryFn: () => host.request('my.list', {})
        })
        // …
      }

      بالنسبة للحالة المشتركة بين مُشغِّل (trigger) ولوحته (panel) — أو حلقة استطلاع — استخدم atom / computed — نفس البدائية (primitive) التي يستخدمها host.state. اشترك في الورقة (leaf) التي تعرض القيمة باستخدام useValue. لإبطال استعلام من خارج React (مثلًا وصول إطار عبر ctx.socket)، استورد queryClient المشترك:

      import { queryClient } from '@hermes/plugin-sdk'

      ctx.socket('/events', () => {
        queryClient.invalidateQueries({ queryKey: ['my-plugin', 'items'] })
      })

      طقم واجهة المستخدم (UI Kit) والسمات (Theming)​

      استورد مكوّنات التطبيق الحقيقية مباشرة حتى تكون واجهتك أصيلة (native) افتراضيًا:

      حزمة واحدة، وSDK لكلا الجانبين​

      الميزة التي تحتاج إلى واجهة desktop و كود من جهة الوكيل (إضافة Python ومسارات backend الخاصة بها ومهارات) لا تحتاج إلى توزيعهما كتثبيتين يعتمد أحدهما على الآخر. ضع desktop/plugin.js داخل حزمة الوكيل. عندما تحطّ الحزمة في أي جذر plugins/ محلي (المنزل الافتراضي أو profile)، تنسخ عملية Electron الرئيسية هذا النصف إلى $HERMES_HOME/desktop-plugins/<id>/ بجانب علامة .hermes-package.json، ويحمّله عارض الواجهة (renderer) عبر خط أنابيب مطابق تمامًا لباب القرص المستقل (hot reload متضمَّن):

      ~/.hermes/plugins/<id>/           # ONE installable folder
      ├── plugin.yaml                   # the agent half: tools, hooks, commands
      ├── skills/…
      ├── dashboard/
      │   ├── manifest.json             # { "name": "<id>", "api": "plugin_api.py" }
      │   └── plugin_api.py             # backend routes → /api/plugins/<id>/
      └── desktop/
          └── plugin.js                 # the desktop half: panes, commands, ctx.rest

      نصف desktop/plugin.js هو إضافة قرص عادية — نفس العقد، ونفس الاستيرادات، ونفس ctx.rest('/…') الذي يصل إلى plugin_api.py الموجود بجانبه. تثبيت أو مشاركة أو إزالة الميزة هو مجلد واحد: تُحدَّث نسخة جذر التطبيق عندما يتغير ملف plugin.js المصدر (hermes plugins update، أو Rescan) وتُزال عندما يختفي مجلد الحزمة. النسخ هو ما يجعل النصف الخاص بـ desktop على مستوى التطبيق: فهو موجود مرة واحدة، مهما كان عدد الـ profiles التي تحمل الحزمة، ولا يظهر أو يختفي أبدًا عندما يبدّل المستخدم محدد profile الخاص بالإمكانيات (Capabilities). لا يفحص عارض الواجهة plugins/ بنفسه أبدًا. تسجّل العلامة اسم الحزمة ومصدرها (ملحق كتالوج أو remote git)، وهذا ما يستخدمه زر Install here في صفحة Plugins لتثبيت نصف الوكيل في profile آخر. تُجهّز النسخة بجوار الهدف ثم تُنقل إلى موضعها بإعادة التسمية، فلا تترك عملية نسخ مقاطعة (قفل ملف عابر أو تعطّل وسط النسخ) مجلدًا نصف مكتوب؛ وتُعامل بقايا desktop-plugins/<id>/ التي لا تحمل علامة ولا plugin.js كتلف من هذا النوع وتُستبدل عند Rescan التالي، بينما يكون المجلد دون علامة الذي يحتوي بالفعل على plugin.js إضافة مستقلة ثبّتها يدويًا ولا يُكتب فوقها مطلقًا.

      تطوير حزمة موحّدة​

      يحمّل التطبيق النسخة في desktop-plugins/<id>/، لا حزمتك. لا تُحدَّث الحزمة المثبّتة (الكتالوج أو Git URL أو مسار file://) إلا عندما يكون plugin.js المصدري أحدث من النسخة ويطلب شيء التحديث — Rescan في Capabilities → Plugins أو تثبيت/تحديث عبر التطبيق أو إعادة تشغيل — لذلك لا يؤدي تحرير ~/.hermes/plugins/<id>/desktop/plugin.js في موضعه إلى شيء على الشاشة حتى ذلك الحين. طوّر بدلًا من ذلك من نسخة مسحوبة مرتبطة بـ plugins/:

      ln -s ~/src/my-plugin ~/.hermes/plugins/my-plugin

      تُوسم نسخة الحزمة المرتبطة بـ "linked": true. يراقب التطبيق desktop/plugin.js في النسخة المسحوبة؛ يعيد كل حفظ مزامنة النسخة (بحسب المحتوى، لا mtime، لذا يُحتسب git stash pop) ويعيد تحميل الإضافة فوريًا. تحتفظ تثبيتات الكتالوج و Git بقاعدة mtime.

      hermes plugins doctor <path-or-id> يحذّر عندما تختلف النسخة عن مصدرك ويذكر النسخة التي عثر عليها:

      WARN: Desktop runs a stale copy of desktop/plugin.js (~/.hermes/desktop-plugins/my-plugin);
      your edits are not loaded. Refresh it with Capabilities → Plugins → Rescan …

      ما زال هناك مفتاحا تفعيل ينطبقان، بشكل مقصود، وكلاهما افتراضيًا معطَّل: نصف desktop يُشحَن كخيار اختياري (opt-in) — يُدرَج ضمن الجرد في Capabilities → Plugins لكنه يبقى معطَّلًا حتى يبدّله المستخدم — مطابقًا لتقييد plugins.enabled الخاص بنصف Python في config.yaml (الحد الأمني أدناه). وضع حزمة في ~/.hermes/plugins خامل على كل الأسطح حتى يقول المستخدم غير ذلك. يتدهور نصف desktop بأمان عندما يكون نصف الـ backend معطَّلًا — يعيد ctx.rest أخطاء، لا انهيارات.

      ملاحظة

      النسخة محلية للجهاز الذي يعمل عليه تطبيق desktop. مقابل backend بعيد، لا يمكن الوصول إلى ~/.hermes/plugins الخاص بالجهاز البعيد كنظام ملفات — فقط الحزم المثبَّتة محليًا تسهم بنصف desktop بهذه الطريقة. بالنسبة لـ backend بعيد، يستنسخ حوار التثبيت نصف desktop بشكل منفصل إلى desktop-plugins/، كما في مستودع خاص بـ Desktop وحده. تعرض الحزمة التي ثُبّت نصف وكيلها على المضيف البعيد دون ذلك الاستنساخ نصف Desktop بوصفه unavailable (remote backend) في صفحة Plugins — لا كنسخة معلّقة — ويوجّه التلميح إلى Install from Git مع تحديد هدف Desktop.

      التوزيع برابط تثبيت​

      اشحن مستودع إضافتك (نصف الوكيل، أو نصف desktop، أو كليهما) واربطه باستخدام مخطط hermes:// — رابط بسيط على موقعك أو في README:

      <a href="hermes://plugin/install?repo=owner/repo&enable=1">Install in Hermes</a>

      يحصل المستخدم على حوار تأكيد (معرّف المستودع، روابط المصدر، فحص لما يشحنه المستودع) ويختار المكوّنات قبل تثبيت أي شيء — الروابط العميقة لا تُثبّت تلقائيًا أبدًا. force=1 يستبدل تثبيتًا موجودًا؛ نُسخ التطوير تستخدم hermes-dev://. مرجع الروابط الكامل: روابط التثبيت بنقرة واحدة.

      جانب Python​

      تعيد إضافات desktop استخدام نقطة تركيب backend الخاصة بإضافة لوحة التحكم. ضع الـ backend في مجلد فرعي dashboard/ ضمن إضافة Hermes عادية وأعلن عنه في manifest.json:

      ~/.hermes/plugins/<id>/
      └── dashboard/
          ├── manifest.json      # { "name": "<id>", "api": "plugin_api.py" }
          └── plugin_api.py      # exports `router = APIRouter()`
      # plugin_api.py
      from fastapi import APIRouter

      router = APIRouter()

      @router.get("/board")
      async def board():
          return {"items": ["one", "two", "three"]}

      @router.post("/action")
      async def action(body: dict):
          return {"ok": True, "received": body}

      تُركَّب المسارات تحت /api/plugins/<id>/ (GET /api/plugins/<id>/board، …). يعمل كود الـ backend داخل عملية gateway، بحيث يمكنه الاستيراد مباشرة من قاعدة كود hermes-agent (hermes_state، وhermes_cli.config، …). راجع توسيع لوحة التحكم → مسارات API للـ backend للمرجع الكامل للـ backend — نقطة التركيب متطابقة.

      backend الخاص بـ Python مقيّد بشكل منفصل

      تفعيل إضافة في لوحة Capabilities → Plugins الخاصة بـ desktop اختيار من جانب عارض الواجهة (renderer)؛ وهو لا يستورد Python. يُستورد plugin_api.py الخاص بإضافة المستخدم فقط عندما تكون الإضافة في قائمة السماح plugins.enabled ضمن config.yaml (وليست في plugins.disabled). إضافات المشروع (./.hermes/) لا تستورد Python تلقائيًا أبدًا. هذا حد أمني، لا إغفال (GHSA-mcfc-hp25-cjv7).

      دفع الأحداث إلى نصف Desktop​

      يعمل backend الخاص بك داخل عملية الـ gateway، لذا يستطيع دفع تحديث إلى نصف Desktop الخاص بك عبر تدفق الأحداث العام للتطبيق — التدفق نفسه الذي يشترك فيه host.onEvent:

      from hermes_cli.plugin_events import broadcast_plugin_event

      broadcast_plugin_event("rss-reader", "feed.updated", {"count": 3})
      # → event "plugin.rss-reader.feed.updated" reaches every connected desktop client
      // register(ctx): the subscription is retired with the plugin
      host.onEvent('plugin.rss-reader.feed.updated', ({ payload }) => refreshFeeds(payload))

      broadcast_plugin_event(plugin_id, event, payload=None): اسم النقل دائمًا plugin.<plugin_id>.<event>. plugin_id هو اسمك في الكتالوج ([a-z0-9_-]{1,64}، دون نقاط — فهو مساحة الأسماء ولا يمكنه كتابة اسم إضافة أخرى)؛ و event الاسم المنقّط المجرّد ("feed.updated"، لا "plugin.rss-reader.feed.updated")، بمقاطع من [A-Za-z0-9_-]، لذا تُطلق "" أو "../x" أو "a..b" الاستثناء ValueError بدلًا من ترك نصف Desktop يستمع إلى اسم لا يصدره أحد. payload قاموس JSON (أو يُحذف → {}) يُسلّم بوصفه payload للحدث؛ ويحمل الإطار session_id: "" ككل حدث عام. التسليم إرسال دون انتظار (يُتخطّى العميل العالق، ولا يعطّل معالجك مطلقًا). تعتمد وجهته على العملية التي ينفَّذ فيها الاستدعاء:

      عملية المستدعيالوجهة
      العملية التي يتصل بها Desktop — أي gateway المضيف الذي يرتبط به Desktop المحلي، أو hermes serve بعيد: موجّهات plugin_api.py و slash commands الإضافات والأدوات و hooks في دور الوكيلكل نافذة Desktop متصلة بتلك العملية
      العملية الفرعية لمضيف الحوسبة dashboard.turn_isolation (أدوات/hooks دور معزول)يُرحَّل عبر أنبوب المضيف (host pipe) إلى العملية الأصل، ثم إلى كل نافذة متصلة
      TUI عبر stdio (hermes في طرفية)عميل تلك الطرفية
      hermes chat أو cron أو hermes plugins validate أو gateway بلا نافذة Desktop متصلةلا أحد — لا يوجد عميل Desktop متصل بتلك العملية؛ الاستدعاء عملية بلا أثر يُسجَّل ذلك عنها

      استخدم هذا بدلًا من استيراد الآليات الداخلية لـ tui_gateway.server؛ وبالنسبة إلى أُطر مقيّدة بالإضافة ذات حمولة مخصّصة لكل اتصال، يظل ctx.socket('/events') المدخل الأغنى.

      الانتقال (rss-reader): أزل قائمة انتظار ~/.hermes/rss-reader/commands.jsonl و GET /commands واستطلاع ctx.rest('/commands') كل 3 s — يستدعي جانب Python broadcast_plugin_event('rss-reader', 'feed.updated', payload) حيث كان يُدرج في القائمة، ويستبدل جانب Desktop المؤقت بـ host.onEvent('plugin.rss-reader.feed.updated', fn) داخل register(ctx).

      استدعاؤه من الإضافة​

      register(ctx) {
        // REST — namespace-relative path.
        const load = () => ctx.rest('/board')                 // GET /api/plugins/<id>/board
        const act  = () => ctx.rest('/action', { method: 'POST', body: { go: true } })

        // Live twin — a WebSocket to your own namespace.
        const stop = ctx.socket('/events', frame => {
          queryClient.invalidateQueries({ queryKey: [ctx.source, 'board'] })
        })
      }

      ctx.rest يراعي profile ويرفض اجتياز المسارات (..) بحيث لا يمكنك أبدًا التوجّه إلى واجهة API خاصة بإضافة أخرى أو مسار أساسي عبره. PluginRestOptions هو { method?, body?, upload?: { filename, contentType?, bytes }, timeoutMs? }.

      ctx.socket يعيد الاتصال تلقائيًا بتراجع تدريجي (backoff) حتى يُستبعَد. ينحل إلى عملية تجاهل (no-op) على remotes بـ OAuth (تذاكر WS أحادية الاستخدام مُدارة من النواة) — عامِله كمُسرِّع فوق الاستطلاع (polling)، لا كبديل عنه. يحتاج كل مستهلك إلى بديل استطلاع على أي حال، لأن أي مقبس (socket) قد ينقطع.

      تعتمد طريقة المصادقة على الـ backend: يحصل الخادم البعيد بوضع token على بيانات اعتماد ?token= نفسها في الاستعلام التي تستخدمها sockets التطبيق نفسه؛ أما gateway المحلي (بلا token ثابت) فيصادق بالمنحة الأصلية (native grant) التي تحملها استدعاءات ctx.rest الخاصة بك. تُصدرها العملية الرئيسية في Desktop للـ profile النشط وتُلحقها كترويسة بذلك الاتصال وحده، فلا تظهر أبدًا في URL يراه كودك. والمنحة مرتبطة بمساحة أسماء إضافتك وبذلك الـ profile؛ ويرفض gateway الترقية (upgrade) إذا كانت الإضافة معطّلة لذلك الـ profile (ولا ينطبق إعداد الـ profile الذي أُطلق به التطبيق). أما إضافة profile ثانوي تعمل في مضيف الإضافات الخاص بها فتتلقى HTTP 501 بدلًا من ذلك، لأن المضيف لا يدعم websockets بعد.

      عندما يستسلم الـ socket (فيصبح الاستطلاع الاحتياطي لديك هو المصدر الوحيد):

      • يواصل إعادة المحاولة، مع تراجع عشوائي (jittered backoff) بحد أقصى 30 s، ما دام Desktop لا يستطيع حلّ اتصال gateway أو إصدار المنحة بعد، أو ما دامت محاولات الاتصال تفشل في الفتح. لا يستطيع العميل التمييز بين ترقية مرفوضة وgateway يُعاد تشغيله أو يُصرَّف (draining) أو يُعاد التأكد منه (re-ensure)، لذا يواصل الـ socket المحاولة خلال إعادة تشغيل مهما طالت، ويعيد الاتصال حالما يرد gateway من جديد.
      • يتوقف بعد 5 محاولات متتالية من الرفض لا تزول من تلقاء نفسها: أن يرفض Desktop إصدار المنحة لسبب يتعلق بالصلاحيات (مسار تحكم في gateway أو مجلد home للـ profile غير آمن)، أو أن يقبل الـ backend لديك الـ socket ثم يغلقه فورًا. ويعيد الـ socket الذي يبقى مفتوحًا العدّ إلى الصفر.
      • يبدأ من جديد عندما يتغير الاتصال النشط أو الـ profile، بعدّ جديد، أو عندما يُعاد تركيب (remount) العرض. كما أن تبديل الـ profile ينقل socket حيًّا: إذ يغلق Desktop الـ socket المرتبط بالـ profile القديم، ويُسقط منحة لا تزال قيد الإصدار له، ويتصل بالـ profile الجديد.

      بالنسبة لبيانات على نطاق gateway بأكمله (وليست في نطاقك الخاص)، استخدم host.request (JSON-RPC) و host.onEvent (تدفق أحداث gateway) بدلًا من ذلك.

      الإعدادات، وحالة التفعيل، والتخزين​

      كل إضافة — سواء مفعَّلة أم لا — تُدرَج ضمن الجرد في Capabilities → Plugins، حيث يفعّلها المستخدم أو يعطّلها فورًا (دون إعادة تشغيل التطبيق)، أو يعرض مجلدها، أو يعيد الفحص. تندرج تفضيلات الإضافة نفسها في Settings → Plugins (صفحات إعدادات الإضافات). يُتذكر اختيار المستخدم:

      • لا اختيار بعد → قيمة defaultEnabled الخاصة بالإضافة نفسها (الافتراضي true). اضبط defaultEnabled: false لشحن إضافة اختيارية تبقى معطَّلة حتى يشغّلها المستخدم.
      • اختيار صريح → يُحفظ ويُراعى عبر إعادة التشغيل. تبقى الإضافة المعطّلة معطّلة — لا تقاوم ذلك؛ فقد عطّلك المستخدم.

      احفظ حالتك الخاصة باستخدام ctx.storage، بنطاق مُميّز باسم إضافتك (hermes.plugin.<id>.*) بحيث لا تستطيع الإضافات قراءة أو إتلاف بيانات بعضها البعض:

      ctx.storage.set('lastTab', 'board')
      const tab = ctx.storage.get('lastTab', 'summary')
      ctx.storage.remove('lastTab')

      للملفات (vault أو مجلد ملاحظات أو عمليات تصدير) استخدم ctx.files: مجلد بياناتك الخاص بالإضافة إضافةً إلى المجلدات التي يمنحك إياها المستخدم.

      الإضافات المضمّنة (Bundled)​

      يمكن لإضافة أن تُشحَن ضمن الشجرة عند apps/desktop/src/plugins/<id>/plugin.tsx (تصدير افتراضي HermesPlugin). تُكتشَف بواسطة discoverBundledPlugins() عند الإقلاع — بلا استيراد، بلا تعديل سجل — وتشارك نفس عقد الجرد + التفعيل/التعطيل الحي كإضافة قرص. الفرقان الاثنان:

      1. تمر عبر بناء Vite الخاص بالتطبيق، لذا يمكنك كتابة JSX حقيقي واستيراد الـ SDK عبر اسمه المستعار @hermes/plugin-sdk.
      2. لا تزال مقيَّدة بأدوات lint إلى @hermes/plugin-sdk + react فقط — بلا داخليات @/… خاصة بالتطبيق.

      لا تُشحَن إضافات desktop في الشجرة الأساسية اليوم؛ يبقى التطبيق المُشحَن غير مزدحم والعروض التوضيحية موجودة في مستودع hermes-example-plugins المصاحب.

      النموذج الأمني​

      تُقيَّم الإضافة المحمَّلة كـ ESM في عالم عارض الواجهة (renderer realm) بـسلطة كاملة على التطبيق — النسخة الوحيدة (singleton) من React، وكامل الـ SDK (RPC الخاص بـ gateway عبر host.request، وctx.rest، والتخزين، وnavigate) والجسر الأصلي window.hermesDesktop (الملفات و git والطرفية والتثبيتات). العزل الذي يوفّره المحمّل هو عزل الأخطاء فقط: لا تستطيع الإضافة تعطيل التطبيق (مساهماتها محاطة بحدود أخطاء ومستمعوها معزولون، ويُتراجع عن register() الذي يطلق استثناءً ويُبلغ عنه في صف الإضافة)، لكنها تستطيع فعل أي شيء يفعله التطبيق. مساحات أسماء تخزين الإضافات اصطلاح، لا حاجز.

      هذا مقبول بالنسبة لمصادر محلية — فملف على القرص يستطيع بالفعل تشغيل كود على جهازك — ولهذا لا يحمّل باب القرص إلا ملفات محلية كتبتها أنت (أو وكيلك). أما تثبيتات الكتالوج فتأتي الثقة فيها من القبول (admission) — إذ راجع شخص الـ commit المثبّت نفسه — ويدعمها حاجزان: فحص lint الخاص بـ desktop surface عند القبول وقائمة السماح بالاستيراد لدى المحمّل (@hermes/plugin-sdk وreact* فقط؛ إذ يُفشل تحميلَ الإضافة أي import ثابت أو ديناميكي لأي شيء آخر، بما في ذلك عناوين https:). لا يُعدّ أيٌّ منهما sandbox. وأما الأبواب التي تلمس بيانات المستخدم خارج التطبيق فهي مقيّدة فوق ذلك: تحتاج ctx.preview.executeJavaScript إلى قدرة معلنة وموافقة المستخدم لكل أصل (سكربتات صفحة المعاينة). وينطبق على الوصول إلى الملفات القاعدة نفسها: ينبغي لإضافة الكتالوج أن تقرأ وتكتب عبر ctx.files، لا عبر جسر الملفات الخام window.hermesDesktop. تُفرَض ctx.files في العملية الرئيسية، لذا فإن الإضافة التي تستخدمها (أو نص غير موثوق تتعامل معه، مثل اسم ملاحظة قادم من النموذج) لا تستطيع مغادرة المجلدات التي منحها المستخدم؛ أما الجسر الخام فلا حد له، ولهذا تطلب مراجعة الكتالوج استخدام ctx.files. وسيحتاج باب المصادر البعيدة المستقبلي إلى حد حقيقي (iframe/worker + CSP + اشتراط القدرات) قبل أن يُتاح؛ فلا تعامل هذا الـ pipeline كحد ثقة.

      مزالق​

      • JSX لا يُحلَّل (parse) في إضافة قرص. يُحمَّل الملف دون تجميع — استخدم jsx() / jsxs() (أو React.createElement)، لا صياغة JSX. (الإضافات المضمّنة مبنية، لذا JSX مقبول فيها.)
      • ثلاثة معرّفات فقط قابلة للحل (resolve): @hermes/plugin-sdk، وreact، وreact/jsx-runtime. أي استيراد آخر يُظهر خطأ تحميل فوري.
      • لا تستخدم ألوانًا ثابتة أبدًا (#000، black، rgb(...)). اترك الخلفية كما هي؛ واستخدم متغيرات السمة (var(--ui-*)) لكل شيء.
      • أشِر فقط إلى ما استوردته. مكوّن نسيت استيراده (مثل StatusDot) يسبب ReferenceError عند العرض — تحقق مرة أخرى من أن كل معرّف في استدعاءات jsx() الخاصة بك موجود في سطر الاستيراد.
      • اقرأ الحالة بشكل أمري (imperatively) في المعالجات ($atom.get())، وليس من إغلاق (closure) خاص بالعرض — فالأحداث السريعة ستَرى قيمًا قديمة خلاف ذلك. اشترك (useValue) فقط في الورقة (leaf) التي تعرض القيمة.
      • يجب أن تتبع لوحات canvas حاويتها باستخدام ResizeObserver وتُعيد قياس canvas (سمتا العرض/الارتفاع، وليس CSS فقط) — فاللوحات تُعاد قياسها باستمرار.
      • لا تستطلع أسرع من بضع ثوانٍ باستخدام host.request؛ فضّل host.onEvent / ctx.socket ودع React Query يزيل التكرار.
      • العناصر العامة المجرّدة لا تُتتبّع. window.setInterval و window.addEventListener و <style> الذي تُلحقه — لا يراها المضيف أبدًا، فتبقى بعد التعطيل وكل إعادة تحميل فوري (لا يمكن إلغاء تحميل وحدات ES؛ تتكدس نسخ نشطة أثناء حلقة التحرير الفوري). استخدم ctx.setTimeout / ctx.setInterval / ctx.addEventListener، واربط أي شيء آخر بـ ctx.onDispose. حالة نطاق الوحدة مسؤوليتك لإعادة ضبطها.
      • مهلة تقييم الوحدة 10 s. تؤدي await في المستوى الأعلى التي لا تنتهي أبدًا (انتظار gateway غير عامل) إلى فشل التحميل بوصفه import timed out بدلًا من تعطيل فحص الإضافات؛ نفّذ الانتظار داخل register().
      • معرّف واحد، ملف واحد.يُحمَّل أول مجلد من مجلدين يصدران id نفسه (تثبيت مستقل بجوار نسخة حزمة موحّدة)، بحسب ترتيب أسماء المجلدات؛ ويعرض اللاحق duplicate id في صفه الخاص ضمن Capabilities ▸ Plugins.
      • ctx.socket عملية تجاهل (no-op) على remotes بـ OAuth. احرص دائمًا على بديل استطلاع.

      الوكلاء: مهارة hermes-desktop-plugins​

      عندما يكتب وكيل إضافة desktop، عليه تحميل مهارة hermes-desktop-plugins المضمّنة — فهي تحمل نفس عقد هذه الصفحة في صيغة موجَّهة للوكيل، مع templates/plugin.js جاهز للنسخ. هذه الصفحة هي المرجع البشري/الخاص بالمطوّر؛ والمهارة هي قائمة التحقق العملية.

      استكشاف الأخطاء وإصلاحها​

      إضافتي لا تظهر. تأكد أن الملف موجود في $HERMES_HOME/desktop-plugins/<id>/plugin.js وأن اسم المجلد يطابق id المُصدَّر. نفّذ ⌘K → Reload desktop plugins. تحقق من التطبيق بحثًا عن رسالة خطأ منبثقة تسمّي الإخفاق، وتابع سجل hermes logs gui -f.

      "unsupported import" عند التحميل. إضافة القرص لا يجوز أن تستورد سوى @hermes/plugin-sdk، وreact، وreact/jsx-runtime. أزل أي استيراد آخر.

      عنصر jsx لا يعرض شيئًا / يُطلق ReferenceError. معرّف مستخدَم في استدعاء jsx() غير مستورَد. أضفه إلى سطر الاستيراد.

      ctx.rest يعيد 404. الـ backend غير مُركَّب: تأكد من أن ~/.hermes/plugins/<id>/dashboard/manifest.json يحتوي "api": "plugin_api.py"، وأن الإضافة مدرجة في plugins.enabled ضمن config.yaml، وأعد تشغيل gateway (تُركَّب مسارات الـ backend عند بدء التشغيل). تابع ~/.hermes/logs/errors.log بحثًا عن Failed to load plugin <id> API routes.

      ctx.socket لا يُطلَق أبدًا. على remote بـ OAuth هو عملية تجاهل (no-op) بالتصميم — استخدم بديل الاستطلاع الخاص بك. وإلا تحقق من أن الـ backend يعرض مسار @router.websocket(...) المطابق تحت نطاقه.

      الألوان تبدو خاطئة بعد تبديل السمة. لقد استخدمت لونًا ثابتًا. استبدله بـ متغير سمة var(--ui-*).
