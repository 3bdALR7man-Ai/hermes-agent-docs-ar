      دورة حياة الجلسة

      الجمهور المستهدف: مطوّرو الـ gateway والقائمون بصيانته ملفات المصدر: gateway/session.py (نحو 1200 سطر + الملفات session_*.py المجاورة)، gateway/run.py (نحو 5500 سطر للواجهة + مراحل run_*.py )، gateway/config.py آخر تحديث: 2026-06-16

      نظرة عامة​

      تمثل الجلسة محادثة متواصلة بين الوكيل ومستخدم واحد أو أكثر على منصة مراسلة. وتحكم دورة حياة الجلسة متى تبقى المحادثات، ومتى تُعاد ضبطها، وكيف تصمد أمام إعادة تشغيل الـ gateway، وكيف تصطف الرسائل أثناء العمليات المتزامنة.

      يوجد نظام الجلسات أساسًا في وحدتين:

      • gateway/session.py — نموذج البيانات (SessionSource, SessionEntry, SessionContext)، وتوليد المفاتيح (build_session_key)، والمخزن الرئيسي (SessionStore).
      • gateway/run.py — واجهة مشغّل الـ gateway (GatewayRunner) التي تربط الجلسات بـ pipeline معالجة الرسائل؛ وتوجد المراحل في ملفات run_*.py المجاورة: صيانة الجلسات (run_watchers.py)، والتخزين المؤقت للوكلاء (run_agent_cache.py)، والاستعادة بعد إعادة التشغيل (session_recovery.py)، وإدراج الرسائل في الطابور (run_busy.py).

      1. SessionSource — واصف منشأ الرسالة​

      SessionSource سجل مجمّد لـ مصدر الرسالة. ويُرفَق بكل MessageEvent وارد ويُستخدم للتوجيه والعزل وحقن السياق.

      الحقول​

      الحقلالنوعالقيمة الافتراضيةالوصف
      platformPlatform(مطلوب)Enum يحدد منصة المراسلة (telegram و discord و slack و signal و whatsapp و matrix و local وغيرها).
      chat_idstr(مطلوب)معرّف المحادثة/المجموعة/القناة على مستوى المنصة. ويُمرَّر عبر تحويل chat_id_key للمحوّل.
      chat_nameOptional[str]Noneاسم المحادثة أو المجموعة المقروء للبشر.
      chat_typestr"dm"أحد "dm", "group", "channel", "thread". يتحكم في توليد مفتاح الجلسة والعزل.
      user_idOptional[str]Noneمعرّف المستخدم الخاص بالمنصة. يُستخدم للتفويض وعزل الجلسات لكل مستخدم.

      thread_idOptional[str]Noneمعرّف موضوع منتدى / سلسلة Discord / سلسلة Slack. يميز المحادثات المتسلسلة.

      الطرق الرئيسية​

      • description (خاصية: str) — ملخّص مقروء للبشر مثل "DM with Alice", "group: My Group, thread: 12345".
      • to_dict() / from_dict() — تسلسل واستعادة البيانات ذهابًا وإيابًا لحفظها في sessions.json.

      2. SessionEntry — سجل الجلسة النشطة​

      SessionEntry سجل البيانات الوصفية لكل جلسة المخزّن في الذاكرة والمحفوظ في {sessions_dir}/sessions.json. ويربط كل عنصر session_key بـ session_id.

      الحقول​

      الحقلالنوعالقيمة الافتراضيةالوصف
      session_keystr(مطلوب)مفتاح حتمي يحدد مسار المحادثة (راجع §4).
      session_idstr(مطلوب)معرّف فريد لهذه النسخة المحددة من المحادثة. الصيغة: YYYYMMDD_HHMMSS_<8hex>.
      created_atdatetime(مطلوب)وقت إنشاء هذه النسخة من الجلسة.
      updated_atdatetime(مطلوب)طابع زمني لآخر نشاط يُستخدم لصيانة الموارد.
      originOptional[SessionSource]Noneالمصدر الذي أنشأ هذه الجلسة، ويُستخدم لتوجيه التسليم.
      display_nameOptional[str]Noneاسم عرض المحادثة (مأخوذ من SessionSource.chat_name).
      platformOptional[Platform]NoneEnum للمنصة محفوظ للتوجيه عبر إعادة التشغيل.
      chat_typestr"dm"نوع المحادثة، محفوظ أيضًا للاستعلام عن السياسة.
      input_tokensint0tokens إدخال LLM (الـ prompt) المستهلكة تراكميًا.
      output_tokensint0tokens إخراج LLM (الإكمال) المستهلكة تراكميًا.
      cache_read_tokensint0tokens قراءة تخزين الـ prompt المؤقت التراكمية.
      cache_write_tokensint0tokens كتابة تخزين الـ prompt المؤقت التراكمية.
      total_tokensint0العدد الإجمالي للـ tokens عبر كل الأدوار.
      estimated_cost_usdfloat0.0التكلفة التراكمية المقدَّرة بـ USD.
      cost_statusstr"unknown"وسم حالة تتبّع التكلفة.
      last_prompt_tokensint0آخر عدد tokens للـ prompt أبلغت عنه API. يُستخدم لفحص دقيق قبل الضغط.

      العلامات المنطقية (آلة الحالة)​

      لدى SessionEntry عدة علامات منطقية تشكل آلة حالة بسيطة تحكم سلوك الجلسة عند الوصول التالي.

      العلامةالنوعالقيمة الافتراضيةالوصف
      was_auto_resetboolFalseتُضبط عندما يؤدي التعليق الصريح إلى جلسة بديلة. ويُحتفَظ بها أيضًا للسجلات التاريخية.
      auto_reset_reasonOptional[str]None"suspended" للتعليق الصريح؛ وقد تحتفظ الصفوف الأقدم بأسباب إعادة ضبط تاريخية.
      reset_had_activityboolFalseما إذا كانت الجلسة المستبدَلة قد شهدت نشاطًا سابقًا.
      is_fresh_resetboolFalseتُضبط بأمر صريح /new أو /reset. تفعّل إعادة حقن مهارات الموضوع/القناة عند أول رسالة. وتُميَّز عن was_auto_reset لتجنب إشعارات "session expired" المضللة.
      expiry_finalizedboolFalseحاجز إنهاء تاريخي يُحتفَظ به للاستعادة؛ ولا يكتبه أي مؤقّت.
      suspendedboolFalseإشارة مسح قسري صارم. يضبطها /stop أو تصعيد حلقة عالقة (3+ إخفاقات إعادة تشغيل متتالية). وعند get_or_create_session()التالي تفرض session_id جديدًا بغض النظر عن resume_pending.
      resume_pendingboolFalseعلامة استعادة مرنة. يضبطها recover_interrupted_turns() (الاستعادة بعد التعطل لدور معلَّم لم يُردّ عليه) أو انتهاء مهلة التفريغ. وعند الوصول التالي، تحتفظ بـ session_id الحالي — فيواصل المستخدم على نص المحادثة نفسه. وتُمسح بعد اكتمال الدور الناجح التالي.
      resume_reasonOptional[str]Noneسبب تعليم الاستئناف: "restart_timeout", "shutdown_timeout", "restart_interrupted".
      last_resume_marked_atOptional[datetime]Noneطابع زمني لآخر تعليم لاستئناف معلّق.

      منطق انتقال الحالة (get_or_create_session)​

                          ┌──────────┐
                          │  Incoming │
                          │  Message  │
                          └────┬─────┘
                               │
                               ▼
                    ┌──────────────────────┐
                    │  session_key exists  │──── No ──► Create fresh SessionEntry
                    │  AND !force_new      │
                    └──────────┬───────────┘
                               │ Yes
                               ▼
                    ┌──────────────────────┐
                    │  entry.suspended?    │──── Yes ──► Auto-reset: new session_id
                    └──────────┬───────────┘           (reason="suspended")
                               │ No
                               ▼
                    ┌──────────────────────┐
                    │ entry.resume_pending?│──── Yes ──► Return existing entry
                    └──────────┬───────────┘           (preserve session_id)
                               │ No                     Clear flag on next successful turn
                               ▼
                    ┌──────────────────────┐
                    │   Policy says reset? │──── Yes ──► Auto-reset: new session_id
                    └──────────┬───────────┘           (reason="idle"/"daily")
                               │ No
                               ▼
                    ┌──────────────────────┐
                    │  Return existing     │
                    │  entry, bump         │
                    │  updated_at          │
                    └──────────────────────┘

      ترتيب الأولوية في get_or_create_session():

      1. suspended=True → فرض إعادة الضبط دائمًا (مسح صارم)
      2. resume_pending=True → الاحتفاظ بـ session_id (استعادة مرنة)
      3. لا محفّز → إعادة العنصر الحالي (تحديث updated_at)

      3. SessionStore — التخزين والعمليات​

      SessionStore طبقة التخزين الرئيسية. تحتفظ بـ dict في الذاكرة (_entries) محفوظة في sessions.json، مع SQLite (SessionDB) كمخزن معتمد للبيانات الوصفية للجلسات ونصوص المحادثات.

      المُنشئ​

      SessionStore(sessions_dir: Path, config: GatewayConfig, has_active_processes_fn=None)
      • sessions_dir — الدليل الذي يوجد فيه sessions.json .
      • config — GatewayConfig نسخة لإعدادات التوجيه والصيانة.
      • has_active_processes_fn — callback اختياري مفتاحه session_key لفحص عمليات الخلفية الجارية. وتُحمى الجلسات ذات العمليات النشطة من تقليم عناصر التوجيه.

      العمليات (الطرق)​

      الطريقةالوصف
      get_or_create_session(source, force_new=False)نقطة الدخول الأساسية. تعيد عنصرًا موجودًا أو تنشئ SessionEntryجديدًا. تقيّم حالة التعليق الصريح والاستعادة بعد إعادة التشغيل. وتنشئ/تنهي سجلات SQLite.
      update_session(session_key, last_prompt_tokens=None)تحديث خفيف للبيانات الوصفية بعد تفاعل. يحدّث updated_at، ويسجّل اختياريًا last_prompt_tokens.
      reset_session(session_key, display_name=None)إعادة ضبط صريحة (من /new أو /reset). تنشئ session_idجديدًا، وتضبط is_fresh_reset=True. تنهي جلسة SQLite القديمة وتنشئ واحدة جديدة.
      switch_session(session_key, target_session_id, *, expected_session_id=None)التبديل إلى معرّف جلسة موجودة مختلفة (من /resume). ينهي جلسة SQLite الحالية ويعيد فتح الهدف. ومع expected_session_id= تكون إعادة التوجيه مقارنةً واستبدالًا: يعيد None دون تبديل حين لا يعود المفتاح يشير إلى تلك الجلسة، كي لا يكتب مستدعٍ حدّد الهدف استنادًا إلى لقطة عبر await (إعادة تثبيت تفويض غير متزامن، أو تصحيح ارتباط موضوع Telegram) فوق /new متزامن أو /resume.
      suspend_session(session_key)تعليم الجلسة بـ suspended=True (من /stop). يفرض إعادة ضبط تلقائية عند الوصول التالي.
      mark_resume_pending(session_key, reason)تعليم الجلسة بـ resume_pending=True (من انتهاء مهلة التفريغ). يحتفظ بـ session_id عند الوصول التالي. ولا يتجاوز suspended=True.
      clear_resume_pending(session_key)مسح resume_pending بعد دور مستأنف ناجح. يُستدعى من الـ gateway بعد عودة run_conversation() .
      recover_interrupted_turns(max_age_seconds)الاستعادة بعد التعطل: ترقية علامات الدور النشط الدائمة التي تركتها العملية المتوقفة إلى resume_pending=True (restart_interrupted). وتكون الجلسات دون علامة قد أنهت دورها فتُترك دون تغيير. يُستدعى عند بدء التشغيل بعد إيقاف غير سليم.
      prune_old_entries(max_age_days)إسقاط العناصر الأقدم من max_age_days (استنادًا إلى updated_at). يتجاوز العناصر suspended والجلسات ذات العمليات النشطة.
      list_sessions(active_minutes=None)إعادة كل الجلسات، مع ترشيح اختياري بالنشاط الحديث. مرتبة حسب updated_at تنازليًا.
      lookup_by_session_id(session_id)العثور على SessionEntry النشط لمعرّف جلسة محفوظ.
      has_any_sessions()التحقق مما إذا كانت قد أُنشئت أي جلسات أصلًا (يستخدم SQLite للتاريخ، لا dict الذاكرة فقط).
      append_to_transcript(session_id, message, skip_db=False)إلحاق رسالة بنص المحادثة في SQLite. skip_db=True يمنع الكتابة المكررة عندما يكون الوكيل قد حفظ بالفعل.
      rewrite_transcript(session_id, messages)استبدال كامل لنص الجلسة (يُستخدم بواسطة /retry, /undo, /compress).
      load_transcript(session_id)تحميل كل الرسائل من نص جلسة SQLite.
      rewind_session(session_id, n=1)الرجوع n أدوار مستخدم بحذف مرن (يحافظ على مسار التدقيق)؛ غلاف رقيق حول SessionDB.rewind_user_turn (hermes_state_rewind.py)، وهو الرجوع نفسه المشترك مع /undo//retry في CLI ومع TUI. يعيد {rewound_count, turns_undone, target_text}.

      الدوال المساعدة الداخلية​

      • _ensure_loaded() / _ensure_loaded_locked() — تحميل sessions.json إلى _entries dict.
      • _save() — كتابة ذرية إلى sessions.json عبر ملف مؤقت + atomic_replace.
      • _generate_session_key(source) — يفوّض إلى build_session_key() مع معاملات الإعدادات.

      تنظيم التخزين​

      {sessions_dir}/
        sessions.json          # In-memory _entries dict, persisted as JSON
                                 Maps session_key → SessionEntry (metadata only)
        {session_id}.jsonl     # (Legacy, removed in spec 002)

      مخزن نصوص المحادثات المعتمد هو SQLite عبر SessionDB (من hermes_state). ويحفظ ملف sessions.json ربط session_key → session_id والبيانات الوصفية للعناصر (العلامات، والطوابع الزمنية، وأعداد tokens). وإذا لم تتوفر SQLite، يعود المخزن إلى JSONL، لكن هذا مسار تدهور.

      4. قواعد توليد SessionKey​

      مفاتيح الجلسات سلاسل حتمية تحدد مسار محادثة. وتُولَّد بواسطة build_session_key(source, group_sessions_per_user, thread_sessions_per_user).

      صيغة المفتاح​

      agent:main:{platform}:{chat_type}[:{chat_id}][:{thread_id}][:{participant_id}]

      قواعد الرسائل المباشرة​

      السيناريوالمفتاح

      رسالة مباشرة مع chat_id + سلسلةagent:main:telegram:dm:12345:thread_678
      رسالة مباشرة دون chat_id ومع participant_idagent:main:signal:dm:user_abc
      رسالة مباشرة دون chat_id أو participant_idagent:main:telegram:dm

      • thread_id يميّز كذلك سلاسل الرسائل المباشرة ضمن المحادثة المباشرة نفسها.
      • دون chat_id، يعود إلى user_id_alt أو user_id بصفته participant_id.
      • دون أي معرّف، تتجمع كل الرسائل المباشرة على تلك المنصة في جلسة مشتركة واحدة.

      • chat_id يحدد المجموعة/القناة الأم.
      • thread_id يميّز السلاسل ضمن ذلك الأصل.
      • العزل لكل مستخدم (إلحاق participant_id) تتحكم فيه:
        • group_sessions_per_user (الافتراضي: True) — جلسات المجموعات/القنوات معزولة.
        • thread_sessions_per_user (الافتراضي: False) — السلاسل مشتركة افتراضيًا (تشارك موضوعات منتدى Telegram وسلاسل Discord و Slack جلسة واحدة لكل سلسلة).
      • participant_id = user_id_alt أو user_id (بهذه الأولوية).
      • تُحوَّل معرّفات WhatsApp إلى صيغة قياسية لمعالجة تبدّل الأسماء البديلة JID/LID.

      حالة خاصة: WhatApp​

      تمر أرقام هواتف WhatsApp عبر canonical_whatsapp_identifier() التي تزيل اللاحقة @s.whatsapp.net وتطبّع إلى صيغة E.164. يمنع هذا تفتّت الجلسة حين يعيد الجسر أشكالًا مختلفة للاسم البديل لرقم الهاتف نفسه.

      5. استراتيجية العزل متعدد المستخدمين​

      يحدد العزل متعدد المستخدمين ما إذا كان عدة مستخدمين في المحادثة نفسها يتشاركون محادثة أو يحصل كل منهم على جلسة خاصة.

      منطق القرار (is_shared_multi_user_session)​

      def is_shared_multi_user_session(source, *, group_sessions_per_user, thread_sessions_per_user):
          if source.chat_type == "dm":
              return False  # DMs are always private
          if source.thread_id:
              return not thread_sessions_per_user  # Threads: shared unless per-user
          return not group_sessions_per_user       # Groups: isolated unless shared

      نوع المحادثةالقيمة الافتراضيةالتحكم بالإعدادات
      رسالة مباشرةخاصة (لا تُشارك مطلقًا)لا ينطبق
      مجموعة/قناةعزل لكل مستخدمgroup_sessions_per_user (الافتراضي: True)
      سلسلة (منتدى، discord)مشتركة (يرى كل المشاركين السياق نفسه)thread_sessions_per_user (الافتراضي: False)

      الأثر على system prompt​

      عندما يكون shared_multi_user_session=True، يحذف system prompt اسم المستخدم الثابت ويذكر بدلًا منه: "Multi-user {thread|session} — messages are prefixed with [sender name]. Multiple users may participate." يضيف الـ gateway أسماء المرسلين الأفراد في بداية كل رسالة مستخدم وقت التشغيل، مع الحفاظ على تخزين الـ prompt المؤقت (لا يتغير system prompt لكل دور).

      6. الحدود الصريحة للمحادثة​

      لا يدوّر الخمول ولا الزمن الفعلي المحادثة مطلقًا. /new و /reset ينشئان حدًا صريحًا؛ ويستمر ضغط السياق في إدارة السجلات الطويلة. وتُتجاهَل إعدادات المؤقّت القديمة.

      يظل التعليق الصريح ينشئ حدًا عند الدور الوارد التالي. وتحترم الاستعادة الحدود الصريحة والمنتهية تاريخيًا بدل إعادة فتحها. ويبقي الإخلاء الخاص بالموارد وحدها وتنظيف WebSocket اليتيم المحادثات قابلة للاستئناف.

      7. تدفق الاسترداد بعد إعادة التشغيل​

      يضمن نظام الاسترداد بعد إعادة التشغيل الحفاظ على الجلسات الجارية عبر إعادة تشغيل الـ gateway أو تعطّله أو انتهاء مهلة الاستنزاف. وهو حل issue رقم #7536.

      الاسترداد من التعطّل (_recover_unclean_sessions)​

      يُستدعى عند بدء الـ gateway إذا لم توجد علامة .clean_shutdown (تعطّل أو خروج غير متوقع). لا يعمل إلا على علامات الأدوار النشطة الدائمة، لا على حداثة النشاط: فالمحادثة التي كانت نشطة قبل التعطّل بقليل وأكملت دورها لا يُرد عليها مجددًا.

      تُضبط العلامة عند بدء الدور وتبقى حتى يُدرج الرد النهائي في سجل التسليم (يحرّرها المحوّل مباشرةً بعد record_delivery_obligation)، أو حتى لا يبقى شيء مستحق (رد مبثوث أو استجابة مكبوتة أو فارغة). لذلك تعني العلامة المتبقية عند البدء إحدى حالتين:

      • حُفظ الرد دون إدراجه في سجل التسليم. يُسجَّل الرد المخزّن في نص المحادثة كصف غير مملوك في السجل، وتُمحى العلامة؛ وتسلّمه جولة الفحص عند الإقلاع مرة واحدة مع إشعار "Recovered reply". لا يُعاد توليد الدور. يُقيّم الرد كما كان سيُقيّم أثناء التسليم المباشر: فعلامة صمت منفردة ([SILENT] أو NO_REPLY وغيرها) في دور داخلي، أو الرد على تنبيه تشخيصي تكتمه سياسة المحادثة، لا يترتب عليه شيء (تُمحى العلامة ولا يُرسل شيء ولا يُستأنف). وتتحول علامة الصمت المنفردة لدور بشري إلى إشعار "returned only a silence marker" نفسه الذي يرسله المسار المباشر.
      • لم يُحفظ أي رد. recover_interrupted_turns() تضبط resume_pending=True و resume_reason="restart_interrupted"، ويُستأنف الدور تلقائيًا مرة واحدة.

      يُخزّن وقت بدء العلامة بصيغة UTC واعية بالمنطقة الزمنية ويُقارن كثوانٍ منذ epoch، فلا تؤدي إعادة التشغيل في منطقة محلية مختلفة (تغيير DST أو الحاوية مقارنةً بـ TZ للوحدة) إلى إسقاط علامة حديثة باعتبارها قديمة أو اعتماد رد الدور السابق كأنه رد هذا الدور. تُقرأ العلامة المكتوبة بواسطة build أقدم (وقت محلي غير واعٍ بالمنطقة) باعتبارها وقت المضيف المحلي.

      تُعيد جولة فحص السجل تسليم أي دور موجود فيه بالفعل، وتمحو أيضًا أي resume_pending لتلك الجلسة، فلا يحدث التسليم وإعادة الإجابة معًا مطلقًا.

      كشف حلقات التعليق (_suspend_stuck_loop_sessions)​

      يعدّ مرات إعادة التشغيل المتتالية عبر ملف JSON ({HERMES_HOME}/restart_counts.json). إذا ظلت جلسة نشطة عبر 3 مرات إعادة تشغيل متتالية أو أكثر، تُعلَّق تلقائيًا ليبدأ المستخدم بداية نظيفة.

      وضع علامة انتهاء مهلة الاستنزاف​

      عند الإيقاف/إعادة التشغيل المنظمين، يستدعي نظام الاستنزاف mark_resume_pending() لكل جلسة كانت في منتصف دور عند انتهاء المهلة. الأسباب:

      • "restart_timeout" — أُنهيت أثناء استنزاف إعادة التشغيل
      • "shutdown_timeout" — أُنهيت أثناء استنزاف الإيقاف
      • "restart_interrupted" — استرداد دور معلّم بلا رد من التعطّل (من recover_interrupted_turns)

      توجد الأسباب الثلاثة جميعها في _AUTO_RESUME_REASONS وتؤهل للاستئناف التلقائي عند البدء.

      الاستئناف التلقائي عند الوصول التالي​

      عندما تصادف get_or_create_session() القيمة resume_pending=True:

      1. تُرجع المدخل الحالي دون إنشاء session_id جديد.
      2. يُحمّل نص المحادثة الحالي كاملًا دون تغيير.
      3. لا تُمحى العلامة هنا — بل تبقى حتى يكتمل الدور الناجح التالي (تُستدعى clear_resume_pending() من الـ gateway بعد أن تُرجع run_conversation() استجابة حقيقية).
      4. إذا قوطع الدور المستأنف مجددًا، تبقى علامة resume_pending مضبوطة، وستعيد محاولة إعادة التشغيل التالية. يعالج عدّاد الحلقة العالقة التصعيد النهائي (3 محاولات → تعليق).

      علامة الإيقاف المنظم (.clean_shutdown)​

      تُكتب في نهاية الإيقاف المنظم. وعند البدء التالي:

      • إذا وُجدت: تخطَّ الاسترداد من التعطّل كليًا وتخلّص من علامات الأدوار اليتيمة. فقد استُنزفت الوكلاء النشطة بالفعل، فلا توجد جلسات عالقة.
      • ثم احذف العلامة.

      يمنع هذا عمليات إعادة الضبط التلقائي غير المرغوبة بعد hermes update أو hermes gateway restart أو /restart.

      8. تدفق وضع الرسائل في قائمة الانتظار​

      يعالج نظام قائمة انتظار الرسائل سيناريوهين:

      1. متابعات المقاطعة — عندما يرسل المستخدم عدة رسائل أثناء معالجة الوكيل، توضع الرسائل اللاحقة كرسائل معلّقة في خانة واحدة.
      2. /queue بنظام FIFO — أوامر /queue الصريحة التي يجب أن ينتج كلٌّ منها دور وكيل كاملًا مستقلًا، بالترتيب ودون دمج.

      بُنى البيانات​

      adapter._pending_messages: Dict[session_key, MessageEvent]
          └── Single "next-up" slot per session. Overwritten on repeat sends
              (burst collapse). Shared with photo-burst follow-ups.

      self._queued_events: Dict[session_key, List[MessageEvent]]
          └── Overflow buffer. Each /queue invocation appends here when the
              slot is occupied. Promoted one-at-a-time after each drain.

      الإدراج في القائمة (_enqueue_fifo)​

      _enqueue_fifo(session_key, event, adapter)
             │
             ▼
      ┌───────────────────────────────────────┐
      │ Is slot free?                         │
      │ (session_key NOT in _pending_messages)│── Yes ──► Place event in slot
      └───────────────────────────────────────┘
             │ No
             ▼
      Append to _queued_events[session_key] (overflow tail)

      الإخراج / الترقية (_promote_queued_event)​

      يُستدعى عند موضع الاستنزاف بعد استهلاك الخانة. إذا وُجد عنصر فائض:

      • عندما تكون pending_event is None (الخانة كانت فارغة)، أرجع رأس القائمة الفائضة كحدث جديد.
      • عندما توجد pending_event، جهّز رأس القائمة الفائضة في الخانة للتكرار الاستدعائي التالي.
      • إذا لم يتوفر محوّل، أعد العنصر إلى _queued_events (لا تُسقطه بصمت).

      عمق القائمة​

      _queue_depth(session_key, adapter) تُرجع len(overflow) + (1 if slot occupied else 0).

      المحو​

      تُمحى أحداث الجلسة الموضوعة في القائمة عند /new و /reset (عبر _handle_reset_command). يُسقط /stop المتابعة ذات الخانة الواحدة التي أرسلها المستخدم أثناء الدور المقاطَع. أما التنبيه الداخلي الموضوع في أيٍّ من المخزنين (إشعار إكمال تفويض غير متزامن، أو notify+wake خاص بـ kanban/cron) فيبقى عبر الأوامر الثلاثة: تتركه _interrupt_and_clear_session في الخانة (وتُرقّيه من القائمة الفائضة إذا كانت متابعة بشرية محذوفة تشغل الخانة)، ليبدأه الاستنزاف التالي للأمر فورًا بدلًا من بقاء الجلسة خاملة حتى رسالة المستخدم التالية. ويُقرّر وقت المعالجة ما إذا كان يمكن لتنبيه مثبت إلى جلسة أغلقها /new للتو الاستمرار في التشغيل (_resolve_async_delegation_session، مع الرفض عند تعذّر التحقق).

      ينهي كلا الأمرين أيضًا التفويضات الخلفية الخاصة بالجلسة (tools.async_delegation. interrupt_for_session، المحددة بمفتاح التوجيه ومعرّف جلسة المنشئ الدائم): توزّع _interrupt_and_clear_session طلب الإيقاف في مسار الانشغال، وتفعل _handle_stop_command الشيء نفسه لجلسة خاملة انتهى دور إرسالها بالفعل (فترد "Stopped" بدلًا من "No active task to stop"). لا تصل المقاطعة القسرية الخاصة بالدور نفسه إلى تلك الوحدات — فهي منفصلة عن _active_children عند الإرسال — لذا، دون توزيع الإيقاف، تعمل حتى الإكمال وتنبّه المحادثة بعد دقائق. تظل كل وحدة موقوفة تنهي عملها طبيعيًا وتعود كإشعار إكمالها مع status="interrupted" والمخرج الجزئي للعملية الفرعية. وكان /new و /reset يفعلان ذلك بالفعل في _handle_reset_command؛ ويكون الاستدعاء المبكر للأداة المساعدة المشتركة آمنًا عند التكرار هناك (طلب المقاطعة القسرية مرتين يعني إيقافًا واحدًا).

      ثبات FIFO​

      ينتج كل استدعاء لـ /queue دور وكيل كاملًا واحدًا بالضبط، بترتيب FIFO، دون دمج. يضمن تصميم _pending_messages ذي الخانة الواحدة + _queued_events للفائض ألّا تؤدي عمليات الإرسال المتكررة أثناء دور نشط إلى معالجة خارج الترتيب.

      9. حقن سياق الجلسة​

      SessionContext يُبنى من SessionSource و GatewayConfig ويُحقن في system prompt للوكيل. ويخبره بما يلي:

      • مصدر الرسالة الحالية
      • المنصات المتصلة
      • الوجهات الممكنة لتسليم مخرجات المهام المجدولة
      • ما إذا كانت الجلسة مشتركة بين عدة مستخدمين

      البناء (build_session_context)​

      def build_session_context(source, config, session_entry=None) -> SessionContext
      1. يجمع المنصات المتصلة من الإعدادات.
      2. يجمع القنوات الرئيسية لكل منصة.
      3. يحدّد shared_multi_user_session عبر is_shared_multi_user_session().
      4. يرفق بيانات الجلسة الوصفية (المفتاح والمعرّف والطوابع الزمنية) إذا توفرت session_entry.

      إخفاء معلومات الهوية الشخصية (build_session_context_prompt)​

      يمكن لقسم system prompt الديناميكي (## Current Session Context) إخفاء معلومات تحديد الهوية الشخصية اختياريًا قبل إرسالها إلى LLM:

      • معرّفات المستخدمين → user_<12hex> (بادئة SHA-256)
      • معرّفات المحادثات → <platform>:<12hex> أو ببساطة <12hex>
      • المنصات المستثناة من الإخفاء: Discord (يحتاج إلى المعرّفات الخام لـ @mentions)، وأي منصة مسجّلة بإضافة غير موسومة بـ pii_safe.

      ينطبق الإخفاء على نص system prompt فقط. ويستخدم التوجيه ومفاتيح الجلسات وعمليات المحوّل القيم الأصلية دائمًا.

      10. الصيانة الخلفية​

      يفحص _session_housekeeping_watcher دوريًا الوكلاء المخزّنة مؤقتًا والخاملة، ويُسقط مدخلات التخزين المؤقت عند ضغط الذاكرة، وينظّف مدخلات التوجيه القديمة كل ساعة. ولا ينهي نص محادثة بسبب الخمول أو وقت اليوم أبدًا.

      تحفظ عمليات الإخلاء بفعل TTL أو LRU أو الضغط نص المحادثة المباشر لدى مزوّدي الذاكرة قبل تحرير العملاء تحريرًا مرنًا. وتظل الأدوار النشطة محمية؛ وتبقى موارد الطرفية والمتصفح والعمليات الخلفية بعد التحرير المرن. يحافظ تنظيف مدخلات التوجيه على نص المحادثة المرجعي في SQLite، وتحمي العمليات النشطة مدخلات توجيهها من التنظيف. وتظل علامات expiry_finalized التاريخية حدودًا للاسترداد، لكنها لم تعد تُكتب بواسطة مراقب مؤقت.

      11. ذاكرة الوكلاء المؤقتة​

      يحتفظ الـ gateway بذاكرة LRU مؤقتة لنُسخ AIAgent مفهرسة بـ session_key للحفاظ على التخزين المؤقت للـ prompt عبر الأدوار.

      خصائص التخزين المؤقت​

      • الحجم الأقصى: 128 مدخلًا (agent.agent_cache.max_size، والقيمة الافتراضية _AGENT_CACHE_MAX_SIZE).
      • سياسة الإخلاء: الأقل استخدامًا مؤخرًا (LRU عبر OrderedDict).
      • TTL للخمول: 3600s (1h) — agent.agent_cache.idle_ttl_secs، تفرضه _session_housekeeping_watcher.
      • ميزانية الذاكرة: agent.agent_cache.memory_high_mb (القيمة الافتراضية auto) — راجع أدناه.
      • القفل: _agent_cache_lock (threading) لضمان أمان الخيوط.

      الإخلاء بسبب ضغط الذاكرة​

      يثبّت الوكيل المخزّن مؤقتًا _session_messages، أي نص المحادثة النشط كاملًا بما فيه مخرجات الأدوات — عشرات MB لجلسة ذات 100 استدعاء أداة أو أكثر. لا يراعي حد المدخلات ولا TTL للخمول ذلك: يبقي gateway الذي يخدم محادثات كثيرة كل نص محادثة دافئ مقيمًا في الذاكرة (لا يشمل فحص الخمول الوكلاء التي نفّذت دورًا ضمن TTL)، فيرتفع RSS حتى يقيّد cgroup التشغيل ولا يعود SIGTERM قادرًا على التفريغ ضمن مهلة إيقاف systemd (#80764).

      _sweep_agent_cache_under_pressure() هو صمام التحكم. يقارن في كل دورة مراقبة الذاكرة المجهولة بـ memory_high_mb — قيمة memory.stat anon الخاصة بـ cgroup عندما يعمل الـ gateway ضمن حد cgroup (وهو النطاق الذي تُحتسب عليه الميزانية، فتُحسب العمليات الفرعية في الوحدة نفسها مثل نوى execute_code؛ #110549)، وإلا يستخدم RSS المجهول الخاص بالعملية؛ وعند تجاوز الميزانية، يُخلي وكلاء LRU عبر المسار المرن نفسه الذي يفرض الحد (_commit_then_release_soft)، ثم ينفّذ malloc_trim لتعود مناطق الذاكرة المحررة فعليًا إلى نظام التشغيل. تعيد الجلسات التي أُخليت بناء نصها من الجلسة المحفوظة عند الدور التالي.

      لا تُسقط ثلاث فئات من الجلسات مطلقًا:

      • الوكلاء الموجودة حاليًا في منتصف دور (عملاؤها و sandboxes الخاصة بها قيد الاستخدام)؛
      • الجلسات protect_recent الأكثر استخدامًا مؤخرًا (تخزين prompts الخاص بها هو الأعلى قيمة)؛
      • أي جلسة لم يكتمل وصول نص محادثتها النشط إلى القرص — تقارن transcript_persistence_caught_up() قيمة _last_flushed_db_idx بـ len(_session_messages)، وهو التباين نفسه الذي يتعامل معه حارس فساد كتابة FTS عندما يحافظ على السجل النشط بدلًا من نص محادثة متأخر.

      memory_high_mb: auto يشتق الميزانية من حد cgroup الذي يعمل الـ gateway ضمنه (memory.high، ثم memory.max، ثم cgroup v1)، مع الرجوع إلى RAM الإجمالية عند عدم وجود حد. اضبط رقمًا لتثبيتها، أو 0/off لتعطيل هذه الجولة كليًا. توجد الأدوات المساعدة في gateway/agent_cache_pressure.py.

      دورة حياة التخزين المؤقت​

      Message arrives
          │
          ▼
      get_or_create_session()  →  session_key obtained
          │
          ▼
      Lookup _agent_cache[session_key]
          │
          ├── Hit → move_to_end(), reuse AIAgent (preserves prompt cache)
          │
          └── Miss → create new AIAgent, store in cache
                      (if at capacity, popitem(last=False) evicts LRU entry)
          │
          ▼
      run_conversation()  →  agent processes message
          │
          ▼
      Housekeeping soft-releases idle agents without ending transcripts

      تدفق التنظيف​

      يزيل إخلاء الموارد الوكيل المخزّن مؤقتًا ويحفظ الذاكرة قبل تحرير العملاء مرنًا. يُحجز التفكيك الكامل عبر _cleanup_agent_resources(agent) لحدود المحادثات الفعلية والإيقاف.

      قاعدة بيانات الحالة واسترداد FTS​

      يوجد نص المحادثة المرجعي في جدولي sessions و messages. جداول FTS5 ومشغّلات مزامنتها فهارس مشتقة يمكن فصلها وإعادة بنائها دون حذف الرسائل المرجعية. راجع استرداد State DB لمعرفة نمط الفشل النشط المحدود وإجراء الإصلاح الصريح.

      عمر المحادثة​

      لا تُدعم إعدادات إعادة الضبط عند الخمول أو يوميًا. وتحتفظ أوامر /new و /reset الصريحة، والضغط والتعليق والاسترداد من التعطّل، بأدوارها المنفصلة في دورة الحياة.
