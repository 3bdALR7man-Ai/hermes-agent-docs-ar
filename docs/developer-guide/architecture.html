      البنية المعمارية (Architecture)

      هذه الصفحة هي الخريطة العليا للآليات الداخلية في Hermes Agent. استخدمها لتتعرّف على موقعك في قاعدة الكود، ثم انتقل إلى المستندات الخاصة بكل نظام فرعي للاطلاع على تفاصيل التنفيذ.

      تدفّق البيانات​

      جلسة CLI​

      User input → HermesCLI.process_input()
        → AIAgent.run_conversation()
          → prompt_builder.build_system_prompt()
          → runtime_provider.resolve_runtime_provider()
          → API call (chat_completions / codex_responses / anthropic_messages)
          → tool_calls? → model_tools.handle_function_call() → loop
          → final response → display → save to SessionDB

      رسالة عبر Gateway​

      Platform event → Adapter.on_message() → MessageEvent
        → GatewayRunner._handle_message()
          → authorize user
          → resolve session key
          → create AIAgent with session history
          → AIAgent.run_conversation()
          → deliver response back through adapter

      مهمة Cron​

      Scheduler tick → load due jobs from jobs.json
        → create fresh AIAgent (no history)
        → inject attached skills as context
        → run job prompt
        → deliver response to target platform
        → update job state and next_run

      ترتيب القراءة المقترح​

      إذا كنت جديدًا على قاعدة الكود:

      1. هذه الصفحة — لتتعرّف على موقعك
      2. آلية عمل Agent Loop من الداخل — كيف يعمل AIAgent
      3. تجميع الـ Prompt — بناء الـ system prompt
      4. تحديد المزوّد وقت التشغيل (Provider Runtime Resolution) — كيف يُختار المزوّدون
      5. إضافة مزوّدين — دليل عملي لإضافة مزوّد جديد
      6. بيئة تشغيل الأدوات (Tools Runtime) — سجل الأدوات، والتوزيع (dispatch)، والبيئات
      7. تخزين الجلسات — مخطط SQLite، و FTS5، وتسلسل نسب الجلسات (lineage)
      8. آلية عمل Gateway من الداخل — الـ gateway الخاص بمنصات المراسلة
      9. ضغط السياق والتخزين المؤقت للـ Prompt (Prompt Caching) — الضغط والتخزين المؤقت
      10. آلية عمل ACP من الداخل — التكامل مع بيئات التطوير (IDE)

      الأنظمة الفرعية الرئيسية​

      حلقة الوكيل (Agent Loop)​

      محرّك التنسيق المتزامن (AIAgent، الذي تكشفه الواجهة run_agent.py؛ بينما توجد الحلقة نفسها في agent/conversation_loop.py وagent/turn_*.py). يتولى اختيار المزوّد، وبناء الـ prompt، وتنفيذ الأدوات، وإعادة المحاولة، واللجوء الاحتياطي (fallback)، والاستدعاءات العكسية (callbacks)، والضغط، والحفظ الدائم. ويدعم ثلاثة أوضاع API لمختلف أنواع الـ backends الخاصة بالمزوّدين.

      → آلية عمل Agent Loop من الداخل

      نظام الـ Prompt​

      بناء الـ prompt وصيانته عبر دورة حياة المحادثة:

      • system_prompt.py + prompt_builder.py — يجمّعان مستويات الـ system prompt المرتّبة (stable → context → volatile): الهوية/إرشادات الأدوات/المهارات، ثم ملفات السياق، ثم كتل الذاكرة/الـ profile/الطابع الزمني
      • prompt_caching.py — يطبّق نقاط التوقف الخاصة بالتخزين المؤقت في Anthropic (cache breakpoints) للتخزين المؤقت للبادئة (prefix caching)
      • context_compressor.py — يلخّص أدوار المحادثة الوسطى حين يتجاوز السياق الحدود المعيّنة

      → تجميع الـ Prompt، ضغط السياق والتخزين المؤقت للـ Prompt (Prompt Caching)

      تحديد المزوّد​

      مُحلِّل مشترك وقت التشغيل يستخدمه كلٌّ من CLI، والـ gateway، و cron، و ACP، والاستدعاءات المساعدة. يربط الثنائيات (provider, model) بالقيم (api_mode, api_key, base_url). ويتعامل مع أكثر من 18 مزوّدًا، وتدفّقات OAuth، ومجمّعات بيانات الاعتماد، وتحليل الأسماء المستعارة.

      → تحديد المزوّد وقت التشغيل (Provider Runtime Resolution)

      نظام الأدوات​

      سجل مركزي للأدوات (tools/registry.py) يضم أكثر من 70 أداة مسجّلة موزّعة على نحو 28 toolset. يسجّل كل ملف أداة نفسه تلقائيًا عند الاستيراد. يتولى السجل جمع المخططات (schemas)، والتوزيع، والتحقق من التوفّر، وتغليف الأخطاء. تدعم أدوات الطرفية 7 أنواع من الـ backends (local، و Docker، و SSH، و Daytona، و Modal، و Singularity، و Vercel Sandbox).

      → بيئة تشغيل الأدوات (Tools Runtime)

      الحفظ الدائم للجلسات​

      تخزين للجلسات قائم على SQLite مع بحث نصي كامل عبر FTS5. تتضمن الجلسات تتبّعًا للنسب (أب/ابن عبر عمليات الضغط)، وعزلًا لكل منصة، وعمليات كتابة ذرّية (atomic) مع معالجة التزاحم.

      → تخزين الجلسات

      Messaging Gateway​

      عملية طويلة التشغيل تضم أكثر من 25 platform adapter (مدمجة + إضافات مضمّنة)، وتوجيهًا موحّدًا للجلسات، وتفويضًا للمستخدمين (قوائم السماح + الاقتران عبر الرسائل المباشرة DM)، وتوزيعًا للـ slash commands، ونظامًا للـ hooks، ونبضات cron، وصيانة في الخلفية.

      → آلية عمل Gateway من الداخل

      نظام الإضافات (Plugins)​

      ثلاثة مصادر للاكتشاف: ~/.hermes/plugins/ (للمستخدم)، و.hermes/plugins/ (للمشروع)، ونقاط الدخول (entry points) الخاصة بـ pip. تسجّل الإضافات الأدوات والـ hooks وأوامر CLI عبر API للسياق. ويوجد نوعان متخصصان من الإضافات: مزوّدو الذاكرة (plugins/memory/) ومحركات السياق (plugins/context_engine/). وكلاهما أحادي الاختيار — أي لا يمكن تفعيل أكثر من واحد من كل نوع في الوقت نفسه، ويُضبط ذلك عبر hermes plugins أو config.yaml.

      → دليل الإضافات، إضافة مزوّد الذاكرة

      Cron​

      مهام وكيل من الدرجة الأولى (وليست مهام shell). تُخزَّن المهام بصيغة JSON، وتدعم صيغ جدولة متعددة، ويمكن أن تُرفق بها مهارات وسكربتات، وأن تُسلِّم نتائجها إلى أي منصة.

      → آلية عمل Cron من الداخل

      التكامل مع ACP​

      يكشف Hermes بوصفه وكيلًا أصيلًا داخل المحرّر عبر stdio/JSON-RPC لكلٍّ من VS Code و Zed و JetBrains.

      → آلية عمل ACP من الداخل

      مسارات التنفيذ (Trajectories)​

      يولّد trajectories بصيغة ShareGPT من جلسات الوكيل لإنتاج بيانات التدريب.

      → صيغة Trajectories والتدريب

      مبادئ التصميم​

      المبدأما يعنيه عمليًا
      ثبات الـ Promptلا يتغيّر الـ system prompt في منتصف المحادثة. ولا توجد تعديلات تكسر التخزين المؤقت إلا عبر إجراءات صريحة من المستخدم (/model).
      تنفيذ قابل للمراقبةكل استدعاء لأداة مرئي للمستخدم عبر الاستدعاءات العكسية. تظهر تحديثات التقدّم في CLI (مؤشر دوّار) وفي الـ gateway (رسائل المحادثة).
      قابل للمقاطعةيمكن إلغاء استدعاءات API وتنفيذ الأدوات أثناء عملها عبر مدخلات المستخدم أو الإشارات (signals).
      نواة مستقلة عن المنصةصنف AIAgent واحد يخدم CLI، والـ gateway، و ACP، والمعالجة الدفعية، وخادم API. وتقع الفروقات بين المنصات في نقطة الدخول، لا في الوكيل.
      اقتران مرنتستخدم الأنظمة الفرعية الاختيارية (MCP، والإضافات، ومزوّدو الذاكرة، وبيئات RL) أنماط السجلات (registry) والتقييد عبر check_fn، لا الاعتماديات الصلبة.
      عزل الـ Profilesيحصل كل profile (hermes -p <name>) على HERMES_HOME وإعدادات وذاكرة وجلسات ومعرّف عملية (PID) للـ gateway خاصة به. ويمكن تشغيل عدة profiles بالتزامن.

      سلسلة اعتماديات الملفات​

      tools/registry.py  (no deps — imported by all tool files)
             ↑
      tools/*.py  (each calls registry.register() at import time)
             ↑
      model_tools.py  (imports tools/registry + triggers tool discovery)
             ↑
      run_agent.py, cli.py, batch_runner.py, environments/

      تعني هذه السلسلة أن تسجيل الأدوات يحدث عند الاستيراد، قبل إنشاء أي نسخة من الوكيل. يُكتشف تلقائيًا أي ملف tools/*.py يحتوي على استدعاء registry.register() في المستوى الأعلى — دون الحاجة إلى قائمة استيراد يدوية.
