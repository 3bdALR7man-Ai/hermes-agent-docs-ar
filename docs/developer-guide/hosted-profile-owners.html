      الغرف المستضافة عبر ملفات profile المحلية

      يعتمد تنفيذ الغرف المستضافة على سلطة الجلسات المعتمدة (canonical session authority). تشغّل كل ملف profile عملية gateway عادية خاصة بها، وتملك قاعدة بيانات الحالة الخاصة بها وحدها. ويتواصل مشغّل الغرفة المصدر (source room driver) مع مالكي الوجهات عبر مقابس التحكم الخاصة (control sockets) المصادَق عليها على مستوى نظام التشغيل؛ فهو لا يطلق أبدًا عامل جلسات قديمًا (legacy session worker) ولا يفتح قاعدة بيانات الوجهة.

      يمكن للغرفة أن تضم ملفات profile التي يخدمها gateway الخاص بها: ملف profile الخاص بالـ gateway نفسه، وكذلك، ضمن gateway.multiplex_profiles، كل ملف profile يخدمه المُجمِّع (multiplexer) حاليًا (يحصل كل ملف profile مخدوم على سلطته وقاعدة بياناته الخاصة هناك). وفي الاتصال ذي نطاق المضيف (host-scoped) — كالمقبس المشترك في Desktop ولوحة التحكم (dashboard) — لا يحتاج ذلك إلى أي إعداد؛ وهذا هو المسار الذي تسلكه ميزة New Group Chat في Desktop. أما الاتصال المرتبط بملف profile واحد فيضم ذلك الملف إضافةً إلى ملفات profile التي تسمّيها مدخلات hosted_rooms.profiles الخاصة به، كما كان سابقًا؛ ويجب أن يشير أي مدخل يسمّي ملف profile مخدومًا إلى مجلده الرئيسي المخدوم (served home). ولا ينضم ملف profile يملكه gateway محلي آخر إلا بوصفه وجهة صريحة في إعدادات ملف profile المصدر:

      hosted_rooms:
        profiles:
          helper: /absolute/path/to/profiles/helper

      يجب أن يطابق الاسم اسم ملف profile الوجهة، ويحتاج الوجهة إلى مالك فعّال (live owner): إما gateway خاص به (ملف profile من نوع gateway.standalone)، وإما مُجمِّع محلي آخر يخدمه. المجلد الرئيسي الواحد يستجيب لاسم واحد. وفي الاتصال ذي نطاق المضيف يحتفظ ملف profile المخدوم بمجلده الرئيسي المخدوم مهما قال مدخله. أما المدخل الذي يسمّي مجلدًا رئيسيًا مضمّنًا أصلًا تحت اسم آخر، أو المدخل المشوّه، فيُتجاهل مع سطر سجل واحد، ويُرفض فقط العضو الجديد الذي يسمّيه؛ أما الغرفة التي تضم أصلًا مثل هذا الاسم المستعار (alias) فتواصل تشغيل أعضائها الآخرين. ووجود المجلد وحده لا يخوّل التنفيذ، لذا فإن ملف profile المثبّت لكنه غير مخدوم هنا (الموقوف، أو الذي يملكه gateway ليس لدى هذا الـ gateway مدخل له) يُرفض عند إنشاء الغرفة، مع ذكر العضو المعني في رسالة الرفض. ويُرفض كذلك ملف profile مخدوم يكون مجلده profiles/<name> رابطًا (link): إذ لا يستطيع نقل الأعضاء (member transport) الوصول إليه باسمه بعد. وتُعرض مدخلات الإعدادات بوصفها بيانات وصفية للقائمة (roster metadata) دون قراءة إعدادات الوجهة أو جلساتها.

      التنفيذ بين ملفَي profile يخدمهما المُجمِّع نفسه مغطّى باختبارات داخل العملية (in-process) تشغّل مقبس التحكم الخاص الحقيقي. لكنه لم يُعتمد بعد على تثبيت حيّ متعدد ملفات profile، ولا يستطيع الأعضاء الذين يكون مجلد profile الخاص بهم رابطًا تشغيل الأدوار.

      تتحقق الوجهة بالاتجاه المعاكس من ملكية الغرفة الحالية، والعضوية، وهوية المهمة الدائمة بدقة، والجيل المستضاف (hosted generation)، و prompt المجمّد، مع المصدر عند الإرسال ومرة أخرى قبل الإخراج من الطابور. وتحتفظ بربط (binding) ذي مساحة أسماء خاصة بالمصدر في قاعدة بياناتها. وإذا كان المصدر أو الوجهة غير متاح، فإن العملية تفشل بإغلاق آمن (fails closed)، ولا يُعاد توجيه العمل المحتفظ به بصمت. وهذه الواجهة الخاصة للمنتِج (producer interface) غير متاحة لعملاء WebSocket العامين. ويسري على مقابس التحكم الوثوق المحلي بين العمليات التي تعمل بمستخدم نظام التشغيل نفسه.

      ينشر بدء التشغيل المحوّلات (adapters) قبل الاستعادة المستضافة. وتحلّ الرقابة المعتمدة (canonical supervision) محل مشغّل الغرفة القديم، مما يتفادى تنافس عقود الإيجار (leases). وتستعيد إعادات المحاولة المكتملة الإيصال نفسه دون inference جديد. أما العمل الذي بدأ بعد تعطّل المالك فيُعدّ مجهول الحالة ويوقف المتابِعين مؤقتًا. ولا يمكن لإعادة المحاولة (Retry) أن تعيد تشغيل عمل مجهول الحالة. ويجب على المستخدم المالك استخدام Discard مع الغرفة والعضو والمهمة والجيل المستضاف بدقة؛ ويُثبَّت حل الحالة المجهولة المعتمد قبل إيصال الإلغاء الخاص بمشغّل المصدر. وتكرار هذا التجاهل (discard) بدقة يستعيد إقرارًا مفقودًا.

      يكتشف Desktop المجموعات المعتمدة (canonical groups) ويرسل أوامر التحكم إلى الاتصال وملف profile والغرفة التي جرى التقاطها. ويعرض العمل المجهول الحالة خيار Discard مع تأكيد، ولا يعرض Retry أبدًا. أما المجموعات الحالية التي تعيش في طبقة العرض (renderer) فقط فتتطلب إنشاء غرفة معتمدة جديدة بشكل صريح؛ ولا يُعاد تشغيل السجل تلقائيًا بوصفه عملًا جديدًا. وتتعامل مساحة العمل المعتمدة حاليًا مع النص وأوامر التنفيذ؛ أما نشر المرفقات فيبقى قدرة مستقلة للغرف.
