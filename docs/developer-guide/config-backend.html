      واجهة Config Backend

      تمرّ كل عمليات القراءة والفحص (stat) والتحقق من الوجود والكتابة الخاصة بملف config.yaml الخاص بالمستخدم في أي profile عبر hermes_cli/config_backend.py. يُختار الـ backend مرة واحدة لكل عملية من HERMES_CONFIG_BACKEND، ولا يُختار أبدًا من قيمة في ملف الإعدادات: القيمة file هي الافتراضية، وremote هو Remote Config (plugins/config_backends/remote/).

      الدوال المساعدة​

      الدالة المساعدةالاستخدام
      read_config_doc(path)تعيد طبقة المستخدم بعد تحليلها (وترفع الأخطاء كما تفعل open مع fast_safe_load)
      read_config_doc_readonly(path)قراءة مخزَّنة مؤقتًا بحسب التوقيع؛ لا تعدّل النتيجة أبدًا
      config_version(path)توقيع التغيّر (tuple الـ stat للملف، أو الإصدار البعيد)
      config_cache_version(path) (config_cache_version_or_none)توقيع لـ cache التحليل: tuple الـ stat مضافًا إليه digest للمحتوى ما دام الأحدث بين mtime و ctime أحدث من utils.RACY_MTIME_WINDOW_NS (يُستخدم utils.file_cache_version في file backend)؛ وفي remote backend يكون الإصدار البعيد
      config_exists(path)هل الطبقة موجودة (الطبقة البعيدة موجودة دائمًا)
      config_version_or_none(path) / version_token(version)الإصدار، أو None عند غيابه؛ ورقم يتغيّر معه (mtime الخاص بـ TUI/الجلسة)
      probe_config_readable(path)ترفع OSError ما دامت الطبقة غير قابلة للقراءة (دون تحليل)؛ ويرفع remote backend الاستثناء ConfigBackendUnavailable ما دام المستوى البعيد (plane) عاجزًا عن خدمتها
      write_config_document(path, doc) / write_config_key(path, key, value)عمليات الكتابة؛ وعادةً يستخدم المستدعون atomic_config_write / atomic_config_replace
      supports_file_tooling() / require_file_tooling(what)بوابة للأدوات التي تنسخ الملف نفسه أو تعدّله أو تنشئ نسخة احتياطية منه (config edit، والنسخ الاحتياطي/الاستعادة، واستنساخ الـ profile)

      الملف <home>/config.yaml وحده هو طبقة المستخدم. أما أي ملف آخر يُمرَّر إلى هذه الدوال المساعدة (مصدر استيراد، أو fixture) فيُقرأ ويُكتب في مكانه أيًّا كان الـ backend المختار. يعتمد cache التحليل على config_cache_version لا على config_version: ففي الأنوية التي لا تدعم الطوابع الزمنية متعددة الحبيبات (multigrain timestamps)، تُبقي إعادة الكتابة في المكان نفسه بالحجم نفسه ضمن tick القراءة كلًا من mtime و ctime والحجم و inode على حالها، فيُبقي tuple الـ stat وحده التحليل الأقدم مثبّتًا طوال عمر العملية (ومن أكثر ما يتضرر بذلك api_key بعد تدويره). أما أي ملف آخر يُشتق منه cache (auth.json، وقوائم الاقتران (pairing)، و.env، وملفات الـ token، وoverlay المُدار) فيعتمد على utils.file_cache_version(path)؛ والتوقيع الذي يُخزَّن ويُقارَن بعد وقت طويل (كاشف تغيّر يؤدي إيجابه الكاذب إلى إعادة اتصال بشيء ما، أو سجل فشل تحليل) يمرّر always_digest=True، لأن digest الـ racy يصبح فارغًا بمجرد استقرار الملف (وهذا ما تفعله manifest المهارات، وhook-consent، وأختام free-tier و onboarding). ويُحكم على «الحداثة» بـ ctime كما بـ mtime، لأن cp -p أو rsync --inplace -t يستعيدان mtime أقدم بعد الكتابة. ولا يحسب worker المرتبط بلقطة إعدادات مجمّدة (frozen config snapshot) digest لأي ملف config.yaml أبدًا: يبقى مفتاحه هناك قائمًا على stat فقط، فلا يجعل فحص المحتوى مثل هذا الـ worker يفتح ملف الـ profile. وتفقد الـ caches المعتمدة على config_cache_version صلاحيتها (miss) عندما يثبّت استطلاع بعيد (remote poll) طبقة جديدة، تمامًا كما تفعل بعد تعديل ملف محلي. ومع file backend، يبقى النطاق المُدار (/etc/hermes) overlay فوق طبقة المستخدم. أما remote backend فيتجاهل ملف config.yaml المُدار: تأتي الإعدادات والأقفال من Remote Config وحده، ويُبلغ hermes doctor عن الملف إن وُجد. ويبقى ملف .env المُدار مطبَّقًا في الوضعين.

      المفاتيح المترابطة التي يجب أن تتغيّر معًا (مفاتيح model.* عند تبديل النموذج، وتبديل /focus في TUI) تمرّ عبر write_config_keys(path, {key: value, ...}). يرسلها remote backend كعملية كتابة CAS واحدة، فيؤدي قفل أي مفتاح منها إلى رفضها كلها.

      فحوص Lint​

      • يرفض scripts/check_config_yaml_writers.py أي تفريغ YAML مباشر لمسار إعدادات.
      • يرفض scripts/check_config_yaml_readers.py أي open / read_text / stat / exists / تحميل YAML مباشر لمسار إعدادات. أما الإنذار الكاذب الحقيقي (ملف إعدادات منتج آخر، أو أدوات ملفات مقيَّدة أصلًا بـ supports_file_tooling()) فيحمل # config-reader: ok — <why> على السطر نفسه.
