      بناء إضافة لمزوّد النماذج

      تصرّح إضافات مزوّدي النماذج (model provider plugins) عن backend للـ inference — سواء كان endpoint متوافقًا مع OpenAI، أو خادم Anthropic Messages، أو Responses API على نمط Codex، أو واجهة Bedrock أصلية — يستطيع Hermes توجيه استدعاءات AIAgent عبره. ويأتي كل مزوّد مدمج (OpenRouter و Anthropic و GMI و DeepSeek و Nvidia، …) على هيئة إضافة من هذا النوع. ويمكن للأطراف الخارجية إضافة مزوّديها بوضع مجلد تحت $HERMES_HOME/plugins/model-providers/ دون أي تغيير في المستودع.

      نصيحة

      إضافات مزوّدي النماذج هي النوع الثالث من إضافات المزوّدين. أما النوعان الآخران فهما إضافات مزوّدي الذاكرة (المعرفة عبر الجلسات) وإضافات Context Engine (استراتيجيات ضغط السياق). وتتبع الأنواع الثلاثة النمط نفسه: "ضع مجلدًا، وصرّح عن profile، دون تعديل المستودع".

      كيف يعمل الاكتشاف​

      providers/__init__.py._discover_providers() بشكل كسول (lazy) في أول مرة تستدعي فيها أي شيفرة get_provider_profile() أو list_providers(). ترتيب الاكتشاف:

      1. الإضافات المضمّنة — <repo>/plugins/model-providers/<name>/ — تأتي مع Hermes
      2. إضافات المستخدم — $HERMES_HOME/plugins/model-providers/<name>/ — ضع مجلدًا؛ تكتشفه العملية الجارية عند البحث التالي عن المزوّد (دون إعادة تشغيل)
      3. الإضافات المثبّتة — $HERMES_HOME/plugins/<name>/ (حيث ينسخ hermes plugins install owner/repo المستودعات) — لا تُستورد إلا عندما يصرّح plugin.yaml بـ kind: model-provider؛ وأي نوع آخر هناك يتبع PluginManager العام
      4. الصيغة القديمة أحادية الملف — <repo>/providers/<name>.py — للتوافق مع الإصدارات السابقة في عمليات التثبيت القابلة للتعديل (editable) خارج الشيفرة الأساسية

      تُطبَّق الخطوتان 2 و 3 لكل مجلد رئيسي لـ profile: تحدد العملية الواحدة التي تخدم عدة profiles (الـ gateway متعدد الـ profiles الذي يتصل به Desktop محلي، أو backend الخاص بـ hermes serve) إضافات الـ profile الذي ترتبط قيمة $HERMES_HOME الخاصة به وقت البحث؛ ولا تظهر إضافة مثبّتة في profile لـ profile آخر. ثبّت الإضافة في كل profile ينبغي أن يستخدمها (hermes -p <profile> plugins install ...).

      تتفوق إضافات المستخدم على الإضافات المضمّنة التي تحمل الاسم نفسه لأن register_provider() تعتمد قاعدة "آخر من يكتب هو الفائز". ضع مجلد $HERMES_HOME/plugins/model-providers/gmi/ لاستبدال profile المدمج الخاص بـ GMI دون لمس المستودع.

      بنية المجلدات​

      plugins/model-providers/my-provider/
      ├── __init__.py       # Calls register_provider(profile) at module-level
      ├── plugin.yaml       # kind: model-provider + metadata (optional but recommended)
      └── README.md         # Setup instructions (optional)

      الملف الإلزامي الوحيد هو __init__.py. أما plugin.yaml فيستخدمه hermes plugins للاستبطان (introspection)، ويستخدمه PluginManager العام لتوجيه الإضافة إلى المحمّل المناسب؛ ودونه يلجأ المحمّل العام إلى أسلوب استدلالي يعتمد على نص الشيفرة المصدرية.

      مثال مبسّط — مزوّد بسيط يعتمد على مفتاح API​

      # plugins/model-providers/acme-inference/__init__.py
      from providers import register_provider
      from providers.base import ProviderProfile

      acme = ProviderProfile(
          name="acme-inference",
          aliases=("acme",),
          display_name="Acme Inference",
          description="Acme — OpenAI-compatible direct API",
          signup_url="https://acme.example.com/keys",
          env_vars=("ACME_API_KEY", "ACME_BASE_URL"),
          base_url="https://api.acme.example.com/v1",
          auth_type="api_key",
          default_aux_model="acme-small-fast",
          fallback_models=(
              "acme-large-v3",
              "acme-medium-v3",
              "acme-small-fast",
          ),
      )

      register_provider(acme)
      # plugins/model-providers/acme-inference/plugin.yaml
      name: acme-inference
      kind: model-provider
      version: 1.0.0
      description: Acme Inference — OpenAI-compatible direct API
      author: Your Name

      حقول ProviderProfile​

      التعريف الكامل موجود في providers/base.py. وأكثر الحقول فائدة:

      الحقلالنوعالغرض
      namestrالمعرّف القياسي — يطابق model.provider في config.yaml والخيار --provider
      aliasestuple[str, ...]أسماء بديلة تحسمها get_provider_profile() (مثل grok → xai)
      api_modestrchat_completions | codex_responses | anthropic_messages | bedrock_converse
      display_namestrالتسمية المقروءة للبشر المعروضة في منتقي hermes model
      descriptionstrالعنوان الفرعي في أداة الاختيار
      signup_urlstrيُعرض أثناء الإعداد عند التشغيل الأول ("احصل على مفتاح API من هنا")
      hiddenboolقبل الإصدار: يُستبعد من كل واجهات الاكتشاف (منتقيات المزوّدين، وقائمة الإعداد، وتبويب الحسابات في لوحة التحكم) حتى تصبح listed() صحيحة — افتراضيًا عندما يسجّل المستخدم الدخول بالاسم (يكتب hermes auth add <name> صفًا في المجمّع). ولا يُقيَّد التحديد بالاسم مطلقًا
      env_varstuple[str, ...]متغيرات البيئة الخاصة بمفتاح API مرتبة حسب الأولوية؛ ويُستخدم إدخال *_BASE_URL الأخير بوصفه تجاوزًا من المستخدم لعنوان base URL
      base_urlstrendpoint الـ inference الافتراضي
      models_urlstrعنوان URL صريح للكتالوج (مع الرجوع إلى {base_url}/models احتياطيًا)
      auth_typestrapi_key | oauth_device_code | oauth_external | copilot | aws_sdk | external_process
      auth_handlerCallable | Noneأوامر hermes auth add/status/logout/refresh <name> التي يملكها المزوّد — راجع المصادقة التي يملكها المزوّد
      refresh_credentialCallable | Noneتدوير صف OAuth في المجمّع بواسطة المزوّد — القسم نفسه
      classify_api_errorCallable | Noneتجاوز تصنيف الأخطاء الخاص بالمزوّد — راجع التعافي وتصنيف الأخطاء
      fallback_modelstuple[str, ...]قائمة منتقاة تُعرض عند فشل جلب الكتالوج المباشر — في منتقي /model وفي مسار مفتاح API عند أول hermes setup / hermes model، اللذين يحددان الكتالوج بالطريقة نفسها (تُدمج fetch_models() مع fallback_models مع تقديم القائمة المنتقاة؛ وتُستخدم fallback_models وحدها عندما تعيد عملية الجلب None أو تطلق استثناءً)
      supports_visionboolيعلن أن API المزوّد تقبل محتوى صور داخل رسائل نتائج الأدوات (قدرة بروتوكولية عامة للمزوّد). يأتي توجيه صور المستخدم لكل نموذج من model_capabilities / models.dev، لا من هذا الخيار
      model_capabilitiesdict[str, dict[str, Any]]إعلانات قدرات كل نموذج بمخطط model_overrides — راجع إعلان قدرات النماذج
      default_headersdict[str, str]تُرسل مع كل طلب (مثل Editor-Version)؛ ويعيد توجيهها أيضًا طلب الكتالوج الافتراضي fetch_models()
      fixed_temperatureAnyNone = استخدام قيمة المستدعي؛ والقيمة الخاصة OMIT_TEMPERATURE = عدم إرسال temperature إطلاقًا (Kimi)
      default_max_tokensint | Noneحد أقصى لـ max_tokens على مستوى المزوّد (Nvidia: 16384)
      unsupported_response_formatstupleresponse_format أنواع ترفضها API مباشرةً؛ تحذفها الطلبات المساعدة بدلًا من تلقي 400 مضمون (DeepSeek: ("json_schema",))
      default_aux_modelstrنموذج منخفض التكلفة للمهام المساعدة (الضغط، الرؤية، التلخيص)

      إعلان قدرات النماذج​

      يحدد Hermes قدرات كل نموذج (supports_reasoning, supports_vision, supports_tools, context_window) من كتالوج models.dev، الذي لا يعرف نماذج المزوّد الموجود خارج الشجرة. أعلنها مرة واحدة على profile:

      register_provider(ProviderProfile(
          name="acme",
          auth_type="api_key",
          env_vars=("ACME_API_KEY",),
          base_url="https://api.acme.example/v1",
          fallback_models=("acme-large-high", "acme-small"),
          model_capabilities={
              "acme-large-high": {
                  "supports_reasoning": False,   # reasoning tier is fixed by the model id
                  "supports_vision": True,
                  "supports_tools": True,
                  "context_window": 64000,
                  "model_family": "acme",
              },
          },
      ))

      المفاتيح معرّفات نماذج مطابقة تمامًا. تستخدم القيم مخطط model_overrides من config.yaml — القيم المنطقية الثلاث للقدرات، وقيمة موجبة لـ context_window، وقيمة اختيارية لـ model_family — وتظل الحقول المحذوفة غير معروفة (لا False)، لذلك يكمّل الإدخال الجزئي بيانات الكتالوج الوصفية دون محوها.

      يغذي الإعلان الواحد كل مستهلك يقرأ الكتالوج عبر agent.models_dev: شارة /model الخاصة بمنتقي reasoning، وتوجيه الصور (تختار decide_image_input_mode وضع native لنموذج supports_vision: True حتى عندما لا تُضبط supports_vision العامة للـ profile)، والبحث عن context window، و /api/model/info في لوحة التحكم. ترتيب الأولوية: تجاوز المستخدم الصريح model_overrides.<provider>.<model> → إعلان الإضافة → الكتالوج → سد الثغرات بواسطة _default. وتحتفظ النماذج التي لا تعلنها الإضافة بمسار الكتالوج/الاستدلالات التقريبية.

      لا يشمل ذلك: شارة fast في المنتقي (استدلالًا تقريبيًا من اسم النموذج في hermes_cli/models.py::model_supports_fast_mode)، ومفردات جهد الاستدلال (agent/reasoning_effort.py)، وحقول طلبات النقل. لا تضيف الإعلانات نماذج إلى المنتقي — استخدم fallback_models / fetch_models لذلك. يُكتشف السجل مرة واحدة لكل عملية: أعد تشغيل Hermes بعد تعديلها.

      الـ hooks القابلة لإعادة التعريف​

      أنشئ فئة فرعية من ProviderProfile للخصوصيات غير البسيطة:

      from typing import Any
      from providers.base import ProviderProfile

      class AcmeProfile(ProviderProfile):
          def prepare_messages(self, messages: list[dict[str, Any]]) -> list[dict[str, Any]]:
              """Provider-specific message preprocessing. Runs after codex
              sanitization, before developer-role swap. Default: pass-through."""
              # Example: Qwen normalizes plain-text content to a list-of-parts
              # array and injects cache_control; Kimi rewrites tool-call JSON
              return messages

          def build_extra_body(self, *, session_id=None, **context) -> dict:
              """Provider-specific extra_body fields merged into the API call.
              Context includes: session_id, provider_preferences, model, base_url,
              reasoning_config. Default: empty dict."""
              # Example: OpenRouter's provider-preferences block,
              # Gemini's thinking_config translation.
              return {}

          def build_api_kwargs_extras(self, *, reasoning_config=None, **context):
              """Returns (extra_body_additions, top_level_kwargs). Needed when some
              fields go top-level (Kimi's reasoning_effort, OpenRouter's verbosity for
              adaptive Anthropic models) and some go in extra_body (OpenRouter's
              reasoning dict). Default: ({}, {})."""
              return {}, {}

          def fetch_models(self, *, api_key=None, base_url=None, timeout=8.0) -> list[str] | None:
              """Live catalog fetch. Default hits {models_url or base_url}/models with
              Bearer auth. Override for: custom auth (Anthropic), no REST endpoint
              (Bedrock → None), or public/unauthenticated catalogs (OpenRouter)."""
              return super().fetch_models(api_key=api_key, base_url=base_url, timeout=timeout)

          def fetch_account_usage(self, *, api_key=None, base_url=None):
              """Return AccountUsageSnapshot for /usage, or None when unavailable.

              The hook runs only when the provider has no built-in usage fetcher.
              It may raise: core catches failures and keeps /usage empty for that turn.
              """
              return None

          def create_client(self, **client_kwargs):
              """Supply your own client object instead of the shared openai.OpenAI.
              Default returns None (= use the standard client). Override when the
              wire protocol is not OpenAI-over-HTTP — e.g. an ACP subprocess shim.
              client_kwargs is what the core would have passed to openai.OpenAI
              (api_key, base_url, command, args, timeouts, headers…); accept **kwargs
              and pick what you need. A raise is logged and falls back to the
              standard client."""
              return None

      استخدام الحساب​

      يمكن لإضافات مزوّدي النماذج توفير استخدام الحساب أو الخطة إلى /usage بإعادة تعريف ProviderProfile.fetch_account_usage. استورد وأعد الكائن المشترك agent.account_usage.AccountUsageSnapshot (مع أي إدخالات AccountUsageWindow)؛ ولا تنسّق المخرجات في الإضافة. تؤدي إعادة None أو إطلاق استثناء إلى ترك /usage فارغًا كما يحدث للمزوّدين دون بيانات استخدام. تحظى دوال جلب الاستخدام المدمجة بالأولوية دائمًا، فلا تستطيع هذه hook استبدال سلوك استخدام الحساب لمزوّد مدمج. تعمل hook تحت مهلة مشتركة قدرها 10 ثوانٍ (agent.account_usage.PLUGIN_USAGE_HOOK_DEADLINE_S) على كل الواجهات؛ ويؤدي تجاوزها إلى عدم عرض شيء في ذلك الدور بدلًا من تعطيل /usage، لذلك اضبط مهلة أقصر لاستدعاءات HTTP الخاصة بك.

      يطبّق profile المضمّن plugins/model-providers/opencode-zen/ هذه hook لنوافذ خطة OpenCode Go؛ وتعرض كل واجهات /usage (أمرا CLI hermes usage و /usage، و messaging gateway، وتغذية الاستخدام في TUI/Desktop) اللقطة عبر منسّق النواة نفسه.

      from datetime import datetime, timezone

      from agent.account_usage import AccountUsageSnapshot, AccountUsageWindow

      def fetch_account_usage(self, *, api_key=None, base_url=None):
          return AccountUsageSnapshot(
              provider=self.name,
              source="my_provider_api",
              fetched_at=datetime.now(timezone.utc),
              windows=(AccountUsageWindow(label="Monthly", used_percent=25),),
          )

      مزوّدو العمليات الخارجية (ACP)​

      وكيل CLI يُدار عبر stdio ليس endpoint من نوع HTTP. اضبط auth_type="external_process"، وصِف طريقة تشغيل الملف التنفيذي، ووفّر العميل عبر create_client. لا حاجة إلى أي تعديلات في الشيفرة الأساسية — فكل من hermes -m <name> و/model وحسم بيانات الاعتماد والحسم وقت التشغيل والعميل المساعد (الضغط، الرؤية) يعتمد على auth_type، لا على اسم المزوّد. ويُعد plugins/model-providers/copilot-acp/ المثال الموجود ضمن الشيفرة الأساسية.

      الحقلالغرض
      process_commandالملف التنفيذي الافتراضي، مثل "copilot"
      process_argsذيل argv الافتراضي، مثل ("--acp", "--stdio")
      process_command_env_varsمتغيرات البيئة التي تتجاوز الملف التنفيذي، ويجري فحصها بالترتيب
      process_args_env_varمتغير البيئة الذي يتجاوز argv (يُقسَّم باستخدام shlex)

      يتلقى العميل الذي تُرجعه create_client القيمتين command وargs ضمن client_kwargs. وإذا كان العميل مكتملًا أصلًا وآمنًا للاستخدام غير المتزامن، فصرّح بـ HERMES_SKIP_TRANSPORT_WRAP = True / HERMES_SKIP_ASYNC_WRAP = True كخصائص للفئة، كي لا يعيد العميل المساعد إرسالها عبر محوّل بروتوكول HTTP.

      صفوف المنتقي للإضافات التي لا تستخدم مفتاح API​

      ينضم كل profile مسجّل إلى CANONICAL_PROVIDERS باسمه المعرّف (تُزال ازدواجية إضافة تعيد إعلان اسم مدمج مثل bedrock ولا يتكرر)، فتظهر إضافات العمليات الخارجية و OAuth في hermes model, /model ومنتقي النماذج في Desktop إلى جانب copilot-acp. يُقيَّد الظهور ببيانات الاعتماد، لا بـ auth_type:

      auth_typeيُدرَج الصف / تكون authenticated عندماقائمة النماذج
      external_processيُعثر على الملف التنفيذي (توجد process_command أو إحدى قيم process_command_env_vars على PATH)، أو تكون base_url بقيمة acp+tcp://… — وهو القيد البنيوي نفسه الذي يعرضه hermes auth status. ويُعدّ العثور على الملف التنفيذي أيضًا دليل تسجيل الدخول (auth_verified) الذي يستخدمه مرشح الاختيار الصريح فقط في منتقي Desktop، فيظهر الصف هناك كما يظهر مزوّد ACP المضمّنfetch_models() (فحص عمليتك الفرعية)، وإلا fallback_models
      oauth_external / oauth_device_codeيحتوي مجمّع بيانات الاعتماد صفًا للاسم المعرّف مع token صالح (غير منتهي) — يقرأ كل من hermes auth status <name> و list_available_providers().authenticated المجمّع؛ ويُبلَّغ عن صف منتهٍ يملك refresh_token و hook refresh_credential بوصفه needs_refreshfetch_models() باستخدام token من المجمّع، وإلا fallback_models (أعلن نموذجًا واحدًا على الأقل)

      تُفهرَس ذاكرة الكتالوج المؤقتة بقيم process_command_env_vars / process_args_env_var للـ profile، لذلك يؤدي توجيه HERMES_<X>_COMMAND إلى ملف تنفيذي مختلف إلى إعادة اكتشاف النماذج. اكتشاف الملف التنفيذي ليس فحص تسجيل دخول: يظل CLI غير المُصادَق عليه مدرجًا، وتبلغ العملية الفرعية عن الإخفاق عند أول استخدام.

      يؤدي اختيار الصف في hermes model (وفي معالج الإعداد) إلى تشغيل مسار عام واحد يعتمد على auth_type للـ profile: يُفحص إطلاق profiles العمليات الخارجية (resolve_external_process_provider_credentials)، وتحتاج profiles OAuth إلى صف صالح في المجمّع (وإلا يطبع المسار hermes auth add <name> ويتوقف)، ثم يُعرض الكتالوج المدمج وتُحفظ config.model مع base_url/api_mode للـ profile. لا حاجة إلى إدخال _model_flow_* في النواة.

      hooks اختيارية للعمليات الخارجية​

      يمكن لـ profiles العمليات الخارجية تطبيق setup_status(**kwargs) التي تعيد {available, logged_in, plan, detail, login_command} و discover_models(**kwargs) التي تعيد [{id, label, note}]. يعتمد المسار العام على logged_in (ويشغّل login_command مباشرةً على TTY، أو يطبع detail خلاف ذلك)، وعندما تعيد discover_models() صفوفًا، يعرضها مدمجةً مع fallback_models; note تظهر كتوضيح باهت لكل صف (· usage credits) ولا تخفي نموذجًا مطلقًا. اجعل fetch_models() تعيد المعرّفات نفسها، كي يتفق /model ومنتقي Desktop مع الإعداد. يجب أن تكون كلتا hook منخفضتي التكلفة وألا تنفّذا inference مطلقًا؛ أعد None للرجوع إلى fallback_models.

      للطلبات غير HTTP القابلة للمقاطعة، طبّق دالة cancel(self) معلنة في الفئة. يستدعيها Hermes من thread المقاطعة بعد وسم عميل الطلب بأنه غير قابل للاستخدام. يجب أن تعود بسرعة وتوقف وسيلة نقلها بأمان، بما في ذلك الإلغاء المتزامن مع بدء العملية؛ ويجب ألا تغلق واصفات الملفات التي يملكها thread الطلب. يظل مالك الطلب يستدعي close() للتنظيف. تحتفظ العملاء التي لا تملك هذه الدالة بمسار الإلغاء الحالي عبر إغلاق socket.

      أعلن model_aliases ({"sonnet": "claude-sonnet-5[1m]"}) لكتالوج لا يعرفه models.dev: يُحدَّد الأمر المجرد /model <alias> و /model <id-prefix> داخل مزوّد العملية أولًا، وتقبل validate_requested_model معرّفًا معلنًا دون فحص process://.

      يحتفظ التفويض الصريح إلى عملية خارجية بالمزوّد المحدد وبروتوكوله عند تحديد أمر العملية الفرعية؛ ولا يحوّل تجاوز الملف التنفيذي وحده مزوّد عملية خارجية إلى ACP.

      يمكن للعملاء الأصليين حفظ بيانات خاصة لإعادة إرسال رسائل المساعد في reasoning_details بنوع ضمن نطاق أسماء هو <provider>.native_assistant. أعلن السلسلة المطابقة في ProviderProfile.native_reasoning_details_type (الافتراضي None). تعيد تنقية طلبات Chat Completions توجيه ذلك الحقل فقط إلى profile الذي أعلنه، حتى بعد اللجوء إلى مزوّد احتياطي أو تبديل النموذج؛ وتحذف الحقول الخاصة الأخرى حتى إذا لم تعد إضافة المصدر مثبتة. وتظل تفاصيل الاستدلال القياسية، مثل reasoning.encrypted في OpenRouter، دون تغيير. تقتصر التصفية على الطلبات: يبقى السجل الدائم سليمًا للعودة إلى المزوّد الأصلي.

      يمكن للمزوّدين إعادة تعريف get_model_context_length(model) بحد موجب ومتحقق منه للـ tokens، أو إعادة None لاستخدام سلسلة البحث الحالية. تحظى الإعدادات الصريحة والتجاوزات الخاصة بنطاق endpoint بالأولوية؛ ويُستشار حد المزوّد قبل التخزين المؤقت العام وفحوص HTTP. لا تخلط بين حد الكتالوج الأقصى واستحقاق الحساب.

      لواجهة تكلفة غير قياسية، يمكن لـ get_usage_cost(model, usage) إعادة agent.usage_pricing.CostResult، أو None للتسعير المعتاد. تكون usage كائنًا من نوع CanonicalUsage تحتفظ فيه raw_usage ببيانات الاستجابة الوصفية عند توفرها. صنّف مجاميع أسعار القائمة الأصلية بوصفها estimated، لا actual أو included مطلقًا؛ فغياب معلومات الفاتورة ليس دليلًا على عدم وجود رسوم. تعيد hooks الافتراضية None، مع الحفاظ على المزوّدين الحاليين.

      اختيار api_mode​

      مصادقة مملوكة للمزوّد (auth_handler, refresh_credential)​

      auth_type يصف نوع بيانات الاعتماد التي يحتاجها المزوّد؛ و auth_handler هو طريقة حصول الإضافة عليها — عبر مسار device-code / OIDC / IdC خاص بها ضمن مجموعة أوامر hermes auth الحالية (يتجاوز محمّل إضافات الأوامر العام manifests مزوّدي النماذج، لذا ليس register(ctx) طريقة إضافة الأوامر). و refresh_credential هو كيفية تدوير مجمع بيانات الاعتماد token مُجمعًا خزّنته الإضافة.

      import uuid
      from providers import register_provider
      from providers.base import ProviderProfile


      def example_auth(action: str, args) -> bool:
          """action: "add" | "status" | "logout" | "refresh"; args: parsed CLI namespace."""
          if action == "add":
              from agent.credential_pool import AUTH_TYPE_OAUTH, PooledCredential, load_pool
              tokens = run_device_code_flow()                      # provider-specific
              load_pool("example-oauth").add_entry(PooledCredential(
                  provider="example-oauth", id=uuid.uuid4().hex[:6], label=tokens["account"],
                  auth_type=AUTH_TYPE_OAUTH, priority=0, source="manual:example_device",
                  access_token=tokens["access_token"], refresh_token=tokens["refresh_token"],
                  extra={"tenant": tokens["tenant"]}))             # any extra keys round-trip through auth.json
              print("Signed in to Example.")
              return True
          if action == "status":
              print("example-oauth: " + ("logged in" if load_pool("example-oauth").entries() else "logged out"))
              return True
          return False   # decline → this action stays with the built-in credential-pool handling


      def example_refresh(entry):
          """Called by the credential pool with the pooled row; return the rotated values, None, or raise."""
          tokens = post_refresh(entry.refresh_token)          # the raw token-endpoint response is fine as-is
          return {"access_token": tokens["access_token"], "refresh_token": tokens["refresh_token"],
                  "expires_at_ms": tokens["expires_at_ms"], "expires_in": tokens["expires_in"]}


      register_provider(ProviderProfile(
          name="example-oauth", auth_type="oauth_external", base_url="https://api.example.com/v1",

      العقد
      auth_handler(action, args)args هو نطاق أسماء hermes auth المحلّل لإجراءات CLI ؛ ويمرر منتقي الإعداد التفاعلي نطاقًا محدودًا لا يحمل إلا provider، لذا اقرأ الخيارات باستخدام getattr(args, name, None). قيمة صادقة = تمت المعالجة (لا يطبع Hermes شيئًا آخر، والخروج 0)؛ قيمة غير صادقة = العودة إلى المسار المدمج لذلك الإجراء. ويتحول الاستثناء إلى SystemExit("<provider> auth handler failed for <action>: …").
      refresh_credential(entry)يتلقى PooledCredential؛ ويعيد تعيينًا للقيم المدوّرة أو None. والمفاتيح التي تكون حقول PooledCredential (access_token, refresh_token, expires_at_ms، …) تستبدل حقول الصف؛ ويذهب كل مفتاح آخر (expires_in, token_type, scope — البنية الخام لـ token-endpoint) إلى entry.extra ويُحفظ ويُستعاد عبر auth.json. وتعني إعادة None/تعيين فارغ أن الإضافة لم تستطع التدوير: يُستبعد الصف مؤقتًا تمامًا كطلب تحديث فاشل (ولا يُبلغ عنه كمحدّث، فلا يُعاد استخدام bearer متوقف). ووجوده هو ما يجعل المزوّد قابلًا للتحديث — hermes auth refresh <name> واسترداد 401 في الحلقة الرئيسية يستدعيانه عبر المجمع دون تدخل أي قائمة أسماء في النواة؛ ولا يصل إليه استرداد 401 في العميل المساعد إلا للصفوف المُجمعة التي يعاملها بالفعل كقابلة للاسترداد (صفوف api-key ومسارات OAuth المدمجة).
      إخفاقات التحديثارفع hermes_cli.auth_constants.AuthError(..., relogin_required=True) (أو مع code invalid_grant / invalid_token / refresh_token_reused) عند انتهاء المنح: يصبح الصف DEAD، ويخرج من التدوير، ويسجل Hermes تحذير WARNING يذكر hermes auth add <name>. وأي استثناء آخر (الشبكة، أو 429، أو 5xx) مؤقت — يُستبعد الصف لدورة تهدئة واحدة ثم تُعاد المحاولة.
      التزامنيعمل hook تحت قفل auth.json المشترك. وقبل استدعائه يعيد المجمع قراءة الصف؛ وإذا كانت عملية Hermes أخرى (gateway + CLI ، أو profile اثنان) قد دوّرت الزوج بالفعل، يُعتمد ذلك الزوج و لا يُستدعى hook الخاص بك — وهذا آمن لـ refresh tokens أحادية الاستخدام. وبعد عودة hook ، يُكتب الصف المدوّر إلى auth.json.
      دون hooksapi_key تتصرف تمامًا كما سابقًا. ويفشل أي auth_type آخر دون auth_handler بوضوح عند hermes auth add.

      hermes auth add|status|logout|refresh <provider> يستشير المعالج أولًا — قبل مسار مجمع بيانات الاعتماد المدمج. وعند تسجيل الاسم نفسه مرتين يتقدم آخر كاتب، لذا تستطيع إضافة مستخدم استبدال مسار مزوّد مضمّن.

      يمرر Hermes نطاق الأسماء المحلّل، لا الخيارات المُعلَنة من المزوّد: اطلب القيم الخاصة بالمزوّد تفاعليًا (أو اقرأ إعداداتك/بيئتك). والصفوف التي تخزنها الإضافة في المجمع ملكها — تبقى المفاتيح الإضافية عبر load → save → load، ولا يمرر Hermes أي أسرار خارج ذلك الصف المُجمع إلى refresh_credential.

          token_url="https://auth.example.com/oauth/token",
          scopes=("inference", "offline_access"),
          redirect_port=0,                                        # 0 = OS-assigned; pin it if the IdP allowlists the URI
      )

      register_provider(ProviderProfile(
          name="example-pkce", auth_type="oauth_external", base_url="https://api.example.com/v1",
          auth_handler=pkce_auth_handler(cfg), refresh_credential=pkce_refresh_credential(cfg)))

      حينها يملك Hermes دورة الحياة كلها: يفتح hermes auth add example-pkce [--no-browser] المتصفح (أو يطبع URL مع تلميح SSH-tunnel على جهاز بعيد)، ويستمع على http://127.0.0.1:<port>/callback، ويفحص CSRF state، ويبادل الرمز باستخدام S256 PKCE ويخزن المنح كبيانات اعتماد oauth مُجمّعة (source: manual:loopback_pkce, expires_at_ms, refresh_token); auth status يبلغ عن تسجيل الدخول / انتهاء الصلاحية؛ ويزيل auth logout الصفوف؛ ويدوّر auth refresh ومسارات استرداد 401 عبر منح refresh_token، مع إعادة قراءة auth.json تحت قفل المصادقة أولًا كي يُعتمد تدوير النظير بدل إنفاق refresh token أحادي الاستخدام مرتين.

      حد الأمان (مفروض قبل أي طلب، عند الدخول والتحديث على حد سواء): يجب أن يكون كلا endpoint بصيغة https:// (لا يُقبل http:// العادي إلا لمضيف بعنوان loopback حرفي — أي IdP تطوير محلي)؛ ويجب أن يكون مضيف token_url هو مضيف authorize_url أو نطاقًا فرعيًا له (أو مدرجًا في allowed_hosts)؛ ويرتبط المستمع بالعنوان الحرفي 127.0.0.1؛ ولا تُسجّل tokens أو state أو PKCE verifier مطلقًا. الحقول الاختيارية: audience, extra_authorize_params, extra_token_params, redirect_path, timeout_seconds, label.

      يضبط العميل السري الذي يوجد سره وراء وسيطك token_request بدل token_url: يستدعيه Hermes بحقوق المنح (grant_type, code / refresh_token, redirect_uri, code_verifier) ويخزن أي JSON لـ token-endpoint يعيده، مع الاحتفاظ بـ refresh_token القديم عندما تحذفه الاستجابة. ارفع AuthError(..., relogin_required=True) للمنح الذي يبلّغ الوسيط عن انتهاء صلاحيته. تُدوّر الصفوف قبل expires_at_ms المخزّن، فتُحدث access tokens غير الشفافة (غير JWT) في وقتها؛ ويستأجر العميل المساعد (الضغط، والعناوين) الصف المُجمع نفسه.

      الاسترداد وتصنيف الأخطاء​

      تُحمَّل إضافة kind: model-provider بواسطة اكتشاف المزوّدين، لا بواسطة مدير الإضافات العام، لذا لا يمكن الوصول منها إلى hook الإضافة transform_api_error_classification دون تقديم مكون إضافة ثانٍ. ويحمل الـ profile نقطة التكامل المكافئة بدلًا من ذلك:

      def classify(error, *, status_code, error_code, message, body, model):
          # A vendor-specific 403 that is a spent plan, not a bad credential.
          if status_code == 403 and error_code == "quota_exhausted":
              return {"reason": "billing", "retryable": False, "should_rotate_credential": True, "should_fallback": True}
          return None  # decline → built-in classification


      register_provider(ProviderProfile(name="example-oauth", auth_type="oauth_external",
                                        base_url="https://api.example.com/v1",
                                        refresh_credential=example_refresh, classify_api_error=classify))
      العقد
      classify_api_error(error, *, status_code, error_code, message, body, model)يستشيره agent.error_classifier.classify_api_error لإخفاقات هذا المزوّد وحده، بعد أي hooks عامة transform_api_error_classification وقبل pipeline المدمج. و message هو نص الخطأ بأحرف صغيرة، و body هو جسم JSON المحلّل (قد يكون فارغًا). أعد {"reason": <FailoverReason name>} بالإضافة إلى retryable / should_compress / should_rotate_credential / should_fallback / error_context الاختيارية للتجاوز (للأسباب النهائية — الفوترة، والمصادقة، و model_not_found … — يتضمن should_fallback: True القيمة retryable: False ما لم تضبطها، لأن سلسلة البدائل لا تعمل إلا للأحكام غير القابلة لإعادة المحاولة؛ وتحافظ أسباب حد المعدل على البنية المدمجة لإعادة المحاولة ثم البديل)؛ ويترك None (أو سبب غير معروف) الحكم المدمج كما هو. تُحتوى الاستثناءات وتُسجل عند DEBUG. ويوجه الحكم الاسترداد نفسه المستخدم للمزوّدين المدمجين — مثلًا يستبعد billing بيانات الاعتماد لمدة TTL الفوترة بدل تهدئة 403 المؤقتة.
      401 على بيانات اعتماد إضافةيعالجه مجمع بيانات الاعتماد دون تعديل النواة: يُحدّث الصف المُجمع الفاشل عبر refresh_credential مرة لكل محاولة (بحد أقصى تحديثين لكل صف في الجلسة)، ويُعاد بناء العميل بالـ token المدوّر وإعادة الطلب. وتستبعد عودة None/فارغة أو استثناء الصف — ثم يدوّر الطلب أو يعود إلى العبارة العامة "sign in again: hermes auth add <name>"، لا إلى إرشاد مزوّد مدمج مطلقًا.
      الاستدعاءات المساعدةتخدم إضافة oauth_external / oauth_device_code التي تقدم create_client المهام المساعدة على صفها المُجمع (يُدوّر الصف الذي يوشك على الانتهاء أولًا)؛ وتأخذ أخطاء 401 المساعدة تحديث المجمع نفسه (try_refresh_current → refresh_credential).

      الاسترداد الذي يظل مرتبطًا بالاسم في النواة سلوك لا يملك بنية عامة آمنة (مخزن token خاص بمزوّد لإعادة المزامنة، أو حاجز استحقاق لشريحة خطة، أو حجر refresh-token أحادي الاستخدام). وتملك الإضافة التي تحتاج أحد هذه السلوكيات تنفيذه داخل refresh_credential / classify_api_error.

      توقيت الاكتشاف​

      اكتشاف المزوّدين كسول — يُطلقه أول استدعاء لـ get_provider_profile() أو list_providers() في العملية. وعمليًا يحدث ذلك مبكرًا عند بدء التشغيل (إذ يوسّع تحميل الوحدة auth.py السجل PROVIDER_REGISTRY فورًا). وإذا احتجت إلى التحقق من تحميل إضافتك، فنفّذ:

      hermes doctor

      — يظهر الـ profile الناجح ذو auth_type="api_key" يظهر profile ضمن قسم Provider Connectivity مع /models الاختبار.

      للفحص البرمجي:

      from providers import list_providers
      for p in list_providers():
          print(p.name, p.base_url, p.api_mode)

      اختبار إضافتك​

      وجّه HERMES_HOME إلى مجلد مؤقت كي لا تلوّث إعداداتك الحقيقية:

      export HERMES_HOME=$HOME/.hermes/cache/scratch/hermes-plugin-test
      mkdir -p $HERMES_HOME/plugins/model-providers/my-provider
      cat > $HERMES_HOME/plugins/model-providers/my-provider/__init__.py <<'EOF'
      from providers import register_provider
      from providers.base import ProviderProfile
      register_provider(ProviderProfile(
          name="my-provider",
          env_vars=("MY_API_KEY",),
          base_url="https://api.my-provider.example.com/v1",
          auth_type="api_key",
      ))
      EOF

      export MY_API_KEY=your-test-key
      hermes -z "hello" --provider my-provider -m some-model

      التكامل مع PluginManager العام​

      المكوّن العام PluginManager (وهو ما يعمل عليه hermes plugins يعمل عليه) يرى إضافات مزوّدي النماذج لكنه لا يستوردها — إذ يتولى providers/__init__.py دورة حياتها. ويسجّل المدير البيان (manifest) لأغراض الاستبطان ويصنّفها حسب kind: model-provider. وعندما تضع إضافة مستخدم غير مصنّفة في $HERMES_HOME/plugins/ وتصادف أنها تستدعي register_provider مع ProviderProfile، يحوّلها المدير تلقائيًا إلى kind: model-provider بأسلوب استدلالي يعتمد على نص الشيفرة المصدرية — فتُوجَّه الإضافة توجيهًا صحيحًا حتى دون plugin.yaml.

      التوزيع عبر pip​

      يمكن توزيع مزوّدي النماذج كحزمة pip. أتِح نقطة دخول (entry point) ضمن المجموعة hermes_agent.plugins في ملف pyproject.toml:

      [project.entry-points."hermes_agent.plugins"]
      acme-inference = "acme_hermes_plugin:register"

      يمكن أن يكون الهدف أحد الخيارين:

      • هو كائنًا قابلًا للاستدعاء (module:func) — يُستدعى دون وسائط، وينبغي أن يستدعي register_provider(profile)، أو
      • هو وحدة مجردة (module) — تُستورد من أجل الأثر الجانبي لاستدعاء register_provider(...) على مستوى الوحدة، على غرار عقد __init__.py في الإضافات القائمة على المجلدات.

      providers/__init__.py نقاط الدخول هذه بنفسه — فالمكوّن العام PluginManager لا يستدعي أبدًا تسجيل المزوّدين لحزم pip (إذ يستهدف مسار نقاط الدخول لديه الإضافات العامة بنمط register(ctx)، ويخضع لـ plugins.enabled)، لذا يجري سجل المزوّدين فحصه الخاص. وتنطبق قاعدتان:

      • التفعيل الصريح (opt-in) مطلوب. تحكم هذا الفحص قائمة السماح نفسها plugins.enabled (وقائمة المنع plugins.disabled) الموجودتان في config.yaml. فلا تُستورد حزمة pip أبدًا لمجرد أنها مثبّتة — بل يجب على المستخدمين إضافة اسم نقطة الدخول إلى plugins.enabled:

        plugins:
          enabled:
            - acme-inference

      • أدنى أسبقية. تُكتشف الإضافات القائمة على نقاط الدخول قبل الإضافات الموجودة في نظام الملفات: ولأن register_provider() تعتمد قاعدة "آخر من يكتب هو الفائز"، فإن أي profile مضمّن أو موجود في $HERMES_HOME يحمل الاسم نفسه يتفوق دائمًا على الـ profile المثبّت عبر pip. ويمكن لحزمة pip أن تضيف مزوّدًا جديدًا فعلًا، لكنها لا تستطيع الاستيلاء بصمت على اسم مزوّد رسمي.

      أما الأهداف التي تتطلب وسائط (مثل register(ctx) في الإضافات العامة) فيتخطاها فحص المزوّدين — لأنها تتبع PluginManager. ونقطة الدخول المعطوبة تُعزل — إذ تُسجَّل بمستوى تحذير وتُتخطى، ولا تعطّل أبدًا اكتشاف المزوّدين الآخرين.

      راجع بناء إضافة لـ Hermes للاطلاع على الإعداد الكامل لنقاط الدخول.
