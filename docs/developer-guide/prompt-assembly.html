      تجميع الـ Prompt

      يفصل Hermes عمدًا بين:

      • حالة الـ system prompt المخزَّنة مؤقتًا
      • الإضافات العابرة وقت استدعاء API

      هذا واحد من أهم قرارات التصميم في المشروع لأنه يؤثّر في:

      • استهلاك الـ token
      • فعالية التخزين المؤقت للـ prompt
      • استمرارية الجلسة
      • صحة الذاكرة

      الملفات الأساسية:

      • run_agent.py
      • agent/prompt_builder.py
      • tools/memory_tool.py

      طبقات الـ system prompt المخزَّنة مؤقتًا​

      يُجمَّع الـ system prompt المخزَّن مؤقتًا كثلاث طبقات مرتّبة (انظر agent/system_prompt.py):

      1. الثابتة (stable) — الهوية (SOUL.md أو الاحتياطية)، وإرشادات الأدوات/النموذج، وموجز التشغيل البرمجي
      2. السياق (context) — system_message المُقدَّمة من المستدعي، وملفات سياق المشروع (.hermes.md / AGENTS.md / CLAUDE.md / .cursorrules)، ثم لقطة (snapshot) مساحة عمل git المرتبطة بـ worktree، وتعليمات المشغّل وتلميحات المنصّة
      3. المتغيّرة (volatile) — فهرس المهارات، ولقطة الذاكرة المدمجة (MEMORY.md)، ولقطة ملف تعريف المستخدم (USER.md)، وكتلة مزوّد الذاكرة الخارجي، وسطر الطابع الزمني/الجلسة/النموذج/المزوّد، ثم تلميحات بيئة التشغيل (المضيف / المجلد الرئيسي / دليل العمل الحالي)

      يُدمَج الـ system prompt النهائي بعد ذلك كالتالي: stable ← context ← volatile.

      هذا الترتيب مهمّ في نقاشات الأسبقية:

      • المهارات جزء من الطبقة الثابتة
      • لقطات الذاكرة/الملف الشخصي جزء من الطبقة المتغيّرة
      • كلتاهما لا تزالان ضمن الـ system prompt المخزَّن مؤقتًا (لا تُحقَنان كطبقات مؤقتة مُضافة في منتصف الدور)

      داخل طبقة السياق، تأتي ملفات المشروع المشتركة قبل أي شيء يسمّي الـ worktree الحالي. تشترك جلسات المشروع نفسه العاملة في worktrees مختلفة لـ git حينئذٍ في بادئة prompt تغطّي كتلة السياق بأكملها، بدلًا من التوقّف عند أول سطر مرتبط بدليل العمل الحالي — وتلك البادئة هي ما تُعيد ذاكرة مزوّد ذات أطول بادئة مشتركة (longest-prefix) استخدامه. الجلسة التي لا تملك لقطة مساحة عمل تُبقي إرشاداتها الختامية ضمن الطبقة الثابتة؛ وتنتهي كتلة بيئة التشغيل دائمًا الطبقة المتغيّرة.

      الأثر على الـ prompts المخزَّنة: تقرأ _stored_prompt_matches_runtime() (في agent/conversation_loop.py) الفقرة الأولى لمعلومات المضيف بعد حدّ # Hermes runtime environment المُصيَّر، مع علامة إغلاق عند النهاية المطلقة تميّز هذا التنسيق عن النصوص القديمة التي تقتبس العنوان. يأتي حدّ وقت التشغيل بعد كل نصوص المشروع والمشغّل والذاكرة والإضافات، بحيث لا تتنكّر الأمثلة في تلك الكتل بوصفها دليل العمل الحالي وقت التشغيل. تُقرأ معلومات النموذج/المزوّد قبل حدّ وقت التشغيل، باستثناء أوصاف embedder. سطر Platform: ليس عمدًا حقل هوية: فتبديل الواجهة (سطح مكتب ↔ TUI) يُبقي البايتات المخزَّنة ويسلّم إرشادات الواجهة الحالية كملاحظة لمرة واحدة على قناة رسالة المستخدم لكل دور (agent/surface_switch.py)، بحيث تبقى البادئة المخزَّنة مؤقتًا كما هي (#104414). تحتفظ الـ prompts القديمة بمرساها الأصلي (المضيف قبل السياق)، لذا تبقى الـ prompts المحفوظة قبل إعادة الترتيب صالحة.

      عند ضبط skip_context_files (مثل تفويض subagent)، لا يُحمَّل SOUL.md ويُستخدم بدلًا منه DEFAULT_AGENT_IDENTITY المُثبَّت في الكود.

      مثال ملموس: system prompt مُجمَّع​

      إليك عرضًا مبسّطًا لشكل الـ system prompt النهائي عند وجود كل الطبقات (تُظهر التعليقات مصدر كل قسم):

      # Layer 1: Agent Identity (from ~/.hermes/SOUL.md)
      You are Hermes, an AI assistant created by Nous Research.
      You are an expert software engineer and researcher.
      You value correctness, clarity, and efficiency.
      ...

      # Layer 2: Tool-aware behavior guidance
      Task-learned procedures, pitfalls, and task-specific preferences belong
      in skills. Memory is the narrow exception for facts that apply to EVERY
      session regardless of task. Skill-writing instructions appear here only
      when skill_manage is available; its absence does not widen memory's scope.
      ...
      When the user references something from a past conversation or you
      suspect relevant cross-session context exists, use session_search
      to recall it before asking them to repeat themselves.

      # Tool-use enforcement (for GPT/Codex models only)
      You MUST use your tools to take action — do not describe what you
      would do or plan to do without actually doing it.
      ...

      # Layer 3: Honcho static block (when active)
      [Honcho personality/context data]

      # Layer 4: Optional system message (from config or API)
      [User-configured system message override]

      # Layer 5: Frozen MEMORY snapshot
      ## Persistent Memory
      - User prefers Python 3.12, uses pyproject.toml
      - Default editor is nvim
      - Working on project "atlas" in ~/code/atlas
      - Timezone: US/Pacific

      # Layer 6: Frozen USER profile snapshot
      ## User Profile
      - Name: Alice
      - GitHub: alice-dev

      # Layer 7: Skills index
      ## Skills (mandatory)
      Before replying, scan the skills below. If one clearly matches
      your task, load it with skill_view(name) and follow its instructions.
      ...
      <available_skills>
        software-development:
          - code-review: Structured code review workflow
          - test-driven-development: TDD methodology
        research:
          - arxiv: Search and summarize arXiv papers
      </available_skills>

      # Layer 8: Context files (from project directory)
      # Project Context
      The following project context files have been loaded and should be followed:

      ## AGENTS.md
      This is the atlas project. Use pytest for testing. The main
      entry point is src/atlas/main.py. Always run `make lint` before
      committing.

      # Layer 9: Timestamp + session
      Current time: 2026-03-30T14:30:00-07:00
      Session: abc123

      # Layer 10: Platform hint
      You are a CLI AI Agent. Try not to use markdown but simple text
      renderable inside a terminal.

      تخصيص تلميحات المنصّة​

      تلميح المنصّة (الطبقة 10 أعلاه) هو الإرشاد الخاص بكل واجهة يحقنه Hermes لـ Telegram وWhatsApp وSlack وCLI ومنصات أخرى — على سبيل المثال "أنت على طرفية، تجنّب Markdown." تعيش القيم الافتراضية المدمجة في PLATFORM_HINTS (agent/system_prompt.py)؛ وتقدّم المنصات التي توفّرها الإضافات تلميحاتها الخاصة عبر سجل المنصّات.

      يمكن للمسؤول (administrator) إضافة نص إلى تلميح منصّة واحدة أو استبداله من config.yaml عبر المفتاح رفيع المستوى platform_hints، دون المساس بأي منصّة أخرى:

      platform_hints:
        whatsapp:
          append: >
            When tabular output would be useful, invoke the table_formatting
            skill instead of emitting a Markdown table.
        slack:
          replace: "You are on Slack. Keep responses tight and avoid wide tables."
        telegram: "Prefer short messages; split long answers."   # shorthand = append
      • append — يُبقي التلميح المدمج ويضيف النص الإضافي بعده.
      • replace — يستبدل التلميح المدمج بالكامل.
      • سلسلة نصية مجرَّدة — اختصار لـ append.
      • replace يتغلّب على append عند وجود كليهما.
      • يُتجاهل أي مُدخل غير سليم البنية بشكل احترازي ويعود إلى الافتراضي غير المُعدَّل، بحيث لا يمكن لقيمة إعداد خاطئة أن تُفسد تجميع الـ prompt أو تتسرّب عبر المنصات.

      يُحسَم التجاوز (override) عند بناء الـ system prompt (بدء الجلسة، ومرة أخرى عند الضغط لأن ذلك يعيد بناء الـ prompt). ينتج عنه تلميح ثابت البايتات لإعداد محدَّد، لذا يعيش في الطبقة الثابتة جنبًا إلى جنب مع التلميح المدمج ولا يُفسد التخزين المؤقت للـ prompt — إنه ليس تعديلًا حيًا في منتصف الجلسة على prompt مُجمَّد.

      كيف يظهر SOUL.md في الـ prompt​

      يعيش SOUL.md في ~/.hermes/SOUL.md ويُستخدم كهوية الوكيل — أول قسم في الـ system prompt. تعمل منطق التحميل في prompt_builder.py كالتالي:

      # From agent/prompt_builder.py (simplified)
      def load_soul_md() -> Optional[str]:
          soul_path = get_hermes_home() / "SOUL.md"
          if not soul_path.exists():
              return None
          content = soul_path.read_text(encoding="utf-8").strip()
          content = _scan_context_content(content, "SOUL.md")  # Security scan
          content = _truncate_content(content, "SOUL.md")       # Cap scales with model context window (20k floor); config override wins
          return content

      عندما تعيد load_soul_md() محتوى، تحلّ محلّ DEFAULT_AGENT_IDENTITY المُثبَّت في الكود. تُستدعى بعد ذلك الدالة build_context_files_prompt() بـ skip_soul=True لمنع ظهور SOUL.md مرتين (مرة كهوية، ومرة كملف سياق).

      إذا لم يكن SOUL.md موجودًا، يعود النظام إلى:

      You are Hermes Agent, built by Nous Research. Be direct: match the length
      of your reply to the weight of the ask — a one-line question gets a
      one-line answer, and finished work gets a short report of what changed,
      what's verified, and what's left, never a replay of the process. No
      filler ("Great question," "I'd be happy to"), no restating the request
      back, no re-summarizing what you already said, no narrating tool calls
      the user can see. Plain claims over adjectives; when unsure, say so
      plainly. Agree because it's right, not because the user said it. Depth
      is earned — give it when the user asks for detail, teaches, or the
      stakes demand it, not by default.

      كيف تُحقَن ملفات السياق​

      تستخدم build_context_files_prompt() نظام أولوية — يُحمَّل نوع سياق مشروع واحد فقط (أول تطابق يفوز):

      # From agent/prompt_builder.py (simplified)
      def build_context_files_prompt(cwd=None, skip_soul=False):
          cwd_path = Path(cwd).resolve()

          # Priority: first match wins — only ONE project context loaded
          project_context = (
              _load_hermes_md(cwd_path)       # 1. .hermes.md / HERMES.md (walks to git root)
              or _load_agents_md(cwd_path)    # 2. AGENTS.md (cwd only)
              or _load_claude_md(cwd_path)    # 3. CLAUDE.md (cwd only)
              or _load_cursorrules(cwd_path)  # 4. .cursorrules / .cursor/rules/*.mdc
          )

          sections = []
          if project_context:
              sections.append(project_context)

          # SOUL.md from HERMES_HOME (independent of project context)
          if not skip_soul:
              soul_content = load_soul_md()
              if soul_content:
                  sections.append(soul_content)

          if not sections:
              return ""

          return (
              "# Project Context\n\n"
              "The following project context files have been loaded "
              "and should be followed:\n\n"
              + "\n".join(sections)
          )

      تفاصيل اكتشاف ملفات السياق​

      الأولويةالملفاتنطاق البحثملاحظات
      1.hermes.md، HERMES.mdمن دليل العمل الحالي حتى جذر gitإعداد مشروع أصلي لـ Hermes
      2AGENTS.mdدليل العمل الحالي فقطملف تعليمات وكيل شائع
      3CLAUDE.mdدليل العمل الحالي فقطتوافق مع Claude Code
      4.cursorrules، .cursor/rules/*.mdcدليل العمل الحالي فقطتوافق مع Cursor

      جميع ملفات السياق:

      • مفحوصة أمنيًا — يُتحقّق منها بحثًا عن أنماط حقن التعليمات (unicode غير مرئي، "تجاهل التعليمات السابقة"، محاولات تسريب بيانات الاعتماد)
      • مقتطَعة — محدودة بعدد أحرف context_file_max_chars باستخدام تقسيم 70/20 بين البداية والنهاية مع علامة اقتطاع. يتناسب هذا الحد مع نافذة سياق النموذج (حد أدنى 20,000 حرف، وحد أقصى 500K)؛ وتغلب قيمة context_file_max_chars الصريحة في config.yaml دائمًا.
      • مُزال منها ترويسة YAML — تُزال ترويسة .hermes.md (محجوزة لتجاوزات إعداد مستقبلية)

      طبقات خاصة بوقت استدعاء API فقط​

      هذه لا تُحفظ عمدًا كجزء من الـ system prompt المخزَّن مؤقتًا:

      • ephemeral_system_prompt
      • رسائل التمهيد المسبق (prefill)
      • طبقات سياق الجلسة المشتقّة من gateway
      • استرجاع Honcho/الخارجي في دور لاحق، مُحقَنًا في رسالة المستخدم للدور الحالي

      يقع سياق إضافة pre_llm_call أيضًا في هذا المسار الخاص بوقت استدعاء API: فيُلحَق برسالة المستخدم الخاصة بالدور الحالي، لا يُكتَب في الـ system prompt المخزَّن مؤقتًا. عندما تُعيد عدة إضافات سياقًا، يُلحق Hermes تلك الكتل السياقية ببعضها (انظر Hooks ← pre_llm_call).

      يحافظ هذا الفصل على استقرار البادئة الثابتة لأغراض التخزين المؤقت.

      لقطات الذاكرة​

      تُلتقط بيانات الذاكرة المحلية وملف تعريف المستخدم في الطبقة المتغيّرة من الـ system prompt. الكتابات في منتصف الجلسة تحدّث حالة القرص لكنها لا تُعدِّل الـ system prompt المخزَّن مؤقتًا والمُجمَّع مسبقًا إلى أن يعمل مسار إعادة بناء (جلسة جديدة، أو مسار إبطال/إعادة بناء صريح مثل إعادة البناء الناتج عن الضغط).

      ملفات السياق​

      يفحص agent/prompt_builder.py ملفات سياق المشروع وينظّفها باستخدام نظام أولوية — يُحمَّل نوع واحد فقط (أول تطابق يفوز):

      1. .hermes.md / HERMES.md (يتنقّل حتى جذر git)
      2. AGENTS.md (دليل العمل الحالي عند بدء التشغيل؛ تُكتشَف الدلائل الفرعية تدريجيًا أثناء الجلسة عبر agent/subdirectory_hints.py)
      3. CLAUDE.md (دليل العمل الحالي فقط)
      4. .cursorrules / .cursor/rules/*.mdc (دليل العمل الحالي فقط)

      يُحمَّل SOUL.md بشكل منفصل عبر load_soul_md() لمكان الهوية. عندما يُحمَّل بنجاح، تمنع build_context_files_prompt(skip_soul=True) ظهوره مرتين.

      تُقتطَع الملفات الطويلة قبل الحقن.

      فهرس المهارات​

      يساهم نظام المهارات بفهرس مهارات مُكثَّف في الـ prompt عندما تكون أدوات المهارات متاحة.

      أسطح التخصيص المدعومة للـ prompt​

      يجب على معظم المستخدمين التعامل مع agent/prompt_builder.py كأنه كود تنفيذي، لا سطح إعدادات. المسار المدعوم للتخصيص هو تغيير مُدخلات الـ prompt التي يحمّلها Hermes بالفعل، بدلًا من تعديل قوالب Python مباشرةً.

      استخدم هذه الأسطح أولًا​

      • ~/.hermes/SOUL.md — استبدل كتلة الهوية الافتراضية المدمجة بشخصية وكيلك الخاصة وسلوكه الدائم.
      • ~/.hermes/MEMORY.md و~/.hermes/USER.md — قدّم حقائق دائمة عبر الجلسات وبيانات ملف تعريف المستخدم التي ينبغي التقاطها كلقطة في الجلسات الجديدة.
      • ملفات سياق المشروع مثل .hermes.md وHERMES.md وAGENTS.md وCLAUDE.md أو .cursorrules — لحقن قواعد عمل خاصة بالمستودع.
      • المهارات — لتغليف سير عمل ومراجع قابلة لإعادة الاستخدام دون تعديل كود الـ prompt الأساسي.
      • إعدادات الـ system prompt الاختيارية / تجاوزات API — لإضافة نص تعليمات خاص بالنشر دون عمل fork لـ Hermes.
      • طبقات عابرة مثل HERMES_EPHEMERAL_SYSTEM_PROMPT أو رسائل التمهيد المسبق — لإضافة إرشادات محصورة بدور واحد لا ينبغي أن تصبح جزءًا من بادئة الـ prompt المخزَّنة مؤقتًا.

      متى تُعدِّل الكود بدلًا من ذلك​

      عدّل agent/prompt_builder.py فقط إذا كنت تحافظ عمدًا على fork أو تساهم بتغييرات سلوك في المشروع الأصلي (upstream). يجمّع ذلك الملف أسلاك الـ prompt وحدود التخزين المؤقت وترتيب الحقن لكل جلسة. التعديلات المباشرة هناك تغييرات منتج عامة، لا تخصيص prompt خاص بمستخدم واحد.

      بعبارة أخرى:

      • إذا أردت هوية مساعد مختلفة، عدّل SOUL.md
      • إذا أردت قواعد مستودع مختلفة، عدّل ملفات سياق المشروع
      • إذا أردت إجراءات تشغيل قابلة لإعادة الاستخدام، أضف مهارات أو عدّلها
      • إذا أردت تغيير كيفية تجميع Hermes للـ prompts للجميع، غيّر كود Python واعتبر ذلك مساهمة كودية

      لماذا يُقسَّم تجميع الـ prompt على هذا النحو​

      البنية المعمارية مُحسَّنة عمدًا من أجل:

      • الحفاظ على التخزين المؤقت للـ prompt من جهة المزوّد
      • تجنّب تعديل السجل دون داعٍ
      • إبقاء دلالات الذاكرة مفهومة
      • السماح لـ gateway/ACP/CLI بإضافة سياق دون تلويث حالة الـ prompt الدائمة
