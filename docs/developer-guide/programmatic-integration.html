      التكامل البرمجي

      يشحن Hermes ثلاثة بروتوكولات لتشغيل الوكيل من برامج خارجية — إضافات IDE، وواجهات مستخدم مخصّصة، وخطوط أنابيب CI، ووكلاء فرعيين مُضمَّنين. اختر ما يناسب النقل والمستهلك لديك.

      البروتوكولالنقلالأفضل لـمُعرَّف في
      ACPJSON-RPC عبر stdioعملاء IDE (VS Code وZed وJetBrains) الذين يتحدّثون بالفعل Agent Client Protocolacp_adapter/
      TUI gatewayJSON-RPC عبر stdio (أو WebSocket)المضيفون المخصّصون الذين يريدون تحكّمًا دقيقًا في الجلسات وslash commands والموافقات وأحداث البثtui_gateway/server.py
      خادم APIHTTP + Server-Sent Eventsواجهات متوافقة مع OpenAI (Open WebUI وLobeChat وLibreChat…) وعملاء ويب مستقلّون عن اللغةgateway/platforms/api_server.py

      تشغّل البروتوكولات الثلاثة نفس نواة AIAgent. تختلف فقط في صيغة السلك (wire format) ومجموعة الميزات التي تكشفها.

      ACP (Agent Client Protocol)​

      يشغّل hermes acp خادم JSON-RPC عبر stdio يتحدّث ACP. يُستخدم في الإنتاج بواسطة VS Code (إضافة ACP الخاصة بـ Zed Industries)، وZed، وأي IDE من JetBrains يملك إضافة ACP.

      القدرات المكشوفة: إنشاء الجلسات، وتقديم الـ prompt، وبث أجزاء رسائل الوكيل، وأحداث استدعاء الأدوات، وطلبات الصلاحيات، وتفريع الجلسة (fork)، والإلغاء، والمصادقة. تُعرَض مخرجات الأدوات في كتل محتوى Diff/ToolCall الخاصة بـ ACP التي يفهمها IDE.

      دورة الحياة الكاملة، وجسر الأحداث، وتدفّق الموافقة: آلية عمل ACP من الداخل.

      hermes acp                  # serve ACP on stdio
      hermes acp --check          # verify ACP dependencies and adapter imports
      hermes acp --setup          # interactive provider/model setup for ACP terminal auth

      TUI Gateway JSON-RPC​

      tui_gateway/server.py هو البروتوكول الذي يتحدّث به TUI المبني بـ Ink (hermes --tui) وجسر PTY الخاص بلوحة التحكم المُضمَّنة. يمكن لأي مضيف خارجي التحدّث بنفس البروتوكول عبر stdio (أو WebSocket عبر tui_gateway/ws.py).

      كتالوج الدوال (مُنتقى)​

      prompt.submit           prompt.background       session.steer
      session.create          session.list            session.active_list
      session.activate        session.close           session.interrupt
      session.history         session.compress        session.branch
      session.title           session.usage           session.status
      clarify.respond         sudo.respond            secret.respond
      approval.respond        config.set / config.get commands.catalog
      command.resolve         command.dispatch        cli.exec
      reload.mcp              reload.env              process.stop
      delegation.status       subagent.interrupt      subagent.steer
      spawn_tree.save / list / load
      terminal.resize         clipboard.paste         image.attach

      session.active_list وsession.activate وsession.close هي عناصر تحكّم الجلسات الحيّة المحلية للعملية التي يستخدمها مبدّل الجلسات في TUI. استخدم session.list / /resume لاكتشاف المحادثات المحفوظة؛ واستخدم دوال الجلسة النشطة فقط للجلسات المفتوحة حاليًا في عملية TUI gateway.

      ضمن gateway مصادَق واحد، فإن استئناف جلسة حيّة أو تفعيلها يُلحق مشتركًا آخر في الأحداث بدلًا من استبدال الاتصال السابق. تصل أحداث البث والطرفية إلى كل العملاء المتّصلين؛ وقطع اتصال عميل واحد لا ينهي جلسة يشاهدها عميل آخر. تبقى حصرية التقديم الحالية وسياسة الإدخال أثناء الانشغال المضبوطة سارية. يمكن للعملاء المتّصلين توجيه subagents الجلسة؛ ولا تزال نتائج متحكّم المتصفح تتطلّب الاتصال الذي سجّل ذلك المتحكّم. هذا لا يتيح لعمليات gateway مستقلّة الكتابة إلى نفس الجلسة، ولا يعني قبول prompt دائمًا عبر إعادة تشغيل المالك.

      إرجاع السجل عند prompt.submit​

      الإرجاع (rewind) / التعديل / إعادة التوليد هو prompt.submit يُسقط جزءًا من المحادثة المخزَّنة قبل تشغيل الدور الجديد. ولأن تلك الكتابة إعادة كتابة إتلافية لصفوف الجلسة الدائمة، لا يحترمها gateway إلا عندما يُعلن العميل نيّته صراحةً:

      الوسيطالمعنى
      truncate_before_user_ordinalفهرس صفري الأساس لدور المستخدم الذي سيُقطَع عنده. يُسقَط كل شيء من ذلك الدور فصاعدًا. لا تُحسَب صفوف الجدول الزمني المخصّصة للعرض فقط (display_kind). يجب أن تكون قيمة صحيحة (integer) فعلية — تُرفض القيمة المنطقية (boolean) في JSON برمز 4004.
      truncate_before_row_idمعرّف صف SQLite صحيح (messages.id / row_id) لدور المستخدم المستهدَف الذي سيُقطَع عنده. العنوان الدائم المفضَّل. عند تقديم كل من الفهرس ومعرّف الصف معًا، يتحقّق gateway من تطابقهما (ويعيد 4030 عند عدم التطابق). يُرفض معرّف صف غير معروف/قديم برمز 4018 — ولا يعود إلى الفهرس كبديل.
      confirm_truncateمطلوب كلما أُرسل فهرس أو معرّف رسالة أو معرّف صف. يُعلن أن هذا التقديم إرجاع فعلي، لا إرسال عادي يحمل بالمصادفة وسائط متبقّية. يُرفض إرساله دون هدف برمز 4004.
      confirm_empty_truncateمطلوب إضافةً عندما يترك القطع المحادثة فارغة (الفهرس 0).

      يُرفض وسيط اقتطاع بلا confirm_truncate برمز 4004 أو 4029 ولا يُكتب أي شيء. يجب على المضيفين الذين ينفّذون الإرجاع ضبط العلامة في اللحظة التي يطلبها فيها المستخدم، ويجب ألا يُبقوا وسائط الاقتطاع في الحالة عبر عمليات إرسال عادية. فضّل truncate_before_row_id (من row_id / _row_id عند الاستئناف) على الفهارس؛ وأبقِ الفهرس كمسار توافق قديم / صف تفاؤلي فقط عندما لا يتوفّر معرّف دائم بعد.

      عند نجاح تقديم اقتطاع مقابل جلسة دائمة، تحمل نتيجة prompt.submit إضافةً survivor_user_row_ids — معرّفات الصفوف الجديدة بعد إعادة الكتابة لأدوار المستخدم الناجية، بترتيب الفهرس المرئي للمستخدم. تعيد إعادة الكتابة إدراج البادئة المُبقاة كصفوف جديدة، لذا يصبح كل معرّف صف خزّنه المضيف قبل الإرجاع قديمًا بعد ذلك؛ أعد ربط المعرّفات المخزَّنة من هذه القائمة (المُدخل null يعني أن ذلك الدور ليس له معرّف دائم — أسقط المخزَّن منه) وإلا سيُرفض الإرجاع التالي الذي يستهدف دورًا ناجيًا أقدم برمز 4018.

      الأحداث المُعادة بثًا​

      message.delta، message.complete، tool.start، tool.progress، tool.complete، approval.request، clarify.request، sudo.request، sudo.expire، secret.request، secret.expire، gateway.ready، بالإضافة إلى أحداث دورة حياة الجلسة والأخطاء. تحمل أحداث انتهاء الصلاحية قيمة { request_id } الأصلية؛ وينبغي أن يمسح المضيفون الخارجيون prompt المعلَّق المطابق فقط.

      خادم API متوافق مع OpenAI​

      يكشف gateway/platforms/api_server.py عن hermes عبر HTTP لأي عميل يتحدّث بالفعل بصيغة OpenAI. مفيد عندما تريد واجهة ويب أمامية، أو مُشغِّل CI يعمل عبر curl، أو مستهلكًا غير مبني بـ Python.

      الـ endpoints:

      POST /v1/chat/completions        OpenAI Chat Completions (streaming via SSE)
      POST /v1/responses               OpenAI Responses API (stateful)
      POST /v1/runs                    Start a run, returns run_id (202)
      GET  /v1/runs/{id}               Run status
      GET  /v1/runs/{id}/events        SSE stream of lifecycle events
      POST /v1/runs/{id}/approval      Resolve a pending approval
      POST /v1/runs/{id}/steer         Inject mid-run guidance at the next tool boundary
      POST /v1/runs/{id}/stop          Interrupt the run
      GET  /v1/capabilities            Machine-readable feature flags
      POST /v1/browser-control/register Register a browser controller
      GET  /v1/browser-control/ws       Browser-controller WebSocket
      GET  /v1/models                  Lists hermes-agent
      GET  /api/model/options          Provider-aware picker inventory
      GET  /health, /health/detailed

      الإعداد، والترويسات (X-Hermes-Session-Id، X-Hermes-Session-Key)، وربط الواجهة الأمامية: خادم API.

      يمكن لإضافات المتصفح الاشتراك في بروتوكول المتحكّم المعطَّل افتراضيًا لأجل تشغيل جلسة المتصفح ذاتها التي فتحت محادثة Hermes. تشترك ناقلات API ولوحة التحكم في وسيط (broker) واحد مرتبط بمُخوَّل (principal) وقائمة سماح قدرات صريحة واحدة؛ انظر التحكّم عبر إضافة المتصفح.

      أسطح كتالوج النماذج​

      يُبقي API المتوافق مع OpenAI عمدًا GET /v1/models بسيطًا: إنه endpoint التوافق الذي تتوقّعه الواجهات الأمامية، لا كتالوج مزوّد/نموذج Hermes المنسَّق الكامل.

      إذا احتاجت خطة تحكّم خارجية إلى صفوف مزوّدي Hermes المنسَّقة، أو تسعير كل نموذج، أو تلميحات القدرات، فاستخدم أحد أسطح أداة الاختيار المصادَق عليها:

      • REST خادم API: GET /api/model/options بمفتاح حامل خادم API
      • REST خلفية لوحة التحكم: GET /api/model/options بـ X-Hermes-Session-Token
      • RPC الخاص بـ TUI gateway: model.options

      تشترك تلك الأسطح في نفس بانٍ الحمولة (payload builder) ونفس سياسة فحص المزوّد المخصّص:

      • الفتح العادي: يفحص المزوّد المخصّص الحالي فقط بحيث لا تُعطِّل endpoints محفوظة غير متصلة أداة الاختيار.
      • التحديث الصريح (refresh=1 أو refresh: true): يُبطل ذاكرة مزوّد النموذج المؤقتة ويفحص كل المزوّدين المخصّصين المحفوظين بحيث تُعاد تعبئة الكتالوجات الحيّة بالكامل.

      استخدم /v1/models للتوافق مع عملاء OpenAI. استخدم /api/model/options أو model.options عندما تبني أداة اختيار نموذج مدركة لـ Hermes.

      POST /v1/runs/{id}/steer هو المكافئ عبر HTTP لأمر /steer في Hermes: فهو لا ينشئ دور مستخدم جديدًا ولا يعيد كتابة مخرجات المساعد الجارية فورًا. بل يُلحَق النص بالتشغيل الحيّ ويصبح مرئيًا للوكيل بعد حدّ الأداة التالي، بحيث يمكنه تصحيح مساره دون إسقاط حلقة استدعاء الأدوات الحالية.

      لا يُقبَل /v1/runs/{id}/steer إلا بينما حالة التشغيل running. تُعيد عمليات التشغيل المُصفوفة أو المعلّقة للموافقة أو المتوقّفة أو المُلغاة أو الفاشلة والمكتملة الرمز 409 run_not_accepting_steer، حتى إذا كان الخادم لا يزال يحتفظ بمراجع داخلية للوكيل أثناء الإيقاف التعاوني.

      رمز 200 (وحدث run.steered) يعني أن النص وُضع في قائمة انتظار، لا أن الوكيل استهلكه. إذا وصل توجيه (steer) بعد الاستجابة النهائية للوكيل — دون حدّ أداة لاحق لتسليمه عنده — يُعاد النص غير المُسلَّم كـ pending_steer في حدث run.completed النهائي وحالة التشغيل، بحيث يمكن للعميل إعادة تشغيله كدور مستخدم تالٍ بدلًا من فقدانه.

      أيّها ينبغي أن أستخدم؟​

      • تكتب إضافة IDE ويتحدّث IDE بالفعل ACP ← ACP. لا عمل بروتوكول على جانب IDE.
      • تكتب مضيف سطح مكتب / ويب / TUI مخصّصًا وتريد كل ميزة في Hermes (slash commands، الموافقات، clarify، متعدد الوكلاء، تفريع الجلسات) ← TUI gateway JSON-RPC.
      • تريد أي واجهة متوافقة مع OpenAI، أو عميل HTTP مستقلًا عن اللغة، أو أتمتة تعمل عبر curl ← خادم API.
      • تريد تضمينًا داخل عملية Python بدون عملية فرعية ← استورد run_agent.AIAgent مباشرةً. انظر Agent Loop.

      التبديل الفوري للنموذج​

      يعمل تبديل النموذج في منتصف الجلسة على كل سطح — فهو في جوهره أمر /model.

      • CLI / TUI: /model claude-sonnet-4 أو /model openrouter:anthropic/claude-sonnet-4.6
      • RPC الخاص بـ TUI gateway: command.dispatch بـ {"command": "/model claude-sonnet-4"}
      • ACP: يرسل IDE الـ slash command كـ prompt؛ ويوزّعه الوكيل
      • خادم API: أدرج حقل model في جسم الطلب

      الحسم المُدرك للمزوّد (نفس اسم النموذج يختار الصيغة الصحيحة لأي مزوّد أنت عليه) مُضمَّن مسبقًا. انظر hermes_cli/model_switch.py.

      ملاحظة حول --mode rpc​

      لا يملك Hermes علامة --mode rpc. تغطّي البروتوكولات الثلاثة أعلاه بالفعل حالات الاستخدام — ACP لعملاء بروتوكول IDE، وTUI gateway للمضيفين الذين يستخدمون JSON-RPC عبر stdio، وخادم API لـ HTTP. إذا وجدت فجوة حقيقية لا يسدّها أيّ منها، افتح مشكلة (issue) مع المستهلك الملموس الذي تبنيه.
