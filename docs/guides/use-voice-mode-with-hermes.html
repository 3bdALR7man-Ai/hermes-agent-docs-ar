      استخدام Voice Mode مع Hermes

      هذا الدليل هو الرفيق العملي لـ مرجع ميزة Voice Mode.

      إذا كانت صفحة الميزة تشرح ما يستطيع الوضع الصوتي فعله، فإن هذا الدليل يوضّح كيف تستخدمه استخدامًا جيدًا على أرض الواقع.

      نصيحة

      يجمع Nous Portal كلًّا من LLM و TTS عبر OAuth واحد، لذا يعمل الوضع الصوتي من البداية إلى النهاية دون أي بيانات اعتماد إضافية.

      فيمَ يفيد الوضع الصوتي​

      يكون الوضع الصوتي مفيدًا بشكل خاص عندما:

      • تريد سير عمل في CLI دون استخدام يديك
      • تريد ردودًا منطوقة في Telegram أو Discord
      • تريد أن يوجد Hermes في قناة صوتية على Discord لإجراء محادثة مباشرة
      • تريد تدوين الأفكار بسرعة، أو تصحيح الأخطاء، أو التحاور ذهابًا وإيابًا وأنت تتجوّل بدلًا من الكتابة

      اختر إعداد الوضع الصوتي المناسب لك​

      توجد في Hermes فعليًا ثلاث تجارب صوتية مختلفة.

      الوضعالأنسب لـالمنصة
      حلقة الميكروفون التفاعليةالاستخدام الشخصي دون يدين أثناء البرمجة أو البحثCLI
      الردود الصوتية في المحادثةردود منطوقة إلى جانب المراسلة المعتادةTelegram, Discord
      بوت القناة الصوتية المباشرةمحادثة مباشرة جماعية أو شخصية في قناة صوتية (VC)القنوات الصوتية في Discord

      المسار الجيد هو:

      1. اجعل المحادثة النصية تعمل أولًا
      2. فعّل الردود الصوتية ثانيًا
      3. انتقل إلى القنوات الصوتية في Discord أخيرًا إذا أردت التجربة الكاملة

      الخطوة 1: تأكّد أولًا من أن Hermes يعمل بشكل طبيعي​

      قبل الاقتراب من الوضع الصوتي، تحقّق مما يلي:

      • أن Hermes يبدأ التشغيل
      • أن المزوّد (provider) لديك مُعدّ
      • أن الوكيل يستطيع الإجابة عن الـ prompts النصية بشكل طبيعي
      hermes

      اطرح سؤالًا بسيطًا:

      What tools do you have available?

      إذا لم يكن ذلك مستقرًا بعد، فأصلح الوضع النصي أولًا.

      الخطوة 2: ثبّت الإضافات (extras) المناسبة​

      الميكروفون والتشغيل الصوتي في CLI​

      cd ~/.hermes/hermes-agent && uv pip install -e ".[voice]"

      منصات المراسلة​

      cd ~/.hermes/hermes-agent && uv pip install -e ".[messaging]"

      ElevenLabs TTS المدفوع​

      cd ~/.hermes/hermes-agent && uv pip install -e ".[tts-premium]"

      NeuTTS المحلي (اختياري)​

      python -m pip install -U neutts[all]

      كل شيء​

      cd ~/.hermes/hermes-agent && uv pip install -e ".[all]"

      الخطوة 3: ثبّت اعتماديات النظام​

      macOS​

      brew install portaudio ffmpeg opus
      brew install espeak-ng

      Ubuntu / Debian​

      sudo apt install portaudio19-dev ffmpeg libopus0
      sudo apt install espeak-ng

      لماذا تهمّ هذه الحزم:

      • portaudio → إدخال الميكروفون / التشغيل الصوتي للوضع الصوتي في CLI
      • ffmpeg → تحويل الصوت لـ TTS وللتسليم عبر منصات المراسلة
      • opus → دعم ترميز الصوت (codec) في Discord
      • espeak-ng → الـ backend الخاص بتحويل النص إلى وحدات صوتية (phonemizer) لـ NeuTTS

      الخطوة 4: اختر مزوّدي STT و TTS​

      يدعم Hermes حزم الكلام المحلية والسحابية على حد سواء.

      الإعداد الأسهل / الأقل تكلفة​

      استخدم STT محليًا و Edge TTS المجاني:

      • مزوّد STT: local
      • مزوّد TTS: edge

      هذه عادةً أفضل نقطة للبدء.

      مثال على ملف البيئة​

      أضف إلى ~/.hermes/.env:

      # Cloud STT options (local needs no key)
      GROQ_API_KEY=***
      VOICE_TOOLS_OPENAI_KEY=***

      # Premium TTS (optional)
      ELEVENLABS_API_KEY=***

      توصيات المزوّدين​

      تحويل الكلام إلى نص (Speech-to-text)​

      • local → أفضل خيار افتراضي للخصوصية والاستخدام دون تكلفة
      • groq → تفريغ صوتي سحابي سريع جدًا
      • openai → خيار احتياطي مدفوع جيد

      تحويل النص إلى كلام (Text-to-speech)​

      • edge → مجاني وجيد بما يكفي لمعظم المستخدمين
      • neutts → TTS مجاني يعمل محليًا على الجهاز
      • elevenlabs → أفضل جودة
      • openai → حل وسط جيد
      • mistral → متعدد اللغات، مع دعم أصلي لـ Opus

      إذا كنت تستخدم hermes setup​

      إذا اخترت NeuTTS في معالج الإعداد، يتحقّق Hermes مما إذا كانت neutts مثبّتة بالفعل. وإن لم تكن موجودة، يخبرك المعالج بأن NeuTTS يحتاج إلى حزمة Python المسماة neutts وحزمة النظام espeak-ng، ويعرض تثبيتهما لك، فيثبّت espeak-ng باستخدام مدير الحزم الخاص بمنصتك، ثم ينفّذ:

      python -m pip install -U neutts[all]

      إذا تخطّيت هذا التثبيت أو فشل، يرجع المعالج إلى Edge TTS.

      الخطوة 5: الإعدادات الموصى بها​

      voice:
        record_key: "ctrl+b"
        submit_mode: "direct"  # TUI: direct | draft
        max_recording_seconds: 120
        auto_tts: false
        beep_enabled: true
        silence_threshold: 200
        silence_duration: 3.0

      stt:
        provider: "local"
        local:
          model: "base"

      tts:
        provider: "edge"
        edge:
          voice: "en-US-AriaNeural"

      هذا إعداد افتراضي متحفّظ وجيد لمعظم الناس.

      في TUI، يتحكّم voice.submit_mode فيما يحدث بعد التفريغ الصوتي:

      • direct (الافتراضي) يرسل النص المفرّغ فورًا.
      • draft يضع النص المفرّغ في مربع الكتابة لتتمكّن من تعديله أو إلغائه قبل الضغط على Enter.

      للحصول على مسودات صوتية قابلة للتعديل، اضبط:

      voice:
        submit_mode: "draft"

      إذا أردت استخدام TTS محلي بدلًا من ذلك، فغيّر كتلة tts إلى:

      tts:
        provider: "neutts"
        neutts:
          ref_audio: ''
          ref_text: ''
          model: neuphonic/neutts-air-q4-gguf
          device: cpu

      حالة الاستخدام 1: الوضع الصوتي في CLI​

      تفعيله​

      شغّل Hermes:

      hermes

      داخل CLI:

      /voice on

      مسار التسجيل​

      المفتاح الافتراضي:

      • Ctrl+B

      سير العمل:

      1. اضغط Ctrl+B
      2. تحدّث
      3. انتظر حتى يوقف اكتشاف الصمت التسجيل تلقائيًا
      4. يفرّغ Hermes كلامك ويردّ عليه
      5. إذا كان TTS مفعّلًا، ينطق الإجابة
      6. يمكن أن تُعاد الحلقة تلقائيًا للاستخدام المتواصل

      أوامر مفيدة​

      /voice
      /voice on
      /voice off
      /voice tts
      /voice status

      أمثلة جيدة على سير العمل في CLI​

      تصحيح الأخطاء على الماشي​

      قل:

      I keep getting a docker permission error. Help me debug it.

      ثم تابع دون استخدام يديك:

      • "Read the last error again" (اقرأ آخر خطأ مرة أخرى)
      • "Explain the root cause in simpler terms" (اشرح السبب الجذري بعبارات أبسط)
      • "Now give me the exact fix" (والآن أعطني الحل الدقيق)

      البحث / العصف الذهني​

      مناسب جدًا لـ:

      • التجوّل أثناء التفكير
      • إملاء أفكار لم تكتمل بعد
      • مطالبة Hermes بتنظيم أفكارك في الوقت الفعلي

      إمكانية الوصول / الجلسات قليلة الكتابة​

      إذا كانت الكتابة غير مريحة، فإن الوضع الصوتي من أسرع الطرق للبقاء داخل حلقة Hermes الكاملة.

      ضبط سلوك CLI​

      عتبة الصمت​

      إذا كان Hermes يبدأ التسجيل أو يوقفه بحساسية مفرطة، فاضبط:

      voice:
        silence_threshold: 250

      كلما ارتفعت العتبة = قلّت الحساسية.

      مدة الصمت​

      إذا كنت تتوقف كثيرًا بين الجمل، فزِد قيمة:

      voice:
        silence_duration: 4.0

      مفتاح التسجيل​

      إذا كان Ctrl+B يتعارض مع الطرفية لديك أو مع عاداتك في tmux:

      voice:
        record_key: "ctrl+space"

      حالة الاستخدام 2: الردود الصوتية في Telegram أو Discord​

      هذا الوضع أبسط من القنوات الصوتية الكاملة.

      يبقى Hermes بوت محادثة عاديًا، لكنه يستطيع نطق الردود.

      شغّل الـ gateway​

      hermes gateway

      فعّل الردود الصوتية​

      داخل Telegram أو Discord:

      /voice on

      أو

      /voice tts

      الأوضاع​

      الوضعالمعنى
      offنص فقط
      voice_onlyالنطق فقط عندما يرسل المستخدم رسالة صوتية
      allنطق كل رد

      متى تستخدم كل وضع​

      • /voice on إذا أردت ردودًا منطوقة فقط على الرسائل التي أصلها صوتي
      • /voice tts إذا أردت مساعدًا ناطقًا بالكامل طوال الوقت

      أمثلة جيدة على سير العمل في المراسلة​

      مساعد Telegram على هاتفك​

      استخدمه عندما:

      • تكون بعيدًا عن جهازك
      • تريد إرسال ملاحظات صوتية وتلقّي ردود منطوقة سريعة
      • تريد أن يعمل Hermes كمساعد متنقّل للبحث أو للعمليات (ops)

      الرسائل المباشرة (DM) في Discord مع مخرجات منطوقة​

      مفيد عندما تريد تفاعلًا خاصًا دون سلوك الإشارة (mention) المطلوب في قنوات الخادم.

      حالة الاستخدام 3: القنوات الصوتية في Discord​

      هذا هو الوضع الأكثر تقدّمًا.

      ينضم Hermes إلى قناة صوتية (VC) في Discord، ويستمع إلى كلام المستخدمين، ويفرّغه نصيًا، ويشغّل pipeline الوكيل المعتاد، ثم ينطق الردود داخل القناة.

      صلاحيات Discord المطلوبة​

      إضافةً إلى إعداد بوت النصوص المعتاد، تأكّد من أن البوت يملك الصلاحيات التالية:

      • Connect
      • Speak
      • ويُفضّل أيضًا Use Voice Activity

      فعّل كذلك الـ privileged intents في Developer Portal:

      • Presence Intent
      • Server Members Intent
      • Message Content Intent

      الانضمام والمغادرة​

      في قناة نصية على Discord يوجد فيها البوت:

      /voice join
      /voice leave
      /voice status

      ما يحدث بعد الانضمام​

      • يتحدث المستخدمون في القناة الصوتية
      • يكتشف Hermes حدود الكلام
      • تُنشر النصوص المفرّغة في القناة النصية المرتبطة
      • يردّ Hermes نصًا وصوتًا
      • القناة النصية هي تلك التي أُرسل فيها الأمر /voice join

      أفضل الممارسات لاستخدام القنوات الصوتية في Discord​

      • أبقِ DISCORD_ALLOWED_USERS محصورًا بدقة
      • استخدم قناة مخصّصة للبوت أو للاختبار في البداية
      • تحقّق من أن STT و TTS يعملان في الوضع الصوتي للمحادثة النصية العادية قبل تجربة وضع القناة الصوتية

      توصيات جودة الصوت​

      إعداد أفضل جودة​

      • STT: large-v3 محليًا أو whisper-large-v3 عبر Groq
      • TTS: ElevenLabs

      إعداد أفضل سرعة / سهولة​

      • STT: base محليًا أو Groq
      • TTS: Edge

      أفضل إعداد دون تكلفة​

      • STT: محلي
      • TTS: Edge

      حالات الإخفاق الشائعة​

      الخطأ "No audio device found"​

      ثبّت portaudio.

      "البوت ينضم لكنه لا يسمع شيئًا"​

      تحقّق مما يلي:

      • أن معرّف مستخدم Discord الخاص بك موجود في DISCORD_ALLOWED_USERS
      • أنك لست في وضع كتم الصوت
      • أن الـ privileged intents مفعّلة
      • أن البوت يملك صلاحيتي Connect/Speak

      "يفرّغ الكلام لكنه لا ينطق"​

      تحقّق مما يلي:

      • إعدادات مزوّد TTS
      • مفتاح API / الحصة المتاحة لـ ElevenLabs أو OpenAI
      • تثبيت ffmpeg لمسارات التحويل الخاصة بـ Edge

      "يُخرج Whisper نصًا غير مفهوم"​

      جرّب:

      • بيئة أكثر هدوءًا
      • قيمة أعلى لـ silence_threshold
      • مزوّد أو نموذج STT مختلفًا
      • عبارات أقصر وأوضح

      "يعمل في الرسائل المباشرة لكن ليس في قنوات الخادم"​

      غالبًا ما يكون السبب سياسة الإشارة (mention).

      افتراضيًا، يحتاج البوت إلى @mention في القنوات النصية لخوادم Discord ما لم يُضبط خلاف ذلك.

      إعداد مقترح للأسبوع الأول​

      إذا أردت أقصر طريق إلى النجاح:

      1. اجعل Hermes يعمل نصيًا
      2. نفّذ hermes setup tts لتفعيل دعم الصوت
      3. استخدم الوضع الصوتي في CLI مع STT محلي + Edge TTS
      4. ثم فعّل /voice on في Telegram أو Discord
      5. وبعد ذلك فقط، جرّب وضع القنوات الصوتية في Discord

      هذا التدرّج يُبقي نطاق تصحيح الأخطاء صغيرًا.
