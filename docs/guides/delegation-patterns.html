      التفويض والعمل المتوازي

      يستطيع Hermes إنشاء وكلاء فرعيين (subagents) معزولين للعمل على مهام بالتوازي. يحصل كل subagent على محادثته الخاصة، وجلسة طرفية خاصة به، وطقم أدوات (toolset) خاص به. لا يعود إلى سياقك سوى الملخّص النهائي — لا تدخل استدعاءات الأدوات الوسيطة إلى نافذة سياقك أبدًا.

      للمرجع الكامل للميزة، راجع تفويض المهام إلى Subagents.

      متى تُفوّض​

      مرشحون جيدون للتفويض:

      • المهام الفرعية الكثيفة الاستدلال (تصحيح الأخطاء، مراجعة الكود، تجميع نتائج البحث)
      • المهام التي قد تُغرق سياقك ببيانات وسيطة
      • مسارات عمل مستقلة متوازية (بحث A و B في آن واحد)
      • مهام تحتاج سياقًا جديدًا حيث تريد أن يتعامل الوكيل معها دون تحيّز

      استخدم شيئًا آخر عندما:

      • استدعاء أداة واحد ← استخدم الأداة مباشرة
      • عمل ميكانيكي متعدد الخطوات بمنطق بين الخطوات ← execute_code
      • مهام تحتاج تفاعل المستخدم ← لا يمكن للـ subagents استخدام clarify
      • تعديلات ملفات سريعة ← نفّذها مباشرة
      • عمل دائم طويل الأمد يجب أن يبقى بعد إغلاق الجلسة أو إعادة تشغيل العملية ← cronjob أو terminal(background=True, notify_on_complete=True). التفويض على المستوى الأعلى غير متزامن (asynchronous) لكنه يبقى محليًا للعملية نفسها.

      النمط: البحث المتوازي​

      ابحث في ثلاثة مواضيع في آن واحد واحصل على ملخصات منظّمة:

      Research these three topics in parallel:
      1. Current state of WebAssembly outside the browser
      2. RISC-V server chip adoption in 2025
      3. Practical quantum computing applications

      Focus on recent developments and key players.

      خلف الكواليس، يستخدم Hermes:

      delegate_task(tasks=[
          {
              "goal": "Research WebAssembly outside the browser in 2025",
              "context": "Focus on: runtimes (Wasmtime, Wasmer), cloud/edge use cases, WASI progress"
          },
          {
              "goal": "Research RISC-V server chip adoption",
              "context": "Focus on: server chips shipping, cloud providers adopting, software ecosystem"
          },
          {
              "goal": "Research practical quantum computing applications",
              "context": "Focus on: error correction breakthroughs, real-world use cases, key companies"
          }
      ])

      تعمل الثلاثة جميعًا بالتزامن. يبحث كل subagent في الويب بشكل مستقل ويعيد ملخصًا. ثم يجمّع الوكيل الأصلي هذه الملخصات في إحاطة متماسكة.

      النمط: مراجعة الكود​

      فوّض مراجعة أمنية إلى subagent بسياق جديد يتعامل مع الكود دون أفكار مسبقة:

      Review the authentication module at src/auth/ for security issues.
      Check for SQL injection, JWT validation problems, password handling,
      and session management. Fix anything you find and run the tests.

      المفتاح هو حقل context — يجب أن يتضمن كل ما يحتاجه الـ subagent:

      delegate_task(
          goal="Review src/auth/ for security issues and fix any found",
          context="""Project at /home/user/webapp. Python 3.11, Flask, PyJWT, bcrypt.
          Auth files: src/auth/login.py, src/auth/jwt.py, src/auth/middleware.py
          Test command: pytest tests/auth/ -v
          Focus on: SQL injection, JWT validation, password hashing, session management.
          Fix issues found and verify tests pass."""
      )
      مشكلة السياق

      لا يعرف الـ subagents أي شيء على الإطلاق عن محادثتك. تبدأ من الصفر تمامًا. إذا فوّضت "أصلح الخطأ الذي كنا نناقشه"، فلن يكون لدى الـ subagent أي فكرة عن الخطأ المقصود. مرّر دائمًا مسارات الملفات ورسائل الأخطاء وبنية المشروع والقيود صراحةً.

      النمط: مقارنة البدائل​

      قيّم عدة مقاربات لنفس المشكلة بالتوازي، ثم اختر الأفضل:

      I need to add full-text search to our Django app. Evaluate three approaches
      in parallel:
      1. PostgreSQL tsvector (built-in)
      2. Elasticsearch via django-elasticsearch-dsl
      3. Meilisearch via meilisearch-python

      For each: setup complexity, query capabilities, resource requirements,
      and maintenance overhead. Compare them and recommend one.

      يبحث كل subagent في خيار واحد بشكل مستقل. ونظرًا لأنها معزولة، لا يوجد تلوّث متبادل — كل تقييم يقف على أسسه الخاصة. يحصل الوكيل الأصلي على الملخصات الثلاثة جميعها ويجري المقارنة.

      النمط: إعادة الهيكلة عبر ملفات متعددة​

      قسّم مهمة إعادة هيكلة كبيرة عبر subagents متوازية، يتولى كل منها جزءًا مختلفًا من قاعدة الكود:

      delegate_task(tasks=[
          {
              "goal": "Refactor all API endpoint handlers to use the new response format",
              "context": """Project at /home/user/api-server.
              Files: src/handlers/users.py, src/handlers/auth.py, src/handlers/billing.py
              Old format: return {"data": result, "status": "ok"}
              New format: return APIResponse(data=result, status=200).to_dict()
              Import: from src.responses import APIResponse
              Run tests after: pytest tests/handlers/ -v"""
          },
          {
              "goal": "Update all client SDK methods to handle the new response format",
              "context": """Project at /home/user/api-server.
              Files: sdk/python/client.py, sdk/python/models.py
              Old parsing: result = response.json()["data"]
              New parsing: result = response.json()["data"] (same key, but add status code checking)
              Also update sdk/python/tests/test_client.py"""
          },
          {
              "goal": "Update API documentation to reflect the new response format",
              "context": """Project at /home/user/api-server.
              Docs at: docs/api/. Format: Markdown with code examples.
              Update all response examples from old format to new format.
              Add a 'Response Format' section to docs/api/overview.md explaining the schema."""
          }
      ])
      نصيحة

      يحصل كل subagent على جلسة طرفية خاصة به. يمكنها العمل على نفس مجلد المشروع دون أن تتعارض مع بعضها البعض — طالما أنها تعدّل ملفات مختلفة. إذا كان اثنان من الـ subagents قد يلمسان نفس الملف، تعامل مع ذلك الملف بنفسك بعد اكتمال العمل المتوازي.

      النمط: الجمع ثم التحليل​

      استخدم execute_code لجمع البيانات الميكانيكي، ثم فوّض التحليل الكثيف الاستدلال:

      # Step 1: Mechanical gathering (execute_code is better here — no reasoning needed)
      execute_code("""
      from hermes_tools import web_search, web_extract

      results = []
      for query in ["AI funding Q1 2026", "AI startup acquisitions 2026", "AI IPOs 2026"]:
          r = web_search(query, limit=5)
          for item in r["data"]["web"]:
              results.append({"title": item["title"], "url": item["url"], "desc": item["description"]})

      # Extract full content from top 5 most relevant
      urls = [r["url"] for r in results[:5]]
      content = web_extract(urls)

      # Save for the analysis step
      import json
      with open("/tmp/ai-funding-data.json", "w") as f:
          json.dump({"search_results": results, "extracted": content["results"]}, f)
      print(f"Collected {len(results)} results, extracted {len(content['results'])} pages")
      """)

      # Step 2: Reasoning-heavy analysis (delegation is better here)
      delegate_task(
          goal="Analyze AI funding data and write a market report",
          context="""Raw data at /tmp/ai-funding-data.json contains search results and
          extracted web pages about AI funding, acquisitions, and IPOs in Q1 2026.
          Write a structured market report: key deals, trends, notable players,
          and outlook. Focus on deals over $100M."""
      )

      هذا غالبًا ما يكون النمط الأكثر كفاءة: يتولى execute_code أكثر من 10 استدعاءات أدوات متسلسلة بتكلفة زهيدة، ثم يقوم subagent بمهمة الاستدلال المكلفة الوحيدة بسياق نظيف.

      الوصول الموروث إلى الأدوات​

      ترث الـ subagents toolsets المفعّلة للوكيل الأصل. لا تقبل delegate_task معامل toolsets ظاهرًا للنموذج، لذا لا يستطيع العمل المفوَّض منح نفسه قدرات لا يملكها الوكيل الأصل. اضبط أدوات الوكيل الأصل قبل بدء المحادثة عندما تحتاج مهمة مفوَّضة إلى وصول للويب أو الطرفية أو الملفات أو غيرها. لا يزال Hermes يستبعد الأدوات المحظورة على الأبناء مثل clarify وmemory وsend_message؛ يحتفظ الأبناء بـ execute_code لاستدعاء الأدوات برمجيًا (Programmatic Tool Calling).

      القيود​

      • 10 مهام متوازية افتراضيًا: تعمل الدفعات افتراضيًا بـ 10 subagents متزامنة (قابلة للضبط عبر delegation.max_concurrent_children في config.yaml، لا سقف أقصى، فقط حدّ أدنى قدره 1)
      • التفويض المتداخل اختياري بالانضمام (opt-in): لا يمكن لـ subagents الورقية (leaf، الافتراضي) استدعاء delegate_task أو clarify أو memory أو execute_code. تحتفظ الـ subagents المنسّقة (orchestrator، عبر role="orchestrator") بـ delegate_task لمزيد من التفويض، لكن فقط عندما تُرفع delegation.max_spawn_depth فوق الافتراضي وهو 1 (حدّ أدنى 1، لا سقف)؛ تبقى الأدوات الثلاث الأخرى محظورة. عطّل هذا عالميًا عبر delegation.orchestrator_enabled: false.

      ضبط التزامن والعمق​

      الإعدادالقيمة الافتراضيةالنطاقالأثر
      max_concurrent_children10>=1حجم الدفعة المتوازية لكل استدعاء لـ delegate_task
      max_spawn_depth1>=1عدد مستويات التفويض التي يمكنها إنشاء المزيد

      مثال: تشغيل 30 عاملًا متوازيًا مع subagents متداخلة:

      delegation:
        max_concurrent_children: 30
        max_spawn_depth: 2
      • أطراف منفصلة (terminals) — يحصل كل subagent على جلسة طرفية خاصة به بمجلد عمل وحالة منفصلين
      • لا سجل محادثة — لا يرى الـ subagents سوى goal وcontext اللذين يمرّرهما الوكيل الأصل عند استدعاء delegate_task
      • 250 تكرارًا افتراضيًا — اضبط delegation.max_iterations على قيمة أقل في config.yaml لأساطيل من المهام البسيطة لتوفير التكلفة
      • غير دائم — يعمل التفويض على المستوى الأعلى في الخلفية وينشر نتيجته لاحقًا، لكنه يبقى مرتبطًا بالجلسة المالكة وعملية Hermes. يمكن لإغلاق الجلسة، أو /stop، أو /new، أو إعادة تشغيل العملية أن تُلغي العمل الجاري أو تتركه معلّقًا. استخدم cronjob أو terminal(background=True, notify_on_complete=True) للعمل الذي يجب أن يبقى بعد هذه الحدود.

      نصائح​

      كن محددًا في الأهداف. "أصلح الخطأ" غامضة جدًا. "أصلح خطأ TypeError في api/handlers.py السطر 47 حيث تستقبل process_request() القيمة None من parse_body()" يمنح الـ subagent ما يكفي للعمل عليه.

      أدرج مسارات الملفات. لا تعرف الـ subagents بنية مشروعك. أدرج دائمًا المسارات المطلقة للملفات ذات الصلة، وجذر المشروع، وأمر الاختبار.

      استخدم التفويض لعزل السياق. أحيانًا تريد منظورًا جديدًا. يجبرك التفويض على صياغة المشكلة بوضوح، ويتعامل معها الـ subagent دون الافتراضات التي تراكمت في محادثتك.

      تحقق من النتائج. ملخصات الـ subagent هي مجرد ملخصات. إذا قال subagent "أصلحت الخطأ والاختبارات تنجح"، تحقق بتشغيل الاختبارات بنفسك أو بقراءة الفرق (diff).

      تظهر الإخفاقات بوضوح. يُبلَّغ عن subagent يموت (خطأ مزوّد، مهلة، تعطل) بإشعار نظيف من سطر واحد — ⚠️ Subagent failed — "your goal": <reason> — في شجرة التفويض في CLI وكإشعار محادثة على منصات الـ gateway، حتى عندما يكون عرض تقدم الأداة مُطفأً. يتلقى الوكيل الأصل أيضًا الخطأ الكامل في نتيجة الأداة.

      للمرجع الكامل للتفويض — جميع المعاملات، والتكامل مع ACP، والإعدادات المتقدمة — راجع تفويض المهام إلى Subagents.
