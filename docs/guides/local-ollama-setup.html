      تشغيل Hermes محليًا مع Ollama — بدون أي تكلفة API

      مستخدمو Desktop: هناك مسار بنقرة واحدة

      في تطبيق Hermes للحاسوب المكتبي، يقوم المسار Settings → Providers → Local Models بتثبيت خادم llama.cpp محلي وإدارته نيابة عنك — بما في ذلك تنزيل النماذج، وملاءمة الذاكرة، وضبط حجم السياق. راجع Local Models. هذا الدليل مخصص للإعداد اليدوي: تحديدًا Ollama، وسير عمل يعتمد على CLI أولًا، أو الخوادم التي تريد تشغيلها بنفسك.

      المشكلة​

      تفرض واجهات LLM السحابية رسومًا بحسب الـ token. يمكن أن تكلّف جلسة برمجة مكثفة 5 إلى 20 دولارًا. وبالنسبة للمشاريع الشخصية أو التعلّم أو الأعمال الحساسة للخصوصية، تتراكم هذه التكلفة — وأنت ترسل كل محادثة إلى طرف ثالث.

      ما يحلّه هذا الدليل​

      ستُعِدّ Hermes Agent ليعمل بالكامل على عتادك الخاص، باستخدام Ollama كـ backend للنموذج. لا مفاتيح API، ولا اشتراكات، ولا بيانات تغادر جهازك. بعد الإعداد، يعمل Hermes تمامًا كما يعمل مع OpenRouter أو Anthropic — أوامر الطرفية، وتحرير الملفات، وتصفح الويب، والتفويض — لكن النموذج يعمل محليًا.

      في نهاية هذا الدليل، سيكون لديك:

      • Ollama يخدم نموذجًا واحدًا أو أكثر من النماذج مفتوحة الأوزان
      • Hermes متصل بـ Ollama كـ endpoint مخصّص
      • وكيل محلي يعمل يستطيع تحرير الملفات، وتشغيل الأوامر، وتصفح الويب
      • اختياريًا: بوت Telegram/Discord يعمل بالكامل على عتادك الخاص

      ما تحتاجه​

      المكوّنالحد الأدنىالموصى به
      RAM8 جيجابايت (لنماذج 3B)32+ جيجابايت (لنماذج 27B فأكبر)
      التخزين5 جيجابايت متاحة30+ جيجابايت (لعدة نماذج)
      المعالج (CPU)4 أنوية8+ أنوية (AMD EPYC، Ryzen، Intel Xeon)
      وحدة معالجة الرسوميات (GPU)غير مطلوبةوحدة NVIDIA GPU بذاكرة VRAM 8+ جيجابايت تسرّع الأداء بشكل ملحوظ
      يعمل بدون GPU، لكن توقّع استجابات أبطأ

      يعمل Ollama على خوادم بدون GPU. يعطي نموذج 9B على معالج حديث بـ 8 أنوية نحو 10 tokens/ثانية. أما نموذج 31B على المعالج فأبطأ (~2–5 tokens/ثانية) — تستغرق كل استجابة 30 إلى 120 ثانية، لكنه يعمل. تُحسّن GPU هذا الأداء بشكل كبير. للإعدادات التي تعتمد على المعالج فقط، وسّع مهلة API عبر متغير البيئة (فهو ليس مفتاحًا في config.yaml):

      # ~/.hermes/.env
      HERMES_API_TIMEOUT=1800   # 30 minutes — generous for slow local models

      الخطوة 1: تثبيت Ollama​

      curl -fsSL https://ollama.com/install.sh | sh

      تحقّق من أنه يعمل:

      ollama --version
      curl http://localhost:11434/api/tags   # Should return {"models":[]}

      الخطوة 2: سحب نموذج (Pull)​

      اختر بناءً على عتادك:

      النموذجالحجم على القرصالذاكرة المطلوبةاستدعاء الأدوات (Tool Calling)الأنسب لـ
      gemma4:31b~20 جيجابايت24+ جيجابايتنعمأفضل جودة — استخدام أدوات وتفكير منطقي قويّين
      gemma2:27b~16 جيجابايت20+ جيجابايتلامهام حوارية، بدون استخدام أدوات
      gemma2:9b~5 جيجابايت8+ جيجابايتلامحادثة سريعة، أسئلة وأجوبة — لا يستطيع استدعاء الأدوات
      llama3.2:3b~2 جيجابايت4+ جيجابايتلاإجابات سريعة خفيفة فقط
      استدعاء الأدوات أمر مهم

      Hermes مساعد وكيلي (agentic) — فهو يحرّر الملفات، ويشغّل الأوامر، ويتصفح الويب عبر استدعاءات الأدوات. النماذج التي لا تدعم استدعاء الأدوات تستطيع فقط المحادثة؛ ولا يمكنها اتخاذ إجراءات. للحصول على تجربة Hermes الكاملة، استخدم نموذجًا يدعم الأدوات (مثل gemma4:31b).

      اسحب النموذج الذي اخترته:

      ollama pull gemma4:31b
      عدة نماذج

      يمكنك سحب عدة نماذج والتبديل بينها داخل Hermes باستخدام /model. يحمّل Ollama النموذج النشط إلى الذاكرة عند الطلب ويفرّغ النماذج الخاملة تلقائيًا.

      تحقّق من أن النموذج يعمل:

      curl http://localhost:11434/v1/chat/completions \
        -H "Content-Type: application/json" \
        -d '{
          "model": "gemma4:31b",
          "messages": [{"role": "user", "content": "Say hello"}],
          "max_tokens": 50
        }'

      يفترض أن ترى استجابة JSON تحتوي على رد النموذج.

      الخطوة 3: إعداد Hermes​

      شغّل معالج إعداد Hermes:

      hermes setup

      عند سؤالك عن المزوّد، اختر Custom Endpoint وأدخل:

      • Base URL: http://localhost:11434/v1
      • API Key: اتركه فارغًا أو اكتب no-key (لا يحتاج Ollama إلى مفتاح)
      • Model: gemma4:31b (أو أي نموذج سحبته)

      بدلًا من ذلك، حرّر ~/.hermes/config.yaml مباشرة:

      model:
        default: "gemma4:31b"
        provider: "custom"
        base_url: "http://localhost:11434/v1"

      الخطوة 4: ابدأ استخدام Hermes​

      hermes

      هذا كل ما في الأمر. أنت الآن تشغّل وكيلًا محليًا بالكامل. جرّبه:

      You: List all Python files in this directory and count the lines of code in each

      You: Read the README.md and summarize what this project does

      You: Create a Python script that fetches the weather for Ho Chi Minh City

      سيستخدم Hermes أداة الطرفية، وعمليات الملفات، ونموذجك المحلي — بلا أي استدعاءات سحابية.

      الخطوة 5: اختر النموذج المناسب لمهمتك​

      لا تحتاج كل مهمة إلى أكبر نموذج. إليك دليلًا عمليًا:

      المهمةالنموذج الموصى بهالسبب
      تحرير الملفات، والبرمجة، وأوامر الطرفيةgemma4:31bالنموذج الوحيد ذو استدعاء أدوات موثوق
      أسئلة وأجوبة سريعة (دون حاجة لاستخدام أدوات)gemma2:9bاستجابات سريعة للمهام الحوارية
      محادثة خفيفةllama3.2:3bالأسرع، لكن بقدرات محدودة جدًا
      ملاحظة

      للعمل الوكيلي الكامل (تحرير الملفات، وتشغيل الأوامر، والتصفح)، يُعدّ gemma4:31b حاليًا أفضل خيار محلي يدعم استدعاء الأدوات. راجع مكتبة نماذج Ollama بحثًا عن نماذج أحدث — فدعم استدعاء الأدوات يتوسّع بسرعة.

      بدّل النماذج أثناء الجلسة مباشرة:

      /model gemma2:9b

      الخطوة 6: التحسين من أجل السرعة​

      زيادة نافذة سياق Ollama​

      يستخدم Ollama افتراضيًا سياقًا بحجم 2048 token. يتطلب Hermes ما لا يقل عن 64,000 token للعمل الوكيلي مع الأدوات:

      # Create a Modelfile that extends context
      cat > /tmp/Modelfile << 'EOF'
      FROM gemma4:31b
      PARAMETER num_ctx 64000
      EOF

      ollama create gemma4-64k -f /tmp/Modelfile

      ثم حدّث إعدادات Hermes لاستخدام gemma4-64k كاسم النموذج.

      إبقاء النموذج محمّلًا​

      يُفرّغ Ollama افتراضيًا النماذج بعد 5 دقائق من الخمول. لبوت gateway دائم، أبقِه محمّلًا:

      # Set keep-alive to 24 hours
      curl http://localhost:11434/api/generate \
        -d '{"model": "gemma4:31b", "keep_alive": "24h"}'

      أو اضبطه عالميًا في بيئة Ollama:

      # /etc/systemd/system/ollama.service.d/override.conf
      [Service]
      Environment="OLLAMA_KEEP_ALIVE=24h"

      استخدام تفريغ الحمل على GPU (إن توفّرت)​

      إذا كانت لديك وحدة NVIDIA GPU، يقوم Ollama تلقائيًا بتفريغ الطبقات (layers) إليها. تحقّق من ذلك بـ:

      ollama ps   # Shows which model is loaded and how many GPU layers

      بالنسبة لنموذج 31B على GPU بذاكرة 12 جيجابايت، ستحصل على تفريغ جزئي (~40 طبقة على GPU والباقي على المعالج)، ما زال يمنحك تسريعًا ملحوظًا.

      الخطوة 7: التشغيل كبوت Gateway (اختياري)​

      بمجرد أن يعمل Hermes محليًا في CLI، يمكنك عرضه كبوت Telegram أو Discord — يعمل بالكامل على عتادك.

      Telegram​

      1. أنشئ بوتًا عبر @BotFather واحصل على الرمز (token)
      2. أضف إلى ملف ~/.hermes/config.yaml:
      model:
        default: "gemma4:31b"
        provider: "custom"
        base_url: "http://localhost:11434/v1"

      platforms:
        telegram:
          enabled: true
          token: "YOUR_TELEGRAM_BOT_TOKEN"
      1. ابدأ الـ gateway:
      hermes gateway

      الآن راسِل بوتك على Telegram — سيردّ باستخدام نموذجك المحلي.

      Discord​

      1. أنشئ تطبيق Discord على discord.com/developers
      2. أضف إلى الإعدادات:
      platforms:
        discord:
          enabled: true
          token: "YOUR_DISCORD_BOT_TOKEN"
      1. ابدأ التشغيل: hermes gateway

      الخطوة 8: إعداد الحلول الاحتياطية (اختياري)​

      قد تواجه النماذج المحلية صعوبة في المهام المعقدة. أعِدّ حلًا سحابيًا احتياطيًا يُفعَّل فقط عند فشل النموذج المحلي:

      model:
        default: "gemma4:31b"
        provider: "custom"
        base_url: "http://localhost:11434/v1"

      fallback_providers:
        - provider: openrouter
          model: anthropic/claude-sonnet-4

      بهذه الطريقة، تكون 90% من استخدامك مجانيًا (محليًا)، ولا تصل إلى واجهة API المدفوعة إلا المهام الصعبة.

      استكشاف الأخطاء وإصلاحها​

      "Connection refused" عند بدء التشغيل​

      Ollama غير قيد التشغيل. شغّله:

      sudo systemctl start ollama
      # or
      ollama serve

      استجابات بطيئة​

      • تحقّق من حجم النموذج مقارنة بالذاكرة (RAM): إذا احتاج نموذجك ذاكرة أكثر من المتاحة، فسينتقل إلى القرص (swap). استخدم نموذجًا أصغر أو أضف ذاكرة.
      • تحقّق من ollama ps: إذا لم تُفرَّغ أي طبقات على GPU، تكون الاستجابات مقيّدة بالمعالج (CPU-bound). هذا طبيعي للخوادم التي تعمل بالمعالج فقط.
      • قلّل السياق: تُبطئ المحادثات الطويلة الاستدلال (inference). استخدم /compress بانتظام، أو اضبط عتبة ضغط أقل في الإعدادات.

      استجابة أولى بطيئة (Prefill)​

      يرسل Hermes حمولة (payload) ثابتة في كل استدعاء API — الـ system prompt بالإضافة إلى مخططات الأدوات لجميع الأدوات المفعّلة — قبل أي محتوى من محادثتك. في الإعدادات التي تعتمد على المعالج فقط أو ذات ذاكرة VRAM منخفضة، تُهيمن معالجة هذا الـ prompt (مرحلة prefill) على الدور الأول: قد يبقى النموذج صامتًا لدقائق أثناء معالجة الـ prompt، ثم يولّد النص بمعدله المعتاد. هذا سلوك متوقّع وليس تعليقًا (hang). يوثّق دليل LLM المحلي على Mac التأثير نفسه — أثناء prefill في السياقات الكبيرة، قد لا تنتج النماذج المحلية أي مخرجات لدقائق أثناء معالجة الـ prompt — ويرفع Hermes تلقائيًا مهلة قراءة البث (stream) من 120 ثانية إلى 1800 ثانية للـ endpoints المحلية (HERMES_STREAM_READ_TIMEOUT).

      ما يساعد:

      • إبقاء النموذج محمّلًا — يُفرّغ Ollama النماذج الخاملة بعد 5 دقائق، ما يضيف إعادة تحميل كاملة قبل الـ prefill التالي. اضبط OLLAMA_KEEP_ALIVE=24h (راجع الخطوة 6).
      • توسيع مهلة API — اضبط HERMES_API_TIMEOUT=1800 في ~/.hermes/.env (راجع ما تحتاجه).
      • قياس الـ prompt الثابت وتقليصه — شغّل hermes prompt-size للحصول على تفصيل بالبايت لحجم الـ system prompt ومخططات الأدوات، ثم عطّل مجموعات الأدوات (toolsets) غير المستخدمة عبر hermes tools وأزل تثبيت المهارات التي لا تحتاجها عبر hermes skills.
      • استخدام تفريغ الحمل على GPU — حتى التفريغ الجزئي يمنح تسريعًا ملحوظًا (راجع الخطوة 6).

      النموذج لا يتبع استدعاءات الأدوات​

      تُنتج النماذج التي لا تدعم استدعاء الأدوات نصًا عاديًا بدلًا من استدعاءات دوال منظّمة. الحلول:

      • استخدم نموذجًا يدعم استدعاء الأدوات — من بين النماذج المذكورة أعلاه، gemma4:31b فقط لديه استدعاء أدوات موثوق.
      • يمتلك Hermes إصلاحًا تلقائيًا — فهو يكتشف استدعاءات الأدوات المُشوَّهة ويحاول إصلاحها تلقائيًا.
      • أعِدّ حلًا احتياطيًا — إذا فشل النموذج المحلي 3 مرات، يتحوّل Hermes إلى مزوّد سحابي.

      إذا طبع النموذج نص JSON خامًا مثل {"name": "web_search", ...} في رده بدلًا من تشغيل الأداة فعليًا، فهذا يعود عادة إلى الخادم (server) وليس النموذج — أي أن استدعاء الأدوات غير مفعّل أو أن صيغة استدعاء الأداة لا تُحلَّل (parsed). راجع جدول الإصلاح الخاص بكل خادم في تظهر استدعاءات الأدوات كنص بدلًا من التنفيذ (يحتاج llama.cpp إلى --jinja، ويحتاج vLLM إلى --enable-auto-tool-choice --tool-call-parser hermes، وهكذا).

      أخطاء نافذة السياق​

      سياق Ollama الافتراضي (2048 token) صغير جدًا للعمل الوكيلي. راجع الخطوة 6 لزيادته.

      مقارنة التكلفة​

      إليك ما يوفّره التشغيل المحلي مقارنة بواجهات API السحابية، بناءً على جلسة برمجة نموذجية (~100 ألف token مدخلات، ~20 ألف token مخرجات):

      المزوّدالتكلفة لكل جلسةشهريًا (استخدام يومي)
      Anthropic Claude Sonnet~0.80 دولار~24 دولارًا
      OpenRouter (GPT-4o)~0.60 دولار~18 دولارًا
      Ollama (محلي)0.00 دولار0.00 دولار

      تكلفتك الوحيدة هي الكهرباء — نحو 0.01 إلى 0.05 دولار لكل جلسة حسب العتاد.

      ما يعمل جيدًا محليًا​

      • تحرير الملفات وتوليد الكود — تتعامل النماذج بحجم 9B فأكبر مع هذا جيدًا
      • أوامر الطرفية — يغلّف Hermes الأمر، ويشغّله، ويقرأ المخرجات بغض النظر عن النموذج
      • تصفح الويب — تقوم أداة المتصفح بالجلب؛ والنموذج يكتفي بتفسير النتائج
      • مهام Cron والمهام المجدولة — تعمل مطابقة للإعدادات السحابية
      • Gateway متعدد المنصات — تعمل Telegram وDiscord وSlack جميعها مع النماذج المحلية

      ما هو أفضل مع النماذج السحابية​

      • الاستدلال المعقّد جدًا متعدد الخطوات — النماذج بحجم 70B فأكبر أو النماذج السحابية مثل Claude Opus أفضل بشكل ملحوظ
      • نوافذ السياق الطويلة — تقدّم النماذج السحابية 100 ألف إلى مليون token؛ وغالبًا ما تكون بيئات التشغيل المحلية أقل افتراضيًا من حد Hermes الأدنى البالغ 64 ألف token ما لم تُعدّها يدويًا
      • السرعة في الاستجابات الطويلة — الاستدلال السحابي أسرع من التشغيل المحلي بالمعالج فقط للنصوص الطويلة

      النقطة المثلى: استخدم النموذج المحلي للمهام اليومية، وأعِدّ حلًا سحابيًا احتياطيًا للمهام الصعبة.
