      AWS Bedrock

      يدعم Hermes Agent خدمة Amazon Bedrock بوصفها مزوّدًا (provider) أصيلًا. ويمنحك ذلك وصولًا كاملًا إلى منظومة Bedrock: مصادقة IAM، و Guardrails، و inference profiles العابرة للمناطق، وجميع النماذج الأساسية (foundation models).

      يوجّه Hermes كل عائلة نماذج عبر الـ API الأنسب لخدمتها:

      عائلة النماذجمسار الـ APIالسبب
      Anthropic ClaudeAnthropic SDK (AnthropicBedrock)التخزين المؤقت للـ prompt (Prompt caching)، وميزانيات التفكير (thinking budgets)، والتفكير التكيّفي (adaptive thinking) — وهي ميزات غير متاحة عبر Converse
      OpenAI GPT-5.5 / GPT-5.6 (Sol, Terra, Luna)endpoint OpenAI Responses في Bedrock Mantle (bedrock-mantle.<region>.api.aws/openai/v1)هذه النماذج متاحة عبر Mantle فقط — إذ تشير بطاقات نماذجها إلى أن bedrock-runtime/Converse غير مدعوم
      كل ما عدا ذلك (Nova، و DeepSeek، و Llama، و GPT-OSS، …)Converse API الأصيل (bedrock-runtime)مجموعة ميزات Bedrock الكاملة: Guardrails، و inference profiles، والبث (streaming)

      تتشارك المسارات الثلاثة سلسلة بيانات اعتماد AWS نفسها وآلية تحديد المنطقة نفسها — فلا حاجة إلى أي إعداد منفصل. تُصادَق الطلبات الموجّهة إلى endpoint الخاص بـ Mantle باستخدام AWS_BEARER_TOKEN_BEDROCK عند ضبطه، وإلا فتُوقَّع بـ SigV4 عبر سلسلة بيانات الاعتماد القياسية في boto3.

      المتطلبات المسبقة​

      • بيانات اعتماد AWS — أي مصدر تدعمه سلسلة بيانات الاعتماد في boto3:
        • دور IAM للمثيل (EC2، و ECS، و Lambda — دون أي إعداد)
        • متغيرا البيئة AWS_ACCESS_KEY_ID + AWS_SECRET_ACCESS_KEY
        • AWS_PROFILE لـ SSO أو الـ profiles المسمّاة
        • aws configure للتطوير المحلي
      • boto3 — ثبّته باستخدام cd ~/.hermes/hermes-agent && uv pip install -e ".[bedrock]"
      • صلاحيات IAM — كحد أدنى:
        • bedrock:InvokeModel و bedrock:InvokeModelWithResponseStream (للـ inference)
        • bedrock:ListFoundationModels و bedrock:ListInferenceProfiles (لاكتشاف النماذج)
      EC2 / ECS / Lambda

      على موارد الحوسبة في AWS، أرفق دور IAM يحمل AmazonBedrockFullAccess وانتهى الأمر. لا مفاتيح API، ولا إعدادات .env — إذ يكتشف Hermes دور المثيل تلقائيًا.

      البدء السريع​

      # Install with Bedrock support
      cd ~/.hermes/hermes-agent && uv pip install -e ".[bedrock]"

      # Select Bedrock as your provider
      hermes model
      # → Choose "More providers..." → "AWS Bedrock"
      # → Select your region and model

      # Start chatting
      hermes chat

      الإعدادات​

      بعد تشغيل hermes model، سيحتوي الملف ~/.hermes/config.yaml على ما يلي:

      model:
        default: us.anthropic.claude-sonnet-4-6
        provider: bedrock
        base_url: https://bedrock-runtime.us-east-2.amazonaws.com

      bedrock:
        region: us-east-2

      المنطقة (Region)​

      اضبط منطقة AWS بأي من الطرق التالية (الأعلى أولوية أولًا):

      1. bedrock.region في config.yaml
      2. متغير البيئة AWS_REGION
      3. متغير البيئة AWS_DEFAULT_REGION
      4. الافتراضي: us-east-1

      Guardrails​

      لتطبيق Amazon Bedrock Guardrails على جميع استدعاءات النماذج:

      bedrock:
        region: us-east-2
        guardrail:
          guardrail_identifier: "abc123def456"  # From the Bedrock console
          guardrail_version: "1"                # Version number or "DRAFT"
          stream_processing_mode: "async"       # "sync" or "async"
          trace: "disabled"                     # "enabled", "disabled", or "enabled_full"

      يُرفق الـ guardrail على مسار Converse (guardrailConfig) وعلى مسار Claude (عبر ترويسات InvokeModel من خلال Anthropic Bedrock SDK، بحيث يُحافظ على التخزين المؤقت للـ prompt والتفكير). ويظهر الطلب المحظور على شكل رفض من مرشّح المحتوى بدلًا من نص صادر عن النموذج. ولا ينطبق stream_processing_mode إلا على Converse.

      لا تطبّق AWS الـ Guardrails على endpoint Mantle Responses الذي تستخدمه نماذج openai.gpt-5.x (وثائق AWS)؛ لذا استخدم نموذجًا يُخدَّم عبر Converse عندما يكون الـ guardrail مطلوبًا.

      اكتشاف النماذج​

      يكتشف Hermes النماذج المتاحة تلقائيًا عبر مستوى التحكم (control plane) في Bedrock. ويمكنك تخصيص الاكتشاف:

      bedrock:
        discovery:
          enabled: true
          provider_filter: ["anthropic", "amazon"]  # Only show these providers
          refresh_interval: 3600                     # Cache for 1 hour

      التخزين المؤقت للـ Prompt (cachePoint)​

      يطبّق Hermes التخزين المؤقت للـ prompt تلقائيًا على مسار Converse API في Bedrock عبر إدراج علامات cachePoint بعد الـ system prompt، وتعريفات الأدوات، وآخر رسالة. ولأن إرسال كتلة cachePoint إلى نموذج لا يدعمها يُطلق ValidationException، فلا تُضاف العلامات إلا للنماذج الموجودة في قائمة سماح معروفة السلامة (معرّفات نماذج Anthropic Claude و Amazon Nova)؛ أما النماذج غير المعروفة فلا تُضاف لها علامات cache افتراضيًا. تستخدم نماذج Claude عادةً مسار AnthropicBedrock SDK الذي يمتلك تخزينه المؤقت الخاص للـ prompt — ويغطي مسار cachePoint في Converse نماذج Nova والمسار الاحتياطي لـ Claude القائم على bearer token. لا حاجة إلى أي إعداد؛ وتظهر عمليات القراءة/الكتابة في الـ cache ضمن حساب الاستخدام.

      استكشاف حجم الـ Context window​

      بالنسبة إلى النماذج التي لا يوجد حجم context window الخاص بها في الجدول الثابت لدى Hermes، يستطيع Hermes استكشاف الحد الفعلي بإرسال طلبات كبيرة الحجم عمدًا على مستويات ثابتة (~1.3M و ~2.2M token) وتحليل قيمة maximum المذكورة في خطأ التحقق من الطول الصادر عن Bedrock. تُغذّي القيم المستكشَفة الـ cache نفسه الخاص بالبيانات الوصفية الذي يستخدمه الجدول الثابت؛ وتُحذف تلقائيًا الإدخالات المخزّنة القديمة التي تُقلّل من حجم نافذة النموذج (مثل الإدخالات المُعبّأة قبل الإتاحة العامة لنافذة 1M الخاصة بنموذج ما) لصالح القيمة المعروفة الأكبر.

      النماذج المتاحة​

      Inference عابر للمناطق (Cross-Region)

      تستخدم النماذج التي تبدأ بالبادئة us. ملفات inference profiles العابرة للمناطق، والتي توفّر سعة أفضل وتحويلًا تلقائيًا عند الأعطال (failover) بين مناطق AWS. أما النماذج التي تبدأ بالبادئة global. فتُوجَّه عبر جميع المناطق المتاحة حول العالم. وتُخدَّم معرّفات نماذج OpenAI openai.* عبر Bedrock Mantle في المنطقة المضبوطة، ولا تستخدم بادئات inference profile.

      تبديل النماذج أثناء الجلسة​

      استخدم الأمر /model أثناء المحادثة:

      /model us.amazon.nova-pro-v1:0
      /model deepseek.v3.2
      /model us.anthropic.claude-opus-4-6-v1

      التشخيص​

      hermes doctor

      يتحقق أمر doctor مما يلي:

      • ما إذا كانت بيانات اعتماد AWS متاحة (متغيرات البيئة، أو دور IAM، أو SSO)
      • ما إذا كان boto3 مثبّتًا
      • ما إذا كان من الممكن الوصول إلى Bedrock API (ListFoundationModels)
      • عدد النماذج المتاحة في منطقتك

      الـ Gateway (منصات المراسلة)​

      يعمل Bedrock مع جميع منصات الـ gateway في Hermes (Telegram، و Discord، و Slack، و Feishu، وغيرها). اضبط Bedrock كمزوّد لديك، ثم شغّل الـ gateway كالمعتاد:

      hermes gateway setup
      hermes gateway start

      يقرأ الـ gateway الملف config.yaml ويستخدم إعدادات مزوّد Bedrock نفسها.

      استكشاف الأخطاء وإصلاحها​

      "No API key found" / "No AWS credentials"​

      يبحث Hermes عن بيانات الاعتماد بالترتيب التالي:

      1. AWS_BEARER_TOKEN_BEDROCK
      2. AWS_ACCESS_KEY_ID + AWS_SECRET_ACCESS_KEY
      3. AWS_PROFILE
      4. البيانات الوصفية لمثيل EC2 (IMDS)
      5. بيانات اعتماد حاوية ECS
      6. دور التنفيذ في Lambda

      إذا لم يُعثر على أيٍّ منها، فشغّل aws configure أو أرفق دور IAM بمثيل الحوسبة لديك.

      "Invocation of model ID ... with on-demand throughput isn't supported"​

      استخدم معرّف inference profile (يبدأ بالبادئة us. أو global.) بدلًا من معرّف النموذج الأساسي المجرّد. على سبيل المثال:

      • ❌ anthropic.claude-sonnet-4-6
      • ✅ us.anthropic.claude-sonnet-4-6

      "ThrottlingException"​

      لقد بلغت حدّ المعدل (rate limit) الخاص بكل نموذج في Bedrock. يعيد Hermes المحاولة تلقائيًا مع تأخير متزايد (backoff). ولزيادة الحدود، اطلب رفع الحصة من وحدة تحكم AWS Service Quotas.

      النشر على AWS بنقرة واحدة​

      للحصول على نشر مؤتمت بالكامل على EC2 باستخدام CloudFormation:

      sample-hermes-agent-on-aws-with-bedrock — ينشئ VPC، ودور IAM، ومثيل EC2، ويضبط Bedrock تلقائيًا. انشره في أي منطقة بنقرة واحدة.
