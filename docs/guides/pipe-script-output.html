      تمرير مخرجات السكربتات إلى منصات المراسلة

      hermes send أداة CLI صغيرة وقابلة للبرمجة النصية تدفع رسالة إلى أي منصة مراسلة يكون Hermes معدًّا لها بالفعل. فكّر فيها كـ curl عابرة للمنصات للإشعارات — لا تحتاج إلى gateway قيد التشغيل، ولا تحتاج إلى LLM، ولا تحتاج إلى إعادة لصق رموز البوت في كل سكربت من سكربتاتك.

      استخدمها من أجل:

      • مراقبة النظام (الذاكرة، القرص، حرارة GPU، انتهاء مهمة طويلة التشغيل)
      • إشعارات CI/CD (اكتمال النشر، فشل الاختبار)
      • سكربتات Cron التي تحتاج إلى إبلاغك بالنتائج
      • رسائل سريعة لمرة واحدة من الطرفية
      • تمرير مخرجات أي أداة إلى أي مكان (make | hermes send --to slack:#builds)

      يعيد الأمر استخدام بيانات الاعتماد ومحوّلات المنصات نفسها التي يستخدمها hermes gateway بالفعل، لذا لا توجد واجهة إعداد ثانية يلزم صيانتها.

      البدء السريع​

      # Plain text to the home channel for a platform
      hermes send --to telegram "deploy finished"

      # Pipe in stdout from anything
      echo "RAM 92%" | hermes send --to telegram:-1001234567890

      # Send a file
      hermes send --to discord:#ops --file /tmp/report.md

      # Attach a subject/header line
      hermes send --to slack:#eng --subject "[CI] build.log" --file build.log

      # Thread target (Telegram topic, Discord thread)
      hermes send --to telegram:-1001234567890:17585 "threaded reply"

      # List every configured target
      hermes send --list

      # Filter by platform
      hermes send --list telegram

      مرجع المعطيات (Arguments)​

      الخيارالوصف
      -t, --to TARGETالوجهة. راجع صيغ الوجهات.
      message (موضعي)نص الرسالة. اتركه لتُقرأ من --file أو stdin.
      -f, --file PATHاقرأ المتن من ملف. يفرض --file - القراءة من stdin.
      -s, --subject LINEأضف سطر عنوان/موضوع قبل المتن.
      -l, --listسرد الوجهات المتاحة. مع فلتر منصة موضعي اختياري.
      -q, --quietبلا مخرجات عند النجاح (رمز الخروج فقط — مثالي للسكربتات).
      --jsonأخرج نتيجة JSON الخام للإرسال.
      -h, --helpاعرض نص المساعدة المدمج.

      صيغ الوجهات​

      الصيغةمثالالمعنى
      platformtelegramإرسال إلى القناة الرئيسية المُعدّة للمنصة
      platform:chat_idtelegram:-1001234567890محادثة / مجموعة / مستخدم رقمي محدّد
      platform:chat_id:thread_idtelegram:-1001234567890:17585خيط محدّد أو موضوع منتدى في Telegram
      platform:#channeldiscord:#opsاسم قناة سهل القراءة (يُحلّ مقابل دليل القنوات)
      platform:+E164signal:+15551234567منصات تُعنون بالهاتف: Signal، SMS، WhatsApp

      تعمل كوجهة أي منصة يوفّر لها Hermes محوّلات: telegram، وdiscord، وslack، وsignal، وsms، وwhatsapp، وmatrix، وmattermost، وfeishu، وdingtalk، وwecom، وweixin، وemail، و غيرها.

      رموز الخروج (Exit Codes)​

      الرمزالمعنى
      0نجح الإرسال (أو السرد)
      1فشل التسليم على مستوى المنصة (المصادقة، الصلاحيات، الشبكة)
      2خطأ في الاستخدام / المعطيات / الإعدادات

      تتّبع رموز الخروج اتفاقية Unix القياسية حتى تستطيع سكربتاتك التفرّع بناءً عليها كما تفعل مع curl أو grep.

      تحديد متن الرسالة​

      يحدّد hermes send متن الرسالة بهذا الترتيب:

      1. معطى موضعي — hermes send --to telegram "hi"
      2. --file PATH — hermes send --to telegram --file msg.txt
      3. stdin المُمرَّر عبر أنبوب (piped) — echo hi | hermes send --to telegram

      عندما يكون stdin طرفية تفاعلية (TTY) (بلا أنبوب)، لا ينتظر Hermes الإدخال — بل ستحصل على خطأ استخدام واضح بدلًا من ذلك. هذا يمنع تعليق السكربتات إذا أغفلت المتن بالخطأ.

      أمثلة من واقع الاستخدام​

      المراقبة: تنبيهات الذاكرة / القرص​

      استبدل استدعاءات curl https://api.telegram.org/... المؤقتة في مراقباتك (watchdogs) بسطر واحد قابل للنقل:

      #!/usr/bin/env bash
      ram_pct=$(free | awk '/^Mem:/ {printf "%d", $3 * 100 / $2}')
      if [ "$ram_pct" -ge 85 ]; then
        hermes send --to telegram --subject "⚠ MEMORY WARNING" \
          "RAM ${ram_pct}% on $(hostname)"
      fi

      بما أن hermes send يعيد استخدام إعدادات Hermes لديك، يعمل السكربت نفسه على أي جهاز مضيف مثبَّت عليه Hermes — دون حاجة لتصدير رموز البوت يدويًا إلى بيئة كل جهاز.

      لا تنبّه الـ gateway بشأن نفسه

      بالنسبة للمراقبات (watchdogs) التي قد تُطلَق عندما يعاني الـ gateway نفسه (تنبيهات نفاد الذاكرة (OOM)، تنبيهات امتلاء القرص)، واصل استخدام استدعاء curl بسيط بدلًا من hermes send. إذا تعذّر تحميل مفسّر Python لأن الجهاز مُثقَل، لا تزال تريد أن يخرج ذلك التنبيه.

      CI / CD: نتائج البناء والاختبار​

      # In .github/workflows/deploy.yml or any CI script
      if ./scripts/deploy.sh; then
        hermes send --to slack:#deploys "✅ ${CI_COMMIT_SHA:0:7} deployed"
      else
        tail -n 100 deploy.log | hermes send \
          --to slack:#deploys --subject "❌ deploy failed"
        exit 1
      fi

      Cron: تقرير يومي​

      # Crontab entry
      0 9 * * * /usr/local/bin/generate-metrics.sh \
        | /home/me/.hermes/bin/hermes send \
            --to telegram --subject "Daily metrics $(date +%Y-%m-%d)"

      المهام الطويلة التشغيل: إبلاغ عند الانتهاء​

      ./train.py --epochs 200 && \
        hermes send --to telegram "training done" || \
        hermes send --to telegram "training failed (exit $?)"

      البرمجة النصية باستخدام --json و--quiet​

      # Hard-fail a script if delivery fails; don't clutter logs on success
      hermes send --to telegram --quiet "keepalive" || {
        echo "Telegram delivery failed" >&2
        exit 1
      }

      # Capture the message ID for later editing / threading
      msg_id=$(hermes send --to discord:#ops --json "build started" \
        | jq -r .message_id)

      هل يحتاج hermes send إلى تشغيل الـ Gateway؟​

      عادةً لا. بالنسبة لأي منصة تعتمد على رمز بوت — Telegram، وDiscord، وSlack، وSignal، وSMS، وWhatsApp Cloud API، ومعظم غيرها — يستدعي hermes send نقطة نهاية REST الخاصة بالمنصة مباشرة باستخدام بيانات الاعتماد من ~/.hermes/.env و~/.hermes/config.yaml. إنها عملية فرعية مستقلة تُنهي عملها فور تسليم الرسالة.

      لا يُطلب gateway حيّ إلا لـمنصات الإضافات (plugin platforms) التي تعتمد على اتصال محوّل دائم (مثلًا، إضافة مخصّصة تُبقي اتصال WebSocket مفتوحًا لفترة طويلة). في هذه الحالة ستحصل على خطأ واضح يشير إلى الـ gateway؛ شغّله بـ hermes gateway start وأعد المحاولة.

      سرد الوجهات واكتشافها​

      قبل الإرسال إلى قناة محدّدة، يمكنك فحص ما هو متاح:

      # Every target across every configured platform
      hermes send --list

      # Just Telegram targets
      hermes send --list telegram

      # Machine-readable
      hermes send --list --json

      يُبنى السرد من ~/.hermes/channel_directory.json، الذي يحدّثه الـ gateway كل بضع دقائق أثناء تشغيله. إذا رأيت "no channels discovered yet"، شغّل الـ gateway مرة واحدة (hermes gateway start) حتى يملأ ذاكرته المؤقتة (cache).

      تُحلّ الأسماء سهلة القراءة (discord:#ops، slack:#engineering) مقابل هذه الذاكرة المؤقتة وقت الإرسال، لذا لست بحاجة إلى حفظ المعرّفات الرقمية.

      مقارنة مع مناهج أخرى​

      المنهجمتعدد المنصاتيعيد استخدام بيانات اعتماد Hermesيحتاج gatewayالأنسب لـ
      hermes send✅✅لا (رمز بوت)كل ما يلي أدناه
      curl خام إلى كل منصةمكتوبة بسكربت منفصل لكل منهايدويلاالمراقبات الحرجة
      مهمة cron بـ --deliver✅✅لامهام الوكيل المجدولة

      hermes send هو عمدًا أبسط واجهة ممكنة. إذا احتجت وكيلًا ليقرر ماذا يقول، جدول مهمة cron — تُسلَّم استجابة الوكيل النهائية تلقائيًا إلى وجهة deliver: المُعدّة (لم يعد الوكيل يطلق الرسائل بنفسه). إذا احتجت تشغيلًا مجدولًا بمحتوى مولَّد بواسطة LLM، استخدم cronjob(action='create', prompt=...) مع deliver='telegram:...'. وإذا احتجت فقط تمرير نص خام عبر أنبوب، استخدم hermes send.

      مواضيع ذات صلة​

      • أتمتة أي شيء باستخدام Cron — مهام مجدولة تُسلَّم مخرجاتها تلقائيًا إلى أي منصة.
      • آلية عمل Gateway من الداخل — موجّه التسليم الذي يتشاركه hermes send مع تسليم cron.
      • إعداد منصات المراسلة — إعداد لمرة واحدة لكل منصة.
