      الانتقال من OpenClaw

      يستورد الأمر hermes claw migrate إعداد OpenClaw لديك (أو الإصدارات القديمة Clawdbot/Moldbot) إلى Hermes. يغطي هذا الدليل بدقة ما يُنقل، وتعيينات مفاتيح الإعدادات، وما ينبغي التحقق منه بعد الانتقال.

      ملاحظة

      هل تنتقل من Claude Code أو OpenAI Codex CLI بدلًا من ذلك؟ استخدم hermes import-agent.

      نصيحة

      إذا كان إعداد OpenClaw لديك متعدد المزوّدين، فإن hermes setup --portal يختصره في OAuth واحد — أكثر من 300 نموذج بالإضافة إلى Tool Gateway بتسجيل دخول واحد. راجع Nous Portal.

      البدء السريع​

      # Preview then migrate (always shows a preview first, then asks to confirm)
      hermes claw migrate

      # Preview only, no changes
      hermes claw migrate --dry-run

      # Full migration including API keys, skip confirmation
      hermes claw migrate --preset full --migrate-secrets --yes

      تعرض عملية الانتقال دائمًا معاينة كاملة لما سيُستورد قبل إجراء أي تغييرات. راجع القائمة، ثم أكّد للمتابعة.

      تقرأ افتراضيًا من ~/.openclaw/. ويُكتشف المجلدان القديمان ~/.clawdbot/ أو ~/.moltbot/ تلقائيًا، وكذلك أسماء ملفات الإعدادات القديمة (clawdbot.json، moltbot.json).

      الخيارات​

      الخيارالوصف
      --dry-runمعاينة فقط — يتوقف بعد عرض ما سيُنقل.
      --preset <name>full (جميع الإعدادات المتوافقة) أو user-data (يستثني إعدادات البنية التحتية). لا يستورد أيٌّ من الإعدادين المسبقين الأسرار (secrets) افتراضيًا — مرّر --migrate-secrets صراحةً.
      --overwriteالكتابة فوق ملفات Hermes الموجودة عند التعارض (الافتراضي: رفض التطبيق عندما تحتوي الخطة على تعارضات).
      --migrate-secretsتضمين مفاتيح API. مطلوب حتى مع --preset full — فلا يوجد إعداد مسبق يستورد الأسرار بصمت.
      --no-backupتخطّي لقطة zip السابقة للانتقال من ~/.hermes/ (افتراضيًا يُكتب أرشيف واحد لنقطة الاستعادة قبل التطبيق، ضمن ~/.hermes/backups/pre-migration-*.zip؛ ويمكن استعادته باستخدام hermes import).
      --source <path>مجلد OpenClaw مخصص.
      --workspace-target <path>المكان الذي يوضع فيه AGENTS.md.
      --skill-conflict <mode>skip (الافتراضي)، أو overwrite، أو rename.
      --yesتخطّي طلب التأكيد بعد المعاينة.

      مدة بقاء الجلسة​

      لا تُستورد مؤقتات إعادة الضبط عند الخمول أو اليومية: فمحادثات Hermes تبقى قائمة حتى تنفّذ /new أو /reset صراحةً. أما إعدادات الجلسة المتقدمة (روابط الهوية، وربط سلاسل النقاش، والصيانة، والنطاق وسياسة الإرسال) فتبقى مؤرشفة للرجوع إليها.

      تحديد مفاتيح API​

      عند تفعيل --migrate-secrets، تُجمع مفاتيح API من أربعة مصادر وفق ترتيب الأولوية التالي:

      1. قيم الإعدادات — models.providers.*.apiKey ومفاتيح مزوّدي TTS في openclaw.json
      2. ملف البيئة — ~/.openclaw/.env (مفاتيح مثل OPENROUTER_API_KEY، و ANTHROPIC_API_KEY، وغيرها)
      3. الكائن الفرعي env في الإعدادات — openclaw.json → "env" أو "env"."vars" (بعض الإعدادات تخزّن المفاتيح هنا بدلًا من ملف .env منفصل)
      4. ملفات تعريف المصادقة (Auth profiles) — ~/.openclaw/agents/main/agent/auth-profiles.json (بيانات اعتماد لكل وكيل)

      لقيم الإعدادات الأولوية. ويملأ كل مصدر لاحق أي فجوات متبقية.

      المفاتيح المستهدفة المدعومة​

      OPENROUTER_API_KEY, OPENAI_API_KEY, ANTHROPIC_API_KEY, DEEPSEEK_API_KEY, GEMINI_API_KEY, ZAI_API_KEY, MINIMAX_API_KEY, ELEVENLABS_API_KEY, TELEGRAM_BOT_TOKEN, VOICE_TOOLS_OPENAI_KEY

      لا تُنسخ أبدًا المفاتيح غير الموجودة في قائمة السماح هذه.

      التعامل مع SecretRef​

      يمكن أن تأتي قيم الـ tokens ومفاتيح API في إعدادات OpenClaw بثلاث صيغ:

      // Plain string
      "channels": { "telegram": { "botToken": "123456:ABC-DEF..." } }

      // Environment template
      "channels": { "telegram": { "botToken": "${TELEGRAM_BOT_TOKEN}" } }

      // SecretRef object
      "channels": { "telegram": { "botToken": { "source": "env", "id": "TELEGRAM_BOT_TOKEN" } } }

      تحلّ عملية الانتقال الصيغ الثلاث جميعها. فبالنسبة إلى قوالب env وكائنات SecretRef التي تحتوي source: "env"، تبحث عن القيمة في ~/.openclaw/.env وفي الكائن الفرعي env داخل openclaw.json. أما كائنات SecretRef التي تحتوي source: "file" أو source: "exec" فلا يمكن حلّها تلقائيًا — إذ تُصدر عملية الانتقال تحذيرًا بشأنها، ويجب إضافة تلك القيم إلى Hermes يدويًا عبر hermes config set.

      بعد الانتقال​

      1. راجع تقرير الانتقال — يُطبع عند الانتهاء مع أعداد العناصر المنقولة والمتخطّاة والمتعارضة.

      2. راجع الملفات المؤرشفة — كل ما في ~/.hermes/migration/openclaw/<timestamp>/archive/ يحتاج إلى معالجة يدوية.

      3. ابدأ جلسة جديدة — تسري المهارات وإدخالات الذاكرة المستوردة في الجلسات الجديدة، لا في الجلسة الحالية.

      4. تحقّق من مفاتيح API — شغّل hermes status للتحقق من مصادقة المزوّدين.

      5. اختبر المراسلة — إذا نقلت tokens المنصات، فأعد تشغيل الـ gateway: systemctl --user restart hermes-gateway

      6. راجع أرشيفات الجلسات — راجع الإعدادات المتقدمة المؤرشفة؛ علمًا بأن مؤقتات إعادة الضبط عند الخمول واليومية لا تُستورد عمدًا.

      7. أعد إقران WhatsApp — يستخدم WhatsApp الإقران عبر رمز QR (Baileys)، وليس نقل الـ token. شغّل hermes whatsapp لإجراء الإقران.

      8. تنظيف الأرشيف — بعد التأكد من أن كل شيء يعمل، شغّل hermes claw cleanup لإعادة تسمية مجلدات OpenClaw المتبقية إلى .pre-migration/ (لتجنّب الالتباس في الحالة).

      استكشاف الأخطاء وإصلاحها​

      "OpenClaw directory not found"​

      تتحقق عملية الانتقال من ~/.openclaw/، ثم ~/.clawdbot/، ثم ~/.moltbot/. إذا كان التثبيت لديك في مكان آخر، فاستخدم --source /path/to/your/openclaw.

      "No provider API keys found"​

      قد تكون المفاتيح مخزّنة في عدة أماكن بحسب إصدار OpenClaw لديك: مضمّنة في openclaw.json تحت models.providers.*.apiKey، أو في ~/.openclaw/.env، أو في الكائن الفرعي داخل openclaw.json المسمّى "env"، أو في agents/main/agent/auth-profiles.json. تتحقق عملية الانتقال من الأماكن الأربعة كلها. وإذا كانت المفاتيح تستخدم SecretRefs من نوع source: "file" أو source: "exec"، فلا يمكن حلّها تلقائيًا — أضفها عبر hermes config set.

      المهارات لا تظهر بعد الانتقال​

      توضع المهارات المستوردة في ~/.hermes/skills/openclaw-imports/. ابدأ جلسة جديدة لتسري، أو شغّل /skills للتحقق من تحميلها.

      صوت TTS لم يُنقل​

      تخزّن OpenClaw إعدادات TTS في مكانين: messages.tts.providers.* وإعداد talk على المستوى الأعلى. تتحقق عملية الانتقال من كليهما. وإذا كان معرّف الصوت قد ضُبط عبر واجهة OpenClaw (ويُخزَّن في مسار مختلف)، فقد تحتاج إلى ضبطه يدويًا: hermes config set tts.elevenlabs.voice_id YOUR_VOICE_ID.
