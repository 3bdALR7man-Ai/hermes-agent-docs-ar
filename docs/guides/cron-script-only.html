      مهام Cron بالسكربتات فقط

      أحيانًا تعرف مسبقًا الرسالة التي تريد إرسالها بالضبط. فلا تحتاج إلى وكيل يفكّر فيها، بل تحتاج فقط إلى سكربت يعمل وفق مؤقّت، وأن تصل مخرجاته (إن وُجدت) إلى Telegram / Discord / Slack / Signal.

      يسمّي Hermes ذلك الوضع دون وكيل (no-agent mode). إنه نظام cron نفسه ولكن دون LLM.

         ┌──────────────────┐          ┌──────────────────┐
         │ scheduler tick   │  every   │ run script       │
         │ (every N minutes)│ ──────▶ │ (bash or python) │
         └──────────────────┘          └──────────────────┘
                                                │
                                                │ stdout
                                                ▼
                                       ┌──────────────────┐
                                       │ delivery router  │
                                       │ (telegram/disc…) │
                                       └──────────────────┘
      • لا استدعاء لـ LLM. صفر tokens، وصفر حلقات وكيل، وصفر إنفاق على النماذج.
      • السكربت هو المهمة. السكربت هو من يقرّر ما إذا كان سيرسل تنبيهًا. أخرِج مخرجات ← تُرسَل رسالة. لا تُخرج شيئًا ← دورة صامتة.
      • Bash أو Python. تعمل ملفات .sh / .bash باستخدام bash من PATH عند توفّره، وإلا فباستخدام /bin/bash؛ وأي امتداد آخر يعمل باستخدام مفسّر Python الحالي. يجب أن تُحلّ المسارات داخل ~/.hermes/scripts/ (الصيغ النسبية أو المطلقة أو التي تبدأ بـ ~ مقبولة ما دامت تبقى داخل ذلك المجلد). ولا ترث سكربتات cron بيانات اعتماد المزوّدين من بيئة عملية Hermes إطلاقًا.
      • المُجدوِل نفسه. تعيش هذه المهام في cronjob إلى جانب مهام LLM، فالإيقاف المؤقت والاستئناف والسرد والسجلات وتحديد أهداف التسليم كلها تعمل بالطريقة نفسها.

      متى تستخدمه​

      استخدم الوضع دون وكيل من أجل:

      • مراقبة الذاكرة / القرص / GPU. تعمل كل 5 دقائق، ولا ترسل تنبيهًا إلا عند تجاوز حدّ معيّن.
      • CI hooks. انتهى النشر ← انشر SHA الخاص بالـ commit. فشل البناء ← أرسل آخر 100 سطر من السجل.
      • المقاييس الدورية. "إيرادات Stripe اليومية في الساعة 9 صباحًا" على شكل استدعاء API بسيط مع طباعة منسّقة.
      • أدوات استطلاع الأحداث الخارجية. افحص API، وأرسل تنبيهًا عند تغيّر الحالة.
      • نبضات التحقق (Heartbeats). أرسل ping إلى لوحة تحكم كل N دقيقة لإثبات أن الجهاز المضيف يعمل.

      استخدم مهمة cron عادية (يقودها LLM) عندما تحتاج إلى أن يقرّر الوكيل ما سيقوله، مثل تلخيص مستند طويل، أو اختيار العناصر المثيرة للاهتمام من خلاصة (feed)، أو صياغة رسالة ودّية مفهومة. أما المسار دون وكيل فهو للحالات التي يكون فيها stdout الخاص بالسكربت هو الرسالة نفسها.

      إنشاؤها من المحادثة​

      المكسب الحقيقي للوضع دون وكيل هو أن الوكيل نفسه يستطيع إعداد أداة المراقبة لك، دون محرّر، ودون shell، ودون الحاجة إلى تذكّر خيارات CLI. تصف ما تريده، فيكتب Hermes السكربت ويجدوله ويخبرك متى سيُنفَّذ.

      مثال على محادثة​

      أنت: نبّهني على telegram إذا تجاوزت RAM نسبة 85%، وافحص ذلك كل 5 دقائق

      Hermes: (يكتب ~/.hermes/scripts/memory-watchdog.sh، ثم يستدعي cronjob(...) مع no_agent=true)

      تم الإعداد. تعمل المهمة كل 5 دقائق، وترسل تنبيهًا إلى Telegram فقط عندما تتجاوز RAM نسبة 85%. السكربت: memory-watchdog.sh. معرّف المهمة: abc123.

      في الخلفية، يُجري الوكيل استدعاءين للأدوات:

      # 1. Write the check script
      write_file(
          path="~/.hermes/scripts/memory-watchdog.sh",
          content='''#!/usr/bin/env bash
      ram_pct=$(free | awk '/^Mem:/ {printf "%d", $3 * 100 / $2}')
      if [ "$ram_pct" -ge 85 ]; then
        echo "RAM ${ram_pct}% on $(hostname)"
      fi
      # Empty stdout = silent tick; no message sent.
      ''',
      )

      # 2. Schedule it — no_agent=True skips the LLM on every tick
      cronjob(
          action="create",
          schedule="every 5m",
          script="memory-watchdog.sh",
          no_agent=True,
          deliver="telegram",
          name="memory-watchdog",
      )

      ومن تلك اللحظة تصبح كل دورة مجانية: يشغّل المُجدوِل السكربت، ويمرّر stdout الخاص به إلى Telegram إن لم يكن فارغًا، ولا يلمس أي نموذج إطلاقًا.

      ما يقرّره الوكيل نيابةً عنك​

      عندما تصوغ طلبًا مثل "نبّهني عندما يحدث X" أو "افحص Y كل N دقيقة وأخبرني إذا حدث Z"، فإن وصف الأداة cronjob في Hermes يوجّهه إلى اختيار no_agent=True كلما كان محتوى الرسالة محدّدًا بالكامل بواسطة السكربت. ويرجع إلى المسار العادي الذي يقوده LLM عندما يحتاج الطلب إلى استدلال ("لخّص الـ issues الجديدة"، "اختر العناوين الأكثر إثارة للاهتمام"، "صُغ تذكيرًا ودّيًا").

      لست مضطرًا إلى تحديد --no-agent بنفسك. يكفي أن تصف السلوك المطلوب.

      إدارة أدوات المراقبة من المحادثة​

      يستطيع الوكيل إيقاف المهام مؤقتًا واستئنافها وتعديلها وإزالتها بالطريقة نفسها التي ينشئها بها:

      أنت: أوقف مراقبة الذاكرة الليلة

      Hermes: (يستدعي cronjob(action='pause', job_id='abc123'))

      تم الإيقاف المؤقت. يمكنك الاستئناف بقول "أعد تشغيلها" أو عبر hermes cron resume abc123.

      أنت: غيّرها لتعمل كل 15 دقيقة

      Hermes: (يستدعي cronjob(action='update', job_id='abc123', schedule='every 15m'))

      دورة الحياة الكاملة (الإنشاء / السرد / التحديث / الإيقاف المؤقت / الاستئناف / التشغيل الفوري / الإزالة) متاحة للوكيل دون أن تحتاج إلى تعلّم أي أوامر CLI.

      إنشاؤها من CLI​

      تفضّل الـ shell؟ يمنحك مسار CLI النتيجة نفسها بثلاثة أوامر:

      # 1. Write your script
      cat > ~/.hermes/scripts/memory-watchdog.sh <<'EOF'
      #!/usr/bin/env bash
      # Alert when RAM usage is over 85%. Silent otherwise.
      RAM_PCT=$(free | awk '/^Mem:/ {printf "%d", $3 * 100 / $2}')
      if [ "$RAM_PCT" -ge 85 ]; then
        echo "⚠ RAM ${RAM_PCT}% on $(hostname)"
      fi
      # Empty stdout = silent run; no message sent.
      EOF
      chmod +x ~/.hermes/scripts/memory-watchdog.sh

      # 2. Schedule it
      hermes cron create "every 5m" \
        --no-agent \
        --script memory-watchdog.sh \
        --deliver telegram \
        --name "memory-watchdog"

      # 3. Verify
      hermes cron list
      hermes cron run <job_id>    # fire it once to test

      هذا كل شيء. لا prompt، ولا مهارة، ولا نموذج.

      كيف تتحوّل مخرجات السكربت إلى تسليم​

      سلوك السكربتالنتيجة
      رمز خروج 0، و stdout غير فارغيُسلَّم stdout كما هو حرفيًا
      رمز خروج 0، و stdout فارغدورة صامتة — لا تسليم
      رمز خروج 0، و stdout يحتوي على {"wakeAgent": false} في السطر الأخيردورة صامتة (بوابة مشتركة مع مهام LLM)
      رمز خروج غير صفرييُسلَّم تنبيه بالخطأ (حتى لا تتعطّل أداة المراقبة بصمت)
      انتهاء مهلة السكربتيُسلَّم تنبيه بالخطأ

      سلوك "الصمت عند الفراغ" هو مفتاح نمط المراقبة الكلاسيكي: يمكن للسكربت أن يعمل كل دقيقة بحرية، لكن القناة لا ترى رسالة إلا عندما يحتاج شيء ما إلى انتباه فعلًا.

      قواعد السكربتات​

      يجب أن توجد السكربتات في ~/.hermes/scripts/. ويُفرض ذلك عند إنشاء المهمة وعند تشغيلها معًا، إذ تُرفض المسارات المطلقة وتوسيع ~/ وأنماط اجتياز المسارات (../). ويُشارَك المجلد نفسه مع بوابة سكربت الفحص المسبق التي تستخدمها مهام LLM.

      يُختار المفسّر بحسب امتداد الملف:

      الامتدادالمفسّر
      .sh, .bashbash من PATH (الاحتياطي /bin/bash)
      أي امتداد آخرsys.executable (مفسّر Python الحالي)

      نحن عمدًا لا نعتدّ بسطور shebang من نوع #!/...، فإبقاء مجموعة المفسّرات صريحة وصغيرة يقلّل المساحة التي يثق بها المُجدوِل.

      صياغة الجدولة​

      مثل جميع مهام cron الأخرى:

      hermes cron create "every 5m"        # interval
      hermes cron create "every 2h"
      hermes cron create "0 9 * * *"       # standard cron: 9am daily
      hermes cron create "30m"             # one-shot: run once in 30 minutes

      راجع مرجع ميزة cron للاطلاع على الصياغة الكاملة.

      أهداف التسليم​

      يقبل --deliver كل ما يعرفه الـ gateway. إليك بعض الصيغ الشائعة:

      --deliver telegram                       # platform home channel
      --deliver telegram:-1001234567890        # specific chat
      --deliver telegram:-1001234567890:17585  # specific Telegram forum topic
      --deliver discord:#ops
      --deliver slack:#engineering
      --deliver signal:+15551234567
      --deliver local                          # just save to ~/.hermes/cron/output/

      لا يلزم وجود gateway قيد التشغيل وقت تشغيل السكربت بالنسبة إلى المنصات التي تعتمد على bot token (Telegram و Discord و Slack و Signal و SMS و WhatsApp)، إذ تستدعي الأداة REST endpoint الخاص بكل منصة مباشرةً باستخدام بيانات الاعتماد الموجودة مسبقًا في ~/.hermes/.env / ~/.hermes/config.yaml.

      التعديل ودورة الحياة​

      hermes cron list                                    # see all jobs
      hermes cron pause <job_id>                          # stop firing, keep definition
      hermes cron resume <job_id>
      hermes cron edit <job_id> --schedule "every 10m"    # adjust cadence
      hermes cron edit <job_id> --agent                   # flip to LLM mode
      hermes cron edit <job_id> --no-agent --script …     # flip back
      hermes cron remove <job_id>                         # delete it

      كل ما يعمل على مهام LLM (الإيقاف المؤقت، والاستئناف، والتشغيل اليدوي، وتغيير أهداف التسليم) يعمل على المهام دون وكيل أيضًا.

      مثال عملي: تنبيه مساحة القرص​

      cat > ~/.hermes/scripts/disk-alert.sh <<'EOF'
      #!/usr/bin/env bash
      # Alert when / or /home is over 90% full.
      THRESHOLD=90
      df -h / /home 2>/dev/null | awk -v t="$THRESHOLD" '
        NR > 1 && $5+0 >= t {
          printf "⚠ Disk %s full on %s\n", $5, $6
        }
      '
      EOF
      chmod +x ~/.hermes/scripts/disk-alert.sh

      hermes cron create "*/15 * * * *" \
        --no-agent \
        --script disk-alert.sh \
        --deliver telegram \
        --name "disk-alert"

      يبقى صامتًا ما دام نظاما الملفات كلاهما دون 90%؛ وعندما يمتلئ أحدهما، يُطلق سطرًا واحدًا بالضبط لكل نظام ملفات تجاوز الحد.

      مقارنة بالأنماط الأخرى​

      النهجما الذي يعملمتى تستخدمه
      cronjob --no-agent (هذه الصفحة)سكربتك وفق جدول Hermesأدوات المراقبة / التنبيهات / المقاييس المتكررة التي لا تحتاج إلى استدلال
      cronjob (الافتراضي، LLM)الوكيل مع سكربت فحص مسبق اختياريعندما يتطلّب محتوى الرسالة استدلالًا على البيانات
      cron نظام التشغيل + curl إلى اشتراك webhookسكربتك وفق جدول نظام التشغيلعندما قد يكون Hermes نفسه في حالة غير سليمة (أي أنه الشيء الذي تراقبه)

      بالنسبة إلى أدوات مراقبة سلامة النظام الحرجة التي يجب أن تعمل حتى عندما يكون الـ gateway متوقفًا، استخدم cron على مستوى نظام التشغيل مع curl بسيط إلى اشتراك webhook في Hermes (أو إلى أي endpoint خارجي للتنبيهات)، فهذه تعمل كعمليات مستقلة في نظام التشغيل ولا تعتمد على كون Hermes قيد التشغيل. أما المُجدوِل المدمج في الـ gateway فهو الخيار الصحيح عندما يكون الشيء المُراقَب خارجيًا.

      ذو صلة​

      • أتمتة أي شيء باستخدام Cron — أنماط cron التي يقودها LLM.
      • مرجع المهام المجدولة (Cron) — صياغة الجدولة الكاملة، ودورة الحياة، وتوجيه التسليم.
      • اشتراكات Webhook — نقاط دخول HTTP من نوع أرسِل وانسَ (fire-and-forget) للمُجدوِلات الخارجية.
      • آلية عمل Gateway من الداخل — الآليات الداخلية لموجّه التسليم.
