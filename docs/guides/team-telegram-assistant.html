      إعداد مساعد Telegram للفريق

      يرشدك هذا الدرس التطبيقي خطوة بخطوة إلى إعداد بوت Telegram يعمل بـ Hermes Agent ويمكن لعدة أعضاء في الفريق استخدامه. في النهاية، سيكون لدى فريقك مساعد ذكاء اصطناعي مشترك يمكنهم مراسلته لطلب المساعدة في الكود، والبحث، وإدارة الأنظمة، وأي شيء آخر — مع حماية قائمة على تفويض كل مستخدم على حدة.

      ما الذي سنبنيه​

      بوت Telegram يتميّز بما يلي:

      • يمكن لأي عضو مصرّح له في الفريق مراسلته مباشرةً لطلب المساعدة — مراجعات الكود، والبحث، وأوامر الـ shell، وتصحيح الأخطاء
      • يعمل على خادمك مع وصول كامل إلى الأدوات — الطرفية، وتحرير الملفات، والبحث في الويب، وتنفيذ الكود
      • جلسات منفصلة لكل مستخدم — يحصل كل شخص على سياق محادثة خاص به
      • آمن افتراضيًا — لا يمكن التفاعل معه إلا للمستخدمين الموافَق عليهم، مع طريقتين للتفويض
      • مهام مجدولة — اجتماعات standup اليومية، وفحوص السلامة، والتذكيرات، تُسلَّم إلى قناة الفريق

      المتطلبات المسبقة​

      قبل البدء، تأكد من توفّر ما يلي:

      • تثبيت Hermes Agent على خادم أو VPS (وليس على حاسوبك المحمول — إذ يجب أن يبقى البوت قيد التشغيل). اتبع دليل التثبيت إن لم تكن قد ثبّته بعد.
      • حساب Telegram خاص بك (بصفتك مالك البوت)
      • مزوّد LLM مُعدّ — على الأقل، مفتاح API لـ OpenAI أو Anthropic أو أي مزوّد آخر مدعوم في ~/.hermes/.env
      نصيحة

      يكفي VPS بتكلفة 5$ شهريًا لتشغيل الـ gateway. فـ Hermes نفسه خفيف — أما التكلفة الحقيقية فتأتي من استدعاءات LLM API، وهي تحدث عن بُعد.

      الخطوة 1: إنشاء بوت Telegram​

      يبدأ كل بوت Telegram مع @BotFather — وهو البوت الرسمي من Telegram لإنشاء البوتات.

      1. افتح Telegram وابحث عن @BotFather، أو انتقل إلى t.me/BotFather

      2. أرسل /newbot — سيسألك BotFather عن أمرين:

        • الاسم المعروض (Display name) — ما يراه المستخدمون (مثل Team Hermes Assistant)
        • اسم المستخدم (Username) — يجب أن ينتهي بـ bot (مثل myteam_hermes_bot)

      3. انسخ token البوت — سيرد BotFather برسالة مشابهة لما يلي:

        Use this token to access the HTTP API:
        7123456789:AAH1bGciOiJSUzI1NiIsInR5cCI6Ikp...

        احفظ هذا الـ token — ستحتاج إليه في الخطوة التالية.

      4. اضبط وصفًا للبوت (اختياري لكنه موصى به):

        /setdescription

        اختر البوت الخاص بك، ثم أدخل نصًا مثل:

        Team AI assistant powered by Hermes Agent. DM me for help with code, research, debugging, and more.

      5. اضبط أوامر البوت (اختياري — يمنح المستخدمين قائمة بالأوامر):

        /setcommands

        اختر البوت الخاص بك، ثم الصق:

        new - Start a fresh conversation
        model - Show or change the AI model
        status - Show session info
        help - Show available commands
        stop - Stop the current task
      تحذير

      حافظ على سرية token البوت، فأي شخص يملكه يستطيع التحكم في البوت. إذا تسرّب، فاستخدم /revoke في BotFather لتوليد token جديد.

      الخطوة 2: إعداد الـ Gateway​

      أمامك خياران: معالج الإعداد التفاعلي (موصى به) أو الإعداد اليدوي.

      الخيار A: الإعداد التفاعلي (موصى به)​

      hermes gateway setup

      يرشدك هذا المعالج خلال كل الخطوات مع إمكانية الاختيار بمفاتيح الأسهم. اختر Telegram، والصق token البوت، ثم أدخل معرّف المستخدم الخاص بك عندما يُطلب منك ذلك.

      الخيار B: الإعداد اليدوي​

      أضف هذه الأسطر إلى ~/.hermes/.env:

      # Telegram bot token from BotFather
      TELEGRAM_BOT_TOKEN=7123456789:AAH1bGciOiJSUzI1NiIsInR5cCI6Ikp...

      # Your Telegram user ID (numeric)
      TELEGRAM_ALLOWED_USERS=123456789

      العثور على معرّف المستخدم الخاص بك​

      معرّف المستخدم في Telegram قيمة رقمية (وليس اسم المستخدم). للعثور عليه:

      1. راسل @userinfobot على Telegram
      2. سيرد فورًا بمعرّف المستخدم الرقمي الخاص بك
      3. انسخ هذا الرقم إلى TELEGRAM_ALLOWED_USERS
      معلومة

      معرّفات المستخدمين في Telegram أرقام دائمة مثل 123456789، وهي تختلف عن @username الذي يمكن تغييره. استخدم دائمًا المعرّف الرقمي في قوائم السماح (allowlists).

      الخطوة 3: تشغيل الـ Gateway​

      اختبار سريع​

      شغّل الـ gateway في الواجهة الأمامية (foreground) أولًا للتأكد من أن كل شيء يعمل:

      hermes gateway

      من المفترض أن ترى مخرجات مثل:

      [Gateway] Starting Hermes Gateway...
      [Gateway] Telegram adapter connected
      [Gateway] Cron scheduler started (tick every 60s)

      افتح Telegram، وابحث عن البوت الخاص بك، وأرسل إليه رسالة. إذا ردّ عليك، فكل شيء جاهز. اضغط Ctrl+C للإيقاف.

      بيئة الإنتاج: التثبيت كخدمة​

      للحصول على نشر دائم يصمد أمام إعادة التشغيل:

      hermes gateway install
      sudo hermes gateway install --system   # Linux only: boot-time system service

      يُنشئ هذا خدمة تعمل في الخلفية: خدمة systemd على مستوى المستخدم في Linux افتراضيًا، أو خدمة launchd على macOS، أو خدمة نظام في Linux تعمل عند الإقلاع إذا مرّرت --system.

      # Linux — manage the default user service
      hermes gateway start
      hermes gateway stop
      hermes gateway status

      # View live logs
      journalctl --user -u hermes-gateway -f

      # Keep running after SSH logout
      sudo loginctl enable-linger $USER

      # Linux servers — explicit system-service commands
      sudo hermes gateway start --system
      sudo hermes gateway status --system
      journalctl -u hermes-gateway -f
      # macOS — manage the service
      hermes gateway start
      hermes gateway stop
      tail -f ~/.hermes/logs/gateway.log
      متغير PATH في macOS

      يلتقط ملف launchd plist قيمة PATH الخاصة بالـ shell لديك وقت التثبيت، حتى تتمكن العمليات الفرعية للـ gateway من العثور على أدوات مثل Node.js و ffmpeg. إذا ثبّتَّ أدوات جديدة لاحقًا، فأعد تنفيذ hermes gateway install لتحديث ملف plist.

      التحقق من أنه يعمل​

      hermes gateway status

      ثم أرسل رسالة تجريبية إلى البوت على Telegram. من المفترض أن تتلقى ردًا خلال ثوانٍ قليلة.

      الخطوة 4: إعداد وصول الفريق​

      لنمنح الآن زملاءك صلاحية الوصول. هناك أسلوبان لذلك.

      الأسلوب A: قائمة سماح ثابتة​

      اجمع معرّف Telegram لكل عضو في الفريق (اطلب منهم مراسلة @userinfobot) وأضفها كقائمة مفصولة بفواصل:

      # In ~/.hermes/.env
      TELEGRAM_ALLOWED_USERS=123456789,987654321,555555555

      أعد تشغيل الـ gateway بعد إجراء التغييرات:

      hermes gateway stop && hermes gateway start

      الأسلوب B: الاقتران عبر DM (موصى به للفرق)​

      الاقتران عبر الرسائل المباشرة (DM pairing) أكثر مرونة — إذ لا تحتاج إلى جمع معرّفات المستخدمين مسبقًا. إليك آلية عمله:

      1. يراسل زميلك البوت مباشرةً — ولأنه ليس ضمن قائمة السماح، يرد البوت برمز اقتران يُستخدم مرة واحدة:

        🔐 Pairing code: XKGH5N7P
        Send this code to the bot owner for approval.

      2. يرسل إليك زميلك الرمز (عبر أي قناة — Slack، أو البريد الإلكتروني، أو شخصيًا)

      3. توافق أنت عليه على الخادم:

        hermes pairing approve telegram XKGH5N7P

      4. يصبح لديه وصول — ويبدأ البوت فورًا في الرد على رسائله

      إدارة المستخدمين المقترنين:

      # See all pending and approved users
      hermes pairing list

      # Revoke someone's access
      hermes pairing revoke telegram 987654321

      # Clear expired pending codes
      hermes pairing clear-pending
      نصيحة

      يُعد الاقتران عبر DM مثاليًا للفرق لأنك لا تحتاج إلى إعادة تشغيل الـ gateway عند إضافة مستخدمين جدد، إذ تسري الموافقات فورًا.

      اعتبارات أمنية​

      • لا تضبط أبدًا GATEWAY_ALLOW_ALL_USERS=true على بوت لديه وصول إلى الطرفية — فأي شخص يعثر على البوت قد يتمكن من تنفيذ أوامر على خادمك
      • تنتهي صلاحية رموز الاقتران بعد ساعة واحدة، وتُولَّد بعشوائية تشفيرية
      • يمنع حدّ المعدل (rate limit) هجمات التخمين (brute-force): طلب واحد لكل مستخدم كل 10 دقائق، وبحد أقصى 3 رموز معلّقة لكل منصة
      • بعد 5 محاولات موافقة فاشلة، تدخل المنصة في حظر مؤقت لمدة ساعة واحدة
      • تُخزَّن جميع بيانات الاقتران بصلاحيات chmod 0600

      الخطوة 5: إعداد البوت​

      تعيين قناة رئيسية​

      القناة الرئيسية (home channel) هي المكان الذي يسلّم إليه البوت نتائج مهام cron والرسائل الاستباقية. ومن دونها، لن تجد المهام المجدولة مكانًا ترسل إليه مخرجاتها.

      الخيار 1: استخدم الأمر /sethome في أي مجموعة أو محادثة على Telegram يكون البوت عضوًا فيها.

      الخيار 2: اضبطها يدويًا في ~/.hermes/.env:

      TELEGRAM_HOME_CHANNEL=-1001234567890
      TELEGRAM_HOME_CHANNEL_NAME="Team Updates"

      للعثور على معرّف القناة، أضف @userinfobot إلى المجموعة — وسيُبلغك بمعرّف المحادثة (chat ID) الخاص بالمجموعة.

      إعداد عرض تقدّم الأدوات​

      تحكّم في مقدار التفاصيل التي يعرضها البوت عند استخدام الأدوات. في ~/.hermes/config.yaml:

      display:
        tool_progress: new    # off | new | all | verbose
      الوضعما تراه
      offردود نظيفة فقط — دون أي نشاط للأدوات
      newحالة موجزة لكل استدعاء أداة جديد (موصى به للمراسلة)
      allكل استدعاء أداة مع تفاصيله
      verboseمخرجات الأدوات كاملة بما في ذلك نتائج الأوامر

      يمكن للمستخدمين أيضًا تغيير ذلك لكل جلسة على حدة باستخدام الأمر /verbose في المحادثة.

      إعداد شخصية للبوت عبر SOUL.md​

      خصّص أسلوب تواصل البوت بتعديل ~/.hermes/SOUL.md:

      للاطلاع على دليل كامل، راجع استخدام SOUL.md مع Hermes.

      # Soul
      You are a helpful team assistant. Be concise and technical.
      Use code blocks for any code. Skip pleasantries — the team
      values directness. When debugging, always ask for error logs
      before guessing at solutions.

      إضافة سياق المشروع​

      إذا كان فريقك يعمل على مشاريع محددة، فأنشئ ملفات سياق حتى يعرف البوت الـ stack التقني الذي تستخدمونه:

      <!-- ~/.hermes/AGENTS.md -->
      # Team Context
      - We use Python 3.12 with FastAPI and SQLAlchemy
      - Frontend is React with TypeScript
      - CI/CD runs on GitHub Actions
      - Production deploys to AWS ECS
      - Always suggest writing tests for new code
      معلومة

      تُحقن ملفات السياق في system prompt لكل جلسة. اجعلها موجزة — فكل حرف يُحتسب من ميزانية الـ tokens لديك.

      الخطوة 6: إعداد المهام المجدولة​

      بعد تشغيل الـ gateway، يمكنك جدولة مهام متكررة تسلّم نتائجها إلى قناة فريقك.

      ملخّص Standup اليومي​

      راسل البوت على Telegram:

      Every weekday at 9am, check the GitHub repository at
      github.com/myorg/myproject for:
      1. Pull requests opened/merged in the last 24 hours
      2. Issues created or closed
      3. Any CI/CD failures on the main branch
      Format as a brief standup-style summary.

      يُنشئ الوكيل مهمة cron تلقائيًا ويسلّم النتائج إلى المحادثة التي طلبت منها ذلك (أو إلى القناة الرئيسية).

      فحص سلامة الخادم​

      Every 6 hours, check disk usage with 'df -h', memory with 'free -h',
      and Docker container status with 'docker ps'. Report anything unusual —
      partitions above 80%, containers that have restarted, or high memory usage.

      إدارة المهام المجدولة​

      # From the CLI
      hermes cron list          # View all scheduled jobs
      hermes cron status        # Check if scheduler is running

      # From Telegram chat
      /cron list                # View jobs
      /cron remove <job_id>     # Remove a job
      تحذير

      تعمل prompts مهام cron في جلسات جديدة تمامًا دون أي ذاكرة للمحادثات السابقة. تأكد من أن كل prompt يتضمن كل السياق الذي يحتاجه الوكيل — مسارات الملفات، والـ URLs، وعناوين الخوادم، والتعليمات الواضحة.

      نصائح لبيئة الإنتاج​

      استخدم Docker للأمان​

      في بوت فريق مشترك، استخدم Docker كـ terminal backend حتى تُنفَّذ أوامر الوكيل داخل حاوية بدلًا من جهازك المضيف:

      # In ~/.hermes/.env
      TERMINAL_ENV=docker
      TERMINAL_DOCKER_IMAGE=nikolaik/python-nodejs:python3.11-nodejs20

      أو في ~/.hermes/config.yaml:

      terminal:
        backend: docker
        container_cpu: 1
        container_memory: 5120
        container_persistent: true

      بهذه الطريقة، حتى لو طلب أحدهم من البوت تنفيذ شيء مدمّر، يبقى نظامك المضيف محميًا.

      مراقبة الـ Gateway​

      # Check if the gateway is running
      hermes gateway status

      # Watch live logs (Linux)
      journalctl --user -u hermes-gateway -f

      # Watch live logs (macOS)
      tail -f ~/.hermes/logs/gateway.log

      إبقاء Hermes محدّثًا​

      من Telegram، أرسل /update إلى البوت — وسيسحب أحدث إصدار ثم يعيد التشغيل. أو من الخادم:

      hermes update
      hermes gateway stop && hermes gateway start

      مواقع السجلات​

      العنصرالموقع
      سجلات الـ Gatewayjournalctl --user -u hermes-gateway (Linux) أو ~/.hermes/logs/gateway.log (macOS)
      مخرجات مهام cron~/.hermes/cron/output/{job_id}/{timestamp}.md
      تعريفات مهام cron~/.hermes/cron/jobs.json
      بيانات الاقتران~/.hermes/pairing/
      سجل الجلسات~/.hermes/sessions/

      التعمّق أكثر​

      أصبح لديك الآن مساعد Telegram يعمل لفريقك. إليك بعض الخطوات التالية:

      • دليل الأمان — نظرة معمّقة على التفويض، وعزل الحاويات، والموافقة على الأوامر
      • Messaging Gateway — مرجع كامل لبنية الـ gateway، وإدارة الجلسات، وأوامر المحادثة
      • إعداد Telegram — تفاصيل خاصة بالمنصة، بما في ذلك الرسائل الصوتية و TTS
      • المهام المجدولة — جدولة cron متقدمة مع خيارات التسليم وتعبيرات cron
      • ملفات السياق (Context Files) — ملفات AGENTS.md و SOUL.md و .cursorrules لتزويد الوكيل بمعرفة المشروع
      • الشخصية — إعدادات الشخصية المسبقة المدمجة وتعريفات الشخصيات المخصصة
      • أضف مزيدًا من المنصات — يمكن للـ gateway نفسه تشغيل Discord وSlack وWhatsApp في آن واحد

      لديك أسئلة أو واجهت مشكلات؟ افتح issue على GitHub — نرحّب بالمساهمات.
