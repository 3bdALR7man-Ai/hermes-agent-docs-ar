      MiniMax OAuth

      يدعم Hermes Agent خدمة MiniMax عبر تدفّق تسجيل دخول OAuth قائم على المتصفح، باستخدام بيانات الاعتماد نفسها الخاصة بـ بوابة MiniMax. لا حاجة إلى مفتاح API أو بطاقة ائتمان — سجّل الدخول مرة واحدة، ويجدّد Hermes جلستك تلقائيًا.

      يعيد النقل استخدام محوّل anthropic_messages (تعرض MiniMax endpoint متوافقًا مع Anthropic Messages على /anthropic)، لذا تعمل جميع ميزات استدعاء الأدوات والبث والسياق الحالية دون أي تغيير في المحوّل.

      نظرة عامة​

      العنصرالقيمة
      معرّف المزوّدminimax-oauth
      الاسم المعروضMiniMax (OAuth)
      نوع المصادقةOAuth عبر المتصفح (تدفّق إعادة توجيه PKCE)
      النقلمتوافق مع Anthropic Messages (anthropic_messages)
      النماذجMiniMax-M2.7، MiniMax-M2.7-highspeed
      Endpoint العالميhttps://api.minimax.io/anthropic
      Endpoint الصينhttps://api.minimaxi.com/anthropic
      يتطلب متغير بيئةلا (MINIMAX_API_KEY لا يُستخدم لهذا المزوّد)

      المتطلبات الأساسية​

      • Python 3.9 أو أحدث
      • تثبيت Hermes Agent
      • حساب MiniMax على minimax.io (عالمي) أو minimaxi.com (الصين)
      • متصفح متاح على الجهاز المحلي (أو استخدم --no-browser للجلسات البعيدة)

      البدء السريع​

      # Launch the provider and model picker
      hermes model
      # → Select "MiniMax (OAuth)" from the provider list
      # → Hermes opens your browser to the MiniMax authorization page
      # → Approve access in the browser
      # → Select a model (MiniMax-M2.7 or MiniMax-M2.7-highspeed)
      # → Start chatting

      hermes

      بعد تسجيل الدخول الأول، تُخزَّن بيانات الاعتماد تحت ~/.hermes/auth.json ويتم تجديدها تلقائيًا قبل كل جلسة.

      تسجيل الدخول يدويًا​

      يمكنك بدء تسجيل الدخول دون المرور بقائمة اختيار النموذج:

      hermes auth add minimax-oauth

      منطقة الصين​

      إذا كان حسابك على منصة الصين (minimaxi.com)، استخدم بدلًا من ذلك مزوّد minimax-cn القائم على مفتاح API — إذ إن minimax-cn مسجَّل بـ auth_type="api_key" فقط (بدون تدفّق OAuth). اضبط MINIMAX_CN_API_KEY (واختياريًا MINIMAX_CN_BASE_URL) مباشرة:

      echo 'MINIMAX_CN_API_KEY=your-key' >> ~/.hermes/.env

      الجلسات البعيدة / بلا واجهة (headless)​

      على الخوادم أو الحاويات التي لا يتوفر فيها متصفح:

      hermes auth add minimax-oauth --no-browser

      سيطبع Hermes رابط التحقق ورمز المستخدم — افتح الرابط على أي جهاز وأدخل الرمز عند الطلب.

      تدفّق OAuth​

      ينفّذ Hermes تدفّق OAuth عبر المتصفح باستخدام PKCE مقابل نقاط نهاية OAuth الخاصة بـ MiniMax:

      1. يولّد Hermes زوج تحقّق/تحدٍّ (verifier / challenge) PKCE وقيمة state عشوائية.
      2. يرسل طلب POST إلى {base_url}/oauth/code مع التحدي ويستلم user_code و verification_uri.
      3. يفتح متصفحك verification_uri. إذا طُلب منك، أدخل user_code.
      4. يستطلع Hermes {base_url}/oauth/token إلى أن يصل الرمز (أو تنتهي المهلة).
      5. تُحفظ الرموز (access_token، refresh_token، تاريخ الانتهاء) في ~/.hermes/auth.json تحت المفتاح minimax-oauth.

      يُشغَّل تجديد الرمز (منح refresh_token القياسي في OAuth) تلقائيًا عند بدء كل جلسة عندما يكون رمز الوصول على بعد 60 ثانية من انتهاء صلاحيته.

      التحقق من حالة تسجيل الدخول​

      hermes doctor

      سيعرض قسم ◆ Auth Providers:

      ✓ MiniMax OAuth  (logged in, region=global)

      أو، إن لم تكن مسجّل الدخول:

      ⚠ MiniMax OAuth  (not logged in)

      تبديل النماذج​

      hermes model
      # → Select "MiniMax (OAuth)"
      # → Pick from the model list

      أو اضبط النموذج مباشرة:

      hermes config set model.default MiniMax-M2.7
      hermes config set model.provider minimax-oauth

      مرجع الإعدادات​

      بعد تسجيل الدخول، سيحتوي ~/.hermes/config.yaml على إدخالات مشابهة لـ:

      model:
        default: MiniMax-M2.7
        provider: minimax-oauth
        base_url: https://api.minimax.io/anthropic

      نقاط نهاية المناطق​

      معرّف المزوّدالبوابةنقطة نهاية الاستدلال
      minimax-oauth (عالمي)https://api.minimax.iohttps://api.minimax.io/anthropic
      minimax-cn (الصين)https://api.minimaxi.comhttps://api.minimaxi.com/anthropic

      أسماء المزوّد المستعارة​

      تشير جميع ما يلي إلى minimax-oauth:

      hermes --provider minimax-oauth    # canonical
      hermes --provider minimax-portal   # alias
      hermes --provider minimax-global   # alias
      hermes --provider minimax_oauth    # alias (underscore form)

      متغيرات البيئة​

      مزوّد minimax-oauth لا يستخدم MINIMAX_API_KEY أو MINIMAX_BASE_URL. هذان المتغيران مخصّصان فقط لمزوّدَي minimax و minimax-cn القائمَين على مفتاح API.

      المتغيرالتأثير
      MINIMAX_API_KEYيُستخدم فقط بواسطة مزوّد minimax — يُتجاهل مع minimax-oauth
      MINIMAX_CN_API_KEYيُستخدم فقط بواسطة مزوّد minimax-cn — يُتجاهل مع minimax-oauth

      لاستخدام minimax-oauth كمزوّد نشط، اضبط model.provider: minimax-oauth في config.yaml (استخدم hermes setup لتدفّق موجَّه)، أو مرّر --provider minimax-oauth لاستدعاء واحد:

      hermes --provider minimax-oauth

      النماذج​

      النموذجالأنسب لـ
      MiniMax-M2.7الاستدلال بسياق طويل، استدعاء الأدوات المعقّد
      MiniMax-M2.7-highspeedزمن استجابة أقل، مهام أخف، الاستدعاءات المساعدة

      يدعم كلا النموذجين سياقًا يصل إلى 200,000 token.

      يُستخدم MiniMax-M2.7 أيضًا تلقائيًا كنموذج مساعد لمهام الرؤية (vision) والتفويض عندما يكون minimax-oauth هو المزوّد الأساسي.

      استكشاف الأخطاء وإصلاحها​

      انتهت صلاحية الرمز (token) — لا يعيد تسجيل الدخول تلقائيًا​

      يجدّد Hermes الرمز عند بدء كل جلسة إذا كان على بعد 60 ثانية من انتهاء صلاحيته. إذا كان رمز الوصول منتهي الصلاحية بالفعل (مثلًا بعد فترة طويلة دون اتصال)، يحدث التجديد تلقائيًا عند الطلب التالي. إذا فشل التجديد بخطأ refresh_token_reused أو invalid_grant، يُعلِّم Hermes الجلسة بأنها تحتاج إلى إعادة تسجيل دخول.

      عندما يكون فشل التجديد نهائيًا (HTTP 4xx، أو invalid_grant، أو منح مُلغى، وما شابه)، يُعلِّم Hermes رمز التجديد بأنه ميت ويعزله محليًا حتى لا يستمر في إعادة محاولة تبادل محكوم عليه بالفشل. يعرض الوكيل رسالة واحدة تفيد بـ"لزوم إعادة المصادقة" ويتوقف عن التدخل إلى أن تسجّل الدخول مرة أخرى.

      الحل: شغّل hermes auth add minimax-oauth مرة أخرى لبدء تسجيل دخول جديد. يُزال الحجر (quarantine) عند أول تبادل ناجح تالٍ.

      انتهت مهلة التفويض​

      لتدفّق رمز الجهاز (device code) نافذة انتهاء صلاحية محدودة. إذا لم توافق على تسجيل الدخول في الوقت المحدد، يُطلق Hermes خطأ انتهاء مهلة.

      الحل: أعد تشغيل hermes auth add minimax-oauth (أو hermes model). يبدأ التدفّق من جديد.

      عدم تطابق state (احتمال CSRF)​

      اكتشف Hermes أن قيمة state التي أعادها خادم التفويض لا تطابق ما أرسله.

      الحل: أعد تشغيل تسجيل الدخول. إذا استمرت المشكلة، تحقّق من وجود وكيل (proxy) أو إعادة توجيه يعدّل استجابة OAuth.

      تسجيل الدخول من خادم بعيد​

      إذا تعذّر على hermes فتح نافذة متصفح، استخدم --no-browser:

      hermes auth add minimax-oauth --no-browser

      يطبع Hermes الرابط والرمز. افتح الرابط على أي جهاز وأكمل التدفّق هناك.

      خطأ "Not logged into MiniMax OAuth" أثناء التشغيل​

      لا يحتوي مخزن المصادقة على بيانات اعتماد لـ minimax-oauth. إما أنك لم تسجّل الدخول بعد، أو أن ملف بيانات الاعتماد قد حُذف.

      الحل: شغّل hermes model واختر MiniMax (OAuth)، أو شغّل hermes auth add minimax-oauth.

      تسجيل الخروج​

      لإزالة بيانات اعتماد MiniMax OAuth المخزّنة:

      hermes auth logout minimax-oauth
