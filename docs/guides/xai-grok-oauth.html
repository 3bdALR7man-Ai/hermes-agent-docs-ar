      xAI Grok OAuth (SuperGrok / X Premium+)

      يدعم Hermes Agent xAI Grok عبر تدفّق تسجيل دخول OAuth بمعرّف جهاز (device-code) عبر المتصفح مقابل accounts.x.ai، باستخدام إما اشتراك SuperGrok (grok.com) أو اشتراك X Premium+ (حساب X مرتبط). لا حاجة إلى XAI_API_KEY — سجّل الدخول مرة واحدة وسيقوم Hermes تلقائيًا بتجديد جلستك في الخلفية.

      عندما تسجّل الدخول بحساب X يملك اشتراك Premium+، تربط xAI تلقائيًا حالة الاشتراك بجلستك على xAI، لذا يعمل تدفّق OAuth بنفس الطريقة التي يعمل بها لدى مشتركي SuperGrok المباشرين.

      يعيد النقل استخدام مهايئ codex_responses (تعرض xAI endpoint على نمط Responses)، لذا يعمل الاستدلال (reasoning) واستدعاء الأدوات (tool-calling) والبث (streaming) وتخزين الـ prompt المؤقت دون أي تعديلات على المهايئ.

      يُعاد استخدام نفس رمز الحامل (bearer token) الخاص بـ OAuth أيضًا في كل واجهة تتعامل مباشرة مع xAI في Hermes — TTS وتوليد الصور وتوليد الفيديو والنسخ الصوتي — بحيث يغطّي تسجيل دخول واحد الأربعة جميعًا.

      المتطلبات الأساسية​

      • Python بإصدار 3.9 أو أحدث
      • تثبيت Hermes Agent
      • اشتراك SuperGrok نشط في حساب xAI الخاص بك، أو اشتراك X Premium+ في حساب X الذي تسجّل الدخول به (تربط xAI الاشتراك تلقائيًا)
      • متصفح متاح في أي مكان يمكنك فيه فتح رابط التحقّق المطبوع
      قد تقيّد xAI الوصول إلى API عبر OAuth حسب المستوى

      تفرض خلفية xAI قائمة سماح (allowlist) خاصة بها على سطح API الخاص بـ OAuth، وقد لوحظ أنها ترفض مشتركي SuperGrok القياسيين برمز HTTP 403 (انظر المشكلة #26847) حتى مع أن الاشتراك داخل التطبيق نشط. إذا نجح تسجيل الدخول عبر OAuth في المتصفح لكن الاستدلال يعيد 403، اضبط XAI_API_KEY وانتقل إلى مسار مفتاح API (provider: xai) — هذا السطح غير خاضع لنفس القيود حاليًا.

      البدء السريع​

      # Launch the provider and model picker
      hermes model
      # → Select "xAI Grok OAuth (SuperGrok / X Premium+)" from the provider list
      # → Hermes opens or prints an accounts.x.ai verification URL
      # → Enter the displayed code if prompted, then approve access in the browser
      # → Pick a model (grok-4.6 is at the top)
      # → Start chatting

      hermes

      بعد أول تسجيل دخول، تُحفظ بيانات الاعتماد تحت ~/.hermes/auth.json وتُجدَّد تلقائيًا قبل انتهاء صلاحيتها.

      تسجيل الدخول يدويًا​

      يمكنك بدء تسجيل الدخول دون المرور عبر أداة اختيار النموذج:

      hermes auth add xai-oauth

      الجلسات البعيدة / بدون واجهة رسومية (headless)​

      على الخوادم أو الحاويات (containers) أو الطرفيات التي لا تعمل إلا عبر المتصفح (مثل Cloud Shell وCodespaces وEC2 Instance Connect) أو جلسات SSH حيث لا يستطيع Hermes فتح متصفح محليًا، يطبع Hermes رابط التحقّق ورمز المستخدم الخاصَّين بـ xAI. افتح الرابط في أي متصفح على حاسوبك المحمول أو في وحدة تحكّم سحابية، أدخل الرمز إن طُلب منك ذلك، وسيستمر Hermes في الاستطلاع (polling) إلى أن توافق xAI على تسجيل الدخول. لا حاجة إلى نفق SSH أو مستمع رد اتصال (callback) محلي.

      hermes auth add xai-oauth --no-browser
      # Open the printed verification URL in your browser.

      ينطبق نفس تدفّق رمز الجهاز عند تسجيل الدخول من لوحة التحكم على الويب أو تطبيق سطح المكتب: يعرض Hermes رابط التحقّق ورمز المستخدم، ثم يستطلع في الخلفية إلى أن توافق على منح الوصول.

      آلية عمل تسجيل الدخول​

      1. يطلب Hermes رمز جهاز من auth.x.ai.
      2. تفتح رابط التحقّق، وتسجّل الدخول، وتُدخل الرمز المعروض إن طُلب منك ذلك، ثم توافق على منح الوصول.
      3. يستطلع Hermes xAI حتى الموافقة، ثم يحفظ الرموز (tokens) في ~/.hermes/auth.json.
      4. بعد ذلك، يجدّد Hermes رمز الوصول في الخلفية — تبقى مسجّلًا للدخول إلى أن تنفّذ hermes auth logout xai-oauth أو تُلغي الوصول من إعدادات حسابك على xAI.

      التحقّق من حالة تسجيل الدخول​

      hermes doctor

      سيعرض قسم ◆ Auth Providers الحالة الراهنة لكل مزوّد، بما في ذلك xai-oauth.

      تبديل النماذج​

      hermes model
      # → Select "xAI Grok OAuth (SuperGrok / X Premium+)"
      # → Pick from the model list (grok-4.6 is pinned to the top)

      أو اضبط النموذج مباشرةً:

      hermes config set model.default grok-4.6
      hermes config set model.provider xai-oauth

      مرجع الإعدادات​

      بعد تسجيل الدخول، سيحتوي ~/.hermes/config.yaml على:

      model:
        default: grok-4.6
        provider: xai-oauth
        base_url: https://api.x.ai/v1

      أسماء بديلة للمزوّد​

      كل ما يلي يُحلَّل إلى xai-oauth:

      hermes --provider xai-oauth        # canonical
      hermes --provider grok-oauth       # alias
      hermes --provider x-ai-oauth       # alias
      hermes --provider xai-grok-oauth   # alias

      الأدوات المباشرة إلى xAI (TTS / الصور / الفيديو / النسخ الصوتي / X Search)​

      بمجرد تسجيل الدخول عبر OAuth، تعيد كل أداة تتعامل مباشرة مع xAI استخدام رمز الحامل نفسه تلقائيًا — لا حاجة إلى إعداد منفصل إلا إذا كنت تفضّل استخدام مفتاح API.

      لاختيار backend لكل أداة:

      hermes tools
      # → Text-to-Speech       → "xAI TTS"
      # → Image Generation     → "xAI Grok Imagine (image)"
      # → Video Generation     → "xAI Grok Imagine"
      # → X (Twitter) Search   → "xAI Grok OAuth (SuperGrok / X Premium+)"

      إذا كانت رموز OAuth محفوظة مسبقًا، تؤكد أداة الاختيار ذلك وتتخطّى طلب بيانات الاعتماد. وإذا لم يكن أي من OAuth أو XAI_API_KEY مضبوطًا، تعرض أداة الاختيار قائمة من 3 خيارات: تسجيل الدخول عبر OAuth، أو لصق مفتاح API، أو التخطّي.

      توليد الفيديو معطّل افتراضيًا

      toolset الخاص بـ video_gen معطّل افتراضيًا. فعّله في hermes tools ← 🎬 Video Generation (اضغط مفتاح المسافة) قبل أن يتمكّن الوكيل من استدعاء video_generate. وإلا فقد يلجأ الوكيل إلى مهارة ComfyUI المضمّنة، وهي أيضًا موسومة لتوليد الفيديو.

      يُفعَّل X search تلقائيًا عند توفّر بيانات اعتماد xAI

      يُفعَّل toolset الخاص بـ x_search تلقائيًا كلّما كانت بيانات اعتماد xAI (رمز OAuth لـ SuperGrok / X Premium+ أو XAI_API_KEY) مضبوطة. عطّله صراحةً عبر hermes tools ← 🐦 X (Twitter) Search (اضغط مفتاح المسافة) إذا كنت لا تريد ذلك. تمرّ الأداة عبر x_search Responses API المدمجة في xAI — وتعمل مع أي من تسجيل دخولك عبر OAuth لـ SuperGrok / X Premium+ أو XAI_API_KEY مدفوع، وتفضّل OAuth عند ضبط كليهما (تستخدم حصة اشتراكك بدلًا من إنفاق API). يُخفى مخطط الأداة عن النموذج عند عدم ضبط أي بيانات اعتماد لـ xAI، بصرف النظر عن كون toolset مفعّلًا أم لا.

      متغيرات البيئة​

      المتغيّرالتأثير
      XAI_BASE_URLتجاوز endpoint الافتراضي https://api.x.ai/v1 (نادرًا ما يُحتاج إليه).

      لاختيار xAI كمزوّد نشط، اضبط model.provider: xai-oauth في config.yaml (استخدم hermes setup للتدفّق الموجَّه) أو مرّر --provider xai-oauth لاستدعاء واحد فقط.

      استكشاف الأخطاء وإصلاحها​

      انتهت صلاحية الرمز — لا يعيد تسجيل الدخول تلقائيًا​

      يجدّد Hermes الرمز قبل كل جلسة، ومرة أخرى تفاعليًا عند حدوث خطأ 401. إذا فشل التجديد برمز invalid_grant (تم إلغاء رمز التجديد، أو تم تدوير الحساب)، يعرض Hermes رسالة إعادة مصادقة مصنَّفة بدلًا من التعطّل.

      عندما يكون فشل التجديد نهائيًا (HTTP 4xx، أو invalid_grant، أو إلغاء المنح، إلخ)، يضع Hermes علامة على رمز التجديد بأنه ميت ويعزله محليًا — بحيث تتخطّى الاستدعاءات اللاحقة محاولة التجديد الفاشلة بدلًا من تكرار نفس خطأ 401 مرارًا. يعرض الوكيل رسالة واحدة بعنوان "مطلوبة إعادة مصادقة" ويتوقّف عن العمل حتى تسجّل الدخول من جديد.

      الحل: نفّذ hermes auth add xai-oauth مجددًا لبدء تسجيل دخول جديد. يُزال الحجر بعد أول تبادل ناجح.

      انتهت مهلة التفويض​

      للموافقة على رمز الجهاز نافذة صلاحية محدودة (تضبط xAI قيمة expires_in في استجابة رمز الجهاز، وعادةً ما تكون بحدود عشرات الدقائق). إذا لم توافق على تسجيل الدخول في الوقت المحدَّد، يرفع Hermes خطأ انتهاء المهلة.

      الحل: أعد تنفيذ hermes auth add xai-oauth (أو hermes model). يبدأ التدفّق من جديد.

      تسجيل الدخول من خادم بعيد​

      في جلسات SSH أو الحاويات يطبع Hermes رابط التحقّق ورمز المستخدم بدلًا من فتح متصفح. افتح ذلك الرابط في متصفح على حاسوبك المحمول أو في وحدة تحكّم سحابية — لا حاجة إلى إعادة توجيه منفذ SSH لـ xAI Grok OAuth.

      hermes auth add xai-oauth --no-browser

      بالنسبة للمزوّدين ذوي إعادة التوجيه الاسترجاعية (loopback) (مثل Spotify وخوادم MCP)، راجع OAuth عبر SSH / الأجهزة البعيدة.

      HTTP 403 بعد تسجيل دخول ناجح (المستوى / الاستحقاق)​

      اكتمل OAuth في المتصفح، وحُفظت الرموز، لكن الاستدلال أو تجديد الرمز يعيد HTTP 403 برسالة شبيهة بـ "The caller does not have permission to execute the specified operation".

      هذه ليست مشكلة رمز قديم — إعادة تنفيذ hermes model لن تغيّر شيئًا. لوحظ أن خلفية xAI تقيّد الوصول إلى API عبر OAuth لمستويات معينة من SuperGrok رغم أن الاشتراك داخل التطبيق نشط (المشكلة #26847).

      الحل: اضبط XAI_API_KEY وانتقل إلى مسار مفتاح API:

      export XAI_API_KEY=xai-...
      hermes config set model.provider xai

      أو رقِّ اشتراكك على x.ai/grok إذا كان مسار OAuth مطلوبًا.

      خطأ "No xAI credentials found" أثناء التشغيل​

      مخزن المصادقة لا يحتوي على أي مُدخل لـ xai-oauth ولا على XAI_API_KEY مضبوط. إما أنك لم تسجّل الدخول بعد، أو أن ملف بيانات الاعتماد قد حُذف.

      الحل: نفّذ hermes model واختر مزوّد xAI Grok OAuth، أو نفّذ hermes auth add xai-oauth.

      تسجيل الخروج​

      لإزالة كل بيانات اعتماد xAI Grok OAuth المحفوظة:

      hermes auth logout xai-oauth

      يمسح هذا كلًا من مُدخل OAuth الوحيد في auth.json وأي صفوف في مجمّع بيانات الاعتماد (credential pool) الخاصة بـ xai-oauth. استخدم hermes auth remove xai-oauth <index|id|label> إذا كنت تريد حذف مُدخل واحد فقط من المجمّع (نفّذ hermes auth list xai-oauth لعرضها).
