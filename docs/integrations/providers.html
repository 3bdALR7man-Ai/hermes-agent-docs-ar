      مزوّدو LLM والنماذج

      تغطي هذه الصفحة إعداد مزوّدي الاستدلال (inference) لـ Hermes Agent — من واجهات API السحابية مثل OpenRouter وAnthropic، إلى endpoints مستضافة ذاتيًا مثل Ollama وvLLM، إلى إعدادات التوجيه (routing) والاحتياط (fallback) المتقدمة. تحتاج إلى مزوّد واحد على الأقل مُهيّأ لاستخدام Hermes.

      الاسم البديل لمفتاح النموذج

      في قسم إعدادات model:، يمكنك استخدام إما default: أو model: كاسم مفتاح لمعرّف النموذج الخاص بك. يعمل كل من model: { default: my-model } و model: { model: my-model } بشكل متطابق.

      Nous Portal​

      Nous Portal هو gateway الاشتراك الموحّد الخاص بـ Nous Research والطريقة الموصى بها لتشغيل Hermes Agent. تسجيل دخول OAuth واحد يغطي أكثر من 300 نموذج وكيلي متطور (Claude، GPT، Gemini، DeepSeek، Qwen، Kimi، GLM، MiniMax، Grok، ...) بالإضافة إلى Tool Gateway (البحث في الويب، توليد الصور، TTS، أتمتة المتصفح) — تُفوتَر مقابل اشتراكك في Nous بدلًا من حسابات منفصلة لكل مزوّد.

      hermes setup --portal     # fresh install — OAuth + provider + gateway in one command
      hermes model              # existing install — pick "Nous Portal" from the list
      hermes portal info        # inspect login + routing at any time

      ليس لديك اشتراك بعد؟ احصل على واحد من portal.nousresearch.com/manage-subscription.

      للتفاصيل الكاملة: راجع صفحة تكامل Nous Portal المخصصة (ما يتضمنه الاشتراك، كتالوج النماذج، استكشاف الأخطاء وإصلاحها) ودليل تشغيل Hermes Agent مع Nous Portal خطوة بخطوة.

      تعريف العميل (Client identification). يحمل كل طلب من Hermes Agent إلى Portal علامة client=hermes-client-v<version> (مثلًا client=hermes-client-v0.13.0) تُضبط تلقائيًا وفق إصدارك المثبَّت. تُرسَل هذه العلامة على جميع مسارات Portal — حلقة الدردشة الرئيسية، الاستدعاءات المساعدة، ملخّص الضغط، استخراج الويب — وتتيح لتحليلات القياس عند Portal تمييز حركة بيانات Hermes عن العملاء الآخرين. لا حاجة لأي إعداد — تتحدث العلامة تلقائيًا عند تنفيذ hermes update.

      مصادقة JWT (تلقائية). يفضّل Hermes JWTs محدودة النطاق من نوع inference:invoke لطلبات Portal مع مسار مفتاح الجلسة المبهم (opaque) القديم كاحتياطي. لا حاجة لأي إعداد — تُدار بيانات الاعتماد عبر تدفق OAuth وتتجدد بشفافية. تُعزَل رموز التحديث (refresh tokens) المُلغاة لتجنب حلقات إعادة التشغيل (replay).

      ملاحظة حول Codex

      يُصادق مزوّد OpenAI Codex عبر رمز الجهاز (device code) (افتح رابطًا، أدخل رمزًا). يخزّن Hermes بيانات الاعتماد الناتجة في مخزن المصادقة الخاص به تحت ~/.hermes/auth.json ويمكنه استيراد بيانات اعتماد Codex CLI الموجودة من ~/.codex/auth.json عند وجودها. لا حاجة لتثبيت Codex CLI.

      إذا فشل تحديث رمز ما بخطأ نهائي (HTTP 4xx، invalid_grant، منحة مُلغاة، إلخ)، يضع Hermes علامة على رمز التحديث كميت ويتوقف عن إعادة تشغيله حتى لا ترى سيلًا من أخطاء المصادقة المتطابقة. يعرض الطلب التالي رسالة إعادة مصادقة مُصنَّفة بدلًا من ذلك. نفّذ hermes auth add openai-codex (أو hermes model → ChatGPT or Codex Subscription) لبدء تسجيل دخول جديد برمز جهاز؛ تُزال العزلة عند نجاح التبادل التالي.

      قد يفشل تسجيل دخول الجهاز بخطأ [SSL: UNEXPECTED_EOF_WHILE_READING] أو مهلة مصافحة TLS على Python/OpenSSL 3.5+ عندما يرفض جهاز وسيط مجموعات ما بعد الكم مثل X25519MLKEM768 (قد يعمل curl مع ذلك). لا يغيّر Hermes سياسة TLS الافتراضية. وجّه OPENSSL_CONF إلى إعداد يقيّد Groups إلى منحنيات كلاسيكية قبل تشغيل hermes model، أو شخّص المشكلة باستخدام TLS 1.2:

      openssl_conf = openssl_init

      [openssl_init]
      ssl_conf = ssl_sect

      [ssl_sect]
      system_default = system_default_sect

      [system_default_sect]
      Groups = x25519:secp256r1:secp384r1:x448
      تحذير

      حتى عند استخدام Nous Portal أو Codex أو endpoint مخصص، تستخدم بعض الأدوات (الرؤية vision، تلخيص الويب، MoA) نموذجًا "مساعدًا" منفصلًا. افتراضيًا (auxiliary.*.provider: "auto")، يوجّه Hermes هذه المهام إلى نموذج الدردشة الرئيسي الخاص بك — نفس النموذج الذي اخترته في hermes model. يمكنك تجاوز كل مهمة على حدة لتوجيهها إلى نموذج أرخص/أسرع (مثل Gemini Flash على OpenRouter) — راجع النماذج المساعدة.

      Nous Tool Gateway

      يحصل مشتركو Nous Portal المدفوعون أيضًا على وصول إلى Tool Gateway — البحث في الويب، توليد الصور، TTS، وأتمتة المتصفح موجّهة عبر اشتراكك. بدون مفاتيح API إضافية. عند التثبيت الجديد، يسجّل hermes setup --portal دخولك، ويضبط Nous كمزوّدك، ويفعّل الـ gateway بأمر واحد. يمكن للمستخدمين الحاليين تفعيله من hermes model أو لكل أداة من hermes tools. افحص التوجيه في أي وقت باستخدام hermes portal info.

      خطط الاشتراك: ما الذي تدفع خطتك مقابله​

      يتيح لك العديد من المزوّدين تسجيل الدخول إلى Hermes باستخدام اشتراك مستهلك (Claude Max، ChatGPT، SuperGrok / X Premium+، …) بدلًا من مفتاح API. ما الذي يدفع مقابله ذلك الاشتراك فعليًا — وما لا يدفعه — يختلف حسب المزوّد، وهو المصدر الأكثر شيوعًا لمفاجآت الفوترة. الجدول أدناه هو النسخة المختصرة؛ يحتوي قسم كل مزوّد الخاص به على التفاصيل.

      الخلايا المُشار إليها بـ غير موثّق حاليًا تعني ذلك بالضبط: لم تُحدِّد وثائق Hermes بعد هذا السلوك. لا تفترض — تحقق من لوحة فوترة مزوّدك، وعامل هذه الحالات كأسئلة مفتوحة.

      الخطة / المسارهل يستطيع Hermes استخدامها؟ما الذي يُستهلَكما الذي لا يُستهلَكالمفاجأة الشائعة
      Anthropic — Claude Max + OAuth✅ نعم — hermes model → Anthropic OAuth. يتطلب Max و رصيد استخدام إضافي مشترىرصيد الاستخدام الإضافي/الزائد الذي أضفته فوق خطة Maxمخصص خطة Max الأساسية (الاستخدام المُضمَّن في Claude Code افتراضيًا)يُفوتَر كل استخدام Hermes كـ "استخدام إضافي" حتى بينما يبقى مخصصك المُضمَّن في Max غير مُستخدَم

      Anthropic (Native)​

      استخدم نماذج Claude مباشرة عبر Anthropic API — بدون حاجة إلى وكيل OpenRouter الوسيط. يدعم ثلاث طرق مصادقة:

      عندما لا تُختار بيانات اعتماد بيئة صريحة، تأخذ منحات OAuth المملوكة لـ Hermes في مجمّع بيانات الاعتماد الأسبقية على تسجيل دخول Claude Code المُستعار. يبقى تسجيل الدخول المُستعار احتياطيًا عندما لا تتوفر منحة OAuth مملوكة. يُحدِّث تعافي المصادقة المساعد بيانات الاعتماد المستخدَمة من قِبل الطلب الفاشل، وليس تسجيل دخول محيطي غير ذي صلة؛ فقد يؤدي تدوير تسجيل دخول مُستعار خلاف ذلك إلى إبطال رمز التحديث الخاص بمالكه.

      يتطلب رصيد "استخدام إضافي" من Claude Max

      عندما تُصادق عبر hermes model → Anthropic OAuth (أو عبر hermes auth add anthropic --type oauth)، يوجَّه Hermes كـ Claude Code مقابل حسابك في Anthropic. يعمل هذا فقط إذا كنت على خطة Claude Max وقد اشتريت رصيد استخدام إضافي. لا يُستهلَك مخصص خطة Max الأساسية (الاستخدام المُضمَّن في Claude Code افتراضيًا) بواسطة Hermes — فقط رصيد الاستخدام الإضافي/الزائد الذي أضفته فوقه. لا يستطيع مشتركو Claude Pro استخدام هذا المسار.

      إذا لم يكن لديك Max + رصيد إضافي، استخدم ANTHROPIC_API_KEY بدلًا من ذلك — تُفوتَر الطلبات بالدفع لكل token مقابل مؤسسة ذلك المفتاح (أسعار API القياسية، مستقلة عن أي اشتراك Claude).

      # With an API key (pay-per-token)
      export ANTHROPIC_API_KEY=***
      hermes chat --provider anthropic --model claude-sonnet-4-6

      # Preferred: authenticate through `hermes model`
      # Hermes will use Claude Code's credential store directly when available
      hermes model

      # Manual override with a setup-token (fallback / legacy)
      export ANTHROPIC_TOKEN=***  # setup-token or manual OAuth token
      hermes chat --provider anthropic

      # Auto-detect Claude Code credentials (if you already use Claude Code)
      hermes chat --provider anthropic  # reads Claude Code credential files automatically

      عندما تختار Anthropic OAuth عبر hermes model، يفضّل Hermes مخزن بيانات الاعتماد الخاص بـ Claude Code على نسخ الرمز إلى ~/.hermes/.env. هذا يُبقي بيانات اعتماد Claude القابلة للتحديث قابلة للتحديث.

      أو اضبطه بشكل دائم:

      model:
        provider: "anthropic"
        default: "claude-sonnet-4-6"
      الأسماء البديلة

      تعمل --provider claude و --provider claude-code أيضًا كاختصار لـ --provider anthropic.

      copilot — Direct Copilot API (مُوصى به). يستخدم اشتراكك في GitHub Copilot للوصول إلى GPT-5.x و Claude و Gemini ونماذج أخرى عبر Copilot API.

      سلوك مصادقة Copilot في Hermes

      يرسل Hermes token من GitHub مدعومًا (gho_* أو github_pat_* أو ghu_*) مباشرةً إلى api.githubcopilot.com ويضمّن ترويسات خاصة بـ Copilot (Editor-Version وCopilot-Integration-Id وOpenai-Intent وx-initiator).

      عند استجابة HTTP 401، ينفّذ Hermes الآن استرداد بيانات اعتماد لمرة واحدة قبل الرجوع إلى الاحتياطي:

      1. إعادة تحديد الـ token عبر سلسلة الأولوية العادية (COPILOT_GITHUB_TOKEN → GH_TOKEN → GITHUB_TOKEN → gh auth token)
      2. إعادة بناء عميل OpenAI المشترك بترويسات محدَّثة
      3. إعادة محاولة الطلب مرة واحدة

      تستخدم بعض الوسائط (proxies) المجتمعية القديمة تدفقات تبادل عبر api.github.com/copilot_internal/v2/token. قد تكون تلك النقطة غير متاحة لبعض أنواع الحسابات (تُعيد 404). لذلك يحافظ Hermes على المصادقة المباشرة بالـ token كمسار أساسي، ويعتمد على تحديث بيانات الاعتماد وقت التشغيل مع إعادة المحاولة لضمان الموثوقية.

      توجيه API: تستخدم نماذج GPT-5+ (باستثناء gpt-5-mini) تلقائيًا واجهة Responses API. أما بقية النماذج (GPT-4o وClaude وGemini وغيرها) فتستخدم Chat Completions. يُكتشف النماذج تلقائيًا من كتالوج Copilot الحي.

      xAI (Grok) — Responses API + التخزين المؤقت للـ prompt​

      يتم توصيل xAI عبر Responses API (نقل codex_responses) لدعم الاستدلال (reasoning) التلقائي على نماذج Grok 4 — دون الحاجة لمعامل reasoning_effort، إذ يقوم الخادم بالاستدلال افتراضيًا. اضبط XAI_API_KEY في ~/.hermes/.env واختر xAI في hermes model، أو استخدم grok كاختصار ضمن /model grok-4-fast-reasoning.

      يمكن لمشتركي SuperGrok و X Premium+ تسجيل الدخول عبر OAuth في المتصفح بدلًا من استخدام مفتاح API — اختر xAI Grok OAuth (SuperGrok / Premium+) في hermes model، أو شغّل hermes auth add xai-oauth. يُعاد استخدام نفس bearer token الخاص بـ OAuth تلقائيًا من قِبل الأدوات المتصلة مباشرة بـ xAI (TTS وتوليد الصور وتوليد الفيديو والنسخ الصوتي). راجع دليل xAI Grok OAuth للاطلاع على التدفق الكامل — وإذا كان Hermes يعمل على مضيف بعيد، راجع أيضًا OAuth عبر SSH / الأجهزة البعيدة لمعرفة نفق ssh -L المطلوب.

      عند استخدام xAI كمزوّد (أي base URL يحتوي x.ai)، يفعّل Hermes تلقائيًا التخزين المؤقت للـ prompt عبر إرسال ترويسة x-grok-conv-id مع كل طلب API. يوجّه هذا الطلبات إلى نفس الخادم ضمن جلسة المحادثة، مما يتيح لبنية xAI التحتية إعادة استخدام أنظمة الـ prompt وسجل المحادثة المخزَّنة مؤقتًا.

      لا حاجة لأي إعداد — يُفعَّل التخزين المؤقت تلقائيًا عند اكتشاف نقطة xAI وتوفّر معرّف جلسة. هذا يقلّل زمن الاستجابة والتكلفة في المحادثات متعددة الأدوار.

      يوفّر xAI أيضًا endpoint مخصّصًا لـ TTS (/v1/tts). اختر xAI TTS في hermes tools → الصوت و TTS، أو راجع صفحة الصوت و TTS للإعدادات.

      انتقال نماذج xAI المُتقاعدة (15 مايو 2026): يعتزم xAI إيقاف grok-4* وgrok-3 وgrok-code-fast-1 وgrok-imagine-image-pro بتاريخ 2026-05-15. يكتشف كل من hermes doctor وبدء تشغيل hermes chat أي إعدادات لا تزال تشير إلى مرجع متقاعد ويطبعان البديل الموصى به. استخدم hermes migrate xai لإعادة كتابة الإعدادات دفعة واحدة — وهو بوضع dry-run افتراضيًا، أضف --apply لكتابة التغييرات (تُحفَظ نسخة مؤرَّخة من الإعدادات السابقة في backups/config/ أولًا).

      hermes migrate xai          # preview replacements
      hermes migrate xai --apply  # rewrite ~/.hermes/config.yaml in place

      خلفية البحث في الويب لـ xAI. عند تفعيل مجموعة أدوات البحث في الويب، يوجّه web.backend: xai عملية البحث عبر نقطة البحث المستضافة من xAI باستخدام نفس بيانات اعتماد XAI_API_KEY / OAuth. لا حاجة لأي إعداد إضافي إذا كان xAI مُهيّأً بالفعل كمزوّد.

      Actual Computer​

      عتادك الخاص كعنقود استدلال خاص عبر Actual Computer. وضعا تقديم اثنان، وكلاهما يستخدم Chat Completions بحيث يُعاد الاستدلال والمحتوى النهائي معًا:

      • مُرحِّل مُستضاف (Hosted relay) — https://api.actual.inc، مشفَّر من طرف إلى طرف، يوجَّه إلى عنقودك الخاص. صادِق باستخدام مفتاح استدلال بادئته ac_ من actual.inc/user/keys.
      • عفريت (daemon) محلي — على الجهاز نفسه عند http://127.0.0.1:8080، بلا اتصال بالكامل (offline). لا حاجة لمفتاح API: يكتشف Hermes الـ base URL المحلي (loopback) ويصادق بواسطة عنصر نائب داخلي تلقائيًا.
      # Hosted relay (ACTUAL_API_KEY in ~/.hermes/.env)
      hermes chat --provider actual --model <model-id-from-your-cluster>

      # Local daemon (model.base_url in ~/.hermes/config.yaml, no key)
      hermes chat --provider actual --model <installed-model-name>

      خزّن إعدادات المزوّد في ~/.hermes/config.yaml؛ لا ينتمي إلى .env سوى مفتاح API المُستضاف:

      model:
        provider: "actual"
        default: "<model-id>"
        base_url: "http://127.0.0.1:8080/v1" # Omit for the hosted relay.

      ملاحظات:

      • تأتي معرّفات النماذج من GET /v1/models الخاص بعنقودك — اكتشفها عبر hermes model أو curl -s https://api.actual.inc/v1/models -H "Authorization: Bearer $ACTUAL_API_KEY".
      • تُسوَّى المضيفات المجرَّدة (bare hosts) في model.base_url: يصبح http://127.0.0.1:8080 هو http://127.0.0.1:8080/v1 تلقائيًا. متغير البيئة القديم ACTUAL_BASE_URL هو احتياطي (fallback) عندما لا يكون هناك عنوان Actual مضبوط في YAML.
      • يستخدم Actual مسار /v1/chat/completions للمحادثة والضغط (compaction) وتوليد العناوين وكل مهمة مساعدة أخرى. ينطبق هذا أيضًا على المزوّدين المخصّصين الموجَّهين إلى api.actual.inc، وعمليات تبديل النموذج، والاحتياطيات (fallbacks). تُتجاوَز إعدادات Responses القديمة في النموذج الرئيسي أو المزوّد المخصّص أو إعدادات المهمة المساعدة تلقائيًا.
      • يُحصَر جهد الاستدلال (reasoning effort) ضمن النطاق المدعوم من Actual (none/low/medium/high/max) — فلن يتسبب إعداد xhigh/ultra العام في رفض الطلبات بخطأ 400.
      • النماذج المحلية الصغيرة: قد تتجاوز مجموعة أدوات Hermes الافتراضية الكاملة مع الـ system prompt نافذة سياق 32 ألف token، مما ينتج عنه خطأ تدفق فارغ (empty-stream) من خوادم عائلة llama.cpp. قيّد مجموعة الأدوات (-t file,web) أو حمّل النموذج بسياق أكبر. تغطي مهارة actual-setup الاختيارية (hermes skills install official/devops/actual-setup) الإعداد واستكشاف الأخطاء بالتفصيل.
      • الأسماء المستعارة: actual-computer وactualcomputer وaci.

      تبديل النماذج باستخدام /model​

      hermes model مقابل /model

      hermes model (يُشغَّل من الطرفية، خارج أي جلسة محادثة) هو معالج الإعداد الكامل للمزوّدين. استخدمه لإضافة مزوّدين جدد، وتشغيل تدفقات OAuth، وإدخال مفاتيح API، وضبط endpoints مخصّصة.

      /model (يُكتَب داخل جلسة محادثة Hermes نشطة) يمكنه فقط التبديل بين المزوّدين والنماذج التي أعددتها بالفعل. لا يمكنه إضافة مزوّدين جدد، أو تشغيل OAuth، أو طلب مفاتيح API. إذا كنت قد أعددت مزوّدًا واحدًا فقط (مثل OpenRouter)، فسيعرض /model نماذج ذلك المزوّد فقط.

      لإضافة مزوّد جديد: اخرج من جلستك (Ctrl+C أو /quit)، شغّل hermes model، أعدّ المزوّد الجديد، ثم ابدأ جلسة جديدة.

      بمجرد ضبط endpoint مخصّص واحد على الأقل، يمكنك تبديل النماذج أثناء الجلسة:

      /model custom:qwen-2.5          # Switch to a model on your custom endpoint
      /model custom                    # Auto-detect the model from the endpoint
      /model openrouter:claude-sonnet-4 # Switch back to a cloud provider

      إذا كانت لديك مزوّدات مخصّصة مُسمّاة (انظر أدناه)، استخدم الصيغة الثلاثية:

      /model custom:local:qwen-2.5    # Use the "local" custom provider with model qwen-2.5
      /model custom:work:llama3       # Use the "work" custom provider with llama3

      عند تبديل المزوّدين، يحفظ Hermes الـ base URL والمزوّد في الإعدادات بحيث يبقى التغيير قائمًا بعد إعادة التشغيل. عند التبديل من endpoint مخصّص إلى مزوّد مدمج، يُمحى الـ base URL القديم تلقائيًا.

      نصيحة

      /model custom (بدون اسم نموذج) يستعلم عن واجهة /models الخاصة بـ endpoint الخاص بك، ويختار النموذج تلقائيًا إذا كان هناك نموذج واحد محمَّل فقط. مفيد للخوادم المحلية التي تشغّل نموذجًا واحدًا.

      كل ما يلي أدناه يتبع نفس النمط — فقط غيّر الرابط والمفتاح واسم النموذج.

      Ollama — نماذج محلية بلا إعداد يُذكر​

      يشغّل Ollama نماذج مفتوحة الأوزان محليًا بأمر واحد. الأفضل لـ: التجريب المحلي السريع، والأعمال الحسّاسة للخصوصية، والاستخدام دون اتصال. يدعم استدعاء الأدوات عبر واجهة OpenAI-compatible API.

      # Install and run a model
      ollama pull qwen2.5-coder:32b
      ollama serve   # Starts on port 11434

      ثم اضبط Hermes:

      hermes model
      # Select "Custom endpoint (self-hosted / VLLM / etc.)"
      # Enter URL: http://localhost:11434/v1
      # Skip API key (Ollama doesn't need one)
      # Enter model name (e.g. qwen2.5-coder:32b)

      أو اضبط config.yaml مباشرةً:

      model:
        default: qwen2.5-coder:32b
        provider: custom
        base_url: http://localhost:11434/v1
        context_length: 64000   # See warning below
      يستخدم Ollama افتراضيًا أطوال سياق منخفضة جدًا

      لا يستخدم Ollama نافذة السياق الكاملة لنموذجك افتراضيًا. اعتمادًا على ذاكرة VRAM لديك، القيمة الافتراضية هي:

      VRAM المتاحةالسياق الافتراضي
      أقل من 24 GB4,096 token
      24–48 GB32,768 token
      48+ GB256,000 token

      يتطلّب Hermes Agent سياقًا لا يقل عن 64,000 token لاستخدام الوكيل مع الأدوات. تُرفَض النوافذ الأصغر عند بدء التشغيل لأن الـ system prompt وأنظمة الأدوات وحالة المحادثة الجارية تحتاج مساحة كافية لسير عمل موثوق متعدد الخطوات.

      كيفية زيادتها (اختر إحدى الطرق):

      # Option 1: Set server-wide via environment variable (recommended)
      OLLAMA_CONTEXT_LENGTH=64000 ollama serve

      # Option 2: For systemd-managed Ollama
      sudo systemctl edit ollama.service
      # Add: Environment="OLLAMA_CONTEXT_LENGTH=64000"
      # Then: sudo systemctl daemon-reload && sudo systemctl restart ollama

      # Option 3: Bake it into a custom model (persistent per-model)
      echo -e "FROM qwen2.5-coder:32b\nPARAMETER num_ctx 64000" > Modelfile
      ollama create qwen2.5-coder-64k -f Modelfile

      لا يمكنك ضبط طول السياق عبر واجهة OpenAI-compatible API (/v1/chat/completions). يجب ضبطه من جهة الخادم أو عبر Modelfile. هذا هو مصدر اللبس الأول عند دمج Ollama مع أدوات مثل Hermes.

      تحقّق من أن سياقك مضبوط بشكل صحيح:

      ollama ps
      # Look at the CONTEXT column — it should show your configured value
      نصيحة

      اعرض النماذج المتاحة عبر ollama list. اسحب أي نموذج من مكتبة Ollama عبر ollama pull <model>. يتولى Ollama تحميل GPU (offloading) تلقائيًا — دون الحاجة لأي إعداد في معظم الحالات.

      vLLM — استدلال GPU عالي الأداء​

      vLLM هو المعيار المتّبع لتقديم LLM في الإنتاج. الأفضل لـ: أقصى إنتاجية على عتاد GPU، وتقديم النماذج الكبيرة، والدُفعات المستمرة (continuous batching).

      pip install vllm
      vllm serve meta-llama/Llama-3.1-70B-Instruct \
        --port 8000 \
        --max-model-len 65536 \
        --tensor-parallel-size 2 \
        --enable-auto-tool-choice \
        --tool-call-parser hermes

      ثم اضبط Hermes:

      hermes model
      # Select "Custom endpoint (self-hosted / VLLM / etc.)"
      # Enter URL: http://localhost:8000/v1
      # Skip API key (or enter one if you configured vLLM with --api-key)
      # Enter model name: meta-llama/Llama-3.1-70B-Instruct

      طول السياق: يقرأ vLLM قيمة max_position_embeddings الخاصة بالنموذج افتراضيًا. إذا تجاوزت ذاكرة GPU لديك، يظهر خطأ ويطلب منك ضبط --max-model-len إلى قيمة أقل. يمكنك أيضًا استخدام --max-model-len auto للعثور تلقائيًا على أقصى قيمة تناسب العتاد. اضبط --gpu-memory-utilization 0.95 (الافتراضي 0.9) لحشر سياق أكبر في VRAM.

      يتطلّب استدعاء الأدوات إعلامات صريحة:

      العلامة (Flag)الغرض
      --enable-auto-tool-choiceمطلوبة لـ tool_choice: "auto" (الافتراضي في Hermes)
      --tool-call-parser <name>مُحلِّل (parser) لصيغة استدعاء الأدوات الخاصة بالنموذج

      المُحلِّلات المدعومة: hermes (لـ Qwen 2.5 وHermes 2/3)، وllama3_json (لـ Llama 3.x)، وmistral، وdeepseek_v3، وdeepseek_v31، وxlam، وpythonic. دون هذه الإعلامات، لن تعمل استدعاءات الأدوات — سيُخرج النموذج استدعاءات الأدوات كنص عادي.

      مُحلِّلات استدلال Qwen: يحافظ Hermes على البيانات الوصفية للاستدلال المُهيكلة مثل reasoning وreasoning_content ودفعات الاستدلال المتدفقة (streamed reasoning deltas) عندما تعيدها الخوادم المتوافقة مع OpenAI. تُعامَل تلك البيانات الوصفية كمسار تفكير/استدلال، وليست بديلًا عن الإجابة المرئية للمساعد. بالنسبة لنماذج استدلال Qwen المُقدَّمة عبر vLLM، تأكد من أن الاستجابة النهائية المرئية للمستخدم لا تزال تظهر في content. إذا ترك --reasoning-parser qwen3 حقل content فارغًا في نشرك، إما عطّل ذلك المُحلِّل أو مرّر خيار طلب مدعومًا من الخادم مثل chat_template_kwargs.enable_thinking: false عبر extra_body.

      نصيحة

      يدعم vLLM الأحجام المقروءة للبشر: --max-model-len 64k (الحرف الصغير k يساوي 1000، والحرف الكبير K يساوي 1024).

      SGLang — تقديم سريع باستخدام RadixAttention​

      SGLang بديل لـ vLLM يعتمد RadixAttention لإعادة استخدام ذاكرة KV المؤقتة. الأفضل لـ: المحادثات متعددة الأدوار (التخزين المؤقت للبادئات/prefix caching)، وفك الترميز المقيَّد، والمخرجات المُهيكلة.

      pip install "sglang[all]"
      python -m sglang.launch_server \
        --model meta-llama/Llama-3.1-70B-Instruct \
        --port 30000 \
        --context-length 65536 \
        --tp 2 \
        --tool-call-parser qwen

      ثم اضبط Hermes:

      hermes model
      # Select "Custom endpoint (self-hosted / VLLM / etc.)"
      # Enter URL: http://localhost:30000/v1
      # Enter model name: meta-llama/Llama-3.1-70B-Instruct

      طول السياق: يقرأ SGLang القيمة من إعدادات النموذج افتراضيًا. استخدم --context-length لتجاوزها. إذا احتجت لتجاوز الحد الأقصى المُعلَن للنموذج، اضبط SGLANG_ALLOW_OVERWRITE_LONGER_CONTEXT_LEN=1.

      استدعاء الأدوات: استخدم --tool-call-parser مع المُحلِّل المناسب لعائلة نموذجك: qwen (لـ Qwen 2.5)، وllama3، وllama4، وdeepseekv3، وmistral، وglm. دون هذا الإعلام، تعود استدعاءات الأدوات كنص عادي.

      يقتصر SGLang افتراضيًا على 128 token كحد أقصى للمخرجات

      إذا بدت الاستجابات مقتطعة، تحقّق من إعداد التوليد الافتراضي للخادم واضبطه من جهة الخادم (مثل --default-max-tokens في SGLang). لا يعرض Hermes إعداد سقف لعدد tokens المخرجات.

      llama.cpp / llama-server — استدلال CPU وMetal​

      يشغّل llama.cpp نماذج مُكمَّمة (quantized) على CPU، وApple Silicon (Metal)، وبطاقات GPU الاستهلاكية. الأفضل لـ: تشغيل النماذج دون GPU مركز بيانات، مستخدمي Mac، والنشر الطرفي (edge).

      # Build and start llama-server
      cmake -B build && cmake --build build --config Release
      ./build/bin/llama-server \
        --jinja -fa \
        -c 64000 \
        -ngl 99 \
        -m models/qwen2.5-coder-32b-instruct-Q4_K_M.gguf \
        --port 8080 --host 0.0.0.0

      طول السياق (-c): تفترض الإصدارات الحديثة القيمة 0 افتراضيًا، والتي تقرأ سياق التدريب الخاص بالنموذج من بيانات GGUF الوصفية. بالنسبة للنماذج ذات سياق تدريب 128 ألف token أو أكثر، قد يتسبب هذا في نفاد الذاكرة (OOM) عند محاولة تخصيص ذاكرة KV المؤقتة الكاملة. اضبط -c صراحةً إلى 64,000 token على الأقل من أجل Hermes. إذا كنت تستخدم فتحات متوازية (-np)، يُقسَّم السياق الإجمالي بين الفتحات — فمع -c 64000 -np 4، تحصل كل فتحة على 16 ألف فقط، وهو أقل من الحد الأدنى لدى Hermes لكل جلسة نشطة.

      ثم اضبط Hermes ليشير إليه:

      hermes model
      # Select "Custom endpoint (self-hosted / VLLM / etc.)"
      # Enter URL: http://localhost:8080/v1
      # Skip API key (local servers don't need one)
      # Enter model name — or leave blank to auto-detect if only one model is loaded

      هذا يحفظ الـ endpoint في config.yaml بحيث يبقى قائمًا عبر الجلسات.

      --jinja مطلوب لاستدعاء الأدوات

      دون --jinja، يتجاهل llama-server معامل tools تمامًا. سيحاول النموذج استدعاء الأدوات بكتابة JSON في نص استجابته، لكن Hermes لن يتعرّف عليه كاستدعاء أداة — سترى JSON خامًا مثل {"name": "web_search", ...} مطبوعًا كرسالة بدلًا من بحث فعلي.

      دعم استدعاء الأدوات الأصلي (أفضل أداء): Llama 3.x، وQwen 2.5 (بما فيه Coder)، وHermes 2/3، وMistral، وDeepSeek، وFunctionary. تستخدم بقية النماذج معالجًا عامًا يعمل لكنه قد يكون أقل كفاءة. راجع وثائق استدعاء الدوال في llama.cpp للاطلاع على القائمة الكاملة.

      يمكنك التحقق من تفعيل دعم الأدوات عبر مراجعة http://localhost:8080/props — يجب أن يكون حقل chat_template موجودًا.

      نصيحة

      حمّل نماذج GGUF من Hugging Face. توفّر التكميم Q4_K_M أفضل توازن بين الجودة واستهلاك الذاكرة.

      LM Studio — تطبيق سطح مكتب بنماذج محلية​

      LM Studio هو تطبيق سطح مكتب لتشغيل النماذج المحلية بواجهة رسومية. الأفضل لـ: من يفضّلون واجهة بصرية، والاختبار السريع للنماذج، ومطوّري macOS/Windows/Linux.

      ابدأ الخادم من تطبيق LM Studio (تبويب Developer → Start Server)، أو استخدم CLI:

      lms server start                        # Starts on port 1234
      lms load qwen2.5-coder --context-length 64000

      ثم اضبط Hermes:

      hermes model
      # Select "LM Studio"
      # Press Enter to use http://localhost:1234/v1
      # Pick one of the discovered models
      # If LM Studio server auth is enabled, enter LM_API_KEY when prompted

      يحافظ Hermes على سياق نسخة LM Studio المحمَّلة بالفعل. بالنسبة لنموذج غير محمَّل في الوضع الصريح الافتراضي، يهمل Hermes context_length ما لم تكن قد ضبطت واحدًا في Hermes، بحيث يستطيع LM Studio تطبيق إعداده الخاص بالنموذج. يستخدم Hermes بعدها فقط طول السياق الذي يبلّغ عنه LM Studio بعد التحميل.

      لتغيير طول السياق في LM Studio:

      1. انقر أيقونة الترس بجانب منتقي النموذج
      2. اضبط "Context Length" على 64000 على الأقل لتجربة سلسة
      3. أعد تحميل النموذج ليصبح التغيير ساري المفعول
      4. إذا لم يستوعب جهازك 64000، فكّر في استخدام نموذج أصغر بطول سياق أكبر.

      بديلًا عن ذلك، استخدم CLI: lms load model-name --context-length 64000

      يمكنك استخدام CLI لتقدير ما إذا كان النموذج سيناسب: lms load model-name --context-length 64000 --estimate-only

      لضبط قيم افتراضية دائمة لكل نموذج: تبويب My Models → أيقونة الترس على النموذج → اضبط حجم السياق. :::

      إذا كنت تستخدم ميزة التحميل عند الطلب (Just-In-Time) / الإخلاء التلقائي (Auto-Evict) في LM Studio وتريد أن يتولى LM Studio إدارة تحميل النموذج وإخلائه من طلبات المحادثة العادية، تخطَّ خطوة التحميل المسبق الصريحة في Hermes:

      hermes config set model.lmstudio_load_mode jit

      أعده إلى سلوك التحميل المسبق الصريح الافتراضي عبر:

      hermes config set model.lmstudio_load_mode explicit

      استدعاء الأدوات: مدعوم منذ LM Studio 0.3.6. تُكتشَف النماذج ذات التدريب الأصلي على استدعاء الأدوات (Qwen 2.5، وLlama 3.x، وMistral، وHermes) تلقائيًا وتُعرَض بشارة أداة. تستخدم النماذج الأخرى بديلًا عامًا قد يكون أقل موثوقية.

      شبكات WSL2 (لمستخدمي Windows)​

      بما أن Hermes Agent يتطلّب بيئة Unix، يشغّله مستخدمو Windows داخل WSL2. إذا كان خادم النموذج لديك (Ollama أو LM Studio أو غيرهما) يعمل على مضيف Windows، فأنت بحاجة لسد الفجوة الشبكية — يستخدم WSL2 محوّل شبكة افتراضيًا بشبكة فرعية خاصة به، لذا يشير localhost داخل WSL2 إلى جهاز Linux الافتراضي، وليس مضيف Windows.

      كلاهما داخل WSL2؟ لا مشكلة.

      إذا كان خادم النموذج لديك يعمل أيضًا داخل WSL2 (شائع مع vLLM وSGLang وllama-server)، يعمل localhost كما هو متوقع — إذ يشتركان في نفس مساحة اسم الشبكة (network namespace). تخطَّ هذا القسم.

      الخيار 1: وضع الشبكات المرآتية (Mirrored) (مُوصى به)​

      متاح على Windows 11 22H2 فأحدث، يجعل الوضع المرآتي localhost يعمل في الاتجاهين بين Windows وWSL2 — أبسط حل.

      1. أنشئ أو حرّر %USERPROFILE%\.wslconfig (مثلًا C:\Users\YourName\.wslconfig):

        [wsl2]
        networkingMode=mirrored

      2. أعد تشغيل WSL من PowerShell:

        wsl --shutdown

      3. أعد فتح طرفية WSL2 لديك. يصل localhost الآن إلى خدمات Windows:

        curl http://localhost:11434/v1/models   # Ollama on Windows — works
      جدار حماية Hyper-V

      في بعض إصدارات Windows 11، يحجب جدار حماية Hyper-V الاتصالات المرآتية افتراضيًا. إذا استمر localhost في عدم العمل بعد تفعيل الوضع المرآتي، شغّل هذا في PowerShell كمسؤول (Admin):

      Set-NetFirewallHyperVVMSetting -Name '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -DefaultInboundAction Allow

      الخيار 2: استخدام عنوان IP لمضيف Windows (Windows 10 / الإصدارات الأقدم)​

      إذا تعذّر عليك استخدام الوضع المرآتي، اعثر على عنوان IP لمضيف Windows من داخل WSL2 واستخدمه بدلًا من localhost:

      # Get the Windows host IP (the default gateway of WSL2's virtual network)
      ip route show | grep -i default | awk '{ print $3 }'
      # Example output: 172.29.192.1

      استخدم هذا العنوان في إعدادات Hermes لديك:

      model:
        default: qwen2.5-coder:32b
        provider: custom
        base_url: http://172.29.192.1:11434/v1   # Windows host IP, not localhost
      مساعد ديناميكي

      قد يتغيّر عنوان IP للمضيف عند إعادة تشغيل WSL2. يمكنك جلبه ديناميكيًا في shell لديك:

      export WSL_HOST=$(ip route show | grep -i default | awk '{ print $3 }')
      echo "Windows host at: $WSL_HOST"
      curl http://$WSL_HOST:11434/v1/models   # Test Ollama

      أو استخدم اسم mDNS الخاص بجهازك (يتطلّب libnss-mdns في WSL2):

      sudo apt install libnss-mdns
      curl http://$(hostname).local:11434/v1/models

      عنوان ربط الخادم (مطلوب لوضع NAT)​

      إذا كنت تستخدم الخيار 2 (وضع NAT بعنوان IP للمضيف)، يجب أن يقبل خادم النموذج على Windows الاتصالات من خارج 127.0.0.1. تنصت معظم الخوادم افتراضيًا على localhost فقط — تأتي اتصالات WSL2 في وضع NAT من شبكة فرعية افتراضية مختلفة وسترفض. في الوضع المرآتي، يُطابِق localhost مباشرةً، لذا يعمل الربط الافتراضي 127.0.0.1 بلا مشكلة.

      الخادمالربط الافتراضيكيفية الإصلاح
      Ollama127.0.0.1اضبط متغير البيئة OLLAMA_HOST=0.0.0.0 قبل بدء تشغيل Ollama (System Settings → Environment Variables على Windows، أو حرّر خدمة Ollama)
      LM Studio127.0.0.1فعّل "Serve on Network" في تبويب Developer → إعدادات Server
      llama-server127.0.0.1أضف --host 0.0.0.0 إلى أمر التشغيل
      vLLM0.0.0.0يرتبط بجميع الواجهات افتراضيًا بالفعل
      SGLang127.0.0.1أضف --host 0.0.0.0 إلى أمر التشغيل

      Ollama على Windows (بالتفصيل): يعمل Ollama كخدمة Windows. لضبط OLLAMA_HOST:

      1. افتح System Properties → Environment Variables
      2. أضف متغير نظام جديدًا: OLLAMA_HOST = 0.0.0.0
      3. أعد تشغيل خدمة Ollama (أو أعد تشغيل الجهاز)

      جدار حماية Windows​

      يعامل جدار حماية Windows شبكة WSL2 كشبكة منفصلة (في كلا وضعَي NAT والمرآتي). إذا استمر فشل الاتصالات بعد الخطوات أعلاه، أضف قاعدة جدار حماية لمنفذ خادم النموذج لديك:

      # Run in Admin PowerShell — replace PORT with your server's port
      New-NetFirewallRule -DisplayName "Allow WSL2 to Model Server" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 11434

      المنافذ الشائعة: Ollama 11434، وvLLM 8000، وSGLang 30000، وllama-server 8080، وLM Studio 1234.

      تحقّق سريع​

      من داخل WSL2، اختبر أنه يمكنك الوصول إلى خادم النموذج لديك:

      # Replace URL with your server's address and port
      curl http://localhost:11434/v1/models          # Mirrored mode
      curl http://172.29.192.1:11434/v1/models       # NAT mode (use your actual host IP)

      إذا حصلت على استجابة JSON تسرد نماذجك، فأنت جاهز. استخدم نفس هذا العنوان كـ base_url في إعدادات Hermes لديك.

      استكشاف أخطاء النماذج المحلية وإصلاحها​

      اكتشاف طول السياق​

      نوافذ السياق وحدود المخرجات مختلفتان

      context_length هي نافذة السياق الكاملة — الميزانية المجمّعة لـ tokens الإدخال و الإخراج (مثلًا 200,000 لـ Claude Opus 4.6). يستخدمها Hermes لتحديد متى يضغط السجل التاريخي وللتحقق من صحة طلبات API.

      تحكم حدود المخرجات استجابة واحدة مُولَّدة، وليس سجل المحادثة. لم يعد Hermes يقرأ model.max_tokens أو HERMES_MAX_TOKENS أو إعدادات سقف مخرجات المزوّد أو model_overrides.*.*.max_output_tokens. أزل هذه الإعدادات القديمة. لا تحصل نقاط النهاية المخصّصة المتوافقة مع OpenAI على سقف مخرجات تلقائي بحجم الكتالوج. تُطبَّق قيم الخادم الافتراضية؛ وقد تكون أقل من الحد الأقصى للنموذج.

      يتطلّب Anthropic Messages الأصلي (بما في ذلك مسار Anthropic Bedrock الأصلي) max_tokens، لذا يوفّر Hermes قيمة داخلية. Bedrock Converse بروتوكول منفصل: يُهمَل معامل inferenceConfig.maxTokens الاختياري افتراضيًا، والذي توثّقه AWS بأنه الحد الأقصى للنموذج. تبقى المهام الداخلية المقيَّدة ومتطلبات البروتوكول الخاصة بالمزوّد تفاصيل تنفيذ. الإهمال لا يختار عالميًا الحد الأقصى لمخرجات النموذج.

      اضبط context_length عندما يخطئ الاكتشاف التلقائي في تحديد حجم النافذة.

      يستخدم Hermes سلسلة تحليل متعددة المصادر لاكتشاف نافذة السياق الصحيحة لنموذجك ومزوّدك:

      1. تجاوز الإعدادات — model.context_length في config.yaml (أعلى أولوية)
      2. مزوّد مخصّص لكل نموذج — providers.<name>.models.<id>.context_length
      3. تخزين مؤقت دائم — قيم مكتشَفة سابقًا (تبقى بعد إعادة التشغيل)
      4. endpoint /models — يستعلم واجهة خادمك (للـ endpoints المحلية/المخصّصة)
      5. /v1/models الخاص بـ Anthropic — يستعلم واجهة Anthropic عن max_input_tokens (لمستخدمي مفتاح API فقط)
      6. واجهة OpenRouter — بيانات وصفية حية للنموذج من OpenRouter
      7. Nous Portal — مطابقة اللواحق لمعرّفات نماذج Nous مقابل بيانات OpenRouter الوصفية
      8. models.dev — سجل يديره المجتمع بأطوال سياق خاصة بكل مزوّد لأكثر من 3800 نموذج عبر أكثر من 100 مزوّد
      9. قيم احتياطية افتراضية — أنماط عائلة نموذج عامة (128K افتراضيًا)

      يعمل هذا بشكل جاهز في معظم الإعدادات. النظام واعٍ بالمزوّد — فقد يكون لنفس النموذج حدود سياق مختلفة تبعًا لمن يقدّمه (مثلًا claude-opus-4.6 بحجم 1M مباشرةً من Anthropic لكن 128K على GitHub Copilot).

      لضبط طول السياق صراحةً، أضف context_length إلى إعدادات نموذجك:

      model:
        default: "qwen3.5:9b"
        base_url: "http://localhost:8080/v1"
        context_length: 131072  # tokens

      بالنسبة للـ endpoints المخصّصة، يمكنك أيضًا ضبط طول السياق لكل نموذج:

      providers:
        my-local-llm:
          api: "http://localhost:11434/v1"
          models:
            qwen3.5:27b:
              context_length: 64000
            deepseek-r1:70b:
              context_length: 65536

      سيطلب منك hermes model إدخال طول السياق عند ضبط endpoint مخصّص. اتركه فارغًا للاكتشاف التلقائي.

      متى تضبط هذا يدويًا
      • تستخدم Ollama مع num_ctx مخصّص أقل من الحد الأقصى للنموذج
      • تريد تقييد السياق أقل من الحد الأقصى للنموذج (مثلًا 8k على نموذج 128k لتوفير VRAM)
      • تعمل خلف وسيط (proxy) لا يعرض /v1/models

      مزوّدون مخصّصون مُسمّون​

      إذا كنت تعمل مع عدة endpoints مخصّصة (مثل خادم تطوير محلي وخادم GPU بعيد)، يمكنك تعريفها كمزوّدين مخصّصين مُسمّين تحت قاموس providers: في config.yaml، مفهرَسة باسم المزوّد:

      providers:
        local:
          api: http://localhost:8080/v1
          # api_key omitted — Hermes uses "no-key-required" for keyless local servers
        work:
          api: https://gpu-server.internal.corp/v1
          key_env: CORP_API_KEY
          transport: chat_completions   # set explicitly by `hermes model` → Custom Endpoint wizard; auto-detection still happens as a fallback
        anthropic-proxy:
          api: https://proxy.example.com/anthropic
          key_env: ANTHROPIC_PROXY_KEY
          transport: anthropic_messages  # for Anthropic-compatible proxies

      يقبل كل إدخال: api (الـ base URL للـ endpoint — base_url/url أسماء بديلة مقبولة)، وname (اسم عرض اختياري؛ الافتراضي هو مفتاح القاموس)، وkey_env أو api_key المضمَّن أو key_cmd (انظر أدناه)، وtransport (chat_completions / anthropic_messages / codex_responses)، وdefault_model، وmodels، وcontext_length، وdiscover_models، وextra_body، وextra_headers، وssl_ca_cert / ssl_verify، وenabled: false لإخفاء إدخال دون حذفه.

      بيانات اعتماد مُصكوكة بأمر (key_cmd)​

      تجسّد فحوصات القدرة (probes) للرؤية والتفكير والنماذج المحلية الأصلية نفس بيانات الاعتماد القابلة للاستدعاء (callable) المستخدَمة من المحادثة قبل بناء ترويسات المصادقة. تعيد استخدام ذاكرة تخزين رمز الأمر المؤقتة دون استبدال العنصر القابل للاستدعاء الخاص بعميل المحادثة. إذا تعذّر على أمر ما صك رمز نصي، ترسل هذه الفحوصات المبذولة (best-effort) بلا bearer بدلًا من تمثيل ككائن أو بيانات اعتماد مُهيَّأة ذات أولوية أدنى. تزيل فحوصات النماذج المحلية الأصلية ترويسة Authorization الموروثة عند فشل الاستدعاء الصريح مع الاحتفاظ بالترويسات المُهيَّأة غير ذات الصلة. تحتفظ المحادثة بمعالجة أخطائها المعتادة.

      غالبًا ما تُصدر بوابات المؤسسات رموزًا مؤقتة قصيرة الأجل (وسطاء SSO/OIDC، وIAM السحابي، ووكلاء المصادقة الداخليون) بدلًا من مفاتيح API ثابتة، لذا يصبح الرمز المنسوخ إلى .env قديمًا في منتصف الجلسة وتبدأ الطلبات بإعادة 401. يسمّي key_cmd أمرًا يطبع رمزًا؛ يشغّله Hermes ويخزّن النتيجة مؤقتًا حتى قبيل انتهاء صلاحيتها بقليل، بحيث تبقى الجلسات الطويلة تعمل دون إعادة تشغيل:

      providers:
        my-gateway:
          base_url: "https://gateway.internal.example.com/v1"
          api_mode: chat_completions
          key_cmd: "my-auth-cli print-token --profile prod"

      يعمل مع أي مساعد يطبع رمزًا — databricks auth token، وgcloud auth print-access-token، وaz account get-access-token، وvault read، أو سكربتات apiKeyHelper على طراز Claude Code.

      يجب أن يطبع الأمر فقط الرمز على stdout: إما مجرَّدًا، أو كـ JSON بحقل access_token (يُعتَد بـ expires_in؛ وكذلك الطوابع الزمنية المطلقة بصيغة ISO مثل expiry/expiresOn). تُرفَض المخرجات متعددة الأسطر بدلًا من تخمينها. إذا لم تُعلَن مدة انتهاء صلاحية، يُعاد صك الرمز ضمن نافذة محدودة.

      الأولوية: يفوز إعلام --api-key الصريح دائمًا؛ وإلا فإن key_cmd يتفوّق على api_key/key_env الثابتَين في نفس الإدخال. تنطبق بيانات الاعتماد المصكوكة على دور الوكيل الرئيسي وعلى المهام المساعدة (توليد العناوين، والضغط، والرؤية، والتضمين) على حد سواء.

      يعتد اكتشاف النماذج أيضًا بـ key_cmd لكل من إدخالات providers: و custom_providers: القديمة، بما في ذلك إعداد hermes model. تُشغَّل المساعدات فقط عندما تكون هناك حاجة لفحص كتالوج حي مصادَق عليه: لا تصك رموزًا كل من اكتشاف الكتالوج المعطَّل وقراءات الكتالوج المخزَّن مؤقتًا الدافئة. تُحصَر الكتالوجات بهوية الأمر، لذا فإن تدوير bearer لا يبطل الكتالوج. تستخدم مساعدات الفحص مصدر رمز قصير الأجل خاصًا بها، وليس ذاكرة تخزين رمز عميل الاستدلال المؤقتة؛ لا تُحفَظ الرموز المصكوكة أبدًا في config.yaml. إذا فشل مساعد، يرجع الاكتشاف إلى النموذج المُهيَّأ دون كشف مخرجات المساعد.

      لا يُخلَط هذا مع secrets.command، الذي يشغّل مساعدًا مرة واحدة عند بدء التشغيل لتعبئة متغيرات البيئة على مستوى العملية بأكملها. استخدم ذلك لمساعد خزنة/سلسلة مفاتيح يعيد أسرارًا كثيرة؛ واستخدم key_cmd عندما يجب إعادة صك بيانات اعتماد مزوّد واحد أثناء الجلسة.

      الصيغة القديمة

      استخدمت الإعدادات الأقدم قائمة custom_providers: من المستوى الأعلى بدلًا من ذلك. لا تزال تعمل — يقرأ Hermes كلا الصيغتين — ويرحّلها hermes update تلقائيًا إلى قاموس providers: (config v12). تختلف أسماء الحقول قليلًا في صيغة القاموس: يصبح model القديم هو default_model، ويصبح api_mode القديم هو transport.

      تحتاج بعض الـ endpoints المتوافقة مع OpenAI حقولًا خاصة بالمزوّد في جسم الطلب. أضف خريطة extra_body إلى المزوّد المخصّص المطابق وسيدمجها Hermes في كل طلب chat-completions لذلك الـ endpoint:

      providers:
        gemma-local:
          api: http://localhost:8080/v1
          default_model: google/gemma-4-31b-it
          extra_body:
            enable_thinking: true
            reasoning_effort: high

      استخدم الشكل الذي يوثّقه خادمك. على سبيل المثال، تتوقع نشرات vLLM Gemma وبعض endpoints من NVIDIA NIM أن يكون enable_thinking تحت chat_template_kwargs بدلًا من كونه حقل extra_body من المستوى الأعلى:

      extra_body:
        chat_template_kwargs:
          enable_thinking: true

      بالنسبة لنماذج استدلال Qwen المُقدَّمة عبر vLLM، يمكن استخدام هذا الشكل نفسه لتعطيل التفكير عندما يفصل مُحلِّل الاستدلال كل النص المُولَّد إلى حقول استدلال ويترك content الخاص بالمساعد فارغًا:

      extra_body:
        chat_template_kwargs:
          enable_thinking: false

      يرافق extra_body المُهيَّأ المزوّد في كل مكان: يُدمَج عند إنشاء الوكيل، ويبقى قائمًا عبر كل دور في الـ gateway (بما في ذلك الأدوار التي تضيف فيها /fast تجاوزات service_tier/speed فوقه — تُدمَج هذه فوق extra_body الخاص بك بدلًا من استبداله)، ويُعاد اشتقاقه عند تبديل /model — فالتبديل إلى مزوّد مخصّص مُسمّى يطبّق extra_body الخاص به، والتبديل بعيدًا عنه يمحوه بحيث لا يتسرّب إلى مزوّد آخر.

      يطلب معالج hermes model → Custom Endpoint الآن وضع API صراحةً ويحفظ إجابتك في config.yaml (كـ transport في إدخال المزوّد). لا يزال الاكتشاف التلقائي المستند إلى الرابط (مثل مسارات /anthropic → anthropic_messages) يحدث كاحتياط عند ترك الحقل فارغًا.

      الرؤية الأصلية لنماذج المزوّد المخصّص. إذا كان endpoint المخصّص لديك يقدّم نموذجًا يدعم الرؤية غير موجود في models.dev، اضبط model.supports_vision: true بحيث يوجّه Hermes الصور المرفقة أصليًا (كأجزاء image_url) بدلًا من معالجتها مسبقًا عبر vision_analyze. مفتاح واحد فقط — لا حاجة لضبط agent.image_input_mode: native أيضًا.

      model:
        provider: custom
        base_url: http://localhost:8080/v1
        default: qwen3.6-35b-a3b
        supports_vision: true   # send images natively; otherwise vision_analyze pre-describes them

      يُعتَد بنفس المفتاح في نماذج المزوّدين المُسمّين لكل نموذج (providers.<name>.models.<id>.supports_vision) ويقبل قيم YAML المنطقية القياسية (true/false/yes/no/on/off/1/0).

      بدِّل بينها أثناء الجلسة عبر الصيغة الثلاثية:

      /model custom:local:qwen-2.5       # Use the "local" endpoint with qwen-2.5
      /model custom:work:llama3-70b      # Use the "work" endpoint with llama3-70b
      /model custom:anthropic-proxy:claude-sonnet-4  # Use the proxy

      يمكنك أيضًا اختيار المزوّدين المخصّصين المُسمّين من قائمة hermes model التفاعلية.

      كتاب وصفات: Together AI، Groq، Perplexity​

      يتحدث جميع مزوّدي السحابة المذكورين في مزوّدون متوافقون آخرون لهجة REST الخاصة بـ OpenAI، لذا يُوصَلون بنفس الطريقة تحت قاموس providers:. فيما يلي ثلاث وصفات جاهزة. تدخل كل واحدة في ~/.hermes/config.yaml ويذهب مفتاح API المطابق إلى ~/.hermes/.env.

      Together AI​

      يستضيف نماذج مفتوحة الأوزان (Llama، وMiniMax، وGemma، وDeepSeek، وQwen) بأسعار أقل بكثير من واجهات API الأصلية. خيار افتراضي جيد لأساطيل النماذج المتعددة.

      # ~/.hermes/config.yaml
      providers:
        together:
          api: https://api.together.xyz/v1
          key_env: TOGETHER_API_KEY
          # transport: chat_completions  # default — no need to set

      model:
        default: MiniMaxAI/MiniMax-M2.7   # or any model from together.ai/models
        provider: custom:together
      # ~/.hermes/.env
      TOGETHER_API_KEY=your-together-key

      بدّل النماذج أثناء الجلسة:

      /model custom:together:meta-llama/Llama-3.3-70B-Instruct-Turbo
      /model custom:together:google/gemma-4-31b-it
      /model custom:together:deepseek-ai/DeepSeek-V3

      واجهة /v1/models الخاصة بـ Together تعمل، لذا يمكن لـ hermes model اكتشاف النماذج المتاحة تلقائيًا.

      Groq​

      استدلال فائق السرعة (~500 tok/s على Llama-3.3-70B). كتالوج صغير لكنه قوي للاستخدام التفاعلي الحسّاس لزمن الاستجابة.

      # ~/.hermes/config.yaml
      providers:
        groq:
          api: https://api.groq.com/openai/v1
          key_env: GROQ_API_KEY

      model:
        default: llama-3.3-70b-versatile
        provider: custom:groq
      # ~/.hermes/.env
      GROQ_API_KEY=your-groq-key

      Perplexity​

      مفيد عندما تريد نموذجًا يقوم ببحث ويب حي واستشهاد تلقائيًا. صارم بشأن النماذج المتاحة — تحقّق من perplexity.ai/settings/api للاطلاع على القائمة الحالية.

      # ~/.hermes/config.yaml
      providers:
        perplexity:
          api: https://api.perplexity.ai
          key_env: PERPLEXITY_API_KEY

      model:
        default: sonar
        provider: custom:perplexity
      # ~/.hermes/.env
      PERPLEXITY_API_KEY=your-perplexity-key

      عدة مزوّدين في إعداد واحد​

      تتركّب الوصفات الثلاث معًا — استخدمها كلها معًا وبدّل حسب كل دور عبر /model custom:<name>:<model>:

      providers:

          key_env: TOGETHER_API_KEY

      model:

        provider: custom:together      # boot to Together; switch freely after
      استكشاف الأخطاء وإصلاحها
      • يجب ألا يطبع hermes doctor أي تحذيرات Unknown provider لأي من هذه الأسماء بعد إصلاحات مُدقِّق CLI في #15083.
      • إذا تعذّر الوصول إلى endpoint /v1/models الخاص بمزوّد ما (Perplexity هي الحالة الشائعة)، سيحفظ hermes model النموذج مع تحذير بدلًا من الرفض الصارم — انظر #15136.
      • لتخطّي المزوّدين المُسمّين تمامًا واستخدام provider: custom المجرَّد مع متغير البيئة CUSTOM_BASE_URL، انظر #15103.

      استضافة Firecrawl ذاتيًا​

      افتراضيًا، يستخدم Hermes واجهة Firecrawl السحابية للبحث في الويب واستخراج بياناته. إذا كنت تفضّل تشغيل Firecrawl محليًا، يمكنك توجيه Hermes إلى نسخة مستضافة ذاتيًا بدلًا من ذلك. راجع ملف SELF_HOST.md الخاص بـ Firecrawl للاطلاع على تعليمات الإعداد الكاملة.

      ما تحصل عليه: دون الحاجة لمفتاح API، ودون حدود معدل، ودون تكاليف لكل صفحة، وسيادة كاملة على البيانات.

      ما تفقده: تستخدم النسخة السحابية محرّك "Fire-engine" المملوك لـ Firecrawl لتجاوز أنظمة مكافحة الروبوتات المتقدمة (Cloudflare، وCAPTCHAs، وتدوير عناوين IP). تستخدم النسخة المستضافة ذاتيًا الجلب الأساسي (fetch) + Playwright، لذا قد تفشل بعض المواقع المحمية. يستخدم البحث DuckDuckGo بدلًا من Google.

      الإعداد:

      1. استنسخ (Clone) وشغّل حزمة Firecrawl على Docker (5 حاويات: API، وPlaywright، وRedis، وRabbitMQ، وPostgreSQL — تتطلّب حوالي 4-8 جيجابايت من الذاكرة):

        git clone https://github.com/firecrawl/firecrawl
        cd firecrawl
        # In .env, set: USE_DB_AUTHENTICATION=false, HOST=0.0.0.0, PORT=3002
        docker compose up -d

      2. وجّه Hermes إلى نسختك (دون الحاجة لمفتاح API):

        hermes config set FIRECRAWL_API_URL http://localhost:3002

      يمكنك أيضًا ضبط كل من FIRECRAWL_API_KEY وFIRECRAWL_API_URL إذا كانت نسختك المستضافة ذاتيًا تفعّل المصادقة.

      توجيه مزوّدي OpenRouter​

      عند استخدام OpenRouter، يمكنك التحكم في كيفية توجيه الطلبات عبر المزوّدين. أضف قسم provider_routing إلى ~/.hermes/config.yaml:

      provider_routing:
        sort: "throughput"          # "price" (default), "throughput", or "latency"
        # only: ["anthropic"]      # Only use these providers
        # ignore: ["deepinfra"]    # Skip these providers
        # order: ["anthropic", "google"]  # Try providers in this order
        # require_parameters: true  # Only use providers that support all request params
        # data_collection: "deny"   # Exclude providers that may store/train on data
        # models:                   # Per-model pins (same keys; unset keys fall through)
        #   "openai/gpt-6-astra": {only: ["openai"]}
        #   "anthropic/claude-fable-5.1": {only: ["anthropic"]}

      اختصارات: ألحق :nitro بأي اسم نموذج للترتيب حسب الإنتاجية (throughput) (مثل anthropic/claude-sonnet-4:nitro)، أو :floor للترتيب حسب السعر. تفاصيل لكل نموذج: توجيه المزوّدين.

      موجّه OpenRouter Pareto Code​

      يقدّم OpenRouter موجّه نماذج برمجة تجريبيًا عند openrouter/pareto-code يوجّه الطلبات تلقائيًا إلى أرخص نموذج يستوفي حدًا أدنى لجودة البرمجة (مُرتَّب بواسطة Artificial Analysis). اختر هذا النموذج واضبط مفتاح min_coding_score في ~/.hermes/config.yaml:

      model:
        provider: openrouter
        model: openrouter/pareto-code

      openrouter:
        min_coding_score: 0.65   # 0.0–1.0; higher = stronger (more expensive) coders. Default 0.65.

      ملاحظات:

      • يُرسَل min_coding_score فقط عندما يكون model.model هو openrouter/pareto-code. على أي نموذج آخر، القيمة بلا أثر.
      • اضبطه على سلسلة نصية فارغة (أو أزل السطر) للسماح لـ OpenRouter باختيار أقوى مبرمج متاح — وهو سلوكه الموثَّق عند حذف قسم الإضافات (plugins).
      • الاختيار حتمي حسب الدرجة في يوم معين، لكن النموذج الفعلي المختار قد يتغيّر مع تحرّك حدود باريتو (Pareto frontier) (نماذج جديدة، تحديثات في معايير القياس).
      • راجع وثائق موجّه Pareto الخاصة بـ OpenRouter للاطلاع على السلوك الكامل للموجّه.
      • لاستخدام موجّه Pareto Code لـ مهمة مساعدة محدَّدة (الضغط، الرؤية، إلخ) بدلًا من الوكيل الرئيسي، اضبط extra_body.plugins تحت تلك المهمة — راجع النماذج المساعدة ← توجيه OpenRouter وPareto Code للمهام المساعدة.

      المزوّدون الاحتياطيون (Fallback Providers)​

      اضبط سلسلة من المزوّدين الاحتياطيين يجرّبها Hermes بالترتيب عندما يفشل النموذج الرئيسي (حدود المعدل، وأخطاء الخادم، وفشل المصادقة). الصيغة القياسية هي قائمة fallback_providers: من المستوى الأعلى:

      fallback_providers:
        - provider: openrouter
          model: anthropic/claude-sonnet-4
        - provider: anthropic
          model: claude-sonnet-4
          # base_url: http://localhost:8000/v1    # optional, for custom endpoints
          # api_mode: chat_completions           # optional override

      لا يزال قاموس fallback_model: القديم أحادي الزوج مقبولًا للتوافق مع الإصدارات السابقة:

      fallback_model:
        provider: openrouter
        model: anthropic/claude-sonnet-4

      عند التفعيل، يبدّل الاحتياط النموذج والمزوّد أثناء الجلسة دون فقدان محادثتك. تُجرَّب السلسلة إدخالًا تلو الآخر؛ التفعيل يحدث مرة واحدة لكل جلسة.

      المزوّدون المدعومون: openrouter، وnous، وnovita، وopenai-codex، وcopilot، وcopilot-acp، وanthropic، وgemini، وqwen-oauth، وhuggingface، وzai، وkimi-coding، وkimi-coding-cn، وminimax، وminimax-cn، وminimax-oauth، وdeepseek، وnvidia، وxai، وxai-oauth، وollama-cloud، وbedrock، وai-gateway، وazure-foundry، وopencode-zen، وopencode-go، وcommandcode، وcommandcode-anthropic، وkilocode، وxiaomi، وarcee، وgmi، وactual، وstepfun، وlmstudio، وalibaba، وalibaba-coding-plan، وtencent-tokenhub، وtencent-tokenplan، وnebius-token-factory، وrouter، وcustom.

      نصيحة

      يُضبَط الاحتياط حصرًا عبر config.yaml — أو تفاعليًا عبر hermes fallback. للاطلاع على التفاصيل الكاملة حول متى يُفعَّل، وكيف تتقدّم السلسلة، وكيف يتفاعل مع المهام المساعدة والتفويض، راجع المزوّدون الاحتياطيون.
