      التثبيت

      شغّل Hermes Agent واجعله جاهزًا للعمل في أقل من دقيقتين!

      دعم المنصات

      للاطلاع على مصفوفة دعم المنصات الكاملة (أنظمة التشغيل وطرق التوزيع المدعومة، والميزات المقتصرة على منصات معيّنة)، راجع دعم المنصات.

      التثبيت السريع​

      باستخدام مُثبّت Hermes Desktop على macOS أو Windows (موصى به)​

      لتثبيت تطبيقَي سطر الأوامر وسطح المكتب بسهولة، نزّل مُثبّت Hermes Desktop من موقعنا وشغّله.

      بدون Hermes Desktop:​

      لتثبيت سطر الأوامر فقط دون Hermes Desktop، نفّذ:

      Linux / macOS / WSL2 / Android (Termux)​

      curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

      Windows (تثبيت أصلي)​

      نفّذ في PowerShell:

      iex (irm https://hermes-agent.nousresearch.com/install.ps1)

      إذا أردت تثبيت Hermes Desktop وتشغيله بعد تثبيت سطر الأوامر فقط، فنفّذ ببساطة:

      hermes desktop

      ما الذي يفعله المُثبّت​

      يتولى المُثبّت كل شيء تلقائيًا — جميع الاعتماديات (Python و Node.js و ripgrep و ffmpeg)، واستنساخ المستودع، والبيئة الافتراضية (virtual environment)، وإعداد الأمر العام hermes، وإعدادات مزوّد LLM. وفي النهاية، تصبح جاهزًا لبدء المحادثة.

      بنية التثبيت​

      يعتمد المكان الذي يضع فيه المُثبّت الملفات على ما إذا كنت تثبّت كمستخدم عادي أو كمستخدم root:

      المُثبّتموقع الكودالملف التنفيذي hermesمجلد البيانات
      لكل مستخدم (مُثبّت git)~/.hermes/hermes-agent/~/.local/bin/hermes (رابط رمزي symlink)~/.hermes/
      وضع root (sudo curl … | sudo bash)/usr/local/lib/hermes-agent//usr/local/bin/hermes/root/.hermes/ (أو $HERMES_HOME)

      تتوافق بنية FHS في وضع root (/usr/local/lib/…، /usr/local/bin/hermes) مع المواقع التي تُثبَّت فيها أدوات المطورين الأخرى على مستوى النظام في Linux. وهي مفيدة لعمليات النشر على الأجهزة المشتركة، حيث ينبغي أن يخدم تثبيت واحد على مستوى النظام جميع المستخدمين. أما الإعدادات الخاصة بكل مستخدم (المصادقة والمهارات والجلسات) فتبقى داخل ~/.hermes/ لكل مستخدم أو في HERMES_HOME المحدد صراحةً.

      بعد التثبيت​

      أعد تحميل الـ shell وابدأ المحادثة:

      source ~/.bashrc   # or: source ~/.zshrc
      hermes             # Start chatting!

      لإعادة ضبط إعدادات بعينها لاحقًا، استخدم الأوامر المخصصة لها:

      hermes model          # Choose your LLM provider and model
      hermes tools          # Configure which tools are enabled
      hermes gateway setup  # Set up messaging platforms
      hermes config set     # Set individual config values
      hermes config get     # Inspect individual config values
      hermes setup          # Or run the full setup wizard to configure everything at once
      الطريق الأسرع: Nous Portal

      اشتراك واحد يغطي أكثر من 300 نموذج، إضافةً إلى Tool Gateway (البحث في الويب، وتوليد الصور، و TTS، والمتصفح السحابي). وفّر على نفسك عناء إدارة مفتاح لكل أداة:

      hermes setup --portal

      يسجّل هذا الأمر دخولك، ويضبط Nous مزوّدًا لك، ويفعّل Tool Gateway، كل ذلك بأمر واحد.

      هل تشغّل Hermes بالفعل على جهاز آخر؟

      لا تحتاج إلى إعادة بناء إعدادك من الصفر. استعد نسخة احتياطية كاملة باستخدام hermes import (راجع تصدير Hermes إلى جهاز آخر)، أو انقل وكيلًا واحدًا باستخدام hermes profile import (راجع نقل profile واحد إلى جهاز آخر). لاحظ أن تصدير الـ profile يستبعد بيانات الاعتماد عن قصد، لذا فإن التصدير وحده ليس نسخة احتياطية كاملة — يشرح قسم hermes backup مقابل hermes profile export متى تستخدم كلًا منهما.

      المتطلبات المسبقة​

      المُثبّت: على المنصات غير Windows، المتطلب المسبق الوحيد هو Git. وعلى Linux، تأكد أيضًا من توفر curl و xz-utils (إذ ينزّل المُثبّت Node.js كأرشيف .tar.xz). ويتطلب تطبيق سطح المكتب كذلك g++ (أو build-essential على Debian/Ubuntu) لتصريف الوحدات الأصلية (native modules). ويتولى المُثبّت كل ما عدا ذلك تلقائيًا:

      • uv (مدير حزم Python سريع)
      • Python 3.11 (عبر uv، دون الحاجة إلى sudo)
      • Node.js v26 (لأتمتة المتصفح وجسر WhatsApp؛ وإذا كان Node 22.22+ أو 24.11+ أو 26+ مثبّتًا على النظام فيُستخدم كما هو)
      • ripgrep (بحث سريع في الملفات)
      • ffmpeg (تحويل صيغ الصوت لـ TTS)
      معلومة

      أنت لا تحتاج إلى تثبيت Python أو Node.js أو ripgrep أو ffmpeg يدويًا. يكتشف المُثبّت ما ينقص ويثبّته نيابةً عنك. فقط تأكد من توفر git (git --version). وعلى Linux، تأكد من تثبيت curl و xz-utils (sudo apt install curl xz-utils على Debian/Ubuntu). ولتطبيق سطح المكتب، ثبّت أيضًا build-essential (sudo apt install build-essential).

      مستخدمو Nix

      لم يعد Nix مسار تثبيت مدعومًا صراحةً (يُقدَّم الدعم بأفضل جهد فقط). إذا كنت تستخدم Nix بالفعل (على NixOS أو macOS أو Linux)، فهناك مسار إعداد مخصص يتضمن Nix flake، ووحدة NixOS تصريحية (declarative)، ووضع حاوية اختياريًا. راجع دليل إعداد Nix و NixOS.

      التثبيت اليدوي / للمطورين​

      إذا أردت استنساخ المستودع والتثبيت من المصدر — للمساهمة، أو للتشغيل من branch محدد، أو للتحكم الكامل في البيئة الافتراضية — فراجع قسم إعداد بيئة التطوير في دليل المساهمة.

      التثبيت دون sudo / لمستخدمي خدمات النظام​

      تشغيل Hermes كمستخدم مخصص غير ذي امتيازات (مثل حساب خدمة systemd باسم hermes، أو أي مستخدم لا يملك صلاحية sudo) مدعوم. الشيء الوحيد في مسار التثبيت الذي يحتاج فعلًا إلى root هو خطوة --with-deps الخاصة بـ Playwright، والتي تثبّت عبر apt مكتبات مشتركة (libnss3 و libxkbcommon وغيرها) يستخدمها Chromium. يكتشف المُثبّت ما إذا كان sudo متاحًا، ويتكيّف بسلاسة عند عدم توفره — فيثبّت الملف التنفيذي لـ Chromium في ذاكرة Playwright المؤقتة (cache) الخاصة بمستخدم الخدمة، ويطبع الأمر الدقيق الذي يجب على المسؤول تنفيذه بشكل منفصل.

      التقسيم الموصى به (Debian/Ubuntu):

      1. لمرة واحدة، كمستخدم مسؤول لديه sudo، ثبّت مكتبات النظام التي يحتاجها Chromium:

        sudo npx playwright install-deps chromium

        (يمكنك تنفيذ هذا من أي مكان — إذ سيجلب npx حزمة Playwright فورًا.)

      2. كمستخدم الخدمة غير ذي الامتيازات، شغّل المُثبّت العادي. سيكتشف غياب sudo، ويتخطى --with-deps، ويثبّت Chromium في ذاكرة Playwright المؤقتة المحلية للمستخدم:

        curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

        إذا أردت تخطي خطوة Playwright كليًا — مثلًا لأنك تعمل دون واجهة رسومية (headless) ولا تحتاج إلى أتمتة المتصفح — فمرّر --skip-browser:

        curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash -s -- --skip-browser

        يثبّت المُثبّت مسبقًا أيضًا cua-driver كي يعمل toolset الخاص بـ Computer Use لحظة تفعيله؛ مرّر --skip-computer-use لإلغاء ذلك (وسيُثبَّت حينها عند الطلب عندما تفعّل الأداة).

      3. اجعل hermes متاحًا في الـ shell الخاص بمستخدم الخدمة. يكتب المُثبّت المُشغّل (launcher) في ~/.local/bin/hermes. وغالبًا ما تمتلك حسابات خدمات النظام متغير PATH محدودًا لا يتضمن ~/.local/bin. إما أن تضيفه إلى بيئة المستخدم، أو أن تنشئ رابطًا رمزيًا للمُشغّل في موقع على مستوى النظام:

        # Option A — add to the service user's profile
        echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc

        # Option B — symlink system-wide (run as an admin)
        sudo ln -s /home/hermes/.hermes/hermes-agent/venv/bin/hermes /usr/local/bin/hermes

      4. التحقق: يُفترض أن يعمل hermes doctor الآن دون مشكلات. إذا ظهر لك ModuleNotFoundError: No module named 'dotenv'، فأنت تستدعي ملف hermes المصدري من المستودع (~/.hermes/hermes-agent/hermes) باستخدام Python الخاص بالنظام بدلًا من مُشغّل البيئة الافتراضية (~/.hermes/hermes-agent/venv/bin/hermes) — أصلح الخطوة 3.

      5. هل تشغّل messaging gateway من هذا الحساب؟ تتوقف الخدمة على مستوى المستخدم عند تسجيل الخروج ولا تبدأ عند الإقلاع ما لم تفعّل lingering لمستخدم الخدمة:

        sudo loginctl enable-linger <service-user>

        راجع Messaging Gateway لإعداد الخدمة نفسها.

      ينطبق النمط نفسه على Arch (يستخدم المُثبّت pacman بمنطق اكتشاف sudo نفسه)، و Fedora/RHEL، و openSUSE — لا تدعم هذه التوزيعات --with-deps مطلقًا، لذا يثبّت المسؤول مكتبات النظام دائمًا بشكل منفصل. ويطبع المُثبّت أوامر dnf/zypper المناسبة.

      استكشاف الأخطاء وإصلاحها​

      المشكلةالحل
      hermes: command not foundأعد تحميل الـ shell (source ~/.bashrc) أو تحقق من PATH
      API key not setنفّذ hermes model لضبط المزوّد، أو hermes config set OPENROUTER_API_KEY your_key
      إعدادات مفقودة بعد التحديثنفّذ hermes config check ثم hermes config migrate

      لمزيد من التشخيص، نفّذ hermes doctor — سيخبرك بالضبط بما ينقص وكيفية إصلاحه.

      مجلدات home المرتبطة رمزيًا والتخزين الخارجي​

      يدعم Hermes أن يكون HERMES_HOME رابطًا رمزيًا (symlink)، وكذلك المجلدات الفرعية داخله، بما في ذلك hooks و skills و sessions و logs. أثناء تهيئة مجلد home، يُحافَظ على روابط المجلدات الموجودة، وتُترك صلاحيات المجلدات المرتبطة (والمجلدات المتفرعة منها مثل logs/curator) لمالكها.

      إذا كان هدف الرابط مفقودًا أو يتعذر الوصول إليه أو ليس مجلدًا، تتوقف التهيئة بخطأ تخزين يذكر المسار وهدف الرابط. لا يستبدل Hermes الرابط ولا ينشئ هدفه المفقود: فذلك قد يؤدي إلى كتابة البيانات على القرص المحلي بينما تكون وحدة التخزين الخارجية أو وحدة NAS غير مُركّبة (unmounted). افحص الرابط المُبلَّغ عنه، وأعد تركيب وحدة التخزين أو صحّح هدف الرابط، وتحقق من صلاحيات الوصول قبل إعادة المحاولة. وإذا كنت تريد عمدًا هدفًا جديدًا لملفات dotfiles، فأنشئه بنفسك فقط بعد التأكد من توفر وحدة التخزين المقصودة.

      يُبلّغ hermes doctor عن حالات الفشل هذه كمشكلات تخزين، لا كملف YAML غير صالح. احتفظ بملف config.yaml الحالي؛ فتنفيذ hermes setup ليس الحل لمجلد غير متاح. هذا فحص لتوفر المجلد، وليس أداة لمراقبة التركيب (mount): فوجود المجلد لا يثبت أن وحدة التخزين المقصودة مُركّبة.

      الاكتشاف التلقائي لطريقة التثبيت​

      يكتشف Hermes تلقائيًا ما إذا كان قد ثُبّت عبر مُثبّت git أو Docker أو NixOS، ويطبع hermes update أمر التحديث المطابق لتلك الطريقة. لا يوجد متغير بيئة يلزم ضبطه — إذ يعتمد الاكتشاف على بنية التثبيت (نسخة ~/.hermes/hermes-agent/ المستنسخة، أو علامة صورة Docker، أو مسار Nix store). ويعرض hermes doctor أيضًا الطريقة المكتشفة ضمن ملخص البيئة.
