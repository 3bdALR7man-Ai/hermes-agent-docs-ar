      تشغيل Hermes على Android باستخدام Termux

      منصة من المستوى 2

      Termux (Android) منصة من المستوى 2 (Tier 2). يُصان سكربت المُثبّت والتوثيق الوارد هنا بأفضل جهد فقط. وقد تؤدي عمليات commit إلى main إلى تعطيل هذه الحزم في أي وقت.

      يمكن تشغيل Hermes Agent مباشرةً على هاتف Android من خلال Termux.

      يوفّر لك ذلك واجهة CLI محلية تعمل على الهاتف، إضافةً إلى الإضافات (extras) الأساسية المعروف حاليًا أنها تُثبَّت دون مشكلات على Android.

      ما المدعوم في المسار المُختبَر؟​

      تثبّت حزمة Termux المُختبَرة ما يلي:

      • Hermes CLI
      • دعم cron
      • دعم PTY والطرفية في الخلفية
      • دعم Telegram gateway (تشغيل يدوي / في الخلفية بأفضل جهد)
      • دعم MCP
      • دعم ذاكرة Honcho
      • دعم ACP

      وبشكل ملموس، يقابل ذلك ما يلي:

      python -m pip install -e '.[termux]' -c constraints-termux.txt

      ما الذي لم يُضمَّن في المسار المُختبَر بعد؟​

      لا تزال بعض الميزات تحتاج إلى اعتماديات من النوع المخصص لأجهزة سطح المكتب أو الخوادم، وهي غير منشورة لـ Android، أو لم يُتحقق منها على الهواتف بعد:

      • .[all] غير مدعوم على Android حاليًا
      • الإضافة voice معطّلة بسبب faster-whisper -> ctranslate2، إذ لا تنشر ctranslate2 حزم wheels لـ Android
      • يتخطى مُثبّت Termux التهيئة التلقائية للمتصفح / Playwright
      • عزل الطرفية القائم على Docker غير متاح داخل Termux
      • قد يعلّق Android مهام Termux التي تعمل في الخلفية، لذا فإن استمرارية gateway تكون بأفضل جهد وليست كخدمة مُدارة عادية

      لا يمنع ذلك Hermes من العمل جيدًا كوكيل CLI أصلي على الهاتف — بل يعني فقط أن التثبيت الموصى به على الهاتف أضيق نطاقًا عن قصد من التثبيت على سطح المكتب أو الخادم.

      خيار pkg الأصلي الذي يصونه المجتمع​

      توزيعة يديرها أحد المساهمين

      مستودع APT هذا يصونه المجتمع عبر @adybag14-cyber وليس توزيعة رسمية من NousResearch. لا تبني NousResearch هذه الحزم ولا توقّعها ولا تستضيفها ولا تدققها. ويعني تفعيل المستودع أنك تثق بالمستودع الذي يديره المساهم وبمفتاح التوقيع الخاص به. ويظل Termux نفسه منصة من المستوى 2 / بأفضل جهد.

      للمستخدمين الذين يفضّلون التثبيت عبر مدير حزم أصلي بدلًا من بناء اعتماديات Python/Rust على الهاتف، يتوفر مستودع APT يصونه المجتمع. مصادر تهيئة المستودع والتحزيم منشورة في adybag14-cyber/termux-python، بينما يوجد بناء حزمة Hermes في adybag14-cyber/termux-hermes.

      ثبّت مفتاح المستودع ومصدره ثم Hermes باستخدام:

      curl -fsSL https://raw.githubusercontent.com/adybag14-cyber/termux-python/main/scripts/setup_apt_repo.sh | bash
      pkg install hermes-agent

      بصمة مفتاح توقيع المستودع الموثّقة حاليًا لدى توزيعة المجتمع هي:

      EAD24A2124EFA7393A78B7B14699F966313F7A6B

      تُوسَم عمليات تثبيت Hermes التي يديرها APT بطريقة التثبيت apt. لذلك لا يشغّل Hermes أداة التحديث الذاتي المعتمدة على Git على الملفات التي تملكها الحزمة؛ استخدم مدير الحزم بدلًا من ذلك:

      pkg update
      pkg upgrade hermes-agent

      يجب الإبلاغ عن مشكلات التحزيم أو المستودع أو التوقيع الخاصة بهذا الخيار في مستودعات التحزيم المجتمعية المذكورة أعلاه. أما أخطاء Hermes أثناء التشغيل فيمكن الإبلاغ عنها هنا، مع مراعاة أن دعم Android/Termux يُقدَّم بأفضل جهد.

      الخيار 1: المُثبّت بسطر واحد​

      يوفّر Hermes الآن مسار تثبيت يراعي بيئة Termux:

      curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

      على Termux، يقوم المُثبّت تلقائيًا بما يلي:

      • يستخدم pkg لحزم النظام
      • ينشئ البيئة الافتراضية (venv) باستخدام python -m venv
      • يحاول أولًا تثبيت الإضافة الشاملة .[termux-all]، ثم يعود إلى الإضافة الأصغر .[termux] (ثم إلى تثبيت أساسي) — ويتبع مُثبّت curl هذا الترتيب تلقائيًا
      • يربط hermes داخل $PREFIX/bin ليبقى ضمن PATH في Termux
      • يتخطى تهيئة المتصفح / WhatsApp غير المُختبَرة

      إذا أردت الأوامر الصريحة أو احتجت إلى تصحيح تثبيت فاشل، فاستخدم المسار اليدوي أدناه.

      الخيار 2: التثبيت اليدوي (بخطوات صريحة بالكامل)​

      1. حدّث Termux وثبّت حزم النظام​

      pkg update
      pkg install -y git python clang rust make pkg-config libffi openssl nodejs ripgrep ffmpeg

      لماذا هذه الحزم؟

      • python — بيئة التشغيل ودعم venv
      نطاق إصدارات Python المدعوم

      يتطلب Hermes Python >=3.11,<3.14. يأتي Termux حاليًا مع python 3.14.x، وهو خارج هذا النطاق — يكتشف المُثبّت ذلك، وسيحاول تلقائيًا استخدام Termux User Repository (TUR) للحصول على مفسّر مدعوم. أما في التثبيت اليدوي، فاحصل عليه بنفسك:

      pkg install tur-repo
      pkg install python3.13

      ثم استخدم python3.13 بدلًا من python في الأوامر أدناه (مثل python3.13 -m venv venv).

      • git — لاستنساخ المستودع وتحديثه
      • clang و rust و make و pkg-config و libffi و openssl — لازمة لبناء بعض اعتماديات Python على Android
      • nodejs — بيئة تشغيل Node اختيارية للتجارب خارج المسار الأساسي المُختبَر
      • ripgrep — بحث سريع في الملفات
      • ffmpeg — تحويلات الوسائط / TTS

      2. استنسخ Hermes​

      git clone https://github.com/NousResearch/hermes-agent.git
      cd hermes-agent

      3. أنشئ بيئة افتراضية​

      python -m venv venv
      source venv/bin/activate
      export ANDROID_API_LEVEL="$(getprop ro.build.version.sdk)"
      python -m pip install --upgrade pip setuptools wheel

      يُعد ANDROID_API_LEVEL مهمًا للحزم المبنية على Rust / maturin مثل jiter.

      4. ثبّت حزمة Termux المُختبَرة​

      python -m pip install -e '.[termux]' -c constraints-termux.txt

      إذا كنت تريد الوكيل الأساسي بالحد الأدنى فقط، فهذا يعمل أيضًا:

      python -m pip install -e '.' -c constraints-termux.txt

      5. أضف hermes إلى PATH في Termux​

      ln -sf "$PWD/venv/bin/hermes" "$PREFIX/bin/hermes"

      المسار $PREFIX/bin موجود بالفعل ضمن PATH في Termux، لذا يجعل هذا الأمرُ hermes متاحًا بشكل دائم في كل shell جديد دون الحاجة إلى إعادة تفعيل venv في كل مرة.

      6. تحقّق من التثبيت​

      hermes --version
      hermes doctor

      7. شغّل Hermes​

      hermes

      الإعدادات اللاحقة الموصى بها​

      اضبط نموذجًا​

      hermes model

      أو اضبط المفاتيح مباشرةً في ~/.hermes/.env.

      أعد تشغيل معالج الإعداد التفاعلي الكامل لاحقًا​

      hermes setup

      ثبّت اعتماديات Node الاختيارية يدويًا​

      يتخطى مسار Termux المُختبَر تهيئة Node والمتصفح عن قصد. إذا أردت تجربة أدوات المتصفح لاحقًا، فإن ما تحتاج إليه يعتمد على الواجهة الخلفية (backend) التي تستخدمها:

      • مزوّدو المتصفح السحابي (Browserbase و Browser Use و Firecrawl) يستضيفون Chromium الخاص بهم، لذا يكفي Node.js وحده — إذ يُحمَّل agent-browser عند أول استخدام بشكل كسول (lazily) عبر npx agent-browser:

        pkg install nodejs-lts

      • أتمتة المتصفح المحلية على Termux تحتاج إلى تثبيت فعلي لـ agent-browser — إذ يُرفض عمدًا الاعتماد على npx وحده كبديل في الوضع المحلي، لأنه هشّ جدًا بحيث لا يمكن اعتباره جاهزًا:

        pkg install nodejs-lts
        npm install -g agent-browser && agent-browser install

      تُضمّن أداة المتصفح مجلدات Termux (/data/data/com.termux/files/usr/bin) تلقائيًا في بحثها ضمن PATH، لذا يُعثر على agent-browser و npx دون أي إعداد إضافي لـ PATH.

      تعامل مع أدوات المتصفح / WhatsApp على Android على أنها تجريبية ما لم يُوثَّق خلاف ذلك.

      استكشاف الأخطاء وإصلاحها​

      ظهور No solution found عند تثبيت .[all]​

      استخدم حزمة Termux المُختبَرة بدلًا من ذلك:

      python -m pip install -e '.[termux]' -c constraints-termux.txt

      العائق حاليًا هو الإضافة voice:

      • voice تجلب faster-whisper
      • faster-whisper تعتمد على ctranslate2
      • ctranslate2 لا تنشر حزم wheels لـ Android

      فشل uv pip install على Android​

      استخدم مسار Termux مع venv من المكتبة القياسية و pip بدلًا من ذلك:

      python -m venv venv
      source venv/bin/activate
      export ANDROID_API_LEVEL="$(getprop ro.build.version.sdk)"
      python -m pip install --upgrade pip setuptools wheel
      python -m pip install -e '.[termux]' -c constraints-termux.txt

      اعتراض jiter / maturin على ANDROID_API_LEVEL​

      اضبط مستوى API صراحةً قبل التثبيت:

      export ANDROID_API_LEVEL="$(getprop ro.build.version.sdk)"
      python -m pip install -e '.[termux]' -c constraints-termux.txt

      يُبلغ hermes doctor بأن ripgrep أو Node مفقود​

      ثبّتهما باستخدام حزم Termux:

      pkg install ripgrep nodejs

      فشل البناء أثناء تثبيت حزم Python​

      تأكد من تثبيت سلسلة أدوات البناء (toolchain):

      pkg install clang rust make pkg-config libffi openssl

      ثم أعد المحاولة:

      python -m pip install -e '.[termux]' -c constraints-termux.txt

      القيود المعروفة على الهواتف​

      • الواجهة الخلفية Docker غير متاحة
      • تحويل الصوت إلى نص محليًا عبر faster-whisper غير متاح في المسار المُختبَر
      • يتخطى المُثبّت إعداد أتمتة المتصفح عن قصد
      • قد تعمل بعض الإضافات الاختيارية، لكن .[termux] و .[termux-all] فقط موثّقتان حاليًا بوصفهما حزم Android المُختبَرة

      إذا واجهت مشكلة جديدة خاصة بـ Android، فيُرجى فتح issue على GitHub يتضمن:

      • إصدار Android لديك
      • termux-info
      • python --version
      • hermes doctor
      • أمر التثبيت الدقيق ومخرجات الخطأ كاملة
