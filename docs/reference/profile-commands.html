      مرجع أوامر Profile

      تغطي هذه الصفحة كل الأوامر المتعلقة بـ profiles في Hermes. للاطلاع على أوامر CLI العامة، راجع مرجع أوامر CLI.

      hermes profile​

      hermes profile <subcommand>

      الأمر الرئيسي لإدارة profiles. تشغيل hermes profile دون أمر فرعي يعرض المساعدة.

      الأمر الفرعيالوصف
      listاسرد كل الـ profiles.
      useاضبط الـ profile النشط (الافتراضي).
      createأنشئ profile جديدًا.
      describeاقرأ وصف profile أو اضبطه (يستخدمه منسّق kanban لتوجيه المهام).
      deleteاحذف profile.
      showاعرض تفاصيل profile.
      aliasأعد توليد الاسم المستعار (alias) الخاص بـ profile في الـ shell.
      renameأعد تسمية profile.
      exportصدّر profile إلى أرشيف tar.gz.
      importاستورد profile من أرشيف tar.gz.
      installثبّت توزيعة profile من رابط git أو مجلد محلي. راجع توزيعات Profile.
      updateأعد سحب profile مُدار بتوزيعة وأعد تطبيق حزمته (bundle).
      infoاعرض بيانات التوزيعة الوصفية لـ profile (رابط الأصل، الـ commit، آخر تحديث).

      hermes profile list​

      hermes profile list

      يسرد كل الـ profiles. يُميَّز الـ profile النشط حاليًا بعلامة *.

      مثال:

      $ hermes profile list
        default
      * work
        dev
        personal

      لا خيارات.

      hermes profile use​

      hermes profile use <name>

      يضبط <name> بوصفه الـ profile النشط. ستستخدم كل أوامر hermes اللاحقة (دون -p) هذا الـ profile.

      المعطىالوصف
      <name>اسم الـ profile المراد تفعيله. استخدم default للعودة إلى الـ profile الأساسي.

      مثال:

      hermes profile use work
      hermes profile use default

      hermes profile create​

      hermes profile create <name> [options]

      ينشئ profile جديدًا.

      المعطى / الخيارالوصف
      <name>اسم الـ profile الجديد. يجب أن يكون اسم مجلد صالحًا (أحرف وأرقام وشرطات وشرطات سفلية).
      --cloneانسخ config.yaml و.env وSOUL.md والمهارات وملفات memories/MEMORY.md / memories/USER.md المنسّقة من الـ profile الحالي. لا تُنسخ الجلسات ولا state.db ولا مهام cron.
      --clone-allانسخ كل شيء (الإعدادات، الذكريات، المهارات، الإضافات) من الـ profile الحالي. يستثني سجل ما بعد التفريع الخاص بكل profile: الجلسات، state.db، النسخ الاحتياطية، لقطات الحالة، نقاط الحفظ (checkpoints) — ومهام cron، التي تبقى مرتبطة بالـ profile المصدر (لأن profile مستنسَخ يرث هذه المهام سيُشغِّل كل مهمة مرتين).
      --clone-from <profile>استنسخ الإعدادات/المهارات/SOUL من profile محدد بدلًا من الحالي. يتضمن --clone ضمنيًا ما لم يُقترن بـ --clone-all.
      --no-aliasتخطَّ إنشاء سكربت الالتفاف (wrapper).
      --description "<text>"وصف من جملة أو جملتين لما يبرع فيه هذا الـ profile. يستخدمه منسّق kanban لتوجيه المهام بحسب الدور بدلًا من اسم الـ profile وحده. تخطَّه وأضفه لاحقًا عبر hermes profile describe. يُحفظ في <profile_dir>/profile.yaml.
      --no-skillsأنشئ profile فارغًا بلا أي مهارات مضمّنة مفعّلة. يكتب علامة .no-bundled-skills في الـ profile حتى لا تعيد عمليات hermes update المستقبلية زرع مجموعة المهارات المضمّنة، ويرفض التركيب مع --clone أو --clone-from أو --clone-all (التي ستنسخ المهارات على أي حال). مفيد لـ profiles منسّقات ضيقة النطاق أو profiles اختبار (sandbox) لا ينبغي أن ترث كتالوج المهارات كاملًا. لتبديل هذا الخيار على profile أُنشئ مسبقًا (بما في ذلك الافتراضي ~/.hermes)، استخدم hermes skills opt-out / hermes skills opt-in.

      إنشاء profile لا يجعل مجلد ذلك الـ profile مجلد المشروع/مساحة العمل الافتراضي لأوامر الطرفية. إن أردت أن يبدأ profile في مشروع محدد، اضبط terminal.cwd في ملف config.yaml الخاص بذلك الـ profile.

      أمثلة:

      # Blank profile — needs full setup
      hermes profile create mybot

      # Clone config only from current profile
      hermes profile create work --clone

      # Clone everything from current profile
      hermes profile create backup --clone-all

      # Clone config from a specific profile
      hermes profile create work2 --clone-from work

      # Clone everything from a specific profile
      hermes profile create work2-backup --clone-from work --clone-all

      hermes profile describe​

      hermes profile describe [<name>] [options]

      اقرأ وصف profile أو اضبطه. يستهلك منسّق kanban هذا الوصف لتوجيه المهام بحسب ما يبرع فيه كل profile، بدلًا من التخمين من اسم الـ profile وحده. يُحفظ في <profile_dir>/profile.yaml بحيث يبقى بعد إعادة التشغيل ويُشارَك مع الـ gateway.

      دون أي أعلام، يطبع الوصف الحالي (أو (no description set for '<name>') إن كان فارغًا).

      المعطى / الخيارالوصف
      <name>الـ profile المراد وصفه. مطلوب ما لم يُستخدم --all --auto.
      --text "<text>"اضبط الوصف على هذا النص بالضبط (من تأليف المستخدم). يستبدل أي وصف موجود.
      --autoولّد وصفًا تلقائيًا من جملة أو جملتين عبر LLM المساعد (auxiliary)، استنادًا إلى المهارات المثبَّتة في الـ profile والنموذج المُهيَّأ والاسم. اضبط النموذج ضمن auxiliary.profile_describer في config.yaml. تُوسَم الأوصاف المولَّدة تلقائيًا بـ description_auto: true ليتمكن dashboard من تمييزها للمراجعة.
      --overwriteمع --auto، استبدل الأوصاف من تأليف المستخدم أيضًا (الافتراضي: تخطّي الـ profiles التي ضُبط وصفها صراحةً).
      --allمع --auto، امسح جميع الـ profiles التي تفتقر إلى وصف.

      أمثلة:

      # Read the current description
      hermes profile describe researcher

      # Set it explicitly
      hermes profile describe researcher --text "Reads source code and writes findings."

      # Let the LLM generate one
      hermes profile describe researcher --auto

      # Fill in descriptions for every profile that doesn't have one
      hermes profile describe --all --auto

      hermes profile delete​

      hermes profile delete <name> [options]

      يحذف profile ويزيل اسمه المستعار (alias) في الـ shell.

      المعطى / الخيارالوصف
      <name>الـ profile المراد حذفه.
      --yes، -yتخطَّ مطالبة التأكيد.

      مثال:

      hermes profile delete mybot
      hermes profile delete mybot --yes
      تحذير

      يحذف هذا نهائيًا مجلد الـ profile بالكامل، بما في ذلك كل الإعدادات والذكريات والجلسات والمهارات. لا يمكن حذف الـ profile default (~/.hermes) — استخدم hermes uninstall لإزالة كل شيء.

      hermes profile show​

      hermes profile show <name>

      يعرض تفاصيل profile بما في ذلك مجلد المنزل الخاص به والنموذج المُهيَّأ وحالة الـ gateway وعدد المهارات وحالة ملف الإعدادات.

      يعرض هذا مجلد منزل Hermes الخاص بالـ profile، وليس مجلد عمل الطرفية. تبدأ أوامر الطرفية من terminal.cwd (أو مجلد الإطلاق في الـ backend المحلي عندما تكون cwd: ".").

      المعطىالوصف
      <name>الـ profile المراد فحصه.

      مثال:

      $ hermes profile show work
      Profile: work
      Path:    ~/.hermes/profiles/work
      Model:   anthropic/claude-sonnet-4 (anthropic)
      Gateway: stopped
      Skills:  12
      .env:    exists
      SOUL.md: exists
      Alias:   ~/.local/bin/work

      hermes profile alias​

      hermes profile alias <name> [options]

      يعيد توليد سكربت الاسم المستعار (alias) في ~/.local/bin/<name>. مفيد إن حُذف الاسم المستعار عن طريق الخطأ أو احتجت إلى تحديثه بعد نقل تثبيت Hermes الخاص بك.

      المعطى / الخيارالوصف
      <name>الـ profile المراد إنشاء الاسم المستعار له أو تحديثه.
      --removeأزل سكربت الالتفاف (wrapper) بدلًا من إنشائه.
      --name <alias>اسم مستعار مخصص (الافتراضي: اسم الـ profile).

      مثال:

      hermes profile alias work
      # Creates/updates ~/.local/bin/work

      hermes profile alias work --name mywork
      # Creates ~/.local/bin/mywork

      hermes profile alias work --remove
      # Removes the wrapper script

      hermes profile rename​

      hermes profile rename <old-name> <new-name>

      يعيد تسمية profile. يحدّث المجلد والاسم المستعار في الـ shell.

      المعطىالوصف
      <old-name>اسم الـ profile الحالي.
      <new-name>الاسم الجديد للـ profile.

      مثال:

      hermes profile rename mybot assistant
      # ~/.hermes/profiles/mybot → ~/.hermes/profiles/assistant
      # ~/.local/bin/mybot → ~/.local/bin/assistant

      hermes profile export​

      hermes profile export <name> [options]

      يصدّر profile كأرشيف tar.gz مضغوط — لقطة قابلة للنقل يمكنك نسخها احتياطيًا أو نقلها إلى جهاز آخر أو تسليمها لشخص آخر. يُستثنى auth.json و.env دائمًا.

      متاح أيضًا في المحادثة كـ /export، وفي تطبيق سطح المكتب عبر ⌘K → Export profile… أو قائمة النقر بزر الفأرة الأيمن على مربع profile. يضيف التصدير من سطح المكتب أيضًا ملف desktop.json (المظهر، الوضع الفاتح/الداكن، السمات المخصصة، لون الشريط الجانبي، تخطيط النافذة) إلى الأرشيف.

      المعطى / الخيارالوصف
      <name>الـ profile المراد تصديره.
      -o، --output <path>مسار ملف الإخراج (الافتراضي: <name>.tar.gz).

      مثال:

      hermes profile export work
      # Creates work.tar.gz in the current directory

      hermes profile export work -o ./work-2026-03-29.tar.gz

      راجع تصدير واستيراد ملف profile لمعرفة ما يُدرَج بالضبط في الأرشيف وما ينبغي التحقق منه قبل إرسال أرشيف إلى شخص آخر.

      hermes profile import​

      hermes profile import <archive> [options]

      يستورد profile من أرشيف tar.gz، بوصفه profile جديدًا. يرفض استبدال profile موجود، ولا يمكنه الاستيراد باسم default (الـ profile الجذري المدمج) — مرّر --name في كلتا الحالتين. يُنشأ سكربت التفاف (wrapper) في الـ shell عندما لا يتعارض الاسم مع أمر موجود.

      متاح أيضًا في المحادثة كـ /import، وفي تطبيق سطح المكتب عبر ⌘K → Import profile… أو زر الاستيراد بجانب + في شريط profiles. يطبّق الاستيراد من سطح المكتب أيضًا أي تراكب (overlay) desktop.json مضمّن (السمة، التخطيط) ويحوّلك إلى الـ profile الجديد.

      المعطى / الخيارالوصف
      <archive>مسار أرشيف tar.gz المراد استيراده.
      --name <name>اسم الـ profile المستورَد (الافتراضي: يُستنتَج من الأرشيف).

      مثال:

      hermes profile import ./work-2026-03-29.tar.gz
      # Infers profile name from the archive

      hermes profile import ./work-2026-03-29.tar.gz --name work-restored

      أوامر التوزيعات​

      نصيحة

      جديد على التوزيعات؟ ابدأ بدليل توزيعات Profile — فهو يغطي السبب والتوقيت والكيفية بأمثلة كاملة. الأقسام أدناه مرجع CLI مقتضب لمن يعرف بالفعل ما يريده.

      تحوّل التوزيعات profile إلى قطعة (artifact) قابلة للمشاركة وذات إصدار، تُنشَر بوصفها مستودع git. يثبّت المستلم التوزيعة بأمر واحد ويمكنه تحديثها لاحقًا في مكانها دون المساس بذكرياته المحلية أو جلساته أو بيانات اعتماده.

      لا يُعَد auth.json و.env أبدًا جزءًا من التوزيعة — بل يبقيان على جهاز المستخدم المثبِّت.

      تُحفَظ بيانات المستلم دائمًا (الذكريات، الجلسات، بيانات المصادقة، تعديلاته الخاصة على .env) عبر التثبيت الأولي والتحديثات اللاحقة.

      معلومة

      هناك طريقتان لمشاركة profile، وهما تتكاملان مع بعضهما. ينتج hermes profile export / import (وكذلك /export و/import في المحادثة) ملفًا واحدًا — بلا مستودع ولا بيان (manifest)، ويحمل التصدير من سطح المكتب سمتك وتخطيطك أيضًا. أما التوزيع (install / update / info) فينشر profile بوصفه مستودع git بحيث يمكن للمستلمين سحب تحديثات ذات إصدار لاحقًا. النسخ الاحتياطي والاستعادة هما وظيفة أخرى لملف التصدير. راجع طريقتان لمشاركة profile.

      hermes profile install​

      hermes profile install <source> [--name <name>] [--alias] [--force] [--yes]

      يثبّت توزيعة profile من رابط git أو مجلد محلي.

      الخيارالوصف
      <source>رابط git (github.com/user/repo، https://...، git@...، ssh://، git://) أو مجلد محلي يحتوي على distribution.yaml في جذره.
      --name NAMEتجاوز اسم الـ profile الوارد في البيان (manifest).
      --aliasأنشئ أيضًا اسمًا مستعارًا (wrapper) في الـ shell (مثلًا telemetry ← hermes -p telemetry).
      --forceاستبدل profile موجودًا بنفس الاسم. تبقى بيانات المستخدم محفوظة.
      -y، --yesتخطَّ مطالبة التأكيد المعروضة قبل التثبيت (منظر البيان manifest).

      يعرض المثبِّت البيان، ويسرد متغيرات البيئة المطلوبة، ويحذّر بشأن مهام cron قبل طلب التأكيد. تُوضَع متغيرات البيئة المطلوبة في ملف .env.EXAMPLE تنسخه إلى .env وتملأه.

      أمثلة:

      # Install from a GitHub repo (shorthand)
      hermes profile install github.com/kyle/telemetry-distribution --alias

      # Install from a full HTTPS git URL
      hermes profile install https://github.com/kyle/telemetry-distribution.git

      # Install from SSH
      hermes profile install git@github.com:kyle/telemetry-distribution.git

      # Install from a local directory during development
      hermes profile install ./telemetry/

      hermes profile update​

      hermes profile update <name> [--force-config] [--yes]

      يستنسخ التوزيعة من مصدرها المسجَّل من جديد ويطبّق التحديثات. تُستبدَل الملفات المملوكة للتوزيعة (SOUL.md، skills/، cron/، mcp.json)؛ ولا تُمَس بيانات المستخدم (الذكريات، الجلسات، بيانات المصادقة، .env) أبدًا.

      يُحفَظ config.yaml افتراضيًا لإبقاء تعديلاتك المحلية. مرّر --force-config لإعادته إلى الإعدادات الأصلية للتوزيعة.

      hermes profile info​

      hermes profile info <name>

      يطبع بيان توزيعة profile — الاسم، الإصدار، إصدار Hermes المطلوب، المؤلف، متطلبات متغيرات البيئة، رابط/مسار المصدر، و طابع Installed: الزمني المسجَّل عند آخر install أو update للتوزيعة. مفيد للتحقق مما يحتاجه profile مشترَك قبل تثبيته، ولاكتشاف "هذا الـ profile ثُبِّت منذ 6 أشهر ولم يُحدَّث منذ ذلك الحين."

      يعرض hermes profile list أيضًا اسم التوزيعة وإصدارها في عمود Distribution، كما يُظهر hermes profile show <name> / delete <name> رابط المصدر بحيث تعرف بلمحة أي profiles أتت من مستودع git وأيها أُنشئ محليًا.

      التوزيعات الخاصة​

      يعمل مستودع git خاص بوصفه مصدر توزيعة دون أي إعداد إضافي — إذ يستدعي التثبيت ملف git الثنائي العادي لديك، لذا تُطبَّق أي مصادقة أعددتها بالفعل في الـ shell (مفتاح SSH، مساعد git credential، بيانات اعتماد HTTPS المخزَّنة عبر GitHub CLI) تلقائيًا.

      # Uses your SSH key, the same as any other `git clone`
      hermes profile install git@github.com:your-org/internal-assistant.git

      # Uses your git credential helper
      hermes profile install https://github.com/your-org/internal-assistant.git

      إن طلب الاستنساخ بيانات اعتماد تفاعليًا في طرفيتك أثناء التثبيت، يمر ذلك الطلب كما هو. أعدّ مصادقتك بالطريقة التي تستخدمها عادةً مع git clone لنفس المستودع أولًا، ثم ثبّت.

      بيان التوزيعة (distribution.yaml)​

      لكل توزيعة ملف distribution.yaml في جذر مستودعها:

      name: telemetry
      version: 0.1.0
      description: "Compliance monitoring harness"
      hermes_requires: ">=0.12.0"
      author: "Your Name"
      license: "MIT"
      env_requires:
        - name: OPENAI_API_KEY
          description: "OpenAI API key"
          required: true
        - name: GRAPHITI_MCP_URL
          description: "Memory graph URL"
          required: false
          default: "http://127.0.0.1:8000/sse"
      distribution_owned:   # optional; defaults to SOUL.md, config.yaml,
                            #   mcp.json, skills/, cron/, distribution.yaml
        - SOUL.md
        - skills/compliance/
        - cron/

      يدعم hermes_requires المعاملات >= و<= و== و!= و> و<، أو إصدارًا مجردًا (يُعامَل كـ >=). يفشل التثبيت برسالة خطأ واضحة إن لم يُلبِّ إصدار Hermes الحالي المواصفة.

      distribution_owned اختياري. إذا ضُبط، فلا يُستبدَل عند التحديث إلا تلك المسارات؛ ويبقى أي شيء آخر في الـ profile مملوكًا للمستخدم. إن أُغفل، تُطبَّق الإعدادات الافتراضية أعلاه.

      نشر توزيعة​

      تأليف توزيعة هو مجرد عملية git push:

      1. في مجلد profile الخاص بك، أنشئ distribution.yaml يحتوي على الأقل على name وversion.
      2. هيّئ مستودع git (أو استخدم مستودعًا موجودًا) وادفعه إلى GitHub أو GitLab أو أي مضيف يمكن لـ Hermes الاستنساخ منه.
      3. أخبر المستلمين بتشغيل hermes profile install <your-repo-url>.

      استخدم وسوم (tags) git للإصدارات ذات الرقم — يحصل من يستنسخون HEAD على أحدث حالتك، ويمكنك دائمًا رفع رقم version: في البيان.

      hermes -p / hermes --profile​

      hermes -p <name> <command> [options]
      hermes --profile <name> <command> [options]

      علم عام لتشغيل أي أمر Hermes تحت profile محدد دون تغيير الافتراضي الثابت. يتجاوز هذا الـ profile النشط لمدة تنفيذ الأمر فقط.

      الخيارالوصف
      -p <name>، --profile <name>الـ profile المراد استخدامه لهذا الأمر.

      أمثلة:

      hermes -p work chat -q "Check the server status"
      hermes --profile dev gateway start
      hermes -p personal skills list
      hermes -p work config edit

      hermes completion​

      hermes completion <shell>

      يولّد سكربتات إكمال الـ shell. يتضمن إكمالات لأسماء profiles وأوامرها الفرعية.

      المعطىالوصف
      <shell>الـ shell المراد توليد إكمالات له: bash أو zsh أو fish.

      أمثلة:

      # Install completions
      hermes completion bash >> ~/.bashrc
      hermes completion zsh >> ~/.zshrc
      hermes completion fish > ~/.config/fish/completions/hermes.fish

      # Reload shell
      source ~/.bashrc

      بعد التثبيت، يعمل إكمال tab لـ:

      • hermes profile <TAB> — الأوامر الفرعية (list، use، create، إلخ)
      • hermes profile use <TAB> — أسماء profiles
      • hermes -p <TAB> — أسماء profiles
