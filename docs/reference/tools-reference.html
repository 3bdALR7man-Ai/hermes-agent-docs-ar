      مرجع الأدوات المدمجة

      توثّق هذه الصفحة أدوات Hermes المدمجة، مُصنّفة حسب toolset. يختلف التوفر حسب المنصة، وبيانات الاعتماد، والـ toolsets المفعّلة.

      أعداد سريعة (السجل الحالي): نحو 86 أداة — 10 أدوات متصفح (أساسية) + أداتا متصفح مقيّدتان بـ CDP، 4 أدوات ملفات، 4 أدوات Home Assistant، أداتا terminal (terminal، process)، 12 أداة واجهة سطح مكتب (read_terminal، close_terminal، open_preview، close_preview، read_preview، drive_preview، annotate_preview، read_window_below، focus_pane، react_to_message، tour، tip — لجلسات تطبيق سطح المكتب فقط)، أداتا ويب، 5 أدوات Feishu، 7 أدوات Spotify (مسجّلة عبر الإضافة (plugin) المضمّنة spotify)، 5 أدوات Yuanbao، 12 أداة kanban (تُسجَّل عند إنشاء موزّع kanban للوكيل)، 3 أدوات مشروع (project) (جلسات سطح المكتب/الواجهة الرسومية)، أداتا Discord، 3 أدوات فيديو (video_generate، xai_video_edit، xai_video_extend)، وعدد من الأدوات المستقلة (memory، clarify، delegate_task، execute_code، cronjob، session_search، skill_view/skill_manage/skills_list، text_to_speech، image_generate، vision_analyze، video_analyze، todo، computer_use، x_search).

      أدوات MCP

      إلى جانب الأدوات المدمجة، يمكن لـ Hermes تحميل أدوات ديناميكيًا من خوادم MCP. تظهر أدوات MCP بالبادئة mcp__<server>__ (مثال: mcp__github__create_issue لخادم github الخاص بـ MCP). راجع تكامل MCP للإعداد.

      browser_get_imagesالحصول على قائمة بجميع الصور في الصفحة الحالية مع روابطها ونصوصها البديلة (alt). مفيدة لإيجاد صور تُحلَّل بأداة vision. يتطلب استدعاء browser_navigate أولًا.—
      browser_navigateالانتقال إلى رابط في المتصفح. يهيّئ الجلسة ويحمّل الصفحة. يجب استدعاؤها قبل أدوات المتصفح الأخرى. لاسترجاع المعلومات البسيط، يُفضَّل استخدام web_search أو web_extract (أسرع وأرخص). استخدم أدوات المتصفح عند الحاجة إلى…—
      browser_pressالضغط على مفتاح لوحة مفاتيح. مفيدة لإرسال النماذج (Enter)، أو التنقل (Tab)، أو اختصارات لوحة المفاتيح. يتطلب استدعاء browser_navigate أولًا.—
      browser_scrollالتمرير في الصفحة باتجاه معيّن. استخدمها لإظهار محتوى إضافي أعلى أو أسفل نافذة العرض الحالية. يتطلب استدعاء browser_navigate أولًا.—
      browser_snapshotالحصول على لقطة نصية لشجرة إمكانية الوصول (accessibility tree) الخاصة بالصفحة الحالية. تُعيد العناصر التفاعلية مع معرّفات ref (مثل @e1، @e2) لاستخدامها مع browser_click و browser_type. full=false (الافتراضي): عرض مختصر للعناصر التفاعلية. full=true: عرض…—
      browser_typeكتابة نص في حقل إدخال محدَّد بمعرّف ref. يمسح الحقل أولًا ثم يكتب النص الجديد. يتطلب استدعاء browser_navigate ثم browser_snapshot أولًا.—
      browser_visionالتقاط لقطة شاشة للصفحة الحالية لتفحّصها بصريًا. استخدمها عندما تحتاج إلى فهم مظهر الصفحة — خصوصًا لأكواد CAPTCHA، وتحديات التحقق البصري، والتخطيطات المعقّدة، أو الحالات التي تفوّت فيها اللقطة النصية معلومات بصرية مهمة. على النماذج ذات الرؤية الأصلية تُرفَق لقطة الشاشة مباشرة؛ وإلا يُعتمَد على نموذج رؤية مساعد…—

      toolset باسم browser (أدوات مقيّدة بـ CDP)​

      تنتمي هاتان الأداتان إلى toolset باسم browser لكنهما تُسجَّلان فقط عند توفّر نقطة نهاية (endpoint) لبروتوكول Chrome DevTools عند بدء الجلسة — عبر /browser connect، أو إعداد browser.cdp_url، أو جلسة Browserbase، أو Camofox.

      الأداةالوصفيتطلب بيئة
      browser_cdpإرسال أمر خام لبروتوكول Chrome DevTools. مخرج طوارئ لعمليات المتصفح غير المغطّاة بأدوات browser_* الأعلى مستوى. راجع https://chromedevtools.github.io/devtools-protocol/نقطة نهاية CDP
      browser_dialogالاستجابة لمربّع حوار JavaScript أصلي (alert / confirm / prompt / beforeunload). استدعِ browser_snapshot أولًا — تظهر مربّعات الحوار المعلَّقة في حقلها pending_dialogs. ثم استدعِ browser_dialog(action='accept'|'dismiss').نقطة نهاية CDP

      toolset باسم clarify​

      الأداةالوصفيتطلب بيئة
      clarifyطرح سؤال على المستخدم عند الحاجة إلى توضيح أو ملاحظات أو قرار قبل المتابعة. تدعم ثلاثة أنماط: 1. اختيار واحد من عدة خيارات — حتى 4 خيارات؛ يختار المستخدم واحدًا أو يكتب إجابته الخاصة عبر خيار خامس هو 'Other'. 2. اختيار متعدد من عدة خيارات — يعرض multi_select=true مربّعات اختيار ويُعيد قائمة بالخيارات المحدَّدة. 3. مفتوح — بلا خيارات؛ يكتب المستخدم إجابة حرّة. تُرتَّب الخيارات من الأفضل فالأقل، فيُوسَم الخيار الأول بـ (Recommended) على كل واجهة ويكون التمييز الافتراضي؛ هذا الوسم للعرض فقط ويُحذَف من الإجابة التي يقرؤها الوكيل. في واجهة CLI الكلاسيكية يُستخدَم مفتاح المسافة لتبديل مربّعات الاختيار المتعدد؛ وعلى منصات المراسلة التي لا تملك واجهات مربّعات اختيار أصلية، يردّ المستخدم بأرقام مفصولة بفواصل/مسافات (مثل "1, 3") أو بنص الخيار.—

      طرح عدة أسئلة دفعة واحدة​

      تقبل أداة clarify أيضًا مصفوفة questions (من 2 إلى 5 أسئلة مستقلة، لكل منها choices و multi_select خاصة بها) بحيث يمكن للوكيل تجميع عدة احتياجات توضيح في مطالبة واحدة بدلًا من طرحها تباعًا. تكون النتيجة مصفوفة responses بالترتيب نفسه، مع إعادة id كل سؤال (عند تحديده) كما هو.

      السلوك حسب كل واجهة:

      • سطح المكتب يعرض كل الأسئلة في بطاقة واحدة. تُخزَّن الاختيارات والإجابات المكتوبة محليًا، وزرّ واحد باسم Confirm and continue (يُفعَّل عند الإجابة عن كل سؤال) يرسل الدفعة كاملة. تبقى الإجابات المخزّنة قابلة للتعديل حتى ذلك التأكيد. يلغي Skip الدفعة كلها.
      • TUI وCLI يعرضان قائمة حالة مختصرة (✓ تمت الإجابة / ▸ نشط / · معلّق) مع توسيع خيارات السؤال النشط فقط. يقفل Enter الإجابة النشطة وينتقل إلى السؤال التالي غير المُجاب عنه؛ ينتقل Tab بين الأسئلة للإجابة بأي ترتيب؛ يلغي Esc الدفعة.
      • منصات المراسلة (Telegram، Discord، …) تعود إلى طرح الأسئلة واحدًا تلو الآخر عبر المطالبة أحادية السؤال المعتادة. إذا توقف المستخدم عن الرد، لا تُرسَل الأسئلة المتبقية.

      إذا انتهت مهلة المطالبة في منتصف الطريق، تُحفَظ الإجابات التي أقفلها المستخدم بالفعل: تحمل نتيجة الأداة هذه الإجابات إضافة إلى "timed_out": true، مع ترك المدخلات غير المُجاب عنها فارغة، بحيث يستطيع الوكيل التمييز بين التجاهل المتعمَّد وغياب المستخدم.

      الأداةالوصفيتطلب بيئة

      toolset باسم kanban​

      تُسجَّل عندما يكون الوكيل إما (أ) قد أنشأه موزّع kanban (مع ضبط متغير البيئة HERMES_KANBAN_TASK) أو (ب) يعمل ضمن profile يفعّل toolset باسم kanban صراحة. تستخدم عناصر العمل المخصَّصة لمهمة (task-scoped workers) أدوات دورة الحياة لمهمتها المسنَدة؛ وتحصل profiles المنسِّقة (orchestrator) إضافة إلى ذلك على أدوات توجيه اللوحة مثل kanban_list وkanban_unblock. راجع Kanban متعدد الوكلاء لمعرفة سير العمل الكامل.

      الأداةالوصفيتطلب بيئة
      kanban_showعرض مهمة kanban النشطة المسنَدة لهذا العنصر العامل (العنوان، الوصف، التعليقات، التبعيات).HERMES_KANBAN_TASK أو toolset باسم kanban

      الجولات (Tours)​

      تكتشف أداة tour أهدافها بنفسها — استدعِ action='targets' فتُعيد كل عنصر قابل للتوجيه على الشاشة مع محدِّد (selector) وتسمية وعلامة stable. تعتمد المحدِّدات المستقرة على الهوية (data-tour، id، data-testid، aria-label) وتصمد أمام إعادة الرسم؛ أما مسارات nth-child الموضعية فلا تصمد، لذا تُرتَّب المستقرة أولًا وينبغي تفضيلها.

      لمنح عنصر مقبضًا ثابتًا خاصًا بك، ضع له وسمًا:

      <div data-tour="composer">…</div>

      تُطبَّق المقابض على العنصر الأساسي (primitive)، لا على موضع الاستدعاء، فتعديل واحد يسمّي كل نسخة منه. المقابض الموجودة حاليًا:

      المقبضما يسمّيه
      overlay-navشريط التنقّل الأيسر لأي تراكب مسار (route overlay) (الإعدادات، cron، profiles، الوكلاء)
      nav-<id>صف واحد في ذلك التنقّل — nav-models، nav-appearance، …
      field-<schemaKey>صف إعدادات واحد، بمفتاح إعداده — field-model، field-provider، …
      page-tabsتبويبات التصفية على أي صفحة من نوع PageSearchShell (المخرجات (artifacts)، المهارات، …)
      artifact-cardبطاقة مخرج (artifact) في الشبكة

      عند إضافة سطح جديد، ضع وسمًا على عنصره الأساسي المشترك بالطريقة نفسها بدلًا من وسم الشاشات واحدة تلو الأخرى — يُبقي ذلك مفردات الجولة صغيرة ويمنع تعطّل المحدِّدات.

      يشغّل المحرّك نفسه الجولات المُنسَّقة (غير التابعة للوكيل) في تطبيق سطح المكتب، بحيث يمكن لميزة أن تقدّم جولتها التعريفية الخاصة:

      import { startTour, showTourStep, stopTour } from '@/lib/tour'

      startTour([
        { selector: '[data-tour="composer"]', title: 'Composer', text: 'Type here.' },
        { selector: '[data-tour="files"]', title: 'Files', text: 'Browse your project.' }
      ])

      يمكن لخطوة أيضًا نقل التطبيق إلى حيث يوجد هدفها، وتعيد الجولة الأمور إلى ما كانت عليه عند انتهائها:

      startTour([
        { navigate: '/artifacts', selector: '[data-tour="page-tabs"]', title: 'Filters', text: '…' },
        { pane: 'sessions', selector: '[data-slot="sidebar"]', title: 'Sessions', text: '…' }
      ])

      تأخذ navigate مسار route، وتأخذ pane اسم لوحة سطح مكتب. يُنفَّذ كلاهما عند الدخول في الخطوة، ويُنتظَر ظهور الأهداف التي تُحمَّل متأخرة، وإغلاق الجولة — بأي طريقة، بما في ذلك Esc — يعيد الأمور إلى حيث بدأت.

      مرِّر 'preview' كوسيط ثانٍ للعمل على الصفحة في لوحة المعاينة بدلًا من التطبيق.

      التلميحات (Tips)​

      التلميح هو خطوة جولة دون الإخراج الكامل: فقاعة واحدة، وسهم واحد، بلا حجب ولا شيء يُتصفَّح عبره. إنه الوزن المناسب لجملة تزداد وضوحًا بإشارة مباشرة إلى ما تتحدّث عنه — "اسم النموذج زرّ" — حيث لا يكون تعتيم التطبيق بأكمله مناسبًا.

      تأخذ أداة tip المحدِّدات نفسها التي تُعيدها tour(action='targets')، لذا الاكتشاف استدعاء واحد لكليهما، وتسمّي مقابض data-tour الثابتة أعلاه الأهداف لكلتيهما. تلميح واحد يظهر على الشاشة في كل مرة؛ يحل تلميح جديد محل الأخير.

      يمكن للتطبيق أيضًا عرض تلميحاته الخاصة، مستعرضًا كتالوجًا مدمجًا لميزات التطبيق بالترتيب، بوتيرة أشبه بتلميحات شاشة تحميل لعبة لا بإشعار: بعد بضع دقائق من بدء التشغيل في أبكر تقدير، ثم مرة واحدة على الأكثر كل ست ساعات، و فقط في لحظة خمول حقيقية. يشارك تلميح من Hermes فترة التهدئة تلك، لذا يمنح المستخدم أيضًا ست ساعات من الهدوء من التناوب. التناوب دورة واحدة فقط: يظهر كل تلميح من الكتالوج مرة واحدة، سواء انتهت مهلته أو أُغلق بعلامة ✕، وحين يأخذ كل تلميح دوره يصمت التطبيق. يعيد صف الإعدادات الدورة من البداية.

      كل من التلميحات والجولات مفعّل افتراضيًا ويمكن إيقافه من Settings ← Appearance (display.in_app_tips، display.in_app_tours). يشمل الإيقاف Hermes نفسه إضافة إلى التطبيق: يصل المفتاح إلى إعدادات gateway المتصلة وتترك الأداة مخطط النموذج، بحيث لا يُخبَر النموذج مطلقًا بسطح لا يُسمَح له باستخدامه. وكما هو الحال مع أي تغيير في المخطط، يسري ذلك في الجلسة التالية — تحتفظ محادثة جارية بالـ toolset التي بدأت بها، ويرفض التطبيق الاستدعاء في غضون ذلك.

      • FAL.ai — Veo 3.1، وPixverse v6، وKling O3 (يتطلب FAL_KEY).
      • OpenRouter — كل نموذج توليدي على واجهة فيديو OpenRouter (Veo 3.1، Sora 2 Pro، Kling 3، Seedance 2، Wan 3، Hailuo 3، Grok Imagine، FLUX 3 Video، …)؛ نص إلى فيديو، وصورة إلى فيديو، ومرجع إلى فيديو؛ يُجلَب الكتالوج وحدود كل نموذج مباشرة (يتطلب OPENROUTER_API_KEY، ويُحتسَب على رصيد OpenRouter الخاص بك).
      • DeepInfra — كتالوج video-gen مباشر عبر نقطة نهاية الفيديوهات المتوافقة مع OpenAI (يتطلب DEEPINFRA_API_KEY).

      تغطي أداة video_generate الواحدة كلا النمطين — مرِّر image_url لتحريك صورة ثابتة، أو اتركه للتوليد من النص وحده. توجِّه الخلفية النشطة تلقائيًا إلى نقطة النهاية الصحيحة. تُعاد صياغة وصف الأداة عند بدء الجلسة ليعكس قدرات الخلفية النشطة الفعلية (الأنماط، ونِسَب العرض إلى الارتفاع، والدقّات، ونطاق المدة، والحدّ الأقصى لصور المرجع، ودعم الصوت). راجع إضافات مزوّدي توليد الفيديو لتأليف خلفية جديدة.

      الأداةالوصفيتطلب بيئة
      video_generateتوليد فيديو من مطالبة نصية (نص إلى فيديو) أو تحريك صورة ثابتة (صورة إلى فيديو) باستخدام خلفية توليد الفيديو التي أعدّها المستخدم. مرِّر image_url لتحريك تلك الصورة؛ اتركه للتوليد من النص وحده. توجِّه الخلفية تلقائيًا إلى نقطة النهاية الصحيحة. تُعيد رابط HTTP أو مسار ملف مطلقًا في الحقل video.إضافة video_gen نشطة + بيانات اعتمادها (مثل XAI_API_KEY، FAL_KEY)
      xai_video_editتعديل فيديو موجود عبر xAI Imagine. خاص بالمزوّد (منفصل عن video_generate). يجب أن يكون video_url رابط MP4 عامًا عبر HTTPS من نتيجة Imagine سابقة.بيانات اعتماد xAI Imagine (مصادقة SuperGrok OAuth أو XAI_API_KEY)
      xai_video_extendإطالة فيديو موجود عبر xAI Imagine. خاص بالمزوّد (منفصل عن video_generate). يجب أن يكون video_url رابط MP4 عامًا عبر HTTPS من نتيجة Imagine سابقة.بيانات اعتماد xAI Imagine (مصادقة SuperGrok OAuth أو XAI_API_KEY)

      toolset باسم web​

      الأداةالوصفيتطلب بيئة
      web_searchالبحث في الويب عن معلومات. تُعيد حتى 5 نتائج افتراضيًا مع العناوين، والروابط، والأوصاف. تقبل limit اختياريًا (من 1 إلى 100، الافتراضي 5). تُمرَّر الاستعلامية إلى الخلفية المُعَدّة، لذا قد تعمل مُعامِلات مثل site:domain وfiletype:pdf وintitle:word و-term و"exact phrase" إن كانت الخلفية تدعمها.EXA_API_KEY أو PARALLEL_API_KEY أو FIRECRAWL_API_KEY أو TAVILY_API_KEY أو PERPLEXITY_API_KEY أو KEENABLE_API_KEY
      web_extractاستخراج المحتوى من روابط صفحات ويب. تُعيد محتوى صفحة نظيفًا بصيغة markdown/نص (بلا تلخيص من LLM — سريعة). تعمل أيضًا مع روابط PDF (أوراق arxiv، مستندات) — مرِّر رابط PDF مباشرة. الصفحات ضمن ميزانية الأحرف (الافتراضي 15000) تُعاد كاملة؛ الصفحات الأكبر تُعيد نافذة بداية+نهاية مع تذييل يشير إلى النص الكامل المحفوظ على القرص. بحد أقصى 5 روابط لكل استدعاء.EXA_API_KEY أو PARALLEL_API_KEY أو FIRECRAWL_API_KEY أو TAVILY_API_KEY أو PERPLEXITY_API_KEY أو KEENABLE_API_KEY

      toolset باسم x_search​

      الأداةالوصفيتطلب بيئة
      x_searchالبحث في منشورات X (Twitter) والملفات الشخصية والمواضيع باستخدام أداة x_search المدمجة في Responses الخاصة بـ xAI. اكتشاف عام للقراءة فقط على X للنقاشات الجارية أو ردود الأفعال أو الادعاءات على X العام (لا صفحات الويب العامة). لا تنشر، ولا ترد، ولا تُعجب، ولا ترسل رسائل مباشرة، ولا ترفع وسائط، ولا تحذف، ولا تتفحّص الحساب المُصادَق عليه على X — تحتاج تلك إلى واجهة API مصادَق عليها منفصلة لـ X (مثل مهارة xurl). معطّلة افتراضيًا — فعّلها من hermes tools ← 🐦 البحث في X (Twitter). يُسجَّل المخطط فقط عند إعداد بيانات اعتماد xAI (مقيّد بدالة تحقق).XAI_API_KEY أو تسجيل دخول عبر xAI Grok OAuth (SuperGrok / Premium+)

      toolset باسم tts​

      الأداةالوصفيتطلب بيئة
      text_to_speechتحويل النص إلى صوت مسموع. تُعيد مسار MEDIA: تسلّمه المنصة كرسالة صوتية. على Telegram تُشغَّل كفقاعة صوتية، وعلى Discord/WhatsApp كمرفق صوتي. في وضع CLI، تُحفَظ في ~/voice-memos/. يختلف الصوت والمزوّد…—

      toolset باسم discord​

      تُسجَّل على toolset منصة hermes-discord (على gateway فقط). تستخدم رمز البوت (bot token) نفسه الذي يستخدمه محوّل المراسلة.

      الأداةالوصفيتطلب بيئة
      discordقراءة خادم Discord والمشاركة فيه. تشمل الإجراءات search_members وfetch_messages وsend_message وreact وfetch_channel وlist_channels وغيرها.DISCORD_BOT_TOKEN

      toolset باسم discord_admin​

      تُسجَّل على toolset منصة hermes-discord. تتطلب إجراءات الإشراف امتلاك البوت صلاحيات Discord المطابقة.

      الأداةالوصفيتطلب بيئة
      discord_adminإدارة خادم Discord عبر REST API: سرد الخوادم/القنوات/الأدوار، وإنشاء/تعديل/حذف القنوات، وإدارة منح الأدوار، والإسكات المؤقت (timeouts)، والطرد، والحظر.DISCORD_BOT_TOKEN + صلاحيات البوت

      toolset باسم spotify​

      تُسجَّل عبر الإضافة (plugin) المضمَّنة spotify. تتطلب رمز OAuth — شغّل hermes auth spotify مرة واحدة للتفويض.

      الأداةالوصفيتطلب بيئة
      spotify_playbackالتحكّم في تشغيل Spotify، أو تفحّص حالة التشغيل النشطة، أو جلب المقاطع المُشغَّلة مؤخرًا.مصادقة Spotify OAuth
      spotify_devicesسرد أجهزة Spotify Connect أو نقل التشغيل إلى جهاز آخر.مصادقة Spotify OAuth
      spotify_queueتفحّص قائمة انتظار المستخدم على Spotify أو إضافة عنصر إليها.مصادقة Spotify OAuth
      spotify_searchالبحث في كتالوج Spotify عن المقاطع، والألبومات، والفنانين، وقوائم التشغيل، والبرامج، والحلقات.مصادقة Spotify OAuth
      spotify_playlistsسرد قوائم تشغيل Spotify وتفحّصها وإنشاؤها وتحديثها وتعديلها.مصادقة Spotify OAuth
      spotify_albumsجلب بيانات ألبوم Spotify الوصفية أو مقاطع الألبوم.مصادقة Spotify OAuth
      spotify_libraryسرد مقاطع المستخدم أو ألبوماته المحفوظة على Spotify، أو حفظها، أو إزالتها.مصادقة Spotify OAuth

      toolset باسم hermes-yuanbao​

      تُسجَّل فقط على toolset منصة hermes-yuanbao. Yuanbao هو تطبيق محادثة تابع لتينسنت (Tencent)؛ تشغّل هذه الأدوات واجهات الرسائل المباشرة والمجموعات والملصقات فيه.

      الأداةالوصفيتطلب بيئة
      yb_query_group_infoالاستعلام عن معلومات أساسية لمجموعة (تُسمّى "派/Pai" في التطبيق): الاسم، والمالك، وعدد الأعضاء.بيانات اعتماد Yuanbao
      yb_query_group_membersالاستعلام عن أعضاء مجموعة (لإشارات @، أو إيجاد مستخدم بالاسم، أو سرد البوتات).بيانات اعتماد Yuanbao
      yb_send_dmإرسال رسالة خاصة/مباشرة إلى مستخدم في مجموعة، مع ملفات وسائط اختيارية.بيانات اعتماد Yuanbao
      yb_search_stickerالبحث في كتالوج ملصقات Yuanbao المدمجة (TIM face) بالكلمة المفتاحية.بيانات اعتماد Yuanbao
      yb_send_stickerإرسال ملصق مدمج إلى محادثة Yuanbao الحالية.بيانات اعتماد Yuanbao
