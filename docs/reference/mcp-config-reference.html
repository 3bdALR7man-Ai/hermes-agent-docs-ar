      مرجع إعدادات MCP

      هذه الصفحة مرجع مختصر مُكمِّل لتوثيق MCP الرئيسي.

      للاطلاع على الشرح المفاهيمي، راجع:

      • MCP (Model Context Protocol)
      • استخدام MCP مع Hermes

      البنية الجذرية للإعدادات​

      mcp_servers:
        <server_name>:
          command: "..."      # stdio servers
          args: []
          env: {}

          # OR
          url: "..."          # HTTP servers
          headers: {}

          # Optional HTTP/SSE TLS settings:
          ssl_verify: true                # bool or path to a CA bundle (PEM)
          client_cert: "/path/to/cert.pem"  # mTLS client certificate (see below)
          # client_key: "/path/to/key.pem"  # optional, when key lives in a separate file

          enabled: true
          timeout: 120
          connect_timeout: 60
          supports_parallel_tool_calls: false
          tools:
            include: []
            exclude: []
            resources: true
            prompts: true

      مفاتيح الخادم​

      المفتاحالنوعينطبق علىالمعنى
      commandstringstdioالملف التنفيذي المراد تشغيله
      argsliststdioالوسائط (arguments) المُمرَّرة إلى العملية الفرعية
      envmappingstdioالبيئة المُمرَّرة إلى العملية الفرعية
      urlstringHTTPendpoint الخاص بخادم MCP البعيد
      headersmappingHTTPالترويسات (headers) المُرسَلة مع طلبات الخادم البعيد
      ssl_verifybool أو stringHTTPالتحقق من TLS. القيمة true (الافتراضية) تستخدم شهادات CA الخاصة بالنظام، والقيمة false تعطّل التحقق (غير آمن)، أو سلسلة نصية تمثّل مسارًا إلى حزمة CA مخصّصة (PEM)
      client_certstring أو listHTTPشهادة العميل لـ mTLS. السلسلة النصية = مسار إلى ملف PEM يحتوي الشهادة + المفتاح. القائمة [cert, key] = ملفان منفصلان. القائمة [cert, key, password] = مفتاح مشفّر
      client_keystringHTTPمسار المفتاح الخاص للعميل، عندما تكون قيمة client_cert سلسلة نصية ويكون المفتاح في ملف منفصل
      enabledboolكلاهماتجاهل الخادم كليًا عندما تكون القيمة false
      timeoutnumberكلاهمامهلة استدعاء الأداة بالثواني (الافتراضي: 300)
      connect_timeoutnumberكلاهمامهلة الاتصال الأولي بالثواني (الافتراضي: 60)
      protocolstringكلاهماالتفاوض على جيل البروتوكول: auto (الافتراضي — المصافحة القديمة initialize أولًا، مع الرجوع إلى فحص server/discover عديم الحالة (stateless) الخاص بمواصفة 2026-07-28 عندما يرفض الخادم المصافحة لأنه يدعم الجيل الحديث فقط)، أو stateless (فحص server/discover أولًا؛ مع محاولة واحدة بالطريقة القديمة)، أو legacy (المصافحة فقط، بلا رجوع احتياطي)
      supports_parallel_tool_callsboolكلاهماالسماح بتشغيل أدوات هذا الخادم بالتزامن
      skip_preflightboolHTTPتجاوز فحص content-type السريع الفشل لـ endpoints صالحة من نوع Streamable HTTP تُرجِع طلبات HEAD/GET فيها content type ليس خاصًا بـ MCP (الافتراضي: false)
      transportstringHTTPاضبطه على sse لاستخدام ناقل SSE بدلًا من Streamable HTTP
      keepalive_intervalnumberكلاهماالفاصل الزمني لإشارات ping التي تتحقق من بقاء الاتصال حيًّا بالثواني (الافتراضي: 180، وحدّه الأدنى 5 ثوانٍ). اضبطه على قيمة أقل من مدة صلاحية الجلسة (TTL) لدى الخادم إذا كان الخادم يحذف الجلسات الخاملة سريعًا
      idle_timeout_secondsnumberstdioإعادة تدوير اختيارية لخادم stdio بعد مدة خمول (0 يعطّلها). يمكن وضعه أيضًا تحت mapping باسم lifecycle:
      max_lifetime_secondsnumberstdioإعادة تدوير اختيارية لخادم stdio بعد بلوغه عمرًا معيّنًا (0 يعطّلها). يمكن وضعه أيضًا تحت mapping باسم lifecycle:
      toolsmappingكلاهماسياسة التصفية والأدوات المساعدة
      authstringHTTPطريقة المصادقة. اضبطه على oauth لتفعيل OAuth 2.1 مع PKCE
      samplingmappingكلاهماسياسة طلبات LLM التي يبادر بها الخادم (راجع دليل MCP)
      elicitationmappingكلاهماطلبات إدخال المستخدم التي يبادر بها الخادم. يضم enabled (الافتراضي true) و timeout بالثواني (الافتراضي 300). تمر الطلبات من نوع النموذج (form) عبر واجهة الموافقة، أما طلبات نوع URL فتُرفَض (راجع دليل MCP)
      truststringكلاهمامستوى الثقة: full (الافتراضي) أو untrusted. على خادم untrusted، يتطلب كل استدعاء لأداة قادرة على الكتابة (أي أداة لا تحمل التعليق التوضيحي readOnlyHint: true) موافقة المستخدم عبر واجهة الموافقة القياسية قبل تشغيله. readOnlyHint مجرد تلميح يقدّمه الخادم — فأقصى ما يستطيعه خادم كاذب هو تخطي الموافقة للأدوات التي يدّعي أنها للقراءة فقط، دون أن يكتسب أي وصول إضافي — لذا صنّف أي خادم لا تتحكم فيه بالكامل على أنه untrusted. تُعامَل القيم غير المعروفة على أنها untrusted (الإغلاق عند الفشل)

      الإشارة إلى متغيرات البيئة​

      يمكن لقيم السلاسل النصية في أي موضع من إدخال الخادم (env و headers و args و url و…) أن تشير إلى متغيرات البيئة (environment variables) بالصيغة ${VAR} أو بصيغة SecretRef المتّبعة في Cursor ${env:VAR} — وكلتاهما تُحلّان إلى المتغير نفسه، لذا تعمل مقتطفات MCP المنسوخة من إعدادات Cursor / Claude دون تعديل:

      mcp_servers:
        github:
          command: "npx"
          args: ["-y", "@modelcontextprotocol/server-github"]
          env:
            GITHUB_PERSONAL_ACCESS_TOKEN: "${env:GITHUB_TOKEN}"   # same as "${GITHUB_TOKEN}"

      تُحلّ القيم من نطاق الأسرار الخاص بالـ profile النشط (مع الرجوع إلى بيئة العملية)، لذا ضع السرّ في ~/.hermes/.env. أما المتغير غير المضبوط فيبقى العنصر النائب الخاص به كما هو حرفيًا.

      متغيرات السياق​

      إلى جانب متغيرات البيئة، تُستبدَل أيضًا متغيرات السياق المتّبعة في Cursor (أسماؤها حساسة لحالة الأحرف):

      المتغيريُحلّ إلى
      ${userHome}المجلد الرئيسي (home) للمستخدم الحالي
      ${workspaceFolder}جذر مساحة عمل الجلسة (مجلد العمل الحالي cwd لطرفية الجلسة إن كان معروفًا، وإلا فمجلد العمل الحالي للعملية)
      ${workspaceFolderBasename}الاسم الأساسي (basename) لـ ${workspaceFolder}
      ${pathSeparator} / ${/}فاصل المسارات في نظام التشغيل (os.sep)
      mcp_servers:
        filesystem:
          command: "npx"
          args: ["-y", "@modelcontextprotocol/server-filesystem", "${workspaceFolder}"]
          env:
            CACHE_DIR: "${userHome}${/}.cache${/}mcp"

      أي إشارة أخرى بالصيغة ${...} تنتقل إلى البحث في متغيرات البيئة الموضّح أعلاه.

      مفاتيح سياسة tools​

      المفتاحالنوعالمعنى
      includestring أو listقائمة سماح لأدوات MCP الأصلية الخاصة بالخادم. يمكن أن تكون الإدخالات أسماء مطابقة تمامًا أو أنماط glob بأسلوب fnmatch (*_radar_*، get_zones_*)
      excludestring أو listقائمة حظر لأدوات MCP الأصلية الخاصة بالخادم. دلالات الاسم المطابق / glob نفسها المتّبعة في include
      resourcesقيمة شبيهة بـ boolتفعيل/تعطيل list_resources + read_resource
      promptsقيمة شبيهة بـ boolتفعيل/تعطيل list_prompts + get_prompt

      دلالات التصفية​

      include​

      إذا ضُبط include، فلن تُسجَّل إلا أدوات MCP الأصلية المذكورة فيه.

      tools:
        include: [create_issue, list_issues]

      exclude​

      إذا ضُبط exclude ولم يُضبط include، فستُسجَّل كل أدوات MCP الأصلية الخاصة بالخادم باستثناء الأسماء المذكورة.

      tools:
        exclude: [delete_customer]

      الأولوية​

      إذا ضُبط كلاهما، تكون الغلبة لـ include.

      tools:
        include: [create_issue]
        exclude: [create_issue, delete_issue]

      النتيجة:

      • تبقى create_issue مسموحًا بها
      • تُتجاهَل delete_issue لأن include له الأولوية

      سياسة الأدوات المساعدة​

      قد يسجّل Hermes أغلفة (wrappers) الأدوات المساعدة التالية لكل خادم MCP:

      الموارد (Resources):

      • list_resources
      • read_resource

      الـ Prompts:

      • list_prompts
      • get_prompt

      تعطيل الموارد​

      tools:
        resources: false

      تعطيل الـ Prompts​

      tools:
        prompts: false

      التسجيل بحسب القدرات المتاحة​

      حتى عند ضبط resources: true أو prompts: true، لا يسجّل Hermes تلك الأدوات المساعدة إلا إذا كانت جلسة MCP تُتيح القدرة (capability) المقابلة فعلًا.

      لذا فإن الحالة التالية طبيعية:

      • تفعّل الـ prompts
      • لكن لا تظهر أي أدوات مساعدة للـ prompts
      • لأن الخادم لا يدعم الـ prompts

      enabled: false​

      mcp_servers:
        legacy:
          url: "https://mcp.legacy.internal"
          enabled: false

      السلوك:

      • لا محاولة للاتصال
      • لا اكتشاف
      • لا تسجيل للأدوات
      • تبقى الإعدادات في مكانها لإعادة استخدامها لاحقًا

      السلوك عند النتيجة الفارغة​

      إذا أزالت التصفية كل الأدوات الأصلية للخادم ولم تُسجَّل أي أدوات مساعدة، فلن ينشئ Hermes toolset تشغيليًا فارغًا من نوع MCP لذلك الخادم.

      أمثلة على الإعدادات​

      قائمة سماح آمنة لـ GitHub​

      mcp_servers:
        github:
          command: "npx"
          args: ["-y", "@modelcontextprotocol/server-github"]
          env:
            GITHUB_PERSONAL_ACCESS_TOKEN: "***"
          tools:
            include: [list_issues, create_issue, update_issue, search_code]
            resources: false
            prompts: false

      قائمة حظر لـ Stripe​

      mcp_servers:
        stripe:
          url: "https://mcp.stripe.com"
          headers:
            Authorization: "Bearer ***"
          tools:
            exclude: [delete_customer, refund_payment]

      خادم توثيق يقتصر على الموارد​

      mcp_servers:
        docs:
          url: "https://mcp.docs.example.com"
          tools:
            include: []
            resources: true
            prompts: false

      شهادة عميل TLS (mTLS)​

      لخوادم HTTP/SSE التي تتطلب شهادة عميل، اضبط client_cert (و client_key اختياريًا):

      mcp_servers:
        # Combined cert + key in a single PEM file
        internal_api:
          url: "https://mcp.internal.example.com/mcp"
          client_cert: "~/secrets/mcp-client.pem"

        # Separate cert and key files
        partner_api:
          url: "https://mcp.partner.example.com/mcp"
          client_cert: "~/secrets/client.crt"
          client_key: "~/secrets/client.key"

        # Encrypted key with a passphrase (3-element list form)
        bank_api:
          url: "https://mcp.bank.example.com/mcp"
          client_cert: ["~/secrets/client.crt", "~/secrets/client.key", "my-passphrase"]

        # Custom CA bundle (private CA / self-signed server)
        lab_api:
          url: "https://mcp.lab.local/mcp"
          ssl_verify: "~/secrets/lab-ca.pem"
          client_cert: "~/secrets/lab-client.pem"

      ملاحظات:

      • تدعم المسارات توسيع ~. تفشل الملفات المفقودة فورًا عند الاتصال مع رسالة خطأ خاصة بالخادم المعني.
      • يعطّل ssl_verify: false التحقق من شهادة الخادم كليًا. لا تستخدمه مع خدمات حقيقية.
      • يعمل مع ناقلَي Streamable HTTP و SSE كليهما.

      إعادة تحميل الإعدادات​

      بعد تغيير إعدادات MCP، أعد تحميل الخوادم باستخدام:

      /reload-mcp

      تسمية الأدوات​

      تصبح أدوات MCP الأصلية الخاصة بالخادم بالشكل التالي:

      mcp__<server>__<tool>

      أمثلة:

      • mcp__github__create_issue
      • mcp__filesystem__read_file
      • mcp__my_api__query_data

      تتبع الأدوات المساعدة نمط البادئة نفسه:

      • mcp__<server>__list_resources
      • mcp__<server>__read_resource
      • mcp__<server>__list_prompts
      • mcp__<server>__get_prompt

      يتوافق فاصل الشرطتين السفليتين المزدوجتين (mcp__…__…) مع الاصطلاح الذي تستخدمه Claude Code و Codex و OpenCode، ويزيل الالتباس عن الحدّ الفاصل بين الخادم والأداة حتى عندما يحتوي أيٌّ من الجزأين على شرطات سفلية.

      تنقية الأسماء​

      يُستبدَل بشرطة سفلية أيُّ حرف ليس حرفًا أبجديًا أو رقمًا أو شرطة سفلية (الشرطات والنقاط والمسافات وغيرها) في أسماء الخوادم وأسماء الأدوات على حدٍّ سواء قبل التسجيل. يضمن ذلك أن تكون أسماء الأدوات معرّفات صالحة لواجهات API الخاصة باستدعاء الدوال (function-calling) في نماذج LLM.

      على سبيل المثال، الخادم المسمّى my-api الذي يُتيح أداة تُدعى list-items.v2 يصبح:

      mcp__my_api__list_items_v2

      ضع هذا في حسبانك عند كتابة مرشّحات include / exclude — استخدم اسم أداة MCP الأصلي (بشرطاته/نقاطه)، لا النسخة المُنقّاة.

      المصادقة عبر OAuth 2.1​

      لخوادم HTTP التي تتطلب OAuth، اضبط auth: oauth في إدخال الخادم:

      mcp_servers:
        protected_api:
          url: "https://mcp.example.com/mcp"
          auth: oauth

      السلوك:

      • يستخدم Hermes تدفّق OAuth 2.1 PKCE الخاص بـ MCP SDK (اكتشاف البيانات الوصفية، وتعريف العميل، وتبادل الـ token، والتحديث)
      • عند الاتصال الأول، تُفتح نافذة متصفح للتفويض
      • تُحفَظ الـ tokens في ~/.hermes/mcp-tokens/<server>.json ويُعاد استخدامها عبر الجلسات
      • يتم تحديث الـ token تلقائيًا؛ ولا يُطلَب التفويض من جديد إلا عند فشل التحديث
      • ينطبق فقط على ناقل HTTP/StreamableHTTP (الخوادم المعتمدة على url)

      تسجيل الدخول برمز الجهاز (RFC 8628)​

      بالنسبة إلى خادم تفويض يُعلن عن device_authorization_endpoint، اختر صراحةً تفويض الجهاز من طرفية على الجهاز الذي يشغّل Hermes:

      hermes mcp login protected_api --flow device

      افتح عنوان URL الخاص بالتحقق المطبوع على أي جهاز وأدخل رمز المستخدم المعروض. يستطلع Hermes حالة الموافقة، ويحترم authorization_pending و slow_down، ويتوقف عند الرفض أو انتهاء الصلاحية. لا يُفتح أي متصفح ولا حاجة إلى مستمع لاستقبال الـ callback. يحدّد oauth.timeout مدة انتظار الموافقة (الافتراضي 300 ثانية)، وهي محدودة أيضًا بمدة صلاحية الرمز.

      اضبط oauth.flow: device على الخادم لجعل hermes mcp login و hermes mcp reauth (بما في ذلك reauth --all) تستخدم تفويض الجهاز. يتجاوز login --flow browser هذا الإعداد لعملية تسجيل دخول واحدة؛ ويبقى PKCE عبر المتصفح هو الافتراضي. تؤدي البيانات الوصفية غير المدعومة إلى خطأ يوضّح ما يجب فعله بدلًا من الرجوع بصمت إلى تدفّق مختلف.

      يطلب تسجيل الدخول بالجهاز منحتَي device و refresh أثناء التسجيل الديناميكي، أو يستخدم قيم oauth.client_id و oauth.client_secret و oauth.token_endpoint_auth_method التي ضبطتها. يجب أن يسمح العميل المسجَّل بتفويض الجهاز. لا يُستخدَم مستند CIMD الخاص بالمتصفح. يُرسَل oauth.scope مع طلب تفويض الجهاز؛ وينطبق oauth.user_agent أيضًا على استطلاع الـ token. تبقى الـ tokens والتسجيل والبيانات الوصفية للجهة المُصدِرة في مخزن tokens الخاص بـ MCP ضمن الـ profile النشط، ويعيد مسار التحديث الحالي وقت التشغيل استخدامها بعد إعادة التشغيل. لا تحلّ منح الأجهزة الفاشلة محلّ بيانات الاعتماد المحفوظة سابقًا.

      تسجيل الدخول الأولي بالجهاز متاح من الطرفية فقط: فلا تبدأ الـ callbacks الخاصة بلوحة التحكم/المتصفح ولا عمليات إعادة الاتصال في الخلفية تفويضَ الجهاز. شغّل أمر تسجيل الدخول على الـ profile نفسه والمضيف نفسه اللذين يعمل عليهما الـ gateway. تتطلب منحة الجهاز المنتهية/المرفوضة التي لا يرافقها refresh token صالح تسجيل دخول صريحًا آخر.

      تعريف العميل: CIMD و DCR​

      يعرّف Hermes نفسه لخوادم التفويض عبر Client ID Metadata Document (CIMD)، وهي الآلية التي اعتمدتها مواصفة MCP 2026-07-28 بدلًا من Dynamic Client Registration. يُنشَر المستند على https://nousresearch.github.io/hermes-agent/docs/oauth/client-metadata.json، وهذا العنوان هو قيمة client_id — إذ يجلبه خادم التفويض ليتعرّف على اسم Hermes وشعاره وعناوين URI المسموح بإعادة التوجيه إليها. لا يُسجَّل أي شيء لكل عملية تثبيت، ولا يوجد أي شيء خاص بالمستخدم.

      القرار النهائي يعود إلى خادم التفويض: إذ يرسل الـ SDK عنوان المستند بوصفه client_id فقط عندما يُعلن الخادم عن client_id_metadata_document_supported: true في بياناته الوصفية، وإلا فإنه يسجّل عبر DCR تمامًا كما كان من قبل. أصبح DCR مهملًا (deprecated) في مواصفة MCP، لكنه لا يزال ما تستخدمه تقريبًا كل الخوادم المنشورة اليوم.

      منافذ الـ Callback​

      يُصرّح المستند بمجموعة ثابتة من عناوين URI لإعادة التوجيه عبر loopback، وتشترط المواصفة أن يكون عنوان URI لإعادة التوجيه في طلب التفويض مطابقًا حرفيًا لأحدها — لذا لا يستطيع تدفّق CIMD استخدام المنفذ العالي العشوائي الذي يختاره Hermes عادةً. ولهذا يثبّت Hermes الـ callback على أحد المنافذ 27890–27894.

      يجب اختيار هذا المنفذ المثبّت قبل معرفة قدرات الخادم، لأن عنوان URI لإعادة التوجيه يُحدَّد في بداية التدفّق بينما لا تصل البيانات الوصفية للخادم إلا في منتصفه. لذا يثبّت Hermes المنفذ لأي تدفّق قد ينتهي باستخدام CIMD، ويعود إلى منفذ عشوائي في بقية الحالات:

      • الخادم الذي اتصل به Hermes من قبل ولا تُعلن بياناته الوصفية المخزّنة مؤقتًا عن دعم CIMD يحتفظ بالمنفذ العشوائي الذي استخدمه دائمًا.
      • الخادم الذي لم يصل إليه Hermes قط يحصل على منفذ مثبّت في أول تسجيل دخول، إذ إن التخمين هو السبيل الوحيد لاستخدام CIMD أصلًا.
      • كل ما من شأنه نقل الـ callback إلى مكان آخر يعيد الأمر إلى المنفذ العشوائي أيضًا: قيمة oauth.client_id مسجّلة مسبقًا، أو oauth.client_secret، أو قيمة مخصّصة لـ oauth.client_name أو oauth.token_endpoint_auth_method، أو تجاوز عبر oauth.redirect_uri أو oauth.redirect_port، أو تسجيل دخول تقوده لوحة التحكم أو تطبيق سطح المكتب، أو تسجيل عميل موجود مسبقًا على القرص، أو انشغال المنافذ الخمسة كلها بعمليات أخرى.

      يُربَط كل منفذ مثبّت فور اختياره ويبقى محجوزًا حتى تصل إعادة التوجيه من المتصفح، لذا لا يمكن لعمليتَي تسجيل دخول متزامنتين — لـ profile ثانٍ، أو لخادم آخر في العملية نفسها — أن تنتهيا على المستمع نفسه.

      عندما يرفض الخادم المستند​

      إذا جلب الخادم المستند ثم رفضه عند endpoint الخاص بالـ token (invalid_client)، يسجّل Hermes هذا الرفض في السجلات، ويدوّنه في ~/.hermes/mcp-tokens/<server>.cimd-off، ويستخدم DCR مع ذلك الخادم من ذلك الحين فصاعدًا.

      أما الخادم الذي لا يستطيع جلب المستند أو التحقق من صحته أصلًا، فيُجهض العملية عند endpoint الخاص بـ التفويض، قبل حدوث أي إعادة توجيه. لا توجد هناك إشارة يستطيع Hermes رصدها، لذا يعرض المتصفح خطأ invalid-client وتنتهي مهلة تسجيل الدخول بعد خمس دقائق. تذكر رسالة انتهاء المهلة المستند وتشير إلى cimd: false. يؤدي تشغيل hermes mcp login <server> إلى مسح الرفض المسجّل، لتحظى النسخة المصحّحة من المستند بفرصة أخرى.

      مفاتيح اختيارية لكل خادم​

      mcp_servers:
        protected_api:
          url: "https://mcp.example.com/mcp"
          auth: oauth
          oauth:
            client_metadata_url: "https://example.com/my-cimd.json"  # self-hosted document
            cimd: false                                              # force DCR
            user_agent: "My-MCP-Client/1.0"                          # token-request User-Agent

      يجب أن تكون قيمة client_metadata_url عنوان URL بـ HTTPS يتضمّن مسارًا (لا أصل مجرّد، ولا جزء fragment، ولا userinfo، ولا مقاطع ./..) ويُرجِع 200 و Content-Type: application/json دون إعادة توجيه — إذ يُحظَر على خوادم التفويض اتّباع إعادة التوجيه عند جلبه. لا يزال Hermes يثبّت الـ callback على النطاق نفسه 27890–27894، لذا يجب أن يُصرّح المستند المستضاف ذاتيًا بعناوين loopback العشرة كلها (http://127.0.0.1:<port>/callback و http://localhost:<port>/callback لكل منفذ)، ويجب أن تكون قيمة client_id فيه هي عنوان URL الخاص به.

      يستبدل user_agent ترويسة User-Agent الافتراضية لمكتبة HTTP في طلبات endpoint الخاص بالـ token فقط (تبادل رمز التفويض والتحديث) — إذ ترفض بعض خوادم التفويض وجدران WAF القيمة الافتراضية python-httpx/... هناك. لا ينطبق مطلقًا على حركة MCP أو اكتشاف OAuth، ولا يمكن ضبط أي ترويسات أخرى لطلبات الـ token. تُتجاهَل القيم الفارغة أو null.

      رابط Add to Hermes​

      يمكن لمورّدي MCP ولصفحات التوثيق تقديم زر "Add to Hermes" بنقرة واحدة يفتح تطبيق Hermes لسطح المكتب مع إعدادات خادم معبّأة مسبقًا، على غرار مخطط cursor://anysphere.cursor-deeplink/mcp/install الخاص بـ Cursor:

      hermes://mcp/install?name=NAME&config=BASE64
      • name — اسم الخادم. يجب أن يطابق ^[A-Za-z0-9._-]{1,64}$.
      • config — كائن إعدادات الخادم على شكل JSON مُرمَّز بـ base64url (يُقبَل base64 القياسي أيضًا). يجب أن يكون الـ JSON بعد فك ترميزه كائنًا يحتوي إما حقلًا نصيًا url (بـ http:///https:// فقط) أو حقلًا نصيًا command، ويمكن أن يتضمن أيًّا من مفاتيح الخادم الموضّحة أعلاه. تُرفَض الحمولات التي تتجاوز 32KB.

      مثال (JavaScript):

      const config = { url: 'https://mcp.example.com/mcp' }
      const link = `hermes://mcp/install?name=example&config=${btoa(JSON.stringify(config))
        .replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '')}`

      فتح الرابط لا يثبّت أي شيء من تلقاء نفسه: إذ يعرض تطبيق سطح المكتب مربع حوار للتأكيد يتضمن اسم الخادم والإعدادات كاملةً بتنسيق مقروء (مع تنبيه إضافي للخوادم المعتمدة على command، لأنها تشغّل عملية محلية)، ويجب على المستخدم التأكيد صراحةً. لا يُستبدَل أبدًا اسم خادم موجود — بل يُطلَب من المستخدم إعادة التسمية أو الإلغاء.
