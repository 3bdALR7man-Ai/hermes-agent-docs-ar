      مرجع Slash Commands

      يملك Hermes واجهتَين لأوامر slash، وتعمل كلتاهما بمحرّك COMMAND_REGISTRY مركزي في hermes_cli/commands.py:

      • أوامر slash التفاعلية في CLI — يوزّعها cli.py، مع إكمال تلقائي من السجلّ
      • أوامر slash في المراسلة — يوزّعها gateway/run.py، مع نص مساعدة وقوائم منصة مُولَّدة من السجلّ

      المهارات المثبَّتة تُعرَض أيضًا كأوامر slash ديناميكية على كلتا الواجهتين. (كان /plan واحدًا منها سابقًا؛ وهو الآن أمر مدمج — راجع جدول الجلسة أدناه.)

      الصلاحيات وتقسيم المشرف/المستخدم​

      كل منصة مراسلة تدعم قائمة سماح لكل مستخدم (Telegram وDiscord وSlack وMatrix وMattermost وSignal، …) تدعم أيضًا تقسيمًا ثنائي المستوى لأوامر slash: يحصل المشرفون على كل أمر مسجَّل، بينما يحصل المستخدمون العاديون فقط على الأسماء التي تدرجها في user_allowed_commands (إضافةً إلى الحد الأدنى المسموح دائمًا /help و/whoami). اضبط allow_admin_from وuser_allowed_commands (والمكافئات لكل مجموعة group_allow_admin_from / group_user_allowed_commands) داخل كتلة extra: الخاصة بالمنصة في ~/.hermes/config.yaml.

      راجع توثيق كل منصة على حدة للأمثلة — البنية متطابقة عبر المنصات:

      • Telegram
      • Discord
      • Slack
      • Matrix
      • Mattermost
      • Signal

      إذا كان allow_admin_from غير مضبوط لنطاق ما، يبقى ذلك النطاق في وضع التوافق الخلفي غير المقيَّد — كل مستخدم مسموح له يمكنه تشغيل كل أمر.

      Slash commands التفاعلية في CLI​

      اكتب / في CLI لفتح قائمة الإكمال التلقائي. الأوامر المدمجة غير حساسة لحالة الأحرف.

      الجلسة (Session)​

      الأمرالوصف
      /new [name] (الاسم البديل: /reset)ابدأ جلسة جديدة (معرّف جلسة وسجلّ جديدان). المعامل الاختياري [name] يضبط عنوان الجلسة الابتدائي — فمثلًا /new my-experiment يفتح جلسة جديدة بعنوان my-experiment بحيث يسهل إيجادها لاحقًا عبر /resume أو /sessions. أضف now أو --yes أو -y لتخطي نافذة التأكيد — مثل /reset now أو /new --yes my-experiment.
      /clearامسح الشاشة وابدأ جلسة جديدة
      /historyاعرض سجلّ المحادثة (يراعي /timestamps)
      /saveاحفظ المحادثة الحالية
      /prompt (الاسم البديل: /compose)أنشئ الـ prompt التالي في $EDITOR (بصيغة markdown) بدلًا من حقل الإدخال المضمّن — مفيد للنصوص الطويلة أو متعددة الأسطر أو التي تحتاج تنسيقًا دقيقًا.
      /retryأعد إرسال الرسالة الأخيرة إلى الوكيل
      /undoاحذف آخر تبادل بين المستخدم والوكيل
      /titleاضبط عنوانًا للجلسة الحالية (الاستخدام: /title اسم جلستي)
      /compress [here [N] | focus topic]اضغط سياق المحادثة يدويًا (تفريغ الذاكرة + تلخيص). /compress here [N] يلخّص كل شيء ما عدا آخر N تبادلات (الافتراضي 2)، التي تبقى كما هي حرفيًا — لتختار حدّ الضغط بنفسك. تحديد موضوع تركيز يضيّق ما يحتفظ به التلخيص الكامل.
      /rollbackاعرض أو استعِد نقاط حفظ نظام الملفات (الاستخدام: /rollback [رقم])
      /diff [staged|all|session] [--stat] [path...]اعرض تغييرات git في مجلد العمل. الافتراضي: التغييرات غير المُهيّأة (unstaged) بالإضافة إلى الملفات غير المتتبَّعة. staged يعرض ما هو مهيّأ للـ commit، وall يعرض كل شيء منذ HEAD، وsession يعرض الفرق التراكمي لكل ما غيّره Hermes هنا (من نقطة أساس آخر checkpoint محفوظة — يتطلب تفعيل نقاط الحفظ؛ ويكمّل /rollback diff <N>). --stat يطبع فقط ملخّص الملفات المتغيّرة؛ معاملات المسار تحصر الفرق.
      /snapshot [create|restore <id>|prune] (الاسم البديل: /snap)أنشئ أو استعِد لقطات (snapshots) لحالة إعدادات Hermes. create [label] يحفظ لقطة، وrestore <id> يعيدها، وprune [N] يحذف اللقطات القديمة، أو اسردها كلها بدون معاملات. استعادة قاعدة البيانات تتم عبر واجهة النسخ الاحتياطي (backup API) الخاصة بـ SQLite بحيث تظل العمليات الحيّة (gateway، لوحة التحكم) تطّلع على البيانات المستعادة بأمان؛ وإذا فشل هذا المسار بينما لا تزال عملية أخرى ممسكة بقاعدة البيانات، ترفض عملية الاستعادة بدلًا من المخاطرة بالتلف — أوقف العملية الممسكة بها وأعد المحاولة.
      /stopأنهِ كل العمليات الخلفية الجارية
      /queue <prompt> (الاسم البديل: /q)ضع prompt في قائمة الانتظار للدور التالي (لا يقاطع استجابة الوكيل الحالية).
      /steer <prompt>أدرج ملاحظة أثناء التشغيل تصل إلى الوكيل بعد استدعاء الأداة التالي — بلا مقاطعة، وبلا دور مستخدم جديد. يُضاف النص إلى محتوى نتيجة الأداة الأخيرة بمجرد اكتمال الأداة الحالية، ما يمنح الوكيل سياقًا جديدًا دون كسر حلقة استدعاء الأداة الجارية. استخدم هذا لتوجيه المسار أثناء المهمة (مثل "ركّز على وحدة المصادقة" بينما الوكيل يشغّل الاختبارات).
      /goal <text>اضبط هدفًا دائمًا يعمل Hermes على تحقيقه عبر الأدوار — تفسيرنا لحلقة Ralph. بعد كل دور، يقرر نموذج حَكَم مساعد ما إذا كان الهدف قد اكتمل؛ وإن لم يكتمل يواصل Hermes تلقائيًا. الأوامر الفرعية: /goal status، /goal pause، /goal resume، /goal clear. الميزانية الافتراضية 20 دورًا (goals.max_turns)، وأي رسالة مستخدم حقيقية تسبق حلقة الاستمرار، وتبقى الحالة عبر /resume. راجع الأهداف الدائمة (Persistent Goals) للشرح الكامل.
      /subgoal <text>أضِف معيارًا يحدده المستخدم إلى الهدف النشط أثناء الحلقة. يعرض prompt الاستمرار كل الأهداف الفرعية على الوكيل حرفيًا، ويأخذها الحَكَم بعين الاعتبار في قرار DONE/CONTINUE — لذا لا يُعدّ الهدف مكتملًا حتى يتحقق الهدف الأصلي وكل هدف فرعي. الأوامر الفرعية: /subgoal (سرد)، /subgoal remove <N>، /subgoal clear. يتطلب /goal نشطًا.
      /heartbeat every <interval> <prompt> (الاسم البديل: /hb)اضبط prompt متكررًا يدخل من جديد في هذه الجلسة كدور مستخدم عادي كلما كانت خاملة وانقضى الفاصل الزمني (الحد الأدنى 60 ثانية؛ الدقّات الفائتة تُدمج). الأوامر الفرعية: /heartbeat status، /heartbeat pause، /heartbeat resume، /heartbeat clear. مقتصر على الجلسة وداخل العملية — استخدم hermes cron للجداول الدائمة والمعزولة. راجع نبضات الجلسة (Session Heartbeats).
      /refine [focus]شغّل مراجعة التحسين الذاتي للذاكرة/المهارات الآن بدلًا من انتظار المُحفّز التلقائي بعد الدور. نص تركيز اختياري يوجّه المراجعة (مثل /refine save the deploy workflow as a skill). تعمل في تفرّع خلفي على لقطة من المحادثة — الجلسة الحيّة وذاكرة التخزين المؤقت للـ prompt لا يُمَسّان؛ وتُبلّغ النتائج عند الانتهاء.
      /review [instructions]ابدأ subagent مراجعة مستقلًا بصلاحية كاملة لمراجعة العمل الذي جرى مناقشته للتو — PR أو كود أو مستندات أو أي عنصر مُشار إليه في آخر 10 رسائل محادثة. يبحث في الخلفية (يفتح الـ PR، يقرأ الفرق، يشغّل الكود) وتعود مراجعته الكاملة إلى هذه الجلسة كإنجاز subagent خلفي يمكن للوكيل الأساسي التصرف بناءً عليه. عيّن نموذجًا مخصصًا للمراجعة عبر auxiliary.review في config.yaml (الافتراضي نموذجك الأساسي). راجع تفويض المهام إلى Subagents.
      /moa <prompt>شغّل prompt واحدًا عبر الإعداد الافتراضي لـMixture of Agents، ثم استعِد نموذجك الحالي. لمرة واحدة فقط — لا يغيّر نموذج جلستك.
      /resume [name]استأنف جلسة مُسمّاة سابقًا
      /sessions (الاسم البديل في TUI: /switch)الـ CLI الكلاسيكي: تصفّح واستأنف الجلسات السابقة في منتقي تفاعلي. TUI: افتح مبدّل الجلسات الحيّة لجلسات TUI المفتوحة حاليًا. استخدم /sessions new في TUI لبدء جلسة حيّة أخرى فورًا.
      /egress [status]اعرض حالة Docker egress proxy — حالة التفعيل/الإعداد/التشغيل، ومصدر بيانات الاعتماد، وتطابقات الـ token، والمزوّدين غير المغطّين، والخطوة التالية للمعالجة. تعمل في CLI و TUI و دردشة Desktop و messaging gateway.
      /redrawافرض إعادة رسم كاملة للواجهة (يعالج انحراف الطرفية بعد تغيير حجم tmux، أو آثار تحديد الفأرة، وما شابه)
      /statusاعرض معلومات الجلسة — النموذج، المزوّد، profile، معرّف الجلسة، مجلد العمل، العنوان، طوابع الإنشاء/التحديث الزمنية، إجماليات الـ token، حالة تشغيل الوكيل — يتبعها محليًا كتلة ملخّص الجلسة (Session recap) (عدد أدوار المستخدم/الوكيل الأخيرة، عدد نتائج الأدوات، أكثر الأدوات استخدامًا، آخر الملفات التي جرى التعامل معها، آخر prompt للمستخدم، وآخر رد للوكيل). الملخّص يُحسب محليًا من المحادثة الموجودة في الذاكرة؛ لا استدعاء لنموذج، ولا أثر على التخزين المؤقت للـ prompt.
      /context [all] (الاسم البديل: /ctx)عرض مرئي لتفصيل نافذة السياق. في CLI/TUI: شبكة رموز 5×20 (كل خلية ≈ 1% من نافذة النموذج) مع جدول تقديري لكل فئة — الـ system prompt، تعريفات الأدوات، القواعد، فهرس المهارات، MCP، الـ subagents، الذاكرة، المحادثة — مقابل المساحة الحرّة. على منصات المراسلة: مقياس استخدام يعرض حدّ/هامش الضغط التلقائي، وإحصاءات الضغط، والإنتاجية التراكمية، والجدول نفسه للفئات بنص عادي. /context all يضيف قوائم تكلفة لكل مهارة و toolset (تكلفة الفهرس مقابل تكلفة تحميل SKILL.md؛ tokens المخطط لكل toolset). للقراءة فقط ويُحسب محليًا — لا استدعاء لنموذج، ولا أثر على التخزين المؤقت للـ prompt.
      /agents (الاسم البديل: /tasks)اعرض الوكلاء النشطين والمهام الجارية عبر الجلسة الحالية.
      /bg <prompt>شغّل prompt في جلسة خلفية منفصلة. يعالج الوكيل الـ prompt بشكل مستقل — تبقى جلستك الحالية متاحة لعمل آخر. تظهر النتائج كلوحة عند انتهاء المهمة. راجع جلسات CLI الخلفية.
      /btw <question>اطرح سؤالًا جانبيًا سريعًا حول المحادثة الحالية دون مقاطعتها. استدعاء LLM مساعد لمرة واحدة يجيب من لقطة للقراءة فقط من النص الكامل — سجلّ الجلسة الحيّة والتخزين المؤقت للـ prompt لا يُمَسّان، ويستمر الدور الحالي في العمل. للعمل المستقل بسياق جديد، استخدم /bg.
      /branch [name] (الاسم البديل: /fork)تفرّع من الجلسة الحالية (استكشف مسارًا مختلفًا)
      /worktree [new [name]|list]حصري لـ CLI. افحص أو أنشئ worktrees معزولة لـ git أثناء الجلسة (مستوحى من /worktree new في Copilot CLI). /worktree وحدها تعرض الـ worktree النشط؛ و/worktree list تسرد worktrees المستودع؛ و/worktree new [name] تنشئ worktree تحت .worktrees/ (متفرّعًا من أحدث نسخة عن بُعد بعد جلبها، مع مراعاة worktree_sync) وتعيد توجيه أدوات الطرفية والملفات الخاصة بالجلسة إليه. الأشجار المسمّاة تستخدم اسمك (فرع hermes/<name>)؛ وغير المسمّاة تأخذ معرّف hermes-<id> عشوائي. عند الخروج، تُبقى الشجرة فقط إن كانت تحوي commits غير مدفوعة — نفس دورة حياة hermes -w. راجع Git Worktrees.
      /handoff <platform>حصري لـ CLI. سلّم الجلسة الحالية إلى منصة مراسلة (Telegram أو Discord أو Slack أو WhatsApp أو Signal أو Matrix). يلتقطها الـ gateway فورًا، وينشئ خيطًا جديدًا على المنصات التي تدعم الخيوط (مواضيع Telegram، خيوط قنوات Discord النصية، خيوط Slack المرتبطة برسالة)، ويعيد ربط الوجهة بمعرّف جلسة CLI لديك بحيث تُعاد المحادثة الكاملة الواعية بالأدوار، ويُصطنع دور مستخدم لتأكيد أن الوكيل يعمل في المكان الجديد. تُغلق جلسة CLI بنجاح مع تلميح /resume؛ استأنف محليًا في أي وقت عبر /resume <title>. يُرفض في منتصف الدور. يتطلب تشغيل الـ gateway وقناة رئيسية مضبوطة للمنصة المستهدفة (/sethome من محادثة الوجهة). راجع التسليم عبر المنصات (Cross-Platform Handoff).
      /journey [list|delete <id>|edit <id>] (الأسماء البديلة: /learning، /memory-graph)افتح الخط الزمني لمسار التعلّم للمهارات والذكريات المُتعلَّمة. يعمل في CLI الكلاسيكي، وكطبقة إضافية في TUI، وفي تطبيق سطح المكتب (لوحة Star Map). غير متاح على منصات المراسلة. راجع مسار التعلّم (Learning Journey).

      الإعدادات (Configuration)​

      الأمرالوصف
      /configاعرض الإعدادات الحالية
      /model [model-name]اعرض أو غيّر النموذج الحالي. يدعم: /model claude-sonnet-4، و/model provider:model (تبديل المزوّدين)، و/model custom:model (endpoint مخصص)، و/model custom:name:model (مزوّد مخصص مُسمّى)، و/model custom (اكتشاف تلقائي من الـ endpoint)، وأنماط حساب OpenRouter المُعدّة مسبقًا (/model @preset/<slug> أو /model <model>@preset/<slug> — هذه الأنماط خاصة بالحساب فتتخطى فحص قائمة النماذج العامة)، والأسماء المستعارة التي يعرّفها المستخدم (/model fav، /model grok — راجع الأسماء المستعارة المخصصة للنماذج). الخيارات: --global يحفظ التغيير في config.yaml؛ و--session يقصره على الجلسة؛ و--once يطبّقه على الدور التالي فقط؛ و--refresh يعيد جلب قائمة نماذج المزوّد؛ و--provider <name> يبدّل الخلفية (يقتصر على الجلسة ما لم تستخدم --global). الأمر /model <name> وحده يقتصر على الجلسة ما لم يُضبط model.persist_switch_by_default: true — إلا إذا لم يكن model.default/model.provider مضبوطًا بعد، فحينها يُحفَظ الاختيار الأول ليحصل الـ profile على قيمة افتراضية حقيقية. القاعدة نفسها تحكم منتقي مُركِّب سطح المكتب. المنتقي التفاعلي: تشغيل /model بلا معاملات يفتح منتقي المزوّد ← النموذج؛ في قائمة النماذج يمكنك الكتابة للتصفية التقريبية (fuzzy) (مثل كتابة grok لتضييق القائمة للنماذج المطابقة)، و Backspace لحذف حرف من التصفية، و Esc لمسحها (أو إغلاق المنتقي). يستقر الاختيار دائمًا على نموذج واحد محدد — التصفية تضيّق القائمة فقط، ولا تخمّن أبدًا. ملاحظة: يقتصر /model على التبديل بين مزوّدين مُعدّين مسبقًا. لإضافة مزوّد جديد، اخرج من الجلسة وشغّل hermes model من الطرفية. ملاحظة حول التكلفة: تبديل النموذج في منتصف المحادثة يصفّر التخزين المؤقت للـ prompt — لأن مفتاح التخزين المؤقت يتضمن النموذج — فيعاد قراءة المحادثة بأكملها في دورك التالي بسعر الإدخال الكامل بدلًا من السعر المخفَّض بنحو 75% للتخزين المؤقت. أمر متوقع لا مفرّ منه، لكن يستحق معرفته في الجلسات الطويلة.
      /codex-runtime [auto|codex_app_server|on|off]بدّل تشغيل Codex app-server runtime الاختياري لنماذج OpenAI/Codex. auto (الافتراضي) يستخدم إكمالات المحادثة القياسية في Hermes؛ وcodex_app_server يسلّم الأدوار إلى عملية فرعية codex app-server لتوفير shell أصلي وapply_patch ومصادقة اشتراك ChatGPT وإضافات Codex المُنقولة. يسري اعتبارًا من الجلسة التالية.
      /personalityاضبط شخصية محدّدة مسبقًا. /personality none (أو default / neutral) يزيل التراكب ويعيد السلوك الأساسي.

      الأمرالوصف

      الأوامر السريعة (Quick Commands)​

      الأوامر السريعة التي يعرّفها المستخدم تربط slash command قصيرًا بأمر shell أو بأمر slash آخر. أعدّها في ~/.hermes/config.yaml:

      quick_commands:
        status:
          type: exec
          command: systemctl status hermes-agent
        deploy:
          type: exec
          command: scripts/deploy.sh
        inbox:
          type: alias
          target: /gmail unread

      ثم اكتب /status أو /deploy أو /inbox في CLI أو منصة مراسلة. تُحلّ الأوامر السريعة وقت التنفيذ وقد لا تظهر في كل جدول إكمال تلقائي/مساعدة مدمج.

      اختصارات الـ prompt النصية فقط غير مدعومة كأوامر سريعة. ضع الـ prompts الطويلة القابلة لإعادة الاستخدام في مهارة، أو استخدم type: alias للإشارة إلى slash command موجود.

      الأسماء المستعارة المخصصة للنماذج​

      عرّف أسماء قصيرة خاصة بك للنماذج التي تستخدمها كثيرًا، ثم اطلبها عبر /model <alias> في جلسة جارية، أو hermes chat --model <alias> عند بدء التشغيل، أو أي منصة مراسلة. تعمل الأسماء المستعارة بشكل متطابق في هذه المسارات، على التبديلات المقتصرة على الجلسة (الافتراضي) وعلى --global.

      يُدعم صيغتان للإعداد:

      الصيغة الكاملة — لتثبيت نموذج ومزوّد محددين، واختياريًا base URL. ضع هذا في ~/.hermes/config.yaml:

      model_aliases:
        fav:
          model: claude-sonnet-4.6
          provider: anthropic
        grok:
          model: grok-4
          provider: x-ai
        ollama-qwen:
          model: qwen3-coder:30b
          provider: custom
          base_url: http://localhost:11434/v1
        theta:
          model: theta-1
          provider: custom
          base_url: https://theta.example.com/v1
          key_env: THETA_API_KEY        # or: api_key: "${THETA_API_KEY}"

      يمكن لاسم مستعار له base_url خاص به أن يحمل بيانات اعتماد ذلك الـ endpoint عبر api_key (قيمة حرفية، أو مرجع "${VAR}") أو key_env (اسم متغير بيئة)؛ ويفوز api_key إذا كان كلاهما مضبوطًا. وإن لم يُضبط أيّ منهما، يُحدَّد المفتاح من host الاسم المستعار ولا يُورَث أبدًا من المزوّد الذي كان نشطًا قبل التبديل.

      الصيغة المختصرة — provider/model في سلسلة واحدة. اضبطها من الـ shell دون تعديل YAML:

      hermes config set model.aliases.fav anthropic/claude-opus-4.6
      hermes config set model.aliases.grok x-ai/grok-4

      ثم في المحادثة:

      /model fav            # session-only
      /model grok --global  # also persists current-model change to config.yaml

      الأسماء المستعارة الخاصة بالمستخدم لها الأولوية على الأسماء القصيرة المدمجة، فتسمية اسم مستعار sonnet أو kimi أو opus إلخ سيحجب الاسم المدمج. أسماء الأسماء المستعارة غير حساسة لحالة الأحرف.

      تحليل الأسماء المستعارة (Alias Resolution)​

      تدعم الأوامر المطابقة بالبادئة (prefix matching): كتابة /h تُحلّ إلى /help، و/mod تُحلّ إلى /model. عندما تكون البادئة غامضة (تطابق عدة أوامر)، تفوز أول مطابقة بترتيب السجلّ. أسماء الأوامر الكاملة والأسماء المستعارة المسجَّلة لها دائمًا الأولوية على مطابقات البادئة.

      Slash commands في المراسلة​

      أوامر خيوط Slack (بادئة !): يمنع Slack نفسه slash commands الأصلية داخل خيوط الرسائل ("/queue is not supported in threads. Sorry!") ولا يوصلها أبدًا إلى Hermes. داخل خيط Slack، استخدم بادئة ! بدلًا منها — !stop، !new، !status — ويوجّهها الـ gateway تمامًا كما لو كانت بصيغة slash. تعمل @Hermes !stop و@Hermes /stop في الخيوط أيضًا. تُفحص الكلمة الأولى فقط مقابل قائمة الأوامر المعروفة، لذا رسائل مثل !nice work تمرّ إلى الوكيل دون تغيير. راجع استخدام الأوامر داخل الخيوط للتفاصيل.

      يدعم messaging gateway الأوامر المدمجة التالية داخل محادثات Telegram وDiscord وSlack وWhatsApp وSignal والبريد الإلكتروني وHome Assistant وTeams:

      الأمرالوصف
      /startأمر بروتوكول خاص بالمنصة. ترسل منصات محادثة كثيرة (Telegram، Discord، ...) أمر /start تلقائيًا عند أول فتح للمستخدم محادثة مع بوت. يُقرّ Hermes باستلامها بصمت — بلا رد من الوكيل، ودون استهلاك دور — بحيث لا تهدر مصافحات أول اتصال دورًا. يمكنك أيضًا إرسالها صراحةً للتأكد من إمكانية الوصول إلى الـ gateway.
      /new [name] (الاسم البديل: /reset)ابدأ جلسة جديدة (معرّف جلسة وسجلّ جديدان). المعامل الاختياري [name] يضبط عنوان الجلسة الابتدائي. أضف now أو --yes أو -y لتخطي نافذة التأكيد — مثل /reset now أو /new --yes my-experiment.

      تأكيدات الأوامر المدمّرة​

      يطلب CLI تأكيدًا قبل تنفيذ slash commands التي تُلقي بحالة الجلسة غير المحفوظة. المجموعة المدمّرة الحالية هي:

      الأمرما يدمّره
      /clearيمسح الشاشة ويبدأ جلسة جديدة — معرّف الجلسة الحالية والسجلّ الموجود في الذاكرة يختفيان.
      /new / /resetيبدأ جلسة جديدة (معرّف جلسة وسجلّ فارغ جديدان).
      /undoيحذف آخر تبادل بين المستخدم والوكيل من السجلّ.
      /exit --delete / /quit --deleteيخرج ويحذف نهائيًا سجلّ SQLite للجلسة الحالية والمحادثات المخزَّنة على القرص.

      لكل واحد من هذه الأوامر يفتح CLI نافذة بثلاثة خيارات: Approve Once (تابع لهذه المرة)، وAlways Approve (تابع واحفظ approvals.destructive_slash_confirm: false بحيث تعمل الأوامر المدمّرة القادمة دون سؤال)، أو Cancel.

      تخطٍّ مضمَّن: أضف now أو --yes أو -y لتجاوز النافذة لاستدعاء واحد — مثل /reset now، و/new --yes my-session، و/clear -y، و/undo -y. مفيد عندما لا تُعرض النافذة بشكل صحيح على طرفيتك (راجع issue #30768 بخصوص PowerShell الأصلي على Windows) أو عند برمجة سكربتات تتفاعل مع CLI.

      اضبط approvals.destructive_slash_confirm: false في ~/.hermes/config.yaml لتعطيل التأكيدات عالميًا؛ وأعده إلى true لإعادة التفعيل. راجع الأمان — تأكيد slash command المدمّرة للسياق.
