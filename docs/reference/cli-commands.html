      مرجع أوامر CLI

      تستخدم أوامر اعتماديات Python في هذه الصفحة نسخة مصدر مسحوبة أعدّها PM. بعد تغيير اعتماديات، أعد تفعيل النسخة المسحوبة وأعد تشغيل Hermes.

      تغطي هذه الصفحة أوامر الطرفية التي تشغّلها من الـ shell.

      لأوامر الـ slash داخل المحادثة، راجع مرجع Slash Commands.

      نقطة الدخول العامة​

      hermes [global-options] <command> [subcommand/options]

      الخيارات العامة​

      الخيارالوصف
      --version, -Vعرض الإصدار والخروج.
      --profile <name>, -p <name>اختيار profile Hermes الذي سيُستخدم لهذا الاستدعاء. يتجاوز الافتراضي الثابت الذي ضبطه hermes profile use.
      --resume <session>, -r <session>استئناف جلسة سابقة بالمعرّف أو العنوان. الكلمة المفتاحية latest تستأنف أحدث جلسة (ضمن نطاق مساحة العمل، بنفس منطق البحث المستخدم في -c).
      --continue [name], -c [name]استئناف أحدث جلسة، أو أحدث جلسة تطابق عنوانًا.
      --in <dir>الانتقال إلى <dir> قبل البدء أو الاستئناف. يحصر عمليات البحث لـ --resume latest / -c ضمن مساحة عمل ذلك المجلد ويُبقي الجلسة هناك (يتخطى استعادة الدليل الحالي المسجَّل).
      --worktree, -wالبدء في worktree معزول لـ git لسير عمل الوكلاء المتوازيين.
      --yoloتجاوز رسائل الموافقة على الأوامر الخطرة.
      --pass-session-idتضمين معرّف الجلسة في system prompt الخاص بالوكيل.
      --ignore-user-configتجاهل ~/.hermes/config.yaml والعودة إلى الإعدادات الافتراضية المضمّنة. تُحمَّل بيانات الاعتماد في .env رغم ذلك.
      --ignore-rulesتخطّي الحقن التلقائي لـAGENTS.md, SOUL.md, .cursorrules والذاكرة والمهارات المحمَّلة مسبقًا.
      --tuiتشغيل TUI بدلًا من CLI الكلاسيكي. مكافئ لـHERMES_TUI=1. يتفوّق دائمًا على display.interface.
      --cliفرض REPL الكلاسيكي القائم على prompt_toolkit. استخدم هذا لتجاوز display.interface: tui لاستدعاء واحد.
      --devمع --tui: تشغيل مصادر TypeScript مباشرة عبر tsx بدلًا من الحزمة المبنية مسبقًا (للمساهمين في TUI).

      hermes-agent (مشغّل قديم لاستعلام واحد)​

      يوفر التثبيت أيضًا hermes-agent، مشغّلًا بسيطًا يرسل استعلامًا واحدًا ويخرج: hermes-agent --query "summarize README.md" (أو hermes-agent "summarize README.md"). hermes-agent --help يسرد خياراته (--model, --base-url, --max-turns, --enabled-toolsets, --disabled-toolsets, --list-tools, --save-trajectories، …)، ويطبع hermes-agent --version الإصدار؛ ولا يبدأ أي منهما الوكيل. وعند تشغيله دون استعلام يطبع المساعدة نفسها ويخرج. ولأي استخدام آخر استخدم hermes (hermes -z <prompt> هو التشغيل البرمجي لمرة واحدة).

      الأوامر ذات المستوى الأعلى​

      الأمرالغرض
      hermes chatمحادثة تفاعلية أو لمرة واحدة مع الوكيل.
      hermes modelاختيار المزوّد والنموذج الافتراضيين تفاعليًا.
      hermes moaإعداد إعدادات مسبقة (presets) مسمّاة لـ Mixture of Agents يمكن اختيارها من منتقي النماذج.
      hermes fallbackإدارة المزوّدين الاحتياطيين الذين تُجرَّب عند حدوث خطأ في النموذج الأساسي.
      hermes gatewayتشغيل أو إدارة خدمة gateway المراسلة.
      hermes proxyproxy محلي متوافق مع OpenAI يُرفق بيانات اعتماد مزوّد OAuth. راجع Subscription Proxy.
      hermes egressجدار حماية لحقن بيانات الاعتماد الصادرة لـ sandboxes الطرفية البعيدة (iron-proxy). معطّل افتراضيًا. راجع Egress proxy.
      hermes lspإدارة تكامل Language Server Protocol (تشخيص دلالي لـ write_file/patch).
      hermes setupمعالج إعداد تفاعلي لكل الإعدادات أو جزء منها.
      hermes whatsappإعداد وإقران جسر WhatsApp.
      hermes whatsapp-cloudإعداد محوّل Meta WhatsApp Business Cloud API الرسمي (يتطلب حساب Business و webhook عامًا). يختلف عن hermes whatsapp (جسر Baileys للحساب الشخصي).
      hermes slackأدوات مساعدة لـ Slack (حاليًا: توليد بيان التطبيق (manifest) بكل الأوامر كـ slash أصلية).
      hermes authإدارة بيانات الاعتماد — الإضافة والعرض والإزالة وإعادة التعيين والحالة وتسجيل الخروج. يتعامل مع تدفقات OAuth لـ Codex/Nous/Anthropic.
      hermes login / logoutمهمل (Deprecated) — استخدم hermes auth بدلًا منه.
      hermes sendإرسال رسالة لمرة واحدة إلى منصة مراسلة مُعدَّة (Telegram و Discord و Slack و Signal و SMS ، ...). مفيد من سكربتات shell ومهام cron و hooks CI و daemons المراقبة — بدون حلقة وكيل، بدون LLM.
      hermes peerتسجيل gateways نظيرة (peer) لـ Hermes على أجهزة أخرى ومراسلة Bot Chats الأساسية لوكلائها مباشرة (hermes peer dm <peer>[/<agent>] "…"). آلية النقل خلف مراسلة bot-إلى-bot عبر الأجهزة.
      hermes secretsإدارة مصادر الأسرار (secrets) الخارجية (حاليًا Bitwarden Secrets Manager) لسحب مفاتيح API عند بدء العملية بدلًا من ~/.hermes/.env.
      hermes migrateتشخيص و(اختياريًا) إعادة كتابة config.yaml لاستبدال مراجع النماذج المتقاعدة أو الإعدادات المهملة (مثل migrate xai).
      hermes codex-runtimeالمكافئ غير التفاعلي لـ /codex-runtime: migrate [--dry-run] [--json] يعيد توليد الكتلة المُدارة من Hermes في ~/.codex/config.toml للـ profile المختار. راجع بيئة تشغيل Codex app-server.
      hermes statusعرض حالة الوكيل والمصادقة والمنصة.
      hermes usageعرض نوافذ حد المعدل للحساب المُعدّ (كتلة /usage) دون جلسة؛ و --json للسكربتات.
      hermes cronفحص مُجدول cron وتشغيل tick له.
      hermes pause / hermes resumeإيقاف طارئ شامل: لا تبدأ أي عمليات cron جديدة (المؤقّت المدمج، و webhook الخاص بـ cron المُدار، واللحاق بالتشغيلات الفائتة)، ولا إرسال مهام kanban، ولا أدوار gateway إلى أن يُستأنف العمل. وأدوار CLI التفاعلي و TUI و Desktop هي أدوار gateway، فتُحجز هي أيضًا، وتعرض كل واجهة "Hermes is paused" مع السبب و "run hermes resume". أما الأدوار الجارية بالفعل فتنتهي؛ ولا يُقتل أي عمل قيد التنفيذ أبدًا.
      hermes kanbanلوحة تعاون متعددة الـ profiles (مهام وروابط وموزّع).
      hermes projectإدارة مساحات عمل (مشاريع) مسمّاة متعددة المجلدات. ترسو عليها مجموعة جلسات desktop ، وعند ربطها بلوحة kanban ، تمنح المهام اصطلاح worktree + branch حتميًا. الحالة لكل profile.
      hermes webhookإدارة اشتراكات webhook الديناميكية للتفعيل القائم على الأحداث.
      hermes hooksفحص أو الموافقة على أو إزالة hooks سكربت الـ shell المعلَنة في config.yaml.
      hermes doctorتشخيص مشاكل الإعدادات والاعتماديات.
      hermes security auditتدقيق سلسلة توريد عند الطلب (OSV.dev) لـ venv ، ومتطلبات الإضافات، وخوادم MCP المثبَّتة بإصدار محدَّد.
      hermes approvalsأدوات رسائل الموافقة — تنقيب سجل الموافقات لاستخراج مقترحات allowlist.
      hermes dumpملخّص إعداد قابل للنسخ واللصق للدعم/التصحيح.
      hermes prompt-sizeعرض تفصيل بالبايت لـ system prompt + مخططات الأدوات (فهرس المهارات، الذاكرة، profile). يعمل دون اتصال.
      hermes debugأدوات تصحيح — رفع السجلات ومعلومات النظام للدعم.
      hermes backupنسخ احتياطي لدليل Hermes الرئيسي إلى ملف zip.
      hermes checkpointsفحص / تقليم / مسح ~/.hermes/checkpoints/ (المخزن الظلّي (shadow store) الذي يستخدمه /rollback). شغّله بدون معاملات للحصول على نظرة عامة على الحالة.
      hermes importاستعادة نسخة احتياطية لـ Hermes من ملف zip.
      hermes logsعرض ومتابعة وتصفية ملفات سجل الوكيل/gateway/الأخطاء.
      hermes configعرض وتحرير وترحيل واستعلام ملفات الإعدادات.
      hermes skinعرض وتبديل وتعديل مظاهر العرض (skins).
      hermes consoleفتح وحدة تحكم Hermes الآمنة.
      hermes pairingالموافقة على أو إبطال رموز إقران المراسلة.
      hermes skillsتصفح المهارات وتثبيتها ونشرها وتدقيقها وإعدادها.
      hermes bundlesتجميع عدة مهارات تحت أمر slash واحد /<name>. راجع حزم المهارات.
      hermes curatorصيانة مهارات في الخلفية — الحالة، التشغيل، الإيقاف المؤقت، التثبيت (pin). راجع Curator.
      hermes journey (يسمّى أيضًا learning, memory-graph)الجدول الزمني للمهارات المُتعلَّمة والذكريات عبر الزمن.
      hermes memoryإعداد مزوّد الذاكرة الخارجي. تُسجَّل أوامر فرعية خاصة بالإضافة (مثل hermes honcho) تلقائيًا عندما يكون مزوّدها نشطًا.
      hermes acpتشغيل Hermes كخادم ACP للتكامل مع المحررات.
      hermes mcpإدارة إعدادات خوادم MCP وتشغيل Hermes كخادم MCP.
      hermes connectorsعرض حسابات الموصّلات (connectors) المستضافة وربطها وإعادة تسميتها وفصلها.
      hermes pluginsإدارة إضافات Hermes Agent (التثبيت والتفعيل والتعطيل والإزالة).
      hermes portalحالة Nous Portal ، رابط الاشتراك، وتوجيه Tool Gateway. راجع Tool Gateway.
      hermes toolsإعداد الأدوات المفعّلة لكل منصة.
      hermes computer-useتثبيت أو فحص backend الخاص بـ Computer Use (cua-driver) (macOS/Windows/Linux).
      hermes petsتصفح وتثبيت واختيار الحيوانات الأليفة المتحركة من petdex المعروضة عبر CLI و TUI وتطبيق desktop. الأوامر الفرعية: list, install, select, show, off, scale, remove, doctor.
      hermes sessionsتصفح الجلسات وتصديرها وتقليمها وإعادة تسميتها وحذفها.
      hermes insightsعرض تحليلات الـ tokens/التكلفة/النشاط.
      hermes clawأدوات مساعدة للانتقال من OpenClaw.
      hermes import-agentاستيراد إعداد Claude Code (~/.claude) أو Codex CLI (~/.codex) للإعداد.
      hermes dashboardتشغيل لوحة التحكم على الويب لإدارة الإعدادات ومفاتيح API والجلسات.
      hermes serveتشغيل خادم Hermes الخلفي (بدون واجهة؛ يشغّل تطبيق desktop والـ backends البعيدة).
      hermes desktop (يسمّى أيضًا gui)بناء وتشغيل تطبيق desktop الأصلي المبني على Electron.
      hermes profileإدارة الـ profiles — نُسخ Hermes معزولة متعددة.
      hermes completionطباعة سكربتات إكمال الـ shell (bash/zsh/fish).
      hermes --versionعرض معلومات الإصدار.
      hermes updateالتحديث إلى أحدث إصدار مستقر (أو القناة المختارة) وإعادة تثبيت الاعتماديات. --check تعاين دون تثبيت؛ --backup تأخذ لقطة (snapshot) لـHERMES_HOME قبل السحب.
      hermes uninstallإزالة Hermes من النظام.

      hermes chat​

      hermes chat [options]

      خيارات شائعة:

      الخيارالوصف
      -q ، --query "..."بذر الجلسة بـ prompt. على TTY حقيقي، يُرسَل الـ prompt حرفيًا كأول دور (turn) في جلسة تفاعلية عادية (لا يُفسَّر أبدًا كأمر slash أو escape لـ ! الخاص بالـ shell) وتبقى الجلسة مفتوحة — مثالي لمشغِّلات نظام التشغيل وتكاملات desktop. مع --oneshot أو -Q أو stdio غير TTY، يجيب ويخرج.
      --query-file PATHقراءة الاستعلام من ملف (- = stdin). لا شيء يُفسَّر بواسطة الـ shell، لذا تصل علامات الاقتباس و $(...) والفواصل العليا (backticks) كما هي — استخدم هذا لأجسام الرسائل البرمجية أو غير الموثوقة (يستخدمه Bot Mode لرسائل teammate DM المباشرة). حصري مع -q.
      --oneshotمع -q/--query-file: الإجابة على الاستعلام والخروج (سلوك الاستعلام الواحد قبل الإصدار 0.21) بدلًا من بذر جلسة تفاعلية. ضمني على stdio غير TTY وبـ -Q.
      -m ، --model <model>تجاوز النموذج لهذا التشغيل.
      -t ، --toolsets <csv>تفعيل مجموعة toolsets مفصولة بفواصل.
      --provider <provider>فرض مزوّد: auto ، openrouter ، nous ، openai-codex (الاسمان البديلان chatgpt و chatgpt-codex)، copilot-acp ، copilot ، anthropic ، gemini ، huggingface ، novita (وله أسماء بديلة novita-ai ، novitaai)، openai-api ، zai ، kimi-coding ، kimi-coding-cn ، minimax ، minimax-cn ، minimax-oauth ، kilocode ، xiaomi ، arcee ، gmi ، upstage (اسم بديل solar)، alibaba ، alibaba-cn ، alibaba-coding-plan (اسم بديل alibaba_coding)، alibaba-coding-plan-cn ، alibaba-token-plan ، alibaba-token-plan-cn ، deepseek ، nvidia ، ollama-cloud ، xai (اسم بديل grok)، xai-oauth (اسم بديل grok-oauth)، qwen-oauth ، bedrock ، opencode-zen ، opencode-go ، commandcode ، commandcode-anthropic ، ai-gateway ، azure-foundry ، lmstudio ، stepfun ، tencent-tokenhub (اسم بديل tencent ، tokenhub)، router (أسماء بديلة ramp-router ، ramp)، nebius-token-factory (أسماء بديلة nebius ، nebius-tf ، tokenfactory)، tencent-tokenplan (أسماء بديلة tokenplan ، tencent-lkeap).
      -s ، --skills <name>تحميل مهارة أو أكثر مسبقًا للجلسة (يمكن تكرارها أو الفصل بينها بفواصل).
      -v ، --verboseمخرجات مفصّلة.
      -Q ، --quietالوضع البرمجي: إخفاء الشعار ومؤشر الانتظار ومعاينات الأدوات.
      --format stream-jsonإصدار JSONL منظَّم لاستدعاء -q / --query. يستلزم --quiet ؛ ولا يمكن دمجه مع --tui.
      --image <path>إرفاق صورة محلية باستعلام واحد.
      --resume <session> / --continue [name]استئناف جلسة مباشرة من chat.
      --worktreeإنشاء worktree معزول لـ git لهذا التشغيل.
      --checkpointsتفعيل نقاط حفظ نظام الملفات قبل التغييرات المدمّرة على الملفات.
      --yoloتخطي رسائل الموافقة.
      --pass-session-idتمرير معرّف الجلسة إلى system prompt.
      --ignore-user-configتجاهل ~/.hermes/config.yaml واستخدام الإعدادات الافتراضية المضمّنة. تُحمَّل بيانات الاعتماد في .env رغم ذلك. مفيد لتشغيلات CI المعزولة، وتقارير الأخطاء القابلة لإعادة الإنتاج، والتكاملات الخارجية.
      --ignore-rulesتخطّي الحقن التلقائي لـ AGENTS.md و SOUL.md و .cursorrules والذاكرة الدائمة والمهارات المحمَّلة مسبقًا. اجمعها مع --ignore-user-config لتشغيل معزول بالكامل.
      --safe-modeوضع استكشاف الأخطاء: تعطيل كل التخصيصات — إعدادات المستخدم، وحقن القواعد/الذاكرة، والإضافات، و hooks الـ shell، وخوادم MCP (يستلزم --ignore-user-config و --ignore-rules). يثبّت الـ gateway القيم الافتراضية في الشيفرة مع خياراتك الصريحة داخل الجلسة، ويشغّل الدور في عملية عامل معزولة لا تقرأ الـ profile أبدًا، فلا يستطيع config.yaml معطوب أن يعيقه. ويتطلب --model صريحًا (إذ لا يوجد profile افتراضي يُورَّث منه)؛ وادمجه مع --provider custom --base-url <url> --api-key <key> للحصول على endpoint صريح بالكامل.
      --base-url <url> / --api-key <key>endpoint صريح متوافق مع OpenAI ومفتاح خاص بالتشغيل فقط للخيار --provider custom. يُحفظ المفتاح في ذاكرة الـ gateway العامل لهذه الجلسة ولا يُكتب على القرص أبدًا.
      --source <tag>وسم مصدر الجلسة للتصفية (الافتراضي: cli ؛ وتكون القيمة الافتراضية لعمليات التشغيل لمرة واحدة oneshot ، التي تخفيها المحدّدات). استخدم tool لتكاملات الجهات الخارجية التي ينبغي ألا تظهر في قوائم جلسات المستخدم. وتُخزَّن القيمة الصريحة لـ --source دائمًا كما أُعطيت، حتى لتشغيل لمرة واحدة أُطلق من داخل جلسة TUI أو Desktop.
      --max-turns <N>الحد الأقصى لتكرارات استدعاء الأدوات لكل دور محادثة (الافتراضي: 500، أو agent.max_turns في الإعدادات).

      --format stream-json — مخرجات JSONL منظَّمة​

      استخدم --format stream-json عندما يحتاج برنامج إلى استهلاك معلومات التقدّم دون كشط مخرجات الطرفية. يتطلب -q / --query (أو --query-file)، ويستلزم وضع CLI الهادئ غير التفاعلي، ويرفض طلبًا صريحًا لـ --tui. وكل سطر stdout كائن JSON واحد؛ وتظل التشخيصات وسطر session_id: على stderr.

      hermes chat -q "Summarize this repository" --format stream-json

      يحمل كل حدث timestamp (الوقت بالميلي ثانية منذ بداية حقبة Unix).

      tool_usename ؛ و input عند توفر وسيطات الأداة

      رموز خروج عمليات التشغيل لمرة واحدة​

      عندما تجيب المحادثة ثم تنتهي (-Q أو chat --oneshot أو استعلام يستخدم stdio غير مرتبط بـ TTY)، يُبلِغ رمز خروج العملية عن نتيجة الدور في المسارين الهادئ وغير الهادئ: 0 اكتمل الدور؛ 1 فشل أو توقف جزئيًا (partial)، أو بلغ ميزانية التكرارات، أو لم يُشغَّل أصلًا (لفشل بيانات الاعتماد / تهيئة الوكيل)؛ 130 تمت مقاطعته. وتخرج عملية عامل أطلقها موزّع Kanban (مع ضبط HERMES_KANBAN_TASK) وفشل دورها فقط بسبب خضوع المزوّد لحدّ المعدل أو زيادة الحمل أو إرجاع 5xx أو انتهاء المهلة أو بلوغ الحساب حدّ الفوترة/الحصة، بالرمز 75 (EX_TEMPFAIL) كي يعيد الموزّع المهمة إلى الطابور دون احتساب فشل. ومع --format stream-json يحمل سجل result النهائي القيمة نفسها لـ exit_code.

      التفويض في تشغيلات المحادثة المحدودة​

      عندما تجيب المحادثة وتخرج، ينتظر delegate_task أبناءه ويعيد نتائجهم في الدور نفسه بدلًا من تشغيلهم في الخلفية. التفاصيل والحدود: التفويض: تشغيلات المحادثة المنتهية.

      hermes -z <prompt> — تشغيل واحد بسكربت​

      للمستدعين البرمجيين (سكربتات shell، و CI، و cron، والعمليات الأم التي تمرّر prompt عبر الأنبوب)، يُعدّ hermes -z أنقى نقطة دخول لتشغيل واحد: prompt واحد يدخل، ونص الرد النهائي يخرج، ولا شيء آخر على stdout أو stderr. لا شعار، لا مؤشر تحميل، لا معاينات أدوات، لا سطر Session: — فقط رد الوكيل النهائي كنص عادي.

      hermes -z "What's the capital of France?"
      # → Paris.

      # Parent scripts can cleanly capture the response:
      answer=$(hermes -z "summarize this" < /path/to/file.txt)

      رموز الخروج: 0 اكتمل الدور؛ 2 فشل أو توقف جزئيًا (partial أو ميزانية التكرارات أو completed: false) — حتى إذا طُبع تفسير؛ 130 تمت مقاطعته؛ 1 اكتمل الدور دون إنتاج أي نص؛ 2 كذلك لأخطاء الاستخدام (خيارات غير صحيحة) قبل بدء التشغيل. وتختلف هذه الرموز عمدًا عن chat -q / -Q أعلاه (اللذين يخرجان بالرمز 1 للفشل/التوقف الجزئي/الميزانية، وبالرمز 0 لدور مكتمل بلا نص): إذ يحجز -z الرمز 1 لحالة "لم يُجب بشيء". احكم على التشغيل من رمز الخروج (أو خيارات --usage-file)، لا من كون stdout غير فارغ.

      --usage-file — تقرير استخدام JSON لخطوط الأنابيب (pipelines)​

      hermes -z "…" --usage-file /path/report.json يكتب تقرير استخدام قابلًا للقراءة آليًا بعد التشغيل: estimated_cost_usd ، input_tokens / output_tokens / cache_read_tokens / cache_write_tokens / reasoning_tokens / total_tokens ، api_calls ، model ، provider ، session_id ، service_tier ، وعلامتَي completed / failed / partial / interrupted ، و turn_exit_reason (سبب كون completed غير صحيح، مثل max_iterations_reached(3/3)). ولا تشمل تلك العدّادات العليا إلا حلقة الوكيل الرئيسية. وتُبلَّغ استدعاءات LLM المساعدة في التشغيل نفسه (توليد العنوان، والرؤية، وضغط السياق، و web_extract ، والمراجعة الخلفية، …) بصورة منفصلة تحت auxiliary — بالإجماليات نفسها إضافةً إلى خريطة by_task لكل مهمة — ويكون total_including_auxiliary (estimated_cost_usd ، total_tokens ، api_calls) هو الإجمالي الكلي المعتمد للفوترة. ويُكتب التقرير حتى عند فشل التشغيل، حتى تتمكن خطوط الأنابيب الدفعية دائمًا من احتساب الإنفاق. لا أثر له خارج -z/--oneshot ، وفشل كتابة الاستخدام لا يخفي أبدًا نتيجة التشغيل نفسه.

      hermes -z "summarize this repo" --usage-file ~/.hermes/cache/scratch/usage.json
      jq .total_including_auxiliary.estimated_cost_usd ~/.hermes/cache/scratch/usage.json
      jq .auxiliary.by_task ~/.hermes/cache/scratch/usage.json      # what did title generation / vision cost?

      hermes model​

      منتقي مزوّد + نموذج تفاعلي. هذا هو الأمر لإضافة مزوّدين جدد، وإعداد مفاتيح API، وتشغيل تدفقات OAuth. شغّله من طرفيتك — وليس من داخل جلسة محادثة Hermes نشطة.

      hermes model

      استخدم هذا عندما تريد:

      • إضافة مزوّد جديد (OpenRouter و Anthropic و Copilot و DeepSeek ومخصص، إلخ)
      • تسجيل الدخول إلى مزوّدين مدعومين بـ OAuth (Anthropic و Copilot و Codex و Nous Portal)
      • إدخال أو تحديث مفاتيح API
      • الاختيار من قوائم النماذج الخاصة بالمزوّد
      • إعداد endpoint مخصص/مستضاف ذاتيًا
      • حفظ الافتراضي الجديد في الإعدادات
      hermes model مقابل /model — اعرف الفرق

      hermes model (يُشغَّل من طرفيتك، خارج أي جلسة Hermes) هو معالج إعداد المزوّد الكامل. يمكنه إضافة مزوّدين جدد، وتشغيل تدفقات OAuth، وطلب مفاتيح API، وإعداد endpoints.

      /model (يُكتب داخل جلسة محادثة Hermes نشطة) يستطيع فقط التبديل بين المزوّدين والنماذج التي أعددتها بالفعل. لا يمكنه إضافة مزوّدين جدد، أو تشغيل OAuth، أو طلب مفاتيح API.

      إذا احتجت إلى إضافة مزوّد جديد: اخرج من جلسة Hermes أولًا (Ctrl+C أو /quit)، ثم شغّل hermes model من موجّه طرفيتك.

      أمر /model الـ slash (في منتصف الجلسة)​

      التبديل بين النماذج المُعدَّة مسبقًا دون مغادرة الجلسة:

      /model                              # Show current model and available options
      /model claude-sonnet-4              # Switch model (auto-detects provider)
      /model zai:glm-5                    # Switch provider and model
      /model custom:qwen-2.5              # Use model on your custom endpoint
      /model custom                       # Auto-detect model from custom endpoint
      /model custom:local:qwen-2.5        # Use a named custom provider
      /model openrouter:anthropic/claude-sonnet-4  # Switch back to cloud

      افتراضيًا، تُطبَّق تغييرات /model لا تسري التغييرات إلا على الجلسة الحالية فقط. أضف --global لحفظ التغيير في config.yaml بشكل دائم (أو اضبط model.persist_switch_by_default: true ليصبح كل تبديل دائمًا):

      /model claude-sonnet-4 --global     # Switch and save as new default
      ماذا لو رأيت نماذج OpenRouter فقط؟

      إذا كنت قد أعددت OpenRouter فقط، فسيعرض /model نماذج OpenRouter فقط. لإضافة مزوّد آخر (Anthropic و DeepSeek و Copilot، إلخ)، اخرج من جلستك وشغّل hermes model من الطرفية.

      عند التبديل بـ --global ، تُحفظ تغييرات المزوّد وعنوان URL الأساسي في config.yaml إلى جانب النموذج. وعند التبديل بعيدًا عن endpoint مخصص، يُمسح عنوان URL الأساسي القديم لمنع تسربه إلى مزوّدين آخرين.

      الأوامر الفرعية:

      الأمر الفرعيالوصف
      runتشغيل gateway في المقدمة (foreground). موصى به لـ WSL و Docker و Termux.
      ensureاكتشاف بيئة تشغيل جلسات محلية أو طلبها دون تثبيت خدمة أو استبدال مالك موجود. يُخرج JSON؛ انظر أدناه.

      stopإيقاف الخدمة (أو عملية المقدمة).
      restartإعادة تشغيل الخدمة.
      statusعرض حالة الخدمة.
      listعرض كل الـ profiles وما إذا كان gateway كل profile يعمل حاليًا (مع PID إن توفّر). مفيد عندما تشغّل عدة profiles جنبًا إلى جنب وتريد نظرة عامة واحدة.

      uninstallإزالة الخدمة المثبَّتة.
      setupإعداد منصة مراسلة تفاعلي.

      migrate-legacyإزالة وحدات hermes.service القديمة المتبقية من التثبيتات قبل إعادة التسمية. لا تُمَس أبدًا وحدات الـ profile (hermes-gateway-<profile>.service) ولا الخدمات غير ذات الصلة. العلامات: --dry-run ، -y/--yes.
      enrollتجريبي: تسجيل هذا الـ gateway مع موصّل relay وحفظ بيانات اعتماد relay لمنصات مدعومة بموصّل. راجع Hermes Relay.

      الخيارات:

      الخيارالوصف
      --allعند start / restart / stop: العمل على gateway كل profile، لا فقط HERMES_HOME النشط. مفيد إذا كنت تشغّل عدة profiles جنبًا إلى جنب وتريد إعادة تشغيلها كلها بعد hermes update.
      -y, --yesعند stop / restart: إذا كان الـ gateway يشغّل أدوار محادثة أو مهام cron أو تفويضات في الخلفية، يعرضها الأمر ويسأل y/N قبل مقاطعتها. ويتخطى --yes السؤال. وإذا لم تتوفر طرفية للسؤال (السكربتات، cron) يرفض الأمر ما لم يُمرَّر --yes. و --interrupt اسم بديل.
      --detachعند restart: إذا لم تكن هناك خدمة gateway مثبّتة، يُبدأ البديل في الخلفية (بالطريقة التي يبدأ بها hermes gateway ensure واحدًا) بدلًا من الطرفية الحالية. يمرّره تطبيق desktop وإعادة تشغيل الاسترداد التابعة للمحدِّث حتى لا يصبح استدعاء إعادة التشغيل قصير العمر هو الـ gateway نفسه. ولا تتغير إعادة تشغيل الخدمة أو المشرف (supervisor) أو مهمة Windows.
      --no-superviseعند run: داخل صورة Docker القائمة على s6-overlay، عدم الاشتراك في الإشراف التلقائي واستخدام دلالات المقدمة السابقة لـ s6 — يعمل gateway كعملية الحاوية الرئيسية دون إعادة تشغيل تلقائي. بلا تأثير خارج صورة s6. مكافئ لضبط HERMES_GATEWAY_NO_SUPERVISE=1.
      --external-supervisorعند run: الإعلان أن مدير عمليات مزوَّد من خلال wrapper يملك gateway الأمامي. استخدم هذا عندما يزيل sudo أو env -i أو wrapper آخر علامة البيئة الأصلية لـ launchd/systemd. تخرج إعادة التشغيل والتحديثات داخل المحادثة إلى ذلك المدير بدلًا من إنشاء بديل منفصل.

      --external-supervisor عقد سياسة إعادة التشغيل: فإعادة التشغيل من داخل المحادثة، أو hermes gateway restart ، أو تحديث يعيد تشغيل الخدمة، تخرج بالحالة 75 (ثم ينتظر CLI معرّف PID الجديد من المشرف بدلًا من تشغيل gateway خاص به في المقدمة)، لذا يجب أن يعيد مشرف wrapper إطلاق gateway بعد ذلك الخروج غير الصفري. وبالنسبة إلى systemd، استخدم Restart=on-failure أو Restart=always ولا تُدرج 75 ضمن RestartPreventExitStatus ؛ بالنسبة لـ launchd، اضبط KeepAlive لإعادة التشغيل بعد الخروجات غير الناجحة. بدون تلك السياسة، تترك إعادة تشغيل مطلوبة gateway متوقفًا.

      يقبل hermes gateway enroll الخيارات --token و --connector-url و --gateway-id و --wake-url. يستبدل رمز التسجيل مع الموصّل ويكتب قيم GATEWAY_RELAY_ID و GATEWAY_RELAY_SECRET و GATEWAY_RELAY_DELIVERY_KEY الناتجة، و GATEWAY_RELAY_URL الاختياري، و(عند إعطاء --wake-url) GATEWAY_RELAY_WAKE_URL في ملف .env الخاص بالـ profile النشط.

      مستخدمو WSL

      استخدم hermes gateway run بدلًا من hermes gateway start — دعم systemd في WSL غير موثوق. لفّه في tmux للاستمرارية: tmux new -s hermes 'hermes gateway run'. راجع الأسئلة الشائعة عن WSL للتفاصيل.

      اكتشاف بيئة التشغيل المحلية وبدؤها​

      يكتشف hermes gateway ensure [--json] [--timeout 60] بيئة تشغيل الجلسات للـ profile النشط أو يبدؤها، ويطبع كائن JSON واحدًا (state و reason_code و endpoint لا يظهر إلا بعد أن يُبلغ الاكتشاف المصادَق عن جاهزية متوافقة؛ ولا تظهر التذاكر أو بيانات الاعتماد أبدًا). وينتظر مالكًا موجودًا أو قيد البدء بدلًا من استبداله، ولا يثبّت خدمة أبدًا. ويعني الخروج بالرمز 0 أن كل شيء جاهز؛ وأي رمز آخر هو رفض أو انتهاء مهلة، ولا يعني أبدًا إذنًا ببدء بديل. أما فحوصات هوية الخدمة، وسياسة صلاحيات home التي تقف خلف unsafe_control_permissions، وكل رموز الخروج: البنية الداخلية للـ gateway: hermes gateway ensure.

      hermes send​

      hermes send --to <target> "message text"
      hermes send --to <target> --file <path>
      echo "message" | hermes send --to <target>
      hermes send --list [platform]

      إرسال رسالة لمرة واحدة إلى منصة مراسلة مُعدَّة دون تشغيل وكيل أو حلقة gateway. يعيد استخدام بيانات اعتماد gateway المُعدَّة مسبقًا (~/.hermes/.env + ~/.hermes/config.yaml) بحيث يمكن لسكربتات العمليات ومهام cron وhooks CI وdaemons المراقبة نشر تحديثات الحالة دون إعادة تنفيذ عميل REST الخاص بكل منصة.

      بالنسبة للمنصات ذات رمز البوت (Telegram وDiscord وSlack وSignal وSMS وWhatsApp-CloudAPI)، لا يلزم تشغيل gateway — يتحدث hermes send مباشرة إلى endpoint REST الخاص بالمنصة. أما منصات الإضافات التي تحتاج محوّلًا دائمًا فلا تزال تتطلب gateway حيًا.

      الخيارالوصف
      -t، --to <TARGET>هدف التسليم. الصيغ: platform (يستخدم القناة الرئيسية)، platform:chat_id، platform:chat_id:thread_id، أو platform:#channel-name. أمثلة: telegram، telegram:-1001234567890، discord:#ops، slack:C0123ABCD، signal:+15551234567.
      -f، --file <PATH>قراءة نص الرسالة من PATH (ملفات نصية فقط — سجلات وتقارير وmarkdown). مرّر - لإجبار القراءة من stdin. لإرسال صورة أو ملف ثنائي آخر، استخدم MEDIA:<path> (انظر أدناه).
      -s، --subject <LINE>إضافة سطر موضوع/عنوان قبل نص الرسالة.
      -l، --list [platform]عرض الأهداف المُعدَّة عبر كل المنصات (أو منصة معيّنة فقط).
      -q، --quietإخفاء stdout عند النجاح — مفيد في السكربتات (الاعتماد على رمز الخروج فقط).
      --jsonإصدار نتيجة JSON خام بدلًا من مخرجات مقروءة للبشر.

      إذا لم يُعطَ معامل message موضعي ولا --file، يقرأ hermes send من stdin عندما لا يكون TTY. رموز الخروج: 0 عند النجاح، 1 عند فشل التسليم/الـ backend، 2 عند أخطاء الاستخدام.

      إرسال الصور والوسائط الأخرى​

      --file مخصص لأجسام نصية فقط. لتسليم صورة أو مستند أو فيديو أو ملف صوتي كمرفق أصلي للمنصة، أشر إليه داخل نص الرسالة بتوجيه MEDIA:<local_path>:

      hermes send --to telegram "MEDIA:~/.hermes/cache/scratch/screenshot.png"
      hermes send --to telegram "Build chart for today MEDIA:~/.hermes/cache/scratch/chart.png"   # with caption
      hermes send --to discord:#ops "MEDIA:~/.hermes/cache/scratch/report.pdf"

      افتراضيًا، تُرسَل ملفات الصور كصور (تعيد منصات مثل Telegram ضغطها). أضف [[as_document]] إلى الرسالة لتسليمها كمرفقات ملفات غير مضغوطة بدلًا من ذلك:

      hermes send --to telegram "[[as_document]] MEDIA:~/.hermes/cache/scratch/screenshot.png"

      أمثلة:

      hermes send --to telegram "deploy finished"
      echo "RAM 92%" | hermes send --to telegram:-1001234567890
      hermes send --to discord:#ops --file ~/.hermes/cache/scratch/report.md
      hermes send --to slack:#eng --subject "[CI]" --file build.log
      hermes send --list                  # all platforms
      hermes send --list telegram         # filter by platform

      hermes peer​

      hermes peer add <name> --url http://host:port --key <API_SERVER_KEY>
      hermes peer list
      hermes peer dm <peer>[/<agent>] "message"
      hermes peer run <peer>[/<agent>] --idempotency-key <key> "message"
      hermes peer status <peer>[/<agent>] <run_id>
      hermes peer stop <peer>[/<agent>] <run_id>
      hermes peer remove <name>

      رسائل bot-إلى-bot مباشرة عبر الأجهزة. سجّل gateway آخر لـHermes (على أي جهاز يشغّل منصة api_server) كـنظير (peer)، ثم راسل وكلاءه: يحلّ hermes peer dm جلسة Bot Chat الأساسية للوكيل البعيد عبر خادم API الخاص بالنظير، ويشغّل دورًا واحدًا للوكيل هناك، ويطبع الرد على stdout — التوأم عبر الأجهزة لأمر مراسلة البوت المحلي hermes -p <bot> chat --in ~ -c "Bot Chat" ….

      <peer> وحدها تستهدف الوكيل الرئيسي لـgateway النظير؛ <peer>/<agent> تستهدف profile مسمًّى على نظير متعدد الإرسال (موجَّه عبر مرآته /p/<profile>/).

      الأمر الفرعيالوصف
      add <name> --url <URL> [--key <KEY>] [--note TEXT]تسجيل أو تحديث نظير. يذهب الرابط إلى config.yaml (bot_peers)؛ يُخزَّن المفتاح كـHERMES_PEER_<NAME>_KEY في ~/.hermes/.env.
      listعرض النظراء وما إذا كان كل منهم لديه مفتاح مُعدّ.
      dm <peer>[/<agent>] [message]مراسلة Bot Chat الأساسية لوكيل النظير وطباعة الرد (--json لمخرجات قابلة للقراءة آليًا؛ تعود الرسالة إلى stdin إن لم تُعطَ).
      run <peer>[/<agent>] [message]بدء دور Bot Chat أساسي طويل بشكل غير متزامن وإعادة run_id ومعرّف الجلسة ومفتاح idempotency (يدعم --json). أعد استخدام --idempotency-key عند إعادة محاولة نفس الطلب.
      status <peer>[/<agent>] <run_id>استطلاع تشغيل نظير غير متزامن وطباعة مخرجاته النهائية عند الاكتمال (يدعم --json).
      stop <peer>[/<agent>] <run_id>إيقاف تشغيل النظير غير المتزامن المحدَّد بدقة دون استهداف دور آخر (يدعم --json).
      remove <name>إزالة نظير من السجل (يبقى إدخال مفتاح .env كما هو).

      عند تسجيل نظير واحد على الأقل، يتضمن بروتوكول مراسلة Bot Mode (agent.bot_mode_protocol) الذي يُلقَّن لكل Bot Chat أساسية تلقائيًا قائمة النظراء ونمط hermes peer dm، بحيث تكتشف الوكلاء زملاء عبر الأجهزة دون تعديلات SOUL. راجع Bot Mode.

      رموز الخروج: 0 عند النجاح، 1 عند فشل التسليم/النظير، 2 عند أخطاء الاستخدام.

      تنبيه

      hermes auth​

      إدارة مجمّعات بيانات الاعتماد لتناوب المفاتيح ضمن المزوّد نفسه. راجع مجمّعات بيانات الاعتماد (Credential Pools) للتوثيق الكامل.

      hermes auth                                              # Interactive wizard
      hermes auth list                                         # Show all pools
      hermes auth list openrouter                              # Show specific provider
      hermes auth add openrouter --api-key sk-or-v1-xxx        # Add API key
      hermes auth add openrouter --type oauth                  # Browser login (OpenRouter PKCE) mints a key for you
      hermes auth add anthropic --type oauth                   # Add OAuth credential
      hermes auth add openai-codex --type oauth --priority 0   # Add an account and try it first
      hermes auth add openai-codex --browser                   # Codex: browser auth-code + PKCE on localhost:1455 instead of device code
      hermes auth remove openrouter 2                          # Remove by index
      hermes auth priority openrouter backup-key 0             # Move a credential to the front of fill_first order
      hermes auth reset openrouter                             # Clear cooldowns
      hermes auth reset openrouter 2                           # Clear the cooldown on one credential
      hermes auth refresh openai-codex work                    # Refresh one OAuth credential and clear its cooldown
      hermes auth status anthropic                             # Show auth status for a provider
      hermes auth logout anthropic                             # Log out and clear stored auth state

      الأوامر الفرعية: add، list، remove، reset، priority، refresh، status، logout. انتقل تسجيل دخول Spotify إلى spotify لإضافة الكتالوج hermes spotify login. عند الاستدعاء دون أمر فرعي، يُطلَق معالج الإدارة التفاعلي.

      كتلة حدود الحساب من slash command /usage — نوافذ Codex ذات 5 ساعات / الأسبوعية، ومواعيد إعادة ضبط الخطة والأرصدة المدَّخرة؛ ونوافذ Anthropic OAuth؛ وأرصدة OpenRouter — دون بدء جلسة، كي تستطيع سكربتات shell ومهام cron قراءتها.

      hermes usage                          # configured model provider, human-readable block
      hermes usage --provider openai-codex  # a specific provider
      hermes usage --json                   # one JSON document on stdout
      الخيارالوصف
      --provider NAMEالمزوّد المراد الاستعلام عنه (الافتراضي: model.provider المضبوط). المدعوم: openai-codex، anthropic، openrouter.
      --jsonطباعة مستند JSON واحد بدلًا من الكتلة المقروءة للبشر.

      تُحسم بيانات الاعتماد تمامًا كما تُحسم لـ /usage في جلسة دون وكيل حي (مخزن المصادقة، ثم مجمّع بيانات الاعتماد)؛ ولا يضيف الأمر ولا يجدّد بيانات اعتماد لن يستخدمها للمحادثة. رمز الخروج 0 عند النجاح؛ و 1 مع سطر stderr واحد عندما لا تكون للمزوّد بيانات اعتماد مضبوطة، أو لا يملك endpoint للاستخدام، أو يفشل الجلب (يبقى stdout فارغًا).

      --json مخطط (المفاتيح ثابتة؛ وقد تُضاف مفاتيح جديدة):

      {

        "source": "usage_api",

        "plan": "Plus",
        "fetched_at": "2026-09-19T07:58:55+00:00",
        "windows": [
          {"label": "Session", "used_percent": 37.0, "resets_at": "2026-09-19T21:00:00+00:00", "detail": null},
          {"label": "Weekly", "used_percent": 12.5, "resets_at": "2026-09-25T09:00:00+00:00", "detail": null}

      used_percent تكون null عندما لا يُبلغ المزوّد عن النافذة؛ و resets_at تكون ISO-8601 UTC أو null (تحمل بعض النوافذ detail بنص حر بدلًا منها)؛ و plan تكون null عندما لا تُعرف.

      hermes cron​

      hermes cron <list|create|edit|pause|resume|run|remove|status|runs|incidents|doctor|tick>
      الأمر الفرعيالوصف
      listعرض المهام المجدولة.
      create / addإنشاء مهمة مجدولة من نص prompt، مع إمكانية إرفاق مهارة واحدة أو أكثر عبر تكرار --skill. يدعم تثبيت مستوى تفكير لكل مهمة عبر --reasoning-effort <none|minimal|low|medium|high|xhigh|max|ultra>.
      editتحديث جدول مهمة أو نص الـ prompt الخاص بها أو اسمها أو طريقة التسليم أو عدد التكرارات أو المهارات المرفقة. يدعم --clear-skills و--add-skill و--remove-skill، إضافةً إلى --reasoning-effort (تمرير سلسلة فارغة يزيل التثبيت).
      pauseإيقاف مهمة مؤقتًا دون حذفها.
      resumeاستئناف مهمة متوقفة مؤقتًا. يظل الموعد المتكرر الذي استحق أثناء التوقف مستحقًا (تشغيل تعويضي واحد أو تخطٍّ مسجّل في التكة التالية)؛ وإلا يُحسب موعد التشغيل المستقبلي التالي.
      runتشغيل مهمة عند دورة الجدولة القادمة.
      removeحذف مهمة مجدولة.
      statusالتحقق من تشغيل مجدول Cron.
      doctorفحص صحة الأسطول للقراءة فقط: التشغيلات الفاشلة، عمليات التسليم الفاشلة، قيمة next_run_at المتأخرة أو المفقودة، السكربتات أو مجلدات العمل المفقودة. يخرج برمز غير صفري عند وجود مشكلات.
      tickتشغيل المهام المستحقة مرة واحدة ثم الخروج.

      المشغّل (trigger) لـ cron قابل للتوصيل عبر مفتاح الإعدادات cron.provider. الفارغ (الافتراضي) يستخدم المؤقت المدمج الذي يعمل داخل العملية نفسها. اضبطه على chronos (المزوّد المُدار من NAS للـ gateways المستضافة بنمط scale-to-zero) — يُعدّ عبر مفاتيح cron.chronos.* (portal_url وcallback_url وexpected_audience و nas_jwks_url) — أو حدّد مزوّدًا مخصصًا تحت plugins/cron/<name>/ أو $HERMES_HOME/plugins/<name>/. أي مزوّد غير معروف أو غير متاح يرجع إلى المزوّد المدمج، بحيث لا يبقى cron بلا مشغّل أبدًا. راجع مستند آلية عمل Cron من الداخل.

      hermes kanban​

      hermes kanban [--board <slug>] <action> [options]

      لوحة تعاون متعددة الـ profiles ومتعددة المشاريع. يمكن لكل تثبيت استضافة عدة لوحات (واحدة لكل مشروع أو مستودع أو نطاق)؛ كل لوحة هي قائمة انتظار مستقلة لها قاعدة بيانات SQLite ونطاق موزّع (dispatcher) خاصين بها. تبدأ التثبيتات الجديدة بلوحة واحدة تُسمى default، وقاعدة بياناتها هي ~/.hermes/kanban.db للتوافق الخلفي؛ أما اللوحات الإضافية فتوجد في ~/.hermes/kanban/boards/<slug>/kanban.db. يفحص الموزّع (dispatcher) المدمج في الـ gateway كل لوحة في كل دورة.

      خيارات عامة (تنطبق على كل إجراء أدناه):

      الخيارالغرض
      --board <slug>العمل على لوحة محددة. الافتراضي هو اللوحة الحالية (تُضبط عبر hermes kanban boards switch، أو متغير البيئة HERMES_KANBAN_BOARD، أو default).

      هذه هي الواجهة المخصصة للبشر / السكربتة. عمّال الوكيل (agent workers) الذين يُنشئهم الموزّع يتعاملون مع اللوحة عبر kanban_* toolset مخصص (kanban_show وkanban_complete وkanban_request_review وkanban_request_changes وkanban_block وkanban_create وkanban_link وkanban_comment وkanban_heartbeat؛ وتحصل profiles المنسّق أيضًا على kanban_list وkanban_unblock) بدلًا من استدعاء hermes kanban عبر الـ shell. العمّال يملكون HERMES_KANBAN_BOARD مثبّتًا في بيئتهم بحيث لا يمكنهم فعليًا رؤية لوحات أخرى.

      الإجراءالغرض
      initإنشاء kanban.db إن لم تكن موجودة. لا يُحدث تأثيرًا إضافيًا عند التكرار (idempotent).
      boards list / boards lsسرد كل اللوحات مع عدد المهام. --json، --all (شمول اللوحات المؤرشفة).
      boards create <slug>إنشاء لوحة جديدة. الخيارات: --name، --description، --icon، --color، --switch (جعلها النشطة). الـ slug بصيغة kebab-case، ويُحوَّل تلقائيًا لحروف صغيرة.
      boards switch <slug> / boards useحفظ <slug> كاللوحة النشطة (يكتب في ~/.hermes/kanban/current).
      boards show / boards currentطباعة اسم اللوحة النشطة حاليًا ومسار قاعدة بياناتها وعدد مهامها.
      boards rename <slug> "<name>"تغيير الاسم المعروض للوحة. الـ slug ثابت لا يتغير.
      boards rm <slug>أرشفة اللوحة (الافتراضي) أو حذفها نهائيًا. --delete يتخطى خطوة الأرشفة. اللوحات المؤرشفة تنتقل إلى boards/_archived/<slug>-<ts>/. يُرفض للوحة default.
      create "<title>"إنشاء مهمة جديدة على اللوحة النشطة. الخيارات: --body، --assignee، --parent (قابل للتكرار)، --workspace scratch|worktree|dir:<path>، --tenant، --priority، --triage، --idempotency-key، --max-runtime، --max-retries، --skill (قابل للتكرار).
      list / lsسرد مهام اللوحة النشطة. تصفية بواسطة --mine، --assignee، --status، --tenant، --archived، --json.
      show <id>عرض مهمة مع تعليقاتها وأحداثها. --json لمخرجات قابلة للمعالجة آليًا.
      assign <id> <profile>تعيين أو إعادة تعيين المهمة. استخدم none لإلغاء التعيين. يُرفض أثناء تشغيل المهمة.
      link <parent> <child>إضافة اعتمادية. يُكتشف التسلسل الدائري (cycle). يجب أن تكون المهمتان على نفس اللوحة.
      unlink <parent> <child>إزالة اعتمادية.
      claim <id>حجز مهمة جاهزة بشكل ذري. يطبع مسار مساحة العمل المُحلَّل.
      comment <id> "<text>"إضافة تعليق. العامل التالي الذي يحجز المهمة يقرأه كجزء من استجابة kanban_show() الخاصة به.
      complete <id>وضع علامة أن المهمة منجزة. الخيارات: --result، --summary، --metadata.
      block <id> "<reason>"وضع علامة أن المهمة معلّقة بانتظار تدخل بشري. كما يضيف السبب كتعليق.
      request-review <id>نقل مهمة إلى review مع تسليم إلى مراجِع — وهذا ليس تعليقًا (block). الخيارات: --summary، --metadata، --reviewer (يعيد التعيين قبل إرسال المراجعة).
      request-changes <id> <reason>قرار المراجِع لتشغيل مراجعة نشط: إغلاق محاولة المراجعة وإعادة توجيه المهمة إلى منفّذها الأصلي.
      reopen-review <id>...إعادة مهمة (أو أكثر) قيد المراجعة لإجراء تعديلات (review → ready/todo). الخيار: --reason (يُضاف كتعليق).
      schedule <id> "<reason>"إيقاف عمل مؤجّل/متابعة في حالة scheduled بحيث لا يظهر كعائق بشري.
      unblock <id>استعادة مهمة معلّقة إلى مرحلتها المصدر (review أو ready)، أو إلى todo إن بقيت الاعتماديات مفتوحة.
      archive <id>إخفاء المهمة من القائمة الافتراضية. الأمر gc سيزيل مساحات العمل المؤقتة.
      tail <id>متابعة تدفق أحداث مهمة.
      dispatchتمريرة موزّع واحدة على اللوحة النشطة. الخيارات: --dry-run، --max N، --failure-limit N، --json.
      context <id>طباعة السياق الكامل الذي سيراه العامل (العنوان + المتن + نتائج المهام الأصل + التعليقات).
      specify <id> / specify --allتحويل مهمة في عمود الفرز (triage) إلى مواصفة محددة (عنوان + متن يتضمن الهدف والنهج ومعايير القبول) عبر الـ LLM المساعد، ثم ترقيتها إلى todo. الخيارات: --tenant (تحديد نطاق --all إلى tenant واحد)، --author، --json. يُضبط النموذج تحت auxiliary.triage_specifier في config.yaml.
      decompose <id> / decompose --allتفريع مهمة في عمود الفرز إلى شجرة من المهام الفرعية الموجَّهة إلى profiles متخصصة حسب الوصف. يرجع إلى ترقية مهمة واحدة بأسلوب specify عندما يقرر الـ LLM أن المهمة لا تستفيد من التفريع. نفس خيارات specify. يُضبط نموذج التفكيك تحت auxiliary.kanban_decomposer في config.yaml؛ أما kanban.orchestrator_profile فيتحكم فقط في من يملك مهمة الجذر/التنسيق بعد التفريع. يعمل أيضًا تلقائيًا في كل دورة موزّع عندما تكون kanban.auto_decompose: true (الافتراضي). راجع التنسيق التلقائي مقابل اليدوي.
      gcإزالة مساحات العمل المؤقتة للمهام المؤرشفة.

      أمثلة:

      # Create a second board and put a task on it without switching away.
      hermes kanban boards create atm10-server --name "ATM10 Server" --icon 🎮
      hermes kanban --board atm10-server create "Restart server" --assignee ops

      # Switch the active board for subsequent calls.
      hermes kanban boards switch atm10-server
      hermes kanban list                  # shows atm10-server tasks

      # Archive a board (recoverable) or hard-delete it.
      hermes kanban boards rm atm10-server
      hermes kanban boards rm atm10-server --delete

      ترتيب تحديد اللوحة (الأولوية الأعلى أولًا): خيار --board <slug> → متغير البيئة HERMES_KANBAN_BOARD → الملف ~/.hermes/kanban/current → default.

      كل الإجراءات متاحة أيضًا كأمر slash في الـ gateway (/kanban …)، بنفس مساحة المعطيات — بما في ذلك الأوامر الفرعية لـ boards والخيار --board.

      للتصميم الكامل — المقارنة مع Cline Kanban / Paperclip / NanoClaw / Gemini Enterprise، وثمانية أنماط للتعاون، وأربع قصص مستخدمين، وبرهان صحة التزامن — راجع دليل مستخدم Kanban.

      hermes egress​

      جدار حماية لحقن بيانات الاعتماد الصادرة لصناديق العزل (sandboxes) الطرفية البعيدة. يُغلّف عفريت iron-proxy — وهو وكيل (proxy) يعترض TLS ويستبدل tokens وكيل مبهمة ببيانات اعتماد API الحقيقية عند حدود الشبكة، بحيث لا تحمل صناديق العزل مفاتيح حقيقية أبدًا. معطّل افتراضيًا؛ راجع صفحة Egress proxy الكاملة للإعداد والبنية.

      hermes egress install                  # download the pinned iron-proxy binary
      hermes egress install --force          # check and repair the managed copy

      hermes egress setup                    # interactive wizard: CA, mappings, config
      hermes egress setup --tunnel-port N    # override the tunnel listener port (default 9090)
      hermes egress setup --from-bitwarden   # use Bitwarden Secrets Manager as credential source
      hermes egress setup --no-bitwarden     # explicitly switch back to env-based credentials
      hermes egress setup --rotate-tokens    # mint fresh proxy tokens (default preserves existing)

      hermes egress start                    # spawn the managed proxy daemon
      hermes egress stop                     # SIGTERM (then SIGKILL after 5s grace)
      hermes egress restart                  # stop (if running) then start — needed for secret changes
      hermes egress reload                   # hot-reload the ruleset in-place (no restart, no dropped
                                             #   connections) via the loopback management API

      hermes egress status                   # binary + config + pid + listening + mappings
      hermes egress status --show-tokens     # print proxy tokens in full (default: redacted)

      hermes egress disable                  # flip proxy.enabled = false (does not stop a running proxy)
      hermes egress config                   # print the path to proxy.yaml for inspection

      التدفقات الشائعة​

      # First-time setup
      export OPENROUTER_API_KEY=…
      hermes egress setup && hermes egress start
      hermes config set terminal.backend docker   # if not already

      # Switching credential source after the fact
      hermes egress setup --from-bitwarden       # env → bitwarden
      hermes egress setup --no-bitwarden         # bitwarden → env
      # (just `setup` without either flag preserves the existing mode)

      # Rotating all tokens (e.g. after a suspected token leak)
      hermes egress setup --rotate-tokens    # setup offers to restart the running daemon for you
      # (running sandboxes still hold old tokens; restart them too)

      # Adding a new upstream
      # Edit ~/.hermes/config.yaml proxy.extra_allowed_hosts: [api.example.com]
      hermes egress setup
      hermes egress restart                  # one-command apply (stop + start)

      اختصارات التشخيص​

      hermes egress status                     # current state in one view
      cat ~/.hermes/proxy/proxy.yaml           # the rendered iron-proxy config
      tail -20 ~/.hermes/proxy/iron-proxy.log  # daemon-level diagnostics
      tail -f ~/.hermes/proxy/iron-proxy.log | jq  # daemon + per-request log (line-delimited JSON; v0.39 combines both streams)

      أوضاع الفشل الشائعة وسبل الاسترجاع مذكورة في Egress proxy → استكشاف الأخطاء وإصلاحها.

      hermes webhook​

      hermes webhook <subscribe|list|remove|test>

      إدارة اشتراكات webhook الديناميكية لتفعيل الوكيل القائم على الأحداث. يتطلب تفعيل منصة webhook في الإعدادات — إن لم تكن مضبوطة، يطبع تعليمات الإعداد.

      الأمر الفرعيالوصف
      subscribe / addإنشاء مسار webhook. يعيد الرابط وسر HMAC لضبطهما في خدمتك.
      list / lsعرض كل الاشتراكات التي أنشأها الوكيل.
      remove / rmحذف اشتراك ديناميكي. لا يؤثر على المسارات الثابتة من config.yaml.
      testإرسال طلب POST تجريبي للتحقق من عمل الاشتراك.

      hermes webhook subscribe​

      hermes webhook subscribe <name> [options]
      الخيارالوصف
      --promptقالب prompt مع مراجع الحمولة بصيغة {dot.notation}.
      --eventsأنواع الأحداث المقبولة مفصولة بفواصل (مثل issues,pull_request). فارغ = الكل.
      --descriptionوصف مقروء للبشر.
      --skillsأسماء المهارات المفصولة بفواصل التي تُحمَّل لتشغيل الوكيل.
      --deliverوجهة التسليم: log (الافتراضي)، telegram، discord، slack، github_comment.
      --deliver-chat-idمعرّف المحادثة/القناة الهدف للتسليم عبر المنصات.
      --secretسر HMAC مخصص. يُنشأ تلقائيًا إن حُذف.
      --deliver-onlyتخطي الوكيل — تسليم الـ --prompt المُصاغ كرسالة حرفية. بلا تكلفة LLM، وتسليم دون الثانية. يتطلب أن يكون --deliver وجهة حقيقية (وليس log).
      --mirror-to-sessionاكتب أيضًا كل رسالة مُسلّمة في جلسة المحادثة المستهدفة، لكي يكون للرد عليها في تلك المحادثة سياق. معطّل افتراضيًا؛ فعّله فقط للمصادر التي تثق بمحتواها ضمن محادثتك.
      --scriptسكربت تصفية/تحويل تحت ~/.hermes/scripts/. تُمرَّر حمولة webhook كـ JSON عبر stdin؛ ويحل مخرج JSON من stdout محل الحمولة، وتُتجاهل webhook عند stdout فارغ أو [SILENT] أو رمز خروج غير صفري. راجع سكربتات التصفية والتحويل.
      --route-profileاربط المسار بـ profile ضمن gateway متعدد profiles: عندئذ لا يمكن الوصول إليه إلا عبر /p/<profile>/webhooks/<name>، ويعمل الوكيل باسم ذلك profile. يُتحقّق منه بمقارنته بالـ profiles الموجودة، ويُحتفظ به عند التحديث إذا أُغفل. ليس هو الخيار العام -p/--profile، الذي يختار gateway الذي يُكتب ملف اشتراكاته. راجع Gateways متعددة profiles.

      تُحفظ الاشتراكات في ~/.hermes/webhook_subscriptions.json، ويعيد محوّل webhook تحميلها أثناء التشغيل دون إعادة تشغيل gateway. تحتفظ إعادة تنفيذ subscribe لاسم موجود بسرّه وربطه بالـ profile ما لم تمرّر --secret / --route-profile.

      hermes doctor​

      hermes doctor [--fix]
      الخيارالوصف
      --fixمحاولة إصلاحات تلقائية حيثما أمكن.

      حالة الخروج: 0 عندما لا يورد التقرير أي مشاكل غير محلولة، و 1 عندما تبقى مشكلة واحدة على الأقل (بما فيها المشاكل التي تعذّر على --fix إصلاحها)، لكي تعتمد بوابة فحص السلامة أو خطوة CI على hermes doctor كفحص.

      يتضمن قسم API Connectivity فحصًا لـ IPv6 route: يفتح اتصال TCP قصيرًا واحدًا عبر IPv6 (لمدة 2 s) بمضيف معروف يدعم IPv4 و IPv6. يُبلّغ عن المسار المُعلن الذي لا يؤدي إلا إلى انتهاء المهلة (بادئة IPv6 تُسقط حركة البيانات) كتحذير يذكر الحل، network.force_ipv4: true. يُعدّ عدم وجود مسار IPv6 أصلًا حالة سليمة ويُبلّغ عنه بالحالة OK؛ ويُتجاوز الفحص إذا كان force_ipv4 مضبوطًا بالفعل.

      فحوص إعدادات endpoints المخصّصة (كلاهما تحذيري فقط؛ لا يعيد --fix كتابتهما):

      • custom_providers الذي لا يكون قائمة YAML (مثل سلسلة نصية تركها تنفيذ خاطئ للأمر config set) كخطأ يذكر المفتاح والنوع المستلَم — يتجاهل وقت التشغيل جميع endpoints المخصّصة حتى يعود إلى كونه قائمة.
      • يُبلّغ عن إدخال قديم في قائمة custom_providers لا يقابله إدخال في providers: (بنفس URL للـ endpoint)، مع بيان النقل المطلوب: لا يزال ذلك الإدخال يُقدّم من مخزن القائمة المتقاعد (يقرأه منتقي النماذج وصفحة Custom Endpoints إلى جانب المخزن الجديد) بدلًا من خريطة providers: التي تعدّلها جميع الواجهات الأخرى، ولا يُعاد تشغيل ترحيل v12 الذي نُفّذ مرة واحدة لنقل القائمة إلى providers:.

      Config Structure يشير أيضًا إلى أي إعداد قائمة/خريطة مخزّن كسلسلة نصية واحدة بين علامات اقتباس (plugins.enabled: '["a","b"]', model_catalog.excluded_providers: '["openai-api"]' — البنية التي كتبتها إصدارات config set القديمة): يتجاهل كل قارئ هذه السلسلة، لذا تبقى الإضافات غير مركّبة بصمت ولا يُطبّق الاستبعاد أبدًا. تذكر النتيجة المفتاح وأمر hermes config set <key> '<literal>' الذي يخزّن قائمة فعلية؛ ويظهر التحذير نفسه في شعار بدء التشغيل. لا يعيد --fix كتابة الملف.

      hermes backup​

      hermes backup [options]

      إنشاء أرشيف zip لإعدادات Hermes ومهاراتك وجلساتك وبياناتك. يستبعد النسخ الاحتياطي كود hermes-agent نفسه، ولا يُضمِّن عناصر نسخ احتياطي سابقة (backups/، state-snapshots/) — كل منها يحتوي بالفعل على نسخته الخاصة من state.db.

      الخيارالوصف
      -o، --output <path>مسار الإخراج لملف zip (الافتراضي: ~/hermes-backup-<timestamp>.zip).
      -q، --quickلقطة سريعة: ملفات الحالة الحرجة فقط (config.yaml، state.db، .env، auth، مهام cron). أسرع بكثير من النسخ الاحتياطي الكامل.
      -l، --label <name>تسمية اللقطة (تُستخدم فقط مع --quick).
      -k، --keep <N>بعد نسخ احتياطي كامل، حذف ملفات hermes-backup-*.zip الأقدم في مجلد الإخراج بعد أحدث N ملفات (الافتراضي 3؛ 0 يحتفظ بالجميع). ملفات zip ذات الأسماء المخصصة لا تُمس أبدًا.

      يستخدم النسخ الاحتياطي واجهة backup() الخاصة بـ SQLite للنسخ الآمن، لذا يعمل بشكل صحيح حتى أثناء تشغيل Hermes (آمن مع وضع WAL).

      ما المستبعد من ملف zip: 0 فقط عندما يُضمّ كل ملف مختار إلى الأرشيف. إذا تعذّرت إضافة بعض الملفات (Backup incomplete: …)، يُحتفظ بملف zip لكي تظل استعادة بقية الملفات ممكنة، لكن الأمر يخرج بالحالة 1 — لن يُبلّغ مؤقّت cron أو systemd عن أرشيف جزئي باعتباره نجاحًا، ويُتجاوز حذف الأرشيفات وفق --keep لكي تبقى الأرشيفات الكاملة الأقدم. وتعني الحالة 2 أن نسخة احتياطية أخرى كانت قيد التنفيذ بالفعل.

      ما يُستبعد من ملف zip:

      • *.db-wal، *.db-shm، *.db-journal — الملفات المرافقة لـ WAL / الذاكرة المشتركة / السجل الخاصة بـ SQLite. ملف *.db حصل بالفعل على لقطة متسقة عبر sqlite3.backup()؛ وإرفاق الملفات المرافقة الحية معه قد يجعل الاستعادة ترى حالة نصف منفَّذة.
      • checkpoints/ — ذواكر مؤقتة لمسار trajectory لكل جلسة. مُفهرسة بتجزئة (hash) ويُعاد توليدها لكل جلسة؛ لن تنتقل بشكل نظيف إلى تثبيت آخر على أي حال.
      • models/، runtimes/، node/ في جذر ~/.hermes (وفي كل profiles/<name>/) — تنزيلات وقت تشغيل قابلة لإعادة التوليد، غالبًا بعشرات الغيغابايتات. المجلدات الأعمق بنفس الأسماء (مثل models/) يُحتفظ بها.
      • Profiles المتصفح: browser-profile/ (لقطة profile الحقيقي — ملفات Cookies / Login Data المنسوخة)، و browser-profiles/ (profiles CDP النشطة) على أي عمق، و browser_profiles/ (مجلد بيانات مستخدم Chromium الخاص بـ backend Browser Use CLI، وفيه ملفات Login Data / Cookies الخاصة به) في جذر ~/.hermes وكل profiles/<name>/. هذه مخازن بيانات اعتماد يجب ألا تدخل أي أرشيف؛ وتُعاد توليدها جميعًا عند التشغيل التالي.
      • العناصر القابلة لإعادة التوليد ضمن cache/ في نفس تلك الجذور — كتالوجات النماذج/الإضافات، الأختام، ملفات تعريف المتصفح، فائض مخرجات الأدوات. القطع الدائمة تبقى في: cache/images، cache/audio، cache/videos، cache/documents، cache/screenshots (الوسائط المُسلَّمة إليك أو المستلمة منك) وcache/citations (سجل الاستشهادات المرجعية). المجلد cache/ الأعمق (داخل مهارة) يُحفظ كاملًا.
      • مقابس Unix، والأجهزة، والروابط الرمزية — لا يمكن لملف zip حملها؛ قبل استبعادها، كان وجود gateway.sock عرضيًا يجعل كل نسخة احتياطية كاملة تُبلّغ عن Backup incomplete.
      • كود hermes-agent نفسه (هذا نسخ احتياطي لبيانات المستخدم، وليس لقطة للمستودع).

      أمثلة​

      hermes backup                           # Full backup to ~/hermes-backup-*.zip
      hermes backup -o ~/backups/hermes.zip   # Full backup to specific path
      hermes backup --quick                   # Quick state-only snapshot
      hermes backup --quick --label "pre-upgrade"  # Quick snapshot with label

      hermes checkpoints​

      hermes checkpoints [COMMAND]

      فحص وإدارة مخزن shadow git في ~/.hermes/checkpoints/ — طبقة التخزين خلف أمر /rollback داخل الجلسة. آمن للتشغيل في أي وقت؛ لا يتطلب تشغيل الوكيل.

      الأمر الفرعيالوصف
      status (الافتراضي)عرض الحجم الإجمالي وعدد المشاريع والتفصيل لكل مشروع. الأمر المجرد hermes checkpoints يكافئ هذا.
      listاسم بديل لـ status.
      pruneفرض تمريرة تنظيف — حذف المشاريع اليتيمة والقديمة، وتشغيل GC للمخزن، وفرض الحد الأقصى للحجم. يتجاهل علامة عدم التكرار (idempotency) الخاصة بـ 24 ساعة.
      clearحذف قاعدة نقاط الحفظ (checkpoint) بالكامل. لا رجعة فيه؛ يطلب تأكيدًا ما لم تُمرَّر -f.
      clear-legacyحذف أرشيفات legacy-<timestamp>/ فقط التي أنتجها الانتقال v1→v2. ينتهي بالحالة 2 (بعد طباعة Could not delete N archive(s)) إذا تعذّر إزالة أي أرشيف، مثل كائنات git للقراءة فقط على Windows.

      الخيارات​

      الخيارالأمر الفرعيالوصف
      --limit Nstatus، listالحد الأقصى لعدد المشاريع المعروضة (الافتراضي 20).
      --retention-days Npruneإسقاط المشاريع التي مرّ على last_touch الخاص بها أكثر من N يوم (الافتراضي 7).
      --max-size-mb Npruneبعد جولة اليتيمة/القديمة، إسقاط أقدم commit لكل مشروع حتى يصبح حجم المخزن الإجمالي ≤ N MB (الافتراضي 500).
      --keep-orphanspruneتخطي حذف المشاريع التي لم يعد مجلد عملها موجودًا.
      -f، --forceclear، clear-legacyتخطي طلب التأكيد.

      أمثلة​

      hermes checkpoints                                  # status overview
      hermes checkpoints prune --retention-days 3         # aggressive cleanup
      hermes checkpoints prune --max-size-mb 200          # tighten size cap once
      hermes checkpoints clear-legacy -f                  # drop v1 archive dirs
      hermes checkpoints clear -f                         # wipe everything

      راجع نقاط الحفظ وأمر /rollback للاطلاع على البنية الكاملة وأوامر الجلسة.

      hermes import​

      hermes import <zipfile> [options]

      استعادة نسخة احتياطية من Hermes أُنشئت سابقًا إلى مجلد Hermes الرئيسي لديك. كل الملفات في الأرشيف تستبدل الملفات الموجودة في مجلد Hermes الرئيسي؛ --force يتخطى فقط طلب التأكيد الذي يظهر عندما يحتوي الهدف بالفعل على تثبيت Hermes.

      الخيارالوصف
      -f، --forceتخطي طلب تأكيد وجود تثبيت سابق.
      تحذير

      أوقف الـ gateway قبل الاستيراد لتجنب التعارضات مع العمليات قيد التشغيل.

      حالة الخروج: 1 عندما يكون الأرشيف تالفًا — قبل كتابة أي شيء، يُفك ضغط كل عنصر مرة واحدة وتُفحص CRC الخاصة به؛ إذا فشل أي منها، يطبع الأمر Error: backup archive is damaged (N member(s) …) مع العناصر المخالفة ويتوقف دون المساس بمجلد Hermes الرئيسي. وكذلك 1 عندما يتعذّر استعادة أي ملف من الأرشيف (يُسرد ضمن Warnings (N files skipped) ويُلخّص بـ Import incomplete: …). تبقى الملفات التي استُعيدت في مواضعها، لكن لا يُبلغ سكربت أو لوحة التحكم عن استعادة جزئية بوصفها نجاحًا. ملفات التشغيل التي يتعمد الاستيراد إبقاءها من هذا الجهاز (gateway.pid و gateway_state.json وغيرها)، والتحذير من جلسات النسخة الاحتياطية الأقدم أدناه، لا يغيّران حالة الخروج.

      قواعد بيانات SQLite​

      .db (state.db، kanban.db، response_store.db، …) لا تُنشر بإعادة تسمية كما تُنشر الملفات العادية. إعادة التسمية كانت ستستبدل inode الملف بينما لا تزال عملية gateway أو dashboard أو WebUI تحتفظ بالملف القديم مفتوحًا: تلك العملية ستستمر في قراءة صفحات ما قبل الاستيراد وستستمر في كتابة جلسات لا يراها أحد آخر، وستكون تلك الجلسات ببساطة غائبة من قاعدة البيانات التي يفتحها الجميع لاحقًا — دون أي تسجيل. بدلًا من ذلك، تُكتب الصفحات المستوردة داخل ملف قاعدة البيانات الموجود، بنفس الطريقة التي ينفذها /snapshot restore، بحيث يتقارب كل اتصال مفتوح على البيانات المستوردة.

      إذا تعذّر استبدال قاعدة البيانات الحية بأمان — فشل نسخ الصفحات ولا تزال عملية أخرى تحتفظ بالملف مفتوحًا — يترك الاستيراد قاعدة البيانات تلك دون تغيير ويدرجها تحت Warnings (N files skipped). أوقف العمليات المحتفِظة بالملف وأعد التشغيل.

      استيراد نسخة احتياطية أقدم فوق عمل أحدث لا يزال مسموحًا، لكنه لم يعد صامتًا. عندما تحتوي state.db المستوردة على رسائل أقل من التي استبدلتها، يُبلّغ الملخص عن ذلك:

        ⚠ Session data replaced by older backup contents:
          state.db: 12 session(s) / 8912 message(s) -> 3 / 24
          Anything recorded after the backup was taken is not in it.
          Recover from a newer backup or snapshot: hermes snapshot list

      أمثلة​

      hermes import ~/hermes-backup-20260423.zip           # Prompts before overwriting existing config
      hermes import ~/hermes-backup-20260423.zip --force   # Overwrite without prompting

      hermes logs​

      عرض ملفات سجلات Hermes ومتابعتها وتصفيتها. كل السجلات مخزَّنة في ~/.hermes/logs/ (أو <profile>/logs/ للـ profiles غير الافتراضية).

      الخيارات​

      الخيارالوصف
      log_nameأي سجل تريد عرضه: agent (الافتراضي)، errors، gateway، gui، desktop، update، handoff، أو list لعرض الملفات المتاحة مع أحجامها.
      -n، --lines <N>عدد الأسطر المعروضة (الافتراضي: 50).
      -f، --followمتابعة السجل في الوقت الفعلي، مثل tail -f. اضغط Ctrl+C للتوقف.
      --level <LEVEL>الحد الأدنى لمستوى السجل المعروض: DEBUG، INFO، WARNING، ERROR، CRITICAL.
      --session <ID>تصفية الأسطر التي تحتوي على جزء من معرّف جلسة.
      --since <TIME>عرض الأسطر من وقت نسبي ماضٍ: 30m، 1h، 2d، إلخ. يدعم s (ثوانٍ)، m (دقائق)، h (ساعات)، d (أيام).
      --component <NAME>تصفية حسب المكوّن: gateway، agent، tools، cli، cron.

      يُعرض أو يُخفى السطر الذي لا يملك طابعًا زمنيًا خاصًا به، مثل إطار traceback أو بقية رسالة متعددة الأسطر، مع السطر ذي الطابع الزمني فوقه.

      أمثلة​

      # View the last 50 lines of agent.log (default)
      hermes logs

      # Follow agent.log in real time
      hermes logs -f

      # View the last 100 lines of gateway.log
      hermes logs gateway -n 100

      # Show only warnings and errors from the last hour
      hermes logs --level WARNING --since 1h

      # Filter by a specific session
      hermes logs --session abc123

      # Follow errors.log, starting from 30 minutes ago
      hermes logs errors --since 30m -f

      # List all log files with their sizes
      hermes logs list

      التصفية​

      يمكن الجمع بين المرشِّحات. عند تفعيل عدة مرشِّحات، يجب أن يجتاز سطر السجل كلها ليُعرض:

      # WARNING+ lines from the last 2 hours containing session "tg-12345"
      hermes logs --level WARNING --since 2h --session tg-12345

      تُضمَّن الأسطر التي لا تحتوي على طابع زمني قابل للتحليل عندما يكون --since مفعّلًا (قد تكون أسطر استمرار لقيد سجل متعدد الأسطر). تُضمَّن الأسطر التي لا يمكن اكتشاف مستوى لها عندما يكون --level مفعّلًا.

      تدوير السجلات​

      يستخدم Hermes RotatingFileHandler الخاص بـ Python. تُدوَّر السجلات القديمة تلقائيًا — ابحث عن agent.log.1، agent.log.2، إلخ. يعرض الأمر الفرعي hermes logs list كل ملفات السجل بما فيها المُدوَّرة.

      hermes prompt-size​

      hermes prompt-size [--platform <name>] [--json]

      يُبلّغ عن ميزانية الـ prompt الثابتة لجلسة جديدة — ما يُرسل في كل استدعاء API قبل أي محتوى محادثة. مفيد عندما يكون لدى محوّل أو وكيل (proxy) لاحق ميزانية prompt أضيق من نافذة سياق النموذج، أو عندما تريد معرفة أي كتلة (فهرس المهارات، الذاكرة، الـ profile) تهيمن.

      يبني نفس system prompt الذي سيبنيه الوكيل، ثم يحلّله إلى:

      • إجمالي الـ system prompt — الـ prompt الكامل المجمَّع (الهوية، التوجيه، فهرس المهارات، ملفات السياق، الذاكرة، الـ profile، الطابع الزمني).
      • فهرس المهارات — كتلة <available_skills>. غالبًا ما تكون هذه أكبر كتلة منفردة عند تثبيت عدد كبير من المهارات.
      • الذاكرة وملف المستخدم — لقطات MEMORY.md / USER.md الخاصة بك.
      • مستويات الـ prompt — ثابت / سياق / متقلّب، بما يطابق طريقة تنظيم Hermes للـ prompt لتحقيق ملاءمة التخزين المؤقت.
      • مخططات الأدوات — JSON الخاص بكل الأدوات المفعّلة (النصف الآخر من الحمولة الثابتة لكل استدعاء).

      يعمل بالكامل دون اتصال — بلا استدعاء API، ويعمل دون أي بيانات اعتماد مضبوطة.

      # Human-readable breakdown for the CLI platform (default)
      hermes prompt-size

      # Simulate a messaging platform's prompt (different platform hint)
      hermes prompt-size --platform telegram

      # Machine-readable output for scripts
      hermes prompt-size --json
      نصيحة

      يتوسع فهرس المهارات ومخططات الأدوات بحسب عدد المهارات والأدوات المفعّلة لديك. لتقليص حجم الـ prompt، عطّل الـ toolsets غير المستخدمة (hermes tools) أو أزل المهارات التي لا تحتاجها (hermes skills). ملفات السياق (AGENTS.md، .cursorrules) في مجلدك الحالي تُحتسب أيضًا ضمن الإجمالي.

      hermes config​

      hermes config <subcommand>

      الأوامر الفرعية:

      الأمر الفرعيالوصف
      showعرض قيم الإعدادات الحالية.
      editفتح config.yaml في محررك.
      get <key> [--json] [--raw]طباعة قيمة إعداد واحدة عبر مفتاح منقّط (مثل hermes config get model.default). --json يُصدر مخرجات قابلة للقراءة آليًا. تُخفى القيم الشبيهة ببيانات الاعتماد (api_key و *_TOKEN و *_SECRET و password وغيرها) باستخدام (sk-o...7890) لأن الوكيل ينفّذ هذا من جلسات تُحفظ نصوص محادثاتها؛ يطبع --raw القيمة الحقيقية (أو اضبط security.redact_secrets: false). يظل المفتاح المتداخل تحت قسم معروف وغير المعرّف في المخطط (compression.compressor.enabled) يطبع قيمته من الملف، مع إشعار stderr بأن Hermes قد لا يقرأه؛ ولا يتغير stdout ولا رمز الخروج (0).
      set <key> <value> [--force]ضبط قيمة إعداد. تنتقل المسارات المنقّطة إلى config.yaml؛ ويُعدّ كل اسم UPPER_SNAKE (OPENROUTER_API_KEY و DISCORD_HOME_CHANNEL و TELEGRAM_GROUP_ALLOWED_USERS و HERMES_TIMEZONE وغيرها) متغير بيئة ينتقل إلى .env — الملف نفسه الذي تكتب فيه إجراءات إعداد المنصات و /sethome، والذي تعتمد عليه كل قارئات وقت التشغيل. لا يكتب config set مفتاح UPPER_SNAKE في config.yaml مطلقًا، بما فيه --force؛ وتُرفض الأسماء الموجودة في قائمة حظر كاتب متغيرات البيئة (HERMES_YOLO_MODE و PATH وغيرها) رفضًا كاملًا؛ ويُحفظ أي اسم UPPER_SNAKE آخر في .env كما هو (تقرؤه الإضافات والمهارات والأدوات الخارجية من بيئة العملية). يُرفض المفتاح المعروف المكتوب تحت بادئة خاطئة (gateway.discord.foo، حيث إن discord.foo نفسه مفتاح معروف) مع اقتراح التصحيح ولا يُكتب شيء؛ ويُكتب أي مسار مجهول آخر تحت قسم معروف (agent.max_turnz، أو مفتاح يُقرأ وقت التشغيل وليس له قيمة افتراضية أولية) مع إشعار اقتراح تصحيح، ويُكتب المفتاح المجهول صغير الأحرف على المستوى الأعلى مع إشعار (تُمرَّر القيم المفردة العليا إلى البيئة للمهارات). يكتب --force أيضًا المسار ذي البادئة الخاطئة المرفوض. تُفحص أنواع القيم مقابل المخطط: فالمفتاح الذي يجب أن يحمل قائمة أو خريطة (custom_providers أو model.aliases أو display.platforms أو plugins.enabled/plugins.disabled أو model_catalog.excluded_providers أو أي مفتاح يحمل إحداهما بالفعل) يرفض سلسلة عادية أو قيمة حرفية ذات بنية خاطئة، وتُرفض القيمة التي تبدو كقائمة/خريطة وليست YAML/JSON صالحًا بدلًا من تخزينها كنص — فلا يُكتب شيء ويذكر الخطأ النوع المتوقع. مرّر قيمة YAML/JSON حرفية (hermes config set custom_providers '[{name: x, base_url: https://...}]')؛ ولتخزين نص يبدأ فحسب بـ [ أو {، ضع عليه علامات اقتباس في YAML ("'[text'"). يظل --force يستبدل قسم خريطة كاملًا؛ ولا يوجد تجاوز لقيمة غير قائمة في موضع قائمة، إلا أن اسمًا منفردًا لقائمة أسماء تُقرأ بتسامح (agent.disabled_toolsets و skills.disabled) يُخزّن كقائمة بعنصر واحد.
      unset <key>إزالة مفتاح إعداد، وإعادته إلى القيمة الافتراضية المدمجة. بالنسبة إلى أسماء UPPER_SNAKE، يزيل ذلك مدخل .env ويسقط أيضًا نسخة config.yaml قديمة في المستوى الأعلى تركتها تشغيلات config set الأقدم (يُبلغ get عن مثل هذه النسخة بوصفها قديمة).
      pathطباعة مسار ملف الإعدادات.
      env-pathطباعة مسار ملف .env.
      checkالتحقق من الإعدادات المفقودة أو القديمة.
      migrateإضافة الخيارات المُستحدثة حديثًا بشكل تفاعلي.

      config set model.provider <provider> يُبقي كتلة model: على مسار واحد: تُزال (ويُذكر ذلك) قيمة model.base_url / model.api_mode المتبقية من المزوّد السابق إذا كانت endpoint لمزوّد آخر — وإلا يُرسل مفتاح المزوّد الجديد إلى endpoint القديم ويفشل بخطأ بيانات اعتماد يذكر المزوّد الخطأ. يبقى URL الذي يمثل endpoint للمزوّد الجديد نفسه أو endpoint لمدخل custom_providers مُسمّى أو أي URL ضمن custom/الأسماء البديلة المحلية؛ ويبقى المضيف غير المعروف (proxy أو خادم LAN) مع تحذير بأنه ما زال مطبّقًا.

      النقاط داخل أسماء المفاتيح​

      hermes config set/get/unset يستخدم . كفاصل للتداخل، لكن كثيرًا من أسماء المفاتيح الفعلية تحتوي نقاطًا حرفية — معرّفات النماذج (grok-4.6، glm-5.3-flash)، معرّفات غرف Matrix (!room:example.org)، أسماء مزوّدين ذات إصدارات. قاعدتان تجعلان هذه قابلة للوصول:

      • المفاتيح الموجودة تعمل تلقائيًا. عند التنقل في تعيين موجود، يُفضَّل مفتاح حرفي موجود يطابق البقية المنقّطة على التقسيم. الأمر hermes config set providers.p.models.grok-4.6.supports_vision true يحدّث إدخال grok-4.6 الفعلي (وتحلّل get/unset بنفس الطريقة).
      • إنشاء مفتاح منقّط جديد يتطلب الإفلات (escaping). أفلت النقاط الحرفية بشرطة مائلة عكسية: الأمر hermes config set 'providers.p.models.grok-4\.7.context_length' 128000 ينشئ مفتاح grok-4.7 الحرفي. (ضع المفتاح بين علامتي اقتباس ليحافظ shell على الشرطة المائلة العكسية.)

      إذا كانت كتابة غير مُفلَتة ستنشئ تعيينًا متداخلًا يُظلّل مفتاحًا منقّطًا مجاورًا موجودًا بالفعل (مثل إنشاء grok-4 بجانب grok-4.6 موجود)، يفشل الأمر برسالة خطأ بدلًا من كتابة إدخال وهمي بصمت لن يقرأه وقت التشغيل أبدًا.

      ملاحظات:

      • --force يمكنها تجاوز حجوبات السياسات غير الخطرة للمهارات من جهات خارجية/المجتمع.

      • --source skills-sh يبحث في دليل skills.sh العام.
      • --source well-known يتيح لك توجيه Hermes إلى موقع يعرض /.well-known/skills/index.json.

      • تمرير رابط http(s)://…/*.md يثبّت SKILL.md بالإضافة إلى الملفات المُشار إليها صراحةً تحت references/، templates/، scripts/، assets/، وexamples/. عندما لا تحتوي بيانات frontmatter على name: ولا يكون slug الرابط معرّفًا صالحًا، تطلب طرفية تفاعلية اسمًا؛ أما الواجهات غير التفاعلية (/skills install داخل TUI، منصات الـ gateway) فتتطلب --name <x> بدلًا من ذلك.

      hermes curator​

      hermes plugins​

      hermes plugins [subcommand]

      إدارة موحّدة للإضافات — الإضافات العامة، ومزوّدو الذاكرة، ومحرّكات السياق في مكان واحد. تشغيل hermes plugins بلا أمر فرعي يفتح شاشة تفاعلية مركّبة بقسمين:

      • الإضافات العامة — مربعات اختيار متعددة لتفعيل/تعطيل الإضافات المثبَّتة
      • إضافات المزوّدين — إعداد باختيار واحد لمزوّد الذاكرة ومحرّك السياق. اضغط ENTER على فئة لفتح مُنتقي راديو.
      الأمر الفرعيالوصف
      (بلا أمر)واجهة تفاعلية مركّبة — مفاتيح إضافات عامة + إعداد إضافات مزوّدين.
      install <identifier> [--force] [--ref COMMIT_SHA] [--allow-removed]تثبيت إضافة من كتالوج إضافات Hermes (اسم إدخال مجرد)، أو رابط Git، أو اختصار owner/repo المختصر. تُحوَّل أسماء الكتالوج إلى commit SHA مُراجع مؤلف من 40 خانة hex، وتُظهر الإمكانيات المعلنة. يُسجّل المصدر والإصدار المسحوب وكتلة منشأ كتالوج متداخلة في ملف المُثبّت plugins/.install-metadata.json ؛ ونسخة .hermes-catalog.json داخل مجلد الإضافة للتسهيل فقط، ولا يُوثق بها مطلقًا. تُعلَّم عناوين URL الخام كمصادر مخصصة (غير مُراجَعة). --ref يختار تثبيتًا مخصصًا بواسطة SHA كامل، ويسجّل SHA الذي سُحب فعليًا. --allow-removed (خطير) يتجاوز قائمة حظر الإضافات المُزالة عند التثبيت، ويعفي ذلك التثبيت من فحوص قائمة المنع عند التحديث والتفعيل والتحميل.
      search [term] [--json]البحث في كتالوج إضافات Hermes (يطابق أسماء الإدخالات والأوصاف والأدوات المُعلَنة؛ حذف term يسرد الكل). الكتالوج مُنسَّق داخل المستودع (plugin-catalog/)، ويُحدَّث من المستودع الحي بذاكرة تخزين مؤقت مدتها 6 ساعات، ويرجع إلى النسخة الموجودة في الشجرة عند عدم الاتصال. مُدرَج في الكتالوج ≠ مُدقَّق؛ فالقبول يراجع الإدخال، لا الكود.
      update <name>أعد تثبيت تثبيتات الكتالوج على SHA الكتالوج المُراجع، أو حدّث تثبيت Git مخصصًا من المصدر/feed المسجّل. يتحقق PM من اعتماديات الإضافات النشطة قبل نشر الكود. لا تتحرك التثبيتات المخصصة الصريحة إلا باستخدام install --force --ref <new-commit>.
      update [--yes]دون اسم: يعرض كل إضافة مثبّتة لها تحديث يستطيع update <name> تطبيقه (إعادة تثبيت من الكتالوج أو Git pull) إضافةً إلى ما يتخطاه مع السبب، ثم يسأل Update all N? [Y/n] ويحدّث كل إضافة عبر مسار الإضافة الواحدة (وتظل مطالبات الموافقة لكل إضافة سارية). ولا يوقف فشل واحد بقية التحديثات؛ ويخرج بالرمز 1 إذا فشل أي منها. وبدون طرفية لا يُحدَّث شيء ما لم يُمرَّر --yes؛ ويُبقي --yes الموافقة مغلقة عند الفشل (fail-closed) (فتظل القدرات الجديدة غير ممنوحة).
      remove <name> (أسماء بديلة: rm, uninstall)إزالة إضافة مثبَّتة.
      enable <name>تفعيل إضافة معطَّلة.
      disable <name>تعطيل إضافة دون إزالتها.
      list (اسم بديل: ls)سرد الإضافات المثبَّتة مع حالة التفعيل/التعطيل.
      doctor [path-or-id] [--ci]التحقق من صحة إضافة أصلية عبر محلّل المانفست الفعلي، والمُحمِّل، ومسار التسجيل. --ci يخرج بالرمز 1 عند وجود أخطاء.
      pack install <path-or-url> [--force]تثبيت حزمة إضافات (hermes-pack.yaml) — مجموعة تصريحية من الإضافات كل منها مثبَّت عند commit SHA دقيق من 40 حرفًا. تعرض شاشة مراجعة إلزامية (كل إضافة ومصدرها والمرجع المثبَّت والقدرات المُعلَنة)، وتطلب تأكيدًا واحدًا لمحتويات الحزمة، ثم تنفّذ عمليات تثبيت عادية مثبَّتة الإصدار. كل إضافة تمر قدراتها المُعلَنة عبر الموافقة القياسية لكل إضافة — فالحزمة لا تمنح صلاحيات جماعية أبدًا. تُبلَّغ الإخفاقات الجزئية لكل إضافة؛ ويخرج برمز غير صفري إذا فشلت أي إضافة. تفاعلي فقط (بلا --yes).
      pack export [--enabled-only] [--name NAME]إخراج YAML حزمة على stdout من التثبيت الحالي: المستودع + SHA الدقيق لكل إضافة مثبَّتة عبر git إضافة إلى إعدادات plugins.entries غير السرية المُنقَّاة. الإضافات المحلية فقط (بلا مصدر git) تُدرَج كتعليقات تحذير، لا كإدخالات قابلة للتثبيت. الأسرار ومنح القدرات وبوابات allow_* تُزال دائمًا.
      pack show <path-or-url>تشغيل تجريبي: تحليل والتحقق من صحة وعرض حزمة دون تثبيت أي شيء.

      تُحفَظ اختيارات إضافات المزوّدين في config.yaml:

      • memory.provider — مزوّد الذاكرة النشط (فارغ = المدمج فقط)
      • context.engine — محرّك السياق النشط ("compressor" = الافتراضي المدمج)

      قائمة الإضافات العامة المعطَّلة مخزَّنة في config.yaml تحت plugins.disabled. كذلك تثبيتات git تسجّل فقط مصدرها المرجعي، والمراجعة المثبَّتة الدقيقة، وحالة التثبيت في ملف الـ profile المحلي المرافق plugins/.install-metadata.json. وهو لا يحتوي إعدادات الإضافة، أو قيم البيئة، أو الأسرار، أو منح القدرات.

      راجع الإضافات (Plugins) وبناء إضافة لـ Hermes.

      الأوامر الفرعية:

      الأمر الفرعيالوصف
      installتشغيل مُثبِّت cua-driver الرسمي (macOS و Windows و Linux).
      install --upgradeإعادة تشغيل المُثبِّت حتى لو كان cua-driver موجودًا بالفعل في PATH. السكربت الرسمي يسحب الإصدار الأحدث دائمًا، لذا هذا يمثّل ترقية في مكانها.

      hermes computer-use install هو نقطة الدخول المستقرة لتثبيت ثنائي cua-driver المستخدَم في toolset computer_use. يشغّل نفس المُثبِّت الرسمي الذي يستدعيه hermes tools عند تفعيلك Computer Use لأول مرة، لذا فهو آمن لإعادة تشغيل التثبيت في حال لم يُطلقه تبديل الـ toolset (على سبيل المثال في إعدادات المستخدمين العائدين).

      إذا كان cua-driver موجودًا بالفعل، يتحقق Hermes من إصداره وبيان تشغيله (manifest). تُترَك النسخة 0.20.0 أو الأحدث المتوافقة كما هي. أما التثبيت القديم أو غير المكتمل القياسي فيُصلَح بالمُثبِّت الرسمي الحالي. لا يستبدل Hermes أبدًا ثنائيًا مخصصًا مُحدَّدًا عبر HERMES_CUA_DRIVER_CMD ؛ حدّث ذلك الثنائي مباشرةً أو أزل التجاوز. يبلّغ hermes computer-use status عند الحاجة إلى إصلاح.

      المدمج computer_use المدمج هو التكامل المُوصى به مع Hermes. أما تسجيل أدوات Cua MCP الخام فبديل عندما تحتاج إلى مفردات الأدوات منخفضة المستوى الخاصة بـ Cua. يكتشف cua-driver skills install وجود Hermes ويربط حزمة مهارات Cua بمجلد مهارات Hermes تلقائيًا.

      وضع الأذونات والموافقة على بيان القدرات تنتمي إلى إطلاق وقت التشغيل. في الوضع المقيَّد، يمرّر Hermes علامتَي Cua الرسميتين --capability-manifest و --approve-capability-manifest. كل نقل MCP يملك جلسة دورة حياة خاصة داخل وقت تشغيله. أسماء الجلسات العامة تسمّي حالة المؤشر والجلسة؛ ولا تملك وقت التشغيل أو تشاركه.

      hermes update تشغيل المُثبِّت الرسمي تلقائيًا في نهاية التحديث إذا كان cua-driver موجودًا في PATH، لذا لن يحتاج معظم المستخدمين لاستدعاء --upgrade يدويًا. استخدمه عندما يُصدر upstream إصلاحًا تريده فورًا دون انتظار تحديث Hermes التالي.

      recoverاسترجاع دون اتصال وغير مُخرِّب لـ state.db تالف إلى قاعدة بيانات نظيفة منفصلة.

      hermes claw​

      hermes claw migrate [options]

      الانتقال بإعداد OpenClaw لديك إلى Hermes. يقرأ من ~/.openclaw (أو مسار مخصص) ويكتب إلى ~/.hermes. يكتشف تلقائيًا أسماء المجلدات القديمة (~/.clawdbot، ~/.moltbot) وأسماء ملفات الإعدادات (clawdbot.json، moltbot.json).

      الخيارالوصف
      --dry-runمعاينة ما سيُنقَل دون كتابة أي شيء.
      --preset <name>نمط الانتقال المسبق: full (كل الإعدادات المتوافقة) أو user-data (يستبعد إعدادات البنية التحتية). لا يستورد أي من النمطين الأسرار — مرّر --migrate-secrets صراحةً.
      --overwriteاستبدال ملفات Hermes الموجودة عند التعارض (الافتراضي: رفض التطبيق عندما تحتوي الخطة على تعارضات).
      --migrate-secretsتضمين مفاتيح API في الانتقال. مطلوب حتى مع --preset full.
      --no-backupتخطي لقطة zip قبل الانتقال لـ ~/.hermes/ (افتراضيًا تُكتَب أرشيف نقطة استعادة واحدة إلى ~/.hermes/backups/pre-migration-*.zip قبل التطبيق؛ قابلة للاستعادة عبر hermes import).
      --source <path>مجلد OpenClaw مخصص (الافتراضي: ~/.openclaw).
      --workspace-target <path>المجلد الهدف لتعليمات مساحة العمل (AGENTS.md).
      --skill-conflict <mode>التعامل مع تعارض أسماء المهارات: skip (الافتراضي)، overwrite، أو rename.
      --yesتخطي طلب التأكيد.

      ما الذي يُنقَل​

      يغطي الانتقال أكثر من 30 فئة عبر الشخصية، والذاكرة، والمهارات، ومزوّدي النماذج، ومنصات المراسلة، وسلوك الوكيل، وسياسات الجلسات، وخوادم MCP، وTTS، وغيرها. تُستورَد العناصر إما مباشرةً إلى مكافئاتها في Hermes أو تُؤرشَف للمراجعة اليدوية.

      مستوردة مباشرةً: SOUL.md، MEMORY.md، USER.md، AGENTS.md، المهارات (4 مجلدات مصدر)، النموذج الافتراضي، المزوّدون المخصصون، خوادم MCP، رموز وقوائم سماح منصات المراسلة (Telegram وDiscord وSlack وWhatsApp وSignal وMatrix وMattermost)، إعدادات الوكيل الافتراضية (مستوى التفكير، الضغط، تأخير التفاعل البشري، المنطقة الزمنية، sandbox)، قواعد الموافقة، إعدادات TTS، إعدادات المتصفح، إعدادات الأدوات، مهلة التنفيذ، قائمة سماح الأوامر، إعدادات الـ gateway، ومفاتيح API من 3 مصادر.

      مؤرشفة للمراجعة اليدوية: مهام cron، والإضافات، وhooks/webhooks، وخلفية الذاكرة (QMD)، وإعدادات سجل المهارات، وواجهة المستخدم/الهوية، والتسجيل، وإعداد تعدد الوكلاء، وربط القنوات، وIDENTITY.md، وTOOLS.md، وHEARTBEAT.md، وBOOTSTRAP.md.

      يفحص تحليل مفتاح API يفحص ثلاثة مصادر بترتيب الأولوية: قيم الإعدادات → ~/.openclaw/.env → auth-profiles.json. كل حقول الرموز تتعامل مع النصوص العادية، وقوالب البيئة (${VAR})، وكائنات SecretRef.

      للاطلاع على خريطة تحويل مفاتيح الإعدادات الكاملة، وتفاصيل معالجة SecretRef، وقائمة التحقق بعد الانتقال، راجع دليل الانتقال الكامل.

      أمثلة​

      # Preview what would be migrated
      hermes claw migrate --dry-run

      # Full migration (all compatible settings, no secrets)
      hermes claw migrate --preset full

      # Full migration including API keys
      hermes claw migrate --preset full --migrate-secrets

      # Migrate user data only (no secrets), overwrite conflicts
      hermes claw migrate --preset user-data --overwrite

      # Migrate from a custom OpenClaw path
      hermes claw migrate --source /home/user/old-openclaw

      hermes serve​

      hermes serve [options]

      تشغيل خادم Hermes الخلفي — gateway الـ JSON-RPC/WebSocket الذي يتصل به تطبيق desktop والعملاء البعيدون. إنه نفس الخادم الذي يشغّله hermes dashboard، لكن بلا واجهة (headless): لا يفتح واجهة متصفح أبدًا. يطلق تطبيق desktop خلفيته الخاصة من hermes serve؛ استخدم هذا الأمر مباشرةً عندما تريد خلفية بلا واجهة على مضيف بعيد. يقبل نفس خيارات --host / --port / --insecure / --skip-build / --stop / --status الخاصة بـ hermes dashboard أدناه (الربط بعنوان غير loopback يُفعِّل نفس بوابة المصادقة). يتطلب الإضافة [web]؛ ويحتاج مقبس Chat المدمج إضافةً إلى [pty] على مضيف POSIX.

      تعارضات المنفذ: إذا كان المنفذ المطلوب (الافتراضي 9119) مشغولًا بالفعل بواسطة عملية أخرى (مثل hermes serve ثانٍ أو الـ gateway)، يطبع الأمر سطر إشارة قابل للمعالجة آليًا BACKEND_PORT_IN_USE port=<port> على stdout، مع تلميح مقروء للبشر يذكر المُحتمِل الشاغل للمنفذ، ويخرج برمز 75 (EX_TEMPFAIL) بدلًا من خطأ عام — بحيث تستطيع السكربتات وتطبيق desktop التمييز بين "منفذ مشغول" و"الخلفية معطَّلة". مرّر --port 0 لربط منفذ عشوائي متاح (الإقلاع الناجح يعلن المنفذ المختار عبر HERMES_BACKEND_READY port=<port>).

      hermes dashboard​

      hermes dashboard [options]

      أطلق لوحة تحكم الويب لإدارة الإعدادات ومفاتيح API والجلسات. للحصول على backend دون واجهة رسومية، استخدم hermes serve. تُعدّ FastAPI و Uvicorn وأداة PTY المساعدة الخاصة بالمنصة اعتماديات أساسية. تضيف web قيودًا دقيقة لمجموعة HTTP، ويختارها إعداد PM القياسي عبر all. إذا تلفت الاعتماديات، نفّذ hermes pm repair. يتطلب تبويب Chat المضمّن بيئة PTY من نوع POSIX، مثل Linux أو macOS أو WSL2. راجع لوحة تحكم Hermes على الويب للتوثيق الكامل.

      الخيارالافتراضيالوصف
      --port9119المنفذ لتشغيل خادم الويب عليه
      --host127.0.0.1عنوان الربط
      --no-open—عدم فتح المتصفح تلقائيًا
      --insecureمعطَّلمهمل (deprecated) / بلا تأثير. كان سابقًا يتخطى المصادقة عند الربط بعنوان غير loopback. منذ تعزيز يونيو 2026 الأمني، يتطلب الربط العام دائمًا مزوّد مصادقة (كلمة مرور أو OAuth). اربط بـ 127.0.0.1 واستخدم نفقًا (tunnel) لإبقائه محليًا.
      --skip-buildمعطَّلتخطي خطوة بناء واجهة الويب وتقديم مجلد dist الموجود مباشرةً. مفيد في السياقات غير التفاعلية (Windows Scheduled Tasks، CI) حيث npm غير متاح. ابنِ مسبقًا بـ cd web && npm run build.

SIGTERM ثم مهلة 10s ثم SIGKILL؛ وتُوقَف أيضًا Chat TUI المستضافة التي تستمر بعد backend الخاص بها (وإلا أبقت state.db-wal المحذوف مفتوحًا ومنعت التشغيل التالي). لا تُمس بوتات Messaging Gateway التي شُغّلت من لوحة التحكم.

      hermes profile​

      hermes profile <subcommand>

      إدارة profiles — نُسخ Hermes متعددة معزولة، لكل منها إعداداتها وجلساتها ومهاراتها ومجلدها الرئيسي الخاص.

      الأمر الفرعيالوصف
      listسرد كل الـ profiles.
      use <name>ضبط profile افتراضي ثابت.
      create <name> [--clone] [--clone-all] [--clone-from <source>] [--no-alias]إنشاء profile جديد. --clone ينسخ الإعدادات، و.env، وSOUL.md، والمهارات، وملفات الذاكرة المُنقَّحة MEMORY.md/USER.md من الـ profile النشط. --clone-all ينسخ كل الحالة. --clone-from يحدّد profile مصدر ويستلزم نسخ الإعدادات ما لم يُقترَن بـ --clone-all.
      delete <name> [-y]حذف profile.
      show <name>عرض تفاصيل profile (المجلد الرئيسي، الإعدادات، إلخ).
      alias <name> [--remove] [--name NAME]إدارة سكربتات wrapper للوصول السريع إلى profile.
      rename <old> <new>إعادة تسمية profile.
      export <name> [-o FILE]تصدير profile إلى أرشيف .tar.gz (نسخة احتياطية محلية).
      import <archive> [--name NAME]استيراد profile من أرشيف .tar.gz (استعادة محلية).
      install <source> [--name N] [--alias] [--force] [-y]تثبيت توزيعة profile من رابط git أو مجلد محلي.
      update <name> [--force-config] [-y]إعادة سحب توزيعة؛ يحافظ على بيانات المستخدم (الذكريات، الجلسات، المصادقة).
      info <name>عرض مانفست توزيعة profile (الإصدار، المتطلبات، المصدر).

      أمثلة:

      hermes profile list
      hermes profile create work --clone
      hermes profile create work --clone --sync-imports   # also carry over the import-agent sync manifest
      hermes profile use work
      hermes profile alias work --name h-work
      hermes profile export work -o work-backup.tar.gz
      hermes profile import work-backup.tar.gz --name restored
      hermes profile install github.com/user/my-distro --alias
      hermes profile update work
      hermes -p work chat -q "Hello from work profile"

      راجع إدارة الحزم لكل أمر فرعي وسلوك المصدر مقابل الحزمة وسياسة التثبيت الكسول وأوامر المشرفين.

      hermes update​

      hermes update [--gateway] [--check] [--plan] [--no-backup] [--backup] [--yes]

      يحدّث نسخة مصدر مسحوبة مقبولة ويجهّز الاعتماديات عبر PM. استخدم --check للمقارنة مع هدف المصدر المضبوط دون تطبيق التحديث. تحتفظ حزم Desktop و Docker و Nix و Termux بمسؤول التحديث الخارجي الخاص بها. راجع التحديث & إلغاء التثبيت دون التثبيت.

      hermes update يتبع قناة التحديث لهذا التثبيت. تستخدم نسخة المصدر المسحوبة من المستودع الرسمي افتراضيًا stable، أي أحدث إصدار GitHub منشور يحمل vX.Y.Z عند commit نفسه؛ وتستخدم forks والمرايا افتراضيًا main. لمتابعة كل commit على main بدلًا من ذلك، نفّذ hermes update --set-channel main; hermes update --set-channel stable يعيد التبديل. على قناة main، قد تُحوَّل النسخة المسحوبة الموجودة على branch آخر إلى branch التحديث قبل السحب. أنشئ commit لعمل branch قبل التحديث إذا أردت إبقاءه خارج تدفق autostash الخاص بالتحديث.

      الخيارالوصف
      --install-idطباعة هوية هذا التثبيت ومساره، ثم الخروج.
      --set-channel CHANNELحفظ قناة التحديث لهذا التثبيت المصدري دون تطبيق تحديث: stable (الإصدارات المنشورة) أو main (كل commit). للتطبيقات المُحزّمة قناة بناء ثابتة وترفض تغيير القناة.
      --channel CHANNELاختيار قناة مصدر لهذا الاستدعاء فقط (stable أو main)؛ لا يُحفظ شيء.
      --branch NAMEاختيار branch للمصدر في هذا الاستدعاء؛ يتقدّم على اختيار قناة المصدر.
      --gatewayوضع داخلي يستخدمه أمر /update في المراسلة. يستخدم IPC القائم على الملفات للطلبات وبث التقدم بدلًا من القراءة من stdin الطرفية. ليس علامة لإعادة تشغيل gateway.
      --checkالتحقق من توفر تحديث دون السحب أو تثبيت التبعيات أو إعادة تشغيل أي شيء.
      --planطباعة خطة التحديث والخروج دون تغيير أي شيء: نوع التثبيت (git/Docker/Nix/apt)، وكل خدمة Hermes قيد التشغيل عبر جميع profiles مع المُشرِف (supervisor) وإصدار الكود قيد التشغيل، وكيفية إعادة تشغيل كل منها. في التثبيتات المُدارة بصورة (image) أو حزمة، يُبلَّغ عن أمر التحديث الخارجي الصحيح بدلًا من ذلك. للقراءة فقط.
      --no-backupتخطي كل النسخ الاحتياطية قبل التحديث لهذا التشغيل (كلًا من لقطة الحالة السريعة وملف zip الكامل)، بغض النظر عن updates.pre_update_backup.
      --backupفرض نسخة احتياطية كاملة قبل التحديث لهذا التشغيل: لقطة الحالة السريعة إضافةً إلى ملف zip كامل لـ HERMES_HOME (الإعدادات، المصادقة، الجلسات، المهارات، بيانات الاقتران). الوضع الافتراضي هو quick — لقطة حالة خفيفة فقط. اضبط الوضع الدائم عبر `updates.pre_update_backup: quick
      --yes، -yافتراض الموافقة على الطلبات التفاعلية مثل ترحيل الإعدادات واستعادة stash. يُتخطى إدخال مفتاح API؛ شغّل hermes config migrate منفصلًا لذلك.

      سلوك إضافي:

      • إعادة تشغيل الـ gateway. بعد تحديث ناجح، يحاول Hermes إعادة تشغيل كل profiles الـ gateway العاملة في المجلد الرئيسي الجاري تحديثه (جذره وكل profiles/<name> تحته) تلقائيًا لتستخدم الكود الجديد. تُسمَّى gateways وخدمات hermes-gateway* التابعة إلى HERMES_HOME مختلف على الجهاز نفسه — تثبيت آخر أو مجلد رئيسي مؤقت يشغّل hermes update — في المخرجات وتُترَك دون مساس. استخدم hermes gateway restart عندما تريد إعادة تشغيل gateway دون تطبيق تحديث.
      • استرجاع مرحلة إعادة التشغيل. إذا أُجهضت مرحلة إعادة التشغيل داخل العملية أثناء استيراد الشجرة المسحوبة حديثًا، تُعاد محاولة profiles الـ gateway المُشرَف عليها عبر عملية Python نظيفة. فقط عمليات إعادة الإطلاق المؤكَّدة بشكل مستقل بواسطة systemd (systemctl --user is-active) تُسجَّل كمُتحقَّق منها؛ أما إعادة الإطلاق التي خرجت برمز 0 فقط فتُسجَّل كـ relaunch_attempted وتظل إعادة التشغيل مستحقة (متابعة gateway_restart؛ ويظل التحديث نفسه يخرج بالرمز 0 لأن الكود في مكانه). لا تُنهى gateways اليدوية وبيئات serve/dashboard مطلقًا دون جهة مخوّلة بإعادة إطلاقها؛ تُسجَّل كمتجاوَزة مع السبب وتبقى في تقرير التحديث غير المكتمل مع أمر إعادة التشغيل الدقيق.
      • إيصالات التحديث + فحص إصدار الأسطول. كل تشغيل يكتب إيصالًا قابلًا للمعالجة آليًا إلى ~/.hermes/logs/update_receipts/ في مجلد Hermes الرئيسي الجذري، حتى من profile ثابت (خطة المجموعة قبل التحديث والخطوات والتجاوزات بأسبابها ونتيجة إعادة التشغيل والمتابعات؛ يشير latest.json إلى الأحدث ويعرض running أثناء التحديث). بعد مرحلة إعادة التشغيل، يتحقق المحدّث من كود كل gateway حيّة مقارنةً بالنسخة المحدّثة ويطبع مصفوفة إصدارات لكل profile. لا تؤدي gateway التي ما زالت على كود ما قبل التحديث إلى فشل التحديث بعد وجود الكود الجديد: يطبع التحديث سطر ⚠ مع أمر إعادة التشغيل الدقيق، ويخرج بالرمز 0 ويسجّل متابعة gateway_restart ويُبقي إعادة التشغيل مستحقة — يحذّر كل بدء CLI منها، ويعيد hermes update التالي المحاولة.
      • تغييرات المصدر المحلية. بالنسبة لتثبيتات git، تُخزَّن (auto-stash) الملفات المُتتبَّعة المتسخة والملفات غير المُتتبَّعة تلقائيًا قبل تحويل الفرع أو السحب (git stash push --include-untracked). التحديثات في طرفية تفاعلية تطلب تأكيدًا قبل استعادة الـ stash. التحديثات غير التفاعلية تستعيده افتراضيًا؛ اضبط updates.non_interactive_local_changes: discard فقط على التثبيتات المُدارة حيث ينبغي التخلص من تعديلات المصدر المحلية بعد سحب ناجح. إذا تعارضت استعادة الـ stash أو فشل السحب، يُترَك الـ stash في مكانه للاسترجاع اليدوي.
      • تراكم ملف قفل npm. قبل الـ stash أو تحويل الفروع، يجري Hermes تنظيفًا بأفضل جهد لفروقات package-lock.json المُتتبَّعة الناتجة عن خطوات npm install/build. أَودِع (commit) أو خزِّن (stash) يدويًا تعديلات ملف القفل المقصودة قبل تشغيل hermes update.
      • لقطة بيانات الاقتران. حتى عندما يكون --backup معطَّلًا، يأخذ hermes update لقطة خفيفة من ~/.hermes/pairing/ وقواعد تعليقات Feishu قبل git pull. يمكنك التراجع عنها بـ hermes backup restore --state pre-update إذا أعاد السحب كتابة ملف كنت تعدّله.
      • تحذير hermes.service القديم. إذا اكتشف Hermes وحدة systemd سابقة لإعادة التسمية باسم hermes.service (بدلًا من hermes-gateway.service الحالية)، يطبع تلميح ترحيل لمرة واحدة لتجنب مشكلات حلقة التذبذب (flap-loop).
      • رموز الخروج. 0 عند النجاح، 1 عند أخطاء السحب/التثبيت/ما بعد التثبيت، 2 عند تغييرات غير متوقعة في شجرة العمل تعيق git pull.
