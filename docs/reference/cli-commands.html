      مرجع أوامر CLI

      تغطي هذه الصفحة أوامر الطرفية التي تشغّلها من الـ shell.

      لأوامر الـ slash داخل المحادثة، راجع مرجع Slash Commands.

      نقطة الدخول العامة​

      hermes [global-options] <command> [subcommand/options]

      الخيارات العامة​

      الخيارالوصف
      --version، -Vعرض الإصدار والخروج.
      --profile <name>، -p <name>اختيار profile Hermes الذي سيُستخدم لهذا الاستدعاء. يتجاوز الافتراضي الثابت الذي ضبطه hermes profile use.
      --resume <session>، -r <session>استئناف جلسة سابقة بالمعرّف أو العنوان. الكلمة المفتاحية latest تستأنف أحدث جلسة (ضمن نطاق مساحة العمل، بنفس منطق البحث المستخدم في -c).
      --continue [name]، -c [name]استئناف أحدث جلسة، أو أحدث جلسة تطابق عنوانًا.
      --in <dir>الانتقال إلى <dir> قبل البدء أو الاستئناف. يحصر عمليات البحث لـ --resume latest / -c ضمن مساحة عمل ذلك المجلد ويُبقي الجلسة هناك (يتخطى استعادة الدليل الحالي المسجَّل).
      --worktree، -wالبدء في worktree معزول لـ git لسير عمل الوكلاء المتوازيين.
      --yoloتجاوز رسائل الموافقة على الأوامر الخطرة.
      --pass-session-idتضمين معرّف الجلسة في system prompt الخاص بالوكيل.
      --ignore-user-configتجاهل ~/.hermes/config.yaml والعودة إلى الإعدادات الافتراضية المضمّنة. تُحمَّل بيانات الاعتماد في .env رغم ذلك.
      --ignore-rulesتخطّي الحقن التلقائي لـAGENTS.md وSOUL.md و.cursorrules والذاكرة والمهارات المحمَّلة مسبقًا.
      --tuiتشغيل TUI بدلًا من CLI الكلاسيكي. مكافئ لـHERMES_TUI=1. يتفوّق دائمًا على display.interface.
      --cliفرض REPL الكلاسيكي القائم على prompt_toolkit. استخدم هذا لتجاوز display.interface: tui لاستدعاء واحد.
      --devمع --tui: تشغيل مصادر TypeScript مباشرة عبر tsx بدلًا من الحزمة المبنية مسبقًا (للمساهمين في TUI).

      hermes chat​

      hermes chat [options]

      خيارات شائعة:

      الخيارالوصف
      -q، --query "..."بذر الجلسة بـ prompt. على TTY حقيقي، يُرسَل الـ prompt حرفيًا كأول دور (turn) في جلسة تفاعلية عادية (لا يُفسَّر أبدًا كأمر slash أو escape لـ! الخاص بالـ shell) وتبقى الجلسة مفتوحة — مثالي لمشغِّلات نظام التشغيل وتكاملات desktop. مع --oneshot أو -Q أو stdio غير TTY، يجيب ويخرج.
      --query-file PATHقراءة الاستعلام من ملف (- = stdin). لا شيء يُفسَّر بواسطة الـ shell، لذا تصل علامات الاقتباس و$(...) والفواصل العليا (backticks) كما هي — استخدم هذا لأجسام الرسائل البرمجية أو غير الموثوقة (يستخدمه Bot Mode لرسائل teammate DM المباشرة). حصري مع -q.
      --oneshotمع -q/--query-file: الإجابة على الاستعلام والخروج (سلوك الاستعلام الواحد قبل الإصدار 0.21) بدلًا من بذر جلسة تفاعلية. ضمني على stdio غير TTY وبـ-Q.
      -m، --model <model>تجاوز النموذج لهذا التشغيل.
      -t، --toolsets <csv>تفعيل مجموعة toolsets مفصولة بفواصل.
      --provider <provider>فرض مزوّد: auto، openrouter، nous، openai-codex، copilot-acp، copilot، anthropic، gemini، huggingface، novita (وله أسماء بديلة novita-ai، novitaai)، openai-api، zai، kimi-coding، kimi-coding-cn، minimax، minimax-cn، minimax-oauth، kilocode، xiaomi، arcee، gmi، upstage (اسم بديل solar)، alibaba، alibaba-cn، alibaba-coding-plan (اسم بديل alibaba_coding)، alibaba-coding-plan-cn، alibaba-token-plan، alibaba-token-plan-cn، deepseek، nvidia، ollama-cloud، xai (اسم بديل grok)، xai-oauth (اسم بديل grok-oauth)، qwen-oauth، bedrock، opencode-zen، opencode-go، opencode-free (أسماء بديلة free، opencode_free؛ بدون مفتاح)، commandcode، commandcode-anthropic، ai-gateway، azure-foundry، lmstudio، stepfun، tencent-tokenhub (اسم بديل tencent، tokenhub)، router (أسماء بديلة ramp-router، ramp)، nebius-token-factory (أسماء بديلة nebius، nebius-tf، tokenfactory)، tencent-tokenplan (أسماء بديلة tokenplan، tencent-lkeap).
      -s، --skills <name>تحميل مهارة أو أكثر مسبقًا للجلسة (يمكن تكرارها أو الفصل بينها بفواصل).
      -v، --verboseمخرجات مفصّلة.
      -Q، --quietوضع برمجي: إخفاء الشعار/مؤشر التحميل/معاينات الأدوات.
      --image <path>إرفاق صورة محلية باستعلام واحد.
      --resume <session> / --continue [name]استئناف جلسة مباشرة من chat.
      --worktreeإنشاء worktree معزول لـgit لهذا التشغيل.
      --checkpointsتفعيل نقاط حفظ نظام الملفات قبل التغييرات المدمّرة على الملفات.
      --yoloتخطي رسائل الموافقة.
      --pass-session-idتمرير معرّف الجلسة إلى system prompt.
      --ignore-user-configتجاهل ~/.hermes/config.yaml واستخدام الإعدادات الافتراضية المضمّنة. تُحمَّل بيانات الاعتماد في .env رغم ذلك. مفيد لتشغيلات CI المعزولة، وتقارير الأخطاء القابلة لإعادة الإنتاج، والتكاملات الخارجية.
      --ignore-rulesتخطّي الحقن التلقائي لـAGENTS.md وSOUL.md و.cursorrules والذاكرة الدائمة والمهارات المحمَّلة مسبقًا. اجمعها مع --ignore-user-config لتشغيل معزول بالكامل.
      --safe-modeوضع استكشاف الأخطاء: تعطيل كل التخصيصات — إعدادات المستخدم، وحقن القواعد/الذاكرة، والإضافات، وhooks الـ shell، وخوادم MCP (يستلزم --ignore-user-config و--ignore-rules). استخدمه لعزل ما إذا كانت المشكلة من إعدادك أم من Hermes نفسه.
      --source <tag>وسم مصدر الجلسة للتصفية (الافتراضي: cli). استخدم tool للتكاملات الخارجية التي يجب ألا تظهر في قوائم جلسات المستخدم.
      --max-turns <N>الحد الأقصى لتكرارات استدعاء الأدوات لكل دور محادثة (الافتراضي: 500، أو agent.max_turns في الإعدادات).

      أمثلة:

      hermes
      hermes chat -q "Summarize the latest PRs"          # seeds an interactive session
      hermes chat --oneshot -q "Summarize the latest PRs"  # answer and exit
      hermes chat --provider openrouter --model anthropic/claude-sonnet-4.6
      hermes chat --toolsets web,terminal,skills
      hermes chat --quiet -q "Return only JSON"
      hermes chat --worktree -q "Review this repo and open a PR"
      hermes chat --ignore-user-config --ignore-rules -q "Repro without my personal setup"
      hermes chat --safe-mode -q "Is this bug mine or Hermes'?"

      التفويض في تشغيلات المحادثة المحدودة​

      عندما تجيب المحادثة وتخرج (-Q، أو chat --oneshot، أو استعلام مع stdio غير TTY)، ينتظر delegate_task أبناءه ويعيد نتائجهم إلى الوالد ضمن الدور نفسه. تستمر مهام الدفعة (batch) الفرعية في العمل بالتوازي، وفق delegation.max_concurrent_children. يمكن للوالد استخدام تلك النتائج في ردّه النهائي قبل خروج CLI.

      • الانضمام التلقائي: لا يلزم اشتراك أو تجاوز لوضع الخلفية. تحافظ جلسات المحادثة التفاعلية عبر TTY وجلسات المراسلة على التفويض في الخلفية.
      • الضمانات القائمة: لا تزال حدود التفويض والمُهل والإلغاء و approvals.single_query_mode سارية. الانضمام لا يوافق تلقائيًا على الأوامر ولا يضمن نتائج ناجحة للأبناء. افحص النتائج وتحقّق من المخرجات.
      • إكمالات الطرفية: هذا لا يغيّر سلوك إشعار طرفية الخلفية ولا مهلة الخروج المحدودة terminal.oneshot_completion_wait_seconds. ذلك الإعداد ليس مهلة تفويض.

      يبقى التفويض محليًا للعملية (process-local). مقاطعة الوالد أو إنهاؤه قد يلغي الأبناء غير المنتهين. استخدم مجدولًا دائمًا للعمل الذي يجب أن يستمر بعد انتهاء العملية المبادِرة.

      hermes -z <prompt> — تشغيل واحد بسكربت​

      للمستدعين البرمجيين (سكربتات shell، وCI، وcron، والعمليات الأم التي تمرّر prompt عبر الأنبوب)، يُعدّ hermes -z أنقى نقطة دخول لتشغيل واحد: prompt واحد يدخل، ونص الرد النهائي يخرج، ولا شيء آخر على stdout أو stderr. لا شعار، لا مؤشر تحميل، لا معاينات أدوات، لا سطر Session: — فقط رد الوكيل النهائي كنص عادي.

      hermes -z "What's the capital of France?"
      # → Paris.

      # Parent scripts can cleanly capture the response:
      answer=$(hermes -z "summarize this" < /path/to/file.txt)

      hermes model​

      منتقي مزوّد + نموذج تفاعلي. هذا هو الأمر لإضافة مزوّدين جدد، وإعداد مفاتيح API، وتشغيل تدفقات OAuth. شغّله من طرفيتك — وليس من داخل جلسة محادثة Hermes نشطة.

      hermes model

      استخدم هذا عندما تريد:

      • إضافة مزوّد جديد (OpenRouter وAnthropic وCopilot وDeepSeek ومخصص، إلخ)
      • تسجيل الدخول إلى مزوّدين مدعومين بـOAuth (Anthropic وCopilot وCodex وNous Portal)
      • إدخال أو تحديث مفاتيح API
      • الاختيار من قوائم النماذج الخاصة بالمزوّد
      • إعداد endpoint مخصص/مستضاف ذاتيًا
      • حفظ الافتراضي الجديد في الإعدادات
      hermes model مقابل /model — اعرف الفرق

      hermes model (يُشغَّل من طرفيتك، خارج أي جلسة Hermes) هو معالج إعداد المزوّد الكامل. يمكنه إضافة مزوّدين جدد، وتشغيل تدفقات OAuth، وطلب مفاتيح API، وإعداد endpoints.

      /model (يُكتب داخل جلسة محادثة Hermes نشطة) يستطيع فقط التبديل بين المزوّدين والنماذج التي أعددتها بالفعل. لا يمكنه إضافة مزوّدين جدد، أو تشغيل OAuth، أو طلب مفاتيح API.

      إذا احتجت إلى إضافة مزوّد جديد: اخرج من جلسة Hermes أولًا (Ctrl+C أو /quit)، ثم شغّل hermes model من موجّه طرفيتك.

      أمر /model الـslash (في منتصف الجلسة)​

      التبديل بين النماذج المُعدَّة مسبقًا دون مغادرة الجلسة:

      /model                              # Show current model and available options
      /model claude-sonnet-4              # Switch model (auto-detects provider)
      /model zai:glm-5                    # Switch provider and model
      /model custom:qwen-2.5              # Use model on your custom endpoint
      /model custom                       # Auto-detect model from custom endpoint
      /model custom:local:qwen-2.5        # Use a named custom provider
      /model openrouter:anthropic/claude-sonnet-4  # Switch back to cloud

      افتراضيًا، تُطبَّق تغييرات /model على الجلسة الحالية فقط. أضف --global لحفظ التغيير في config.yaml بشكل دائم (أو اضبط model.persist_switch_by_default: true ليصبح كل تبديل دائمًا):

      /model claude-sonnet-4 --global     # Switch and save as new default
      ماذا لو رأيت نماذج OpenRouter فقط؟

      إذا كنت قد أعددت OpenRouter فقط، فسيعرض /model نماذج OpenRouter فقط. لإضافة مزوّد آخر (Anthropic وDeepSeek وCopilot، إلخ)، اخرج من جلستك وشغّل hermes model من الطرفية.

      عند التبديل بـ--global، تُحفظ تغييرات المزوّد وعنوان URL الأساسي في config.yaml إلى جانب النموذج. وعند التبديل بعيدًا عن endpoint مخصص، يُمسح عنوان URL الأساسي القديم لمنع تسربه إلى مزوّدين آخرين.

      hermes gateway​

      hermes gateway <subcommand>

      الأوامر الفرعية:

      الأمر الفرعيالوصف
      runتشغيل gateway في المقدمة (foreground). موصى به لـWSL وDocker وTermux.
      startبدء خدمة systemd/launchd المثبَّتة في الخلفية.
      stopإيقاف الخدمة (أو عملية المقدمة).
      restartإعادة تشغيل الخدمة.
      statusعرض حالة الخدمة.
      listعرض كل الـ profiles وما إذا كان gateway كل profile يعمل حاليًا (مع PID إن توفّر). مفيد عندما تشغّل عدة profiles جنبًا إلى جنب وتريد نظرة عامة واحدة.
      installالتثبيت كخدمة خلفية systemd (Linux) أو launchd (macOS).
      uninstallإزالة الخدمة المثبَّتة.
      setupإعداد منصة مراسلة تفاعلي.
      migrateنقل gateways مستقلة لكل profile إلى gateway واحد افتراضي متعدد الإرسال (multiplexed) (--multiplex، وهو الافتراضي) أو التراجع من البيان (manifest) المسجَّل (--standalone). يشغّل فحصًا مبدئيًا (رموز bot مكررة، وناقلات منفذ ثانوية بدون مدخل /p/<profile>/) ولا يغيّر شيئًا عند الحظر. العلامات: --dry-run، -y/--yes. راجع الانتقال من gateways لكل profile.
      migrate-legacyإزالة وحدات hermes.service القديمة المتبقية من التثبيتات قبل إعادة التسمية. لا تُمَس أبدًا وحدات الـ profile (hermes-gateway-<profile>.service) ولا الخدمات غير ذات الصلة. العلامات: --dry-run، -y/--yes.
      enrollتجريبي: تسجيل هذا الـ gateway مع موصّل relay وحفظ بيانات اعتماد relay لمنصات مدعومة بموصّل. راجع Hermes Relay.

      الخيارات:

      الخيارالوصف
      --allعند start / restart / stop: العمل على gateway كل profile، لا فقط HERMES_HOME النشط. مفيد إذا كنت تشغّل عدة profiles جنبًا إلى جنب وتريد إعادة تشغيلها كلها بعد hermes update.
      --no-superviseعند run: داخل صورة Docker القائمة على s6-overlay، عدم الاشتراك في الإشراف التلقائي واستخدام دلالات المقدمة السابقة لـs6 — يعمل gateway كعملية الحاوية الرئيسية دون إعادة تشغيل تلقائي. بلا تأثير خارج صورة s6. مكافئ لضبط HERMES_GATEWAY_NO_SUPERVISE=1.
      --external-supervisorعند run: الإعلان أن مدير عمليات مزوَّد من خلال wrapper يملك gateway الأمامي. استخدم هذا عندما يزيل sudo أو env -i أو wrapper آخر علامة البيئة الأصلية لـlaunchd/systemd. تخرج إعادة التشغيل والتحديثات داخل المحادثة إلى ذلك المدير بدلًا من إنشاء بديل منفصل.

      --external-supervisor عقد سياسة إعادة تشغيل: تخرج إعادة تشغيل داخل المحادثة أو تحديث بإعادة تشغيل الخدمة برمز حالة 75، لذا يجب أن يعيد مشرف الـ wrapper تشغيل gateway بعد ذلك الخروج غير الصفري. بالنسبة لـsystemd، استخدم Restart=on-failure أو Restart=always ولا تُدرج 75 ضمن RestartPreventExitStatus؛ بالنسبة لـlaunchd، اضبط KeepAlive لإعادة التشغيل بعد الخروجات غير الناجحة. بدون تلك السياسة، تترك إعادة تشغيل مطلوبة gateway متوقفًا.

      يقبل hermes gateway enroll الخيارات --token و--connector-url و--gateway-id و--wake-url. يستبدل رمز التسجيل مع الموصّل ويكتب قيم GATEWAY_RELAY_ID وGATEWAY_RELAY_SECRET وGATEWAY_RELAY_DELIVERY_KEY الناتجة، وGATEWAY_RELAY_URL الاختياري، و(عند إعطاء --wake-url) GATEWAY_RELAY_WAKE_URL في ملف .env الخاص بالـ profile النشط.

      مستخدمو WSL

      استخدم hermes gateway run بدلًا من hermes gateway start — دعم systemd في WSL غير موثوق. لفّه في tmux للاستمرارية: tmux new -s hermes 'hermes gateway run'. راجع الأسئلة الشائعة عن WSL للتفاصيل.

      hermes send​

      hermes send --to <target> "message text"
      hermes send --to <target> --file <path>
      echo "message" | hermes send --to <target>
      hermes send --list [platform]

      إرسال رسالة لمرة واحدة إلى منصة مراسلة مُعدَّة دون تشغيل وكيل أو حلقة gateway. يعيد استخدام بيانات اعتماد gateway المُعدَّة مسبقًا (~/.hermes/.env + ~/.hermes/config.yaml) بحيث يمكن لسكربتات العمليات ومهام cron وhooks CI وdaemons المراقبة نشر تحديثات الحالة دون إعادة تنفيذ عميل REST الخاص بكل منصة.

      بالنسبة للمنصات ذات رمز البوت (Telegram وDiscord وSlack وSignal وSMS وWhatsApp-CloudAPI)، لا يلزم تشغيل gateway — يتحدث hermes send مباشرة إلى endpoint REST الخاص بالمنصة. أما منصات الإضافات التي تحتاج محوّلًا دائمًا فلا تزال تتطلب gateway حيًا.

      الخيارالوصف
      -t، --to <TARGET>هدف التسليم. الصيغ: platform (يستخدم القناة الرئيسية)، platform:chat_id، platform:chat_id:thread_id، أو platform:#channel-name. أمثلة: telegram، telegram:-1001234567890، discord:#ops، slack:C0123ABCD، signal:+15551234567.
      -f، --file <PATH>قراءة نص الرسالة من PATH (ملفات نصية فقط — سجلات وتقارير وmarkdown). مرّر - لإجبار القراءة من stdin. لإرسال صورة أو ملف ثنائي آخر، استخدم MEDIA:<path> (انظر أدناه).
      -s، --subject <LINE>إضافة سطر موضوع/عنوان قبل نص الرسالة.
      -l، --list [platform]عرض الأهداف المُعدَّة عبر كل المنصات (أو منصة معيّنة فقط).
      -q، --quietإخفاء stdout عند النجاح — مفيد في السكربتات (الاعتماد على رمز الخروج فقط).
      --jsonإصدار نتيجة JSON خام بدلًا من مخرجات مقروءة للبشر.

      إذا لم يُعطَ معامل message موضعي ولا --file، يقرأ hermes send من stdin عندما لا يكون TTY. رموز الخروج: 0 عند النجاح، 1 عند فشل التسليم/الـ backend، 2 عند أخطاء الاستخدام.

      إرسال الصور والوسائط الأخرى​

      --file مخصص لأجسام نصية فقط. لتسليم صورة أو مستند أو فيديو أو ملف صوتي كمرفق أصلي للمنصة، أشر إليه داخل نص الرسالة بتوجيه MEDIA:<local_path>:

      hermes send --to telegram "MEDIA:/tmp/screenshot.png"
      hermes send --to telegram "Build chart for today MEDIA:/tmp/chart.png"   # with caption
      hermes send --to discord:#ops "MEDIA:/tmp/report.pdf"

      افتراضيًا، تُرسَل ملفات الصور كصور (تعيد منصات مثل Telegram ضغطها). أضف [[as_document]] إلى الرسالة لتسليمها كمرفقات ملفات غير مضغوطة بدلًا من ذلك:

      hermes send --to telegram "[[as_document]] MEDIA:/tmp/screenshot.png"

      أمثلة:

      hermes send --to telegram "deploy finished"
      echo "RAM 92%" | hermes send --to telegram:-1001234567890
      hermes send --to discord:#ops --file /tmp/report.md
      hermes send --to slack:#eng --subject "[CI]" --file build.log
      hermes send --list                  # all platforms
      hermes send --list telegram         # filter by platform

      add <name> --url <URL> [--key <KEY>] [--note TEXT]تسجيل أو تحديث نظير. يذهب الرابط إلى config.yaml (bot_peers)؛ يُخزَّن المفتاح كـHERMES_PEER_<NAME>_KEY في ~/.hermes/.env.
      listعرض النظراء وما إذا كان كل منهم لديه مفتاح مُعدّ.
      dm <peer>[/<agent>] [message]مراسلة Bot Chat الأساسية لوكيل النظير وطباعة الرد (--json لمخرجات قابلة للقراءة آليًا؛ تعود الرسالة إلى stdin إن لم تُعطَ).
      run <peer>[/<agent>] [message]بدء دور Bot Chat أساسي طويل بشكل غير متزامن وإعادة run_id ومعرّف الجلسة ومفتاح idempotency (يدعم --json). أعد استخدام --idempotency-key عند إعادة محاولة نفس الطلب.
      status <peer>[/<agent>] <run_id>استطلاع تشغيل نظير غير متزامن وطباعة مخرجاته النهائية عند الاكتمال (يدعم --json).
      stop <peer>[/<agent>] <run_id>إيقاف تشغيل النظير غير المتزامن المحدَّد بدقة دون استهداف دور آخر (يدعم --json).
      remove <name>إزالة نظير من السجل (يبقى إدخال مفتاح .env كما هو).

      عند تسجيل نظير واحد على الأقل، يتضمن بروتوكول مراسلة Bot Mode (agent.bot_mode_protocol) الذي يُلقَّن لكل Bot Chat أساسية تلقائيًا قائمة النظراء ونمط hermes peer dm، بحيث تكتشف الوكلاء زملاء عبر الأجهزة دون تعديلات SOUL. راجع Bot Mode.

      رموز الخروج: 0 عند النجاح، 1 عند فشل التسليم/النظير، 2 عند أخطاء الاستخدام.

      hermes auth​

      إدارة مجمّعات بيانات الاعتماد لتناوب المفاتيح ضمن المزوّد نفسه. راجع مجمّعات بيانات الاعتماد (Credential Pools) للتوثيق الكامل.

      hermes auth                                              # Interactive wizard
      hermes auth list                                         # Show all pools
      hermes auth list openrouter                              # Show specific provider
      hermes auth add openrouter --api-key sk-or-v1-xxx        # Add API key
      hermes auth add openrouter --type oauth                  # Browser login (OpenRouter PKCE) mints a key for you
      hermes auth add anthropic --type oauth                   # Add OAuth credential
      hermes auth add openai-codex --type oauth --priority 0   # Add an account and try it first
      hermes auth remove openrouter 2                          # Remove by index
      hermes auth priority openrouter backup-key 0             # Move a credential to the front of fill_first order
      hermes auth reset openrouter                             # Clear cooldowns
      hermes auth reset openrouter 2                           # Clear the cooldown on one credential
      hermes auth refresh openai-codex work                    # Refresh one OAuth credential and clear its cooldown
      hermes auth status anthropic                             # Show auth status for a provider
      hermes auth logout anthropic                             # Log out and clear stored auth state
      hermes auth spotify                                      # Authenticate Hermes with Spotify via PKCE

      الأوامر الفرعية: add، list، remove، reset، priority، refresh، status، logout، spotify. عند الاستدعاء بدون أمر فرعي، يُطلق معالج الإدارة التفاعلي.

      hermes kanban​

      hermes kanban [--board <slug>] <action> [options]

      لوحة تعاون متعددة الـ profiles ومتعددة المشاريع. يمكن لكل تثبيت استضافة عدة لوحات (واحدة لكل مشروع أو مستودع أو نطاق)؛ كل لوحة هي قائمة انتظار مستقلة لها قاعدة بيانات SQLite ونطاق موزّع (dispatcher) خاصين بها. تبدأ التثبيتات الجديدة بلوحة واحدة تُسمى default، وقاعدة بياناتها هي ~/.hermes/kanban.db للتوافق الخلفي؛ أما اللوحات الإضافية فتوجد في ~/.hermes/kanban/boards/<slug>/kanban.db. يفحص الموزّع (dispatcher) المدمج في الـ gateway كل لوحة في كل دورة.

      خيارات عامة (تنطبق على كل إجراء أدناه):

      الخيارالغرض
      --board <slug>العمل على لوحة محددة. الافتراضي هو اللوحة الحالية (تُضبط عبر hermes kanban boards switch، أو متغير البيئة HERMES_KANBAN_BOARD، أو default).

      هذه هي الواجهة المخصصة للبشر / السكربتة. عمّال الوكيل (agent workers) الذين يُنشئهم الموزّع يتعاملون مع اللوحة عبر kanban_* toolset مخصص (kanban_show وkanban_complete وkanban_request_review وkanban_request_changes وkanban_block وkanban_create وkanban_link وkanban_comment وkanban_heartbeat؛ وتحصل profiles المنسّق أيضًا على kanban_list وkanban_unblock) بدلًا من استدعاء hermes kanban عبر الـ shell. العمّال يملكون HERMES_KANBAN_BOARD مثبّتًا في بيئتهم بحيث لا يمكنهم فعليًا رؤية لوحات أخرى.

      الإجراءالغرض
      initإنشاء kanban.db إن لم تكن موجودة. لا يُحدث تأثيرًا إضافيًا عند التكرار (idempotent).
      boards list / boards lsسرد كل اللوحات مع عدد المهام. --json، --all (شمول اللوحات المؤرشفة).
      boards create <slug>إنشاء لوحة جديدة. الخيارات: --name، --description، --icon، --color، --switch (جعلها النشطة). الـ slug بصيغة kebab-case، ويُحوَّل تلقائيًا لحروف صغيرة.
      boards switch <slug> / boards useحفظ <slug> كاللوحة النشطة (يكتب في ~/.hermes/kanban/current).
      boards show / boards currentطباعة اسم اللوحة النشطة حاليًا ومسار قاعدة بياناتها وعدد مهامها.
      boards rename <slug> "<name>"تغيير الاسم المعروض للوحة. الـ slug ثابت لا يتغير.
      boards rm <slug>أرشفة اللوحة (الافتراضي) أو حذفها نهائيًا. --delete يتخطى خطوة الأرشفة. اللوحات المؤرشفة تنتقل إلى boards/_archived/<slug>-<ts>/. يُرفض للوحة default.
      create "<title>"إنشاء مهمة جديدة على اللوحة النشطة. الخيارات: --body، --assignee، --parent (قابل للتكرار)، --workspace scratch|worktree|dir:<path>، --tenant، --priority، --triage، --idempotency-key، --max-runtime، --max-retries، --skill (قابل للتكرار).
      list / lsسرد مهام اللوحة النشطة. تصفية بواسطة --mine، --assignee، --status، --tenant، --archived، --json.
      show <id>عرض مهمة مع تعليقاتها وأحداثها. --json لمخرجات قابلة للمعالجة آليًا.
      assign <id> <profile>تعيين أو إعادة تعيين المهمة. استخدم none لإلغاء التعيين. يُرفض أثناء تشغيل المهمة.
      link <parent> <child>إضافة اعتمادية. يُكتشف التسلسل الدائري (cycle). يجب أن تكون المهمتان على نفس اللوحة.
      unlink <parent> <child>إزالة اعتمادية.
      claim <id>حجز مهمة جاهزة بشكل ذري. يطبع مسار مساحة العمل المُحلَّل.
      comment <id> "<text>"إضافة تعليق. العامل التالي الذي يحجز المهمة يقرأه كجزء من استجابة kanban_show() الخاصة به.
      complete <id>وضع علامة أن المهمة منجزة. الخيارات: --result، --summary، --metadata.
      block <id> "<reason>"وضع علامة أن المهمة معلّقة بانتظار تدخل بشري. كما يضيف السبب كتعليق.
      request-review <id>نقل مهمة إلى review مع تسليم إلى مراجِع — وهذا ليس تعليقًا (block). الخيارات: --summary، --metadata، --reviewer (يعيد التعيين قبل إرسال المراجعة).
      request-changes <id> <reason>قرار المراجِع لتشغيل مراجعة نشط: إغلاق محاولة المراجعة وإعادة توجيه المهمة إلى منفّذها الأصلي.
      reopen-review <id>...إعادة مهمة (أو أكثر) قيد المراجعة لإجراء تعديلات (review ← ready/todo). الخيار: --reason (يُضاف كتعليق).
      schedule <id> "<reason>"إيقاف عمل مؤجّل/متابعة في حالة scheduled بحيث لا يظهر كعائق بشري.
      unblock <id>استعادة مهمة معلّقة إلى مرحلتها المصدر (review أو ready)، أو إلى todo إن بقيت الاعتماديات مفتوحة.
      archive <id>إخفاء المهمة من القائمة الافتراضية. الأمر gc سيزيل مساحات العمل المؤقتة.
      tail <id>متابعة تدفق أحداث مهمة.
      dispatchتمريرة موزّع واحدة على اللوحة النشطة. الخيارات: --dry-run، --max N، --failure-limit N، --json.
      context <id>طباعة السياق الكامل الذي سيراه العامل (العنوان + المتن + نتائج المهام الأصل + التعليقات).
      specify <id> / specify --allتحويل مهمة في عمود الفرز (triage) إلى مواصفة محددة (عنوان + متن يتضمن الهدف والنهج ومعايير القبول) عبر الـ LLM المساعد، ثم ترقيتها إلى todo. الخيارات: --tenant (تحديد نطاق --all إلى tenant واحد)، --author، --json. يُضبط النموذج تحت auxiliary.triage_specifier في config.yaml.
      decompose <id> / decompose --allتفريع مهمة في عمود الفرز إلى شجرة من المهام الفرعية الموجَّهة إلى profiles متخصصة حسب الوصف. يرجع إلى ترقية مهمة واحدة بأسلوب specify عندما يقرر الـ LLM أن المهمة لا تستفيد من التفريع. نفس خيارات specify. يُضبط نموذج التفكيك تحت auxiliary.kanban_decomposer في config.yaml؛ أما kanban.orchestrator_profile فيتحكم فقط في من يملك مهمة الجذر/التنسيق بعد التفريع. يعمل أيضًا تلقائيًا في كل دورة موزّع عندما تكون kanban.auto_decompose: true (الافتراضي). راجع التنسيق التلقائي مقابل اليدوي.
      gcإزالة مساحات العمل المؤقتة للمهام المؤرشفة.

      أمثلة:

      # Create a second board and put a task on it without switching away.
      hermes kanban boards create atm10-server --name "ATM10 Server" --icon 🎮
      hermes kanban --board atm10-server create "Restart server" --assignee ops

      # Switch the active board for subsequent calls.
      hermes kanban boards switch atm10-server
      hermes kanban list                  # shows atm10-server tasks

      # Archive a board (recoverable) or hard-delete it.
      hermes kanban boards rm atm10-server
      hermes kanban boards rm atm10-server --delete

      ترتيب تحديد اللوحة (الأولوية الأعلى أولًا): خيار --board <slug> ← متغير البيئة HERMES_KANBAN_BOARD ← الملف ~/.hermes/kanban/current ← default.

      كل الإجراءات متاحة أيضًا كأمر slash في الـ gateway (/kanban …)، بنفس مساحة المعطيات — بما في ذلك الأوامر الفرعية لـ boards والخيار --board.

      للاطلاع على التصميم الكامل — المقارنة مع Cline Kanban وPaperclip وNanoClaw وGemini Enterprise، وأنماط التعاون الثمانية، وقصص المستخدمين الأربع، وإثبات صحة التزامن — راجع docs/hermes-kanban-v1-spec.pdf في المستودع أو دليل مستخدم Kanban.

      hermes egress​

      جدار حماية لحقن بيانات الاعتماد الصادرة لصناديق العزل (sandboxes) الطرفية البعيدة. يُغلّف عفريت iron-proxy — وهو وكيل (proxy) يعترض TLS ويستبدل tokens وكيل مبهمة ببيانات اعتماد API الحقيقية عند حدود الشبكة، بحيث لا تحمل صناديق العزل مفاتيح حقيقية أبدًا. معطّل افتراضيًا؛ راجع صفحة Egress proxy الكاملة للإعداد والبنية.

      hermes egress install                  # download the pinned iron-proxy binary
      hermes egress install --force          # re-download even if already installed

      hermes egress setup                    # interactive wizard: CA, mappings, config
      hermes egress setup --tunnel-port N    # override the tunnel listener port (default 9090)
      hermes egress setup --from-bitwarden   # use Bitwarden Secrets Manager as credential source
      hermes egress setup --no-bitwarden     # explicitly switch back to env-based credentials
      hermes egress setup --rotate-tokens    # mint fresh proxy tokens (default preserves existing)

      hermes egress start                    # spawn the managed proxy daemon
      hermes egress stop                     # SIGTERM (then SIGKILL after 5s grace)
      hermes egress restart                  # stop (if running) then start — needed for secret changes
      hermes egress reload                   # hot-reload the ruleset in-place (no restart, no dropped
                                             #   connections) via the loopback management API

      hermes egress status                   # binary + config + pid + listening + mappings
      hermes egress status --show-tokens     # print proxy tokens in full (default: redacted)

      hermes egress disable                  # flip proxy.enabled = false (does not stop a running proxy)
      hermes egress config                   # print the path to proxy.yaml for inspection

      hermes backup​

      hermes backup [options]

      إنشاء أرشيف zip لإعدادات Hermes ومهاراتك وجلساتك وبياناتك. يستبعد النسخ الاحتياطي كود hermes-agent نفسه، ولا يُضمِّن عناصر نسخ احتياطي سابقة (backups/، state-snapshots/) — كل منها يحتوي بالفعل على نسخته الخاصة من state.db.

      الخيارالوصف
      -o، --output <path>مسار الإخراج لملف zip (الافتراضي: ~/hermes-backup-<timestamp>.zip).
      -q، --quickلقطة سريعة: ملفات الحالة الحرجة فقط (config.yaml، state.db، .env، auth، مهام cron). أسرع بكثير من النسخ الاحتياطي الكامل.
      -l، --label <name>تسمية اللقطة (تُستخدم فقط مع --quick).
      -k، --keep <N>بعد نسخ احتياطي كامل، حذف ملفات hermes-backup-*.zip الأقدم في مجلد الإخراج بعد أحدث N ملفات (الافتراضي 3؛ 0 يحتفظ بالجميع). ملفات zip ذات الأسماء المخصصة لا تُمس أبدًا.

      يستخدم النسخ الاحتياطي واجهة backup() الخاصة بـ SQLite للنسخ الآمن، لذا يعمل بشكل صحيح حتى أثناء تشغيل Hermes (آمن مع وضع WAL).

      ما المستبعد من ملف zip:

      • *.db-wal، *.db-shm، *.db-journal — الملفات المرافقة لـ WAL / الذاكرة المشتركة / السجل الخاصة بـ SQLite. ملف *.db حصل بالفعل على لقطة متسقة عبر sqlite3.backup()؛ وإرفاق الملفات المرافقة الحية معه قد يجعل الاستعادة ترى حالة نصف منفَّذة.
      • checkpoints/ — ذواكر مؤقتة لمسار trajectory لكل جلسة. مُفهرسة بتجزئة (hash) ويُعاد توليدها لكل جلسة؛ لن تنتقل بشكل نظيف إلى تثبيت آخر على أي حال.
      • models/، runtimes/، node/ في جذر ~/.hermes (وفي كل profiles/<name>/) — تنزيلات وقت تشغيل قابلة لإعادة التوليد، غالبًا بعشرات الغيغابايتات. المجلدات الأعمق بنفس الأسماء (مثل models/ الخاص بمهارة ما) تُحفظ.
      • العناصر القابلة لإعادة التوليد ضمن cache/ في نفس تلك الجذور — كتالوجات النماذج/الإضافات، الأختام، ملفات تعريف المتصفح، فائض مخرجات الأدوات. القطع الدائمة تبقى في: cache/images، cache/audio، cache/videos، cache/documents، cache/screenshots (الوسائط المُسلَّمة إليك أو المستلمة منك) وcache/citations (سجل الاستشهادات المرجعية). المجلد cache/ الأعمق (داخل مهارة) يُحفظ كاملًا.
      • مقابس Unix، والأجهزة، والروابط الرمزية — لا يمكن لملف zip حملها؛ قبل استبعادها، كان وجود gateway.sock عرضيًا يجعل كل نسخة احتياطية كاملة تُبلّغ عن Backup incomplete.
      • كود hermes-agent نفسه (هذا نسخ احتياطي لبيانات المستخدم، وليس لقطة للمستودع).

      أمثلة​

      hermes backup                           # Full backup to ~/hermes-backup-*.zip
      hermes backup -o /tmp/hermes.zip        # Full backup to specific path
      hermes backup --quick                   # Quick state-only snapshot
      hermes backup --quick --label "pre-upgrade"  # Quick snapshot with label

      hermes checkpoints​

      hermes checkpoints [COMMAND]

      فحص وإدارة مخزن shadow git في ~/.hermes/checkpoints/ — طبقة التخزين خلف أمر /rollback داخل الجلسة. آمن للتشغيل في أي وقت؛ لا يتطلب تشغيل الوكيل.

      الأمر الفرعيالوصف
      status (الافتراضي)عرض الحجم الإجمالي وعدد المشاريع والتفصيل لكل مشروع. الأمر المجرد hermes checkpoints يكافئ هذا.
      listاسم بديل لـ status.
      pruneفرض تمريرة تنظيف — حذف المشاريع اليتيمة والقديمة، وتشغيل GC للمخزن، وفرض الحد الأقصى للحجم. يتجاهل علامة عدم التكرار (idempotency) الخاصة بـ 24 ساعة.
      clearحذف قاعدة نقاط الحفظ (checkpoint) بالكامل. لا رجعة فيه؛ يطلب تأكيدًا ما لم تُمرَّر -f.
      clear-legacyحذف أرشيفات legacy-<timestamp>/ الناتجة عن ترحيل v1←v2 فقط.

      الخيارات​

      الخيارالأمر الفرعيالوصف
      --limit Nstatus، listالحد الأقصى لعدد المشاريع المعروضة (الافتراضي 20).
      --retention-days Npruneإسقاط المشاريع التي مرّ على last_touch الخاص بها أكثر من N يوم (الافتراضي 7).
      --max-size-mb Npruneبعد تمريرة اليتيمة/القديمة، إسقاط أقدم commit لكل مشروع حتى يصبح حجم المخزن الإجمالي ≤ N ميغابايت (الافتراضي 500).
      --keep-orphanspruneتخطي حذف المشاريع التي لم يعد مجلد عملها موجودًا.
      -f، --forceclear، clear-legacyتخطي طلب التأكيد.

      أمثلة​

      hermes checkpoints                                  # status overview
      hermes checkpoints prune --retention-days 3         # aggressive cleanup
      hermes checkpoints prune --max-size-mb 200          # tighten size cap once
      hermes checkpoints clear-legacy -f                  # drop v1 archive dirs
      hermes checkpoints clear -f                         # wipe everything

      راجع نقاط الحفظ وأمر /rollback للاطلاع على البنية الكاملة وأوامر الجلسة.

      hermes import​

      hermes import <zipfile> [options]

      استعادة نسخة احتياطية من Hermes أُنشئت سابقًا إلى مجلد Hermes الرئيسي لديك. كل الملفات في الأرشيف تستبدل الملفات الموجودة في مجلد Hermes الرئيسي؛ --force يتخطى فقط طلب التأكيد الذي يظهر عندما يحتوي الهدف بالفعل على تثبيت Hermes.

      الخيارالوصف
      -f، --forceتخطي طلب تأكيد وجود تثبيت سابق.
      تحذير

      أوقف الـ gateway قبل الاستيراد لتجنب التعارضات مع العمليات قيد التشغيل.

      قواعد بيانات SQLite​

      عناصر .db (state.db، kanban.db، response_store.db، …) لا تُنشر بإعادة تسمية كما تُنشر الملفات العادية. إعادة التسمية كانت ستستبدل inode الملف بينما لا تزال عملية gateway أو dashboard أو WebUI تحتفظ بالملف القديم مفتوحًا: تلك العملية ستستمر في قراءة صفحات ما قبل الاستيراد وستستمر في كتابة جلسات لا يراها أحد آخر، وستكون تلك الجلسات ببساطة غائبة من قاعدة البيانات التي يفتحها الجميع لاحقًا — دون أي تسجيل. بدلًا من ذلك، تُكتب الصفحات المستوردة داخل ملف قاعدة البيانات الموجود، بنفس الطريقة التي ينفذها /snapshot restore، بحيث يتقارب كل اتصال مفتوح على البيانات المستوردة.

      إذا تعذّر استبدال قاعدة البيانات الحية بأمان — فشل نسخ الصفحات ولا تزال عملية أخرى تحتفظ بالملف مفتوحًا — يترك الاستيراد قاعدة البيانات تلك دون تغيير ويدرجها تحت Warnings (N files skipped). أوقف العمليات المحتفِظة بالملف وأعد التشغيل.

      استيراد نسخة احتياطية أقدم فوق عمل أحدث لا يزال مسموحًا، لكنه لم يعد صامتًا. عندما تحتوي state.db المستوردة على رسائل أقل من التي استبدلتها، يُبلّغ الملخص عن ذلك:

        ⚠ Session data replaced by older backup contents:
          state.db: 12 session(s) / 8912 message(s) -> 3 / 24
          Anything recorded after the backup was taken is not in it.
          Recover from a newer backup or snapshot: hermes snapshot list

      أمثلة​

      hermes import ~/hermes-backup-20260423.zip           # Prompts before overwriting existing config
      hermes import ~/hermes-backup-20260423.zip --force   # Overwrite without prompting

      hermes logs -f

      # View the last 100 lines of gateway.log
      hermes logs gateway -n 100

      hermes logs --level WARNING --since 1h

      hermes prompt-size​

      hermes prompt-size [--platform <name>] [--json]

      يُبلّغ عن ميزانية الـ prompt الثابتة لجلسة جديدة — ما يُرسل في كل استدعاء API قبل أي محتوى محادثة. مفيد عندما يكون لدى محوّل أو وكيل (proxy) لاحق ميزانية prompt أضيق من نافذة سياق النموذج، أو عندما تريد معرفة أي كتلة (فهرس المهارات، الذاكرة، الـ profile) تهيمن.

      يبني نفس system prompt الذي سيبنيه الوكيل، ثم يحلّله إلى:

      • إجمالي الـ system prompt — الـ prompt الكامل المجمَّع (الهوية، التوجيه، فهرس المهارات، ملفات السياق، الذاكرة، الـ profile، الطابع الزمني).
      • فهرس المهارات — كتلة <available_skills>. غالبًا ما تكون هذه أكبر كتلة منفردة عند تثبيت عدد كبير من المهارات.
      • الذاكرة وملف المستخدم — لقطات MEMORY.md / USER.md الخاصة بك.
      • مستويات الـ prompt — ثابت / سياق / متقلّب، بما يطابق طريقة تنظيم Hermes للـ prompt لتحقيق ملاءمة التخزين المؤقت.
      • مخططات الأدوات — JSON الخاص بكل الأدوات المفعّلة (النصف الآخر من الحمولة الثابتة لكل استدعاء).

      يعمل بالكامل دون اتصال — بلا استدعاء API، ويعمل دون أي بيانات اعتماد مضبوطة.

      # Human-readable breakdown for the CLI platform (default)
      hermes prompt-size

      # Simulate a messaging platform's prompt (different platform hint)
      hermes prompt-size --platform telegram

      # Machine-readable output for scripts
      hermes prompt-size --json

      النقاط داخل أسماء المفاتيح​

      يستخدم hermes config set/get/unset النقطة . كفاصل للتداخل، لكن كثيرًا من أسماء المفاتيح الفعلية تحتوي نقاطًا حرفية — معرّفات النماذج (grok-4.6، glm-5.3-flash)، معرّفات غرف Matrix (!room:example.org)، أسماء مزوّدين ذات إصدارات. قاعدتان تجعلان هذه قابلة للوصول:

      • المفاتيح الموجودة تعمل تلقائيًا. عند التنقل في تعيين موجود، يُفضَّل مفتاح حرفي موجود يطابق البقية المنقّطة على التقسيم. الأمر hermes config set providers.p.models.grok-4.6.supports_vision true يحدّث إدخال grok-4.6 الفعلي (وتحلّل get/unset بنفس الطريقة).
      • إنشاء مفتاح منقّط جديد يتطلب الإفلات (escaping). أفلت النقاط الحرفية بشرطة مائلة عكسية: الأمر hermes config set 'providers.p.models.grok-4\.7.context_length' 128000 ينشئ مفتاح grok-4.7 الحرفي. (ضع المفتاح بين علامتي اقتباس ليحافظ shell على الشرطة المائلة العكسية.)

      إذا كانت كتابة غير مُفلَتة ستنشئ تعيينًا متداخلًا يُظلّل مفتاحًا منقّطًا مجاورًا موجودًا بالفعل (مثل إنشاء grok-4 بجانب grok-4.6 موجود)، يفشل الأمر برسالة خطأ بدلًا من كتابة إدخال وهمي بصمت لن يقرأه وقت التشغيل أبدًا.

      إدارة موحّدة للإضافات — الإضافات العامة، ومزوّدو الذاكرة، ومحرّكات السياق في مكان واحد. تشغيل hermes plugins بلا أمر فرعي يفتح شاشة تفاعلية مركّبة بقسمين:

      • الإضافات العامة — مربعات اختيار متعددة لتفعيل/تعطيل الإضافات المثبَّتة
      • إضافات المزوّدين — إعداد باختيار واحد لمزوّد الذاكرة ومحرّك السياق. اضغط ENTER على فئة لفتح مُنتقي راديو.
      الأمر الفرعيالوصف
      (بلا أمر)واجهة تفاعلية مركّبة — مفاتيح إضافات عامة + إعداد إضافات مزوّدين.
      install <identifier> [--force] [--ref COMMIT_SHA] [--allow-removed]تثبيت إضافة من كتالوج إضافات Hermes (اسم إدخال مجرد)، أو رابط Git، أو اختصار owner/repo. أسماء الكتالوج تُحلّ إلى مستودع الإدخال عند commit SHA مثبَّت من 40 حرفًا سداسيًا عشريًا، وتعرض ملخص القدرات المُعلَن، وتسجّل مصدر الكتالوج في ملف مرافق .hermes-catalog.json. الروابط الخام تُعلَّم كمصادر مخصصة (غير مُراجَعة)؛ --ref (commit SHA كامل من 40 حرفًا) يثبّتها. --allow-removed (خطير) يتجاوز قائمة حظر الإضافات المُزالة.
      search [term] [--json]البحث في كتالوج إضافات Hermes (يطابق أسماء الإدخالات والأوصاف والأدوات المُعلَنة؛ حذف term يسرد الكل). الكتالوج مُنسَّق داخل المستودع (plugin-catalog/)، ويُحدَّث من المستودع الحي بذاكرة تخزين مؤقت مدتها 6 ساعات، ويرجع إلى النسخة الموجودة في الشجرة عند عدم الاتصال. مُدرَج في الكتالوج ≠ مُدقَّق؛ فالقبول يراجع الإدخال، لا الكود.
      update <name>سحب أحدث التغييرات لإضافة مثبَّتة غير مثبَّتة الإصدار (unpinned). الإضافات المثبَّتة الإصدار يجب إعادة تثبيتها بـ --force --ref <new-commit> للانتقال.
      remove <name> (أسماء بديلة: rm، uninstall)إزالة إضافة مثبَّتة.
      enable <name>تفعيل إضافة معطَّلة.
      disable <name>تعطيل إضافة دون إزالتها.
      list (اسم بديل: ls)سرد الإضافات المثبَّتة مع حالة التفعيل/التعطيل.
      doctor [path-or-id] [--ci]التحقق من صحة إضافة أصلية عبر محلّل المانفست الفعلي، والمُحمِّل، ومسار التسجيل. --ci يخرج بالرمز 1 عند وجود أخطاء.
      pack install <path-or-url> [--force]تثبيت حزمة إضافات (hermes-pack.yaml) — مجموعة تصريحية من الإضافات كل منها مثبَّت عند commit SHA دقيق من 40 حرفًا. تعرض شاشة مراجعة إلزامية (كل إضافة ومصدرها والمرجع المثبَّت والقدرات المُعلَنة)، وتطلب تأكيدًا واحدًا لمحتويات الحزمة، ثم تنفّذ عمليات تثبيت عادية مثبَّتة الإصدار. كل إضافة تمر قدراتها المُعلَنة عبر الموافقة القياسية لكل إضافة — فالحزمة لا تمنح صلاحيات جماعية أبدًا. تُبلَّغ الإخفاقات الجزئية لكل إضافة؛ ويخرج برمز غير صفري إذا فشلت أي إضافة. تفاعلي فقط (بلا --yes).
      pack export [--enabled-only] [--name NAME]إخراج YAML حزمة على stdout من التثبيت الحالي: المستودع + SHA الدقيق لكل إضافة مثبَّتة عبر git إضافة إلى إعدادات plugins.entries غير السرية المُنقَّاة. الإضافات المحلية فقط (بلا مصدر git) تُدرَج كتعليقات تحذير، لا كإدخالات قابلة للتثبيت. الأسرار ومنح القدرات وبوابات allow_* تُزال دائمًا.
      pack show <path-or-url>تشغيل تجريبي: تحليل والتحقق من صحة وعرض حزمة دون تثبيت أي شيء.

      تُحفَظ اختيارات إضافات المزوّدين في config.yaml:

      • memory.provider — مزوّد الذاكرة النشط (فارغ = المدمج فقط)
      • context.engine — محرّك السياق النشط ("compressor" = الافتراضي المدمج)

      قائمة الإضافات العامة المعطَّلة مخزَّنة في config.yaml تحت plugins.disabled. كذلك تثبيتات git تسجّل فقط مصدرها المرجعي، والمراجعة المثبَّتة الدقيقة، وحالة التثبيت في ملف الـ profile المحلي المرافق plugins/.install-metadata.json. وهو لا يحتوي إعدادات الإضافة، أو قيم البيئة، أو الأسرار، أو منح القدرات.

      إذا كان cua-driver موجودًا بالفعل، يتحقق Hermes من إصداره وبيان تشغيله (manifest). تُترَك النسخة 0.20.0 أو الأحدث المتوافقة كما هي. أما التثبيت القديم أو غير المكتمل القياسي فيُصلَح بالمُثبِّت الرسمي الحالي. لا يستبدل Hermes أبدًا ثنائيًا مخصصًا مُحدَّدًا عبر HERMES_CUA_DRIVER_CMD؛ حدّث ذلك الثنائي مباشرةً أو أزل التجاوز. يبلّغ hermes computer-use status عند الحاجة إلى إصلاح.

      toolset computer_use المدمج هو التكامل المُوصى به مع Hermes. أما تسجيل أدوات Cua MCP الخام فبديل عندما تحتاج إلى مفردات الأدوات منخفضة المستوى الخاصة بـ Cua. يكتشف cua-driver skills install وجود Hermes ويربط حزمة مهارات Cua بمجلد مهارات Hermes تلقائيًا.

      وضع الأذونات والموافقة على بيان القدرات تنتمي إلى إطلاق وقت التشغيل. في الوضع المقيَّد، يمرّر Hermes علامتَي Cua الرسميتين --capability-manifest و--approve-capability-manifest. كل نقل MCP يملك جلسة دورة حياة خاصة داخل وقت تشغيله. أسماء الجلسات العامة تسمّي حالة المؤشر والجلسة؛ ولا تملك وقت التشغيل أو تشاركه.

      يعيد hermes update تشغيل المُثبِّت الرسمي تلقائيًا في نهاية التحديث إذا كان cua-driver موجودًا في PATH، لذا لن يحتاج معظم المستخدمين لاستدعاء --upgrade يدويًا. استخدمه عندما يُصدر upstream إصلاحًا تريده فورًا دون انتظار تحديث Hermes التالي.

      الأوامر الفرعية:

      الأمر الفرعيالوصف
      listسرد الجلسات الأخيرة.
      browseمُنتقي جلسات تفاعلي مع بحث واستئناف. يعرض كل صف علامة حالة دورة الحياة (done / intr / err / empty، مُستنتَجة من الرسالة الأخيرة للجلسة) وعدد رسائلها. اضغط d على صف مُحدَّد (بينما مرشّح البحث فارغ) لحذف تلك الجلسة بعد تأكيد y/N؛ وأثناء تفعيل مرشّح، يكتب d في البحث بدلًا من ذلك.

      statsعرض إحصاءات مخزن الجلسات.
      rename <session-id> <title>ضبط أو تغيير عنوان جلسة.
      optimizeاسترجاع مساحة القرص: دمج قطاعات فهرس FTS5 + VACUUM. غير مُخرِّب — لا تتغير بيانات الجلسات.
      optimize-storageترحيل فهرس البحث النصي الكامل إلى تخطيط v23 المضغوط ذي المحتوى الخارجي؛ يستعيد هذا في قواعد البيانات الكبيرة جزءًا كبيرًا من حجم state.db.
      repairإصلاح مخطط state.db المُشوَّه (مثل table messages_fts already exists) بحيث تعود الجلسات المخفية للظهور؛ تُؤخَذ نسخة احتياطية أولًا.
      repair-routingإعادة ربط محادثات gateway العالقة في صفوف جلسات فقدت هوية توجيهها (محادثة "تقفز إلى الوراء في الزمن" بعد إعادة تشغيل). تشغيل تجريبي افتراضيًا؛ --apply ينفّذ عمليات التبنّي (أوقف الـ gateway أولًا)؛ --max-gap-seconds N يضبط نافذة التجاور. تُصلَح فقط الحالات غير الملتبسة. راجع الجلسات ← إصلاح جلسات gateway العالقة.
      recoverاسترجاع دون اتصال وغير مُخرِّب لـ state.db تالف إلى قاعدة بيانات نظيفة منفصلة.
      retitle-skillsإعادة توليد عناوين للجلسات المفتوحة بأمر /skill، باستخدام ما كتبه المستخدم فعليًا؛ يسرد التغييرات ما لم تُمرَّر --apply.

      hermes claw​

      hermes claw migrate [options]

      الانتقال بإعداد OpenClaw لديك إلى Hermes. يقرأ من ~/.openclaw (أو مسار مخصص) ويكتب إلى ~/.hermes. يكتشف تلقائيًا أسماء المجلدات القديمة (~/.clawdbot، ~/.moltbot) وأسماء ملفات الإعدادات (clawdbot.json، moltbot.json).

      الخيارالوصف
      --dry-runمعاينة ما سيُنقَل دون كتابة أي شيء.
      --preset <name>نمط الانتقال المسبق: full (كل الإعدادات المتوافقة) أو user-data (يستبعد إعدادات البنية التحتية). لا يستورد أي من النمطين الأسرار — مرّر --migrate-secrets صراحةً.
      --overwriteاستبدال ملفات Hermes الموجودة عند التعارض (الافتراضي: رفض التطبيق عندما تحتوي الخطة على تعارضات).
      --migrate-secretsتضمين مفاتيح API في الانتقال. مطلوب حتى مع --preset full.
      --no-backupتخطي لقطة zip قبل الانتقال لـ ~/.hermes/ (افتراضيًا تُكتَب أرشيف نقطة استعادة واحدة إلى ~/.hermes/backups/pre-migration-*.zip قبل التطبيق؛ قابلة للاستعادة عبر hermes import).
      --source <path>مجلد OpenClaw مخصص (الافتراضي: ~/.openclaw).
      --workspace-target <path>المجلد الهدف لتعليمات مساحة العمل (AGENTS.md).
      --skill-conflict <mode>التعامل مع تعارض أسماء المهارات: skip (الافتراضي)، overwrite، أو rename.
      --yesتخطي طلب التأكيد.

      ما الذي يُنقَل​

      يغطي الانتقال أكثر من 30 فئة عبر الشخصية، والذاكرة، والمهارات، ومزوّدي النماذج، ومنصات المراسلة، وسلوك الوكيل، وسياسات الجلسات، وخوادم MCP، وTTS، وغيرها. تُستورَد العناصر إما مباشرةً إلى مكافئاتها في Hermes أو تُؤرشَف للمراجعة اليدوية.

      مستوردة مباشرةً: SOUL.md، MEMORY.md، USER.md، AGENTS.md، المهارات (4 مجلدات مصدر)، النموذج الافتراضي، المزوّدون المخصصون، خوادم MCP، رموز وقوائم سماح منصات المراسلة (Telegram وDiscord وSlack وWhatsApp وSignal وMatrix وMattermost)، إعدادات الوكيل الافتراضية (مستوى التفكير، الضغط، تأخير التفاعل البشري، المنطقة الزمنية، sandbox)، قواعد الموافقة، إعدادات TTS، إعدادات المتصفح، إعدادات الأدوات، مهلة التنفيذ، قائمة سماح الأوامر، إعدادات الـ gateway، ومفاتيح API من 3 مصادر.

      مؤرشفة للمراجعة اليدوية: مهام cron، والإضافات، وhooks/webhooks، وخلفية الذاكرة (QMD)، وإعدادات سجل المهارات، وواجهة المستخدم/الهوية، والتسجيل، وإعداد تعدد الوكلاء، وربط القنوات، وIDENTITY.md، وTOOLS.md، وHEARTBEAT.md، وBOOTSTRAP.md.

      يفحص تحليل مفتاح API ثلاثة مصادر بترتيب الأولوية: قيم الإعدادات ← ~/.openclaw/.env ← auth-profiles.json. كل حقول الرموز تتعامل مع النصوص العادية، وقوالب البيئة (${VAR})، وكائنات SecretRef.

      للاطلاع على خريطة تحويل مفاتيح الإعدادات الكاملة، وتفاصيل معالجة SecretRef، وقائمة التحقق بعد الانتقال، راجع دليل الانتقال الكامل.

      أمثلة​

      # Preview what would be migrated
      hermes claw migrate --dry-run

      # Full migration (all compatible settings, no secrets)
      hermes claw migrate --preset full

      # Full migration including API keys
      hermes claw migrate --preset full --migrate-secrets

      # Migrate user data only (no secrets), overwrite conflicts
      hermes claw migrate --preset user-data --overwrite

      # Migrate from a custom OpenClaw path
      hermes claw migrate --source /home/user/old-openclaw

      hermes serve​

      hermes serve [options]

      تشغيل خادم Hermes الخلفي — gateway الـ JSON-RPC/WebSocket الذي يتصل به تطبيق desktop والعملاء البعيدون. إنه نفس الخادم الذي يشغّله hermes dashboard، لكن بلا واجهة (headless): لا يفتح واجهة متصفح أبدًا. يطلق تطبيق desktop خلفيته الخاصة من hermes serve؛ استخدم هذا الأمر مباشرةً عندما تريد خلفية بلا واجهة على مضيف بعيد. يقبل نفس خيارات --host / --port / --insecure / --skip-build / --stop / --status الخاصة بـ hermes dashboard أدناه (الربط بعنوان غير loopback يُفعِّل نفس بوابة المصادقة). يتطلب الإضافة [web]؛ ويحتاج مقبس Chat المدمج إضافةً إلى [pty] على مضيف POSIX.

      تعارضات المنفذ: إذا كان المنفذ المطلوب (الافتراضي 9119) مشغولًا بالفعل بواسطة عملية أخرى (مثل hermes serve ثانٍ أو الـ gateway)، يطبع الأمر سطر إشارة قابل للمعالجة آليًا BACKEND_PORT_IN_USE port=<port> على stdout، مع تلميح مقروء للبشر يذكر المُحتمِل الشاغل للمنفذ، ويخرج برمز 75 (EX_TEMPFAIL) بدلًا من خطأ عام — بحيث تستطيع السكربتات وتطبيق desktop التمييز بين "منفذ مشغول" و"الخلفية معطَّلة". مرّر --port 0 لربط منفذ عشوائي متاح (الإقلاع الناجح يعلن المنفذ المختار عبر HERMES_BACKEND_READY port=<port>).

      hermes dashboard​

      hermes dashboard [options]

      إطلاق لوحة التحكم على الويب — واجهة مستخدم عبر المتصفح لإدارة الإعدادات ومفاتيح API ومراقبة الجلسات. (للحصول على خلفية بلا واجهة متصفح — مثل ما يطلقه تطبيق desktop — استخدم hermes serve أعلاه.) يتطلب cd ~/.hermes/hermes-agent && uv pip install -e ".[web]" (FastAPI + Uvicorn). تبويب Chat المدمج في المتصفح متاح دائمًا ويحتاج إضافةً إلى الإضافة pty (cd ~/.hermes/hermes-agent && uv pip install -e ".[web,pty]") وبيئة PTY من نوع POSIX مثل Linux أو macOS أو WSL2. راجع لوحة تحكم Hermes على الويب للتوثيق الكامل.

      الخيارالافتراضيالوصف
      --port9119المنفذ لتشغيل خادم الويب عليه
      --host127.0.0.1عنوان الربط
      --no-open—عدم فتح المتصفح تلقائيًا
      --insecureمعطَّلمهمل (deprecated) / بلا تأثير. كان سابقًا يتخطى المصادقة عند الربط بعنوان غير loopback. منذ تعزيز يونيو 2026 الأمني، يتطلب الربط العام دائمًا مزوّد مصادقة (كلمة مرور أو OAuth). اربط بـ 127.0.0.1 واستخدم نفقًا (tunnel) لإبقائه محليًا.
      --skip-buildمعطَّلتخطي خطوة بناء واجهة الويب وتقديم مجلد dist الموجود مباشرةً. مفيد في السياقات غير التفاعلية (Windows Scheduled Tasks، CI) حيث npm غير متاح. ابنِ مسبقًا بـ cd web && npm run build.
      --isolatedمعطَّلعند الإطلاق من profile مُسمّى (worker dashboard)، يشغّل خادمًا مخصصًا لكل profile بدلًا من التوجيه إلى لوحة تحكم الجهاز.
      --stop—إيقاف عمليات hermes dashboard قيد التشغيل والخروج.
      --status—سرد عمليات hermes dashboard قيد التشغيل والخروج.

      hermes profile​

      hermes profile <subcommand>

      إدارة profiles — نُسخ Hermes متعددة معزولة، لكل منها إعداداتها وجلساتها ومهاراتها ومجلدها الرئيسي الخاص.

      الأمر الفرعيالوصف
      listسرد كل الـ profiles.
      use <name>ضبط profile افتراضي ثابت.
      create <name> [--clone] [--clone-all] [--clone-from <source>] [--no-alias]إنشاء profile جديد. --clone ينسخ الإعدادات، و.env، وSOUL.md، والمهارات، وملفات الذاكرة المُنقَّحة MEMORY.md/USER.md من الـ profile النشط. --clone-all ينسخ كل الحالة. --clone-from يحدّد profile مصدر ويستلزم نسخ الإعدادات ما لم يُقترَن بـ --clone-all.
      delete <name> [-y]حذف profile.
      show <name>عرض تفاصيل profile (المجلد الرئيسي، الإعدادات، إلخ).
      alias <name> [--remove] [--name NAME]إدارة سكربتات wrapper للوصول السريع إلى profile.
      rename <old> <new>إعادة تسمية profile.
      export <name> [-o FILE]تصدير profile إلى أرشيف .tar.gz (نسخة احتياطية محلية).
      import <archive> [--name NAME]استيراد profile من أرشيف .tar.gz (استعادة محلية).
      install <source> [--name N] [--alias] [--force] [-y]تثبيت توزيعة profile من رابط git أو مجلد محلي.
      update <name> [--force-config] [-y]إعادة سحب توزيعة؛ يحافظ على بيانات المستخدم (الذكريات، الجلسات، المصادقة).
      info <name>عرض مانفست توزيعة profile (الإصدار، المتطلبات، المصدر).

      أمثلة:

      hermes profile list
      hermes profile create work --clone
      hermes profile use work
      hermes profile alias work --name h-work
      hermes profile export work -o work-backup.tar.gz
      hermes profile import work-backup.tar.gz --name restored
      hermes profile install github.com/user/my-distro --alias
      hermes profile update work
      hermes -p work chat -q "Hello from work profile"

      hermes update​

      hermes update [--gateway] [--check] [--plan] [--no-backup] [--backup] [--yes]

      يسحب أحدث كود hermes-agent ويعيد تثبيت التبعيات في venv المُدار، ثم يعيد تشغيل hooks ما بعد التثبيت (خوادم MCP، مزامنة المهارات، تثبيت الإكمال). آمن للتشغيل على تثبيت حيّ. استخدم --check لمعرفة ما إذا كانت نسختك المسحوبة متأخرة عن origin/main دون التثبيت.

      يسحب hermes update فرع التحديث المضبوط (الافتراضي: main). إذا كانت نسختك المسحوبة على فرع آخر، قد يحوّل Hermes إلى فرع التحديث قبل السحب. أَودِع (commit) عمل الفرع قبل التحديث إذا أردت إبقاءه خارج تدفق autostash الخاص بالتحديث.

      الخيارالوصف
      --gatewayوضع داخلي يستخدمه أمر /update في المراسلة. يستخدم IPC القائم على الملفات للطلبات وبث التقدم بدلًا من القراءة من stdin الطرفية. ليس علامة لإعادة تشغيل gateway.
      --checkالتحقق من توفر تحديث دون السحب أو تثبيت التبعيات أو إعادة تشغيل أي شيء.
      --planطباعة خطة التحديث والخروج دون تغيير أي شيء: نوع التثبيت (git/Docker/Nix/apt)، وكل خدمة Hermes قيد التشغيل عبر جميع profiles مع المُشرِف (supervisor) وإصدار الكود قيد التشغيل، وكيفية إعادة تشغيل كل منها. في التثبيتات المُدارة بصورة (image) أو حزمة، يُبلَّغ عن أمر التحديث الخارجي الصحيح بدلًا من ذلك. للقراءة فقط.
      --no-backupتخطي كل النسخ الاحتياطية قبل التحديث لهذا التشغيل (كلًا من لقطة الحالة السريعة وملف zip الكامل)، بغض النظر عن updates.pre_update_backup.
      --backupفرض نسخة احتياطية كاملة قبل التحديث لهذا التشغيل: لقطة الحالة السريعة إضافةً إلى ملف zip كامل لـ HERMES_HOME (الإعدادات، المصادقة، الجلسات، المهارات، بيانات الاقتران). الوضع الافتراضي هو quick — لقطة حالة خفيفة فقط. اضبط الوضع الدائم عبر `updates.pre_update_backup: quick
      --yes، -yافتراض الموافقة على الطلبات التفاعلية مثل ترحيل الإعدادات واستعادة stash. يُتخطى إدخال مفتاح API؛ شغّل hermes config migrate منفصلًا لذلك.

      سلوك إضافي:

      • إعادة تشغيل الـ gateway. بعد تحديث ناجح، يحاول Hermes إعادة تشغيل كل profiles الـ gateway قيد التشغيل تلقائيًا ليأخذوا الكود الجديد. استخدم hermes gateway restart عندما تريد إعادة تشغيل gateway دون تطبيق تحديث.
      • استرجاع مرحلة إعادة التشغيل. إذا أُجهضت مرحلة إعادة التشغيل داخل العملية أثناء استيراد الشجرة المسحوبة حديثًا، تُعاد محاولة profiles الـ gateway المُشرَف عليها عبر عملية Python نظيفة. فقط عمليات إعادة الإطلاق المؤكَّدة بشكل مستقل بواسطة systemd (systemctl --user is-active) تُسجَّل كمُتحقَّق منها؛ أما إعادة الإطلاق التي خرجت برمز 0 فقط فتُسجَّل كـ relaunch_attempted ولا تزال تُفشِل التحديث بحذر. خوادم gateway اليدوية وأوقات تشغيل serve/dashboard لا تُقتَل أبدًا دون سلطة إعادة إطلاق؛ تُسجَّل كمتخطاة مع سبب وتبقى في تقرير التحديث غير المكتمل مع أمر إعادة التشغيل الدقيق.
      • إيصالات التحديث + فحص إصدار الأسطول. كل تشغيل يكتب إيصالًا قابلًا للمعالجة آليًا إلى ~/.hermes/logs/update_receipts/ (خطة الأسطول قبل التحديث، الخطوات، التخطيات مع أسبابها، نتيجة إعادة التشغيل؛ latest.json يشير إلى الأحدث). بعد مرحلة إعادة التشغيل، يتحقق المحدِّث من كود كل gateway حيّ قيد التشغيل مقابل النسخة المسحوبة المحدَّثة ويطبع مصفوفة إصدارات لكل profile؛ أي gateway لا يزال على كود ما قبل التحديث يُفشِل التحديث (رمز الخروج 1) مع أمر إعادة التشغيل الدقيق.
      • تغييرات المصدر المحلية. بالنسبة لتثبيتات git، تُخزَّن (auto-stash) الملفات المُتتبَّعة المتسخة والملفات غير المُتتبَّعة تلقائيًا قبل تحويل الفرع أو السحب (git stash push --include-untracked). التحديثات في طرفية تفاعلية تطلب تأكيدًا قبل استعادة الـ stash. التحديثات غير التفاعلية تستعيده افتراضيًا؛ اضبط updates.non_interactive_local_changes: discard فقط على التثبيتات المُدارة حيث ينبغي التخلص من تعديلات المصدر المحلية بعد سحب ناجح. إذا تعارضت استعادة الـ stash أو فشل السحب، يُترَك الـ stash في مكانه للاسترجاع اليدوي.
      • تراكم ملف قفل npm. قبل الـ stash أو تحويل الفروع، يجري Hermes تنظيفًا بأفضل جهد لفروقات package-lock.json المُتتبَّعة الناتجة عن خطوات npm install/build. أَودِع (commit) أو خزِّن (stash) يدويًا تعديلات ملف القفل المقصودة قبل تشغيل hermes update.
      • لقطة بيانات الاقتران. حتى عندما يكون --backup معطَّلًا، يأخذ hermes update لقطة خفيفة من ~/.hermes/pairing/ وقواعد تعليقات Feishu قبل git pull. يمكنك التراجع عنها بـ hermes backup restore --state pre-update إذا أعاد السحب كتابة ملف كنت تعدّله.
      • تحذير hermes.service القديم. إذا اكتشف Hermes وحدة systemd سابقة لإعادة التسمية باسم hermes.service (بدلًا من hermes-gateway.service الحالية)، يطبع تلميح ترحيل لمرة واحدة لتجنب مشكلات حلقة التذبذب (flap-loop).
      • رموز الخروج. 0 عند النجاح، 1 عند أخطاء السحب/التثبيت/ما بعد التثبيت، 2 عند تغييرات غير متوقعة في شجرة العمل تعيق git pull.
