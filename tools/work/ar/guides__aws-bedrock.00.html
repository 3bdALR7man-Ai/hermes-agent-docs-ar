AWS Bedrock

تستخدم أوامر اعتماديات Python في هذه الصفحة نسخة مصدر مسحوبة ومجهّزة عبر PM. بعد تغيير أي اعتمادية، أعد تفعيل النسخة المسحوبة وأعد تشغيل Hermes.

يدعم Hermes Agent خدمة Amazon Bedrock بوصفها مزوّدًا (provider) أصيلًا. ويمنحك ذلك وصولًا كاملًا إلى منظومة Bedrock: مصادقة IAM، و Guardrails، و inference profiles العابرة للمناطق، وجميع النماذج الأساسية (foundation models).

يوجّه Hermes كل عائلة نماذج عبر الـ API الأنسب لخدمتها:

تتشارك المسارات الثلاثة سلسلة بيانات اعتماد AWS نفسها وآلية تحديد المنطقة نفسها — فلا حاجة إلى أي إعداد منفصل. تُصادَق الطلبات الموجّهة إلى endpoint الخاص بـ Mantle باستخدام AWS_BEARER_TOKEN_BEDROCK عند ضبطه، وإلا فتُوقَّع بـ SigV4 عبر سلسلة بيانات الاعتماد القياسية في boto3.

المتطلبات المسبقة

  • بيانات اعتماد AWS — أي مصدر تدعمه سلسلة بيانات الاعتماد في boto3:
    • دور IAM للمثيل (EC2، و ECS، و Lambda — دون أي إعداد)
    • AWS_ACCESS_KEY_ID + AWS_SECRET_ACCESS_KEY كمتغيرات بيئة
    • AWS_PROFILE لـ SSO أو الـ profiles المسمّاة
    • aws configure للتطوير المحلي
  • boto3 — ثبّته باستخدام cd ~/.hermes/hermes-agent && python -c "import pm; pm.sync_venv(['bedrock'], explicit=True)"
  • صلاحيات IAM — كحد أدنى:
    • bedrock:InvokeModel و bedrock:InvokeModelWithResponseStream (للـ inference)
    • bedrock:ListFoundationModels و bedrock:ListInferenceProfiles (لاكتشاف النماذج)
    • bedrock:GetInferenceProfile (فقط إذا كانت model.default تمثل ARN لـ application inference profile — ويُستخدم لتحديد حجم context window من النموذج المغلّف)
EC2 / ECS / Lambda

على موارد الحوسبة في AWS، أرفق دور IAM يحمل AmazonBedrockFullAccess وانتهى الأمر. لا مفاتيح API، ولا إعدادات .env — إذ يكتشف Hermes دور المثيل تلقائيًا.

Guardrails

لتطبيق Amazon Bedrock Guardrails على جميع استدعاءات النماذج:

يُرفق الـ guardrail على مسار Converse (guardrailConfig) وعلى مسار Claude (عبر ترويسات InvokeModel من خلال Anthropic Bedrock SDK، بحيث يُحافظ على التخزين المؤقت للـ prompt والتفكير). ويظهر الطلب المحظور على شكل رفض من مرشّح المحتوى بدلًا من نص صادر عن النموذج. ولا ينطبق stream_processing_mode إلا على Converse.

لا تطبّق AWS خدمة Guardrails على endpoint الخاص بـ Mantle Responses المستخدم لمعرّفات openai.gpt-* المجرّدة (وثائق AWS). استخدم نموذجًا يقدّمه Converse، مثل inference profile لـ OpenAI يبدأ بـ us. أو global.، عندما تحتاج إلى guardrail.

اكتشاف النماذج

يكتشف Hermes النماذج المتاحة تلقائيًا عبر مستوى التحكم (control plane) في Bedrock. ويمكنك تخصيص الاكتشاف:

التخزين المؤقت للـ Prompt (cachePoint)

يطبّق Hermes التخزين المؤقت للـ prompt تلقائيًا على مسار Converse API في Bedrock عبر إدراج علامات cachePoint بعد الـ system prompt، وتعريفات الأدوات، وآخر رسالة. ولأن إرسال كتلة cachePoint إلى نموذج لا يدعمها يُطلق ValidationException، فلا تُضاف العلامات إلا للنماذج الموجودة في قائمة سماح معروفة السلامة (معرّفات نماذج Anthropic Claude و Amazon Nova)؛ أما النماذج غير المعروفة فلا تُضاف لها علامات cache افتراضيًا. تستخدم نماذج Claude عادةً مسار AnthropicBedrock SDK الذي يمتلك تخزينه المؤقت الخاص للـ prompt — ويغطي مسار cachePoint في Converse نماذج Nova والمسار الاحتياطي لـ Claude القائم على bearer token. لا حاجة إلى أي إعداد؛ وتظهر عمليات القراءة/الكتابة في الـ cache ضمن حساب الاستخدام.

استكشاف حجم الـ Context window

بالنسبة إلى النماذج التي لا يوجد حجم context window الخاص بها في الجدول الثابت لدى Hermes، يستطيع Hermes استكشاف الحد الفعلي بإرسال طلبات كبيرة الحجم عمدًا على مستويات ثابتة (~1.3M و ~2.2M token) وتحليل قيمة maximum الواردة في خطأ التحقق من الطول في Bedrock. تغذّي القيم المستكشفة ذاكرة البيانات الوصفية المؤقتة نفسها التي يستخدمها الجدول الثابت؛ وتُحذف تلقائيًا المدخلات القديمة التي تقلّل من حجم نافذة النموذج (مثل المدخلات التي أُنشئت قبل الإتاحة العامة لنافذته ذات 1M) لصالح القيمة الأكبر المعروفة.

إذا لم يعرف الاستكشاف ولا الجدول الثابت نموذجًا، يستخدم Hermes قيمة احتياطية قدرها 128,000 token ويسجّل WARNING يذكر اسم النموذج. اضبط model.context_length في config.yaml على الحجم الفعلي لنافذة النموذج.

Application inference profiles. لا يذكر ARN مثل arn:aws:bedrock:us-west-2:123456789012:application-inference-profile/abcdef123456 أي نموذج، لذا لا يستطيع الاستكشاف ولا الجدول الثابت تحديد حجمه. يستدعي Hermes bedrock:GetInferenceProfile في منطقة ARN ويحدد النافذة من النموذج الذي يغلّفه الـ profile (1M لـ profile يغلّف Claude Sonnet 4.6). ودون هذه الصلاحية تُطبّق القيمة الافتراضية 128,000 token، ويذكر WARNING اسم الـ profile؛ اضبط model.context_length صراحةً لتجاوز القيمة في الحالتين.

Inference عابر للمناطق (Cross-Region)

تستخدم النماذج التي تبدأ بالبادئة us. ملفات inference profiles العابرة للمناطق، والتي توفّر سعة أفضل وتحويلًا تلقائيًا عند الأعطال (failover) بين مناطق AWS. أما النماذج التي تبدأ بالبادئة global. فتوجَّه عبر جميع المناطق المتاحة عالميًا.

لنماذج OpenAI صيغتان للـ endpoint. معرّف openai.* المجرّد خاص بالمنطقة، ويرسله Hermes إلى endpoint الخاص بـ Responses في Bedrock Mantle ضمن المنطقة المضبوطة. أما معرّفا us.openai.* و global.openai.* فهما inference profiles عابرة للمناطق. ويرسلهما Hermes إلى bedrock-runtime عبر Converse API، وهو المسار نفسه المستخدم للـ inference profiles الأخرى. تسرد بطاقة كل نموذج لدى AWS الـ profiles التي يتيحها والمناطق التي يقدّمه Mantle فيها.

استكشاف الأخطاء وإصلاحها

"No API key found" / "No AWS credentials"

يبحث Hermes عن بيانات الاعتماد بالترتيب التالي:

  1. AWS_BEARER_TOKEN_BEDROCK
  2. AWS_ACCESS_KEY_ID + AWS_SECRET_ACCESS_KEY
  3. AWS_PROFILE
  4. البيانات الوصفية لمثيل EC2 (IMDS)
  5. بيانات اعتماد حاوية ECS
  6. دور التنفيذ في Lambda

إذا لم يُعثر على أيٍّ منها، فشغّل aws configure أو أرفق دور IAM بمثيل الحوسبة لديك.

"Invocation of model ID ... with on-demand throughput isn't supported"

استخدم معرّف inference profile (يبدأ بالبادئة us. أو global.) بدلًا من معرّف النموذج الأساسي المجرّد. على سبيل المثال:

  • ❌ anthropic.claude-sonnet-4-6
  • ✅ us.anthropic.claude-sonnet-4-6

"ThrottlingException"

لقد بلغت حدّ المعدل (rate limit) الخاص بكل نموذج في Bedrock. يعيد Hermes المحاولة تلقائيًا مع تأخير متزايد (backoff). ولزيادة الحدود، اطلب رفع الحصة من وحدة تحكم AWS Service Quotas.
