الإضافات المدمجة

يأتي Hermes مع مجموعة صغيرة من الإضافات المضمّنة في المستودع. توجد هذه الإضافات تحت <repo>/plugins/<name>/ وتُحمَّل تلقائيًا إلى جانب الإضافات التي يثبّتها المستخدم في ~/.hermes/plugins/. وتستخدم واجهة الإضافات نفسها التي تستخدمها إضافات الجهات الخارجية — hooks، والأدوات، و slash commands — مع فارق أنها تُصان داخل شجرة المستودع.

راجع صفحة الإضافات (Plugins) للتعرف على نظام الإضافات عمومًا، وصفحة بناء إضافة لـ Hermes لكتابة إضافتك الخاصة.

كيف يعمل الاكتشاف

يفحص PluginManager أربعة مصادر، بالترتيب التالي:

  1. المضمّنة (Bundled) — <repo>/plugins/<name>/ (وهي موضوع هذه الصفحة)
  2. المستخدم (User) — ~/.hermes/plugins/<name>/
  3. المشروع (Project) — ./.hermes/plugins/<name>/ (يتطلب HERMES_ENABLE_PROJECT_PLUGINS=1)
  4. نقاط دخول Pip — hermes_agent.plugins

عند تعارض الأسماء، تكون الأولوية للمصادر اللاحقة — فإضافة مستخدم باسم disk-cleanup ستحل محل الإضافة المضمّنة.

يُستثنى plugins/memory/ و plugins/context_engine/ عمدًا من فحص الإضافات المضمّنة. إذ تستخدم هذه المجلدات مسارات اكتشاف خاصة بها، لأن مزوّدي الذاكرة ومحركات السياق (context engines) مزوّدون يُختار واحد منهم فقط، ويُعدّون عبر hermes memory setup / context.engine في الإعدادات.
