معلومة

ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

مهارة IP as Logo

أنشئ أبسط شخصية IP لطيفة ممكنة: رمزًا متراصًا محبّبًا يظل قابلًا للتعرّف عليه بحجم 32 × 32 ، لا رسمًا تفصيليًا لشخصية.

ملاحظات التكييف مع Hermes (بقية هذا المستند هي سير العمل الأصلي، محفوظًا دون تغيير — لقطة من s1dashu/ip-as-logo-skill عند commit b1bf517c، بتاريخ 20 أغسطس 2026، بترخيص MIT — راجع LICENSE):

  • مسار توليد الصور: استخدم الأداة المدمجة image_generate مع aspect_ratio="square". يضبط المستخدم backend النشط — فلا تختر النماذج أو تبدّلها. وتتلقى backends الحديثة المتّبعة للتعليمات (GPT Image و Seedream و FLUX و Grok Imagine) قالب الـ prompt كاملًا مع سطر Constraints: باللغة الطبيعية؛ ولا تتيح image_generate معاملًا باسم negative_prompt ، لذا استخدم دائمًا وضع القيود داخل الـ prompt الرئيسي الموصوف أدناه.
  • المرشّحات المتوازية: عندما يذكر النص الأصلي "subagents"، استخدم delegate_task مع مهمة لكل مرشّح فقط إذا أراد المستخدم السرعة وكانت الدفعة كبيرة؛ وإلا فاستدعاءات image_generate المتتابعة في دور واحد أبسط وتُبقي كل النتائج في هذه المحادثة.
  • حفظ النتائج: تعيد image_generate عنوان URL أو مسار ملف. سلّم كل مرشّح إلى المستخدم مع تسميته (تسري أعراف تسليم الملفات الخاصة بالمنصة)؛ ولا تُعِد استضافته أو تعالجه لاحقًا.
  • ضمان الجودة: وفق قواعد التسليم أدناه، لا تفحص المرشّحات أو تعيد محاولتها أو ترشّحها تلقائيًا. ولا تشغّل vision_analyze على نتيجة إلا إذا طلب المستخدم صراحةً التحقق من المطابقة.

متى تُستخدم

استخدمها عندما يريد المستخدم تميمة، أو شخصية IP، أو شخصية علامة تجارية، أو "شعارًا لطيفًا" لمنتج أو مستودع أو تطبيق أو مجتمع.

المتطلبات المسبقة

  • backend لتوليد الصور مضبوط للأداة المدمجة image_generate ؛ تحقق باستخدام hermes tools ، وفعّل واحدًا هناك إذا أبلغت الأداة عن عدم وجود backend.
  • vision_analyze فقط للتحقق من المطابقة بطلب صريح؛ و delegate_task فقط للدفعات الكبيرة عندما يريد المستخدم السرعة.

الإجراء

  1. حلّل الطلب بحثًا عن موضوع IP صريح وسياق المنتج المتاح. ولا تطلب من المستخدم اختيار وضع الألوان إلا إذا أراد صراحةً التحكم فيه.
  2. عندما لا يحدّد المستخدم موضوع IP وتكون مساحة العمل الحالية مستودع منتج، افحص السياق ذي الصلة للقراءة فقط قبل طرح الأسئلة. فضّل README ووثائق المنتج وبيانات الحزمة أو التطبيق الوصفية ونص الصفحة التعريفية وملفات manifest و design tokens. واعتبر السياق كافيًا عندما يمكن استنتاج غرض المنتج وجمهوره الأساسي والشخصية المطلوبة بثقة معقولة.
  3. عندما لا يكفي سياق المنتج، اطرح جولةً واحدةً مجمّعة من الأسئلة الخلفية حول ما يفعله المنتج ومن يخدمهم والإحساس الذي ينبغي أن ينقله. ولا تبدأ استبيانًا خلفيًا ثانيًا. وواصل بأفضل تفسير تدعمه الإجابة.
  4. بمجرد كفاية السياق، اعرض دائمًا 3 اتجاهات موجزة قبل التوليد، واقترح صراحةً توليد 6 مرشّحات مستقلة في دفعة واحدة. ولا تولّد حتى يوافق المستخدم، إلا إذا كان الطلب الحالي يجيز 6 مخرجات صراحةً أو يطلب المتابعة دون تأكيد آخر.
  5. اختر الاتجاهات الثلاثة المقترحة بعناية:
    • عندما يحدّد المستخدم موضوع IP صراحةً، احتفظ به واقترح 3 معالجات تصميم متميزة بناءً على معالجة الشكل الخارجي، أو منطقة اللون الثانوية، أو السمة المحدِّدة، أو إبراز الشخصية.
    • عندما لا يحدّد المستخدم موضوع IP، اقترح 3 موضوعات IP أو استعارات مختلفة فعلًا. واربط كلًا منها بخاصية منتج أو وعد علامة تجارية مختلف؛ ولا تقدّم 3 حيوانات اعتباطية بلا مبرّر.
  6. فسّر استجابة المستخدم بدقة:
    • إذا قبل المستخدم الاتجاهات الثلاثة واقتراح الصور الست، فولّد نسختين مستقلتين لكل اتجاه وسمّهما A1 و A2 و B1 و B2 و C1 و C2. خصّص A1 و B1 و C1 للركن السفلي الأيسر، و A2 و B2 و C2 للركن السفلي الأيمن، كي يُختبَر كل اتجاه مرة من كل جانب.
    • إذا اختار المستخدم اتجاهًا واحدًا لكنه قبل 6 صور، فولّد 6 نسخ مضبوطة من ذلك الاتجاه وسمّها من A1 إلى A6. وخصّص النسخ ذات الأرقام الفردية للركن السفلي الأيسر، والزوجية للركن السفلي الأيمن.
    • إذا رفض المستخدم الكمية أو الاتجاهات أو التوزيع المقترح، فاتبع تعليماته البديلة دون الجدال لصالح الافتراضي.
    • لدفعة مصغّرة مصرح بها مسبقًا (مثل "ولّد 2 بالضبط") لم يحدّد المستخدم اتجاهاتها، فضّل اتجاهًا واحدًا مع N نسخ موسومة بـ A1..AN ؛ واذكر الاتجاه ومبرّره في التقرير. وتخطَّ جولة اقتراح الاتجاهات الثلاثة إذا كان الطلب يجيز دفعة محددة مسبقًا ويمنع المزيد من التأكيد — فقاعدة "اعرض دائمًا 3 اتجاهات" في الخطوة 4 لا تسري إلا عندما تكون جولة الاقتراح ممكنة.
    • لأي حجم افتراضي زوجي آخر للدفعة، قسّم المرشّحات بالتساوي بين الركنين السفليين الأيسر والأيمن. ولدفعة فردية، خصّص المرشّح الإضافي لأحد الجانبين عمدًا وسجّل عدم التوازن. ولا تستخدم الموضع السفلي الأوسط إلا بطلب صريح من المستخدم.
  7. اجعل الافتراضي لكل مرشّح 3 ألوان دلالية بالضبط في الصورة كاملةً: لونين أساسيين لشخصية IP بالضبط، ولون خلفية واحدًا بالضبط. وأعد استخدام لوني IP لعلامات الوجه بدلًا من إضافة ألوان دلالية أخرى. واتبع طلب المستخدم الصريح لعدد ألوان آخر. واحتفظ بإشارات المنتج المطلوبة والسمات التعريفية وحدود التعقيد وأي لوحة ألوان مقدَّمة متسقةً بما يكفي للمقارنة المفيدة.
  8. حدّد مسار توليد الصور المتاح قبل الوعد بالمخرجات. وفي Hermes، هو الأداة image_generate ؛ وإذا أبلغت عن عدم وجود backend مضبوط، فاطلب من المستخدم تفعيل واحد (hermes tools) بدلًا من اختلاق النتائج.
  9. إذا كانت الدفعة كبيرة وأراد المستخدم السرعة، فشغّل المرشّحات بالتوازي عبر delegate_task (مرشّح لكل مهمة، وموجز المنتج نفسه وقيود مشتركة، واتجاه أو نسخة مخصَّصة لكل منها). وإلا فولّد المرشّحات عبر استدعاءات منفصلة لـ image_generate.
  10. إذا قدّم المستخدم لوحة ألوان للخلفية، فاحجز كل لون فيها للخلفيات ما لم يذكر خلاف ذلك صراحةً. واختر لونين أساسيين لـ IP بالضبط بصورة مستقلة وفق الموضوع والسياق، ما لم يخصّص المستخدم ألوانًا للموضوع أيضًا. ولا تعتبر أي لوحة تاريخية أو نموذجية قائمةً مغلقة للخلفيات المسموحة.
  11. جرّد كل موضوع وفق ميزانية التعقيد أدناه. وولّد كل مرشّح كأصل مربع منفصل بكامل الدقة؛ ولا تطلب أبدًا من نموذج الصور تركيب لوحة عرض مجمّعة أو شبكة أو ورقة متعددة الصور. ولا تستخدم المرشّحات السابقة كمراجع صور عند اختبار قابلية إعادة الإنتاج من الـ prompt وحده.
  12. عامل كل دفعة كسحب إبداعي من مرور واحد. ولّد كل مرشّح مطلوب مرةً واحدةً، ثم احتفظ بكل نتيجة معادة وسلّمها كما هي. ولا تفحص المخرجات لحجب التسليم، أو تصنيفها موصى بها أو غير موصى بها، أو إعادة محاولتها تلقائيًا، أو إصلاحها بمعالجة لاحقة.
  13. احتفظ بكل نتيجة مولَّدة وسمّها. واذكر كل تسمية واتجاه IP ومبرّره والركن المخصَّص والمسار المحفوظ والـ prompt وتعيين الألوان والأبعاد (عندما لا يعيد backend إلا عنوان URL دون حجم pixels، أبلغ عن "مربع بالدقة الأصلية لـ backend" — ولا تفحص الصورة لمجرد قياسها). واعرض كل النتائج معًا؛ ولا تولّد تحسينات أو بدائل إلا عندما يطلب المستخدم صراحةً سحبًا آخر.

عند اقتراح الاتجاهات قبل التوليد، صف كلًا منها في سطر واحد موجز: <IP subject> — <product connection> — <defining silhouette>. واختم باقتراح مباشر لتوليد 6 صور وفق التوزيع أعلاه. ولا تحوّل مرحلة الاكتشاف إلى ورشة طويلة للعلامة التجارية إلا إذا طلبها المستخدم.

ميزانية التعقيد

  • ابنِ شكلًا خارجيًا متصلًا واحدًا مهيمنًا من نحو 4–7 أشكال هندسية أساسية كبيرة. وادمج أو احذف أي شكل لا يحمل هوية أو تعبيرًا أو قابلية للتعرّف.
  • استخدم سمةً واحدةً محدِّدة للنوع كحد أقصى: مثل منقار كبير ذي كيس، أو زوج واحد من القرون الملتفّة، أو واقٍ عريض واحد. وللموضوعات بلا أطراف أو سمات (الثعابين والأشباح والكتل)، قد تكون السمة المحدِّدة حركةً في الشكل الخارجي — لفة ممتلئة واحدة أو حافة متموجة واحدة — وتختزل قاعدة السمات المزدوجة إلى العينين.
  • استخدم منطقتين داخليتين عريضتين للألوان كحد أقصى تقابلان لوني IP الأساسيين. واجعل الوجه عينين وفمًا صغيرًا واحدًا فقط عند الحاجة للتعبير. واحذف الحواجب واللمعان وفتحتي الأنف والملمس والخطوط الخارجية والعلامات الزخرفية ما لم تكن ضرورية للتعرّف.
  • أزل الريش المتكرر والحراشف وخصل الفراء وصفائح الدروع والأزرار والبراغي والأرقام والتسميات والتفاصيل التصويرية الأخرى.
  • اجعل التبسيط واللطافة والشخصية الطفولية المحبّبة صفات حاسمة. وفضّل رأسًا كبيرًا ونِسَبًا متراصة وخدودًا ناعمة وعينين بسيطتين متباعدتين وتعبيرًا هادئًا ودودًا عندما يناسب الموضوع.
  • اشترط شكلًا خارجيًا أسود واضحًا وقابليةً للتعرّف بحجم 32 × 32. وإذا اختفت سمة أو أصبحت تشويشًا بذلك الحجم، فكبّرها أو ادمجها أو أزلها.

لغة الأشكال والتكوين

  • استخدم حدودًا سميكة مستديرة ثقيلة وكتل ألوان عريضة.
  • امنع الزوايا الحادة والأذنين أو المنقار المدبّبين والذيول الإبرية وقرون الاستشعار الرفيعة والابتسامات الرفيعة والفجوات الضيقة وأطراف اللهب أو الريش الحادة. واستبدل كل طرف ضروري بنهاية مستديرة غير حادة بوضوح.
  • أظهر كلا طرفي السمات التعريفية المزدوجة، مثل الأذنين أو القرنين أو الجناحين أو الخياشيم أو الجرسين.
  • أظهر الشخصية قائمةً وتنبثق من الركن السفلي الأيسر أو الأيمن المخصَّص، وتملأ نحو 85–95% من اللوحة كي تظل شخصية IP مهيمنة بصريًا.
  • يُرحَّب بالقص عند الأسفل أو الجانب المخصَّص عندما يعزّز الإحساس بالانبثاق من ذلك الركن، لكن لا تفرض ملامسة دقيقة للحافة أو قصًا ثابتًا.
  • لا تضع الشخصية في الوسط أو في الوسط السفلي أبدًا إلا إذا طلب المستخدم ذلك صراحةً.
  • احتفظ بكلا طرفي السمات التعريفية المزدوجة ضمن التكوين المرئي.
  • أبقِ العمل الفني قائمًا؛ ولا تُدِر اللوحة أو تُمل العلامة الرئيسية دون طلب صريح.

البساطة والمعالجة البصرية

  • ابدأ بأشكال دلالية كبيرة ونظيفة وبأقوى شكل خارجي بسيط ممكن. ويجب أن تُفهَم الشخصية فورًا قبل ملاحظة أي سمة داخلية.
  • فضّل أشكالًا أقل وأكبر وأنعم على المزيد من التحديد. ولا تضف سمة لمجرد تفسير البنية التشريحية أو المادة.
  • أبقِ علامات الوجه صغيرة وبسيطة وثانوية. ولا تضف بقع لمعان براقة أو تصويرًا تفصيليًا للتجاويف في العينين أو الفم أو الأنف أو السمات الصغيرة الأخرى.
  • أبقِ لون الخلفية المسمّى مصمتًا ومتجانسًا بصريًا، دون مشهد أو ملمس أو هالة أو تظليل حواف أو اختلاف إضاءة.
  • اطلب التأثير البُعدي الخفيف فقط بالجملة الواحدة المستخدمة في قالب الـ prompt. ولا توسّعها إلى شدة رقمية أو تعليمات للتدرجات أو الإضاءات أو الظلال. وتُقبَل التدرجات والتظليل أو البُعدية الخفيفة العارضة التي يعيدها المولِّد، ولا يجوز أن تؤدي إلى الترشيح أو إعادة المحاولة.
  • اجعل الاتجاه البصري المطلوب رسوميًا وبسيطًا بدلًا من طلب تصوير صلصالي أو قابل للنفخ أو بلاستيكي أو قطني أو شبيه بالألعاب أو واقعي فوتوغرافيًا.

اللون واللوحة

  • اجعل الافتراضي 3 ألوان دلالية بالضبط في الصورة الكاملة: لونين أساسيين لـ IP بالضبط، ولون خلفية واحدًا بالضبط.
  • اختر لوني IP من سياق المنتج وهوية الموضوع والشخصية المطلوبة وطلب المستخدم. ونظّمهما في كتل عريضة مقصودة؛ وأعد استخدام أحدهما لعلامات الوجه، وأبقِ الآخر في منطقة محدِّدة واحدة متصلة بدلًا من نثر أجزاء زخرفية.
  • اختر لوني الموضوع بصورة مستقلة عن الخلفية. وفضّل ألوانًا واضحة حيوية للموضوع عندما يناسبه ذلك، لكن لا تفرض تشبّعًا عامًا أو OKLCH أو تغيير تدرج لوني أو نطاقات chroma على IP.
  • اختر الخلفية بحرية وفق السياق أو من لوحة قدّمها المستخدم. وما لم يطلب لونًا زاهيًا، هدّئ الخلفية قليلًا بخفض تشبّعها بدرجة بسيطة؛ وأبقِها ملوّنة ومقصودة بوضوح، لا زاهية أو رمادية أو موحلة. ولوحات الألوان التاريخية والأمثلة اقتراحات فقط، وليست قائمة سماح أو لوحة افتراضية إلزامية أبدًا.
  • حافظ على فصل بصري واضح بين الشكل الخارجي المهيمن لـ IP وعلامات وجهه والخلفية. وإذا سبّبت خلفية مقدّمة من المستخدم فصلًا ضعيفًا، فعدّل ألوان الموضوع أولًا بدلًا من استبدال الخلفية المطلوبة.
  • نوّع استراتيجيات لوني IP عمدًا عبر الدفعة، بدلًا من تكرار التركيبة نفسها التي تطغى عليها الألوان المحايدة.
  • عامل لوني الشخصية كعائلتين لونيتين دلاليتين. ولا يُبطل اختلاف الدرجة اللونية العارض داخل أي عائلة المخرجات.
  • سمِّ لون الخلفية المصمت المقصود مباشرةً. واطلب أن يملأ كل مساحة مفتوحة والأركان غير المشغولة، بينما تشغل الشخصية ركن الانبثاق المخصَّص. ولا تستخدم مصطلحات أوضاع الصور مثل opaque أو alpha أو transparency في prompt التوليد.
  • ولّد مربعًا مباشرًا بنسبة 1:1 وزوايا خارجية مربعة (aspect_ratio="square" في image_generate). واقبل الدقة المربعة الأصلية لـ backend كما هي؛ ولا تُعِد أخذ العينات لمجرد بلوغ عدد pixels محدد.

قالب الـ prompt

صف الشكل المرئي المطلوب كصورة فقط. ولا تخبر مولّد الصور أبدًا بأن الصورة logo أو brand mark أو app icon أو icon asset ، أو مخصَّصة لأي من هذه الاستخدامات. ولا تضف تمهيدًا لحالة استخدام أو نوع أصل يكشف ذلك الاستخدام. ولا تسري هذه القاعدة إلا على prompt التوليد؛ ويجوز للمحادثة المحيطة مع المستخدم واسم المهارة وصف المشروع الأوسع.

image_generate تتلقى سلسلة prompt واحدة، لذا أبقِ دائمًا سطر Constraints: باللغة الطبيعية داخل الـ prompt الرئيسي (لا توجد قناة منفصلة لـ negative prompt). وسجّل الـ prompt وتعيين الألوان المستخدمين لكل مرشّح في تقرير التوليد.

سلوك التسليم

  • عامل التوليد كسحب احتمالي، لا كاختبار مطابقة.
  • ولّد العدد المطلوب من المرشّحات المستقلة مرة واحدة، وسلّم كل صورة معادة.
  • لا تفحص أو تُبلِغ عن alpha أو الشفافية أو وضع الخلفية افتراضيًا.
  • لا تحجب التسليم، أو ترتّب المرشّحات بوصفها مطابقة أو غير مطابقة، أو تسمّها موصى بها أو غير موصى بها، أو تعيد تلقائيًا محاولة أي نتيجة بسبب خلفيتها أو ألوانها أو تفاصيلها أو تكوينها أو تدرّجها أو تظليلها أو بُعديتها.
  • لا تعالج نتيجةً لاحقًا لجعلها تبدو أكثر مطابقة. وإذا طلب المستخدم لاحقًا اتجاهًا آخر أو بديلًا، فولّد مرشّحًا مستقلًا جديدًا استجابةً لذلك الطلب الصريح.

المزالق

  • أكبر نمط فشل هو زحف التفاصيل: تضيف النماذج خطوطًا خارجية وملمسًا وألوانًا إضافية ومشاهد. وسطر Constraints: في قالب الـ prompt أساسي — فلا تختصره أبدًا.
  • تسمية الأصل "شعارًا" أو "أيقونة" في prompt التوليد تطلق تأطيرًا للعرض (شارات وبطاقات ونماذج عرض). وأبقِ الـ prompt تصويريًا خالصًا.
  • طلب شبكة/لوحة عرض مجمّعة للنسخ في استدعاء واحد ينتج شخصيات صغيرة غير متسقة. مرشّح واحد لكل استدعاء، دائمًا.
  • إذا عادت نتيجتان في دفعة متطابقتين تقريبًا، فهذا سلوك احتمالي طبيعي — سلّم كلتيهما؛ ولا تُعِد التوليد بصمت.

التحقق

  • لكل مرشّح مسلَّم تسمية ومبرّر اتجاه وركن مخصَّص و prompt وتعيين ألوان ومسار ملف أو URL في التقرير النهائي.
  • يطابق عدد الدفعة ما وافق عليه المستخدم؛ ولم يُحجَب أي مرشّح أو تُعَد محاولته أو يُعالَج لاحقًا.
