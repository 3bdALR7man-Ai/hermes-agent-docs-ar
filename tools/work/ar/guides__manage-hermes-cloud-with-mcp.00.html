إدارة Hermes Cloud عبر MCP

يشغّل Hermes Cloud نُسخًا مستضافة من Hermes Agent نيابةً عنك. عادةً ما تديرها من صفحة /agents في Nous Portal. يربط هذا الدليل Hermes Agent المحلي لديك بخادم MCP الخاص بالـ Portal، لتتمكن من إدارة تلك النُّسخ السحابية بمجرد طلب ذلك — "اعرض وكلائي السحابيين"، "أعد تشغيل النسخة المتوقفة"، "كم تكلّفني" — دون مغادرة الطرفية.

إنه خادم MCP قياسي تستضيفه Nous Research، ومحمي بتسجيل دخول OAuth نفسه الذي تستخدمه بالفعل للـ Portal. بعد الاتصال، يحصل Hermes على أداتين يمكنه استدعاؤهما نيابةً عنك.

ما الذي يمكنك فعله به

بعد الاتصال، يستطيع النموذج استدعاء هذه الأدوات على مؤسستك (org) في Hermes Cloud:

اطلب…ما يحدث خلف الكواليس
"اعرض وكلائي السحابيين"agents (list)
"ما حالة <name>؟"agents (get / status)
"كم تكلّف هذه النسخة تقريبًا؟"agents (cost_estimate)
"شغّل / أوقف / أعد تشغيل <name>"agent (start / stop / restart)
"أنشئ نسخة جديدة باسم <name>"agent (create)
"احذف <name> نهائيًا"agent (destroy)
"حدّث متغيرات البيئة / الصورة (image) في <name>"agent (update_env / update_image)

يُنفَّذ كل استدعاء على مؤسستك أنت بهويتك في الـ Portal، ويُعاد التحقق من العضوية في كل استدعاء — فلا يمكن للاتصال أن يمسّ إلا النُّسخ التي تتحكم فيها بالفعل من واجهة الويب.

الخطوة 1: إضافة الخادم

يُخبر --auth oauth ‏Hermes بأن هذا خادم HTTP محمي بـ OAuth. عند الاتصال لأول مرة، يقوم Hermes بما يلي:

  1. يكتشف الـ endpoints الخاصة بـ OAuth في الخادم تلقائيًا (عبر البيانات الوصفية وفق RFC 9728 / 8414).
  2. يسجّل نفسه كعميل (RFC 7591 Dynamic Client Registration) — دون أي secret تحتاج إلى نسخه.
  3. يفتح متصفحك على الـ Portal لتسجيل الدخول ومنح التفويض.
  4. يخزّن الـ token الناتج ضمن ~/.hermes/mcp-tokens/ ويعيد استخدامه (ويتم تجديده تلقائيًا).

اختيار المؤسسة

إذا كان حسابك في الـ Portal ينتمي إلى أكثر من مؤسسة، فسيعرض المتصفح أداة اختيار المؤسسة (org picker) أثناء التفويض — اختر المؤسسة التي ينبغي أن يديرها هذا الاتصال. يتم الاختيار مرة واحدة في المتصفح، ولا يوجد ما تمرّره عبر سطر الأوامر. أما الحسابات ذات المؤسسة الواحدة فتتخطى هذه الخطوة وتُربط تلقائيًا.

إذا احتجت يومًا إلى توجيه الاتصال إلى مؤسسة مختلفة، فأزل الخادم ثم أعد إضافته (hermes mcp remove hermes-cloud، ثم أمر add مرة أخرى) واختر المؤسسة الأخرى في المتصفح.

استكشاف الأخطاء وإصلاحها

يعرض المتصفح أداة اختيار المؤسسة ولست متأكدًا أيها أختار

أنت تنتمي إلى عدة مؤسسات في الـ Portal. اختر المؤسسة التي تريد إدارة نُسخها في Hermes Cloud من خلال هذا الاتصال. إذا لم تكن متأكدًا، فهي المؤسسة التي تملك النُّسخ التي تراها في صفحة /agents في الـ Portal. يمكنك إعادة الاختيار لاحقًا بإزالة الخادم وإعادة إضافته.

يطلب مني تسجيل الدخول مرة أخرى

تتجدد OAuth tokens تلقائيًا، لكن إذا ألغى الـ Portal جلستك (بسبب تغيير كلمة المرور، أو الإلغاء، أو انتهاء الصلاحية)، فسيطلب منك الاستدعاء التالي إعادة التفويض. أعد تنفيذ الأمر hermes mcp add — وسيُصدر مسار المتصفح token جديدًا.

بيئة دون واجهة (Headless) / SSH / جهاز بعيد

يعمل OAuth browser callback على الجهاز الذي يعمل عليه Hermes. على الجهاز البعيد، مرّر منفذ loopback عبر SSH (port forwarding) — وهو النمط نفسه المتّبع مع أي تسجيل دخول آخر عبر OAuth. راجع OAuth عبر SSH / الأجهزة البعيدة.

انظر أيضًا

  • Nous Portal — الاشتراك، والنماذج، و Tool Gateway التي تقف خلف تسجيل الدخول نفسه
  • استخدام MCP مع Hermes — ربط خوادم MCP وتصفيتها بشكل عام
  • نظرة عامة على ميزة MCP — ما هو MCP وكيف يستخدمه Hermes
  • مرجع إعدادات MCP — كل حقول mcp_servers، بما في ذلك auth: oauth
  • OAuth عبر SSH — تسجيل الدخول من البيئات البعيدة أو البيئات التي لا يتوفر فيها سوى المتصفح (browser-only)
