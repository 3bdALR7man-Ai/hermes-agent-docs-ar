فحص قاعدة الكود باستخدام pygount

حلّل المستودعات لمعرفة عدد أسطر الكود، وتوزيع اللغات، وعدد الملفات، ونسب الكود إلى التعليقات باستخدام pygount.

متى تُستخدم

  • يطلب المستخدم عدد أسطر الكود (LOC)
  • يريد المستخدم توزيعًا للغات في المستودع
  • يسأل المستخدم عن حجم قاعدة الكود أو تركيبتها
  • يريد المستخدم نسب الكود إلى التعليقات
  • أسئلة عامة من نوع "ما حجم هذا المستودع"

المتطلبات الأساسية

1. الملخص الأساسي (الأكثر شيوعًا)

احصل على توزيع كامل للغات مع عدد الملفات وأسطر الكود وأسطر التعليقات:

مهم: استخدم دائمًا --folders-to-skip لاستبعاد مجلدات الاعتماديات (dependencies) والبناء (build)، وإلا فسيقوم pygount بمسحها بالكامل وقد يستغرق وقتًا طويلًا جدًا أو يتعلّق.

2. الاستبعادات الشائعة للمجلدات

عدّلها حسب نوع المشروع:

3. التصفية حسب لغة معيّنة

4. مخرجات تفصيلية ملفًا بملف

5. صيغ المخرجات

6. تفسير النتائج

أعمدة جدول الملخص:

  • Language — لغة البرمجة المكتشَفة
  • Files — عدد الملفات من تلك اللغة
  • Code — أسطر الكود الفعلي (التنفيذي/التصريحي)
  • Comment — الأسطر التي هي تعليقات أو توثيق
  • % — النسبة المئوية من الإجمالي

لغات وهمية خاصة (pseudo-languages):

  • __empty__ — ملفات فارغة
  • __binary__ — ملفات ثنائية (صور، ملفات مُصرّفة، إلخ)
  • __generated__ — ملفات مُولَّدة تلقائيًا (يُكتشف ذلك بشكل تخميني)
  • __duplicate__ — ملفات ذات محتوى متطابق
  • __unknown__ — أنواع ملفات غير معروفة

مزالق شائعة

  1. استبعد دائمًا .git وnode_modules وvenv — بدون --folders-to-skip، سيقوم pygount بمسح كل شيء وقد يستغرق دقائق أو يتعلّق عند أشجار الاعتماديات الكبيرة.
  2. ملفات Markdown تُظهر 0 سطر كود — يصنّف pygount كل محتوى Markdown كتعليقات، لا كأكواد. هذا سلوك متوقّع.
  3. ملفات JSON تُظهر أعداد أسطر كود منخفضة — قد يحسب pygount أسطر JSON بشكل متحفّظ. للحصول على عدد دقيق لأسطر JSON، استخدم wc -l مباشرة.
  4. المستودعات الأحادية الكبيرة (monorepos) — بالنسبة للمستودعات الكبيرة جدًا، فكّر باستخدام --suffix لاستهداف لغات محدّدة بدلًا من مسح كل شيء.
