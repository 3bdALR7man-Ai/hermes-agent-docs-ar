عميل gateway الكلاسيكي (الترحيل الأولي)

تعتمد الأوامر العادية hermes --cli و hermes chat و hermes chat -q '…' -Q، وكذلك الأمر hermes -z '…' على المستوى الأعلى، على سلطة gateway (gateway authority). وتسلّم عمليات إطلاق المحادثة المباشرة عبر cli.main التحكم إلى gateway قبل إنشاء وكيل محلي. ويستخدم التمهيد المحلي (local bootstrap) دورة حياة ensure القياسية وتذكرة تحكم خاصة تُستخدم مرة واحدة، دون تثبيت أي خدمة. أما HERMES_TUI_GATEWAY_URL الصريح فيبقى للاتصال البعيد فقط: إذا فشل الاتصال أو المصادقة فلن يُطلق أي بديل محلي.

يطبع العميل معرّف Session: المحفوظ إلى stderr. استأنف الجلسة باستخدام hermes --cli chat --resume ID. يُقبل الإدخال مع input_id جديد، وتأتي الأحداث والردود النهائية من السلطة. الأوامر /quit و /exit و /detach ونهاية الإدخال (EOF) وإغلاق الطرفية تفصل العميل (detach) فقط. أما /stop فيرسل مقاطعة مقيّدة بجيل التنفيذ (execution-generation-fenced). وتعرض الموافقات المعلّقة /approve ID once|deny|…؛ ويُستخدم /answer ID TEXT للإجابة عن طلبات التوضيح. يعتمد العميل معرّف prompt المعروض والجيل الذي التقطه، لا waiter أُعيد بناؤه محليًا. ويقرّ /discard ID بفقدان قبول (admission) ضاع عند إعادة تشغيل المالك (prompt.resolve_unknown). والأوامر /branch [title] و /model <model> [--provider name] و /compress [here [N] | <focus>] [--preview] هي عمليات session.mutate مقيّدة بالمراجعة (revision-fenced) (hermes_cli/gateway_mutations.py)؛ ويبدّل /yolo [on|off] تجاوز الموافقات لهذه الجلسة لدى المالك (config.set مع المفتاح yolo). أما /title [name] (session.mutate rename) و /undo [N] و /retry (session.mutate rewind؛ ويعيد /undo الرسالة المحذوفة إلى محرر الإدخال) و /new [title] / /reset (session.create بطلب الإطلاق المجمَّد لهذه الجلسة) و /usage (تقرير المالك مضافًا إليه آخر دور مثبَّت) و /tools (toolsets الإطلاق) فتُنفَّذ داخل العارض (view) (hermes_cli/gateway_chat_commands.py). وكل أمر آخر يُرسل إلى المالك بصيغة slash.exec: تُنفَّذ هناك عمليات القراءة التي جرت مراجعتها، وتطبع البقية /x is not available on the shared gateway yet مع رابط إلى جدول تكافؤ الأوامر الذي يبيّن ما يفعله كل عميل محلي مع كل أمر.

ينتهي stdout في الوضع أحادي التنفيذ (one-shot) بالرد النهائي. وبدون -Q تطبع الجلسة المستأنفة سجلها المخزّن أولًا (أسطر user: / assistant:)، ويتبع الردَّ مقطع Resume this session with: (انظر Launch options)؛ أما -Q فيطبع الرد وحده. رمز الخروج 0 عند اكتمال القبول، و 1 عند فشل التنفيذ أو الاتصال، و 2 لخيارات الواجهة الأمامية غير المدعومة، و 3 عند وجود عنصر تحكم معلّق يتطلب إعادة اتصال تفاعلية أو دور ضاع في انهيار gateway (امسحه باستخدام hermes sessions discard <id> --yes)، و 130 عند الفصل بلوحة المفاتيح. ولا يعني وجود عنصر تحكم معلّق أن الدور أُلغي. ولم يعد -z يتجاوز سياسة الموافقات ضمنيًا.

خيارات الإطلاق

يعلن gateway عن معاملات الإنشاء التي يقبلها عبر runtime.describe (session_create.parameters، من gateway.session_policy.CREATE_FIELDS). ولا يرسل العميل خيار إنشاء إلا إذا كان معلنًا عنه؛ ويُرفض الخيار المطلوب إذا كان gateway أقدم ولا يعلن عنه (Gateway does not support creation options: …). يُرسل cwd الخاص بالمستدعي عندما يكون معلنًا عنه؛ وإذا كان gateway قديمًا لا يدعم cwd فإنه يطبع تحذيرًا بأنه يستخدم دليل التنفيذ المضبوط لديه، بينما يُرفض الخيار الصريح --in. يمكن للاستئناف أن يكرّر خيارات الإنشاء نفسها التي جُمّدت بها الجلسة (تعيد السكربتات تشغيل سطر الأوامر نفسه)؛ ويُرفض أي خيار من شأنه تغيير المسار المجمَّد.

الخيارات المقبولة والمجمَّدة في الجلسة عند الإنشاء (_POLICY في hermes_cli/gateway_chat.py): --model و --provider و --base-url و --api-key (في الذاكرة فقط، ولا تُحفظ أبدًا) و --reasoning و --toolsets و --max-turns و --skills (تُصيَّر مرة واحدة داخل prompt المجمَّد) و --checkpoints و --yolo و --accept-hooks (وكذلك HERMES_ACCEPT_HOOKS=1) و --pass-session-id و --ignore-rules و --ignore-user-config و --safe-mode (كلاهما يتطلب --model صريحًا؛ ويشغّل safe mode الدور في worker معزول لا يقرأ profile أبدًا). ومقبولة أيضًا: --source <label> و --resume <id-or-title> و -c <title> و -c <title> --create-if-missing و --in <dir> و --query-file و --format stream-json و -z ... --usage-file و -c المجرد (جلسة breadcrumb الخاصة بهذه الطرفية، وإلا أحدث جلسة CLI) و --resume latest (أحدث جلسة CLI، مع إعطاء الأولوية لمساحة العمل هذه؛ وكلاهما يحلّه المالك، session.resume latest='cli') و --list-tools / --list-toolsets (يطبعان الفهرس ثم ينتهيان؛ دون جلسة). وينتهي chat -q بدون -Q بمقطع main الذي يبدأ بـ Resume this session with: hermes --resume <id>.

حدود التكافؤ الحالية — ليست تكافؤًا كاملًا مع CLI الكلاسيكي

ما زالت المهام التالية معلّقة: العرض القديم الكامل، وتكافؤ سجل slash، وتحرير السجل التفاعلي، وإعادة الاتصال التلقائي، وسجلات العميل الدائمة لحالات ضياع ACK، وتمهيد تسجيل الدخول البعيد، واستئناف المالك البارد (cold-owner)، واختبارات الجودة (QA) الأصلية على Windows/macOS. يحافظ العميل على آلية المصادقة القائمة للعنوان البعيد الصريح، ولا يحصل على بيانات اعتماد بعيدة ولا يولّدها.

يختبر tests/hermes_cli/test_gateway_chat_native.py على tmux/PTY الأصلي في الوضع الكلاسيكي: الإدخال الجديد، والفصل، والاستئناف بالمعرّف المحفوظ، والتنفيذ أحادي الدور (one-shot)، عبر daemon عادي مع نموذج loopback وقيم HOME/HERMES_HOME معزولة وcwd المستدعي. وتسجّل أدوات رصد الـ constructors أنه لا يوجد AIAgent أو SessionDB أو GatewayRunner على جهة العميل. كما يرفض الاختبار خيار موافقة غير صالح، ثم يعيد الاتصال ويوافق قبل أثر حقيقي على الطرفية في fixture مملوك. أما تغطية الأصلي لحالتي التحكم القديم (stale-control) والإيقاف النشط (active-Stop) والتفاعل الأصلي مع clarify فتبقى أعمال قبول منفصلة.

لاختبار التوافق بين نسختين مسحوبتين (checkout)، حمّل إضافة خيارات pytest محدودة النطاق وحدّد النسخة المسحوبة لنظير gateway المؤقت (تزيل بيئة المُشغِّل العادي المعزولة عمدًا أي تجاوزات عشوائية لمتغيرات البيئة):

يبلّغ الإيصال صراحةً عن caller_cwd_effect_verified. في بيئة تشغيل تدعم cwd يرسل العميل الأصلي النموذج وtoolsets وcwd، وتكتب الطرفية الحقيقية دليل التنفيذ الفعلي في إيصال مؤقت مملوك. أما في بيئة تشغيل أقدم فيجب أن يُرفض --in الصريح دون ذلك الأثر. لا تحتسب الحالة الأخيرة تكافؤًا في cwd. يستخدم العميل والـ daemon كلاهما مجلدات home اختبارية معزولة؛ ولا يثبّت هذا الخيار خدمة ولا يغيّر النسخة المسحوبة المحددة.
