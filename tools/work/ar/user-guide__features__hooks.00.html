Event Hooks

لدى Hermes أربعة أنظمة hooks تُشغّل كودًا مخصّصًا عند نقاط رئيسية من دورة الحياة:

النظاميُسجَّل عبريعمل فيحالة الاستخدام
Gateway hooksHOOK.yaml + handler.py في ~/.hermes/hooks/الـ Gateway فقطالتسجيل، التنبيهات، webhooks
Plugin hooksctx.register_hook() في إضافة (plugin)CLI + Gatewayاعتراض الأدوات، القياسات، الضوابط الوقائية
Shell hooksكتلة hooks: في config.yaml الخاص بالـ profile تشير إلى سكربتات shellCLI + Gateway + محادثة Desktop/TUI/لوحة التحكمسكربتات جاهزة للحجب والتنسيق التلقائي وحقن السياق
Outbound webhooksقائمة hooks.outbound: في ~/.hermes/config.yamlCLI + Gatewayدفع أحداث دورة حياة موقّعة إلى نقاط نهاية HTTP خارجية — CI، لوحات تحكم، وكلاء آخرون

تُعزَل أخطاء ردود نداء الـ hooks وتُسجَّل بدلًا من تعطيل الوكيل. ليست كل الـ hooks سلبية: يمكن لـ hooks التوجيه/التحكم تغيير التدفّق، ويمكن للتحويلات استبدال المحتوى، ويمكن لـ hook من نوع pre_tool_call على مستوى shell أن يحجب أو يفشل بأمان.

Gateway Event Hooks

تُطلَق Gateway hooks تلقائيًا أثناء عمل الـ gateway (Telegram، Discord، Slack، WhatsApp، Teams) دون حجب خط أنابيب الوكيل الرئيسي.

إنشاء Hook

كل hook هو مجلد تحت ~/.hermes/hooks/ يحتوي ملفين:

HOOK.yaml

تحدّد قائمة events الأحداث التي تُشغِّل مُعالِجك. يمكنك الاشتراك في أي تركيبة من الأحداث، بما فيها أشكال جامعة مثل command:*.

handler.py

قواعد المُعالِج:

  • يجب أن يُسمَّى handle
  • يستقبل event_type (نص) وcontext (قاموس)
  • يمكن أن يكون async def أو def عادية — كلاهما يعمل
  • تُلتقَط الأخطاء وتُسجَّل، دون أن تُعطِّل الوكيل أبدًا

الأحداث المتاحة

الحدثمتى يُطلَقمفاتيح السياق
gateway:startupبدء عملية الـ gatewayplatforms (قائمة أسماء المنصات النشطة)
session:startإنشاء جلسة مراسلة جديدةplatform، user_id، session_id، session_key
session:endانتهاء جلسة (قبل إعادة الضبط)platform، user_id، session_key
session:resetشغّل المستخدم /new أو /resetplatform، user_id، session_key
session:compressاكتمال ضغط السياق لجلسةplatform، session_id، old_session_id (فارغ عند الضغط في المكان نفسه)، in_place (منطقي — true = ضُغط النص في نفس المعرّف، false = دُوِّر من old_session_id)، compression_count
agent:startيبدأ الوكيل معالجة رسالةplatform، user_id، chat_id، thread_id (معرّف موضوع منتدى/جذر thread؛ فارغ خارج موضوع)، chat_type ("dm" | "group" | "forum"؛ فارغ إن كان مجهولًا)، session_id، message (مُقتصَرة على 500 حرف)
agent:stepكل تكرار من حلقة استدعاء الأدواتplatform، user_id، session_id، iteration، tool_names
agent:endانتهاء الوكيل من المعالجةنفس مفاتيح agent:start، بالإضافة إلى response (مُقتصَرة على 500 حرف)
reaction:addedأُضيف تفاعل إيموجي إلى رسالة يستطيع البوت رؤيتها (adapter الخاص بـ Slack حاليًا). يتطلّب صلاحية reactions:read + اشتراك حدث البوت reaction_added؛ ويجب أن يكون البوت عضوًا في القناة.platform، reaction، user_id، item_user_id، item_type، channel_id، message_ts، team_id، event_ts، raw_event
reaction:removedأُزيل تفاعل إيموجي من رسالة يستطيع البوت رؤيتها. يتطلّب اشتراك حدث البوت reaction_removed.نفس شكل reaction:added
command:*تنفيذ أي slash commandplatform، user_id، command، args

مطابقة الرموز الجامعة

تُطلَق المُعالِجات المسجَّلة لـ command:* عند أي حدث command: (command:model، command:reset، إلخ). راقب كل الـ slash commands باشتراك واحد.

الردود ضمن المواضيع

يجب أن يُضمِّن المُعالِج الذي يرسل رسالة متابعة إلى نفس موضوع منتدى Telegram العنصر message_thread_id=int(thread_id) عندما يكون chat_type == "forum" وthread_id غير فارغ.

درس تطبيقي: BOOT.md — تشغيل قائمة تحقّق عند بدء التشغيل في كل إقلاع للـ gateway

نمط شائع من المجتمع: ضع قائمة تحقّق بصيغة Markdown في ~/.hermes/BOOT.md، واجعل الوكيل يُشغّلها مرة واحدة في كل مرة يبدأ فيها الـ gateway. مفيد لـ "في كل إقلاع، تحقّق من إخفاقات cron ليلًا وأبلغني على Discord إن فشل أي شيء"، أو "لخّص آخر 24 ساعة من deploy.log وانشره في Slack #ops".

يُظهر هذا الدرس التطبيقي كيفية بناء ذلك بنفسك كـ hook مُعرَّف من المستخدم. لا يشحن Hermes hook مدمج لـ BOOT.md — بل تُعِدّ بالضبط السلوك الذي تريده.

ما الذي نبنيه

  1. ملف في ~/.hermes/BOOT.md يحتوي تعليمات بدء تشغيل بلغة طبيعية.
  2. gateway hook يُطلَق عند gateway:startup، ويُنشئ وكيلًا لمرة واحدة بنموذج/بيانات اعتماد الـ gateway الخاص بك المُحلَّلة، ويُشغّل تعليمات BOOT.md.
  3. عُرف [SILENT] ليتمكّن الوكيل من الانسحاب من إرسال رسالة عندما لا يوجد ما يُبلَّغ عنه.

الخطوة 1: اكتب قائمة تحقّقك

أنشئ ~/.hermes/BOOT.md. اكتبها كما لو كنت تعطي تعليمات لمساعد بشري:

يرى الوكيل هذا كجزء من الـ prompt الخاص به، لذا فإن أي شيء يمكنك وصفه بلغة عادية يعمل — استدعاءات الأدوات، أوامر shell، إرسال الرسائل، تلخيص الملفات.

الخطوة 2: أنشئ الـ hook

~/.hermes/hooks/boot-md/HOOK.yaml

~/.hermes/hooks/boot-md/handler.py

السطران الأساسيان:

  • تقرأ _resolve_gateway_model() النموذج المُعدّ حاليًا للـ gateway.
  • تُحلّ _resolve_runtime_agent_kwargs() بيانات اعتماد المزوّد بنفس طريقة دور gateway عادي — بما في ذلك مفاتيح API وعناوين URL الأساسية ورموز OAuth ومجمّعات بيانات الاعتماد.

بدون هذين، يعود AIAgent() المجرد إلى الافتراضيات المدمجة ويُخفق بخطأ 401 أمام أي نقطة نهاية غير افتراضية.

الخطوة 3: اختبرها

أعد تشغيل الـ gateway:

راقب السجلّات:

يجب أن ترى Running BOOT.md (N chars) متبوعًا إمّا بـ boot-md completed: ... (ملخّص لما فعله الوكيل) أو boot-md completed (nothing to report) عندما يرد الوكيل برمز صمت دقيق مثل [SILENT].

احذف ~/.hermes/BOOT.md لتعطيل قائمة التحقّق — يبقى الـ hook مُحمَّلًا لكنه يتخطّى بصمت عندما لا يكون الملف موجودًا.

توسعة النمط

  • قوائم تحقّق واعية بالجدول: اعتمد على datetime.now().weekday() داخل تعليمات BOOT.md ("إذا كان الإثنين، تحقّق أيضًا من سجلّ النشر الأسبوعي"). التعليمات نص حرّ، لذا فأي شيء يستطيع الوكيل الاستدلال عليه مقبول.
  • قوائم تحقّق متعددة: وجّه الـ hook إلى ملف مختلف (STARTUP.md، MORNING.md، إلخ) وسجّل مجلدات hook منفصلة لكل واحد.
  • البديل بلا وكيل: إن لم تحتج إلى حلقة وكيل كاملة، تخطَّ AIAgent كليًا واجعل المُعالِج ينشر إشعارًا ثابتًا مباشرة عبر httpx. أرخص وأسرع وبلا اعتماد على مزوّد.

لماذا ليس هذا ميزة مدمجة

شحن إصدار سابق من Hermes هذا كـ hook مدمج وكان يُنشئ وكيلًا بصمت بافتراضيات مجردة عند كل إقلاع للـ gateway. فاجأ ذلك المستخدمين ذوي نقاط النهاية المخصّصة وجعل الميزة غير مرئية للمستخدمين الذين لم يعرفوا أنها تعمل. الحفاظ عليها كنمط موثَّق — تبنيه أنت، في مجلد الـ hooks الخاص بك — يعني أنك ترى بالضبط ما يفعله وتختار المشاركة فيه بكتابة الملفات.

كيف يعمل

  1. عند إقلاع الـ gateway، يفحص HookRegistry.discover_and_load() مجلد ~/.hermes/hooks/
  2. يُحمَّل كل مجلد فرعي يحتوي HOOK.yaml + handler.py ديناميكيًا
  3. تُسجَّل المُعالِجات للأحداث المُعلَنة الخاصة بها
  4. عند كل نقطة من دورة الحياة، يُطلق hooks.emit() كل المُعالِجات المطابقة
  5. تُلتقَط الأخطاء في أي مُعالِج وتُسجَّل — لا يُعطِّل hook معطوب الوكيل أبدًا
معلومة

تُطلَق Gateway hooks فقط في الـ gateway (Telegram، Discord، Slack، WhatsApp، Teams). لا يُحمِّل CLI gateway hooks. للـ hooks التي تعمل في كل مكان، استخدم plugin hooks.
