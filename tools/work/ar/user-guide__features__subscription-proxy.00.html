Proxy الاشتراك (Subscription Proxy)

الـ subscription proxy خادم HTTP محلي يتيح للتطبيقات الخارجية — مثل OpenViking و Karakeep و Open WebUI، وأي تطبيق يتعامل مع chat completions المتوافقة مع OpenAI — استخدام اشتراكك لدى المزوّد الذي يديره Hermes بوصفه LLM endpoint خاصًا بها. يُرفق الـ proxy بيانات الاعتماد الصحيحة (ويحدّثها تلقائيًا)، فلا يحتاج التطبيق أبدًا إلى مفتاح API ثابت.

يختلف هذا عن خادم API:

خادم APISubscription proxy
ما الذي يقدّمهوكيلك (مجموعة الأدوات الكاملة، والذاكرة، والمهارات)inference خام من النموذج
حالة الاستخدام"استخدم Hermes كـ backend للمحادثة""استخدم اشتراكي في Portal من تطبيق آخر"
المصادقةAPI_SERVER_KEY الخاص بكأي bearer (يُرفق الـ proxy المفتاح الحقيقي)
استدعاءات الأدواتنعم — الوكيل يشغّل الأدواتلا — تمرير مباشر فقط

استخدم خادم API عندما تريد الوكيل كـ backend. واستخدم الـ proxy عندما تريد فقط النموذج عبر اشتراكك.

البدء السريع

1. سجّل الدخول إلى مزوّدك (مرة واحدة)

يفتح هذا الأمر متصفحك لإتمام تدفق OAuth الخاص بـ Nous Portal. ويخزّن Hermes الـ refresh token في ~/.hermes/auth.json — وهو المكان نفسه الذي تُحفظ فيه جميع عمليات تسجيل الدخول إلى مزوّدي Hermes.

2. شغّل الـ proxy

اتركه يعمل في الواجهة. استخدم tmux أو nohup أو وحدة systemd إذا أردت أن يستمر في العمل بعد تسجيل الخروج.

3. وجّه تطبيقك إليه

تأخذ إعدادات أي تطبيق متوافق مع OpenAI القيم الثلاث نفسها:

يتجاهل الـ proxy الترويسة Authorization القادمة من تطبيقك، ويُرفق بيانات اعتماد Portal الحقيقية الخاصة بك بالطلب المُرسل إلى المصدر (upstream). ويتم التحديث تلقائيًا عندما يقترب الـ bearer من انتهاء صلاحيته.

المزوّدون المتاحون

المتوفر حاليًا: nous (Nous Portal) و xai (xAI / Grok). ويمكن إضافة مزيد من مزوّدي OAuth عبر تنفيذ الواجهة البرمجية UpstreamAdapter في hermes_cli/proxy/adapters/.

التحقق من الحالة

إذا ظهرت لك الرسالة not logged in، فنفّذ hermes portal. وإذا ظهرت لك credentials need attention، فهذا يعني أن الـ refresh token قد أُلغي (وهو أمر نادر — يحدث إذا سجّلت الخروج من واجهة Portal على الويب) — ما عليك سوى إعادة تنفيذ hermes portal.

المسارات المسموح بها

لا يُمرّر الـ proxy إلا المسارات التي يقدّمها المصدر فعليًا. بالنسبة إلى Nous Portal:

/v1/completionsإكمال النصوص بالصيغة القديمة (Legacy)

أما المسارات الأخرى (/v1/images/generations، و /v1/audio/speech، وغيرها) فتُرجع 404 مع رسالة خطأ واضحة تشير إلى المسارات المسموح بها. وهذا يمنع العملاء الشاردة من تسريب طلبات غريبة إلى المصدر.

الإتاحة على الشبكة المحلية (LAN)

يرتبط الـ proxy افتراضيًا بالعنوان 127.0.0.1 (localhost فقط). للسماح للأجهزة الأخرى على شبكتك باستخدامه:

⚠ انتبه: أصبح بإمكان أي شخص على شبكتك الآن استخدام اشتراكك في Portal. فالـ proxy لا يملك مصادقة خاصة به — إذ يقبل أي bearer. استخدم جدار حماية أو VPN أو reverse proxy مع مصادقة مناسبة إذا كنت ستتيحه خارج شبكتك الموثوقة.

حدود المعدل (Rate limits)

تنطبق حدود RPM/TPM الخاصة بفئة اشتراكك في Portal على الـ proxy بأكمله. فالـ proxy لا يوزّع الطلبات ولا يجمّع بيانات اعتماد متعددة — بل هو bearer واحد بكامل حصة اشتراكك. راقب الاستخدام على portal.nousresearch.com.

البنية المعمارية (Architecture)

الـ proxy بسيط إلى أقصى حد عن قصد. لكل طلب:

  1. يستقبل POST /v1/chat/completions من تطبيقك
  2. يبحث عن بيانات الاعتماد الحالية للـ adapter (ويحدّثها إذا كانت على وشك الانتهاء)
  3. يمرّر جسم الطلب حرفيًا، مع Authorization: Bearer <minted-key>
  4. يبث الاستجابة كما هي دون تغيير (مع الحفاظ على SSE)

لا تحويل. ولا تسجيل لأجسام الطلبات. ولا حلقة وكيل (agent loop). فالـ proxy مجرد ممر مباشر يُرفق بيانات الاعتماد.

المستقبل: مزيد من مزوّدي OAuth

نظام الـ adapters قابل للتوسعة عبر الإضافات. تتطلب إضافة مزوّد جديد (مثل HuggingFace، أو chat endpoint الخاص بـ GitHub Copilot، أو Anthropic عبر OAuth) تنفيذ UpstreamAdapter في hermes_cli/proxy/adapters/<provider>.py وتسجيله في adapters/__init__.py. أما المزوّدون غير المتوافقين مع OpenAI على مستوى البروتوكول (مثل Anthropic Messages API) فسيحتاجون إلى طبقة تحويل، وهذا خارج نطاق التصميم الحالي.
