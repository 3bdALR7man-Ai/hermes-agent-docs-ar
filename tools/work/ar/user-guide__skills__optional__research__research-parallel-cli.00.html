Parallel CLI

استخدم parallel-cli عندما يريد المستخدم Parallel صراحةً، أو عندما يستفيد سير عمل موجَّه للطرفية من مجموعة أدوات Parallel الخاصة بالمزوّد للبحث في الويب، والاستخراج، والبحث العميق، والإثراء، واكتشاف الكيانات، أو المراقبة.

هذا سير عمل اختياري من طرف ثالث، وليس قدرة أساسية في Hermes.

توقعات مهمة:

  • Parallel خدمة مدفوعة بمستوى مجاني، وليست أداة محلية مجانية بالكامل.
  • تتداخل مع web_search / web_extract الأصليتين في Hermes، لذا لا تُفضِّلها افتراضيًا لعمليات البحث العادية.
  • فضِّل هذه المهارة عندما يذكر المستخدم Parallel تحديدًا أو يحتاج قدرات مثل الإثراء أو FindAll أو سير عمل المراقبة الخاص بـ Parallel.

parallel-cli مصمَّمة للوكلاء:

  • مخرجات JSON عبر --json
  • تنفيذ أوامر غير تفاعلي
  • مهام غير متزامنة طويلة الأمد باستخدام --no-wait وstatus وpoll
  • ربط السياق عبر --previous-interaction-id
  • البحث والاستخراج والبحث العميق والإثراء واكتشاف الكيانات والمراقبة، كلها في CLI واحدة

متى تُستخدم

فضِّل هذه المهارة عندما:

  • يذكر المستخدم صراحةً Parallel أو parallel-cli
  • تحتاج المهمة سير عمل أغنى من عملية بحث/استخراج بسيطة لمرة واحدة
  • تحتاج مهام بحث عميق غير متزامنة يمكن إطلاقها واستطلاعها لاحقًا
  • تحتاج إثراءً منظَّمًا، أو اكتشاف كيانات FindAll، أو مراقبة

فضِّل web_search / web_extract الأصليتين في Hermes لعمليات البحث السريعة لمرة واحدة عندما لا يُطلَب Parallel تحديدًا.

مجموعة القواعد الأساسية

  1. فضِّل دائمًا --json عندما تحتاج مخرجات قابلة للقراءة الآلية.
  2. فضِّل الوسائط الصريحة وسير العمل غير التفاعلي.
  3. للمهام طويلة الأمد، استخدم --no-wait ثم status / poll.
  4. استشهد فقط بالروابط التي تعيدها مخرجات CLI.
  5. احفظ مخرجات JSON الكبيرة في ملف مؤقت عندما يُتوقَّع طرح أسئلة متابعة.
  6. استخدم العمليات الخلفية فقط لسير العمل طويل الأمد فعليًا؛ وإلا شغّلها في المقدمة.
  7. فضِّل أدوات Hermes الأصلية ما لم يرغب المستخدم في Parallel تحديدًا أو يحتاج سير عمل مقتصرًا عليها.

الخيارات والأنماط الشائعة

خيارات مفيدة شائعة:

  • --json لمخرجات منظَّمة
  • --no-wait للمهام غير المتزامنة
  • --previous-interaction-id <id> لمهام المتابعة التي تعيد استخدام سياق سابق
  • --max-results <n> لعدد نتائج البحث
  • --mode one-shot|agentic لسلوك البحث
  • --include-domains domain1.com,domain2.com
  • --exclude-domains domain1.com,domain2.com
  • --after-date YYYY-MM-DD

اقرأ من stdin عندما يكون ذلك مناسبًا:

البحث

استخدمها لعمليات بحث ويب حالية بنتائج منظَّمة.

قيود مفيدة:

  • --include-domains لتضييق النطاق إلى مصادر موثوقة
  • --exclude-domains لاستبعاد النطاقات المزعجة
  • --after-date للتصفية حسب الحداثة
  • --max-results عندما تحتاج تغطية أوسع

إذا كنت تتوقّع أسئلة متابعة، احفظ المخرجات:

عند تلخيص النتائج:

  • ابدأ بالإجابة
  • أدرج التواريخ والأسماء والحقائق الملموسة
  • استشهد فقط بالمصادر المُعادة
  • تجنّب اختلاق روابط أو عناوين مصادر

الاستخراج

استخدمها لاستخراج محتوى نظيف أو markdown من رابط.

استخدم --objective عندما تكون الصفحة واسعة وتحتاج شريحة واحدة فقط من المعلومات.

البحث العميق

استخدمها لمهام بحث متعددة الخطوات أعمق قد تستغرق وقتًا.

مستويات المعالج الشائعة:

  • lite / base لتمريرات أسرع وأرخص
  • core / pro لتوليف أكثر شمولًا
  • ultra لأثقل مهام البحث

متزامن

إطلاق غير متزامن + استطلاع

ربط السياق / المتابعة

سير عمل Hermes الموصى به:

  1. أطلِق باستخدام --no-wait --json
  2. احفظ مُعرِّف التشغيل/المهمة المُعاد
  3. إذا أراد المستخدم متابعة عمل آخر، تابع مباشرةً
  4. لاحقًا استدعِ status أو poll
  5. لخِّص التقرير النهائي مع استشهادات من المصادر المُعادة

الإثراء

الحالة / الاستطلاع

استخدم مصفوفات JSON صريحة لتعريفات الأعمدة عند العمل بدون تفاعل. تحقّق من ملف المخرجات قبل الإبلاغ عن النجاح.

FindAll

استخدمها لاكتشاف كيانات على نطاق الويب عندما يريد المستخدم مجموعة بيانات مُكتشَفة بدلًا من إجابة قصيرة.

هذا خيار أنسب من البحث العادي عندما يريد المستخدم مجموعة كيانات مُكتشَفة يمكن مراجعتها أو تصفيتها أو إثراؤها لاحقًا.

المراقبة

استخدمها لاكتشاف التغييرات المستمر عبر الزمن.

الإنشاء عادةً هو الجزء الحساس لأن التواتر والتسليم يهمّان:

استخدم هذا عندما يريد المستخدم تتبّعًا متكررًا لصفحة أو مصدر بدلًا من جلب لمرة واحدة.

أنماط الاستخدام الموصى بها لـ Hermes

إجابة سريعة مع استشهادات

  1. شغّل parallel-cli search ... --json
  2. حلِّل العناوين والروابط والتواريخ والمقتطفات
  3. لخِّص مع استشهادات مضمَّنة من الروابط المُعادة فقط

التحقيق في رابط

  1. شغّل parallel-cli extract URL --json
  2. عند الحاجة، أعد التشغيل مع --objective أو --full-content
  3. اقتبس أو لخِّص محتوى markdown المُستخرَج

سير عمل بحث طويل

  1. شغّل parallel-cli research run ... --no-wait --json
  2. خزّن المُعرِّف المُعاد
  3. تابع عملًا آخر أو استطلِع الحالة دوريًا
  4. لخِّص التقرير النهائي مع استشهادات

سير عمل إثراء منظَّم

  1. افحص ملف المدخلات وأعمدته
  2. استخدم enrich suggest أو زوّد أعمدة إثراء صريحة
  3. شغّل enrich run
  4. استطلِع اكتمال المهمة عند الحاجة
  5. تحقّق من ملف المخرجات قبل الإبلاغ عن النجاح

التعامل مع الأخطاء ورموز الخروج

توثِّق CLI رموز الخروج التالية:

  • 0 نجاح
  • 2 مدخل غير صحيح
  • 3 خطأ مصادقة
  • 4 خطأ API
  • 5 انتهاء المهلة (timeout)

إذا واجهت أخطاء مصادقة:

  1. تحقّق من parallel-cli auth
  2. تأكّد من PARALLEL_API_KEY أو شغّل parallel-cli login / parallel-cli login --device
  3. تحقّق من أن parallel-cli موجودة في PATH

الصيانة

تحقّق من حالة المصادقة/التثبيت الحالية:

أوامر التحديث:

المزالق

  • لا تُغفل --json ما لم يرغب المستخدم صراحةً في مخرجات مهيَّأة لقراءة بشرية.
  • لا تستشهد بمصادر غير موجودة في مخرجات CLI.
  • قد يتطلّب login تفاعلًا عبر PTY/المتصفح.
  • فضِّل التنفيذ في المقدمة للمهام القصيرة؛ لا تُفرِط في استخدام العمليات الخلفية.
  • بالنسبة لمجموعات النتائج الكبيرة، احفظ JSON في /tmp/*.json بدلًا من حشو كل شيء في السياق.
  • لا تختر Parallel بصمت عندما تكون أدوات Hermes الأصلية كافية بالفعل.
  • تذكّر أن هذا سير عمل من مزوّد خارجي يتطلّب عادةً مصادقة حساب واستخدامًا مدفوعًا يتجاوز المستوى المجاني.
