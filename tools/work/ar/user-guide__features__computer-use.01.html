الاختبار باستخدام بناء محلي لـ cua-driver

عندما تطوّر cua-driver نفسه — أو تريد اختبار إصلاح لم يُصدر بعد — وجّه Hermes إلى ملف تنفيذي بنيته من المصدر بدلًا من الإصدار المنشور. يحدد Hermes موقع المشغّل عبر shutil.which("cua-driver") ولا يفرض HERMES_CUA_DRIVER_VERSION، لذا يُقبل البناء المحلي (الذي يظهر إصداره على شكل 0.0.0-local-*) كما هو. هناك طريقتان:

الخيار A — install-local (البناء ثم إضافته إلى PATH)

من النسخة المسحوبة (checkout) لديك من trycua/cua، شغّل المُثبّت المحلي الأصلي. فهو يبني الـ backend المكتوب بـ Rust في وضع الإصدار (release) ويضع cua-driver في بنية التثبيت نفسها التي يستخدمها مُثبّت الإنتاج، مع إضافة مجلد bin الخاص به إلى PATH لديك:

  • على Windows يُجهَّز البناء ضمن %USERPROFILE%\.cua-driver\packages\… ويُربط إليه %LOCALAPPDATA%\Programs\Cua\cua-driver\bin (المُضاف إلى PATH الخاص بالمستخدم) عبر junction. أما على macOS/Linux فيُنشأ symlink لـ cua-driver داخل ~/.local/bin (يمكنك تغييره عبر --bin-dir <path>).
  • يتخطى -NoAutoStart تسجيل خدمة daemon cua-driver-serve التي تعمل عند تسجيل الدخول — فلا تحتاج إليها لاختبار Hermes (راجع الملاحظات).

ثم افتح shell جديدًا (كي يظهر تغيير PATH) وتحقق:

الخيار B — توجيه Hermes مباشرةً إلى الملف التنفيذي المبني (أسرع دورة عمل)

تخطَّ إجراءات التثبيت كليًا: نفّذ cargo build واضبط HERMES_CUA_DRIVER_CMD على الملف التنفيذي الناتج. هذا الخيار هو الأنسب لدورة التعديل/البناء/الاختبار السريعة.

التأكد من أن Hermes يستخدم بناءك

  • يطبع hermes computer-use status مسار الملف التنفيذي الذي حُدِّد وإصداره.
  • يتأكد hermes computer-use doctor من إمكانية الوصول إلى الملف التنفيذي ويختبر مسار MCP الكامل من البداية إلى النهاية.
  • داخل الجلسة، يختبر computer_use(action="capture") العملية الفرعية cua-driver mcp التي أُطلقت.

ملاحظات ومزالق

  • يُطلق Hermes وسيط stdio من نوع cua-driver mcp. في الجلسة العادية يتصل هذا الوسيط بخدمة daemon القياسية على الجهاز (وقد يشغّلها). أما في وضع YOLO الصريح في Hermes، فيمتلك Hermes بدلًا من ذلك عملية فرعية خاصة cua-driver serve --embedded ويوجّه الوسيط إلى الـ socket أو الـ named pipe الخاص بها. ولا يزال نمط autostart/UIAccess على Windows مهمًا للإدخال التفاعلي في Session 1+ عبر SSH — راجع قسم القيود.
  • الملف التنفيذي المقفل على Windows. قد تحتفظ خدمة daemon cua-driver-serve العاملة بالملف cua-driver.exe وتمنع استبداله عند إعادة البناء. يعيد install-local.ps1 تسمية الملف التنفيذي المقفل تلقائيًا لإبعاده عن الطريق؛ أما إذا نفّذت cargo build يدويًا (الخيار B)، فأوقفها أولًا عبر cua-driver autostart disable (أو schtasks /End /TN cua-driver-serve).
  • دورة إعادة البناء. بعد تعديل مصدر cua-driver، أعد تشغيل install-local (يعيد البناء والتجهيز ويبدّل junction current) في الخيار A، أو أعد تنفيذ cargo build فقط في الخيار B — ولا حاجة إلى أي تغيير في Hermes في الحالتين.
  • البنايات المحلية تتخطى فحص الإصدار. يحذّر Hermes عندما يكون cua-driver المثبّت أقدم من خط الأساس المختبَر لكل نظام تشغيل، لكنه يستثني بنايات التطوير 0.0.0-local-* — لذا لن يؤدي بناؤك المحلي إلى ظهور ذلك التحذير أبدًا.

استكشاف الأخطاء وإصلاحها

أول ما تفعله عند حدوث أي خلل: شغّل hermes computer-use doctor. تخبرك مصفوفة الفحوص المنظّمة (وتخبر أي وكيل يساعدك في التصحيح) بالضبط بما هو خاطئ.

حالات فشل محددة لا يكتشفها doctor:

computer_use backend unavailable: cua-driver is not installed — شغّل hermes computer-use install لجلب الملف التنفيذي لـ cua-driver، أو شغّل hermes tools وفعّل toolset الخاص بـ Computer Use.

النقرات تبدو بلا أثر — التقط الشاشة وتحقق. قد تكون هناك نافذة منبثقة (modal) لم ترها تحجب الإدخال. أغلقها باستخدام escape أو زر الإغلاق.

فهارس العناصر قديمة — فهارس SOM صالحة فقط حتى عملية capture التالية. أعد الالتقاط بعد أي إجراء يغيّر الحالة. يحمل الـ wrapper قيم element_token مبهمة لاكتشاف الفهارس القديمة — لذا سترى خطأً صريحًا بدلًا من نقرة خاطئة.

"blocked pattern in type text" — النص الذي حاولت كتابته عبر type يطابق قائمة أنماط الـ shell الخطرة. قسّم الأمر أو أعد النظر فيه.

التقاطات فارغة على Linux — DISPLAY غير مضبوط، أو أنك تعمل على Wayland خالص دون جسر XWayland. سيشير hermes computer-use doctor إلى ذلك بـ ax_capability: fail مع التلميح Set DISPLAY (X11)….

التقاطات فارغة على Windows عبر SSH — أنت في Session 0 (جلسة الخدمات). تحكّم مباشرةً من RDP / console، أو اضبط نمط التشغيل التلقائي — راجع cua.ai/docs/how-to-guides/driver/windows-ssh.
