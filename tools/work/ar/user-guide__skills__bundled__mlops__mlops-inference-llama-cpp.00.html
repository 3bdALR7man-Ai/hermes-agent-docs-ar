llama.cpp + GGUF

استخدم هذه المهارة لعمليات الـ inference المحلية بصيغة GGUF، أو اختيار الـ quant، أو اكتشاف مستودعات Hugging Face المتوافقة مع llama.cpp.

متى تُستخدم

  • تشغيل نماذج محلية على CPU أو Apple Silicon أو CUDA أو ROCm أو معالجات Intel الرسومية
  • إيجاد ملف GGUF المناسب لمستودع Hugging Face محدّد
  • بناء أمر llama-server أو llama-cli انطلاقًا من الـ Hub
  • البحث في الـ Hub عن نماذج تدعم llama.cpp فعليًا
  • حصر ملفات .gguf المتاحة وأحجامها لمستودع معيّن
  • الاختيار بين متغيرات Q4/Q5/Q6/IQ وفقًا لذاكرة RAM أو VRAM لدى المستخدم

سير عمل اكتشاف النماذج

فضِّل مسارات العمل عبر الروابط (URL) قبل اللجوء إلى hf أو Python أو سكربتات مخصّصة.

  1. ابحث عن مستودعات مرشّحة في الـ Hub:
    • الأساس: https://huggingface.co/models?apps=llama.cpp&sort=trending
    • أضف search=<term> لعائلة نماذج محدّدة
    • أضف num_parameters=min:0,max:24B أو ما شابه عندما تكون هناك قيود على الحجم لدى المستخدم
  2. افتح المستودع بعرض التطبيق المحلي (local-app) الخاص بـ llama.cpp:
    • https://huggingface.co/<repo>?local-app=llama.cpp
  3. اعتمد مقتطف local-app كمصدر موثوق عندما يكون ظاهرًا:
    • انسخ أمر llama-server أو llama-cli كما هو تمامًا
    • اذكر الـ quant الموصى به كما يعرضه HF تمامًا
  4. اقرأ رابط ?local-app=llama.cpp نفسه كنص صفحة أو HTML واستخرج القسم الموجود تحت Hardware compatibility:
    • فضِّل تسميات الـ quant وأحجامه الدقيقة الواردة فيه على الجداول العامة
    • احتفظ بالتسميات الخاصة بالمستودع مثل UD-Q4_K_M أو IQ4_NL_XL
    • إن لم يكن هذا القسم ظاهرًا في مصدر الصفحة الذي تم جلبه، فأشِر إلى ذلك واعتمد بدلًا منه على tree API إلى جانب إرشادات الـ quant العامة
  5. استعلم عن tree API للتأكد مما هو موجود فعليًا:
    • https://huggingface.co/api/models/<repo>/tree/main?recursive=true
    • احتفظ بالعناصر التي يكون فيها type مساويًا لـ file وينتهي فيها path بـ .gguf
    • استخدم path وsize كمصدر موثوق لأسماء الملفات وأحجامها بالبايت
    • افصل نقاط التحقق (checkpoints) المكمَّمة (quantized) عن ملفات projector من نوع mmproj-*.gguf وملفات shard من نوع BF16/
    • استخدم https://huggingface.co/<repo>/tree/main فقط كخيار احتياطي للعرض البشري
  6. إن لم يكن مقتطف local-app مرئيًا كنص، أعِد بناء الأمر انطلاقًا من المستودع والـ quant المختار:
    • اختيار مختصر للـ quant: llama-server -hf <repo>:<QUANT>
    • بديل بالملف الدقيق: llama-server --hf-repo <repo> --hf-file <filename.gguf>
  7. لا تقترح التحويل من أوزان Transformers إلا إذا كان المستودع لا يوفّر ملفات GGUF أصلًا.

اختيار الـ quant

اعتمد على صفحة الـ Hub أولًا، وعلى القواعد العامة (heuristics) ثانيًا.

  • فضِّل الـ quant الدقيق الذي تُشير إليه HF كمتوافق مع ملف عتاد (hardware profile) المستخدم.
  • للمحادثة العامة، ابدأ بـ Q4_K_M.
  • للعمل البرمجي أو التقني، فضِّل Q5_K_M أو Q6_K إذا سمحت الذاكرة بذلك.
  • لميزانيات RAM الضيقة جدًا، فكّر في Q3_K_M أو متغيرات IQ، أو متغيرات Q2 فقط إن كان المستخدم يُعطي الأولوية صراحةً للمواءمة على حساب الجودة.
  • للمستودعات متعددة الوسائط (multimodal)، اذكر mmproj-*.gguf بشكل منفصل. فملف الـ projector ليس ملف النموذج الرئيسي.
  • لا توحّد (normalize) التسميات الخاصة بالمستودع. إذا كانت الصفحة تكتب UD-Q4_K_M، فاذكر UD-Q4_K_M.

استخراج ملفات GGUF المتاحة من مستودع

عندما يسأل المستخدم عن ملفات GGUF الموجودة، أعِد له:

  • اسم الملف
  • حجم الملف
  • تسمية الـ quant
  • ما إذا كان الملف نموذجًا رئيسيًا أم ملف projector مساعدًا

تجاهل ما يلي إلا إذا طُلب:

  • README
  • ملفات shard من نوع BF16
  • ملفات imatrix أو القطع الأثرية الخاصة بالمعايرة (calibration)

استخدم tree API في هذه الخطوة:

  • https://huggingface.co/api/models/<repo>/tree/main?recursive=true

بالنسبة لمستودع مثل unsloth/Qwen3.6-35B-A3B-GGUF، يمكن أن تُظهر صفحة local-app رقاقات (chips) للـ quant مثل UD-Q4_K_M وUD-Q5_K_M وUD-Q6_K وQ8_0، في حين تكشف tree API عن مسارات ملفات دقيقة مثل Qwen3.6-35B-A3B-UD-Q4_K_M.gguf وQwen3.6-35B-A3B-Q8_0.gguf مع أحجامها بالبايت. استخدم tree API لتحويل تسمية الـ quant إلى اسم ملف دقيق.
