أتمتة المتصفح

تمنح مجموعة أدوات browser الوكيلَ متصفح ويب حقيقيًا. تتولى أداة واحدة القيادة — browser_exec، التي تشغّل شيفرة Python كتبها النموذج على المتصفح عبر Chrome DevTools Protocol (CDP) — مع ثلاث أدوات مرافقة (browser_cdp و browser_dialog لا تتوفران إلا عند ضبط CDP endpoint، راجع الأدوات المرافقة):

الأداةالغرض
browser_execالتنقل والقراءة والنقر والكتابة واستخراج البيانات والتقاط لقطات الشاشة، بتشغيل Python مع helpers للمتصفح مستوردة مسبقًا.
browser_cdpإرسال أمر CDP خام واحد (ملفات تعريف الارتباط، والتحكم بالشبكة، والتقييم ضمن نطاق iframe، وكل ما لا تغطيه الـ helpers).
browser_dialogقبول أو تجاهل نافذة JavaScript أصلية (alert / confirm / prompt / beforeunload) تحجب الصفحة.
browser_vaultتعبئة بيانات تسجيل الدخول المحفوظة والبطاقات والعناوين ورموز 2FA في الصفحة الحالية دون أن تدخل الأسرار إلى المحادثة.

مصدر المتصفح خيار منفصل:

  • Chromium المحلي (الافتراضي) — يشغّل Hermes نسخة Chromium المُحزَّمة الخاصة به، بوضع headless، مع متصفح واحد لكل جلسة. دون مفتاح API ودون إعداد.
  • المتصفحات السحابية — اشتراك Nous، أو Browserbase، أو سحابة Browser Use، أو Firecrawl، أو إضافة (plugin) لمزوّد متصفح.
  • Lightpanda — محرك headless خفيف للتصفح النصي أولًا على الأجهزة الصغيرة.
  • متصفحك الخاص — اتصل بمتصفح Chrome أو Brave أو Chromium أو Edge قيد التشغيل باستخدام /browser connect.
  • ملفك الشخصي الحقيقي — نسخة مُدارة من ملف متصفحك اليومي، بما فيها تسجيلات الدخول (اختياري، بتفعيل منك).
نصيحة

لاسترجاع المعلومات البسيط، فضّل web_search أو web_extract — فهما أسرع وأرخص. استخدم المتصفح عندما يحتاج الوكيل إلى التفاعل مع صفحة (النقر على الأزرار، وتعبئة النماذج، والتعامل مع المحتوى الديناميكي).

كيف تعمل browser_exec

يرسل كل استدعاء كتلة Python (code) تعمل وقد استُوردت لها helpers المتصفح مسبقًا؛ وما تطبعه الشيفرة يعود نتيجةً للاستدعاء. تستمر جلسة المتصفح عبر الاستدعاءات (التبويبات المفتوحة وملفات تعريف الارتباط والصفحة الحالية)، أما متغيرات Python فلا تستمر — إذ يبدأ كل استدعاء بمفسّر جديد. ويبقى مجلد workspace خاص بالجلسة ($BH_AGENT_WORKSPACE، ويُعاد أيضًا باسم workspace) بين الاستدعاءات، فيمكن لعمليات الاستخراج الطويلة إلحاق الدفعات بملف ثم تجميعها في النهاية.

الـ helpers:

Helperوظيفتها
new_tab(url)فتح URL (استخدمها للتنقل الأول).
goto_url(url)التنقل في التبويب الحالي (للتنقلات اللاحقة).
wait_for_load()انتظار اكتمال تحميل الصفحة.
page_info()تلخيص حالة الصفحة الحالية.
js(expr)تقييم JavaScript وإرجاع القيمة (غلّف أجسام الدوال هكذا: js('(() => {...})()')).
fill_input(selector, text)الكتابة في حقل إدخال.
click_at_xy(x, y)النقر على إحداثيات منفذ العرض (viewport).
capture_screenshot()حفظ لقطة شاشة وطباعة مسارها.
cdp('Domain.method', **kwargs)CDP الخام — مثل cdp('Accessibility.getFullAXTree') للحصول على شجرة إمكانية الوصول، و cdp('DOM.getBoxModel', backendNodeId=n) للحصول على إحداثيات النقر.
ensure_real_tab()التعافي من تبويب قديم أو داخلي.

يجمع النموذج إجراءً فرعيًا كاملًا (التنقل والانتظار والاستخراج والتنفيذ) في استدعاء واحد بدلًا من استدعاء لكل خطوة:

لقطات الشاشة. مع نموذج يدعم الرؤية أصلًا، تُرفق الصورة المحفوظة عبر capture_screenshot() بنتيجة الأداة ويفحصها النموذج مباشرة. أما النماذج النصية فقط فيُطلب منها العمل نصيًا أولًا (page_info() و js() و fill_input())؛ ويمكنها مع ذلك تمرير مسار محفوظ إلى vision_analyze. وعلى منصات المراسلة يمكنك أن تطلب من الوكيل إرسال لقطة شاشة إليك — فتصلك كمرفق صورة أصلي.

المعاملات. إلى جانب code، تقبل الأداة timeout_s (الافتراضي 300، والحد الأقصى 1800) و session. يحصل كل اسم session على عملية driver خاصة به ومتصفح خاص به (Chromium منفصل محليًا، ومتصفح سحابي منفصل مع المزوّدين السحابيين)، فلا تتعارض subagents المتوازية أو المحادثات المتزامنة على متصفح مشترك واحد. وعند إغفال session تُستخدم الجلسة الافتراضية المشتركة، وهي مناسبة للتصفح الواحد في كل مرة. وعندما يكون التصفح بالملف الشخصي الحقيقي مفعّلًا، تتيح الأداة أيضًا الخيار local (راجع ذلك القسم).

ملاحظة

تنفّذ browser_exec شيفرة Python كتبها النموذج على جهازك، لذا لا تُقدَّم إلا للجلسات التي لديها أيضًا toolset الخاص بـ terminal. والمنصة المضبوطة دون وصول إلى الطرفية (مثل واجهة مراسلة مقيّدة) لا تحصل على متصفح.

الـ driver هو browser-harness، المحرك الذي يعمل عليه Browser Use CLI. وهو اعتمادية Python عادية لـ Hermes، لذا يشحنه كل تثبيت — بما فيه تطبيق Desktop — دون تنزيل منفصل.

Chromium المحلي (الافتراضي)

عندما لا يكون هناك مزوّد سحابي ولا endpoint من /browser connect ولا مفتاح ملف شخصي حقيقي مضبوطًا، يشغّل Hermes نسخة Chromium للجلسة بنفسه ويوجّه browser_exec إليها. ولا يُمَسّ متصفح Chrome المثبّت لديك أبدًا — فلا يوجد مفتاح chrome://inspect تحتاج إلى تفعيله ولا نافذة منبثقة "Allow remote debugging?" — كما يعمل على الخوادم عديمة الواجهة (headless) التي لا تحتوي على متصفح مكتبي إطلاقًا.

  • متصفح واحد لكل جلسة، بملف شخصي جديد مؤقت افتراضيًا: يبدأ الوكيل دون تسجيل دخول في أي موقع، ولا يبقى شيء بعد انتهاء الجلسة.
  • headless افتراضيًا. اضبط browser.headed: true للحصول على نافذة مرئية (راجع أدناه).
  • تنظيف تلقائي. يُغلق المتصفح بعد browser.inactivity_timeout ثانية من الخمول (الافتراضي 120)، وعند خروج Hermes، وبواسطة عملية تنظيف العمليات اليتيمة إن تعطّلت عملية.

أي Chromium. يختار Hermes أول ما يجده من الآتي:

  1. browser.executable_path، إن كان مضبوطًا.
  2. نسخة Chromium (Chrome for Testing) التي يثبّتها مدير حزم Hermes — إذ تثبّتها المُثبّتات و hermes update افتراضيًا.
  3. /etc/hermes/chromium-executable-path في صورة Docker الرسمية.
  4. نسخة chromium / chromium-browser الخاصة بالنظام على PATH (Android/Termux، والمنصات التي لا يملك مدير الحزم بناء Chromium لها).

إن لم يُعثر على أي منها، تعرض أداة المتصفح تلميحًا واضحًا بدلًا من الفشل بصمت. وإذا ثبّتّ باستخدام --skip-browser / -SkipBrowser، أو فشل التنزيل، فثبّته باستخدام:

يلغي هذا أيضًا اختيار --skip-browser السابق، فتُبقي التحديثات المتصفح محدّثًا. وعلى Linux قد يحتاج Chromium أيضًا إلى مكتبات النظام الخاصة بالتوزيعة (يثبّتها npx playwright install-deps chromium على Debian/Ubuntu). وعلى Android/Termux، نفّذ pkg install chromium حيث يوفّره المستودع لديك؛ وبدون Chromium على النظام يكون التصفح غير متاح على ذلك الجهاز.

الخيارات المحلية (~/.hermes/config.yaml):

يحتفظ browser.user_data_dir بملفات تعريف الارتباط وتسجيلات الدخول عبر الجلسات: فتتشارك كل الجلسات حينها مجلد الملف الشخصي ذاك. اتركه فارغًا للحصول على تصفح معزول مؤقت.

الوضع المرئي (headed) — نافذة المتصفح المرئية

يفعل الوضع المرئي أمرين:

  1. يشغّل Chromium بنافذة مرئية، فيمكنك مراقبة عمل الوكيل والتدخل يدويًا (تحديات تسجيل الدخول، و CAPTCHA).
  2. يُبقي المتصفح مفتوحًا بين الأدوار. عادةً يُنظَّف المتصفح بعد كل رد من الوكيل؛ وفي الوضع المرئي يُتخطى التنظيف في كل دور لتبقى حالة تسجيل الدخول نشطة طوال المحادثة.

لا تزال المتصفحات الخاملة تُنظَّف بعد browser.inactivity_timeout، وتُغلق كلها عند الإيقاف. وعلى مضيف بلا شاشة (الخوادم، CI) يعمل المتصفح دائمًا في وضع headless. ولا يؤثر الوضع المرئي إلا في المتصفحات المحلية — أما الجلسات السحابية فلا تتأثر.

المتصفحات السحابية

لمشتركي Nous

إذا كان لديك اشتراك مدفوع في Nous Portal، فيمكنك استخدام متصفح سحابي عبر Tool Gateway دون أي مفاتيح API منفصلة. يمكن للتثبيتات الجديدة تنفيذ hermes setup --portal لتسجيل الدخول وتفعيل كل أدوات الـ gateway دفعة واحدة؛ أما التثبيتات الحالية فيمكنها اختيار Nous Subscription كمزوّد للمتصفح عبر hermes model أو hermes tools.

اختر مزوّدًا في hermes tools → Browser Automation. ثم تقود browser_exec متصفح ذلك المزوّد تمامًا كما تقود Chromium المحلي.

Browser Use السحابي

احصل على مفتاح API من browser-use.com. يشغّل Browser Use Cloud متصفح Chromium مُدارًا مع تفعيل وضع التخفّي (stealth) و الـ proxies السكنية افتراضيًا، ويتضمن حلّ CAPTCHA، ويدعم الـ profiles الدائمة لملفات تعريف الارتباط (cookies) و localStorage وكلمات المرور المحفوظة.

Browserbase

احصل على بيانات الاعتماد من browserbase.com. الإعدادات الاختيارية:

Firecrawl

احصل على مفتاح API من firecrawl.dev، ثم اختر Firecrawl في hermes tools → Browser Automation.

اختيار المزوّد

توفّر مفاتيح .env أعلاه بيانات الاعتماد فقط. أما المتصفح النشط فيُحدَّد بواسطة الاختيار browser.cloud_provider الذي يكتبه hermes tools → Browser Automation (local أو browserbase أو browser-use أو firecrawl أو nous لـ Nous Subscription؛ وتضيف إضافات المزوّدين أسماءها الخاصة). بمجرد وجود اختيار، لا تؤدي إضافة مفتاح أو إزالته إلى تبديل المزوّد — والمزوّد المختار الذي ينقصه مفتاح يُنتج خطأً مع توجيه لتنفيذ hermes tools بدلًا من إعادة التوجيه بصمت. أما الإعدادات التي لم تُضبط من قبل فتواصل الاكتشاف التلقائي من بيانات الاعتماد المتاحة.

تستهلك الجلسات السحابية أرصدة المزوّد. ويحررها Hermes عند انتهاء المحادثة، وبعد browser.inactivity_timeout، وعند إنهاء العملية.

التوجيه الهجين: السحابة لعناوين URL العامة، والمتصفح المحلي لـ LAN/localhost

عند إعداد مزوّد سحابي، يُطلق Hermes تلقائيًا متصفح Chromium محليًا مساعدًا (sidecar) لعناوين URL التي تُحلّ إلى عنوان خاص/loopback/LAN (localhost, 127.0.0.1, 192.168.x.x, 10.x.x.x, 172.16-31.x.x, *.local, *.lan, *.internal ، و IPv6 loopback ::1 ، و link-local 169.254.x.x). أما عناوين URL العامة فتستمر في استخدام المزوّد السحابي في المحادثة نفسها.

يحلّ هذا سير العمل الشائع "أطوّر محليًا لكنني أستخدم Browserbase" — إذ يستطيع الوكيل التقاط لقطة شاشة للوحة التحكم لديك على http://localhost:3000 وكذلك استخراج بيانات https://github.com دون أن تبدّل المزوّدين أو تعطّل حماية SSRF. ولا يرى المزوّد السحابي عنوان URL الخاص أبدًا.

هذه الميزة مفعّلة افتراضيًا. لتعطيلها (فتذهب جميع عناوين URL إلى المزوّد السحابي المُعدّ):

عند تعطيل التوجيه التلقائي، تُرفض عناوين URL الخاصة مع الرسالة "Blocked: URL targets a private or internal address" ما لم تضبط أيضًا browser.allow_private_urls: true (الذي يسمح للمزوّد السحابي بمحاولة الوصول إليها — وهو ما لن ينجح عادةً لأن Browserbase وأمثاله لا يستطيعون الوصول إلى شبكة LAN لديك).

الـ sidecar هو نفسه Chromium المحلي الموصوف أعلاه، لذا يحتاج إلى تثبيت ذلك Chromium. ولا تزال عمليات إعادة التوجيه بعد التنقل من URL عام إلى عنوان خاص محظورة (فلا يمكنك استخدام حيلة إعادة التوجيه إلى الداخل للوصول إلى شبكتك المحلية عبر المسار العام).

التصفح بالـ profile الحقيقي (استخدم تسجيلات دخولك)

افتراضيًا، يعمل التصفح المحلي في profile نظيف مؤقت يُتخلّص منه لاحقًا — فالوكيل غير مسجّل الدخول في أي شيء. فعّل التصفح بالـ profile الحقيقي لتسمح للوكيل بالتصفح بصفتك أنت، مع تسجيلات الدخول وملفات تعريف الارتباط الموجودة لديك:

عند التفعيل، ينسخ Hermes الـ profile النشط لمتصفحك الافتراضي — أي الـ profile الذي تتصفح به فعلًا (Local State → profile.last_used)، مع ملفات تعريف الارتباط وتسجيلات الدخول المحفوظة والتفضيلات — إلى لقطة (snapshot) مُدارة تحت ~/.hermes/browser-profile/<browser>/ ، ثم يُطلق الملف التنفيذي الحقيقي لمتصفحك على تلك اللقطة ويربط محرك التصفح به. إن إطلاق الملف التنفيذي الحقيقي (بدلًا من Chromium مضمّن مع خيارات mock-keychain) هو ما يُبقي ملفات تعريف الارتباط المشفّرة بواسطة نظام التشغيل قابلة لفك التشفير — ففي macOS تُشفَّر ملفات تعريف الارتباط في Chrome عبر Keychain، والإطلاق باستخدام mock-keychain سيُسقطها جميعًا بصمت، فيفتح المتصفح دون تسجيل دخول. لا يُفتح الـ profile الحي لمتصفحك مباشرةً أبدًا: فاللقطة مجلد منفصل، لذا لا تتنازع مع متصفحك قيد التشغيل على قفل الـ profile، كما تتجنّب حظر Chrome 136+ للتصحيح عن بُعد على مجلد الـ profile الافتراضي. تُعاد مزامنة ملفات المصادقة (cookies/logins/preferences) من الـ profile الحقيقي كلما أُطلقت جلسة جديدة، لذا فإن تسجيلات الدخول التي تُجريها في متصفحك تظهر في جلسة الوكيل. لا يُنسخ إلا الـ profile النشط — ولا تُلتقط أبدًا لقطات لأي profiles أخرى في Chrome.

يعمل متصفح اللقطة (snapshot) في وضع headless — فهو يقود الملف الشخصي الخاص بك في الخلفية دون نافذة مرئية ولا يسرق التركيز أبدًا، لذا يمكنك مواصلة العمل بينما ينشر الوكيل التغريدات أو يعبّئ النماذج أو يستخرج البيانات نيابةً عنك. (يعني headless هنا وضع headless الجديد في Chrome، الذي يقرأ مخزن ملفات تعريف الارتباط العادي لديك، لذا تظل تسجيلات دخولك تُحمَّل.) وإذا كنت تفضّل مشاهدته أثناء العمل، فإن مفتاح الوضع المرئي (headed) نفسه ينطبق هنا — إذ يفتح browser.headed: true نافذة مرئية للتصفح بالملف الشخصي الحقيقي أيضًا. أما على مضيف بلا شاشة (الخوادم، CI) فيعمل دائمًا في وضع headless بغض النظر عن ذلك.

إذا كان لمتصفحك عدة profiles (مثل profile للعمل وآخر شخصي) ولا تريد أن يحدد "أيّ profile استخدمته آخر مرة" هوية الوكيل، فثبّت مصدر اللقطة صراحةً:

لا يعود الـ pin الذي يسمّي مجلد profile غير موجود إلى آخر profile مستخدم بصمت أبدًا: يحصل الوكيل على متصفح جديد دون تسجيلات دخولك مع رسالة تسمّي الـ pin الخاطئ.

عند إيقاف المفتاح مجددًا، يحذف Hermes مخزن اللقطات (~/.hermes/browser-profile/) عند الاستخدام التالي للمتصفح، حتى لا تبقى بيانات الاعتماد المنسوخة بعد سحب موافقتك.

عندما يتعذّر نسخ profile الخاص بك، يظل المتصفح يعمل

لا يحرمك التصفح بالـ profile الحقيقي من المتصفح أبدًا. وإذا تعذّر على Hermes نسخ profile الخاص بك، يحصل الوكيل على متصفح جديد دون تسجيلات دخولك في تلك الجلسة، وتذكر أول نتيجة متصفح السبب (real_profile_unavailable)، ليتمكن من إخبارك بدلًا من التصرف كأنه مسجّل الدخول. ويحدث ذلك في الحالات التالية:

  • Windows، عند أول استخدام فقط: يحتفظ Chrome/Edge/Brave قيد التشغيل بقاعدة بيانات ملفات تعريف الارتباط بقفل حصري (يمنع الجميع)، ولذلك تتطلب النسخة الأولى أن يكون المتصفح مغلقًا بالكامل، بما في ذلك أي نسخة تعمل في الخلفية أو شريط النظام (فخيار "continue running background apps when closed" في Chrome يُبقي chrome.exe قيد التشغيل بعد إغلاق النافذة). وبعد نسخة ناجحة واحدة، يعيد أي إطلاق لاحق والمتصفح مفتوح استخدام تلك النسخة: تكون تسجيلات دخولك كما كانت وقت آخر نسخة، وتتحدث في المرة التالية التي يشغّل فيها Hermes متصفحه بينما متصفحك مغلق.
  • المتصفح الافتراضي لديك ليس Chromium مدعومًا (Firefox، أو قناة Beta/Dev/Canary)، أو أن الـ profile المثبَّت غير موجود.
  • قاعدة بيانات ملفات تعريف الارتباط غير قابلة للقراءة أو تالفة: تسمّيها الرسالة وتذكر خطأ SQLite.

في macOS و Linux يحتفظ Chrome قيد التشغيل بالملفات Login Data وLogin Data For Account وWeb Data (كلمات المرور المحفوظة والملء التلقائي) بقفل كتابة، لكن الملف Cookies يمكن نسخه مع ذلك، وملفات تعريف الارتباط هي ما يُبقيك مسجّل الدخول في المواقع. ينسخ Hermes ملفات تعريف الارتباط ويتخطى ملفات كلمات المرور/الملء التلقائي المقفلة، فيمكنك إبقاء متصفحك مفتوحًا. وتُنسخ كل قاعدة بيانات عبر النسخ الاحتياطي المتصل في SQLite (وليس نسخًا خامًا للملف، وقد يفقد تسجيلات الدخول الحديثة).

اضبط browser.real_profile_autoclose: true ليتمكن Hermes من أن يعرض عليك إغلاق المتصفح نيابةً عنك عندما يكون محتفظًا بقفل الـ profile (حالة Windows). وحتى مع تفعيل هذا الخيار، لا يغلقه Hermes تلقائيًا أبدًا: يسألك الوكيل أولًا، ولا ينفّذ إلا بعد موافقتك الأمر hermes browser close-profile (الذي يُنهي شجرة عمليات المتصفح المرتبطة بذلك الـ profile، مع فقدان علامات التبويب غير المحفوظة). وعندها تلتقط جلسة المتصفح الجديدة profile الخاص بك.

  • المتصفحات المدعومة: Chrome و Edge و Brave و Brave Origin و Chromium (أيّها كان الافتراضي في نظام التشغيل). وإذا كان المتصفح الافتراضي من خارج عائلة Chromium (مثل Firefox) فيحصل الوكيل على متصفح جديد ورسالة واضحة بدلًا من تخمين الـ profile المطلوب استخدامه.
  • يعمل مع أي مصدر للمتصفح. محليًا يعمل تلقائيًا بمجرد تفعيل المفتاح. وفي ظل مزوّد متصفح سحابي، لا يزال بإمكان الوكيل فتح جلسة محلية بالملف الشخصي الحقيقي عند الطلب عبر أداة browser_exec باستخدام وسيطها local (لا تتيح الأداة هذا الوسيط إلا عند تفعيل هذا المفتاح) — بينما يواصل المزوّد السحابي خدمة كل ما عدا ذلك.
  • الإطار الأمني: هذه ميزة للراحة مشروطة بالموافقة، وليست حدًّا للعزل. فالصفحة التي يزورها الوكيل تعمل مع تسجيلات دخولك الحقيقية، لذا لا تفعّلها إلا عندما تريد أن يتصرف الوكيل بصفتك. معطّلة افتراضيًا.
  • Desktop: بدّل المفتاح من Capabilities → Tools → Browser → Use My Real Browser Profile (يقع المفتاح أعلى خيارات الـ backend)، أو من Settings → Config ضمن قسم browser القسم.

التشغيل المجدول وغير المراقَب

تسمح جلسة profile حقيقي لـ cronjob بالتحكم في موقع سجّلت دخولك إليه بالفعل. تعمل اللقطة دون واجهة افتراضيًا، وتُعاد مزامنة ملفات المصادقة (Cookies, Login Data ، …) من profile الحقيقي عند كل جلسة جديدة — تُعاد الاستفادة من الجلسة المفتوحة كما هي، لذا تحدث المزامنة عند إطلاق جلسة جديدة. دون بيانات اعتماد محفوظة في الخزنة، تظهر الجلسة المنتهية على الموقع كصفحة دخول تُبلغ عنها النبضة غير المراقَبة بدلًا من أن تتعطل عندها.

جهّز ثلاثة أمور قبل جدولة جلسة:

  • فعّل المفتاح. browser.use_real_profile قيمته الافتراضية false ، ودونه تحصل المهمة على profile نظيف بلا مصادقة — راجع أعلاه.
  • امنح المهمة toolset المتصفح: cronjob(action="create", enabled_toolsets=["browser", ...], ...) — تتقدم قائمة خاصة بكل مهمة على إعدادات منصة cron (التفاصيل).
  • افترض أنه لا يمكن طلب أي مدخلات. جلسة cron أو webhook أو API أو hermes chat -q ليس فيها من يجيب عن prompt، لذا فإن الموقع الذي لا يمكن استخدامه بملفات تعريف الارتباط المتزامنة وحدها — نموذج دخول أو تحدي 2FA جديد — يحتاج إلى حفظ بيانات اعتماده مسبقًا، بما فيها مفتاح المصادِق. هذه مهمة خزنة بيانات الاعتماد، وهي ما يتيح استمرار التشغيل بعد انتهاء جلستك الشخصية.

متطلب Windows: يجب إغلاق المتصفح تمامًا قبل أخذ اللقطة الأولى. وبعد ذلك، تعيد النبضة التي تعمل والمتصفح مفتوح استخدام آخر لقطة (تسجيلات الدخول كما كانت وقت تلك النسخة)؛ وإذا لم توجد لقطة بعد، تعمل النبضة على متصفح جديد غير مسجّل الدخول. ولا يغلقه Hermes أبدًا دون أن يسألك أولًا (راجع الملاحظة أعلاه).

المهارة المضمّنة product-price-monitor مثال تطبيقي للشكل المتكرر — عقد مراقبة JSON يُكتب أثناء الإعداد، ثم نبضة مجدولة واحدة تعيد قراءته وتقارن وتُنبه عند التغيير — لكنها تغطي جانب الجدولة لا تسجيل الدخول.
