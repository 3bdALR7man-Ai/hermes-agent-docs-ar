التخزين المؤقت للـ Prompt

يُفعّل Hermes التخزين المؤقت للـ prompt عبر الجلسات تلقائيًا عندما يدعمه المزوّد النشط — دون أي إعداد من المستخدم.

بالنسبة لـ Claude عبر Anthropic الأصلية, OpenRouter وNous Portal، يُرفق Hermes نقاط توقّف cache_control نقاط الفصل مع TTL مدته 1 ساعة (ttl: "1h") على system prompt وكتل المهارات. يدفع الإرسال الأول ضمن ساعة جديدة كامل معدّلات الإدخال؛ أما الإرسالات اللاحقة عبر أي جلسة ضمن الساعة نفسها فتُسحب من التخزين المؤقت بمعدّل القراءة المخفَّض. يعني هذا أن system prompt، ومحتوى المهارات المُحمَّل، والجزء الأولي من أي include طويل السياق يُعاد استخدامها عبر جلسات hermes وعبر الـ subagents المتفرّعة خلال الساعة الأولى.

يُحدّد Qwen Cloud (Alibaba DashScope) لدى المزوّد الأعلى مدة صلاحية التخزين المؤقت بـ 5 دقائق، لذا يستخدم Hermes مدة صلاحية نقطة التوقّف البالغة 5 دقائق هناك بدلًا من ذلك. أما مسارات Claude الأخرى عبر طرف ثالث (AWS Bedrock و Azure Foundry) فتعود إلى إعدادات التخزين المؤقت الافتراضية الخاصة بالمزوّد. يستخدم xAI Grok آلية منفصلة قائمة على معرّف محادثة مثبَّت للجلسة — راجع التخزين المؤقت للـ prompt في xAI.

لا يوجد مفتاح لتعطيل هذا — التخزين المؤقت مُفعّل دائمًا ويوفّر المال حتى في المحادثات ذات الدور الواحد لأن system prompt وحده يمثّل نسبة معتبرة من عدد رموز الإدخال.

المفتاح الصريح الوحيد هو مستوى مدة صلاحية التخزين المؤقت الذي يطلبه Hermes على نقاط توقّف من نمط Anthropic:

cache_ttl مدة صلاحية نقطة التوقّف التي يُرفقها Hermes لـ Claude عبر Anthropic API الأصلية و OpenRouter و Nous Portal. يُحترم فقط المستويان اللذان تدعمهما Anthropic ("5m", "1h") — وتُتجاهل أي قيمة أخرى. أما المزوّدون ذوو الحدود الخاصة (مثل Qwen Cloud، الذي لا يتجاوز 5 دقائق) فتبقى مُحدَّدة بما يسمح به الطرف الأعلى.

تكتب فئة 1h بسعر يعادل 2x السعر الأساسي للإدخال (تكتب فئة 5m بسعر 1.25x)، ولا تكون مجدية إلا إذا فصلت بين أدوارك أكثر من خمس دقائق — وإلا تُكتب كل نتيجة أداة بالمعدل الأعلى للاحتفاظ الذي لا يستخدمه أحد. "auto" يختار الفئة لكل جلسة بحسب من يحدّد وتيرتها: 1h للجلسات التي يكتب فيها شخص (CLI و TUI و Desktop و Telegram/Discord/Slack وسائر منصات المراسلة)، و 5m للجلسات التي تحدّد الآلات وتيرتها (subagents ومهام cron وتشغيل hermes -q لمرة واحدة و webhooks وعمال Kanban وخادم API والتشغيل المستدعى بأداة والتشغيل الدفعي). في تثبيت تُترك فيه الجلسات التفاعلية معلّقة ثم تُستأنف خلال اليوم، خفّض auto فاتورة كتابة التخزين المؤقت التفاعلي بنحو 40%، دون تغيير إنفاق subagents المتفرّعة. تُقيّد subagents المفوّضة دائمًا بـ 5m ، بصرف النظر عن الإعداد.
