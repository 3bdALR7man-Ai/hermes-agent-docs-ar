أوامر التوزيعات

نصيحة

جديد على التوزيعات؟ ابدأ بدليل توزيعات Profile — فهو يغطي السبب والتوقيت والكيفية بأمثلة كاملة. الأقسام أدناه مرجع CLI مقتضب لمن يعرف بالفعل ما يريده.

تحوّل التوزيعات profile إلى قطعة (artifact) قابلة للمشاركة وذات إصدار، تُنشَر بوصفها مستودع git. يثبّت المستلم التوزيعة بأمر واحد ويمكنه تحديثها لاحقًا في مكانها دون المساس بذكرياته المحلية أو جلساته أو بيانات اعتماده.

لا يُعَد auth.json و.env أبدًا جزءًا من التوزيعة — بل يبقيان على جهاز المستخدم المثبِّت.

تُحفَظ بيانات المستلم دائمًا (الذكريات، الجلسات، بيانات المصادقة، تعديلاته الخاصة على .env) عبر التثبيت الأولي والتحديثات اللاحقة.

معلومة

هناك طريقتان لمشاركة profile، وهما تتكاملان مع بعضهما. ينتج hermes profile export / import (وكذلك /export و/import في المحادثة) ملفًا واحدًا — بلا مستودع ولا بيان (manifest)، ويحمل التصدير من سطح المكتب سمتك وتخطيطك أيضًا. أما التوزيع (install / update / info) فينشر profile بوصفه مستودع git بحيث يمكن للمستلمين سحب تحديثات ذات إصدار لاحقًا. النسخ الاحتياطي والاستعادة هما وظيفة أخرى لملف التصدير. راجع طريقتان لمشاركة profile.

hermes profile install

يثبّت توزيعة profile من رابط git أو مجلد محلي.

الخيارالوصف
<source>رابط git (github.com/user/repo، https://...، git@...، ssh://، git://) أو مجلد محلي يحتوي على distribution.yaml في جذره.
--name NAMEتجاوز اسم الـ profile الوارد في البيان (manifest).
--aliasأنشئ أيضًا اسمًا مستعارًا (wrapper) في الـ shell (مثلًا telemetry → hermes -p telemetry).
--forceاستبدل profile موجودًا بنفس الاسم. تبقى بيانات المستخدم محفوظة.
-y، --yesتخطَّ مطالبة التأكيد المعروضة قبل التثبيت (منظر البيان manifest).

يعرض المثبِّت البيان، ويسرد متغيرات البيئة المطلوبة، ويحذّر بشأن مهام cron قبل طلب التأكيد. تُوضَع متغيرات البيئة المطلوبة في ملف .env.EXAMPLE تنسخه إلى .env وتملأه.

أمثلة:

hermes profile update

يعيد استنساخ التوزيع من مصدره المسجّل ويطبّق التحديثات. تُستبدل الملفات التابعة للتوزيع (SOUL.md و mcp.json)، كما تُستبدل المهارات ومهام cron التي يوفّرها التوزيع؛ أما المهارات أو مهام cron التي أضفتها بنفسك ضمن skills/ أو cron/ فتبقى في مكانها. لا تُمسّ بيانات المستخدم (الذكريات والجلسات والمصادقة و .env) مطلقًا. يُرفض مجلد skills/, cron/ أو مجلد فئة المهارات المرتبط برابط رمزي قبل كتابة أي شيء — استبدل الرابط بمجلد فعلي وأعد التنفيذ.

يُحفَظ config.yaml افتراضيًا لإبقاء تعديلاتك المحلية. مرّر --force-config لإعادته إلى الإعدادات الأصلية للتوزيعة.

hermes profile info

يطبع بيان توزيعة profile — الاسم، الإصدار، إصدار Hermes المطلوب، المؤلف، متطلبات متغيرات البيئة، رابط/مسار المصدر، و طابع Installed: الزمني المسجَّل عند آخر install أو update للتوزيعة. مفيد للتحقق مما يحتاجه profile مشترَك قبل تثبيته، ولاكتشاف "هذا الـ profile ثُبِّت منذ 6 أشهر ولم يُحدَّث منذ ذلك الحين."

يعرض hermes profile list أيضًا اسم التوزيعة وإصدارها في عمود Distribution، كما يُظهر hermes profile show <name> / delete <name> رابط المصدر بحيث تعرف بلمحة أي profiles أتت من مستودع git وأيها أُنشئ محليًا.

التوزيعات الخاصة

يعمل مستودع git خاص بوصفه مصدر توزيعة دون أي إعداد إضافي — إذ يستدعي التثبيت ملف git الثنائي العادي لديك، لذا تُطبَّق أي مصادقة أعددتها بالفعل في الـ shell (مفتاح SSH، مساعد git credential، بيانات اعتماد HTTPS المخزَّنة عبر GitHub CLI) تلقائيًا.

إن طلب الاستنساخ بيانات اعتماد تفاعليًا في طرفيتك أثناء التثبيت، يمر ذلك الطلب كما هو. أعدّ مصادقتك بالطريقة التي تستخدمها عادةً مع git clone لنفس المستودع أولًا، ثم ثبّت.

بيان التوزيعة (distribution.yaml)

لكل توزيعة ملف distribution.yaml في جذر مستودعها:

يدعم hermes_requires المعاملات >= و<= و== و!= و> و<، أو إصدارًا مجردًا (يُعامَل كـ >=). يفشل التثبيت برسالة خطأ واضحة إن لم يُلبِّ إصدار Hermes الحالي المواصفة.

distribution_owned اختياري. إذا ضُبط، تُحدّث تلك المسارات فقط؛ ويظل كل ما عداها في profile تابعًا للمستخدم. يُدمج مجلد المهارات، مثل skills/ أو فئة مثل skills/research/، على مستوى كل مهارة: تُستبدل المهارات التي يوفّرها التوزيع، وتبقى المهارات التي أضفتها هناك. وتُترك المهارة التي يحذفها المؤلف لاحقًا من التوزيع في مكانها عند التحديث، كما هو الحال مع skills/ في المستوى الأعلى. إذا أُغفل، تُطبّق القيم الافتراضية أعلاه.

نشر توزيعة

تأليف توزيعة هو مجرد عملية git push:

  1. في مجلد profile الخاص بك، أنشئ distribution.yaml يحتوي على الأقل على name وversion.
  2. هيّئ مستودع git (أو استخدم مستودعًا موجودًا) وادفعه إلى GitHub أو GitLab أو أي مضيف يمكن لـ Hermes الاستنساخ منه.
  3. أخبر المستلمين بتشغيل hermes profile install <your-repo-url>.

استخدم وسوم (tags) git للإصدارات ذات الرقم — يحصل من يستنسخون HEAD على أحدث حالتك، ويمكنك دائمًا رفع رقم version: في البيان.

hermes -p / hermes --profile

علم عام لتشغيل أي أمر Hermes تحت profile محدد دون تغيير الافتراضي الثابت. يتجاوز هذا الـ profile النشط لمدة تنفيذ الأمر فقط.

الخيارالوصف
-p <name>، --profile <name>الـ profile المراد استخدامه لهذا الأمر.

أمثلة:

hermes completion

يولّد سكربتات إكمال الـ shell. يتضمن إكمالات لأسماء profiles وأوامرها الفرعية.

المعطىالوصف
<shell>الـ shell المراد توليد إكمالات له: bash أو zsh أو fish.

أمثلة:

بعد التثبيت، يعمل إكمال tab لـ:

  • hermes profile <TAB> — الأوامر الفرعية (list، use، create، إلخ)
  • hermes profile use <TAB> — أسماء profiles
  • hermes -p <TAB> — أسماء profiles
