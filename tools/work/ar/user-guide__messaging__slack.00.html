إعداد Slack

اربط Hermes Agent بـ Slack كبوت باستخدام Socket Mode. يستخدم Socket Mode اتصالات WebSocket بدلًا من نقاط نهاية HTTP عامة، لذا لا تحتاج نسخة Hermes لديك إلى أن تكون متاحة للعموم — فهي تعمل خلف جدران الحماية، وعلى حاسوبك المحمول، أو على خادم خاص.

تطبيقات Slack الكلاسيكية أصبحت مُهملة

تطبيقات Slack الكلاسيكية (التي تستخدم RTM API) أصبحت مُهملة بالكامل في مارس 2025. يستخدم Hermes حزمة Bolt SDK الحديثة مع Socket Mode. إذا كان لديك تطبيق كلاسيكي قديم، فيجب عليك إنشاء تطبيق جديد باتباع الخطوات أدناه.

الخطوة 1: إنشاء تطبيق Slack

أسرع طريقة هي لصق manifest يولّده Hermes لك. فهو يعرّف كل slash command مدمج (/btw، /stop، /model، ...)، وكل نطاق (scope) OAuth مطلوب، وكل اشتراك بالأحداث (event subscription)، ويفعّل Socket Mode — كل ذلك دفعة واحدة.

الخيار ب: من الصفر (يدويًا)

  1. اذهب إلى https://api.slack.com/apps
  2. انقر على Create New App
  3. اختر From scratch
  4. أدخل اسم تطبيق (مثل "Hermes Agent") واختر مساحة العمل الخاصة بك
  5. انقر على Create App

ستصل إلى صفحة Basic Information الخاصة بالتطبيق. تابع مع الخطوات 2 إلى 6 أدناه.

انتقل إلى Features → OAuth & Permissions في الشريط الجانبي. مرّر إلى Scopes → Bot Token Scopes وأضف التالي:

app_mentions:readاكتشاف الإشارة إلى البوت (@mention) في القنوات

غياب النطاقات = غياب الميزات

بدون channels:history و groups:history، فإن البوت لن يستقبل الرسائل في القنوات — وسيعمل فقط في الرسائل المباشرة. وبدون files:read، يمكن لـ Hermes التحدث لكن لا يمكنه قراءة المرفقات التي يرفعها المستخدمون بشكل موثوق. هذه هي النطاقات الأكثر شيوعًا في النسيان.

نطاقات اختيارية:

الخطوة 3: تفعيل Socket Mode

يتيح Socket Mode للبوت الاتصال عبر WebSocket بدلًا من الحاجة إلى عنوان URL عام.

  1. في الشريط الجانبي، اذهب إلى Settings → Socket Mode
  2. فعّل خيار Enable Socket Mode
  3. ستُطالَب بإنشاء App-Level Token:
    • سمّه شيئًا مثل hermes-socket (الاسم لا يهم)
    • أضف النطاق connections:write
    • انقر على Generate
  4. انسخ الـ token — يبدأ بـ xapp-. هذا هو SLACK_APP_TOKEN الخاص بك
نصيحة

يمكنك دائمًا العثور على App-Level Tokens أو إعادة توليدها من Settings → Basic Information → App-Level Tokens.

الخطوة 4: الاشتراك في الأحداث

هذه الخطوة حاسمة — فهي تتحكم في الرسائل التي يمكن للبوت رؤيتها.

  1. في الشريط الجانبي، اذهب إلى Features → Event Subscriptions
  2. فعّل خيار Enable Events
  3. وسّع قسم Subscribe to bot events وأضف:
الحدثمطلوب؟الغرض
message.imنعميستقبل البوت الرسائل المباشرة
message.mpimنعميستقبل البوت الرسائل في الرسائل المباشرة الجماعية (multi-person DMs) التي أُضيف إليها
message.channelsنعميستقبل البوت الرسائل في القنوات العامة التي أُضيف إليها
message.groupsموصى بهيستقبل البوت الرسائل في القنوات الخاصة المدعو إليها
app_mentionنعميمنع أخطاء Bolt SDK عند الإشارة إلى البوت (@mention)
  1. انقر على Save Changes في أسفل الصفحة
نسيان الاشتراك في الأحداث هو المشكلة الأكثر شيوعًا رقم 1 في الإعداد

إذا كان البوت يعمل في الرسائل المباشرة لكن ليس في القنوات، فمن شبه المؤكد أنك نسيت إضافة message.channels (للقنوات العامة) و/أو message.groups (للقنوات الخاصة). فبدون هذه الأحداث، لا يُرسل Slack رسائل القنوات إلى البوت إطلاقًا.

الخطوة 5: تفعيل تبويب Messages

تفعّل هذه الخطوة الرسائل المباشرة إلى البوت. وبدونها، يرى المستخدمون رسالة "Sending messages to this app has been turned off" عند محاولة إرسال رسالة مباشرة إلى البوت.

  1. في الشريط الجانبي، اذهب إلى Features → App Home
  2. مرّر إلى Show Tabs
  3. فعّل خيار Messages Tab
  4. فعّل خيار "Allow users to send Slash commands and messages from the messages tab"
بدون هذه الخطوة، تُحظر الرسائل المباشرة تمامًا

حتى مع كل النطاقات والاشتراكات بالأحداث الصحيحة، لن يسمح Slack للمستخدمين بإرسال رسائل مباشرة إلى البوت ما لم يكن تبويب Messages مفعّلًا. هذا متطلب من منصة Slack نفسها، وليس مشكلة في إعدادات Hermes.

الخطوة 6: تثبيت التطبيق في مساحة العمل

  1. في الشريط الجانبي، اذهب إلى Settings → Install App
  2. انقر على Install to Workspace
  3. راجع الصلاحيات ثم انقر على Allow
  4. بعد التفويض، سترى Bot User OAuth Token يبدأ بـ xoxb-
  5. انسخ هذا الـ token — هذا هو SLACK_BOT_TOKEN الخاص بك
نصيحة

إذا غيّرت النطاقات أو الاشتراكات بالأحداث لاحقًا، يجب عليك إعادة تثبيت التطبيق حتى تسري التغييرات. ستعرض صفحة Install App شريطًا يطالبك بذلك.

الخطوة 7: العثور على معرّفات المستخدمين للقائمة المسموح بها

يستخدم Hermes معرّفات الأعضاء (Member IDs) في Slack (وليس أسماء المستخدمين أو أسماء العرض) للقائمة المسموح بها.

للعثور على معرّف عضو:

  1. في Slack، انقر على اسم المستخدم أو صورته الرمزية
  2. انقر على View full profile
  3. انقر على زر ⋮ (المزيد)
  4. اختر Copy member ID

تبدو معرّفات الأعضاء كما يلي: U01ABC2DEF3. تحتاج معرّف عضويتك الخاص على الأقل.

Slash Commands

كل أمر من أوامر Hermes (/btw، /stop، /new، /model، /help، ...) هو slash command أصيل في Slack — تمامًا بنفس الطريقة التي تعمل بها في Telegram وDiscord. اكتب / في Slack وستسرد قائمة الإكمال التلقائي كل أوامر Hermes مع وصفها.

خلف الكواليس: يأتي Hermes مع manifest تطبيق Slack مولَّد (انظر الخطوة 1، الخيار أ) يعرّف كل أمر موجود في COMMAND_REGISTRY كـ slash command. وفي Socket Mode، يوجّه Slack حدث الأمر عبر الـ WebSocket بغض النظر عن حقل url في الـ manifest.

تجربة المراسلة الخاصة بـ Agent

تستخدم تطبيقات Slack الجديدة تجربة المراسلة Agent من Slack. يمكن لتطبيقات Hermes Assistant القائمة الانتقال بإعادة توليد الـ manifest مع --agent-view:

حدّث الـ manifest في Features → App Manifest، ثم أعد تثبيت التطبيق إذا طلب Slack ذلك. لا يمكن التراجع عن عرض Agent إلى عرض Assistant، وقد يحتاج المستخدمون إلى تحديث Slack يدويًا (hard-refresh) بعد التبديل. يشترك manifest Agent المولَّد في message.im و app_home_opened و app_context_changed، بحيث يمكن لـ Hermes تمييز رسالة مباشرة من تبويب Messages واستقبال سياق Slack النشط للمستخدم مع كل دور. يقدّم Hermes هذا السياق فقط كتصنيف (label)؛ فهو لا يقرأ سجل القناة المعروضة.

تحديث Slash Commands بعد التحديثات

عندما يضيف Hermes أوامر جديدة (مثلًا بعد hermes update)، أعد توليد الـ manifest وحدّث تطبيق Slack الخاص بك:

ثم في Slack:

  1. افتح https://api.slack.com/apps → تطبيق Hermes الخاص بك
  2. Features → App Manifest → Edit
  3. الصق المحتوى الجديد لملف ~/.hermes/slack-manifest.json
  4. Save. سيطلب Slack إعادة تثبيت التطبيق إذا تغيّرت النطاقات أو slash commands.

الأمر القديم /hermes <subcommand> لا يزال يعمل

للتوافق مع الإصدارات السابقة من الـ manifest، لا يزال بإمكانك كتابة /hermes bg run the tests — يوجّهه Hermes بنفس طريقة /bg run the tests. تعمل الأسئلة الحرة أيضًا: تُعامَل /hermes what's the weather? كرسالة عادية.

استخدام الأوامر داخل الـ threads (بادئة !cmd)

يحظر Slack نفسه slash commands الأصيلة داخل ردود الـ thread — جرّب /queue في thread وسيرد Slack برسالة "/queue is not supported in threads. Sorry!" لا يوجد إعداد على مستوى التطبيق يعيد تفعيلها؛ فـ Slack لا يوصّلها إلى Hermes إطلاقًا.

كحل بديل، يتعرّف Hermes على علامة ! في البداية كبادئة أمر بديلة تعمل داخل الـ threads (وفي أي مكان آخر). اكتب !queue، !stop، !model gpt-5.4، إلخ، كرد thread عادي — يعاملها Hermes بنفس طريقة صيغة الـ slash ويرد في نفس الـ thread.

يُفحص الرمز الأول فقط مقابل قائمة الأوامر المعروفة، لذا تمر الرسائل العادية مثل !nice work إلى الوكيل دون تغيير. تعمل صيغة العلامة أيضًا خلف الإشارة (@Hermes !stop) ومع المسافات البيضاء البادئة — كلاهما يُرسل كأوامر داخل الـ threads.

عادةً ما تُعرض مطالبات الموافقة (موافقة الأوامر الخطرة / execute_code) كأزرار تفاعلية. عندما يتعذّر توصيل الأزرار ويلجأ Hermes إلى مطالبة نصية، تطلب منك المطالبة الرد بـ !approve / !deny — الصيغة التي تعمل داخل الـ threads.

ردود الـ slash عابرة (ephemeral)

تُسلَّم الردود على slash command أصيل (مثل /status، /help) بشكل عابر — "Only visible to you" — بحيث لا تُغرق مخرجات الأوامر القناة أبدًا. يُستبدَل العنصر النائب "Running /cmd…" بالرد الفعلي؛ وتُقسَّم الردود الطويلة إلى رسائل عابرة متتالية. يحدّ Slack تدفق الرد عند 5 منشورات، لذا تُختتم المخرجات الطويلة جدًا بإشعار اقتطاع صريح بدلًا من إسقاطها بصمت. إذا فشل المسار العابر الأساسي، يعيد Hermes المحاولة عبر مسار API عابر ثانٍ — لا يُنشر رد الـ slash أبدًا علنًا في القناة كحل بديل. (الأوامر المكتوبة كرسائل عادية — !cmd في الـ threads، @Hermes /cmd — تُرَد عليها كرسائل مرئية عادية بدلًا من ذلك.)

مطالبات التوضيح (clarify) (أزرار بنقرة واحدة)

عندما يحتاج الوكيل إلى طرح سؤال متعدد الخيارات عليك (أداة clarify)، يعرضه Slack كأزرار Block Kit — نقرة واحدة لكل خيار، بالإضافة إلى زر "✏️ Other…" الذي يبدّل إلى وضع النص الحر (تصبح رسالتك المكتوبة التالية هي الإجابة). بعد النقر، تُحدَّث الرسالة في مكانها لتُظهر مَن أجاب وما الذي اختاره؛ وتُتجاهل النقرات اللاحقة على نفس المطالبة. تخضع نقرات الأزرار لنفس تفويض المستخدم الذي تخضع له الرسائل، والمطالبات منتهية الصلاحية (إعادة تشغيل الـ gateway، انتهاء المهلة) تطلب منك إعادة السؤال بدلًا من ابتلاع النقرة بصمت. تُعرَض أسئلة clarify المفتوحة كسؤال عادي وتقبل ردك المكتوب التالي. لا حاجة لأي إعداد — يعمل هذا بغض النظر عن ضبط rich_blocks.

كيف يستجيب البوت

فهم كيفية تصرّف Hermes في السياقات المختلفة:

السياقالسلوك
الرسائل المباشرةيستجيب البوت لكل رسالة — دون الحاجة إلى @mention
القنواتيستجيب البوت فقط عند الإشارة إليه (@mention) (مثل @Hermes Agent what time is it?). وفي القنوات، يرد Hermes في thread مرتبط بتلك الرسالة.
الـ Threadsإذا أشرت إلى Hermes (@mention) داخل thread قائم، فسيرد في نفس الـ thread. وبمجرد أن تكون للبوت جلسة نشطة في thread، فإن الردود اللاحقة في ذلك الـ thread لا تحتاج إلى @mention — يتابع البوت المحادثة بشكل طبيعي.
نصيحة

في القنوات، أشِر دائمًا إلى البوت (@mention) لبدء محادثة. وبمجرد أن يكون البوت نشطًا في thread، يمكنك الرد في ذلك الـ thread دون الإشارة إليه. أما خارج الـ threads، فتُتجاهَل الرسائل التي لا تتضمن @mention لمنع الضجيج في القنوات المزدحمة.
