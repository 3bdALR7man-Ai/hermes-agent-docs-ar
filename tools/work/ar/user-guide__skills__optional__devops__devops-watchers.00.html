Watchers

استطلع مصادر خارجية على فترات زمنية وتفاعل فقط مع العناصر الجديدة. ثلاثة سكربتات جاهزة بالإضافة إلى مساعد watermark مشترك؛ اربطها بمهمة cron (أو شغّلها عند الحاجة من الطرفية).

متى تُستخدم

  • يريد المستخدم مراقبة موجز RSS/Atom والحصول على إشعار بالإدخالات الجديدة
  • يريد المستخدم مراقبة issues / pulls / releases / commits لمستودع GitHub
  • يريد المستخدم استطلاع أي نقطة نهاية JSON والحصول على إشعار بالعناصر الجديدة
  • يطلب المستخدم "watcher لـ X" أو "أعلمني عند تغيّر X"

النموذج الذهني

الـ watcher هو مجرد سكربت:

  1. يجلب البيانات من المصدر الخارجي
  2. يقارنها بملف watermark يحتوي المعرّفات المُشاهدة مسبقًا
  3. يكتب الـ watermark الجديد مرة أخرى
  4. يطبع العناصر الجديدة على stdout (أو لا شيء عند عدم وجود تغيير)

تتولى السكربتات أدناه الأمور الثلاثة كلها. يشغّلها الوكيل عبر أداة الطرفية — من مهمة cron، أو webhook، أو محادثة تفاعلية — ويبلّغ بما هو جديد.

سكربتات جاهزة

توجد السكربتات الثلاثة كلها في $HERMES_HOME/skills/devops/watchers/scripts/ بمجرد تثبيت المهارة. يقرأ كل واحد منها WATCHER_STATE_DIR (الافتراضي $HERMES_HOME/watcher-state/) لملف حالته، مُفهرَسًا بمعطى --name.

السكربتما يراقبهمفتاح إزالة التكرار
watch_rss.pyرابط موجز RSS 2.0 أو Atom<guid> / <id>
watch_http_json.pyأي نقطة نهاية JSON تُعيد قائمة كائناتحقل معرّف قابل للتهيئة
watch_github.pyissues / pulls / releases / commits لمستودع في GitHubid / sha

السكربتات الثلاثة كلها:

  • يسجّل التشغيل الأول خط أساس — لا يعيد أبدًا تشغيل الموجز الحالي
  • الـ watermark مجموعة معرّفات محدودة (500 كحد أقصى) للحد من استهلاك الذاكرة
  • صيغة المخرجات: ## <title>\n<url>\n\n<optional body> لكل عنصر
  • مخرجات stdout فارغة عند عدم وجود جديد — يعامل المستدعي ذلك بصمت
  • كود خروج غير صفري عند أخطاء الجلب

كتابة watcher خاص بك

تستخدم السكربتات الثلاثة كلها القالب نفسه: تحميل الـ watermark، الجلب، حساب الفرق، الحفظ، الإصدار. scripts/_watermark.py هو المساعد المشترك؛ استورده لتحصل مجانًا على كتابة ذرية (atomic) + مجموعة معرّفات محدودة + خط أساس للتشغيل الأول. راجع أيًا من السكربتات المرجعية الثلاثة لترى كم هو قليل الكود التمهيدي (boilerplate) اللازم.

المزالق الشائعة

  1. طباعة ترويسة "لا عناصر جديدة" في كل دورة. يعتمد المستدعون على أن stdout الفارغ يعني الصمت. إذا طبعت أي شيء عند عدم وجود فرق، فأنت تُغرق القناة برسائل. تتعامل السكربتات المُرفَقة مع هذا، ويجب أن تفعل السكربتات المخصّصة الشيء نفسه.
  2. توقّع أن يُصدر التشغيل الأول عناصر. لن يفعل — يسجّل التشغيل الأول خط أساس. إذا احتجت ملخّصًا أوليًا، احذف ملف الحالة بعد التشغيل الأول أو أضِف خيار --prime-with-latest N في سكربتك الخاص.
  3. نمو الـ watermark بلا حدود. يحدّه المساعد المشترك عند 500 معرّف. ارفع الحد للموجزات كثيرة التغيّر؛ اخفضه على أنظمة ملفات محدودة.
  4. وضع مجلد الحالة حيث لا يستطيع sandbox الوكيل الكتابة. $HERMES_HOME/watcher-state/ قابل للكتابة دائمًا. قد لا ترى واجهات Docker/Modal الخلفية مسارات مضيف عشوائية.
