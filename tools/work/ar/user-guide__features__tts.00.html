الصوت و TTS

يدعم Hermes Agent كلًّا من إخراج تحويل النص إلى كلام (text-to-speech) وتفريغ الرسائل الصوتية نصيًا عبر جميع منصات المراسلة.

مشتركو Nous

إذا كان لديك اشتراك مدفوع في Nous Portal، فإن OpenAI TTS متاح عبر Tool Gateway دون الحاجة إلى مفتاح OpenAI API منفصل. يمكن لعمليات التثبيت الجديدة تشغيل hermes setup --portal لتسجيل الدخول وتفعيل كل أدوات الـ gateway دفعة واحدة؛ أما عمليات التثبيت الحالية فيمكنها اختيار Nous Subscription لـ TTS وحده عبر hermes model أو hermes tools.

الإعدادات

يختار MiniMax TTS المنطقة والـ endpoint وبيانات الاعتماد معًا:

  • القيمة region: "global" تستخدم https://api.minimax.io/v1/t2a_v2 مع MINIMAX_API_KEY.
  • القيمة region: "cn" تستخدم https://api.minimaxi.com/v1/t2a_v2 مع MINIMAX_CN_API_KEY.
  • إذا أُغفل region، تبقى الأولوية لـ MINIMAX_API_KEY حفاظًا على التوافق مع الإصدارات السابقة. وإذا لم يُضبط سوى MINIMAX_CN_API_KEY، يختار Hermes المنطقة cn.
  • يجب أن تتوفر للمنطقة المختارة صراحةً بيانات الاعتماد المطابقة لها، إذ لا يستعير Hermes أبدًا مفتاح المنطقة الأخرى. ولا يغيّر تجاوز base_url بيانات الاعتماد المختارة، ويُرفض أي تجاوز يشير إلى الـ endpoint الرسمي للمنطقة الأخرى.

التحكم في السرعة: تُطبَّق القيمة العامة tts.speed على جميع المزوّدين افتراضيًا. ويمكن لكل مزوّد تجاوزها بإعداد speed الخاص به (مثل tts.openai.speed: 1.5). وتتقدّم السرعة الخاصة بالمزوّد على القيمة العامة. القيمة الافتراضية هي 1.0 (السرعة العادية).

Persona Prompts في Gemini

يستطيع Gemini TTS اتباع توجيهات أداء مكتوبة بلغة طبيعية. اضبط tts.gemini.persona_prompt_file على ملف Markdown أو ملف نصي محلي يصف شخصية الصوت (persona). يمكن أن يتضمن الملف أقسامًا بأسلوب Gemini مثل AUDIO PROFILE و SCENE و DIRECTOR'S NOTES و SAMPLE CONTEXT و TRANSCRIPT.

إذا احتوى الملف على {transcript} أو {{ transcript }}، يستبدل Hermes هذا العنصر النائب بنص TTS الفعلي. وإلا فيُلحق Hermes قسمًا معنونًا TRANSCRIPT تلقائيًا. يبقى الـ prompt الخاص بالشخصية محليًا ولا يظهر في رد المحادثة.

الوسوم الصوتية (Gemini و xAI)

يدعم Gemini 3.1 Flash TTS من Google و Grok TTS من xAI وسومًا صوتية حرة بين أقواس مربعة مثل [whispers] و [excitedly] و [very slow] و [laughs]، وغيرها من ملاحظات الأداء التعبيري. فعّل tts.gemini.audio_tags أو tts.xai.auto_speech_tags كي يُجري Hermes مرحلة إعادة صياغة مخفية قبل TTS. تُدرج إعادة الصياغة الوسوم ضمن نص TTS فقط؛ ويبقى رد المحادثة المرئي دون تغيير.

تستخدم إعادة الصياغة auxiliary.tts_audio_tags، وتعتمد افتراضيًا على نموذج المحادثة الرئيسي لديك. تجاوز هذه المهمة المساعدة إذا أردت أن يتولى نموذج أرخص أو أسرع إدراج الوسوم.

اللغة (endpoints المتوافقة مع OpenAI): تُمرَّر tts.openai.language إلى الـ endpoint كمعامل طلب lang_code. وهي مخصصة لخوادم TTS المتوافقة مع OpenAI التي تدعم lang_code — مثل Kokoro-FastAPI، حيث تختار language: "es" محلّل الفونيمات الإسباني بدلًا من الإنجليزي الافتراضي. اتركها دون ضبط عند استخدام OpenAI API الرسمية، التي لا تقبل هذا المعامل. وعند عدم ضبطها، لا يُرسل أي شيء إضافي.

الفقاعات الصوتية في Telegram و ffmpeg

تتطلب الفقاعات الصوتية في Telegram صيغة الصوت Opus/OGG:

  • OpenAI و ElevenLabs و Mistral تُنتج Opus أصلًا — دون إعداد إضافي
  • Edge TTS (الافتراضي) يُخرج MP3 ويحتاج إلى ffmpeg للتحويل:
  • MiniMax TTS يُخرج MP3 ويحتاج إلى ffmpeg للتحويل من أجل الفقاعات الصوتية في Telegram
  • Google Gemini TTS يُخرج PCM خامًا ويستخدم ffmpeg لترميزه مباشرةً إلى Opus من أجل الفقاعات الصوتية في Telegram
  • xAI TTS يُخرج MP3 ويحتاج إلى ffmpeg للتحويل من أجل الفقاعات الصوتية في Telegram
  • NeuTTS يُخرج WAV ويحتاج كذلك إلى ffmpeg للتحويل من أجل الفقاعات الصوتية في Telegram
  • KittenTTS يُخرج WAV ويحتاج كذلك إلى ffmpeg للتحويل من أجل الفقاعات الصوتية في Telegram
  • Piper يُخرج WAV ويحتاج كذلك إلى ffmpeg للتحويل من أجل الفقاعات الصوتية في Telegram

دون ffmpeg، يُرسل الصوت الناتج عن Edge TTS و MiniMax TTS و NeuTTS و KittenTTS و Piper كملفات صوتية عادية (قابلة للتشغيل، لكنها تظهر كمشغّل مستطيل بدلًا من فقاعة صوتية).

نصيحة

إذا أردت الفقاعات الصوتية دون تثبيت ffmpeg، فانتقل إلى المزوّد OpenAI أو ElevenLabs أو Mistral.

Piper (محلي، 44 لغة)

Piper محرك TTS عصبي محلي وسريع من Open Home Foundation (القائمون على صيانة Home Assistant). يعمل بالكامل على المعالج (CPU)، ويدعم 44 لغة بأصوات مدرّبة مسبقًا، ولا يحتاج إلى مفتاح API.

ثبّته عبر hermes tools → Voice & TTS → Piper — وسينفّذ Hermes الأمر pip install piper-tts نيابةً عنك. أو ثبّته يدويًا: pip install piper-tts.

التبديل إلى Piper:

عند أول استدعاء TTS لصوت غير مخزّن محليًا، يشغّل Hermes python -m piper.download_voices <name> وينزّل النموذج (نحو 20-90MB حسب مستوى الجودة) إلى ~/.hermes/cache/piper-voices/. وتعيد الاستدعاءات اللاحقة استخدام النموذج المخزّن.

اختيار صوت. يغطي كتالوج الأصوات الكامل الإنجليزية والإسبانية والفرنسية والألمانية والإيطالية والهولندية والبرتغالية والروسية والبولندية والتركية والصينية والعربية والهندية وغيرها — ولكل منها مستويات الجودة x_low / low / medium / high. استمع إلى عينات الأصوات على rhasspy.github.io/piper-samples.

استخدام صوت منزّل مسبقًا. اضبط tts.piper.voice على مسار مطلق ينتهي بـ .onnx:

الإعدادات المتقدمة (tts.piper.length_scale / noise_scale / noise_w_scale / volume / normalize_audio، use_cuda) تقابل واحدًا لواحد إعدادات SynthesisConfig في Piper. وتُتجاهل في إصدارات piper-tts الأقدم.

التحميل المسبق والإلغاء عبر مفاتيح الكلام (المحركات المحلية)

تحمّل المحركات المحلية (Piper و KittenTTS) نموذجها عند الحاجة فقط (lazily)، لذا فدون مساعدة، يدفع الرد المنطوق الأول بعد تفعيل الكلام ثمن تحميل النموذج كاملًا — وفي التثبيت الجديد، ثمن تنزيل الصوت أيضًا — على شكل صمت قبل الكلمة الأولى. لذلك يعدّ Hermes مفاتيح تفعيل إخراج الكلام إشارةً إلى أن TTS على وشك أن يُستخدم:

  • Desktop — الخيار Read replies aloud تفضيل محلي في تطبيق سطح المكتب، مستقل عن إعداد voice.auto_tts الخاص بالـ gateway في Settings → Voice. تُرحَّل القيمة المشتركة مرة واحدة، ثم لا تتجاوز تغييرات إعدادات الـ gateway اللاحقة مفتاح سطح المكتب. إذا كان التخزين المحلي ممتلئًا أو غير متاح، يظل الاختيار ساريًا لهذه النافذة؛ ويبقى الاحتفاظ به بعد إعادة التحميل بأفضل جهد. يؤدي تفعيل Read replies aloud، أو بدء محادثة صوتية، إلى تحميل المحرك المضبوط مسبقًا في الخلفية فورًا. ويؤدي تعطيل كليهما مجددًا إلى إلغاء تحميل النموذج المقيم في الذاكرة (يبلغ حجم صوت Piper عشرات الـ MB، و KittenTTS حتى نحو 80MB) كي لا يبقى في الذاكرة العشوائية دون فائدة.
  • CLI / TUI — يفعل /voice tts (و /voice on عندما يكون voice.auto_tts مضبوطًا) الشيء نفسه؛ بينما يحرّره /voice off.

يحتفظ كل مفتاح بـ عقد استخدام (lease) على المحرك؛ ولا يُلغى تحميل النموذج إلا عند تحرير آخر عقد عبر كل الواجهات، لذا فإن إيقاف القراءة بصوت عالٍ في نافذة Desktop واحدة لا يسحب الصوت أبدًا من محادثة جارية في نافذة أخرى. أما مع المزوّدين السحابيين فلا يوجد نموذج للاحتفاظ به — إذ يقتصر دور المفتاح على التأكد من وجود الـ SDK الذي يُثبَّت عند الحاجة (edge-tts و ElevenLabs و Mistral). التحميل المسبق بأفضل جهد: فإذا تعذّر تحميل المحرك، يظل تفعيل المفتاح ناجحًا، ويرجع الرد الأول إلى التحميل عند الطلب كما في السابق.

يستدعي Desktop المسار POST /api/audio/tts-lease مع {"lease": "<name>", "active": true|false}؛ ويمكن للواجهات الأمامية الأخرى استخدام الـ endpoint نفسه.

يصل عقد الاستخدام نفسه أيضًا إلى المزوّدين الذين يعرّفهم المستخدم، لذا يستطيع خادم TTS المستضاف ذاتيًا تحميل نموذجه مسبقًا وإلغاء تحميله مع المفاتيح: إذ يشغّل مزوّد الأوامر الأمرين الاختياريين warm_command / release_command، ويتلقى مزوّد إضافة Python الاستدعاءين warm() / release().

مزوّدو الأوامر المخصصة

إذا كان محرك TTS الذي تريده غير مدعوم أصلًا (VoxCPM أو MLX-Kokoro أو XTTS CLI أو سكربت لاستنساخ الصوت أو أي شيء آخر يوفّر CLI)، يمكنك ربطه بوصفه مزوّدًا من نوع command دون كتابة أي كود Python. يكتب Hermes نص الإدخال في ملف UTF-8 مؤقت، ويشغّل أمر الـ shell الخاص بك، ثم يقرأ الملف الصوتي الذي أنتجه الأمر.

عرّف مزوّدًا واحدًا أو أكثر ضمن tts.providers.<name> وبدّل بينها عبر tts.provider: <name> — بالطريقة نفسها التي تبدّل بها بين المزوّدين المدمجين مثل edge و openai.

قيم output_format المدعومة: mp3 (الافتراضية)، wav، ogg، flac، m4a، aac، amr، opus. يجب أن يُنتج أمرك تلك الصيغة فعلًا (مثلًا عبر ffmpeg)؛ إذ يكتفي Hermes بالتحقق من القيمة المعلنة وتسمية ملف الإخراج وفقًا لها. وتؤول القيمة غير المعروفة إلى mp3. كما تُتاح الصيغة المختارة للأمر عبر العنصر النائب {format}.

بيئة العملية الفرعية: يعمل مزوّدو الأوامر (TTS و STT) مع إزالة أسرار Hermes من بيئة العملية الفرعية — إذ تُحذف tokens بوتات الـ gateway، ومفاتيح API لمزوّدي LLM، وبيانات اعتماد الترحيل الداخلية؛ بينما تُحفظ PATH و HOME وإعدادات اللغة المحلية (locale) وغيرها من المتغيرات العادية. إذا كان قالب الأمر يحتاج إلى مفتاح API خاص به من البيئة (مثل أمر curl من سطر واحد)، فأدرج أسماء المتغيرات ضمن env_passthrough في إعدادات المزوّد:

مثال: Doubao (seed-tts-2.0 للغة الصينية)

للحصول على TTS صيني عالي الجودة عبر API ثنائية الاتجاه للبث المتدفق seed-tts-2.0 من ByteDance، ثبّت حزمة PyPI doubao-speech واربطها كمزوّد أوامر:

تأتي بيانات الاعتماد من بيئة الـ shell لديك (VOLCENGINE_APP_ID / VOLCENGINE_ACCESS_TOKEN) أو من ~/.doubao-speech/config.yaml. اختر صوتًا بإضافة --voice zh-female-warm (أو أي اسم بديل آخر من doubao-speech list-voices) إلى الأمر. تتضمن doubao-speech أيضًا ASR متدفقًا — راجع قسم STT أدناه لمعرفة كيفية دمجه مع Hermes. المصدر والتوثيق الكامل: github.com/Hypnus-Yuan/doubao-speech.

العناصر النائبة

يمكن لقالب الأمر لديك الإشارة إلى هذه العناصر النائبة. يستبدلها Hermes وقت العرض ويضع كل قيمة بين علامات اقتباس shell مناسبة للسياق المحيط (دون اقتباس / اقتباس مفرد / اقتباس مزدوج)، لذا تكون المسارات التي تحتوي على مسافات وغيرها من المحارف الحساسة للـ shell آمنة.

العنصر النائبالمعنى

{text_path}اسم بديل لـ {input_path}

ملاحظات حول السلوك

  • الأسماء المدمجة لها الأولوية دائمًا. لا يحجب الإدخال tts.providers.openai أبدًا مزوّد OpenAI الأصلي، لذا لا يمكن لأي إعدادات من المستخدم استبدال مزوّد مدمج بصمت.
  • التسليم الافتراضي يكون كمستند. يسلّم مزوّدو الأوامر الصوت كمرفقات صوتية عادية على كل المنصات. ويمكنك تفعيل التسليم كفقاعة صوتية لكل مزوّد على حدة عبر voice_compatible: true.
  • تظهر حالات فشل الأوامر للوكيل. فرمز الخروج غير الصفري، أو الإخراج الفارغ، أو انتهاء المهلة، كلها تعيد خطأً يتضمن stderr/stdout الخاص بالأمر، كي تتمكن من تصحيح أخطاء المزوّد من داخل المحادثة.
  • type: command هو الافتراضي عند ضبط command:. كتابة type: command صراحةً ممارسة جيدة لكنها غير مطلوبة؛ فأي إدخال يحتوي على سلسلة command غير فارغة يُعامل كمزوّد أوامر.
  • {input_path} / {text_path} قابلان للتبادل. استخدم أيهما أوضح في أمرك.

الأمان

يشغّل المزوّدون من نوع command أي أمر shell تضبطه، بصلاحيات المستخدم الخاص بك. يضع Hermes قيم العناصر النائبة بين علامات اقتباس ويفرض المهلة المضبوطة، لكن قالب الأمر نفسه يُعدّ إدخالًا محليًا موثوقًا — لذا تعامل معه كما تتعامل مع سكربت shell موجود في PATH لديك.

مزوّدو إضافات Python

بالنسبة إلى محركات TTS التي لا يمكن التعبير عنها بأمر shell واحد — مثل حزم Python SDK التي لا تملك CLI، أو محركات البث المتدفق، أو واجهات API لسرد الأصوات، أو المصادقة التي تتطلب تجديد OAuth — سجّل إضافة Python عبر ctx.register_tts_provider(). تعمل الإضافة جنبًا إلى جنب مع سجل مزوّدي الأوامر المخصصة (ولا تستبدله)؛ فاختر الواجهة التي تناسب محركك.

الـ hooks الاختيارية

تجاوز هذه الدوال في صنف المزوّد الخاص بك للحصول على تكامل أغنى:

  • list_voices() → قائمة من قواميس {id, display, language, gender, preview_url} تُعرض في hermes tools.
  • list_models() → قائمة من قواميس {id, display, languages, max_text_length}.
  • get_setup_schema() → تعيد {name, badge, tag, env_vars: [{key, prompt, url}]} لتغذية صف أداة الاختيار في hermes tools / hermes setup. ودونها تظل الإضافة تعمل، لكن صفها في أداة الاختيار يكون بالحد الأدنى.
  • stream(text, *, voice, model, format, **extra) → مكرِّر (iterator) يُنتج بايتات الصوت للتسليم المتدفق (ترفع افتراضيًا NotImplementedError).
  • الخاصية voice_compatible → اضبطها على True إذا كان إخراجك متوافقًا مع Opus وينبغي أن يسلّمه الـ gateway كفقاعة صوتية (القيمة الافتراضية False = مرفق صوتي عادي).
  • warm() / release() → تُستدعيان عندما تفعّل واجهة ما إخراج الكلام / عند تحرير آخر عقد استخدام عبر الواجهات، ما دام مزوّدك هو tts.provider المضبوط — حمّل خادم نموذج محليًا مسبقًا أو ألغِ تحميله هنا. كلتاهما لا تفعلان شيئًا افتراضيًا؛ وتُسجَّل الاستثناءات بمستوى debug ولا تُفشل تفعيل المفتاح أبدًا.

راجع agent/tts_provider.py للاطلاع على الصنف المجرد (ABC) الكامل مع سلاسل التوثيق (docstrings).
