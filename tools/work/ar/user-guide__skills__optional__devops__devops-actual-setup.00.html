مهارة إعداد Actual Computer

تُعِدّ actual.inc (Actual Computer) كمزوّد inference لـ Hermes. يحوّل Actual عتاد المستخدم الخاص إلى عنقود inference خاص ويعرض واجهة برمجية متوافقة مع OpenAI بطريقتين: relay مستضاف ومشفّر من طرف إلى طرف على https://api.actual.inc (يُصادَق عليه بمفتاح ac_)، وdaemon محلي على الجهاز على http://127.0.0.1:8080 (بلا مصادقة على loopback). هذه المهارة لا تُثبّت daemon Actual للمستخدم — تفويض الجهاز يتطلب إنسانًا في متصفح.

متى تُستخدم

  • يريد المستخدم إضافة actual.inc كمزوّد inference (relay سحابي أو محلي).
  • لدى المستخدم مفتاح ac_ ويريد توجيه Hermes عبر عنقود Actual الخاص به.
  • يريد المستخدم inference محليًا بالكامل على الجهاز عبر daemon Actual.
  • استكشاف الأخطاء: طلبات Actual تفشل بأخطاء 400 غامضة أو تدفقات فارغة.

المتطلبات الأساسية

  • يمتلك Hermes دعمًا أصيلًا (first-class) لمزوّد actual (معرّف المزوّد actual، والأسماء البديلة actual-computer، actualcomputer، aci). لا تُعِدّ Actual كإدخال custom_providers / providers.actual.* على Hermes الحالي — فالمزوّد المدمج يمتلك الاسم ويتولى تلقائيًا توحيد صيغة عنوان URL الأساسي، ونقل Responses، ووضع عدم المصادقة المحلي.
  • وضع relay: حساب Actual ومفتاح inference من نوع ac_ من https://actual.inc/user/keys.
  • الوضع المحلي: ثبّت المستخدم الـ daemon (curl -fsSL "https://actual.inc/install" | bash) وأكمل تفويض الجهاز بتشغيل actual مرة واحدة وفتح رابط https://actual.inc/device?code=... المطبوع في متصفح. مرّر ذلك الرابط للمستخدم وانتظر — لا تختلق بريدًا إلكترونيًا أبدًا ولا تفوّض نيابة عنه. تنتهي صلاحية الرموز خلال 5 دقائق؛ أعد تشغيل actual للحصول على رمز جديد.

المزالق

  1. مزلق reasoning_effort (يعالجه Hermes منذ صار المزوّد أصيلًا). تقبل backends من نوع SGLang/vLLM في Actual فقط none/low/medium/high/max؛ وكانت xhigh/ultra تفشل سابقًا بخطأ غامض Expecting value: line 1 column 1 (char 0) (خطأ HTTP 400 مغلّف). يقيّد المزوّد المدمج xhigh→high وultra→max عند الإرسال. إذا استمر الطلب بإرجاع 400 على نسخة Hermes قديمة، اضبط حدًا أقصى لكل نموذج: agent.reasoning_overrides.<model>: high في config.yaml.
  2. فيضان نافذة السياق على النماذج المحلية الصغيرة. toolset الافتراضي في Hermes حوالي 26 ألف token من المخططات مع system prompt حوالي 9 آلاف token. النموذج المحمَّل بسياق 32 ألف token يفيض قبل الدور الأول، وخوادم عائلة llama.cpp تُصدر data: [DONE] مجرّدة — يُبلّغ Hermes بـ Provider returned an empty stream with no finish_reason. هذه ليست مشكلة SSE. الحلول: قيّد الأدوات (-t file,web)، أو حمّل النموذج بـ n_ctx أكبر، أو اختر نموذجًا بسياق >=64 ألف لدعم toolset الكامل. تتبّع upstream: #51448 (لا تفتح مشكلات جديدة؛ أضف الأدلة هناك). ذات صلة لكن مختلفة: #65631 (SSE بحالة HTTP-200 يحمل خطأ 400)، #56516 (تدفقات استدلال فقط).
  3. معرّفات التنزيل مقابل الأسماء المثبّتة. يأخذ actual models download صيغة repo/QUANT ويعيد خطأ 409 بلا تحديد صريح للتكميم (quantization)؛ بينما يأخذ actual models load الاسم المثبَّت من actual models list.
  4. نماذج الاستدلال تُعيد محتوى فارغًا. تصدر متغيرات استدلال GLM/Qwen التفكير في حقل reasoning منفصل ويمكن أن تستهلك max_tokens صغيرة بالكامل على الاستدلال. امنح max_tokens سخيّة قبل افتراض الفشل.
  5. لا تنشئ مزوّدًا مخصصًا باسم actual. بعض أدلة الإعداد الأقدم (قبل الدعم الأصيل) كتبت كتل إعدادات providers.actual.*. على Hermes الحالي، يفوز المزوّد المدمج بالاسم؛ وكتل الإعداد المخصصة القديمة تُتجاهَل أو تتعارض. احذفها واستخدم مسار متغيرات البيئة + model.provider أعلاه.
