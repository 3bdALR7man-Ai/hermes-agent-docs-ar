Hermes Desktop

تطبيق Hermes لسطح المكتب هو تطبيق أصلي (native) مبني حول الوكيل نفسه الذي تحصل عليه من CLI ومن الـ gateway — الإعدادات نفسها، ومفاتيح API نفسها، والجلسات نفسها، والمهارات نفسها، والذاكرة نفسها. فهو ليس منتجًا منفصلًا ولا نسخة مبسّطة؛ بل يستخدم نواة Hermes Agent وإعداداتها ذاتها، ويشغّلها عبر واجهة مستخدم حديثة ومصمَّمة بعناية. إذا سبق لك استخدام hermes في الطرفية، فكل ما أعددته هناك موجود هنا بالفعل، وكل ما تفعله هنا يظهر هناك.

يعمل على macOS (Apple Silicon) و Windows و Linux — راجع دعم المنصات للمصفوفة الكاملة.

ما الفرق بين الواجهات؟

لدى Hermes عدة واجهات أمامية تتواصل جميعها مع الوكيل نفسه:

  • تطبيق سطح المكتب (Desktop App) (هذه الصفحة) — تطبيق أصلي بواجهة مصمَّمة خصيصًا للمحادثة والإعداد والإدارة.
  • CLI (hermes) وTUI (hermes --tui) — واجهات طرفية.
  • لوحة تحكم الويب (hermes dashboard) — لوحة إدارة في المتصفح؛ ويضمّن تبويب Chat الاختياري فيها واجهة TUI عبر طرفية وهمية (pseudo-terminal).

اختر ما يناسب الموقف. فهي تتشارك الحالة، لذا يمكنك بدء جلسة في إحداها واستئنافها في أخرى.

استخدم مساحة عمل Desktop من المتصفح

يستطيع الـ gateway تقديم مساحة العمل هذه إلى متصفح عادي: الجلسات، والـ profiles، وCapabilities، وMessaging، وArtifacts، والمهام المجدولة، وشجرة ملفات المضيف، ومراجعة Git، والمعاينات، وشريط الطرفية. وهذا ليس Web Dashboard. فعّله مرة واحدة، ثم افتحه بالأمر hermes webapp:

يقدّم الـ gateway حينئذٍ الـ Webapp على http://127.0.0.1:9120 (راجع Configuration → Webapp للاطلاع على المضيف والمنفذ). يبني hermes webapp الحزمة (bundle) إذا كانت قديمة، ويشغّل الـ gateway إذا لم يكن قيد التشغيل، ويفتح رابط تسجيل دخول للاستخدام مرة واحدة. تعمل المحادثات على ذلك الـ gateway، وهو العملية نفسها التي تخدم CLI وDesktop الأصلي والمراسلة، فترى كل واجهة محادثة واحدة بطابور واحد.

تسجيل الدخول. يعمل الرابط مرة واحدة فقط، خلال 60 ثانية. يبادله المتصفح بتسجيل دخول يحتفظ به في ذلك التبويب، فتحافظ إعادة تحميل الصفحة على تسجيل دخولك، وكذلك إعادة تشغيل الـ gateway. أما التبويب الجديد أو عنوان URL المجرد فيعرض تعليمات بدل الوصول: شغّل hermes webapp مرة أخرى للحصول على رابط جديد. وتسلّم New Window ونوافذ الـ profile والنوافذ المنبثقة للجلسات تسجيل الدخول برابط خاص بها للاستخدام مرة واحدة. وعلى Linux يتحقق الـ gateway من أن اتصال المتصفح يخص مستخدم نظام التشغيل لديك؛ وعلى Windows يمر الرابط فقط عبر سطر أوامر مشغّل المتصفح، الذي لا يستطيع المستخدمون العاديون الآخرون قراءته. وعلى macOS وأنظمة BSD وillumos لا يتحقق أي من الأمرين، لذا يكتب الأمر الرابط في صفحة لا يقرؤها إلا مستخدم نظام التشغيل لديك (في مجلد webapp ضمن الدليل الرئيسي للـ gateway) ويفتح تلك الصفحة: فلا يرى المشغّل إلا مسارها. وعلى macOS قد يُفتح المتصفح حيث لا تراه (عبر SSH، أو على شاشة الـ Mac نفسه): فإن لم يُفتح أي متصفح، شغّل hermes webapp --no-open للحصول على الرابط. وحيث يتعذر فتح متصفح (--no-open، أو جلسة SSH على BSD أو illumos) وعلى WSL (حيث يصل متصفح Windows إلى الـ gateway عبر مرحّل WSL)، يطبع الأمر رابط الاستخدام الواحد لتفتحه بنفسك؛ وإلى أن يُستخدم يسجّل متصفحًا دخولًا بصفتك، فأبقِه خاصًا. يسجّل hermes webapp --sign-out خروج كل التبويبات دفعة واحدة: تُغلق اتصالاتها المفتوحة، بما في ذلك عارضو Bot Desktop، ويعرض كل منها تعليمات تسجيل الدخول. وخلف بوابة تسجيل الدخول (أدناه) يسجّل أيضًا خروج كل متصفح سجّل دخوله بحساب لوحة التحكم؛ ويجب على كل منها تسجيل الدخول من جديد. ولا تعمل رموز الحساب التي يحتفظ بها هذا الدخول في ملفات تعريف الارتباط (cookies) على الـ Webapp إلا بصفتها ذلك الدخول (يرفضها الـ gateway بوصفها bearer token، في عنوان URL الخاص بالاتصال وفي تجديد الـ token)، فتنتهي بانتهائه. أما تطبيق Hermes الأصلي الذي سجّل دخوله إلى الـ gateway بنفسه فيبقى مسجّلًا.

لـ profile مسمّى، يفتح hermes -p work webapp الـ Webapp على work. تتشارك الـ profiles التي يخدمها الـ gateway الافتراضي الـ Webapp نفسه؛ أما الـ gateway الخاص بـ profile مستقل فيقدّم Webapp خاصًا به عندما يفعّله ملف إعداداته.

من جهاز آخر. اضبط webapp.host على 0.0.0.0؛ عندها يشترط الـ gateway بوابة تسجيل الدخول للوحة التحكم (اسم مستخدم وكلمة مرور لشبكة LAN أو VPN موثوقة، وOAuth/OIDC لأي شيء مكشوف على الإنترنت). وخلف reverse proxy أو نفق (tunnel) تشغّله بنفسك، أبقِ المضيف على loopback واضبط webapp.public_url على العنوان الذي يقدّم الخدمة بدلًا منه؛ وهذا يشترط تسجيل الدخول نفسه. يفتح hermes webapp حينئذٍ عنوان الـ Webapp الذي تسجّل دخولك إليه بحساب لوحة التحكم لديك: webapp.public_url إن كان مضبوطًا؛ وعلى الـ LAN، العنوان الذي سجّل Web Access → Start تسجيل الدخول عبر Nous له، ما دام لا يزال عنوان هذا الجهاز ومنفذ الـ Webapp؛ وإلا فعنوان loopback (مزوّد كلمة مرور، أو تسجيل دخول أعددته يدويًا لذلك العنوان). لا تخدم روابط الاستخدام الواحد إلا Webapp لا يحتاج إلى تسجيل دخول. يوصى بشدة باستخدام HTTPS عن بُعد.

ما الذي يفقده HTTP العادي. تعطّل المتصفحات الميزات التي تحتاج إلى سياق آمن (secure context) على عنوان HTTP عادي غير loopback (يُعدّ http://localhost وhttp://127.0.0.1 آمنين): عارض شاشة البوت، والميكروفون (الإملاء، والصوت المباشر، وكلمة التنبيه عن بُعد)، وقراءة الحافظة (لصق الطرفية، ولصق صورة)، وإشعارات النظام. وتخبرك شاشة البوت والصوت المباشر بذلك بدلًا من الفتح. يطبع hermes webapp وhermes webapp --status ملاحظة عندما يكون العنوان الذي يفتحه المتصفح (webapp.public_url، وإلا عنوان الـ LAN الذي سجّل له Start تسجيل الدخول) HTTP عاديًا على مضيف آخر. وللاحتفاظ بهذه الميزات، افتح الـ Webapp عبر HTTPS (webapp.public_url) أو عبر نفق SSH إلى 127.0.0.1.

تعامل مع الوصول إلى Webapp كأنه وصول إلى Hermes على المضيف

يستطيع مستخدم Webapp المسجَّل دخوله تنفيذ أوامر عشوائية بصفة حساب نظام التشغيل الذي يشغّل Hermes، وتشغيل أدوات الوكيل، واستخدام ملفات المضيف وGit، والوصول إلى بيئة ذلك الحساب وبيانات اعتماده. لا تكشفه دون مزوّد تسجيل دخول. ويفضّل استخدام نفق SSH أو Tailscale أو VPN موثوق آخر.

يعرض hermes webapp --status ما إذا كان الـ gateway يقدّم الـ Webapp. وعندما يتعذر ذلك (المنفذ مشغول، أو تسجيل الدخول مطلوب ولم يُعدّ أي مزوّد تسجيل دخول، أو تعذّرت قراءة أو كتابة ملف تسجيل دخول المتصفح الخاص بالـ Webapp webapp/session-token في دليل Hermes الرئيسي)، يظل الـ gateway يخدم العملاء الأصليين وتبيّن الحالة السبب. يقرأ الـ gateway هذه الإعدادات عند بدء تشغيله، لذا أعد تشغيله بعد معالجة السبب (hermes gateway restart). وإذا كان المنفذ مشغولًا، يستبدل الـ gateway أيضًا تسجيل دخول الـ Webapp، فتحتاج التبويبات المفتوحة إلى hermes webapp مرة أخرى. وإذا لم تُبنَ حزمة الـ Webapp بعد، تذكر الحالة ذلك بدلًا من هذا: يبنيها hermes webapp، ويقدّمها الـ gateway العامل دون إعادة تشغيل.

تُجهَّز الملفات التي يختارها المتصفح والصور الملصقة أو المسقطة ضمن الـ profile النشط قبل أن تدخل مسار المرفقات المعتاد، بحدّ 16 MiB لكل ملف. تُنزَّل ملفات المضيف عبر مدير التنزيلات في المتصفح، ويُشغَّل الصوت والفيديو المدعومان داخل الصفحة وفق قواعد الوصول إلى الملفات في الخادم. أما Save Image لعناوين URL من أصول مختلفة (cross-origin) فيحتاج إلى CORS، بحدّ 25 MiB ومهلة 30 ثانية. تُفتح روابط المواقع في تبويب منفصل؛ وتستخدم معاينات URL الصريحة iframe معزولًا (sandboxed) لا يستطيع فتح نوافذ منبثقة، لذا استخدم Open in browser للمواقع التي ترفض التضمين. وتبقى الميزات الخاصة بالتطبيق الأصلي في Electron: الاختصارات العامة، والطبقات العائمة الدائمة الظهور، وفحص نوافذ نظام التشغيل، وتشغيل الطرفية الخارجية، والمحدّث (updater).

تعرض المحادثات المكتوبة قبل أن يمتلك الـ gateway الجلسات سجلّها لكن لا يمكن متابعتها من المتصفح حتى يجري تبنّيها: شغّل hermes sessions adopt مرة واحدة على المضيف (hermes -p <profile> sessions adopt لـ profile آخر)، أو افتحها مرة واحدة في Desktop الأصلي أو TUI أو CLI.

افتحه من هاتفك أو من حاسوب آخر

في التطبيق الأصلي، يفعّل Settings → Web Access الـ Webapp للأجهزة الأخرى، خلف تسجيل الدخول بحساب Nous لديك (Providers → Accounts). ويظهر فقط في التطبيق الأصلي على اتصاله المحلي، ولا يستطيع تغييره إلا ذلك التطبيق: فلا يستطيع متصفح سجّل دخوله عبر الشبكة ذلك.

  • This network: تفتح الأجهزة المتصلة بشبكة Wi-Fi نفسها العنوان http://<this computer's address>:<port>، حيث المنفذ هو webapp.port (9120 ما لم تضبط منفذًا آخر، أو اختار Start منفذًا لـ profile مستقل). وهذا HTTP عادي: الاتصال غير مشفّر، لذا قد يقرؤه الآخرون على الشبكة، وتعطّل المتصفحات الميزات المذكورة تحت What plain HTTP loses أعلاه. استخدمه فقط على شبكة تثق بها.
  • My own URL: عنوان HTTPS تشغّله بالفعل (Tailscale Serve، أو نفق، أو reverse proxy) ويحوّل إلى http://127.0.0.1:<port>. يُحفظ بوصفه webapp.public_url. لا تحوّل ذلك المنفذ من الراوتر مباشرة أبدًا.

Start يبني الـ Webapp إذا كان مفقودًا أو قديمًا (وهو البناء نفسه الذي ينفّذه hermes webapp، وقد يستغرق بضع دقائق في أول مرة)، ويسجّل عنوان تسجيل الدخول الخاص به في حساب Nous لديك عندما يتغير ذلك العنوان، ويحفظ إعدادات webapp: ويعيد تشغيل الـ gateway الذي يقرؤها عند بدء تشغيله. وأثناء تشغيل محادثة يرفض الـ gateway إعادة التشغيل: تعرض اللوحة Restart needed، وتُطبَّق الإعدادات عند إعادة التشغيل التالية، ويعيد Restart gateway تشغيله بعد انتهاء المحادثة. ويوقف Stop الـ Webapp بالطريقة نفسها. أما الـ Webapp الذي فعّلته لهذا الحاسوب فقط (webapp.enabled: true دون Web Access) فيظهر على أنه مُقدَّم على هذا الحاسوب.

يغيّر Web Access إعدادات webapp: فقط ويحتفظ بـ webapp.port لديك. ولا يمسّ dashboard.public_url، فتحتفظ لوحة التحكم المستقلة التي تنشرها على حدة بعنوانها الخاص. ويستخدم تسجيل الدخول عبر Nous فيه عميل تسجيل دخول خاصًا به، يسجّله أول Start في حساب Nous لديك ويحتفظ به في الدليل الرئيسي للـ gateway (webapp/sign-in-registration.json). لا يقرأ Start قيمة HERMES_DASHBOARD_OAUTH_CLIENT_ID في .env ولا يكتبها أبدًا، لذا لا يغيّر تفعيل Web Access تسجيل الدخول عبر Nous للوحة التحكم المستقلة. ويقدّم الـ profile المستقل الذي له gateway خاص به الـ Webapp الخاص به على منفذ مستقل: فعندما لا يكون webapp.port مضبوطًا، يختار أول Start أول منفذ خالٍ فوق 9120 لا يستخدمه أي profile آخر ويحفظه بوصفه webapp.port لذلك الـ profile، فيبقى عنوانه ثابتًا بعد إعادات التشغيل. أما webapp.port الذي تضبطه أنت فيُحتفظ به دائمًا. يعيد hermes update بناء الـ Webapp كلما فعّله أي profile. وإذا فشل هذا البناء، يبلّغ الـ gateway بأن الـ Webapp غير متاح، وتذكر الصفحة ذلك، إلى أن يعيد hermes webapp بناءه.

الطرفية في Webapp

يفتح شريط الطرفية الـ shell التفاعلي للمضيف، ويعمل بوصفه عملية فرعية للـ gateway، في مجلدك الرئيسي ما لم يحدد terminal.cwd مجلدًا آخر. يؤدي إسقاط الملفات عليه إلى رفعها إلى المضيف (16 MiB لكل ملف) وكتابة مساراتها. وتفصل إعادة تحميل الصفحة أو فقدان الاتصال الطرفية دون إنهاء الـ shell الخاص بها؛ ويعيد تبويب الطرفية المحفوظ الاتصال بذلك الـ shell وبـ profile الخاص به. وإخفاء الطرفية ليس إغلاقها؛ أما إغلاق تبويبها فينهي الـ shell. ويستولي تبويب متصفح ثانٍ يتصل بالطرفية نفسها على الاتصال.

تُحفظ الـ shells المفصولة لمدة 15 دقيقة أثناء تشغيل الـ gateway، وبحدّ أقصى 16 طرفية للمضيف بما فيها المفصولة. وإعادة تشغيل الـ gateway أو تحديثه ينهيها. وتعيد إعادة الاتصال عرض ما يصل إلى 1 MiB من المخرجات الأخيرة؛ وقد تحتاج البرامج ذات الشاشة الكاملة إلى أمر إعادة رسم خاص بها.

تُثبَّت اعتماديات npm الخاصة بالحزمة في .build/webapp-workspace داخل النسخة المسحوبة (checkout)، بمعزل عن Desktop الأصلي، ولا يُعاد تثبيتها إلا عند تغيّر ملف القفل (lockfile). وعند تعطيل التثبيت الكسول (lazy installs)، لا يثبّتها hermes webapp العادي؛ أما --build-only أو --force-build فيثبّتانها.
