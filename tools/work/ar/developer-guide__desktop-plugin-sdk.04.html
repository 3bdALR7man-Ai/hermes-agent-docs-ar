backend لإضافتك

إذا احتاجت إضافتك عملًا من جهة الخادم، اشحن ملف Python plugin_api.py واستدعِه عبر ctx.rest / ctx.socket — نطاق مقيّد بإضافتك بحكم البناء.

حزمة واحدة، وSDK لكلا الجانبين

الميزة التي تحتاج إلى واجهة desktop و كود من جهة الوكيل (إضافة Python ومسارات backend الخاصة بها ومهارات) لا تحتاج إلى توزيعهما كتثبيتين يعتمد أحدهما على الآخر. ضع desktop/plugin.js داخل حزمة الوكيل. عندما تحطّ الحزمة في أي جذر plugins/ محلي (المنزل الافتراضي أو profile)، تنسخ عملية Electron الرئيسية هذا النصف إلى $HERMES_HOME/desktop-plugins/<id>/ بجانب علامة .hermes-package.json، ويحمّله عارض الواجهة (renderer) عبر خط أنابيب مطابق تمامًا لباب القرص المستقل (hot reload متضمَّن):

نصف desktop/plugin.js هو إضافة قرص عادية — نفس العقد، ونفس الاستيرادات، ونفس ctx.rest('/…') الذي يصل إلى plugin_api.py الموجود بجانبه. تثبيت أو مشاركة أو إزالة الميزة هو مجلد واحد: تُحدَّث نسخة جذر التطبيق عندما يتغير ملف plugin.js المصدر (hermes plugins update، أو Rescan) وتُزال عندما يختفي مجلد الحزمة. النسخ هو ما يجعل النصف الخاص بـ desktop على مستوى التطبيق: فهو موجود مرة واحدة، مهما كان عدد الـ profiles التي تحمل الحزمة، ولا يظهر أو يختفي أبدًا عندما يبدّل المستخدم محدد profile الخاص بالإمكانيات (Capabilities). لا يفحص عارض الواجهة plugins/ بنفسه أبدًا. تسجّل العلامة اسم الحزمة ومصدرها (ملحق كتالوج أو remote git)، وهذا ما يستخدمه زر Install here في صفحة Plugins لتثبيت نصف الوكيل في profile آخر. تُجهّز النسخة بجوار الهدف ثم تُنقل إلى موضعها بإعادة التسمية، فلا تترك عملية نسخ مقاطعة (قفل ملف عابر أو تعطّل وسط النسخ) مجلدًا نصف مكتوب؛ وتُعامل بقايا desktop-plugins/<id>/ التي لا تحمل علامة ولا plugin.js كتلف من هذا النوع وتُستبدل عند Rescan التالي، بينما يكون المجلد دون علامة الذي يحتوي بالفعل على plugin.js إضافة مستقلة ثبّتها يدويًا ولا يُكتب فوقها مطلقًا.

تطوير حزمة موحّدة

يحمّل التطبيق النسخة في desktop-plugins/<id>/، لا حزمتك. لا تُحدَّث الحزمة المثبّتة (الكتالوج أو Git URL أو مسار file://) إلا عندما يكون plugin.js المصدري أحدث من النسخة ويطلب شيء التحديث — Rescan في Capabilities → Plugins أو تثبيت/تحديث عبر التطبيق أو إعادة تشغيل — لذلك لا يؤدي تحرير ~/.hermes/plugins/<id>/desktop/plugin.js في موضعه إلى شيء على الشاشة حتى ذلك الحين. طوّر بدلًا من ذلك من نسخة مسحوبة مرتبطة بـ plugins/:

تُوسم نسخة الحزمة المرتبطة بـ "linked": true. يراقب التطبيق desktop/plugin.js في النسخة المسحوبة؛ يعيد كل حفظ مزامنة النسخة (بحسب المحتوى، لا mtime، لذا يُحتسب git stash pop) ويعيد تحميل الإضافة فوريًا. تحتفظ تثبيتات الكتالوج و Git بقاعدة mtime.

hermes plugins doctor <path-or-id> يحذّر عندما تختلف النسخة عن مصدرك ويذكر النسخة التي عثر عليها:

ما زال هناك مفتاحا تفعيل ينطبقان، بشكل مقصود، وكلاهما افتراضيًا معطَّل: نصف desktop يُشحَن كخيار اختياري (opt-in) — يُدرَج ضمن الجرد في Capabilities → Plugins لكنه يبقى معطَّلًا حتى يبدّله المستخدم — مطابقًا لتقييد plugins.enabled الخاص بنصف Python في config.yaml (الحد الأمني أدناه). وضع حزمة في ~/.hermes/plugins خامل على كل الأسطح حتى يقول المستخدم غير ذلك. يتدهور نصف desktop بأمان عندما يكون نصف الـ backend معطَّلًا — يعيد ctx.rest أخطاء، لا انهيارات.

ملاحظة

النسخة محلية للجهاز الذي يعمل عليه تطبيق desktop. مقابل backend بعيد، لا يمكن الوصول إلى ~/.hermes/plugins الخاص بالجهاز البعيد كنظام ملفات — فقط الحزم المثبَّتة محليًا تسهم بنصف desktop بهذه الطريقة. بالنسبة لـ backend بعيد، يستنسخ حوار التثبيت نصف desktop بشكل منفصل إلى desktop-plugins/، كما في مستودع خاص بـ Desktop وحده. تعرض الحزمة التي ثُبّت نصف وكيلها على المضيف البعيد دون ذلك الاستنساخ نصف Desktop بوصفه unavailable (remote backend) في صفحة Plugins — لا كنسخة معلّقة — ويوجّه التلميح إلى Install from Git مع تحديد هدف Desktop.

backend الخاص بـ Python مقيّد بشكل منفصل

تفعيل إضافة في لوحة Capabilities → Plugins الخاصة بـ desktop اختيار من جانب عارض الواجهة (renderer)؛ وهو لا يستورد Python. يُستورد plugin_api.py الخاص بإضافة المستخدم فقط عندما تكون الإضافة في قائمة السماح plugins.enabled ضمن config.yaml (وليست في plugins.disabled). إضافات المشروع (./.hermes/) لا تستورد Python تلقائيًا أبدًا. هذا حد أمني، لا إغفال (GHSA-mcfc-hp25-cjv7).

دفع الأحداث إلى نصف Desktop

يعمل backend الخاص بك داخل عملية الـ gateway، لذا يستطيع دفع تحديث إلى نصف Desktop الخاص بك عبر تدفق الأحداث العام للتطبيق — التدفق نفسه الذي يشترك فيه host.onEvent:

broadcast_plugin_event(plugin_id, event, payload=None): اسم النقل دائمًا plugin.<plugin_id>.<event>. plugin_id هو اسمك في الكتالوج ([a-z0-9_-]{1,64}، دون نقاط — فهو مساحة الأسماء ولا يمكنه كتابة اسم إضافة أخرى)؛ و event الاسم المنقّط المجرّد ("feed.updated"، لا "plugin.rss-reader.feed.updated")، بمقاطع من [A-Za-z0-9_-]، لذا تُطلق "" أو "../x" أو "a..b" الاستثناء ValueError بدلًا من ترك نصف Desktop يستمع إلى اسم لا يصدره أحد. payload قاموس JSON (أو يُحذف → {}) يُسلّم بوصفه payload للحدث؛ ويحمل الإطار session_id: "" ككل حدث عام. التسليم إرسال دون انتظار (يُتخطّى العميل العالق، ولا يعطّل معالجك مطلقًا). تعتمد وجهته على العملية التي ينفَّذ فيها الاستدعاء:

عملية المستدعيالوجهة
hermes serve (backend الخاص بـ Desktop): موجّهات plugin_api.py و slash commands الإضافات والأدوات و hooks في دور الوكيلكل نافذة Desktop متصلة
العملية الفرعية لمضيف الحوسبة dashboard.turn_isolation (أدوات/hooks دور معزول)يُرحَّل عبر قناة المضيف إلى hermes serve، ثم إلى كل نافذة
TUI عبر stdio (hermes في طرفية)عميل تلك الطرفية
hermes gateway run (منصات المراسلة)، hermes chat، و cron، و hermes plugins validateلا أحد — لا يوجد عميل Desktop متصل بتلك العملية؛ الاستدعاء عملية بلا أثر يُسجَّل ذلك عنها

استخدم هذا بدلًا من استيراد الآليات الداخلية لـ tui_gateway.server؛ وبالنسبة إلى أُطر مقيّدة بالإضافة ذات حمولة مخصّصة لكل اتصال، يظل ctx.socket('/events') المدخل الأغنى.

الانتقال (rss-reader): أزل قائمة انتظار ~/.hermes/rss-reader/commands.jsonl و GET /commands واستطلاع ctx.rest('/commands') كل 3 s — يستدعي جانب Python broadcast_plugin_event('rss-reader', 'feed.updated', payload) حيث كان يُدرج في القائمة، ويستبدل جانب Desktop المؤقت بـ host.onEvent('plugin.rss-reader.feed.updated', fn) داخل register(ctx).

استدعاؤه من الإضافة

ctx.rest يراعي profile ويرفض اجتياز المسارات (..) بحيث لا يمكنك أبدًا التوجّه إلى واجهة API خاصة بإضافة أخرى أو مسار أساسي عبره. PluginRestOptions هو { method?, body?, upload?: { filename, contentType?, bytes }, timeoutMs? }.

ctx.socket يعيد الاتصال تلقائيًا بتراجع تدريجي (backoff) حتى يُستبعَد. ينحل إلى عملية تجاهل (no-op) على remotes بـ OAuth (تذاكر WS أحادية الاستخدام مُدارة من النواة) — عامِله كمُسرِّع فوق الاستطلاع (polling)، لا كبديل عنه. يحتاج كل مستهلك إلى بديل استطلاع على أي حال، لأن أي مقبس (socket) قد ينقطع.

بالنسبة لبيانات على نطاق gateway بأكمله (وليست في نطاقك الخاص)، استخدم host.request (JSON-RPC) و host.onEvent (تدفق أحداث gateway) بدلًا من ذلك.

الإعدادات، وحالة التفعيل، والتخزين

كل إضافة — سواء مفعَّلة أم لا — تُدرَج ضمن الجرد في Capabilities → Plugins، حيث يفعّلها المستخدم أو يعطّلها فورًا (دون إعادة تشغيل التطبيق)، أو يعرض مجلدها، أو يعيد الفحص. تندرج تفضيلات الإضافة نفسها في Settings → Plugins (صفحات إعدادات الإضافات). يُتذكر اختيار المستخدم:

  • لا اختيار بعد → قيمة defaultEnabled الخاصة بالإضافة نفسها (الافتراضي true). اضبط defaultEnabled: false لشحن إضافة اختيارية تبقى معطَّلة حتى يشغّلها المستخدم.
  • اختيار صريح → يُحفظ ويُراعى عبر إعادة التشغيل. تبقى الإضافة المعطّلة معطّلة — لا تقاوم ذلك؛ فقد عطّلك المستخدم.

احفظ حالتك الخاصة باستخدام ctx.storage، بنطاق مُميّز باسم إضافتك (hermes.plugin.<id>.*) بحيث لا تستطيع الإضافات قراءة أو إتلاف بيانات بعضها البعض:

الإضافات المضمّنة (Bundled)

يمكن لإضافة أن تُشحَن ضمن الشجرة عند apps/desktop/src/plugins/<id>/plugin.tsx (تصدير افتراضي HermesPlugin). تُكتشَف بواسطة discoverBundledPlugins() عند الإقلاع — بلا استيراد، بلا تعديل سجل — وتشارك نفس عقد الجرد + التفعيل/التعطيل الحي كإضافة قرص. الفرقان الاثنان:

  1. تمر عبر بناء Vite الخاص بالتطبيق، لذا يمكنك كتابة JSX حقيقي واستيراد الـ SDK عبر اسمه المستعار @hermes/plugin-sdk.
  2. لا تزال مقيَّدة بأدوات lint إلى @hermes/plugin-sdk + react فقط — بلا داخليات @/… خاصة بالتطبيق.

لا تُشحَن إضافات desktop في الشجرة الأساسية اليوم؛ يبقى التطبيق المُشحَن غير مزدحم والعروض التوضيحية موجودة في مستودع hermes-example-plugins المصاحب.

النموذج الأمني

تُقيَّم الإضافة المحمَّلة كـ ESM في عالم عارض الواجهة (renderer realm) بـسلطة كاملة على التطبيق — النسخة الوحيدة (singleton) من React، وكامل الـ SDK (RPC الخاص بـ gateway عبر host.request، وctx.rest، والتخزين، وnavigate) والجسر الأصلي window.hermesDesktop (الملفات و git والطرفية والتثبيتات). العزل الذي يوفّره المحمّل هو عزل الأخطاء فقط: لا تستطيع الإضافة تعطيل التطبيق (مساهماتها محاطة بحدود أخطاء ومستمعوها معزولون، ويُتراجع عن register() الذي يطلق استثناءً ويُبلغ عنه في صف الإضافة)، لكنها تستطيع فعل أي شيء يفعله التطبيق. مساحات أسماء تخزين الإضافات اصطلاح، لا حاجز.

هذا مقبول بالنسبة لمصادر محلية — فملف قرص يستطيع بالفعل تشغيل كود على جهازك — ولذلك لا يحمّل مدخل القرص إلا ملفات محلية كتبتها أنت (أو وكيلك). بالنسبة إلى تثبيتات الكتالوج، تأتي الثقة من القبول — راجع شخص الـ commit المثبّت نفسه — مدعومة بحاجزين: فحص lint لـ desktop surface عند القبول وقائمة السماح بالاستيراد لدى المحمّل (@hermes/plugin-sdk و react* فقط؛ يفشل تحميل أي import ثابت أو ديناميكي لشيء آخر، بما فيه عناوين URL من نوع https:). لا يُعدّ أيٌّ منهما sandbox. سيحتاج مدخل مصادر بعيدة مستقبلي إلى حد فعلي (iframe/worker + CSP + اشتراط القدرات) قبل إتاحته؛ لا تعامل pipeline هذا كحد ثقة.

مزالق

  • JSX لا يُحلَّل (parse) في إضافة قرص. يُحمَّل الملف دون تجميع — استخدم jsx() / jsxs() (أو React.createElement)، لا صياغة JSX. (الإضافات المضمّنة مبنية، لذا JSX مقبول فيها.)
  • ثلاثة معرّفات فقط قابلة للحل (resolve): @hermes/plugin-sdk، وreact، وreact/jsx-runtime. أي استيراد آخر يُظهر خطأ تحميل فوري.
  • لا تستخدم ألوانًا ثابتة أبدًا (#000، black، rgb(...)). اترك الخلفية كما هي؛ واستخدم متغيرات السمة (var(--ui-*)) لكل شيء.
  • أشِر فقط إلى ما استوردته. مكوّن نسيت استيراده (مثل StatusDot) يسبب ReferenceError عند العرض — تحقق مرة أخرى من أن كل معرّف في استدعاءات jsx() الخاصة بك موجود في سطر الاستيراد.
  • اقرأ الحالة بشكل أمري (imperatively) في المعالجات ($atom.get())، وليس من إغلاق (closure) خاص بالعرض — فالأحداث السريعة ستَرى قيمًا قديمة خلاف ذلك. اشترك (useValue) فقط في الورقة (leaf) التي تعرض القيمة.
  • يجب أن تتبع لوحات canvas حاويتها باستخدام ResizeObserver وتُعيد قياس canvas (سمتا العرض/الارتفاع، وليس CSS فقط) — فاللوحات تُعاد قياسها باستمرار.
  • لا تستطلع أسرع من بضع ثوانٍ باستخدام host.request؛ فضّل host.onEvent / ctx.socket ودع React Query يزيل التكرار.
  • العناصر العامة المجرّدة لا تُتتبّع. window.setInterval و window.addEventListener و <style> الذي تُلحقه — لا يراها المضيف أبدًا، فتبقى بعد التعطيل وكل إعادة تحميل فوري (لا يمكن إلغاء تحميل وحدات ES؛ تتكدس نسخ نشطة أثناء حلقة التحرير الفوري). استخدم ctx.setTimeout / ctx.setInterval / ctx.addEventListener، واربط أي شيء آخر بـ ctx.onDispose. حالة نطاق الوحدة مسؤوليتك لإعادة ضبطها.
  • مهلة تقييم الوحدة 10 s. تؤدي await في المستوى الأعلى التي لا تنتهي أبدًا (انتظار gateway غير عامل) إلى فشل التحميل بوصفه import timed out بدلًا من تعطيل فحص الإضافات؛ نفّذ الانتظار داخل register().
  • معرّف واحد، ملف واحد.يُحمَّل أول مجلد من مجلدين يصدران id نفسه (تثبيت مستقل بجوار نسخة حزمة موحّدة)، بحسب ترتيب أسماء المجلدات؛ ويعرض اللاحق duplicate id في صفه الخاص ضمن Capabilities ▸ Plugins.
  • ctx.socket عملية تجاهل (no-op) على remotes بـ OAuth. احرص دائمًا على بديل استطلاع.

الوكلاء: مهارة hermes-desktop-plugins

عندما يكتب وكيل إضافة desktop، عليه تحميل مهارة hermes-desktop-plugins المضمّنة — فهي تحمل نفس عقد هذه الصفحة في صيغة موجَّهة للوكيل، مع templates/plugin.js جاهز للنسخ. هذه الصفحة هي المرجع البشري/الخاص بالمطوّر؛ والمهارة هي قائمة التحقق العملية.

استكشاف الأخطاء وإصلاحها

إضافتي لا تظهر. تأكد أن الملف موجود في $HERMES_HOME/desktop-plugins/<id>/plugin.js وأن اسم المجلد يطابق id المُصدَّر. نفّذ ⌘K → Reload desktop plugins. تحقق من التطبيق بحثًا عن رسالة خطأ منبثقة تسمّي الإخفاق، وتابع سجل hermes logs gui -f.

"unsupported import" عند التحميل. إضافة القرص لا يجوز أن تستورد سوى @hermes/plugin-sdk، وreact، وreact/jsx-runtime. أزل أي استيراد آخر.

عنصر jsx لا يعرض شيئًا / يُطلق ReferenceError. معرّف مستخدَم في استدعاء jsx() غير مستورَد. أضفه إلى سطر الاستيراد.

ctx.rest يعيد 404. الـ backend غير مُركَّب: تأكد من أن ~/.hermes/plugins/<id>/dashboard/manifest.json يحتوي "api": "plugin_api.py"، وأن الإضافة مدرجة في plugins.enabled ضمن config.yaml، وأعد تشغيل gateway (تُركَّب مسارات الـ backend عند بدء التشغيل). تابع ~/.hermes/logs/errors.log بحثًا عن Failed to load plugin <id> API routes.

ctx.socket لا يُطلَق أبدًا. على remote بـ OAuth هو عملية تجاهل (no-op) بالتصميم — استخدم بديل الاستطلاع الخاص بك. وإلا تحقق من أن الـ backend يعرض مسار @router.websocket(...) المطابق تحت نطاقه.

الألوان تبدو خاطئة بعد تبديل السمة. لقد استخدمت لونًا ثابتًا. استبدله بـ متغير سمة var(--ui-*).
