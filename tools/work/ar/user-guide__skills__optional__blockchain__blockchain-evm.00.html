معلومة

ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

مهارة EVM Blockchain

استعلم عن بيانات سلاسل EVM المتوافقة عبر 8 سلاسل مع تسعير بالدولار الأمريكي. 14 أمرًا: portfolio المحفظة، معلومات العملة (token)، المعاملات، النشاط، متتبّع الغاز، إحصاءات الشبكة، البحث عن السعر، الفحص عبر عدة سلاسل، رصد الحيتان (whale detection)، تحليل ENS، فحص allowance، فاحص العقود، ومفكّك المعاملات.

يدعم 8 سلاسل: Ethereum و BNB Chain (BSC) و Base و Arbitrum One و Polygon و Optimism و Avalanche (C-Chain) و zkSync Era.

لا حاجة إلى مفتاح API. اعتماديات خارجية صفرية — مكتبة Python القياسية فقط (urllib، json، argparse، threading).

يحلّ محل مهارة base المستقلة. عملات Base الخاصة (AERO، DEGEN، TOSHI، BRETT، WELL، cbETH، cbBTC، wstETH، rETH) وكل وظائف Base RPC التي كانت سابقًا ضمن optional-skills/blockchain/base/ باتت مدمجة في هذه المهارة. مرّر --chain base إلى أي أمر لتغطية Base.

متى تُستخدم

  • يطلب المستخدم رصيد محفظة أو portfolio على أي سلسلة EVM
  • يريد المستخدم فحص نفس المحفظة على جميع السلاسل في وقت واحد
  • يريد المستخدم فحص معاملة عبر hash الخاص بها (أو فك تشفير ما فعلته)
  • يريد المستخدم بيانات وصفية أو سعرًا أو المعروض أو القيمة السوقية لعملة ERC-20
  • يريد المستخدم سجل المعاملات الأخيرة لعنوان معيّن
  • يريد المستخدم أسعار الغاز الحالية أو مقارنة الرسوم بين السلاسل
  • يريد المستخدم العثور على تحويلات حيتان (whale) كبيرة في الكتل الأخيرة
  • يطلب المستخدم تحليل اسم ENS (مثل vitalik.eth) أو البحث العكسي عن عنوان
  • يريد المستخدم التحقق مما إذا كان لعقد ما موافقات (approvals) خطرة على عملات معيّنة
  • يريد المستخدم فحص عقد ذكي (هل هو proxy؟ ERC-20؟ ERC-721؟ ما حجم الـ bytecode؟)
  • يريد المستخدم مقارنة تكاليف الغاز بين السلاسل قبل تنفيذ معاملة

المتطلبات الأساسية

مكتبة Python 3.8+ القياسية فقط. لا حاجة إلى تثبيت أي حزم عبر pip. التسعير: واجهة CoinGecko المجانية (بحدّ معدل، ~10-30 طلبًا في الدقيقة). ENS: واجهة ensideas.com العامة. فك تشفير المعاملات: واجهة 4byte.directory العامة.

تجاوز endpoint الخاص بـ RPC: export EVM_RPC_URL=https://your-rpc.com

مسار السكربت المساعد: ~/.hermes/skills/blockchain/evm/scripts/evm_client.py

الإجراء

0. التحقق من الإعداد

1. Portfolio المحفظة

الرصيد الأصلي (native) + عملات ERC-20 المعروفة، مرتّبة حسب القيمة بالدولار.

2. الفحص عبر عدة سلاسل

يفحص جميع السلاسل الـ 8 في وقت واحد لنفس العنوان باستخدام threads.

المخرجات: الرصيد الأصلي لكل سلسلة + العملات المملوكة + الإجمالي الكلي بالدولار.

3. المقارنة (الغاز + الأسعار)

يُستعلم عن جميع السلاسل الـ 8 بالتوازي. يُظهر السلسلة الأرخص والأغلى.

4. تفاصيل المعاملة وفك تشفيرها

يستخدم فك التشفير 4byte.directory لترجمة 0xa9059cbb -> transfer(address,uint256).

5. تحليل ENS

6. فاحص Allowance (الأمان)

يفحص موافقات ERC-20 الممنوحة لعقود DEX/جسور (bridges) معروفة.

يضع علامة على الموافقات غير المحدودة (UNLIMITED) كخطر مرتفع (HIGH).

7. فاحص العقود

يكتشف: proxy (EIP-1967/EIP-1167)، ERC-20، ERC-721، ERC-165. يُظهر حجم الـ bytecode وعنوان implementation في حالة الـ proxy.

8. رصد الحيتان

9. متتبّع الغاز

يُظهر سعر gwei + التكلفة بالدولار لكل من: التحويل، تحويل ERC-20، الموافقة (approve)، المبادلة (swap)، سكّ NFT، ونقل NFT.

المزالق

  • الفئة المجانية من CoinGecko: ~10-30 طلبًا في الدقيقة. استخدم --no-prices لفحص أسرع للمحفظة.
  • قد تحدّ خوادم RPC العامة من معدل الطلبات. اضبط EVM_RPC_URL على endpoint خاص للاستخدام الإنتاجي.
  • يفحص كل من wallet وallowance قائمة عملات معروفة فقط (~30 عملة لكل سلسلة). استخدم مستكشف كتل (block explorer) لاكتشاف كامل للعملات.
  • يفحص activity الكتل الأخيرة فقط (بحد أقصى 200). للسجل الكامل، استخدم Etherscan API.
  • يشغّل multichain 8 threads بالتوازي — قد يؤدي ذلك إلى بلوغ حدود المعدل على خوادم RPC العامة.
  • يعتمد تحليل ENS على endpoint عام واحد (ensideas.com / ens.vitalik.ca) بلا بديل احتياطي. إذا تعطّل ذلك الـ endpoint، سيفشل ens — أعد المحاولة لاحقًا أو استخدم مستكشف كتل.
  • يعتمد فك تشفير المعاملات على endpoint عام واحد (4byte.directory) بلا بديل احتياطي. المحدّدات (selectors) غير الموجودة في قاعدة بياناتهم تظهر كـ unknown.
  • تقديرات غاز L2 تخص تنفيذ L2 فقط. على شبكات rollup مثل Base وArbitrum وOptimism وzkSync، تشمل التكلفة الفعلية للمعاملة أيضًا رسوم نشر البيانات على L1 والتي تعتمد على حجم calldata وأسعار غاز L1 الحالية. لا يقدّر أمر gas هذا المكوّن الخاص بـ L1. بالنسبة إلى Base تحديدًا، راجع oracle رسوم L1 الخاص بالشبكة (العقد 0x420000000000000000000000000000000000000F).
  • يتم التحقق من مدخلات العنوان / hash المعاملة من حيث بادئة 0x والطول الصحيح وكونها hex، لكن حالة الأحرف الخاصة بـ checksum في EIP-55 لا يتم فرضها (تقبل نقاط RPC أي حالة أحرف للـ hex).
