أسباب إخفاق التثبيت والتحديث

منذ الإصدار v4 لمخطط الحزمة (يُوسَّع في مكانه بالإضافة فقط، فتظل كل الصيغ المرسَلة سابقًا صالحة)، يبيّن مقياسان قائمان سبب إخفاقهما. تحتفظ الصفوف المسجّلة قبل التغيير بحقولها القديمة وتظل قابلة للتجميع في حزم.

المقياسالأبعاد المضافةالسؤال الذي يجيب عنه
hermes.extension.install.countفئة الإخفاق، السجلسبب إخفاق تثبيت المهارات والإضافات و MCP، ومصدر skills-hub الذي يفشل. تكون قيمة failure_class هي none عند النجاح، وإلا اسمًا من مجموعة مغلقة لخروج الإخفاق الذي أوقف التثبيت. المهارات: ambiguous, auth_rejected, fetch_failed, invalid_bundle, invalid_name, not_found, rate_limited, scan_blocked, stale_index. الإضافات: already_installed, clone_failed, deps_declined, deps_failed, git_missing, incompatible, invalid_source, manifest_invalid, non_interactive, removed_from_catalog, scan_blocked. خوادم MCP: auth_required, bootstrap_failed, clone_failed, config_invalid, config_rejected, connect_failed, git_missing, missing_credentials, server_start_failed. قد تكون قيمة كل نوع أيضًا exception, filesystem_error, network, other, permission. يُصنَّف الخطأ المرفوع دون فئة مسمّاة بحسب نوعه في Python فقط (تُعرض PermissionError كـ permission، وأخطاء الاتصال والمهلة كـ network، وغيرها من OSError كـ filesystem_error، وأي شيء آخر كـ exception، مع حذف اسم نوعه). تُضبط registry على صفوف المهارات فقط: مهايئ skills-hub الذي حدّد المهارة أو قدّمها، إحدى قيم browse-sh, clawhub, github, hermes-index, lobehub, official, skills-sh, url, well-known (معرّفات المهايئات التي يبنيها tools/skills_hub_search.py::create_source_router)، أو unresolved حين لا يجيب أي مهايئ، أو none لاستعادة المهارات المدمجة وكل صف إضافة/MCP، أو other خلاف ذلك. الصف الذي تكون فيه failure_class خارج مجموعة نوعه، أو تكون none عند الإخفاق أو مضبوطة عند النجاح، أو يسمّي سجلًا في صف إضافة/MCP، غير صالح. لا يُسجَّل أبدًا المعرّف أو URL أو نص الخطأ أو المسار؛ يحتفظ name بقاعدته القائمة: اسم الكتالوج أو custom.
hermes.update.runفئة الإخفاقسبب إخفاق hermes update إلى جانب موضعه (failed_stage). none ما لم تكن النتيجة failed أو refused أو partial. تُشتق من إيصال التحديث النهائي فقط: build_failed و deps_failed و exception و fleet_stale و fleet_unverified و git_failed و interrupted و lock_held و managed_install و os_error و disk_full و permission_denied و restart_failed و subprocess_failed، وإلا other؛ وتبلّغ التحديثات الذاتية المحزَّمة لـ Desktop عن unknown (يحمل RPC الخاص بها مرحلة، لا سببًا أبدًا). يُقرأ الاستثناء الذي أنهى التشغيل باسم نوعه وحده، لا برسالته أبدًا (تُعرض PermissionError كـ permission_denied، وتُعرض OSError ذات errno يساوي ENOSPC كـ disk_full)؛ وتُعرض إعادة استئناف gateway فاشلة على Windows بعد التحديث كـ restart_failed. يسجّل كل خروج يوقف التشغيل قبل علامة مرحلة التطبيق token واحدًا من مجموعة مغلقة عند الخروج نفسه، ويقرأه التشغيل (تنطلق بعض هذه الحالات، وهي syntax_rollback و stash_restore_rejected و unexpected_branch و head_moved، بعدما ينقل git الشجرة ويعيدها أو يتركها ليستعيدها التشغيل التالي): fetch_failed و git_timeout (وصل استدعاء git شبكي إلى حد زمن المحدِّث) و channel_unresolved (يشمل أيضًا اسم قناة غير صالح في config.yaml) و gateway_pause_failed (Windows: تعذّر إيقاف الـ gateways مؤقتًا بأمان قبل نقل venv) و git_in_progress (كانت عملية merge/rebase/... جارية بالفعل) و git_index_locked و merge_conflict (commits محلية على branch مخصّص) و checkout_move_failed و branch_missing و parked_branch_blocked و detached_head و unexpected_branch و head_moved (تحرّك ref أثناء التحديث) و target_unresolved و target_syntax_error (رُفض قبل النقل) و syntax_rollback (نُقل وفشل فحص الصياغة ثم أُعيد) و commit_point_refused (تعذّرت تهيئة نقطة commit؛ لم يتحرّك شيء) و downgrade_refused (الهدف أقدم من وقت تشغيل الـ gateway الذي يحتفظ state.db الخاص بالـ profile بسجل له بالفعل؛ لم يتحرّك شيء) و venv_foreign_owner و local_changes_blocked (تغييرات محلية تعذّر على git وضعها في stash، أو شجرة غير نظيفة لن يستبدلها خيار ZIP الاحتياطي) و stash_restore_rejected و not_git_checkout و old_version_handoff (تعذّر اكتمال تسليم التحكم من محدِّث أقدم) و branch_unsupported و download_failed و zip_failed و disk_full و lock_held و managed_install. أصبحت aborted_before_apply الآن مجرد قيمة احتياطية لخروج كهذا بلا token مسجَّل. يقرأ فحص الصياغة المسبق عند البدء الملفات الحرجة للهدف من مخزن كائنات git؛ وعند انتهاء مهلة القراءة (يجلب تثبيت بلا blobs كل blob عند الحاجة)، يتجاوزها الفحص كما لو كانت ملفات غائبة ويقرّر فحص الصياغة بعد النقل، فلا يفشل التشغيل بعد الآن كـ subprocess_failed. يحدث رفض قفل التحديث ورفض عملية Git ورفض التثبيت المُدار قبل فتح إيصال التشغيل؛ ولا تكتب هذه الحالات إيصالًا (مخزن الإيصالات مملوك للتحديث الذي يمسك القفل)، وتسجّل صفًا واحدًا بذلك الـ token، مع kind هو desktop عندما تسمّي علامة التحديث تسليم Desktop لهذا التشغيل (كمفوَّض له أو شريك تسليمه)، لا لمجرد أن تحديثًا آخر يمسك العلامة. لا يُعرض خطأ git الذي أنهى نقل النسخة المسحوبة كـ git_index_locked إلا حين يبلّغ git أن قفل index موجود بالفعل؛ ويُعرض رفض git لصلاحية كتابته (أو كتابة أي ملف) كـ permission_denied. لا يُقرأ token إلا ما دام التشغيل بلا علامة تطبيق، فلا يمكن لسبب أن يستمر بعد الخروج الذي سجّله. التشغيل الذي نفّذ commit ثم قُوطع، أو تعذّرت إعادة تطبيق تغييراته المحلية الموضوعة في stash، يُعرض بالنتيجة partial (interrupted / local_changes_parked، و failed_stage هو apply للحالة الأخيرة)، وليس failed أبدًا؛ وتُبقي المتابعات المستحقة وحدها التشغيل في حالة success (العقد C3). يُعلَّق التشغيل الذي يُنهيه مفسّر ما قبل التحديث مع الـ token ورمز الخروج ونوع الاستثناء في بداية سبب الإيقاف (أو إحدى عبارتين ثابتتين في Hermes) وأعلام إعادة التشغيل/إجراء المستخدم (لا argv أو مسارات أو رسائل أبدًا)، فيُصنَّف تمامًا مثل التشغيل نفسه لو انتهى داخل العملية. يُعرض التشغيل الفاشل الذي نجحت علامات مراحله كلها الآن بـ failed_stage هو verify (كتب التحقق بعد إعادة التشغيل partial) أو restart (تركت إعادة تشغيل متجاوَزة إعادة تشغيل مستحقة للأسطول) بدلًا من other؛ ويحتفظ تشغيل partial ذو علامة بناء أو إعادة تشغيل فاشلة بتلك المرحلة، ولا يفشل صف مرحلة التحقق فيه إلا عندما يضم الأسطول صفًا قديمًا أو متوقفًا.

التثبيتات الجديدة

المقياسالأبعادالسؤال الذي يجيب عنه
hermes.install.runالمُثبّت (install_sh، install_ps1، other)، النتيجة (success، failed)، مرحلة الفشل (prerequisites، repository، venv، python_deps، config، products، setup، gateway، complete، other; none عند النجاح)، فئة الفشل (unsupported_platform، download_failed، download_digest_mismatch، uv_unusable، git_missing، curl_missing، libstdcxx_missing، git_extract_failed، dir_not_checkout، git_clone_failed، git_fetch_failed، local_changes_blocked، git_checkout_failed، git_reset_failed، commit_not_on_branch، filesystem_error، python_install_failed، deps_install_failed، products_build_failed، setup_failed، gateway_failed، interrupted، other; none عند النجاح)، فئة المدة (lt_30s … gte_15m)عدد مرات نجاح تشغيل جديد لـ install.sh / install.ps1، والمرحلة والسبب من القائمة المغلقة اللذين يفشل عندهما. يعمل المُثبّت قبل سؤال الموافقة ولا يرسل شيئًا أبدًا: يترك تشغيل كامل (لا استدعاء --stage / -Stage منفردًا، لذا لا تُحتسب استدعاءات مُثبّت تمهيد Desktop لكل مرحلة) ملفًا محليًا صغيرًا واحدًا تحت $HERMES_HOME/telemetry/shared_metrics/pending_installs/ لا يحمل إلا هذه tokens، ومعرّفًا عشوائيًا، ووقتي البدء والانتهاء (لا نص الخطأ، ولا المسارات، ولا عناوين URL، ولا أسماء المضيفين أبدًا). يحتسبه بدء Hermes لاحق في ذلك الـ profile مرة واحدة، وفقط عندما يكون الجمع مفعّلًا حينها؛ أما البدء مع تعطيل الجمع، أو أي إجابة ترفض المشاركة، فيحذف الملفات دون الإبلاغ عنها. عند تفعيل الإرسال، لا يُسجَّل الصف إلا في يوم UTC يمكن لحزمته اجتياز بوابة الموافقة على الإرسال، أي عندما تكون نافذة موافقة الإرسال قد فُتحت عند 00:00 UTC في ذلك اليوم أو قبله: الموافقة المقدَّمة أثناء التثبيت نفسه (مرحلة الإعداد) تفتح النافذة في منتصف اليوم، لذا ينتظر الإيصال أول بدء في يوم لاحق، بدلًا من دخوله حزمة يوم الموافقة التي لا تُرسل أبدًا. عند تفعيل الجمع وتعطيل الإرسال، يُسجَّل الصف في أول بدء ويبقى على هذا الجهاز. يُحذف دون إبلاغ إيصال لم يحتسبه أي بدء خلال 7 أيام، فلا يُحتسب تثبيت قديم تحت إصدار Hermes لاحق أبدًا؛ ويُحذف الإيصال غير المقروء أيضًا. إيقاف التثبيت بواسطة Ctrl-C أو SIGTERM أو إغلاق الطرفية (SIGHUP) يسجَّل كـ interrupted، حتى إن التقطته العملية الفرعية للمرحلة وخرجت بخطئها الخاص؛ أما Ctrl-C الذي تعالجه مرحلة وتتعافى منه (منتقي المزوّد في الإعداد) فلا يوقف التثبيت. لذا لا يُحتسب التثبيت الفاشل إلا عندما ينجح تثبيت لاحق أو بدء Hermes في الـ profile نفسه مع تفعيل الجمع؛ ولا يُحتسب أبدًا تثبيت فاشل لا يتبعه أحدهما.

تُكتب الحالة المحلية تحت:

تحتفظ قاعدة البيانات بحالة المجاميع وصندوق الحزم الصادرة ضمن معاملات. ملفات الحزم مستندات فروق غير قابلة للتغيير، تتوافق مع مخطط JSON مغلق، وتُكتب باستبدال ذري كـ JSON مختصر (يعرض jq . إحداها بتنسيق مقروء). بعد قبول خدمة الاستقبال حزمة أو رفضها، لا تحتفظ قاعدة البيانات إلا بحالة إرسالها وتحذف نسختها من المتن؛ والملف هو نسخة السجل المحلية. تسجّل كل حزمة إصدار Hermes، وعائلة OS، والبنية المعمارية، وطريقة التثبيت كموارد عميل ذات قيم محدودة. تُصدَّر قيم المنصة أو التثبيت غير المعروفة كـ unknown؛ ولا تُضمَّن أبدًا سلاسل المنصة الخام أو أسماء المضيفين أو المسارات. تُحفَظ محليًا صفوف المجاميع التي حُزمت بالكامل وصفوف الحزم وملفاتها التي صُدِّرت بنجاح لمدة 30 يومًا. لا تُقلَّم أبدًا صفوف الحزم المعلّقة والعدّادات ذات الفروق غير المصدَّرة. تبقى مخططات الحزم v1 و v2 و v3 دون تغيير لملفات الصندوق الصادر الموجودة. تستخدم الحزم الجديدة v4، الذي يضيف failure_class إلى hermes.compression.count و hermes.memory.op.count، ويظل يقبل مجموعات حقولهما من v3 (وبتوسعة في المكان بقيم إضافية فقط، حتى بعد صدور v4 في إصدار مستقر، أُضيف أيضًا failure_class إلى hermes.extension.install.count / hermes.update.run وكذلك registry إلى الأول، مع الاستمرار في قبول مجموعات حقولهما السابقة من v4؛ وجاء hermes.prepared_compaction.count وحقل compression_prepare_ahead الاختياري في اللقطة بالطريقة نفسها)، مثلما قبل v3 مجموعات حقول v2 لـ hermes.model_route.count، hermes.tool_call.count وعدّادات المهام، فتُفرَّغ العدّادات المسجّلة قبل الترقية بأمان. المفردات المشتقة من السجلات داخل المستودع (أسماء الأدوات، والمنصات، ومزوّدو الذاكرة، وفئات الأخطاء) مقيدة بنمط في مخطط JSON؛ وقائمة السماح المعتمدة هي shared_metrics_contract.py. تظل القيم التي لم يعد Hermes يصدرها مقبولة بوصفها قيمًا قديمة (legacy) كي تُفرَّغ العدّادات المسجّلة بإصدار أقدم: فأدوات المتصفح المدمجة المُزالة (browser_navigate، browser_snapshot، browser_click، browser_type، browser_scroll، browser_back، browser_press، browser_console، browser_get_images، browser_vision) تظل أسماء أدوات صالحة، وcamofox يظل تسمية صالحة لـ browser backend. يُشحن Camofox الآن كإضافة الكتالوج camofox، لذا تُبلغ أدواته عن plugin.

تحتوي كل حزمة على install_id يُولَّد كـ UUID عشوائي. رغم اسم حقل المخطط، فإن نطاقه الحالي هو HERMES_HOME واحد، لذا فهو بدقة أكبر معرّف profile دائم باسم مستعار. لا يُشتق من بيانات الأجهزة أو الحساب أو المضيف أو المسار أو بيانات الاعتماد. يظل ثابتًا عبر حزم ذلك الـ profile، لذا يمكنه الربط بين تلك الحزم المحلية. حذف $HERMES_HOME/telemetry/shared_metrics يعيد ضبط المعرّف مع جميع المجاميع وملفات الحزم.

التسليم البعيد اختياري التفعيل ومعطّل افتراضيًا. تطلبت إعادة استخدام المعرّف المحلي الدائم عن بعد قرارًا منفصلًا يتعلق بالمنتج والخصوصية، ويشمل الموافقة، ونطاق الهوية، وسلوك إعادة الضبط، والاحتفاظ، والحذف — وقد اتُّخذ هذا القرار.

سُجِّلت تلك القرارات في الملحق A، وأُصدر المصدِّر الذي ينفّذها. الجمع وحده لا يزال لا يرسل شيئًا: لا يعمل المُرسل إلا عندما تكون telemetry.shared_metrics.send أيضًا true. تحمل كل حزمة مرسلة install_id الثابت كما هو (قرار المنتج، 2026-08-27 — راجع A.2 للسجل، بما فيه تصميم الاسم المستعار القائم على HMAC الذي استُبدل).

نطاق هوية التثبيت هو HERMES_HOME واحد. لإعادة ضبطها، أوقف عمليات Hermes وأزل $HERMES_HOME/telemetry/shared_metrics. يزيل ذلك عمدًا الهوية القديمة وقاعدة بيانات المجاميع والحزم المحلية المنتظرة معًا؛ وتنشئ الجلسة التالية التي وافقت على المشاركة هوية جديدة. تعطيل المقاييس المشتركة يوقف الجمع الجديد لكنه لا يحذف بصمت الحالة المحلية التي جُمعت سابقًا.

اختبار فحص سريع

شغّل دور Hermes CLI فعليًا باستخدام خادم النموذج المحلي الحتمي:

يستخدم السكربت اعتماد nemo-relay المثبّت افتراضيًا. لا تمرّر --relay-python ../nemo-relay/python إلا عند اختبار ربط Relay مبني محليًا.

يجعل الفحص السريع النموذج المحلي يطلب استدعاءً فعليًا لأداة read_file قبل رده النهائي، ثم ينفّذ انتقالات المهارة: الإنشاء، والتحميل، وإعادة الاستخدام، والتصحيح، والتحرير، والقدم، والأرشفة، والاستعادة، والتثبيت، عبر ربط Relay المثبّت. يتحقق من عدّادات النموذج والمزوّد والمهمة والأداة والمهارة في SQLite، ويفحص جميع حزم الفروق المصدَّرة وفق المخطط المغلق، ويتحقق من عدّاد نشاط العميل ذي الاسم المستعار، ويتأكد من غياب قيم الاختبار الكاشفة للـ prompt والاستجابة ومعرّف استدعاء الأداة ونتيجة الأداة واسم المهارة عن الحزم.
