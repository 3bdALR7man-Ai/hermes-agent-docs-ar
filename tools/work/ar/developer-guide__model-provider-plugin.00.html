بناء إضافة لمزوّد النماذج

تصرّح إضافات مزوّدي النماذج (model provider plugins) عن backend للـ inference — سواء كان endpoint متوافقًا مع OpenAI، أو خادم Anthropic Messages، أو Responses API على نمط Codex، أو واجهة Bedrock أصلية — يستطيع Hermes توجيه استدعاءات AIAgent عبره. ويأتي كل مزوّد مدمج (OpenRouter و Anthropic و GMI و DeepSeek و Nvidia، …) على هيئة إضافة من هذا النوع. ويمكن للأطراف الخارجية إضافة مزوّديها بوضع مجلد تحت $HERMES_HOME/plugins/model-providers/ دون أي تغيير في المستودع.

نصيحة

إضافات مزوّدي النماذج هي النوع الثالث من إضافات المزوّدين. أما النوعان الآخران فهما إضافات مزوّدي الذاكرة (المعرفة عبر الجلسات) وإضافات Context Engine (استراتيجيات ضغط السياق). وتتبع الأنواع الثلاثة النمط نفسه: "ضع مجلدًا، وصرّح عن profile، دون تعديل المستودع".

كيف يعمل الاكتشاف

providers/__init__.py._discover_providers() بشكل كسول (lazy) في أول مرة تستدعي فيها أي شيفرة get_provider_profile() أو list_providers(). ترتيب الاكتشاف:

  1. الإضافات المضمّنة — <repo>/plugins/model-providers/<name>/ — تأتي مع Hermes
  2. إضافات المستخدم — $HERMES_HOME/plugins/model-providers/<name>/ — ضع مجلدًا؛ تكتشفه العملية الجارية عند البحث التالي عن المزوّد (دون إعادة تشغيل)
  3. الإضافات المثبّتة — $HERMES_HOME/plugins/<name>/ (حيث ينسخ hermes plugins install owner/repo المستودعات) — لا تُستورد إلا عندما يصرّح plugin.yaml بـ kind: model-provider؛ وأي نوع آخر هناك يتبع PluginManager العام
  4. الصيغة القديمة أحادية الملف — <repo>/providers/<name>.py — للتوافق مع الإصدارات السابقة في عمليات التثبيت القابلة للتعديل (editable) خارج الشيفرة الأساسية

تُطبَّق الخطوتان 2 و 3 لكل مجلد رئيسي لـ profile: تحدد العملية الواحدة التي تخدم عدة profiles (الـ gateway متعدد الـ profiles الذي يتصل به Desktop محلي، أو backend الخاص بـ hermes serve) إضافات الـ profile الذي ترتبط قيمة $HERMES_HOME الخاصة به وقت البحث؛ ولا تظهر إضافة مثبّتة في profile لـ profile آخر. ثبّت الإضافة في كل profile ينبغي أن يستخدمها (hermes -p <profile> plugins install ...).

تتفوق إضافات المستخدم على الإضافات المضمّنة التي تحمل الاسم نفسه لأن register_provider() تعتمد قاعدة "آخر من يكتب هو الفائز". ضع مجلد $HERMES_HOME/plugins/model-providers/gmi/ لاستبدال profile المدمج الخاص بـ GMI دون لمس المستودع.

بنية المجلدات

الملف الإلزامي الوحيد هو __init__.py. أما plugin.yaml فيستخدمه hermes plugins للاستبطان (introspection)، ويستخدمه PluginManager العام لتوجيه الإضافة إلى المحمّل المناسب؛ ودونه يلجأ المحمّل العام إلى أسلوب استدلالي يعتمد على نص الشيفرة المصدرية.

إعلان قدرات النماذج

يحدد Hermes قدرات كل نموذج (supports_reasoning, supports_vision, supports_tools, context_window) من كتالوج models.dev، الذي لا يعرف نماذج المزوّد الموجود خارج الشجرة. أعلنها مرة واحدة على profile:

المفاتيح معرّفات نماذج مطابقة تمامًا. تستخدم القيم مخطط model_overrides من config.yaml — القيم المنطقية الثلاث للقدرات، وقيمة موجبة لـ context_window، وقيمة اختيارية لـ model_family — وتظل الحقول المحذوفة غير معروفة (لا False)، لذلك يكمّل الإدخال الجزئي بيانات الكتالوج الوصفية دون محوها.

يغذي الإعلان الواحد كل مستهلك يقرأ الكتالوج عبر agent.models_dev: شارة /model الخاصة بمنتقي reasoning، وتوجيه الصور (تختار decide_image_input_mode وضع native لنموذج supports_vision: True حتى عندما لا تُضبط supports_vision العامة للـ profile)، والبحث عن context window، و /api/model/info في لوحة التحكم. ترتيب الأولوية: تجاوز المستخدم الصريح model_overrides.<provider>.<model> → إعلان الإضافة → الكتالوج → سد الثغرات بواسطة _default. وتحتفظ النماذج التي لا تعلنها الإضافة بمسار الكتالوج/الاستدلالات التقريبية.

لا يشمل ذلك: شارة fast في المنتقي (استدلالًا تقريبيًا من اسم النموذج في hermes_cli/models.py::model_supports_fast_mode)، ومفردات جهد الاستدلال (agent/reasoning_effort.py)، وحقول طلبات النقل. لا تضيف الإعلانات نماذج إلى المنتقي — استخدم fallback_models / fetch_models لذلك. يُكتشف السجل مرة واحدة لكل عملية: أعد تشغيل Hermes بعد تعديلها.

الـ hooks القابلة لإعادة التعريف

أنشئ فئة فرعية من ProviderProfile للخصوصيات غير البسيطة:

استخدام الحساب

يمكن لإضافات مزوّدي النماذج توفير استخدام الحساب أو الخطة إلى /usage بإعادة تعريف ProviderProfile.fetch_account_usage. استورد وأعد الكائن المشترك agent.account_usage.AccountUsageSnapshot (مع أي إدخالات AccountUsageWindow)؛ ولا تنسّق المخرجات في الإضافة. تؤدي إعادة None أو إطلاق استثناء إلى ترك /usage فارغًا كما يحدث للمزوّدين دون بيانات استخدام. تحظى دوال جلب الاستخدام المدمجة بالأولوية دائمًا، فلا تستطيع هذه hook استبدال سلوك استخدام الحساب لمزوّد مدمج. تعمل hook تحت مهلة مشتركة قدرها 10 ثوانٍ (agent.account_usage.PLUGIN_USAGE_HOOK_DEADLINE_S) على كل الواجهات؛ ويؤدي تجاوزها إلى عدم عرض شيء في ذلك الدور بدلًا من تعطيل /usage، لذلك اضبط مهلة أقصر لاستدعاءات HTTP الخاصة بك.

يطبّق profile المضمّن plugins/model-providers/opencode-zen/ هذه hook لنوافذ خطة OpenCode Go؛ وتعرض كل واجهات /usage (أمرا CLI hermes usage و /usage، و messaging gateway، وتغذية الاستخدام في TUI/Desktop) اللقطة عبر منسّق النواة نفسه.

مزوّدو العمليات الخارجية (ACP)

وكيل CLI يُدار عبر stdio ليس endpoint من نوع HTTP. اضبط auth_type="external_process"، وصِف طريقة تشغيل الملف التنفيذي، ووفّر العميل عبر create_client. لا حاجة إلى أي تعديلات في الشيفرة الأساسية — فكل من hermes -m <name> و/model وحسم بيانات الاعتماد والحسم وقت التشغيل والعميل المساعد (الضغط، الرؤية) يعتمد على auth_type، لا على اسم المزوّد. ويُعد plugins/model-providers/copilot-acp/ المثال الموجود ضمن الشيفرة الأساسية.

الحقلالغرض
process_commandالملف التنفيذي الافتراضي، مثل "copilot"
process_argsذيل argv الافتراضي، مثل ("--acp", "--stdio")
process_command_env_varsمتغيرات البيئة التي تتجاوز الملف التنفيذي، ويجري فحصها بالترتيب
process_args_env_varمتغير البيئة الذي يتجاوز argv (يُقسَّم باستخدام shlex)

يتلقى العميل الذي تُرجعه create_client القيمتين command وargs ضمن client_kwargs. وإذا كان العميل مكتملًا أصلًا وآمنًا للاستخدام غير المتزامن، فصرّح بـ HERMES_SKIP_TRANSPORT_WRAP = True / HERMES_SKIP_ASYNC_WRAP = True كخصائص للفئة، كي لا يعيد العميل المساعد إرسالها عبر محوّل بروتوكول HTTP.

صفوف المنتقي للإضافات التي لا تستخدم مفتاح API

ينضم كل profile مسجّل إلى CANONICAL_PROVIDERS باسمه المعرّف (تُزال ازدواجية إضافة تعيد إعلان اسم مدمج مثل bedrock ولا يتكرر)، فتظهر إضافات العمليات الخارجية و OAuth في hermes model, /model ومنتقي النماذج في Desktop إلى جانب copilot-acp. يُقيَّد الظهور ببيانات الاعتماد، لا بـ auth_type:

auth_typeيُدرَج الصف / تكون authenticated عندماقائمة النماذج
external_processيُعثر على الملف التنفيذي (توجد process_command أو إحدى قيم process_command_env_vars على PATH)، أو تكون base_url بقيمة acp+tcp://… — وهو القيد البنيوي نفسه الذي يعرضه hermes auth status. ويُعدّ العثور على الملف التنفيذي أيضًا دليل تسجيل الدخول (auth_verified) الذي يستخدمه مرشح الاختيار الصريح فقط في منتقي Desktop، فيظهر الصف هناك كما يظهر مزوّد ACP المضمّنfetch_models() (فحص عمليتك الفرعية)، وإلا fallback_models
oauth_external / oauth_device_codeيحتوي مجمّع بيانات الاعتماد صفًا للاسم المعرّف مع token صالح (غير منتهي) — يقرأ كل من hermes auth status <name> و list_available_providers().authenticated المجمّع؛ ويُبلَّغ عن صف منتهٍ يملك refresh_token و hook refresh_credential بوصفه needs_refreshfetch_models() باستخدام token من المجمّع، وإلا fallback_models (أعلن نموذجًا واحدًا على الأقل)

تُفهرَس ذاكرة الكتالوج المؤقتة بقيم process_command_env_vars / process_args_env_var للـ profile، لذلك يؤدي توجيه HERMES_<X>_COMMAND إلى ملف تنفيذي مختلف إلى إعادة اكتشاف النماذج. اكتشاف الملف التنفيذي ليس فحص تسجيل دخول: يظل CLI غير المُصادَق عليه مدرجًا، وتبلغ العملية الفرعية عن الإخفاق عند أول استخدام.

يؤدي اختيار الصف في hermes model (وفي معالج الإعداد) إلى تشغيل مسار عام واحد يعتمد على auth_type للـ profile: يُفحص إطلاق profiles العمليات الخارجية (resolve_external_process_provider_credentials)، وتحتاج profiles OAuth إلى صف صالح في المجمّع (وإلا يطبع المسار hermes auth add <name> ويتوقف)، ثم يُعرض الكتالوج المدمج وتُحفظ config.model مع base_url/api_mode للـ profile. لا حاجة إلى إدخال _model_flow_* في النواة.

hooks اختيارية للعمليات الخارجية

يمكن لـ profiles العمليات الخارجية تطبيق setup_status(**kwargs) التي تعيد {available, logged_in, plan, detail, login_command} و discover_models(**kwargs) التي تعيد [{id, label, note}]. يعتمد المسار العام على logged_in (ويشغّل login_command مباشرةً على TTY، أو يطبع detail خلاف ذلك)، وعندما تعيد discover_models() صفوفًا، يعرضها مدمجةً مع fallback_models; note تظهر كتوضيح باهت لكل صف (· usage credits) ولا تخفي نموذجًا مطلقًا. اجعل fetch_models() تعيد المعرّفات نفسها، كي يتفق /model ومنتقي Desktop مع الإعداد. يجب أن تكون كلتا hook منخفضتي التكلفة وألا تنفّذا inference مطلقًا؛ أعد None للرجوع إلى fallback_models.

للطلبات غير HTTP القابلة للمقاطعة، طبّق دالة cancel(self) معلنة في الفئة. يستدعيها Hermes من thread المقاطعة بعد وسم عميل الطلب بأنه غير قابل للاستخدام. يجب أن تعود بسرعة وتوقف وسيلة نقلها بأمان، بما في ذلك الإلغاء المتزامن مع بدء العملية؛ ويجب ألا تغلق واصفات الملفات التي يملكها thread الطلب. يظل مالك الطلب يستدعي close() للتنظيف. تحتفظ العملاء التي لا تملك هذه الدالة بمسار الإلغاء الحالي عبر إغلاق socket.

أعلن model_aliases ({"sonnet": "claude-sonnet-5[1m]"}) لكتالوج لا يعرفه models.dev: يُحدَّد الأمر المجرد /model <alias> و /model <id-prefix> داخل مزوّد العملية أولًا، وتقبل validate_requested_model معرّفًا معلنًا دون فحص process://.

يحتفظ التفويض الصريح إلى عملية خارجية بالمزوّد المحدد وبروتوكوله عند تحديد أمر العملية الفرعية؛ ولا يحوّل تجاوز الملف التنفيذي وحده مزوّد عملية خارجية إلى ACP.

يمكن للعملاء الأصليين حفظ بيانات خاصة لإعادة إرسال رسائل المساعد في reasoning_details بنوع ضمن نطاق أسماء هو <provider>.native_assistant. أعلن السلسلة المطابقة في ProviderProfile.native_reasoning_details_type (الافتراضي None). تعيد تنقية طلبات Chat Completions توجيه ذلك الحقل فقط إلى profile الذي أعلنه، حتى بعد اللجوء إلى مزوّد احتياطي أو تبديل النموذج؛ وتحذف الحقول الخاصة الأخرى حتى إذا لم تعد إضافة المصدر مثبتة. وتظل تفاصيل الاستدلال القياسية، مثل reasoning.encrypted في OpenRouter، دون تغيير. تقتصر التصفية على الطلبات: يبقى السجل الدائم سليمًا للعودة إلى المزوّد الأصلي.

يمكن للمزوّدين إعادة تعريف get_model_context_length(model) بحد موجب ومتحقق منه للـ tokens، أو إعادة None لاستخدام سلسلة البحث الحالية. تحظى الإعدادات الصريحة والتجاوزات الخاصة بنطاق endpoint بالأولوية؛ ويُستشار حد المزوّد قبل التخزين المؤقت العام وفحوص HTTP. لا تخلط بين حد الكتالوج الأقصى واستحقاق الحساب.

لواجهة تكلفة غير قياسية، يمكن لـ get_usage_cost(model, usage) إعادة agent.usage_pricing.CostResult، أو None للتسعير المعتاد. تكون usage كائنًا من نوع CanonicalUsage تحتفظ فيه raw_usage ببيانات الاستجابة الوصفية عند توفرها. صنّف مجاميع أسعار القائمة الأصلية بوصفها estimated، لا actual أو included مطلقًا؛ فغياب معلومات الفاتورة ليس دليلًا على عدم وجود رسوم. تعيد hooks الافتراضية None، مع الحفاظ على المزوّدين الحاليين.

اختيار api_mode

يُتعرَّف إلى 4 قيم مدمجة (chat_completions, codex_responses, anthropic_messages, bedrock_converse)، إضافةً إلى أي وضع تسجّله إضافة بنفسها. يختار Hermes أحدها بناءً على:

  1. التجاوز الصريح من المستخدم (config.yaml model.api_mode عند ضبطه)
  2. التوجيه الخاص بكل نموذج في OpenCode ‏(opencode_model_api_mode لـ Zen و Go)
  3. الاكتشاف التلقائي من عنوان URL — اللاحقة /anthropic → anthropic_messages، وapi.openai.com → codex_responses، وapi.x.ai → codex_responses، و/coding على نطاقات Kimi → chat_completions
  4. قيمة api_mode كخيار احتياطي عندما لا يجد الاكتشاف من عنوان URL شيئًا
  5. القيمة الافتراضيةchat_completions

اضبط profile.api_mode لتطابق القيمة الافتراضية التي يعتمدها مزوّدك — فهي تعمل كتلميح. وتظل تجاوزات المستخدم لعنوان URL هي الفائزة.

توفير بروتوكول النقل الخاص بك

تسجّل الإضافة التي تتحدث بروتوكولًا لا تغطيه وسائل النقل المدمجة بروتوكولًا وتسميه في profile:

تقبل كل بوابة تحقق من api_mode (determine_api_mode، وتحديد وقت التشغيل، وإنشاء الوكيل، والتفويض) الوضع إذا وفقط إذا عرفه سجل وسائل النقل؛ ويظل profile الذي يسمّي وضعًا لم يسجّله أحد يعود إلى chat_completions.
