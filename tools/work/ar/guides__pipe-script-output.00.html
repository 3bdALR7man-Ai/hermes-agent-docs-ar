تمرير مخرجات السكربتات إلى منصات المراسلة

hermes send أداة CLI صغيرة وقابلة للبرمجة النصية تدفع رسالة إلى أي منصة مراسلة يكون Hermes معدًّا لها بالفعل. فكّر فيها كـ curl عابرة للمنصات للإشعارات — لا تحتاج إلى gateway قيد التشغيل، ولا تحتاج إلى LLM، ولا تحتاج إلى إعادة لصق رموز البوت في كل سكربت من سكربتاتك.

استخدمها من أجل:

  • مراقبة النظام (الذاكرة، القرص، حرارة GPU، انتهاء مهمة طويلة التشغيل)
  • إشعارات CI/CD (اكتمال النشر، فشل الاختبار)
  • سكربتات Cron التي تحتاج إلى إبلاغك بالنتائج
  • رسائل سريعة لمرة واحدة من الطرفية
  • تمرير مخرجات أي أداة إلى أي مكان (make | hermes send --to slack:#builds)

يعيد الأمر استخدام بيانات الاعتماد ومحوّلات المنصات نفسها التي يستخدمها hermes gateway بالفعل، لذا لا توجد واجهة إعداد ثانية يلزم صيانتها.

تحديد متن الرسالة

يحدّد hermes send متن الرسالة بهذا الترتيب:

  1. معطى موضعي — hermes send --to telegram "hi"
  2. --file PATH — hermes send --to telegram --file msg.txt
  3. stdin المُمرَّر عبر أنبوب (piped) — echo hi | hermes send --to telegram

عندما يكون stdin طرفية تفاعلية (TTY) (بلا أنبوب)، لا ينتظر Hermes الإدخال — بل ستحصل على خطأ استخدام واضح بدلًا من ذلك. هذا يمنع تعليق السكربتات إذا أغفلت المتن بالخطأ.

لا تنبّه الـ gateway بشأن نفسه

بالنسبة للمراقبات (watchdogs) التي قد تُطلَق عندما يعاني الـ gateway نفسه (تنبيهات نفاد الذاكرة (OOM)، تنبيهات امتلاء القرص)، واصل استخدام استدعاء curl بسيط بدلًا من hermes send. إذا تعذّر تحميل مفسّر Python لأن الجهاز مُثقَل، لا تزال تريد أن يخرج ذلك التنبيه.

هل يحتاج hermes send إلى تشغيل الـ Gateway؟

عادةً لا. بالنسبة لأي منصة تعتمد على رمز بوت — Telegram، وDiscord، وSlack، وSignal، وSMS، وWhatsApp Cloud API، ومعظم غيرها — يستدعي hermes send نقطة نهاية REST الخاصة بالمنصة مباشرة باستخدام بيانات الاعتماد من ~/.hermes/.env و~/.hermes/config.yaml. إنها عملية فرعية مستقلة تُنهي عملها فور تسليم الرسالة.

لا يُطلب gateway حيّ إلا لـمنصات الإضافات (plugin platforms) التي تعتمد على اتصال محوّل دائم (مثلًا، إضافة مخصّصة تُبقي اتصال WebSocket مفتوحًا لفترة طويلة). في هذه الحالة ستحصل على خطأ واضح يشير إلى الـ gateway؛ شغّله بـ hermes gateway start وأعد المحاولة.

مقارنة مع مناهج أخرى

hermes send هو عمدًا أبسط واجهة ممكنة. إذا احتجت وكيلًا ليقرر ماذا يقول، جدول مهمة cron — تُسلَّم استجابة الوكيل النهائية تلقائيًا إلى وجهة deliver: المُعدّة (لم يعد الوكيل يطلق الرسائل بنفسه). إذا احتجت تشغيلًا مجدولًا بمحتوى مولَّد بواسطة LLM، استخدم cronjob(action='create', prompt=...) مع deliver='telegram:...'. وإذا احتجت فقط تمرير نص خام عبر أنبوب، استخدم hermes send.

مواضيع ذات صلة

  • أتمتة أي شيء باستخدام Cron — مهام مجدولة تُسلَّم مخرجاتها تلقائيًا إلى أي منصة.
  • آلية عمل Gateway من الداخل — موجّه التسليم الذي يتشاركه hermes send مع تسليم cron.
  • إعداد منصات المراسلة — إعداد لمرة واحدة لكل منصة.
