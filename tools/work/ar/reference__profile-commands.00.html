مرجع أوامر Profile

تغطي هذه الصفحة كل الأوامر المتعلقة بـ profiles في Hermes. للاطلاع على أوامر CLI العامة، راجع مرجع أوامر CLI.

hermes profile

الأمر الرئيسي لإدارة profiles. تشغيل hermes profile دون أمر فرعي يعرض المساعدة.

الأمر الفرعيالوصف
listاسرد كل الـ profiles.
useاضبط الـ profile النشط (الافتراضي).
createأنشئ profile جديدًا.
describeاقرأ وصف profile أو اضبطه (يستخدمه منسّق kanban لتوجيه المهام).
deleteاحذف profile.
showاعرض تفاصيل profile.
aliasأعد توليد الاسم المستعار (alias) الخاص بـ profile في الـ shell.
renameأعد تسمية profile.
exportصدّر profile إلى أرشيف tar.gz.
importاستورد profile من أرشيف tar.gz.
installثبّت توزيعة profile من رابط git أو مجلد محلي. راجع توزيعات Profile.
updateأعد سحب profile مُدار بتوزيعة وأعد تطبيق حزمته (bundle).
infoاعرض بيانات التوزيعة الوصفية لـ profile (رابط الأصل، الـ commit، آخر تحديث).

المعطى / الخيارالوصف
<name>اسم الـ profile الجديد. يجب أن يكون اسم مجلد صالحًا (أحرف وأرقام وشرطات وشرطات سفلية).
--cloneانسخ config.yaml, .env, SOUL.md، والمهارات، والملفين المنتقَيَين memories/MEMORY.md / memories/USER.md، وإعدادات مزوّد الذاكرة النشط memory.providerنفسه (<provider>/ أو <provider>.json، مثل hindsight/config.json) من الـ profile الحالي. ولا تُنسخ الجلسات أو state.db أو مهام cron.
--clone-allانسخ كل شيء (الإعدادات، والذكريات، والمهارات، والإضافات) من الـ profile الحالي. يستثني السجل الخاص بكل profile: الجلسات، و state.db، والنسخ الاحتياطية، و state-snapshots، ونقاط الحفظ — ومهام cron التي تبقى مرتبطة بالـ profile المصدر (إذ يؤدي توريثها لنسخة مستنسخة إلى إطلاق كل مهمة مرتين). عندما يكون المصدر هو الـ profile الافتراضي، تُتجاوز أيضًا أشجار النماذج المحلية على مستوى الجهاز (models/, runtimes/, node/) — وهي الأشجار نفسها التي يستثنيها hermes backup .
--clone-from <profile>استنسخ الإعدادات/المهارات/SOUL من profile محدد بدلًا من الحالي. يتضمن --clone ضمنيًا ما لم يُقترن بـ --clone-all.
--no-aliasتخطَّ إنشاء سكربت الالتفاف (wrapper).
--description "<text>"وصف من جملة أو جملتين لما يبرع فيه هذا الـ profile. يستخدمه منسّق kanban لتوجيه المهام بحسب الدور بدلًا من اسم الـ profile وحده. تخطَّه وأضفه لاحقًا عبر hermes profile describe. يُحفظ في <profile_dir>/profile.yaml.
--no-skillsأنشئ profile فارغًا بلا أي مهارات مضمّنة مفعّلة. يكتب علامة .no-bundled-skills في الـ profile حتى لا تعيد عمليات hermes update المستقبلية زرع مجموعة المهارات المضمّنة، ويرفض التركيب مع --clone أو --clone-from أو --clone-all (التي ستنسخ المهارات على أي حال). مفيد لـ profiles منسّقات ضيقة النطاق أو profiles اختبار (sandbox) لا ينبغي أن ترث كتالوج المهارات كاملًا. لتبديل هذا الخيار على profile أُنشئ مسبقًا (بما في ذلك الافتراضي ~/.hermes)، استخدم hermes skills opt-out / hermes skills opt-in.

إنشاء profile لا يجعل مجلد ذلك الـ profile مجلد المشروع/مساحة العمل الافتراضي لأوامر الطرفية. إن أردت أن يبدأ profile في مشروع محدد، اضبط terminal.cwd في ملف config.yaml الخاص بذلك الـ profile.

أمثلة:

hermes profile describe

اقرأ وصف profile أو اضبطه. يستهلك منسّق kanban هذا الوصف لتوجيه المهام بحسب ما يبرع فيه كل profile، بدلًا من التخمين من اسم الـ profile وحده. يُحفظ في <profile_dir>/profile.yaml بحيث يبقى بعد إعادة التشغيل ويُشارَك مع الـ gateway.

دون أي أعلام، يطبع الوصف الحالي (أو (no description set for '<name>') إن كان فارغًا).

المعطى / الخيارالوصف
<name>الـ profile المراد وصفه. مطلوب ما لم يُستخدم --all --auto.
--text "<text>"اضبط الوصف على هذا النص بالضبط (من تأليف المستخدم). يستبدل أي وصف موجود.
--autoولّد تلقائيًا وصفًا من 1-2 جملة عبر LLM المساعد، استنادًا إلى مهارات الـ profile المثبتة ونموذجه المضبوط واسمه. اضبط النموذج ضمن auxiliary.profile_describer في config.yaml. تُوسَم الأوصاف المولَّدة تلقائيًا بـ description_auto: true ليتمكن dashboard من تمييزها للمراجعة.
--overwriteمع --auto، استبدل الأوصاف من تأليف المستخدم أيضًا (الافتراضي: تخطّي الـ profiles التي ضُبط وصفها صراحةً).
--allمع --auto، امسح جميع الـ profiles التي تفتقر إلى وصف.

hermes profile rename

يعيد تسمية profile. ويحدّث الدليل واسم shell البديل. وتُزال خدمة gateway المثبّتة بالاسم القديم (hermes -p <old-name> gateway install)، سواء كان الـ gateway يعمل أم لا، لأنها ستبدأ بالاسم القديم عند تسجيل الدخول التالي؛ أعد تثبيتها باستخدام hermes -p <new-name> gateway install. وداخل صورة Docker، تنتقل خانة gateway في s6 إلى الاسم الجديد.

ترحّل إعادة التسمية أيضًا هوية الجلسة/التوجيه المحفوظة للـ profile — مفاتيح الجلسات (agent:<old>:*), sessions.profile_name، والنبضات، وصفوف التوجيه/التسليم — إلى الاسم الجديد. ويتولى gateway حي متعدد الإرسال ذلك الترحيل (إذ يحتفظ بفهرس التوجيه في الذاكرة)، لذا حين يعمل يفوّض CLI الأمر إليه. ويُعاد مفتاح سجل نقاط الحفظ (/rollback) لمساحات العمل داخل دليل الـ profile إلى مسارها الجديد أيضًا، كي يبقى متاحًا بعد إعادة التسمية؛ ويعيد hermes profile migrate-identity محاولة تلك الخطوة أيضًا إذا أُبلغ عن فشلها.

hermes profile migrate-identity

يعيد محاولة ترحيل الهوية لإعادة تسمية اكتملت بالفعل. نفّذه إذا حذّر hermes profile rename من تعذّر ترحيل هوية الجلسة بواسطة الـ gateway الحي: أعد تشغيل الـ gateway (فيعيد تحميل فهرس التوجيه من قاعدة البيانات ويُطبَّق الترحيل)، أو أوقفه — وفي غياب gateway يحتفظ بالمخزن ينفّذ الأمر إعادة الكتابة الدائمة بنفسه.

تقود الترحيلَ الصفوف التي ما زالت تذكر <old>، لذا لا يلزم وجود profiles/<old> ؛ ولا يُفحَص إلا <new> . العملية idempotent — تنجح إعادة تشغيل ترحيل مكتمل دون أن يبقى شيء لإعادة تعيين مفاتيحه. يخرج برمز غير صفري عندما يرفض gateway حي الترحيل، أو ترفض قاعدة بيانات إعادة الكتابة (تعارض توجيه، أو قفل، أو فشل إحدى القاعدتين ونجاح الأخرى)، مع ذكر قاعدة البيانات والخطأ.

مثال:

hermes profile purge-identity

يعيد محاولة تنقية الهوية لحذف اكتمل بالفعل. نفّذه إذا أبلغ hermes profile delete بأن تسوية هوية الجلسة/التوجيه ما زالت معلّقة: أعد تشغيل الـ gateway (فيعيد تحميل فهرس التوجيه من قاعدة البيانات وتُطبَّق التنقية)، أو أوقفه — وفي غياب gateway يحتفظ بالمخزن ينفّذ الأمر الحذف الدائم بنفسه.

تعتمد التنقية على <name> وحده، لذا لا يلزم وجود دليل الـ profile — لكن يُرفض profile نشط مجددًا بهذا الاسم: فتسوية الهوية تتم بالاسم، وتنقيتها ستزيل معه توجيه الـ profile الجديد. وتُحذف مفاتيح التوجيه (agent:<name>:*) وصفوف النبضات وارتباطات موضوعات Telegram/صفوف الأوضاع الخاصة بالـ profile؛ وتُعلَّم صفوف delivery_obligations بـ abandoned بدل إسقاطها كي لا تضيع حالة التسليم المعلّقة بصمت. ولا تحذف التنقية نفسها صفوف الجلسات — فهي تسوّي الهوية لا السجل؛ ويقرر hermes profile deleteما إذا كان سجل المحادثة يبقى بعد الحذف، إذ يزيل profiles/<name>/الخاص بالـ profile بما فيه state.db . العملية idempotent — تنجح إعادة تشغيل تنقية مكتملة دون أن يبقى شيء لتنقيته. ويخرج برمز غير صفري حين يعود الاسم profile نشطًا، أو يرفض gateway حي التنقية، أو ترفض قاعدة بيانات الحذف (قفل، أو فشل جزئي).

مثال:

hermes profile export

يصدّر profile كأرشيف tar.gz مضغوط — لقطة محمولة يمكنك نسخها احتياطيًا أو نقلها إلى جهاز آخر أو تسليمها لشخص آخر. auth.json, .env ومخازن بيانات الاعتماد الأخرى مستثناة دائمًا؛ راجع محتويات ملف التصدير.

متاح أيضًا في المحادثة كـ /export، وفي تطبيق سطح المكتب عبر ⌘K → Export profile… أو قائمة النقر بزر الفأرة الأيمن على مربع profile. يضيف التصدير من سطح المكتب أيضًا ملف desktop.json (المظهر، الوضع الفاتح/الداكن، السمات المخصصة، لون الشريط الجانبي، تخطيط النافذة) إلى الأرشيف.
