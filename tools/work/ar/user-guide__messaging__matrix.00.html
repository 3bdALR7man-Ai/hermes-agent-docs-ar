إعداد Matrix

يتكامل Hermes Agent مع Matrix، بروتوكول المراسلة المفتوح والاتحادي (federated). يتيح لك Matrix تشغيل homeserver خاص بك أو استخدام homeserver عام مثل matrix.org — في كلتا الحالتين، تحتفظ أنت بالسيطرة على اتصالاتك. يتصل البوت عبر SDK بايثون mautrix، ويعالج الرسائل عبر خط أنابيب Hermes Agent (بما في ذلك استخدام الأدوات، الذاكرة، والاستدلال)، ويستجيب في الوقت الفعلي. يدعم النصوص، مرفقات الملفات، الصور، الصوت، الفيديو، والتشفير التام بين الطرفين (E2EE) الاختياري.

يعمل Hermes مع أي homeserver لـ Matrix — Synapse أو Conduit أو Dendrite أو matrix.org.

قبل الإعداد، إليك الجزء الذي يريد معظم الناس معرفته: كيف يتصرف Hermes بمجرد اتصاله.

كيف يتصرف Hermes

السياقالسلوك
الرسائل المباشرة (DMs)يستجيب Hermes لكل رسالة. لا حاجة إلى @mention. لكل DM جلسته الخاصة. اضبط MATRIX_DM_MENTION_THREADS=true لبدء thread عند الإشارة إلى البوت (@mentioned) في DM.
الغرف (Rooms)افتراضيًا، يتطلب Hermes إشارة (@mention) للاستجابة. اضبط MATRIX_REQUIRE_MENTION=false أو أضف معرّفات الغرف إلى MATRIX_FREE_RESPONSE_ROOMS لغرف الاستجابة الحرة. تُقبل دعوات الغرف تلقائيًا.
الـ Threadsيدعم Hermes threads في Matrix (MSC3440). إذا رددت في thread، يُبقي Hermes سياق الـ thread معزولًا عن الخط الزمني الرئيسي للغرفة. الـ threads التي شارك فيها البوت مسبقًا لا تتطلب إشارة.
الـ Threading التلقائيافتراضيًا، ينشئ Hermes تلقائيًا thread لكل رسالة يستجيب لها في غرفة. يحافظ هذا على عزل المحادثات. اضبط MATRIX_AUTO_THREAD=false لتعطيله. اضبط MATRIX_DM_AUTO_THREAD=true (الافتراضي false) لإنشاء threads تلقائيًا لرسائل DM أيضًا — وهذا مختلف عن MATRIX_DM_MENTION_THREADS، التي تبدأ thread فقط عند الإشارة إلى البوت (@mentioned) في DM.
الأوامريقبل Hermes أوامر /commands العادية عندما يرسلها عميل Matrix الخاص بك. إذا كان عميلك يحجز / للأوامر المحلية، استخدم !commands بدلًا من ذلك؛ يوحّد Hermes الأسماء البديلة المعروفة لـ !command إلى /command.
عناصر التحكم التفاعليةيمكن أن تستخدم موافقة الأوامر الخطرة واختيار /model ردود أفعال (reactions) Matrix. يمكن تقييد ردود أفعال الموافقة بالمستخدم الذي طلب الإجراء.
نشاط التفكير والأدواتيستخدم Matrix أجزاء thread قابلة للتحرير لعرض التفكير/نشاط الأدوات عند تفعيل تقدّم الـ gateway، بحيث لا تُغرق التحديثات الخط الزمني الرئيسي للغرفة.
الغرف المشتركة بين عدة مستخدمينافتراضيًا، يعزل Hermes سجل الجلسة لكل مستخدم داخل الغرفة. لا يشترك شخصان يتحدثان في نفس الغرفة في نسخة واحدة من المحادثة إلا إذا عطّلت ذلك صراحةً.
رموز LaTeX الرياضيةتُرسَل $...$ (ضمن السطر) و $$...$$ (منفصلة) في الردود كترميز data-mx-maths الخاص بـ Element، لذا تنسّقها العملاء التي تفعّل Settings → Labs → Render LaTeX maths in messages باستخدام KaTeX. تبقى علامات الدولار غير المزدوجة ($5 or $10) كما هي حرفيًا، ويحتفظ نص body العادي بصيغة TeX الخام للعملاء الأخرى.

تعطيل ردود الأفعال

يؤدي MATRIX_REACTIONS=false إلى إيقاف ردود أفعال الإيموجي الخاصة بدورة حياة المعالجة (👀/✅/❌) التي ينشرها البوت على الرسائل الواردة. مفيد للغرف التي تكون فيها أحداث ردود الأفعال مزعجة أو غير مدعومة من جميع العملاء المشاركين.

الإشارات على مستوى الغرفة

يرسل Hermes إشارات مستخدم Matrix منظّمة لمعرّفات Matrix الصريحة مثل @alice:example.org. إشعارات @room على مستوى الغرفة معطّلة افتراضيًا؛ اضبط MATRIX_ALLOW_ROOM_MENTIONS=true فقط في الغرف المسموح فيها للبوت بإشعار الجميع.

ملاحظة

إذا كنت تُرقّي من إصدار لم يكن يحتوي على MATRIX_REQUIRE_MENTION، فقد كان البوت يستجيب سابقًا لجميع الرسائل في الغرف. للحفاظ على ذلك السلوك، اضبط MATRIX_REQUIRE_MENTION=false.

النطاقالسلوك
autoالافتراضي المتوافق مع الإصدارات السابقة. يتحكم سلوك MATRIX_AUTO_THREAD الحالي في الـ threads الاصطناعية.
roomتبقى رسائل الغرفة غير المسلسلة (unthreaded) في جلسة غرفة ثابتة واحدة. لا تزال threads Matrix الحقيقية تستخدم جذر الـ thread الخاص بها.
threadتُركّب رسائل الغرفة غير المسلسلة thread/جلسة من معرّف الحدث المُطلِق.

يتضمن Hermes الآن اسم غرفة Matrix الحالية ومعرّفها وموضوعها ومعرّف الرسالة، وملاحظة حدود غرفة Matrix في prompt الوكيل. يعرض /status أيضًا نطاق غرفة/جلسة Matrix الحالي، ولن يستأنف /resume بصمت جلسة مسمّاة من غرفة Matrix أخرى ما لم تستخدم صراحةً /resume --cross-room <session name>.

يتحكم MATRIX_SESSION_SCOPE=room في مسار الغرفة/الـ thread. لا يزال إعداد group_sessions_per_user الحالي يتحكم فيما إذا كان المستخدمون داخل تلك الغرفة يشتركون في المسار. مع group_sessions_per_user: true (الافتراضي)، يحصل Alice و Bob على جلستي Project B منفصلتين. مع group_sessions_per_user: false، تحصل الغرفة على محادثة Project B واحدة مشتركة.

الإشعارات الصادرة لكامل الغرفة معطّلة افتراضيًا. أبقِ MATRIX_ALLOW_ROOM_MENTIONS=false ما لم يكن مسموحًا صراحةً للبوت بإيقاظ الغرفة بأكملها باستخدام @room.

تُخفي التشخيصات وحمولات التصحيح رموز وصول Matrix ومفاتيح الاسترداد ومعرّفات الأجهزة ونصوص الرسائل. تُحدَّد تنزيلات الوسائط بروابط محتوى Matrix mxc:// وتُرفض عندما تتجاوز MATRIX_MAX_MEDIA_BYTES. عامل الغرف الاتحادية (federated) و homeservers غير الموثوقة كمدخلات غير موثوقة: أبقِ قوائم السماح للغرف محكمة، وفضّل الرسائل المباشرة أو الغرف الخاصة للعمل الكثيف الاعتماد على الأدوات، وتجنّب تفويض ghosts الجسر أو دُمى appservice كمستخدمين مسموح بهم.

الوضعالسلوك

  • الانضمام التلقائي إلى الغرف المشفّرة عند الدعوة

أدوات وعناصر تحكم Matrix

لا يعرض Hermes أدوات وكيل خاصة بـ Matrix (مثل إنشاء الغرف، الدعوات، أو الحذف/التنقيح (redaction)) — يتفاعل الوكيل مع Matrix عبر تسليم الرسائل العادي. يستخدم المحول (adapter) ردود الأفعال والحذف داخليًا لتشغيل مطالبات الموافقة والمنتقيات (pickers).

إذا ضُبط MATRIX_ALLOWED_ROOMS، يستجيب Hermes فقط في تلك الغرف (الرسائل المباشرة معفاة).

تستخدم عناصر تحكم ردود الأفعال:

  • ✅ موافقة لمرة واحدة
  • ♾️ موافقة دائمة
  • ❌ رفض
  • ردود أفعال رقمية لاختيارات /model

اضبط MATRIX_APPROVAL_REQUIRE_SENDER=false إذا كنت تريد عن قصد أن يشغّل أي مستخدم Matrix مصرّح له في الغرفة مطالبة موافقة/اختيار نموذج. الإعداد الافتراضي مرتبط بالطالب عندما يعرف Hermes من طلب الإجراء.

التحقق بالتوقيع المتقاطع (Cross-Signing) (موصى به)

إذا كان حساب Matrix الخاص بك يفعّل التوقيع المتقاطع (الافتراضي في Element)، اضبط مفتاح الاسترداد حتى يتمكن البوت من توقيع جهازه ذاتيًا عند بدء التشغيل. بدون هذا، قد ترفض عملاء Matrix الأخرى مشاركة جلسات التشفير مع البوت بعد تدوير مفتاح الجهاز.

أين تجده: في Element، اذهب إلى Settings → Security & Privacy → Encryption → مفتاح الاسترداد الخاص بك (يُسمى أيضًا "Security Key"). هذا هو المفتاح الذي طُلب منك حفظه عند إعداد التوقيع المتقاطع لأول مرة.

عند كل بدء تشغيل، إذا ضُبط MATRIX_RECOVERY_KEY، يستورد Hermes مفاتيح التوقيع المتقاطع من التخزين الآمن للأسرار الخاص بـ homeserver ويوقّع الجهاز الحالي. هذا العملية مُتحايثة (idempotent) وآمنة لتُترك مفعّلة بشكل دائم.

إذا أنشأ Hermes مفتاح استرداد Matrix جديدًا، فلن يسجّل المفتاح الخام أبدًا في السجلات. اضبط MATRIX_RECOVERY_KEY_OUTPUT_FILE=/secure/path/matrix-recovery-key.txt قبل بدء التشغيل لكتابة مفتاح مولَّد مرة واحدة بصلاحيات ملف 0600؛ لا يُستبدَل الملف إذا كان موجودًا بالفعل.

حذف مخزن التشفير (crypto store)

إذا حذفت ~/.hermes/platforms/matrix/store/crypto.db، يفقد البوت هوية التشفير الخاصة به. مجرد إعادة التشغيل بنفس معرّف الجهاز لن يُستعاد بالكامل — لا يزال homeserver يحتفظ بمفاتيح لمرة واحدة موقّعة بمفتاح الهوية القديم، ولا يمكن للأقران إنشاء جلسات Olm جديدة.

يكتشف Hermes هذه الحالة عند بدء التشغيل ويرفض تفعيل E2EE، مسجّلًا: device XXXX has stale one-time keys on the server signed with a previous identity key.

أسهل تعافٍ: إنشاء رمز وصول جديد (الذي يحصل على معرّف جهاز جديد بدون سجل مفاتيح قديمة). راجع قسم "الترقية من إصدار سابق مع E2EE" أدناه. هذا هو المسار الأكثر موثوقية ويتجنب المساس بقاعدة بيانات homeserver.

التعافي اليدوي (متقدم — يحافظ على نفس معرّف الجهاز):

  1. أوقف Synapse واحذف الجهاز القديم من قاعدة بياناته:

    أو عبر admin API الخاص بـ Synapse (لاحظ معرّف المستخدم المُرمّز بترميز URL):

    ملاحظة: قد يؤدي حذف جهاز عبر admin API أيضًا إلى إبطال رمز الوصول المرتبط. قد تحتاج إلى إنشاء رمز جديد بعد ذلك.

  2. احذف مخزن التشفير المحلي وأعد تشغيل Hermes:

قد تخزّن عملاء Matrix أخرى (Element، matrix-commander) مؤقتًا مفاتيح الجهاز القديمة. بعد التعافي، اكتب /discardsession في Element لإجبار إنشاء جلسة تشفير جديدة مع البوت.

معلومة

إذا لم تكن حزمة mautrix[encryption] مثبّتة أو libolm مفقودة، يتراجع البوت تلقائيًا إلى عميل عادي (غير مشفّر). سترى تحذيرًا في السجلات.
