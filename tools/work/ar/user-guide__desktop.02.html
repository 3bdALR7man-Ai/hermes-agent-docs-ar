Quick Entry

Quick Entry مربع كتابة صغير متاح دائمًا، تستدعيه عبر اختصار عام من أي مكان في نظامك — أرسل prompt دون الانتقال إلى النافذة الرئيسية (أو حتى فتحها). فعّله من Settings → Advanced → Quick Entry؛ الاختصار الافتراضي هو Ctrl/Cmd+Shift+Space ويمكنك تعيين اختصارك الخاص (يتطلب مفتاح تعديل واحدًا على الأقل). وإذا كان تطبيق آخر يستخدم المجموعة نفسها، فسيخبرك صف الإعداد بذلك لتختار مجموعة مختلفة.

الصوت

تحدّث إلى Hermes واستمع إلى ردوده، عبر الوضع الصوتي نفسه المتاح في الواجهات الأخرى. على macOS، سيطلب نظام التشغيل مرة واحدة الإذن بالوصول إلى الميكروفون.

وضع HUD

⌘/Ctrl+Shift+H (أو زر شريط العنوان) يفصل المحادثة في شريط عائم بلا إطار، يبقى دائمًا في المقدمة فوق أي شيء تعمل عليه. تتنحّى نافذة التطبيق جانبًا؛ ويحتفظ الـ HUD بمحادثتك الحيّة ومربع كتابة. والمكان الذي تضعه فيه هو سياق بحد ذاته — فموضع الشريط يخبر Hermes بالتطبيق والشاشة اللذين تسأل عنهما، فتُفهم "هذا" و"هنا" و"تلك الصفحة" على أنها ما يقع أسفله.

  • تحريك الشريط — على macOS و Windows، اضغط مطوّلًا في أي مكان على مربع الكتابة لحظةً، ثم اسحب. على Linux/X11، اضغط باستمرار على Ctrl واسحب بزر الفأرة الأساسي للإمساك الفوري (حتى فوق النص المحدد)؛ ويبقى الضغط المطوّل متاحًا أيضًا. أبقِ الإمساك مستمرًا أثناء استخدام اختصار تبديل سطح المكتب لنقل الـ HUD إلى سطح مكتب افتراضي آخر. على Wayland الأصلي، يكون شريط مربع الكتابة مقبض سحب تابعًا للـ compositor (وهي الطريقة الوحيدة لتحريكه، لأن التطبيق لا يستطيع تحديد موضع نافذته بنفسه).
  • تغيير الحجم — اسحب أي حافة أو زاوية من الشريط؛ وتبقى الحافة المقابلة مثبّتة. يتيح Wayland الأصلي الحافتين اليمنى والسفلى فقط لأن الـ compositor لا يسمح للتطبيقات بتحديد مواضع نوافذها الرئيسية بنفسها.
  • إعادة ضبط التخطيط — يعيد عنصر التجاهل في الشريط الحجم الافتراضي و(على X11 / macOS / Windows) الموضع الافتراضي. استخدمه إذا جعل حجمٌ محفوظ الـ HUD غير قابل للاستخدام.
  • النقر للاستدعاء — فعّل Tap to summon HUD ضمن Settings → Keyboard Shortcuts → HUD gesture، ثم اضغط وحرّر ⌘+Option على macOS أو Ctrl+Alt على Windows/Linux X11. حرّر المفتاحين خلال نصف ثانية دون ضغط مفتاح آخر أو تنفيذ إجراء بالفأرة. على Windows استخدم Alt الأيسر؛ فالأيمن محجوز لتخطيطات AltGr. يفتح ذلك HUD أو يركز عليه من تطبيق آخر؛ ولا يغلقه بالتبديل أو يسجّل صوتًا أو يرسل رسالة. معطّل افتراضيًا، ويُحفظ على هذا الجهاز فقط. يتطلب macOS صلاحية Input Monitoring؛ ولا تعرض الصفحة أدوات الاسترداد إلا إذا احتاجت الصلاحية أو خطأ آخر إلى معالجة. لا يتيح Linux Wayland هذه الحركة، فواصل استخدام اختصار HUD داخل التطبيق هناك.
  • الانتقال إلى المؤشر — ⌘/Ctrl+Shift+G (اختصار عام يعمل من أي تطبيق) ينقل HUD إلى موضع مؤشرك. على Wayland الأصلي لا يفعل شيئًا — فالـ compositor يتحكم بالموضع.
  • الخروج — انقر زر الخروج في الشريط، أو اضغط ⌘/Ctrl+Shift+H مرة أخرى، أو اضغط ⌘/Ctrl+W أثناء تركيز الـ HUD. تعود نافذة التطبيق إلى المقدمة مع جلستك ومؤشر الكتابة في مربع الكتابة.

Linux / Wayland

في جلسة Wayland محلية (XDG_SESSION_TYPE=wayland، أو عند ضبط WAYLAND_DISPLAY) يبدأ Hermes باستخدام --ozone-platform=wayland كي لا يعود Electron إلى XWayland. يجب تحديد المنصة في سطر أوامر العملية قبل تحميل JavaScript التطبيق. وتظل الأولوية لـ --ozone-platform الصريح أو desktop.ozone_platform_hint: x11 أو منصة ozone في desktop.electron_flags. تعمل عمليات السحب والنقر عبر النافذة وتغيير الحجم على مسار Wayland الأصلي.

على Hyprland (بما في ذلك Omarchy) يُجعل الـ HUD عائمًا ومثبّتًا عبر IPC الخاص بالـ compositor بعد ظهوره — وإلا فإن Hyprland يرصفه مثل أي نافذة أخرى، ويتجاهل always-on-top، ولا يفعل السحب عبر الـ compositor شيئًا. لا حاجة إلى أي قاعدة نوافذ إضافية.

WSLg (استخدام GPU الخاص بـ Windows من WSL2)

تحت WSLg المحلي، يبدأ Hermes باستخدام --ozone-platform=wayland لتجنب إزاحة النافذة المكبّرة واختلاف مواضع اختبار نقر الفأرة في XWayland (microsoft/wslg#1015). يجب اختيار المنصة عند بدء العملية، قبل تحميل Electron لـ JavaScript التطبيق. يظل --ozone-platform=x11 و desktop.ozone_platform_hint: x11 الصريحان متاحين. يرسم التطبيق أدوات التصغير والتكبير والإغلاق الخاصة به على WSLg.

عندما يعمل hermes gui داخل WSL2 مع وجود /dev/dxg وتثبيت d3d12_dri.so الخاص بـ Mesa، يضبط المُشغِّل GALLIUM_DRIVER=d3d12 لـ Electron كي يستخدم العرض GPU الخاص بـ Windows بدلًا من المُرسِّم البرمجي llvmpipe؛ ويُترك دون تغيير أي من GALLIUM_DRIVER أو MESA_LOADER_DRIVER_OVERRIDE أو LIBGL_ALWAYS_SOFTWARE أو LIBGL_DRIVERS_PATH إذا ضُبط صراحةً في بيئتك (فمثلًا GALLIUM_DRIVER=llvmpipe hermes gui يبقي العرض البرمجي).

الإعدادات & التهيئة الأولى

أدِر المزوّدين والنماذج والأدوات وبيانات الاعتماد من واجهة مستخدم حقيقية بدلًا من تحرير YAML. تُوصلك التهيئة الأولى إلى رسالتك الأولى في ثوانٍ. وتغطي أجزاء الإعدادات المزوّدين/المفاتيح، واختيار النموذج، وإعداد الـ toolsets، وخوادم MCP، والـ gateway، وإدارة الجلسات.

  • جزء إعدادات المزوّدين — موضع مخصص لإدارة مزوّدي inference، مع واجهة Accounts / API-keys لتسجيل الدخول وتخزين بيانات الاعتماد لكل مزوّد. تتشارك Accounts و API keys و Custom Endpoints اختيار Settings Applies to: تستهدف قراءات بيانات الاعتماد وتحريرها وإزالة حسابات OAuth وحفظ/اختبار endpoints المخصّصة وتسجيل الدخول الذي يبدأ هنا الـ profile المحدد، لا profile المحادثة النشطة. يحتفظ مسار الدخول بهذا الهدف حتى حفظ بيانات الاعتماد واختيار النموذج. يؤدي تغيير Applies to يتجاهل مسودات بيانات الاعتماد غير المحفوظة. إغلاق نافذة تسجيل الدخول يلغي الاستطلاع (polling) ويتجاهل النتائج المتأخرة؛ لكن عملية كتابة بيانات اعتماد أُرسلت بالفعل قد تكتمل في الـ profile الأصلي. أما بيانات اعتماد CLI المُدارة خارجيًا فتستخدم الـ CLI الخاص بها ولا يشملها منتقي الـ profile هذا. ويثبّت عرض Local Models فيه بيئة تشغيل llama.cpp على الجهاز ويديرها — راجع النماذج المحلية (Local Models).
  • كل مزوّد وكل نموذج في القوائم — تعرض الواجهة الرسومية القائمة الكاملة للمزوّدين وكل نموذج يعرفه hermes model، فتختار من الكتالوج نفسه الذي يراه CLI بدلًا من مجموعة فرعية منتقاة.
  • Endpoints مخصّصة مع وضع API — Settings → Providers → Custom Endpoints تحتوي على منتقي API Mode (Auto-detect و Chat Completions و Responses API و Anthropic Messages) — الاختيار نفسه الذي يتيحه hermes model لمزوّد مخصّص. يُحفظ بوصفه providers.<id>.api_mode في config.yaml، فلا يُستدعى مضيف يدعم Responses وحدها أو متوافق مع Anthropic على /chat/completions بعد الآن. يفحص Test النقل الذي ستستخدمه فعليًا، لا /v1/models وحده: يرسل طلبًا من token واحد إلى مسار الوضع المثبّت (أو الوضع الذي يحدده Auto-detect)، ويفشل مع تسمية النقل إذا لم يقدّمه المضيف. ويحافظ Test أيضًا على بيانات الأسماء البديلة التي يعلنها gateway في /v1/models (canonical_model و reasoning_effort): اختيار اسم بديل مثل gpt-5.6-sol-high يحفظ النموذج المرجعي ويثبّت جهده ضمن agent.reasoning_overrides.
  • xAI Grok OAuth — Grok مزوّد OAuth كامل الدعم في المشغّل؛ سجّل الدخول عبر مسار المتصفح شأنه شأن مزوّدي OAuth الآخرين.
  • تثبيت backends الأدوات من الواجهة الرسومية — نفّذ خطوات تثبيت backend الأداة التالية للإعداد من التطبيق مباشرةً بدلًا من الانتقال إلى الطرفية. في منتقي terminal backend، يطلب اختيار backend موسوم بـ Needs setup تأكيدًا أولًا؛ ويُبقي الرفض الـ backend الحالي محددًا.
  • منتقي خط الطرفية — اختر خطًا مثبّتًا في Settings → Appearance. تعرض Nerd Fonts مثل MesloLGS NF فواصل Powerlevel10k وأيقوناته في الطرفيات التفاعلية وطرفيات الوكيل معًا؛ ويُحفظ الإعداد لكل profile.
  • Reasoning Blocks — Settings → Chat → Reasoning Blocks (display.show_reasoning في config.yaml) يُظهر أو يخفي تفكير النموذج في نص المحادثة (عند التعطيل تظهر الإجابات فقط). تتحدّث المحادثات المفتوحة بمجرد حفظ الإعداد. تؤدي كتابة /reasoning hide أو /reasoning show في مربع الكتابة إلى تبديل الإعداد نفسه، ويتبعه نص المحادثة المفتوح فورًا.
  • Reopen Last Chat on Launch — افتراضيًا، يستأنف التطبيق من حيث توقفت عند التشغيل من البداية. عطّل ذلك من Settings → Appearance (أو اضبط display.resume_last_session: false في config.yaml) لتبدأ دائمًا بمحادثة جديدة. ولا تُتجاوز الروابط العميقة (deep links) والوجهات الصريحة أبدًا في كلتا الحالتين.
  • تحذير النموذج المساعد — إذا بدّلت النموذج الرئيسي إلى مزوّد جديد بينما لا تزال المهام المساعدة (توليد العناوين، والتلخيص، وما شابهها) مثبّتة على مزوّد آخر، يحذّرك التطبيق كي لا توزّع العمل بين مزوّدين اثنين دون أن تدري.
  • جهد الاستدلال لكل مهمة — يحتوي كل صف ضمن Settings → Model → Auxiliary models على منتقي استدلال بجوار اختيار المزوّد/النموذج: مستوى، أو Off، أو inherit · main model effort (القيمة الافتراضية التي تزيل تجاوز المهمة). يُحفظ بوصفه auxiliary.<task>.reasoning_effort في config.yaml، وهو المفتاح نفسه الذي يكتبه hermes model، ويظهر في ملخّص الصف عند ضبطه. استخدمه لتشغيل الأدوات المساعدة المتكررة مثل الضغط أو توليد العناوين باستدلال منخفض أو معدوم، بينما يبقى الوكيل الرئيسي عند مستوى مرتفع.
  • سمات VS Code Marketplace — إلى جانب السمات المدمجة الجاهزة، تتضمن إعدادات المظهر بحثًا مباشرًا في VS Code Marketplace: اختر أي سمة ألوان، وسينزّلها التطبيق ويحوّلها ويثبّتها كسمة Desktop. يتوفر المستورد نفسه من لوحة الأوامر (Install theme)، ويمكن إزالة السمات المستوردة مجددًا من إعدادات المظهر.
  • إبقاء الحاسوب مستيقظًا — Settings → Advanced → Keep computer awake يمنع سكون الجهاز لاستمرار تشغيلات الوكيل الطويلة أو الليلية (يمكن أن تخفت الشاشة). يحافظ While working على يقظة الجهاز أثناء وجود دور جارٍ فقط، ويتركه ينام طبيعيًا عند انتهاء التشغيل أو فشله؛ ويحافظ Always على يقظته كلما كان Hermes مفتوحًا. هذا إعداد خاص بكل حاسوب.

أُعيد تصميم التهيئة الأولى بالاعتماد على نظام تصميم موحّد للنوافذ المنبثقة، ويمكنك اختيار Choose provider later لتخطي إعداد المزوّد والدخول إلى التطبيق أولًا.

ما تعرفه محادثة الإعداد عن حاسوبك

تحمل الرسالة الأولى لمحادثة الإعداد كتلة قصيرة من الحقائق، لكي تسمّي حاسوبك وتعرض مهام أولى تلائمه: نظام التشغيل وإصداره و CPU و RAM وفئة GPU وما إذا كان Spark ولغتك. تُرسل الكتلة إلى مزوّد inference الذي تستخدمه محادثة الإعداد وتبقى في سجلها. تعرض بطاقة الاسم اسمك الكامل من سجل الحساب، لكنه يبقى على هذا الحاسوب ما لم تختره. ولاختيار الإضافات والمهام الأولى المعروضة، يفحص الإعداد أيضًا وجود التطبيقات التي تتحكم فيها تلك الإضافات، مثل Blender و NVIDIA App و NVIDIA Broadcast على حاسوب Windows ذي GPU من NVIDIA. يبحث في مجلدات التثبيت المعتادة وفي PATH وفي قائمة Windows للبرامج المثبّتة، ويقرأ إصدار كل نسخة يعثر عليها، ويقرأ لبعض التطبيقات ملف تشغيلها الخاص لمعرفة ما إذا كانت تعمل. لا يُقرأ أي شيء آخر على الحاسوب للإعداد. يحتفظ الإعداد بملف صغير في مجلد setup-cards الخاص بـ profile الإعداد، يحوي سطر الجهاز واختياراتك، وينسخه إلى محادثة مهمتك الأولى. تُحفظ المحادثتان على هذا الحاسوب كأي محادثة أخرى. مع backend بعيد، تصف الحقائق الجهاز البعيد، لا الحاسوب الذي أمامك.

إعدادات كل profile: نطاق "Applies to"

عندما يكون لديك اثنان أو أكثر من الـ profiles، تعرض صفحات الإعدادات المستندة إلى ملف الإعدادات — Model و Workspace و Safety و Memory & Context و Voice و Chat و Advanced و Tools & Keys — إضافةً إلى Providers → Custom Endpoints والنافذة المنبثقة Messaging صف شرائح مشتركًا بعنوان Applies to في الأعلى. يحدد هذا الصف الـ profile الذي تستهدفه تعديلاتك:

  • الاختيار الافتراضي يتبع الـ profile النشط، ويتصرف تمامًا كما في السابق — فتحرّر الـ profile الذي تستخدمه.
  • اختر profile آخر لعرض إعداداته هو وتحريرها دون تبديل التطبيق بأكمله؛ ويبقى الاختيار قائمًا أثناء تنقلك بين صفحات الإعدادات.
  • تبديل الـ profile النشط في التطبيق يعيد ضبط المنتقي، كي لا تستمر التعديلات في الوصول بصمت إلى profile اختير سابقًا.
  • عندما يكون لديك أقل من profile اثنين، يُخفى صف الشرائح بالكامل.

(تتعامل صفحة Gateways مع الـ profiles بشكل مختلف — عبر القسم الفرعي Per-profile overrides — ولكل من عرضي Capabilities و Scheduled Jobs منتقي نطاق خاص به.)

أجزاء الإدارة

يعرض التطبيق أيضًا واجهة الإدارة الأوسع في Hermes، فلا تحتاج إلى اللجوء إلى الطرفية:

  • Skills — تصفّح المهارات وثبّتها وأدِرها. يعرض تبويب Skills مهاراتك المثبّتة مع مفاتيح التفعيل/التعطيل، وتحتها الكتالوج الكامل للمهارات الاختيارية المدمجة التي تأتي مع Hermes — ولكل عنصر زر Install يحوّل الصف إلى قائمة المثبّتة عند اكتماله. تفتح أزرار Install in Hermes في Skills Hub العام روابط hermes://skill/install?identifier=... تثبّت عبر pipeline نفسه بعد تأكيدك (راجع روابط المهارات).
  • رسم الذاكرة البياني (Star Map) — اكتب /journey (أو الأسماء البديلة /learning و/memory-graph) في المحادثة لفتح كوكبة تفاعلية من المهارات والذكريات المكتسبة عبر الزمن، مع شريط تمرير لإعادة التشغيل. يمكن تحرير العُقد أو حذفها مباشرةً من اللوحة (تُؤرشف المهارات، وتُزال الذكريات). راجع رحلة التعلّم (Learning Journey).
  • Cron — اعرض المهام المجدولة. مع تفعيل All profiles، تجمع القائمة مهام كل profiles؛ ويذهب سجل تشغيل المهمة وإجراءاتها (الإيقاف المؤقت والاستئناف والتحرير والحذف) دائمًا إلى الـ profile المالك، أيًا كان الـ profile النشط.
  • Profiles — بدّل بين الـ profiles الخاصة بـ Hermes (إعدادات/مهارات/جلسات معزولة).
  • Messaging — أعِدّ قنوات الـ gateway. تتضمن Telegram بطاقة Quick setup: انقر Create with QR، وامسح الرمز (أو افتح الرابط) في Telegram، وسيتولى Hermes إنشاء البوت، واكتشاف معرّف المستخدم الخاص بك لإضافته إلى قائمة السماح، وحفظ بيانات الاعتماد، وإعادة تشغيل الـ gateway نيابةً عنك. وأي عملية حفظ لبيانات الاعتماد أو مسحها أو تبديل تفعيلها تُبقي شريط Restart now على الصفحة إلى أن يُعاد تشغيل الـ gateway فعليًا؛ وإذا فشلت إعادة التشغيل، يبقى الشريط ظاهرًا كي تعيد المحاولة أو تعيد التشغيل يدويًا.
  • Agents وCommand Center — واجهات تنسيق (orchestration) للعمل متعدد الوكلاء.

Bot Mode (مدمج)

Bot Mode يأتي مع التطبيق ومفعّل افتراضيًا: قائمة بمبدأ "محادثة واحدة لكل وكيل"، يظهر فيها كل profile من Hermes كبوت له صورته الرمزية الخاصة (وجه هندسي، أو صورة مرفوعة، أو صورة شخصية مولّدة بالذكاء الاصطناعي، أو حيوان أليف بأسلوب pixel)، ومحادثة Bot Chat الأساسية الخاصة به، وRoutines الخاصة به (مهام متكررة تعتمد على cron في Hermes). توجد القائمة في الشريط الجانبي الأيسر كتبويب بجوار محادثاتك — شريط تبويبات Sessions | Bots — بدلًا من جزء ثانٍ مكدّس أسفل قائمة الجلسات. أما التثبيتات التي اعتمدت التخطيط المكدّس القديم فتُنقل إلى شريط التبويبات تلقائيًا، مرة واحدة؛ وإذا كنت قد رتّبت الأجزاء يدويًا، فسيُترك تخطيطك كما هو. يُثبَّت جزء Cronjobs (Routines) بجوار المحادثة فقط أثناء تفعيل تبويب Bots، ويختفي عند العودة إلى Sessions (أما إصدارات سطح المكتب الأقدم فتُبقيه ظاهرًا دائمًا).

أنشئ وكلاء جددًا من القائمة — Name / Title / Description مع قسم Advanced قابل للكشف يتضمن الواجهة الكاملة للقدرات (النموذج، و SOUL، والمهارات، والـ toolsets، وخوادم MCP) — ونظّمهم في أقسام، وافتح محادثات جماعية يتداول فيها عدة بوتات. تظهر المحادثات الجماعية كصفوف مستقلة بأسلوب Discord في القائمة — صور رمزية مكدّسة للأعضاء، وعدد الأعضاء، ومعاينة لآخر سطر في الغرفة، وشارة "needs you" — متداخلة مع صفوف البوتات وفق ترتيب التثبيت ثم الأحدث نفسه. والنقر على صف مجموعة يفتح الغرفة كتبويب يشغل نافذة المحادثة الرئيسية (أما إصدارات سطح المكتب الأقدم فتلجأ إلى فتحها داخل اللوحة الجانبية للبوتات).

تتراسل البوتات فيما بينها: اكتب @researcher have a look at this في أي محادثة وسيسلّم البوت النشط الرسالة ثم يعود إليك بالنتيجة، كما تصل البوتات إلى محادثات Bot Chat الخاصة ببعضها مباشرةً (hermes -p <bot> chat). يعلّم الـ backend جلسة Bot Chat الأساسية لكل بوت بروتوكول المراسلة تلقائيًا (الإعداد agent.bot_mode_protocol، مفعّل افتراضيًا) — بما في ذلك عندما يفتحها بوت زميل دون واجهة من CLI — بحيث تعمل الردود والتسليمات بين البوتات دون المساس بملف SOUL.md الخاص بك، وتبقى جلساتك العادية دون تغيير.

جلسات Bot Mode — أي محادثة Bot Chat الأساسية لكل بوت وكل جلسة عضو في محادثة جماعية — مخفية دائمًا من الشريط الجانبي العام Sessions. فهي توجد في جزء Bots (صفوف القائمة، وعروض الغرف، ومستعرض جلسات كل بوت) بدلًا من أن تتداخل مع محادثاتك الخاصة.

يمكن إخفاء البوتات التي لا تستخدمها: انقر بالزر الأيمن على صف البوت → Hide Bot. تغادر البوتات المخفية القائمة لكنها تواصل العمل — إذ تظل الإشارات بـ @ تُحلّ وتبقى عضوية المحادثات الجماعية دون تغيير. يظهر مفتاح على شكل عين في ترويسة Bots كلما كان هناك بوت مخفي واحد على الأقل؛ انقره لإظهار البوتات المخفية باهتة في مكانها (والنقر بالزر الأيمن → Unhide Bot يعيد أحدها)، وتعرض العين نقطة عندما يكون لدى بوت مخفي نشاط غير مقروء. تُخزَّن حالة الإخفاء في الـ profile الخاص بالبوت، لذا تنتقل معه عبر الأجهزة.

لا تريده؟ عطّل مفتاح Desktop الخاص به من Capabilities → Plugins → Bots — فتُلغى تسجيلات القائمة، وجزء الـ routines، والـ middleware الخاص بمربع الكتابة مباشرةً، دون الحاجة إلى إعادة التشغيل.

الدليل الكامل — إنشاء الوكلاء (بما في ذلك منتقي Create on متعدد الأجهزة)، والقائمة عبر الاتصالات المختلفة، والإشارات بين البوتات، وكيف تقرر المحادثات الجماعية من يرد: Bot Mode: قائمة من الوكلاء.

لوحة المفاتيح & التنقل

  • لوحة الأوامر — اضغط Cmd+K أو Cmd+P (Ctrl+K / Ctrl+P على Windows/Linux) للانتقال إلى الإجراءات والتنقل في التطبيق من لوحة المفاتيح: افتح أي صفحة أو قسم إعدادات، أو انتقل إلى جلسة بعنوانها أو معرّفها، أو بدّل النموذج/السمة/وضع الألوان، أو افتح طرفية، أو أعد تشغيل الـ gateway، أو حدّث Hermes، وغير ذلك.
  • اختصارات قابلة لإعادة التعيين — Settings → Keyboard Shortcuts (أو Cmd/Ctrl+/) يفتح لوحة الاختصارات حيث يمكنك إعادة تعيين كل الاختصارات تقريبًا — التبديل بين الـ profiles، والتنقل بين الجلسات، وتبديل العروض، وأي اختصارات تضيفها إضافات سطح المكتب. وتُعلَّم التعيينات المكررة كتعارضات. بعض الاختصارات الافتراضية التي تستحق المعرفة: Cmd/Ctrl+N جلسة جديدة، وCmd/Ctrl+. لـ Command Center، وCmd/Ctrl+, لـ Settings، وCmd/Ctrl+Shift+F للبحث في الجلسات، وCmd/Ctrl+1–9 للتبديل إلى التبويب رقم N في الجزء تحت المؤشر (أو الجزء المُركّز)، ولتبديل profiles عندما لا يملك أي جزء شريط تبويبات، و Shift+X للتبديل بين الوضع الفاتح/الداكن.
  • اختصارات تكبير مخصصة — كبّر الواجهة أو صغّرها بخطوات نصفية لتحكم أدق في حجم النص.
  • مبدّل لغة الواجهة — غيّر لغة واجهة التطبيق من داخله: الإنجليزية، والصينية المبسطة (zh-Hans)، والصينية التقليدية (zh-Hant)، واليابانية، والعربية (RTL)، والروسية.

الجلسات & profiles

  • إعادة تصميم قائمة الجلسات — قائمة جلسات مُعاد تصميمها مع الأرشفة وأدوات تنظيم عامة للجلسات، لتبقى القائمة سهلة الإدارة مع نموها.
  • البحث في الجلسات بالمعرّف — اعثر على جلسة محددة مباشرةً بمعرّفها.
  • جلسات متزامنة عبر عدة profiles — شغّل جلسات عبر عدة profiles في الوقت نفسه، وأشر إلى جلسة في profile آخر باستخدام روابط @session العابرة للـ profiles.
  • تصدير profile واستيراده — شارك إعدادًا كاملًا كملف واحد. ⌘K → Export profile… (أو انقر بالزر الأيمن على مربع profile في الشريط) يكتب ملف .tar.gz يضم المهارات، والذاكرة، والشخصية، ومهام cron، والإضافات، والإعدادات؛ مع إزالة مفاتيح API. والتصدير من تطبيق سطح المكتب يضمّن أيضًا المظهر والواجهة — الـ skin، والوضع الفاتح/الداكن، والسمات المخصصة، ولون الـ profile في الشريط، وتخطيط النوافذ — بحيث يصل الـ profile المستورد بالشكل الذي كان عليه لدى المُرسِل. استورد عبر ⌘K → Import profile… أو الزر المجاور لزر + في الشريط؛ فيُطبَّق الـ overlay وتنتقل إلى الـ profile الجديد. ويعمل الأرشيف نفسه مع /export / /import في المحادثة، ومع hermes profile export / import من الـ shell. راجع تصدير ملف profile واستيراده.
