مزوّدو الذاكرة (Memory Providers)

يتضمن Hermes Agent عدد 2 من إضافات مزوّدي الذاكرة الخارجية (RetainDB و ByteRover)، تمنحان الوكيل معرفة دائمة عبر الجلسات تتجاوز MEMORY.md و USER.md المدمجَين، ويتوفر المزيد (مثل Honcho و Hindsight و Supermemory و Holographic) من كتالوج الإضافات. لا يمكن تنشيط إلا مزوّد خارجي واحد في الوقت نفسه — وتبقى الذاكرة المدمجة نشطة دائمًا إلى جانبه.

البدء السريع

يمكنك أيضًا اختيار مزوّد الذاكرة النشط عبر hermes plugins → Provider Plugins → Memory Provider.

أو اضبطه يدويًا في ~/.hermes/config.yaml:

كيف يعمل

عندما يكون أحد مزوّدي الذاكرة نشطًا، يقوم Hermes تلقائيًا بما يلي:

  1. حقن سياق المزوّد في system prompt (ما يعرفه المزوّد)
  2. الجلب المسبق للذكريات ذات الصلة قبل كل دور (في الخلفية، دون حجب)
  3. مزامنة أدوار المحادثة مع المزوّد بعد كل رد
  4. استخلاص الذكريات عند انتهاء الجلسة (للمزوّدين الذين يدعمون ذلك)
  5. عكس عمليات الكتابة إلى الذاكرة المدمجة على المزوّد الخارجي
  6. إضافة أدوات خاصة بالمزوّد كي يتمكن الوكيل من البحث في الذكريات وتخزينها وإدارتها

تستمر الذاكرة المدمجة (MEMORY.md / USER.md) في العمل تمامًا كما كانت. فالمزوّد الخارجي إضافة إليها لا بديل عنها.

كل ما يسلّمه Hermes إلى المزوّد (الأدوار، ونص المحادثة بما فيه مخرجات الأدوات، واستعلامات الاسترجاع، ونصوص المحادثات عند انتهاء الجلسة وقبل الضغط، وعمليات كتابة الذاكرة المنسوخة، ونتائج التفويض، ووسائط أدوات المزوّد نفسه) يمر أولًا بآلية تنقية الأسرار نفسها المستخدمة لتسليم المحادثات ومهام cron، لذلك يُحجب المفتاح المنسوخ إلى مخرجات الأداة قبل أن يتمكن المزوّد من تخزينه. وكما في تنقية التسليم، تُطبّق هذه الآلية حتى مع security.redact_secrets: false. ولا تُكتشف بيانات الاعتماد التي لا تملك صيغة قابلة للتعرّف (كلمة مرور عشوائية، أو token مبهم خارج سياق key=value أو Bearer )؛ ويحتفظ نص المحادثة المحلي بالنص الأصلي.
