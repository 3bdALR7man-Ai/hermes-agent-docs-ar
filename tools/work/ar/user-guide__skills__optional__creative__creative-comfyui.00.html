معلومة

ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

ComfyUI

ولِّد الصور والفيديو والصوت والمحتوى ثلاثي الأبعاد عبر ComfyUI باستخدام comfy-cli الرسمية للإعداد ودورة الحياة، وواجهة REST/WebSocket المباشرة لتنفيذ الـ workflow.

محتويات هذه المهارة

مستندات مرجعية (references/):

  • official-cli.md — كل أمر comfy ...، مع الخيارات (flags)
  • rest-api.md — endpoints الخاصة بـ REST + WebSocket (محلي + سحابي)، ومخططات الحمولة (payload schemas)
  • workflow-format.md — صيغة JSON بتنسيق API، وأنواع العُقد الشائعة، وتخطيط المعاملات (param mapping)
  • template-integrity.md — تحويل comfyui-workflow-templates من صيغة المحرِّر إلى صيغة API: تجاوز Reroute، مفاتيح المُدخلات الديناميكية المنقّطة (values.a، resize_type.width)، خصوصيات Cloud (إعادة توجيه 302، مهمة واحدة متزامنة في الفئة المجانية، سقف VRAM عند 1080p)، ودمج ffmpeg متوافق مع Discord. بقلم @purzbeats. حمّل هذا الملف كلما بدأت من قالب رسمي.

متى تُستخدم

  • يطلب المستخدم توليد صور باستخدام Stable Diffusion أو SDXL أو Flux أو SD3، إلخ
  • يريد المستخدم تشغيل ملف workflow معيّن في ComfyUI
  • يريد المستخدم تسلسل خطوات توليدية (txt2img ← upscale ← إصلاح الوجه)
  • يحتاج المستخدم إلى ControlNet، أو inpainting، أو img2img، أو خطوط أنابيب (pipelines) متقدّمة أخرى
  • يطلب المستخدم إدارة قائمة انتظار ComfyUI، أو فحص النماذج، أو تثبيت عُقد مخصّصة
  • يريد المستخدم توليد فيديو/صوت/محتوى ثلاثي الأبعاد عبر AnimateDiff أو Hunyuan أو Wan أو AudioCraft، إلخ

البنية المعمارية: طبقتان

لماذا طبقتان؟ الواجهة الرسمية (CLI) ممتازة للتثبيت وإدارة الخادم لكنها توفر دعمًا محدودًا لتنفيذ الـ workflow. تسدّ واجهة REST/WS تلك الفجوة — تتولى السكربتات حقن المعاملات، ومراقبة التنفيذ، وتنزيل النواتج التي لا تقوم بها CLI.

الخطوة 1: احصل على JSON خاص بـ workflow بصيغة API

يجب أن تكون الـ workflows بصيغة API (لكل عقدة class_type). تأتي من:

  • واجهة ComfyUI على الويب ← Workflow → Export (API) (الواجهة الأحدث) أو زر "Save (API Format)" القديم (الواجهة الأقدم)
  • دليل workflows/ الخاص بهذه المهارة (أمثلة جاهزة للتشغيل)
  • تنزيلات من المجتمع (civitai، Reddit، Discord) — عادةً بصيغة المحرِّر، يجب تحميلها في ComfyUI ثم إعادة تصديرها

صيغة المحرِّر (مصفوفتا nodes وlinks على المستوى الأعلى) غير قابلة للتنفيذ مباشرة. تكتشف السكربتات ذلك وتخبرك بإعادة التصدير.

الإعداد والتهيئة

عندما يطلب المستخدم إعداد ComfyUI، أول ما يجب فعله هو سؤاله عمّا إذا كان يريد Comfy Cloud (مستضاف، بلا تثبيت، مفتاح API) أو محلي (تثبيت ComfyUI على جهازه). لا تبدأ بتنفيذ أوامر التثبيت أو فحوصات العتاد قبل أن يجيب.

التوثيق الرسمي: https://docs.comfy.org/installation توثيق CLI: https://docs.comfy.org/comfy-cli/getting-started توثيق Cloud: https://docs.comfy.org/get_started/cloud واجهة Cloud API: https://docs.comfy.org/development/cloud/overview

الخطوة 0: اسأل بين محلي وCloud (دائمًا أولًا)

نص مقترح:

"هل تريد تشغيل ComfyUI محليًا على جهازك، أم استخدام Comfy Cloud؟

  • Comfy Cloud — مستضاف على وحدات معالجة رسومية RTX 6000 Pro، وجميع النماذج الشائعة مثبّتة مسبقًا، بلا إعداد. يتطلب مفتاح API (اشتراك مدفوع مطلوب فعليًا لتشغيل الـ workflows؛ الفئة المجانية للقراءة فقط). الأفضل إذا لم يكن لديك GPU قوي.
  • محلي — مجاني، لكن يجب أن يستوفي جهازك متطلبات العتاد:
    • GPU من NVIDIA بذاكرة VRAM ≥6 غيغابايت (≥8 غيغابايت لـ SDXL، ≥12 غيغابايت لـ Flux/الفيديو)، أو
    • GPU من AMD بدعم ROCm (لينكس)، أو
    • جهاز Mac بمعالج Apple Silicon (M1 فما فوق) بذاكرة موحّدة ≥16 غيغابايت (يُنصح بـ ≥32 غيغابايت).
    • أجهزة Mac بمعالج Intel والأجهزة بلا GPU لن تعمل — استخدم Cloud بدلًا من ذلك.

أيّهما تريد؟"

التوجيه:

  • Cloud ← انتقل إلى المسار A.
  • محلي ← نفّذ فحص العتاد أولًا، ثم اختر مسارًا من المسارات B–E حسب النتيجة.
  • غير متأكد ← نفّذ فحص العتاد ودَع النتيجة تقرّر.

الخطوة 1: تحقق من العتاد (فقط إذا اختار المستخدم محلي)

النتيجةالمعنىالإجراء

marginalSD1.5 يعمل؛ SDXL محدود؛ Flux/الفيديو غير مرجّحمحلي مناسب لـ workflows الخفيفة، وإلا فـ المسار A (Cloud)

يُظهر السكربت أيضًا wsl: true (WSL2 مع تمرير NVIDIA) و rosetta: true (بايثون x86_64 على Apple Silicon — يجب إعادة تثبيته كـ ARM64).

إذا كانت النتيجة cloud لكن المستخدم يريد التشغيل المحلي، لا تتابع بصمت. اعرض مصفوفة notes حرفيًا واسأله عمّا إذا كان يريد (أ) الانتقال إلى Cloud أو (ب) فرض تثبيت محلي (سيسبب نفاد ذاكرة (OOM) أو بطئًا غير قابل للاستخدام مع النماذج الحديثة).

خصوصيات Cloud

  • الرابط الأساسي: https://cloud.comfy.org
  • المصادقة: ترويسة X-API-Key (أو ?token=KEY لـ WebSocket)
  • مفتاح API: اضبط $COMFY_CLOUD_API_KEY مرة واحدة وستلتقطه السكربتات تلقائيًا
  • تنزيل النواتج: يعيد /api/view إعادة توجيه 302 إلى رابط موقَّع؛ تتبعه السكربتات وتحذف X-API-Key قبل الجلب من نظام التخزين الخلفي (لا تُسرِّب مفتاح API إلى S3/CloudFront).
  • اختلافات endpoints عن ComfyUI المحلي:
    • /api/object_info، /api/queue، /api/userdata — 403 على الفئة المجانية؛ للمدفوعين فقط.
    • يُعاد تسمية /history إلى /history_v2 على Cloud (توجّه السكربتات تلقائيًا).
    • يُعاد تسمية /models/<folder> إلى /experiment/models/<folder> على Cloud (توجّه السكربتات تلقائيًا).
    • يُتجاهل حاليًا clientId في WebSocket — تستقبل كل الاتصالات الخاصة بمستخدم نفس البث. رشِّح حسب prompt_id من جانب العميل.
    • يُقبَل subfolder عند الرفع لكن يُتجاهل — لدى Cloud مساحة أسماء مسطّحة.
  • المهام المتزامنة: Free/Standard: 1، Creator: 3، Pro: 5. تُصفّ الزيادات (Extras) تلقائيًا. استخدم run_batch.py --parallel N لتشبع حدود فئتك.
