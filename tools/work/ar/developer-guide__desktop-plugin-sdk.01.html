طقم واجهة المستخدم (UI Kit) والسمات (Theming)

استورد مكوّنات التطبيق الحقيقية مباشرة حتى تكون واجهتك أصيلة (native) افتراضيًا:

Button، وInput، وTextarea، وSelect*، وSwitch، وCheckbox، وSegmentedControl، وTabs*، وDialog*، وConfirmDialog، وDropdownMenu*، وContextMenu*، وPopover*، وTip/Tooltip*، وBadge، وKbd/KbdGroup، وSearchField، وScrollArea، وSeparator، وSkeleton، وGlyphSpinner، وLoader، وEmptyState، وErrorState، وCopyButton، وStatusDot، وLogView، وCodicon، وDecodeText.

بالإضافة إلى مساعدات: cn (دمج classes)، وicons.* (مجموعة lucide الخاصة بالتطبيق)، وhaptic، وprofileColor / profileColorSoft (ألوان هوية حتمية)، ومنسّقات الوقت relativeTime / fmtDateTime / fmtDayTime / coarseElapsed، وuseI18n (نصوص محلَّية — تبقى إضافتك قابلة للترجمة)، و evaluateRuntimeReadiness.

صمّم باستخدام متغيرات السمة (theme variables)، ولا تستخدم ألوانًا ثابتة أبدًا. تجلس اللوحات (panes) بالفعل على خلفية محرر التطبيق — اترك الخلفية كما هي واستخدم المتغيرات لكل شيء آخر: var(--ui-text-secondary)، وvar(--ui-text-tertiary)، وvar(--ui-text-quaternary)، وvar(--ui-stroke-secondary)، وvar(--ui-accent). بالنسبة للرسم على canvas، حلّها مرة واحدة باستخدام getComputedStyle(canvas).getPropertyValue('--ui-accent'). هذا ما يجعل الإضافة تُعيد تلوين نفسها تلقائيًا مع كل سمة.

backend لإضافتك

إذا احتاجت إضافتك عملًا من جهة الخادم، اشحن ملف Python plugin_api.py واستدعِه عبر ctx.rest / ctx.socket — نطاق مقيّد بإضافتك بحكم البناء.

حزمة واحدة، وSDK لكلا الجانبين

الميزة التي تحتاج إلى واجهة desktop وكود من جهة الوكيل (إضافة Python، مسارات الـ backend الخاصة بها، مهارات) لا تحتاج إلى الشحن كتثبيتين مترابطين. ضع ملف desktop/plugin.js داخل حزمة الوكيل. عندما تحطّ الحزمة في أي جذر plugins/ محلي (المنزل الافتراضي أو profile)، تنسخ عملية Electron الرئيسية هذا النصف إلى $HERMES_HOME/desktop-plugins/<id>/ بجانب علامة .hermes-package.json، ويحمّله عارض الواجهة (renderer) عبر خط أنابيب مطابق تمامًا لباب القرص المستقل (hot reload متضمَّن):

نصف desktop/plugin.js هو إضافة قرص عادية — نفس العقد، ونفس الاستيرادات، ونفس ctx.rest('/…') الذي يصل إلى plugin_api.py الموجود بجانبه. تثبيت أو مشاركة أو إزالة الميزة هو مجلد واحد: تُحدَّث نسخة جذر التطبيق عندما يتغير ملف plugin.js المصدر (hermes plugins update، أو Rescan) وتُزال عندما يختفي مجلد الحزمة. النسخ هو ما يجعل النصف الخاص بـ desktop على مستوى التطبيق: فهو موجود مرة واحدة، مهما كان عدد الـ profiles التي تحمل الحزمة، ولا يظهر أو يختفي أبدًا عندما يبدّل المستخدم محدد profile الخاص بالإمكانيات (Capabilities). لا يفحص عارض الواجهة plugins/ بنفسه أبدًا. تسجّل العلامة اسم الحزمة ومصدرها (ملحق كتالوج أو remote git)، وهذا ما يستخدمه زر Install here في صفحة الإضافات لتثبيت نصف الوكيل في profile آخر.

ما زال هناك مفتاحا تفعيل ينطبقان، بشكل مقصود، وكلاهما افتراضيًا معطَّل: نصف desktop يُشحَن كخيار اختياري (opt-in) — يُدرَج ضمن الجرد في Capabilities → Plugins لكنه يبقى معطَّلًا حتى يبدّله المستخدم — مطابقًا لتقييد plugins.enabled الخاص بنصف Python في config.yaml (الحد الأمني أدناه). وضع حزمة في ~/.hermes/plugins خامل على كل الأسطح حتى يقول المستخدم غير ذلك. يتدهور نصف desktop بأمان عندما يكون نصف الـ backend معطَّلًا — يعيد ctx.rest أخطاء، لا انهيارات.

ملاحظة

النسخة محلية للجهاز الذي يعمل عليه تطبيق desktop. مقابل backend بعيد، لا يمكن الوصول إلى ~/.hermes/plugins الخاص بالجهاز البعيد كنظام ملفات — فقط الحزم المثبَّتة محليًا تسهم بنصف desktop بهذه الطريقة. بالنسبة لـ backend بعيد، يستنسخ حوار التثبيت نصف desktop بشكل منفصل إلى desktop-plugins/، تمامًا كما يحدث مع مستودع خاص بـ desktop فقط.

استدعاؤه من الإضافة

ctx.rest يراعي profile ويرفض اجتياز المسارات (..) بحيث لا يمكنك أبدًا التوجّه إلى واجهة API خاصة بإضافة أخرى أو مسار أساسي عبره. PluginRestOptions هو { method?, body?, upload?: { filename, contentType?, bytes }, timeoutMs? }.

ctx.socket يعيد الاتصال تلقائيًا بتراجع تدريجي (backoff) حتى يُستبعَد. ينحل إلى عملية تجاهل (no-op) على remotes بـ OAuth (تذاكر WS أحادية الاستخدام مُدارة من النواة) — عامِله كمُسرِّع فوق الاستطلاع (polling)، لا كبديل عنه. يحتاج كل مستهلك إلى بديل استطلاع على أي حال، لأن أي مقبس (socket) قد ينقطع.

بالنسبة لبيانات على نطاق gateway بأكمله (وليست في نطاقك الخاص)، استخدم host.request (JSON-RPC) و host.onEvent (تدفق أحداث gateway) بدلًا من ذلك.

الإعدادات، وحالة التفعيل، والتخزين

كل إضافة — سواء مفعَّلة أم لا — تُدرَج ضمن الجرد في Capabilities → Plugins، حيث يبدّلها المستخدم حيًا (بلا إعادة تشغيل للتطبيق)، أو يكشف مجلدها، أو يعيد الفحص. اختيار المستخدم يُتذكَّر:

  • لا اختيار بعد ← defaultEnabled الخاصة بالإضافة نفسها (الافتراضي true). اضبط defaultEnabled: false لشحن إضافة اختيارية تبقى معطَّلة حتى يشغّلها المستخدم.
  • اختيار صريح ← يُحفظ ويُحترَم عبر إعادات التشغيل. إضافة معطَّلة تبقى معطَّلة — لا تقاوم ذلك؛ فقد أطفأك المستخدم.

احفظ حالتك الخاصة باستخدام ctx.storage، بنطاق مُميّز باسم إضافتك (hermes.plugin.<id>.*) بحيث لا تستطيع الإضافات قراءة أو إتلاف بيانات بعضها البعض:

الإضافات المضمّنة (Bundled)

يمكن لإضافة أن تُشحَن ضمن الشجرة عند apps/desktop/src/plugins/<id>/plugin.tsx (تصدير افتراضي HermesPlugin). تُكتشَف بواسطة discoverBundledPlugins() عند الإقلاع — بلا استيراد، بلا تعديل سجل — وتشارك نفس عقد الجرد + التفعيل/التعطيل الحي كإضافة قرص. الفرقان الاثنان:

  1. تمر عبر بناء Vite الخاص بالتطبيق، لذا يمكنك كتابة JSX حقيقي واستيراد الـ SDK عبر اسمه المستعار @hermes/plugin-sdk.
  2. لا تزال مقيَّدة بأدوات lint إلى @hermes/plugin-sdk + react فقط — بلا داخليات @/… خاصة بالتطبيق.

لا تُشحَن إضافات desktop في الشجرة الأساسية اليوم؛ يبقى التطبيق المُشحَن غير مزدحم والعروض التوضيحية موجودة في مستودع hermes-example-plugins المصاحب.

النموذج الأمني

تُقيَّم الإضافة المحمَّلة كـ ESM في عالم عارض الواجهة (renderer realm) بـسلطة كاملة على التطبيق — النسخة الوحيدة (singleton) من React، وكامل الـ SDK (RPC الخاص بـ gateway عبر host.request، وctx.rest، والتخزين، وnavigate). العزل الذي يوفّره المحمّل هو عزل الأخطاء فقط: لا يمكن لإضافة أن تُسقط التطبيق (المساهمات محدودة الأخطاء، والمستمعون معزولون)، لكن يمكنها فعل أي شيء يستطيع التطبيق فعله.

هذا مقبول بالنسبة لمصادر محلية — إذ يمكن لملف على القرص أصلًا تشغيل كود على جهازك — وهذا سبب أن باب القرص لا يحمّل إلا ملفات محلية كتبتَها أنت (أو وكيلك). فحص integrity (sha256-…) الاختياري يثبت فقط أن البايتات تطابق تجزئة (hash)؛ ولا يعزل. باب مصدر بعيد مستقبلي سيحتاج حدًا حقيقيًا (iframe/worker + CSP + تقييد صلاحيات) قبل أن يصبح جاهزًا؛ لا تعامل خط الأنابيب هذا كحد ثقة.

مزالق

  • JSX لا يُحلَّل (parse) في إضافة قرص. يُحمَّل الملف دون تجميع — استخدم jsx() / jsxs() (أو React.createElement)، لا صياغة JSX. (الإضافات المضمّنة مبنية، لذا JSX مقبول فيها.)
  • ثلاثة معرّفات فقط قابلة للحل (resolve): @hermes/plugin-sdk، وreact، وreact/jsx-runtime. أي استيراد آخر يُظهر خطأ تحميل فوري.
  • لا تستخدم ألوانًا ثابتة أبدًا (#000، black، rgb(...)). اترك الخلفية كما هي؛ واستخدم متغيرات السمة (var(--ui-*)) لكل شيء.
  • أشِر فقط إلى ما استوردته. مكوّن نسيت استيراده (مثل StatusDot) يسبب ReferenceError عند العرض — تحقق مرة أخرى من أن كل معرّف في استدعاءات jsx() الخاصة بك موجود في سطر الاستيراد.
  • اقرأ الحالة بشكل أمري (imperatively) في المعالجات ($atom.get())، وليس من إغلاق (closure) خاص بالعرض — فالأحداث السريعة ستَرى قيمًا قديمة خلاف ذلك. اشترك (useValue) فقط في الورقة (leaf) التي تعرض القيمة.
  • يجب أن تتبع لوحات canvas حاويتها باستخدام ResizeObserver وتُعيد قياس canvas (سمتا العرض/الارتفاع، وليس CSS فقط) — فاللوحات تُعاد قياسها باستمرار.
  • لا تستطلع أسرع من بضع ثوانٍ باستخدام host.request؛ فضّل host.onEvent / ctx.socket ودع React Query يزيل التكرار.
  • ctx.socket عملية تجاهل (no-op) على remotes بـ OAuth. احرص دائمًا على بديل استطلاع.

استكشاف الأخطاء وإصلاحها

إضافتي لا تظهر. تأكد أن الملف موجود في $HERMES_HOME/desktop-plugins/<id>/plugin.js وأن اسم المجلد يطابق id المُصدَّر. نفّذ ⌘K → Reload desktop plugins. تحقق من التطبيق بحثًا عن رسالة خطأ منبثقة تسمّي الإخفاق، وتابع سجل hermes logs gui -f.

"unsupported import" عند التحميل. إضافة القرص لا يجوز أن تستورد سوى @hermes/plugin-sdk، وreact، وreact/jsx-runtime. أزل أي استيراد آخر.

عنصر jsx لا يعرض شيئًا / يُطلق ReferenceError. معرّف مستخدَم في استدعاء jsx() غير مستورَد. أضفه إلى سطر الاستيراد.

ctx.rest يعيد 404. الـ backend غير مُركَّب: تأكد من أن ~/.hermes/plugins/<id>/dashboard/manifest.json يحتوي "api": "plugin_api.py"، وأن الإضافة مدرجة في plugins.enabled ضمن config.yaml، وأعد تشغيل gateway (تُركَّب مسارات الـ backend عند بدء التشغيل). تابع ~/.hermes/logs/errors.log بحثًا عن Failed to load plugin <id> API routes.

ctx.socket لا يُطلَق أبدًا. على remote بـ OAuth هو عملية تجاهل (no-op) بالتصميم — استخدم بديل الاستطلاع الخاص بك. وإلا تحقق من أن الـ backend يعرض مسار @router.websocket(...) المطابق تحت نطاقه.

الألوان تبدو خاطئة بعد تبديل السمة. لقد استخدمت لونًا ثابتًا. استبدله بـ متغير سمة var(--ui-*).
