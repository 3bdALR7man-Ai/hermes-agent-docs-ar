معلومة

ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

here.now

يتيح here.now للوكلاء نشر المواقع وتخزين ملفات خاصة في Drives سحابية.

استخدم here.now لمهمّتين:

  • المواقع (Sites): انشر مواقع وملفات على {slug}.here.now.
  • Drives: خزّن ملفات الوكيل الخاصة في مجلدات سحابية.

الوثائق الحالية

قبل الإجابة عن أسئلة حول إمكانيات here.now أو ميزاته أو مساراته، اقرأ الوثائق الحالية:

→ https://here.now/docs

اقرأ الوثائق:

  • عند أول تفاعل متعلق بـ here.now في المحادثة
  • في أي وقت يسأل فيه المستخدم كيف يفعل شيئًا
  • في أي وقت يسأل فيه المستخدم عمّا هو ممكن أو مدعوم أو مُوصى به
  • قبل إخبار المستخدم بأن ميزة ما غير مدعومة

مواضيع تتطلب الوثائق الحالية (لا تعتمد على نص المهارة المحلي وحده):

  • Drives ومشاركتها
  • النطاقات المخصّصة
  • المدفوعات وتقييد الدفع
  • forking (التفريع)
  • مسارات proxy ومتغيرات الخدمة
  • المعرّفات (handles) والروابط
  • الحدود والحصص (quotas)
  • توجيه SPA
  • معالجة الأخطاء وإصلاحها
  • توفّر الميزات

إذا تعارضت الوثائق مع سلوك API الفعلي، ثق بسلوك API الفعلي.

إذا فشل جلب الوثائق أو انتهت مهلته، تابع باستخدام نص المهارة المحلي ومخرجات API/السكربت الفعلية. فضّل سلوك API الفعلي في العمليات النشطة.

المتطلبات

  • الملفات التنفيذية المطلوبة: curl، file، jq
  • متغير بيئة اختياري: $HERENOW_API_KEY
  • متغير رمز Drive اختياري: $HERENOW_DRIVE_TOKEN
  • ملف بيانات اعتماد اختياري: ~/.herenow/credentials
  • مسارات مساعدة المهارة:
    • ${HERMES_SKILL_DIR}/scripts/publish.sh لنشر المواقع
    • ${HERMES_SKILL_DIR}/scripts/drive.sh لتخزين Drive الخاص

إنشاء موقع

يُخرج الرابط المباشر (مثلًا https://bright-canvas-a7k2.here.now/).

يتكون هذا التدفق من ثلاث خطوات في الخلفية: الإنشاء/التحديث -> رفع الملفات -> الإنهاء (finalize). لا يصبح الموقع حيًا إلا بعد نجاح الإنهاء.

بلا مفتاح API، يُنشئ هذا موقعًا مجهول الهوية تنتهي صلاحيته خلال 24 ساعة. مع مفتاح API محفوظ، يكون الموقع دائمًا.

بنية الملفات: بالنسبة لمواقع HTML، ضع index.html في جذر الدليل الذي تنشره، لا داخل دليل فرعي. تصبح محتويات الدليل جذر الموقع. على سبيل المثال، انشر my-site/ حيث يوجد my-site/index.html — لا تنشر مجلدًا أصليًا يحتوي على my-site/.

يمكنك أيضًا نشر ملفات خام دون أي HTML. تحصل الملفات المفردة على عارض تلقائي غني (صور، PDF، فيديو، صوت). تحصل الملفات المتعددة على قائمة أدلة مُولَّدة تلقائيًا مع تصفح للمجلدات ومعرض صور.

تحديث موقع موجود

يحمّل السكربت تلقائيًا claimToken من .herenow/state.json عند تحديث المواقع المجهولة الهوية. مرّر --claim-token {token} لتجاوز ذلك.

تتطلب التحديثات المُصادَق عليها مفتاح API محفوظًا.

استخدام Drive

استخدم Drive عندما يريد المستخدم تخزينًا سحابيًا خاصًا لملفات الوكيل: المستندات، السياق، الذاكرة، الخطط، الأصول، الوسائط، الأبحاث، الكود، وأي شيء آخر يجب أن يستمر دون أن يُنشر كموقع ويب.

يمتلك كل حساب مسجّل الدخول Drive افتراضيًا باسم My Drive.

استخدم رموز Drive محدودة النطاق (scoped) لتسليم المهام بين الوكلاء. إذا استلمت كتلة مشاركة herenow_drive، استخدم token الخاص بها كـ Authorization: Bearer <token> مقابل api_base، واحترم pathPrefix عند وجوده، وحافظ على ETags عند الكتابة. تعني قيمة pathPrefix المساوية لـ null وصولًا كاملًا إلى Drive. إذا كانت المهارة متاحة، فضّل drive.sh؛ وإلا استدعِ عمليات API المذكورة مباشرةً.

تخزين مفتاح API

يقرأ سكربت النشر مفتاح API من هذه المصادر (يفوز أول تطابق):

  1. خيار --api-key {key} (لأتمتة CI/السكربتات فقط — تجنّبه في الاستخدام التفاعلي)
  2. متغير البيئة $HERENOW_API_KEY
  3. ملف ~/.herenow/credentials (المُوصى به للوكلاء)

مهم: بعد استلام مفتاح API، احفظه فورًا — نفّذ الأمر أعلاه بنفسك. لا تطلب من المستخدم تنفيذه يدويًا. تجنّب تمرير المفتاح عبر خيارات CLI (مثل --api-key) في الجلسات التفاعلية؛ فملف بيانات الاعتماد هو طريقة التخزين المفضّلة.

لا تُدرج أبدًا بيانات الاعتماد أو ملفات الحالة المحلية (~/.herenow/credentials، .herenow/state.json) في نظام التحكم بالمصادر.

قبل إنشاء المواقع أو تحديثها، يمكنك فحص هذا الملف للعثور على slugs سابقة. عامل .herenow/state.json كذاكرة تخزين مؤقت داخلية فقط. لا تعرض أبدًا مسار هذا الملف المحلي كرابط، ولا تستخدمه أبدًا كمرجع موثوق لوضع المصادقة أو تاريخ الانتهاء أو رابط المطالبة (claim).

ما تخبر به المستخدم

بالنسبة للمواقع المنشورة:

  • شارك دائمًا siteUrl من تشغيل السكربت الحالي.
  • اقرأ واتّبع أسطر publish_result.* من stderr الخاصة بالسكربت لتحديد وضع المصادقة.
  • عندما تكون publish_result.auth_mode=authenticated: أخبر المستخدم أن الموقع دائم ومحفوظ في حسابه. لا حاجة إلى رابط مطالبة (claim URL).
  • عندما تكون publish_result.auth_mode=anonymous: أخبر المستخدم أن صلاحية الموقع تنتهي خلال 24 ساعة. شارك رابط المطالبة (إذا كان publish_result.claim_url غير فارغ ويبدأ بـ https://) ليتمكن من الاحتفاظ به دائمًا. حذّره من أن رموز المطالبة تُعاد مرة واحدة فقط ولا يمكن استرجاعها.
  • لا تخبر المستخدم أبدًا بفحص .herenow/state.json بحثًا عن روابط المطالبة أو حالة المصادقة.

بالنسبة لـ Drives:

  • لا تصف ملفات Drive بأنها روابط عامة.
  • أخبر المستخدم أن محتويات Drive خاصة ما لم تُشارك برمز محدود النطاق.
  • عند مشاركة الوصول مع وكيل آخر، فضّل رمزًا محدود النطاق بـ pathPrefix ضيّق ومدة صلاحية (TTL) قصيرة.
