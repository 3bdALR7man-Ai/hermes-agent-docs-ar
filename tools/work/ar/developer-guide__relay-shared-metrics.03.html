تضبط هذه المقاييس حلقة الوكيل نفسها. لا تُحتسَب حلقات المراجعة الخلفية و Curator الخاصة بـ Hermes مطلقًا؛ وتُحتسَب subagents المفوّضة (فاستدعاءات أدواتها وحلقاتها وردودها سلوك نموذج أيضًا). لا يغادر نص الأوامر أو مسارات الملفات أو وسائط الأدوات أو نص الرد مطلقًا — بل القيم المغلقة أدناه وحدها.

الكفاءة: تكلفة الدور والهدر وكلفة الأدوات وانقطاعات التخزين المؤقت للـ prompt

يتبع المزوّد والنموذج قواعد مسار النموذج أعلاه. "دور المستخدم" هو رسالة مستخدم واحدة حتى ردها النهائي؛ ولا يُعد العمل الذي يملكه Hermes (مراجعة الذاكرة/المهارات في الخلفية و Curator وأدوار subagents المفوَّضة نفسها) دور مستخدم.cache_break و tool_output_truncation سلوك النموذج والأداة، لذا تُحتسَب subagents المفوَّضة فيهما؛ ولا تُحتسَب مراجعة الخلفية و Curator أبدًا.

أسباب إخفاق التثبيت والتحديث

منذ الإصدار v4 لمخطط الحزمة (يُوسَّع في مكانه بالإضافة فقط، فتظل كل الصيغ المرسَلة سابقًا صالحة)، يبيّن مقياسان قائمان سبب إخفاقهما. تحتفظ الصفوف المسجّلة قبل التغيير بحقولها القديمة وتظل قابلة للتجميع في حزم.

المقياسالأبعاد المضافةالسؤال الذي يجيب عنه
hermes.extension.install.countفئة الإخفاق، السجلسبب إخفاق تثبيت المهارات والإضافات و MCP، ومصدر skills-hub الذي يفشل. تكون قيمة failure_class هي none عند النجاح، وإلا اسمًا من مجموعة مغلقة لخروج الإخفاق الذي أوقف التثبيت. المهارات: ambiguous, auth_rejected, fetch_failed, invalid_bundle, invalid_name, not_found, rate_limited, scan_blocked, stale_index. الإضافات: already_installed, clone_failed, deps_declined, deps_failed, git_missing, incompatible, invalid_source, manifest_invalid, non_interactive, removed_from_catalog, scan_blocked. خوادم MCP: auth_required, bootstrap_failed, clone_failed, config_invalid, config_rejected, connect_failed, git_missing, missing_credentials, server_start_failed. قد تكون قيمة كل نوع أيضًا exception, filesystem_error, network, other, permission. يُصنَّف الخطأ المرفوع دون فئة مسمّاة بحسب نوعه في Python فقط (تُعرض PermissionError كـ permission، وأخطاء الاتصال والمهلة كـ network، وغيرها من OSError كـ filesystem_error، وأي شيء آخر كـ exception، مع حذف اسم نوعه). تُضبط registry على صفوف المهارات فقط: مهايئ skills-hub الذي حدّد المهارة أو قدّمها، إحدى قيم browse-sh, clawhub, github, hermes-index, lobehub, official, skills-sh, url, well-known (معرّفات المهايئات التي يبنيها tools/skills_hub_search.py::create_source_router)، أو unresolved حين لا يجيب أي مهايئ، أو none لاستعادة المهارات المدمجة وكل صف إضافة/MCP، أو other خلاف ذلك. الصف الذي تكون فيه failure_class خارج مجموعة نوعه، أو تكون none عند الإخفاق أو مضبوطة عند النجاح، أو يسمّي سجلًا في صف إضافة/MCP، غير صالح. لا يُسجَّل أبدًا المعرّف أو URL أو نص الخطأ أو المسار؛ يحتفظ name بقاعدته القائمة: اسم الكتالوج أو custom.
hermes.update.runفئة الإخفاقسبب إخفاق hermes update إلى جانب موضعه (failed_stage). none ما لم تكن النتيجة failed أو refused أو partial. تُشتق من إيصال التحديث النهائي فقط: build_failed و deps_failed و exception و fleet_stale و fleet_unverified و git_failed و interrupted و lock_held و managed_install و os_error و disk_full و permission_denied و restart_failed و subprocess_failed، وإلا other؛ وتبلّغ التحديثات الذاتية المحزَّمة لـ Desktop عن unknown (يحمل RPC الخاص بها مرحلة، لا سببًا أبدًا). يُقرأ الاستثناء الذي أنهى التشغيل باسم نوعه وحده، لا برسالته أبدًا (تُعرض PermissionError كـ permission_denied، وتُعرض OSError ذات errno يساوي ENOSPC كـ disk_full)؛ وتُعرض إعادة استئناف gateway فاشلة على Windows بعد التحديث كـ restart_failed. يسجّل كل خروج يوقف التشغيل قبل علامة مرحلة التطبيق token واحدًا من مجموعة مغلقة عند الخروج نفسه، ويقرأه التشغيل (تنطلق بعض هذه الحالات، وهي syntax_rollback و stash_restore_rejected و unexpected_branch و head_moved، بعدما ينقل git الشجرة ويعيدها أو يتركها ليستعيدها التشغيل التالي): fetch_failed و git_timeout (وصل استدعاء git شبكي إلى حد زمن المحدِّث) و channel_unresolved (يشمل أيضًا اسم قناة غير صالح في config.yaml) و gateway_pause_failed (Windows: تعذّر إيقاف الـ gateways مؤقتًا بأمان قبل نقل venv) و git_in_progress (كانت عملية merge/rebase/... جارية بالفعل) و git_index_locked و merge_conflict (commits محلية على branch مخصّص) و checkout_move_failed و branch_missing و parked_branch_blocked و detached_head و unexpected_branch و head_moved (تحرّك ref أثناء التحديث) و target_unresolved و target_syntax_error (رُفض قبل النقل) و syntax_rollback (نُقل وفشل فحص الصياغة ثم أُعيد) و commit_point_refused (تعذّرت تهيئة نقطة commit؛ لم يتحرّك شيء) و downgrade_refused (الهدف أقدم من وقت تشغيل الـ gateway الذي يحتفظ state.db الخاص بالـ profile بسجل له بالفعل؛ لم يتحرّك شيء) و venv_foreign_owner و local_changes_blocked (تغييرات محلية تعذّر على git وضعها في stash، أو شجرة غير نظيفة لن يستبدلها خيار ZIP الاحتياطي) و stash_restore_rejected و not_git_checkout و old_version_handoff (تعذّر اكتمال تسليم التحكم من محدِّث أقدم) و branch_unsupported و download_failed و zip_failed و disk_full و lock_held و managed_install. أصبحت aborted_before_apply الآن مجرد قيمة احتياطية لخروج كهذا بلا token مسجَّل. يقرأ فحص الصياغة المسبق عند البدء الملفات الحرجة للهدف من مخزن كائنات git؛ وعند انتهاء مهلة القراءة (يجلب تثبيت بلا blobs كل blob عند الحاجة)، يتجاوزها الفحص كما لو كانت ملفات غائبة ويقرّر فحص الصياغة بعد النقل، فلا يفشل التشغيل بعد الآن كـ subprocess_failed. يحدث رفض قفل التحديث ورفض عملية Git ورفض التثبيت المُدار قبل فتح إيصال التشغيل؛ ولا تكتب هذه الحالات إيصالًا (مخزن الإيصالات مملوك للتحديث الذي يمسك القفل)، وتسجّل صفًا واحدًا بذلك الـ token، مع kind هو desktop عندما تسمّي علامة التحديث تسليم Desktop لهذا التشغيل (كمفوَّض له أو شريك تسليمه)، لا لمجرد أن تحديثًا آخر يمسك العلامة. لا يُعرض خطأ git الذي أنهى نقل النسخة المسحوبة كـ git_index_locked إلا حين يبلّغ git أن قفل index موجود بالفعل؛ ويُعرض رفض git لصلاحية كتابته (أو كتابة أي ملف) كـ permission_denied. لا يُقرأ token إلا ما دام التشغيل بلا علامة تطبيق، فلا يمكن لسبب أن يستمر بعد الخروج الذي سجّله. التشغيل الذي نفّذ commit ثم قُوطع، أو تعذّرت إعادة تطبيق تغييراته المحلية الموضوعة في stash، يُعرض بالنتيجة partial (interrupted / local_changes_parked، و failed_stage هو apply للحالة الأخيرة)، وليس failed أبدًا؛ وتُبقي المتابعات المستحقة وحدها التشغيل في حالة success (العقد C3). يُعلَّق التشغيل الذي يُنهيه مفسّر ما قبل التحديث مع الـ token ورمز الخروج ونوع الاستثناء في بداية سبب الإيقاف (أو إحدى عبارتين ثابتتين في Hermes) وأعلام إعادة التشغيل/إجراء المستخدم (لا argv أو مسارات أو رسائل أبدًا)، فيُصنَّف تمامًا مثل التشغيل نفسه لو انتهى داخل العملية. يُعرض التشغيل الفاشل الذي نجحت علامات مراحله كلها الآن بـ failed_stage هو verify (كتب التحقق بعد إعادة التشغيل partial) أو restart (تركت إعادة تشغيل متجاوَزة إعادة تشغيل مستحقة للأسطول) بدلًا من other؛ ويحتفظ تشغيل partial ذو علامة بناء أو إعادة تشغيل فاشلة بتلك المرحلة، ولا يفشل صف مرحلة التحقق فيه إلا عندما يضم الأسطول صفًا قديمًا أو متوقفًا.
