مرجع Toolsets

الـ toolsets هي حزم مسمّاة من الأدوات تتحكم فيما يستطيع الوكيل فعله. وهي الآلية الأساسية لضبط توفر الأدوات حسب المنصة، أو الجلسة، أو المهمة.

كيف تعمل الـ Toolsets

تنتمي كل أداة إلى toolset واحد فقط. عند تفعيل toolset، تصبح كل الأدوات في تلك الحزمة متاحة للوكيل. تأتي الـ toolsets في ثلاثة أنواع:

  • الأساسية (Core) — مجموعة منطقية واحدة من الأدوات المترابطة (مثلًا، file تضم read_file وwrite_file وpatch وsearch_files)
  • المركّبة (Composite) — تجمع عدة toolsets أساسية لسيناريو شائع (مثلًا، debugging تضم أدوات الملفات والطرفية والويب)
  • الخاصة بالمنصة (Platform) — إعداد كامل للأدوات مخصص لسياق نشر معين (مثلًا، hermes-cli هو الافتراضي لجلسات CLI التفاعلية)

Toolsets الديناميكية

Toolsets خوادم MCP

يولّد كل خادم MCP مضبوط toolset باسم mcp-<server> وقت التشغيل. فمثلًا، إذا ضبطت خادم MCP باسم github، يُنشأ toolset باسم mcp-github يضم كل الأدوات التي يعرضها ذلك الخادم.

هذا ينشئ toolset باسم mcp-github يمكنك الإشارة إليه في --toolsets أو إعدادات المنصة. اسم الخادم المجرّد (github) يعمل كاسم بديل. إذا سُمّي خادم كـ toolset مدمجة (browser, web)، يُحدَّد الاسم على أنه الأدوات المدمجة بالإضافة إلى أدوات mcp__<server>__* الخاصة بالخادم؛ ولا يحجب أي منهما الآخر.

Toolsets الإضافات

يمكن للإضافات تسجيل toolsets خاصة بها عبر ctx.register_tool() أثناء تهيئة الإضافة. تظهر هذه إلى جانب الـ toolsets المدمجة ويمكن تفعيلها/تعطيلها بنفس الطريقة.

Toolsets مخصصة

عرّف toolsets مخصصة في config.yaml لإنشاء حزم خاصة بالمشروع:

أحرف البدل (Wildcards)

  • all أو * — يتوسّع ليشمل كل toolset مسجّل (مدمج + ديناميكي + إضافة)

عدد قليل من الأدوات لديه فحص توفر إضافي فوق الانتماء إلى toolset، ولا يُفعَّل بمجرد all/* وحده:

  • الأدوات المشروطة بالإمكانية (المتصفح، computer_use، code_execution و Feishu و cronjob) لا تظهر إلا عند ضبط متطلبات backend/بيانات الاعتماد الخاصة بها.
  • الأدوات المشروطة بسير العمل — أي toolset kanban — اختيارية عمدًا. خيار all/* لا يفعّل Kanban؛ يجب أن تُدرج kanban صراحةً (أو أن تكون عامل مهام أنشأه المُوزِّع مع ضبط HERMES_KANBAN_TASK). أدوات كانبان تُعدّل حالة لوحة مشتركة، لذا تبقى معطّلة افتراضيًا حتى تحت all.

العلاقة مع hermes tools

يوفّر أمر hermes tools واجهة نصية (curses) لتبديل الأدوات الفردية تشغيلًا وإيقافًا لكل منصة. يعمل هذا على مستوى الأداة (أدق من مستوى الـ toolset) ويُحفَظ في config.yaml. الأدوات المعطّلة تُستبعد حتى لو كان الـ toolset الخاص بها مفعّلًا.

راجع أيضًا: مرجع الأدوات للاطلاع على القائمة الكاملة للأدوات الفردية ومعاملاتها.
