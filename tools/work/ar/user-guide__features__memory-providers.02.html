Mem0

كتالوج الإضافات

تصون Mem0 المزوّد Mem0 ويُثبَّت من كتالوج الإضافات بدلًا من تضمينه في Hermes. المصدر: mem0ai/mem0 — integrations/hermes-plugin-mem0. تُنقل الإعدادات الحالية تلقائيًا — راجع الانتقال من Mem0 المضمّن.

استخلاص للحقائق بواسطة LLM على جانب الخادم، مع بحث دلالي، وإعادة ترتيب النتائج (reranking)، وإزالة تلقائية للتكرار. يتوفر بثلاثة أوضاع اتصال: المنصة (Mem0 Cloud)، ولوحة تحكم مستضافة ذاتيًا (خادم Mem0 تشغّله عبر Docker)، و OSS (Mem0 داخل العملية مع LLM ومخزن متجهات خاصين بك).

الانتقال من Mem0 المضمّن

كان Mem0 يُضمَّن في شجرة Hermes (وكإضافة pip باسم hermes-agent[mem0]). إذا كان config.yaml يحتوي بالفعل memory.provider: mem0، فلا يلزم معظم المستخدمين فعل شيء:

  • hermes update يثبّت إضافة الكتالوج في المجلد الرئيسي لكل profile يسمّي المزوّد.
  • إذا كانت الإضافة لا تزال ناقصة عند أول بدء للوكيل (hermes chat، أو gateway، أو Desktop)، يثبّتها Hermes ويخبرك بذلك.
  • مع security.allow_lazy_installs: false، لا يثبّت مسار بدء الوكيل أي شيء؛ ويطبع بدلًا من ذلك أمر hermes plugins install mem0 الدقيق.

memory.provider, $HERMES_HOME/mem0.json، ومفاتيح MEM0_* في .env، والذكريات المخزّنة في Mem0 Cloud أو خادم Mem0 الخاص بك أو مخزن OSS المحلي دون تغيير. تحقّق باستخدام hermes memory status و hermes plugins list.

Hindsight

كتالوج الإضافات

تصون Hindsight شركة vectorize-io وتُثبَّت من كتالوج الإضافات بدلًا من تضمينها في Hermes. توجد تفاصيل الإعداد في توثيق الجهة الأصلية: hindsight.vectorize.io/sdks/integrations/hermes.

ذاكرة طويلة الأمد مع رسم بياني معرفي (knowledge graph)، وتحديد الكيانات (entity resolution)، واسترجاع متعدد الاستراتيجيات. توفّر الأداة hindsight_reflect تركيبًا عبر الذكريات لا يقدّمه أي مزوّد آخر. ويحتفظ تلقائيًا بأدوار المحادثة كاملة (بما في ذلك استدعاءات الأدوات) مع تتبّع المستندات على مستوى الجلسة.

تخزين البياناتHindsight Cloud، أو PostgreSQL مضمّن محليًا، أو خادم Hindsight محلي خارجي
التكلفةحسب تسعير Hindsight (سحابي) أو مجاني (محلي)

الانتقال من Hindsight المضمّن

كان Hindsight يُضمَّن في شجرة Hermes (وكإضافة pip باسم hermes-agent[hindsight]). إذا كان config.yaml يحتوي بالفعل memory.provider: hindsight، فلا يلزم معظم المستخدمين فعل شيء:

  • hermes update يثبّت إضافة الكتالوج في المجلد الرئيسي لكل profile يسمّي المزوّد. يسمّي كل سطر profile المعني. وفي الطرفية، يطلب الإذن قبل تهيئة اعتماديات Python للإضافة؛ وإذا استخدمت عدة profiles المزوّد، تُطرح الأسئلة مرة واحدة وتسري الإجابات عليها جميعًا. ودون طرفية (تطبيق Desktop، أو سكربت، أو خدمة)، لا يوجد من يجيب، فيهيئها كل profile دون تدخل عندما تكون security.allow_lazy_installs الخاصة به مفعّلة (الافتراضي)؛ أما profile الذي يعطّلها فيحصل بدلًا من ذلك على أمر hermes -p <profile> plugins install hindsight الدقيق، ويظل نقل profiles الأخرى مستمرًا.
  • إذا ظلت الإضافة ناقصة عند أول بدء للوكيل (hermes chat، أو Desktop، أو gateway، وغيرها)، يثبّتها Hermes مع اعتمادياتها ويعرض ✓ Memory provider 'hindsight' moved out of core — installed its plugin from the catalog (memory.provider and your stored memories are unchanged; check its settings with `hermes memory status`). تتلقى منصات المراسلة ذلك السطر مع أول رد.
  • إذا تعذّر التثبيت عند بدء الوكيل، ترى السبب بدلًا من تشغيله بصمت دون ذاكرة خارجية: مع security.allow_lazy_installs: false، يسمّي التحذير أمر التثبيت لذلك profile؛ وتعرض حالات عدم الاتصال أو رفض التثبيت الخطأ والأمر نفسه. وبعد محاولة فاشلة، يتجاوز بدء الوكيل خلال الساعة التالية التثبيت ويكرر الأمر فقط؛ بينما يعيد hermes update المحاولة دائمًا.
  • لا يطرح بدء الوكيل سؤالًا مطلقًا (فالـ prompt الخاص بالمحادثة يمتلك الطرفية). لذلك لا يُثبَّت عند بدء الوكيل مزوّد كتالوج لم يُضمَّن قط في Hermes (مثل mnemosyne): يسمّي التحذير hermes plugins install <name> لذلك profile، أو يمكنك تثبيته من صفحة Plugins في لوحة التحكم/Desktop.

ما يتغير على القرص: تظهر الإضافة في ~/.hermes/plugins/hindsight/ ويُضاف إلى config.yaml إعداد plugins.enabled: [hindsight]. memory.provider, $HERMES_HOME/hindsight/config.json, HINDSIGHT_API_KEY في .env وبيانات بنك الذاكرة الخاصة بك دون تغيير. تحقّق باستخدام hermes memory status (المزوّد نشط) و hermes plugins list (الإضافة مثبّتة ومفعّلة).

من أين تقرأ الإضافة إعداداتها

يقرأ Hindsight $HERMES_HOME/hindsight/config.json (لكل مجلد رئيسي لـ profile)، و ~/.hindsight/config.json (المشتركة القديمة)، ومتغيرات HINDSIGHT_* في .env. ولا يقرأ قسم memory.hindsight في config.yaml: يُتجاهل أي مفتاح memory.hindsight.* هناك. عدّل ملف config.json الخاص بالإضافة (جدول المفاتيح أعلاه)، أو استخدم hermes memory setup.

يصون Holographic المطوّر itpartypattaya ويُثبَّت من كتالوج الإضافات بدلًا من تضمينه في Hermes. وهو المزوّد نفسه الذي كان يُضمَّن في الشجرة، بالاسم والإعدادات وقاعدة البيانات نفسها. تُنقل الإعدادات الحالية تلقائيًا — راجع الانتقال من Holographic المضمّن.
