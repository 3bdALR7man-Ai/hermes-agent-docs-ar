Google Vertex AI

يدعم Hermes Agent نماذج Gemini على Google Cloud Vertex AI عبر endpoint المتوافق مع OpenAI في Vertex. وعلى خلاف مزوّد Google AI Studio (الذي يستخدم مفتاح API ثابتًا مع generativelanguage.googleapis.com)، يمنحك Vertex حدود معدل على مستوى المؤسسات وفوترة/أرصدة GCP، وهو الخيار المناسب عندما تريد أن يُحتسب استخدام Gemini على حساب Google Cloud الخاص بك بدلًا من مفتاح AI Studio.

يصادق Vertex عبر OAuth2، وليس بمفتاح API

لا يوفّر Vertex أي مفتاح API ثابت للـ endpoint القياسي. إذ يحتاج كل طلب إلى OAuth2 access token قصير الأجل (مدة صلاحية TTL ≈ ساعة واحدة) يُصدَر إما من ملف JSON لحساب خدمة (service account) أو من Application Default Credentials (ADC). يُصدر Hermes هذه الـ tokens ويجدّدها تلقائيًا نيابةً عنك — فلن تحتاج أبدًا إلى لصق token يدويًا. ولهذا السبب لا ينجح لصق token مؤقت في حقل api_key الخاص بمزوّد مخصص: إذ تنتهي صلاحيته في منتصف الجلسة.

المتطلبات المسبقة

  • مشروع على Google Cloud مع تفعيل Vertex AI API وتفعيل الفوترة.
  • بيانات الاعتماد، وتكون أحد الخيارين:
    • ملف مفتاح JSON لحساب خدمة يملك الدور roles/aiplatform.user، أو
    • Application Default Credentials عبر gcloud auth application-default login (أو خادم البيانات الوصفية عند التشغيل على VM في GCP).
  • google-auth — يُثبَّت تلقائيًا في أول مرة تختار فيها Vertex (تثبيت عند الحاجة). وإذا فشل ذلك، فشغّل hermes setup لإصلاح التثبيت المُدار.

متغيرات البيئة لها الأولوية على config.yaml

يتجاوز VERTEX_PROJECT_ID و VERTEX_REGION القيمتين vertex.project_id / vertex.region في config.yaml. استخدمهما للتجاوز على مستوى كل shell، واحتفظ بالإعدادات الدائمة في config.yaml.

كيف تعمل المصادقة

  1. يحدّد Hermes بيانات الاعتماد بالترتيب التالي: VERTEX_CREDENTIALS_PATH → GOOGLE_APPLICATION_CREDENTIALS → ADC.
  2. يُصدر OAuth2 access token (بنطاق cloud-platform) ويخزّنه مؤقتًا، ثم يجدّده عندما يتبقى على انتهاء صلاحيته 5 دقائق أو أقل.
  3. يُسلَّم الـ token إلى عميل OpenAI قياسي موجّه إلى endpoint الخاص بـ Vertex:
    أما المواقع الإقليمية فتستخدم مضيفًا بالشكل {region}-aiplatform.googleapis.com بدلًا من ذلك.
  4. إذا استمرت الجلسة أطول من عمر الـ token وأعاد أحد الطلبات 401، يُصدر Hermes الـ token من جديد ويعيد المحاولة تلقائيًا. وفي حالة gateway يعمل لفترة طويلة، إذا انتهت صلاحية refresh token الخاص بـ ADC نفسه، يلجأ Hermes إلى ملف JSON لحساب الخدمة إن كان مضبوطًا.

المنطقة global لنماذج Gemini 3.x

تُخدَّم نماذج المعاينة Gemini 3.x عبر endpoint global. وقد تُعيد الـ endpoints الإقليمية (us-central1، وغيرها) الخطأ 404 لهذه النماذج. اترك region: global كما هو ما لم يكن لديك سبب محدد لتثبيت منطقة بعينها.

تبديل النماذج أثناء الجلسة

يبدّل /model بين المزوّدين والنماذج المضبوطة مسبقًا؛ ولا يجمع بيانات اعتماد جديدة. لذا اضبط Vertex أولًا باستخدام hermes model.

الاستدلال / التفكير

يتيح Vertex ميزانية التفكير (thinking budget) الخاصة بـ Gemini عبر الواجهة المتوافقة مع OpenAI. ويعيّن Hermes إعداد مستوى الاستدلال (reasoning effort) الخاص به إلى extra_body.google.thinking_config تلقائيًا، بحيث يعمل reasoning_effort بالطريقة نفسها التي يعمل بها على واجهات Gemini الأخرى.

التشخيص

يُبلغ أمر doctor عمّا إذا كان من الممكن تحديد بيانات اعتماد Vertex (مسار حساب الخدمة أو ADC) وعمّا إذا كان المزوّد مضبوطًا.

استكشاف الأخطاء وإصلاحها

"Vertex AI credentials could not be resolved"

لم يعثر Hermes على ملف JSON لحساب خدمة ولا على ADC صالحة للعمل. إما أن تضبط VERTEX_CREDENTIALS_PATH في ~/.hermes/.env، أو تشغّل gcloud auth application-default login. وإذا لم يكن مشروعك مضمّنًا في بيانات الاعتماد، فاضبط vertex.project_id في config.yaml.

google-auth غير مثبّت

يثبّته Hermes عند الحاجة في أول مرة تختار فيها مزوّد Vertex. وإذا فشل ذلك، فشغّل hermes setup لإصلاح التثبيت المُدار.

الخطأ 404 مع نماذج Gemini 3.x

على الأرجح أنك تستخدم endpoint إقليميًا. اضبط region: global في قسم vertex: من config.yaml (أو ألغِ ضبط VERTEX_REGION).

403 / رفض الصلاحية

يحتاج حساب الخدمة (أو هوية ADC الخاصة بك) إلى الدور roles/aiplatform.user على المشروع، ويجب أن تكون Vertex AI API مفعّلة لذلك المشروع.
