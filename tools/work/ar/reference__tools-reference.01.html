catalog toolset

يُفعّل للجلسات التي يكون مصدرها تطبيق سطح المكتب، أيًا كان backend المتصل به. لا تحصل عليه جلسات CLI أو TUI أو hermes -z أو cron أو kanban أو المراسلة مطلقًا، حتى إذا ذكرته قائمة إعدادات. لا يتضمنه all. أزله باستخدام agent.disabled_toolsets: [catalog].

الأداةالوصفالبيئة المطلوبة
manage_catalogجلسات سطح المكتب فقط، مؤجّل خلف tool_search افتراضيًا. يسرد search إضافات الكتالوج ومهارات hub المطابقة لـ query (واختياريًا kind واحد) مع id, kind, display, tier, platforms و installed (الموجود في profile هذه المحادثة)؛ ولا يغيّر شيئًا. يأخذ install الوسيط items: [{kind, id}] ويعرض بطاقة موافقة واحدة بصف لكل عنصر (Install و Advanced و Skip)؛ يُعرض المعرّف الذي لا يعرفه الكتالوج، أو الإضافة التي لا تستطيع العمل على OS هذا، كعنصر فاشل مع السبب. يُثبَّت الصف الموافق عليه في profile هذه المحادثة (أو profile المختار ضمن Advanced) عند commit الذي راجعه الكتالوج، مع قائمة الحظر والفحص الأمني والتفعيل المباشر نفسها في تبويب Plugins، لكي تصبح أدوات MCP ومهارات الإضافة قابلة للاستخدام فورًا في محادثات ذلك profile المفتوحة. تسرد النتيجة كل صف بالحالة connected (مع tools و skill), skipped, failed (مع detail) أو not_connected؛ ينهي الصف الفاشل الانتظار مثل المثبّت أو المتجاوز، ويُفعّل التثبيت إضافة كتالوج موجودة على القرص لكنها غير مفعّلة. لا يستطيع النموذج تمرير مصدر أو commit أو profile أو إعداد. في أي مكان آخر، يعيد الاستدعاء أمر hermes plugins install / hermes skills install المطلوب تنفيذه بدلًا من ذلك.—

setup toolset

يُفعّل بواسطة إعداد profile الإعداد الخاص بتطبيق سطح المكتب (platform_toolsets.cli). تحصل جلسات سطح المكتب وحدها على أدواته؛ ولا تحصل عليها جلسات CLI أو hermes -z أو cron أو kanban أو المراسلة مطلقًا. لا يتضمنه all. ولا يسرده hermes tools.

الأداةالوصفالبيئة المطلوبة
setup_chooseعبر toolset setup فقط، ولجلسات سطح المكتب فقط؛ لا يُؤجّل مطلقًا إلا إذا ذكرته قائمة tools.tool_search.defer. يعرض بطاقة واحدة في محادثة الإعداد: تكون قيمة kind هي question, accent, theme, layout, connectors, plugins, tour أو fork، و question عنوان البطاقة. الحقل options مطلوب: يستبدل حتى 12 صفًا من نوع {id, label, detail?} (بمعرّفات فريدة) قائمة التطبيق، وتعرض القيمة [] قائمة التطبيق لمنتقي الخيارات أو تطلب نصًا حرًا للنوع question. tour (Quick tour و Show me everything و Skip) و fork (مهمتان أوليان تُنشآن عند عرض البطاقة اعتمادًا على التطبيقات والإضافات المختارة سابقًا وهذا الحاسوب، ثم "I have something in mind" و "Help me set up this <machine>" و "Let's figure it out together") صفوف backend دائمًا. تحصل بطاقة الاسم (question "What should I call you?") على اسم الحساب الكامل كصف من backend، لذا لا يصل الاسم إلى النموذج إلا في النتيجة عندما يختاره المستخدم. تبدأ بطاقة الإضافات مع اختيار Blender مسبقًا إذا كان موجودًا. وتظل البطاقة التي تحتوي خيارات تقبل إجابة مكتوبة. يتيح multi_select للمستخدم اختيار عدة صفوف. يُطبّق اختيار لون تمييز أو سمة أو تخطيط في التطبيق فور اختياره. تتضمن النتيجة outcome (submitted, typed, cancelled أو no_answer مع notice), picked (معرّف خيار، أو الإجابة الحرة، أو قائمة معرّفات مع multi_select), said (مع typed: كلمات مكتوبة في صندوق المحادثة لا تسمّي أي صف في البطاقة بالمعرّف أو التسمية؛ لا يُختار أو يُسجّل شيء)، و label (الاسم الذي عرضته البطاقة لكل اختيار، مثل Ultraviolet لـ #8a2be2) عندما يكون الاختيار أحد صفوف البطاقة. عندما لا تتاح قائمة الموصلات (لا هوية Nous، بعد محاولة تسجيل ضيف واحدة)، أو تكون قائمة الإضافات فارغة، يعيد الاستدعاء no_answer مع notice فورًا ولا يعرض بطاقة. يسجّل الاختيارات للتسليم: يسلّم start_chat التطبيقات والإضافات المختارة إلى محادثة المهمة، التي تتصل بها وتثبّتها أولًا. في أي مكان آخر، يعيد الاستدعاء خطأ.—

start_chat toolset

يُفعّل فقط عندما يذكره ملف الإعدادات الخاص بـ profile (platform_toolsets.cli). تحصل جلسات سطح المكتب وحدها على أداته؛ ولا تحصل عليها جلسات CLI أو hermes -z أو cron أو kanban أو المراسلة مطلقًا. لا يتضمنه all. لا يسرده hermes tools. ولا تحصل عليه subagents مطلقًا.

الأداةالوصفالبيئة المطلوبة
start_chatيفتح محادثة جديدة في تطبيق سطح المكتب ويرسل message بوصفها أول رسالة مستخدم. تعرض المحادثة المستدعية بطاقة بعنوان المحادثة الجديدة و profile الخاص بها وزر Open؛ ينقل التطبيق المستخدم إلى المحادثة الجديدة فقط عندما يشاهد المحادثة المستدعية، وإلا تظهر في الشريط الجانبي. تبدأ المحادثة الجديدة دون سجل. يجب أن يذكر profile اسم profile موجود (لا يُنشأ مطلقًا)؛ وإذا أُغفل، تعمل المحادثة في profile المستدعي نفسه. تأخذ المحادثة الجديدة إعداداتها من profile الخاص بها، لا من المستدعي مطلقًا. يسمّي title (حتى 40 محرفًا) المحادثة في الشريط الجانبي؛ وإذا أُغفل، تسمّي المحادثة نفسها. يفتح كل استدعاء محادثة أخرى: لا توجد إزالة لتكرار الاستدعاءات. يوسم استدعاء started من محادثة profile الإعداد في تطبيق سطح المكتب إلى profile آخر إعدادَ المستخدم الأولي بأنه مكتمل. النتيجة started مع session_id و profile للمحادثة الجديدة، أو rejected مع reason (profile مجهول، أو رسالة فارغة، أو عنوان طويل جدًا، أو الاستدعاء ليس من محادثة سطح المكتب).—

الجولات (Tours)

لإلقاء نظرة عامة على التطبيق، يُشغّل gui_tour(action='start') دون خطوات جولة تطبيق سطح المكتب المدمجة. يعرض preset='quick' أربعة عناصر أساسية (الجلسات ومحرّر الرسائل والجلسة الجديدة والنموذج)؛ ويضيف preset='full' (الافتراضي) محطات لوضع الواجهة الحالي. تُتجاوز المحطات التي لا يظهر عنصرها على الشاشة. لا تعمل الجولة المدمجة إلا على surface='app'، ولا يمكن الجمع بين preset و steps.

لجولة مخصّصة، تكتشف أداة gui_tour أهدافها بنفسها — استدعِ action='targets' فتُعيد كل عنصر قابل للتوجيه على الشاشة مع محدِّد (selector) وتسمية وعلامة stable. تعتمد المحدِّدات المستقرة على الهوية (data-tour، id، data-testid، aria-label) وتصمد أمام إعادة الرسم؛ أما مسارات nth-child الموضعية فلا تصمد، لذا تُرتَّب المستقرة أولًا وينبغي تفضيلها.

لمنح عنصر مقبضًا ثابتًا خاصًا بك، ضع له وسمًا:

تُطبَّق المقابض على العنصر الأساسي (primitive)، لا على موضع الاستدعاء، فتعديل واحد يسمّي كل نسخة منه. المقابض الموجودة حاليًا:

المقبضما يسمّيه
overlay-navشريط التنقّل الأيسر لأي تراكب مسار (route overlay) (الإعدادات، cron، profiles، الوكلاء)
nav-<id>صف واحد في ذلك التنقّل — nav-models، nav-appearance، …
field-<schemaKey>صف إعدادات واحد، بمفتاح إعداده — field-model، field-provider، …
page-tabsتبويبات التصفية على أي صفحة من نوع PageSearchShell (المخرجات (artifacts)، المهارات، …)
artifact-cardبطاقة مخرج (artifact) في الشبكة

عند إضافة سطح جديد، ضع وسمًا على عنصره الأساسي المشترك بالطريقة نفسها بدلًا من وسم الشاشات واحدة تلو الأخرى — يُبقي ذلك مفردات الجولة صغيرة ويمنع تعطّل المحدِّدات.

يشغّل المحرّك نفسه الجولات المُنسَّقة (غير التابعة للوكيل) في تطبيق سطح المكتب، بحيث يمكن لميزة أن تقدّم جولتها التعريفية الخاصة:

يمكن لخطوة أيضًا نقل التطبيق إلى حيث يوجد هدفها، وتعيد الجولة الأمور إلى ما كانت عليه عند انتهائها:

تأخذ navigate مسار route، وتأخذ pane اسم لوحة سطح مكتب. يُنفَّذ كلاهما عند الدخول في الخطوة، ويُنتظَر ظهور الأهداف التي تُحمَّل متأخرة، وإغلاق الجولة — بأي طريقة، بما في ذلك Esc — يعيد الأمور إلى حيث بدأت.

مرِّر 'preview' كوسيط ثانٍ للعمل على الصفحة في لوحة المعاينة بدلًا من التطبيق.

التلميحات (Tips)

التلميح هو خطوة جولة دون الإخراج الكامل: فقاعة واحدة، وسهم واحد، بلا حجب ولا شيء يُتصفَّح عبره. إنه الوزن المناسب لجملة تزداد وضوحًا بإشارة مباشرة إلى ما تتحدّث عنه — "اسم النموذج زرّ" — حيث لا يكون تعتيم التطبيق بأكمله مناسبًا.

تأخذ أداة show_tip المحدّدات نفسها التي يوردها gui_tour(action='targets')، لذا يكون الاكتشاف استدعاءً واحدًا لكليهما، ويكون data-tour الثابتة أعلاه الأهداف لكلتيهما. تلميح واحد يظهر على الشاشة في كل مرة؛ يحل تلميح جديد محل الأخير.

يمكن للتطبيق أيضًا عرض تلميحاته الخاصة، مستعرضًا كتالوجًا مدمجًا لميزات التطبيق بالترتيب، بوتيرة أشبه بتلميحات شاشة تحميل لعبة لا بإشعار: بعد بضع دقائق من بدء التشغيل في أبكر تقدير، ثم مرة واحدة على الأكثر كل ست ساعات، و فقط في لحظة خمول حقيقية. يشارك تلميح من Hermes فترة التهدئة تلك، لذا يمنح المستخدم أيضًا ست ساعات من الهدوء من التناوب. التناوب دورة واحدة فقط: يظهر كل تلميح من الكتالوج مرة واحدة، سواء انتهت مهلته أو أُغلق بعلامة ✕، وحين يأخذ كل تلميح دوره يصمت التطبيق. يعيد صف الإعدادات الدورة من البداية.

كل من التلميحات والجولات مفعّل افتراضيًا ويمكن إيقافه من Settings → Appearance (display.in_app_tips، display.in_app_tours). يشمل الإيقاف Hermes نفسه إضافة إلى التطبيق: يصل المفتاح إلى إعدادات gateway المتصلة وتترك الأداة مخطط النموذج، بحيث لا يُخبَر النموذج مطلقًا بسطح لا يُسمَح له باستخدامه. وكما هو الحال مع أي تغيير في المخطط، يسري ذلك في الجلسة التالية — تحتفظ محادثة جارية بالـ toolset التي بدأت بها، ويرفض التطبيق الاستدعاء في غضون ذلك.

toolset باسم video_gen

toolset اختيارية (غير مُحمَّلة في مجموعة hermes-cli الافتراضية). أضفها عبر --toolsets video_gen أو فعّلها من hermes tools → توليد الفيديو (Video Generation)، والذي يرشدك أيضًا خطوة بخطوة لاختيار خلفية (backend).

تُشحَن الخلفيات (backends) كإضافات (plugins) تحت plugins/video_gen/<name>/:

  • xAI Grok-Imagine — نص إلى فيديو وصورة إلى فيديو (مصادقة SuperGrok OAuth أو XAI_API_KEY).
  • FAL.ai — Veo 3.1 و Pixverse v6 و Kling 3.0 / O3 (يتطلب FAL_KEY).
  • OpenRouter — كل نموذج توليدي على واجهة فيديو OpenRouter (Veo 3.1، Sora 2 Pro، Kling 3، Seedance 2، Wan 3، Hailuo 3، Grok Imagine، FLUX 3 Video، …)؛ نص إلى فيديو، وصورة إلى فيديو، ومرجع إلى فيديو؛ يُجلَب الكتالوج وحدود كل نموذج مباشرة (يتطلب OPENROUTER_API_KEY أو بيانات اعتماد مضافة باستخدام hermes auth add openrouter، وتُحتسب على رصيدك في OpenRouter).
  • DeepInfra — كتالوج video-gen مباشر عبر نقطة نهاية الفيديوهات المتوافقة مع OpenAI (يتطلب DEEPINFRA_API_KEY).

تغطي أداة video_generate الواحدة كلا النمطين — مرِّر image_url لتحريك صورة ثابتة، أو أغفله للتوليد من النص وحده. يوجّه backend النشط تلقائيًا إلى endpoint الصحيح. كما في image_generate، يضبط المستخدم النموذج (video_gen.model) ولا يستطيع الوكيل اختياره — لا تأخذ أي أداة فيديو وسيط model. يُعاد بناء وصف الأداة عند بدء الجلسة ليعكس الإمكانات الفعلية للـ backend النشط (أنماط الإدخال ونسب العرض إلى الارتفاع والدقات ونطاق المدة والحد الأقصى للصور المرجعية ودعم الصوت). راجع إضافات مزوّدي توليد الفيديو لتأليف خلفية جديدة.
