معلومة

ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

فحص قواعد الكود باستخدام pygount

حلّل المستودعات لمعرفة عدد أسطر الكود، وتوزيع اللغات، وعدد الملفات، ونسب الكود إلى التعليقات باستخدام pygount.

متى تُستخدم

  • يطلب المستخدم عدد أسطر الكود (LOC)
  • يريد المستخدم توزيعًا للغات في مستودع
  • يسأل المستخدم عن حجم قاعدة الكود أو تركيبتها
  • يريد المستخدم نسب الكود إلى التعليقات
  • أسئلة عامة من نوع "ما حجم هذا المستودع"

المتطلبات الأساسية

1. ملخّص أساسي (الأكثر شيوعًا)

احصل على توزيع كامل للغات مع عدد الملفات وأسطر الكود وأسطر التعليقات:

مهم: استخدم دائمًا --folders-to-skip لاستبعاد أدلة الاعتماديات/البناء، وإلا ستزحف pygount عبرها وقد تستغرق وقتًا طويلًا جدًا أو تتجمّد.

2. الاستثناءات الشائعة للمجلدات

عدّل بحسب نوع المشروع:

3. التصفية حسب لغة محددة

4. ناتج تفصيلي ملفًا بملف

5. صيغ الناتج

6. تفسير النتائج

أعمدة جدول الملخّص:

  • Language — لغة البرمجة المكتشَفة
  • Files — عدد الملفات لتلك اللغة
  • Code — أسطر الكود الفعلي (القابل للتنفيذ/التصريحي)
  • Comment — الأسطر التي هي تعليقات أو توثيق
  • % — النسبة من الإجمالي

لغات زائفة خاصة:

  • __empty__ — ملفات فارغة
  • __binary__ — ملفات ثنائية (صور، ملفات مُصرَّفة، إلخ)
  • __generated__ — ملفات مُولَّدة تلقائيًا (تُكتشف استدلاليًا)
  • __duplicate__ — ملفات ذات محتوى متطابق
  • __unknown__ — أنواع ملفات غير معروفة

مزالق

  1. استبعد دائمًا .git، و node_modules، و venv — بدون --folders-to-skip، ستزحف pygount عبر كل شيء وقد تستغرق دقائق أو تتجمّد عند أشجار الاعتماديات الكبيرة.
  2. يُظهر Markdown صفر أسطر كود — تصنّف pygount كل محتوى Markdown كتعليقات، لا كود. هذا سلوك متوقّع.
  3. تُظهر ملفات JSON عدد أسطر كود منخفض — قد تحسب pygount أسطر JSON بتحفّظ. للحصول على عدد دقيق لأسطر JSON، استخدم wc -l مباشرة.
  4. المستودعات الأحادية الكبيرة (Monorepos) — للمستودعات الكبيرة جدًا، فكّر في استخدام --suffix لاستهداف لغات محددة بدلًا من فحص كل شيء.
