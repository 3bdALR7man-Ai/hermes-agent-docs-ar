إعداد مصادقة GitHub

تُعِدّ هذه المهارة المصادقة كي يتمكّن الوكيل من العمل مع مستودعات GitHub وطلبات pull request والمشكلات (issues) والتكامل المستمر (CI). وهي تغطّي مسارين:

  • git (متاح دائمًا) — يستخدم personal access tokens عبر HTTPS أو مفاتيح SSH
  • gh CLI (إن كان مثبّتًا) — وصول أغنى إلى API الخاص بـ GitHub مع مسار مصادقة أبسط

مسار الاكتشاف

عندما يطلب منك المستخدم العمل مع GitHub، نفّذ هذا التحقق أولًا:

شجرة القرار:

  1. إذا أظهر gh auth status أنّك مصادَق عليك ← أنت جاهز، استخدم gh لكل شيء
  2. إذا كان gh مثبّتًا لكن غير مصادَق عليه ← استخدم طريقة "gh auth" أدناه
  3. إذا لم يكن gh مثبّتًا ← استخدم طريقة "git فقط" أدناه (لا حاجة إلى sudo)

الطريقة 1: المصادقة باستخدام git فقط (بدون gh، بدون sudo)

تعمل هذه الطريقة على أي جهاز مثبّت عليه git. لا حاجة لصلاحيات الجذر (root).

الخيار أ: HTTPS مع Personal Access Token (موصى به)

هذه هي الطريقة الأكثر قابلية للنقل — تعمل في كل مكان، ولا تحتاج إلى إعداد SSH.

الخطوة 1: إنشاء personal access token

اطلب من المستخدم الانتقال إلى: https://github.com/settings/tokens

  • اضغط "Generate new token (classic)"
  • أعطه اسمًا مثل "hermes-agent"
  • اختر النطاقات (scopes):
    • repo (وصول كامل إلى المستودع — قراءة، كتابة، push، PRs)
    • workflow (تشغيل وإدارة GitHub Actions)
    • read:org (عند العمل مع مستودعات مؤسسة)
  • اضبط تاريخ انتهاء الصلاحية (90 يومًا خيار افتراضي جيد)
  • انسخ الـ token — لن يظهر مجددًا
