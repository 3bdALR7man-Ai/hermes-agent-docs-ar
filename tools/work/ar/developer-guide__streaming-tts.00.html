البث المتدفق لـ TTS

يمكن لـ Hermes بثّ صوت TTS فور وصوله من المزوّد، بدلًا من انتظار الصوت كاملًا قبل تشغيله. ويستخدم ذلك Voice Mode (المحادثة الحية في CLI/TUI)، واتصال speak-stream WebSocket في لوحة التحكم، وأي مهايئ منصة يختار البث الصوتي — عبر StreamingTTSConsumer في gateway. وتبدأ الردود الصوتية الكلام بعد أول عبارة بدلًا من انتظار التوليد والتركيب كاملين.

البنية المعمارية

يتكوّن pipeline البث من 4 أجزاء:

  1. المنتِج — يصدر LLM أجزاء نصية أثناء توليد الاستجابة
  2. مجزِّئ الجمل — يجمع tools.tts_streaming.SentenceChunker الأجزاء النصية، ويزيل كتل <think> (حتى عندما تنقسم بين الأجزاء)، ويفرّغ الجمل المكتملة
  3. مزوّد TTS — تحوّل نسخة مسجّلة من StreamingTTSProvider كل جملة إلى أجزاء PCM خام (int16 أحادي القناة بمعدل sample_rate الذي يعلنه المزوّد)
  4. مصبّ الصوت — sounddevice.OutputStream للتشغيل المحلي (tools.tts_tool_speaker.stream_tts_to_speaker)، أو نقطة التكامل write_streaming_tts في مهايئ منصة gateway (gateway/streaming_tts_consumer.py)

وحتى المزوّدون بلا API مجزّأ يحصلون على تشغيل لكل جملة عبر مسار text_to_speech_tool المتزامن المجرَّب، لذا يتيح edge (الافتراضي) محادثةً أيضًا. ويُنقَّح كل النص المنطوق باستخدام tools.tts_text_normalize.prepare_spoken_text (منقّح واحد لكل المسارات).

كيفية اختيار مزوّد

افتراضيًا، يبثّ الموزّع عبر المزوّد الذي ضبطته بالفعل (tts.provider) عندما يملك API مجزّأ — ولا يبدّل صوتك بصمت إلى مزوّد آخر لمجرد الحصول على البث.

للتجاوز، اضبط tts.streaming.provider في config.yaml لديك:

  • اسم مزوّد (elevenlabs أو gemini أو openai أو xai) يثبّت ذلك المزوّد المتدفق
  • auto يستعرض قائمة الأولوية elevenlabs → gemini → openai → xai ويستخدم أول مزوّد تتحدد بيانات اعتماده — اختيار صريح لـ "أفضل صوت مجزّأ متاح"

إضافة مزوّد بث جديد

  1. أنشئ فئة مشتقة من StreamingTTSProvider في tools/tts_streaming.py
  2. اضبط sample_rate (و channels / sample_width إذا لم يكن التنسيق int16 أحادي القناة)
  3. نفّذ available() (فحصًا خالصًا — لا تثبّت شيئًا أبدًا)، و stream(self, text) -> Iterator[bytes] التي تنتج أجزاء PCM خام
  4. أضف decorator @register("yourname")
  5. أضف اختبارات في tests/tools/test_tts_streaming.py

تفرض ABC العقد؛ ويتيح السجل اكتشاف المزوّد؛ ويتولى الموزّع (stream_tts_to_speaker) والمستهلك في gateway مخزن الجمل المؤقت وأحداث الإيقاف ومصبّ الصوت تلقائيًا.

مزوّدو الإضافات

تنضم نسخة TTSProvider لإضافة (مسجّلة باستخدام ctx.register_tts_provider()) إلى هذا المسار دون تغيير النواة. وتضبط streams_pcm = True وقيمة موجبة لـ stream_sample_rate ، وتنتج stream(text, format="pcm", voice=, model=, speed=) الخاصة بها PCM بتنسيق int16 أحادي القناة. وتكيّفها resolve_streaming_provider (tools.tts_streaming._PluginPCMStreamer) تحت قواعد التوجيه نفسها الخاصة بالموزّع المتزامن (tools.tts_tool_plugins): لا تصل الأسماء المدمجة إلى السجل أبدًا، ويسود مزوّد type: command بالاسم نفسه، وتحصل الإضافة على tts.voice / tts.model / tts.speed نفسها الخاصة بـ synthesize(). وتبثّ الإضافة المضبوطة أولًا. وتحت tts.streaming.provider: auto لا تُجرَّب إلا بعد قائمة الأولوية المدمجة. وتُقرَأ streams_pcm و stream_sample_rate و is_available() عند كل تحديد لمزوّد بث. وإذا كان المعدل مفقودًا أو أبلغ المزوّد عن عدم توفره، يحتفظ Hermes بالتركيب لكل جملة. وكما مع مزوّدي البث المدمجين، يجلب pipeline المتحدث حتى 3 جمل مسبقًا، لذا يجب أن تتحمل stream() الخاصة بالإضافة الاستدعاءات المتزامنة (فالمسار المتزامن يسلسل synthesize() ؛ أما هذا المسار فلا يفعل).

البث في Gateway (مهايئات المنصات)

gateway/streaming_tts_consumer.py يربط أجزاء الوكيل بنقطة تكامل البث الصوتي في المهايئ. وتختار المهايئات ذلك بتجاوز الآتي على BasePlatformAdapter:

  • supports_streaming_tts(chat_id, audio_format) -> bool
  • begin_streaming_tts / write_streaming_tts / finish_streaming_tts / abort_streaming_tts

تكون القيم الافتراضية لكل منها غير مدعومة/بلا إجراء، لذا لا تتغير المهايئات القائمة. وعند اكتمال البث الصوتي لدور، يُمنع رد auto-TTS كامل الملف لذلك الدور (بلا تشغيل مزدوج)؛ وعند فشل البث قبل سماع أي صوت، يعود gateway إلى الرد الصوتي القديم كامل الملف.
