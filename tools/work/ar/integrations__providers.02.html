Actual Computer

استخدم عتادك نفسه كعنقود inference خاص عبر Actual Computer. يتوفر وضعان للخدمة، كلاهما يستخدم Chat Completions لإعادة محتوى الاستدلال والمحتوى النهائي معًا:

  • وسيط مستضاف — https://api.actual.inc، بتشفير من طرف إلى طرف، يوجّه إلى عنقودك . صادِق باستخدام مفتاح inference ذي بادئة ac_ من actual.inc/user/keys.
  • daemon محلي — على الجهاز عند http://127.0.0.1:8080، ويعمل دون اتصال تمامًا. لا يلزم مفتاح API: يكتشف Hermes عنوان loopback الأساسي ويصادق تلقائيًا بقيمة بديلة داخلية.

خزّن إعدادات المزوّد في ~/.hermes/config.yaml؛ ولا يُحفظ في .envإلا مفتاح API الخاص بالخدمة المستضافة:

ملاحظات:

  • تأتي معرّفات النماذج من GET /v1/models في عنقودك — اكتشفها باستخدام hermes model أو curl -s https://api.actual.inc/v1/models -H "Authorization: Bearer $ACTUAL_API_KEY".
  • تُطبَّع عناوين المضيف المجرّدة في model.base_url : فيصبح http://127.0.0.1:8080 تلقائيًا http://127.0.0.1:8080/v1 . ويُستخدم متغير البيئة القديم ACTUAL_BASE_URL كخيار احتياطي عندما لا يُضبط URL لـ Actual في YAML.
  • يستخدم Actual /v1/chat/completions للمحادثة، والضغط، وتوليد العناوين، وكل المهام المساعدة الأخرى. وينطبق ذلك أيضًا على المزوّدين المخصّصين المستهدفين لـ api.actual.inc، والتبديل بين النماذج، والخيارات الاحتياطية. وتُتجاوز إعدادات Responses القديمة في إعدادات النموذج الرئيسي أو المزوّد المخصّص أو المهمة المساعدة تلقائيًا.
  • يُحصر جهد الاستدلال في النطاق الذي يدعمه Actual (none/low/medium/high/max) — فلا تؤدي قيمة عامة من xhigh/ultra إلى إخفاق الطلبات بخطأ 400.
  • النماذج المحلية الصغيرة: يمكن لـ toolset الافتراضية الكاملة في Hermes مع system prompt أن تتجاوز context window بحجم 32k، مما يسبب خطأ بث فارغ من خوادم عائلة llama.cpp. قلّص toolset (-t file,web) أو حمّل النموذج بسياق أكبر. وتغطي المهارة الاختيارية actual-setup (hermes skills install official/devops/actual-setup ) الإعداد واستكشاف الأخطاء وإصلاحها بالتفصيل.
  • الأسماء البديلة: actual-computer، actualcomputer، aci.

Hugging Face Inference Providers

يوجّه Hugging Face Inference Providers إلى أكثر من 20 نموذجًا مفتوحًا عبر endpoint موحّد متوافق مع OpenAI (router.huggingface.co/v1). تُوجَّه الطلبات تلقائيًا إلى أسرع خلفية متاحة (Groq و Together و SambaNova وغيرها) مع تبديل تلقائي عند الفشل (automatic failover).

أو اضبطه بشكل دائم في config.yaml:

احصل على token من huggingface.co/settings/tokens — تأكد من تفعيل صلاحية "Make calls to Inference Providers". تتوفر فئة مجانية (رصيد 0.10$ شهريًا، بلا هامش ربح إضافي على أسعار المزوّدين).

يمكنك إلحاق لواحق توجيه (routing suffixes) بأسماء النماذج: :fastest (الافتراضي)، أو :cheapest، أو :provider_name لفرض خلفية محدَّدة.

يمكن تجاوز الـ base URL عبر HF_BASE_URL.

تبديل النماذج باستخدام /model

hermes model مقابل /model

hermes model (يُشغَّل من الطرفية، خارج أي جلسة محادثة) هو معالج الإعداد الكامل للمزوّدين. استخدمه لإضافة مزوّدين جدد، وتشغيل تدفقات OAuth، وإدخال مفاتيح API، وضبط endpoints مخصّصة.

/model (يُكتَب داخل جلسة محادثة Hermes نشطة) يمكنه فقط التبديل بين المزوّدين والنماذج التي أعددتها بالفعل. لا يمكنه إضافة مزوّدين جدد، أو تشغيل OAuth، أو طلب مفاتيح API. إذا كنت قد أعددت مزوّدًا واحدًا فقط (مثل OpenRouter)، فسيعرض /model نماذج ذلك المزوّد فقط.

لإضافة مزوّد جديد: اخرج من جلستك (Ctrl+C أو /quit)، شغّل hermes model ، أعدّ المزوّد الجديد، ثم ابدأ جلسة جديدة.

يستخدم Ollama افتراضيًا أطوال سياق منخفضة جدًا

لا يستخدم Ollama نافذة السياق الكاملة لنموذجك افتراضيًا. اعتمادًا على ذاكرة VRAM لديك، القيمة الافتراضية هي:

VRAM المتاحةالسياق الافتراضي
أقل من 24 GB4,096 token
24–48 GB32,768 token
48+ GB256,000 token

يتطلّب Hermes Agent سياقًا لا يقل عن 64,000 token لاستخدام الوكيل مع الأدوات. تُرفَض النوافذ الأصغر عند بدء التشغيل لأن الـ system prompt وأنظمة الأدوات وحالة المحادثة الجارية تحتاج مساحة كافية لسير عمل موثوق متعدد الخطوات.

كيفية زيادتها (اختر إحدى الطرق):

لا يمكنك ضبط طول السياق عبر واجهة OpenAI-compatible API (/v1/chat/completions). يجب ضبطه من جهة الخادم أو عبر Modelfile. هذا هو مصدر اللبس الأول عند دمج Ollama مع أدوات مثل Hermes.

vLLM — استدلال GPU عالي الأداء

vLLM هو المعيار المتّبع لتقديم LLM في الإنتاج. الأفضل لـ: أقصى إنتاجية على عتاد GPU، وتقديم النماذج الكبيرة، والدُفعات المستمرة (continuous batching).

ثم اضبط Hermes:

طول السياق: يقرأ vLLM قيمة max_position_embeddings الخاصة بالنموذج افتراضيًا. إذا تجاوزت ذاكرة GPU لديك، يظهر خطأ ويطلب منك ضبط --max-model-len إلى قيمة أقل. يمكنك أيضًا استخدام --max-model-len auto للعثور تلقائيًا على أقصى قيمة تناسب العتاد. اضبط --gpu-memory-utilization 0.95 (الافتراضي 0.9) لحشر سياق أكبر في VRAM.

يتطلّب استدعاء الأدوات إعلامات صريحة:

العلامة (Flag)الغرض
--enable-auto-tool-choiceمطلوبة لـ tool_choice: "auto" (الافتراضي في Hermes)
--tool-call-parser <name>مُحلِّل (parser) لصيغة استدعاء الأدوات الخاصة بالنموذج

المُحلِّلات المدعومة: hermes (لـ Qwen 2.5 و Hermes 2/3)، و llama3_json (لـ Llama 3.x)، و mistral ، و deepseek_v3 ، و deepseek_v31 ، و xlam ، و pythonic. دون هذه الإعلامات، لن تعمل استدعاءات الأدوات — سيُخرج النموذج استدعاءات الأدوات كنص عادي.

مُحلِّلات استدلال Qwen: يحافظ Hermes على البيانات الوصفية للاستدلال المُهيكلة مثل reasoning و reasoning_content ودفعات الاستدلال المتدفقة (streamed reasoning deltas) عندما تعيدها الخوادم المتوافقة مع OpenAI. تُعامَل تلك البيانات الوصفية كمسار تفكير/استدلال، وليست بديلًا عن الإجابة المرئية للمساعد. بالنسبة لنماذج استدلال Qwen المُقدَّمة عبر vLLM، تأكد من أن الاستجابة النهائية المرئية للمستخدم لا تزال تظهر في content. إذا ترك --reasoning-parser qwen3 حقل content فارغًا في نشرك، إما عطّل ذلك المُحلِّل أو مرّر خيار طلب مدعومًا من الخادم مثل chat_template_kwargs.enable_thinking: false عبر extra_body.

نصيحة

يدعم vLLM الأحجام المقروءة للبشر: --max-model-len 64k (الحرف الصغير k يساوي 1000، والحرف الكبير K يساوي 1024).

إذا بدت الاستجابات مقتطعة، تحقّق من إعداد التوليد الافتراضي للخادم واضبطه من جهة الخادم (مثل --default-max-tokens في SGLang). لا يعرض Hermes إعداد سقف لعدد tokens المخرجات.

llama.cpp / llama-server — استدلال CPU و Metal

يشغّل llama.cpp نماذج مُكمَّمة (quantized) على CPU، و Apple Silicon (Metal)، وبطاقات GPU الاستهلاكية. الأفضل لـ: تشغيل النماذج دون GPU مركز بيانات، مستخدمي Mac، والنشر الطرفي (edge).

طول السياق (-c): تفترض الإصدارات الحديثة القيمة 0 افتراضيًا، والتي تقرأ سياق التدريب الخاص بالنموذج من بيانات GGUF الوصفية. بالنسبة للنماذج ذات سياق تدريب 128 ألف token أو أكثر، قد يتسبب هذا في نفاد الذاكرة (OOM) عند محاولة تخصيص ذاكرة KV المؤقتة الكاملة. اضبط -c صراحةً إلى 64,000 token على الأقل من أجل Hermes. إذا كنت تستخدم فتحات متوازية (-np)، يُقسَّم السياق الإجمالي بين الفتحات — فمع -c 64000 -np 4 ، تحصل كل فتحة على 16 ألف فقط، وهو أقل من الحد الأدنى لدى Hermes لكل جلسة نشطة.

هذا يحفظ الـ endpoint في config.yaml بحيث يبقى قائمًا عبر الجلسات.

--jinja مطلوب لاستدعاء الأدوات

دون --jinja ، يتجاهل llama-server معامل tools تمامًا. سيحاول النموذج استدعاء الأدوات بكتابة JSON في نص استجابته، لكن Hermes لن يتعرّف عليه كاستدعاء أداة — سترى JSON خامًا مثل {"name": "web_search", ...} مطبوعًا كرسالة بدلًا من بحث فعلي.

دعم استدعاء الأدوات الأصلي (أفضل أداء): Llama 3.x، و Qwen 2.5 (بما فيه Coder)، و Hermes 2/3، و Mistral، و DeepSeek، و Functionary. تستخدم بقية النماذج معالجًا عامًا يعمل لكنه قد يكون أقل كفاءة. راجع وثائق استدعاء الدوال في llama.cpp للاطلاع على القائمة الكاملة.

يمكنك التحقق من تفعيل دعم الأدوات عبر مراجعة http://localhost:8080/props — يجب أن يكون حقل chat_template موجودًا.

LM Studio — تطبيق سطح مكتب بنماذج محلية

ابدأ الخادم من تطبيق LM Studio (تبويب Developer → Start Server)، أو استخدم CLI:

ثم اضبط Hermes:

يحافظ Hermes على سياق نسخة LM Studio المحمَّلة بالفعل. بالنسبة لنموذج غير محمَّل في الوضع الصريح الافتراضي، يهمل Hermes context_length ما لم تكن قد ضبطت واحدًا في Hermes، بحيث يستطيع LM Studio تطبيق إعداده الخاص بالنموذج. يستخدم Hermes بعدها فقط طول السياق الذي يبلّغ عنه LM Studio بعد التحميل.

لتغيير طول السياق في LM Studio:

  1. انقر أيقونة الترس بجانب منتقي النموذج
  2. اضبط "Context Length" على 64000 على الأقل لتجربة سلسة
  3. أعد تحميل النموذج ليصبح التغيير ساري المفعول
  4. إذا لم يستوعب جهازك 64000، فكّر في استخدام نموذج أصغر بطول سياق أكبر.

بديلًا عن ذلك، استخدم CLI: lms load model-name --context-length 64000
