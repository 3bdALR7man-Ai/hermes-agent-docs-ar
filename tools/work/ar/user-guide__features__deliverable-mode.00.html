Deliverable Mode

عندما يعمل Hermes Agent داخل gateway للمراسلة (Slack و Discord و Telegram و WhatsApp و Signal وغيرها)، يمكنه تسليم الملفات المُولَّدة مباشرة إلى المحادثة — لا بوصفها مسارات يحتاج المستخدم إلى نسخها، بل كمرفقات أصلية.

يظهر المخطط كصورة ضمن الرسالة. ويظهر تقرير PDF كملف قابل للتنزيل. ويُرفع جدول البيانات بصيغة .xlsx. ولا يحتاج الوكيل إلى كتابة وسم MEDIA: أو فعل أي شيء خاص — بل يولّد الملف فحسب ويذكر مساره المطلق في الرد. يلتقط الـ gateway المسار من النص، ويحذفه من الرسالة الظاهرة، ويرفع الملف بالطريقة الأصلية للمنصة.

آلية العمل

تتكامل ثلاثة عناصر معًا:

  1. يمتلك الوكيل أدوات تنتج ملفات. execute_code للمخططات عبر matplotlib، ومهارة docx لمستندات Word، ومهارة xlsx لـ جداول البيانات، ومهارتَي pdf و latex-pdf-report لملفات PDF، ومهارة powerpoint للعروض التقديمية، و image_generate للصور، و text_to_speech للصوت، وما إلى ذلك.

  2. يفحص الـ gateway ردود الوكيل بحثًا عن مسارات الملفات. ويستخرج أي مسار مطلق (~/.hermes/cache/scratch/...) أو مسار نسبي إلى المجلد الرئيسي (~/...) ينتهي بامتداد مدعوم. ويتجاهل المسارات داخل كتل الكود والكود المضمّن حتى لا تتشوّه أمثلة الكود مطلقًا.

  3. يوجّه الـ gateway الملف بحسب نوعه. تُضمَّن الصور داخل الرسالة حيث تدعم المنصة ذلك؛ وتُضمَّن الفيديوهات داخل الرسالة؛ ويُوجَّه الصوت إلى مرفقات صوتية أو رسائل صوتية؛ ويُرفع كل ما عدا ذلك كمرفق ملف.

تشجيع الوكيل على إنتاج المُخرَجات (artifacts)

لا يلجأ الوكيل إلى إنتاج المُخرَجات افتراضيًا — بل يحتاج إلى أن يعرف أن عليه ذلك. طريقتان لتوجيهه إلى ذلك:

على مستوى الجلسة: اطلب ذلك صراحةً ("أرسل لي المقارنة في مخطط"، "أعد البيانات بصيغة CSV") أو اكتب تعليمات مخصّصة / مدخلًا للشخصية يفضّل الردود في صورة مُخرَجات على منصات المراسلة.

على مستوى المشروع: أضف هذا التفضيل إلى AGENTS.md / CLAUDE.md / .cursorrules في المشروع الذي يعمل منه الوكيل، أو إلى شخصيتك العامة في ~/.hermes/SOUL.md، أو كإعداد مسبق مُسمّى ضمن agent.personalities في ~/.hermes/config.yaml (يمكن التبديل إليه لكل جلسة عبر /personality).

الآلية التي على الوكيل استخدامها بسيطة: أنشئ الملف في مسار مطلق (مثل ~/.hermes/cache/scratch/q3-revenue.png)، واذكر هذا المسار كنص عادي في الرد. يتولى الـ gateway الباقي. وتُتجاهل المسارات داخل كتل الكود المسيّجة أو علامات backtick حتى لا تتشوّه أمثلة الكود أبدًا.

Kanban: المُخرَجات ترافق إشعارات الإنجاز

إذا استخدمت سير عمل Kanban متعدد الوكلاء في Hermes، فيمكن للعاملين إرفاق ملفات التسليم باستدعاء kanban_complete الخاص بهم:

عندما يسلّم مُرسِل إشعارات الـ gateway رسالة "task completed" إلى من اشترك في المهمة في Slack/Telegram/غيرها، فإنه يرفع أيضًا كل مُخرَج كمرفق أصلي إلى تلك المحادثة. ويحصل الشخص على ملف التسليم و الملخّص في مكان واحد.

الملفات غير الموجودة على القرص عند تشغيل مُرسِل الإشعارات تُتجاوَز بصمت.

ربط مزيد من الخدمات عبر MCP

بالإضافة إلى pipeline تسليم المُخرَجات، يستطيع الوكيل الوصول إلى خدمات أخرى عبر MCP (Model Context Protocol). وتوفر منظومة MCP خوادم مجتمعية لمعظم الأدوات الشائعة — ثبّت ما تحتاج إليه منها:

الخدمةما تتيحه
Notionقراءة صفحات Notion وقواعد بياناتها والكتابة فيها، والاستعلام عن مساحة العمل
GitHubIssues و PRs والتعليقات والبحث في المستودعات بما يتجاوز gh CLI
Linearالتذاكر والمشاريع والدورات (cycles)
Slackالبحث على مستوى مساحة العمل كلها، وقراءة القنوات الأخرى
Gmailفرز البريد الوارد، وإرسال البريد، وإدارة التصنيفات
Salesforceالعملاء المحتملون (leads) والفرص (opportunities) وبيانات الحسابات
Snowflake / BigQueryاستعلامات SQL على مستودعات البيانات
Google Driveالبحث عن الملفات، ومحتوياتها، وإدارة المشاركة

ثبّت خوادم MCP عبر ~/.hermes/config.yaml ضمن قسم mcp_servers . راجع التكامل مع MCP للاطلاع على دليل الإعداد الكامل.

مقارنة مع Perplexity Computer في Slack

يستند تكامل Perplexity Computer مع Slack إلى الفكرة نفسها: يولّد الوكيل ملف تسليم (مخططًا، أو PDF، أو عرض شرائح) ويرسله إلى سلسلة الرسائل كمرفق أصلي. ويوفر Deliverable Mode في Hermes Agent نمط الاستخدام نفسه محليًا:

  • يجري التوليد داخل venv / sandbox الخاص بالمستخدم نفسه (دون مستأجر بعيد).
  • تصل الملفات إلى المحادثة عبر API نفسه في Slack: files.uploadV2.
  • يتحقق تنوّع الموصلات عبر MCP بدلًا من كتالوج منتقى يضم 400 تكامل مستضاف — ثبّت تلك التي تستخدمها فعليًا.

تبقى OAuth tokens على جهاز المستخدم في auth.json / .env. ولا يوجد تخزين مستضاف للـ tokens. ولا توجد microVM متعددة المستأجرين. والنتيجة النهائية واحدة.
