Archify (بصيانة upstream)

مدخل كتالوج (catalog stub). يُصان هذا المدخل في upstream على tt-a1i/archify: يشحن المشروع دليل مهارة مكتفٍ ذاتيًا (archify/) يضم Node CLI والمخططات (schemas) ومحرّكات العرض (renderers) والأمثلة والمراجع. يسحب hermes skills install official/creative/archify الشجرة الحالية مباشرة من ذلك المستودع (بحجر صحي (quarantine) وفحص كأي تثبيت من hub) — لا يحتوي هذا الدليل سوى بيانات الكتالوج الوصفية، لذا لا يمكن للنسخة المُدرَجة (vendored) أن تصبح قديمة أبدًا.

يحوّل Archify مواصفات JSON مصغَّرة ومكتوبة النوع (typed) إلى مخطط HTML مكتفٍ ذاتيًا وقابل للاستكشاف: بأنواع architecture وworkflow وsequence وdataflow وlifecycle (آلة الحالات)، ومظاهر داكنة/فاتحة، والتحريك والتكبير (pan/zoom)، والبحث، وتتبّع العلاقات، وحركة تتبّع اختيارية، وتصدير بصيغ PNG/JPEG/WebP/SVG/WebM. يقبل متطلبات بلغة طبيعية أو محتوى Mermaid ملصق (flowchart، sequenceDiagram، stateDiagram) ويمكنه قراءة أدلة من المستودع (repository evidence) عندما يجب أن يعكس المخطط كودًا فعليًا. يمرّ كل مرشّح عبر إيصال (receipt) من 9 فحوصات validate / deliver، لذا يكون الناتج قابلًا للتحقق لا مجرد تقدير بصري.

المتطلبات الأساسية

  • Node.js 18+ على PATH (يؤكد node bin/archify.mjs doctor التثبيت؛ لا حاجة إلى npm install داخل حزمة المهارة).
  • تسحب عمليات التثبيت نحو 200 ملف (~8 ميغابايت، معظمها اختبارات وأمثلة من upstream) من GitHub؛ الجلب مثبَّت على SHA شجرة واحد، مسجَّل في بيانات الحزمة الوصفية.
  • تشغّل خطوة "الوعي بالتحديثات" (Update awareness) الخاصة بـ upstream السكربت scripts/check-update.mjs، الذي يقرأ بيان إصدار (release manifest) من GitHub ويكتفي بطباعة إشعار — لا يقوم أبدًا بتنزيل أو تثبيت أي شيء. تخطَّها إذا لم تُرغب في اتصالات صادرة.

بعد التثبيت، تظل مهارة architecture-diagram المضمّنة (bundled) هي البديل الخالي من الاعتماديات (وهي تنقل نفس أصل Cocoon AI الذي نشأ منه archify)؛ فضّل archify عندما يريد المستخدم إيصالات موثَّقة، أو تحويل Mermaid، أو أنواع sequence/lifecycle، أو تصديرًا يتجاوز ملف HTML واحد.
