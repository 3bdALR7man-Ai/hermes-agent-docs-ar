AgentMail Skill

تمنح AgentMail الوكيل صندوق بريد إلكتروني خاصًا به لإرسال الرسائل، واستقبال الردود، وإتمام تدفقات OTP عبر البريد الإلكتروني، وتشغيل حلقات بريد واردة. استخدمها لصناديق البريد المملوكة للوكيل، لا لصندوق بريد IMAP/SMTP موجود لدى المستخدم.

استخدم CLI الخاص بـ agentmail أولًا. استخدم MCP فقط عندما يتوقّع إطار العمل أدوات MCP؛ استخدم REST فقط عندما يفتقد CLI عملية مطلوبة.

متى تُستخدم

  • يحتاج الوكيل إلى عنوان بريد إلكتروني يملكه.
  • تتضمّن المهمة تدفقات OTP عبر البريد، أو ردودًا، أو محادثات (threads)، أو تصنيفات، أو مرفقات.
  • يحتاج الوكيل إلى تسليم عبر webhook أو WebSocket للبريد الوارد.

استخدم --format json كلما احتاج أمر أو سكربت آخر إلى المعرّفات (IDs).

مرجع سريع

  • websockets.md: أحداث إلى عملية وكيل محلية.
  • mcp.md: التكامل مع MCP.

الإجراء

  1. ثبّت agentmail-cli@latest وتحقّق بالأمر agentmail inboxes list --format json.
  2. إذا لم يتوفّر مفتاح API، أكمل signup.md.
  3. استخدم core.md لتدفقات صندوق البريد، والإرسال، والقراءة، والرد، والتحويل، والتصنيف، والمحادثات، والمرفقات.
  4. أضِف webhooks.md أو websockets.md فقط عندما لا يكفي الاستطلاع الدوري (polling).

المزالق الشائعة

  • فضّل AGENTMAIL_API_KEY على --api-key.
  • لا تكشف أبدًا AGENTMAIL_API_KEY في الـ prompts، أو السجلات، أو الروابط، أو الملفات المرفوعة إلى commit.
  • استخدم قيم client_id ثابتة لعمليات الإنشاء التي تُعاد محاولتها.
  • فضّل extracted_text أو extracted_html كمُدخل للـ LLM عند توفّرهما.
  • تفاعل مع message.received، لا مع الرسائل التي أرسلها الوكيل.
