إعداد Nix و NixOS

منصة من المستوى 2

تُعد Nix و NixOS منصات من المستوى 2 (Tier 2). يُصان الـ flake ووحدة NixOS الموثّقان هنا بأفضل جهد فقط. وقد تؤدي عمليات commit إلى main إلى تعطيل هذه الحزم في أي وقت.

للحصول على إعداد مدعوم، استخدم أحد مسارات التثبيت القياسية - إما Docker أو بيئة FHS.

يوفّر Hermes Agent كلًّا من Nix flake، ووحدة NixOS، ووحدة Home Manager.

ما الذي يختلف عن التثبيت القياسي

يدير المُثبّت curl | bash كلًّا من Python و Node والاعتماديات بنفسه. أما Nix flake فيحلّ محل كل ذلك — فكل اعتمادية Python هي Nix derivation يبنيها uv2nix، وأدوات وقت التشغيل (Node.js و git و ripgrep و ffmpeg) مُضمَّنة في PATH الخاص بالملف التنفيذي. لا يوجد pip وقت التشغيل، ولا تفعيل لـ venv، ولا npm install.

لمستخدمي غير NixOS، لا يتغير سوى خطوة التثبيت. فكل ما يليها (hermes setup، hermes gateway install، تعديل الإعدادات) يعمل تمامًا كما في التثبيت القياسي.

لمستخدمي وحدة NixOS، تختلف دورة الحياة بأكملها: الإعدادات موجودة في configuration.nix، والأسرار تمر عبر sops-nix/agenix، والخدمة عبارة عن وحدة systemd، وأوامر الإعدادات في CLI محظورة. تدير hermes بالطريقة نفسها التي تدير بها أي خدمة NixOS أخرى.

وحدة NixOS

يُصدِّر الـ flake الوحدة nixosModules.default — وهي وحدة خدمة NixOS كاملة تدير بشكل تصريحي إنشاء المستخدم، والمجلدات، وتوليد الإعدادات، والأسرار، والمستندات، ودورة حياة الخدمة.

ملاحظة

تحتاج هذه الوحدة إلى NixOS. إن Hermes وكيل لشخص واحد. إذا أردت وكيلًا لشخص واحد وليس خدمة نظام، فاستخدم وحدة Home Manager. تعمل تلك الوحدة على NixOS وعلى كل نظام آخر يدعمه Home Manager.

الإعدادات الدنيا

الأسرار مطلوبة

يفترض سطر environmentFiles أعلاه أنك قد أعددت sops-nix أو agenix. يجب أن يحتوي الملف على مفتاح واحد على الأقل لمزوّد LLM (مثل OPENROUTER_API_KEY=sk-or-...). راجع إدارة الأسرار للإعداد الكامل. إذا لم يكن لديك مدير أسرار بعد، فيمكنك استخدام ملف عادي كنقطة بداية — فقط تأكد من أنه غير قابل للقراءة من قِبل الجميع:

addToSystemPackages

يؤدي ضبط addToSystemPackages = true إلى أمرين: يضع hermes CLI ضمن PATH الخاص بالنظام و يضبط HERMES_HOME على مستوى النظام بحيث تتشارك واجهة CLI التفاعلية الحالة (الجلسات، والمهارات، و cron) مع خدمة gateway. ومن دونه، يؤدي تشغيل hermes في الـ shell إلى إنشاء مجلد ~/.hermes/ منفصل.

الإعدادات

الإعدادات التصريحية

يقبل الخيار settings مجموعة سمات (attrset) عشوائية تُحوَّل إلى config.yaml. ويدعم الدمج العميق عبر تعريفات وحدات متعددة (من خلال lib.recursiveUpdate)، لذا يمكنك تقسيم الإعدادات على عدة ملفات:

يُدمج كلاهما دمجًا عميقًا وقت التقييم. تتغلب المفاتيح المُعرَّفة في Nix دائمًا على المفاتيح الموجودة في ملف config.yaml الحالي على القرص، لكن المفاتيح التي يضيفها المستخدم ولا يمسّها Nix تبقى محفوظة. وهذا يعني أنه إذا أضاف الوكيل أو تعديل يدوي مفاتيح مثل skills.disabled أو streaming.enabled، فإنها تبقى بعد nixos-rebuild switch.

تسمية النماذج

يستخدم settings.model.default معرّف النموذج الذي يتوقعه المزوّد. مع OpenRouter (الافتراضي)، تبدو المعرّفات مثل "anthropic/claude-sonnet-4" أو "google/gemini-3-flash". إذا كنت تستخدم مزوّدًا مباشرةً (Anthropic، OpenAI)، فاضبط settings.model.base_url ليشير إلى API الخاص به، واستخدم معرّفات النماذج الأصلية لديه (مثل "claude-sonnet-4-20250514"). وعندما لا يكون base_url مضبوطًا، يستخدم Hermes مزوّد OpenRouter افتراضيًا.

اكتشاف مفاتيح الإعدادات المتاحة

نفّذ nix build .#configKeys && cat result لعرض كل مفتاح إعدادات نهائي مُستخرج من DEFAULT_CONFIG في Python. يمكنك لصق ملف config.yaml الحالي داخل الـ attrset الخاص بـ settings — فالبنية متطابقة بنسبة 1:1.

إدارة الأسرار

لا تضع مفاتيح API أبدًا في settings أو environment

تنتهي القيم الموجودة في تعبيرات Nix داخل /nix/store، وهو قابل للقراءة من قِبل الجميع. استخدم دائمًا environmentFiles مع مدير أسرار.

يُدمج كل من environment (متغيرات غير سرية) و environmentFiles (ملفات سرية) في $HERMES_HOME/.env وقت التفعيل (nixos-rebuild switch). يقرأ Hermes هذا الملف عند كل بدء تشغيل، لذا تسري التغييرات بتنفيذ systemctl restart hermes-agent — دون الحاجة إلى إعادة إنشاء الحاوية.

يحتاج documents إلى workingDirectory صريح

ترفض الوحدة documents إلى أن تضبط workingDirectory. تختلف القيمة الافتراضية لهذا الخيار في كل وحدة: فهي مجلد home الخاص بك في Home Manager، و ${stateDir}/workspace في NixOS. ولذلك فإن ترك القيمة الافتراضية دون ضبط يضع الملفات في مجلد لم تختره أنت. أما اختيار مجلد له المسار نفسه للقيمة الافتراضية فهو اختيار صحيح، ويستوفي القاعدة.

يثبّت hermesHomeFiles الملفات في HERMES_HOME. يقرأ Hermes ملف الهوية وملفات الذاكرة الخاصة بالوكيل من ذلك المجلد. لا يعمل SOUL.md و memories/ إلا من هناك. أما وضع SOUL.md في documents فينشئ ملفًا في مساحة العمل، ولا يحمّل Hermes ذلك الملف كهوية:

كل قيمة إما نص (string) أو مسار. يمكن أن يحتوي المفتاح في أي من الخيارين على مجلدات فرعية، وتنشئ الوحدة المجلدات الأم. ويعيد كل تفعيل تثبيت الملفات من جديد.

لا يحتاج hermesHomeFiles إلى workingDirectory، لأن الوحدة تملك المجلد HERMES_HOME. ومعظم المستخدمين يحتاجون إلى hermesHomeFiles.

خوادم MCP

يضبط الخيار mcpServers بشكل تصريحي خوادم MCP (Model Context Protocol). يستخدم كل خادم إما وسيلة النقل stdio (أمر محلي) أو HTTP (عنوان URL بعيد).

النقل عبر Stdio (خوادم محلية)

نصيحة

تُستبدل متغيرات البيئة الواردة في قيم env من $HERMES_HOME/.env وقت التشغيل. استخدم environmentFiles لحقن الأسرار — ولا تضع tokens مباشرةً في إعدادات Nix أبدًا.

النقل عبر HTTP (خوادم بعيدة)

النقل عبر HTTP مع OAuth

اضبط auth = "oauth" للخوادم التي تستخدم OAuth 2.1. ينفّذ Hermes تدفق PKCE الكامل — اكتشاف البيانات الوصفية (metadata)، والتسجيل الديناميكي للعميل، وتبادل token، والتحديث التلقائي.

تُخزَّن tokens في $HERMES_HOME/mcp-tokens/<server-name>.json وتبقى محفوظة بعد إعادة التشغيل وإعادة البناء.

تفويض OAuth الأولي على الخوادم التي تعمل دون واجهة (headless)

يتطلب تفويض OAuth الأول تدفق موافقة عبر المتصفح. في عمليات النشر دون واجهة، يطبع Hermes عنوان URL الخاص بالتفويض في stdout/السجلات بدلًا من فتح متصفح.
