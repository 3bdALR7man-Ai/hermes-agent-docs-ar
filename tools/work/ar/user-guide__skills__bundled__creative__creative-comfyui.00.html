معلومة

ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

ComfyUI

ولّد الصور والفيديو والصوت والمحتوى ثلاثي الأبعاد عبر ComfyUI باستخدام comfy-cli الرسمي للإعداد ودورة حياة الخدمة، و REST/WebSocket API المباشر لتنفيذ تدفقات العمل (workflows).

ما تحتويه هذه المهارة

وثائق مرجعية (references/):

  • official-cli.md — كل أوامر comfy ... مع خياراتها (flags)
  • rest-api.md — نقاط REST و WebSocket (محليًا وعلى السحابة)، ومخططات الحمولة (payload)
  • workflow-format.md — صيغة JSON بتنسيق API، أنواع العُقد الشائعة، وربط المعاملات
  • template-integrity.md — تحويل comfyui-workflow-templates من تنسيق المحرر إلى تنسيق API: تجاوز Reroute، مفاتيح المدخلات الديناميكية المنقّطة (values.a, resize_type.width)، خصائص Cloud (إعادة توجيه 302، مهمة واحدة متزامنة على المستوى المجاني، سقف VRAM عند 1080p)، ودمج ffmpeg المتوافق مع Discord. من تأليف @purzbeats. حمّل هذا الملف كلما بدأت من قالب رسمي.

متى تستخدمها

  • عندما يطلب المستخدم توليد صور بـ Stable Diffusion أو SDXL أو Flux أو SD3 وغيرها.
  • عندما يريد المستخدم تشغيل ملف تدفق عمل ComfyUI محدد.
  • عندما يريد المستخدم ربط خطوات توليد متسلسلة (txt2img ← ترقية ← استعادة الوجه).
  • عندما يحتاج المستخدم إلى ControlNet أو inpainting أو img2img أو أنابيب متقدمة أخرى.
  • عندما يطلب المستخدم إدارة قائمة انتظار ComfyUI، أو فحص النماذج، أو تثبيت عُقد مخصّصة.
  • عندما يريد المستخدم توليد فيديو/صوت/محتوى ثلاثي الأبعاد عبر AnimateDiff أو Hunyuan أو Wan أو AudioCraft وغيرها.

البنية المعمارية: طبقتان

لماذا طبقتان؟ الـ CLI الرسمي ممتاز للتثبيت وإدارة الخادم لكنه يقدّم دعمًا محدودًا لتنفيذ تدفقات العمل. تسدّ REST/WS API تلك الفجوة — إذ تتولى السكربتات حقن المعاملات، ومراقبة التنفيذ، وتنزيل المخرجات، وهو ما لا يقوم به الـ CLI.

الإعداد والانضمام

عندما يطلب المستخدم إعداد ComfyUI، أول شيء ينبغي فعله هو سؤاله عمّا إذا كان يريد Comfy Cloud (مُستضاف، بلا تثبيت، بمفتاح API) أو محليًا (تثبيت ComfyUI على جهازه). لا تبدأ بتشغيل أوامر التثبيت أو فحوصات العتاد قبل أن يجيب.

الوثائق الرسمية: https://docs.comfy.org/installation وثائق CLI: https://docs.comfy.org/comfy-cli/getting-started وثائق Cloud: https://docs.comfy.org/get_started/cloud Cloud API: https://docs.comfy.org/development/cloud/overview

الخطوة 0: اسأل عن محلي مقابل Cloud (دائمًا أولًا)

نص مقترح:

"هل تريد تشغيل ComfyUI محليًا على جهازك، أم استخدام Comfy Cloud؟

  • Comfy Cloud — مُستضاف على وحدات معالجة رسومية RTX 6000 Pro، مع كل النماذج الشائعة مثبّتة مسبقًا، وبلا أي إعداد. يتطلب مفتاح API (اشتراك مدفوع مطلوب لتشغيل تدفقات العمل فعليًا؛ المستوى المجاني للقراءة فقط). الأنسب إن لم يكن لديك GPU كافٍ.
  • محليًا — مجاني، لكن يجب أن يستوفي جهازك متطلبات العتاد:
    • GPU من NVIDIA بذاكرة ≥6 GB VRAM (≥8 GB لـ SDXL، ≥12 GB لـ Flux/الفيديو)، أو
    • GPU من AMD يدعم ROCm (Linux)، أو
    • Mac بمعالج Apple Silicon (M1 فما فوق) بذاكرة موحّدة ≥16 GB (يُنصح بـ ≥32 GB).
    • أجهزة Mac بمعالج Intel والأجهزة بلا GPU لن تعمل — استخدم Cloud بدلًا من ذلك.

أيهما تفضّل؟"

التوجيه:

  • Cloud ← انتقل إلى المسار A.
  • محليًا ← نفّذ فحص العتاد أولًا، ثم اختر مسارًا من المسارات B–E بناءً على النتيجة.
  • غير متأكد ← نفّذ فحص العتاد ودع النتيجة تقرر.

خصائص Cloud

  • الرابط الأساسي: https://cloud.comfy.org
  • المصادقة: ترويسة X-API-Key (أو ?token=KEY لـ WebSocket)
  • مفتاح API: اضبط $COMFY_CLOUD_API_KEY مرة واحدة وتلتقطه السكربتات تلقائيًا
  • تنزيل المخرجات: يُعيد /api/view إعادة توجيه 302 إلى رابط موقّع؛ تتبع السكربتات ذلك الرابط وتزيل X-API-Key قبل الجلب من خدمة التخزين (كي لا يتسرّب مفتاح API إلى S3/CloudFront).
  • الفروقات في نقاط النهاية (endpoints) مقارنة بـ ComfyUI المحلي:
    • /api/object_info, /api/queue, /api/userdata — 403 على المستوى المجاني؛ مدفوعة فقط.
    • يُعاد تسمية /history إلى /history_v2 على السحابة (توجّهها السكربتات تلقائيًا).
    • يُعاد تسمية /models/<folder> إلى /experiment/models/<folder> على السحابة (توجّهها السكربتات تلقائيًا).
    • يُتجاهل حاليًا clientId في WebSocket — كل الاتصالات لمستخدم واحد تستلم نفس البث. صفِّ حسب prompt_id من جانب العميل.
    • يُقبل subfolder عند الرفع لكن يُتجاهل — تستخدم السحابة مساحة أسماء مسطّحة.
  • المهام المتزامنة: Free/Standard: 1، Creator: 3، Pro: 5. المهام الإضافية تدخل قائمة الانتظار تلقائيًا. استخدم run_batch.py --parallel N لاستغلال مستواك بالكامل.

إدارة قائمة الانتظار والنظام

المزالق

  1. تنسيق API مطلوب — يتوقّع كل سكربت ونقطة النهاية /api/prompt أن يكون JSON تدفق العمل بتنسيق API. تكتشف السكربتات تنسيق المحرر (مصفوفتا nodes و links على المستوى الأعلى) وتطلب منك إعادة التصدير عبر "Workflow → Export (API)" (الواجهة الأحدث) أو "Save (API Format)" (الواجهة الأقدم).

  2. يجب أن يكون الخادم قيد التشغيل — كل عمليات التنفيذ تتطلب خادمًا حيًا. يشغّل comfy launch --background واحدًا. تحقّق بـ curl http://127.0.0.1:8188/system_stats.

  3. أسماء النماذج دقيقة — حساسة لحالة الأحرف، وتشمل امتداد الملف. يقوم check_deps.py بمطابقة تقريبية (مع/بدون الامتداد وبادئة المجلد)، لكن يجب أن يستخدم تدفق العمل نفسه الاسم القانوني (canonical). استخدم comfy model list لمعرفة ما هو مثبّت.

  4. عُقد مخصّصة مفقودة — تعني رسالة "class_type not found" أن عقدة مطلوبة غير مثبّتة. يُبلّغ check_deps.py بأي حزمة يجب تثبيتها؛ ويشغّل auto_fix_deps.py التثبيت نيابة عنك.

  5. دليل العمل (working directory) — يكتشف comfy-cli مساحة عمل ComfyUI تلقائيًا. إذا فشلت الأوامر برسالة "no workspace found"، استخدم comfy --workspace /path/to/ComfyUI <command> أو comfy set-default /path/to/ComfyUI.

  6. حدود API للمستوى المجاني على Cloud — تُعيد /api/prompt, /api/view, /api/upload/*, /api/object_info كلها 403 على الحسابات المجانية. يتعامل health_check.py و check_deps.py مع ذلك بسلاسة ويعرضان رسالة واضحة.

  7. مهلة تدفقات عمل الفيديو/الصوت — تُكتشف تلقائيًا عندما تكون عقدة المخرجات VHS_VideoCombine أو SaveVideo وغيرها؛ ترتفع القيمة الافتراضية من 300 ثانية إلى 900 ثانية. تجاوزها صراحة بـ --timeout 1800.

  8. اجتياز المسارات (path traversal) في أسماء ملفات المخرجات — تمرّ أسماء الملفات القادمة من الخادم عبر safe_path_join لرفض أي شيء يخرج عن --output-dir. أبقِ هذه الحماية مفعّلة — إذ يمكن لتدفقات العمل ذات عُقد الحفظ المخصّصة أن تنتج مسارات عشوائية.

  9. JSON تدفق العمل كود تعسّفي — تشغّل العُقد المخصّصة كود Python، لذا فإرسال تدفق عمل مجهول له نفس مستوى الثقة الخطر لأمر eval. افحص تدفقات العمل من مصادر غير موثوقة قبل تشغيلها.

  10. بذرة عشوائية تلقائيًا — مرّر seed: -1 في --args (أو استخدم --randomize-seed واحذف seed) للحصول على بذرة جديدة في كل تشغيل. تُسجَّل البذرة الفعلية إلى stderr.

  11. مُوجِّه tracking — قد يطلب أول تشغيل لـ comfy إذنًا للتحليلات. استخدم comfy --skip-prompt tracking disable لتخطّي ذلك بشكل غير تفاعلي. يقوم comfyui_setup.sh بهذا نيابة عنك.
