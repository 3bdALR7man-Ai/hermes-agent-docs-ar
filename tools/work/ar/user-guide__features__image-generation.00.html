الإعداد

مشتركو Nous

إذا كان لديك اشتراك مدفوع في Nous Portal، فيمكنك استخدام توليد الصور عبر Tool Gateway دون مفتاح FAL API. ويبقى اختيارك للنموذج محفوظًا في كلا المسارين. يمكن للتثبيتات الجديدة تشغيل hermes setup --portal لتسجيل الدخول وتفعيل جميع أدوات الـ gateway دفعة واحدة؛ أما التثبيتات الحالية فيمكنها اختيار Nous Subscription بوصفه الـ backend لتوليد الصور عبر hermes tools.

صف Nous Subscription هو الصف المُدار الوحيد. يشمل منتقي نماذجه كل gateway يشغّله الاشتراك — كتالوج FAL أعلاه و Krea 2 الأصلي (krea-2-medium و krea-2-large و krea-2-medium-turbo) وأي نماذج صور لدى Nous Portal — ويُدرج كل نموذج مرة واحدة، ويحدد اختيارك أي gateway يخدم الطلب. ترى حسابات مجمّع الأدوات المجانية نماذج FAL فقط؛ تتطلب نماذج Krea و Portal اشتراكًا مدفوعًا. عند اختيار نموذج Krea 2، يتيح image_generate أيضًا إعداد creativity لدى Krea وأشرطة تمرير intensity و complexity و movement (-100 إلى 100).

إذا أعاد الـ gateway المُدار الاستجابة HTTP 4xx لنموذج معين، فهذا يعني أن ذلك النموذج لم يُمرَّر بعد عبر الـ proxy من جهة البوابة (portal) — وسيخبرك الوكيل بذلك مع خطوات المعالجة (التبديل إلى FAL.ai في hermes tools باستخدام FAL_KEY الخاص بك للوصول المباشر، أو اختيار نموذج مختلف).

الإعداد واختيار النموذج

شغّل أمر الأدوات:

انتقل إلى 🎨 Image Generation، واختر الـ backend (Nous Subscription أو FAL.ai)، وبعدها تعرض أداة الاختيار جميع النماذج المدعومة في جدول بأعمدة محاذاة — استخدم مفاتيح الأسهم للتنقل، و Enter للاختيار:

يُحفَظ اختيارك في config.yaml:

image_gen.provider هو مفتاح الاختيار الوحيد: nous توجّه الطلبات عبر Tool Gateway المُدار؛ واسم المورّد (fal، openai، xai، krea، ...) يتصل مباشرةً باستخدام مفتاحك الخاص. يتبع وقت التشغيل هذا الاختيار المحفوظ دائمًا — إذ يُتجاهَل FAL_KEY الموجود في .env ما دام الإعداد provider: nous، ويؤدي provider: fal دون FAL_KEY إلى الخطأ image_gen is configured to use fal (set via hermes tools), but FAL_KEY is not set. Run 'hermes tools' to change it. بدلًا من إعادة التوجيه بصمت. غيّر المزوّدين عبر hermes tools، لا بإضافة المفاتيح أو حذفها. (القيمة المنطقية القديمة use_gateway موروثة (legacy) — ما زالت تُقرأ على أنها nous عندما تكون true، لكنها لم تعد تُكتب أبدًا.)

max_parallel_requests قيمته الافتراضية 4. يقيّدها Hermes بحيث لا تقل عن واحد ولا تتجاوز الحد العام لعمّال الأدوات (tool-worker)، فيتلقى مزوّدو الصور طلبات متوازية محدودة دون السماح لدفعة صور بتجاوز سقف التزامن الخاص بالوكيل.

OpenRouter: كتالوج Image API الكامل

مع image_gen.provider: openrouter، تعرض أداة اختيار النماذج كتالوج الصور الحي الكامل لدى OpenRouter — أي نماذج Image API المخصّصة (Seedream و FLUX.2 و Recraft و Qwen Image و MAI و Krea و Riverflow و Grok Imagine وغيرها — أكثر من 40 معرّفًا) مدمجةً مع نماذج الصور في chat-completions. يُجلَب الكتالوج مباشرةً من GET /images/models و GET /models، لذا تظهر النماذج الجديدة في أداة الاختيار بمجرد أن يوفّرها OpenRouter؛ دون الحاجة إلى تحديث Hermes. ويوجّه التوليد كل نموذج تلقائيًا إلى الواجهة التي تخدمه (POST /images/generations المخصّصة أو chat-completions). يمرّر Nous Portal بروتوكول chat-completions فقط، لذا تعرض أداة الاختيار الخاصة به النماذج التي تُخدَم عبر المحادثة فقط.

توضع الإعدادات الاختيارية لكل طلب الخاصة بنماذج Image API ضمن قسم الإعدادات المخصّص لها (أو عبر متغيرات البيئة OPENROUTER_IMAGE_API_*):

جودة GPT-Image

جودة طلبات fal-ai/gpt-image-1.5 و fal-ai/gpt-image-2 مثبّتة على medium (~$0.034–$0.06/image بدقة 1024×1024). لا نتيح المستويين low / high كخيار للمستخدم حتى تبقى فوترة Nous Portal قابلة للتنبؤ لجميع المستخدمين — إذ يتراوح فرق التكلفة بين المستويات من 3 إلى 22 ضعفًا. إذا أردت خيارًا أرخص، فاختر Klein 9B أو Z-Image Turbo؛ وإذا أردت جودة أعلى، فاستخدم Nano Banana Pro أو Recraft V4 Pro.

FAL: ‏GPT Image 2.5

اختر GPT Image 2.5 Flare أو GPT Image 2.5 Sunburst ضمن hermes tools → Image Generation → FAL.ai. معرّفات النماذج هي:

  • openai/gpt-image-2.5/flare/text-to-image
  • openai/gpt-image-2.5/sunburst/text-to-image

على سبيل المثال:

يؤدي تمرير image_url أو صور مرجعية إلى الاختيار التلقائي لـ endpoint openai/gpt-image-2.5/flare/edit أو openai/gpt-image-2.5/sunburst/edit المقابل. ويقبل كلاهما حتى 16 صورة مصدرية. يثبّت Hermes الجودة على medium، تماشيًا مع سياسته الحالية لـ FAL GPT Image بدلًا من القيمة الافتراضية الأعلى تكلفةً لدى FAL وهي high. يستخدم الوضعان الأفقي والعمودي إعدادات 4:3 المسبقة لاستيفاء الحد الأدنى لعدد البكسلات؛ أما المربع فيستخدم square_hd. ويبقى تكبير الدقة (upscaling) معطّلًا ما لم يُطلَب.

تحتسب FAL الرسوم بحسب الـ tokens، لا بسعر ثابت للصورة: $5/M لإدخال النص، و$1.25/M لإدخال النص المخزّن مؤقتًا، و$10/M لإخراج النص، و$8/M لإدخال الصور، و$2/M لإدخال الصور المخزّن مؤقتًا، و $30/M لإخراج الصور، مع التقريب للأعلى إلى $0.0001 لكل طلب. راجع صفحتي Flare و Sunburst. يتطلب استخدام FAL مباشرةً مفتاح FAL_KEY ممولًا برصيد؛ أما التوفر عبر الـ gateway المُدار فيعتمد على قائمة الـ endpoints المسموح بها في ذلك الـ gateway، ولا يُستدَل عليه من توفر النموذج لدى FAL. وتبقى القيم الافتراضية الحالية للمزوّد والنموذج دون تغيير.

OpenAI API: ‏GPT Image 2.5

يدعم المزوّد OpenAI نموذجي GPT Image 2.5 Flare (للإنشاء اليومي السريع) و Sunburst (للتوليد والتحرير بدقة)، باستخدام OPENAI_API_KEY. اخترهما عبر hermes tools → Image Generation → OpenAI، أو اضبط:

gpt-image-2.5-flare و gpt-image-2.5-sunburst يستخدمان الجودة التلقائية. أضف -low أو -medium أو -high أو -xhigh أو -max لاختيار جودة ثابتة، مثل gpt-image-2.5-sunburst-high. ويدعم كلاهما التوليد والتحرير مع ما يصل إلى 16 صورة مرجعية. وتبقى اختيارات GPT Image 2 الحالية والقيمة الافتراضية gpt-image-2-medium دون تغيير.

هذا استخدام مدفوع لـ API، منفصل عن اشتراك ChatGPT/Codex. تبلغ تكلفة كلا النموذجين $5 لكل مليون token من إدخال النص، و$8 لكل مليون token من إدخال الصور، و $30 لكل مليون token من إخراج الصور (وأسعار الإدخال المخزّن مؤقتًا هي $1.25 و$2 على التوالي). تختلف تكلفة الصورة الواحدة بحسب الاستخدام؛ ولا تقدّر حاسبة GPT Image 2 استهلاك الـ tokens في الإصدار 2.5. راجع الوثائق الرسمية لـ Flare و Sunburst.

المزوّد OpenAI (Codex auth) لا يقدّم الإصدار 2.5. يقبل backend الخاص بـ Codex أي قيمة model (بما فيها معرّفات غير موجودة)، ويولّد بمحركه المُدار من الخادم، لذا سيكون مستوى Flare أو Sunburst "المختار" مجرد تسمية بلا أثر. اختر مزوّد OpenAI API المباشر أو FAL للإصدار 2.5.

Endpoint صور مخصّص متوافق مع OpenAI

يمكن توجيه مزوّد OpenAI إلى أي endpoint /v1/images/generations متوافق مع OpenAI (gateway محلي أو proxy مقيّد بمهمة أو API gateway خارجي)، مستقلًا عن مزوّد المحادثة، واستمداد مفتاحه من متغير تختاره:

لا يُخزَّن إلا اسم المتغير في config.yaml؛ ويبقى السرّ في .env أو بيئة العملية. تستخدم فحوص الإتاحة والتوليد آلية التحديد نفسها، لذا تكفي قيمة key_env مضبوطة — ولا يلزم OPENAI_API_KEY. تمر الطلبات عبر عميل HTTP الخاص بـ Hermes، الذي يراعي HTTP(S)_PROXY/NO_PROXY لكنه يتجاهل proxies النظام على macOS (التي لا يرى Python قائمة استثناءاتها)، فتتصل endpoints localhost مباشرةً. تُرسل ترويسة OpenAI-Project فارغة في طلبات الصور: فالقيمة OPENAI_PROJECT_ID المضبوطة للمحادثة تؤدي بخلاف ذلك إلى إرجاع endpoint الصور خطأ 403 model_not_found في المشاريع ذات قائمة سماح بالنماذج، بينما يحمل المفتاح نفسه المشروع بالفعل.

أسماء نماذج Gateway. تُحوَّل معرّفات الكتالوج لـ OpenAI: يُرسل gpt-image-2-medium بوصفه model: gpt-image-2 + quality: medium. تُرسل أي قيمة أخرى لـ image_gen.openai.model (أو OPENAI_IMAGE_MODEL) حرفيًا بوصفها model مع عدم وجود quality حقل، فتتلقى gateway التي تقدم أسماء نماذج صور خاصة بها (custom-image-model و grok-imagine-image وغيرها) ذلك المعرّف نفسه تمامًا ولا ترى تعداد جودة قد ترفضه. لا يُمرّر image_gen.model المشترك في المستوى الأعلى مطلقًا — فقد يحمل معرّف مزوّد آخر (مثل مسار FAL) من اختيار سابق.

إعادة استخدام endpoint مخصّص مُسمّى. إذا كانت gateway مُصرّحًا بها بالفعل ضمن providers: للمحادثة، فوجّه مزوّد الصور إليها باستخدام الاسم بدلًا من تكرار URL والمفتاح:

ترتيب التحديد هو image_gen.openai.base_url → URL الخاص بالـ endpoint المُسمّى → OPENAI_BASE_URL، والمتغير المُسمّى بـ image_gen.openai.key_env → api_key/key_env الخاص بالـ endpoint المُسمّى → OPENAI_API_KEY؛ لذا يتجاوز base_url أو key_env الصريح بجوار provider ذلك الجزء من الـ endpoint. يُسجَّل الاسم غير المطابق لأي مدخل providers: كتحذير ويُتجاهل.

OpenAI (Codex auth): يحدد backend الجودة والحجم

يرسل Hermes الطلب مباشرةً إلى endpoints images/generations / images/edits الأصلية لدى backend الخاص بـ Codex (المسار نفسه الذي يستخدمه عميل Codex الرسمي)، فلا يُستخدم نموذج محادثة، ولا يعتمد الاستدعاء على نماذج المحادثة المتوفرة حاليًا في خطة ChatGPT لديك. لكن backend يعامل model و quality و size كتوصيات: فقد يُرجع مستوى جودة أو أبعادًا مختلفة عن المطلوب (قد يأتي طلب عمودي بصورة مربعة). تحمل النتيجة reported_quality و reported_size و pixel_size إلى جانب ما طُلب، بالإضافة إلى imagegen_request_id لدعم OpenAI. للتحكم الدقيق بالجودة والحجم، اضبط backend OpenAI (مفتاح API) أو FAL أو xAI بدلًا من ذلك.

تُعرَض قدرة النموذج النشط على التحرير في وصف الأداة وقت التشغيل، فيعرف الوكيل ما إذا كان image_url سيُحترَم قبل أن يستدعي الأداة.

تكبير الدقة (Upscaling)

بالتفعيل الاختياري فقط

لا يكبّر أي نموذج الدقة افتراضيًا. فنماذج الصور الحديثة تُخرج أفضل جودة لديها بشكل أصلي، ومكبّرات الدقة المتاحة هي محسّنات إبداعية (تمريرات diffusion) قد تعيد رسم المحتوى بشكل خفي — مما يُضعف النصوص المعروضة والوجوه والتفاصيل الدقيقة. لذلك لا يعمل تكبير الدقة إلا عندما يطلبه الوكيل صراحةً.

المعامل upscale (تفعيل اختياري لكل استدعاء)

  • upscale: true — يضيف تمريرة عالية الدقة بعد التوليد:
الـ Backendمكبّر الدقة
FAL.aiClarity Upscaler (2×، +$0.03/MP)
KreaKrea Enhance (2×، بحد أقصى 8K)
الـ backends الأخرىلا يوجد مكبّر دقة؛ تُعاد الدقة الأصلية
  • upscale: false / أو إغفاله — الدقة الأصلية (الافتراضي)

video_generate يقبل أيضًا upscale: true على الـ backend الخاص بـ FAL، فيضيف مكبّر الفيديو SeedVR2 من ByteDance (2×، $0.001/MP من الفيديو الناتج) بعد التوليد.

عند تشغيل تمريرة الصور في FAL، تُستخدم الإعدادات التالية:

الإعدادالقيمة
معامل التكبير (Upscale factor)2×
الإبداعية (Creativity)0.35
التشابه (Resemblance)0.6
مقياس التوجيه (Guidance scale)4
خطوات الـ inference18

إذا فشل تكبير الدقة (مشكلة في الشبكة، أو حدّ المعدل)، تُعاد الصورة الأصلية تلقائيًا. وتتضمن الاستجابة upscaled: true/false ليعرف الوكيل الدقة التي حصل عليها.

آلية العمل الداخلية

  1. تحديد النموذج — تقرأ _resolve_fal_model() القيمة image_gen.model من config.yaml، ثم تعود احتياطيًا إلى متغير البيئة FAL_IMAGE_MODEL، ثم إلى fal-ai/flux-2/klein/9b.
  2. بناء الحمولة (payload) — تحوّل _build_fal_payload() قيمة aspect_ratio إلى الصيغة الأصلية للنموذج (enum للإعداد المسبق، أو enum لنسبة الأبعاد، أو قيمة GPT حرفية)، وتدمج المعاملات الافتراضية للنموذج، وتطبّق أي تجاوزات من المستدعي، ثم ترشّح النتيجة وفق القائمة البيضاء supports الخاصة بالنموذج حتى لا تُرسَل المفاتيح غير المدعومة أبدًا.
  3. الإرسال — توجّه _submit_fal_request() الطلب عبر بيانات اعتماد FAL المباشرة أو عبر Nous gateway المُدار، بحسب الاختيار المحفوظ في image_gen.provider.
  4. تكبير الدقة — لا يعمل إلا عندما يمرّر الوكيل upscale: true؛ فالقيمة الافتراضية في الكتالوج معطّلة لكل النماذج.
  5. التسليم — يُعاد URL الصورة النهائية إلى الوكيل، الذي يُصدر الوسم MEDIA:<url> الذي تحوّله محوّلات المنصات (platform adapters) إلى وسائط أصلية.
  6. حساب الاستخدام — تُرجع نماذج الصور المفوترة بحسب tokens (نماذج OpenRouter chat-image و Image API مثل google/gemini-3.1-flash-lite-image و OpenAI gpt-image) أعداد tokens حقيقية، لذا يُسجّل كل استدعاء في session_model_usage كمهمة image_generation تحت مزوّد الفوترة والنموذج، ويظهر في hermes insights وتحليلات Usage بلوحة التحكم إلى جانب استدعاءات النماذج الأخرى. لا تُرجع backends المفوترة لكل صورة (FAL و xAI و Krea وغيرها) استخدام tokens ولا تُسجّل هناك.
