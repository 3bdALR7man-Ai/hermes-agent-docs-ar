المتغيرالوصف
HERMES_TUIتشغيل TUI بدلًا من CLI الكلاسيكي عند ضبطه على 1. يعادل تمرير --tui
HERMES_TUI_DIRمسار دليل ui-tui/ مبني مسبقًا (يجب أن يحتوي على dist/entry.js وnode_modules مملوءة). تستخدمه التوزيعات و Nix لتخطي npm install عند أول تشغيل
HERMES_TUI_RESUMEاستئناف جلسة TUI محددة بمعرّفها عند الإطلاق. عند ضبطه، يتخطى hermes --tui صياغة جلسة جديدة ويلتقط الجلسة المسمّاة بدلًا من ذلك — مفيد لإعادة الاتصال بعد انقطاع أو تعطل الطرفية
HERMES_TUI_THEMEفرض سمة لون TUI: light، أو dark، أو قيمة سداسية عشرية خام من 6 أحرف للخلفية (مثلًا ffffff أو 1a1a2e). عند عدم ضبطه، يكتشف Hermes ذلك تلقائيًا باستخدام COLORFGBG واستعلامات خلفية الطرفية؛ يتجاوز هذا المتغير الاكتشاف على طرفيات (Ghostty، Warp، iTerm2، وغيرها) لا تضبط COLORFGBG
HERMES_INFERENCE_MODELفرض النموذج لـ hermes -z / hermes chat دون تعديل config.yaml. يقترن مع خيار --provider. مفيد للمستدعين النصّيين (السكربتات) (المُنظِّف sweeper، وCI، ومشغّلات الدُفعات) الذين يحتاجون تجاوز النموذج الافتراضي لكل تشغيل

إعدادات الجلسة

المتغيرالوصف
HERMES_SESSION_IDيُصدَّر تلقائيًا إلى كل عملية فرعية للأدوات يفرّخها Hermes (terminal، وexecute_code، والـ shell الدائم، ومهايئات Docker/Singularity، وتشغيلات subagent المفوَّضة). يضبطه الوكيل على معرّف الجلسة الحالية؛ يمكن لسكربتات المستخدم المستدعاة من الأدوات قراءته لربط مخرجاتها أو بياناتها التحليلية أو آثارها الجانبية بجلسة Hermes المصدر. لا ينبغي ضبطه يدويًا — تجاوزه من shell أب لا يسري إلا خارج تشغيل الوكيل، ويُستبدَل بمجرد أن يبدأ الوكيل جلسة
AI_AGENTتُضبط على hermes-agent بواسطة نقاط دخول CLI والـ gateway (فقط عندما لا تكون مضبوطة مسبقًا من قِبل مُشغّل خارجي)، وتُصدَّر إلى كل shell لأداة terminal — بما في ذلك الخلفيات البعيدة (Docker، وSSH، وModal، وDaytona، وSingularity، وVercel). المعيار الناشئ العابر للوكلاء لإسناد العمليات الفرعية — تقرأه أدوات عامة (مثل كاشف الوكيل في huggingface_hub) لتعرف أنها تعمل تحت وكيل ذكاء اصطناعي. القيمة تطابق معرّف Hermes في سجل حاضنات الوكلاء (agent-harness) العام. لا تضبطه يدويًا
HERMES_AGENTتُضبط على true بواسطة نقاط دخول CLI والـ gateway وتُصدَّر إلى كل shell لأداة terminal بحيث تستطيع العمليات الفرعية اكتشاف أنها تعمل داخل Hermes تحديدًا. لا تضبطه يدويًا

ضغط السياق (في config.yaml فقط)

يُضبط ضغط السياق حصريًا عبر config.yaml — لا توجد متغيرات بيئة له. تعيش إعدادات العتبة في كتلة compression:، بينما يعيش نموذج/مزوّد التلخيص تحت auxiliary.compression:

ترحيل قديم

الإعدادات القديمة التي تحتوي compression.summary_model وcompression.summary_provider وcompression.summary_base_url تُرحَّل تلقائيًا إلى auxiliary.compression.* عند أول تحميل

ملاحظة

متغيرات AUXILIARY_WEB_EXTRACT_* باتت متقادمة: لم تعد web_extract ولقطات المتصفح تستخدم LLM مساعدًا. تُقتطَع الصفحات واللقطات الطويلة بشكل حتمي مع تخزين النص الكامل على القرص لتصفّح read_file

لعُقد النهاية (endpoints) المباشرة الخاصة بمهام محددة، يستخدم Hermes مفتاح API المضبوط للمهمة أو OPENAI_API_KEY. لا يُعيد استخدام OPENROUTER_API_KEY لتلك العُقد المخصَّصة

المزوّدون الاحتياطيون (في config.yaml فقط)

تُضبط سلسلة النموذج الأساسي الاحتياطية حصريًا عبر config.yaml — لا توجد متغيرات بيئة لها. أضف قائمة fallback_providers على المستوى الأعلى بمفاتيح provider وmodel لتفعيل التبديل التلقائي عند مواجهة نموذجك الرئيسي أخطاءً. تستشير المهام المساعدة التي مزوّدها auto هذه السلسلة أيضًا قبل سلسلة اكتشاف المهام المساعدة المدمجة في Hermes

لا يزال الشكل القديم أحادي المزوّد fallback_model على المستوى الأعلى مقروءًا للتوافق مع الإصدارات السابقة، لكن يجب أن تستخدم الإعدادات الجديدة fallback_providers. لسياسة المهام المساعدة الخاصة بكل مهمة، استخدم auxiliary.<task>.fallback_chain في config.yaml؛ لا يوجد متغير بيئة مكافئ
