hermes checkpoints

فحص وإدارة مخزن shadow git في ~/.hermes/checkpoints/ — طبقة التخزين خلف أمر /rollback داخل الجلسة. آمن للتشغيل في أي وقت؛ لا يتطلب تشغيل الوكيل.

الأمر الفرعيالوصف
status (الافتراضي)عرض الحجم الإجمالي وعدد المشاريع والتفصيل لكل مشروع. الأمر المجرد hermes checkpoints يكافئ هذا.
listاسم بديل لـ status.
pruneفرض تمريرة تنظيف — حذف المشاريع اليتيمة والقديمة، وتشغيل GC للمخزن، وفرض الحد الأقصى للحجم. يتجاهل علامة عدم التكرار (idempotency) الخاصة بـ 24 ساعة.
clearحذف قاعدة نقاط الحفظ (checkpoint) بالكامل. لا رجعة فيه؛ يطلب تأكيدًا ما لم تُمرَّر -f.
clear-legacyحذف أرشيفات legacy-<timestamp>/ فقط التي أنتجها الانتقال v1→v2. ينتهي بالحالة 2 (بعد طباعة Could not delete N archive(s)) إذا تعذّر إزالة أي أرشيف، مثل كائنات git للقراءة فقط على Windows.

الخيارات

الخيارالأمر الفرعيالوصف
--limit Nstatus، listالحد الأقصى لعدد المشاريع المعروضة (الافتراضي 20).
--retention-days Npruneإسقاط المشاريع التي مرّ على last_touch الخاص بها أكثر من N يوم (الافتراضي 7).
--max-size-mb Npruneبعد جولة اليتيمة/القديمة، إسقاط أقدم commit لكل مشروع حتى يصبح حجم المخزن الإجمالي ≤ N MB (الافتراضي 500).
--keep-orphanspruneتخطي حذف المشاريع التي لم يعد مجلد عملها موجودًا.
-f، --forceclear، clear-legacyتخطي طلب التأكيد.

hermes import

استعادة نسخة احتياطية من Hermes أُنشئت سابقًا إلى مجلد Hermes الرئيسي لديك. كل الملفات في الأرشيف تستبدل الملفات الموجودة في مجلد Hermes الرئيسي؛ --force يتخطى فقط طلب التأكيد الذي يظهر عندما يحتوي الهدف بالفعل على تثبيت Hermes.

الخيارالوصف
-f، --forceتخطي طلب تأكيد وجود تثبيت سابق.
تحذير

أوقف الـ gateway قبل الاستيراد لتجنب التعارضات مع العمليات قيد التشغيل.

حالة الخروج: 1 عندما يكون الأرشيف تالفًا — قبل كتابة أي شيء، يُفك ضغط كل عنصر مرة واحدة وتُفحص CRC الخاصة به؛ إذا فشل أي منها، يطبع الأمر Error: backup archive is damaged (N member(s) …) مع العناصر المخالفة ويتوقف دون المساس بمجلد Hermes الرئيسي. وكذلك 1 عندما يتعذّر استعادة أي ملف من الأرشيف (يُسرد ضمن Warnings (N files skipped) ويُلخّص بـ Import incomplete: …). تبقى الملفات التي استُعيدت في مواضعها، لكن لا يُبلغ سكربت أو لوحة التحكم عن استعادة جزئية بوصفها نجاحًا. ملفات التشغيل التي يتعمد الاستيراد إبقاءها من هذا الجهاز (gateway.pid و gateway_state.json وغيرها)، والتحذير من جلسات النسخة الاحتياطية الأقدم أدناه، لا يغيّران حالة الخروج.

قواعد بيانات SQLite

.db (state.db، kanban.db، response_store.db، …) لا تُنشر بإعادة تسمية كما تُنشر الملفات العادية. إعادة التسمية كانت ستستبدل inode الملف بينما لا تزال عملية gateway أو dashboard أو WebUI تحتفظ بالملف القديم مفتوحًا: تلك العملية ستستمر في قراءة صفحات ما قبل الاستيراد وستستمر في كتابة جلسات لا يراها أحد آخر، وستكون تلك الجلسات ببساطة غائبة من قاعدة البيانات التي يفتحها الجميع لاحقًا — دون أي تسجيل. بدلًا من ذلك، تُكتب الصفحات المستوردة داخل ملف قاعدة البيانات الموجود، بنفس الطريقة التي ينفذها /snapshot restore، بحيث يتقارب كل اتصال مفتوح على البيانات المستوردة.

إذا تعذّر استبدال قاعدة البيانات الحية بأمان — فشل نسخ الصفحات ولا تزال عملية أخرى تحتفظ بالملف مفتوحًا — يترك الاستيراد قاعدة البيانات تلك دون تغيير ويدرجها تحت Warnings (N files skipped). أوقف العمليات المحتفِظة بالملف وأعد التشغيل.

استيراد نسخة احتياطية أقدم فوق عمل أحدث لا يزال مسموحًا، لكنه لم يعد صامتًا. عندما تحتوي state.db المستوردة على رسائل أقل من التي استبدلتها، يُبلّغ الملخص عن ذلك:

hermes prompt-size

يُبلّغ عن ميزانية الـ prompt الثابتة لجلسة جديدة — ما يُرسل في كل استدعاء API قبل أي محتوى محادثة. مفيد عندما يكون لدى محوّل أو وكيل (proxy) لاحق ميزانية prompt أضيق من نافذة سياق النموذج، أو عندما تريد معرفة أي كتلة (فهرس المهارات، الذاكرة، الـ profile) تهيمن.

يبني نفس system prompt الذي سيبنيه الوكيل، ثم يحلّله إلى:

  • إجمالي الـ system prompt — الـ prompt الكامل المجمَّع (الهوية، التوجيه، فهرس المهارات، ملفات السياق، الذاكرة، الـ profile، الطابع الزمني).
  • فهرس المهارات — كتلة <available_skills>. غالبًا ما تكون هذه أكبر كتلة منفردة عند تثبيت عدد كبير من المهارات.
  • الذاكرة وملف المستخدم — لقطات MEMORY.md / USER.md الخاصة بك.
  • مستويات الـ prompt — ثابت / سياق / متقلّب، بما يطابق طريقة تنظيم Hermes للـ prompt لتحقيق ملاءمة التخزين المؤقت.
  • مخططات الأدوات — JSON الخاص بكل الأدوات المفعّلة (النصف الآخر من الحمولة الثابتة لكل استدعاء).

يعمل بالكامل دون اتصال — بلا استدعاء API، ويعمل دون أي بيانات اعتماد مضبوطة.

نصيحة

يتوسع فهرس المهارات ومخططات الأدوات بحسب عدد المهارات والأدوات المفعّلة لديك. لتقليص حجم الـ prompt، عطّل الـ toolsets غير المستخدمة (hermes tools) أو أزل المهارات التي لا تحتاجها (hermes skills). ملفات السياق (AGENTS.md، .cursorrules) في مجلدك الحالي تُحتسب أيضًا ضمن الإجمالي.

hermes config

الأوامر الفرعية:

الأمر الفرعيالوصف
showعرض قيم الإعدادات الحالية.
editفتح config.yaml في محررك.
get <key> [--json] [--raw]طباعة قيمة إعداد واحدة عبر مفتاح منقّط (مثل hermes config get model.default). --json يُصدر مخرجات قابلة للقراءة آليًا. تُخفى القيم الشبيهة ببيانات الاعتماد (api_key و *_TOKEN و *_SECRET و password وغيرها) باستخدام (sk-o...7890) لأن الوكيل ينفّذ هذا من جلسات تُحفظ نصوص محادثاتها؛ يطبع --raw القيمة الحقيقية (أو اضبط security.redact_secrets: false). يظل المفتاح المتداخل تحت قسم معروف وغير المعرّف في المخطط (compression.compressor.enabled) يطبع قيمته من الملف، مع إشعار stderr بأن Hermes قد لا يقرأه؛ ولا يتغير stdout ولا رمز الخروج (0).
set <key> <value> [--force]ضبط قيمة إعداد. تنتقل المسارات المنقّطة إلى config.yaml؛ ويُعدّ كل اسم UPPER_SNAKE (OPENROUTER_API_KEY و DISCORD_HOME_CHANNEL و TELEGRAM_GROUP_ALLOWED_USERS و HERMES_TIMEZONE وغيرها) متغير بيئة ينتقل إلى .env — الملف نفسه الذي تكتب فيه إجراءات إعداد المنصات و /sethome، والذي تعتمد عليه كل قارئات وقت التشغيل. لا يكتب config set مفتاح UPPER_SNAKE في config.yaml مطلقًا، بما فيه --force؛ وتُرفض الأسماء الموجودة في قائمة حظر كاتب متغيرات البيئة (HERMES_YOLO_MODE و PATH وغيرها) رفضًا كاملًا؛ ويُحفظ أي اسم UPPER_SNAKE آخر في .env كما هو (تقرؤه الإضافات والمهارات والأدوات الخارجية من بيئة العملية). يُرفض المفتاح المعروف المكتوب تحت بادئة خاطئة (gateway.discord.foo، حيث إن discord.foo نفسه مفتاح معروف) مع اقتراح التصحيح ولا يُكتب شيء؛ ويُكتب أي مسار مجهول آخر تحت قسم معروف (agent.max_turnz، أو مفتاح يُقرأ وقت التشغيل وليس له قيمة افتراضية أولية) مع إشعار اقتراح تصحيح، ويُكتب المفتاح المجهول صغير الأحرف على المستوى الأعلى مع إشعار (تُمرَّر القيم المفردة العليا إلى البيئة للمهارات). يكتب --force أيضًا المسار ذي البادئة الخاطئة المرفوض. تُفحص أنواع القيم مقابل المخطط: فالمفتاح الذي يجب أن يحمل قائمة أو خريطة (custom_providers أو model.aliases أو display.platforms أو plugins.enabled/plugins.disabled أو model_catalog.excluded_providers أو أي مفتاح يحمل إحداهما بالفعل) يرفض سلسلة عادية أو قيمة حرفية ذات بنية خاطئة، وتُرفض القيمة التي تبدو كقائمة/خريطة وليست YAML/JSON صالحًا بدلًا من تخزينها كنص — فلا يُكتب شيء ويذكر الخطأ النوع المتوقع. مرّر قيمة YAML/JSON حرفية (hermes config set custom_providers '[{name: x, base_url: https://...}]')؛ ولتخزين نص يبدأ فحسب بـ [ أو {، ضع عليه علامات اقتباس في YAML ("'[text'"). يظل --force يستبدل قسم خريطة كاملًا؛ ولا يوجد تجاوز لقيمة غير قائمة في موضع قائمة، إلا أن اسمًا منفردًا لقائمة أسماء تُقرأ بتسامح (agent.disabled_toolsets و skills.disabled) يُخزّن كقائمة بعنصر واحد.
unset <key>إزالة مفتاح إعداد، وإعادته إلى القيمة الافتراضية المدمجة. بالنسبة إلى أسماء UPPER_SNAKE، يزيل ذلك مدخل .env ويسقط أيضًا نسخة config.yaml قديمة في المستوى الأعلى تركتها تشغيلات config set الأقدم (يُبلغ get عن مثل هذه النسخة بوصفها قديمة).
pathطباعة مسار ملف الإعدادات.
env-pathطباعة مسار ملف .env.
checkالتحقق من الإعدادات المفقودة أو القديمة.
migrateإضافة الخيارات المُستحدثة حديثًا بشكل تفاعلي.

config set model.provider <provider> يُبقي كتلة model: على مسار واحد: تُزال (ويُذكر ذلك) قيمة model.base_url / model.api_mode المتبقية من المزوّد السابق إذا كانت endpoint لمزوّد آخر — وإلا يُرسل مفتاح المزوّد الجديد إلى endpoint القديم ويفشل بخطأ بيانات اعتماد يذكر المزوّد الخطأ. يبقى URL الذي يمثل endpoint للمزوّد الجديد نفسه أو endpoint لمدخل custom_providers مُسمّى أو أي URL ضمن custom/الأسماء البديلة المحلية؛ ويبقى المضيف غير المعروف (proxy أو خادم LAN) مع تحذير بأنه ما زال مطبّقًا.

النقاط داخل أسماء المفاتيح

hermes config set/get/unset يستخدم . كفاصل للتداخل، لكن كثيرًا من أسماء المفاتيح الفعلية تحتوي نقاطًا حرفية — معرّفات النماذج (grok-4.6، glm-5.3-flash)، معرّفات غرف Matrix (!room:example.org)، أسماء مزوّدين ذات إصدارات. قاعدتان تجعلان هذه قابلة للوصول:

  • المفاتيح الموجودة تعمل تلقائيًا. عند التنقل في تعيين موجود، يُفضَّل مفتاح حرفي موجود يطابق البقية المنقّطة على التقسيم. الأمر hermes config set providers.p.models.grok-4.6.supports_vision true يحدّث إدخال grok-4.6 الفعلي (وتحلّل get/unset بنفس الطريقة).
  • إنشاء مفتاح منقّط جديد يتطلب الإفلات (escaping). أفلت النقاط الحرفية بشرطة مائلة عكسية: الأمر hermes config set 'providers.p.models.grok-4\.7.context_length' 128000 ينشئ مفتاح grok-4.7 الحرفي. (ضع المفتاح بين علامتي اقتباس ليحافظ shell على الشرطة المائلة العكسية.)

إذا كانت كتابة غير مُفلَتة ستنشئ تعيينًا متداخلًا يُظلّل مفتاحًا منقّطًا مجاورًا موجودًا بالفعل (مثل إنشاء grok-4 بجانب grok-4.6 موجود)، يفشل الأمر برسالة خطأ بدلًا من كتابة إدخال وهمي بصمت لن يقرأه وقت التشغيل أبدًا.

  • --source well-known يتيح لك توجيه Hermes إلى موقع يعرض /.well-known/skills/index.json.
  • --source browse-sh يبحث في كتالوج browse.sh الذي يضم أكثر من 200 مهارة أتمتة متصفح خاصة بمواقع محددة. المعرّفات تبدو مثل browse-sh/airbnb.com/search-listings-ddgioa.
  • تمرير رابط http(s)://…/*.md يثبّت SKILL.md بالإضافة إلى الملفات المُشار إليها صراحةً تحت references/، templates/، scripts/، assets/، وexamples/. عندما لا تحتوي بيانات frontmatter على name: ولا يكون slug الرابط معرّفًا صالحًا، تطلب طرفية تفاعلية اسمًا؛ أما الواجهات غير التفاعلية (/skills install داخل TUI، منصات الـ gateway) فتتطلب --name <x> بدلًا من ذلك.

hermes bundles

حزم المهارات تجمع عدة مهارات تحت أمر slash واحد بصيغة /<bundle-name>. استدعاء الحزمة يحمّل كل مهارة مُشار إليها في رسالة مستخدم واحدة مُجمَّعة. التخزين: ~/.hermes/skill-bundles/<slug>.yaml. راجع حزم المهارات لمخطط YAML والسلوك.

الأوامر الفرعية:

الأمر الفرعيالوصف
listسرد الحزم المثبَّتة (الافتراضي عند عدم تمرير أمر فرعي)
show <name>عرض اسم حزمة ووصفها ومهاراتها ومسار ملفها
create <name>إنشاء حزمة جديدة. مرّر --skill <id> (تكرارًا) أو اتركه للإدخال التفاعلي. تتوفر --description، --instruction، --force.
delete <name>إزالة ملف حزمة
reloadإعادة فحص ~/.hermes/skill-bundles/ والإبلاغ عن الحزم المضافة/المُزالة

أمثلة:

في جلسة محادثة، يعرض /bundles الحزم المثبَّتة، ويحمّل /<bundle-name> واحدة منها.
