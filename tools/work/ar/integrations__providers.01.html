Anthropic (التشغيل الأصلي)

استخدم نماذج Claude مباشرة عبر Anthropic API — بدون حاجة إلى وكيل OpenRouter الوسيط. يدعم ثلاث طرق مصادقة:

عندما لا تُختار بيانات اعتماد بيئة صريحة، تتقدم منح OAuth التي يملكها Hermes في مجمع بيانات الاعتماد على تسجيل دخول Claude Code المستعار. ويظل تسجيل الدخول المستعار هو البديل عند عدم توفر منح OAuth مملوك — إلا إذا كان auth.adopt_external_logins: false مضبوطًا، وعندئذ لا يقرأ Hermes بيانات اعتماد Claude Code أو يحدثها مطلقًا (راجع تسجيلات دخول CLI المستعارة). يحدث استرداد المصادقة المساعدة بيانات الاعتماد التي استخدمها الطلب الفاشل، لا تسجيل دخول متاحًا غير مرتبط؛ وإلا فقد يؤدي تدوير تسجيل دخول مستعار إلى إبطال refresh token الخاص بمالكه.

يتطلب رصيد "extra usage" من Claude Max

عندما تُصادق عبر hermes model → Anthropic OAuth (أو عبر hermes auth add anthropic --type oauth)، يوجَّه Hermes كـ Claude Code مقابل حسابك في Anthropic. يعمل هذا فقط إذا كنت على خطة Claude Max وقد اشتريت رصيد استخدام إضافي. لا يُستهلَك مخصص خطة Max الأساسية (الاستخدام المُضمَّن في Claude Code افتراضيًا) بواسطة Hermes — فقط رصيد الاستخدام الإضافي/الزائد الذي أضفته فوقه. لا يستطيع مشتركو Claude Pro استخدام هذا المسار.

إذا لم يكن لديك Max + رصيد إضافي، استخدم ANTHROPIC_API_KEY بدلًا من ذلك — تُفوتَر الطلبات بالدفع لكل token مقابل مؤسسة ذلك المفتاح (أسعار API القياسية، مستقلة عن أي اشتراك Claude).

عندما تختار Anthropic OAuth عبر hermes model، يفضّل Hermes مخزن بيانات الاعتماد الخاص بـ Claude Code على نسخ الرمز إلى ~/.hermes/.env. هذا يُبقي بيانات اعتماد Claude القابلة للتحديث قابلة للتحديث.

GitHub Copilot

يدعم Hermes منصة GitHub Copilot باعتبارها مزوّدًا من الدرجة الأولى، بوضعين اثنين:

copilot — API Copilot المباشر (مُوصى به). يستخدم اشتراكك في GitHub Copilot للوصول إلى GPT-5.x و Claude و Gemini ونماذج أخرى عبر Copilot API.

خيارات المصادقة (يتم التحقق منها بهذا الترتيب):

  1. COPILOT_GITHUB_TOKEN متغير البيئة
  2. GH_TOKEN متغير البيئة
  3. GITHUB_TOKEN متغير البيئة
  4. gh auth token عبر CLI

إذا لم يُعثر على أي token ، يعرض hermes model يوفر تسجيل الدخول عبر OAuth برمز الجهاز (device code) — وهو نفس التدفق الذي يستخدمه Copilot CLI و opencode.

أنواع الـ token

لا يدعم Copilot API لا يدعم Personal Access Tokens التقليدية (ghp_*). أنواع الـ token المدعومة:

إذا أعاد gh auth token لديك token من نوع ghp_*، استخدم hermes model للمصادقة عبر OAuth بدلًا من ذلك.

سلوك مصادقة Copilot في Hermes

يرسل Hermes token من GitHub مدعومًا (gho_*, github_pat_* أو ghu_*) مباشرةً إلى api.githubcopilot.com ويضمّن ترويسات خاصة بـ Copilot (Editor-Version, Copilot-Integration-Id, Openai-Intent, x-initiator).

عند استجابة HTTP 401، ينفّذ Hermes الآن استرداد بيانات اعتماد لمرة واحدة قبل الرجوع إلى الاحتياطي:

  1. إعادة تحديد الـ token عبر سلسلة الأولوية العادية (COPILOT_GITHUB_TOKEN → GH_TOKEN → GITHUB_TOKEN → gh auth token)
  2. إعادة بناء عميل OpenAI المشترك بترويسات محدَّثة
  3. إعادة محاولة الطلب مرة واحدة

تستخدم بعض الوسائط (proxies) المجتمعية القديمة تدفقات تبادل عبر api.github.com/copilot_internal/v2/token. قد تكون تلك النقطة غير متاحة لبعض أنواع الحسابات (تُعيد 404). لذلك يحافظ Hermes على المصادقة المباشرة بالـ token كمسار أساسي، ويعتمد على تحديث بيانات الاعتماد وقت التشغيل مع إعادة المحاولة لضمان الموثوقية.

توجيه API: تستخدم نماذج GPT-5+ (باستثناء gpt-5-mini) تلقائيًا واجهة Responses API. أما بقية النماذج (GPT-4o و Claude و Gemini وغيرها) فتستخدم Chat Completions. يُكتشف النماذج تلقائيًا من كتالوج Copilot الحي.

الاكتشاف التلقائي لنقطة Z.AI

xAI (Grok) — Responses API + التخزين المؤقت للـ prompt

يتم توصيل xAI عبر Responses API (نقل codex_responses) لدعم الاستدلال (reasoning) التلقائي على نماذج Grok 4 — دون الحاجة لمعامل reasoning_effort، إذ يقوم الخادم بالاستدلال افتراضيًا. اضبط XAI_API_KEY في ~/.hermes/.env واختر xAI في hermes model، أو استخدم grok كاختصار ضمن /model grok-4-fast-reasoning.

يمكن لمشتركي SuperGrok و X Premium+ تسجيل الدخول عبر OAuth في المتصفح بدلًا من استخدام مفتاح API — اختر xAI Grok OAuth (SuperGrok / Premium+) في hermes model، أو شغّل hermes auth add xai-oauth. يُعاد استخدام نفس bearer token الخاص بـ OAuth تلقائيًا من قِبل الأدوات المتصلة مباشرة بـ xAI (TTS وتوليد الصور وتوليد الفيديو والنسخ الصوتي). راجع دليل xAI Grok OAuth للاطلاع على التدفق الكامل — وإذا كان Hermes يعمل على مضيف بعيد، راجع أيضًا OAuth عبر SSH / الأجهزة البعيدة لمعرفة نفق ssh -L المطلوب.

عند استخدام xAI كمزوّد (أي base URL يحتوي x.ai)، يفعّل Hermes تلقائيًا التخزين المؤقت للـ prompt عبر إرسال ترويسة x-grok-conv-id مع كل طلب API. يوجّه هذا الطلبات إلى نفس الخادم ضمن جلسة المحادثة، مما يتيح لبنية xAI التحتية إعادة استخدام أنظمة الـ prompt وسجل المحادثة المخزَّنة مؤقتًا.

لا حاجة لأي إعداد — يُفعَّل التخزين المؤقت تلقائيًا عند اكتشاف نقطة xAI وتوفّر معرّف جلسة. هذا يقلّل زمن الاستجابة والتكلفة في المحادثات متعددة الأدوار.

يوفّر xAI أيضًا endpoint مخصّصًا لـ TTS (/v1/tts). اختر xAI TTS في hermes tools → الصوت و TTS ، أو راجع صفحة الصوت و TTS للإعدادات.

انتقال نماذج xAI المُتقاعدة (15 مايو 2026): يعتزم xAI إيقاف grok-4*, grok-3, grok-code-fast-1 وgrok-imagine-image-pro بتاريخ 2026-05-15. يكتشف كل من hermes doctor وبدء تشغيل hermes chat أي إعدادات لا تزال تشير إلى مرجع متقاعد ويطبعان البديل الموصى به. استخدم hermes migrate xai لإعادة كتابة الإعدادات دفعة واحدة — وهو بوضع dry-run افتراضيًا، أضف --apply لكتابة التغييرات (تُحفَظ نسخة مؤرَّخة من الإعدادات السابقة في backups/config/ أولًا).

خلفية البحث في الويب لـ xAI. عند تفعيل مجموعة أدوات البحث في الويب، يوجّه web.backend: xai عملية البحث عبر نقطة البحث المستضافة من xAI باستخدام نفس بيانات اعتماد XAI_API_KEY / OAuth. لا حاجة لأي إعداد إضافي إذا كان xAI مُهيّأً بالفعل كمزوّد.

DeepInfra

يُكتشف DeepInfra (--provider deepinfra, DEEPINFRA_API_KEY) مباشرة من كتالوجه. ويُتحكم في الاستدلال عبر حقل reasoning_effort في المستوى الأعلى لدى DeepInfra ، لذا يعمل agent.reasoning_effort, /reasoning <level>, --reasoning و agent.reasoning_overrides لكل نموذج في الاتجاهين: يفعّل الجهد التفكير للنماذج التي تعطله افتراضيًا (DeepSeek-V4.x)، بينما /reasoning none يوقفه للنماذج التي تفعّله افتراضيًا (GLM-4.6، و Qwen3-Thinking). وترك الاستدلال دون ضبط يبقي القيمة الافتراضية لكل نموذج لدى DeepInfra ؛ ويُدعم xhigh أصلًا، ويُرسل ultra بصيغة max.

AWS Bedrock

أو بشكل دائم في config.yaml:

NIM المحلي

يضمّن Hermes تلقائيًا ترويسة أصل الفوترة (billing-origin) الخاصة بـ NIM مع كل طلب موجَّه إلى build.nvidia.com — دون الحاجة لأي إعداد. هذا يوجّه الاستهلاك إلى الأصل الصحيح في لوحة فوترة NVIDIA.

GMI Cloud

نماذج مفتوحة ونماذج استدلال (reasoning) عبر GMI Cloud — واجهة متوافقة مع OpenAI ، مصادقة بمفتاح API.

أو اضبطه بشكل دائم في config.yaml:

يمكن تجاوز الـ base URL عبر GMI_BASE_URL (الافتراضي: https://api.gmi-serving.com/v1).
