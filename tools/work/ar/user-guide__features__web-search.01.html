الإعداد حسب الإمكانية

استخدم مزوّدين مختلفين للبحث مقابل الاستخراج. يتيح لك هذا الجمع بين بحث مجاني (SearXNG) ومزوّد استخراج مدفوع، أو العكس:

عندما تكون المفاتيح الخاصة بكل إمكانية فارغة، يعود كلاهما إلى web.backend. لا يُكتشف backend تلقائيًا من مفتاح API/URL المتاح إلا إذا لم يُكتب قط اختيار ويب مشترك (web.backend أو صف hermes tools المُدار) — بمجرد وجود اختيار مشترك، يستخدمه وقت التشغيل دائمًا، ولا تؤدي إضافة مفتاح إلى .env إلى إعادة توجيه حركة الويب. يؤثر المفتاح الخاص بإمكانية في تلك الإمكانية وحدها: ضبط web.extract_backend وحده يبقي web_search على backend المكتشف تلقائيًا.

ترتيب الأولوية (لكل إمكانية):

  1. web.search_backend / web.extract_backend (صريح لكل إمكانية؛ nous = Tool Gateway المُدار لتلك الإمكانية وحدها، راجع Tool Gateway)
  2. web.backend (الاحتياطي المشترك؛ nous = Tool Gateway المُدار)
  3. الاكتشاف التلقائي من متغيرات البيئة (فقط في الإعدادات التي لم تُضبط قط)

الاكتشاف التلقائي

إذا لم يُختَر أي backend على الإطلاق من قبل (لم تُكتَب web.backend ولا أي مفتاح خاص بإمكانية سواء من قِبَلك أو من hermes tools)، يختار Hermes أول backend متاح استنادًا إلى بيانات الاعتماد المضبوطة:

هوية Nous موجودة (أي حساب، بما في ذلك المستوى المجاني والضيوف المجهولون)بحث ويب مُدار (web_search فقط)؛ ولا يتغيّر الاستخراج ولا الحلقة أدناه التي لا تحتاج إلى مفاتيح
(لا شيء مضبوط على الإطلاق)حلقة بلا مفتاح: exa / parallel / firecrawl / keenable (بالتناوب)

الحلقة المجانية بلا مفتاح: عندما لا يوجد أي من بيانات الاعتماد أعلاه، تتناوب الطلبات عبر المستويات المجانية العامة لمزوّدي الحلقة (Exa و Parallel و Firecrawl و Keenable)، فتعمل أدوات الويب على تثبيت جديد دون أي إعداد — ويُحوَّل تلقائيًا الطلب الذي بلغ حد المعدل أو البحث الذي يرفضه المزوّد إلى المزوّد التالي في الحلقة. ثبّت مزوّدًا واحدًا في hermes tools لإيقاف التناوب (تُستخدم الحلقة عندئذٍ فقط كتعاقب احتياطي عند التقييد). جميع المستويات المجانية مقيَّدة بمعدّل من طرف المزوّد تحت حِمل مفاجئ (burst)؛ أما الاستخدام العادي المستمر فيمرّ بسلاسة. اضبط web.keyless_fallback: false لتعطيل المستوى — عند تعطيله دون بيانات اعتماد، لا تتاح أدوات الويب حتى تضبط مزوّدًا. لا تتأثر هوية Nous (بما فيها الضيف) بهذا المفتاح: يستمر تطبيق web_search المُدار، وإن كان web_extract يحتاج إلى مزوّد مضبوط.

الإنقاذ بلا مفتاح لمرة واحدة للـ backends المرتبطة بمفتاح: عندما يفشل backend الذي اخترته أو الذي يملك مفتاحًا — بما فيه مسار Nous Tool Gateway (web.backend: nous) — في استدعاء (مفتاح غير صالح أو انقطاع أو gateway غير متاح أو خطأ 5xx من المصدر الأعلى)، يُعاد هذا الاستدعاء وحده تلقائيًا عبر حلقة المستوى المجاني التي لا تحتاج مفاتيح بدلًا من إصدار خطأ — وتذكر النتيجة المزوّد الذي خدمه والسبب (rescued_from / backend_error). لا يكون هذا التعويض ثابتًا أبدًا: يحاول الاستدعاء التالي مباشرة لِـ web_search/web_extract الـ backend الذي اخترته من جديد. عطّله بضبط web.keyless_rescue: false (وهو معطَّل أيضًا كلما كان keyless_fallback معطَّلًا).

يُعد xAI Web Search لا يدخل في سلسلة الاكتشاف التلقائي — فوجود XAI_API_KEY مضبوطًا (أو تسجيل الدخول عبر xAI Grok OAuth) لا يوجّه تلقائيًا حركة الويب عبر xAI، لأن بيانات الاعتماد تلك تُستخدم أيضًا في الاستدلال (inference) و TTS وتوليد الصور وقد يريد المستخدم backend مختلفًا للويب. فعّله صراحة بضبط web.backend: "xai".

استكشاف الأخطاء وإصلاحها

web_search القيمة {"success": false}

  • تحقّق من إمكانية الوصول إلى SEARXNG_URL متاح: curl -s "http://localhost:8888/search?q=test&format=json"
  • إذا ظهر لك HTTP 403، فصيغة JSON معطّلة — أضف json إلى قائمة formats في settings.yml وأعد التشغيل
  • إذا ظهر لك خطأ اتصال، فقد لا تكون الحاوية قيد التشغيل: docker ps | grep searxng

web_extract رسالة "search-only backend"

لا يستطيع SearXNG استخراج محتوى عناوين URL. اضبط web.extract_backend على مزوّد يدعم الاستخراج:

يعيد SearXNG عدد نتائج 0

بعض النسخ العامة تعطّل بعض محرّكات البحث أو الفئات. جرّب:

  • استعلامًا مختلفًا
  • نسخة عامة أخرى من searx.space
  • استضافة نسختك الخاصة للحصول على نتائج موثوقة

تقييد المعدل على نسخة عامة

انتقل إلى نسخة مستضافة ذاتيًا (راجع الخيار أ أعلاه). مع Docker، لا تخضع نسختك الخاصة لأي حدود معدّل.

web_extract محتوى مقتطَعًا مع تذييل [TRUNCATED] التذييل

هذا متوقّع للصفحات التي تتجاوز ميزانية الأحرف. يذكر التذييل الملف على القرص الذي يحتفظ بالنص الكامل النظيف واستدعاء read_file الدقيق لتصفّح الجزء المحذوف من المنتصف. لرؤية المزيد ضمن الاستجابة نفسها، ارفع قيمة web.extract_char_limit في config.yaml أو مرّر قيمة char_limit أكبر في الاستدعاء.
