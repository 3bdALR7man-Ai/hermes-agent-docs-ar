repair-promptsأبلغ عن system prompts المخزّنة التي ثبت تدهورها بسبب خلل ضغط الصيانة السابق لـ #122822. الوضع الافتراضي للإبلاغ فقط؛ --apply يمسح الصفوف المتحقق منها ليعيد الدور التالي بناءها، و --json قابل للقراءة آليًا (وغير تفاعلي عند الجمع مع --apply)، أما session_id الصريح فهو تجاوز تدميري يمكنه مسح prompt سليم أيضًا. الصفوف التي لا تحتوي على تثبيت tools[] قابل للقراءة، أو التي لا تثبّت إلا الذاكرة، تُعرض كغير قابلة للتحقق ولا يغيّرها الفحص (تعيد جلسة الذاكرة وحدها عند استئنافها تثبيت مجموعة أدواتها كاملة، وبعدها يمكن للفحص مسحها). أعد تشغيل gateway يعمل بعد --apply لتدخل الصفوف المصلحة حيز التنفيذ. راجع الجلسات → إصلاح Prompts مخزّنة متدهورة.
repair-profilesصحّح حالة الجلسات والتوجيه وموضوعات Telegram والوضع الصوتي التي حُفظت تحت profile خاطئ (صفوف في مخزن profile آخر، وتسميات تخالف مفتاح الجلسة، وروابط أبوة تتجاوز profiles، وصفوف فهرس لـ profiles محذوفة). افتراضيًا محاكاة دون تغييرات؛ --apply ينفّذ الإصلاحات بعد أخذ لقطة لكل مخزن (أوقف gateway أولًا)؛ --legacy-main rekey|move يحدّد طبيعة صفوف agent:main داخل مخزن profile مسمّى؛ --json للأتمتة. راجع الجلسات → إصلاح حالة انتقلت بين Profiles.
recoverاسترجاع دون اتصال وغير مُخرِّب لـ state.db تالف إلى قاعدة بيانات نظيفة منفصلة.
retitle-skillsإعادة توليد عناوين للجلسات المفتوحة بأمر /skill ، باستخدام ما كتبه المستخدم فعليًا؛ يسرد التغييرات ما لم تُمرَّر --apply مُرّر.

hermes import-agent

استيراد إعداد OpenClaw (~/.openclaw) أو Claude Code (~/.claude) أو OpenAI Codex CLI (~/.codex) أو Cursor (~/.cursor) إلى Hermes: تتحول التعليمات والقواعد إلى مدخلات في الذاكرة، وتتحول قواعد صلاحيات Bash(...) إلى command_allowlist/approvals.deny، وتُوضع خوادم MCP في mcp_servers، وتُنسخ المهارات. يعرض معاينة أولًا دائمًا. لا تُستورد مفاتيح API وبيانات الاعتماد أبدًا، باستثناء المفاتيح المسموح بها في OpenClaw عند تمرير --migrate-secrets. ويعيد --sync استيراد مصادر Claude Code و Codex و Cursor المسجّلة التي تغيّرت. وعلى تثبيت جديد، يعرض hermes setup تثبيت الإضافة وتشغيل الاستيراد نيابةً عنك عندما يجد أحد هذه الوكلاء.

انتقل الأمر من النواة إلى إضافة agent-importers الرسمية، مع hermes claw (ترحيل OpenClaw) الذي تحتفظ الإضافة بصيغته. وبدون الإضافة، يطبع hermes import-agent و hermes claw سطر التثبيت. راجع دليل الاستيراد لمعرفة الخيارات وجداول المطابقة.

OpenClaw: hermes import-agent openclaw

الانتقال بإعداد OpenClaw لديك إلى Hermes. يقرأ من ~/.openclaw (أو مسار مخصص) ويكتب إلى ~/.hermes. يكتشف تلقائيًا أسماء المجلدات القديمة (~/.clawdbot، ~/.moltbot) وأسماء ملفات الإعدادات (clawdbot.json، moltbot.json).

الخيارالوصف
--dry-runمعاينة ما سيُنقَل دون كتابة أي شيء.
--preset <name>نمط الانتقال المسبق: full (كل الإعدادات المتوافقة) أو user-data (يستبعد إعدادات البنية التحتية). لا يستورد أي من النمطين الأسرار — مرّر --migrate-secrets صراحةً.
--overwriteاستبدال ملفات Hermes الموجودة عند التعارض (الافتراضي: رفض التطبيق عندما تحتوي الخطة على تعارضات).
--migrate-secretsتضمين مفاتيح API في الانتقال. مطلوب حتى مع --preset full.
--no-backupتخطي لقطة zip قبل الانتقال لـ ~/.hermes/ (افتراضيًا تُكتَب أرشيف نقطة استعادة واحدة إلى ~/.hermes/backups/pre-migration-*.zip قبل التطبيق؛ قابلة للاستعادة عبر hermes import).
--source <path>مجلد OpenClaw مخصص (الافتراضي: ~/.openclaw).
--workspace-target <path>المجلد الهدف لتعليمات مساحة العمل (AGENTS.md).
--skill-conflict <mode>التعامل مع تعارض أسماء المهارات: skip (الافتراضي)، overwrite، أو rename.
--yesتخطي طلب التأكيد.

يعيد hermes claw cleanup تسمية مجلدات OpenClaw المتبقية إلى *.pre-migration بعد إتمام الترحيل (يتوقف OpenClaw عن العمل بعد ذلك؛ أعد تسميتها لإلغاء ذلك).

ما الذي يُنقَل

يغطي الانتقال أكثر من 30 فئة عبر الشخصية، والذاكرة، والمهارات، ومزوّدي النماذج، ومنصات المراسلة، وسلوك الوكيل، وسياسات الجلسات، وخوادم MCP، وTTS، وغيرها. تُستورَد العناصر إما مباشرةً إلى مكافئاتها في Hermes أو تُؤرشَف للمراجعة اليدوية.

مستوردة مباشرةً: SOUL.md، MEMORY.md، USER.md، AGENTS.md، المهارات (4 مجلدات مصدر)، النموذج الافتراضي، المزوّدون المخصصون، خوادم MCP، رموز وقوائم سماح منصات المراسلة (Telegram وDiscord وSlack وWhatsApp وSignal وMatrix وMattermost)، إعدادات الوكيل الافتراضية (مستوى التفكير، الضغط، تأخير التفاعل البشري، المنطقة الزمنية، sandbox)، قواعد الموافقة، إعدادات TTS، إعدادات المتصفح، إعدادات الأدوات، مهلة التنفيذ، قائمة سماح الأوامر، إعدادات الـ gateway، ومفاتيح API من 3 مصادر.

مؤرشفة للمراجعة اليدوية: مهام cron، والإضافات، وhooks/webhooks، وخلفية الذاكرة (QMD)، وإعدادات سجل المهارات، وواجهة المستخدم/الهوية، والتسجيل، وإعداد تعدد الوكلاء، وربط القنوات، وIDENTITY.md، وTOOLS.md، وHEARTBEAT.md، وBOOTSTRAP.md.

يفحص تحليل مفتاح API يفحص ثلاثة مصادر بترتيب الأولوية: قيم الإعدادات → ~/.openclaw/.env → auth-profiles.json. كل حقول الرموز تتعامل مع النصوص العادية، وقوالب البيئة (${VAR})، وكائنات SecretRef.

للاطلاع على خريطة تحويل مفاتيح الإعدادات الكاملة، وتفاصيل معالجة SecretRef، وقائمة التحقق بعد الانتقال، راجع دليل الانتقال الكامل.

أمثلة

hermes serve

تشغيل خادم Hermes الخلفي — gateway الـ JSON-RPC/WebSocket الذي يتصل به تطبيق desktop والعملاء البعيدون. إنه نفس الخادم الذي يشغّله hermes dashboard، لكن بلا واجهة (headless): لا يفتح واجهة متصفح أبدًا. يطلق تطبيق desktop خلفيته الخاصة من hermes serve؛ استخدم هذا الأمر مباشرةً عندما تريد خلفية بلا واجهة على مضيف بعيد. يقبل نفس خيارات --host / --port / --insecure / --skip-build / --stop / --status الخاصة بـ hermes dashboard أدناه (الربط بعنوان غير loopback يُفعِّل نفس بوابة المصادقة). يتطلب الإضافة [web]؛ ويحتاج مقبس Chat المدمج إضافةً إلى [pty] على مضيف POSIX.

تعارضات المنفذ: إذا كان المنفذ المطلوب (الافتراضي 9119) مشغولًا بالفعل بواسطة عملية أخرى (مثل hermes serve ثانٍ أو الـ gateway)، يطبع الأمر سطر إشارة قابل للمعالجة آليًا BACKEND_PORT_IN_USE port=<port> على stdout، مع تلميح مقروء للبشر يذكر المُحتمِل الشاغل للمنفذ، ويخرج برمز 75 (EX_TEMPFAIL) بدلًا من خطأ عام — بحيث تستطيع السكربتات وتطبيق desktop التمييز بين "منفذ مشغول" و"الخلفية معطَّلة". مرّر --port 0 لربط منفذ عشوائي متاح (الإقلاع الناجح يعلن المنفذ المختار عبر HERMES_BACKEND_READY port=<port>).

hermes dashboard

أطلق لوحة تحكم الويب لإدارة الإعدادات ومفاتيح API والجلسات. للحصول على backend دون واجهة رسومية، استخدم hermes serve. تُعدّ FastAPI و Uvicorn وأداة PTY المساعدة الخاصة بالمنصة اعتماديات أساسية. تضيف web قيودًا دقيقة لمجموعة HTTP، ويختارها إعداد PM القياسي عبر all. إذا تلفت الاعتماديات، نفّذ hermes pm repair. يتطلب تبويب Chat المضمّن بيئة PTY من نوع POSIX، مثل Linux أو macOS أو WSL2. راجع لوحة تحكم Hermes على الويب للتوثيق الكامل.

الخيارالافتراضيالوصف
--port9119المنفذ لتشغيل خادم الويب عليه
--host127.0.0.1عنوان الربط
--no-open—عدم فتح المتصفح تلقائيًا

--status—سرد عمليات hermes dashboard قيد التشغيل والخروج.

hermes webapp

افتح مساحة عمل Hermes Desktop في متصفح عادي. يخدمها الـ gateway على listener خاص به عندما تكون webapp.enabled مساوية لـ true في ملف الإعدادات (Configuration → Webapp). يبني هذا الأمر حزمة Webapp عندما تكون قديمة، ويشغّل الـ gateway إن لم يكن يعمل، ويفتح رابط تسجيل دخول صالحًا لمرة واحدة. تعمل المحادثات على ذلك الـ gateway، وهو نفسه الذي يستخدمه CLI و Desktop والمراسلة. راجع Desktop App → Use the Desktop workspace from a browser.

الرابط صالح لمدة 60 ثانية ويعمل مرة واحدة؛ يستبدله المتصفح بتسجيل الدخول الذي يحتفظ به في ذلك التبويب. لا يستطيع الحصول على رابط إلا مستخدم نظام التشغيل الخاص بك: إذ يجيب الـ gateway عن هذا الأمر عبر socket التحكم الخاص به. على Linux يتحقق الـ gateway من أن اتصال المتصفح يخص مستخدم نظام التشغيل الخاص بك؛ وعلى Windows لا يتحقق من شيء، ولا ينتقل الرابط إلا في سطر أوامر مشغّل المتصفح، الذي لا يستطيع المستخدمون العاديون الآخرون قراءته. وعلى macOS و BSDs و illumos لا ينطبق أي من الأمرين، لذلك لا يمرّر الأمر الرابط إلى مشغّل المتصفح أبدًا: بل يكتبه في صفحة لا يقرؤها إلا مستخدم نظام التشغيل الخاص بك (webapp/launch-*.html في مجلد gateway home) ويفتح تلك الصفحة. وحيث لا يستطيع فتح متصفح، وعلى WSL، يطبع الرابط لتفتحه بنفسك. وعلى macOS قد يُفتح المتصفح في مكان لا تراه (عبر SSH، أو على شاشة جهاز Mac نفسه): فإذا لم يُفتح أي متصفح، شغّل hermes webapp --no-open للحصول على الرابط. وإلى أن يُستخدم، فإنه يسجّل دخول متصفح باسمك، لذا أبقِه خاصًا.

بالنسبة إلى profile مسمّى يخدمه الـ gateway الافتراضي (hermes -p work webapp)، تُفتح Webapp على ذلك الـ profile.

خلف بوابة تسجيل الدخول إلى لوحة التحكم (webapp.host: 0.0.0.0 أو ::، أو عند ضبط webapp.public_url)، يفتح الأمر عنوان Webapp بدلًا من رابط لمرة واحدة، حيث يعود تسجيل الدخول: فعند ضبط webapp.public_url يكون ذلك العنوان؛ وعلى الشبكة المحلية (LAN) يكون العنوان الذي سجّل له Web Access Start تسجيل دخول Nous (webapp/sign-in-registration.json)، ما دام لا يزال عنوان LAN لهذا الجهاز ومنفذ Webapp؛ وإلا فعنوان الـ loopback، الذي يخدم مزوّد كلمة مرور أو تسجيل دخول أُعدّ يدويًا له. تسجّل الدخول هناك بحساب لوحة التحكم. وعندما يعجز الـ gateway عن خدمة Webapp، يذكر الأمر السبب؛ ويقرأ الـ gateway إعدادات Webapp عند بدء تشغيله، لذا شغّل hermes gateway restart بعد إصلاح السبب. أما حزمة Webapp التي لم تُبنَ بعد فهي استثناء: يبنيها هذا الأمر، ويخدمها الـ gateway العامل فورًا.

hermes profile

إدارة profiles — نُسخ Hermes متعددة معزولة، لكل منها إعداداتها وجلساتها ومهاراتها ومجلدها الرئيسي الخاص.

الأمر الفرعيالوصف
listسرد كل الـ profiles.
use <name>ضبط profile افتراضي ثابت.
create <name> [--clone] [--clone-all] [--clone-from <source>] [--no-alias]إنشاء profile جديد. --clone ينسخ الإعدادات، و.env، وSOUL.md، والمهارات، وملفات الذاكرة المُنقَّحة MEMORY.md/USER.md من الـ profile النشط. --clone-all ينسخ كل الحالة. --clone-from يحدّد profile مصدر ويستلزم نسخ الإعدادات ما لم يُقترَن بـ --clone-all.
delete <name> [-y]حذف profile.
show <name>عرض تفاصيل profile (المجلد الرئيسي، الإعدادات، إلخ).
alias <name> [--remove] [--name NAME]إدارة سكربتات wrapper للوصول السريع إلى profile.
rename <old> <new>إعادة تسمية profile.
export <name> [-o FILE]تصدير profile إلى أرشيف .tar.gz (نسخة احتياطية محلية).
import <archive> [--name NAME]استيراد profile من أرشيف .tar.gz (استعادة محلية).
install <source> [--name N] [--alias] [--force] [-y]تثبيت توزيعة profile من رابط git أو مجلد محلي.
update <name> [--force-config] [-y]إعادة سحب توزيعة؛ يحافظ على بيانات المستخدم (الذكريات، الجلسات، المصادقة).
info <name>عرض مانفست توزيعة profile (الإصدار، المتطلبات، المصدر).

أمثلة:

hermes completion

طباعة سكربت إكمال shell إلى stdout. صدّر المخرجات في ملف إعداد shell الخاص بك لإكمال tab لأوامر Hermes وأوامرها الفرعية وأسماء الـ profiles.

أمثلة:

hermes pm

إدارة الأدوات محددة الإصدار وبيئات اعتماديات Python وتشخيصاتها. لا يحدّث هذا الأمر تطبيق Hermes نفسه.

لتطوير المصدر، نفّذ سكربت الإعداد مرة واحدة، ثم فعّل البيئة المثبّتة باستخدام source ./activate أو . .\activate.ps1 في PowerShell. استخدم deactivate لاستعادة بيئة الـ shell السابقة. راجع سير عمل المطوّر للتجهيز والأوامر اليومية وتحديث الاعتماديات وبيئات الاختبار.

راجع إدارة الحزم لكل أمر فرعي وسلوك المصدر مقابل الحزمة وسياسة التثبيت الكسول وأوامر المشرفين.
