Guidance: توليد مقيّد من LLM

متى تستخدم هذه المهارة

استخدم Guidance عندما تحتاج إلى:

  • التحكم في صياغة مخرجات LLM عبر regex أو grammars
  • ضمان توليد JSON/XML/كود صالح
  • تقليل زمن الاستجابة (latency) مقارنة بأساليب الـ prompting التقليدية
  • فرض صيغ منظّمة (تواريخ، بريد إلكتروني، معرّفات، إلخ)
  • بناء سير عمل متعدد الخطوات باستخدام تدفق تحكم بأسلوب Python
  • منع المخرجات غير الصالحة عبر قيود نحوية (grammatical constraints)

التثبيت

البدء السريع

مثال أساسي: توليد منظّم

صيغة المحادثة مع نموذج محلي

دعم القيود (constraints) يتطلّب وصولًا محليًا إلى الـ logits. التوليد المقيّد باستخدام regex أو select() أو grammars يعمل فقط مع الـ backends المحلية (Transformers وLlamaCpp). أما backends واجهات API البعيدة (OpenAI ونسخ Azure) فتدعم gen() / المحادثة غير المقيّدة فقط — ولا يمكنها فرض قيود على مستوى الـ token. الإصدار guidance 0.3.x لا يتضمّن الفئة models.Anthropic.

المفاهيم الأساسية

1. مدراء السياق (Context Managers)

يستخدم Guidance مدراء سياق بأسلوب Python للتفاعلات على طراز المحادثة.

الفوائد:

  • تدفّق محادثة طبيعي
  • فصل واضح للأدوار
  • سهل القراءة والصيانة

2. التوليد المقيّد (Constrained Generation)

يضمن Guidance تطابق المخرجات مع الأنماط المحدَّدة باستخدام regex أو grammars.

قيود Regex

كيف يعمل ذلك:

  • يُحوَّل الـ regex إلى grammar على مستوى الـ token
  • تُستبعَد الرموز (tokens) غير الصالحة أثناء التوليد
  • لا يمكن للنموذج إنتاج سوى مخرجات مطابقة

قيود الاختيار (Selection Constraints)

3. معالجة حدود الـ Token (Token Healing)

يقوم Guidance تلقائيًا بـ"معالجة" حدود الـ token بين الـ prompt والتوليد.

المشكلة: تُنشئ عملية التقطيع إلى tokens حدودًا غير طبيعية.

الحل: يتراجع Guidance عن token واحد ويعيد التوليد.

الفوائد:

  • حدود نصية طبيعية
  • لا مشاكل تباعد غير مريحة
  • أداء أفضل للنموذج (يرى تسلسلات tokens طبيعية)

4. التوليد القائم على Grammar

عرّف بنى معقّدة عبر تركيب دوال grammar. صيغة القالب النصي grammar= لم تعد جزءًا من guidance الحالي — ابنِ الـ grammars من دوال قابلة للتركيب، أو استخدم guidance.json() لصيغة JSON.

حالات الاستخدام:

  • مخرجات منظّمة معقّدة
  • بنى بيانات متداخلة
  • صياغة لغات البرمجة
  • لغات مخصّصة لمجال معيّن (DSL)

5. دوال Guidance

أنشئ أنماط توليد قابلة لإعادة الاستخدام باستخدام المُزخرِف (decorator) @guidance.

دوال ذات حالة (Stateful Functions):

إعداد الـ Backend

OpenAI (بعيد — غير مقيّد فقط)

لا تستطيع backends واجهات API البعيدة إجراء توليد مقيّد (regex/select/grammar)؛ استخدمها فقط للمحادثة العادية أو gen(). أما للقيود، فاستخدم backend محليًا.

متى تختار Guidance:

  • عند الحاجة إلى قيود regex/grammar
  • عند رغبتك في Token Healing
  • عند بناء سير عمل معقّد مع تدفق تحكم
  • عند استخدام نماذج محلية (Transformers، llama.cpp)
  • عند تفضيلك صياغة بأسلوب Python

متى تختار البدائل:

  • Instructor: عند الحاجة إلى التحقق عبر Pydantic مع إعادة المحاولة تلقائيًا
  • Outlines: عند الحاجة إلى التحقق من مخطط JSON schema
  • LMQL: عند تفضيل صياغة استعلام تصريحية

خصائص الأداء

تقليل زمن الاستجابة:

  • أسرع بنسبة 30-50% من الـ prompting التقليدي للمخرجات المقيّدة
  • يقلّل Token Healing من إعادة التوليد غير الضرورية
  • تمنع قيود Grammar توليد tokens غير صالحة

استهلاك الذاكرة:

  • عبء إضافي طفيف مقارنة بالتوليد غير المقيّد
  • يُخزَّن تجميع الـ grammar مؤقتًا بعد أول استخدام
  • ترشيح فعّال للـ tokens وقت الـ inference

كفاءة استخدام الـ Tokens:

  • يمنع إهدار tokens على مخرجات غير صالحة
  • لا حاجة لحلقات إعادة المحاولة
  • مسار مباشر نحو مخرجات صالحة
