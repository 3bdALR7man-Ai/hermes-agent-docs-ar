التثبيت السريع

حزم Desktop على macOS أو Windows

نزّل حزمة منصتك من موقع Hermes من موقعنا وشغّله.

  • Windows: افتح تنزيل .appinstaller باستخدام Windows App Installer. يثبّت حزمة MSIX الموقّعة ويسجّل مصدر تحديثها. تخضع حزم Microsoft Store لملكية Store منفصلة.
  • macOS: افتح DMG، ثم انسخ Hermes.app إلى Applications. يتضمن ملف ZIP التطبيق الموقّع الذي تستخدمه أداة التحديث التلقائي.

تتضمن الحزم المضمّنة الوكيل و Python والاعتماديات المدعومة والواجهات المبنية مسبقًا. لا يبني التشغيل الأول بيئة التشغيل الأساسية هذه. وقد يظل الوصول إلى المزوّد والتكاملات الاختيارية يتطلبان اتصالًا بالشبكة.

يختلف مُثبّت الإقلاع Hermes-Setup: إذ ينزّل تثبيتًا من المصدر ويبني تطبيق سطح المكتب. راجع Hermes Desktop.

لا يوجد تنزيل Desktop منفصل مخصص للعمل البعيد وحده. لاستخدام Desktop مع Hermes backend على جهاز آخر، ثبّت إحدى الحزم أعلاه واربطه من Settings → Gateways؛ راجع الاتصال بـ backend بعيد.

ما يفعله المُثبّت من المصدر

تستنسخ السكربتات المصدر، وتجهّز uv، وتفوّض تهيئة الاعتماديات إلى PM. يوفر PM نسخًا مثبّتة الإصدار من Python و Node.js و npm و ripgrep و FFmpeg. يختار التثبيت من المصدر إضافة Python all، لا كل إضافة اختيارية. ويثبّت PM أيضًا أدوات المتصفح واستخدام الحاسوب افتراضيًا: agent-browser و Chromium المثبّت الإصدار الخاص به، و cua-driver (برنامج تشغيل استخدام الحاسوب، على macOS و Windows و glibc Linux). إذا فشل تنزيل، يكتمل التثبيت رغم ذلك ويطبع الأمر اللازم لإعادة المحاولة. برنامج تشغيل المتصفح الافتراضي (browser-harness، محرّك Browser Use CLI) اعتمادية Python عادية، لذلك يتضمنه كل تثبيت بالفعل، بما فيه تطبيق Desktop. تستخدم الأدوات الاختيارية الأخرى مسارات التثبيت الخاصة بميزاتها.

يستقر التثبيت الجديد على أحدث إصدار مستقر، وهي القناة التي يتبعها hermes update بعد ذلك (راجع التحديث). لتثبيت أحدث نسخة من main بدلًا من ذلك، مرّر --channel main على POSIX أو -Channel main على Windows (أو اضبط HERMES_INSTALL_CHANNEL=main أولًا في حالة الأوامر ذات السطر الواحد).

لاستبعاد أدوات المتصفح، مرّر --skip-browser على POSIX أو -SkipBrowser على Windows؛ ولبرنامج تشغيل استخدام الحاسوب، مرّر --skip-computer-use / -SkipComputerUse. يتذكر Hermes هذه الاختيارات: فلا تعيد التثبيتات اللاحقة ولا hermes update إضافتها. شغّل hermes pm install agent-browser أو hermes pm install cua-driver لتثبيتها وإلغاء ذلك الاختيار.

تنشئ السكربتات مشغّلًا وتهيّئ مجلد البيانات. ويستدعي التشغيل التفاعلي أيضًا الإعداد وضبط gateway. يتجاوز --non-interactive على POSIX، أو -NonInteractive على Windows، المراحل التي تحتاج إلى إدخال. وتبني المرحلة الاختيارية --include-desktop / -IncludeDesktop سطح المكتب من المصدر.

تعرض السكربتات في الطرفية سطر حالة واحدًا لكل خطوة وتكتب مخرجات git و uv وعمليات البناء إلى logs/install.log ضمن مجلد بيانات Hermes؛ وتطبع الخطوة الفاشلة آخر أسطره ومسار السجل. وفي CI (عند ضبط CI أو GITHUB_ACTIONS)، أو عند إعادة توجيه المخرجات، أو مع --verbose / -Verbose أو HERMES_INSTALL_VERBOSE=1، تُبث كل المخرجات بدلًا من ذلك.

HERMES_HOME يختار بيانات المستخدم. ويختار خيار --dir في سكربت POSIX نسخته المسحوبة من المصدر بصورة مستقلة. يوفر Windows -HermesHome و -InstallDir. لا يؤدي تشغيل سكربت POSIX بصفة root إلى اختيار بنية FHS تلقائيًا: إذ يستخدم المجلد الرئيسي لـ root ما لم توفر مسار مصدر صريحًا.

تختلف دورة حياة مخزن أدوات PM عن أجيال Python الخاصة بكل تثبيت. راجع إدارة الحزم لمعرفة مواقعها. لا تحذف جذر البيانات لإصلاح تثبيت التطبيق.

هل تشغّل Hermes بالفعل على جهاز آخر؟

لا تحتاج إلى إعادة بناء إعدادك من الصفر. استعد نسخة احتياطية كاملة باستخدام hermes import (راجع تصدير Hermes إلى جهاز آخر)، أو انقل وكيلًا واحدًا باستخدام hermes profile import (راجع نقل profile واحد إلى جهاز آخر). لاحظ أن تصدير الـ profile يستبعد بيانات الاعتماد عن قصد، لذا فإن التصدير وحده ليس نسخة احتياطية كاملة — يشرح قسم hermes backup مقابل hermes profile export متى تستخدم كلًا منهما.

المتطلبات المسبقة

في سكربت المصدر لـ POSIX، وفّر Git و curl و tar وأدوات SHA-256. ويمكن لـ Windows تجهيز أرشيف Git for Windows المثبّت الإصدار عند غياب Git. ينزّل السكربت دائمًا إصدار uv المحدد والمتحقق منه؛ ولا يستخدم أي uv موجود مسبقًا في PATH لديك.

تعمل التثبيتات الرسمية الحالية على Python 3.14. يسمح النطاق الأوسع >=3.11,<3.15 في pyproject.toml لتثبيتات Python الأقدم بتشغيل أداة التحديث قبل أن يحوّلها PM إلى 3.14؛ ولا يَعِد بدعم بيئة التشغيل الحالية على 3.11–3.13. يختار PM إصدارات الأدوات المُدارة من pm/lock.json؛ ولا يتبنى إصدارات Node عشوائية من النظام كبيئة تشغيل مثبتة.

قد يتطلب البناء من المصدر مترجمًا أصليًا ومكتبات تطوير للمنصة. ويضيف بناء Electron من المصدر متطلبات لوحدات Node الأصلية. لا تنطبق متطلبات البناء المسبقة هذه على تثبيت حزمة سطح مكتب كاملة. ويتطلب Linux Chromium أيضًا مكتبات نظام توفرها التوزيعة.

على glibc Linux، يرتبط Node.js المُدار بـ libatomic.so.1، وهي لا تتوفر في صور Debian و Ubuntu وعائلة RHEL الدنيا. وعندما تكون المكتبة ناقصة، يثبّت المُثبّت و hermes update حزمة التوزيعة (libatomic1 على apt و zypper، و libatomic على dnf/yum و apk، و gcc-libs على pacman). يشغّلان مدير الحزم مباشرةً بصفة root، أو عبر sudo -n خلاف ذلك. ويطلب التشغيل التفاعلي كلمة مرور sudo مرة واحدة قبل تثبيت الاعتماديات. ولا يطلب التشغيل مع --non-interactive أي إدخال. وإذا تعذّر إجراء التثبيت، يسمّي الخطأ الأمر الدقيق لمدير الحزم الذي عثر عليه.

مستخدمو Nix

لم يعد Nix مسار تثبيت مدعومًا صراحةً (يُقدَّم الدعم بأفضل جهد فقط). إذا كنت تستخدم Nix بالفعل (على NixOS أو macOS أو Linux)، فهناك مسار إعداد مخصص يتضمن Nix flake، ووحدة NixOS تصريحية (declarative)، ووضع حاوية اختياريًا. راجع دليل إعداد Nix و NixOS.

مجلدات home المرتبطة رمزيًا والتخزين الخارجي

يدعم Hermes أن يكون HERMES_HOME رابطًا رمزيًا (symlink)، وكذلك المجلدات الفرعية داخله، بما في ذلك hooks و skills و sessions و logs. أثناء تهيئة مجلد home، يُحافَظ على روابط المجلدات الموجودة، وتُترك صلاحيات المجلدات المرتبطة (والمجلدات المتفرعة منها مثل logs/curator) لمالكها.

إذا كان هدف الرابط مفقودًا أو يتعذر الوصول إليه أو ليس مجلدًا، تتوقف التهيئة بخطأ تخزين يذكر المسار وهدف الرابط. لا يستبدل Hermes الرابط ولا ينشئ هدفه المفقود: فذلك قد يؤدي إلى كتابة البيانات على القرص المحلي بينما تكون وحدة التخزين الخارجية أو وحدة NAS غير مُركّبة (unmounted). افحص الرابط المُبلَّغ عنه، وأعد تركيب وحدة التخزين أو صحّح هدف الرابط، وتحقق من صلاحيات الوصول قبل إعادة المحاولة. وإذا كنت تريد عمدًا هدفًا جديدًا لملفات dotfiles، فأنشئه بنفسك فقط بعد التأكد من توفر وحدة التخزين المقصودة.

hermes doctor عن حالات الفشل هذه كمشكلات تخزين، لا كملف YAML غير صالح. احتفظ بملف config.yaml الحالي؛ فتنفيذ hermes setup ليس الحل لمجلد غير متاح. هذا فحص لتوفر المجلد، وليس أداة لمراقبة التركيب (mount): فوجود المجلد لا يثبت أن وحدة التخزين المقصودة مُركّبة.

الاكتشاف التلقائي لطريقة التثبيت

تتحدد الجهة المسؤولة عن التحديث بحسب التثبيت قيد التشغيل، لا بحسب مجلد بياناته الرئيسي وحده. تستخدم النسخ المسحوبة من المصدر مسار تحديث Git المُدار. وتحتفظ حزم Desktop و Docker و Nix و Termux بآلية التحديث الخاصة بمالك الحزمة. يعرض hermes doctor منشأ التثبيت. راجع التحديث وإلغاء التثبيت قبل تغيير الملفات التي تديرها الحزمة.
