مزوّدو LLM والنماذج

تغطي هذه الصفحة إعداد مزوّدي الاستدلال (inference) لـ Hermes Agent — من واجهات API السحابية مثل OpenRouter و Anthropic، إلى endpoints مستضافة ذاتيًا مثل Ollama و vLLM، إلى إعدادات التوجيه (routing) والاحتياط (fallback) المتقدمة. تحتاج إلى مزوّد واحد على الأقل مُهيّأ لاستخدام Hermes.

يرسل كلا مزوّدي OpenCode المدمجَين ترويسة x-opencode-session مبهمة خاصة بكل محادثة في كل طلب (الأدوار الرئيسية على كل وسائل النقل، إضافة إلى الاستدعاءات المساعدة مثل الضغط والعناوين وفحوص الموافقة واستعلامات skills-hub والأسئلة الجانبية /btw — بما فيها التي تعمل في الخلفية بعد انتهاء الدور؛ وتستخدم استدعاءات Kanban دون واجهة specify/decompose وتقديرات لوحة التحكم مفتاحًا لكل مهمة؛ وترسل العمليات المنفردة دون جلسة حية أصلًا، كتوليد رسالة commit في Desktop من لوحة المراجعة، مفتاحًا مؤقتًا جديدًا). ويستخدمه OpenCode لتثبيت محادثة على backend واحد كي يظل تخزين الـ prompt المؤقت جاهزًا؛ وتُشتق القيمة من معرّف جلسة Hermes (أو معرّف مهمة Kanban) ولا تحمل أي بيانات شخصية.

يثبّت كل من مزوّدي OpenCode المدمجَين وسيطه الخاص على opencode.ai (opencode-zen → /zen/v1, opencode-go → /zen/go/v1). ويُصحَّح model.base_url المتبقي من الوسيط الآخر إلى وسيط المزوّد المحدَّد، ويحدد النموذج الذي تختاره (-m, /model، أو عنصر احتياطي، أو تجاوز للقناة) الوسيط المستخدم — فلا يرسل التبديل من نموذج Zen إلى نموذج خاص بـ Go الطلب إلى Zen أبدًا. ويُعاد تطبيق التوجيه نفسه لكل نموذج عند استئناف جلسة (hermes --resume, /resume، ومسارات الاستئناف في TUI و Desktop): فلا تُنقل صيغة نقل أو URL وسيط سُجّل حين كانت الجلسة تعمل بنموذج OpenCode مختلف إلى النموذج الذي تُفتح الجلسة عليه مجددًا. وتُعامل نماذج OpenCode التي يحتوي معرّفها علامة -vision (مثل deepseek-v4-flash-vision-exp) بوصفها قادرة على الرؤية حتى قبل إدراجها في models.dev، لذا يرفق agent.image_input_mode: auto الصور أصليًا دون تجاوز supports_vision . والمزوّد المخصّص الذي تعرّفه ضمن providers: ويمتد اسمه من slug عائلة (مثل opencode-go-bridge) يحصل كذلك على توجيه API-mode لكل نموذج وعلى معالجة /v1 الخاصَين بالعائلة، لكن base_url له يُؤخذ كما أُعلن: سمِّه بحسب الوسيط الذي يشير إليه فعليًا. وتتبع المهام المساعدة (auxiliary.compression، والعناوين، والرؤية، و MoA) الموجّهة إلى مزوّد OpenCode جدول النماذج نفسه، لذا يعمل نموذج خاص بـ Responses مثل gpt-5.6-luna أو ذو صيغة Anthropic مثل minimax-m2.5 هناك تمامًا كما يعمل في المحادثة الرئيسية.

لمسار مفتاح API الرسمي، راجع دليل Google Gemini المخصص.

اسم بديل لمفتاح النموذج

في قسم الإعدادات model: ، يمكنك استخدام default: أو model: كاسم مفتاح لمعرّف نموذجك. ويعمل كل من model: { default: my-model } و model: { model: my-model } بالطريقة نفسها.

Nous Portal

Nous Portal هو gateway الاشتراك الموحّد الخاص بـ Nous Research والطريقة الموصى بها لتشغيل Hermes Agent. تسجيل دخول OAuth واحد يغطي أكثر من 300 نموذج وكيلي متطور (Claude، GPT، Gemini، DeepSeek، Qwen، Kimi، GLM، MiniMax، Grok، ...) بالإضافة إلى Tool Gateway (البحث في الويب، توليد الصور، TTS، أتمتة المتصفح) — تُفوتَر مقابل اشتراكك في Nous بدلًا من حسابات منفصلة لكل مزوّد.

ليس لديك اشتراك بعد؟ احصل على واحد من portal.nousresearch.com/manage-subscription.

للتفاصيل الكاملة: راجع صفحة تكامل Nous Portal المخصصة (ما يتضمنه الاشتراك، كتالوج النماذج، استكشاف الأخطاء وإصلاحها) ودليل تشغيل Hermes Agent مع Nous Portal خطوة بخطوة.

تعريف العميل (Client identification). يحمل كل طلب من Hermes Agent إلى Portal علامة client=hermes-client-v<version> (مثلًا client=hermes-client-v0.13.0) تُضبط تلقائيًا وفق إصدارك المثبَّت. تُرسَل هذه العلامة على جميع مسارات Portal — حلقة الدردشة الرئيسية، الاستدعاءات المساعدة، ملخّص الضغط، استخراج الويب — وتتيح لتحليلات القياس عند Portal تمييز حركة بيانات Hermes عن العملاء الآخرين. لا حاجة لأي إعداد — تتحدث العلامة تلقائيًا عند تنفيذ hermes update.

مصادقة JWT (تلقائية). يفضّل Hermes JWTs محدودة النطاق من نوع inference:invoke لطلبات Portal مع مسار مفتاح الجلسة المبهم (opaque) القديم كاحتياطي. لا حاجة لأي إعداد — تُدار بيانات الاعتماد عبر تدفق OAuth وتتجدد بشفافية. تُعزَل رموز التحديث (refresh tokens) المُلغاة لتجنب حلقات إعادة التشغيل (replay).

ملاحظة Codex

يصادق مزوّد OpenAI Codex عبر device code افتراضيًا (افتح URL وأدخل رمزًا). ويمكن للمؤسسات التي تعطّل منح device-code اختيار تدفق رمز التفويض بالمتصفح + PKCE بدلًا منه: hermes auth add openai-codex --browser (لتسجيل دخول واحد) أو auth.codex_login_flow: browser في config.yaml (لكل تسجيل دخول Codex، بما فيه hermes model). ويستمع ذلك التدفق على http://localhost:1455/auth/callback — وهو redirect URI المسجّل لعميل Codex، لذا فالمنفذ ثابت؛ وإذا كان مشغولًا بالفعل (تسجيل دخول Codex CLI جارٍ)، يبلغ Hermes بذلك ويعود إلى device code. وعبر SSH يحتاج المستمع إلى نفق (ssh -N -L 1455:127.0.0.1:1455 user@host، راجع OAuth عبر SSH). ويخزّن Hermes بيانات الاعتماد الناتجة في مخزن مصادقته الخاص ضمن ~/.hermes/auth.json ويمكنه استيراد بيانات اعتماد Codex CLI الموجودة من ~/.codex/auth.json عند توفرها. ولا يلزم تثبيت Codex CLI. ويُتحكم في التبنّي التلقائي لتسجيل دخول Codex CLI (حين يفشل تحديث Hermes نفسه) عبر auth.adopt_external_logins — راجع تسجيلات دخول CLI المستعارة.

إذا فشل تحديث token بخطأ نهائي (HTTP 4xx، أو invalid_grant، أو منح ملغى، وغيرها)، يعلّم Hermes token التحديث بوصفه منتهيًا ويتوقف عن إعادة استخدامه كي لا ترى سيلًا من إخفاقات المصادقة المتطابقة. ويعرض الطلب التالي بدلًا من ذلك رسالة إعادة مصادقة ذات نوع محدد. نفّذ hermes auth add openai-codex (أو hermes model → اشتراك ChatGPT أو Codex) لبدء تسجيل دخول جديد (device code، أو --browser لتدفق loopback PKCE)؛ ويُرفع العزل عند التبادل الناجح التالي.

قد يفشل تسجيل دخول الجهاز بـ [SSL: UNEXPECTED_EOF_WHILE_READING] أو انتهاء مهلة مصافحة TLS على Python/OpenSSL 3.5+ حين يرفض جهاز وسيط مجموعات ما بعد الكم مثل X25519MLKEM768 (وقد يظل curl يعمل). وإسقاط اتصال مرة واحدة ليس قاتلًا: أثناء انتظار موافقتك في المتصفح، يواصل Hermes الاستطلاع خلال ما يصل إلى ستة أخطاء نقل متتالية (ويعيد طلب device-code وتبادل token مرتين) قبل الاستسلام، لذا لا يظهر هذا الخطأ إلا إذا استمر تعطل الشبكة. ولا يغيّر Hermes سياسة TLS الافتراضية. وجّه OPENSSL_CONF إلى إعدادات تقصر Groups على المنحنيات التقليدية قبل تشغيل hermes model، أو شخّص باستخدام TLS 1.2:

تحذير

حتى عند استخدام Nous Portal أو Codex أو endpoint مخصّص، تستخدم بعض الأدوات (الرؤية، وتلخيص الويب، و MoA) نموذجًا "مساعدًا" منفصلًا. وافتراضيًا (auxiliary.*.provider: "auto") يوجّه Hermes هذه المهام إلى نموذج محادثتك الرئيسي — وهو النموذج نفسه الذي اخترته في hermes model. ويمكنك تجاوز كل مهمة منفردة لتوجيهها إلى نموذج أرخص/أسرع (مثل Gemini Flash على OpenRouter) — راجع النماذج المساعدة.

Nous Tool Gateway

يحصل أيضًا المشتركون المدفوعون في Nous Portal على الوصول إلى Tool Gateway — حيث يُوجَّه البحث في الويب وتوليد الصور و TTS وأتمتة المتصفح عبر اشتراكك. ولا تلزم مفاتيح API إضافية. وفي تثبيت جديد، يسجّل hermes setup --portal دخولك، ويعيّن Nous مزوّدًا لك، ويفعّل الـ gateway بأمر واحد. ويمكن للمستخدمين الحاليين تفعيله من hermes model أو لكل أداة من hermes tools. وافحص التوجيه في أي وقت باستخدام hermes portal info.

خطط الاشتراك: ما الذي تدفع خطتك مقابله

يتيح لك العديد من المزوّدين تسجيل الدخول إلى Hermes باستخدام اشتراك مستهلك (Claude Max، ChatGPT، SuperGrok / X Premium+، …) بدلًا من مفتاح API. ما الذي يدفع مقابله ذلك الاشتراك فعليًا — وما لا يدفعه — يختلف حسب المزوّد، وهو المصدر الأكثر شيوعًا لمفاجآت الفوترة. الجدول أدناه هو النسخة المختصرة؛ يحتوي قسم كل مزوّد الخاص به على التفاصيل.

الخلايا المُشار إليها بـ غير موثّق حاليًا تعني ذلك بالضبط: لم تُحدِّد وثائق Hermes بعد هذا السلوك. لا تفترض — تحقق من لوحة فوترة مزوّدك، وعامل هذه الحالات كأسئلة مفتوحة.

Anthropic. يوجَّه مسار OAuth كـ Claude Code مقابل حسابك في Anthropic ويعمل فقط على خطة Claude Max مع رصيد استخدام إضافي مشترى — لا يُستهلَك مخصص Max الأساسي أبدًا بواسطة Hermes، فقط رصيد الاستخدام الإضافي/الزائد المُضاف فوقه. لا يستطيع مشتركو Claude Pro استخدام هذا المسار؛ البديل المدعوم هو ANTHROPIC_API_KEY، الذي يُفوتَر بالدفع لكل token مقابل مؤسسة ذلك المفتاح بأسعار API القياسية. راجع Anthropic (Native) أدناه.

OpenAI Codex. يُصادق Hermes عبر ChatGPT device-code OAuth، ويخزّن بيانات الاعتماد في ~/.hermes/auth.json، ويمكنه استيراد بيانات اعتماد Codex CLI الموجودة من ~/.codex/auth.json. مستويات خطة ChatGPT المؤهَّلة، وكيفية احتساب استخدام Hermes ضمن حدود Codex لخطتك، غير موثّقة حاليًا — تغطي ملاحظة Codex تحت Nous Portal سلوك المصادقة وتحديث الرمز فقط.

xAI (SuperGrok / X Premium+). يعمل OAuth عبر المتصفح مع اشتراك SuperGrok نشط أو اشتراك X Premium+ على حساب X المرتبط، ويُعاد استخدام نفس رمز bearer بواسطة أدوات xAI المباشرة (TTS، توليد الصور، توليد الفيديو، التفريغ الصوتي، بحث X). إذا أعاد الاستدلال HTTP 403 بعد تسجيل دخول ناجح، فهذا قيد على مستوى/أهلية من جانب xAI، وليس رمزًا قديمًا — الحل البديل هو التبديل إلى XAI_API_KEY. راجع xAI (Grok) أدناه ودليل xAI Grok OAuth.

Google Gemini. لا توجد حاليًا طريقة لتسجيل الدخول إلى Hermes باستخدام اشتراك Gemini للمستهلكين — يأخذ مزوّد gemini مفتاح API، وتُفوتَر Google Vertex AI إلى مشروع GCP الخاص بك. يُوصى بمشروع Google Cloud مُفعَّل الفوترة لاستخدام الوكيل؛ حصص المستوى المجاني صغيرة جدًا لجلسات الوكيل طويلة الأمد. راجع دليل Google Gemini.
