معلومة

ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

مهارة Hyperliquid

استعلم عن بيانات سوق وحسابات Hyperliquid عبر endpoint /info العام. للقراءة فقط — بلا مفتاح API، وبلا توقيع، وبلا تنفيذ أوامر.

12 أمرًا: dexs، markets، spots، candles، funding، l2، state، spot-balances، fills، orders، review، export. مكتبة قياسية (stdlib) فقط (urllib، json، argparse).

متى تُستخدم

  • يطلب المستخدم بيانات سوق Hyperliquid للعقود الآجلة (perp) أو السوق الفوري (spot)، أو الشموع (candles)، أو التمويل (funding)، أو دفتر L2
  • يريد المستخدم فحص مراكز perp لمحفظة ما، أو أرصدة spot، أو الصفقات المنفَّذة (fills)، أو الأوامر
  • يريد المستخدم مراجعة ما بعد التداول تجمع بين الصفقات الأخيرة وسياق السوق
  • يريد المستخدم فحص perp dexs المنشأة من قِبل builders أو أسواق HIP-3
  • يريد المستخدم تصديرًا موحّدًا بصيغة JSON للشموع والتمويل تحضيرًا للاختبار الرجعي (backtesting)

المتطلبات الأساسية

مكتبة قياسية (stdlib) فقط — بلا حزم خارجية وبلا مفتاح API.

يقرأ السكربت الملف ${HERMES_HOME:-~/.hermes}/.env لقيمتين افتراضيتين اختياريتين:

  • HYPERLIQUID_API_URL — تكون افتراضيًا https://api.hyperliquid.xyz. اضبطها على https://api.hyperliquid-testnet.xyz للشبكة التجريبية (testnet).
  • HYPERLIQUID_USER_ADDRESS — العنوان الافتراضي لأوامر state وspot-balances و fills وorders وreview. إذا لم تُضبط، مرّر العنوان كأول وسيطة (argument) موضعية.

يُؤخذ بالاعتبار ملف .env خاص بالمشروع في دليل العمل الحالي كبديل احتياطي للتطوير.

السكربت المساعد: ~/.hermes/skills/blockchain/hyperliquid/scripts/hyperliquid_client.py

الإجراء

1. اكتشاف DEXs والأسواق

  • تنطبق --dex فقط على endpoints العقود الآجلة (perp)؛ أغفلها لاستخدام أول perp dex.
  • قد تظهر أزواج spot باسم PURR/USDC أو بأسماء بديلة مثل @107.
  • تسبق أسواق HIP-3 اسم العملة باسم الـ dex، مثل mydex:BTC.

2. سحب بيانات السوق التاريخية

تُقسَّم endpoints النطاقات الزمنية إلى صفحات (pagination). للنطاقات الأكبر، كرّر الطلب بقيمة startTime لاحقة أو استخدم export (أدناه).

3. فحص دفتر الأوامر المباشر

استخدمه عند السؤال عن عمق الدفتر، أو السيولة قصيرة المدى، أو التأثير المحتمل لأمر كبير في السوق.

4. مراجعة حساب

يعيد state مراكز العقود الآجلة (perp)؛ ويعيد spot-balances جرد spot. استخدمهما لأسئلة مثل "كيف حال مراكزي؟" أو "ما الذي أحمله؟" أو "كم المتاح للسحب؟".

5. مراجعة الصفقات المنفَّذة والأوامر

6. توليد مراجعة تداول

يقدّم تقارير عن الربح والخسارة المحقَّقين، والرسوم، وعدد مرات الربح/الخسارة، وتفصيل حسب العملة، واتجاه السوق، ومتوسط التمويل لكل عقد آجل (perp) تم تداوله، إضافة إلى مؤشرات إرشادية (استنزاف الرسوم، التركّز، الخسائر المخالفة للاتجاه).

لتحليل أعمق لما بعد التداول: ابدأ بـ review لتحديد العملات أو الفترات الإشكالية ← اسحب fills وorders لتلك الفترة ← اسحب candles وfunding لكل عملة تم تداولها ← احكم على جودة القرار بمعزل عن جودة النتيجة.

7. تصدير مجموعة بيانات قابلة لإعادة الاستخدام

يحتوي JSON الناتج على: إصدار المخطط (schema)، بيانات وصفية عن المصدر، النطاق الزمني الدقيق، صفوف الشموع الموحّدة، صفوف التمويل الموحّدة، إحصاءات ملخّصة. استخدم --end-time-ms للحصول على نطاقات قابلة لإعادة الإنتاج.

المزالق

  • endpoints المعلومات العامة محدودة بحدّ معدل. قد تعيد الاستعلامات التاريخية الكبيرة نطاقات محدودة (capped)؛ كرّر الطلب بقيم startTime لاحقة.
  • يستخدم fills --hours ... واجهة userFillsByTime، التي لا تكشف سوى نافذة متجدّدة حديثة — وليس السجل الكامل.
  • يعيد historicalOrders الأوامر الأخيرة فقط؛ وليس تصديرًا كاملًا.
  • أمر review إرشادي (heuristic). لا يمكنه إعادة بناء النية، أو جودة تنفيذ الأمر، أو الانزلاق (slippage) الحقيقي من الصفقات المنفَّذة وحدها.
  • يكتب أمر export مجموعة بيانات موحّدة، وليس محرّك اختبار رجعي. ستظل بحاجة إلى نموذج انزلاق/تنفيذ خاص بك.
  • الأسماء البديلة لأزواج spot مثل @107 معرّفات صالحة حتى عندما تُظهر الواجهة اسمًا أكثر وضوحًا.
  • l2 لقطة (snapshot) في لحظة معينة، وليس سلسلة زمنية.

التحقق
