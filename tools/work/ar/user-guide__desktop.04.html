بناء المُثبّتات:

يُنفَّذ التوقيع والتوثيق (notarization) على macOS/Windows تلقائيًا عند وجود بيانات الاعتماد المطلوبة في البيئة (CSC_LINK / CSC_KEY_PASSWORD / APPLE_* لـ macOS، وWIN_CSC_* لـ Windows).

صلاحيات macOS وإعادة البناء المحلية (TCC)

أوقف جميع طلبات إذن المجلدات بمفتاح واحد. يطلب macOS الإذن لكل فئة على حدة (Desktop، ثم Downloads، ثم Documents، ...) كلما وصل Hermes إلى مجلد منها. ويغطي منح إذن Full Disk Access واحد جميع هذه المجلدات بشكل دائم — ومع هويات التوقيع الثابتة في Hermes يبقى الإذن ساريًا بعد كل تحديث:

  1. System Settings → Privacy & Security → Full Disk Access (أو نفّذ open "x-apple.systempreferences:com.apple.preference.security?Privacy_AllFiles")
  2. فعّل تطبيق الطرفية الذي تستخدمه — وكذلك Hermes.app إذا كنت تستخدم Desktop.
  3. أغلقها تمامًا ثم أعد تشغيلها مرة واحدة.

يُبلغ hermes doctor عمّا إذا كان سياق الطرفية الحالي يملك هذا الإذن بالفعل، ويعرض hermes setup هذه النصيحة على macOS عندما لا يملكه.

يحفظ macOS الأذونات الممنوحة (Full Disk Access، و Desktop/Downloads/Documents، و Accessibility، و Automation، والميكروفون) مرتبطةً بـهوية توقيع الكود الخاصة بالتطبيق، لا بمساره. وتُوقَّع التطبيقات المبنية محليًا والمحدَّثة ذاتيًا بتوقيع ad-hoc ثابت مرتبط بالمعرّف، لذا تبقى الأذونات سارية عبر التحديثات.

ملاحظة لمرة واحدة: الأذونات الممنوحة لإصدارات بُنيت قبل إصلاح التوقيع المرتبط بالمعرّف (PR #73681) تحمل الشرط القديم المرتبط بـ cdhash. يستمر macOS في عرض المفتاح بحالة ON لتلك الأذونات القديمة لكنه يعيد طلب الإذن، لأن الإذن المخزّن لم يعد يطابق الملف التنفيذي المُعاد بناؤه — ولا يحتوي طلب الإذن الحديث على زر Allow، فيبدو كأنه لا يوجد ما يمكن إعادة تفعيله. إذا حدث ذلك، فأعد ضبط الإذن القديم مرة واحدة وامنحه من جديد:

ثم فعّل المُدخل الجديد (ON) في System Settings، وأغلق Hermes تمامًا وأعد تشغيله. وتبقى الأذونات ثابتة من ذلك الحين.

للحصول على أقوى ضمان — هوية مرتبطة بشهادة، وهي الآلية نفسها التي يعتمد عليها مستخدمو yabai/skhd — أنشئ شهادة توقيع كود موقّعة ذاتيًا مرة واحدة واطلب من Hermes استخدامها. يتولى الأمر الواحد كل شيء (ينشئ الشهادة في login keychain، ويمنح codesign حق الوصول، ويكتب الإعدادات، ويعيد توقيع التطبيق المحزوم):

أو نفّذ ذلك يدويًا:

  1. Keychain Access → Certificate Assistant → Create a Certificate…
  2. الاسم (Name): Hermes Local Signing، ونوع الهوية (Identity Type): Self-Signed Root، ونوع الشهادة (Certificate Type): Code Signing.
  3. في Keychain Access، انقر نقرًا مزدوجًا على الشهادة الجديدة → Trust → واضبط Code Signing على Always Trust (فالشهادة الموقّعة ذاتيًا المستوردة لا تُعد هوية توقيع صالحة إلى أن تُمنح الثقة لتوقيع الكود — ويجب أن يُدرجها security find-identity -v -p codesigning بعد ذلك).
  4. hermes config set desktop.macos_signing_identity "Hermes Local Signing"

استخدم --identity <name> مع الأمر لإنشاء/استخدام شهادة باسم مختلف (الافتراضي: Hermes Local Signing). والأمر idempotent (تكرار تنفيذه لا يغيّر النتيجة) — أعد تشغيله بعد التحديثات لإعادة توجيه الإعدادات وإعادة توقيع التطبيق المُعاد بناؤه.

يعيد التحديث التالي توقيع التطبيق المُعاد بناؤه بتلك الشهادة؛ فتبقى كل أذونات TCC سارية. لا حاجة إلى حساب Apple Developer. وتُكتشف إصدارات الإصدار الرسمية الموثّقة (notarized) ولا يُعاد توقيعها أبدًا.

ملاحظة لمرة واحدة: تغيير هوية التوقيع (بما في ذلك أول تحديث بعد هذا الإصلاح) يغيّر هوية التطبيق مرة واحدة، لذا سيطلب macOS الإذن مرة أخيرة. وتبقى الأذونات ثابتة من ذلك الحين. إذا علِق إذن ما، فأعد ضبطه باستخدام tccutil reset All com.nousresearch.hermes ثم امنحه من جديد.
