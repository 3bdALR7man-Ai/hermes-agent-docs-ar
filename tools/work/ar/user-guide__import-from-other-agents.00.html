الاستيراد من وكلاء آخرين

hermes import-agent إعداد Claude Code أو OpenAI Codex CLI الحالي لديك إلى Hermes بأمر واحد. يتّبع النمط نفسه المعتمد على المعاينة أولًا في hermes claw migrate: تشاهد دائمًا خطة لكل عنصر قبل كتابة أي شيء، ولا يمسّ --dry-run القرص أبدًا.

تتحوّل قواعد بادئة Bash(npm run test:*) الخاصة بـ Claude إلى أنماط npm run test*. أما قواعد الصلاحيات غير Bash (Read(...)، WebFetch، ...) فتضبط أدوات خاصة بـ Claude وتُدرَج كقواعد غير مُطابَقة بدلًا من استيرادها.

ما لا يُستورَد أبدًا

مفاتيح API وبيانات الاعتماد. لا تُقرَأ ملفات بيانات الاعتماد (~/.claude/.credentials.json، ~/.codex/auth.json) أبدًا، وتُحذَف متغيرات بيئة خادم MCP أو الترويسات (headers) ذات الأسماء التي تبدو سرّية (*_TOKEN، *_API_KEY، Authorization، ...) وتُدرَج في التقرير حتى تعيد إضافتها عن قصد. شغّل hermes setup لإعداد المزوّدين، أو أضِف الأسرار (secrets) إلى ~/.hermes/.env.

ملاحظات حول السلوك

  • المعاينة أولًا، دائمًا. يطبع الأمر الخطة الكاملة قبل التطبيق؛ وفي الجلسات غير التفاعلية يتوقف عند المعاينة ما لم تمرّر --yes.
  • دمج، لا استبدال. تُنقَّى مدخلات الذاكرة من التكرار مقارنة بملف MEMORY.md الحالي لديك؛ وتُدمَج أنماط قائمتَي السماح والمنع مع ما هو موجود بالفعل في config.yaml.
  • تُتجاوَز التعارضات افتراضيًا. يُبلَّغ عن خادم MCP أو مهارة موجودة مسبقًا في Hermes كتعارض؛ مرِّر --overwrite لاستبدالها.
  • الملفات المُشوَّهة لا توقف التشغيل. يتحوّل ملف settings.json أو config.toml التالف إلى خطأ خاص بذلك العنصر في التقرير بينما يستمر استيراد كل شيء آخر.
  • قادم من OpenClaw بدلًا من ذلك؟ استخدم hermes claw migrate.

إبقاء الاستيرادات متزامنة

يسجّل كل استيراد ناجح مصدره (وبصمة كل ما قرأه) في ~/.hermes/import-sync.json. عندما تتغيّر إعدادات الوكيل الآخر لاحقًا — كإضافة مهارات جديدة أو تعديل CLAUDE.md / AGENTS.md أو إضافة خوادم MCP — اجلب التغييرات باستخدام:

لا تتطلب المزامنة مطالبات وتكلفتها منخفضة: تُتجاوَز المصادر التي لم تتغير ملفاتها عبر مقارنة البصمات، لذا يمكنك تشغيلها وفق جدول بأمان (مثل مهمة cron يومية). القواعد:

  • تظل عمليات دمج الذاكرة والإعدادات تزيل التكرار — لا تضيف المزامنة أبدًا مدخلات أو أنماطًا موجودة لديك مسبقًا.
  • المهارات التي سبق استيرادها عبر import-agent تُحدَّث في مكانها عندما تتغير النسخة المصدرية.
  • لا تُستبدَل أبدًا المهارات التي أنشأتها أو عدّلتها بنفسك ضمن فئة الاستيراد — تظل قواعد التعارض المعتادة سارية عليها (استخدم --overwrite في تشغيل يدوي لفرض الاستبدال).
  • لا تؤدي ملفات بيانات الاعتماد أبدًا إلى تشغيل المزامنة — تتجاهل البصمة تحديثات الـ tokens في ~/.claude/.credentials.json أو ~/.codex/auth.json، وتظل الأسرار تُحذف من كل ما يُستورَد.

يحاكي هذا التحديثات التلقائية في Settings > Import ضمن ChatGPT Work، مع تكييفها كأمر صريح قابل للفحص بدل خدمة تعمل في الخلفية.

manifest خاص بكل profile. ويُنقَل إلى profile تنشئه باستخدام hermes profile create <name> --clone --sync-imports، لذا يواصل hermes -p <name> import-agent --sync الجلب من أشجار الملفات الخارجية نفسها (راجع Profiles).
