الاستيراد من وكلاء آخرين

يستورد hermes import-agent إعدادك الحالي من OpenClaw أو Claude Code أو OpenAI Codex CLI أو Cursor إلى Hermes بأمر واحد. تشاهد دائمًا خطة لكل عنصر قبل كتابة أي شيء، ولا يمسّ --dry-run القرص أبدًا.

يأتي هذا الأمر من إضافة agent-importers الرسمية في كتالوج الإضافات، وتتولى Nous Research صيانتها في NousResearch/hermes-official-plugins.

الطريقة السهلة: hermes setup

في التثبيت الجديد، يفحص hermes setup وجود ~/.openclaw (أو ~/.clawdbot / ~/.moltbot القديمين) و~/.claude و~/.codex و~/.cursor قبل أي شيء آخر. وعند العثور على أحدها يسألك "Import your setup from Claude Code?" (مع ذكر ما وجده)؛ وإذا وجد عدة مصادر فتختار منها من قائمة تحقق محدَّدة بالكامل. وافق، فيثبّت الإعداد إضافة agent-importers من الكتالوج ما لم تكن مثبّتة لديك، ثم ينفّذ الاستيراد الموضح أدناه لكل مصدر اخترته، بما في ذلك المعاينة والتأكيد. وفي حالة OpenClaw يمرّر --migrate-secrets كما كانت خطوة OpenClaw المدمجة القديمة في Hermes تفعل، فتنتقل مفاتيح API ورموز البوتات (tokens) ويأتي قسما المزوّدين والمراسلة اللذان يليانه مملوءين مسبقًا. وإذا اخترت بعد ذلك Quick Setup وجلب الاستيراد نموذجًا مع مفتاحه، يسألك الإعداد هل تبقي ذلك النموذج (الافتراضي) أم تنتقل إلى Nous Portal. أجب بالنفي، أو لا تملك أيًّا من هذه المجلدات، فلا يُثبَّت شيء. هل أعددت Hermes من قبل؟ استخدم الأوامر أدناه.

يدويًا

ثبّت الإضافة مرة واحدة لكل profile:

ما الذي يُستورَد

OpenClaw (~/.openclaw)

لدى OpenClaw دليله الخاص الانتقال من OpenClaw، ويضم الربط الكامل (الشخصية، والذاكرة، والمهارات، ومزوّدي النماذج، ومنصات المراسلة، وسلوك الوكيل، وخوادم MCP وغيرها)، والخيارات --preset و--migrate-secrets و--workspace-target و--skill-conflict، والنسخة الاحتياطية قبل الانتقال، والأمر hermes claw cleanup. ولا تزال الصيغة الأقدم hermes claw migrate تعمل وتنفّذ الاستيراد نفسه.

ترويسة .mdc (frontmatter) التي تضم description وglobs وalwaysApply هي بيانات توجيه وصفية لمحرك القواعد في Cursor، وتُحذف؛ ولا يُستورد إلا متن القاعدة. والمهارة هي المجلد الذي يحوي SKILL.md، لذا يُستورد skills/shipping/land-it/ باسم cursor-imports/land-it/؛ ويُبلَّغ عن مهارتين بالاسم نفسه في مجلدين مختلفين بوصفهما تعارضًا.

ما لا يُستورَد أبدًا

مفاتيح API وبيانات الاعتماد. (OpenClaw هو الاستثناء الوحيد: فمفاتيح API ورموز البوتات المدرجة في قائمته المسموح بها لا تنتقل إلا عند تمرير --migrate-secrets.) لا تُقرأ ملفات بيانات الاعتماد (~/.claude/.credentials.json و~/.codex/auth.json و~/.cursor/cli-config.json) أبدًا، وتُحذف متغيرات بيئة خادم MCP أو الترويسات (headers) ذات الأسماء التي تبدو سرّية (*_TOKEN و*_API_KEY وAuthorization و...) وتُدرَج في التقرير لتعيد إضافتها عن قصد. شغّل hermes setup لإعداد المزوّدين، أو أضِف الأسرار (secrets) إلى ~/.hermes/.env.

ملاحظات حول السلوك

  • المعاينة أولًا، دائمًا. يطبع الأمر الخطة الكاملة قبل التطبيق؛ وفي الجلسات غير التفاعلية يتوقف عند المعاينة ما لم تمرّر --yes.
  • دمج، لا استبدال. تُنقَّى مدخلات الذاكرة من التكرار مقارنة بملف MEMORY.md الحالي لديك؛ وتُدمَج أنماط قائمتَي السماح والمنع مع ما هو موجود بالفعل في config.yaml.
  • تُتجاوَز التعارضات افتراضيًا. يُبلَّغ عن خادم MCP أو مهارة موجودة مسبقًا في Hermes كتعارض؛ مرِّر --overwrite لاستبدالها.
  • الملفات المُشوَّهة لا توقف التشغيل. يتحوّل ملف settings.json أو config.toml التالف إلى خطأ خاص بذلك العنصر في التقرير بينما يستمر استيراد كل شيء آخر.

إبقاء الاستيرادات متزامنة

يسجّل كل استيراد ناجح من Claude Code أو Codex CLI أو Cursor مصدره (وبصمة كل ما قرأه) في ~/.hermes/import-sync.json. وعندما يتغيّر إعداد الوكيل الآخر لاحقًا — كإضافة مهارات جديدة أو تعديل CLAUDE.md/AGENTS.md أو إضافة خوادم MCP — اجلب التغييرات باستخدام:

لا تتطلب المزامنة مطالبات وتكلفتها منخفضة: تُتجاوَز المصادر التي لم تتغير ملفاتها عبر مقارنة البصمات، لذا يمكنك تشغيلها وفق جدول بأمان (مثل مهمة cron يومية). القواعد:

  • تظل عمليات دمج الذاكرة والإعدادات تزيل التكرار — لا تضيف المزامنة أبدًا مدخلات أو أنماطًا موجودة لديك مسبقًا.
  • المهارات التي سبق استيرادها عبر import-agent تُحدَّث في مكانها عندما تتغير النسخة المصدرية.
  • لا تُستبدَل أبدًا المهارات التي أنشأتها أو عدّلتها بنفسك ضمن فئة الاستيراد — تظل قواعد التعارض المعتادة سارية عليها (استخدم --overwrite في تشغيل يدوي لفرض الاستبدال).
  • لا تؤدي ملفات بيانات الاعتماد أبدًا إلى تشغيل المزامنة — تتجاهل البصمة تحديثات الـ tokens في ~/.claude/.credentials.json أو ~/.codex/auth.json، وتظل الأسرار تُحذف من كل ما يُستورَد.

يحاكي هذا التحديثات التلقائية في Settings > Import ضمن ChatGPT Work، مع تكييفها كأمر صريح قابل للفحص بدل خدمة تعمل في الخلفية.

manifest خاص بكل profile. ويُنقَل إلى profile تنشئه باستخدام hermes profile create <name> --clone --sync-imports، لذا يواصل hermes -p <name> import-agent --sync الجلب من أشجار الملفات الخارجية نفسها (راجع Profiles).

الترقية من إصدار كان import-agent مدمجًا فيه

كان الأمران hermes import-agent وhermes claw يأتيان داخل نواة Hermes. وتبقى الأوامر وخياراتها وملف import-sync.json دون تغيير في الإضافة:

  • الـ profiles التي لها مصدر مزامنة مسجَّل (ملف import-sync.json الذي تقرؤه عمليات --sync المجدولة) تُثبَّت لها الإضافة تلقائيًا بواسطة hermes update، أو عند أول تشغيل بعد التحديث (مع احترام security.allow_lazy_installs). وإذا أزلتها لاحقًا (hermes plugins remove agent-importers) فتبقى مُزالة.
  • أما الجميع فيثبّتونها عند حاجتهم التالية إليها: يعرضها hermes setup الجديد عندما يجد أحد هذه الوكلاء، ويطبع تشغيل hermes import-agent أو hermes claw دون الإضافة أمر التثبيت.
