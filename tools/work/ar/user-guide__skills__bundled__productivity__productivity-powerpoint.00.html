مهارة Powerpoint

أنشئ عروض PowerPoint (.pptx) وافحصها وحرّرها باستخدام مكتبة python-pptx. خمسة سكربتات مساعدة تغطي إنشاء عرض من مواصفات JSON، وقراءة منظّمة لمحتواه، والتعديل في الموضع نفسه، وإنشاء عروض ذات هوية بصرية من قالب، وعرض الشرائح كصور — كل ذلك دون اتصال ودون الحاجة إلى تثبيت PowerPoint.

متى تُستخدم

  • عندما يطلب المستخدم إنشاء عرض شرائح أو تقرير تقديمي أو pitch deck.
  • عندما تحتاج إلى استخراج النص أو الملاحظات أو الجداول أو بيانات الرسوم البيانية أو الصور من ملف .pptx شاركه أحدهم.
  • عندما تحتاج إلى تحديث عرض موجود: استبدال نص، تحديث أو تعديل بيانات رسم بياني، تبديل شعار، تكرار/حذف/إعادة ترتيب الشرائح، ضبط الخلفيات، التذييلات، الروابط التشعبية، أو ملاحظات المتحدث.
  • عندما يجب إنتاج عرض متوافق مع الهوية البصرية انطلاقًا من قالب .pptx خاص بالشركة.
  • لا تستخدم هذه المهارة لملفات .ppt (الصيغة الثنائية القديمة) — حوّلها أولًا باستخدام soffice --convert-to pptx old.ppt إذا كان LibreOffice متوفرًا.

المتطلبات المسبقة

  • Python 3.10 أو أحدث مع تثبيت python-pptx (pip install python-pptx).
  • اختياري: LibreOffice (soffice) مع poppler (pdftoppm أو pdftocairo) لعرض الشرائح كصور PNG وللتصدير إلى PDF. يكتشف pptx_render.py كليهما عبر shutil.which ويتراجع بسلاسة (يُرجع {"rendered": false, "missing": [...]}، ورمز خروج 0) عند غيابهما — كل عمليات الإنشاء والقراءة والتحرير تعمل من دونهما.
  • تحقّق من التوفر عبر terminal: python -c "import pptx; print(pptx.__version__)" و which soffice pdftoppm.

طريقة التشغيل

كل السكربتات موجودة في scripts/، وتقبل --help، وتطبع JSON على stdout، وتخرج برمز غير صفري عند الفشل. شغّلها عبر terminal:

أنشئ مواصفات JSON باستخدام write_file؛ وافحص مخرجات السكربت وملفات JSON الناتجة باستخدام read_file.

الإجراء

1. إنشاء عرض

اكتب مواصفات JSON (راجع pptx_create.py --help للاطلاع على الصيغة الكاملة)، ثم شغّل pptx_create.py. لكل شريحة يمكنك ضبط: layout (title، title_content، section، two_content، title_only، blank)، و title، وsubtitle، وbullets (نصوص، أو قواميس تحوي level من 0 إلى 4، وsize بالنقاط، وbold، وitalic، وfont، وcolor بصيغة hex، وlink لعنوان رابط تشعبي)، وbackground (لون صلب بصيغة hex)، وfooter (نص؛ يُفعّل عنصر التذييل النائب في التخطيط)، وslide_number (true؛ يُفعّل عنصر رقم الشريحة النائب في التخطيط)، وimages (المسار مع left/top/width/height بالإنش)، و tables (rows كقائمة من القوائم)، وshapes (rectangle، rounded_rectangle، oval، diamond، right_arrow، chevron، مع fill بصيغة hex ونص اختياري text)، وcharts (bar، bar_h، line، pie مع categories وseries)، وnotes (ملاحظات المتحدث).

2. قراءة عرض

يُرجع pptx_read.py deck.pptx --outline حجم الشريحة، وقائمة التخطيطات المتاحة، ولكل شريحة: اسم التخطيط، ونصوص جميع الأشكال، وخلايا الجداول، وقائمة الصور (اسم الملف/الامتداد/الحجم بالبايت)، وفئات/سلاسل/ قيم الرسوم البيانية، وملاحظات المتحدث. استخدم --images DIR لتفريغ الصور المضمّنة إلى ملفات، ثم vision_analyze على أي صورة مُصدَّرة إذا احتجت إلى رؤية محتواها.

3. تحرير عرض

يجمع pptx_edit.py عدة عمليات في تمريرة واحدة؛ استخدم --output للاحتفاظ بالنسخة الأصلية. يفحص استبدال النص أشكال الشريحة وخلايا الجداول والملاحظات. تبديل الصورة يعيد توجيه معرّف علاقة الصورة (rId) بحيث يُحافظ على الموضع والحجم. حذف شريحة يُسقط العلاقة وعنصر <p:sldId>؛ وإعادة الترتيب تنقل عنصر <p:sldId> ضمن <p:sldIdLst> (لا توفر python-pptx واجهة برمجية عامة لأيٍّ منهما — السكربت ينفّذ العمل على مستوى XML). يضيف --duplicate-slide N نسخة مستقلة كاملة من الشريحة N في نهاية العرض: يُستنسخ XML الخاص بالأشكال مع علاقات الصور والوسائط والروابط التشعبية وتُعاد تعيين معرّفات rId، لذا لا يؤثر تحرير النسخة أبدًا على الأصل. تُرفض الشرائح التي تحوي رسومًا بيانية (انظر الأخطاء الشائعة). يعدّل --set-notes/ --append-notes ملاحظات المتحدث؛ بينما تتولى --set-background و--hyperlink و--enable-slide-number و--set-footer تحسين مظهر العرض.

تُجرى تحديثات الرسوم البيانية عبر مواصفات JSON تُمرَّر بـ --chart-data. الاستبدال الكامل: {"slide": 0, "chart": 0, "categories": [...], "series": {...}}. أما للتعديلات الدقيقة، مرّر "ops" بدلًا من ذلك — وهي قائمة من {"op": "update_series", "name": ..., "values": [...]}، و add_series، وremove_series، وrename_category (باستخدام from/to أو index)، وset_title. بما أن python-pptx لا يستطيع سوى استبدال كامل مجموعة بيانات الرسم البياني (replace_data)، تُنفَّذ العمليات بقراءة البيانات الحالية → تعديلها → استبدالها؛ فتجربة التعديل الجزئي هي غلاف حول ذلك، وأي بيانات رسم بياني لا يمكن التعبير عنها كفئات وسلاسل رقمية سيُعاد تنسيقها خلال هذه العملية.

4. البناء انطلاقًا من قالب

يفتح pptx_from_template.py ملف .pptx خاصًا بالهوية البصرية، ويستبدل كل {{token}} بقيم من ملف JSON عبر الشرائح والجداول والملاحظات، ويمكنه إضافة شرائح جديدة تستخدم تخطيطات القالب نفسها (بالاسم أو بالفهرس) بحيث ترث خطوط وألوان القالب الرئيسي. نصيحة: للبدء من قالب خالٍ من الشرائح تمامًا، احذف الشرائح الموجودة لاحقًا باستخدام pptx_edit.py --remove-slide.

5. التحقق البصري

يحوّل pptx_render.py deck.pptx --outdir ./render العرض إلى PDF باستخدام soffice --headless ثم يقسّمه إلى صورة PNG واحدة لكل شريحة باستخدام pdftoppm (أو pdftocairo). يسرد JSON الناتج مسارات صور PNG — راجع كل واحدة منها باستخدام vision_analyze. عند غياب أي من الأداتين يخرج السكربت برمز 0 مع {"rendered": false, "missing": [...]} وإرشادات؛ ارجع عندها إلى المخطط العام بصيغة JSON من pptx_read.py، الذي يتحقق من المحتوى والبنية، لكن ليس من المظهر البصري.

الأخطاء الشائعة

  • تجزئة الأجزاء النصية (runs): يقسّم PowerPoint نص الفقرة إلى أجزاء نصية عند حدود التدقيق الإملائي والتحرير. يدمج --replace-text أولًا الأجزاء المتجاورة المتطابقة في التنسيق، بحيث تُستبدل المطابقات الموزّعة على هذه الأجزاء مع الحفاظ الكامل على التنسيق. لا تُعاد كتابة الفقرة بتنسيق الجزء الأول إلا عندما تمتد المطابقة عبر أجزاء مختلفة التنسيق فعليًا — تحقّق من تلك الشرائح بعد الاستبدال.
  • لا يمكن تكرار شرائح الرسوم البيانية: تتضمّن كل علاقة رسم بياني جزء مصنّف XLSX منفصلًا؛ واستنساخ هذا الترابط بشكل موثوق غير مدعوم، لذا يرفض --duplicate-slide شرائح الرسوم البيانية برسالة واضحة بدلًا من إتلاف العرض. أعد بناء الرسم البياني على شريحة جديدة بدلًا من ذلك. تُنقَل علاقات الروابط التشعبية الخارجية والصور والوسائط، بينما تُعاد علاقات التخطيط والملاحظات من جديد.
  • عمليات الرسم البياني غلاف وظيفي: يستبدل python-pptx مجموعة البيانات بأكملها؛ وتُجري "ops" عملية ذهاب وإياب عبر بيانات الرسم الحالية باستخدام replace_data، ولا يمكن تغيير نوع الرسم البياني.
  • إعادة الترتيب تتم على مستوى XML: لا توفر python-pptx واجهة برمجية مدعومة لإعادة الترتيب. يتلاعب --move-slide مباشرة بعنصر <p:sldIdLst>؛ وهذا آمن للعروض العادية، لكن أعد قراءة العرض بعد ذلك للتأكد.
  • نسخ الشرائح بين عروض مختلفة غير مدعوم — يعمل التكرار فقط ضمن العرض نفسه، حيث تكون التخطيطات والنماذج الرئيسية مشتركة.
  • يُنسخ تفعيل التذييل ورقم الشريحة العنصر النائب من تخطيط الشريحة؛ وفي التخطيطات التي لا تحوي هذه العناصر النائبة، يفشل --set-footer برسالة واضحة (أضف مربع نص بدلًا من ذلك).
  • تُطبَّق الروابط التشعبية على الأجزاء النصية كاملة؛ يربط --hyperlink كل جزء نصي يحتوي النص المحدد في تلك الشريحة.
  • القالب الافتراضي لـ python-pptx بنسبة 4:3؛ ويضبط سكربت الإنشاء النسبة 16:9 ما لم تنص المواصفات على خلاف ذلك. القوالب المخصّصة تحتفظ بحجمها الخاص.
  • تختلف فهارس التخطيطات باختلاف القالب. بالنسبة للقوالب ذات الهوية البصرية، اسرد أسماء التخطيطات أولًا: pptx_read.py template.pptx --outline (layouts_available).
  • slide.shapes.title تكون None في التخطيطات الفارغة (blank) — يتعامل سكربت الإنشاء مع هذه الحالة، لكن تذكّرها عند كتابة كود python-pptx مخصّص.
  • مرّر دائمًا encoding="utf-8" عند كتابة ملفات المواصفات؛ فقد تُملأ عناصر نائبة مثل {{city}} بقيم غير ASCII.

التحقق

  1. بعد أي عملية إنشاء أو تحرير، شغّل pptx_read.py OUT.pptx --outline وتحقّق من تطابق عدد الشرائح والنصوص والجداول والملاحظات وقيم الرسوم البيانية مع المقصود.
  2. استخدم --images DIR ثم تحقّق من حجم الملفات للتأكد من تضمين الصور.
  3. اعرض كل شريحة باستخدام pptx_render.py deck.pptx --outdir ./render وراجع كل صورة PNG باستخدام vision_analyze — فهذا يكشف الأشكال المتداخلة والنص المقطوع ومشاكل الألوان التي لا يكشفها المخطط العام. إذا كانت أدوات العرض غير متوفرة، يُبلغ السكربت بذلك؛ اعتمد عندها على المخطط العام.
  4. مجموعة الاختبارات المضمّنة هي العقد الكامل: python -m pytest tests/ -q (تتطلب python-pptx و pytest).
