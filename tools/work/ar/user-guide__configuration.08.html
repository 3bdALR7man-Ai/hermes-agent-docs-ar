البث (Streaming)

ابثّ الـ tokens إلى الطرفية أو منصات المراسلة أولًا بأول، بدلًا من انتظار الاستجابة كاملة.

بث CLI

عند التفعيل، تظهر الاستجابات token بعد token داخل صندوق بث. تظل استدعاءات الأدوات مُلتقَطة بصمت. إذا لم يدعم المزوّد البث، يعود النظام تلقائيًا إلى العرض العادي.

بث Gateway (Telegram، Discord، Slack)

عند التفعيل، يرسل البوت رسالة عند وصول أول token، ثم يعدّلها تدريجيًا كلما وصلت المزيد من الـ tokens. المنصات التي لا تدعم تعديل الرسائل (Signal، Email، Home Assistant) يُكتشف ذلك تلقائيًا عند أول محاولة — يُعطَّل البث بسلاسة لتلك الجلسة دون إغراق برسائل متعددة.

للحصول على تحديثات منتصف الدور الطبيعية بشكل منفصل دون تعديل تدريجي للـ tokens، اضبط display.interim_assistant_messages: true.

معالجة التجاوز: إذا تجاوز النص المبثوث حد طول رسالة المنصة (~4096 حرفًا)، تُنهى الرسالة الحالية وتبدأ رسالة جديدة تلقائيًا.

النهاية الحديثة (Telegram): تحافظ editMessageText في Telegram على الطابع الزمني الأصلي للرسالة، لذا فإن ردًا مبثوثًا طويل الأمد سيحتفظ بطابع أول token الزمني حتى بعد الانتهاء. اضبط fresh_final_after_seconds > 0 للاشتراك في تسليم المعاينات القديمة كرسائل نهائية جديدة تمامًا مع حذف المعاينة على أساس أفضل جهد. القيمة الافتراضية هي 0، والتي تُنهي دائمًا الردود المبثوثة في مكانها وتتجنب تسلسل الرسالة المكررة/الحذف اللحظي على العملاء الذين يُظهرون العمليتين معًا.

الإعدادات الافتراضية للبث لكل منصة

المفتاح الرئيسي streaming.enabled قيمته false افتراضيًا — لا شيء يُبث حتى تُفعّله. بعد التفعيل، يُحدَّد البث لكل منصة على حدة: يأتي Telegram بـ display.platforms.telegram.streaming: true (يبث) بينما Discord بـ display.platforms.discord.streaming: false (لا يبث). لذا بعد تفعيل البث، يبث Telegram مباشرة بينما يبقى Discord على الردود بالرسالة الكاملة حتى تغيّر مفتاحه. يمكنك ضبط مفاتيح كل منصة هذه من مفاتيح Channels في لوحة التحكم أو مباشرة في ~/.hermes/config.yaml.

عزل جلسات المحادثة الجماعية

حدّد عدد جلسات المحادثة التي يمكن أن تكون مفتوحة فعليًا في آن واحد عبر CLI وTUI/لوحة التحكم وgateway المراسلة:

تُشغَل الخانة (slot) عندما تنفّذ الجلسة دورها الأول، لا عند فتح نافذة محادثة. فتح محادثة أو استئنافها أو إعادة الاتصال بها لا يكلّف شيئًا حتى ترسل رسالة، لذا فإن تبويبات Desktop الخاملة (وإعادة الاتصال في الخلفية التي يطلقها websocket متقطع) لا يمكنها استنزاف gateway المراسلة الذي يشارك هذا الحد.

عند بلوغ الحد، يُعيد Hermes رسالة حد مباشرة تسمّي الواجهات التي تشغل الخانات. تحتفظ الجلسات النشطة الحالية بسلوكها المعتاد. شغّل hermes status لرؤية استخدام الخانات الحالي وكل من يشغلها.

المفتاح الأساسي هو max_concurrent_sessions على المستوى الأعلى. يقبل Hermes أيضًا gateway.max_concurrent_sessions كخيار احتياطي، لكن المفتاح على المستوى الأعلى يفوز عند ضبط الاثنين معًا.

يُفرض الحد عبر ملف إيجار (lease) محلي وقت التشغيل وهو بأفضل جهد: يفشل Hermes بأمان (fails open) إذا تعذّرت قراءة السجل أو قفله حتى لا يُترك المستخدمون معلّقين. وهو مُصمّم لبيئة تشغيل مضيف/profile واحد، وليس لـ $HERMES_HOME مشترك مُحمّل عبر عدة أجهزة.

حدّد ما إذا كانت المحادثات المشتركة تحتفظ بمحادثة واحدة لكل غرفة أو محادثة واحدة لكل مشارك:

  • true هي القيمة الافتراضية والموصى بها. في قنوات Discord ومجموعات Telegram وقنوات Slack والسياقات المشتركة المماثلة، يحصل كل مُرسِل على جلسته الخاصة عندما توفّر المنصة معرّف مستخدم.
  • false يعيد سلوك الغرفة المشتركة القديم. قد يكون هذا مفيدًا إذا أردت صراحة أن يعامل Hermes قناة ما كمحادثة تعاونية واحدة، لكنه يعني أيضًا أن المستخدمين يتشاركون السياق وتكاليف الـ tokens وحالة المقاطعة.
  • الرسائل المباشرة (DM) لا تتأثر. لا يزال Hermes يفهرس الـ DMs حسب معرّف المحادثة/DM كالمعتاد.
  • تظل الخيوط (Threads) معزولة عن قناتها الأصل في كلتا الحالتين؛ ومع true، يحصل كل مشارك أيضًا على جلسته الخاصة داخل الخيط.

لتفاصيل السلوك والأمثلة، راجع الجلسات (Sessions) ودليل Discord.

سلوك الرسائل المباشرة غير المصرَّح بها

حدّد ما يفعله Hermes عندما يرسل مستخدم مجهول رسالة مباشرة:

  • pair هي القيمة الافتراضية لمنصات المحادثة المباشرة المشابهة للدردشة. يرفض Hermes الوصول، لكنه يردّ برمز إقران لمرة واحدة في الرسائل المباشرة.
  • ignore يُسقط الرسائل المباشرة غير المصرَّح بها بصمت.
  • يفترض البريد الإلكتروني القيمة ignore ما لم يُضبط platforms.email.unauthorized_dm_behavior: pair، لأن صناديق الوارد قد تحتوي على بريد غير مقروء لا علاقة له بالموضوع.
  • تتجاوز أقسام المنصات القيمة الافتراضية العامة، لذا يمكنك إبقاء الإقران مفعّلًا على نطاق واسع مع جعل منصة واحدة أكثر هدوءًا.

الأوامر السريعة

عرّف أوامر مخصّصة تُنفّذ إما أوامر shell دون استدعاء LLM، أو تُسمِّي slash command بديلًا لآخر. أوامر Exec السريعة لا تستهلك tokens ومفيدة من منصات المراسلة (Telegram، Discord، إلخ) لفحوصات الخادم أو السكربتات المساعدة السريعة.

الاستخدام: اكتب /status أو /disk أو /update أو /gpu أو /restart في CLI أو أي منصة مراسلة. تُنفَّذ أوامر exec محليًا على المضيف وتُعيد المخرجات مباشرة — دون استدعاء LLM ودون استهلاك tokens. أوامر alias تُعيد التوجيه إلى slash command المُهيَّأ كهدف.

  • مهلة 30 ثانية — تُنهى الأوامر طويلة التشغيل مع رسالة خطأ
  • الأولوية — تُفحص الأوامر السريعة قبل أوامر المهارات، لذا يمكنك تجاوز أسماء المهارات
  • الإكمال التلقائي — تُحلّ الأوامر السريعة وقت الإرسال ولا تظهر في جداول الإكمال التلقائي المدمجة لـ slash commands
  • النوع — الأنواع المدعومة هي exec وalias؛ الأنواع الأخرى تُظهر خطأ
  • يعمل في كل مكان — CLI وTelegram وDiscord وSlack وWhatsApp وSignal والبريد الإلكتروني وHome Assistant

اختصارات الـ prompt النصية فقط ليست أوامر سريعة صالحة. لسير عمل prompt قابل لإعادة الاستخدام، أنشئ مهارة أو alias لـ slash command موجود.

تأخير بشري

محاكِ إيقاع استجابة يشبه البشر في منصات المراسلة:

تنفيذ الكود

اضبط أداة execute_code:

mode يتحكم في دليل العمل ومفسّر Python للسكربتات:

  • project (الافتراضي) — تعمل السكربتات في دليل عمل الجلسة باستخدام python الخاص بـ virtualenv/conda النشط. تُحلّ اعتماديات المشروع (pandas، torch، حزم المشروع) والمسارات النسبية (.env، ./data.csv) بشكل طبيعي، مطابِقةً ما تراه terminal().
  • strict — تعمل السكربتات في دليل تجهيز مؤقت باستخدام sys.executable (بايثون Hermes الخاص). أقصى قابلية لإعادة الإنتاج، لكن اعتماديات المشروع والمسارات النسبية لن تُحلّ.

تنظيف متغيرات البيئة (يزيل *_API_KEY و*_TOKEN و*_SECRET و*_PASSWORD و*_CREDENTIAL و*_PASSWD و*_AUTH) وقائمة السماح للأدوات تنطبقان بالتساوي في كلا الوضعين — تغيير الوضع لا يغيّر الوضع الأمني.

تدعم أداتا web_search وweb_extract خمسة مزوّدي خلفية. اضبط الخلفية في config.yaml أو عبر hermes tools:

اختيار الخلفية: يستخدم وقت التشغيل دائمًا اختيار web.backend المخزَّن (يُضبط عبر hermes tools؛ يوجّه nous عبر Tool Gateway المُدار). فقط إذا لم يُختَر أي خلفية ويب من قبل، يُكتشف واحد تلقائيًا من مفاتيح API المتاحة: إذا كان SEARXNG_URL فقط مضبوطًا، يُستخدم SearXNG؛ وإذا كان EXA_API_KEY فقط، يُستخدم Exa؛ وإذا كان TAVILY_API_KEY فقط، يُستخدم Tavily؛ وإذا كان PERPLEXITY_API_KEY فقط، يُستخدم Perplexity؛ وإذا كان PARALLEL_API_KEY فقط، يُستخدم Parallel؛ وإذا كان KEENABLE_API_KEY فقط، يُستخدم Keenable. مع عدم وجود اختيار وعدم وجود أي بيانات اعتماد على الإطلاق، تتناوب الطلبات بنظام round-robin عبر حلقة المستوى المجاني بلا مفتاح (Exa / Parallel / Firecrawl / Keenable) مع تجاوز تلقائي إلى التالي في الطابور عند بلوغ حدود المعدل — راجع دليل البحث في الويب للتفاصيل. بمجرد وجود اختيار، لا تغيّر إضافة مفتاح إلى .env المسار. اختيار Tavily أو Firecrawl أو Keenable في hermes tools يعمل أيضًا دون مفتاح.

SearXNG محرك بحث تلوي (metasearch) مجاني ومستضاف ذاتيًا ويحترم الخصوصية يستعلم أكثر من 70 محرك بحث. لا حاجة إلى مفتاح API — فقط اضبط SEARXNG_URL على نُسختك (مثلًا http://localhost:8080). SearXNG للبحث فقط؛ تتطلب web_extract مزوّد استخراج منفصلًا (اضبط web.extract_backend). راجع دليل إعداد البحث في الويب لتعليمات إعداد Docker.

Firecrawl المستضاف ذاتيًا: اضبط FIRECRAWL_API_URL ليشير إلى نسختك الخاصة. عند ضبط رابط مخصّص، يصبح مفتاح API اختياريًا (اضبط `USE_DB_AUTHENTICATION=*** على الخادم لتعطيل المصادقة).

أوضاع بحث Parallel: اضبط PARALLEL_SEARCH_MODE للتحكم في سلوك البحث — fast أو one-shot أو agentic (الافتراضي: agentic).

Exa: اضبط EXA_API_KEY في ~/.hermes/.env. يدعم التصفية حسب category (company، research paper، news، people، personal site، pdf) وفلاتر النطاق والتاريخ.

المتصفح

اضبط سلوك أتمتة المتصفح:

سياسات مربعات الحوار:

  • must_respond (الافتراضي) — التقط مربع الحوار، اعرضه في browser_snapshot.pending_dialogs، وانتظر استدعاء الوكيل لـ browser_dialog(action=...). بعد dialog_timeout_s ثانية دون رد، يُرفض مربع الحوار تلقائيًا لمنع تعليق خيط JS في الصفحة إلى الأبد.
  • auto_dismiss — التقط، وارفض فورًا. لا يزال الوكيل يرى سجل مربع الحوار في browser_snapshot.recent_dialogs مع closed_by="auto_policy" بعد الحدث.
  • auto_accept — التقط، واقبل فورًا. مفيد للصفحات ذات مطالبات beforeunload العدوانية.

راجع صفحة ميزة المتصفح لسير عمل مربع الحوار الكامل.

يدعم toolset المتصفح عدة مزوّدين. راجع صفحة ميزة المتصفح لتفاصيل Browserbase وBrowser Use وإعداد CDP لعائلة Chromium المحلية.

المنطقة الزمنية

تجاوز المنطقة الزمنية المحلية للخادم بسلسلة منطقة زمنية IANA. يؤثر في الطوابع الزمنية في السجلات، وجدولة cron، وحقن الوقت في system prompt.

القيم المدعومة: أي معرّف منطقة زمنية IANA (مثل America/New_York، Europe/London، Asia/Kolkata، UTC). اتركه فارغًا أو احذفه لاستخدام الوقت المحلي للخادم.

Discord

اضبط سلوكيات Discord الخاصة بـ gateway المراسلة:

  • require_mention — عندما تكون true (الافتراضي)، يستجيب البوت في قنوات الخادم فقط عند الإشارة إليه بـ @BotName. الرسائل المباشرة تعمل دائمًا دون إشارة.
  • free_response_channels — قائمة معرّفات قنوات مفصولة بفواصل يستجيب فيها البوت لكل رسالة دون الحاجة إلى إشارة.
  • auto_thread — عندما تكون true (الافتراضي)، تُنشئ الإشارات في القنوات خيطًا تلقائيًا للمحادثة، مما يبقي القنوات نظيفة (مماثل لخيوط Slack).

الأمان

الفحص الأمني قبل التنفيذ وتعتيم الأسرار:

  • redact_secrets — عندما تكون true، يكتشف النظام تلقائيًا الأنماط الشبيهة بمفاتيح API والـ tokens وكلمات المرور ويعتّمها في مخرجات الأدوات قبل دخولها سياق المحادثة والسجلات. مفعّلة افتراضيًا. اضبطها على false صراحة فقط عندما تحتاج إلى سلاسل شبيهة ببيانات اعتماد خام لأغراض التصحيح أو تطوير المُعتِّم.
  • tirith_enabled — عندما تكون true، تُفحص أوامر الطرفية بواسطة Tirith قبل التنفيذ للكشف عن العمليات الخطرة المحتملة.
  • tirith_path — مسار ملف tirith التنفيذي. اضبط هذا إذا كان tirith مثبَّتًا في موقع غير قياسي.
  • tirith_timeout — أقصى عدد من الثواني لانتظار فحص tirith. تتابع الأوامر تنفيذها إذا انتهت مهلة الفحص.
  • tirith_fail_open — عندما تكون true (الافتراضي)، يُسمح بتنفيذ الأوامر إذا كان tirith غير متاح أو فشل. اضبطها على false لمنع الأوامر عندما لا يستطيع tirith التحقق منها.

قائمة حظر المواقع

احظر نطاقات معيّنة من الوصول إليها بواسطة أدوات الويب والمتصفح الخاصة بالوكيل:

عند التفعيل، يُرفض أي رابط يطابق نمط نطاق محظور قبل تنفيذ أداة الويب أو المتصفح. ينطبق هذا على web_search وweb_extract وbrowser_navigate وأي أداة تصل إلى الروابط.

تدعم قواعد النطاق:

  • نطاقات دقيقة: admin.example.com
  • نطاقات فرعية عامة (wildcard): *.internal.company.com (تحظر كل النطاقات الفرعية)
  • نطاقات TLD عامة: *.local

تحتوي الملفات المشتركة على قاعدة نطاق واحدة في كل سطر (يُتجاهل السطر الفارغ وتعليقات #). الملفات المفقودة أو غير القابلة للقراءة تسجّل تحذيرًا لكنها لا تعطّل أدوات الويب الأخرى.

تُخزَّن السياسة مؤقتًا لمدة 30 ثانية، لذا تسري تغييرات الإعدادات بسرعة دون إعادة تشغيل.

الأنماط عبارة عن أنماط fnmatch غير حساسة لحالة الأحرف ويجب وضعها بين علامتي اقتباس في YAML (نجمة * في البداية دون اقتباس تسبب خطأ تحليل). راجع الأمان — قواعد الرفض المُعرَّفة من المستخدم للتفاصيل.

سياسة موافقة ذكية مخصّصة

approvals.smart_policy تتيح لك إضافة قواعدك الخاصة إلى تعليمات مراجع الموافقة الذكية. عند ضبطه، يُضاف النص إلى system prompt لـ LLM الحارس (القناة الموثوقة — لا يُدمج أبدًا مع نص الأمر غير الموثوق)، لذا يمكنك تشديد حكمه أو تخفيفه لبيئتك دون تعديل الكود:

نقاط الحفظ (Checkpoints)

لقطات تلقائية لنظام الملفات قبل عمليات الملفات المدمّرة. راجع نقاط الحفظ والتراجع للتفاصيل.
