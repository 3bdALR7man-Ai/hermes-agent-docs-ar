النشر عبر عدة gateways

يدعم Hermes تشغيل عدة عمليات gateway بالتزامن — واحدة لكل profile (default و writer و admin و coder و researcher). يفتح كل gateway اتصاله الخاص بواجهات API للمنصات ويسلّم الرسائل إلى المشتركين في profile الخاص به.

تشمل اشتراكات المهام أيضًا ملاحظات المراجعة. يُسلّم حدث مراجعة changes_requested كإشعار review-BLOCK قابل لاتخاذ إجراء. وتوقظ الاشتراكات التي تستخدم notify+wake أيضًا المحادثة/الخيط/الجلسة الأصلية المحددة لكي يفحص المتحكّم البطاقة الحالية والتشغيل الحالي؛ بينما يظل notify للإشعار السلبي فقط، و wake للإيقاظ فقط. لا تنشئ ملاحظات المراجعة مهمة ولا ترفع حظرها ولا تعيد إدراجها في قائمة الانتظار ولا تعدّلها بأي شكل آخر.

نهج موزّع واحد

يمتلك gateway واحد فقط موزّع kanban. يُبقي gateway المالك kanban.dispatch_in_gateway: true (القيمة الافتراضية)؛ ويضبطه كل gateway آخر على false.

لماذا يهم ذلك: للتوزيع مالك واحد لكيلا تتسابق عدة gateways لإطلاق العمل نفسه. أما تسليم الإشعارات فمملوك لكل profile: يستطلع كل gateway فقط اشتراكات profiles التي يستضيف محوّلات منصاتها. يمنع الحجز الذرّي للأحداث التسليم المكرّر عبر عمليات المراقبة.
