سير عمل المطوّر

يطلب التفعيل من PM تجهيز سلسلة الأدوات لنسخة مصدر مسحوبة أو مزامنتها، ثم يتيحها في الـ shell. لا يختار مفسّر Python لمحررك، ولا يعيد توجيه تطبيق Desktop مثبّت إلى هذه النسخة المسحوبة.

تجهيز نسخة مسحوبة

استخدم طرفية عادية خارج تطبيق Hermes المغلّف. اخرج أولًا من أي بيئة Python افتراضية حالية. في Windows، استخدم PowerShell الأصلي مع Git. في ARM64، يجهّز PM أدوات Visual Studio C++ و Clang و Rust الأصلي ومكتبات OpenSSL التطويرية الثابتة قبل كل بناء اعتماديات من نسخة مسحوبة: الإعداد و activate.ps1, install.ps1, hermes update والإصلاح على السواء. يعيد استخدام التثبيتات الموجودة ويثبّت المتطلبات المفقودة. تتطلب مكونات Visual Studio المفقودة حقوق مسؤول: يطلبها التثبيت التفاعلي عبر UAC، بينما تحتاج عمليات CI و ssh والتشغيل المجدول إلى PowerShell بصلاحيات Administrator. يستخدم OpenSSL triplet arm64-windows-static-md من vcpkg. ينتج التثبيت المشترك المتضرر خطأ إصلاح، لا حذفًا تلقائيًا. لا تنطبق متغيرات بيئة المترجم و OpenSSL إلا على بناء اعتماديات PM، لا على الـ shell لديك مطلقًا.

ما تزال المنصات الأخرى تتطلب أدوات المترجم الأصلية والمكتبات اللازمة للاعتماديات التي لا تملك wheels متوافقة.

لإصدار Python المثبّت على macOS، يضبط PM AR افتراضيًا على /usr/bin/ar: ما يزال sysconfig للمفسّر الموزّع يشير إلى مجلد LLVM المؤقت الخاص بمورّده. ينطبق ذلك على بناء المصدر والحزم معًا. تبقى قيم AR و CC الصريحة هي المرجع؛ لا يغيّر PM سلسلة أدوات مفسّر يوفّره المستدعي مثل Nix Python. لا حاجة إلى افتراضي CC للإصدار المثبّت الحالي.

قبل وجود Python، يحصل bootstrap الخاص بـ shell على المفسّر المثبّت. بمجرد إمكان تشغيل Python، يسلّم عمل الاعتماديات إلى PM. يجهّز محرك PM الخاص وقت تشغيله الصغير المقفول قبل حل اعتماديات التطبيق. مشروعه مستقل عن مساحة عمل التطبيق: يجب ألا تمنع اعتمادية تطبيق معطّلة مدير الاعتماديات من بدء التشغيل.

uv تفصيل تنفيذ خاص بـ PM. يطلب كود التطبيق ومسارات الإعداد ومستدعو البناء عمليات Python، لا ملفات uv التنفيذية أو معاملات أوامره. لا تغيّر بيئة Hermes بأوامر pip أو uv الخام.

يحتوي وقت تشغيل PM على ruamel.yaml, packaging, tomli-w و truststore لا شجرة اعتماديات التطبيق. تعمل أوامر CLI والتثبيتات والإصلاحات التي يطلبها التطبيق هناك. تبقى عمليات البحث للقراءة فقط عن المسارات والأدوات المثبّتة محلية. تستخدم فحوص حداثة البيئة عامل PM جاهزًا. لا يضيف PM اعتمادياته مطلقًا إلى استيرادات وكيل يعمل بالفعل. تستخدم قارئات وكاتبات YAML الأصلية ruamel؛ وقد تظل حزم الطرف الثالث تحتاج إلى PyYAML في بيئة التطبيق. تبقى إثباتات الفشل قائمة على stdlib فقط.

يفعّل CLI والعامل في PM truststore قبل استيراد عملاء HTTPS. يستخدم ذلك مخزن شهادات المنصة حتى إذا لم تحدّد مسارات OpenSSL المضمّنة في Python bootstrap مكانه. لا تُطلب اعتماديات تطبيق أو تجاوزات مسارات شهادات. بعد أول تثبيت، يعيد PM بناء بيئته الصغيرة مقابل Python المُدار عند الاستدعاء التالي؛ وتعيد الاستدعاءات اللاحقة استخدامها.

pm.venv_is_current() يفحص عبر عامل PM موجود، حتى عند تعطيل التثبيتات الكسولة. لا يُقلع PM مطلقًا من أجل فحص. إذا تعذّر وقت تشغيل المدير، يعيد false دون تنزيل أدوات أو اعتماديات. شغّل hermes pm install صراحة لتجهيز PM أولًا.

تجهّز الحزم الأصلية وصور Docker lock PM نفسه عبر منشئ وقت التشغيل المشترك. يزوّد Termux ذلك المنشئ بـ wheelhouse دون اتصال ومتحقق منه. يبني Nix lock PM كـ derivation مستقل. لا تستخدم العمّال المغلّفة إلا مجلد اعتماديات PM المسجّل، لا مكتبات التطبيق مطلقًا.

تفعيل تثبيت موجود

في كل shell جديد، استعد قيم home التطوير وادخل النسخة المسحوبة. ثم فعّلها؛ لا يوجد أمر إعداد منفصل لتتذكره:

الـ shellالدخولالخروج
Bashsource ./activatedeactivate
fishsource ./activate.fishdeactivate
PowerShell. .\activate.ps1deactivate

النقطة والمسافة في البداية مطلوبتان في PowerShell. تنفيذ .\activate.ps1 دون dot-sourcing لا يوفّر نطاق الجلسة نفسه. activate يستخدم صيغة Bash. استخدم Bash لهذه الوصفة بدلًا من sh أو افتراض أن ملف بدء Zsh له دلالات Bash؛ لدى fish ملف activate.fish خاص به يعمل بالطريقة نفسها.

يستدعي كل تفعيل مسار تثبيت/مزامنة PM، ويثق في digest الأداة المسجّل بدلًا من إعادة hash كل إدخال. ما يزال PM يثبّت أداة مفقودة ويعيد بناء جيل اعتماديات قديم؛ ويحتفظ التثبيت المتعمّد بفحص البايتات. شغّل python -m pm.cli install أو hermes update لإعادة فحص البايتات المحققة. يعيد فشل الإعداد خطأ قبل تغيير بيئة الـ shell المفعّلة، بما في ذلك عند إعادة تحميل بيئة نشطة أصلًا.

بعد المزامنة، يسبق التفعيل PATH بأدوات PM المثبّتة ويضبط PYTHONPATH إلى هذه النسخة المسحوبة وشجرة اعتمادياتها المحددة. ويعرّف أيضًا hermes كدالة shell لهذا worktree. تشغّل الدالة CLI هذه النسخة وتخفي الأمر المثبّت، بما فيه اسم MSIX البديل. تعمل فقط عندما يكون الـ shell داخل worktree هذا، وترفض خارجه، فلا يرث worktree شقيق الأمر. يكتسب prompt بادئة تسمّي branch، ويفقدها خارج الشجرة. لا يغيّر PATH على مستوى النظام ولا يثبّت prompt تقليديًا لـ venv. ابدأ في shell نظيف بدلًا من تعشيشه داخل venv أخرى. deactivate يعيد قيم البيئة التي التقطها سكربت التفعيل، ويزيل الدالة وبادئة prompt. لا يلغي تثبيت الحزم ولا يوقف عمليات بدأتَها.

لتشغيل أمر أو سكربت واحد في تلك البيئة دون تفعيل shell، سبقه بـ scripts/run-in-hermes-env. يطبّق البيئة نفسها على ذلك الأمر وحده، ويزامن أولًا إذا لم توجد بيئة موروثة أو كانت الموروثة قديمة، ويترك الـ shell كما هو. يعيد scripts/run_tests.sh تشغيل نفسه بهذه الطريقة، وتسلّم سكربتات Python في المستودع نفسها إليه من سطر shebang.

تحقّق من المفسّر والمصدر قبل العمل:

python يجب أن يشير إلى مفسّر مخزن PM. و pm.__file__ يجب أن يشير إلى داخل هذه النسخة المسحوبة. تأتي الاعتماديات من البيئة المحددة التي قد توجد خارج المستودع. يعني الاستيراد المفقود أن الإعداد أو الاختيار يحتاج مراجعة، حتى إذا أعاد source ./activate نفسه بنجاح.

تحديث الاعتماديات دون تغيير branches

بعد تغيير branch أو lockfile، أعد تحميل سكربت التفعيل لمزامنة الاعتماديات الجديدة واختيارها (source ./activate في Bash أو . .\activate.ps1 في PowerShell). للمزامنة دون تفعيل shell:

بعد مزامنة مستقلة، أعد تفعيل البيئة وأعد تشغيل العمليات المتأثرة. استخدم python -m pm.cli doctor لتشخيص الأدوات و python -m pm.cli status لآخر إثبات مزامنة. لا تشغّل hermes update لمجرد تحديث branch ميزة: فهو تحديث للتطبيق وقد يغيّر branch المصدر.

أسماء الأدوات المُدارة وأسماء إضافات Python واجهتان مختلفتان:

يثبّت الأمر الأول أداة. ويضيف الثاني extra معلنة لوقت التشغيل إلى اختيار Python الحالي لهذا التثبيت. تتراكم الإضافات (extras) عبر مزامنة PM. تنتمي مجموعتا الاعتماديات dev و test إلى بيئة الاختبار المنفصلة فقط، لا venv التطبيق المحددة. بعد تغيير extras، أعد التفعيل قبل بدء عملية Python أخرى.

المزامنة بعد تحرير pyproject.toml

  1. حرّر pyproject.toml. ثبّت إصدار كل اعتمادية كما تتطلب سياسة تثبيت إصدارات الاعتماديات. عبّر عن حدود المنصة بعلامات PEP 508، أو قيّد extra كاملة في [tool.hermes.extras-platforms].

  2. أعد إنشاء lock:

    يعيد هذا حل uv.lock من pyproject.toml بالإعدادات نفسها التي يفحصها CI، بما فيها حجر exclude-newer لمدة 14 يومًا. لا يغيّر أي بيئة. عندما يكون lock محدّثًا أصلًا، يذكر ذلك ولا يكتب شيئًا. (hermes pm lock --bump NAME VERSION عملية مختلفة: تثبّت أداة مُدارة في pm/lock.json ولا تمس uv.lock.)

  3. أعد تحميل سكربت التفعيل (source ./activate أو . .\activate.ps1 في PowerShell) لمزامنة venv التطبيق ومفسّر الاختبار مع lock الجديد. يغطي التفعيل [all]. إذا أضفت extra اختيارية خارج [all], hermes pm lock يطبع الأمر الذي يضيفها أيضًا إلى مفسّر الاختبار، مثل source ./activate --test-extras all,NAME.

  4. أدرج pyproject.toml و uv.lock في commit معًا.

لاعتماديات JS، حدّث manifest الحزمة المالكة و lock. لا تحرّر معلومات PM أو مساحات العمل المولّدة، ولا تثبّت حزمًا مباشرة داخل جيل محدد.

بيئات الاختبار والمحرر

source ./activate (أو . .\activate.ps1 في PowerShell) وكلا سكربتي setup-hermes المباشرين تجهّز مفسّر اختبار معزولًا من مجموعتي الاعتماديات المقفلتين dev و test. يستخدم scripts/run_tests.sh ذلك المفسّر، ويعيد التفعيل إذا تغيّرت النسخة المسحوبة أو مدخلات اعتمادياتها. لا تختار venv التطبيق ولا أدوات التثبيت ولا الحزم أيًا من المجموعتين. يغطي افتراضي المطوّر [all] ؛ لتغيير تغطية الاختبار، مرّر --test-extras=anthropic إلى تفعيل POSIX أو -TestExtras anthropic إلى PowerShell؛ تختار تلك المعاملات extras لوقت التشغيل في مفسّر الاختبار وحده.

في بيئة معزولة لا يتاح فيها التفعيل (مثل shell تطوير Nix)، يمكن للمستدعي توفير HERMES_PYTHON صراحة مع pytest، أو بناء بيئة مؤقتة مستقلة:

يجب ألا يكون المخرج موجودًا. لإعادة توليده، أوقف عملياته وتعمد إزالة تلك البيئة المؤقتة وحدها أولًا. ثم شغّل scripts/run_tests.sh (عبر Bash في Windows). تتضمن مجموعة اعتماديات الاختبار اختبارات المشغّل الأصلي، ولا تدخل وقت تشغيل مغلّفًا مطلقًا.

لتصحيح الأخطاء في المحرر، اختر ذلك المفسّر المستقل، واضبط مجلد العمل إلى هذه النسخة، وشغّل hermes كالسكربت. أبقِ HERMES_HOME الخاص به منفصلًا عن الإنتاج. لا يهيئ تفعيل الطرفية محررًا يعمل بالفعل. لا توجّه محررًا إلى جيل PM عابر أو ملف Python تنفيذي لتطبيق موقّع.

واجهات عمليات Python

استخدم وحدة pm العامة لعمل اعتماديات Python:

العمليةالملكية
pm.sync_venv(extras, explicit=True)جهّز اتحاد اعتماديات التطبيق الكامل واختره، بما فيه الإضافات المفعّلة.
pm.sync_venv(repair=True, explicit=True)أعد بناء مجموعة الاعتماديات المسجّلة في جيل تطبيق جديد.
pm.build_environment(source=..., out=..., explicit=True)ابنِ مخرجًا جديدًا يملكه المستدعي وتحقّق منه. لا اكتشاف إضافات ولا اختيار للتطبيق.
pm.lock_project(source, explicit=True)حدّث lock مشروع صريح دون اختيار بيئة.
pm.ensure_environment(name, requirements, explicit=True)جهّز جيل اعتماديات معزولًا واختره، وأعد مسار Python الخاص به.
pm.ensure_python_tool(name, requirements, executable, explicit=True)جهّز أداة معزولة وأعد مسار ملفها التنفيذي.
pm.environment_python(name) / pm.python_tool(name, executable)اقرأ المسارات المحددة دون تثبيت شيء.
pm.venv_is_current()اسأل عامل PM جاهزًا عما إذا كانت اعتماديات التطبيق محدّثة. أعد false إذا تعذّر وقت تشغيل المدير.

pm.stage_manager_runtime(...) هو استثناء bootstrap. يجهّز وقت تشغيل PM المقفول نفسه عبر المحرك الخاص المباشر، لأن ذلك الوقت لا يستطيع بناء نفسه عبر عامله. لا يعرّض uv للمستدعي.

pm.build_env هو واجهة الأوامر لأعمال البناء و lock الصريحة. شغّل python -m pm.build_env --help لخياراته المدعومة. افتراضيًا، تستخدم عمليات بناء المشاريع lock المعتمد. يحلّ --resolve قبل البناء. يختار --python مفسّر بناء صريحًا. يزيل --sealed مراجع .pth وقت البناء. ويتحكم --offline و --cache في الحصول على الاعتماديات.

لبناء بيئة التطبيق، يجب أن يكون PM قادرًا بالفعل على البدء في Python المستدعي. هذه العمليات ليست bootstrap لمفسّر. لا تعدّل استيرادات تطبيق جارٍ ولا تستبدل بيئته المحددة. تبقى عمليات uv2nix التصريحية مملوكة لـ Nix. لا تدير أوامر مدير الحزم لمشاريع غير مرتبطة أو sandboxes للوكلاء Hermes نفسه.

الأوامر

الأمرالأثر
pm install [names...]ثبّت الحزم المسماة. دون أسماء، وفّر الأدوات المطلوبة مع Python، وضعها على PATH، ثم زامن extra all. يثبّت التثبيت المجرد أيضًا الأدوات الاختيارية الافتراضية (agent-browser و Chromium و cua-driver)؛ وفشل تنزيلها يطبع تحذيرًا ولا يفشل التثبيت. تسمية حزمة رفضتها سابقًا تعكس ذلك الاختيار.
pm install --without NAMEنفّذ تثبيتًا مجردًا دون الحزمة الاختيارية الافتراضية NAME (agent-browser أو cua-driver)، وسجّل الاختيار. تستبعدها أيضًا التثبيتات المجردة اللاحقة و hermes update. تستخدم خيارات المُثبّت --skip-browser / -SkipBrowser و --skip-computer-use / -SkipComputerUse ذلك.
pm install --tools-onlyثبّت مجموعة اعتماديات الأداة الكاملة وضعها على PATH، ثم توقف. لا تعمل مزامنة venv.
pm env [names...]اطبع قيم البيئة التي يساهم بها PM للحزم المثبّتة كـ JSON. لا يثبّت حزمًا مفقودة، وإن كان إطلاق Hermes البارد قد يجهّز وقت تشغيل Python الخاص به أولًا.
pm doctorافحص هويات الأدوات المثبّتة وملفاتها و digests مقابل lock.
pm repairأعد بناء مجموعة اعتماديات Python المسجّلة في جيل جديد، وتحقق منها ثم اخترها. لا يحدّث الإصدارات المثبتة أو الميزات أو إعدادات الإضافات.
pm statusاطبع آخر إثبات مزامنة/تحديث كـ JSON، أو أبلغ عن عدم وجود إثبات.
pm gcأزل إدخالات مخزن الأدوات غير المرجعية وأجزاء التنزيل المؤهلة وأجيال Python غير المستخدمة والمُدارة بالعقود وحالة installs/INSTALL_KEY/ للنسخ المسحوبة المحذوفة (worktree أُزيل من مجلد .worktrees/ ما يزال موجودًا، أو clone تحت جذر البيانات؛ تُحفظ النسخ التي لا تستطيع هذه العملية رؤيتها، مثل تثبيت مضيف يُرى من حاوية تشارك جذر البيانات، وتُحفظ كذلك أي حالة ما يزال قفل تثبيتها أو عقد جيلها محتجزًا). يستعيد منظّف worktrees الذي يعمل عند التشغيل تلك المجلدات اليتيمة أيضًا.

pm env يستبعد متغيرات العملية الموروثة، بما فيها بيانات الاعتماد. وقد تكشف مخرجاته مسارات تثبيت محلية؛ راجعها قبل مشاركتها.

أوامر القائمين على الصيانة

تغيّر هذه الأوامر مدخلات الاعتماديات أو تجهّز مخرجات بناء. ليست بدائل لآلية تحديث تطبيق مثبّت.

الأمرالأثر
pm lockأعد إنشاء lock لـ uv.lock من pyproject.toml. لا يغيّر بيئة؛ ولا يكتب شيئًا عندما يكون lock محدّثًا.
pm lock --bump NAME VERSIONحل مخرجات الأهداف المدعومة واحسب hashes، ثم اكتب تثبيت الأداة إلى pm/lock.json.
pm update [names...]استعلم عن إصدارات الأصل، وغيّر تثبيتات الأدوات، وثبّت الأدوات المتغيّرة.
pm update --checkاستعلم دون كتابة. قد يعني الخروج 1 وجود تحديثات؛ افحص المخرجات لتمييز الخطأ.
pm update --target TARGETحل الإصدارات للهدف المحدد.
pm update --uv / --npmحدّث أيضًا حل اعتماديات Python أو npm.
pm update --termux [--check]أعد تثبيت أرشيفات termux pool التي تقاعدت من rolling pool (جدول تثبيت runtime-lib وصفوف lock الخاصة بـ bionic). --check يُبلغ دون كتابة ويخرج 1 عند تقاعد تثبيت.
pm install --target TARGET NAME...جهّز حزمًا صريحة لأهداف مختلفة دون تسجيلها كوقت تشغيل مثبّت للمضيف. هدف win32 git يثبّت أرشيف PortableGit ذاتي الاستخراج: تجهيزه يشغّل مستخرج المورّد، لذا يتطلب مضيف Windows.
pm bundle --out DIR [--ref REF]جهّز لقطة مصدر وأدوات أصلية ومعلومات واعتماديات Python. لا ينتج مُثبّت Desktop موقّعًا.

يبني منشئ Desktop الكامل أيضًا واجهات JavaScript، ويولّد مشغّلات ويستدعي التغليف الأصلي. يمكن للقائمين على الصيانة قراءة بناء أدوات تثبيت Desktop.

إعادة محاولات الشبكة

يعيد PM محاولة أخطاء HTTP العابرة أثناء تنزيل الأدوات وحساب hashes للمخرجات والبحث عن الإصدارات. لكل فحص أو نقل أربع محاولات كحد أقصى. فترات التراجع 1 و 2 و 4 ثوانٍ. يمكن لـ header Retry-After تمديد الانتظار حتى 30 ثانية. تذكر كل إعادة محاولة سببها وتأخيرها والمحاولة التالية في السجل.

حالات HTTP القابلة للإعادة هي 408 و 429 و 500 و 502 و 503 و 504. تُعاد أيضًا الاتصالات المُعاد ضبطها والمهل وأخطاء DNS المؤقتة ومتُون الاستجابة المنقطعة. تحافظ التنزيلات ذات النطاقات على البايتات المكتملة. تتطلب خوادم دون دعم نطاقات دفقًا جديدًا. يقطع الإيقاف المؤقت التراجع ويحفظ التنزيل الجزئي.

لا يعيد PM محاولة hashes غير الصحيحة أو أخطاء الشهادات أو نظام الملفات المحلي أو غيرها من الأخطاء الدائمة. فحص ناجح يتبعه GET نطاق بخطأ 403 أو 404 يحافظ على احتياط CDN: محاولة تسلسلية واحدة للنطاقات المفقودة. لا تتكرر عمليات الاستخراج والتحقق والنشر. تبقى طلبات حزم Python و npm تحت سياسات إعادة المحاولة الخاصة بـ uv و npm.

التشخيص

  • بناء اعتماديات Python بطيء: تفعّل أوامر uv المتدفقة من PM المخرجات التفصيلية. تعرض سجلات الحزم والبناء نشاط الحزم و stdout/stderr الخاص بـ build-backend أثناء البناء، لا بعد الفشل فقط.
  • أداة مفقودة أو قديمة: اقرأ hermes pm doctor ، ثم استخدم تثبيت PM صريحًا على تثبيت قابل للكتابة.
  • بيئة جديدة تتطلب إعادة التشغيل: أعد تشغيل عملية Hermes المتأثرة. لا تضف شجرة site-packages ثانية إلى استيراداتها الحيّة.
  • تعارض اعتماديات: اقرأ hermes pm status. صحّح متطلبات الإضافة قبل إعادة محاولة القبول.
  • اعتماديات Python متضررة: شغّل hermes pm repair ، ثم أعد تشغيل Hermes. يعيد الإصلاح بناء مساحة عمل الجيل المحدد و lock المحفوظين دون تحليل إعدادات الإضافات. السجل غير المقروء أو lock المحفوظ المفقود يفشل دون اختيار مجموعة اعتماديات ناقصة. قبل وجود جيل، يستخدم الإصلاح lock المشحون أو المعتمد ومجموعة الميزات المسجّلة.
  • تثبيت اعتماديات منقطع: يطلب بدء التشغيل إصلاح PM نفسه قبل تفعيل الاعتماديات. المحاولات التلقائية محدودة؛ ويعيد pm repair المحاولة صراحة. يحفظ الإصلاح الفاشل الاختيار السابق وعلامة إعادة المحاولة.
  • ملف Python تنفيذي أو مصدر تطبيق متضرر: أصلح أو أعد التثبيت عبر مالك الحزمة. لا يستطيع PM العمل دون تلك الملفات. لا يعدّل إصلاح الاعتماديات ملفات الحمولة الموقّعة مطلقًا.
  • حزمة أو extra غير معروفة: استخدم الاسم المعلن. يأخذ pm install أسماء الحزم، لا أسماء extras الخاصة بـ Python أو مواصفات pip.
