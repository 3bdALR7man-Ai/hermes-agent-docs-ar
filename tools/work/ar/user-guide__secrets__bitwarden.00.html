Bitwarden Secrets Manager

اسحب مفاتيح API من Bitwarden Secrets Manager عند بدء تشغيل العملية بدلًا من تخزينها كنص صريح داخل ~/.hermes/.env. يحلّ سرّ تمهيدي واحد (access token لحساب آلة) محلّ N من المفاتيح الخاصة بكل مزوّد، ويصبح تدوير (rotation) أي بيانات اعتماد مجرد تغيير واحد في تطبيق Bitwarden على الويب.

آلية العمل

  1. تُنشئ حساب آلة (machine account) في Bitwarden Secrets Manager، وتمنحه صلاحية القراءة على مشروع (project)، ثم تولّد access token.
  2. يخزّن Hermes ذلك الـ token الوحيد في ~/.hermes/.env باسم BWS_ACCESS_TOKEN.
  3. في كل مرة يبدأ فيها hermes (أو الـ gateway، أو مهمة cron)، وبعد تحميل ~/.hermes/.env، يستدعي Hermes الأمر bws secret list <project_id> ويضع المفاتيح المُعادة في os.environ.
  4. افتراضيًا، يستبدل Hermes القيم الموجودة مسبقًا في بيئتك، فيكون Bitwarden هو مصدر الحقيقة — دوّر المفتاح مرة واحدة في تطبيق الويب وستلتقطه كل عمليات Hermes عند بدء تشغيلها التالي. اضبط override_existing: false في الإعدادات إن أردت أن تكون الأولوية لـ .env بدلًا من ذلك.

يُنزَّل الملف التنفيذي bws تلقائيًا إلى ~/.hermes/bin/ عند أول استخدام — دون حاجة إلى apt أو brew أو sudo.

لماذا حسابات الآلة (ولماذا لا يُطلب 2FA)

صُمّم Bitwarden Secrets Manager لأحمال العمل غير التفاعلية: لا يمكن حماية حسابات الآلة بالمصادقة الثنائية (2FA) لعدم وجود إنسان في الحلقة. فالـ access token هو بيانات الاعتماد نفسها، ويستطيع أي شخص يملكه قراءة كل سرّ يملك حساب الآلة صلاحية الوصول إليه، لذا تعامل معه كـ bearer token عالي القيمة — خزّنه في .env (وليس في config.yaml)، وألغِه ثم أعد توليده من تطبيق Bitwarden على الويب إذا تسرّب يومًا.

تُعِدّ حساب الآلة في تطبيق الويب، حيث تنطبق المصادقة الثنائية المعتادة لديك. وبعد ذلك يعمل الـ token باستقلالية.

الإعداد

1. أنشئ حساب آلة و access token

في تطبيق Bitwarden على الويب (أو vault.bitwarden.eu لحسابات الاتحاد الأوروبي):

  1. انتقل إلى Secrets Manager من مُبدِّل المنتجات.
  2. أنشئ Project أو اختر واحدًا موجودًا (مثل "Hermes keys").
  3. أضف مفاتيح المزوّدين كأسرار. تصبح قيمة Name للسرّ هي اسم متغير البيئة — استخدم OPENROUTER_API_KEY و ANTHROPIC_API_KEY وغيرها.
  4. Machine accounts → New machine account → My Hermes machine → تبويب Projects → امنح صلاحية Read على مشروعك.
  5. تبويب Access tokens → Create access token → مدة الصلاحية Never (أو اختر تاريخًا) → انسخ الـ token (يبدأ بـ 0.). لا يستطيع Bitwarden استرجاعه مرة أخرى — فاحتفظ بالنسخة.

يتوفر Secrets Manager ضمن الخطة المجانية من Bitwarden مع بعض الحدود؛ فلا تحتاج إلى خطة مدفوعة لتجربة ذلك.

2. شغّل المعالج (wizard)

سيقوم المعالج بما يلي:

  1. تنزيل bws v2.0.0 والتحقق منه في ~/.hermes/bin/bws.
  2. مطالبتك بإدخال الـ access token (يكون الإدخال مخفيًا). ويُخزَّن في ~/.hermes/.env باسم BWS_ACCESS_TOKEN.
  3. سؤالك عن منطقة Bitwarden التي ينتمي إليها حساب الآلة — US Cloud أو EU Cloud أو self-hosted / custom URL. وتُخزَّن في config.yaml باسم secrets.bitwarden.server_url وتُمرَّر إلى bws باسم BWS_SERVER_URL.
  4. عرض المشاريع التي يستطيع حساب الآلة رؤيتها لتختار أحدها. ويُخزَّن في config.yaml باسم secrets.bitwarden.project_id.
  5. جلب أسرار المشروع تجريبيًا وإظهار متغيرات البيئة التي ستُحَلّ قيمها.
  6. ضبط secrets.bitwarden.enabled: true.

حالات الإخفاق

لا يعطّل Bitwarden بدء تشغيل Hermes أبدًا. إذا حدث أي خطأ، فسترى تحذيرًا من سطر واحد في stderr ويواصل Hermes العمل بأي بيانات اعتماد موجودة مسبقًا في .env:

ملاحظات أمنية

  • الـ token التمهيدي (BWS_ACCESS_TOKEN) حساس بحد ذاته — فأي شخص يملكه يستطيع قراءة كل سرّ يملك حساب الآلة صلاحية الوصول إليه. تعامل معه كما تتعامل مع أي مفتاح API آخر.
  • يرفض Hermes السماح لـ Bitwarden باستبدال الـ token التمهيدي نفسه، حتى مع override_existing: true. وإذا خزّنت BWS_ACCESS_TOKEN كسرّ داخل المشروع، فسيُتجاوز بصمت أثناء التطبيق.
  • يُتحقَّق من ملف bws التنفيذي المُنزَّل بمطابقته مع checksum من نوع SHA-256 المنشور في إصدار GitHub نفسه، ويؤدي عدم التطابق إلى إيقاف التثبيت.
  • يُحدَّث الإصدار المثبّت (bws v2.0.0 وقت كتابة هذا الدليل) عبر PRs إلى هذا المستودع — فلا يرقّي Hermes أداة bws تلقائيًا إلى "latest" لأن بنية الإصدارات في المصدر الأصلي (upstream) قد تتغير.

متى لا تستخدم هذه الميزة

  • الإعدادات الشخصية على جهاز واحد حيث يكفي ~/.hermes/.env. فأنت تستبدل بيانات اعتماد بأخرى وتضيف اعتمادًا على الشبكة عند بدء التشغيل.
  • البيئات المعزولة عن الشبكة (air-gapped) التي لا تستطيع الوصول إلى api.bitwarden.com.
  • CI/CD حيث تكون آلية حقن الأسرار الحالية (GitHub Actions secrets و Vault وغيرها) مُعدّة بالفعل — اختر مسارًا واحدًا لا مسارين.

الحالة المناسبة لهذه الميزة هي أساطيل الأجهزة المتعددة، وأجهزة التطوير المشتركة، وخوادم VPS الخاصة بالـ gateway، أو أي إعداد تريد فيه تدويرًا وإلغاءً مركزيين عبر عدة تثبيتات لـ Hermes.
