hermes gateway

الأوامر الفرعية:

الأمر الفرعيالوصف
runتشغيل gateway في المقدمة (foreground). موصى به لـWSL وDocker وTermux.
startبدء خدمة systemd/launchd المثبَّتة في الخلفية.
stopإيقاف الخدمة (أو عملية المقدمة).
restartإعادة تشغيل الخدمة.
statusعرض حالة الخدمة.
listعرض كل الـ profiles وما إذا كان gateway كل profile يعمل حاليًا (مع PID إن توفّر). مفيد عندما تشغّل عدة profiles جنبًا إلى جنب وتريد نظرة عامة واحدة.
installالتثبيت كخدمة خلفية systemd (Linux) أو launchd (macOS).
uninstallإزالة الخدمة المثبَّتة.
setupإعداد منصة مراسلة تفاعلي.
migrateنقل gateways مستقلة لكل profile إلى gateway واحد افتراضي متعدد الإرسال (multiplexed) (--multiplex، وهو الافتراضي) أو التراجع من البيان (manifest) المسجَّل (--standalone). يشغّل فحصًا مبدئيًا (رموز bot مكررة، وناقلات منفذ ثانوية بدون مدخل /p/<profile>/) ولا يغيّر شيئًا عند الحظر. العلامات: --dry-run، -y/--yes. راجع الانتقال من gateways لكل profile.
migrate-legacyإزالة وحدات hermes.service القديمة المتبقية من التثبيتات قبل إعادة التسمية. لا تُمَس أبدًا وحدات الـ profile (hermes-gateway-<profile>.service) ولا الخدمات غير ذات الصلة. العلامات: --dry-run، -y/--yes.
enrollتجريبي: تسجيل هذا الـ gateway مع موصّل relay وحفظ بيانات اعتماد relay لمنصات مدعومة بموصّل. راجع Hermes Relay.

الخيارات:

الخيارالوصف
--allعند start / restart / stop: العمل على gateway كل profile، لا فقط HERMES_HOME النشط. مفيد إذا كنت تشغّل عدة profiles جنبًا إلى جنب وتريد إعادة تشغيلها كلها بعد hermes update.
--no-superviseعند run: داخل صورة Docker القائمة على s6-overlay، عدم الاشتراك في الإشراف التلقائي واستخدام دلالات المقدمة السابقة لـs6 — يعمل gateway كعملية الحاوية الرئيسية دون إعادة تشغيل تلقائي. بلا تأثير خارج صورة s6. مكافئ لضبط HERMES_GATEWAY_NO_SUPERVISE=1.
--external-supervisorعند run: الإعلان أن مدير عمليات مزوَّد من خلال wrapper يملك gateway الأمامي. استخدم هذا عندما يزيل sudo أو env -i أو wrapper آخر علامة البيئة الأصلية لـlaunchd/systemd. تخرج إعادة التشغيل والتحديثات داخل المحادثة إلى ذلك المدير بدلًا من إنشاء بديل منفصل.

--external-supervisor عقد سياسة إعادة تشغيل: تخرج إعادة تشغيل داخل المحادثة أو تحديث بإعادة تشغيل الخدمة برمز حالة 75، لذا يجب أن يعيد مشرف الـ wrapper تشغيل gateway بعد ذلك الخروج غير الصفري. بالنسبة لـsystemd، استخدم Restart=on-failure أو Restart=always ولا تُدرج 75 ضمن RestartPreventExitStatus؛ بالنسبة لـlaunchd، اضبط KeepAlive لإعادة التشغيل بعد الخروجات غير الناجحة. بدون تلك السياسة، تترك إعادة تشغيل مطلوبة gateway متوقفًا.

يقبل hermes gateway enroll الخيارات --token و--connector-url و--gateway-id و--wake-url. يستبدل رمز التسجيل مع الموصّل ويكتب قيم GATEWAY_RELAY_ID وGATEWAY_RELAY_SECRET وGATEWAY_RELAY_DELIVERY_KEY الناتجة، وGATEWAY_RELAY_URL الاختياري، و(عند إعطاء --wake-url) GATEWAY_RELAY_WAKE_URL في ملف .env الخاص بالـ profile النشط.

مستخدمو WSL

استخدم hermes gateway run بدلًا من hermes gateway start — دعم systemd في WSL غير موثوق. لفّه في tmux للاستمرارية: tmux new -s hermes 'hermes gateway run'. راجع الأسئلة الشائعة عن WSL للتفاصيل.

hermes lsp

إدارة تكامل Language Server Protocol. يشغّل LSP خوادم لغة حقيقية (pyright وgopls وrust-analyzer، ...) في الخلفية ويغذّي تشخيصاتها في فحص ما بعد الكتابة المستخدَم في write_file وpatch. مشروط باكتشاف مساحة عمل git — لا يعمل LSP إلا عندما يكون دليل العمل الحالي أو الملف المعدَّل داخل worktree لـgit.

الأوامر الفرعية:

الأمر الفرعيالوصف
statusعرض حالة الخدمة، والخوادم المُعدَّة، وحالة التثبيت.
listطباعة سجل الخوادم المدعومة. مرّر --installed-only لتخطي غير المثبَّتة.
install <id>تثبيت ثنائي (binary) خادم واحد فورًا.
install-allتثبيت كل خادم له وصفة تثبيت تلقائي معروفة.
restartإيقاف العملاء (clients) قيد التشغيل بحيث تُعاد ولادتهم عند التعديل التالي.
which <id>طباعة مسار الثنائي المحلول لخادم واحد.

راجع LSP — التشخيص الدلالي (Semantic Diagnostics) للدليل الكامل، واللغات المدعومة، وإعدادات الضبط.

hermes setup

المسار الأسهل: hermes setup --portal — تسجيل الدخول عبر OAuth إلى Nous Portal والاشتراك في Tool Gateway بضربة واحدة.

التشغيل الأول: يطلق معالج المرة الأولى.

مستخدم عائد (مُعدّ بالفعل): ينتقل مباشرة إلى معالج إعادة الإعداد الكامل — كل سؤال يعرض قيمتك الحالية كافتراضي، اضغط Enter للاحتفاظ بها أو اكتب قيمة جديدة. بدون قائمة.

انتقل إلى قسم واحد بدلًا من المعالج الكامل:

القسمالوصف
modelإعداد المزوّد والنموذج.
terminalإعداد terminal backend وsandbox.
gatewayإعداد منصة المراسلة.
toolsتفعيل/تعطيل الأدوات لكل منصة.
agentإعدادات سلوك الوكيل.

الخيارات:

الخيارالوصف
--quickفي تشغيلات المستخدم العائد: اسأل فقط عن العناصر المفقودة أو غير المضبوطة. تخطَّ العناصر المُعدَّة بالفعل.
--non-interactiveاستخدام الإعدادات الافتراضية / قيم البيئة دون أسئلة.
--resetإعادة تعيين الإعدادات إلى الافتراضي قبل الإعداد.
--reconfigureاسم بديل للتوافق الخلفي — الآن يقوم hermes setup المجرَّد على تثبيت موجود بهذا افتراضيًا.
--portalإعداد Nous Portal بضربة واحدة: تسجيل الدخول عبر OAuth، وضبط Nous كمزوّد الاستدلال، والاشتراك في Tool Gateway. يتخطى بقية المعالج.

hermes portal

فحص مصادقة Nous Portal، وتوجيه Tool Gateway، والوصول إلى صفحة الاشتراك. الاستدعاء بدون أمر فرعي يشغّل status.

الأمر الفرعيالوصف
status (الافتراضي)حالة مصادقة Portal + ملخّص توجيه Tool Gateway لكل أداة. يظهر أيضًا عند عدم إعطاء أمر فرعي.
openفتح portal.nousresearch.com/manage-subscription في متصفحك الافتراضي.

hermes slack

يولّد بيان تطبيق (manifest) Slack يسجّل كل أمر gateway في COMMAND_REGISTRY (/btw، /stop، /model، ...) كأمر slash أصيل في Slack — بما يطابق Discord وTelegram. الصق المخرجات في إعدادات تطبيق Slack الخاص بك على https://api.slack.com/apps ← تطبيقك ← Features → App Manifest → Edit، ثم Save. يطلب Slack إعادة التثبيت إذا تغيّرت النطاقات (scopes) أو أوامر slash.

العلامةالافتراضيالغرض
--write [PATH]stdoutالكتابة إلى ملف بدلًا من stdout. --write المجرَّدة تكتب $HERMES_HOME/slack-manifest.json.
--name NAMEHermesاسم عرض البوت في Slack.
--description DESCوصف افتراضيوصف البوت المعروض في دليل تطبيقات Slack.
--long-description TEXTغير مضبوطضبط display_information.long_description مباشرة (175–4000 حرف). غير متوافق مع --slashes-only.
--long-description-file PATHغير مضبوطقراءة الوصف الطويل من ملف نصي UTF-8، مع الحفاظ على محتواه تمامًا. حصري مع --long-description وغير متوافق مع --slashes-only.
--slashes-onlyمعطّلإصدار features.slash_commands فقط للدمج في بيان يُصان يدويًا.

شغّل hermes slack manifest --write مرة أخرى بعد hermes update لالتقاط أي أوامر جديدة.

hermes send

إرسال رسالة لمرة واحدة إلى منصة مراسلة مُعدَّة دون تشغيل وكيل أو حلقة gateway. يعيد استخدام بيانات اعتماد gateway المُعدَّة مسبقًا (~/.hermes/.env + ~/.hermes/config.yaml) بحيث يمكن لسكربتات العمليات ومهام cron وhooks CI وdaemons المراقبة نشر تحديثات الحالة دون إعادة تنفيذ عميل REST الخاص بكل منصة.

بالنسبة للمنصات ذات رمز البوت (Telegram وDiscord وSlack وSignal وSMS وWhatsApp-CloudAPI)، لا يلزم تشغيل gateway — يتحدث hermes send مباشرة إلى endpoint REST الخاص بالمنصة. أما منصات الإضافات التي تحتاج محوّلًا دائمًا فلا تزال تتطلب gateway حيًا.

الخيارالوصف
-t، --to <TARGET>هدف التسليم. الصيغ: platform (يستخدم القناة الرئيسية)، platform:chat_id، platform:chat_id:thread_id، أو platform:#channel-name. أمثلة: telegram، telegram:-1001234567890، discord:#ops، slack:C0123ABCD، signal:+15551234567.
-f، --file <PATH>قراءة نص الرسالة من PATH (ملفات نصية فقط — سجلات وتقارير وmarkdown). مرّر - لإجبار القراءة من stdin. لإرسال صورة أو ملف ثنائي آخر، استخدم MEDIA:<path> (انظر أدناه).
-s، --subject <LINE>إضافة سطر موضوع/عنوان قبل نص الرسالة.
-l، --list [platform]عرض الأهداف المُعدَّة عبر كل المنصات (أو منصة معيّنة فقط).
-q، --quietإخفاء stdout عند النجاح — مفيد في السكربتات (الاعتماد على رمز الخروج فقط).
--jsonإصدار نتيجة JSON خام بدلًا من مخرجات مقروءة للبشر.

إذا لم يُعطَ معامل message موضعي ولا --file، يقرأ hermes send من stdin عندما لا يكون TTY. رموز الخروج: 0 عند النجاح، 1 عند فشل التسليم/الـ backend، 2 عند أخطاء الاستخدام.

إرسال الصور والوسائط الأخرى

--file مخصص لأجسام نصية فقط. لتسليم صورة أو مستند أو فيديو أو ملف صوتي كمرفق أصلي للمنصة، أشر إليه داخل نص الرسالة بتوجيه MEDIA:<local_path>:

افتراضيًا، تُرسَل ملفات الصور كصور (تعيد منصات مثل Telegram ضغطها). أضف [[as_document]] إلى الرسالة لتسليمها كمرفقات ملفات غير مضغوطة بدلًا من ذلك:

أمثلة:

hermes peer

رسائل bot-إلى-bot مباشرة عبر الأجهزة. سجّل gateway آخر لـHermes (على أي جهاز يشغّل منصة api_server) كـنظير (peer)، ثم راسل وكلاءه: يحلّ hermes peer dm جلسة Bot Chat الأساسية للوكيل البعيد عبر خادم API الخاص بالنظير، ويشغّل دورًا واحدًا للوكيل هناك، ويطبع الرد على stdout — التوأم عبر الأجهزة لأمر مراسلة البوت المحلي hermes -p <bot> chat --in ~ -c "Bot Chat" ….

<peer> وحدها تستهدف الوكيل الرئيسي لـgateway النظير؛ <peer>/<agent> تستهدف profile مسمًّى على نظير متعدد الإرسال (موجَّه عبر مرآته /p/<profile>/).

الأمر الفرعيالوصف
add <name> --url <URL> [--key <KEY>] [--note TEXT]تسجيل أو تحديث نظير. يذهب الرابط إلى config.yaml (bot_peers)؛ يُخزَّن المفتاح كـHERMES_PEER_<NAME>_KEY في ~/.hermes/.env.
listعرض النظراء وما إذا كان كل منهم لديه مفتاح مُعدّ.
dm <peer>[/<agent>] [message]مراسلة Bot Chat الأساسية لوكيل النظير وطباعة الرد (--json لمخرجات قابلة للقراءة آليًا؛ تعود الرسالة إلى stdin إن لم تُعطَ).
run <peer>[/<agent>] [message]بدء دور Bot Chat أساسي طويل بشكل غير متزامن وإعادة run_id ومعرّف الجلسة ومفتاح idempotency (يدعم --json). أعد استخدام --idempotency-key عند إعادة محاولة نفس الطلب.
status <peer>[/<agent>] <run_id>استطلاع تشغيل نظير غير متزامن وطباعة مخرجاته النهائية عند الاكتمال (يدعم --json).
stop <peer>[/<agent>] <run_id>إيقاف تشغيل النظير غير المتزامن المحدَّد بدقة دون استهداف دور آخر (يدعم --json).
remove <name>إزالة نظير من السجل (يبقى إدخال مفتاح .env كما هو).

عند تسجيل نظير واحد على الأقل، يتضمن بروتوكول مراسلة Bot Mode (agent.bot_mode_protocol) الذي يُلقَّن لكل Bot Chat أساسية تلقائيًا قائمة النظراء ونمط hermes peer dm، بحيث تكتشف الوكلاء زملاء عبر الأجهزة دون تعديلات SOUL. راجع Bot Mode.

رموز الخروج: 0 عند النجاح، 1 عند فشل التسليم/النظير، 2 عند أخطاء الاستخدام.

hermes secrets

سحب مفاتيح API من مدير أسرار خارجي عند بدء العملية بدلًا من تخزينها في ~/.hermes/.env. يدعم حاليًا Bitwarden Secrets Manager. راجع الدليل الكامل: تكامل Bitwarden.

الأوامر الفرعية لـbitwarden (اسم بديل bw):

الأمر الفرعيالوصف
setupمعالج تفاعلي: تثبيت ثنائي bws المثبَّت بإصدار محدَّد، وحفظ رمز وصول، واختيار مشروع. يقبل --project-id و--access-token و--server-url للاستخدام غير التفاعلي.
statusعرض الإعدادات الحالية، ومسار/إصدار الثنائي، وحالة التحقق من الرمز.
tokenتدوير رمز الوصول: يتحقق من الرمز الجديد مقابل Bitwarden قبل تخزينه في .env (رمز مرفوض لا يغيّر شيئًا). يقبل --access-token للاستخدام غير التفاعلي و--no-verify لتخطي الفحص.
syncجلب الأسرار الآن والإبلاغ عمّا تغيّر. أضف --apply لتصدير الأسرار فعليًا إلى بيئة الـ shell الحالية (الافتراضي تشغيل تجريبي/dry-run).
installتنزيل والتحقق من ثنائي bws المثبَّت بإصدار محدَّد. --force يعيد التنزيل حتى لو كانت هناك نسخة مُدارة موجودة بالفعل.
disableإيقاف تكامل Bitwarden.

hermes migrate

تشخيص و(اختياريًا) إعادة كتابة config.yaml النشط لاستبدال مراجع النماذج المتقاعدة أو الإعدادات المهملة. تُؤخذ نسخة احتياطية مؤرَّخة من config.yaml الأصلي قبل أي إعادة كتابة (تخطَّها بـ--no-backup).

الأمر الفرعيالوصف
xaiفحص config.yaml بحثًا عن مراجع لنماذج xAI المُجدوَل تقاعدها في 15 مايو 2026 و(مع --apply) إعادة كتابتها في مكانها إلى البدائل الرسمية وفق دليل انتقال xAI. الافتراضي تشغيل تجريبي/dry-run.

علامات شائعة للأوامر الفرعية للانتقال (migration):

العلامةالوصف
--applyإعادة كتابة config.yaml في مكانها (الافتراضي: تشغيل تجريبي/dry-run، بدون كتابة).
--no-backupتخطي النسخة الاحتياطية المؤرَّخة لـconfig.yaml عند التطبيق.

لا تخلط بينه وبين hermes claw migrate (استيراد لمرة واحدة لإعدادات OpenClaw إلى Hermes) — hermes migrate هو أمر إعادة كتابة الإعدادات ذو المستوى الأعلى.

hermes proxy

تشغيل خادم HTTP محلي متوافق مع OpenAI يعيد توجيه الطلبات إلى مزوّد upstream مصادَق عليه عبر OAuth (مثل Nous Portal وxAI). يمكن للتطبيقات الخارجية توجيه طلباتها إلى الـ proxy بأي رمز حامل (bearer token)؛ ويرفق الـ proxy بيانات اعتماد OAuth الحقيقية الخاصة بك عند الخروج. راجع Subscription Proxy للدليل الكامل.

الأمر الفرعيالوصف
startتشغيل الـ proxy في المقدمة. العلامات: --provider <nous|xai> (الافتراضي nous)، --host <addr> (الافتراضي 127.0.0.1؛ استخدم 0.0.0.0 للكشف على الشبكة المحلية)، --port <int> (الافتراضي 8645).
statusعرض upstreams الـ proxy الجاهزة (بيانات اعتماد موجودة، OAuth صالح).
providersعرض مزوّدي upstream المتاحين للـ proxy.

hermes security

فحص ثغرات عند الطلب مقابل OSV.dev. يغطي venv الخاص بـHermes (توزيعات PyPI المثبَّتة)، واعتماديات Python المعلَنة بواسطة الإضافات تحت ~/.hermes/plugins/، وخوادم MCP المثبَّتة بإصدار محدَّد عبر npx/uvx في config.yaml. لا يفحص الحزم المثبَّتة عالميًا ولا إضافات المحرر/المتصفح.

الأمر الفرعيالوصف
auditتشغيل تدقيق سلسلة توريد لمرة واحدة.

علامات audit:

العلامةالافتراضيالوصف
--jsonمعطّلإصدار JSON قابل للقراءة آليًا بدلًا من نص مقروء للبشر.
--fail-on <level>criticalالخروج برمز غير صفري عندما تصل أي نتيجة إلى هذه الخطورة (low، moderate، high، critical).
