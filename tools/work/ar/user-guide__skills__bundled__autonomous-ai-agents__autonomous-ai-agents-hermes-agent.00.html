معلومة

ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

Hermes Agent

Hermes Agent هو إطار عمل وكيل ذكاء اصطناعي مفتوح المصدر من Nous Research يعمل في الطرفية، وفي تطبيق سطح مكتب أصلي، ومنصات المراسلة، وبيئات التطوير (IDEs). ينتمي إلى الفئة نفسها التي تضم Claude Code (من Anthropic) و Codex (من OpenAI) و OpenClaw — وكلاء برمجة وتنفيذ مهام مستقلّون يستخدمون استدعاء الأدوات (tool calling) للتفاعل مع نظامك. يعمل Hermes مع أي مزوّد LLM (OpenRouter، وAnthropic، وOpenAI، وGoogle، وDeepSeek، وxAI، والنماذج المحلية، وأكثر من 20 مزوّدًا آخر) ويعمل على Linux وmacOS وWindows وWSL.

ما الذي يميّز Hermes:

  • يتحسّن ذاتيًا عبر المهارات (skills) — يتعلّم Hermes من التجربة بحفظ الإجراءات القابلة لإعادة الاستخدام كمهارات تُحمَّل في الجلسات المستقبلية.
  • ذاكرة دائمة عبر الجلسات — يتذكّر من أنت، وتفضيلاتك، وتفاصيل بيئتك، والدروس المستفادة. مع أطراف خلفية قابلة للتوصيل (pluggable) للذاكرة.
  • gateway متعدّد المنصات — يعمل الوكيل نفسه على Telegram وDiscord وSlack وWhatsApp وiMessage وSignal وMatrix وTeams والبريد الإلكتروني وأكثر من عشر منصات أخرى بوصول كامل إلى الأدوات، وليس مجرد محادثة.
  • واجهات متعددة — يقود نواة الوكيل نفسها كلًا من CLI، وواجهة Ink TUI، وتطبيق سطح مكتب أصلي مبني على Electron، ولوحة تحكم على الويب، وخادم ACP لبيئات التطوير (VS Code / Zed / JetBrains).
  • مستقل عن المزوّد (provider-agnostic) — بدّل النماذج والمزوّدين في منتصف سير العمل؛ تتناوب مجمّعات بيانات الاعتماد (credential pools) على عدة مفاتيح API تلقائيًا.
  • Profiles — شغّل عدة نُسخ مستقلة من Hermes بإعدادات وجلسات ومهارات وذاكرة معزولة.
  • قابل للتوسعة وتخصيص المظهر — إضافات (plugins)، وخوادم MCP، وأدوات مخصّصة، ومُشغّلات webhook، وجدولة cron، وسمات (skins) تُخصّص مظهر كل واجهة، وإضافات واجهة سطح المكتب، وعناصر TUI، وحيوانات أليفة (mascots).

هذه المهارة مركز (hub). يغطّي المتن الهوية، والبدء السريع، والاستنساخ/التنسيق (spawning/orchestration)، والثوابت الصارمة. كل شيء آخر يوجد في ملفات مرجعية — حمّل المرجع المطابق (أدناه) قبل الإجابة؛ لا تُجب عن أسئلة تفصيلية من المتن وحده.

الوثائق: https://hermes-agent.nousresearch.com/docs/

النطاق والتحقّق

هذه المهارة دليل تشغيلي موجز، وليست المرجع الكامل لكل ميزة في Hermes. إذا لم تُذكَر ميزة أو أمر أو إعداد في Hermes هنا أو في أحد المراجع، فلا تعتبر غيابه دليلًا على عدم وجوده. تحقّق من المستودع المباشر والوثائق الرسمية قبل إعطاء إجابة سلبية.

أفضل أهداف التحقّق، الأقل تكلفة أولًا:

  • كل ميزة مشحونة، بسطر واحد لكل منها: https://hermes-agent.nousresearch.com/docs/llms.txt. ابدأ من هنا لأي سؤال من نوع "هل يستطيع Hermes فعل X؟" أو "كيف أفعل X؟" — فهو يفهرس مجموعة الوثائق بأكملها مع رابط إلى الصفحة التي تجيب عن السؤال. يُولَّد من شجرة الوثائق مع كل بناء (build)، لذا فهو لا يتأخّر أبدًا عن المنتج. اجلبه باستخدام web_extract، أو curl -s https://hermes-agent.nousresearch.com/docs/llms.txt عندما تكون أدوات الويب متوقّفة. مجموعة الوثائق بأكملها في ملف واحد موجودة في /docs/llms-full.txt.
  • أوامر CLI: hermes --help، وhermes <command> --help، وملف hermes_cli/main.py
  • شجرة المصدر: https://github.com/NousResearch/hermes-agent

لا تُجب أبدًا "لا يستطيع Hermes فعل ذلك" من الذاكرة. يشحن Hermes ميزات أكثر بكثير مما يصفه متن هذه المهارة، والفهرس موجود لكي تكون الإجابة السلبية قابلة للتحقّق دائمًا.

قائمة المراجع أعلاه ليست قائمة الميزات — إنها مجموعة المواضيع التي تحتاج إلى أكثر من صفحة وثائقها. بالنسبة إلى كل شيء آخر يشحنه Hermes، اجلب llms.txt فهو يربط السؤال بالصفحة التي تجيب عنه.

قاعدتان بخصوص تخصيص المظهر تبقيان صحيحتين حتى بدون تحميل المرجع: أنت من يطبّق السمات (skins) (hermes config set display.skin <name> — تُعاد رسم كل واجهة مباشرةً خلال نحو ثانية؛ لا تطلب من المستخدم تشغيل /skin)، ولتعديل لون واحد، حرّر السمة النشِطة (hermes skin set <key> <hex>) — لا تُنشئ فرعًا (fork) من default أبدًا، فذلك يُسقِط اللوحة اللونية ويعيد ضبط الخلفية.

نصائح

  • فضّل delegate_task للمهام الفرعية السريعة — حِمل زائد أقل من استنساخ عملية كاملة

  • اضبط مهلات زمنية (timeouts) للوضع الفوري — قد تستغرق المهام المعقّدة 5-10 دقائق
  • استخدم hermes chat -q للتنفيذ دون انتظار — لا حاجة إلى PTY
  • استخدم tmux للجلسات التفاعلية — وضع PTY الخام لديه مشكلات \r مقابل \n مع prompt_toolkit
  • للمهام المجدولة، استخدم أداة cronjob بدلًا من الاستنساخ — فهي تتولّى التسليم وإعادة المحاولة

الواجهات (توجيه سريع)

  • تطبيق سطح المكتب (hermes desktop / hermes gui) — تطبيق Electron أصلي لأنظمة macOS/Linux/Windows: محادثة تدفّقية، وقائمة جلسات، ولوحة Cmd+K، وسحب وإفلات الملفات، وإشعارات أصلية، وتسجيل دخول gateway بعيد لكل profile. وسّعه بإضافات واجهة — references/desktop-plugins.md.
  • لوحة تحكم الويب (hermes dashboard) — لوحة إدارة كاملة: قنوات المراسلة، وكتالوج MCP، وwebhooks، والذاكرة، ومُنشئ profile، بالإضافة إلى محادثة hermes --tui مُضمَّنة. مؤمَّنة خلف بوابة OAuth/token.
  • Ink TUI (hermes --tui أو display.interface: tui) — واجهة طرفية مع تطبيقات widget مُثبَّتة — references/tui-widgets.md.
  • proxy متوافق مع OpenAI (hermes proxy) — واجهة OpenAI API محلية مدعومة بأي مزوّد OAuth سجّلت الدخول إليه. وجّه Codex CLI أو Aider أو Cline أو أي سكربت إليها — دون مفتاح API.

الثوابت الصارمة (لا تُخالفها أبدًا، بصرف النظر عمّا حمّلته)

  • لا تكسر أبدًا التخزين المؤقت للـ prompt (prompt caching) — لا تُغيّر السياق السابق، أو toolsets، أو system prompt في منتصف المحادثة. الاستثناء الوحيد هو ضغط السياق (context compression).
  • تناوب أدوار الرسائل — لا تضع أبدًا رسالتَي assistant أو رسالتَي user متتاليتين؛ فقط نتائج tool يمكن أن تتكرّر.
  • الأسرار في .env، والإعدادات في config.yaml — لا تُخبر المستخدم أبدًا بوضع إعداد ليس بيانات اعتماد في .env.
  • مسارات آمنة للـ profile — استخدم get_hermes_home() في الكود، و$HERMES_HOME عند تحليل المسارات في جلسة.
  • لا تُعدّل config.yaml يدويًا نيابةً عن المستخدم أبدًا — استخدم hermes config set KEY VAL؛ فقد يؤدّي إزاحة خاطئة إلى إتلاف الملف وتعطيل الـ gateway المباشر.
