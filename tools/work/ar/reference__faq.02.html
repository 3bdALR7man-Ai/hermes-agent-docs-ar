Profiles

كيف تختلف profiles عن مجرد ضبط HERMES_HOME؟

Profiles طبقة مُدارة فوق HERMES_HOME. أنت تستطيع ضبط HERMES_HOME=/some/path يدويًا قبل كل أمر، لكن profiles تتولى كل التفاصيل نيابةً عنك: إنشاء بنية الأدلة، وتوليد أسماء shell البديلة (hermes-work)، وتتبّع الـ profile النشط في ~/.hermes/active_profile، ومزامنة تحديثات المهارات عبر كل profiles تلقائيًا. وتتكامل أيضًا مع إكمال الأوامر بمفتاح Tab كي لا تضطر إلى تذكّر المسارات.

هل يمكن لـ profile اثنَين مشاركة bot token نفسه؟

لا. تتطلب كل منصة مراسلة (Telegram و Discord وغيرهما) وصولًا حصريًا إلى bot token. إذا حاول profile اثنان استخدام الـ token نفسه في آن واحد، يفشل اتصال الـ gateway الثاني. أنشئ بوتًا منفصلًا لكل profile — في Telegram، تحدث إلى @BotFather لإنشاء بوتات إضافية.

هل تتشارك profiles الذاكرة أو الجلسات؟

لا. لكل profile مخزن ذاكرة وقاعدة بيانات جلسات ودليل مهارات خاصة به. وهي معزولة تمامًا. إذا أردت بدء profile جديد بذكريات وجلسات موجودة، فاستخدم hermes profile create newname --clone-all لنسخ كل شيء من الـ profile الحالي، أو أضف --clone-from <profile> للنسخ من profile مصدر محدد.

هذا العزل أيضًا هو سبب عدم تشغيل وكيلَين مطلقًا على نفس الـ profile أو مجلد Hermes الرئيسي: فكلاهما يكتب الذاكرة تلقائيًا ويحمّل كل منهما كتابات الآخر عند بدء الجلسة، لذا تتدهور حالتهما المخزّنة مع كل جلسة. وكيل واحد لكل profile؛ ولذاكرة مشتركة فعليًا بين الوكلاء، استخدم مزوّد ذاكرة خارجيًا.

ماذا يحدث عندما أشغّل hermes update?

hermes update يسحب أحدث كود ويعيد تثبيت الاعتماديات مرة واحدة (لا لكل profile). ثم يزامن المهارات المحدّثة عبر كل profiles تلقائيًا. لا تحتاج إلى تشغيل hermes update إلا مرة واحدة — إذ يغطي كل profile على الجهاز.

كم profile يمكنني تشغيله؟

لا يوجد حد صارم. كل profile دليل تحت ~/.hermes/profiles/ يحمل ملف هوية واحدًا على الأقل (config.yaml, .env, SOUL.md, profile.yaml, auth.json أو state.db)؛ والدليل المجرّد دون أحدهما (المتبقي من تدوير سجل أو دورة cron) ليس profile — فلا يُدرج ولا يُقدَّم، ويبلّغ -p <name> عن فقدانه، ويرفض hermes profile create <name> الكتابة فوقه حتى تنقله أو تزيله. يعتمد الحد العملي على مساحة القرص وعدد gateways المتزامنة التي يتحملها نظامك (كل gateway عملية Python خفيفة). لا بأس بتشغيل عشرات profiles؛ ولا يستهلك profile الخامل أي موارد.

تشغيل عدة وكلاء على رقم WhatsApp واحد (ربط حسب المحادثة)

السيناريو: في OpenClaw، كان لديك عدة وكلاء مستقلين مرتبطين بمحادثات WhatsApp محددة — واحد لمجموعة قائمة تسوق العائلة، وآخر لمحادثتك الخاصة. هل يستطيع Hermes فعل ذلك؟

القيد الحالي: يحتاج كل profile من profiles Hermes إلى رقم/جلسة WhatsApp خاصة به. لا يمكنك ربط عدة profiles بمحادثات مختلفة على نفس رقم WhatsApp — إذ يستخدم جسر WhatsApp (Baileys) جلسة مصادَق عليها واحدة لكل رقم.

الحلول البديلة:

  1. استخدم profile واحد مع تبديل الشخصية. أنشئ ملفات سياق AGENTS.md مختلفة أو استخدم أمر /personality لتغيير السلوك حسب المحادثة. يرى الوكيل في أي محادثة هو ويمكنه التكيّف.

  2. استخدم مهام cron للمهام المتخصصة. بالنسبة لمتتبّع قائمة تسوق، أنشئ مهمة cron تراقب محادثة محددة وتدير القائمة — بلا حاجة لوكيل منفصل.

  3. استخدم أرقامًا منفصلة. إذا احتجت وكلاء مستقلين حقًا، اربط كل profile برقم WhatsApp خاص به. تعمل الأرقام الافتراضية من خدمات مثل Google Voice لهذا الغرض.

  4. استخدم Telegram أو Discord بدلًا من ذلك. تدعم هاتان المنصتان الربط حسب المحادثة بشكل أكثر طبيعية — تحصل كل مجموعة Telegram أو قناة Discord على جلستها الخاصة، ويمكنك تشغيل عدة رموز بوت (واحد لكل profile) على نفس الحساب.
