ملخّص الدور وتدفّق رموز مؤشر الانتظار (Spinner)

يطبع display.turn_summary (الافتراضي true) سطر محاسبة خافتًا واحدًا بعد كل دور في CLI التفاعلي، يلخّص ما فعله ذلك الدور فعليًا:

يُلاحَظ الحصر من تغذية تقدّم الأدوات التي تتلقّاها CLI بالفعل، لذا لا يكلّف شيئًا إضافيًا. تفاصيل:

  • وقت الجدار الزمني هو المدة الفعلية للدور (2m05s بعد نقطة الدقيقة الواحدة).
  • تُجمَّع استدعاءات الأدوات حسب الفعل (edited، read، ran، searched، …) بصيغة جمع صحيحة؛ وتُدمَج أدوات الإضافات/MCP التي لا فعل مُنسَّق لها في called N tools.
  • يظهر السطر +X -Y لفروقات الأسطر فقط عندما تُبلّغ نتيجة الأداة بالفعل عن فرق (حاليًا patch). لا يستدعي Hermes git أبدًا لحسابها، لذا يُحتسَب تعديل write_file دون فرق.
  • لا تُحتسَب استدعاءات الأدوات الفاشلة — كتابة مرفوضة لا تُعرَض أبدًا كتعديل ناجح (راجع مدقّق تعديل الملفات للتحذير المكمّل).
  • تُحدَّد الأدوار الطويلة بأربعة أجزاء فعل بالإضافة إلى ذيل +N more بحيث لا يلتفّ السطر أبدًا.
  • لا يطبع دور سريع بلا استدعاءات أدوات شيئًا على الإطلاق.

يُلحق display.spinner_token_flow (الافتراضي true) رموز الإخراج التراكمية للدور الجاري بمؤقت مؤشر الانتظار الحي في CLI:

العدّ لكل دور (تُحدَّد إجماليات الجلسة كخط أساس عند بداية الدور) ويتحدّث مع تبليغ كل استدعاء API في الدور عن الاستخدام. لا يُعرَض شيء قبل وصول أول تقرير استخدام، فلن ترى أبدًا ↓ 0 tok مضلّلًا.

كلا المفتاحين مخصّصان للعرض فقط ولـ CLI فقط: يُكبتان في الوضع الصامت، وعندما يكون display.tool_progress على off، وفي تشغيلات الاستعلام الواحد/الدفعية -Q، وفي أسطح gateway/المراسلة (تستخدم تلك display.runtime_footer بدلًا من ذلك). اضبط أيًا من المفتاحين على false لإيقافه.

مدقّق تعديل الملفات

عندما يكون display.file_mutation_verifier على true (الافتراضي)، يُلحق Hermes تنبيهًا من سطر واحد برد المساعد النهائي كلّما فشل استدعاء write_file أو patch أثناء الدور ولم يُستبدَل قط بكتابة ناجحة إلى المسار نفسه. يلتقط هذا صنف "دفعة تصحيحات متوازية، نصفها يفشل صامتًا، والنموذج يلخّص النجاح" دون أن يتطلّب منك تشغيل git status يدويًا بعد كل تعديل.

  • الكتابة مرفوضة — المسار على قائمة حظر بيانات الاعتماد أو خارج HERMES_WRITE_SAFE_ROOT (راجع أمان كتابة الملفات)

  • بوّابة الصياغة (Syntax) — فشل المحتوى المرشَّح في التحقّق من صحة JSON/YAML/TOML قبل الكتابة

لغة واجهة المستخدم للرسائل الثابتة

يترجم إعداد display.language مجموعة صغيرة من الرسائل الثابتة الموجّهة للمستخدم — مطالبة الموافقة في CLI، وبعض ردود أوامر gateway الشرطية (مثل إشعارات إيقاف إعادة التشغيل التدريجي، و"انتهت صلاحية الموافقة"، و"تم مسح الهدف"). وهو لا يترجم ردود الوكيل، أو سطور السجلّ، أو مُخرَجات الأدوات، أو تتبّعات الأخطاء (tracebacks)، أو أوصاف الأوامر الشرطية — تبقى هذه بالإنجليزية. إذا أردت أن يردّ الوكيل نفسه بلغة أخرى، فأخبره ببساطة في prompt أو رسالة النظام الخاصة بك.

القيم المدعومة: en (الافتراضي)، zh (الصينية المبسّطة)، zh-hant (الصينية التقليدية)، ja (اليابانية)، de (الألمانية)، es (الإسبانية)، fr (الفرنسية)، tr (التركية)، uk (الأوكرانية)، af (الأفريكانية)، ko (الكورية)، it (الإيطالية)، ga (الأيرلندية)، pt (البرتغالية)، ru (الروسية)، hu (المجرية). القيم غير المعروفة تعود إلى الإنجليزية.

يمكنك أيضًا ضبط هذا لكل جلسة عبر متغير البيئة HERMES_LANGUAGE، الذي يتجاوز قيمة الإعدادات.

الوضعما تراه
offصامت — الرد النهائي فقط
newمؤشر الأداة فقط عند تغيّر الأداة
allكل استدعاء أداة مع معاينة قصيرة (الافتراضي)
verboseالمعاملات والنتائج الكاملة وسجلّات التصحيح

في CLI، تنقّل بين هذه الأوضاع بـ /verbose. لاستخدام /verbose في منصات المراسلة (Telegram، Discord، Slack، إلخ)، اضبط tool_progress_command: true في قسم display أعلاه. سيدور الأمر عندها بين الأوضاع ويحفظ في الإعدادات.

يتطلّب تقدّم الأدوات مهايئ gateway قادرًا على عرض تحديثات التقدّم بأمان. المنصات التي لا تدعم تحرير الرسائل، بما فيها Signal، تكبت فقاعات تقدّم الأدوات حتى لو حفظ /verbose وضعًا غير off.

off يخفي زخرفة استدعاء الأدوات فقط. حالة التطبيق التي لها سطحها الخاص في تطبيق Desktop وTUI — قائمة المهام (todo_list)، وتقدّم الـ subagent، وأسئلة التوضيح، وبطاقات موافقة MCP — تستمر في التدفّق بغض النظر عن هذا الإعداد.

عرض التركيز (/focus، CLI + TUI)

يُفعّل display.focus_view: true عرض التركيز — وضع عرض مخفَّض المُخرَجات لوقت تريد فيه الإجابة، لا سرد الأحداث خطوة بخطوة. إنه طبقة رقيقة فوق آلية tool_progress نفسها بدلًا من مسار كبت ثانٍ:

  • تفعيله يُثبّت tool_progress على off ويخزّن وضعك السابق في display.focus_saved_tool_progress؛
  • يستعيد /focus off ذلك الوضع تمامًا، بحيث ينجو إعداد /verbose verbose من رحلة الذهاب والإياب؛
  • ينتهي كل دور مكتمل بسطر استرداد خافت — ⋯ 7 tool lines hidden · /focus off to show — يُحتسَب مقابل وضعك قبل التركيز، بحيث لا يدّعي أبدًا إخفاء أسطر كنت قد أوقفتها بالفعل؛
  • شارة ◉ focus دائمة تجلس في شريط الحالة (كلٌّ من CLI المبني على prompt_toolkit وInk TUI) بحيث لا يكون الوضع المخفَّض غير مرئي أبدًا؛
  • التنقّل عبر /verbose أثناء تفعيل التركيز يعيد الوضع إلى /verbose ويمسح الشارة.

عرض التركيز مخصّص للعرض فقط. فهو لا يعدّل أبدًا تاريخ المحادثة، أو system prompt، أو مخططات الأدوات، أو أي حمولة طلب؛ فالتفصيل المخفي مكبوت على الشاشة، لا محذوف أبدًا، والتخزين المؤقت للـ prompt غير متأثر تمامًا.

اختيار حقول شريط الحالة (CLI/TUI)

يعرض شريط الحالة التفاعلي أسفل CLI/TUI النموذج، واستخدام السياق، وعدد عمليات الضغط، وعدّادات النشاط الخلفي، والمؤقّتات، وشارات الوضع. يختار display.status_bar.fields أيًا منها يكون مرئيًا — مفيد لشريط أدنى (النموذج + المدة فقط) أو لإظهار إجمالي رموز الجلسة الاختياري:

الحقول المدعومة: model، و context_detail (الرموز المستخدَمة/الإجمالية)، و context_pct (النسبة المئوية + مقياس)، و cache_hit (نسبة إصابة التخزين المؤقت للـ prompt — تُعاد ضبطها عند تبديل النموذج والضغط)، و latency (متوسط زمن استجابة API المتحرّك، لآخر 10 استدعاءات)، و tps (متوسط رموز الإخراج/الثانية المتحرّك، لآخر 10 استدعاءات)، و compressions، و bg_tasks، و bg_processes، و bg_subagents، و goal، و git_branch (⎇ فرع git الحالي لدليل العمل — اختياري فقط، لا يُعرَض افتراضيًا أبدًا؛ يعرض HEAD المنفصل commit مختصرًا)، و duration، و prompt_elapsed، و idle_since، و focus، و yolo، و stash، و battery، و title (شارة الجلسة محاذاة لليمين)، و total_tokens (مجموع الجلسة Σ — اختياري فقط، لا يُعرَض افتراضيًا أبدًا).

ملاحظات:

  • القائمة الفارغة (الافتراضي) تُبقي المجموعة القياسية — كل شيء عدا total_tokens و git_branch.
  • تتحكّم الإعدادات في الظهور، لا الترتيب؛ تُعرَض الحقول في مواضعها المدمجة.
  • ما زالت الطرفيات الضيّقة تسقط الحقول الخاصة بالوضع العريض فقط (context_detail، cache_hit، latency، tps، prompt_elapsed، idle_since) بغض النظر عن الإعدادات (يظهر cache_hit أيضًا في الفئة المتوسطة ≥52 عمودًا).
  • يبقى latency/tps مخفيَّين حتى تُسجَّل استدعاءات API (مثلًا لا يُبلّغ backend خادم تطبيق Codex عن زمن استجابة).
  • يتوافق ظهور battery و title هنا مع مفاتيح التبديل الخاصة بهما (/battery، /title) — يجب تفعيل كليهما ليظهر القطاع.
  • يُصفّي المفتاح نفسه أيضًا قاعدة حالة Ink TUI (hermes tui)، حيث تُعرَض cache_hit و latency و tps كأجزاء ذيلية مُخصَّصة بالعرض (◎ / ◷ / ↑) على الطرفيات ذات ≥96/104/110 عمودًا على التوالي.
  • مخصّص للعرض فقط: لا أثر على التخزين المؤقت للـ prompt أو حمولات الطلبات. تسري التغييرات عند بدء الجلسة التالية.

تذييل بيانات التشغيل الوصفية (gateway فقط)

عندما يكون display.runtime_footer.enabled: true، يُلحق Hermes تذييل سياق تشغيل صغيرًا بالرسالة الأخيرة من كل دور gateway. يمكن أن يعرض التذييل الحالي النموذج، ونسبة نافذة السياق المئوية، ودليل العمل الحالي. معطّل افتراضيًا؛ فعّله لكل gateway إن أراد فريقك أن يتضمّن كل ردّ هذا الإسناد.

الحقول المدعومة:

تجاوزات التقدّم لكل منصة

لدى منصات مختلفة احتياجات إسهاب مختلفة. استخدم display.platforms لضبط أوضاع لكل منصة:

من CLI، استخدم المسار الأصلي — hermes config set display.platforms.telegram.streaming false. يُقبل الاختصار hermes config set platforms.telegram.streaming false أيضًا: لأن إعدادات العرض الخاصة بكل منصة (streaming، show_reasoning، tool_progress، …) لا تُقرأ إلا من display.platforms، تُعيد config set/get/unset توجيه ذلك الاختصار إلى المفتاح الأصلي وتطبع ملاحظة. مفاتيح الاتصال ضمن الكتلة العلوية platforms.<name> (token، enabled، reply_to_mode، extra) لا يُعاد توجيهها.

المنصات التي لا تحمل تجاوزًا تعود إلى قيمة tool_progress العامة. مفاتيح المنصات الصالحة: telegram، discord، slack، signal، whatsapp، matrix، mattermost، email، sms، homeassistant، dingtalk، feishu، wecom، weixin، bluebubbles، qqbot. لا يزال مفتاح display.tool_progress_overrides القديم يُحمَّل للتوافق مع الإصدارات السابقة لكنه متقادم ويُرحَّل إلى display.platforms عند أول تحميل.

Signal مُدرَجة كمفتاح منصة صالح لأن الإعداد يمكن أن يُحفَظ لكل منصة، لكن مهايئ Signal الحالي لا يستطيع تحرير الرسائل المُرسَلة ولا يعرض فقاعات تقدّم الأدوات. أبقِ tool_progress لـ Signal مضبوطًا على off؛ استخدم CLI أو منصة مراسلة قادرة على التحرير إذا أردت مشاهدة كل استدعاء أداة مباشرة.

interim_assistant_messages خاص بـ gateway فقط. عند تفعيله، يرسل Hermes تحديثات المساعد المكتملة في منتصف الدور كرسائل دردشة منفصلة. هذا مستقل عن tool_progress ولا يتطلّب تدفّق gateway.

يتحكّم show_commentary (الافتراضي true) في قناة التعليق الخاصة بنماذج Codex Responses — السرد المصقول للتقدّم الذي تنتجه هذه النماذج إلى جانب استدلالها الخاص. عند التفعيل، تُسلَّم كل رسالة تعليق مكتملة كتحديث مرحلي مرئي (على gateway يتطلّب هذا أيضًا interim_assistant_messages). اضبطه على false إذا كان السرد الإضافي يزعجك: يعود التعليق حينها إلى قناة الاستدلال ولا يُعرَض إلا عند تفعيل show_reasoning.

الخصوصية

عندما يكون redact_pii على true، يُخفي gateway المعلومات الشخصية القابلة للتعريف من system prompt قبل إرسالها إلى LLM على المنصات المدعومة:

الحقلالمعالجة
أرقام الهاتف (معرّف المستخدم على WhatsApp/Signal)تُجزَّأ (hash) إلى user_<12-char-sha256>
معرّفات المستخدمينتُجزَّأ إلى user_<12-char-sha256>
معرّفات المحادثاتيُجزَّأ الجزء الرقمي، مع الحفاظ على بادئة المنصة (telegram:<hash>)
معرّفات القناة الرئيسية (Home)يُجزَّأ الجزء الرقمي
أسماء/أسماء مستخدمي المستخدمينغير متأثرة (يختارها المستخدم، ومرئية علنًا)

دعم المنصات: ينطبق الإخفاء على WhatsApp وSignal وTelegram. يُستثنى Discord وSlack لأن أنظمة الإشارة (mentions) لديهما (<@user_id>) تتطلّب المعرّف الحقيقي في سياق LLM.

التجزئات (hashes) حتمية — يُطابَق المستخدم نفسه دائمًا إلى التجزئة نفسها، بحيث يستطيع النموذج تمييز المستخدمين في المحادثات الجماعية. يستخدم التوجيه والتسليم القيم الأصلية داخليًا.

هوية طلب OpenAI Codex

تطلب OpenAI من أطر Codex الخارجية (Third-party harnesses) أن تُعرِّف نفسها. ترسل الطلبات المصادَق عليها عبر ChatGPT إلى نقطة Codex الطرفية الرسمية تلقائيًا originator: hermes-agent و User-Agent: HermesAgent/<version>. تُحفَظ ترويسة حساب ChatGPT الحالية كما هي. لا يُرسَل أي محتوى prompt إضافي أو طلب قياس عن بُعد (telemetry). تظل طلبات OpenAI API المباشرة والنقاط الطرفية الوسيطة المخصّصة دون تغيير.

تحويل الكلام إلى نص (STT)

حل اللغة واحد بالنسبة لـكل مزوّد STT (local، وgroq، وopenai، وmistral، وxai، وelevenlabs، وdeepinfra، ومزوّدي الأوامر، والإضافات): stt.<provider>.language ← stt.language ← متغير البيئة HERMES_LOCAL_STT_LANGUAGE ← الاكتشاف التلقائي للمزوّد. الافتراضي هو stt.language: "en" — إذ يخطئ الاكتشاف التلقائي لـ Whisper كثيرًا في تحديد المقاطع القصيرة أو ذات اللكنة، ما يظهر كملاحظات صوتية تُنسَخ بلغة خاطئة. ينبغي على المتحدثين بغير الإنجليزية ضبط stt.language إلى رمز لغتهم مرة واحدة (مثل "es"، "zh"، "uk")؛ اضبطه على "" لاستعادة الاكتشاف التلقائي للاستخدام متعدّد اللغات.

اضبط stt.echo_transcripts: false عندما يحتاج gateway إلى نسخ الملاحظات الصوتية للوكيل لكن يجب ألا ينشر النسخ الخام مرة أخرى في المحادثة (على سبيل المثال، بوتات WhatsApp الموجَّهة للعملاء).

سلوك المزوّد:

  • يستخدم local برنامج faster-whisper العامل على جهازك. ثبّته بشكل منفصل عبر pip install faster-whisper. تصليب هلوسة الصمت مُفعّل افتراضيًا: يمنع مرشّح Silero VAD الصمت/الضجيج من الوصول إلى Whisper إطلاقًا، ويُعطَّل الاشتراط عبر النوافذ (cross-window conditioning)، وتُسقَط المقاطع التي يُصنّفها النموذج نفسه بأنها على الأرجح ليست كلامًا ومنخفضة الثقة معًا. اضبط stt.local.vad: false لنسخ صوت غير كلامي (موسيقى، محيطي) بالسلوك الخام. يبقى النموذج مُحمَّلًا في الذاكرة بين الرسائل الصوتية لنسخ منخفض زمن الاستجابة؛ اضبط stt.local.unload_after_idle_seconds (مثل 300 لخمس دقائق) لتحرير النموذج تلقائيًا عند الخمول. يحرّر هذا ذاكرة GPU على مضيفات CUDA (الفائدة الرئيسية عندما يشارك نموذج محلي وحدة معالجة الرسومات)؛ وعلى المعالج (CPU) تصبح الذاكرة قابلة لإعادة الاستخدام من قِبل العملية، رغم أن البصمة المرئية لنظام التشغيل قد لا تنكمش حتى تحتاج العملية إلى المساحة لشيء آخر. تُعيد الرسالة الصوتية التالية تحميل النموذج بشفافية.
  • يستخدم groq نقطة Groq الطرفية المتوافقة مع Whisper ويقرأ GROQ_API_KEY. مرّر stt.groq.language (أو متغير البيئة العام HERMES_LOCAL_STT_LANGUAGE) لتخطّي الاكتشاف التلقائي وتقليل زمن الاستجابة.
  • يستخدم openai واجهة OpenAI للكلام ويقرأ VOICE_TOOLS_OPENAI_KEY.

يحصل مزوّدو السحابة (groq، وopenai، وmistral، وxai، وelevenlabs، وdeepinfra) على اقتصاص صمت قبل الرفع افتراضيًا عند تثبيت ffmpeg: تُطوى فترات الصمت الطويلة في ملاحظة صوتية على جانب العميل قبل رفع الملف، مع الاحتفاظ بـ cloud_trim_keep_ms من كل فترة توقّف بحيث ينجو الإيقاع الطبيعي. يعني الصوت الأقصر رفعًا أسرع، وفوترة أقل لكل دقيقة صوت، وهلوسات صمت أقل من النموذج البعيد. تتخطّى المقاطع الأقصر من 12 ثانية الاقتصاص تمامًا (لا يمكن أن تُحدث التوفيرات فرقًا هناك، ويفرض عدة مزوّدين حدًّا أدنى للفوترة لكل طلب على أي حال). الاقتصاص بأفضل جهد — إذا كان ffmpeg مفقودًا، أو فشل الاقتصاص، أو كان المقطع في معظمه صمتًا، أو كان الاقتصاص سيوفّر أقل من نحو 10%، يُرفَع الملف الأصلي دون تغيير. اضبط stt.cloud_trim_silence: false لرفع الأصل دائمًا (مثلًا عند نسخ موسيقى أو صوت محيطي عبر مزوّد سحابي). لا تحصل مزوّدو نوع الأوامر (command) والإضافات على صوت مُقتصَّص أبدًا.

يُحترَم stt.provider المختار صراحةً بصرامة — إذا كان غير متاح، يفشل النسخ برسالة توجيهية لتشغيل hermes tools بدلًا من تبديل المزوّدين. لا يكتشف Hermes تلقائيًا إلا عندما لم يُختَر أي مزوّد قط، وبهذا الترتيب: local ← groq ← openai.

تجاوزات نموذج Groq وOpenAI مُدفوعة بمتغيرات البيئة:

prompt النسخ (تلميحات مفردات)

stt.prompt تلميح ثابت اختياري يُمرَّر إلى خلفيات STT القادرة على استقبال prompt. استخدمه لأسماء الأعلام، وأسماء المنتجات، والمصطلحات التخصّصية التي تخطئ فيها نماذج عائلة Whisper سماعًا في العادة:

التركيب. قيمة الإعدادات هي الأساس. الإضافات التي تُسجّل hook الـ pre_transcription تُعدّل فوقه، مع أسبقية آخر كاتب لكل حقل. تتألف تلميحات إضافات متعدّدة بشكل حتمي: يُحمّل اكتشاف الإضافات الإضافات بترتيب مُرتَّب حسب معرّف الإضافة، وتعمل استدعاءات كل إضافة بترتيب تسجيلها الخاص، بحيث تُنتج المجموعة نفسها من الإضافات دائمًا prompt نهائيًا واحدًا. يمسح hook يُعيد سلسلة فارغة لـ prompt prompt الإعدادات لذلك الطلب. يمكن للـ hooks أيضًا تجاوز language و model؛ أما file_path فللقراءة فقط وأي محاولة لتغييره تُسجَّل وتُسقَط. مع عدم وجود hook مُسجَّل وعدم ضبط stt.prompt، يكون الطلب الصادر مطابقًا للإصدارات السابقة.

الطول. لا تشترط نماذج عائلة Whisper إلا بآخر نحو 224 رمز prompt. بالنسبة لخلفيات عائلة whisper (local، openai، groq، deepinfra) يفرض Hermes هذا السقف على جانب العميل: يُقتَطع prompt نهائي مفرط الطول إلى ذيله مع تحذير مُسجَّل — لا يُخفق الطلب أبدًا بسبب طول الـ prompt. أما الخلفيات الأخرى (mistral، مزوّدو الإضافات) فتتلقّى الـ prompt دون تغيير وتملك تحقّقها الخاص. أبقِ التلميحات قصيرة ومحدَّدة في كلتا الحالتين.

تُرفَع الـ prompts مع صوتك

تُرسَل الـ prompt النهائية إلى مزوّد STT المُعدّ إلى جانب ملف الصوت. أبقِ الأسرار والسياق المشتقّ من الجلسة خارج stt.prompt وخارج أي شيء يُعيده hook الـ pre_transcription، خصوصًا عندما يكون المزوّد واجهة API مستضافة لا faster-whisper المحلية.

الوضع الصوتي (CLI)

استخدم /voice on في CLI لتفعيل وضع الميكروفون، و record_key لبدء/إيقاف التسجيل، و /voice tts لتبديل الردود المنطوقة. راجع الوضع الصوتي (Voice Mode) للإعداد الشامل والسلوك الخاص بكل منصة.
