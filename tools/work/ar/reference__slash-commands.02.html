الأوامر السريعة (Quick Commands)

الأوامر السريعة التي يعرّفها المستخدم تربط slash command قصيرًا بأمر shell أو بأمر slash آخر. أعدّها في ~/.hermes/config.yaml:

ثم اكتب /status أو /deploy أو /inbox في CLI أو منصة مراسلة. تُحلّ الأوامر السريعة وقت التنفيذ وقد لا تظهر في كل جدول إكمال تلقائي/مساعدة مدمج.

اختصارات الـ prompt النصية فقط غير مدعومة كأوامر سريعة. ضع الـ prompts الطويلة القابلة لإعادة الاستخدام في مهارة، أو استخدم type: alias للإشارة إلى slash command موجود.

تحليل الأسماء المستعارة (Alias Resolution)

تدعم الأوامر المطابقة بالبادئة (prefix matching): كتابة /h تُحلّ إلى /help، و/mod تُحلّ إلى /model. عندما تكون البادئة غامضة (تطابق عدة أوامر)، تفوز أول مطابقة بترتيب السجلّ. أسماء الأوامر الكاملة والأسماء المستعارة المسجَّلة لها دائمًا الأولوية على مطابقات البادئة.

Slash commands في المراسلة

أوامر خيوط Slack (بادئة !): يمنع Slack نفسه slash commands الأصلية داخل خيوط الرسائل ("/queue is not supported in threads. Sorry!") ولا يوصلها أبدًا إلى Hermes. داخل خيط Slack، استخدم بادئة ! بدلًا منها — !stop، !new، !status — ويوجّهها الـ gateway تمامًا كما لو كانت بصيغة slash. تعمل @Hermes !stop و@Hermes /stop في الخيوط أيضًا. تُفحص الكلمة الأولى فقط مقابل قائمة الأوامر المعروفة، لذا رسائل مثل !nice work تمرّ إلى الوكيل دون تغيير. راجع استخدام الأوامر داخل الخيوط للتفاصيل.

/reload-mcp (الاسم البديل: /reload_mcp)أعد تحميل خوادم MCP من الإعدادات وأعد فحص توفّر الأدوات.
/verboseتنقّل بين أوضاع عرض تقدّم الأدوات. معطّل افتراضيًا في المراسلة — فعّله بضبط display.tool_progress_command: true في config.yaml.
/yoloبدّل وضع YOLO — تخطَّ كل موافقات الأوامر الخطرة.
/commands [page]تصفّح كل الأوامر والمهارات (مقسّمة إلى صفحات).
/approve [session|always]وافق على أمر خطر معلّق ونفّذه. session يوافق لهذه الجلسة فقط؛ وalways يضيفه إلى القائمة الدائمة المسموحة.
/denyارفض أمرًا خطرًا معلّقًا.
/updateحدّث Hermes Agent إلى أحدث إصدار.
/restartأعد تشغيل الـ gateway بسلاسة بعد استنفاد عمليات التشغيل النشطة. عند عودة الـ gateway إلى الاتصال، يرسل تأكيدًا إلى محادثة/خيط الطالب.
/debugارفع تقرير تصحيح (معلومات النظام + السجلّات) واحصل على روابط قابلة للمشاركة.
/helpاعرض مساعدة المراسلة.
/<skill-name>استدعِ أي مهارة مُثبَّتة باسمها.

تأكيدات الأوامر المدمّرة

يطلب CLI تأكيدًا قبل تنفيذ slash commands التي تُلقي بحالة الجلسة غير المحفوظة. المجموعة المدمّرة الحالية هي:

الأمرما يدمّره
/clearيمسح الشاشة ويبدأ جلسة جديدة — معرّف الجلسة الحالية والسجلّ الموجود في الذاكرة يختفيان.
/new / /resetيبدأ جلسة جديدة (معرّف جلسة وسجلّ فارغ جديدان).
/undoيحذف آخر تبادل بين المستخدم والوكيل من السجلّ.
/exit --delete / /quit --deleteيخرج ويحذف نهائيًا سجلّ SQLite للجلسة الحالية والمحادثات المخزَّنة على القرص.

لكل واحد من هذه الأوامر يفتح CLI نافذة بثلاثة خيارات: Approve Once (تابع لهذه المرة)، وAlways Approve (تابع واحفظ approvals.destructive_slash_confirm: false بحيث تعمل الأوامر المدمّرة القادمة دون سؤال)، أو Cancel.

تخطٍّ مضمَّن: أضف now أو --yes أو -y لتجاوز النافذة لاستدعاء واحد — مثل /reset now، و/new --yes my-session، و/clear -y، و/undo -y. مفيد عندما لا تُعرض النافذة بشكل صحيح على طرفيتك (راجع issue #30768 بخصوص PowerShell الأصلي على Windows) أو عند برمجة سكربتات تتفاعل مع CLI.

اضبط approvals.destructive_slash_confirm: false في ~/.hermes/config.yaml لتعطيل التأكيدات عالميًا؛ وأعده إلى true لإعادة التفعيل. راجع الأمان — تأكيد slash command المدمّرة للسياق.
