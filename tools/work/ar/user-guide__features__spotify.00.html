Spotify

يستطيع Hermes التحكم في Spotify مباشرةً — التشغيل، وقائمة الانتظار، والبحث، وقوائم التشغيل، والمقاطع/الألبومات المحفوظة، وسجل الاستماع — باستخدام Web API الرسمية من Spotify مع PKCE OAuth. تُخزَّن الـ tokens في ~/.hermes/auth.json وتُجدَّد تلقائيًا عند تلقي الخطأ 401؛ لذا لا تحتاج إلى تسجيل الدخول إلا مرة واحدة لكل جهاز (تنتهي صلاحية refresh tokens بعد نحو 6 أشهر؛ وعندها أعد تشغيل hermes auth spotify).

على خلاف تكاملات OAuth المدمجة في Hermes (Google و GitHub Copilot و Codex)، يتطلب Spotify من كل مستخدم تسجيل تطبيق مطوّر خفيف خاص به، إذ لا يسمح Spotify للأطراف الثالثة بنشر تطبيق OAuth عام يمكن لأي شخص استخدامه. تستغرق العملية نحو دقيقتين، ويرشدك hermes auth spotify خلالها خطوة بخطوة.

المتطلبات المسبقة

  • حساب Spotify. يكفي الحساب المجاني (Free) لأدوات البحث وقوائم التشغيل والمكتبة والنشاط. أما Premium فمطلوب للتحكم في التشغيل (التشغيل، والإيقاف المؤقت، والتخطي، والانتقال إلى موضع، ومستوى الصوت، والإضافة إلى قائمة الانتظار، ونقل التشغيل).
  • تثبيت Hermes Agent وتشغيله.
  • لأدوات التشغيل: جهاز Spotify Connect نشط — يجب أن يكون تطبيق Spotify مفتوحًا على جهاز واحد على الأقل (هاتف، أو سطح مكتب، أو مشغّل ويب، أو مكبّر صوت) كي تجد Web API ما تتحكم فيه. إذا لم يكن هناك جهاز نشط، فستتلقى 403 Forbidden مع رسالة "no active device"؛ افتح Spotify على أي جهاز وأعد المحاولة.

الإعداد

دفعة واحدة: hermes tools أو إعداد التشغيل الأول

هذا أسرع مسار. شغّل:

مرّر إلى 🎵 Spotify، واضغط مفتاح المسافة لتفعيله، ثم s للحفظ. يتوفر مفتاح التبديل نفسه أيضًا أثناء تدفق التشغيل الأول hermes setup / hermes setup tools. يبقى Spotify اختياريًا يتطلب التفعيل، لذا فإن تفعيله هناك يشغّل إعدادات المزوّد نفسها التي يشغّلها hermes tools.

ينقلك Hermes مباشرةً إلى تدفق OAuth — وإذا لم يكن لديك تطبيق Spotify بعد، يرشدك إلى إنشائه في المكان نفسه. وبمجرد الانتهاء، يكون الـ toolset مفعّلًا ومصادَقًا عليه في خطوة واحدة.

إذا كنت تفضّل تنفيذ الخطوات بشكل منفصل (أو كنت تعيد المصادقة لاحقًا)، فاستخدم التدفق ذا الخطوتين أدناه.

التدفق ذو الخطوتين

1. فعّل الـ toolset

فعّل 🎵 Spotify، واحفظ، وعندما يُفتح المعالج المضمّن، أغلقه (Ctrl+C). يبقى الـ toolset مفعّلًا؛ ولا يُؤجَّل إلا خطوة المصادقة.

2. شغّل معالج تسجيل الدخول

لا تظهر أدوات Spotify السبع في toolset الوكيل إلا بعد الخطوة 1 — فهي معطّلة افتراضيًا كي لا يُرسل المستخدمون الذين لا يريدونها مخططات أدوات إضافية مع كل استدعاء API.

إذا لم يكن HERMES_SPOTIFY_CLIENT_ID مضبوطًا، يرشدك Hermes إلى تسجيل التطبيق مباشرةً:

  1. يفتح https://developer.spotify.com/dashboard في متصفحك
  2. يطبع القيم الدقيقة التي عليك لصقها في نموذج "Create app" لدى Spotify
  3. يطلب منك إدخال Client ID الذي تحصل عليه
  4. يحفظه في ~/.hermes/.env كي تتخطى عمليات التشغيل اللاحقة هذه الخطوة
  5. ينتقل مباشرةً إلى تدفق الموافقة في OAuth

بعد موافقتك، تُكتب الـ tokens ضمن providers.spotify في ~/.hermes/auth.json. لا يتغير مزوّد inference النشط — فمصادقة Spotify مستقلة عن مزوّد LLM لديك.

التشغيل عبر SSH / في بيئة بلا واجهة (headless)

إذا كان SSH_CLIENT أو SSH_TTY مضبوطًا، يتخطى Hermes فتح المتصفح تلقائيًا في كل من المعالج وخطوة OAuth. انسخ عنوان URL للوحة التحكم وعنوان URL للتفويض اللذين يطبعهما Hermes، وافتحهما في متصفح على جهازك المحلي، وتابع كالمعتاد — إذ يظل مستمع HTTP المحلي يعمل على المضيف البعيد على المنفذ 43827. ولا يستطيع متصفح حاسوبك المحمول الوصول إلى الـ loopback البعيد دون تمرير محلي (local-forward) عبر SSH:

لإعدادات jump-box / bastion وغيرها من المزالق (mosh و tmux وتعارض المنافذ)، راجع OAuth عبر SSH / الأجهزة البعيدة.

التحقق

يعرض ما إذا كانت الـ tokens موجودة وموعد انتهاء صلاحية access token. التجديد تلقائي: فعندما يعيد أي استدعاء لـ Spotify API الخطأ 401، يستبدل العميل refresh token ويعيد المحاولة مرة واحدة. تبقى refresh tokens محفوظة عبر عمليات إعادة تشغيل Hermes، لذا لا تحتاج إلى إعادة المصادقة إلا إذا ألغيت صلاحية التطبيق في إعدادات حساب Spotify أو شغّلت hermes auth logout spotify.

الجدولة: Spotify + cron

بما أن أدوات Spotify أدوات Hermes عادية، يمكن لمهمة cron تعمل في جلسة Hermes تشغيل الموسيقى وفق أي جدول زمني، دون الحاجة إلى كتابة كود جديد.

قائمة تشغيل للاستيقاظ صباحًا

ما يحدث في الساعة 7 صباحًا كل يوم عمل:

  1. يُطلق Cron جلسة Hermes بلا واجهة.
  2. يقرأ الوكيل الـ prompt، ويستدعي spotify_devices list للعثور على "kitchen speaker" بالاسم، ثم spotify_devices transfer → spotify_playback set_volume → spotify_playback set_shuffle → spotify_search + spotify_playback play.
  3. تبدأ الموسيقى على المكبّر المستهدف. التكلفة الإجمالية: جلسة واحدة، وبضعة استدعاءات أدوات، دون أي تدخل بشري.

الاسترخاء ليلًا

مزالق

  • يجب وجود جهاز نشط عند انطلاق مهمة cron. إذا لم يكن هناك عميل Spotify قيد التشغيل (هاتف/سطح مكتب/مكبّر Connect)، تعيد إجراءات التشغيل 403 no active device. بالنسبة إلى قوائم التشغيل الصباحية، الحيلة هي استهداف جهاز يعمل دائمًا (Sonos أو Echo أو مكبّر ذكي) بدلًا من هاتفك.
  • يلزم Premium لأي شيء يغيّر التشغيل — التشغيل، والإيقاف المؤقت، والتخطي، ومستوى الصوت، ونقل التشغيل. أما مهام cron للقراءة فقط (مثل مهمة مجدولة "أرسل لي بالبريد المقاطع التي شغّلتها مؤخرًا") فتعمل بلا مشكلات مع Free.
  • يرث وكيل cron الـ toolsets النشطة لديك. يجب تفعيل Spotify في hermes tools كي ترى جلسة cron أدوات Spotify.
  • تعمل مهام cron مع skip_memory=True كي لا تكتب في مخزن الذاكرة لديك.

المرجع الكامل لـ cron: مهام Cron.

تسجيل الخروج

يزيل الـ tokens من ~/.hermes/auth.json. ولمسح إعدادات التطبيق أيضًا، احذف HERMES_SPOTIFY_CLIENT_ID (و HERMES_SPOTIFY_REDIRECT_URI إن كنت قد ضبطته) من ~/.hermes/.env، أو شغّل المعالج مجددًا.

لإلغاء صلاحية التطبيق من جانب Spotify، زر صفحة التطبيقات المرتبطة بحسابك وانقر على REMOVE ACCESS.

استكشاف الأخطاء وإصلاحها

403 Forbidden — Player command failed: No active device found — تحتاج إلى أن يكون Spotify قيد التشغيل على جهاز واحد على الأقل. افتح تطبيق Spotify على هاتفك أو سطح المكتب أو مشغّل الويب، وشغّل أي مقطع لثانية واحدة لتسجيل الجهاز، ثم أعد المحاولة. يعرض spotify_devices list الأجهزة المرئية حاليًا.

403 Forbidden — Premium required — أنت تستخدم حسابًا مجانيًا (Free) وتحاول تنفيذ إجراء يغيّر التشغيل. راجع مصفوفة الميزات أعلاه.

204 No Content عند get_currently_playing — لا شيء قيد التشغيل حاليًا على أي جهاز. هذه استجابة Spotify العادية وليست خطأً؛ ويعرضها Hermes كنتيجة فارغة توضيحية (is_playing: false).

INVALID_CLIENT: Invalid redirect URI — لا يطابق redirect URI في إعدادات تطبيق Spotify لديك ما يستخدمه Hermes. القيمة الافتراضية هي http://127.0.0.1:43827/spotify/callback. إما أن تضيفها إلى قائمة redirect URIs المسموح بها في تطبيقك، أو أن تضبط HERMES_SPOTIFY_REDIRECT_URI في ~/.hermes/.env على القيمة التي سجّلتها.

429 Too Many Requests — حدّ المعدل (rate limit) لدى Spotify. يعيد Hermes رسالة خطأ واضحة؛ انتظر دقيقة وأعد المحاولة. إذا استمر ذلك، فالأرجح أنك تشغّل حلقة متقاربة في سكربت — إذ تُعاد تهيئة حصة Spotify كل 30 ثانية تقريبًا.

يتكرر ظهور 401 Unauthorized — أُلغيت صلاحية refresh token الخاص بك (عادةً لأنك أزلت التطبيق من حسابك، أو لأن التطبيق حُذف). شغّل hermes auth spotify مجددًا.

المعالج لا يفتح المتصفح — إذا كنت متصلًا عبر SSH أو تعمل داخل حاوية دون شاشة، يكتشف Hermes ذلك ويتخطى الفتح التلقائي. انسخ عنوان URL للوحة التحكم الذي يطبعه وافتحه يدويًا.
