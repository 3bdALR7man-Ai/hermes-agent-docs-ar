Outlines: التوليد المُقيَّد للنص

متى تستخدم هذه المهارة

استخدم Outlines عندما تحتاج إلى:

  • ضمان صحة بنية JSON/XML/الكود أثناء التوليد
  • استخدام نماذج Pydantic لمخرجات آمنة النوع (type-safe)
  • دعم النماذج المحلية (Transformers، llama.cpp، vLLM)
  • تعظيم سرعة الـ inference بتوليد مُقيَّد بلا أي تكلفة إضافية
  • التوليد وفق مخططات JSON تلقائيًا
  • التحكم في أخذ عينات token على مستوى القواعد النحوية (grammar)

نجوم GitHub: أكثر من 12,000 | من: dottxt.ai (المعروفة سابقًا باسم .txt)

ملاحظة حول الواجهة (Outlines 1.x): تستهدف هذه المهارة واجهة الإصدار v1 الحالية. المساعدات السابقة للإصدار 1.0 (outlines.models.transformers(...)، outlines.generate.json/choice/regex/...) قد أُزيلت. في الإصدار v1 تُنشئ النموذج باستخدام outlines.from_transformers(...) (أو from_vllm، from_llamacpp، from_openai) ثم تستدعي النموذج مباشرةً مع نوع مخرجات: model(prompt, output_type). تُعاد مخرجات JSON/Pydantic كـ سلسلة JSON نصية — تحقق منها باستخدام YourModel.model_validate_json(result).

المفاهيم الأساسية

1. أخذ عينات token مُقيَّد

يقيّد Outlines توليد الـ token على مستوى logit باستخدام آلة حالات (automaton) مُصرَّفة (compiled) من نوع مخرجاتك.

كيف يعمل:

  1. تحويل نوع المخرجات (JSON/Pydantic/regex/Literal) إلى مخطط (schema) أو قواعد نحوية (grammar)
  2. تصريف (compile) القواعد النحوية إلى آلة حالات على مستوى الـ token
  3. تصفية الـ tokens غير الصالحة في كل خطوة أثناء التوليد
  4. التقديم السريع (fast-forward) عندما يوجد token صالح واحد فقط

الفوائد:

  • بلا أي تكلفة إضافية: تجري التصفية على مستوى الـ token
  • تحسين السرعة: تقديم سريع عبر المسارات الحتمية
  • صلاحية مضمونة: يستحيل صدور مخرجات غير صالحة

متى تختار Outlines:

  • عند استخدام نماذج محلية (Transformers، llama.cpp، vLLM)
  • عند الحاجة إلى أقصى سرعة inference
  • عند الرغبة في دعم نماذج Pydantic
  • عند الحاجة إلى توليد مُقيَّد بلا أي تكلفة إضافية
  • عند الحاجة إلى التحكم في عملية أخذ عينات token

متى تختار بدائل أخرى:

  • Instructor: عند الحاجة إلى نماذج API مع إعادة محاولة تلقائية
  • Guidance: عند الحاجة إلى token healing وسير عمل معقّد
  • LMQL: عند تفضيل صياغة استعلام تصريحية (declarative)

خصائص الأداء

السرعة:

  • بلا أي تكلفة إضافية: التوليد المُقيَّد بسرعة التوليد غير المُقيَّد نفسها
  • تحسين التقديم السريع (Fast-forward): يتخطى الـ tokens الحتمية
  • أسرع بمقدار 1.2 إلى 2 مرة من أساليب التحقق بعد التوليد

الذاكرة:

  • تُصرَّف آلة الحالات مرة واحدة لكل نوع مخرجات (وتُخزَّن مؤقتًا)
  • تكلفة إضافية طفيفة أثناء التشغيل
  • كفاءة عالية مع vLLM للإنتاجية المرتفعة

الدقة:

  • 100% مخرجات صالحة (مضمونة عبر آلة الحالات المُقيَّدة)
  • لا حاجة لحلقات إعادة المحاولة
  • تصفية حتمية للـ tokens
