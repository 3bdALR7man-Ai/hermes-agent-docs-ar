Codex CLI

فوّض مهام البرمجة إلى Codex عبر طرفية Hermes. Codex هو أداة سطر أوامر لوكيل برمجة مستقل تابع لـ OpenAI.

متى تُستخدم

  • بناء الميزات
  • إعادة الهيكلة (Refactoring)
  • مراجعات PR
  • إصلاح المشكلات (issues) بالجملة

تتطلّب أداة سطر الأوامر codex ومستودع git.

المتطلبات المسبقة

  • Codex مُثبَّت: npm install -g @openai/codex
  • مصادقة OpenAI مُهيَّأة: إما OPENAI_API_KEY أو بيانات اعتماد Codex OAuth من مسار تسجيل الدخول الخاص بـ Codex CLI
  • يجب التشغيل داخل مستودع git — يرفض Codex العمل خارجه
  • استخدم pty=true في استدعاءات الطرفية — Codex تطبيق طرفية تفاعلي

بالنسبة إلى Hermes نفسه، يستخدم model.provider: openai-codex بيانات اعتماد Codex OAuth المُدارة من Hermes من ~/.hermes/auth.json بعد تنفيذ hermes auth add openai-codex. أما بالنسبة إلى أداة Codex CLI المستقلة، فقد توجد جلسة CLI OAuth صالحة تحت ~/.codex/auth.json؛ لا تعتبر غياب OPENAI_API_KEY وحده دليلًا على غياب مصادقة Codex.

الخيارات الأساسية

الخيارالتأثير
exec "prompt"تنفيذ فوري، يخرج عند الانتهاء
--sandbox workspace-write (-s)محصور داخل sandbox لكنه يوافق تلقائيًا على تغييرات الملفات ضمن مساحة العمل (وضع البناء التلقائي المُوصى به)
--dangerously-bypass-approvals-and-sandboxبلا sandbox، بلا موافقات (الأسرع والأكثر خطورة؛ يظل --yolo يعمل كاسم مستعار مخفي)
--sandbox danger-full-accessبلا sandbox خاص بـ Codex؛ مفيد عندما يعطّل سياق خدمة المضيف أداة bubblewrap

مُهمل (deprecated): لا يزال --full-auto يعمل لكن الإصدار الحالي من الأداة يحذّر باستخدام --sandbox workspace-write بدلًا منه.

تنبيه بخصوص Hermes Gateway

عند استدعاء Codex CLI من سياق gateway/خدمة تابع لـ Hermes (مثلًا، جلسات الوكيل المُشغَّلة عبر Telegram)، قد تفشل حماية sandbox من نوع workspace-write الخاصة بـ Codex حتى عندما يعمل الأمر نفسه في shell التفاعلي للمستخدم. من الأعراض النموذجية أخطاء bubblewrap/مساحة أسماء المستخدم مثل setting up uid map: Permission denied أو loopback: Failed RTM_NEWADDR: Operation not permitted.

القواعد

  1. استخدم دائمًا pty=true — Codex تطبيق طرفية تفاعلي ويتجمّد بدون PTY
  2. مستودع git مطلوب — لن يعمل Codex خارج مجلد git. استخدم mktemp -d && git init للعمل التجريبي
  3. استخدم exec للمهام الفورية — يُشغّل codex exec "prompt" المهمة ويخرج بسلاسة
  4. --sandbox workspace-write للبناء — يوافق تلقائيًا على التغييرات ضمن sandbox (خيار --full-auto مُهمل لهذا الغرض)
  5. الخلفية للمهام الطويلة — استخدم background=true وراقب بأداة process
  6. لا تتدخّل — راقب باستخدام poll/log، وتحلَّ بالصبر مع المهام طويلة الأمد
  7. التوازي مقبول — شغّل عدة عمليات Codex في وقت واحد للعمل بالجملة
