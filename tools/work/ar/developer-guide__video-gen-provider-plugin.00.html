بناء إضافة مزوّد توليد الفيديو

تسجّل إضافات مزوّد توليد الفيديو (video-gen provider plugins) backend يخدم كل استدعاء لأداة video_generate. تُشحَن المزوّدات المدمجة (xAI وFAL وOpenRouter وDeepInfra) كإضافات. أضف مزوّدًا جديدًا، أو تجاوز واحدًا مضمّنًا، بوضع مجلد في plugins/video_gen/<name>/.

نصيحة

video-gen يعكس إضافات مزوّدي توليد الصور شبه سطر بسطر — إن كنت قد بنيت backend لتوليد الصور، فأنت تعرف الشكل بالفعل. الاختلافات الرئيسية: طريقة capabilities() التي تعلن الأنماط (modalities)/نسب العرض إلى الارتفاع/المُدد، واصطلاح توجيه (routing) — مرّر image_url لاستخدام تحويل الصورة إلى فيديو، أو احذفه لاستخدام تحويل النص إلى فيديو (يختار المزوّد الـ endpoint الصحيح داخليًا).

الواجهة الموحّدة (أداة واحدة، نمطان)

تعرض أداة video_generate نمطين عبر معامل واحد:

  • تحويل النص إلى فيديو — استدعِ الأداة بـprompt فقط. يوجّه المزوّد إلى endpoint تحويل النص إلى فيديو.
  • تحويل الصورة إلى فيديو — استدعِ الأداة بـprompt + image_url. يوجّه المزوّد إلى endpoint تحويل الصورة إلى فيديو.

عمليتا التعديل والتوسيع (edit وextend) خارج النطاق عمدًا. لا يدعمهما معظم الـ backends، وسيفرض عدم الاتساق نصًا خاصًا بكل backend داخل وصف أداة الوكيل.

كيف يعمل الاكتشاف

يفحص Hermes ثلاثة أماكن بحثًا عن backends لتوليد الفيديو:

  1. المضمّنة (Bundled) — <repo>/plugins/video_gen/<name>/ (تُحمَّل تلقائيًا بـkind: backend)
  2. مستخدم (User) — ~/.hermes/plugins/video_gen/<name>/ (بالاشتراك عبر plugins.enabled)
  3. Pip — حزم تعلن نقطة دخول hermes_agent.plugins

تستدعي دالة register(ctx) الخاصة بكل إضافة ctx.register_video_gen_provider(...). يُختار المزوّد النشط عبر video_gen.provider في config.yaml؛ ويرشد hermes tools ← Video Generation المستخدمين خلال الاختيار. وعلى خلاف image_generate، لا يوجد backend قديم (legacy) ضمن الشجرة — فكل مزوّد هو إضافة.

بنية المجلدات

فئة VideoGenProvider المجرّدة (ABC)

اشتقّ فئة فرعية من agent.video_gen_provider.VideoGenProvider. المطلوب: خاصية name وطريقة generate().

بيان الإضافة (manifest)

مخطط video_generate

تعرض الأداة مخططًا واحدًا عبر كل backend. تتجاهل المزوّدات المعاملات التي لا تدعمها.

المعاملما تفعله
promptتعليمة نصية (مطلوبة)
image_urlعند ضبطها ← تحويل الصورة إلى فيديو؛ عند حذفها ← تحويل النص إلى فيديو
reference_image_urlsمراجع النمط/الشخصية (حسب المزوّد)
durationثوانٍ — يحصرها المزوّد ضمن حدوده
aspect_ratio"16:9"، "9:16"، "1:1"، ... — يحصرها المزوّد ضمن حدوده
resolution"480p" / "540p" / "720p" / "1080p" — يحصرها المزوّد ضمن حدوده
negative_promptمحتوى يُتجنَّب (Pixverse/Kling فقط)
audioصوت أصلي (فئة تسعير Veo3 / Pixverse)
seedقابلية إعادة الإنتاج
modelتجاوز النموذج/العائلة النشطة

تعلن capabilities() الخاصة بالمزوّد أي من هذه المعاملات مدعوم. يرى الوكيل قدرات الـ backend النشط في وصف الأداة، ويُعاد بناؤها ديناميكيًا عندما يغيّر المستخدم الـ backend عبر hermes tools.

عائلات النماذج وتوجيه الـ endpoint (نمط FAL)

عندما يملك backend الخاص بك عدة endpoints لكل "نموذج" — كما في FAL، حيث تملك كل عائلة (Veo 3.1 وPixverse v6 وKling O3) رابط /text-to-video ورابط /image-to-video معًا — مثّل كل عائلة كإدخال واحد في الكتالوج. تختار دالة generate() الخاصة بك الـ endpoint الصحيح بناءً على ما إذا كان image_url قد مُرِّر:

يختار المستخدم veo3.1 مرة واحدة في hermes tools. لا يفكر الوكيل أبدًا في الـ endpoints — فهو فقط يمرّر (أو لا يمرّر) image_url.

أولوية الاختيار

بالنسبة لإعدادات النموذج الخاصة بكل نسخة (راجع plugins/video_gen/fal/__init__.py):

  1. الكلمة المفتاحية model= من استدعاء الأداة
  2. متغير البيئة <PROVIDER>_VIDEO_MODEL
  3. video_gen.<provider>.model في config.yaml
  4. video_gen.model في config.yaml (عندما يكون أحد معرّفاتك)
  5. default_model() الخاصة بالمزوّد

شكل الاستجابة

تنتج success_response() وerror_response() شكل القاموس (dict) الذي يعيده كل backend. استخدمهما — لا تبنِ القاموس يدويًا.

مفاتيح النجاح: success، video (رابط أو مسار مطلق)، model، prompt، modality ("text" أو "image")، aspect_ratio، duration، provider، إضافة إلى extra.

مفاتيح الخطأ: success، video (None)، error، error_type، model، prompt، aspect_ratio، provider.

أين تُحفظ المخرجات (artifacts)

إذا كان backend الخاص بك يعيد base64، استخدم save_b64_video() للكتابة تحت $HERMES_HOME/cache/videos/. أما للبايتات الخام من جلب HTTP لاحق، فاستخدم save_bytes_video(). وإلا، أعد الرابط الأصلي مباشرة — يحل gateway الروابط البعيدة عند التسليم.

الاختبار

ضع اختبار دخان (smoke test) تحت tests/plugins/video_gen/test_<name>_plugin.py. تُظهر اختبارات xAI وFAL النمط — سجّل، تحقّق من الكتالوج، مارس التوجيه مع image_url وبدونه، وتأكد من استجابات خطأ نظيفة عند غياب المصادقة.
