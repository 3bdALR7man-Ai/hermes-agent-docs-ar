صيغة Trajectory

يحفظ Hermes Agent مسارات المحادثة (trajectories) بصيغة JSONL متوافقة مع ShareGPT لاستخدامها كبيانات تدريب، ومُخرَجات لتصحيح الأخطاء، ومجموعات بيانات للتعلّم المعزَّز (reinforcement learning).

ملفات المصدر: agent/trajectory.py، و agent/session_persistence.py (ابحث عن _save_trajectory)، و batch_runner.py

قاعدة تسمية الملفات

تُكتب مسارات المحادثة (trajectories) إلى ملفات في مجلد العمل الحالي:

الملفمتى
trajectory_samples.jsonlالمحادثات التي اكتملت بنجاح (completed=True)
failed_trajectories.jsonlالمحادثات التي فشلت أو انقطعت (completed=False)

يكتب مُشغّل الدُفعات (batch runner) (batch_runner.py) إلى ملف مُخرَج مخصّص لكل دُفعة (مثال: batch_001_output.jsonl) مع حقول بيانات وصفية إضافية.

يمكنك تجاوز اسم الملف عبر المعامل filename في save_trajectory().

وسم محتوى الاستدلال (Reasoning)

يُطبّع محوّل مسار المحادثة (trajectory converter) كل الاستدلال (reasoning) إلى وسوم <think>، بصرف النظر عن الطريقة التي أنتج بها النموذج ذلك أصلًا:

  1. tokens الاستدلال الأصلية (native) (حقل msg["reasoning"] من مزوّدين مثل Anthropic، وسلسلة OpenAI o): تُغلَّف بالشكل <think>\n{reasoning}\n</think>\n وتُضاف قبل المحتوى.

  2. REASONING_SCRATCHPAD بصيغة XML (عندما يكون الاستدلال الأصلي مُعطَّلًا ويستدل النموذج عبر XML موجَّه من system prompt): تُحوَّل وسوم <REASONING_SCRATCHPAD> إلى <think> عبر convert_scratchpad_to_think().

  3. كتل think فارغة: كل دور من نوع gpt مضمون أن يحتوي على كتلة <think>. إن لم يُنتَج أي استدلال، تُدرَج كتلة فارغة: <think>\n</think>\n — وهذا يضمن صيغة متسقة لبيانات التدريب.

تطبيع استدعاء الأدوات

تُحوَّل استدعاءات الأدوات من صيغة API (التي تتضمّن tool_call_id، واسم الدالة، والمعاملات كسلسلة JSON) إلى JSON مُغلَّف بـ XML:

  • تُحلَّل المعاملات من سلاسل JSON إلى كائنات (دون ترميز مزدوج)
  • إذا فشل تحليل JSON (وهذا لا ينبغي أن يحدث — إذ يُتحقَّق منه أثناء المحادثة)، تُستخدم قيمة فارغة {} مع تسجيل تحذير
  • استدعاءات الأدوات المتعددة في دور واحد للمساعد تُنتج كتل <tool_call> متعددة في رسالة gpt واحدة

تطبيع استجابة الأدوات

تُجمَّع كل نتائج الأدوات التي تلي رسالة المساعد في دور tool واحد مع استجابات JSON مُغلَّفة بـ XML:

  • إذا بدا محتوى الأداة على شكل JSON (يبدأ بـ { أو [)، يُحلَّل بحيث يحتوي حقل المحتوى على كائن/مصفوفة JSON بدلًا من سلسلة نصية
  • تُدمَج نتائج الأدوات المتعددة بأسطر جديدة في رسالة واحدة
  • تُطابَق أسماء الأدوات حسب الموقع مقابل مصفوفة tool_calls الخاصة برسالة المساعد الأصلية

رسالة System

تُنشَأ رسالة System عند وقت الحفظ (وليست مأخوذة من المحادثة). وهي تتبع قالب prompt الخاص باستدعاء الدوال في Hermes، وتتضمّن:

  • مقدّمة تشرح بروتوكول استدعاء الدوال
  • كتلة XML من نوع <tools> تحتوي على تعريفات أدوات JSON
  • مرجع المخطط لكائنات FunctionCall
  • مثال <tool_call>

تتضمّن تعريفات الأدوات name و description و parameters و required (تُضبَط على null لمطابقة الصيغة القياسية).

التحكّم في حفظ مسار المحادثة (Trajectory)

حفظ مسار المحادثة (Trajectory) هو مفتاح تبديل على مستوى run_agent.py / المكتبة — لا تعرض واجهة CLI الخاصة بـ hermes مفتاح إعداد أو علامة (flag) لذلك:

أو برمجيًا: AIAgent(..., save_trajectories=True) / initialize_agent(..., save_trajectories=True). عند التفعيل، يُستدعى التابع _save_trajectory() في نهاية كل دور من أدوار المحادثة.

يحفظ مُشغّل الدُفعات (batch runner) مسارات المحادثة دائمًا (فهذا هو غرضه الأساسي).

العيّنات (samples) التي لا تحتوي على أي استدلال عبر كل الأدوار تُستبعَد تلقائيًا بواسطة مُشغّل الدُفعات لتجنّب تلويث بيانات التدريب بأمثلة بلا استدلال.
