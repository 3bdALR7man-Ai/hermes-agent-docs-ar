معلومة

ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

مهارة Stripe Link CLI

تُغلّف هذه المهارة @stripe/link-cli بحيث يستطيع Hermes إتمام عمليات الشراء نيابةً عن المستخدم باستخدام بطاقات افتراضية لمرة استخدام واحدة أو رموز دفع مشتركة (SPT). كل عملية إنفاق تخضع لموافقة داخل تطبيق Link على الجوال أو الويب — لا يستطيع Hermes الموافقة على نفسه.

مقتصرة حاليًا على الولايات المتحدة (متطلب حساب Link). لا يدعم Windows الأداة المصدر — لذا هذه المهارة مقيَّدة بـ [linux, macos].

متى تُستخدم

عبارات التفعيل:

  • "اشترِ X"، "ادفع مقابل X"، "نفّذ عملية شراء"، "أكمل الدفع"
  • "أحضر لي بطاقة"، "أحتاج طريقة دفع"
  • "سجّل الدخول إلى Link"، "اربط محفظة Link الخاصة بي"
  • استجابة HTTP 402 من واجهة برمجية تابعة لتاجر مع www-authenticate: ... method="stripe"

إذا أراد المستخدم استدعاء واجهة برمجية مدفوعة (HTTP 402، بلا نموذج دفع)، فمسار card غير مناسب — استخدم SPT عبر هذه المهارة نفسها، أو انقل المهمة إلى مهارة mpp-agent.

المتطلبات الأساسية

  • Node.js 20+ متاح ضمن PATH (node --version)
  • مقيم في الولايات المتحدة (متطلب حساب Link)

لا يلزم إعداد حساب Link وطريقة الدفع وتطبيق موافقة الإنفاق قبل أن يحاول Hermes الدفع — فأداة سطر الأوامر ترشد المستخدم خلالها عند أول تشغيل:

  • حساب Link على https://app.link.com — يُنشأ/يُربط أثناء أول مصادقة لـ link-cli
  • طريقة دفع واحدة على الأقل — تُضاف أثناء أول تشغيل على https://app.link.com/wallet
  • تطبيق Link على الجوال أو الويب — يُفتح للموافقة على أول طلب إنفاق عند إجرائه

لا حاجة إلى متغيرات بيئة — تخزّن أداة سطر الأوامر حالة المصادقة محليًا ضمن دليل إعداداتها الخاص.

كيفية التشغيل

تُنفَّذ كل الأوامر عبر أداة terminal. تكتشف أداة سطر الأوامر تلقائيًا الاستدعاءات غير التفاعلية (non-TTY) وتصدر مخرجات toon مضغوطة افتراضيًا — وهذا مناسب للنموذج. مرّر --format json إذا احتاجت خطوة إلى حقول منظَّمة.

لاكتشاف الأوامر: link-cli --llms-full. للحصول على مخطط أمر قبل استدعائه: link-cli <command> --schema.

الإجراء

1. التحقق من المصادقة أو إنشاؤها

إذا لم تكن هناك مصادقة، سجّل الدخول باسم عميل واضح (يظهر هذا الاسم في تطبيق Link الخاص بالمستخدم):

تستقصي صيغة --interval/--timeout بشكل مضمَّن بحيث لا يحتاج الوكيل إلى إدارة خطوة _next. اطبع رابط التحقق والعبارة للمستخدم وانتظر عودة أداة سطر الأوامر.

لا تتابع بعد هذه الخطوة إلا بعد أن يؤكد auth status تسجيل الدخول.

2. تقييم التاجر قبل إنشاء طلب إنفاق

حدّد نوع بيانات الاعتماد:

واجهة التاجر--credential-type
نموذج دفع ويب قياسي / Stripe Elementscard (الافتراضي)
يعيد HTTP 402 مع method="stripe" في www-authenticateshared_payment_token
يعيد HTTP 402 بدون method="stripe"غير مدعوم — توقّف

بالنسبة إلى استجابات 402، لا تفكّ ترميز التحدّي يدويًا. مرّر الترويسة الخام:

يتحقق هذا من صحة التحدّي ويستخرج معرّف الشبكة ومتن الطلب المفكوك الترميز.

3. سرد طرق الدفع والشحن

استخدم أول مدخل ما لم يحدد المستخدم غير ذلك. يمثّل id من payment-methods list قيمة --payment-method-id في الخطوة التالية.

4. إنشاء طلب الإنفاق

أكّد المجموع النهائي مع المستخدم قبل إصدار هذا الأمر. المبالغ بالسنتات.

لتجار MPP أضف --credential-type shared_payment_token.

يرسل --request-approval إشعارًا إلى تطبيق Link الخاص بالمستخدم ويستقصي حتى يوافق أو يرفض. تخرج أداة سطر الأوامر برمز غير صفري عند الرفض أو انتهاء المهلة.

5. استرجاع بيانات الاعتماد — بأمان

لا تطبع تفاصيل البطاقة إلى stdout. استخدم --output-file بحيث لا يدخل رقم البطاقة (PAN) أبدًا إلى نص محادثة الوكيل أو سجلاته:

يُكتب الملف بصلاحيات 0600؛ ويعرض stdout فقط حقولًا مُخفاة جزئيًا (العلامة التجارية، آخر 4 أرقام، تاريخ الانتهاء) بالإضافة إلى مسار card_output_file.

6. استخدام بيانات الاعتماد

  • لعملية دفع عبر الويب: سلّم مسار الملف للمستخدم، أو مرّره إلى أداة تشغّل المتصفح تملأ النموذج مباشرةً من القرص. لا تستخدم أبدًا read_file أو cat على ملف البطاقة لإدخاله في سياق تفكير الوكيل.

المزالق

  • مقتصر على الولايات المتحدة. خارج الولايات المتحدة، سيفشل auth login. أخبر المستخدم بذلك، ولا تستمر في إعادة المحاولة.
  • يجب ألا يدخل رقم البطاقة (PAN) أبدًا إلى سياق الوكيل. استخدم --output-file في كل مرة. إذا كنت قد استرجعتها بالفعل دون ذلك، فإن تنفيذ link-cli auth logout وحده لا يكفي — البطاقة لمرة استخدام واحدة، لكن نظافة التدوير لا تزال مهمة.
  • يحجب --request-approval حتى يتصرف المستخدم. إذا كان المستخدم نائمًا، ستصل أداة سطر الأوامر إلى مهلتها الزمنية. حدّد التوقعات مسبقًا.
  • أوامر _next متعددة الخطوات. تعيد بعض الأوامر _next.command الذي يجب تنفيذه للمتابعة. عند الشك، فضّل الخيارات ذات الاستقصاء المضمَّن (--interval/--timeout).
  • تفتَرِض صيغة المخرجات toon افتراضيًا في وضع non-TTY. مناسبة للنص العادي، لكن إذا احتاجت خطوة لاحقة إلى تحليل حقل محدد، مرّر --format json.
  • لا تفترض card افتراضيًا. توجد خطوة تقييم التاجر (القسم 2) لأن اختيار نوع بيانات الاعتماد الخاطئ يُفشل الشراء بصمت أو يسرّب بيانات أكثر من اللازم.
