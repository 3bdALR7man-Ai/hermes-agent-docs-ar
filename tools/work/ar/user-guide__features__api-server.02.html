config.yaml

يمكن وضع الإعدادات نفسها في ~/.hermes/config.yaml ضمن قسم متداخل gateway.api_server: في القسم:

port, key, host, cors_origins و model_name تلقائيًا إلى إعدادات extra الخاصة بالمنصة، لذا تتصرف تمامًا مثل نظيراتها من متغيرات البيئة API_SERVER_* المكافئة من متغيرات البيئة. تتقدم متغيرات البيئة على config.yaml. كما تُقبل هذه الكتلة أيضًا تحت gateway.platforms.api_server: أو ضمن قسم platforms.api_server: في المستوى الأعلى.

حدّ عمليات التشغيل المتزامنة

يحد خادم API عدد عمليات تشغيل الوكيل التي يمكن تنفيذها معًا عبر endpoints التي تبدأ تشغيلًا مباشرة: endpoints المتوافقة مع OpenAI ، و endpoints الخاصة بـ Runs ، و endpoints محادثة الجلسة (POST /api/sessions/{id}/chat ونسخته /stream، اللذان يحملان رسائل الوكلاء المباشرة بين الأجهزة). تمر عمليات التشغيل التي يفعّلها cron (POST /api/jobs/{id}/run, POST /api/cron/fire) عبر مُجدول cron وتخضع لحدود cron نفسها، لا لهذا السقف. ويُقرأ السقف من gateway.api_server.max_concurrent_runs (القيمة الافتراضية 10; 0 تعطّل الحد، والقيم السالبة تُقيَّد إلى 0). وعند بلوغ الحد، تُرفض الطلبات الجديدة التي تبدأ عمليات تشغيل مع HTTP 429 Too many concurrent runs (max N) — على العملاء زيادة مهلة الانتظار ثم إعادة المحاولة.

حجم السجل المخزّن لتسلسل previous_response_id

تضمّن كل لقطة /v1/responses مخزّنة سجل المحادثة التراكمي الكامل (وهذا ما يعيد تسلسل previous_response_id و conversation تشغيله)، بما في ذلك كل مخرجات الأدوات حرفيًا. لذا قد تجعل محادثة ذات بضعة مخرجات أدوات كبيرة عملية response_store.db واحدة تكتب عدة مئات KB. اضبط gateway.api_server.history_tool_output_max_chars (الافتراضي 0 = التخزين حرفيًا) لتقييد كل مُخرج أداة وكل وسيط نصي لاستدعاء أداة في السجل المخزّن بهذا العدد من المحارف؛ ويُقتطع أي شيء أطول إلى بدايته بالإضافة إلى علامة ...[N more chars]. ولا يُمس نص المستخدم والمساعد مطلقًا، و response.completed وأحداث SSE التزايدية لا تتأثر. ولأن السجل المخزّن هو ما يراه النموذج في الدور المتسلسل التالي، فإن تفعيل السقف يقلّص أيضًا ما يُعاد عرضه على النموذج — اتركه عند 0 إذا احتاج سير عملك مخرجات أدوات كاملة عبر الأدوار.

ترويسات الأمان

تتضمن جميع الاستجابات ترويسات أمان:

  • X-Content-Type-Options: nosniff — تمنع تخمين نوع MIME (MIME sniffing)
  • Referrer-Policy: no-referrer — تمنع تسريب المُحيل (referrer)

CORS

خادم API لا يفعّل CORS للمتصفحات افتراضيًا.

للوصول المباشر من المتصفح، اضبط قائمة سماح صريحة:

عند تفعيل CORS:

  • استجابات Preflight تتضمن Access-Control-Max-Age: 600 (تخزين مؤقت لمدة 10 دقائق)
  • استجابات البث عبر SSE تتضمن ترويسات CORS لكي تعمل عملاء EventSource في المتصفح بشكل صحيح
  • X-Hermes-Session-Id ترويسة طلب مسموح بها، لذا يمكن للمتصفحات على مصدر مُدرج في قائمة السماح طلب استئناف الجلسة.
  • Idempotency-Key ترويسة طلب مسموح بها — ويمكن للعملاء إرسالها لمنع التكرار (راجع مفاتيح Idempotency لمعرفة ما يغطيه المفتاح ومدة الاحتفاظ به)

معظم الواجهات الأمامية الموثّقة مثل Open WebUI تتصل من خادم إلى خادم ولا تحتاج إلى CORS إطلاقًا.

إعداد متعدد المستخدمين باستخدام Profiles

لمنح عدة مستخدمين نسخة Hermes معزولة خاصة بكل منهم (إعدادات وذاكرة ومهارات منفصلة)، استخدم الـ profiles:

يُعلن خادم API الخاص بكل profile تلقائيًا عن اسم الـ profile بوصفه معرّف النموذج:

  • http://localhost:8643/v1/models → النموذج alice
  • http://localhost:8644/v1/models → النموذج bob

في Open WebUI ، أضف كلًّا منها كاتصال منفصل. ستعرض القائمة المنسدلة للنماذج alice و bob كنموذجين مختلفين، يعتمد كلٌّ منهما على نسخة Hermes معزولة تمامًا. راجع دليل Open WebUI لمزيد من التفاصيل.

القيود

  • تخزين الاستجابات — تُحفظ الاستجابات المخزّنة (الخاصة بـ previous_response_id) في SQLite وتبقى بعد إعادة تشغيل gateway. الحد الأقصى 100 استجابة مخزّنة (مع الإزالة وفق LRU).
  • لا يوجد رفع للملفات — الصور المضمّنة مدعومة على كلٍّ من /v1/chat/completions و /v1/responses، لكن الملفات المرفوعة (file, input_file, file_id) ومدخلات المستندات غير المصوّرة غير مدعومة عبر API.
  • عملاء OpenAI البسيطة ما زالت ترى اسمًا مستعارًا — /v1/models عن الاسم المستعار الثابت لـ Hermes (hermes-agent أو اسم الـ profile النشط). أما العملاء الأغنى بالميزات فيمكنها إرسال تجاوزات صريحة لـ provider / model_options في الطلبات.

Proxy Mode

يعمل خادم API أيضًا كـ backend لوضع وضع proxy في gateway. فعندما تُضبط نسخة Hermes gateway أخرى بـ GATEWAY_PROXY_URL يشير إلى خادم API هذا، فإنها تُعيد توجيه جميع الرسائل إليه بدلًا من تشغيل وكيلها الخاص. وهذا يتيح عمليات نشر مقسّمة — مثل حاوية Docker تتولى Matrix E2EE وتمرّر الرسائل إلى وكيل يعمل على الجهاز المضيف.

راجع Proxy Mode في Matrix للاطلاع على دليل الإعداد الكامل.
