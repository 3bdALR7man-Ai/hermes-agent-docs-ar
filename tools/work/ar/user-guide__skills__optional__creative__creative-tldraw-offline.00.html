معلومة

ما يلي هو التعريف الكامل للمهارة الذي يحمّله Hermes عند تفعيل هذه المهارة، وهو ما يراه الوكيل كتعليمات أثناء عمل المهارة.

مهارة tldraw offline

اعمل مع تطبيق tldraw offline لسطح المكتب (offline.tldraw.com): اقرأ اللوحة المفتوحة، وأجرِ التعديلات عليها، واكتب سكربتات المستند — وهي كود JavaScript مضمّن في ملف .tldraw يعمل عند التحميل ويمنح الملف سلوكًا دائمًا. يشغّل التطبيق API محلي عبر HTTP (الافتراضي localhost:7236) يستخدمه وكيل البرمجة عبر أمر curl عادي من الطرفية الخاصة به — وهذه بالضبط طريقة عمل عرض الصفحة الرئيسية للتطبيق نفسه (Codex يحرّر لوحة مباشرة). لا يستخدم الوكيل computer-use أو النقر عبر واجهة المستخدم الرسومية، ولا يعدّل ملف .tldraw يدويًا مباشرة. أبقِ tldraw offline مفتوحًا أثناء عملك.

متى تُستخدم

  • عندما يفتح المستخدم tldraw offline ويطلب منك إنشاء لوحة أو تعديلها (مخططات، تصاميم أولية wireframes، تخطيطات).
  • عندما تريد إضافة سلوك دائم لرسمة (أشكال تفاعلية، أزرار تفاعلية، حركة، منطق ربط) عبر سكربت مستند مضمّن.

لا تضع الأشكال يدويًا لتقليد رسمة — اكتب الكود الذي يولّدها. الوكلاء أفضل بكثير في كتابة سكربتات اللوحة من الرسم عليها مباشرة.

المتطلبات المسبقة

  • تثبيت tldraw offline وتشغيله، مع فتح مستند. الإصدارات: https://github.com/tldraw/tldraw-offline/releases/latest (DMG لنظام macOS، Windows x64/Arm64، Linux x86_64/arm64 بصيغة AppImage أو amd64/arm64 .deb).
  • تثبيت Agent Skills داخل التطبيق: Develop → Install Agent Skills. يكتب التطبيق مهارة tldraw الخاصة به إلى ~/.codex/skills/، و~/.claude/skills/، و~/.cursor/skills/، و~/.gemini/skills/ — ليعلّم ذلك الوكيل وصفات curl أدناه. (تعكس مهارة Hermes هذه نفس التوجيهات لصالح Hermes.)
  • الـ API المحلي للتحكم. عند الإطلاق يكتب التطبيق ملف server.json إلى مجلد إعداداته (Linux: ~/.config/tldraw/، macOS: ~/Library/Application Support/tldraw/، Windows: %APPDATA%\tldraw\) ويحتوي على port (الافتراضي 7236)، وtoken من نوع bearer، وpid، وstartedAt. يحتاج كل طلب باستثناء GET / إلى Authorization: Bearer <token>. الإغلاق النظيف يحذف server.json؛ فإذا كان موجودًا لكن المنفذ لا يستجيب، فهذا يعني أن التطبيق أُغلق بشكل غير نظيف — اعتبره غير شغّال.
  • أعد قراءة المنفذ والـ token في كل استدعاء shell. كل استدعاء طرفية هو shell جديد، لذا لا يبقى token تم تصديره عبر export — فـ"صدّره مرة واحدة وأعد استخدامه" يرسل token فارغًا ويسبب أخطاء 401. اقرأ الاثنين ضمن سطر واحد في بداية كل استدعاء: PORT=$(jq -r .port <server.json>); TOKEN=$(jq -r .token <server.json>).
  • لا حاجة لحساب أو اتصال بالشبكة للتحرير المحلي.

سكربت المستند الجاهز للتكييف هو scripts/main.js.

مرجع سريع

عقد سكربت المستند (تم التحقق منها مقابل ملف script-context.d.ts المضمّن في التطبيق):

  • ctx.editor — كائن Editor الحيّ (createShape، updateShape، deleteShapes، getCurrentPageShapes، getShape، getBindingsFromShape، zoomToFit، on('tick'|'event', fn)، run(fn, { history: 'ignore' })).
  • ctx.helpers — createShapeIfMissing، createShapesIfMissing، createArrowBetweenShapes(from, to, { arrowheadEnd })، translateShapes، onShapeTranslate(id, fn, { signal })، richTextToPlainText، boxShapes، getLints.
  • ctx.signal — كائن AbortSignal؛ اربط به كل عملية إلغاء لمستمع أو مؤقّت.
  • ملف config.js (منفصل) يسجّل أدوات مخصصة للأشكال/الأدوات/المكوّنات ويعمل قبل التركيب (mount)؛ بينما يعمل main.js على المحرر بعد تركيبه ويُعاد تشغيله عند الحفظ.

واجهة تفاعلية (أزرار قابلة للنقر تتحكم في الحالة)

يمكن للأشكال المرسومة أن تتصرف كتطبيق حقيقي — وهذا ما لا تستطيعه لوحة ثابتة. مثال كامل: scripts/counter.js (عرض رقمي + أزرار MINUS وRESET وPLUS).

حدود التحقق — اقرأ هذا قبل الادعاء أن التفاعل يعمل أو لا يعمل. يوصي دليل الوكيل الخاص بالتطبيق نفسه بالتحقق من سكربت واجهة قابلة للنقر عبر "نقرة محاكاة واحدة وقراءة حالة واحدة" باستخدام /exec (يستدعي editor.dispatch حدث pointer، وينتظر دورة (tick)، ثم يقرأ حالة الشكل) — وليس عبر تحريك ماوس حقيقي. وبهذا المعيار، فإن العدّاد مُتحقَّق منه: النقرات المُطلقة برمجيًا خفضته 0 → 1 → 2 → 1 → 0. وهناك تنبيهان يستحقان التسجيل:

  • لا يعمل السكربت إلا بعد أن يطبّقه مراقب الملفات (file-watcher) الخاص بالتطبيق. على Linux يستخدم هذا المراقب inotify؛ وعلى مضيف نفدت فيه قيمة fs.inotify.max_user_instances تظهر رسالة inotify_add_watch ... No space left on device، ويعرض script-status state: "not-watching" / hasEntry: false، ولا يُنفَّذ السكربت أبدًا. هذا حد من حدود المضيف، وليس خللًا في السكربت — سطح المكتب العادي لا يتأثر بذلك.
  • تشغيل اللوحة باستخدام computer-use يحتاج توصيلًا في المقدمة (foreground) لا في الخلفية. يعيد نمط التوصيل الافتراضي background في cua-driver background_unavailable ضد renderer محجوب من Electron — لكن هذه أول عقبة وليست جدارًا. يعيد cua-driver تلميحًا escalation: "foreground"؛ اضبط delivery_mode: "foreground" (مع bring_to_front) وسيصل مسار X11 XTest الخاص به (x11_xtest_fg) بالنقرات — وهذا يُغلق مربع حوار الموافقة على "Run Script" وينقر على اللوحة. تم التحقق من ذلك من قبل فريق Cua على نفس إصدار AppImage رقم v1.11.0 (Linux/X11). لا تستنتج أن "Electron يرفض النقرات الاصطناعية" وتستسلم في وضع الخلفية — بل انتقل إلى المقدمة. (المسار الفعلي للمنتج يبقى /exec، وليس النقرات؛ هذه الملاحظة تخص الاختبار المدفوع بـ computer-use.)

النمط:

  • ابحث عن الأزرار عبر meta (أو التسمية المرئية عبر helpers.richTextToPlainText)، لا عبر إحداثيات ثابتة مُبرمَجة مسبقًا.
  • يجب أن يتولى سكربت واحد كلًا من البناء والقراءة. فإذا أُنشئت الأشكال بمسار كود (بـ meta.action: 'inc') بينما يقرأ المعالج اصطلاحًا آخر (meta.action === 'PLUS')، لا تفعل النقرات شيئًا بصمت. اجعل الأزرار مبنية بنفس السكربت الذي يتولى معالجتها، أو ابدأ بلوحة فارغة ليبنيها السكربت من جديد — لا تضع أبدًا أشكالًا غير متطابقة مسبقًا في قاعدة بيانات الملف.
  • احفظ حالة التطبيق داخل meta الخاصة بالشكل (مثل meta.count) واعرضها في تسمية richText لذلك الشكل، لتبقى بعد الحفظ وقابلة للقراءة عند التحقق.
  • افصل المستمع عند إلغاء signal. تجاهل هذا ليس أمرًا شكليًا: عند الحفظ التالي يبقى onEvent القديم متصلًا إلى جانب الجديد، فتُطلق كل نقرة مرتين ويقفز العدّاد بمقدار 2 بدلًا من 1.
  • للحركة المستمرة استخدم editor.on('tick', fn)؛ ولنقطة ارتكاز متحركة مع أجزاء متصلة بها استخدم helpers.onShapeTranslate(id, fn, { signal }).

تسليم ملف .tldraw مُبرمَج يعمل تلقائيًا

ملف .tldraw هو ملف zip يحتوي metadata.json + session.json + db.sqlite + assets/

  • script/ (هذه المدخلات فقط قابلة للتعبئة). لكي يعمل السكربت تلقائيًا دون ظهور مربع حوار الموافقة "This document contains a script → Run Script":
  • يجب أن يحمل metadata.json بيانًا لـ script: { "sha256": "<digest>" }، حيث البصمة (digest) هي sha256 محسوبة على كل مسار مرتّب ضمن script/ بالصيغة `${path}\0${sha256hex(bytes)}\n`. وأي تعارض يُرفض باعتباره تلاعبًا.
  • ثِق مسبقًا بالبصمة بإضافتها إلى ~/.tldraw/script-trust.json ({ "trusted": ["<digest>"] }، أو $TLDRAW_SCRIPT_TRUST). يتخطى التطبيق الموافقة عندما تكون isScriptTrusted(digest) صحيحة (true).

الإجراء

  1. اقرأ الـ token والمنفذ الحاليين من server.json. حدّد المستند المستهدف عبر api.getFocusedDoc() (أو api.getDocs())؛ سمِّه صراحةً إن كان هناك عدة مستندات مفتوحة.
  2. للتخطيط/التوليد استخدم /exec. أما للسلوك الدائم فعدّل script/main.js عبر /script-workspace.
  3. اجعل السكربتات متكافئة القوة (idempotent): أنشئ الأشكال الدائمة باستخدام helpers.createShapeIfMissing ومعرّفات ثابتة عبر createShapeId('name'). تُعاد السكربتات عند كل تحميل.
  4. أبقِ الكتابات التي يملكها السكربت خارج سجل تراجع المستخدم: editor.run(fn, { history: 'ignore' }) (أو helpers.translateShapes، التي تفعل ذلك فعليًا).
  5. للتفاعلية، استخدم editor.store.listen(cb) وأزله عند إلغاء signal. وللتفاعل استخدم editor.on('event', h) (اختبار الاصطدام لـ pointer_down بإحداثيات الصفحة)؛ وللحركة استخدم editor.on('tick', h).
  6. لنقطة ارتكاز متحركة واحدة مع مكوّنات داخلية مرتبطة بها، يُفضَّل استخدام helpers.onShapeTranslate(anchorId, fn, { signal }) بدلًا من مستمع عام على المخزن — إذ يمكن لمستمع عام أن يحوّل كتاباتك الخاصة إلى حلقات ارتداد (feedback loops).

خصائص الأشكال (تم التحقق منها مقابل مخطط tldraw SDK v5)

تقبل editor.createShape / createShapeIfMissing خصائص جزئية (تملأ أدوات الشكل القيم الافتراضية). أما عند بناء سجلات خام لقطة ملف، فكل خاصية أدناه مطلوبة (شغّل scripts/validate_shapes.mjs):

الشكلالخصائص المطلوبة
noterichText، color، labelColor، size، font، align، verticalAlign، growY، fontSizeAdjustment، url، scale، textLastEditedBy
textrichText، color، size، font، textAlign، w، scale، autoSize
framew، h، name، color
geogeo، w، h، color، fill، richText (+ dash/size/إلخ بقيم افتراضية)

يجب أن يكون richText ناتجًا من toRichText('...') — أي سلسلة نصية عادية تُرفض. تعداد color: black grey light-violet violet blue light-blue yellow orange green light-green light-red red white. تعداد font: draw sans serif mono.

مزالق شائعة

  • store.listen يُطلَق في الدورة (tick) التالية بعد التنفيذ (commit)، وليس بشكل متزامن. إن كتبت شكلًا وقرأت الحالة فورًا متوقعًا أن يكون المستمع قد عمل، فلن يكون قد عمل بعد. تم التحقق مباشرة: تُظهر قراءة ضمن نفس الدور 0 عمليات إطلاق؛ وبعد دورة واحدة من setTimeout تظهر عملية إطلاق واحدة. لنفس السبب يذكر التطبيق أن editor.dispatch غير متزامن — انتظر دورة قبل التحقق.
  • ctx، وليس متغيرات عامة (globals). نقطة الدخول هي export default function ({ editor, helpers, signal }). لا يوجد كائن editor عام في سكربت المستند. تأتي createShapeId / toRichText / Vec من import ... from 'tldraw'.
  • richText، وليس text. تستخدم تسميات النص/الملاحظة/الشكل الهندسي richText: toRichText(s).
  • السجلات الخام تحتاج كل خاصية؛ أما createShape فلا. ضمن التطبيق، مرّر فقط الخصائص التي تهمك؛ أما لقطة .tldraw المبنية يدويًا فتحتاج المجموعة الكاملة (الجدول).
  • تُعاد السكربتات عند كل تحميل — اجعلها متكافئة القوة. استخدم createShapeIfMissing بمعرّفات ثابتة وإلا كرّرت المحتوى وأتلفت تعديلات المستخدم.
  • نظّف عند إلغاء signal. استخدم signal.addEventListener('abort', () => stop()) لكل store.listen / editor.on / setInterval؛ يُطلَق الإشارة قبل إعادة التشغيل وعند الإغلاق.
  • أبقِ كتابات السكربت خارج التراجع: editor.run(fn, { history: 'ignore' }).
  • يتوقف editor.on('tick') عند إخفاء النافذة (فهو حلقة RAF)؛ بينما يستمر setInterval بالإطلاق لكن Electron يحدّه إلى نحو مرة واحدة في الثانية في الخلفية.
  • يحتاج الـ API إلى الـ token من نوع bearer من server.json؛ ويمكن أن يكون المنفذ غير الافتراضي (يختار server.listen(0) منفذًا) — اقرأ الملف دائمًا، ولا تكتب 7236 ثابتًا.
  • لا تستورد إلا tldraw / react / react-dom — فهذا ليس مشروع Node.

التحقق

  • مخطط الأشكال (دون اتصال، بلا تطبيق): node scripts/validate_shapes.mjs — يبني مخطط tldraw الفعلي ويتحقق من note/text/frame. عند النجاح تُطبع 3/3.
  • تعديلات اللوحة الحية: بعد /exec، تحقق بالقراءة عبر /api/search → api.getShapes(docId) (تُعيد { page, viewport, shapes }) و api.getBindings(docId) (مصفوفة). تأكد من وجود الأشكال/الروابط المتوقعة. احصل على api.getScreenshot(docId) (تُعيد { filePath, ... }) وافحص صورة PNG/JPEG باستخدام vision_analyze.
  • تطبيق السكربت الدائم: GET /api/doc/:id/script-status. النجاح يعني state: "applied" (currentDiskDigest === lastAppliedDigest === manifestSha256، وpendingApply === false، وlastApplyError === null). إذا بقيت الحالة "pending" بعد إعادة محاولة قصيرة، أبلغ بذلك بدلًا من ادعاء النجاح؛ أما "error" فتعني فشل التطبيق — اقرأ errorLogPath.
