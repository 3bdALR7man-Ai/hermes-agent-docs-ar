التصفية على مستوى كل خادم

يمكنك التحكم في الأدوات التي يضيفها كل خادم MCP إلى Hermes ، ما يتيح إدارة دقيقة لمساحة أسماء الأدوات لديك.

تعطيل خادم بالكامل

عند ضبط enabled: false، يتخطى Hermes الخادم كليًا ولا يحاول حتى الاتصال به.

قائمة سماح لأدوات الخادم

لا تُسجَّل إلا أدوات خادم MCP المذكورة.

يمكن أن تكون الإدخالات في include/exclude أيضًا أنماط glob ‏(*, ?, [...]، وتُطابَق مع مراعاة حالة الأحرف): فالنمط include: ["*_dns_*"] يسجّل كل أداة يحتوي اسمها على _dns_. أما الإدخالات العادية التي لا تتضمن محارف خاصة فتبقى مطابقة تامة. وأنماط glob هي الطريقة العملية لتصفية الخوادم التي توفّر آلاف الأدوات المولَّدة تلقائيًا للـ endpoints بحسب عائلة المنتج.

قائمة حظر لأدوات الخادم

تُسجَّل جميع أدوات الخادم باستثناء الأدوات المستبعدة.

أنماط Glob

تقبل كلتا القائمتين أنماط glob على نمط fnmatch إلى جانب الأسماء الدقيقة — وهذا ضروري للواجهات المسطّحة الضخمة مثل API MCP الخاص بـ Cloudflare ‏(?codemode=false، بنحو 3,300 أداة)، حيث يكون استبعاد مجالات المنتجات endpoint تلو الآخر أمرًا غير عملي:

الإدخالات التي لا تحتوي على محارف glob الخاصة (*, ?, [) تُطابَق بدقة — فالإدخال docs يستبعد فقط الأداة المسمّاة docs، ولا يستبعد أبدًا docs_search.

السلوك وقت التشغيل

وقت الاكتشاف

يكتشف Hermes خوادم MCP عند بدء التشغيل ويسجّل أدواتها في سجل الأدوات المعتاد.

لا يُوصل أكثر من 4 خوادم في الوقت نفسه لكل تمريرة اكتشاف (بدء التشغيل، و /reload-mcp، ومراقب الإعدادات). ينشئ كل خادم stdio شجرة عمليات فرعية خاصة به، لذا كانت التمريرة غير المحدودة ذات الخوادم الكثيرة تطلقها كلها في اللحظة نفسها — طفرة CPU/RAM ، وفي مجموعات متعددة الـ profiles دفعة متزامنة من استدعاءات المزوّد. اضبط ذلك في config.yaml:

تعمل التمريرة ذات الخوادم الأكثر من السقف على دفعات؛ وتحتفظ كل دفعة بميزانية 120 s المعتادة (التمرير الكامل مقيد بـ 300 s)، لذا تنتهي المجموعة البطيئة لاحقًا بدل انتهاء مهلتها.

بدء كسول

يُسجّل الخادم ذو lazy: true من التخزين المؤقت للمخطط على القرص بدلًا من ذلك: تظهر أدواته في السجل فورًا، وتُنشأ العملية (أو يُوصل endpoint HTTP) عند أول استدعاء أداة. يُكتب التخزين المؤقت عند كل اتصال حي، لذا يكون التشغيل الأول لخادم جديد أو متغير فوريًا دائمًا. وتعرض اللافتة ولوحة جلسة TUI ذلك الخادم بوصفه lazy مع عدد أدواته المخزّن مؤقتًا (3 tool(s) (lazy, starts on first use)) — فهو خادم يعمل، لا خادم فاشل — ويحتسبه ملخص اكتشاف بدء التشغيل بوصفه N lazy, not spawned yet.

الاكتشاف الديناميكي للأدوات

يمكن لخوادم MCP إبلاغ Hermes عند تغيّر أدواتها المتاحة وقت التشغيل عبر إرسال إشعار notifications/tools/list_changed. وعندما يتلقى Hermes هذا الإشعار، يعيد تلقائيًا جلب قائمة أدوات الخادم ويحدّث السجل — دون الحاجة إلى تشغيل /reload-mcp يدويًا.

يفيد هذا مع خوادم MCP التي تتغير قدراتها ديناميكيًا (مثل خادم يضيف أدوات عند تحميل مخطط قاعدة بيانات جديد، أو يزيل أدوات عندما تتوقف خدمة ما عن العمل).

عملية التحديث محمية بقفل، بحيث لا تتسبب الإشعارات المتلاحقة من الخادم نفسه في عمليات تحديث متداخلة. أما إشعارات تغيّر الـ prompts والموارد (prompts/list_changed, resources/list_changed) فتُستقبل لكن لا يُتخذ بشأنها أي إجراء بعد.

إعادة التحميل

إذا غيّرت إعدادات MCP ، فاستخدم:

يعيد هذا تحميل خوادم MCP من الإعدادات ويحدّث قائمة الأدوات المتاحة. وهو أيضًا الطريقة الصريحة لإعادة فحص الأدوات المشروطة بالتوفر (Docker ، وHASS_TOKEN، و OAuth…): فمجموعة أدوات الجلسة تبقى مجمّدة فيما عدا ذلك، لذا فإن بيانات الاعتماد أو الـ daemon الذي يظهر في منتصف الجلسة لا يُلتقط إلا عند /reload-mcp, /new، أو ضغط السياق. أما تغييرات الأدوات وقت التشغيل التي يدفعها الخادم نفسه، فراجع الاكتشاف الديناميكي للأدوات أعلاه.

يراقب Messaging Gateway عامل (hermes gateway run) أيضًا config.yaml بنفسه: خلال نحو دقيقة من إزالة إدخال mcp_servers أو ضبط enabled: false، يُفك اتصال ذلك الخادم؛ ويُوصل الإدخال المضاف حديثًا. ويُعاد تلقائيًا طلب اتصال خادم فشل اتصاله الأول (مضيف غير قابل للوصول، أو خادم OAuth على جهاز دون واجهة لم يكن لديه token بعد) بحسب جدول تهدئة الاتصال (30 s ، يتضاعف حتى 10 min) بعد إصلاح السبب. لا تلزم إعادة تشغيل أو /reload-mcp كي يسري التعديل.

انتهاء صلاحية OAuth tokens في الخلفية. لا يفتح الـ gateway أو /reload-mcp أو الاختبار الذاتي الدوري لخادم معلّق متصفحًا مطلقًا — فلا يوجد أحد لإكمال العملية. وعندما يتوقف refresh token عن العمل يُعلّق الخادم مع تحذير في gateway.log وتعيد التفويض مرة واحدة باستخدام hermes mcp login <server> (أو زر Authorize في Desktop/لوحة التحكم)؛ ويلتقط الخادم المعلّق الـ token الجديد عند اختباره التالي.

اقرأ الحالة والجسم أولًا: تعني 400/405 على POST initialize عادة أن endpoint لا يدعم إلا SSE (اضبط transport: sse) أو أن proxy أمامه يرفض الطلب؛ وتعني 401/403 أن token أو منح OAuth غير صحيح؛ ويعني جسم HTML أن URL يشير إلى صفحة ويب، لا endpoint MCP. hermes logs --level debug يعرض أيضًا endpoint الدقيق الذي استخدمته كل محاولة اتصال.

الأدوات لا تظهر

الأسباب المحتملة:

  • فشل الخادم في الاتصال
  • فشل الاكتشاف
  • استبعدت إعدادات التصفية لديك الأدوات
  • القدرة المساعدة غير موجودة على ذلك الخادم
  • الخادم معطّل بواسطة enabled: false

إذا كنت تُجري التصفية عن قصد، فهذا متوقع.

لماذا لم تظهر الأدوات المساعدة للموارد أو الـ prompts ؟

  1. أن تسمح بها إعداداتك
  2. أن تدعم جلسة الخادم تلك القدرة فعلًا

هذا مقصود، ويُبقي قائمة الأدوات معبّرة عن الواقع بدقة.

عندما تكون قيمة supports_parallel_tool_calls هي true، قد ينفّذ Hermes عدة أدوات من ذلك الخادم في الوقت نفسه ضمن دفعة واحدة من استدعاءات الأدوات، تمامًا كما يفعل مع الأدوات المدمجة المخصّصة للقراءة فقط (web_search و read_file وغيرهما).

تنبيه

لا تفعّل الاستدعاءات المتوازية إلا لخوادم MCP التي تكون أدواتها آمنة للتشغيل في الوقت نفسه. إذا كانت الأدوات تقرأ وتكتب حالة مشتركة أو ملفات أو قواعد بيانات أو موارد خارجية، فراجع حالات التسابق (race conditions) في القراءة/الكتابة قبل تفعيل هذا الإعداد.

دعم MCP Elicitation

يمكن لخوادم MCP أن تطلب من المستخدم مدخلات منظّمة في منتصف استدعاء أداة عبر بروتوكول elicitation/create ‏(mcp Python SDK ≥ 1.11.0). يوجّه Hermes طلبات الـ elicitation من نوع وضع النموذج عبر واجهة الموافقة الموجودة لديه — مطالبة تفاعلية في CLI/TUI ، أو أزرار موافقة على منصات الـ gateway مثل Telegram و Slack — بحيث يصل الطلب إليك أينما كانت الجلسة. أما طلبات الـ elicitation من نوع وضع URL (حيث يوجّهك الخادم إلى عنوان URL خارجي) فتُرفض لأنها غير مدعومة.

تطابق المهلة الافتراضية البالغة 5 دقائق القيمة الافتراضية لموافقات الـ gateway ، حتى يتسع الوقت للمستخدمين على الواجهات غير المتزامنة للرد قبل أن يستسلم الخادم. وتُتتبَّع المقاييس لكل خادم (الطلبات، والمقبولة، والمرفوضة، والأخطاء) في المعالج.

تشغيل Hermes كخادم MCP

إلى جانب الاتصال بخوادم MCP ، يمكن لـ Hermes أيضًا أن يكون خادم MCP. يتيح ذلك للوكلاء الآخرين الداعمين لـ MCP ‏(Claude Code و Cursor و Codex أو أي عميل MCP) استخدام قدرات المراسلة في Hermes — سرد المحادثات، وقراءة سجل الرسائل، وإرسال الرسائل عبر جميع منصاتك المتصلة.

متى تستخدم هذا

  • تريد أن يرسل Claude Code أو Cursor أو أي وكيل برمجة آخر رسائل Telegram/Discord/Slack ويقرأها عبر Hermes
  • تريد خادم MCP واحدًا يربطك بجميع منصات المراسلة المتصلة بـ Hermes دفعة واحدة
  • لديك بالفعل gateway لـ Hermes قيد التشغيل مع منصات متصلة

يتضمن خادم MCP جسر أحداث حيًّا يستطلع قاعدة بيانات الجلسات في Hermes بحثًا عن رسائل جديدة. يمنح هذا عملاء MCP اطلاعًا شبه فوري على المحادثات الواردة:

أنواع الأحداث: message, approval_requested, approval_resolved

طابور الأحداث موجود في الذاكرة ويبدأ عند اتصال الجسر. أما الرسائل الأقدم فمتاحة عبر messages_read.

الخيارات

كيف يعمل

يقرأ خادم MCP بيانات المحادثات مباشرةً من مخزن الجلسات في Hermes — إذ يُعد ~/.hermes/state.db المصدر الأساسي، بينما يُحتفظ بـ sessions.json فقط كمصدر احتياطي قديم. يستطلع خيط (thread) في الخلفية قاعدة البيانات بحثًا عن رسائل جديدة ويحتفظ بطابور أحداث في الذاكرة. ولإرسال الرسائل، يستخدم محرك الإرسال الداخلي نفسه (tools/send_message_tool.py) الذي يشغّل تسليم مهام cron و CLI ‏hermes send CLI.

لا يلزم أن يكون الـ gateway قيد التشغيل لعمليات القراءة (سرد المحادثات، وقراءة السجل، واستطلاع الأحداث). لكنه يلزم أن يكون قيد التشغيل لعمليات الإرسال، لأن محوّلات المنصات (platform adapters) تحتاج إلى اتصالات نشطة.

القيود الحالية

  • يوفّر hermes mcp serve المدمج حاليًا خادم MCP يعمل عبر stdio فقط. إذا كنت تحتاج إلى خادم HTTP MCP ، فشغّل محوّلًا منفصلًا — أو، وهو الأكثر شيوعًا بكثير، استخدم جانب العميل في MCP ضمن Hermes ، والذي يدعم بالفعل stdio و HTTP كليهما (url + headers في mcp_servers.yaml / config.yaml؛ راجع خوادم HTTP أعلاه).
  • استطلاع الأحداث بفواصل تقارب 200ms عبر استطلاع لقاعدة البيانات مُحسَّن بالاعتماد على mtime (يتخطى العمل عندما لا تتغير الملفات)
  • لا يوجد دعم لبروتوكول الإشعارات الفورية claude/channel بروتوكول إشعارات دفع بعد
  • الإرسال نصي فقط (لا يمكن إرسال وسائط/مرفقات عبر messages_send)
