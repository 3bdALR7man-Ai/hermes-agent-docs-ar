Google Workspace

Gmail وCalendar وDrive وContacts وSheets وDocs — عبر OAuth الذي يديره Hermes وغلاف CLI رفيع. عندما يكون gws مثبّتًا، تستخدمه المهارة كـ backend للتنفيذ لتغطية أوسع لـ Google Workspace؛ وإلا فإنها تتراجع إلى تطبيق عميل Python المضمَّن.

  • scripts/setup.py — إعداد OAuth2 (نفّذه مرة واحدة للتفويض)

الإعداد لأول مرة

الإعداد غير تفاعلي بالكامل — أنت تقوده خطوة بخطوة بحيث يعمل على CLI أو Telegram أو Discord أو أي منصة.

عرّف اختصارًا أولًا:

الخطوة 0: تحقّق مما إذا كان الإعداد قد تم مسبقًا

إذا طُبعت AUTHENTICATED، انتقل إلى قسم الاستخدام — الإعداد تم بالفعل.

الخطوة 1: الفرز — اسأل المستخدم عمّا يحتاجه

قبل بدء إعداد OAuth، اسأل المستخدم سؤالين:

السؤال 1: "ما خدمات Google التي تحتاجها؟ البريد الإلكتروني فقط، أم أيضًا Calendar/Drive/Sheets/Docs؟"

  • البريد الإلكتروني فقط ← لا يحتاجون هذه المهارة على الإطلاق. استخدم مهارة himalaya بدلًا منها — فهي تعمل بكلمة مرور تطبيق Gmail (Settings ← Security ← App Passwords) وتستغرق دقيقتين للإعداد. لا حاجة إلى مشروع Google Cloud. حمّل مهارة himalaya واتّبع تعليمات إعدادها.

  • البريد الإلكتروني + Calendar ← تابع مع هذه المهارة، لكن استخدم --services email,calendar أثناء المصادقة بحيث تطلب شاشة الموافقة النطاقات (scopes) التي يحتاجونها فعلًا فقط.

  • Calendar/Drive/Sheets/Docs فقط ← تابع مع هذه المهارة واستخدم مجموعة --services أضيق مثل calendar,drive,sheets,docs.

  • وصول كامل إلى Workspace ← تابع مع هذه المهارة واستخدم مجموعة الخدمات الافتراضية all.

السؤال 2: "هل يستخدم حساب Google الخاص بك الحماية المتقدمة (Advanced Protection) (تتطلب مفاتيح أمان مادية لتسجيل الدخول)؟ إذا لم تكن متأكدًا، فالأرجح أنك لا تستخدمها — فهذا أمر كنت ستشترك فيه صراحةً."

  • لا / غير متأكد ← إعداد عادي. تابع أدناه.
  • نعم ← يجب على مسؤول Workspace الخاص بهم إضافة معرّف عميل OAuth إلى قائمة التطبيقات المسموح بها في المؤسسة قبل أن تعمل الخطوة 4. أخبرهم بذلك مسبقًا.

الخطوة 2: إنشاء بيانات اعتماد OAuth (لمرة واحدة، ~5 دقائق)

أخبر المستخدم:

تحتاج إلى عميل Google Cloud OAuth. هذا إعداد لمرة واحدة:

  1. أنشئ مشروعًا أو اختر واحدًا: https://console.cloud.google.com/projectselector2/home/dashboard
  2. فعّل واجهات API المطلوبة من مكتبة API: https://console.cloud.google.com/apis/library فعّل: Gmail API وGoogle Calendar API وGoogle Drive API وGoogle Sheets API وGoogle Docs API وPeople API
  3. أنشئ عميل OAuth هنا: https://console.cloud.google.com/apis/credentials Credentials ← Create Credentials ← OAuth 2.0 Client ID
  4. نوع التطبيق: "Desktop app" ← Create
  5. إذا كان التطبيق لا يزال في وضع Testing، أضف حساب Google الخاص بالمستخدم كمستخدم اختبار هنا: https://console.cloud.google.com/auth/audience Audience ← Test users ← Add users
  6. نزّل ملف JSON وأخبرني بمسار الملف

ملاحظة مهمة بخصوص Hermes CLI: إذا كان مسار الملف يبدأ بـ /، فلا ترسل المسار المجرّد وحده كرسالة مستقلة في CLI، لأنه قد يُفهَم خطأً كأمر slash command. أرسله ضمن جملة بدلًا من ذلك، مثل: The JSON file path is: ~/Downloads/client_secret_....json

بمجرد أن يزوّدوك بالمسار:

إذا لصقوا قيم معرّف العميل / سر العميل الخام بدلًا من مسار ملف، فاكتب لهم بنفسك ملف OAuth JSON صالحًا من نوع Desktop، واحفظه في مكان واضح (مثلًا ~/Downloads/hermes-google-client-secret.json)، ثم نفّذ --client-secret على ذلك الملف.

استخدم مجموعة الخدمات المختارة في الخطوة 1. أمثلة:

يُعيد هذا JSON يحتوي على حقل auth_url ويحفظ أيضًا الرابط الدقيق في ~/.hermes/google_oauth_last_url.txt.

قواعد الوكيل لهذه الخطوة:

  • استخرج حقل auth_url وأرسل ذلك الرابط الدقيق إلى المستخدم في سطر واحد.
  • أخبر المستخدم أن المتصفح سيفشل غالبًا على http://localhost:1 بعد الموافقة، وأن هذا متوقَّع.
  • اطلب منهم نسخ الرابط المُعاد توجيهه بالكامل من شريط عنوان المتصفح.
  • إذا ظهر للمستخدم Error 403: access_denied، أرسله مباشرة إلى https://console.cloud.google.com/auth/audience لإضافة نفسه كمستخدم اختبار.

الخطوة 4: استبدال الرمز (code)

سيلصق المستخدم إما رابطًا مثل http://localhost:1/?code=4/0A...&scope=... أو سلسلة الرمز فقط. كلاهما يعمل. تخزّن خطوة --auth-url جلسة OAuth معلَّقة مؤقتة محليًا بحيث يمكن لِـ --auth-code إتمام استبدال PKCE لاحقًا، حتى على الأنظمة بلا واجهة رسومية:

إذا فشل --auth-code لانتهاء صلاحية الرمز، أو لأنه استُخدم من قبل، أو لأنه جاء من علامة تبويب متصفح أقدم، فإنه يُعيد الآن رابط fresh_auth_url جديدًا. في هذه الحالة، أرسل الرابط الجديد إلى المستخدم فورًا واطلب منه إعادة المحاولة بأحدث إعادة توجيه من المتصفح فقط.

الخطوة 5: تحقّق

يجب أن تُطبع AUTHENTICATED. الإعداد مكتمل — يتجدَّد الـ token تلقائيًا من الآن فصاعدًا.

ملاحظات

  • يُخزَّن الـ token في ~/.hermes/google_token.json ويتجدَّد تلقائيًا.
  • تُخزَّن حالة/مُحقِّق (verifier) جلسة OAuth المعلَّقة مؤقتًا في ~/.hermes/google_oauth_pending.json حتى يكتمل الاستبدال.
  • إذا كان gws مثبّتًا، فإن google_api.py يوجّهه إلى ملف بيانات الاعتماد نفسه ~/.hermes/google_token.json. لا يحتاج المستخدمون إلى تنفيذ مسار gws auth login منفصل.
  • للإلغاء: $GSETUP --revoke

صيغة المخرجات

تُعيد جميع الأوامر JSON. حلّلها بـ jq أو اقرأها مباشرة. الحقول الرئيسية:

  • بحث Gmail: [{id, threadId, from, to, subject, date, snippet, labels}]
  • جلب Gmail (get): {id, threadId, from, to, subject, date, labels, body}
  • إرسال/ردّ Gmail: {status: "sent", id, threadId}
  • سرد Calendar: [{id, summary, start, end, location, description, htmlLink}]
  • إنشاء Calendar: {status: "created", id, summary, htmlLink}
  • بحث Drive: [{id, name, mimeType, modifiedTime, webViewLink}]
  • جلب Drive (get): {id, name, mimeType, modifiedTime, size, webViewLink, parents, owners}
  • رفع Drive: {status: "uploaded", id, name, mimeType, webViewLink}
  • تنزيل Drive: {status: "downloaded", id, name, path, mimeType}
  • إنشاء مجلد Drive: {status: "created", id, name, webViewLink}
  • مشاركة Drive: {status: "shared", permissionId, fileId, role, type}
  • حذف Drive: {status: "trashed" | "deleted", fileId, permanent}
  • سرد Contacts: [{name, emails: [...], phones: [...]}]
  • جلب Sheets (get): [[cell, cell, ...], ...]
  • إنشاء Sheets: {status: "created", spreadsheetId, title, spreadsheetUrl}
  • إنشاء Docs: {status: "created", documentId, title, url}
  • إلحاق Docs (append): {status: "appended", documentId, inserted_at, characters}

القواعد

  1. لا ترسل أبدًا بريدًا إلكترونيًا، ولا تنشئ/تحذف أحداث تقويم، ولا تحذف ملفات Drive، ولا تشارك ملفات، ولا تعدّل Docs/Sheets دون التأكيد مع المستخدم أولًا. اعرض ما سيُنفَّذ (المستلمون، معرّفات الملفات، المحتوى، دور المشاركة) واطلب الموافقة. بالنسبة لِـ drive delete، فضّل سلة المحذوفات الافتراضية (القابلة للتراجع) على --permanent.
  2. تحقّق من المصادقة قبل أول استخدام — نفّذ setup.py --check. إذا فشل، أرشد المستخدم خلال الإعداد.
  3. استخدم مرجع صياغة بحث Gmail للاستعلامات المعقّدة — حمّله بواسطة skill_view("google-workspace", file_path="references/gmail-search-syntax.md").
  4. يجب أن تتضمّن أوقات Calendar المنطقة الزمنية — استخدم دائمًا ISO 8601 مع إزاحة (مثلًا 2026-03-01T10:00:00-06:00) أو UTC (Z).
  5. احترم حدود المعدل — تجنّب استدعاءات API متتالية سريعة. اجمع عمليات القراءة في دفعات عند الإمكان.
