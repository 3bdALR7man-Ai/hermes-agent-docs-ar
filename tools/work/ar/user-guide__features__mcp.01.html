كيف يسجّل Hermes أدوات MCP

يضيف Hermes بادئة إلى أسماء أدوات MCP حتى لا تتعارض مع أسماء الأدوات المدمجة:

أمثلة:

الخادمأداة MCPالاسم المسجَّل
filesystemread_filemcp_filesystem_read_file
githubcreate-issuemcp_github_create_issue
my-apiquery.datamcp_my_api_query_data

عمليًا، لا تحتاج عادةً إلى استدعاء الاسم ذي البادئة يدويًا — إذ يرى Hermes الأداة ويختارها أثناء استدلاله المعتاد.

تنقية نتائج الأدوات و _meta

يُطبَّق سلوكان على كل نتيجة لأداة MCP قبل أن يراها النموذج:

  • تُزال محارف Unicode TAG غير المرئية. المحارف الواقعة في النطاق U+E0000–U+E007F لا تظهر إطلاقًا في الطرفيات وواجهات المحادثة، لكنها مرئية بالكامل للنموذج — وهي قناة تهريب كلاسيكية لحقن الـ prompt (prompt injection) يستغلها خادم خبيث أو مُخترَق. يزيلها Hermes من نتائج الأدوات، ومحتوى الموارد، وأوصاف الأدوات. أما تسلسلات وسوم الإيموجي المشروعة (مثل أعلام المناطق 🏴󠁧󠁢󠁳󠁣󠁴󠁿) فتُحفظ كما هي.
  • تُعرض بيانات _meta الخاصة بالمورِّدين؛ أما المفاتيح المحجوزة للبروتوكول فلا. عندما يُرفق خادم خريطة _meta بنتيجة أداة (بمساحات أسماء خاصة بالمورِّدين مثل com.example/handoff)، يمرّرها Hermes إلى النموذج إلى جانب محتوى النتيجة. وتُحذف المفاتيح الواقعة تحت البادئات المحجوزة للبروتوكول — أي تسمية modelcontextprotocol أو mcp متبوعة بتسمية أخرى، مثل modelcontextprotocol.io/... أو tools.mcp.com/... — بما يتوافق مع قواعد أسماء المفاتيح في مواصفة MCP. وإذا لم يتبقَّ شيء موجَّه إلى النموذج، يُحذف الحقل _meta كليًا.

أدوات MCP المساعدة

عندما يكون ذلك مدعومًا، يسجّل Hermes أيضًا أدوات مساعدة حول موارد MCP والـ prompts:

  • list_resources
  • read_resource
  • list_prompts
  • get_prompt

تُسجَّل هذه الأدوات لكل خادم بنمط البادئة نفسه، على سبيل المثال:

  • mcp_github_list_resources
  • mcp_github_get_prompt

مهم

أصبحت هذه الأدوات المساعدة الآن تراعي القدرات المتاحة:

  • لا يسجّل Hermes أدوات الموارد المساعدة إلا إذا كانت جلسة MCP تدعم فعلًا عمليات الموارد
  • لا يسجّل Hermes أدوات الـ prompts المساعدة إلا إذا كانت جلسة MCP تدعم فعلًا عمليات الـ prompts

لذا فإن الخادم الذي يوفّر أدوات قابلة للاستدعاء دون موارد/prompts لن يحصل على تلك الأغلفة الإضافية.

التصفية على مستوى كل خادم

يمكنك التحكم في الأدوات التي يضيفها كل خادم MCP إلى Hermes، ما يتيح إدارة دقيقة لمساحة أسماء الأدوات لديك.

تعطيل خادم بالكامل

عند ضبط enabled: false، يتخطى Hermes الخادم كليًا ولا يحاول حتى الاتصال به.

قائمة سماح لأدوات الخادم

لا تُسجَّل إلا أدوات خادم MCP المذكورة.

يمكن أن تكون الإدخالات في include/exclude أيضًا أنماط glob ‏(*، ?، [...]، وتُطابَق مع مراعاة حالة الأحرف): فالنمط include: ["*_dns_*"] يسجّل كل أداة يحتوي اسمها على _dns_. أما الإدخالات العادية التي لا تتضمن محارف خاصة فتبقى مطابقة تامة. وأنماط glob هي الطريقة العملية لتصفية الخوادم التي توفّر آلاف الأدوات المولَّدة تلقائيًا للـ endpoints بحسب عائلة المنتج.

الإدخالات التي لا تحتوي على محارف glob الخاصة (*، ?، [) تُطابَق بدقة — فالإدخال docs يستبعد فقط الأداة المسمّاة docs، ولا يستبعد أبدًا docs_search.

السلوك وقت التشغيل

وقت الاكتشاف

يكتشف Hermes خوادم MCP عند بدء التشغيل ويسجّل أدواتها في سجل الأدوات المعتاد.

الاكتشاف الديناميكي للأدوات

يمكن لخوادم MCP إبلاغ Hermes عند تغيّر أدواتها المتاحة وقت التشغيل عبر إرسال إشعار notifications/tools/list_changed. وعندما يتلقى Hermes هذا الإشعار، يعيد تلقائيًا جلب قائمة أدوات الخادم ويحدّث السجل — دون الحاجة إلى تشغيل /reload-mcp يدويًا.

يفيد هذا مع خوادم MCP التي تتغير قدراتها ديناميكيًا (مثل خادم يضيف أدوات عند تحميل مخطط قاعدة بيانات جديد، أو يزيل أدوات عندما تتوقف خدمة ما عن العمل).

عملية التحديث محمية بقفل، بحيث لا تتسبب الإشعارات المتلاحقة من الخادم نفسه في عمليات تحديث متداخلة. أما إشعارات تغيّر الـ prompts والموارد (prompts/list_changed، resources/list_changed) فتُستقبل لكن لا يُتخذ بشأنها أي إجراء بعد.

هذا مقصود، ويُبقي قائمة الأدوات معبّرة عن الواقع بدقة.

عندما تكون قيمة supports_parallel_tool_calls هي true، قد ينفّذ Hermes عدة أدوات من ذلك الخادم في الوقت نفسه ضمن دفعة واحدة من استدعاءات الأدوات، تمامًا كما يفعل مع الأدوات المدمجة المخصّصة للقراءة فقط (web_search و read_file وغيرهما).

تنبيه

لا تفعّل الاستدعاءات المتوازية إلا لخوادم MCP التي تكون أدواتها آمنة للتشغيل في الوقت نفسه. إذا كانت الأدوات تقرأ وتكتب حالة مشتركة أو ملفات أو قواعد بيانات أو موارد خارجية، فراجع حالات التسابق (race conditions) في القراءة/الكتابة قبل تفعيل هذا الإعداد.

دعم MCP Elicitation

يمكن لخوادم MCP أن تطلب من المستخدم مدخلات منظّمة في منتصف استدعاء أداة عبر بروتوكول elicitation/create ‏(mcp Python SDK ≥ 1.11.0). يوجّه Hermes طلبات الـ elicitation من نوع form-mode عبر واجهة الموافقة الموجودة لديه — مطالبة تفاعلية في CLI/TUI، أو أزرار موافقة على منصات الـ gateway مثل Telegram و Slack — بحيث يصل الطلب إليك أينما كانت الجلسة. أما طلبات الـ elicitation من نوع URL-mode (حيث يوجّهك الخادم إلى عنوان URL خارجي) فتُرفض لأنها غير مدعومة.

تشغيل Hermes كخادم MCP

إلى جانب الاتصال بخوادم MCP، يمكن لـ Hermes أيضًا أن يكون خادم MCP. يتيح ذلك للوكلاء الآخرين الداعمين لـ MCP ‏(Claude Code و Cursor و Codex أو أي عميل MCP) استخدام قدرات المراسلة في Hermes — سرد المحادثات، وقراءة سجل الرسائل، وإرسال الرسائل عبر جميع منصاتك المتصلة.

متى تستخدم هذا

  • تريد أن يرسل Claude Code أو Cursor أو أي وكيل برمجة آخر رسائل Telegram/Discord/Slack ويقرأها عبر Hermes
  • تريد خادم MCP واحدًا يربطك بجميع منصات المراسلة المتصلة بـ Hermes دفعة واحدة
  • لديك بالفعل gateway لـ Hermes قيد التشغيل مع منصات متصلة

الخيارات

كيف يعمل

يقرأ خادم MCP بيانات المحادثات مباشرةً من مخزن الجلسات في Hermes — إذ يُعد ~/.hermes/state.db المصدر الأساسي، بينما يُحتفظ بـ sessions.json فقط كمصدر احتياطي قديم. يستطلع خيط (thread) في الخلفية قاعدة البيانات بحثًا عن رسائل جديدة ويحتفظ بطابور أحداث في الذاكرة. ولإرسال الرسائل، يستخدم محرك الإرسال الداخلي نفسه (tools/send_message_tool.py) الذي يشغّل تسليم مهام cron و CLI ‏hermes send.

لا يلزم أن يكون الـ gateway قيد التشغيل لعمليات القراءة (سرد المحادثات، وقراءة السجل، واستطلاع الأحداث). لكنه يلزم أن يكون قيد التشغيل لعمليات الإرسال، لأن محوّلات المنصات (platform adapters) تحتاج إلى اتصالات نشطة.

القيود الحالية

  • يوفّر hermes mcp serve المدمج حاليًا خادم MCP يعمل عبر stdio فقط. إذا كنت تحتاج إلى خادم HTTP MCP، فشغّل محوّلًا منفصلًا — أو، وهو الأكثر شيوعًا بكثير، استخدم جانب العميل في MCP ضمن Hermes، والذي يدعم بالفعل stdio و HTTP كليهما (url + headers في mcp_servers.yaml / config.yaml؛ راجع خوادم HTTP أعلاه).
  • استطلاع الأحداث بفواصل تقارب 200ms عبر استطلاع لقاعدة البيانات مُحسَّن بالاعتماد على mtime (يتخطى العمل عندما لا تتغير الملفات)
  • لا يوجد دعم لبروتوكول الإشعارات الفورية claude/channel بعد
  • الإرسال نصي فقط (لا يمكن إرسال وسائط/مرفقات عبر messages_send)
