hermes send

إرسال رسالة لمرة واحدة إلى منصة مراسلة مُعدَّة دون تشغيل وكيل أو حلقة gateway. يعيد استخدام بيانات اعتماد gateway المُعدَّة مسبقًا (~/.hermes/.env + ~/.hermes/config.yaml) بحيث يمكن لسكربتات العمليات ومهام cron وhooks CI وdaemons المراقبة نشر تحديثات الحالة دون إعادة تنفيذ عميل REST الخاص بكل منصة.

بالنسبة للمنصات ذات رمز البوت (Telegram وDiscord وSlack وSignal وSMS وWhatsApp-CloudAPI)، لا يلزم تشغيل gateway — يتحدث hermes send مباشرة إلى endpoint REST الخاص بالمنصة. أما منصات الإضافات التي تحتاج محوّلًا دائمًا فلا تزال تتطلب gateway حيًا.

الخيارالوصف
-t، --to <TARGET>هدف التسليم. الصيغ: platform (يستخدم القناة الرئيسية)، platform:chat_id، platform:chat_id:thread_id، أو platform:#channel-name. أمثلة: telegram، telegram:-1001234567890، discord:#ops، slack:C0123ABCD، signal:+15551234567.
-f، --file <PATH>قراءة نص الرسالة من PATH (ملفات نصية فقط — سجلات وتقارير وmarkdown). مرّر - لإجبار القراءة من stdin. لإرسال صورة أو ملف ثنائي آخر، استخدم MEDIA:<path> (انظر أدناه).
-s، --subject <LINE>إضافة سطر موضوع/عنوان قبل نص الرسالة.
-l، --list [platform]عرض الأهداف المُعدَّة عبر كل المنصات (أو منصة معيّنة فقط).
-q، --quietإخفاء stdout عند النجاح — مفيد في السكربتات (الاعتماد على رمز الخروج فقط).
--jsonإصدار نتيجة JSON خام بدلًا من مخرجات مقروءة للبشر.

إذا لم يُعطَ معامل message موضعي ولا --file، يقرأ hermes send من stdin عندما لا يكون TTY. رموز الخروج: 0 عند النجاح، 1 عند فشل التسليم/الـ backend، 2 عند أخطاء الاستخدام.

إرسال الصور والوسائط الأخرى

--file مخصص لأجسام نصية فقط. لتسليم صورة أو مستند أو فيديو أو ملف صوتي كمرفق أصلي للمنصة، أشر إليه داخل نص الرسالة بتوجيه MEDIA:<local_path>:

افتراضيًا، تُرسَل ملفات الصور كصور (تعيد منصات مثل Telegram ضغطها). أضف [[as_document]] إلى الرسالة لتسليمها كمرفقات ملفات غير مضغوطة بدلًا من ذلك:

أمثلة:

hermes peer

رسائل bot-إلى-bot مباشرة عبر الأجهزة. سجّل gateway آخر لـHermes (على أي جهاز يشغّل منصة api_server) كـنظير (peer)، ثم راسل وكلاءه: يحلّ hermes peer dm جلسة Bot Chat الأساسية للوكيل البعيد عبر خادم API الخاص بالنظير، ويشغّل دورًا واحدًا للوكيل هناك، ويطبع الرد على stdout — التوأم عبر الأجهزة لأمر مراسلة البوت المحلي hermes -p <bot> chat --in ~ -c "Bot Chat" ….

<peer> وحدها تستهدف الوكيل الرئيسي لـgateway النظير؛ <peer>/<agent> تستهدف profile مسمًّى على نظير متعدد الإرسال (موجَّه عبر مرآته /p/<profile>/).

الأمر الفرعيالوصف
add <name> --url <URL> [--key <KEY>] [--note TEXT]تسجيل أو تحديث نظير. يذهب الرابط إلى config.yaml (bot_peers)؛ يُخزَّن المفتاح كـHERMES_PEER_<NAME>_KEY في ~/.hermes/.env.
listعرض النظراء وما إذا كان كل منهم لديه مفتاح مُعدّ.
dm <peer>[/<agent>] [message]مراسلة Bot Chat الأساسية لوكيل النظير وطباعة الرد (--json لمخرجات قابلة للقراءة آليًا؛ تعود الرسالة إلى stdin إن لم تُعطَ).
run <peer>[/<agent>] [message]بدء دور Bot Chat أساسي طويل بشكل غير متزامن وإعادة run_id ومعرّف الجلسة ومفتاح idempotency (يدعم --json). أعد استخدام --idempotency-key عند إعادة محاولة نفس الطلب.
status <peer>[/<agent>] <run_id>استطلاع تشغيل نظير غير متزامن وطباعة مخرجاته النهائية عند الاكتمال (يدعم --json).
stop <peer>[/<agent>] <run_id>إيقاف تشغيل النظير غير المتزامن المحدَّد بدقة دون استهداف دور آخر (يدعم --json).
remove <name>إزالة نظير من السجل (يبقى إدخال مفتاح .env كما هو).

عند تسجيل نظير واحد على الأقل، يتضمن بروتوكول مراسلة Bot Mode (agent.bot_mode_protocol) الذي يُلقَّن لكل Bot Chat أساسية تلقائيًا قائمة النظراء ونمط hermes peer dm، بحيث تكتشف الوكلاء زملاء عبر الأجهزة دون تعديلات SOUL. راجع Bot Mode.

رموز الخروج: 0 عند النجاح، 1 عند فشل التسليم/النظير، 2 عند أخطاء الاستخدام.

hermes secrets

سحب مفاتيح API من مدير أسرار خارجي عند بدء العملية بدلًا من تخزينها في ~/.hermes/.env. يدعم حاليًا Bitwarden Secrets Manager. راجع الدليل الكامل: تكامل Bitwarden.

الأوامر الفرعية لـbitwarden (اسم بديل bw):

الأمر الفرعيالوصف
setupمعالج تفاعلي: تثبيت ثنائي bws المثبَّت بإصدار محدَّد، وحفظ رمز وصول، واختيار مشروع. يقبل --project-id و--access-token و--server-url للاستخدام غير التفاعلي.

hermes migrate

تشخيص و(اختياريًا) إعادة كتابة config.yaml النشط لاستبدال مراجع النماذج المتقاعدة أو الإعدادات المهملة. تُؤخذ نسخة احتياطية مؤرَّخة من config.yaml الأصلي قبل أي إعادة كتابة (تخطَّها بـ--no-backup).

الأمر الفرعيالوصف
xaiفحص config.yaml بحثًا عن مراجع لنماذج xAI المُجدوَل تقاعدها في 15 مايو 2026 و(مع --apply) إعادة كتابتها في مكانها إلى البدائل الرسمية وفق دليل انتقال xAI. الافتراضي تشغيل تجريبي/dry-run.

علامات شائعة للأوامر الفرعية للانتقال (migration):

العلامةالوصف
--applyإعادة كتابة config.yaml في مكانها (الافتراضي: تشغيل تجريبي/dry-run، بدون كتابة).

لا تخلط بينه وبين hermes claw migrate (استيراد لمرة واحدة لإعدادات OpenClaw إلى Hermes) — hermes migrate هو أمر إعادة كتابة الإعدادات ذو المستوى الأعلى.

hermes codex-runtime

يشغّل ترحيل ~/.codex/config.toml الذي يطلقه /codex-runtime codex_app_server، دون جلسة محادثة: تُنقل إعدادات mcp_servers في Hermes (مع إضافات codex المثبّتة والقيمة الافتراضية default_permissions) إلى الكتلة المُدارة للـ profile المحدد (hermes -p <name> codex-runtime migrate). يُحفظ نص المستخدم خارج الكتلة حرفيًا؛ ويُحفظ [mcp_servers.<name>] الذي يملكه المستخدم ويحمل اسم خادم Hermes نفسه، ويُتخطَّى نقل إعدادات Hermes لذلك الاسم (ويُبلَّغ عنه كـ preserved_user_servers). تُفحص النتيجة بوصفها TOML قبل الكتابة الذرية؛ ويكون رمز الخروج 1 إذا احتوى التقرير على أخطاء.

الخيارالوصف
--dry-runحساب الترحيل والإبلاغ عنه دون كتابة config.toml.
--jsonطباعة تقرير الترحيل الكامل بصيغة JSON (migrated، preserved_user_servers، skipped_keys_per_server، errors، target_path، written).

hermes proxy

تشغيل خادم HTTP محلي متوافق مع OpenAI يعيد توجيه الطلبات إلى مزوّد upstream مصادَق عليه عبر OAuth (مثل Nous Portal وxAI). يمكن للتطبيقات الخارجية توجيه طلباتها إلى الـ proxy بأي رمز حامل (bearer token)؛ ويرفق الـ proxy بيانات اعتماد OAuth الحقيقية الخاصة بك عند الخروج. راجع Subscription Proxy للدليل الكامل.

الأمر الفرعيالوصف
startتشغيل الـ proxy في المقدمة. العلامات: --provider <nous|xai> (الافتراضي nous)، --host <addr> (الافتراضي 127.0.0.1؛ استخدم 0.0.0.0 للكشف على الشبكة المحلية)، --port <int> (الافتراضي 8645).
statusعرض upstreams الـ proxy الجاهزة (بيانات اعتماد موجودة، OAuth صالح).
providersعرض مزوّدي upstream المتاحين للـ proxy.

hermes usage

كتلة حدود الحساب من slash command /usage — نوافذ Codex ذات 5 ساعات / الأسبوعية، ومواعيد إعادة ضبط الخطة والأرصدة المدَّخرة؛ ونوافذ Anthropic OAuth؛ وأرصدة OpenRouter — دون بدء جلسة، كي تستطيع سكربتات shell ومهام cron قراءتها.

الخيارالوصف
--provider NAMEالمزوّد المراد الاستعلام عنه (الافتراضي: model.provider المضبوط). المدعوم: openai-codex، anthropic، openrouter.
--jsonطباعة مستند JSON واحد بدلًا من الكتلة المقروءة للبشر.

تُحسم بيانات الاعتماد تمامًا كما تُحسم لـ /usage في جلسة دون وكيل حي (مخزن المصادقة، ثم مجمّع بيانات الاعتماد)؛ ولا يضيف الأمر ولا يجدّد بيانات اعتماد لن يستخدمها للمحادثة. رمز الخروج 0 عند النجاح؛ و 1 مع سطر stderr واحد عندما لا تكون للمزوّد بيانات اعتماد مضبوطة، أو لا يملك endpoint للاستخدام، أو يفشل الجلب (يبقى stdout فارغًا).

--json مخطط (المفاتيح ثابتة؛ وقد تُضاف مفاتيح جديدة):

used_percent تكون null عندما لا يُبلغ المزوّد عن النافذة؛ و resets_at تكون ISO-8601 UTC أو null (تحمل بعض النوافذ detail بنص حر بدلًا منها)؛ و plan تكون null عندما لا تُعرف.

hermes status

--deepإجراء فحوص أعمق قد تستغرق وقتًا أطول. يتضمن --full.

hermes cron

الأمر الفرعيالوصف
listعرض المهام المجدولة.
create / addإنشاء مهمة مجدولة من نص prompt، مع إمكانية إرفاق مهارة واحدة أو أكثر عبر تكرار --skill. يدعم تثبيت مستوى تفكير لكل مهمة عبر --reasoning-effort <none|minimal|low|medium|high|xhigh|max|ultra>.
editتحديث جدول مهمة أو نص الـ prompt الخاص بها أو اسمها أو طريقة التسليم أو عدد التكرارات أو المهارات المرفقة. يدعم --clear-skills و--add-skill و--remove-skill، إضافةً إلى --reasoning-effort (تمرير سلسلة فارغة يزيل التثبيت).
pauseإيقاف مهمة مؤقتًا دون حذفها.
resumeاستئناف مهمة متوقفة مؤقتًا. يظل الموعد المتكرر الذي استحق أثناء التوقف مستحقًا (تشغيل تعويضي واحد أو تخطٍّ مسجّل في التكة التالية)؛ وإلا يُحسب موعد التشغيل المستقبلي التالي.
runتشغيل مهمة عند دورة الجدولة القادمة.
removeحذف مهمة مجدولة.
statusالتحقق من تشغيل مجدول Cron.
doctorفحص صحة الأسطول للقراءة فقط: التشغيلات الفاشلة، عمليات التسليم الفاشلة، قيمة next_run_at المتأخرة أو المفقودة، السكربتات أو مجلدات العمل المفقودة. يخرج برمز غير صفري عند وجود مشكلات.
tickتشغيل المهام المستحقة مرة واحدة ثم الخروج.

المشغّل (trigger) لـ cron قابل للتوصيل عبر مفتاح الإعدادات cron.provider. الفارغ (الافتراضي) يستخدم المؤقت المدمج الذي يعمل داخل العملية نفسها. اضبطه على chronos (المزوّد المُدار من NAS للـ gateways المستضافة بنمط scale-to-zero) — يُعدّ عبر مفاتيح cron.chronos.* (portal_url وcallback_url وexpected_audience و nas_jwks_url) — أو حدّد مزوّدًا مخصصًا تحت plugins/cron/<name>/ أو $HERMES_HOME/plugins/<name>/. أي مزوّد غير معروف أو غير متاح يرجع إلى المزوّد المدمج، بحيث لا يبقى cron بلا مشغّل أبدًا. راجع مستند آلية عمل Cron من الداخل.
