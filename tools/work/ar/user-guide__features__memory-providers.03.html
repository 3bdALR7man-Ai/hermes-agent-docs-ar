Supermemory

كتالوج الإضافات

تتولى Supermemory صيانة Supermemory، ويُثبّت من كتالوج الإضافات بدلًا من تضمينه مع Hermes. المصدر والمرجع الكامل للإعدادات: supermemoryai/hermes-supermemory. تُرحّل الإعدادات الحالية تلقائيًا — راجع الانتقال من Supermemory المضمّن.

ذاكرة دلالية طويلة الأمد مع استرجاع profile، وبحث دلالي، وأدوات ذاكرة صريحة، والتقاط المحادثة لكل دور (مستند واحد لكل جلسة في كل نافذة مدتها 4 ساعات).

الأنسب لـالاسترجاع الدلالي مع بناء ملف تعريفي للمستخدم ورسم بياني على مستوى الجلسة
المتطلباتhermes plugins install supermemory (يثبّت Supermemory SDK مع الإضافة)؛ مفتاح API سحابي، أو خادم مستضاف ذاتيًا
تخزين البياناتSupermemory Cloud أو مستضاف ذاتيًا
التكلفةحسب تسعير Supermemory (سحابي) / مجاني (مستضاف ذاتيًا)

الأدوات: supermemory_store (حفظ ذكريات صريحة)، supermemory_search (بحث بالتشابه الدلالي)، supermemory_forget (النسيان بواسطة المعرّف أو بأفضل استعلام مطابق)، supermemory_profile (الملف الشخصي الدائم + السياق الحديث)

الإعداد:

إعداد النسخة المستضافة ذاتيًا:

بعد hermes plugins install supermemory وقبل تنفيذ hermes memory setup، اضبط base_url في $HERMES_HOME/supermemory.json:

ثم شغّل hermes memory setup وأدخل مفتاح API الذي يطبعه الخادم المحلي. فضبط الـ endpoint أولًا يضمن أن يبقى فحص الاتصال أثناء الإعداد محليًا أيضًا.

متغيرات البيئة: SUPERMEMORY_API_KEY (مطلوب)، SUPERMEMORY_BASE_URL (قيمة احتياطية للتوافق عندما لا يكون base_url مضبوطًا)، SUPERMEMORY_CONTAINER_TAG (يتجاوز ملف الإعدادات).

ترتيب أولوية عنوان URL الأساسي هو supermemory.json → SUPERMEMORY_BASE_URL → https://api.supermemory.ai. تستخدم عمليات SDK وفحوص الإعداد/الحالة جميعًا endpoint الذي جرى حلّه.

الميزات الرئيسية:

  • تسييج تلقائي للسياق (context fencing) — يزيل الذكريات المسترجعة من الأدوار الملتقطة لمنع التلوث التكراري للذاكرة
  • التقاط لكل دور — يُكتب كل دور مكتمل وقت اكتماله، بمستند واحد لكل جلسة في كل نافذة مدتها 4 ساعات
  • تُعاد محاولة كتابات الأدوار الفاشلة (مرة واحدة على الأقل) في الدور التالي أو عند نهاية الجلسة أو /reset أو إيقاف التشغيل
  • توجيه مستضاف ذاتيًا من طرف إلى طرف — تستخدم طلبات SDK والفحص endpoint المضبوط نفسه
  • تُحقن حقائق الملف الشخصي في الدور الأول وعلى فترات قابلة للضبط
  • حاويات ضمن نطاق الـ profile — استخدم {identity} في container_tag (مثل hermes-{identity} → hermes-coder) لعزل الذكريات لكل profile في Hermes
  • وضع الحاويات المتعددة — فعّل enable_custom_container_tags مع قائمة custom_containers للسماح للوكيل بالقراءة والكتابة عبر حاويات مسمّاة. أما العمليات التلقائية فتبقى على الحاوية الأساسية.

الانتقال من Supermemory المضمّن

كان Supermemory يُضمّن داخل شجرة Hermes (وكإضافة pip hermes-agent[supermemory]). إذا كان ملف config.yaml لديك يحتوي بالفعل على memory.provider: supermemory، فلا يلزم معظم المستخدمين إجراء شيء:

  • hermes update يثبّت إضافة الكتالوج في مجلد كل profile يذكر المزوّد (يُنفّذ ذلك حتى عندما تكون قيمة security.allow_lazy_installs هي false).
  • إذا ظلت الإضافة مفقودة عند بدء الوكيل لأول مرة (hermes chat أو gateway أو غيرهما)، يثبّتها Hermes ويطبع ✓ Memory provider 'supermemory' moved out of core — installed its plugin from the catalog (your memory.supermemory settings and data are unchanged).
  • مع security.allow_lazy_installs: false، يسجّل مسار بدء الوكيل بدلًا من ذلك سطرًا واحدًا — Memory provider 'supermemory' is not installed; security.allow_lazy_installs is off — run `hermes plugins install supermemory`. — وتنفّذ hermes plugins install supermemory بنفسك.

ما يتغيّر على القرص: تظهر الإضافة في ~/.hermes/plugins/supermemory/ ويُضاف إلى config.yaml الإدخال plugins.enabled: [supermemory]. يُثبّت Supermemory SDK من بيانات الحزمة الوصفية الخاصة بالإضافة، لذا لم تعد الإضافات (extras) hermes-agent[supermemory] مطلوبة. يبقى memory.provider, $HERMES_HOME/supermemory.json، والمفاتيح SUPERMEMORY_* في .env، والذكريات المخزّنة في حسابك على Supermemory دون مساس. تحقّق باستخدام hermes memory status (المزوّد نشط) و hermes plugins list (الإضافة مثبّتة ومفعّلة).

Memori

ذاكرة منظَّمة طويلة الأمد باستخدام Memori Cloud، مع التقاط الأدوار المكتملة في الخلفية، وسياق للأدوار يراعي الأدوات، وأدوات استرجاع صريحة للحقائق، والملخصات، والحصة، والتسجيل، والملاحظات.

الأنسب لـاسترجاع يتحكم فيه الوكيل مع إسناد منظَّم إلى المشروع والجلسة
المتطلباتCLI وتكامل مزوّد hermes-memori متاحان من جهة خارجية + مفتاح Memori API
تخزين البياناتMemori Cloud
التكلفةحسب تسعير Memori

الأدوات: memori_recall (البحث في الذاكرة طويلة الأمد)، memori_recall_summary (سياق ملخّص)، memori_quota (الاستخدام/الحصة)، memori_signup (طلب رسالة بريد إلكتروني للتسجيل)، memori_feedback (إرسال ملاحظات حول التكامل)

الإعداد:

hermes-memori تكامل خارجي، لا اسم أداة يديرها PM. اتّبع تعليمات ناشره لتثبيت CLI في بيئة مستقلة. قبل تشغيل مُثبّته، تأكّد من أنه يستهدف مجلد Hermes المقصود ويوفّر مزوّدًا باعتماديات Python مصرّح بها. لا تسمح لمُثبّت خارجي باستخدام pip للتثبيت داخل البيئة التي اختارها Hermes. لا يجعل توفّر CLI وحده مزوّد Python متاحًا داخل Hermes؛ فالتوزيع الذي يوفّر entry point فقط يحتاج إلى بناء يديره المالك ويتضمنه.

إذا لم يدعم المُثبّت قبول مزوّدي المجلدات المُدار عبر PM، فاطلب من الناشر ذلك التكامل بدلًا من اختراع أمر حزمة hermes pm install. أعد تشغيل Hermes بعد نجاح تجهيز الاعتماديات.

عزل الـ Profiles

تُعزل بيانات كل مزوّد لكل profile على حدة:

  • مزوّدو التخزين المحلي (Holographic، و ByteRover) يستخدمون مسارات $HERMES_HOME/ التي تختلف من profile إلى آخر
  • المزوّدون المعتمدون على ملفات الإعدادات (Honcho، و Mem0، و Hindsight، و Supermemory) يخزّنون الإعدادات في $HERMES_HOME/، لذا يكون لكل profile بيانات اعتماده الخاصة
  • المزوّدون السحابيون (RetainDB) يشتقّون تلقائيًا أسماء مشاريع خاصة بنطاق كل profile
  • المزوّدون المعتمدون على متغيرات البيئة (OpenViking) يُضبطون عبر ملف .env الخاص بكل profile

انتقال المزوّدين إلى كتالوج الإضافات

ينتقل مزوّدو الذاكرة من شجرة Hermes إلى مستودعات القائمين على صيانتها، ويُنشرون عبر كتالوج الإضافات. انتقل Hindsight أولًا (راجع الانتقال من Hindsight المضمّن)، ثم Honcho (راجع الترقية من Honcho المضمّن)، و Supermemory (راجع الانتقال من Supermemory المضمّن)، و Mem0 (راجع الانتقال من Mem0 المضمّن)، و OpenViking (راجع الانتقال من OpenViking المضمّن)، و Holographic (تتولى itpartypattaya صيانته الآن، راجع الانتقال من Holographic المضمّن). يغادر RetainDB و ByteRover النواة في 15 أكتوبر 2026؛ ومستودعاتهما المستقلة بلا قائم على الصيانة ومتاحة لمن يتولى صيانتها. لا يتغيّر شيء بالنسبة إليك: يبقى اسم المزوّد وإعداداته ومجلد بياناته وأدواته كما هي. عندما يتوقف Hermes عن تضمين مزوّد أعددته، يثبّت hermes update إضافة الكتالوج الخاصة به لكل profile يذكره؛ وإذا حدّثت عبر تطبيق Desktop، يفعل الوكيل الشيء نفسه عند بدئه لأول مرة. تُعرض لك كل نتيجة — في الطرفية أو Desktop أو مع الرد الأول على منصة مراسلة. إذا تعذّر التثبيت (security.allow_lazy_installs: false أو انقطاع الاتصال أو الرفض)، يتضمن التحذير أمر hermes plugins install <name> الدقيق.
