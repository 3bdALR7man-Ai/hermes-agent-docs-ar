transform_terminal_output

يُطلَق داخل أداة terminal بعد أن تكون بيئة التنفيذ قد حدّت بالفعل التقاط العملية الأمامية (foreground)، وقبل حد المخرجات النهائي. يتيح للإضافات استبدال stdout/stderr الملتقطة؛ ويظل الاستبدال خاضعًا لحد المخرجات النهائي.

يُطلَق أيضًا لمخرجات العمليات الخلفية في طريقها إلى النموذج أو المحادثة: نتائج process_manage poll / wait / log / kill (ومعاينات list)، وإشعارات الإكمال والنبض ومراقبة الأنماط. تكون returncode بالقيمة None ما دامت العملية تعمل، وتكون env_type سلسلة فارغة (لا تُسجَّل البيئة لكل عملية). في الحالتين يعمل الـ hook قبل حجب الأسرار، لذا يُحجَب أي بديل لا يزال يتضمن بيانات اعتماد.

توقيع الاستدعاء:

المعاملالنوعالوصف
commandstrأمر الـ shell الذي أنتج المخرجات.
outputstrstdout/stderr المدمجة بعد التقاط العملية المحدود.
returncodeintرمز إرجاع العملية.
task_idstrمعرّف المهمة الفعلي، أو سلسلة فارغة.
env_typestrنوع بيئة التنفيذ.

قيمة الإرجاع: أول str يستبدل المخرجات؛ None يتركها دون تغيير. يمكن أن يحوي الأمر والمخرجات بيانات اعتماد أو بيانات حساسة أخرى.

يقترن بـ transform_tool_result، الذي يعمل لاحقًا لكل أداة، بما فيها terminal.

transform_llm_output

يُطلَق مرة واحدة لكل دور بعد اكتمال حلقة استدعاء الأدوات وإنتاج النموذج ردًا نهائيًا، قبل تسليم ذلك الرد إلى المستخدم (CLI، أو gateway، أو مستدعٍ برمجي) و قبل حفظ صف المساعد — فالبديل هو ما تخزّنه الجلسة، وما يعرضه /resume، وما يعيد الدور التالي عرضه، فلا يختلف سجل المحادثة عما رآه المستخدم أبدًا. تُلحَق إضافات Hermes الختامية (تحذير تعديل الملفات وملاحظة الخروج غير الطبيعي) بعد ذلك، ولا تُعدّ جزءًا من response_text. يتيح لإضافة إعادة كتابة النص النهائي للمساعد بأساليب البرمجة التقليدية — دون استهلاك tokens إضافية لـ inference على نصوص طابع SOUL أو تحويل موجّه بمهارة.

توقيع الاستدعاء:

المعاملالنوعالوصف
response_textstrنص الرد النهائي للوكيل في هذا الدور.
session_idstrمعرّف الجلسة لهذه المحادثة (قد يكون فارغًا للتشغيلات الفردية).
modelstrاسم النموذج الذي أنتج الرد (مثل anthropic/claude-sonnet-4.6).
platformstrمنصة التسليم (cli، telegram، discord، …؛ فارغة إن لم تُضبط).

قيمة الإرجاع: str غير فارغة لاستبدال نص الرد، أو None أو سلسلة فارغة لتركه دون تغيير. تفوز أول سلسلة غير فارغة عند تسجيل عدة إضافات. بخلاف تحويلي الأداة والطرفية، لا تُقبَل السلسلة الفارغة كاستبدال.

حالات الاستخدام: تطبيق تحويل شخصية/مفردات (كلام قراصنة، سبونجبوب)، حجب معرّفات خاصة بالمستخدم من النص النهائي، إلحاق توقيع خاص بالمشروع، فرض دليل أسلوب داخلي دون استهلاك tokens على تعليمات SOUL.

عند تفعيل بث CLI، يُطبَع تحويل إلحاقي فقط بعد الجسم المُبثّ. أما التحويل الذي يستبدل الرد فيُطبَع كاملًا بعد الجسم المُبثّ، موسومًا كتحويل بعد-البث، بحيث لا يُفقَد المحتوى البديل صمتًا أبدًا.

الـ hook مقيَّد برد غير فارغ وغير مقاطَع — لن يُطلَق عند مقاطعات زر التوقف أو الأدوار الفارغة. تُسجَّل الاستثناءات كتحذيرات ولا تُعطِّل تنفيذ الوكيل.

Hooks مراقبة طلبات API

pre_api_request

يُطلَق لكل محاولة مزوّد مباشرة قبل إرسالها. هذا للمراقبة فقط. حقول user_message و conversation_history و request_messages القديمة خام وغير مُنقَّاة عمدًا لأغراض التوافق؛ يُفضَّل للمستهلكين الجدد استخدام مغلَّف request المُنقَّى.

post_api_request

يُطلَق بعد تطبيع استجابة المزوّد بنجاح. هذا للمراقبة فقط. يُفضَّل استخدام response المُنقَّاة؛ assistant_message هي الرسالة المطبَّعة الخام، و usage تحوي بيانات المحاسبة.

api_request_error

يُطلَق لمحاولة مزوّد فاشلة مع توقيت الحالة/إعادة المحاولة، وكائن error، و request المُنقَّاة. هذا للمراقبة فقط. قد تحوي رسائل الخطأ بيانات المزوّد أو المستخدم.

Hooks مراقبة الاستدعاءات المساعدة

pre_auxiliary_call / post_auxiliary_call

استدعاءات LLM المساعدة — تسمية الجلسات، وضغط السياق، ومستشارو MoA والمجمِّع، والرؤية، وتصنيف الموافقات، والذاكرة، وغيرها من المهام الجانبية — تعمل خارج حلقة استدعاء الأدوات الرئيسية، وهي لا تُطلِق pre_api_request / post_api_request (يظل نطاقهما محصورًا في الدور، لذا لا ترى إضافة تتبّع لكل دور حركة المهام الجانبية عرضًا أبدًا). اشترك بدلًا من ذلك في pre_auxiliary_call / post_auxiliary_call: يُطلَقان مرة لكل محاولة فعلية لدى المزوّد (بما فيها إعادات المحاولة والبدائل الاحتياطية)، بنفس بنية الحمولة مع إضافة aux_task (اسم المهمة، مثل title_generation، compression، moa_aggregator، vision). تكون session_id / task_id / turn_id خاصة بالدور الأب عندما يجري الاستدعاء ضمن دور، وتكون فارغة فيما عدا ذلك؛ وتشترك جميع محاولات الاستدعاء المنطقي الواحد في api_request_id (aux-…)، ويميّز retry_count بينها. كلاهما للمراقبة فقط ولا يوقف التنفيذ عند الفشل: يُسجَّل أي callback يثير استثناءً أو تنتهي مهلته، وتستمر المهمة المساعدة. يحمل post_auxiliary_call الحقلين error / error_type عندما تثير المحاولة استثناءً، ويحمل streaming: True (وتكون usage/response بالقيمة None) عند إرجاع الاستجابة كتدفّق.

on_skill_lifecycle

يُطلَق بعد تغيير معتمد في حالة استخدام مهارة. هو للمراقبة فقط، ويكشف skill_name المحلي، وبيانات المصدر، ومعرّفات الارتباط، وعدد الاستخدامات، وأعلام إعادة الاستخدام.

مراقبو دورة حياة Kanban

kanban_task_claimed المدمِّرة

يُطلَق بعد commit الاستحواذ في عملية الموزّع، مباشرة قبل إطلاق العامل.

kanban_task_completed

يُطلَق بعد الإكمال والتنظيف، عادة في عملية العامل. يمكن أن يحوي summary محتوى خاصًا بالمشروع أو المستخدم.

kanban_task_blocked

يُطلَق بعد انتقال حظر عادي. يستدعيه مسار انتظار الاعتماديات قبل خروج معاملة الكتابة تلك. يمكن أن يحوي reason محتوى خاصًا بالمشروع أو المستخدم.

كل hooks الـ kanban الثلاثة للمراقبة فقط وتحمل task_id, profile_name, board, assignee، و run_id؛ ويضيف الإكمال summary، ويضيف الحظر reason.

مراقِبو دورة حياة عامل Kanban ، وتعديل المهام، والتوزيع

تُوسِّع خمسة مراقِبين إضافيين (RFC #58548) عائلة kanban. جميعها للمراقبة فقط، وتُطلَق بعد التزام المعاملة ذات الصلة، وتُختصَر عند has_hook — فبلا مشترِك، يبقى سلوك التوزيع دون تغيير. تحمل hooks المحصورة بمهمة نفس الحقول المشتركة التي تحملها hooks أعلاه.

  • on_kanban_worker_spawned — بعد عودة spawn_fn وحفظ معرّف عملية العامل (PID). يضيف worker_pid (قد يكون None) و workspace_path. يعمل داخل قفل التوزيع؛ اجعل الاستدعاءات سريعة.
  • on_kanban_worker_exited — مشتق من التكة (tick)، عندما يستعيد detect_crashed_workers مهمة ذات PID ميت. يضيف worker_pid, exit_kind, exit_code, outcome, retry_status.
  • on_kanban_worker_stale_claim — عندما تُستعاد ملكية منتهية الصلاحية (TTL)؛ لا تُطلَق تمديدات PID الحي. يضيف worker_pid, heartbeat_stale, retry_status.
  • on_kanban_task_updated — بعد كتابة ملتزَمة لحقل مهمة خارج دورة حياة الاستحواذ/الإكمال/الحظر (assign_task، تجاوزات النموذج/الاستدلال، محرِّرات لوحة التحكم). يضيف changed_fields — أسماء الحقول فقط، دون قيمها أبدًا.
  • on_kanban_dispatch_tick — مرة واحدة لكل تكة موزِّع، بعد تحرير قفل التوزيع مباشرة، بما في ذلك تكات الخمول والمتنازَع عليها بالقفل. الحمولة: board, profile_name, dry_run, outcome, result.
