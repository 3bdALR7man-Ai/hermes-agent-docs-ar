تسجيل تطبيق Microsoft Graph

يقرأ pipeline اجتماعات Teams نصوص الاجتماعات المفرّغة (transcripts) والتسجيلات والملفات المرتبطة بها من Microsoft Graph باستخدام مصادقة على مستوى التطبيق فقط (app-only) (أي daemon) — دون تسجيل دخول مستخدم، ودون موافقة تفاعلية لكل اجتماع. ويتطلب ذلك تسجيل تطبيق في Azure AD مع صلاحيات تطبيق (application permissions) حاصلة على موافقة المسؤول (admin consent).

يرشدك هذا الدليل خلال ما يلي:

  1. إنشاء تسجيل التطبيق (app registration)
  2. إنشاء client secret
  3. منح صلاحيات Graph API التي يحتاجها الـ pipeline
  4. منح موافقة المسؤول على تلك الصلاحيات
  5. (اختياري) تقييد نطاق التطبيق بمستخدمين محددين عبر Application Access Policy

تحتاج إلى صلاحيات مسؤول الـ tenant (أو إلى مسؤول يمنح الموافقة نيابةً عنك) لإتمام ذلك. احتفظ بالقيم التي تجمعها — فستضعها في ~/.hermes/.env في النهاية.

المتطلبات المسبقة

  • tenant على Microsoft 365 يتضمن تراخيص Teams Premium أو Teams تُنتج نصوصًا مفرّغة وتسجيلات للاجتماعات
  • وصول بصلاحيات المسؤول إلى بوابة Azure على entra.microsoft.com
  • endpoint عبر HTTPS يمكن الوصول إليه علنًا لاستقبال إشعارات التغيير (change notifications) من Graph (يُعدّ لاحقًا في خطوة مستمع الـ webhook)

الخطوة 1: إنشاء تسجيل التطبيق

  1. سجّل الدخول إلى entra.microsoft.com بصفتك مسؤول الـ tenant.
  2. انتقل إلى Identity → Applications → App registrations.
  3. انقر New registration.
  4. املأ الحقول التالية:
    • Name: Hermes Teams Meeting Pipeline (أو أي اسم تتعرّف عليه).
    • Supported account types: Accounts in this organizational directory only (Single tenant) (أي الحسابات ضمن هذا الدليل التنظيمي فقط).
    • Redirect URI: اتركه فارغًا — فالمصادقة على مستوى التطبيق فقط لا تحتاج إليه.
  5. انقر Register.

ستنتقل إلى صفحة النظرة العامة الخاصة بالتطبيق. انسخ قيمتين:

  • Application (client) ID → MSGRAPH_CLIENT_ID
  • Directory (tenant) ID → MSGRAPH_TENANT_ID

الخطوة 2: إنشاء Client Secret

  1. من شريط التنقل الأيسر، افتح Certificates & secrets.
  2. انقر New client secret.
  3. Description: hermes-graph-secret. Expires: اختر قيمة تتوافق مع سياسة التدوير (rotation) لديك (المعتاد من 6 إلى 24 شهرًا).
  4. انقر Add.
  5. انسخ قيمة العمود Value فورًا — فهي لا تُعرض إلا مرة واحدة. هذه القيمة هي MSGRAPH_CLIENT_SECRET.

العمود Secret ID ليس هو السر. ما تحتاج إليه هو العمود Value.

الخطوة 3: منح صلاحيات Graph API

يستخدم الـ pipeline الحد الأدنى اللازم من صلاحيات التطبيق. أضف ما تحتاج إليه فقط؛ فكل صلاحية توسّع نطاق ما يستطيع التطبيق قراءته على مستوى الـ tenant بأكمله.

  1. من شريط التنقل الأيسر، افتح API permissions.
  2. انقر Add a permission → Microsoft Graph → Application permissions.
  3. أضف من الجدول أدناه الصلاحيات التي تتوافق مع ما تريد أن يفعله الـ pipeline.
  4. بعد الإضافة، انقر Grant admin consent for <your tenant>. يجب أن يتحول العمود Status إلى علامة صح خضراء لكل صلاحية.

غير موصى بها

  • OnlineMeetings.ReadWrite.All / Chat.ReadWrite بدون .All — نطاقها أوسع مما يحتاجه الـ pipeline.
  • الصلاحيات المفوّضة (Delegated permissions) — يستخدم الـ pipeline تدفّق app-only (client-credentials)؛ ولن تعمل الصلاحيات المفوّضة دون تسجيل دخول مستخدم.

الخطوة 4: (موصى بها) تقييد نطاق التطبيق عبر Application Access Policy

افتراضيًا، تمنح صلاحيات التطبيق مثل OnlineMeetings.Read.All التطبيقَ وصولًا إلى كل اجتماع في الـ tenant. هذا مقبول في العروض التوضيحية للشركاء وفي tenants التطوير؛ أما في بيئة الإنتاج فستحتاج على الأرجح إلى تقييد المستخدمين الذين يستطيع التطبيق قراءة اجتماعاتهم.

توفّر Microsoft خاصية Application Access Policies في Teams لهذا الغرض تحديدًا. لا تتوفر هذه السياسة إلا عبر PowerShell؛ ولا توجد لها واجهة في البوابة.

يأتي Hermes مع اختبار سريع (smoke test) لمصادقة Graph. من مجلد تثبيت Hermes لديك:

يطبع التشغيل الناجح سلسلة token طويلة وقاموس حالة (health dict) يُظهر cached: True وقيمة expires_in_seconds قريبة من 3600. أما حالات الفشل فتُنتج MicrosoftGraphTokenError مع رمز خطأ Azure — وأكثرها شيوعًا:

خطأ Azureالمعنىالحل

تدوير الـ Client Secret

لأسرار العملاء في Azure تاريخ انتهاء صلاحية صارم. قبل أن ينتهي سرّك:

  1. أنشئ client secret ثانيًا في الخطوة 2 دون حذف الأول.
  2. حدّث MSGRAPH_CLIENT_SECRET في ~/.hermes/.env بالقيمة الجديدة.
  3. أعد تشغيل الـ gateway كي يُلتقط السر الجديد: hermes gateway restart.
  4. تحقّق باستخدام الاختبار السريع أعلاه.
  5. احذف السر القديم من بوابة Azure.

الخطوات التالية

بعد التحقق من بيانات الاعتماد بنجاح، تابع مع:

  • إعداد مستمع الـ webhook — شغّل منصة الـ gateway msgraph_webhook التي تستقبل إشعارات التغيير من Graph.
  • إعدادات الـ pipeline — اضبط بيئة تشغيل pipeline اجتماعات Teams و CLI الخاص بالمشغّل.
  • التسليم إلى الخارج — اربط الملخّصات لتُرسل مجددًا إلى قناة أو محادثة على Teams.

ستُنشر تلك الصفحات مع طلبات الـ PR التي تضيف بيئة التشغيل المقابلة. أما إعداد بيانات الاعتماد هذا فهو متطلب مسبق مستقل، ويمكنك إتمامه مسبقًا بأمان.
