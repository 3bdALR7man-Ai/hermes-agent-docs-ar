ملفات السياق (Context Files)

يكتشف Hermes Agent تلقائيًا ملفات السياق التي تُشكّل سلوكه ويحمّلها. بعض هذه الملفات محلية على مستوى المشروع وتُكتشف من مجلد العمل. أما SOUL.md فأصبح الآن عامًا على مستوى نسخة Hermes، ولا يُحمَّل إلا من HERMES_HOME.

نظام الأولوية

لا يُحمَّل إلا نوع واحد من سياق المشروع في كل جلسة (يُعتمد أول تطابق): .hermes.md → AGENTS.override.md → AGENTS.md → CLAUDE.md → .cursorrules. أما SOUL.md فيُحمَّل دائمًا بشكل مستقل بوصفه هوية الوكيل (الخانة رقم 1).

إذا وُجد AGENTS.override.md بجوار AGENTS.md، يُحمَّل ملف التجاوز بدلًا من الملف المُضاف إلى المستودع — احتفظ بملف AGENTS.override.md شخصي (مستثنى عادةً عبر gitignore) عندما تريد تعليمات مختلفة عن تلك الموجودة في المستودع، دون تعديل ملف AGENTS.md المتتبَّع.

AGENTS.md

AGENTS.md هو ملف السياق الأساسي للمشروع. يُخبر الوكيل بكيفية هيكلة مشروعك، والاصطلاحات الواجب اتباعها، وأي تعليمات خاصة.

سلسلة المجلدات (جذر git → مجلد العمل)

عندما يقع مجلد العمل داخل مستودع git، يحمّل Hermes عند بدء الجلسة سلسلة مدمجة من ملفات AGENTS.md: ملف AGENTS.md الموجود في جذر git أولًا، ثم ملف AGENTS.md في كل مجلد وسيط نزولًا حتى مجلد العمل. تظهر الملفات الأعمق لاحقًا في الـ prompt، لذا تكون الأولوية للإرشادات الأكثر تحديدًا. يحصل كل ملف على ترويسة مصدر خاصة به (مثل ## ../../AGENTS.md)، وتُحذف النسخ المتطابقة المكررة على طول السلسلة.

خارج مستودع git، يُفحص مجلد العمل نفسه فقط — ولا يُرجع أبدًا إلى المجلدات الأم، لذا لا يمكن لملف AGENTS.md مزروع في /tmp أو $HOME أن يتسرّب إلى جلسات غير ذات صلة.

الاكتشاف التدريجي للمجلدات الفرعية

عند بدء الجلسة، يحمّل Hermes ملف AGENTS.md من مجلد العمل إلى الـ system prompt. ومع تنقّل الوكيل داخل المجلدات الفرعية أثناء الجلسة (عبر read_file و terminal و search_files وغيرها)، فإنه يكتشف تدريجيًا ملفات السياق في تلك المجلدات ويحقنها في المحادثة لحظة أن تصبح ذات صلة.

يتميّز هذا النهج بميزتين مقارنةً بتحميل كل شيء عند بدء التشغيل:

  • لا تضخّم في الـ system prompt — لا تظهر تلميحات المجلدات الفرعية إلا عند الحاجة
  • الحفاظ على prompt cache — يبقى الـ system prompt ثابتًا عبر الأدوار

يُفحص كل مجلد فرعي مرة واحدة على الأكثر في كل جلسة. كما يصعد الاكتشاف عبر المجلدات الأم، لذا فإن قراءة backend/src/main.py ستكتشف backend/AGENTS.md حتى لو لم يكن في backend/src/ ملف سياق خاص به.

معلومة

تخضع ملفات سياق المجلدات الفرعية لنفس الفحص الأمني الذي تخضع له ملفات السياق عند بدء التشغيل، وتُحظر الملفات الخبيثة.

مثال على AGENTS.md

SOUL.md

يتحكم SOUL.md في شخصية الوكيل ونبرته وأسلوب تواصله. راجع صفحة الشخصية (Personality) للاطلاع على التفاصيل الكاملة.

الموقع:

  • ~/.hermes/SOUL.md
  • أو $HERMES_HOME/SOUL.md إذا كنت تشغّل Hermes بمجلد home مخصص

تفاصيل مهمة:

  • ينشئ Hermes ملف SOUL.md افتراضيًا تلقائيًا إن لم يكن موجودًا بعد
  • يحمّل Hermes ملف SOUL.md من HERMES_HOME فقط
  • لا يبحث Hermes عن SOUL.md في مجلد العمل
  • إذا كان الملف فارغًا، فلا يُضاف أي شيء من SOUL.md إلى الـ prompt
  • إذا كان الملف يحتوي على محتوى، يُحقن هذا المحتوى حرفيًا بعد الفحص والاقتطاع

.cursorrules

Hermes متوافق مع ملف .cursorrules ووحدات القواعد .cursor/rules/*.mdc الخاصة بـ Cursor IDE. إذا وُجدت هذه الملفات في جذر مشروعك ولم يُعثر على ملف سياق ذي أولوية أعلى (.hermes.md أو AGENTS.md أو CLAUDE.md)، فإنها تُحمَّل بوصفها سياق المشروع.

هذا يعني أن اصطلاحات Cursor الموجودة لديك تُطبَّق تلقائيًا عند استخدام Hermes.

كيفية تحميل ملفات السياق

عند بدء التشغيل (system prompt)

تُحمَّل ملفات السياق بواسطة build_context_files_prompt() في agent/prompt_builder.py:

  1. فحص مجلد العمل — يبحث عن .hermes.md → AGENTS.md → CLAUDE.md → .cursorrules (يُعتمد أول تطابق)
  2. قراءة المحتوى — يُقرأ كل ملف كنص UTF-8
  3. الفحص الأمني — يُفحص المحتوى بحثًا عن أنماط prompt injection
  4. الاقتطاع — تُقتطع الملفات التي تتجاوز حد الأحرف من المنتصف مع الإبقاء على البداية والنهاية (70% للبداية، و20% للنهاية، مع علامة في المنتصف). يكون الحد هو قيمة context_file_max_chars الصريحة من config.yaml عند ضبطها؛ وإلا فإنه يتغير ديناميكيًا بحسب context window الخاصة بالنموذج (بحد أدنى 20,000 حرف، وحد أقصى 500,000)
  5. التجميع — تُدمج جميع الأقسام تحت ترويسة # Project Context
  6. الحقن — يُضاف المحتوى المجمّع إلى الـ system prompt

أثناء الجلسة (الاكتشاف التدريجي)

يراقب SubdirectoryHintTracker في agent/subdirectory_hints.py وسائط استدعاءات الأدوات بحثًا عن مسارات الملفات:

  1. استخراج المسارات — بعد كل استدعاء أداة، تُستخرج مسارات الملفات من الوسائط (path و workdir وأوامر الـ shell)
  2. الصعود عبر المجلدات الأم — يُفحص المجلد وما يصل إلى 5 مجلدات أم (مع التوقف عند المجلدات التي سبقت زيارتها)
  3. تحميل التلميحات — إذا عُثر على AGENTS.md أو CLAUDE.md أو .cursorrules، فإنه يُحمَّل (أول تطابق في كل مجلد)
  4. الفحص الأمني — نفس فحص prompt injection المطبّق على ملفات بدء التشغيل
  5. الاقتطاع — بحد أقصى 8,000 حرف لكل ملف
  6. الحقن — يُلحق بنتيجة الأداة، فيراه النموذج ضمن السياق بصورة طبيعية

الأمان: الحماية من Prompt Injection

تُفحص جميع ملفات السياق بحثًا عن أي prompt injection محتمل قبل تضمينها. يبحث الفاحص عن:

  • محاولات تجاوز التعليمات: "ignore previous instructions"، "disregard your rules"
  • أنماط الخداع: "do not tell the user"
  • تجاوز الـ system prompt: "system prompt override"
  • تعليقات HTML مخفية: <!-- ignore instructions -->
  • عناصر div مخفية: <div style="display:none">
  • تسريب بيانات الاعتماد: curl ... $API_KEY
  • الوصول إلى ملفات الأسرار: cat .env، cat credentials
  • الأحرف غير المرئية: المسافات صفرية العرض (zero-width spaces)، وأحرف تجاوز الاتجاه الثنائي (bidirectional overrides)، وأحرف ربط الكلمات (word joiners)

إذا اكتُشف أي نمط تهديد، يُحظر الملف:

تحذير

يحمي هذا الفاحص من أنماط الحقن الشائعة، لكنه ليس بديلًا عن مراجعة ملفات السياق في المستودعات المشتركة. تحقّق دائمًا من محتوى AGENTS.md في المشاريع التي لم تكتبها بنفسك.

حدود الحجم

الحدالقيمة
الحد الأقصى للأحرف لكل ملفcontext_file_max_chars عند ضبطه؛ وإلا فهو ديناميكي (يتغير بحسب context window الخاصة بالنموذج، بحد أدنى 20,000 وحد أقصى 500,000)
مهلة القراءة لكل ملفcontext_file_read_timeout (الافتراضي 5 ثوانٍ)؛ يُتخطى الملف الذي تستغرق قراءته وقتًا أطول — مثلًا على iCloud Drive أو OneDrive أو NFS — مع إصدار تحذير
نسبة البداية عند الاقتطاع70%
نسبة النهاية عند الاقتطاع20%
علامة الاقتطاع10% (تعرض أعداد الأحرف وتقترح استخدام أدوات الملفات)

نصائح لملفات سياق فعّالة

أفضل الممارسات لملف AGENTS.md
  1. اجعله موجزًا — ابقَ دون قيمة context_file_max_chars المضبوطة لديك؛ فالوكيل يقرأه في كل دور
  2. نظّمه بالعناوين — استخدم أقسام ## للبنية المعمارية والاصطلاحات والملاحظات المهمة
  3. أدرج أمثلة ملموسة — اعرض أنماط الكود المفضّلة، وأشكال API، واصطلاحات التسمية
  4. اذكر ما يجب تجنّبه — "لا تعدّل ملفات الترحيل (migration) مباشرةً أبدًا"
  5. اذكر المسارات والمنافذ الرئيسية — يستخدمها الوكيل في أوامر الطرفية
  6. حدّثه مع تطوّر المشروع — السياق القديم أسوأ من عدم وجود سياق
