Node.js Inspect Debugger

نظرة عامة

عندما لا يكفي console.log، شغّل مفحّص V8 المدمج في Node برمجيًا من الطرفية. تحصل على نقاط توقف حقيقية، وخطو Step In/Over/Out، وتتبّع مكدس الاستدعاءات (call stack)، وعرض النطاقات المحلية/الإغلاق (closure)، وتقييم أي تعبير في الإطار المتوقف.

أداتان، اختر واحدة:

  • node inspect — مدمجة، بلا تثبيت، REPL عبر CLI. الأفضل للفحص السريع.
  • ndb / CDP عبر chrome-remote-interface — قابلة للبرمجة من Node/Python؛ الأفضل عندما تريد أتمتة عدد كبير من نقاط التوقف، أو تجميع الحالة عبر عدة تشغيلات، أو التصحيح دون تفاعل من حلقة وكيل (agent loop).

فضّل node inspect أولًا. فهي متاحة دائمًا و REPL سريع.

متى تستخدمها

  • يفشل اختبار Node وتحتاج إلى رؤية حالة وسيطة
  • تتعطل ui-tui أو تتصرف بشكل خاطئ وتريد فحص حالة React/Ink قبل العرض (pre-render)
  • تسيء العمليات الفرعية لـ tui_gateway (_SlashWorker، عمّال جسر PTY) التصرف
  • تحتاج إلى فحص قيمة في closure لا يستطيع console.log الوصول إليها دون تعديل الكود
  • الأداء: الاتصال بعملية قيد التشغيل لالتقاط ملف تعريف CPU أو لقطة heap

لا تستخدمها في: ما يحلّه console.log في أقل من دقيقة. التصحيح المعتمد على نقاط التوقف أثقل؛ استخدمه عندما تكون الفائدة حقيقية.

مزالق شائعة

  1. أرقام أسطر خاطئة في مصدر TS. تصيب نقاط التوقف كود JS المُصدَر، لا ملف .ts. إما (أ) التوقف في dist/*.js المبني، أو (ب) تفعيل خرائط المصدر (sourcemaps) عبر (node --enable-source-maps) واستخدام sb('src/app.tsx', N) — لكن فقط مع عملاء CDP الذين يتّبعون خرائط المصدر. لا تفعل ذلك واجهة node inspect عبر CLI.

  2. --inspect مقابل --inspect-brk. يبدأ --inspect المفحّص لكن لا يوقفه؛ فيتجاوز سكربتك أول نقطة توقف إن اتصلت متأخرًا جدًا. استخدم --inspect-brk عندما تحتاج إلى تعيين نقاط التوقف قبل تشغيل أي كود.

  3. تعارض المنافذ (ports). الافتراضي هو 9229. إذا كانت عدة عمليات Node قيد الفحص، مرّر --inspect=0 (منفذ عشوائي) واقرأ الرابط الفعلي من /json/list:

  4. العمليات الفرعية. لا يفحص --inspect على عملية أب عملياتها الفرعية. استخدم NODE_OPTIONS='--inspect-brk' node parent.js لينتقل ذلك إلى كل عملية فرعية؛ وانتبه أنها جميعًا تحتاج منافذ فريدة (يزيد Node المنفذ تلقائيًا عند وراثة NODE_OPTIONS='--inspect').

  5. إنهاء في الخلفية. إذا ضغطت Ctrl+C للخروج من node inspect بينما الهدف متوقف، يبقى الهدف متوقفًا. إما نفّذ cont أولًا، أو أنهِ الهدف صراحةً بـ kill.

  6. تشغيل node inspect عبر طرفية وكيل. إنه REPL متوافق مع PTY. في Hermes، شغّله بـ terminal(pty=true) أو background=true مع process(action='submit', data='...'). يعمل نمط المقدمة غير PTY للأوامر المفردة لكن ليس للخطو التفاعلي.

  7. الأمان. يعرّض --inspect=0.0.0.0:9229 تنفيذ كود تعسفي. اربط دائمًا بـ 127.0.0.1 (الافتراضي) إلا إذا كانت لديك شبكة معزولة.

قائمة التحقق

بعد إعداد جلسة تصحيح، تحقّق من:

  • يعيد curl -s http://127.0.0.1:9229/json/list الهدف الذي تتوقعه بالضبط
  • نقطة التوقف الأولى تُصاب فعليًا (إن لم تُصب، فمن المرجّح أنك فوّت --inspect-brk أو اتصلت بعد اكتمال التنفيذ)
  • عرض المصدر عند التوقف يُظهر الملف الصحيح (عدم التطابق = مشكلة في خرائط المصدر، انظر المزلق 1)
  • يعيد exec process.pid في repl رقم العملية (PID) الذي قصدت الاتصال به
