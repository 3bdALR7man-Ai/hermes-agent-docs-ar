GitHub

اعمل مع GitHub من البداية إلى النهاية باستخدام واجهة سطر الأوامر gh (مع الرجوع إلى REST حيث يُذكر ذلك): المصادقة، والقضايا، ودورة حياة PR، والتسليم من قضية إلى PR، ومراجعة الكود، وإدارة المستودعات. تُوحّد هذه المهارة ست مهارات سابقة؛ يعيش كل سير عمل كاملًا في ملف مرجعه الخاص — اقرأ دائمًا المرجع المطابق قبل بدء ذلك السير، والنص أدناه يوجّهك فحسب.

الانضباط الأساسي (يسري على كل سير عمل)

  • فحص أولي مرة واحدة لكل جلسة: gh auth status — إذا فشل، انتقل إلى references/auth.md قبل أي شيء آخر.
  • فضّل gh على REST الخام؛ انزل إلى gh api فقط لأجل endpoints التي لا تغطيها الواجهة الأساسية (تسردها ورقة الغش).
  • لا تُبلغ أبدًا بأن CI ناجح دون التحقق بنفسك عبر gh pr checks؛ ولا تدّعِ أبدًا أن الدمج تمّ دون التحقق من state,mergedAt.
  • اقرأ السياق الكامل قبل الكتابة: gh issue view --comments / gh pr view --comments — القرارات تعيش في الخيوط، لا في العناوين.
  • افحص التكرارات قبل إنشاء أي شيء: gh pr list --search / gh issue list --search.

التحقّق

  • يُحدّد ملف مرجع سير العمل نفسه معنى الاكتمال لتلك المهمة.
  • شامل لجميع الحالات: كل ادّعاء بشأن حالة بعيدة (CI، الدمج، الإصدار، حالة القضية) مدعوم بقراءة gh حديثة، لا بالذاكرة.
