API دورة حياة Subagent العامة

يمكن للإضافات إطلاق جلسات Hermes فرعية جديدة والإشراف عليها دون استيراد tools.delegate_tool أو آليات gateway الداخلية أو حالة TUI أو حقول AIAgent. تحلّ الخدمة والدها من دور الوكيل الحالي، لذا تعمل في جلسات CLI و gateway والجلسات غير التفاعلية وجلسات عامل kanban. ويفشل الإطلاق خارج دور وكيل نشط بأمان (fail closed) مع الرسالة No active Hermes parent session. وتعمل الواجهة (facade) أيضًا عند تشغيل إضافة تحت plugins.isolation: host.

تقبل الطلبات goal و context و role و model و provider و allowed_toolsets و blocked_tools و working_directory و parent_session_id و correlation_id و metadata و timeout_seconds، مع مراعاة القيود الواردة أدناه.

SubagentHandle قابل للتسلسل (serializable) ويحمل صلاحية مبهمة ذات إصدار. وقد تصل الطلبات والمقابض (handles) أيضًا بصيغة mappings، بما في ذلك سجلات الاتصال الخاصة بمضيف الإضافات. مرّر المقبض إلى status أو wait أو cancel أو steer أو result أو reconnect؛ وأي مقبض مشوَّه أو مزوَّر يُعيد UNKNOWN/UNKNOWN_HANDLE ولا يمكنه الوصول إلى عملية فرعية.

يضع steer(handle, text) النص في قائمة الانتظار ليُطبَّق عند حدّ التكرار التالي للعملية الفرعية، ويعيد True ما دامت العملية الفرعية تقبل التوجيه. ويعيد False عند النص الفارغ، أو المقابض غير المعروفة أو المزوَّرة، أو المقابض التي تملكها جلسة والدة أخرى، أو عملية فرعية انتهت أو توقفت عن قبول التوجيه.

الحالات المستقرة هي PENDING، وSTARTING، وRUNNING، وSUCCEEDED، وFAILED، وINTERRUPTED، وCANCEL_REQUESTED، وCANCELLED، وUNKNOWN.

cancel(handle, reason=...) تعاونية بطبيعتها: تطلب من الوكيل الفرعي مقاطعة العمل عند أقرب نقطة آمنة له وتعيد CANCEL_REQUESTED؛ ولا تدّعي أبدًا الاكتمال حتى تلاحظ wait أو result حالة نهائية. النتائج النهائية غير قابلة للتغيير، ومتماثلة القوة (idempotent)، ومحدودة بـ 32 ألف حرف، وتحذف النصوص الكاملة والتفكير المخفي، وتتضمن تجزئة (hash) نتيجة مستقرة.

هذه الواجهة تنفيذ غير متزامن (asynchronous) مُدار بدورة حياة. يستخدم إنشاء العملية الفرعية وإكمالها نفس المسار المملوك للمضيف الذي يستخدمه delegate_task، بما في ذلك استعادة حل الأداة الخاص بالوالد، وإشعار الذاكرة، وhooks subagent_stop المُسلسَلة، وتنظيف الموارد، وتجميع تكلفة العملية الفرعية. وهي لا تغيّر أداة delegate_task المتزامنة، ولا التفويض الدفعي، ولا عرضها في gateway/TUI. يحتفظ التنفيذ الأولي بالبيانات الوصفية والنتائج النهائية داخل العملية لمدة ساعة واحدة. بعد إعادة تشغيل العملية، تعيد reconnect RECONNECT_UNAVAILABLE ولا تُطلق أبدًا عملية فرعية بديلة. كما لا يمكن لخيوط Python (threads) قيد التشغيل النجاة من خروج العملية؛ يجب على المستدعين معاملة تلك المقابض على أنها مقاطعة بسبب خروج العملية.

الطلبات تفشل بأمان (fail-closed): أحجام الهدف/السياق/البيانات الوصفية محدودة، وتُرفض مجموعات الأدوات (toolsets) غير المعروفة أو التي توسّع نطاق الوالد (وتُعدّ مجموعات الأدوات المسجَّلة من الإضافات معروفة)، وتُرفض صراحةً حظر الأدوات الفردية، وتجاوزات دليل العمل، ومهلات الإطلاق الفردية حتى يستطيع Hermes دعمها دون إضعاف العزل. استخدم allowed_toolsets لتضييق نطاق العملية الفرعية؛ ويظل حظر الأدوات غير الآمنة الموجود مسبقًا في Hermes مفروضًا.

التوجيه

تتبع العمليات الفرعية إعدادات delegation (provider و model و base_url و api_key و api_mode و request_overrides) تمامًا كما يفعل أبناء delegate_task. ويتجاوز model الوارد في الطلب النموذج المضبوط. أما provider الاختياري فيسمّي مزوّدًا مضبوطًا لهذا الإطلاق، بأسبقية الطلب > إعدادات delegation > الوالد؛ ويوفّر المزوّد المختار حزمة بيانات الاعتماد الخاصة به. وإذا تعذّر حلّ المزوّد يُطلَق SubagentLifecycleError قبل الإطلاق. لا تكشف النواة provider للنموذج: فالإضافة هي التي تختاره، مثلًا من إعدادات المشغّل.
